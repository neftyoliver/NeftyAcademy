OpenGL 드라이버는 GLSL 원문을 받아 실행 중에 컴파일했습니다. 회사마다 컴파일러의 앞단이 달라서 한 드라이버에서 되던 셰이더가 다른 드라이버에서는 문법 오류를 내기도 했고, 프로그램을 띄울 때마다 원문을 파싱하는 비용을 치렀으며, 셰이더 원문이 그대로 배포되었습니다. 벌칸은 그 대신 **SPIR-V**라는 이진 중간 표현을 받습니다. SPIR-V는 2015년 OpenCL 2.1과 함께 1.0이 나왔고, 2016년 벌칸 1.0의 셰이더 형식이 되었으며, OpenGL 4.6도 확장(ARB_gl_spirv)으로 받습니다.

중간 표현을 두면 일이 둘로 나뉩니다. 언어를 읽는 **앞단**(GLSL과 HLSL의 glslang, HLSL의 DXC, Slang 등)은 개발자의 기계에서 돌고, 드라이버는 32비트 낱말로 된 단순한 형식만 읽어 GPU 기계어로 바꾸는 **뒷단**만 맡습니다. 그 사이에서 최적화기, 검증기, 리플렉션, 다른 언어로의 역번역 같은 도구가 언어와 상관없이 같은 형식을 다룹니다. 아래 프로그램은 GLSL을 번역한 뒤 SPIRV-Tools의 최적화기와 검증기를 거칩니다.

```cpp vk pkg=SPIRV-Tools with=vkx_instance.hpp,vkx_device.hpp,vkx_pipeline.hpp
#include <spirv-tools/libspirv.hpp>
#include <spirv-tools/optimizer.hpp>
#include "vkx_pipeline.hpp"

const char* CS = R"(#version 450
layout(local_size_x = 64) in;
layout(binding = 0) buffer Data { float v[]; };
float square(float x) { return x * x; }
void main() {
    uint i = gl_GlobalInvocationID.x;
    float unused = sin(float(i));   // 결과를 아무도 쓰지 않는다
    v[i] = square(v[i]) + 1.0;
})";

// 명령의 첫 낱말은 위 16비트가 낱말 수, 아래 16비트가 명령 번호다
void count(const char* label, const std::vector<uint32_t>& m) {
    int instructions = 0, functions = 0;
    std::string ext;
    for (size_t at = 5; at < m.size(); at += m[at] >> 16) {
        uint32_t op = m[at] & 0xFFFF;
        ++instructions;
        functions += op == 54;                  // OpFunction
        if (op == 12)   // OpExtInst: 넷째 낱말이 GLSL.std.450의 명령 번호
            ext += m[at + 4] == 13 ? " Sin" : m[at + 4] == 50 ? " Fma" : " 그 밖";
    }
    std::printf("%s %3zu낱말, 명령 %2d개, 함수 %d개, 확장 명령:%s\n", label,
                m.size(), instructions, functions, ext.c_str());
}

int main() {
    std::vector<uint32_t> plain = vkx::compile(CS, shaderc_compute_shader), fast;
    spvtools::Optimizer optimizer(SPV_ENV_VULKAN_1_3);
    optimizer.RegisterPerformancePasses();   // spirv-opt -O와 같은 패스들
    optimizer.Run(plain.data(), plain.size(), &fast);
    std::printf("GLSL 원문 %zu바이트\n", std::strlen(CS));
    count("그대로", plain);
    count("-O    ", fast);

    spvtools::SpirvTools tools(SPV_ENV_VULKAN_1_3);
    std::string text;
    tools.Disassemble(fast, &text, SPV_BINARY_TO_TEXT_OPTION_FRIENDLY_NAMES);
    std::printf("%s", text.substr(text.find("%main = OpFunction")).c_str());

    tools.SetMessageConsumer([](spv_message_level_t, const char*,
                                const spv_position_t&, const char* msg) {
        std::string s = msg;   // 줄 끝의 빈칸은 지우고 찍는다
        for (size_t p; (p = s.find(" \n")) != std::string::npos;) s.erase(p, 1);
        while (!s.empty() && (s.back() == ' ' || s.back() == '\n')) s.pop_back();
        std::printf("검증기: %s\n", s.c_str());
    });
    std::printf("-O 결과 검증: %s\n", tools.Validate(fast) ? "통과" : "실패");
    std::vector<uint32_t> broken = fast;   // OpCapability Shader를 Matrix로 바꾼다
    for (size_t at = 5; at < broken.size(); at += broken[at] >> 16)
        if ((broken[at] & 0xFFFF) == 17 && broken[at + 1] == 1) broken[at + 1] = 0;
    std::printf("Shader 능력을 뺀 모듈 검증: %s\n",
                tools.Validate(broken) ? "통과" : "실패");
}
```

GLSL 원문 291바이트
그대로 320낱말, 명령 78개, 함수 2개, 확장 명령: Sin
-O     198낱말, 명령 46개, 함수 1개, 확장 명령: Fma
%main = OpFunction %void None %3
%5 = OpLabel
%25 = OpAccessChain %_ptr_Input_uint %gl_GlobalInvocationID %uint_0
%26 = OpLoad %uint %25
%41 = OpAccessChain %_ptr_StorageBuffer_float %_ %int_0 %26
%42 = OpLoad %float %41
%45 = OpExtInst %float %1 Fma %42 %42 %float_1
OpStore %41 %45
OpReturn
OpFunctionEnd
-O 결과 검증: 통과
검증기: Operand 2 of MemoryModel requires one of these capabilities: Shader
  OpMemoryModel Logical GLSL450

- **최적화기**: `spirv-opt -O`와 같은 패스들이 작은 함수 `square`를 안으로 넣고(함수 2개 → 1개), 아무도 쓰지 않는 `sin`을 지우고, 곱하고 더하기를 `Fma` 하나로 합쳐 320낱말을 198낱말로 줄였습니다. 이런 최적화를 드라이버마다 따로 하지 않아도 됩니다
- **검증기**: SPIR-V에는 형식 규칙이 많습니다. 예를 들어 셰이더용 메모리 모델(`GLSL450`)을 쓰려면 `Shader` 능력을 먼저 밝혀야 하고, 이를 빼면 검증기가 어느 명령이 틀렸는지 짚습니다. 검증 레이어도 `vkCreateShaderModule`에서 같은 검증기를 돌립니다
- **사람이 읽는 꼴**: `%42 = OpLoad %float %41`처럼, 결과마다 한 번만 정해지는 번호(SSA)를 붙인 명령의 나열입니다. 구조는 [「모듈의 구조」](#/read/cpp-vulkan/spv-module)에서 봅니다

<Note>
SPIR-V는 GPU 기계어가 아니라서 드라이버는 여전히 파이프라인을 만들 때 컴파일합니다. 줄어든 것은 원문을 파싱하고 검사하는 앞단의 일과, 회사마다 달랐던 언어 해석입니다. OpenCL의 이전 형식(SPIR 1.2, 2.0)은 LLVM IR을 바탕으로 했지만, SPIR-V는 LLVM에 묶이지 않은 독자 형식입니다.
</Note>

## 정리

- OpenGL은 드라이버가 GLSL 원문을 실행 중에 컴파일했고, 회사마다 해석이 달랐으며, 원문이 그대로 배포되었다
- 벌칸은 이진 중간 표현 SPIR-V를 받아, 언어를 읽는 앞단은 개발자 쪽으로, GPU 기계어를 만드는 뒷단만 드라이버에 남겼다
- 같은 형식 위에서 최적화기·검증기·리플렉션·역번역 도구가 언어와 상관없이 돈다
