커맨드 버퍼의 명령은 기록한 차례로 시작되지만 실행은 겹치거나 차례가 바뀔 수 있습니다. 같은 메모리를 건드리는 두 명령의 순서는 **파이프라인 배리어**가 겁니다. 배리어에는 앞선 명령의 어느 단계·어떤 접근이 끝난 뒤에 뒤따르는 명령의 어느 단계·어떤 접근을 시작할지 적습니다. 아래 프로그램은 복사 명령을 여러 가지로 잇고, `VkValidationFeaturesEXT`로 켠 동기화 검증이 알린 이름을 적습니다.

```cpp vk with=vkx_instance.hpp,vkx_device.hpp,vkx_cmd.hpp,vkx_resource.hpp
#include <functional>
#include <string>
#include "vkx_cmd.hpp"
#include "vkx_resource.hpp"

// 검증 레이어가 처음 알린 규칙의 이름만 적어 둔다(메시지 전체에는 핸들 값이 섞인다)
std::string seen;
VKAPI_ATTR VkBool32 VKAPI_CALL collect(
        VkDebugUtilsMessageSeverityFlagBitsEXT, VkDebugUtilsMessageTypeFlagsEXT,
        const VkDebugUtilsMessengerCallbackDataEXT* d, void*) {
    if (seen.empty()) seen = d->pMessageIdName;
    return VK_FALSE;
}

// 검증 레이어에 동기화 검증까지 켠 인스턴스. 메시지는 collect가 받는다
VkInstance make_checked_instance(VkDebugUtilsMessengerEXT* messenger) {
    const char* layer = "VK_LAYER_KHRONOS_validation";
    std::vector<const char*> extensions{VK_EXT_DEBUG_UTILS_EXTENSION_NAME,
                                        VK_EXT_VALIDATION_FEATURES_EXTENSION_NAME};
    VkInstanceCreateFlags flags = 0;
    const char* portability = VK_KHR_PORTABILITY_ENUMERATION_EXTENSION_NAME;
    if (vkx::has_instance_extension(portability)) {
        extensions.push_back(portability);
        flags |= VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR;
    }
    VkDebugUtilsMessengerCreateInfoEXT mci{
        .sType = VK_STRUCTURE_TYPE_DEBUG_UTILS_MESSENGER_CREATE_INFO_EXT,
        .messageSeverity = VK_DEBUG_UTILS_MESSAGE_SEVERITY_WARNING_BIT_EXT |
                           VK_DEBUG_UTILS_MESSAGE_SEVERITY_ERROR_BIT_EXT,
        .messageType = VK_DEBUG_UTILS_MESSAGE_TYPE_VALIDATION_BIT_EXT,
        .pfnUserCallback = collect};
    const VkValidationFeatureEnableEXT sync =
        VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT;
    VkValidationFeaturesEXT features{
        .sType = VK_STRUCTURE_TYPE_VALIDATION_FEATURES_EXT, .pNext = &mci,
        .enabledValidationFeatureCount = 1, .pEnabledValidationFeatures = &sync};
    VkApplicationInfo app{.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO,
                          .apiVersion = VK_API_VERSION_1_3};
    VkInstanceCreateInfo ci{.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO,
                            .pNext = &features, .flags = flags,
                            .pApplicationInfo = &app, .enabledLayerCount = 1,
                            .ppEnabledLayerNames = &layer,
                            .enabledExtensionCount = uint32_t(extensions.size()),
                            .ppEnabledExtensionNames = extensions.data()};
    VkInstance instance;
    vkx::check(vkCreateInstance(&ci, nullptr, &instance), "vkCreateInstance");
    auto create = reinterpret_cast<PFN_vkCreateDebugUtilsMessengerEXT>(
        vkGetInstanceProcAddr(instance, "vkCreateDebugUtilsMessengerEXT"));
    vkx::check(create(instance, &mci, nullptr, messenger), "메신저 만들기");
    return instance;
}

// 앞선 명령들의 (src 단계, 접근)이 끝나고 그 결과가 보인 뒤에야
// 뒤따르는 명령들의 (dst 단계, 접근)이 시작되게 한다
void barrier(VkCommandBuffer cmd, VkPipelineStageFlags2 src,
             VkAccessFlags2 src_access, VkPipelineStageFlags2 dst,
             VkAccessFlags2 dst_access) {
    VkMemoryBarrier2 b{.sType = VK_STRUCTURE_TYPE_MEMORY_BARRIER_2,
                       .srcStageMask = src, .srcAccessMask = src_access,
                       .dstStageMask = dst, .dstAccessMask = dst_access};
    VkDependencyInfo dep{.sType = VK_STRUCTURE_TYPE_DEPENDENCY_INFO,
                         .memoryBarrierCount = 1, .pMemoryBarriers = &b};
    vkCmdPipelineBarrier2(cmd, &dep);
}

int main() {
    if (!vkx::has_layer("VK_LAYER_KHRONOS_validation")) {
        std::puts("검증 레이어가 없어서 위험을 찾아낼 수 없습니다");
        return 0;
    }
    VkDebugUtilsMessengerEXT messenger;
    VkInstance instance = make_checked_instance(&messenger);
    vkx::Device dev = vkx::make_device(instance);
    vkx::Commands cmds = vkx::make_commands(dev);
    const auto USAGE =
        VK_BUFFER_USAGE_TRANSFER_SRC_BIT | VK_BUFFER_USAGE_TRANSFER_DST_BIT;
    vkx::Buffer src = vkx::make_buffer(dev, 64, USAGE, true);
    vkx::Buffer a = vkx::make_buffer(dev, 64, USAGE, false);
    vkx::Buffer b = vkx::make_buffer(dev, 64, USAGE, false);
    vkx::Buffer c = vkx::make_buffer(dev, 64, USAGE, false);
    std::memset(src.mapped, 7, 64);

    VkCommandBuffer cmd = cmds.cmd;   // 경우마다 처음부터 다시 기록한다
    auto copy = [&](const vkx::Buffer& from, const vkx::Buffer& to) {
        VkBufferCopy all{0, 0, 64};
        vkCmdCopyBuffer(cmd, from.handle, to.handle, 1, &all);
    };
    const auto COPY = VK_PIPELINE_STAGE_2_COPY_BIT;
    const auto WROTE = VK_ACCESS_2_TRANSFER_WRITE_BIT;
    const auto READS = VK_ACCESS_2_TRANSFER_READ_BIT;
    const auto ALL = VK_PIPELINE_STAGE_2_ALL_COMMANDS_BIT;
    const auto ANY = VK_ACCESS_2_MEMORY_READ_BIT | VK_ACCESS_2_MEMORY_WRITE_BIT;

    // 이벤트는 배리어를 알리는 자리와 기다리는 자리로 나눈다(내용은 같게)
    VkEventCreateInfo eci{.sType = VK_STRUCTURE_TYPE_EVENT_CREATE_INFO};
    VkEvent wrote_a;
    vkx::check(vkCreateEvent(dev.handle, &eci, nullptr, &wrote_a), "이벤트");
    VkMemoryBarrier2 wb{.sType = VK_STRUCTURE_TYPE_MEMORY_BARRIER_2,
                        .srcStageMask = COPY, .srcAccessMask = WROTE,
                        .dstStageMask = COPY, .dstAccessMask = READS};
    VkDependencyInfo split{.sType = VK_STRUCTURE_TYPE_DEPENDENCY_INFO,
                           .memoryBarrierCount = 1, .pMemoryBarriers = &wb};

    struct Case { const char* what; std::function<void()> record; };
    const Case cases[] = {
        {"a에 쓰고 곧바로 a를 읽음", [&] { copy(src, a); copy(a, b); }},
        {"쓰기와 읽기 사이에 배리어", [&] {
             copy(src, a);
             barrier(cmd, COPY, WROTE, COPY, READS);
             copy(a, b);
         }},
        {"배리어가 다른 쓰임을 가리킴", [&] {
             copy(src, a);
             barrier(cmd, COPY, WROTE, VK_PIPELINE_STAGE_2_COMPUTE_SHADER_BIT,
                     VK_ACCESS_2_SHADER_STORAGE_READ_BIT);
             copy(a, b);   // 복사는 컴퓨트 셰이더가 아니다
         }},
        {"단계만 적고 접근은 비운 배리어", [&] {
             copy(src, a);
             barrier(cmd, COPY, 0, COPY, 0);
             copy(a, b);
         }},
        {"무엇이든 기다리는 배리어", [&] {
             copy(src, a);
             barrier(cmd, ALL, ANY, ALL, ANY);
             copy(a, b);
         }},
        {"a에 두 번 씀", [&] { copy(src, a); copy(src, a); }},
        {"a를 읽고 곧바로 a에 씀", [&] { copy(a, b); copy(src, a); }},
        {"읽기와 쓰기 사이에 단계만 적은 배리어", [&] {
             copy(a, b);
             barrier(cmd, COPY, 0, COPY, 0);
             copy(src, a);
         }},
        {"a를 두 번 읽음", [&] { copy(a, b); copy(a, c); }},
        {"이벤트: 쓰고, 알리고, 딴 일을 하고, 기다린 뒤 읽음", [&] {
             copy(src, a);
             vkCmdSetEvent2(cmd, wrote_a, &split);
             copy(src, c);
             vkCmdWaitEvents2(cmd, 1, &wrote_a, &split);
             copy(a, b);
         }},
        {"이벤트: 알린 뒤에 쓴 것은 기다려 주지 않음", [&] {
             vkCmdSetEvent2(cmd, wrote_a, &split);
             copy(src, a);
             vkCmdWaitEvents2(cmd, 1, &wrote_a, &split);
             copy(a, b);
         }}};

    for (const Case& k : cases) {
        seen.clear();
        vkx::begin(cmds);
        k.record();
        vkx::submit_and_wait(dev, cmds);
        vkResetEvent(dev.handle, wrote_a);   // 다음 경우를 위해 되돌린다
        std::printf("%-30s %s\n", seen.empty() ? "-" : seen.c_str(), k.what);
    }

    vkDestroyEvent(dev.handle, wrote_a, nullptr);
    for (vkx::Buffer* buf : {&src, &a, &b, &c}) vkx::destroy(dev, *buf);
    vkx::destroy(dev, cmds);
    vkx::destroy(dev);
    auto destroy = reinterpret_cast<PFN_vkDestroyDebugUtilsMessengerEXT>(
        vkGetInstanceProcAddr(instance, "vkDestroyDebugUtilsMessengerEXT"));
    destroy(instance, messenger, nullptr);
    vkDestroyInstance(instance, nullptr);
}
```

```text
SYNC-HAZARD-READ-AFTER-WRITE   a에 쓰고 곧바로 a를 읽음
-                              쓰기와 읽기 사이에 배리어
SYNC-HAZARD-READ-AFTER-WRITE   배리어가 다른 쓰임을 가리킴
SYNC-HAZARD-READ-AFTER-WRITE   단계만 적고 접근은 비운 배리어
-                              무엇이든 기다리는 배리어
SYNC-HAZARD-WRITE-AFTER-WRITE  a에 두 번 씀
SYNC-HAZARD-WRITE-AFTER-READ   a를 읽고 곧바로 a에 씀
-                              읽기와 쓰기 사이에 단계만 적은 배리어
-                              a를 두 번 읽음
-                              이벤트: 쓰고, 알리고, 딴 일을 하고, 기다린 뒤 읽음
SYNC-HAZARD-READ-AFTER-WRITE   이벤트: 알린 뒤에 쓴 것은 기다려 주지 않음
```

- **세 가지 위험**: 배리어 없이 이어지는 쓴 뒤 읽기, 쓴 뒤 쓰기, 읽은 뒤 쓰기는 결과가 정해지지 않습니다. 읽기끼리는 겹쳐도 됩니다
- **단계와 접근**: 앞쪽(src)은 같은 큐에 먼저 낸 명령 가운데, 뒤쪽(dst)은 나중에 낼 명령 가운데 그 단계에서 그 접근을 하는 것을 가리킵니다. 복사는 COPY 단계의 일이라 뒤쪽을 컴퓨트 셰이더로 적은 배리어는 복사를 막지 못했습니다
- **접근 마스크**: 단계만 적으면 실행 순서만 걸립니다. 쓴 값을 뒤따르는 접근에 보이게 하는 것은 접근 마스크라서 쓰기 뒤에는 접근까지 적습니다. 읽은 뒤 쓰기는 순서만 지키면 되어 단계만으로 충분했습니다
- **큰 망치**: ALL_COMMANDS에 `MEMORY_READ | MEMORY_WRITE`는 무엇이든 기다리게 하지만 겹쳐 하던 일을 모두 세웁니다. 원인을 좁힐 때만 씁니다
- **이벤트**: `vkCmdSetEvent2`까지의 명령을 `vkCmdWaitEvents2` 뒤의 명령이 기다립니다. 사이의 명령(c에 쓰는 복사)은 묶이지 않고, 알린 뒤에 쓴 것은 기다리지 않습니다. 두 호출에 같은 `VkDependencyInfo`를 주며, 다른 큐가 알린 이벤트는 못 기다립니다

## 자주 쓰는 짝

| 앞선 일 → 뒤의 일 | 앞쪽 단계 / 접근 | 뒤쪽 단계 / 접근 |
| --- | --- | --- |
| 복사로 채움 → 정점 버퍼 | `COPY` / `TRANSFER_WRITE` | `VERTEX_INPUT` / `VERTEX_ATTRIBUTE_READ` |
| 컴퓨트가 씀 → 정점 버퍼 | `COMPUTE_SHADER` / `SHADER_STORAGE_WRITE` | `VERTEX_INPUT` / `VERTEX_ATTRIBUTE_READ` |
| 색 첨부물에 그림 → 샘플링 | `COLOR_ATTACHMENT_OUTPUT` / `COLOR_ATTACHMENT_WRITE` | `FRAGMENT_SHADER` / `SHADER_SAMPLED_READ` |
| 깊이에 그림 → 샘플링 | `EARLY_FRAGMENT_TESTS`와 `LATE_FRAGMENT_TESTS` / `DEPTH_STENCIL_ATTACHMENT_WRITE` | `FRAGMENT_SHADER` / `SHADER_SAMPLED_READ` |
| GPU가 씀 → CPU가 읽음 | 쓴 단계 / 쓴 접근 | `HOST` / `HOST_READ` |

이미지 배리어는 레이아웃도 바꿉니다([「레이아웃 전환」](#/read/cpp-vulkan/tex-layout)). 버퍼는 리소스를 짚지 않는 `VkMemoryBarrier2`로 충분하고, 한자리의 배리어는 `VkDependencyInfo` 하나에 모읍니다. 동적 렌더링 안에는 넣을 수 없어서(1.4의 `dynamicRenderingLocalRead` 같은 기능을 켠 때만 예외) 렌더링 앞뒤에 둡니다.

## 큐 패밀리 소유권 넘기기

배리어는 한 큐 안의 명령만 잇습니다. `VK_SHARING_MODE_EXCLUSIVE`로 만든 리소스의 내용을 다른 큐 패밀리에서 이어 쓰려면 소유권을 넘깁니다([「큐 패밀리」](#/read/cpp-vulkan/setup-queues)). 보내는 패밀리의 큐와 받는 패밀리의 큐에서 같은 `VkBufferMemoryBarrier2`나 이미지 배리어를 한 번씩 실행합니다. 두 배리어는 `srcQueueFamilyIndex`와 `dstQueueFamilyIndex`, 범위, 레이아웃이 같아야 하고 전환은 한 번만 일어납니다. 보내는 쪽은 뒤쪽 접근이, 받는 쪽은 앞쪽 접근이 무시되며, 두 제출의 순서는 세마포어로 잇습니다([「펜스와 세마포어」](#/read/cpp-vulkan/tri-sync)). 넘기지 않으면 읽은 내용이 정해지지 않으므로 내용이 필요 없을 때만 건너뜁니다. lavapipe는 패밀리가 하나라 실행해 보이지 못했습니다.

<Note>
동기화 검증이 조용하다고 배리어가 옳다는 보증은 아닙니다. 레이어의 문서도 셰이더의 디스크립터 접근은 정밀하지 않고 CPU 쪽 접근은 보지 않는다고 밝힙니다. 이 책의 레이어(1.3.275)는 컴퓨트 셰이더의 스토리지 버퍼 쓰기를 읽기로 보아, 그 버퍼를 배리어 없이 바로 복사해도 조용했습니다.
</Note>

## 정리

- 배리어는 앞선 (단계, 접근)이 끝난 뒤에 뒤따르는 (단계, 접근)이 시작되게 하고, 적은 쓰임이 실제와 맞아야 통한다
- 쓰기 뒤에는 접근 마스크까지, 읽은 뒤 쓰기에는 단계만 있으면 되고, 이벤트는 알리는 자리와 기다리는 자리를 나눈다
- 배리어는 한 큐 안에서만 통하고, 패밀리를 넘는 리소스는 배리어 짝과 세마포어로 소유권을 넘긴다
