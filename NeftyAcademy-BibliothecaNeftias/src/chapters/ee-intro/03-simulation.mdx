부품을 꽂기 전에 컴퓨터로 회로를 먼저 돌려 볼 수 있습니다. 그 표준이 1970년대 UC 버클리에서 나온 **SPICE**이고, 지금의 회로 시뮬레이터 대부분이 그 후손입니다. 이 쪽은 무료 오픈 소스인 **ngspice**로, [「옴의 법칙」](#/read/ee-intro/ohm)에서 손으로 푼 회로를 그대로 돌려 봅니다.

## 고를 수 있는 프로그램

| 프로그램 | 성격 |
| --- | --- |
| ngspice | 오픈 소스, 명령줄. KiCad 안에도 들어 있다 |
| LTspice | Analog Devices의 무료 프로그램. 회로도를 그려서 돌린다 |
| KiCad | 회로도·기판 설계 프로그램. 회로도에서 바로 ngspice를 부른다 |
| Falstad 회로 시뮬레이터 | 웹 브라우저에서 전류가 흐르는 모습을 움직이는 그림으로 |

회로도를 그리는 프로그램도 속에서는 **넷리스트**라는 글로 바꿔 SPICE에 넘깁니다. 넷리스트를 읽을 줄 알면 어느 프로그램이든 무슨 일이 일어나는지 알 수 있습니다.

## 넷리스트 읽는 법

```spice
* 9V에 1k와 2k를 직렬로
V1 in 0 DC 9
R1 in mid 1k
R2 mid 0 2k
.control
op
print v(in) v(mid) i(V1)
.endc
.end
```

- 첫 줄은 **제목**입니다. 회로로 읽지 않으니 비워 두지 말고 설명을 씁니다
- 소자 한 줄은 `이름 마디1 마디2 값`입니다. 이름의 첫 글자가 종류를 정합니다(V 전압원, R 저항, C 축전기, L 인덕터, D 다이오드, I 전류원)
- **마디**(node)는 이름 붙인 연결점이고, `0`은 반드시 있어야 하는 **땅**입니다. 같은 이름의 마디는 이어져 있다는 뜻이라, 선을 따로 그리지 않습니다
- 값에는 `k`(10³), `meg`(10⁶), `m`(10⁻³), `u`(10⁻⁶), `n`, `p` 같은 접두어를 씁니다. **`M`은 메가가 아니라 밀리**라는 것이 유명한 함정입니다. 메가는 `meg`입니다
- `.control`과 `.endc` 사이에 할 일을 적고, `.end`로 끝냅니다

```text
$ ngspice -b div.cir
v(in) = 9.000000e+00
v(mid) = 6.000000e+00
i(v1) = -3.00000e-03
```

`op`(동작점)는 모든 것이 자리 잡은 직류 상태를 구합니다. 가운데 마디가 6V, 전류 3mA로 손 계산과 같습니다. 전원 전류가 **음수**인 것은 SPICE가 전압원의 + 단자로 **들어가는** 방향을 양으로 세기 때문입니다. 전원은 전류를 + 단자에서 내보내니 음수로 나옵니다. 처음에 누구나 한 번씩 놀라는 부분입니다.

## 시간에 따라: 과도 해석

축전기를 저항으로 채우는 회로입니다. 전압을 0에서 5V로 한 번에 올리고, 시간이 지나며 축전기 전압이 어떻게 오르는지 봅니다.

```spice
* 1k 저항으로 1uF 축전기 채우기 (시간 상수 1ms)
V1 in 0 PULSE(0 5 0 1n 1n 10m 20m)
R1 in out 1k
C1 out 0 1u IC=0
.control
tran 0.1m 5m uic
meas tran v1ms find v(out) at=1m
meas tran v3ms find v(out) at=3m
meas tran v5ms find v(out) at=5m
meas tran t63 when v(out)=3.1606 rise=1
.endc
.end
```

```text
v1ms                =  3.161309e+00
v3ms                =  4.751575e+00
v5ms                =  4.966444e+00
t63                 =  9.996316e-04
```

- `tran 0.1m 5m`은 0.1ms 간격으로 5ms까지 계산하라는 뜻이고, `meas`로 원하는 순간의 값을 뽑았습니다
- 저항 × 정전 용량(1kΩ × 1µF = 1ms)을 **시간 상수** τ라고 합니다. τ만큼 지나면 최종값의 63.2%(5V의 3.16V)에 닿고, 3τ에 95%, 5τ에 99.3%입니다. 시뮬레이션의 1ms, 3ms, 5ms 값이 이 비율과 맞고, 3.16V를 지나는 순간도 0.9996ms로 거의 정확히 τ입니다
- 축전기와 인덕터는 다음 장 [「집중 소자 (lumped elements)」](#/read/ee-intro/lumped)에서 더 봅니다

## 쓸기: 다이오드의 휜 곡선

`dc`는 전원의 값을 차례로 바꾸며 동작점을 여러 번 구합니다(직류 쓸기).

```spice
* 다이오드에 거는 전압을 0.5V에서 0.8V까지 바꾸며
V1 a 0 DC 0
D1 a 0 DMOD
.model DMOD D(IS=1e-12 N=1 RS=0.5)
.control
dc V1 0.5 0.8 0.1
let id = -i(V1)
print id
.endc
.end
```

```text
Index   v-sweep         id
0       5.000000e-01    2.473766e-04
1       6.000000e-01    9.819365e-03
2       7.000000e-01    9.332439e-02
3       8.000000e-01    2.436359e-01
```

옴의 법칙 쪽의 이상적인 계산은 0.7V에서 576mA, 0.8V에서는 27A를 넘었는데, 시뮬레이션은 93mA, 244mA에서 멈춥니다. 모델에 넣은 **몸속 저항**(`RS=0.5`)이 큰 전류에서 전압을 빼앗기 때문입니다. 이처럼 시뮬레이션의 정확도는 **모델이 얼마나 실제와 닮았는지**에 달려 있습니다. 부품 제조사는 데이터시트와 함께 SPICE 모델 파일을 내놓는 경우가 많습니다.

<Note>
처음 출력 줄의 `print v(a) -i(V1)`은 의도와 달리 "v(a)에서 i(V1)을 뺀 값" 하나로 읽혔습니다. 식을 공백으로 나눠도 연산자로 이어 읽기 때문입니다. 그래서 `let id = -i(V1)`로 새 이름을 붙여 찍었습니다. 시뮬레이터의 출력이 손 계산과 다르면, 회로보다 먼저 **무엇을 찍었는지**를 의심해 봅니다.
</Note>

## 시뮬레이션을 믿는 법

- 결과가 나오면 먼저 **손으로 대충** 맞춰 봅니다. 자릿수가 다르면 값의 접두어(`M`과 `meg`!)나 마디 이름 오타일 가능성이 큽니다
- 시뮬레이션은 넣은 것만 압니다. 빵판의 이웃 줄 사이 정전 용량, 선의 저항, 전원의 한계는 따로 넣지 않으면 없는 것으로 칩니다
- 그래서 시뮬레이션은 실험을 **대신**하지 않고, 실험에서 무엇을 볼지 미리 알려 줍니다. 둘이 다르면 그 차이가 가장 많은 것을 가르쳐 줍니다

## 정리

- SPICE 넷리스트는 제목, `이름 마디 마디 값` 꼴의 소자 줄, 할 일, `.end`로 되어 있고, 마디 `0`이 땅이며 `M`은 밀리, `meg`가 메가다
- `op`는 직류 동작점, `tran`은 시간에 따른 변화, `dc`는 전원을 바꿔 가며 쓸기이고, 전압원 전류는 들어가는 방향이 양이라 음수로 나온다
- 시뮬레이션 결과는 손 계산으로 자릿수를 맞춰 보고, 모델에 넣지 않은 것은 모른다는 것을 기억하며 실험과 견준다
