커널은 에지가 날 때마다 이벤트를 만들어 쌓아 두고, 프로그램은 제 형편이 될 때 가져갑니다. 그 사이를 잇는 것이 버퍼입니다. 프로그램이 제때 가져가면 버퍼를 의식할 일이 없습니다. 문제는 가져가는 것보다 쌓이는 것이 빠를 때입니다.

## 커널의 버퍼와 buffer 객체

| | 커널의 버퍼 | buffer 객체 |
| --- | --- | --- |
| 있는 곳 | 커널 안, 요청마다 하나 | 내 프로그램의 메모리 |
| 채우는 쪽 | 에지가 날 때 커널이 | 읽는 함수가 커널의 것을 옮겨서 |
| 기본 크기 | 줄 수의 16배 | 64개 |
| 가장 큰 크기 | 1024개 | 1024개 |

- **`gpiod_request_config_set_event_buffer_size`**: 소비자 이름을 적던 request_config에, 커널의 버퍼에 담을 이벤트의 수를 청해 둡니다. 0은 기본값을 쓰라는 뜻입니다. 청한 대로 된다는 보장은 없어서, 커널은 더 넉넉히 잡을 수도 있고 큰 값은 자릅니다([「소비자 이름」](#/read/libgpiod/rq-consumer))
- **요청할 때 정해진다**: 커널의 버퍼는 요청과 함께 크기가 굳습니다. 도중에 키울 수 없습니다
- **`gpiod_edge_event_buffer_new`**: 한 번에 읽어 올 개수만큼의 자리를 프로그램 쪽에 만듭니다. 0을 주면 64개, 1024보다 큰 수를 주면 1024개가 됩니다
- **buffer 객체를 크게 잡아도 이벤트가 더 남지는 않는다**: 이것은 옮겨 담는 그릇일 뿐입니다. 읽으러 가기 전에 버려진 것은 그릇이 커도 돌아오지 않습니다
- **줄이 여럿이어도 버퍼는 하나다**: 한 요청에 든 줄들의 이벤트는 일어난 차례대로 한 버퍼에 섞여 들어갑니다

## 넘치면 오래된 것부터 버려진다

아래 예제는 줄 하나의 에지를 지켜보다가 1초 동안 딴 일을 합니다. 그 사이에 펄스 40개, 곧 에지 80개가 몰려옵니다.

```c gpiosim=burst
// 딴 일을 하는 1초 사이에 에지 80개가 온다. 뒤늦게 읽어서 남은 것을 센다
#include <gpiod.h>
#include <stdio.h>
#include <stdlib.h>
#include <threads.h>

enum {
    PULSES = 23,                             // GPIO 23, 헤더의 핀 16
    ROOM = 64,                               // 한 번에 읽어 올 이벤트의 수
};

// 두 방향의 에지를 보는 입력으로 요청한다. kernel_room이 0이면 커널의 기본 크기
static struct gpiod_line_request* request_edges(struct gpiod_chip* chip,
                                                unsigned int offset,
                                                size_t kernel_room) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    struct gpiod_line_request* request = nullptr;
    if (settings && config && request_config) {
        gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_INPUT);
        gpiod_line_settings_set_edge_detection(settings, GPIOD_LINE_EDGE_BOTH);
        gpiod_line_config_add_line_settings(config, &offset, 1, settings);
        gpiod_request_config_set_consumer(request_config, "counter");
        gpiod_request_config_set_event_buffer_size(request_config, kernel_room);
        request = gpiod_chip_request_lines(chip, request_config, config);
    }
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(int argc, char** argv) {
    size_t kernel_room = argc > 1 ? strtoul(argv[1], nullptr, 10) : 0;
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_line_request* pulses = request_edges(chip, PULSES, kernel_room);
    gpiod_chip_close(chip);
    struct gpiod_edge_event_buffer* buffer = gpiod_edge_event_buffer_new(ROOM);
    if (!pulses || !buffer) {
        perror("요청");
        return 1;
    }
    thrd_sleep(&(struct timespec){.tv_sec = 1}, nullptr);  // 딴 일을 하는 1초

    unsigned long expected = 1;              // 다음에 와야 할 번호
    unsigned long lost = 0;
    while (gpiod_line_request_wait_edge_events(pulses, 0) == 1) {
        int count = gpiod_line_request_read_edge_events(pulses, buffer, ROOM);
        if (count < 0) {
            perror("읽기");
            break;
        }
        unsigned long first = 0;
        unsigned long last = 0;
        for (int i = 0; i < count; ++i) {
            struct gpiod_edge_event* event =
                gpiod_edge_event_buffer_get_event(buffer, (unsigned long)i);
            unsigned long number = gpiod_edge_event_get_line_seqno(event);
            if (i == 0) first = number;
            last = number;
            lost += number - expected;       // 건너뛴 번호만큼 잃었다
            expected = number + 1;
        }
        printf("%2d개를 읽었다. 번호 %lu부터 %lu까지\n", count, first, last);
    }
    printf("일어난 에지 %lu개, 잃은 것 %lu개\n", expected - 1, lost);
    gpiod_edge_event_buffer_free(buffer);
    gpiod_line_request_release(pulses);
}
```

```text
16개를 읽었다. 번호 65부터 80까지
일어난 에지 80개, 잃은 것 64개
```

- **80개가 났는데 16개만 남았다**: 줄 하나의 기본 크기는 16입니다. 1초 뒤에 읽으러 갔을 때 버퍼에는 가장 나중의 16개만 있었습니다
- **새것이 들어오고 오래된 것이 나간다**: 버퍼가 찼을 때 커널은 가장 오래된 이벤트를 버리고 새 이벤트를 넣습니다
- **오류는 없다**: 읽는 함수는 남은 것을 멀쩡히 돌려줍니다. 버려졌다는 사실을 알려 주는 것은 이벤트에 적힌 번호뿐입니다

같은 프로그램에 `128`을 주어 커널의 버퍼를 128개로 청하면 하나도 잃지 않습니다. buffer 객체가 64개짜리라서 두 번에 나눠 읽었습니다.

```text
64개를 읽었다. 번호 1부터 64까지
16개를 읽었다. 번호 65부터 80까지
일어난 에지 80개, 잃은 것 0개
```

## 번호로 잃은 것 알아채기

- **이벤트마다 번호가 둘 붙는다**: `gpiod_edge_event_get_line_seqno`는 그 줄에서 몇 번째 이벤트인지, `gpiod_edge_event_get_global_seqno`는 요청 전체에서 몇 번째인지를 줍니다. 둘 다 1부터 셉니다
- **번호는 에지가 날 때 붙는다**: 버려진 이벤트의 번호는 다시 쓰이지 않습니다. 그래서 받은 번호가 건너뛰었으면 그 사이의 것을 잃은 것입니다. 예제는 1번을 기다리다 65번을 받고 64개를 잃었다고 셈했습니다
- **세기만 한다면 번호가 곧 개수다**: 마지막 이벤트의 줄 번호가, 요청한 뒤로 커널이 그 줄에서 알아챈 에지의 수입니다. 예제의 마지막 줄은 이벤트를 16개만 받고도 80을 적었습니다
- **잃었으면 상태를 다시 맞춘다**: 눌림과 뗌을 따라가던 프로그램은 번호가 건너뛴 것을 본 순간 지금의 값을 한 번 읽어서 제 상태를 고칩니다([「값 읽기」](#/read/libgpiod/in-read))
- **번호는 32비트다**: 커널이 번호를 담는 자리가 32비트라, 43억 개쯤에서 0으로 돌아갑니다. 오래 도는 프로그램은 번호의 차이를 32비트 정수로 셈합니다

## 크기 고르기

- **읽지 못하는 가장 긴 시간으로 정한다**: 프로그램이 다른 일에 묶여 있을 수 있는 시간에 그동안 날 수 있는 에지의 수를 곱해, 그보다 넉넉히 청합니다
- **1024로도 모자라면 방법을 바꾼다**: 그만큼 몰려오는 신호는 에지 이벤트로 받을 것이 아닙니다([「커널 드라이버에 맡길 것들」](#/read/libgpiod/tm-kernel))
- **시끄러운 줄은 요청을 따로 한다**: 버퍼를 함께 쓰므로, 줄 하나가 버퍼를 채우면 같은 요청의 조용한 줄에서 난 이벤트도 밀려납니다
- **자주 읽는 것이 먼저다**: 큰 버퍼는 읽기가 잠깐 밀릴 때를 넘기게 해 줄 뿐입니다. 읽는 것보다 내내 빨리 오는 신호는 어떤 크기로도 넘칩니다

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, 펄스는 대본으로 넣었습니다. 흉내 칩의 버퍼는 리눅스 커널의 문서와 소스에 적힌 대로, 줄 수의 16배를 기본으로 잡고 차면 가장 오래된 것을 버리게 만든 것입니다. 진짜 커널이 청한 수를 실제로 얼마로 잡았는지는 프로그램에서 알아볼 방법이 없습니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했고, 보드에서 버퍼를 넘치게 해 보지는 못했습니다.
</Note>

## 정리

- 커널의 버퍼는 요청마다 하나이고 기본 크기는 줄 수의 16배다. 요청할 때 더 크게 청할 수 있다
- 버퍼가 차면 오래된 이벤트부터 버려지고, 읽는 쪽에는 오류가 나지 않는다
- 잃었는지는 이벤트의 번호가 건너뛰었는지로 안다. 에지의 수만 필요하면 마지막 번호를 본다
