libgpiod의 파이썬 바인딩은 `gpiod`라는 모듈입니다. C 라이브러리를 부르는 확장 모듈 위에 파이썬 클래스를 얹은 것이어서, 커널에 닿는 길은 C로 쓴 프로그램과 같습니다. 코드는 훨씬 짧아집니다. 칩을 열고 요청하고 닫는 일이 함수 하나이고, 설정은 사전이며, 줄은 `with` 블록이 놓아 줍니다.

## C와 짝지어 보기

| C | 파이썬 | 달라지는 것 |
| --- | --- | --- |
| 칩 열기, 요청, 칩 닫기 | `gpiod.request_lines()` | 호출 하나가 셋을 한다 |
| 설정 객체 셋 | `LineSettings`를 담은 사전 | 줄을 열쇠로, 설정을 값으로 적는다 |
| `gpiod_line_request_release` | `with` 블록 | 블록을 벗어나면 놓는다 |
| -1과 `errno` | 예외 | `OSError`와 그 갈래 |
| `GPIOD_LINE_VALUE_ACTIVE` | `Value.ACTIVE` | `gpiod.line`의 열거형이다 |
| 오프셋 | 오프셋이나 줄 이름 | `"GPIO17"`로도 쥔다 |
| 나노초, 마이크로초의 정수 | 초를 적은 수나 `timedelta` | 단위를 틀리기 어렵다 |

- **메서드의 이름은 그대로다**: `set_value`, `get_values`, `wait_edge_events`, `read_edge_events`, `reconfigure_lines`입니다. C의 이름에서 앞머리만 뗀 것입니다
- **줄을 이름으로 가리킨다**: 사전의 열쇠와 `set_value`의 첫 인수에 오프셋 대신 줄 이름을 줄 수 있습니다. 이름은 보드마다 다르다는 것을 잊지 않습니다([「줄 이름으로 찾기」](#/read/libgpiod/ch-names))
- **적지 않은 설정은 기본값이다**: `LineSettings()`는 방향을 건드리지 않고 에지 감지를 끈 설정입니다. 바꿀 것만 이름을 붙여 적습니다
- **칩 객체도 있다**: 줄 정보를 읽거나 지켜볼 때에는 `with gpiod.Chip(...) as chip:`으로 칩을 직접 엽니다

## 누르는 동안 켜는 예제

```python
# 단추를 누르는 동안 LED를 켠다. libgpiod의 파이썬 바인딩으로 쓴 것
from datetime import timedelta

import gpiod
from gpiod.line import Bias, Direction, Edge, Value

LED = 17       # GPIO 17, 핀 11
BUTTON = 27    # GPIO 27, 핀 13

# 줄마다의 설정을 사전으로 적는다. 단추는 풀업을 켠 액티브 로 입력이다
config = {
    LED: gpiod.LineSettings(direction=Direction.OUTPUT),
    BUTTON: gpiod.LineSettings(
        direction=Direction.INPUT,
        bias=Bias.PULL_UP,
        active_low=True,
        edge_detection=Edge.BOTH,
        debounce_period=timedelta(milliseconds=10),
    ),
}

try:
    with gpiod.request_lines(
        "/dev/gpiochip0", consumer="press-light", config=config
    ) as request:
        try:
            while True:
                request.wait_edge_events()       # 인수가 없으면 끝없이 기다린다
                for event in request.read_edge_events():
                    pressed = event.event_type is event.Type.RISING_EDGE
                    value = Value.ACTIVE if pressed else Value.INACTIVE
                    request.set_value(LED, value)
                    print("눌림" if pressed else "뗌", "줄 번호", event.line_seqno)
        finally:
            request.set_value(LED, Value.INACTIVE)   # 끄고 나서 놓는다
except KeyboardInterrupt:
    pass                 # Ctrl+C로 끝냈다. with 블록을 벗어나며 줄은 놓였다
except OSError as error:
    print(error)         # 줄이 쓰이고 있다, 권한이 없다 같은 실패
```

- **요청은 호출 하나다**: `gpiod.request_lines`가 칩을 열고, 사전에 적힌 대로 줄을 요청하고, 칩을 닫은 뒤 요청을 돌려줍니다
- **`with`가 놓는다**: 블록을 벗어나면 줄이 놓입니다. 예외로 벗어날 때에도 그렇습니다. 그 전에 LED를 끄려고 `finally`를 두었습니다([「놓아주기」](#/read/libgpiod/rq-release))
- **이벤트는 리스트로 온다**: `read_edge_events()`가 돌려주는 것은 이벤트 객체의 리스트입니다. 버퍼를 따로 만들지 않고, 받은 객체는 다음 읽기 뒤에도 그대로 있습니다
- **기다리는 시간**: `wait_edge_events()`에 아무것도 주지 않으면 끝없이 기다립니다. `0.5`나 `timedelta(milliseconds=500)`을 주면 그 시간까지 기다리고, 시간이 다 되면 `False`를 돌려줍니다
- **Ctrl+C는 `KeyboardInterrupt`다**: 신호 처리기를 달지 않아도 됩니다. 파이썬이 기다리는 도중의 신호를 예외로 바꿔 줍니다([「기다리고 읽기」](#/read/libgpiod/ed-wait))

## 예외로 오는 오류

| 일어난 일 | 일어나는 예외 |
| --- | --- |
| 줄이 쓰이고 있다(`EBUSY`), 그 밖의 `errno` | `OSError` |
| 권한이 없다 | `PermissionError` |
| 그런 칩이 없다 | `FileNotFoundError` |
| 인수가 틀렸다(`EINVAL`) | `ValueError` |
| 닫은 칩을 썼다 | `gpiod.ChipClosedError` |
| 놓은 요청을 썼다 | `gpiod.RequestReleasedError` |

- **`OSError` 하나로 잡힌다**: `PermissionError`와 `FileNotFoundError`는 `OSError`의 갈래입니다. `error.errno`에 번호가 있어서 `errno.EBUSY`와 견줄 수 있습니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))
- **모르는 줄 이름**: 요청에 없는 이름으로 값을 쓰면 `ValueError`입니다

## apt와 pip의 두 꾸러미

```sh
sudo apt install python3-libgpiod              # 배포판의 것
python3 -m venv env                            # 또는 가상 환경을 만들고
env/bin/pip install 'gpiod>=2.0.2'             # PyPI의 것을 그 안에 깐다
env/bin/python -c 'import gpiod; print(gpiod.__version__, gpiod.api_version)'
```

- **배포판의 것은 판을 본다**: 데비안 13의 `python3-libgpiod`는 2.2이고 12의 것은 1.6입니다. 1.6의 파이썬 바인딩은 생김새가 전혀 달라서 이 쪽의 코드가 돌지 않습니다([「libgpiod 2.x 설치와 버전 확인」](#/read/libgpiod/st-install))
- **PyPI의 `gpiod`는 제 libgpiod를 품고 있다**: 시스템에 깔린 판과 상관없이 2의 바인딩을 얻습니다. 설치할 때 C 확장을 빌드하므로 `python3-dev`가 있어야 한다고 README가 적습니다
- **2.0.2부터가 공식이다**: 그 앞의 `gpiod`(1.5.4까지)는 다른 사람이 만든 다른 꾸러미였습니다. 그래서 판을 적어서 깝니다
- **pip는 가상 환경에서**: Raspberry Pi OS는 북웜부터 시스템의 파이썬에 pip로 까는 것을 막습니다
- **두 숫자**: `__version__`은 바인딩의 판이고 `api_version`은 그 밑의 C 라이브러리의 판입니다

## 파이썬의 한계

- **늦게 깨는 정도는 C와 같았다**: 1ms마다 깨는 반복문을 파이썬 3.13으로 짜서 이 책을 쓴 컴퓨터에서 돌리니, 늦음의 가운데 값이 0.1ms로 C와 같았습니다. 늦음을 정하는 것은 언어가 아니라 커널입니다([「사용자 공간에서 얼마나 정확한가」](#/read/libgpiod/tm-jitter))
- **호출 하나는 더 든다**: 가벼운 `ioctl` 하나가 C에서 0.2µs쯤, 파이썬에서 0.3µs쯤이었습니다. 바인딩의 메서드에는 파이썬 쪽의 일이 더 붙지만, 그것은 재지 못했습니다
- **그래서 할 수 있는 일도 같다**: LED, 단추, 릴레이처럼 느린 일에는 충분합니다. 박자가 빠듯한 일은 어느 언어로 써도 사용자 공간에서는 지켜지지 않습니다
- **더 짧게 쓰는 길**: 파이썬에는 핀 하나를 한 줄로 다루는 라이브러리들이 따로 있습니다([「gpiozero, lgpio, pigpio와 견주기」](#/read/libgpiod/bn-others))

<Note>
이 쪽의 예제는 돌려 보지 못했습니다. 바인딩의 C 확장을 빌드하지 않았고, 이 책의 흉내 칩은 C의 함수만 흉내 내기 때문입니다. 파이썬 3.13으로 문법만 검사했고 출력은 싣지 않았습니다. 함수와 인수의 이름, 예외의 종류, 기다리는 시간의 뜻은 libgpiod 2.2.4에 든 바인딩(2.2.0)의 파이썬 소스와 C 소스를 읽어 적었습니다. 꾸러미에 관한 것은 그 바인딩의 README와 데비안의 꾸러미 목록, 라즈베리파이의 글에서 옮겼습니다. 늦음과 호출의 시간은 CPU가 둘인 x86-64 가상 머신에서 잰 것이고, GPIO는 건드리지 않았습니다.
</Note>

## 정리

- 파이썬 바인딩은 `gpiod` 모듈이다. `gpiod.request_lines`에 줄과 `LineSettings`의 사전을 주고 `with`로 쥔다
- 실패는 `OSError`와 그 갈래로 오고, Ctrl+C는 `KeyboardInterrupt`로 온다
- 배포판의 `python3-libgpiod`는 판을 확인하고, PyPI의 `gpiod`는 2.0.2 이상을 가상 환경에 깐다
