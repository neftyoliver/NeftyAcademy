라즈베리파이의 GPIO를 다루는 라이브러리는 libgpiod만이 아닙니다. 옛 글과 예제에는 RPi.GPIO와 pigpio가 가장 많이 나오고, 요즘의 파이썬 글에는 gpiozero가 나옵니다. 어느 것이 무엇 위에 서 있는지를 알면 남의 코드를 읽을 때도, 내 것을 고를 때도 헷갈리지 않습니다.

## 같은 일을 gpiozero와 lgpio로

앞의 두 쪽에서 쓴, 단추를 누르는 동안 LED를 켜는 일입니다. 먼저 gpiozero입니다.

```python
# gpiozero: 단추를 누르는 동안 LED를 켠다
from signal import pause

from gpiozero import LED, Button

led = LED(17)
button = Button(27)              # 풀업을 켠다. 단추는 핀과 GND 사이에 단다

button.when_pressed = led.on
button.when_released = led.off

pause()                          # 스크립트가 끝나지 않게 붙잡아 둔다
```

같은 일을 lgpio의 파이썬 모듈로 쓰면 이렇습니다.

```python
# lgpio: 단추를 누르는 동안 LED를 켠다
import time

import lgpio

LED = 17
BUTTON = 27

handle = lgpio.gpiochip_open(0)                  # /dev/gpiochip0
lgpio.gpio_claim_output(handle, LED)
lgpio.gpio_claim_alert(handle, BUTTON, lgpio.BOTH_EDGES, lgpio.SET_PULL_UP)
lgpio.gpio_set_debounce_micros(handle, BUTTON, 10_000)


def on_edge(chip, gpio, level, timestamp):
    if level in (0, 1):                          # 2는 에지가 아니라 감시 시간 알림
        lgpio.gpio_write(handle, LED, 1 if level == 0 else 0)   # 누르면 LOW


callback = lgpio.callback(handle, BUTTON, lgpio.BOTH_EDGES, on_edge)
try:
    while True:
        time.sleep(1)
except KeyboardInterrupt:
    pass
finally:
    callback.cancel()
    lgpio.gpio_write(handle, LED, 0)
    lgpio.gpiochip_close(handle)
```

- **gpiozero는 부품을 다룬다**: 줄이 아니라 `LED`와 `Button` 같은 부품의 객체를 만들고, 일어날 일에 함수를 답니다. 풀업과 에지, 기다리는 일은 라이브러리가 맡습니다
- **번호는 GPIO 번호다**: 헤더의 핀 번호로 적으려면 `LED("BOARD11")`처럼 씁니다([「핀 번호: 헤더, BCM, 줄 오프셋」](#/read/libgpiod/gp-numbering))
- **gpiozero는 혼자서 핀을 만지지 않는다**: 핀 팩토리라는 밑단을 골라 씁니다. 정해 주지 않으면 lgpio, RPi.GPIO, pigpio, 순수 파이썬 구현의 차례로 되는 것을 찾습니다. `GPIOZERO_PIN_FACTORY` 환경 변수로 고를 수 있고, 5에서 되는 것은 lgpio뿐이라고 문서가 적습니다
- **lgpio는 libgpiod와 같은 층이다**: 같은 문자 장치를 쓰는 C 라이브러리와 그 파이썬 모듈입니다. 줄을 차지하고, 쓰고, 읽고, 에지는 콜백으로 받습니다. 콜백이 받는 `level`은 0이 내려감, 1이 올라감입니다
- **두 예제 모두 돌려 보지 못했다**: 문법만 검사했습니다

## 견주는 표

| 라이브러리 | 언어 | 밑바닥 | 5에서 |
| --- | --- | --- | --- |
| libgpiod | C, C++, 파이썬 | 문자 장치 | 된다 |
| lgpio | C, 파이썬 | 문자 장치 | 된다 |
| gpiozero | 파이썬 | 고른 핀 팩토리 | lgpio로 된다 |
| rpi-lgpio | 파이썬 | lgpio | 된다고 한다 |
| RPi.GPIO | 파이썬 | 레지스터를 직접 | 안 된다 |
| pigpio | C, 파이썬 | DMA와 레지스터 | 안 된다 |

- **옛 코드의 `import RPi.GPIO`**: 5에서는 돌지 않습니다. rpi-lgpio는 같은 이름의 모듈을 lgpio 위에 다시 만든 것이어서, 이것을 깔면 옛 코드가 그대로 돕니다. 그 문서는 똑같이 움직이지 않는 곳이 있다고 적어 둡니다
- **pigpio**: 라즈베리파이의 GPIO 백서는 5에서 아직 되지 않는다고 하고, 새 프로젝트에 권하지 않습니다([「/dev/mem으로 레지스터를 만지던 라이브러리들」](#/read/libgpiod/hs-devmem))
- **WiringPi**: 만든 이가 손을 뗀 뒤 Grazer Computer Club이 이어받았고, 백서는 5에서도 된다고 적습니다
- **백서의 권고**: C와 C++에는 libgpiod, 파이썬에는 lgpio를 밑단으로 한 gpiozero, 셸에서는 libgpiod의 도구입니다

## 박자를 맞추는 방법

- **libgpiod와 lgpio는 프로그램이 박자를 쥔다**: 둘 다 문자 장치에 값을 쓰는 것이어서 앞 장에서 잰 한계가 그대로입니다. lgpio에는 PWM과 서보 펄스를 내는 `tx_pwm`과 `tx_servo`가 있지만 소프트웨어로 박자를 맞춥니다. 그 문서는 서보 펄스를 시험할 때에만 쓰라고 하고, 떨림 때문에 서보가 꿈틀거려 열이 나고 일찍 닳을 수 있다고 적습니다([「소프트웨어 PWM의 한계」](#/read/libgpiod/tm-softpwm))
- **pigpio는 박자를 하드웨어에 맡겼다**: DMA와 칩의 PWM, PCM 장치를 써서 GPIO 0부터 31까지의 어느 핀에나 박자가 고른 PWM과 서보 펄스를 냈고, 5µs마다 핀을 읽어 시각을 붙였습니다. 프로그램이 늦게 깨어도 파형이 흔들리지 않은 까닭입니다
- **그 방법이 5에서 막혔다**: 백서는 pigpio가 브로드컴의 SoC에 맞춰 짠 것이라고 적습니다. 5에서는 헤더의 핀을 RP1이 맡습니다([「라즈베리파이 5에서 깨진 것들」](#/read/libgpiod/hs-pi5))
- **지금 그 자리를 채우는 것**: 커널의 PWM과 드라이버, 5의 PIO입니다([「커널 드라이버에 맡길 것들」](#/read/libgpiod/tm-kernel))
- **gpiozero의 PWM은 밑단을 따른다**: 문서는 pigpio 팩토리가 DMA로 박자를 맞춘 PWM을 내고, 순수 파이썬 구현에는 PWM이 없다고 적습니다

## libgpiod에 딸린 것들

- **바인딩이 넷이다**: C++, 파이썬 말고도 GLib과 Rust의 바인딩이 같은 저장소에 있습니다
- **D-Bus로 부리는 데몬**: `gpio-manager`라는 데몬이 줄을 대신 쥐고, `gpiocli`라는 명령이 그 데몬에게 일을 시킵니다. 데몬이 쥐고 있으므로 명령이 끝나도 줄의 상태가 남습니다. 데비안 13의 꾸러미 목록에서는 이것을 찾지 못했습니다
- **명령줄 도구**: `gpioset`, `gpioget`, `gpiomon` 같은 것들입니다([「gpioset과 gpioget」](#/read/libgpiod/tl-set-get))

## 고르는 기준

- **C나 C++로 짠다면**: libgpiod입니다. 이 책이 다룬 것입니다
- **파이썬으로 부품을 빨리 붙여 본다면**: gpiozero입니다. 줄의 설정까지 손대야 하면 libgpiod의 파이썬 바인딩이나 lgpio로 내려갑니다([「파이썬 바인딩」](#/read/libgpiod/bn-python))
- **옛 RPi.GPIO 코드를 살려야 한다면**: rpi-lgpio로 돌리고, 새로 쓰는 코드는 다른 것으로 씁니다
- **박자가 빠듯하다면**: 라이브러리를 고르는 문제가 아닙니다. 커널의 PWM과 드라이버를 씁니다
- **한 줄은 한 주인**: 문자 장치를 쓰는 라이브러리끼리는 같은 줄을 함께 쥘 수 없습니다. 한 프로그램 안에서 둘을 섞을 때에는 줄을 나눕니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))

<Note>
이 쪽의 어느 라이브러리도 깔거나 돌려 보지 못했습니다. 두 예제는 파이썬 3.13으로 문법만 검사했습니다. gpiozero의 것은 2.0.1의 문서에서, lgpio의 것은 그 라이브러리의 C와 파이썬 문서에서, pigpio의 것은 그 누리집에서, rpi-lgpio의 것은 그 문서와 PyPI에서 옮겼습니다. 5에서 되는지와 권고는 라즈베리파이의 GPIO 백서(2025년 8월 판)에 적힌 대로입니다. 그 뒤에 달라졌을 수 있으니 쓰기 전에 각 문서를 봅니다. libgpiod의 바인딩과 데몬은 2.2.4의 문서를 읽어 적었습니다.
</Note>

## 정리

- libgpiod와 lgpio는 문자 장치를 직접 쓰는 같은 층이고, gpiozero는 그 위에서 부품을 다루는 파이썬 라이브러리다
- RPi.GPIO와 pigpio는 레지스터를 직접 만지던 것이라 5에서 돌지 않는다. 옛 코드는 rpi-lgpio로 돌린다
- 박자가 고른 PWM은 pigpio가 하드웨어에 맡겨 내던 것이다. 지금은 커널의 PWM과 드라이버가 그 일을 한다
