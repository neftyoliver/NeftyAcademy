앞의 세 쪽은 프로그램이 지킬 수 있는 박자의 한계를 쟀습니다. 그 한계 밖의 일은 커널의 드라이버가 합니다. 라즈베리파이에서는 `config.txt`에 `dtoverlay=` 한 줄을 적어 드라이버를 핀에 붙이고([「dtoverlay로 기능 켜기」](#/read/sbc-start/cfg-overlays)), 프로그램은 드라이버가 내주는 파일이나 장치를 읽습니다.

## 커널 안이 다른 점

- **인터럽트를 받은 자리에서 일한다**: 드라이버는 핀이 바뀌었다는 인터럽트를 받는 그 자리에서 시각을 적고 할 일을 합니다. 프로그램이 깨어나 CPU를 얻기를 기다리지 않습니다
- **마이크로초를 제자리에서 기다린다**: 커널에는 `udelay`처럼 정한 마이크로초만큼 제자리에서 도는 함수가 있고, 다른 일이 끼어들지 못하게 막아 둔 구간에서도 쓸 수 있습니다. 핀을 흔들어 I2C를 만드는 `i2c-gpio`는 기다리는 시간의 기본값이 2µs이고, 그것으로 100kHz쯤의 클럭을 냅니다
- **전용 회로를 부린다**: PWM, SPI, I2C, UART의 박자는 칩 안의 회로가 만듭니다. 드라이버는 그 회로에 값을 적어 넣습니다
- **결과는 파일이나 장치로 나온다**: 프로그램은 온도가 적힌 파일을 읽거나 키 이벤트를 받습니다. 어떤 언어로도 읽을 수 있습니다
- **커널도 다 지키지는 못한다**: `dht11` 드라이버의 소스에는 받은 신호를 풀지 못했을 때 오류를 돌려주는 길이 있습니다. 드라이버에 맡긴 값도 읽기가 실패할 수 있고, 프로그램은 그때 다시 읽습니다

## 오버레이로 붙는 드라이버

| 하려는 일 | 오버레이 | 프로그램이 보는 것 |
| --- | --- | --- |
| 1-Wire 온도 센서 | `w1-gpio` | `/sys/bus/w1/devices` 아래의 온도 파일 |
| DHT11, DHT22 | `dht11` | IIO 장치의 `in_temp_input` 같은 파일 |
| 적외선 리모컨 받기 | `gpio-ir` | 키 입력 이벤트 |
| 로터리 엔코더 | `rotary-encoder` | 입력 장치의 축 |
| 단추를 키로 | `gpio-key` | 키 입력 이벤트 |
| 상태를 알리는 LED | `gpio-led` | `/sys/class/leds` 아래의 파일 |
| 온도에 따라 도는 팬 | `gpio-fan` | 손댈 것이 없다 |
| I2C 버스 하나 더 | `i2c-gpio` | `/dev/i2c-N` |
| PWM | `pwm-2chan` | `/sys/class/pwm` |
| 색이 바뀌는 LED 띠 | `ws2812-pio` | `/dev/leds0` |

- **핀은 인수로 고른다**: `dtoverlay=w1-gpio,gpiopin=17`처럼 적습니다. 적지 않았을 때의 핀은 오버레이마다 달라서, 1-Wire와 DHT는 GPIO 4이고 적외선 받기는 18입니다
- **LED와 단추도 맡길 수 있다**: `gpio-led`에 `trigger=heartbeat`를 주면 커널이 그 LED를 깜빡입니다. 프로그램을 띄워 둘 필요가 없습니다. `gpio-key`는 단추를 키보드의 키처럼 만들어 줍니다
- **5에만 있는 것**: `ws2812-pio`와 `pwm-pio`는 RP1의 PIO를 씁니다([「라즈베리파이 5의 RP1」](#/read/sbc-start/hdr-rp1))
- **없는 것도 있다**: 초음파 거리 센서와 키패드의 오버레이는 README에서 찾지 못했습니다

## 온도는 커널이 읽는 예제

1-Wire 온도 센서 DS18B20을 `w1-gpio`에 맡기면 드라이버가 센서마다 `temperature`라는 파일을 내줍니다. 읽으면 1000분의 1도 단위의 정수가 나옵니다. 아래 예제는 그 숫자를 표준 입력으로 받아 히터의 릴레이를 켜고 끕니다. 박자가 빠듯한 일은 커널이, 느린 일은 libgpiod가 맡았습니다.

```c gpiosim=quiet stdin='21500 20400 19800 20900 22100 21000'
// 온도는 커널의 1-Wire 드라이버가 읽고, 이 프로그램은 그 숫자로 릴레이만 몬다
//   while sleep 1; do cat /sys/bus/w1/devices/28-*/temperature; done | ./thermo
#include <gpiod.h>
#include <stdio.h>

enum { RELAY = 23 };                         // GPIO 23, 핀 16
// 1000분의 1도로 적은 문턱: 20도 아래에서 켜고 22도 위에서 끈다
enum { ON_BELOW = 20'000, OFF_ABOVE = 22'000 };

static struct gpiod_line_request* request_output(struct gpiod_chip* chip,
                                                 unsigned int offset,
                                                 enum gpiod_line_value first,
                                                 const char* consumer) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    struct gpiod_line_request* request = nullptr;
    if (settings && config && request_config) {
        gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_OUTPUT);
        gpiod_line_settings_set_output_value(settings, first);
        gpiod_line_config_add_line_settings(config, &offset, 1, settings);
        gpiod_request_config_set_consumer(request_config, consumer);
        request = gpiod_chip_request_lines(chip, request_config, config);
    }
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_line_request* relay =
        request_output(chip, RELAY, GPIOD_LINE_VALUE_INACTIVE, "thermo");
    gpiod_chip_close(chip);
    if (!relay) {
        perror("GPIO 23 요청");
        return 1;
    }
    long milli;
    bool heating = false;
    while (scanf("%ld", &milli) == 1) {      // 표준 입력으로 온도가 한 줄씩 온다
        // 켜져 있을 때와 꺼져 있을 때의 문턱을 달리해서, 경계에서 떨지 않게 한다
        const bool want = heating ? milli < OFF_ABOVE : milli < ON_BELOW;
        if (want != heating) {
            heating = want;
            gpiod_line_request_set_value(relay, RELAY,
                                         heating ? GPIOD_LINE_VALUE_ACTIVE
                                                 : GPIOD_LINE_VALUE_INACTIVE);
        }
        printf("%.1f도, 히터 %s\n", (double)milli / 1000.0, heating ? "켬" : "끔");
    }
    gpiod_line_request_release(relay);       // 꺼 둔 채로 놓는다
}
```

```text
21.5도, 히터 끔
20.4도, 히터 끔
19.8도, 히터 켬
20.9도, 히터 켬
22.1도, 히터 끔
21.0도, 히터 끔
```

- **출력은 지어 넣은 온도로 얻었다**: 여섯 숫자를 표준 입력에 넣어 돌린 것입니다. 보드에서는 맨 위 주석의 명령처럼 1초마다 온도 파일을 읽어 프로그램에 이어 줍니다
- **센서와 말하는 일은 보이지 않는다**: 1-Wire의 박자는 드라이버 안에서 끝납니다. 프로그램에 오는 것은 숫자 하나입니다
- **센서의 폴더는 28로 시작한다**: DS18B20의 족 번호가 0x28이어서 폴더의 이름이 `28-`로 시작합니다. 옛 방식의 파일 `w1_slave`는 두 줄을 내주고, 둘째 줄의 `t=` 뒤에 같은 숫자가 있습니다
- **문턱이 둘이다**: 20도 아래에서 켜고 22도 위에서 끕니다. 문턱이 하나면 그 언저리에서 릴레이가 쉴 새 없이 붙었다 떨어집니다([「릴레이와 트랜지스터 몰기」](#/read/libgpiod/out-relay))

## 줄의 주인

- **드라이버가 쥔 줄은 쓸 수 없다**: 오버레이가 가져간 줄은 커널의 것입니다. libgpiod로 요청하면 `EBUSY`가 돌아옵니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))
- **누가 쥐었는지 본다**: `gpioinfo`가 그 줄의 소비자 이름을 보여 줍니다([「gpiodetect와 gpioinfo」](#/read/libgpiod/tl-detect))
- **핀마다 고른다**: 한 보드에서 섞어 쓰는 것이 보통입니다. 박자가 빠듯한 장치의 핀은 드라이버에게, 나머지는 libgpiod에게 줍니다. 위의 예제가 그 꼴입니다
- **오버레이는 켤 때 붙는다**: `config.txt`를 고친 뒤에는 다시 켭니다. 돌고 있는 채로 얹는 명령도 있습니다

## 직접 하는 일

- **고르는 차례**: 전용 회로가 있는지, 커널에 드라이버가 있는지를 먼저 봅니다. 둘 다 없을 때 libgpiod로 짭니다
- **드라이버가 없는 장치**: 초음파 거리 센서는 타임스탬프로 폭을 재고, 키패드는 느린 박자로 훑습니다. 프로그램으로 해도 되는 일들입니다([「초음파 거리 센서」](#/read/libgpiod/pj-ultrasonic), [「키패드 훑기」](#/read/libgpiod/pj-keypad))
- **프로그램의 판단이 들어가는 것**: 신호등의 차례나 길게 누르기처럼 규칙을 내가 정하는 일은 프로그램의 몫입니다([「신호등」](#/read/libgpiod/pj-traffic))
- **원리를 보려는 것**: 로터리 엔코더에는 오버레이가 있지만, 다음 장에서는 직접 읽어 봅니다([「로터리 엔코더」](#/read/libgpiod/pj-encoder))

<Note>
오버레이의 이름과 인수, 기본 핀은 라즈베리파이 펌웨어 저장소의 overlays README에서, 온도 파일의 뜻은 리눅스 커널의 w1_therm 문서에서, `udelay`는 커널의 지연 함수 문서에서 옮겼습니다. `dht11`의 파일 이름과 오류를 돌려주는 길은 그 드라이버의 소스와, 그 파일을 읽은 예가 실린 메일링 리스트의 글에서 봤습니다. 어느 오버레이도 보드에서 얹어 보지 못했습니다. 예제는 이 책의 흉내 칩에서 지어 넣은 온도로 돌렸고, 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 확인했습니다. 센서와 릴레이를 달아 돌려 보지는 못했습니다.
</Note>

## 정리

- 박자가 빠듯한 일은 커널의 드라이버가 한다. 인터럽트를 받은 자리에서 일하고, 전용 회로를 부린다
- 라즈베리파이에서는 `dtoverlay=` 한 줄로 드라이버를 핀에 붙이고, 프로그램은 파일이나 장치를 읽는다
- 드라이버가 쥔 줄은 libgpiod로 쓸 수 없다. 핀마다 누구에게 맡길지 고른다
