입력으로 둔 핀은 바깥의 전압을 읽기만 하고 스스로는 아무 전압도 내지 않습니다. 그래서 단추가 떨어져 있는 동안에는 읽을 전압이 없습니다. 풀업과 풀다운은 그 빈 시간에 선을 한쪽으로 붙들어 두는 저항입니다. 이 쪽은 단추를 다는 두 가지 회로와, 풀 저항의 세기가 무엇을 바꾸는지를 봅니다.

## 떠 있는 입력

- **읽을 것이 없다**: 단추가 떨어져 있으면 선은 어디에도 이어져 있지 않습니다. 이때의 전압은 LOW와 HIGH의 문턱 사이 어디든 될 수 있고, 읽을 때마다 다른 값이 나옵니다
- **프로그램은 가려내지 못한다**: 읽은 값은 0 아니면 1입니다. 떠 있어서 나온 0인지 눌러서 나온 0인지는 코드에서 알 길이 없습니다
- **저항으로 붙든다**: 선을 큰 저항으로 3.3V에 묶으면 풀업, GND에 묶으면 풀다운입니다. 단추가 떨어져 있을 때의 값이 정해지고, 단추가 닿으면 단추 쪽이 이깁니다. 저항이 크기 때문입니다

## 단추를 다는 두 회로

| 회로 | 단추의 다른 쪽 | 뗐을 때 | 눌렀을 때 |
| --- | --- | --- | --- |
| 풀업 | GND | HIGH | LOW |
| 풀다운 | 3.3V | LOW | HIGH |

- **풀업 쪽을 더 많이 쓴다**: 단추까지 가는 선이 신호와 GND 둘뿐입니다. 선의 껍질이 벗겨져 쇠 상자에 닿아도 눌린 것으로 읽힐 뿐입니다. 풀다운 회로는 3.3V를 단추까지 끌고 나가야 하고, 그 선이 GND에 닿으면 전원이 맞붙습니다
- **누르면 0이 된다**: 풀업 회로에서는 눌린 것이 LOW입니다. 줄을 액티브 로로 설정해 두면 라이브러리가 뒤집어 주므로, 코드에서는 눌린 것을 활성으로 읽습니다([「액티브 로」](#/read/libgpiod/out-active-low))
- **접점은 떨린다**: 쇠붙이 둘이 붙고 떨어지는 순간에 값이 여러 번 오갑니다. 풀 저항이 고쳐 주는 일이 아니고, 따로 걸러야 합니다([「디바운스」](#/read/libgpiod/ed-debounce))

## 세기가 바꾸는 것

풀 저항은 값이 작을수록 세게 붙듭니다. 세면 잡음에 잘 버티고 빨리 돌아오지만, 단추를 누르고 있는 동안 전류를 더 씁니다. 아래 예제가 풀업 다섯 가지를 놓고 그 세 가지를 계산합니다.

```c
// 풀업 저항의 세기에 따라 달라지는 것: 눌렀을 때의 전류, 버티는 잡음, 돌아오는 시간
#include <stdio.h>

enum {
    SUPPLY_MV = 3300,
    LOW_BELOW_MV = 800,                      // 이 아래로 내려가야 LOW로 읽힌다
    HIGH_ABOVE_MV = 2000,                    // 이 위로 올라와야 HIGH로 읽힌다
    WIRE_PF = 100,                           // 선과 핀이 가진 용량(어림)
};

struct pull {
    long ohm;
    const char* where;
};

int main(void) {
    const struct pull pulls[] = {
        {1800, "GPIO 2와 3에 납땜된 풀업"}, {4700, "바깥에 다는 센 풀업"},
        {10'000, "바깥에 다는 흔한 풀업"},  {33'000, "칩 안의 풀업, 가장 셀 때"},
        {73'000, "칩 안의 풀업, 가장 약할 때"},
    };
    printf("  저항  누르면  잡음한도    돌아오기  어디의 풀업인가\n");
    for (size_t i = 0; i < sizeof pulls / sizeof pulls[0]; ++i) {
        long r = pulls[i].ohm;
        // 단추가 선을 GND에 붙였을 때 풀업으로 흐르는 전류
        long pressed_ua = SUPPLY_MV * 1000L / r;
        // HIGH인 선을 LOW의 문턱까지 끌어내리려면 밖에서 빼내야 하는 전류
        long noise_ua = (SUPPLY_MV - LOW_BELOW_MV) * 1000L / r;
        // 단추를 뗀 뒤 선이 HIGH의 문턱까지 올라오는 시간: RC × ln(3.3 ÷ 1.3)
        long rise_ns = r * WIRE_PF / 1000 * 932 / 1000;
        printf("%5ldΩ  %4ldµA  %6ldµA  %8.1fµs  %s\n", r, pressed_ua, noise_ua,
               (double)rise_ns / 1000, pulls[i].where);
    }
}
```

```text
  저항  누르면  잡음한도    돌아오기  어디의 풀업인가
 1800Ω  1833µA    1388µA       0.2µs  GPIO 2와 3에 납땜된 풀업
 4700Ω   702µA     531µA       0.4µs  바깥에 다는 센 풀업
10000Ω   330µA     250µA       0.9µs  바깥에 다는 흔한 풀업
33000Ω   100µA      75µA       3.1µs  칩 안의 풀업, 가장 셀 때
73000Ω    45µA      34µA       6.8µs  칩 안의 풀업, 가장 약할 때
```

- **누르면**: 단추가 눌려 있는 동안 풀업을 거쳐 흐르는 전류입니다. 문이 닫혀 있는 것을 알리는 스위치처럼 내내 눌려 있는 것이라면 이 전류가 계속 흐릅니다. 건전지로 도는 장치에서는 따져야 합니다
- **잡음한도**: HIGH로 붙들린 선을 LOW의 문턱까지 끌어내리는 데 드는 전류입니다. 칩 안의 풀업은 수십 µA면 넘어갑니다. 긴 선이 모터나 릴레이 곁을 지나면 그만한 전류가 끼어들 수 있습니다
- **돌아오기**: 단추를 떼면 풀업이 선의 용량을 채워야 HIGH가 됩니다. 저항이 클수록 느리지만 가장 약한 풀업으로도 7µs가 안 되므로 단추에서는 문제가 되지 않습니다
- **고르는 법**: 한 뼘 남짓한 선에 단 단추는 칩 안의 풀업으로 충분합니다. 선이 길거나 잡음이 많은 자리에서는 바깥에 10kΩ이나 4.7kΩ을 답니다

## 칩 안의 풀

- **켜진 직후**: 헤더의 핀은 입력이고 GPIO 0부터 8은 풀업, 9부터 27은 풀다운이 걸려 있습니다. 내 보드에서 그런지는 `sudo pinctrl -p`로 봅니다([「pinctrl」](#/read/libgpiod/tl-pinctrl))
- **GPIO 2와 3**: 보드에 1.8kΩ 풀업이 납땜되어 있어 끌 수 없습니다. 풀다운 회로에는 이 두 핀을 쓰지 않습니다
- **코드에서 고른다**: 줄을 요청할 때 설정에 풀업, 풀다운, 끔, 그대로 둠 가운데 하나를 적습니다([「바이어스 설정」](#/read/libgpiod/in-bias))
- **바깥에 달았으면 안의 것은 끈다**: 바깥에 풀업을 달았는데 칩 안의 풀다운이 켜져 있으면 두 저항이 전압을 나눕니다. GPIO 9부터 27은 기본이 풀다운이므로 이 일이 실제로 일어납니다
- **부탁일 뿐이다**: 커널 문서는 풀 설정을 되는 데까지만 해 주는 것으로 적습니다. 칩에 그런 회로가 없으면 오류 없이 넘어가고 선은 떠 있게 됩니다. 줄 정보에 보이는 것도 요청한 설정이지 회로가 실제로 그렇게 되었다는 뜻이 아닙니다

<Note>
문턱 전압과 풀 저항의 범위는 라즈베리파이 공식 문서의 표에 있는 4의 값이고, 기본 풀의 방향은 그 문서가 가리키는 칩의 자료에서 온 것입니다. 선의 용량 100pF은 어림으로 넣은 값이고, 잡음한도는 직류로 따진 단순한 기준입니다. 실제 잡음은 짧게 튀는 것이어서 이 숫자보다 사정이 복잡합니다. 단추의 선을 쇠 상자와 견준 이야기는 회로를 꾸밀 때의 일반 지식입니다. 예제는 x86-64와 aarch64에서 같은 출력을 냈고, 회로를 꾸며 재 본 것은 아닙니다.
</Note>

## 정리

- 아무것도 잇지 않은 입력은 값이 정해지지 않으므로 풀업이나 풀다운으로 붙든다
- 단추는 풀업을 걸고 GND 쪽에 다는 회로를 주로 쓰고, 그때 눌린 것은 LOW다
- 풀 저항이 셀수록 잡음에 버티고 전류를 더 쓴다. 칩 안의 풀은 약하므로 긴 선에는 바깥에 단다
