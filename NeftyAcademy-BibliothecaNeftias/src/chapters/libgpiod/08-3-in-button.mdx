단추는 사람이 누르는 스위치입니다. 값을 읽는 법과 풀을 거는 법은 앞의 두 쪽에서 봤고, 여기서는 그 값에서 한 번 눌렀다는 사실을 알아냅니다. 걸리는 것은 접점입니다. 쇠붙이 둘이 붙고 떨어지는 순간에 값이 여러 번 오가서, 읽은 대로 세면 한 번 누른 것이 여러 번이 됩니다.

## 풀업과 액티브 로로 읽는 단추

단추의 한 다리를 GPIO 27(핀 13)에, 다른 다리를 맞은편의 GND(핀 14)에 잇습니다. 요청에는 설정 셋을 적습니다.

| 설정 | 단추에서 하는 일 |
| --- | --- |
| 방향을 입력으로 | 핀이 전압을 내지 않고 읽기만 한다 |
| 바이어스를 풀업으로 | 단추를 뗀 동안 선을 3.3V 쪽에 붙든다 |
| 액티브 로 | 눌려서 LOW가 된 것을 active로 읽게 한다 |

- **부품은 단추와 선 둘이면 된다**: 풀 저항은 칩 안의 것을 씁니다. 핀과 단추 사이에 330Ω에서 1kΩ을 넣어 두면, 이 줄을 실수로 출력으로 요청한 채 단추를 눌러도 전류가 한도 안에 머뭅니다([「3.3V, 전류 한계, 보호 저항」](#/read/libgpiod/gp-electrical))
- **액티브 로는 읽는 값만 뒤집는다**: 풀업은 그대로 풀업입니다. 커널은 풀의 방향을 고를 때 액티브 로를 보지 않습니다([「액티브 로」](#/read/libgpiod/out-active-low))
- **풀업을 빼먹으면 줄곧 눌린 것이 된다**: GPIO 27의 기본 풀은 풀다운입니다. 뗀 단추가 LOW로 읽히고, 액티브 로가 그것을 눌림으로 바꿉니다. 기본 상태의 흉내 칩에서 풀업을 적는 줄을 지우고 돌리면 20ms에 눌림이 한 번 찍히고 끝납니다. 앞서 돈 프로그램이 풀업을 걸어 둔 보드에서는 멀쩡해 보일 수도 있습니다([「바이어스 설정」](#/read/libgpiod/in-bias))

## 떨림을 거르는 계수기

접점의 떨림은 [「gpiomon」](#/read/libgpiod/tl-mon)에서 에지가 여러 개 찍히는 것으로 봤습니다. 아래 예제는 단추를 5ms마다 읽고, 믿고 있던 값과 다른 값이 다섯 번 내리 읽혔을 때에만 바뀐 것으로 칩니다. 단추는 0.15초 동안 한 번, 1.4초 동안 한 번 눌립니다.

```c gpiosim=press
// 단추를 5ms마다 읽어 떨림을 거르고, 짧게 누른 것과 길게 누른 것을 가른다
#include <gpiod.h>
#include <stdio.h>
#include <threads.h>

enum {
    BUTTON = 27,                             // GPIO 27, 핀 13. 건너편은 GND
    STEP_MS = 5,                             // 읽는 간격
    NEED = 5,                                // 이만큼 내리 달라야 바뀐 것으로 친다
    LONG_MS = 1000,                          // 이보다 오래 눌렀으면 길게 누른 것
};

// 떨림을 거르는 계수기
struct debouncer {
    bool state;                              // 믿기로 한 값
    int differ;                              // 그것과 다른 값이 이어진 횟수
};

// 방금 읽은 값을 넣는다. 믿는 값이 바뀌었으면 true를 돌려준다
static bool debounce(struct debouncer* filter, bool raw) {
    filter->differ = raw != filter->state ? filter->differ + 1 : 0;
    if (filter->differ < NEED) {
        return false;
    }
    filter->state = raw;
    filter->differ = 0;
    return true;
}

// 풀업을 켠 액티브 로 입력으로 요청한다. 눌린 동안 active로 읽힌다
static struct gpiod_line_request* request_button(struct gpiod_chip* chip,
                                                 unsigned int offset,
                                                 const char* consumer) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    struct gpiod_line_request* request = nullptr;
    if (settings && config && request_config) {
        gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_INPUT);
        gpiod_line_settings_set_bias(settings, GPIOD_LINE_BIAS_PULL_UP);
        gpiod_line_settings_set_active_low(settings, true);
        gpiod_line_config_add_line_settings(config, &offset, 1, settings);
        gpiod_request_config_set_consumer(request_config, consumer);
        request = gpiod_chip_request_lines(chip, request_config, config);
    }
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_line_request* button = request_button(chip, BUTTON, "button");
    gpiod_chip_close(chip);
    if (!button) {
        perror("요청");
        return 1;
    }
    const struct timespec step = {.tv_nsec = STEP_MS * 1'000'000};
    struct debouncer filter = {0};
    bool raw_before = false;
    int raw_presses = 0;                     // 읽은 값 그대로 센 누름
    int presses = 0;                         // 걸러서 센 누름
    long pressed_at = 0;
    for (long ms = 0; ms <= 4000; ms += STEP_MS) {
        enum gpiod_line_value value = gpiod_line_request_get_value(button, BUTTON);
        if (value == GPIOD_LINE_VALUE_ERROR) {
            perror("읽기");
            break;
        }
        bool raw = value == GPIOD_LINE_VALUE_ACTIVE;
        raw_presses += raw && !raw_before;
        raw_before = raw;
        if (debounce(&filter, raw)) {
            if (filter.state) {
                ++presses;
                pressed_at = ms;
                printf("%4ldms  눌림\n", ms);
            } else {
                long held = ms - pressed_at;
                printf("%4ldms  뗌    %4ldms 동안 눌렸다, %s\n", ms, held,
                       held >= LONG_MS ? "길게" : "짧게");
            }
        }
        thrd_sleep(&step, nullptr);
    }
    printf("그대로 세면 %d번, 걸러 세면 %d번 눌렀다\n", raw_presses, presses);
    gpiod_line_request_release(button);
}
```

```text
1035ms  눌림
1185ms  뗌     150ms 동안 눌렸다, 짧게
2025ms  눌림
3425ms  뗌    1400ms 동안 눌렸다, 길게
그대로 세면 5번, 걸러 세면 2번 눌렀다
```

- **그대로 세면 다섯 번이다**: 두 번 누른 것이 다섯 번으로 세어졌습니다. 붙을 때의 떨림, 뗄 때의 떨림, 길게 누르던 도중에 접점이 잠깐 뜬 것이 하나씩 더해졌습니다
- **`debounce`는 다른 값이 내리 읽힐 때만 센다**: 도중에 믿던 값이 한 번이라도 다시 읽히면 0부터 다시 셉니다. 떨림도, 한 번 튄 잡음도 다섯을 채우지 못합니다
- **아는 시각은 늦어진다**: 1004.5ms에 닿은 접점을 1035ms에 알았습니다. 떨림이 끝난 뒤로 다섯 번을 채워야 하기 때문입니다
- **누른 길이는 거의 그대로 나온다**: 길이는 두 시각의 차이라서 늦어진 만큼이 서로 지워집니다. 붙을 때와 뗄 때의 떨림이 다르면 그 차이만큼은 어긋납니다
- **시간은 바퀴 수로 셌다**: 예제는 한 바퀴를 5ms로 치고 더합니다. 진짜 보드에서는 한 바퀴가 그보다 조금 길어서, 적힌 시간이 실제보다 짧게 나옵니다. 짧게와 길게를 가르는 데는 지장이 없습니다([「사용자 공간에서 얼마나 정확한가」](#/read/libgpiod/tm-jitter))

## 읽는 간격과 횟수 고르기

- **간격 곱하기 횟수가 거르는 시간이다**: 5ms마다 다섯 번이면 첫 번째부터 다섯 번째까지 20ms입니다. 이것이 가장 긴 떨림보다 길어야 떨림이 눌림이나 뗌으로 세어지지 않습니다
- **떨림은 부품마다 다르다**: 잭 갠슬이 스위치 열여덟 가지를 300번씩 눌러 잰 글에서, 열여섯은 평균 1.6ms에 길어야 6.2ms 떨렸고 하나는 뗄 때 157ms까지 떨렸습니다. 내 단추는 직접 재 봅니다([「gpiomon」](#/read/libgpiod/tl-mon))
- **너무 길면 굼뜨다**: 같은 글은 50ms 늦게 켜진 LED는 곧바로 켜진 것처럼 보였고 100ms는 눈에 띄었다고 적으며, 거르는 시간으로 20ms에서 50ms를 권합니다
- **한 번 읽고 믿지 않는다**: 떨림보다 긴 간격으로 한 번씩 읽어 그대로 믿는 방법도 떨림은 넘깁니다. 그러나 읽는 순간에 튄 잡음 하나를 눌림으로 받아들입니다. 촘촘히 읽고 여러 번 확인하는 쪽이 긴 선과 잡음에 버팁니다
- **쉬지 못한다**: 이 프로그램은 아무도 단추를 누르지 않는 동안에도 1초에 200번 깨어납니다. 값이 바뀔 때까지 자는 방식이 에지 이벤트입니다([「에지 감지 켜기」](#/read/libgpiod/ed-request))
- **커널에 맡길 수도 있다**: 요청에 디바운스 기간을 적으면 커널이 걸러 줍니다. 리눅스 커널 문서는 그 설정이 에지 이벤트뿐 아니라 읽어 가는 값에도 듣는다고 적습니다([「디바운스」](#/read/libgpiod/ed-debounce))

## 길게 누름과 여러 단추

- **예제는 뗄 때 가른다**: 뗀 순간에 눌려 있던 길이를 보고 짧게와 길게를 정합니다. 짧게 누른 것인지는 떼기 전에는 알 수 없습니다
- **누르고 있는 동안 반응하려면**: 3초 누르면 꺼지는 단추처럼 떼기 전에 일해야 하면, 바퀴마다 눌린 채 지난 시간을 보고 문턱을 넘는 바퀴에서 한 번만 일합니다. 그 누름은 뗄 때 짧은 누름으로 다시 세지 않게 표시해 둡니다
- **단추가 여럿이면**: 오프셋들을 한 요청에 모으고 같은 settings를 붙입니다. 한 바퀴에 `gpiod_line_request_get_values` 한 번으로 모두 읽고, `struct debouncer`는 단추마다 하나씩 둡니다([「값 읽기」](#/read/libgpiod/in-read))
- **계속 도는 프로그램은 신호로 끝낸다**: 예제는 4초 뒤에 스스로 끝납니다. 켜 두는 프로그램은 Ctrl+C를 받아 반복을 끝내고 줄을 놓습니다([「놓아주기」](#/read/libgpiod/rq-release))

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, 단추가 눌리고 떼이는 시각과 떨림, 도중에 접점이 뜨는 것은 대본으로 넣었습니다. 흉내 칩의 시간은 가상이어서 한 바퀴가 정확히 5ms입니다. 풀업을 뺀 경우도 흉내 칩에서 돌려 본 것입니다. 스위치를 잰 값과 권하는 시간은 잭 갠슬의 글에서, 디바운스 설정이 읽는 값에도 듣는다는 것은 리눅스 커널 문서에서, 풀을 고를 때 액티브 로를 보지 않는다는 것은 커널 소스에서 확인했습니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했고, 보드와 단추로 돌려 보지는 못했습니다.
</Note>

## 정리

- 단추는 GND 쪽에 달고, 풀업을 켠 액티브 로 입력으로 요청한다. 눌린 동안 active로 읽힌다
- 접점은 떨린다. 일정한 간격으로 읽으면서 다른 값이 여러 번 내리 읽혔을 때만 바뀐 것으로 친다
- 거르는 시간은 가장 긴 떨림보다 길게, 사람이 굼뜨다고 느끼는 것보다 짧게 잡는다
