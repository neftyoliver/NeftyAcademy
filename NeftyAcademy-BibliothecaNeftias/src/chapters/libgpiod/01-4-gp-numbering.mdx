같은 핀을 가리키는 말이 넷입니다. 배선 그림은 핀 번호로 말하고, 문서와 도구는 GPIO 번호로 말하고, libgpiod의 함수는 칩과 오프셋을 받고, 커널은 줄에 이름도 붙여 둡니다. 이 쪽은 넷이 어떻게 이어지는지를 정리하고, 코드에 무엇을 적을지를 정합니다. 헤더의 생김새와 핀을 세는 법은 「라즈베리파이 시작하기」의 [「핀 배치와 번호 붙이는 세 가지 방식」](#/read/sbc-start/hdr-pinout)에서 봤습니다.

## 네 가지 번호

| 가리키는 말 | 같은 핀의 예 | 만나는 곳 |
| --- | --- | --- |
| 핀 번호 | 11 | 배선 그림, 선을 꽂을 때 |
| GPIO 번호 | GPIO 17 | 공식 문서, `pinctrl`, 오버레이의 파라미터. BCM 번호라고도 한다 |
| 칩과 오프셋 | `gpiochip0`의 17번 줄 | libgpiod의 함수와 `gpioset` 같은 도구 |
| 줄 이름 | `GPIO17` | `gpioinfo`의 출력, 이름으로 찾는 함수와 도구 |

- **핀 번호와 GPIO 번호 사이에는 규칙이 없다**: 표를 봐야 합니다. 아래 예제는 그 표를 배열로 품고 있습니다
- **GPIO 번호와 오프셋은 같다**: 헤더를 맡은 칩에서는 그렇습니다. GPIO 17은 그 칩의 17번 줄입니다
- **이름은 있을 수도 없을 수도 있다**: 줄의 이름은 보드의 디바이스 트리가 붙입니다. 붙이지 않은 줄은 이름이 없습니다

## 핀에서 줄까지

```c gpiosim
// 핀 번호를 libgpiod가 받는 칩과 오프셋으로 바꾸고, 그 줄의 이름을 묻는다
#include <errno.h>
#include <gpiod.h>
#include <stdio.h>
#include <string.h>

enum { V3 = -1, V5 = -2, GND = -3 };         // GPIO가 아닌 핀

// 핀 1~40에 나와 있는 것. 0 이상이면 GPIO 번호다
static const signed char header[41] = {
    0,   V3,  V5, 2,  V5,  3,  GND, 4,  14, GND, 15, 17, 18,  27,
    GND, 22,  23, V3, 24,  10, GND, 9,  25, 11,  8,  GND, 7,  0,
    1,   5,   GND, 6, 12,  13, GND, 19, 16, 26,  20, GND, 21,
};

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_chip_info* about = gpiod_chip_get_info(chip);
    const char* chip_name = gpiod_chip_info_get_name(about);
    printf("%s [%s] 줄 %zu개\n", chip_name, gpiod_chip_info_get_label(about),
           gpiod_chip_info_get_num_lines(about));

    const int pins[] = {11, 7, 8, 3, 27, 6};
    for (size_t i = 0; i < sizeof pins / sizeof pins[0]; ++i) {
        int gpio = header[pins[i]];
        if (gpio < 0) {
            printf("핀 %2d  GPIO가 아니다\n", pins[i]);
            continue;
        }
        // 헤더를 맡은 칩에서는 GPIO 번호가 곧 오프셋이다
        struct gpiod_line_info* info =
            gpiod_chip_get_line_info(chip, (unsigned int)gpio);
        const char* name = info ? gpiod_line_info_get_name(info) : nullptr;
        printf("핀 %2d  GPIO %2d  %s의 %2d번 줄  이름 %s\n", pins[i], gpio,
               chip_name, gpio, name ? name : "(없음)");
        gpiod_line_info_free(info);
    }

    const char* const asked[] = {"GPIO17", "GPIO4"};
    for (size_t i = 0; i < sizeof asked / sizeof asked[0]; ++i) {
        int offset = gpiod_chip_get_line_offset_from_name(chip, asked[i]);
        if (offset >= 0)
            printf("이름으로 찾기 %s: %d번 줄\n", asked[i], offset);
        else
            printf("이름으로 찾기 %s: %s\n", asked[i], strerror(errno));
    }
    gpiod_chip_info_free(about);
    gpiod_chip_close(chip);
}
```

핀  8  GPIO 14  gpiochip0의 14번 줄  이름 TXD1

위는 4 Model B의 칩으로 돌린 것입니다. 같은 프로그램을 5의 칩으로 돌리면 이렇게 나옵니다.

```text
gpiochip0 [pinctrl-rp1] 줄 54개
핀 11  GPIO 17  gpiochip0의 17번 줄  이름 GPIO17
핀  7  GPIO  4  gpiochip0의  4번 줄  이름 GPIO4
핀  8  GPIO 14  gpiochip0의 14번 줄  이름 GPIO14
핀  3  GPIO  2  gpiochip0의  2번 줄  이름 GPIO2
핀 27  GPIO  0  gpiochip0의  0번 줄  이름 ID_SDA
핀  6  GPIO가 아니다
이름으로 찾기 GPIO17: 17번 줄
이름으로 찾기 GPIO4: 4번 줄
```

- **오프셋은 두 보드가 같다**: 핀 11은 어느 보드에서나 `gpiochip0`의 17번 줄입니다. 칩의 이름표는 다르지만 코드에 적는 숫자는 그대로입니다
- **이름은 보드마다 다르다**: 4의 디바이스 트리는 핀의 주된 쓰임을 이름으로 삼아서 GPIO 4가 `GPIO_GCLK`, GPIO 14가 `TXD1`, GPIO 2가 `SDA1`입니다. 5는 GPIO 2부터 27까지를 모두 `GPIO2`처럼 번호로 부릅니다
- **두 보드에 다 있는 이름**: 헤더의 줄 가운데에는 `GPIO17`처럼 4에서도 번호로 불리는 것(5, 6, 12, 13, 16부터 27)과 `ID_SDA`, `ID_SCL`입니다. `GPIO4`라는 이름으로 찾는 코드는 5에서만 돕니다
- **없는 이름**: 찾지 못하면 함수는 -1을 주고 `errno`는 `ENOENT`입니다. 출력의 글이 그 오류의 말입니다([「줄 이름으로 찾기」](#/read/libgpiod/ch-names))
- **ID_SDA**: GPIO 0과 1은 HAT의 EEPROM을 읽는 데 쓰는 줄입니다. 헤더에 나와 있지만 내 회로에는 쓰지 않습니다

## 칩의 번호

- **헤더의 칩은 `gpiochip0`**: 4에서는 처음부터 그랬습니다. 5에서는 2024년 7월의 커널부터이고 그 앞에는 `gpiochip4`였습니다. 옛 글의 `/dev/gpiochip4`는 `/dev/gpiochip0`으로 바꿔 읽습니다([「라즈베리파이 5에서 깨진 것들」](#/read/libgpiod/hs-pi5))
- **칩은 여럿이다**: 4에는 줄 여덟 개짜리 칩이 하나 더 있고, 5에는 넷이 더 있습니다. 4의 그 칩에는 보드 안의 LED와 전원 스위치 같은 것이 달려 있습니다. 헤더의 핀이 아니므로 내 프로그램이 만질 일은 없습니다
- **이름표로 확인한다**: 칩의 정보에는 드라이버가 붙인 이름표가 있습니다. 4는 `pinctrl-bcm2711`, 5는 `pinctrl-rp1`입니다. 번호를 믿지 못할 자리에서는 이름표를 보고 고릅니다([「칩 열기」](#/read/libgpiod/ch-open))

## 코드에 적는 것

- **GPIO 번호를 적는다**: 오프셋으로 그대로 쓸 수 있고 두 보드에서 같습니다. 이 책의 예제는 모두 그렇게 합니다
- **핀 번호는 주석에**: `enum { LED = 17 };  // GPIO 17, 헤더의 핀 11`처럼 옆에 적어 두면 회로를 다시 꾸밀 때 표를 또 찾지 않습니다
- **칩의 경로는 한곳에**: `"/dev/gpiochip0"`을 코드 여기저기에 적지 않습니다. 상수 하나로 두거나 실행할 때 인자로 받습니다
- **이름은 보드가 정해졌을 때만**: 한 가지 보드에서만 돌 프로그램이라면 이름으로 찾는 것이 읽기 좋습니다. 여러 보드에서 돌아야 하면 번호를 씁니다

<Note>
핀과 GPIO의 표는 공식 문서의 헤더 그림에서 옮겼습니다. 줄의 이름은 흉내 칩에 넣어 둔 것이 그대로 나온 것인데, 4의 것은 리눅스 커널의 4 Model B용 디바이스 트리에서, 5의 것은 커널의 RP1 바인딩 문서에 실린 예에서 가져왔습니다. Raspberry Pi OS의 커널은 여기에 자기 수정을 얹으므로 내 보드에서는 `gpioinfo -c gpiochip0`으로 확인합니다. 칩 번호가 바뀐 때는 라즈베리파이의 GPIO 백서에서 옮겼습니다. 예제는 흉내 칩에서 돌렸고 진짜 보드에서 돌려 보지는 못했습니다.
</Note>

## 정리

- 핀 번호는 자리, GPIO 번호는 칩의 신호 번호이고, 헤더를 맡은 칩에서는 GPIO 번호가 곧 줄의 오프셋이다
- 헤더의 칩은 4와 5 모두 `/dev/gpiochip0`이고 오프셋도 같지만, 줄의 이름은 보드마다 다르다
- 코드에는 GPIO 번호를 적고 핀 번호는 주석에 둔다. 이름으로 찾는 것은 보드가 정해졌을 때만 쓴다
