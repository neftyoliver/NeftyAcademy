지금까지의 예제는 0.25초를 자고, 5ms마다 단추를 읽었습니다. 그 시간이 얼마나 정확하게 지켜지는지는 따지지 않았습니다. 리눅스에서는 여러 프로그램이 CPU를 나눠 쓰고, 어느 것이 언제 도는지는 커널이 정합니다. 프로그램이 정한 시각을 얼마나 지킬 수 있는지 재 봅니다.

## 잠이 늦게 깨는 까닭

- **일찍 깨지는 않는다**: 잠드는 함수는 적어 준 시간이 다 지나야 돌아옵니다. 그보다 먼저 돌아오는 것은 신호가 왔을 때뿐입니다([「놓아주기」](#/read/libgpiod/rq-release))
- **늦게는 깬다**: 시간이 다 되어도 곧바로 돌지는 못합니다. 커널이 타이머가 끝난 것을 알아채고 프로그램을 깨워야 하고, CPU가 그 프로그램에게 돌아와야 합니다
- **타이머 여유**: 커널은 가까운 때에 끝나는 타이머들을 묶어 처리하려고 보통 프로그램의 타이머를 조금 늦춥니다. 이 여유(timer slack)는 보통 50µs입니다
- **차례를 기다린다**: 깨어났을 때 CPU가 다른 프로그램을 돌리고 있으면, 그것을 곧바로 밀어내지 못하고 기다릴 수 있습니다
- **길이로 자면 밀린다**: `thrd_sleep`은 지금부터 얼마 동안이라는 길이를 받습니다. 늦게 깬 시간과 일하는 데 쓴 시간이 바퀴마다 더해지므로 박자가 조금씩 뒤로 밀립니다([「LED 켜기」](#/read/libgpiod/out-led))
- **시각으로 자면 밀리지 않는다**: `clock_nanosleep`에 `TIMER_ABSTIME`을 주면 깨어날 시각을 적습니다. 한 번 늦게 깨도 다음 눈금은 처음 정한 자리에 있습니다. 적은 시각이 이미 지났으면 자지 않고 돌아옵니다

## 늦는 정도를 재는 프로그램

아래 프로그램은 1ms마다 깨어나기를 1000번 하고, 정한 시각보다 늦게 깬 시간을 모아 크기순으로 늘어놓습니다. GPIO를 쓰지 않으므로 어느 리눅스 컴퓨터에서나 돕니다.

```c
// 1ms마다 깨어나기를 1000번 하면서, 정한 시각보다 얼마나 늦게 깨는지 잰다
#define _POSIX_C_SOURCE 200809L              // clock_nanosleep을 쓰려고
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/prctl.h>
#include <time.h>

enum { ROUNDS = 1000 };
static const int64_t SECOND = 1'000'000'000;
static const int64_t PERIOD = 1'000'000;     // 1ms를 나노초로

static int64_t now_ns(void) {
    struct timespec now;
    clock_gettime(CLOCK_MONOTONIC, &now);
    return now.tv_sec * SECOND + now.tv_nsec;
}

static int by_size(const void* a, const void* b) {
    int64_t x = *(const int64_t*)a;
    int64_t y = *(const int64_t*)b;
    return (x > y) - (x < y);
}

int main(int argc, char** argv) {
    bool relative = false;
    for (int i = 1; i < argc; ++i) {
        if (strcmp(argv[i], "relative") == 0) relative = true;
        // 커널이 타이머를 묶어 처리하려고 두는 여유를 1ns로 줄인다
        if (strcmp(argv[i], "tight") == 0) prctl(PR_SET_TIMERSLACK, 1UL);
    }

    static int64_t late[ROUNDS];
    const int64_t start = now_ns();
    int64_t wake = start;
    for (int i = 0; i < ROUNDS; ++i) {
        if (relative) {
            // 길이로 잔다: 지금부터 1ms
            wake = now_ns() + PERIOD;
            struct timespec length = {.tv_nsec = PERIOD};
            clock_nanosleep(CLOCK_MONOTONIC, 0, &length, nullptr);
        } else {
            // 시각으로 잔다: 처음에 정한 박자의 다음 눈금까지
            wake += PERIOD;
            struct timespec at = {.tv_sec = wake / SECOND,
                                  .tv_nsec = wake % SECOND};
            clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &at, nullptr);
        }
        late[i] = now_ns() - wake;
    }
    const int64_t total = now_ns() - start;

    qsort(late, ROUNDS, sizeof late[0], by_size);
    printf("늦게 깬 정도: 가운데 %lldµs, 100번에 99번은 %lldµs 안, "
           "가장 크게 %lldµs\n",
           (long long)(late[ROUNDS / 2] / 1000),
           (long long)(late[ROUNDS * 99 / 100] / 1000),
           (long long)(late[ROUNDS - 1] / 1000));
    printf("1000바퀴에 걸린 시간: %.3f초\n", (double)total / (double)SECOND);
}
```

```sh
gcc -std=c23 -Wall -Wextra -O2 jitter.c -o jitter
./jitter
./jitter relative
```

이 책을 쓴 컴퓨터에서 차례로 돌린 결과이고, 돌릴 때마다 달라집니다.

```text
늦게 깬 정도: 가운데 99µs, 100번에 99번은 222µs 안, 가장 크게 1712µs
1000바퀴에 걸린 시간: 1.000초
늦게 깬 정도: 가운데 101µs, 100번에 99번은 228µs 안, 가장 크게 1800µs
1000바퀴에 걸린 시간: 1.113초
```

- **가운데 값이 0.1ms이다**: 바퀴의 절반은 이보다 더 늦었습니다. 1ms 박자의 10분의 1입니다
- **가끔 크게 늦는다**: 가장 늦은 바퀴는 1.7ms를 늦어서 눈금 하나를 통째로 지나쳤습니다. 타이밍을 정하는 것은 가운데 값이 아니라 이 꼬리입니다
- **시각으로 자면 박자가 지켜진다**: 1000바퀴가 1.000초에 끝났습니다. 늦게 깬 것이 다음 바퀴로 넘어가지 않았습니다
- **길이로 자면 밀린다**: `relative`를 주면 같은 1000바퀴에 1.113초가 걸렸습니다. 바퀴마다 늦은 만큼이 쌓인 것입니다. 5ms를 한 바퀴로 치던 [「단추 읽기」](#/read/libgpiod/in-button)의 예제가 시간을 실제보다 짧게 세는 까닭입니다

## 조건별로 잰 값

같은 프로그램을 네 조건에서 스무 번씩 돌렸습니다. 가운데와 99번째는 스무 번의 가운데 값이고, 가장 큰 값은 스무 번 사이의 범위입니다. 바쁠 때란 CPU가 둘인 컴퓨터에서 쉬지 않고 도는 프로그램 넷을 함께 돌린 때입니다.

| 조건 | 가운데 | 100번에 99번 | 가장 크게 |
| --- | --- | --- | --- |
| 한가할 때 | 100µs | 233µs | 0.3~2.4ms |
| 한가할 때, `tight` | 50µs | 150µs | 0.2~3.0ms |
| CPU가 바쁠 때 | 69µs | 4.0ms | 1.7~9.5ms |
| 바쁠 때, `chrt -f 50` | 20µs | 64µs | 0.05~4.4ms |

- **늦는 시간의 절반은 타이머 여유였다**: `tight`로 여유를 1ns로 줄이자 가운데 값이 100µs에서 50µs로 내려갔습니다. 가장 큰 값은 그대로입니다
- **바쁘면 꼬리가 길어진다**: 100번에 한 번은 4ms쯤 늦었습니다. 1ms 박자에서 눈금 넷을 지나친 것입니다. 깨어난 뒤에 CPU를 얻기까지 기다린 시간입니다. 가운데 값이 오히려 작아진 까닭은 확인하지 못했습니다
- **실시간 정책은 대개를 고친다**: `chrt -f 50`으로 돌리면(다음 절) 바쁜 가운데에서도 99번째가 64µs였습니다. 그러나 가장 큰 값은 4.4ms까지 나왔습니다. 가장 나쁜 경우는 남았습니다

## 덜 늦게 하는 방법

- **주기적인 일은 시각으로 잔다**: 권한도 설정도 필요 없습니다. 박자가 밀리는 것만 막고, 한 번 한 번이 늦는 것은 그대로입니다
- **타이머 여유를 줄인다**: `prctl(PR_SET_TIMERSLACK, 1UL)` 한 줄입니다. 수십 µs를 덜어 주지만 꼬리에는 듣지 않습니다
- **실시간 정책으로 돌린다**: `sudo chrt -f 50 ./jitter`는 프로그램을 `SCHED_FIFO` 정책의 우선순위 50으로 돌립니다. 우선순위는 1부터 99까지입니다. 이 정책의 프로그램은 깨어나면 보통 프로그램을 곧바로 밀어내고, 타이머 여유도 적용받지 않습니다
- **실시간 정책에는 값이 따른다**: 이 정책의 프로그램은 스스로 잠들거나 기다릴 때까지 CPU를 놓지 않습니다. 쉬지 않고 도는 반복문을 이렇게 돌리면 다른 프로그램이 굶습니다. 커널이 기본으로 1초에 0.95초까지만 돌게 막아 두지만, 잘못된 프로그램을 끌 틈을 남기는 장치일 뿐입니다
- **실시간 커널**: 리눅스 6.12부터는 `PREEMPT_RT` 설정으로 커널을 빌드할 수 있습니다. 커널 안에서 끼어들 수 없던 자리를 줄여, 우선순위 높은 프로그램이 깨어나서 실제로 돌기까지의 시간을 줄입니다. `uname -v`에 `PREEMPT_RT`가 보이면 그 커널입니다. Raspberry Pi OS의 커널이 어느 쪽인지는 확인하지 못했습니다

## GPIO 일과 견주기

| 일 | 한 눈금 | 가끔 수 ms를 늦으면 |
| --- | --- | --- |
| LED 깜빡임, 릴레이 | 0.1초 이상 | 티가 나지 않는다 |
| 단추 훑어 읽기 | 5ms | 한두 바퀴 늦게 안다 |
| 폭으로 값을 전하는 펄스 | 폭의 차이가 µs 단위 | 그 펄스가 다른 값이 된다 |
| 9600bps 시리얼 흉내 | 비트 하나가 104µs | 비트 여럿을 건너뛴다 |

- **아는 것과 제때 하는 것은 다르다**: 에지 이벤트의 타임스탬프는 커널이 인터럽트를 받을 때 찍으므로, 프로그램이 늦게 깨어도 달라지지 않습니다. 언제 일어났는지는 믿을 수 있고, 제때 반응하는 것은 앞의 표만큼만 믿을 수 있습니다([「타임스탬프와 시계 고르기」](#/read/libgpiod/ed-timestamp))
- **타임스탬프에도 오차는 있다**: 핀이 바뀐 때부터 커널이 인터럽트를 받아 시계를 읽기까지의 시간입니다. 그 크기는 보드에서 재지 못했습니다
- **그래서 출력이 먼저 무너진다**: 들어오는 펄스의 폭은 두 타임스탬프의 차이로 압니다. 내보내는 펄스의 폭은 프로그램이 제때 깨어야 지켜집니다([「소프트웨어 PWM의 한계」](#/read/libgpiod/tm-softpwm))
- **받아낼 수 있는 에지의 빠르기**: 프로그램이 늦게 깨는 동안 이벤트는 커널의 버퍼에 쌓입니다. 줄 하나에 16개가 기본이므로, 5ms를 늦는 일이 있는 프로그램은 초당 3,200개보다 빠른 에지를 놓칠 수 있습니다. 버퍼를 키워도 에지마다 인터럽트가 걸리는 부담은 남습니다([「이벤트 버퍼」](#/read/libgpiod/ed-buffer))
- **값을 쓰는 시간은 작다**: libgpiod로 값을 한 번 쓰는 것은 시스템 호출 한 번입니다. 이 책을 쓴 컴퓨터에서 가벼운 `ioctl` 하나는 0.2µs쯤이었습니다. 레지스터를 직접 만지는 것보다 느리지만, 이 표에서 문제가 된 것은 쓰는 시간이 아니라 쓸 때를 맞추는 일입니다([「/dev/mem으로 레지스터를 만지던 라이브러리들」](#/read/libgpiod/hs-devmem))
- **마이크로초의 일은 맡긴다**: 그런 신호는 커널의 드라이버나 전용 하드웨어가 만듭니다([「비트뱅잉」](#/read/libgpiod/tm-bitbang), [「커널 드라이버에 맡길 것들」](#/read/libgpiod/tm-kernel))

<Note>
이 쪽의 숫자는 라즈베리파이에서 잰 것이 아닙니다. CPU가 둘인 x86-64 가상 머신(리눅스 6.18, glibc 2.39)에서 쟀고, 가상 머신이라 그 바깥의 사정도 섞여 있습니다. 꼬리가 길다는 것과 무엇이 그것을 줄이는지를 보이려는 숫자이고, 보드의 값은 같은 프로그램을 보드에서 돌려 얻어야 합니다. 같은 컴퓨터에서 rt-tests 꾸러미의 `cyclictest`로 재도 비슷했습니다. 프로그램은 aarch64로도 컴파일해 봤습니다. 나머지는 리눅스 설명서와 커널 문서에서 옮겼습니다.
</Note>

## 정리

- 잠은 일찍 깨지 않고 늦게 깬다. 이 책이 잰 컴퓨터에서는 대개 0.1ms, 가끔 수 ms를 늦었다
- 주기적인 일은 `clock_nanosleep`과 `TIMER_ABSTIME`으로 시각을 정해 잔다. 길이로 자면 박자가 밀린다
- 실시간 정책은 대개를 좋게 할 뿐 가장 나쁜 경우를 없애지 못한다. 마이크로초의 일은 사용자 공간에 맡기지 않는다
