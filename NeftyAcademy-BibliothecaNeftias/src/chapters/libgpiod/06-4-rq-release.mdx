쥔 줄은 놓아야 다른 프로그램이 쓸 수 있습니다. 놓는 것 자체는 함수 하나입니다. 이 쪽에서 눈여겨볼 것은 그 뒤입니다. 줄을 놓았다고 핀이 꺼지는 것은 아니고, 라즈베리파이에서는 켜 둔 등이 켜진 채로 남습니다. 그것을 알고 끝내는 코드와 모르고 끝내는 코드는 다릅니다.

## 놓는 법과 놓이는 때

- **`gpiod_line_request_release`**: 요청의 파일을 닫고 객체를 풀어 줍니다. 그 뒤로 그 포인터는 쓸 수 없습니다. `nullptr`를 넘겨도 됩니다
- **프로그램이 끝나면 커널이 놓는다**: 스스로 끝났든 죽임을 당했든, 프로세스가 사라지면 그 프로세스가 쥔 줄은 모두 풀립니다. 임자가 사라진 줄이 잠긴 채로 남는 일은 없습니다
- **쥐고 있는 동안만 보장된다**: 커널 문서는 줄의 상태가 요청의 파일이 닫힐 때까지 지켜진다고 적습니다. 닫힌 뒤의 줄은 누구의 손에도 있지 않고, 기본 상태로 돌아갈 수도 있다고 적습니다

## 놓은 뒤의 핀

아래 예제는 두 가지를 합니다. 먼저 등을 켠 채로 줄을 놓아 봅니다. 그다음 다시 쥐고 깜빡이다가, Ctrl+C가 오면 끄고 놓습니다.

```c gpiosim=sigint
// 줄을 놓으면 핀이 어떻게 되는가. 그리고 신호를 받았을 때 끄고 놓는 꼴
#include <gpiod.h>
#include <signal.h>
#include <stdio.h>
#include <threads.h>

enum { LED = 17 };                           // GPIO 17, 헤더의 핀 11

static volatile sig_atomic_t stop;           // 신호가 오면 1이 된다
static void on_signal(int) { stop = 1; }

// GPIO 17을 출력으로 쥔다. 첫 값은 active
static struct gpiod_line_request* hold_led(struct gpiod_chip* chip) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_line_request* request = nullptr;
    unsigned int offset = LED;
    if (settings && config) {
        gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_OUTPUT);
        gpiod_line_settings_set_output_value(settings, GPIOD_LINE_VALUE_ACTIVE);
        gpiod_line_config_add_line_settings(config, &offset, 1, settings);
        request = gpiod_chip_request_lines(chip, nullptr, config);
    }
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    signal(SIGINT, on_signal);
    signal(SIGTERM, on_signal);

    puts("[1] 켠 채로 놓는다");
    gpiod_line_request_release(hold_led(chip));
    thrd_sleep(&(struct timespec){.tv_sec = 1}, nullptr);

    puts("[2] 깜빡이다가 신호를 받으면 끄고 놓는다");
    struct gpiod_line_request* request = hold_led(chip);
    gpiod_chip_close(chip);                  // 요청을 받았으니 칩은 닫아도 된다
    if (!request) {
        perror("요청");
        return 1;
    }
    bool on = true;
    while (!stop) {
        thrd_sleep(&(struct timespec){.tv_nsec = 400'000'000}, nullptr);
        if (stop) break;
        on = !on;
        gpiod_line_request_set_value(request, LED, on ? GPIOD_LINE_VALUE_ACTIVE
                                                      : GPIOD_LINE_VALUE_INACTIVE);
    }
    puts("신호를 받았다");
    gpiod_line_request_set_value(request, LED, GPIOD_LINE_VALUE_INACTIVE);
    gpiod_line_request_release(request);
}
```

```text
[1] 켠 채로 놓는다
핀|   0.000s  GPIO 17 → HIGH
[2] 깜빡이다가 신호를 받으면 끄고 놓는다
핀|   1.400s  GPIO 17 → LOW
핀|   1.800s  GPIO 17 → HIGH
신호를 받았다
핀|   2.000s  GPIO 17 → LOW
```

- **[1] 놓았는데 꺼지지 않았다**: HIGH가 된 뒤로 `→ LOW`가 없습니다. 라즈베리파이의 커널은 놓은 줄의 상태를 그대로 둡니다. 등은 켜진 채이고, 그 핀은 임자 없이 값을 내고 있습니다
- **[2] 끄고 나서 놓았다**: 마지막 `→ LOW`는 프로그램이 스스로 낸 것입니다. 이것이 끝내는 바른 차례입니다

같은 프로그램을 `config.txt`에 `dtparam=strict_gpiod`를 적은 보드에서 돌리면 이렇게 됩니다.

```text
[1] 켠 채로 놓는다
핀|   0.000s  GPIO 17 → HIGH
핀|   0.000s  GPIO 17 → LOW
[2] 깜빡이다가 신호를 받으면 끄고 놓는다
핀|   1.000s  GPIO 17 → HIGH
핀|   1.400s  GPIO 17 → LOW
핀|   1.800s  GPIO 17 → HIGH
신호를 받았다
핀|   2.000s  GPIO 17 → LOW
```

- **놓는 순간 입력으로 돌아갔다**: [1]에서 HIGH 바로 뒤에 `→ LOW`가 붙었습니다. 핀이 값을 내기를 그만두자 풀다운이 선을 끌어내린 것입니다. 이 설정은 놓인 GPIO를 입력으로 되돌립니다
- **어느 쪽에도 기대지 않는다**: 남는 보드에서는 켜진 채 남고, 돌아가는 보드에서는 켜 두려던 것이 꺼집니다. 놓기 전에 스스로 뜻한 값을 내고, 계속 값을 내야 하면 놓지 않습니다

## 끝낼 때의 꼴

- **처리기는 깃발만 세운다**: `on_signal`은 `stop`에 1을 넣을 뿐입니다. 신호 처리기 안에서 libgpiod를 부르지 않습니다. 깃발의 형은 `volatile sig_atomic_t`입니다
- **본문이 깃발을 보고 나온다**: 반복문을 빠져나와 값을 inactive로 내고 줄을 놓습니다. `thrd_sleep`은 신호가 오면 다 자지 않고 돌아오므로 곧바로 반응합니다
- **`SIGTERM`도 받는다**: 서비스로 돌릴 때 systemd가 멈추라고 보내는 신호가 이것입니다
- **칩은 일찍 닫았다**: 요청을 받은 뒤에는 칩이 필요 없어서 반복문에 들어가기 전에 닫았습니다
- **더 꼼꼼한 길**: `signal` 대신 `sigaction`을 쓰는 법과 신호를 파일 서술자로 받는 법은 「리눅스 시스템 호출」에서 다룹니다

## 처리기가 돌지 못하는 끝

- **죽임과 전원**: `kill -9`, 프로그램의 죽음, 뽑힌 전원에는 처리기가 돌지 않습니다. 라즈베리파이에서는 핀이 마지막 값을 그대로 냅니다
- **안전은 회로로 만든다**: 멈추면 위험한 것은 프로그램이 죽어도 꺼지는 쪽으로 배선합니다. 핀이 입력으로 떠도 꺼진 쪽에 머물도록 풀다운을 달고([「풀업과 풀다운」](#/read/libgpiod/gp-pull)), 히터나 모터처럼 켜진 채 남으면 안 되는 것은 프로그램 밖에 끄는 장치를 둡니다([「릴레이와 트랜지스터 몰기」](#/read/libgpiod/out-relay))
- **다시 켰을 때**: 보드가 켜지는 동안 핀은 입력이고 기본 풀에 끌려 있습니다. 그 상태가 꺼짐이 되게 회로를 꾸밉니다

## 놓지 않으면

- **잃어버린 요청**: 요청 객체의 포인터를 잃으면 프로그램이 끝날 때까지 그 줄은 잠깁니다. 오래 도는 프로그램이 같은 줄을 다시 요청하면 제 손에 걸려 busy가 납니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))
- **오류로 빠져나가는 길에서도**: 함수가 중간에 돌아가는 모든 길에서 요청을 놓습니다

<Note>
예제는 이 책의 흉내 칩에서 두 번 돌린 것입니다. 한 번은 놓은 출력이 남는 쪽으로, 한 번은 입력으로 돌아가는 쪽으로 흉내 칩을 맞췄고, Ctrl+C는 2초에 오도록 대본에 넣었습니다. 라즈베리파이의 커널이 놓은 줄의 상태를 둔다는 것은 라즈베리파이의 GPIO 백서에서, `strict_gpiod`가 하는 일은 펌웨어 저장소의 overlays README에서 옮겼습니다. 진짜 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했습니다. 어느 쪽도 보드에서 확인하지 못했고, `strict_gpiod`가 4와 5에서 똑같이 듣는지도 알지 못합니다.
</Note>

## 정리

- `gpiod_line_request_release`로 놓고, 프로그램이 끝나면 커널이 놓는다. 줄의 상태는 쥐고 있는 동안만 보장된다
- 라즈베리파이의 커널은 놓은 출력을 그대로 두고, `dtparam=strict_gpiod`를 적으면 입력으로 되돌린다
- 끝낼 때는 신호를 받아 스스로 뜻한 값을 내고 놓는다. 처리기가 돌지 못하는 끝은 회로가 막는다
