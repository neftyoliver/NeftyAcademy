[「이더넷 프로토콜」](#/read/c-mid/net-ethernet)의 프레임은 깨지면 버려지고, IP 패킷은 순서가 바뀌거나 사라질 수 있습니다. **TCP**는 그 위에서 "보낸 바이트가 빠짐없이, 보낸 순서대로 도착한다"는 약속을 만들어 냅니다. 웹, 메일, SSH, 데이터베이스 연결이 모두 TCP 위에 있습니다. 이 쪽은 C의 소켓으로 서버와 클라이언트를 한 프로그램 안에 만들어 봅니다.

## TCP가 해 주는 일

- **연결**: 주고받기 전에 세 번 인사(SYN, SYN-ACK, ACK)해서 양쪽이 준비됐는지 확인한다
- **순서와 재전송**: 바이트마다 번호를 매기고, 받은 쪽이 "여기까지 받았다"(ACK)고 알린다. 답이 없으면 다시 보내고, 순서가 바뀌어 온 것은 받는 쪽이 맞춰 놓는다
- **흐름 제어와 혼잡 제어**: 받는 쪽이 처리할 수 있는 만큼, 네트워크가 견딜 수 있는 만큼만 보내도록 속도를 스스로 조절한다

대신 처음 인사하는 시간이 들고, 잃어버린 조각을 다시 받을 때까지 뒤의 데이터도 기다립니다. 늦게 와도 소용없는 데이터(실시간 음성, 게임 위치)에는 [「UDP」](#/read/c-mid/net-udp)가 낫습니다.

## 소켓 함수의 순서

| 서버 | 클라이언트 |
| --- | --- |
| `socket` → `bind`(주소·포트 정하기) → `listen` | `socket` |
| `accept`(누가 올 때까지 기다림) | `connect`(서버에 인사) |
| `recv` / `send` | `send` / `recv` |
| `close` | `close` |

`accept`는 연결 하나마다 **새 소켓**을 돌려줍니다. 처음 소켓은 계속 다음 손님을 기다리는 데 쓰고, 새 소켓으로 그 손님과 이야기합니다.

## 한 프로그램 안의 서버와 클라이언트

서버를 [「스레드 만들고 기다리기」](#/read/c-mid/thr-create)의 `thrd_create`로 띄우고, 같은 컴퓨터 안의 루프백 주소(127.0.0.1)로 접속합니다.

```c flags=-D_POSIX_C_SOURCE=200809L
#include <arpa/inet.h>
#include <netinet/in.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <threads.h>
#include <unistd.h>

// 원하는 만큼 다 올 때까지 되풀이해 읽는다
static int recv_all(int fd, void *buf, size_t n)
{
    char *p = buf;
    while (n > 0) {
        ssize_t r = recv(fd, p, n, 0);
        if (r <= 0)
            return -1;              // 0이면 상대가 연결을 닫았다
        p += r;
        n -= (size_t)r;
    }
    return 0;
}

static int send_msg(int fd, const char *s)
{
    uint32_t len = htonl((uint32_t)strlen(s));  // 길이를 네트워크 순서로
    if (send(fd, &len, 4, 0) != 4)
        return -1;
    return send(fd, s, strlen(s), 0) == (ssize_t)strlen(s) ? 0 : -1;
}

static int server(void *arg)
{
    int lfd = *(int *)arg;
    int c = accept(lfd, nullptr, nullptr);
    char buf[256];
    uint32_t len;
    int count = 0;
    while (recv_all(c, &len, 4) == 0) {
        len = ntohl(len);
        if (len >= sizeof buf || recv_all(c, buf, len) != 0)
            break;
        buf[len] = '\0';
        printf("메시지 %d: %s (%u바이트)\n", ++count, buf, len);
    }
    printf("상대가 닫음, 서버 끝\n");
    close(c);
    return 0;
}

int main(void)
{
    int lfd = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in a = {.sin_family = AF_INET,
                            .sin_addr.s_addr = htonl(INADDR_LOOPBACK),
                            .sin_port = 0};    // 0: 빈 포트를 아무거나
    socklen_t alen = sizeof a;
    if (bind(lfd, (struct sockaddr *)&a, sizeof a) != 0 || listen(lfd, 1) != 0)
        return 1;
    getsockname(lfd, (struct sockaddr *)&a, &alen);   // 받은 포트 알아내기

    thrd_t t;
    thrd_create(&t, server, &lfd);

    int fd = socket(AF_INET, SOCK_STREAM, 0);
    if (connect(fd, (struct sockaddr *)&a, sizeof a) != 0)
        return 1;
    const char *msgs[] = {"고양이", "꼬리 흔들기", "야옹"};
    for (int i = 0; i < 3; i++)
        send_msg(fd, msgs[i]);
    close(fd);                      // 다 보냈으면 닫는다

    thrd_join(t, nullptr);
    close(lfd);
    return 0;
}
```

```text
메시지 1: 고양이 (9바이트)
메시지 2: 꼬리 흔들기 (16바이트)
메시지 3: 야옹 (6바이트)
상대가 닫음, 서버 끝
```

- 포트를 0으로 `bind`하면 운영체제가 비어 있는 포트를 골라 주고, `getsockname`으로 무엇을 받았는지 알아냅니다. 시험할 때 "이미 쓰는 포트" 오류를 피하는 방법입니다
- 서버 스레드가 `accept`에 닿기 전에 클라이언트가 `connect`해도 괜찮습니다. `listen` 뒤부터는 커널이 인사를 대신 받아 줄 세워 두기 때문입니다
- 한글 "고양이"가 9바이트인 것은 UTF-8에서 한 글자가 3바이트라서입니다. 네트워크는 글자가 아니라 바이트를 나릅니다
- 클라이언트가 `close`하면 서버의 `recv`가 0을 돌려줍니다. 이것이 "상대가 다 보내고 닫았다"는 표시입니다

## 메시지의 경계는 없다

TCP는 **바이트의 흐름**만 약속합니다. `send`를 세 번 했다고 `recv`가 세 번에 나눠 받는 것이 아닙니다. 같은 루프백에서 서버가 0.1초 쉬었다가 `recv` 한 번을 부르게 하고, 클라이언트가 3바이트, 4바이트, 2바이트를 따로 보내 보았습니다. 다섯 번 모두 `recv` 한 번에 9바이트가 한꺼번에 왔습니다. 반대로 큰 데이터는 여러 번에 나뉘어 올 수도 있습니다.

그래서 위 예제는 메시지마다 **길이 4바이트를 앞에 붙이고**, 받는 쪽은 `recv_all`로 정확히 그만큼 모일 때까지 되풀이해 읽습니다. 길이는 `htonl`로 **네트워크 바이트 순서**(빅 엔디언)로 바꿔 보내고 `ntohl`로 되돌립니다. 보내는 쪽과 받는 쪽 CPU의 엔디언이 달라도 같은 값으로 읽히게 하는 약속입니다. 다른 방법으로는 HTTP처럼 줄바꿈으로 끝을 표시하는 것이 있습니다.

<Note kind="warn">
`send`도 요청한 바이트를 다 보내지 못하고 일부만 보냈다고 돌려줄 수 있습니다(특히 큰 데이터나 논블로킹 소켓). 실제 코드에서는 `recv_all`처럼 `send_all`도 만들어 되풀이합니다. 그리고 받은 길이 값을 믿지 말고, 위 예제의 `len >= sizeof buf` 검사처럼 상한을 확인해야 합니다. 상대가 길이를 40억이라고 보내면 메모리를 다 쓰거나 버퍼를 넘칠 수 있습니다.
</Note>

## 여러 손님 받기

위 서버는 손님 하나를 받고 끝납니다. 실제 서버는 손님이 여럿이므로 연결마다 스레드를 띄우거나, `poll`·`epoll`(리눅스), `kqueue`(BSD·macOS)로 소켓 여러 개를 한 스레드에서 지켜보다가 데이터가 온 소켓만 처리합니다. 수천 개의 연결을 다루는 서버는 거의 후자를 씁니다. libuv 같은 라이브러리가 운영체제마다 다른 이 방식을 하나로 감싸 줍니다.

## 정리

- TCP는 연결을 맺고 번호·확인·재전송으로 바이트가 빠짐없이 순서대로 오게 하며, 그 대가로 지연이 생길 수 있다
- 서버는 `socket`, `bind`, `listen`, `accept`, 클라이언트는 `socket`, `connect`의 순서이고, `recv`가 0이면 상대가 닫은 것이다
- TCP에는 메시지 경계가 없으므로 길이를 앞에 붙이거나 끝 표시를 정하고, 다 모일 때까지 되풀이해 읽는다
