윈도우는 [「POSIX와 ISO C」](#/read/basics/std-posix-c)에서 본 POSIX를 따르지 않습니다. 대신 **Win32 API**라는 자기만의 C 함수 묶음이 있고, 파일, 프로세스, 스레드, 창, 네트워크를 모두 이것으로 다룹니다. [「윈도우: Win32」](#/read/c-basic/win-win32)에서 창을 띄울 때 그 일부를 봤습니다. 이 쪽은 창 말고 시스템 쪽 Win32를 리눅스·POSIX와 견주며 정리합니다.

<Note kind="warn">
아래 예제는 리눅스에서 MinGW-w64(GCC 13)로 경고 없이 컴파일하고, 만든 `.exe`가 어떤 DLL을 가져오는지 확인한 데까지입니다. 윈도우에서 실행해 보지는 못했습니다. 윈도우 프로그램을 리눅스에서 돌려 주는 Wine도 깔아 봤지만 이 검사 기계의 환경에서는 실행되지 않았습니다.
</Note>

## windows.h와 핵심 DLL

Win32 함수는 `#include <windows.h>` 하나로 대부분 선언되고, 실제 구현은 윈도우에 들어 있는 DLL에 있습니다.

| DLL | 맡는 일 | 예 |
| --- | --- | --- |
| `kernel32.dll` | 파일, 메모리, 프로세스, 스레드 | `CreateFileW`, `CreateProcessW`, `CreateThread` |
| `user32.dll` | 창, 메시지, 입력 | `CreateWindowExW`, `MessageBoxW` |
| `gdi32.dll` | 2D 그리기 | `TextOutW`, `BitBlt` |
| `advapi32.dll` | 레지스트리, 보안, 서비스 | `RegOpenKeyExW` |
| `ws2_32.dll` | 네트워크 소켓 | `socket`, `WSAStartup` |
| `bcrypt.dll` | 암호와 난수 | `BCryptGenRandom` |

리눅스에서 C 라이브러리가 시스템 콜을 감싸 주듯, 윈도우에서는 이 DLL들이 커널(`ntdll.dll` 아래)을 감쌉니다. 윈도우의 진짜 시스템 콜 번호는 버전마다 바뀌어 공개된 약속이 아니므로, 프로그램은 반드시 이 DLL들을 거쳐야 합니다.

## A와 W, 그리고 UTF-16

Win32에는 같은 함수가 두 벌 있습니다. `CreateFileA`(A는 ANSI)와 `CreateFileW`(W는 wide)입니다.

| | `…A` 함수 | `…W` 함수 |
| --- | --- | --- |
| 글자 | `char`, 시스템의 옛 코드 페이지(한국어 윈도우는 CP949) | `wchar_t`, UTF-16 |
| 글자 상수 | `"메모.txt"` | `L"메모.txt"` |
| 권장 | 옛 코드와 맞출 때만 | 새 코드는 이쪽 |

[「ASCII와 유니코드」](#/read/basics/std-text)에서 윈도우 내부가 UTF-16이라고 했습니다. `A` 함수는 넘긴 글을 W로 바꿔 부르는 껍데기라서, 코드 페이지에 없는 글자(다른 나라 글자, 이모지)가 든 파일 이름은 다루지 못합니다. 헤더는 `CreateFile`처럼 끝 글자 없는 이름도 주는데, `UNICODE` 매크로가 정의돼 있으면 `W`, 아니면 `A`로 바뀝니다. 헷갈리지 않게 처음부터 `W` 이름을 직접 쓰는 것이 좋습니다.

## HANDLE과 GetLastError

```c nocheck
#include <windows.h>
#include <bcrypt.h>
#include <stdio.h>

int main(void)
{
    SetConsoleOutputCP(CP_UTF8);                   // 콘솔이 UTF-8을 찍게

    // 파일 만들고 쓰기: 이름은 UTF-16(L"...")으로 넘긴다
    HANDLE h = CreateFileW(L"메모.txt", GENERIC_WRITE, 0, NULL,
                           CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL);
    if (h == INVALID_HANDLE_VALUE) {
        printf("CreateFileW 실패: 오류 %lu\n", GetLastError());
        return 1;
    }
    const char text[] = "안녕\r\n";
    DWORD written = 0;
    WriteFile(h, text, (DWORD)(sizeof text - 1), &written, NULL);
    CloseHandle(h);
    printf("%lu바이트를 썼다\n", written);

    // 없는 파일을 열어 오류 번호 보기
    h = CreateFileW(L"없는파일.txt", GENERIC_READ, 0, NULL, OPEN_EXISTING, 0, NULL);
    if (h == INVALID_HANDLE_VALUE)
        printf("없는 파일: 오류 %lu (ERROR_FILE_NOT_FOUND = %ld)\n",
               GetLastError(), ERROR_FILE_NOT_FOUND);

    // 보안용 난수
    unsigned char key[8];
    if (BCryptGenRandom(NULL, key, sizeof key,
                        BCRYPT_USE_SYSTEM_PREFERRED_RNG) == 0)
        puts("BCryptGenRandom: 8바이트를 받았다");
    return 0;
}
```

```sh
x86_64-w64-mingw32-gcc -std=c17 -Wall -Wextra -Wpedantic -O2 \
    w.c -lbcrypt -o w.exe
```

만든 `w.exe`는 `bcrypt.dll`, `KERNEL32.dll`, `msvcrt.dll`을 가져옵니다([「PE」](#/read/c-mid/exe-pe)의 가져오기 표). POSIX와 견주면 이렇습니다.

| 하는 일 | POSIX | Win32 |
| --- | --- | --- |
| 열린 것을 가리키는 값 | 파일 기술자 `int` | `HANDLE` |
| 실패의 표시 | `-1` | `INVALID_HANDLE_VALUE` 또는 `NULL`(함수마다 다르다) |
| 실패의 까닭 | `errno` | `GetLastError()` |
| 닫기 | `close(fd)` | `CloseHandle(h)` |
| 파일 열기 | `open` | `CreateFileW` (여는 것도 "만들기"라고 부른다) |

`HANDLE`은 파일뿐 아니라 프로세스, 스레드, 이벤트, 뮤텍스를 모두 가리킵니다. 리눅스가 무엇이든 파일 기술자로 만들었던 것([「리눅스」](#/read/c-mid/plat-linux))과 같은 생각입니다. 실패했는지 보는 값이 함수마다 다르다는 점(어떤 것은 `NULL`, 어떤 것은 `INVALID_HANDLE_VALUE`)이 흔한 실수거리입니다.

## POSIX 대신 쓰는 것들

| 하고 싶은 일 | 리눅스·POSIX | 윈도우 |
| --- | --- | --- |
| 프로그램 띄우기 | `posix_spawn`, `fork`+`exec` | `CreateProcessW` (`fork`는 없다) |
| 스레드 | `pthread_create` | `CreateThread`, C11 `thrd_create` |
| 동적 라이브러리 열기 | `dlopen`, `dlsym` | `LoadLibraryW`, `GetProcAddress` |
| 파일 변경 알림 | `inotify` | `ReadDirectoryChangesW` |
| 많은 소켓 기다리기 | `epoll` | IOCP(입출력 완료 포트) |
| 보안용 난수 | `getrandom` | `BCryptGenRandom` |
| 설정 저장 | 설정 파일(`/etc`, `~/.config`) | 레지스트리, `%APPDATA%` 폴더 |

[「다른 프로그램을 띄우기」](#/read/c-mid/hack-launch)에서 말한 대로 `CreateProcessW`는 인자를 배열이 아니라 글 한 줄로 받으므로 따옴표 처리에 주의해야 합니다. 여러 OS를 함께 지원하는 프로그램은 이런 차이를 감추는 라이브러리를 쓰는 경우가 많습니다([「크로스플랫폼 앱 생태계」](#/read/c-mid/cross-platform)).

<Note kind="tip">
Win32 함수의 설명서는 마이크로소프트의 Learn 사이트에 함수마다 있고, 아래쪽 "Requirements" 표에 필요한 헤더, 가져오기 라이브러리(`Bcrypt.lib` 같은 것), 지원하는 가장 오래된 윈도우 버전이 적혀 있습니다. MinGW에서는 `.lib` 대신 `-lbcrypt`처럼 같은 이름으로 링크합니다.
</Note>

## 정리

- 윈도우는 POSIX 대신 Win32 API를 주며, `windows.h`로 선언하고 `kernel32.dll` 같은 시스템 DLL이 구현을 맡는다
- 문자열을 받는 함수는 A(옛 코드 페이지)와 W(UTF-16) 두 벌이 있고, 새 코드는 `L"…"` 글자와 `W` 함수를 쓴다
- 열린 것은 `HANDLE`, 실패의 까닭은 `GetLastError()`로 다루며, `fork`, `epoll` 같은 POSIX 기능에는 각각 윈도우의 짝이 있다
