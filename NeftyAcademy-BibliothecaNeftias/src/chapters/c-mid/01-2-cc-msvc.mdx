윈도우용 프로그램을 만드는 가장 흔한 컴파일러는 마이크로소프트의 MSVC입니다. 비주얼 스튜디오가 쓰는 컴파일러이고, [「윈도우: Win32」](#/read/c-basic/win-win32) 창 띄우기 예제도 이것으로 빌드하는 것이 기본입니다. 이 쪽은 MSVC를 명령 줄에서 쓰는 법과 GCC·Clang과 다른 점을 정리합니다.

<Note kind="warn">
이 책의 검사 기계는 리눅스라서 MSVC(`cl.exe`)를 직접 돌려 보지 못했습니다. `cl` 명령과 옵션은 마이크로소프트 문서를 기준으로 적었고, 실제로 돌린 것은 MSVC와 같은 옵션을 받는 LLVM의 `clang-cl`(18.1.3)입니다. 둘을 구분해 적었습니다.
</Note>

## 설치와 개발자 명령 창

MSVC는 비주얼 스튜디오에 들어 있습니다. 2025년 11월에 나온 비주얼 스튜디오 2026이 MSVC 빌드 도구 14.50(컴파일러 19.50)을 실었고, 그 뒤로 MSVC는 비주얼 스튜디오와 따로 1년에 두 번(5월과 11월) 새 버전이 나옵니다. 편집기 없이 컴파일러만 필요하면 "Build Tools for Visual Studio"만 깔아도 됩니다. 설치할 때 **"C++를 사용한 데스크톱 개발"** 묶음을 고르면 C 컴파일러와 윈도우 SDK가 함께 들어옵니다.

MSVC는 리눅스의 컴파일러처럼 아무 터미널에서나 쓸 수 없습니다. 헤더와 라이브러리의 위치를 알려 주는 환경 변수가 필요하기 때문입니다. 시작 메뉴의 **"Developer Command Prompt for VS 2026"**(또는 "Developer PowerShell")을 열면 그 변수들이 잡힌 창이 뜹니다. 거기서 `cl`이라고 치면 버전이 나옵니다.

## cl로 컴파일하기

```bat
cl /W4 /std:c17 hello.c
hello.exe
```

`cl`은 GCC나 Clang처럼 컴파일과 링크를 한 번에 합니다. 옵션은 `-` 대신 `/`로 시작합니다(`-`도 받습니다). 결과로 이런 파일이 생깁니다.

| 파일 | 뜻 | 리눅스에서 비슷한 것 |
| --- | --- | --- |
| `hello.obj` | 목적 파일(COFF 형식) | `hello.o`(ELF) |
| `hello.exe` | 실행 파일(PE 형식) | `hello`(ELF) |
| `hello.pdb` | 디버그 정보(`/Zi`를 줄 때) | 실행 파일 안의 DWARF |

실행 파일 형식의 차이는 [「PE」](#/read/c-mid/exe-pe)와 [「ELF」](#/read/c-mid/exe-elf)에서 봅니다.

## 옵션 맞대기

| 하고 싶은 일 | GCC·Clang | MSVC `cl` |
| --- | --- | --- |
| 결과 파일 이름 | `-o hello` | `/Fe:hello.exe` (목적 파일은 `/Fo`) |
| 컴파일만 | `-c` | `/c` |
| 경고 켜기 | `-Wall -Wextra` | `/W4` (`/Wall`은 너무 많다) |
| 경고를 오류로 | `-Werror` | `/WX` |
| 최적화 | `-O2` | `/O2` |
| 디버그 정보 | `-g` | `/Zi` |
| C 표준 | `-std=c17` | `/std:c11`, `/std:c17`, `/std:clatest` |
| 매크로 정의 | `-DNAME=1` | `/DNAME=1` |
| 헤더 폴더 | `-Iinclude` | `/Iinclude` |
| 주소 새니타이저 | `-fsanitize=address` | `/fsanitize=address` |

<Note>
MSVC는 오랫동안 C 지원이 C89에 머물러 C 개발자들의 불만을 샀습니다. 2020년(비주얼 스튜디오 2019 16.8)부터 C11과 C17을 지원하기 시작했고, C23은 `/std:clatest`로 일부만 쓸 수 있습니다. C11의 `threads.h`는 2023년(비주얼 스튜디오 2022 17.8)에야 들어왔고 복소수 타입(`_Complex`)은 지원하지 않으니, 윈도우까지 지원하는 C 코드는 쓰려는 기능이 MSVC에서 되는지 먼저 확인하는 것이 좋습니다.
</Note>

## C 런타임 고르기

윈도우에는 리눅스의 glibc 같은 C 라이브러리(C 런타임, CRT)가 프로그램에 붙는 방식이 두 가지 있습니다.

| 옵션 | 방식 | 특징 |
| --- | --- | --- |
| `/MD` | 런타임 DLL을 실행 시점에 불러온다 | 기본값. 실행 파일이 작다 |
| `/MT` | 런타임을 실행 파일에 합쳐 넣는다 | 다른 PC에 런타임이 없어도 돈다. 파일이 크다 |

`/MD`로 만든 프로그램을 다른 PC에 가져가면 "VCRUNTIME140.dll이 없습니다" 같은 오류가 날 수 있습니다. 그 PC에 "Visual C++ 재배포 가능 패키지"를 깔거나 `/MT`로 빌드하면 됩니다. 한 프로그램 안의 라이브러리들은 같은 방식으로 빌드해야 합니다. 섞으면 한쪽에서 `malloc`한 메모리를 다른 쪽에서 `free`할 때 망가질 수 있습니다. 라이브러리를 합치는 두 방식은 [「정적 라이브러리」](#/read/c-mid/lib-static)와 [「동적 라이브러리」](#/read/c-mid/lib-dynamic)에서 이어집니다.

## clang-cl로 들여다보기

LLVM에는 MSVC의 옵션을 그대로 받는 `clang-cl`이 있습니다. 리눅스에서도 윈도우용 목적 파일을 만들 수 있어서 MSVC 쪽 코드 생성을 엿볼 수 있습니다.

```c nocheck
int scale(int value, int percent)
{
    return value * percent / 100;
}
```

```sh
clang-cl /c /W4 /O2 /Fam.asm m.c
```

같은 함수를 리눅스용(`clang -O2`)과 견준 결과입니다(설명에 필요한 줄만).

```text nocheck
윈도우 (clang-cl)              리눅스 (clang)
scale:                         scale:
    imul  ecx, edx                 imul  edi, esi
    movsxd rax, ecx                movsxd rax, edi
    imul  rax, rax, 1374389535     imul  rax, rax, 1374389535
    ...                            ...
    ret                            ret
```

첫 줄이 다릅니다. **인자가 들어오는 레지스터**가 윈도우는 `ecx`, `edx`, 리눅스는 `edi`, `esi`입니다. 같은 x86-64 CPU라도 OS마다 호출 규약이 달라서, 리눅스용 목적 파일과 윈도우용 목적 파일은 섞어 링크할 수 없습니다. 이 약속을 [「ABI」](#/read/c-basic/abi)라고 불렀습니다. 나머지는 똑같습니다. 100으로 나누기를 `1374389535`를 곱하고 오른쪽으로 미는 것으로 바꾼 것도 같습니다(나눗셈이 곱셈보다 훨씬 느리기 때문입니다).

`file m.obj`로 보면 `Intel amd64 COFF object file`이라고 나옵니다. 윈도우 형식의 목적 파일입니다. 다만 `#include <stdio.h>` 같은 헤더는 윈도우 SDK와 MSVC가 있어야 해서, 리눅스의 `clang-cl`로 `hello.c`를 컴파일하면 `'stdio.h' file not found`로 멈춥니다. 실제 윈도우 프로그램은 윈도우에서 빌드하는 것이 가장 쉽습니다.

<Note kind="tip">
비주얼 스튜디오 2026에는 Clang(LLVM 20)도 선택 부품으로 들어 있습니다. 같은 코드를 MSVC와 Clang 두 컴파일러로 빌드해 보면 한쪽만 잡는 경고와 버그를 찾을 수 있습니다. 세 컴파일러를 함께 쓰는 법은 다음 쪽 [「GCC」](#/read/c-mid/cc-gcc)와 「크로스플랫폼 앱 생태계」에서 이어집니다.
</Note>

## 정리

- MSVC는 비주얼 스튜디오(또는 Build Tools)에 든 윈도우의 기본 C 컴파일러이고, 개발자 명령 창에서 `cl`로 쓴다
- `cl`의 옵션은 `/W4`, `/O2`, `/Zi`, `/std:c17`처럼 `/`로 시작하며, C 런타임을 DLL로 쓸지(`/MD`) 합쳐 넣을지(`/MT`) 골라야 한다
- 윈도우와 리눅스는 같은 x86-64라도 인자를 받는 레지스터(호출 규약)가 달라서 목적 파일을 섞어 쓸 수 없다
