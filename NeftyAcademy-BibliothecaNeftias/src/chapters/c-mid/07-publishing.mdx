프로그램을 다 만들었다면 이제 다른 사람이 쓸 수 있게 건네야 합니다. "내 컴퓨터에서는 되는데"를 넘어서려면 무엇을, 어떤 모양으로, 어떤 약속과 함께 건넬지 정해야 합니다. 이 쪽은 C 프로그램을 공개하는 흔한 길을 [「Makefile」](#/read/c-mid/build-make)의 작은 예제로 하나씩 밟아 봅니다.

## 무엇을 건넬까

| 건네는 것 | 받는 사람이 할 일 | 좋은 점 |
| --- | --- | --- |
| 소스 코드 | 직접 빌드한다 | 어떤 CPU, OS에서든 빌드할 수 있다. 고쳐 쓸 수 있다 |
| 실행 파일 | 내려받아 실행한다 | 컴파일러가 없어도 된다 |
| 패키지(`.deb`, 설치 프로그램) | 패키지 매니저로 깐다 | 설치, 삭제, 업데이트가 깔끔하다 |

오픈소스 프로젝트는 보통 셋을 모두 합니다. 소스는 깃허브 같은 곳에 두고, 버전마다 실행 파일과 패키지를 "릴리스"로 올립니다.

## 소스를 공개할 때

소스 저장소에 꼭 있어야 하는 파일이 있습니다.

| 파일 | 담는 것 |
| --- | --- |
| `LICENSE` | 남이 이 코드를 어떤 조건으로 쓸 수 있는지. 없으면 아무도 쓸 수 없다 |
| `README.md` | 무엇을 하는 프로그램인지, 빌드하는 법, 쓰는 법 |
| 빌드 파일 | `Makefile`이나 `CMakeLists.txt` |
| `.gitignore` | 빌드 결과(`.o`, 실행 파일)를 저장소에 넣지 않게 |

[「소프트웨어의 갈래」](#/read/basics/software-kinds)에서 본 대로 라이선스가 없는 코드는 "마음대로 써도 된다"가 아니라 "아무 권리도 주지 않은 것"입니다. 남의 라이브러리를 썼다면 그 라이선스가 내 프로그램을 공개하는 방식에 조건을 붙이는지도 확인해야 합니다. 특히 GPL 라이브러리를 [정적으로](#/read/c-mid/lib-static) 넣었다면 내 소스도 GPL로 공개해야 할 수 있습니다.

## 버전 번호

버전마다 이름을 붙여야 사용자가 "어느 버전의 버그인지", "업데이트해야 하는지"를 압니다. 가장 널리 쓰는 약속은 **유의적 버전**(Semantic Versioning)입니다.

```text
1.4.2
│ │ └─ 고침(patch): 버그만 고쳤다. 그냥 올려도 된다
│ └─── 기능(minor): 새 기능을 더했지만 옛 쓰임은 그대로 된다
└───── 주(major): 옛 쓰임이 깨진다. 올리기 전에 살펴봐야 한다
```

[「동적 라이브러리」](#/read/c-mid/lib-dynamic)의 soname이 주 번호만 따르는 것도 같은 생각입니다. 깃에서는 릴리스할 커밋에 `git tag v1.4.2`로 꼬리표를 붙여 둡니다([「Git 기초」](#/read/basics/git)).

## 실행 파일을 건넬 때

실행 파일은 **CPU와 OS마다 따로** 만들어야 합니다. [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)과 [「PE」](#/read/c-mid/exe-pe)에서 본 대로 하나의 PC에서도 여러 가지를 만들 수 있습니다.

| 받는 쪽 | 만드는 법 | 파일 이름의 예 |
| --- | --- | --- |
| 리눅스 PC | `gcc` | `clampdemo-1.0.0-linux-x86_64` |
| 라즈베리파이 64비트 | `aarch64-linux-gnu-gcc` | `clampdemo-1.0.0-linux-arm64` |
| 윈도우 | MSVC 또는 `x86_64-w64-mingw32-gcc` | `clampdemo-1.0.0-windows-x86_64.exe` |
| 맥 | 맥의 `clang`, 유니버설 바이너리로 | `clampdemo-1.0.0-macos-universal` |

리눅스 실행 파일은 빌드한 기계의 glibc보다 옛 glibc에서는 돌지 않을 수 있습니다([「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)의 함정). 그래서 리눅스용 실행 파일은 일부러 오래된 배포판에서 빌드하거나 정적으로 링크해 내놓기도 합니다.

## .deb 패키지 만들기

데비안 계열(우분투, 라즈베리파이 OS)에서는 `.deb` 패키지로 건네면 `apt`나 `dpkg`로 깔고 지울 수 있습니다. 가장 간단한 패키지는 폴더 하나와 설명 파일 하나로 만들어집니다.

```text
pkg/
├── DEBIAN/
│   └── control          패키지 설명
└── usr/
    └── bin/
        └── clampdemo    깔릴 자리 그대로
```

`pkg/DEBIAN/control`

```text
Package: clampdemo
Version: 1.0.0
Architecture: amd64
Maintainer: Nefty <nefty@example.com>
Depends: libc6 (>= 2.34)
Description: 값을 범위 안으로 자르는 작은 예제
```

```sh
dpkg-deb --build --root-owner-group pkg clampdemo_1.0.0_amd64.deb
sudo dpkg -i clampdemo_1.0.0_amd64.deb      # 깔기
clampdemo
sudo dpkg -r clampdemo                       # 지우기
```

```text nocheck
dpkg-deb: building package 'clampdemo' in 'clampdemo_1.0.0_amd64.deb'.
Setting up clampdemo (1.0.0) ...
0 42 100
```

2,690바이트짜리 패키지가 만들어졌고, 깔자 `/usr/bin/clampdemo`가 생겨 아무 폴더에서나 실행됐습니다. `dpkg -r`로 지우니 파일도 깨끗이 사라졌습니다. `Depends`의 `libc6 (>= 2.34)`는 [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)에서 `objdump -T`로 본 요구 버전(`GLIBC_2.34`)을 적은 것입니다. 라즈베리파이용은 `Architecture: arm64`로 따로 만듭니다. 정식 배포판에 들어가는 패키지는 소스에서 패키지를 만드는 규칙까지 갖춰야 해서 훨씬 복잡하지만, 내 기기들에 나눠 까는 정도라면 이것으로 충분합니다.

## 체크섬과 서명

내려받은 파일이 중간에 망가지거나 바뀌지 않았는지 확인할 수 있게, 릴리스에는 보통 **체크섬**을 함께 둡니다.

```text nocheck
$ sha256sum clampdemo_1.0.0_amd64.deb
633bb2cf5e556aec207163732f2b716f0fe9b18527d8199fdaafdb441dcf2115
  clampdemo_1.0.0_amd64.deb
```

(실제로는 한 줄에 나옵니다.) 받은 사람이 같은 명령을 돌려 같은 값이 나오면 같은 파일입니다. 패키지 안의 시각이 빌드마다 달라서, 같은 소스로 다시 만들어도 이 값은 바뀝니다. 다만 체크섬은 "같은 곳에서 받은 파일과 같다"만 보여 줄 뿐, 그곳이 진짜인지는 알려 주지 않습니다. 그래서 만든 사람의 열쇠로 **서명**도 합니다. 리눅스 배포판의 저장소는 GPG 서명을 쓰고, 윈도우는 실행 파일에 코드 서명(Authenticode)을 넣지 않으면 "알 수 없는 게시자" 경고를 띄웁니다. 맥은 서명에 더해 애플의 공증(notarization)까지 받지 않으면 인터넷에서 받은 앱의 실행을 막습니다([「Mach-O」](#/read/c-mid/exe-macho)).

<Note kind="tip">
릴리스 과정을 손으로 하면 언젠가 빠뜨립니다. 깃허브 액션 같은 CI에 "꼬리표를 붙이면 네 가지 실행 파일을 빌드하고, 체크섬을 만들어, 릴리스에 올린다"를 적어 두면 버전마다 같은 결과가 나옵니다. CI는 「C++ 고급」의 [「지속적 통합」](#/read/cpp-advanced/tool-ci)에서 다룹니다.
</Note>

## 정리

- 프로그램은 소스, 실행 파일, 패키지로 건넬 수 있고, 소스에는 라이선스와 빌드 방법을 반드시 함께 둔다
- 유의적 버전(주.기능.고침)으로 바뀐 정도를 알리고, 실행 파일은 CPU와 OS마다 따로 만들어 이름에 표시한다
- `.deb`는 `DEBIAN/control`과 깔릴 자리를 담은 폴더로 만들 수 있고, 릴리스에는 체크섬과 서명을 함께 둔다
