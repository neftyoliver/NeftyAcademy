**PCI Express**(PCIe)는 그래픽카드, NVMe SSD, 네트워크 카드처럼 빠른 장치를 CPU에 잇는 길입니다. 「컴퓨터의 입문」의 [「버스와 입출력」](#/read/basics/arch-bus-io)에서 큰 그림을 봤으니, 이 쪽은 운영체제가 PCIe 장치를 어떻게 찾고 알아보는지를 C로 직접 읽어 봅니다.

## 레인과 세대

PCIe 연결은 **레인**(lane) 여러 개로 됩니다. 레인 하나는 보내는 선 한 쌍과 받는 선 한 쌍이고, x1, x4, x16처럼 몇 개를 묶었는지로 너비를 말합니다. 세대가 올라갈 때마다 레인 하나의 빠르기가 대략 두 배가 됩니다.

| 세대 | 레인당 전송률 | x16 한 방향(부호화 손실 전) |
| --- | --- | --- |
| 3.0 | 8 GT/s | 16 GB/s |
| 4.0 | 16 GT/s | 32 GB/s |
| 5.0 | 32 GT/s | 64 GB/s |
| 6.0 | 64 GT/s | 128 GB/s |

7.0(128 GT/s) 규격은 2025년에 나왔고, 8.0은 아직 초안 단계입니다. 새 세대의 장치는 옛 슬롯에 꽂아도 낮은 쪽 세대와 너비로 맞춰서 동작합니다.

## 소프트웨어가 보기에는 PCI 그대로

PCIe는 선은 완전히 새로 만들었지만, 소프트웨어가 보는 모양은 옛 PCI 버스와 똑같이 남겨 두었습니다. 그래서 운영체제의 장치 찾기 방식이 그대로 통합니다.

- 장치마다 **버스:장치.기능**(BDF) 번호가 붙는다. `00:02.0`은 버스 0, 장치 2, 기능 0이다
- 각 기능에는 **설정 공간**이 있다. 앞 64바이트의 모양은 정해져 있고, PCI는 256바이트, PCIe는 4096바이트까지 쓴다
- 설정 공간의 **BAR**(Base Address Register)에 "이 장치의 레지스터를 메모리 몇 번지에 비춰 달라"를 적는다. 그 뒤로 드라이버는 그 주소를 읽고 쓰는 것으로 장치를 조종한다
- **능력 목록**(capability list)이 설정 공간 안에 연결 리스트로 이어져, 장치가 지원하는 기능(MSI-X 인터럽트, 전원 관리 등)을 알린다

## sysfs로 설정 공간 읽기

리눅스는 PCI 장치마다 `/sys/bus/pci/devices/<BDF>/config` 파일을 만들어, 설정 공간을 그대로 읽게 해 줍니다. 루트가 아니면 앞 64바이트만 보입니다.

```c flags=-D_DEFAULT_SOURCE
#include <dirent.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static uint16_t rd16(const uint8_t *c, int o)
{
    return (uint16_t)(c[o] | c[o + 1] << 8);
}

static const char *cap_name(uint8_t id)
{
    switch (id) {
    case 0x05: return "MSI";
    case 0x09: return "제조사 고유";
    case 0x10: return "PCIe";
    case 0x11: return "MSI-X";
    default: return "기타";
    }
}

int main(void)
{
    struct dirent **list;
    int count = scandir("/sys/bus/pci/devices", &list, nullptr, alphasort);
    if (count < 0) {
        perror("scandir");
        return 1;
    }
    for (int i = 0; i < count; i++) {
        struct dirent *e = list[i];
        if (e->d_name[0] == '.')
            continue;
        char path[300];
        snprintf(path, sizeof path, "/sys/bus/pci/devices/%s/config",
                 e->d_name);
        FILE *f = fopen(path, "rb");
        if (!f)
            continue;
        uint8_t c[256] = {0};
        size_t n = fread(c, 1, sizeof c, f);    // 설정 공간의 앞부분
        fclose(f);
        if (n < 64)
            continue;

        printf("%s %04x:%04x 종류 %02x%02x 머리 %u",
               e->d_name + 5, rd16(c, 0), rd16(c, 2), c[0x0B], c[0x0A],
               c[0x0E] & 0x7F);
        // 상태 레지스터 4번 비트가 서 있으면 능력 목록이 있다
        if ((rd16(c, 6) & 0x10) && n == sizeof c) {
            const char *last = nullptr;
            int same = 0;
            printf(" 능력:");
            for (uint8_t p = c[0x34] & 0xFC; p; p = c[p + 1] & 0xFC) {
                const char *name = cap_name(c[p]);
                if (last && strcmp(name, last) != 0) {
                    printf(" %s×%d", last, same);
                    same = 0;
                }
                last = name;
                same++;
            }
            if (last)
                printf(" %s×%d", last, same);
        }
        printf("\n");
    }
    for (int i = 0; i < count; i++)
        free(list[i]);
    free(list);
    return 0;
}
```

이 검사용 가상 머신의 장치들입니다. 진짜 PC에서 돌리면 그래픽카드, NVMe, USB 컨트롤러가 나옵니다.

- **0x0번 바이트의 제조사:장치 번호**: 8086은 인텔, 1af4는 레드햇입니다. 레드햇 번호의 장치들은 **virtio**, 곧 가상 머신을 위해 만든 가상 장치입니다. `lspci -nn`으로 보면 1042가 블록 장치(디스크), 1041이 네트워크, 1044가 난수 발생기로 나옵니다
- **종류(class)**: 0600은 호스트 브리지, 0180은 저장 장치, 0200은 이더넷입니다. 드라이버는 번호나 종류를 보고 붙습니다
- **능력 목록**: 상태 레지스터(6번)의 4번 비트가 "목록이 있다"는 표시이고, 0x34번 바이트가 첫 항목 위치, 각 항목의 다음 바이트가 다음 위치입니다. virtio 장치들은 "제조사 고유" 능력 다섯 개로 자기 레지스터 위치를 알리고, MSI-X로 인터럽트를 냅니다
- 이 가상 머신의 장치들은 PCIe 능력(0x10)이 없는 옛 PCI 모양입니다. 진짜 PCIe 장치라면 목록에 "PCIe"가 있고, 그 안에 지금 연결된 세대와 레인 수가 들어 있습니다. sysfs의 `current_link_speed`, `current_link_width` 파일로도 볼 수 있습니다

<Note>
설정 공간을 **쓰는** 것은 위험합니다. 잘못 쓰면 장치가 멈추거나 시스템이 다운됩니다. `setpci` 같은 도구도 무엇을 하는지 정확히 알 때만 씁니다. 장치 레지스터를 사용자 프로그램에서 직접 다루는 길(sysfs의 `resource0` 파일을 메모리에 비추기, VFIO)도 있지만, 대개는 커널 드라이버의 몫입니다.
</Note>

## 장치가 직접 메모리에 쓴다: DMA

빠른 장치는 CPU가 바이트를 하나하나 옮겨 주기를 기다리지 않습니다. 드라이버가 "이 메모리에 받아라"라고 주소를 알려 주면, 장치가 PCIe를 통해 **직접 메모리에 쓰고**(DMA) 다 되면 인터럽트로 알립니다. NVMe SSD와 네트워크 카드가 빠른 까닭입니다. 아무 장치나 아무 메모리에 쓰면 위험하므로, 요즘 컴퓨터는 IOMMU로 장치마다 쓸 수 있는 메모리를 제한합니다.

## 정리

- PCIe는 레인을 묶은 너비(x1~x16)와 세대로 빠르기가 정해지고, 세대마다 레인당 전송률이 대략 두 배가 된다
- 소프트웨어에게는 옛 PCI와 같은 모양이라, BDF 번호와 설정 공간의 제조사·장치 번호, 종류, BAR, 능력 목록으로 장치를 알아본다
- 리눅스에서는 sysfs의 `config` 파일로 설정 공간을 읽을 수 있고, 빠른 장치는 DMA로 메모리에 직접 쓴 뒤 인터럽트로 알린다
