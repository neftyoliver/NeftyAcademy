네트워크는 층으로 쌓여 있습니다. 맨 아래 층은 이웃한 기계끼리 한 덩어리, 곧 **프레임**을 건네는 일입니다. 유선 랜은 이 층에서 **이더넷** 형식을 쓰고, Wi-Fi는 자기 형식이 따로 있지만 운영체제에는 이더넷처럼 보이게 해 줍니다. 그 위에 IP가 "어느 컴퓨터로"를, 다시 그 위에 [「TCP」](#/read/c-mid/net-tcp)와 [「UDP」](#/read/c-mid/net-udp)가 "어느 프로그램으로"를 맡습니다. 이 쪽은 맨 아래 프레임을 바이트 하나까지 직접 짜 봅니다.

## 층 쌓기

| 층 | 주소 | 하는 일 |
| --- | --- | --- |
| 이더넷 | MAC 주소(6바이트) | 같은 랜 안의 이웃에게 프레임 건네기 |
| IP | IP 주소 | 여러 랜을 건너 목적지 컴퓨터까지 |
| TCP / UDP | 포트 번호 | 그 컴퓨터의 어느 프로그램인지 |
| 응용 | 이름, 경로 | HTTP, MQTT 같은 프로그램끼리의 약속 |

보낼 때는 위층의 데이터 앞에 아래층이 자기 머리를 하나씩 붙이고, 받을 때는 아래층부터 하나씩 떼어 냅니다. 웹 페이지 한 조각은 결국 이더넷 프레임 안의 IP 안의 TCP 안에 들어 있습니다.

## 프레임 하나 짜기

```c flags=-lz
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include <zlib.h>

static void print_mac(const char *label, const uint8_t *m)
{
    printf("%s %02x:%02x:%02x:%02x:%02x:%02x", label,
           m[0], m[1], m[2], m[3], m[4], m[5]);
    printf(" (%s, %s)\n", (m[0] & 1) ? "여럿에게" : "한 곳에",
           (m[0] & 2) ? "직접 정한 주소" : "제조사 주소");
}

int main(void)
{
    uint8_t f[64] = {0};
    const uint8_t dst[6] = {0xff, 0xff, 0xff, 0xff, 0xff, 0xff};
    const uint8_t src[6] = {0x02, 0xfc, 0x00, 0x00, 0x00, 0x01};
    memcpy(f, dst, 6);
    memcpy(f + 6, src, 6);
    f[12] = 0x88;                     // 종류 0x88B5: 실험용 번호
    f[13] = 0xB5;
    const char *msg = "hello, wire";
    memcpy(f + 14, msg, strlen(msg));

    size_t len = 60;                  // 짧으면 0으로 채워 60바이트
    uLong fcs = crc32(0L, f, (uInt)len);
    for (int i = 0; i < 4; i++)       // FCS는 낮은 바이트부터 붙는다
        f[len + (size_t)i] = (uint8_t)(fcs >> (8 * i));

    print_mac("받는 곳", f);
    print_mac("보낸 곳", f + 6);
    printf("종류 0x%02X%02X, 데이터 \"%s\"\n", f[12], f[13], (char *)f + 14);
    printf("틀 %zu바이트 + FCS %08lx = %zu바이트\n", len, fcs, len + 4);

    // 받는 쪽: FCS까지 넣고 CRC를 돌리면 늘 같은 값
    printf("FCS 포함 CRC %08lx\n", crc32(0L, f, (uInt)(len + 4)));
    f[20] ^= 0x01;                    // 선에서 한 비트가 뒤집혔다면
    printf("한 비트 깨진 뒤 %08lx\n", crc32(0L, f, (uInt)(len + 4)));
    return 0;
}
```

```text
받는 곳 ff:ff:ff:ff:ff:ff (여럿에게, 직접 정한 주소)
보낸 곳 02:fc:00:00:00:01 (한 곳에, 직접 정한 주소)
종류 0x88B5, 데이터 "hello, wire"
틀 60바이트 + FCS 4ef08965 = 64바이트
FCS 포함 CRC 2144df1c
한 비트 깨진 뒤 0b6ce77e
```

프레임은 앞에서부터 이렇게 생겼습니다.

| 자리 | 길이 | 내용 |
| --- | --- | --- |
| 받는 MAC | 6 | `ff:ff:ff:ff:ff:ff`는 랜 전체에 외치는 방송 주소 |
| 보낸 MAC | 6 | 보낸 네트워크 카드의 주소 |
| 종류(EtherType) | 2 | 안에 든 것: 0x0800은 IPv4, 0x86DD는 IPv6, 0x0806은 ARP |
| 데이터 | 46~1500 | 위층의 내용. 모자라면 0으로 채운다 |
| FCS | 4 | 깨졌는지 보는 CRC-32 |

- **MAC 주소**의 첫 바이트 맨 아래 비트가 1이면 여러 곳에 보내는 주소(멀티캐스트·방송)이고, 그다음 비트가 1이면 제조사가 아니라 사람이나 소프트웨어가 정한 주소입니다. 보낸 곳 `02:fc:...`는 이 검사용 가상 머신의 네트워크 카드 주소로, 0x02 비트가 서 있으니 가상 머신 관리 프로그램이 정한 것입니다. 휴대폰이 Wi-Fi마다 쓰는 무작위 MAC도 이 비트를 세웁니다
- 종류 0x88B5는 실험용으로 비워 둔 번호라 아무 프로토콜과도 겹치지 않습니다
- 머리 14바이트와 데이터를 합쳐 **최소 60바이트**(FCS까지 64바이트)여야 합니다. 그래서 짧은 데이터 뒤를 0으로 채웠습니다. 데이터의 최대 크기 1500바이트를 **MTU**라고 합니다
- **FCS**는 [「자주 쓰이는 C 생태계 라이브러리」](#/read/c-mid/common-libraries)에서 본 zlib의 `crc32`와 같은 계산입니다. Python으로 같은 바이트를 계산해도 `4ef08965`가 나왔습니다

받는 쪽 검사가 재미있습니다. FCS를 낮은 바이트부터 붙인 프레임 전체에 다시 CRC를 돌리면, 내용이 무엇이든 늘 `2144df1c`라는 같은 값이 남습니다. 네트워크 카드는 이 값인지만 보고 맞으면 받고, 아니면 조용히 버립니다. 한 비트만 뒤집혀도 전혀 다른 값이 됩니다. 이더넷은 깨진 프레임을 다시 보내 달라고 하지 않습니다. 잃어버린 것을 다시 보내는 일은 TCP의 몫입니다.

## 이 컴퓨터의 네트워크 카드

리눅스는 네트워크 장치를 `/sys/class/net/` 아래에 보여 줍니다. 이 검사용 가상 머신에서 읽어 본 값입니다.

```text nocheck
장치   MAC 주소             MTU    상태
eth0   02:fc:00:00:00:01    1400   up
lo     00:00:00:00:00:00    65536  unknown
```

`eth0`의 MTU가 1500이 아니라 1400인 것은, 가상 머신의 패킷이 바깥으로 나갈 때 다른 머리가 더 붙기 때문에(터널) 미리 줄여 둔 것으로 보입니다. `lo`는 자기 자신에게 보내는 가상 장치(루프백)라 진짜 선이 없고 MTU도 큽니다. 같은 정보는 `ip link` 명령이나 C의 `getifaddrs`로도 얻습니다.

<Note>
직접 짠 프레임을 실제로 내보내려면 리눅스의 `AF_PACKET` 소켓(raw 소켓)을 쓰는데, 관리자 권한(`CAP_NET_RAW`)이 필요하고, 남의 네트워크에서 함부로 보내면 안 됩니다. 프레임을 들여다보는 일은 Wireshark나 `tcpdump -e`로 하는 것이 안전하고 편합니다.
</Note>

## 정리

- 네트워크는 이더넷, IP, TCP·UDP, 응용의 층으로 쌓이고, 보낼 때마다 아래층이 머리를 하나씩 붙인다
- 이더넷 프레임은 받는 MAC, 보낸 MAC, 종류 번호, 46~1500바이트 데이터, CRC-32 FCS로 되어 있고 최소 64바이트다
- 받는 쪽은 FCS까지 CRC를 돌려 정해진 값이 남는지로 깨짐을 알아채고 버리며, 다시 보내기는 위층이 맡는다
