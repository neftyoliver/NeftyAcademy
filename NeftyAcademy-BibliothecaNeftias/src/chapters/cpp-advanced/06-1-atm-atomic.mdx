수 하나를 여러 스레드가 고칠 때는 [뮤텍스 대신 `std::atomic`](#/read/cpp-stl/conc-mutex)을 쓴다고 했습니다. [뮤텍스 자체도](#/read/cpp-advanced/sync-mutex) 이것으로 만들어집니다. 이 챕터는 그 바닥입니다. 먼저 `std::atomic`이 약속하는 것과 약속하지 않는 것을 가릅니다.

## 쪼개지지 않는 연산

`std::atomic<T>`의 연산 **하나**는 다른 스레드에게 "하기 전"과 "한 뒤"로만 보입니다. 반쯤 된 모습은 없고, 그래서 [자료 경합](#/read/cpp-stl/conc-thread)이 아닙니다.

```cpp
#include <atomic>
#include <print>
#include <thread>

struct Reading {
    int celsius;
    int humidity;
};

int main()
{
    std::atomic<int> one_step = 0;
    std::atomic<int> two_steps = 0;
    {
        auto work = [&] {
            for (int i = 0; i < 1'000'000; ++i) {
                ++one_step;                     // 원자적 연산 하나
                // 읽기 하나와 쓰기 하나. 사이에 틈이 있다
                two_steps = two_steps + 1;
            }
        };
        std::jthread a(work);
        std::jthread b(work);
    }
    std::println("++x         {}", one_step.load());
    std::println("x = x + 1   2000000 인가: {}", two_steps.load() == 2'000'000);

    // 8바이트 구조체도 통째로 원자적이다
    std::atomic<Reading> latest = Reading{21, 40};
    latest.store({22, 38});
    Reading seen = latest.load();
    std::println("{} {}", seen.celsius, seen.humidity);

    int old_value = one_step.exchange(0);           // 새 값을 넣고 옛 값을 받는다
    std::println("{} → {}", old_value, one_step.load());
}
```

```text
++x         2000000
x = x + 1   2000000 인가: false
22 38
2000000 → 0
```

`two_steps = two_steps + 1`은 원자적인 읽기와 원자적인 쓰기, **두** 연산입니다. 두 스레드가 같은 값을 읽고 각자 1을 더해 쓰면 하나가 사라집니다. 돌려 보면 155만에서 177만 사이가 나왔습니다. ThreadSanitizer는 이 코드에 아무 말도 하지 않습니다. 자료 경합(정의되지 않은 동작)은 없기 때문입니다. **경합이 없다는 것과 맞다는 것은 다릅니다.**

| 연산 | 뜻 |
| --- | --- |
| `load()`, `store(v)` | 읽기, 쓰기 |
| `exchange(v)` | 쓰고, 있던 값을 돌려준다 |
| `fetch_add`, `fetch_sub`, `++`, `--`, `+=`, `-=` | 더하고 빼기. 정수와 포인터, C++20부터 실수 |
| `fetch_and`, `fetch_or`, `fetch_xor` | 비트 연산. 정수만 |
| `compare_exchange_weak`, `compare_exchange_strong` | [예상한 값일 때만 바꾼다](#/read/cpp-advanced/atm-cas) |

이 표에 없는 것은 원자적으로 할 수 없습니다. 곱하기, 최댓값 갱신, "0보다 클 때만 빼기"는 읽고-계산하고-쓰는 사이에 틈이 생기므로 마지막 줄의 비교 후 교환으로 만듭니다.

## 기계에서는

| 연산 | x86-64 | AArch64 | 한 번의 값 (x86-64) |
| --- | --- | --- | --- |
| 읽기 | `mov` | `ldar` | 0.3 ns |
| 쓰기 | `xchg` | `stlr` | 5.8 ns |
| 더하기 | `lock add` | `ldaddal`, 또는 `ldaxr`·`stlxr` 고리 | 5.8 ns |
| 비교 후 교환 | `lock cmpxchg` | `casal`, 또는 고리 | 8.6 ns |

GCC 14 `-O2`가 만든 명령이고, 값은 x86-64 서버 VM에서 다투는 스레드 없이 잰 것입니다. 보통 변수에 1을 더하는 것(`add`)과 비교하면 `lock`이 붙은 명령은 열 배쯤 비쌉니다. 그 캐시 줄을 혼자 쥐고, 앞서 미뤄 둔 쓰기를 모두 끝낸 뒤에야 실행되기 때문입니다. 다투는 스레드가 있으면 여기에 [캐시 줄을 주고받는 값](#/read/cpp-advanced/atm-false-sharing)이 더해집니다.

AArch64에는 길이 둘 있습니다. 라즈베리 파이 5의 코어(ARMv8.2)에는 `ldaddal` 같은 명령 하나가 있고, 파이 4의 코어(ARMv8.0)에는 없어서 "읽고, 더하고, 그 사이에 아무도 안 건드렸으면 쓴다"를 될 때까지 되풀이합니다. GCC는 기본 설정에서 둘 다 되는 코드를 만듭니다. `__aarch64_ldadd4_acq_rel` 같은 작은 함수를 부르고, 그 함수가 실행 중에 CPU를 보고 고릅니다.

## 어떤 타입이 되나

`T`는 [통째로 복사해도 되는 타입](#/read/cpp-syntax/ct-assert)(trivially copyable)이어야 합니다. 정수, 실수, 포인터, `enum`, 그런 것들만 든 구조체입니다. `std::string`은 안 됩니다. 구조체는 **통째로만** 읽고 씁니다. `latest.celsius`처럼 멤버 하나를 고치는 길은 없습니다.

| 타입 | 크기 | 잠금 없이 되나 |
| --- | --- | --- |
| `atomic<bool>`, `atomic<int>`, `atomic<long long>`, `atomic<T*>`, `atomic<double>` | `T`와 같다 | 된다 |
| 8바이트 구조체 | 8 | 된다 |
| 16바이트 구조체 | 16 | GCC 14는 안 된다. Clang 20은 `-mcx16`을 주면 된다 |
| 32바이트 구조체 | 32 | 안 된다 |

x86-64와 AArch64에서 `is_lock_free()`로 물은 결과입니다. 잠금 없이 안 되는 타입도 **쓸 수는 있습니다.** 컴파일러의 보조 라이브러리가 안에서 잠금을 걸어 줍니다(GCC에서는 `-latomic`을 붙여 링크합니다). 원자적이라는 약속은 지켜지지만, 빠르리라는 기대와 [인터럽트 처리기에서 써도 된다](#/read/cpp-embedded/isr-atomic)는 보장은 사라집니다. 기대가 중요한 곳에는 한 줄을 적어 둡니다.

```cpp nocheck
static_assert(std::atomic<Reading>::is_always_lock_free);
```

## 원자적이어도 틀리는 것

| 코드 | 문제 | 고치는 법 |
| --- | --- | --- |
| `x = x + 1;` | 연산이 둘이다 | `++x` 또는 `x.fetch_add(1)` |
| `if (stock > 0) --stock;` | 확인과 빼기 사이의 틈 | [비교 후 교환](#/read/cpp-advanced/atm-cas) |
| `atomic<int> head, tail;`을 함께 바꾼다 | 둘 사이의 관계는 지켜지지 않는다 | 뮤텍스, 또는 한 값에 합친다 |
| `volatile int flag;` | `volatile`은 원자적이 아니다. 경합이다 | `std::atomic<int>` |
| `std::atomic<int> b = a;` | 복사도 이동도 없다. 컴파일 오류 | `b = a.load();` |

`volatile`은 [장치 레지스터처럼](#/read/cpp-embedded/reg-volatile) "읽고 쓸 때마다 정말로 메모리에 다녀와라"는 뜻입니다. 스레드 사이의 순서나 쪼개지지 않음은 약속하지 않습니다. C에서 넘어온 코드에 가장 흔한 오해입니다.

<Note>
보통 변수를 **잠깐만** 원자적으로 다루려면 C++20의 `std::atomic_ref<T>`를 씁니다. `std::atomic_ref<int> ref(plain); ref.fetch_add(1);`처럼 감싸서 쓰고, 그동안에는 그 변수를 `atomic_ref`를 거치지 않고 건드리면 안 됩니다. 깃발 하나에는 `std::atomic_flag`가 있습니다. 어느 플랫폼에서나 잠금 없이 된다고 표준이 보장하는 유일한 타입입니다.
</Note>

## 정리

- `std::atomic`의 연산 하나는 쪼개지지 않는다. 연산 둘을 이어 쓰면 그 사이는 지켜지지 않는다
- 읽기는 공짜에 가깝고, 쓰기와 더하기는 6 ns쯤이다. 8바이트까지는 어디서나 잠금 없이 된다
- `volatile`은 원자적이 아니다. 여러 값이 함께 맞아야 하는 상태는 여전히 뮤텍스의 일이다
