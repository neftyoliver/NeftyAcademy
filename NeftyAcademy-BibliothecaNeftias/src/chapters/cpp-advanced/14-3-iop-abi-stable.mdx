export const summary = '라이브러리만 바꿔 끼우면 옛 프로그램이 겪는 일 여섯 가지. 조용히 깨지는 까닭, 깨지 않고 키우는 법';

[pimpl](#/read/cpp-advanced/te-pimpl)과 [「구현마다 다른 ABI」](#/read/cpp-stl/impl-abi)에서 미뤄 둔 이야기입니다. 공유 라이브러리의 좋은 점은 **프로그램을 다시 빌드하지 않고 라이브러리만 새것으로 바꿀 수 있다**는 것입니다. 그러려면 새 라이브러리가 옛 프로그램과 바이너리 수준에서 맞아야 합니다. 이것이 ABI 안정성입니다. 맞지 않으면 무슨 일이 생기는지 직접 바꿔 끼워 봅니다.

## 바꿔 끼워 보기

```cpp nocheck
// motor.h (1.0)
#pragma once

class Motor {
public:
    Motor();
    virtual ~Motor();
    virtual void start();
    virtual void stop();
    void set_speed(int rpm, int ramp_ms = 100);
    int id() const { return id_; }          // 헤더에 본문이 있다

private:
    int id_;
    int rpm_;
};

enum class Mode { Idle, Run };
const char* name_of(Mode mode);
```

```cpp nocheck
// app.cpp: 1.0의 헤더로 컴파일해 두고 다시 컴파일하지 않는다
#include "motor.h"

#include <print>

[[gnu::noinline]] void run(Motor& motor)
{
    motor.start();
    motor.set_speed(600);
    motor.stop();
}

int main()
{
    Motor motor;
    run(motor);
    std::println("프로그램: id {}, 모드 {}", motor.id(), name_of(Mode::Run));
}
```

```text nocheck
라이브러리: start
라이브러리: 600 rpm, 100 ms 동안
라이브러리: stop
프로그램: id 7, 모드 Run
```

`app`은 이대로 두고 `libmotor.so.1`만 여섯 번 바꿨습니다. 한 번에 한 가지씩 고친 2.0입니다.

| 2.0에서 고친 것 | 다시 빌드하지 않은 `app`이 겪은 일 |
| --- | --- |
| 가상 함수 `pause()`를 `start`와 `stop` 사이에 끼웠다 | `stop()`을 불렀는데 **`pause`가 실행됐다** |
| 멤버 `double calibration_`을 `id_` 앞에 더했다 | `id()`가 7이 아니라 0을 돌려줬다. 생성자는 객체 밖의 스택에 썼다 |
| 기본 인자를 100에서 500으로 바꿨다 | 여전히 100이 넘어갔다 |
| `rpm`의 타입을 `int`에서 `long`으로 바꿨다 | `symbol lookup error: undefined symbol: _ZN5Motor9set_speedEii` |
| 열거자 `Calibrate`를 `Idle`과 `Run` 사이에 끼웠다 | `Mode::Run`을 넘겼는데 라이브러리는 `Calibrate`로 읽었다 |
| 함수 `speed()`를 더하고 `stop`의 구현을 고쳤다 | 문제없다. 새 구현이 바로 쓰였다 |

여섯 가운데 넷이 깨졌고, **오류로 알려 준 것은 하나뿐**입니다. 나머지는 틀린 채로 끝까지 돌았습니다. 둘째 줄의 스택 쓰기는 AddressSanitizer를 켜야 `stack-buffer-overflow … in Motor::Motor()`로 보입니다.

## 왜 조용한가

프로그램을 컴파일할 때 헤더에서 읽은 것이 기계어에 숫자로 박힙니다. 라이브러리를 올릴 때 맞춰 보는 것은 **이름뿐**입니다.

| 프로그램에 박히는 것 | 그래서 깨는 변화 |
| --- | --- |
| 객체의 크기, 멤버의 자리 | 멤버를 더하거나 빼거나 순서를 바꾼다 |
| 가상 함수의 번호 | 가상 함수를 더하거나 순서를 바꾼다 |
| 기본 인자, 열거자의 값, 상수 | 값을 바꾼다 |
| 헤더에 본문이 있는 함수와 템플릿 | 본문을 고친다. 옛 프로그램은 옛 본문을 그대로 쓴다 |
| 함수의 이름 (인자 타입이 새겨져 있다) | 시그니처를 바꾼다. 이것만 올릴 때 걸린다 |

## 깨지 않고 키우기

| 방법 | 지키는 것 |
| --- | --- |
| [pimpl](#/read/cpp-advanced/te-pimpl), [속을 가린 핸들](#/read/cpp-advanced/iop-c-abi) | 크기와 멤버의 자리. 속은 마음대로 바꾼다 |
| 고치지 않고 더한다 | 있던 함수는 그대로 두고 새 이름의 함수를 더한다 |
| 헤더에는 선언만 둔다 | 본문은 `.cpp`에. [내보인 것](#/read/cpp-advanced/iop-shared)이 적을수록 묶이는 것도 적다 |
| 구조체의 맨 앞에 크기를 둔다 | 뒤에 멤버를 더해도 옛 프로그램을 알아본다 (아래) |
| 깰 때는 이름을 바꾼다 | `libmotor.so.1`을 `libmotor.so.2`로. 옛 프로그램은 옛것을 계속 쓴다 |

넷째 줄을 프로그램 하나로 흉내 냅니다.

```cpp
#include <algorithm>
#include <cstdint>
#include <cstring>
#include <print>

// 1.0의 헤더로 컴파일된 프로그램이 아는 모양
struct OptionsV1 {
    std::uint32_t size;      // 부르는 쪽이 sizeof를 적어 넣는다
    std::int32_t rate;
};

// 2.0의 헤더. 뒤에만 더했다
struct Options {
    std::uint32_t size;
    std::int32_t rate;
    std::int32_t channels;
    std::int32_t gain;
};

// 2.0의 라이브러리. 옛 프로그램과 새 프로그램을 모두 받는다
void configure(const void* given)
{
    Options options{sizeof(Options), 0, 1, 10};      // 새 멤버의 기본값
    std::uint32_t size = 0;
    std::memcpy(&size, given, sizeof size);          // 맨 앞의 크기부터 읽는다
    std::memcpy(&options, given, std::min<std::size_t>(size, sizeof options));
    std::println("rate {}, channels {}, gain {} (받은 크기 {})", options.rate,
                 options.channels, options.gain, size);
}

int main()
{
    const OptionsV1 old_caller{sizeof(OptionsV1), 48000};
    configure(&old_caller);                          // 1.0의 프로그램
    const Options new_caller{sizeof(Options), 96000, 2, 20};
    configure(&new_caller);                          // 2.0의 프로그램
}
```

```text
rate 48000, channels 1, gain 10 (받은 크기 8)
rate 96000, channels 2, gain 20 (받은 크기 16)
```

라이브러리는 받은 크기만큼만 읽고 나머지는 기본값으로 둡니다. 지킬 약속은 둘입니다. 뒤에만 더하고, 있던 멤버의 뜻을 바꾸지 않습니다.

다섯째 줄의 이름은 공유 라이브러리 안에 적힌 `SONAME`입니다. 프로그램은 링크할 때 그 이름을 기억합니다.

```text nocheck
$ g++ -fPIC -shared -Wl,-soname,libmotor.so.1 motor.cpp -o libmotor.so.1
$ readelf -d app | grep NEEDED
 0x0000000000000001 (NEEDED)             Shared library: [libmotor.so.1]
```

## 도구에게 묻기

두 판을 견주는 일은 `abidiff`(libabigail)가 합니다. 디버그 정보(`-g`)를 넣어 빌드한 두 파일을 주면 됩니다.

```text nocheck
$ abidiff lib_v1.so lib_a.so        # 1.0과, pause()를 끼운 2.0
1 Added function:
  [A] 'method virtual void Motor::pause()'    {_ZN5Motor5pauseEv}
    note that this adds a new entry to the vtable of class Motor
… (줄임. 들여쓰기도 줄였다)
  the vtable offset of method virtual void Motor::stop() changed from 3 to 4
    note that this is an ABI incompatible change to the vtable of class Motor
```

위의 여섯 가운데 다섯을 알아봤습니다. 멤버를 더한 것은 `type size changed from 128 to 192 (in bits)`로, 함수만 더한 것은 `2 Added functions`로 나옵니다. **기본 인자를 바꾼 것은 차이 없음**으로 나왔습니다. 바이너리에 없는 정보이기 때문입니다. 헤더에 있는 본문을 고친 것도 같은 까닭으로 보이지 않습니다.

<Note>
표준 라이브러리도 이 약속에 묶여 있습니다. libstdc++가 `std::string`의 속을 바꾸면서 [이름을 `__cxx11`로 갈아 둔 것](#/read/cpp-stl/impl-abi)이 "깰 때는 이름을 바꾼다"의 예입니다. 내 라이브러리의 경계에 `std::string`을 두면 그 약속까지 함께 떠안습니다.
</Note>

## 정리

- 프로그램에는 크기, 멤버의 자리, 가상 함수의 번호, 기본 인자, 열거자의 값이 박힌다. 올릴 때 맞춰 보는 것은 이름뿐이다
- 여섯 가지를 바꿔 끼워 넷이 깨졌고 오류는 하나였다. `stop()`이 `pause()`를 부르고 `id()`가 0을 돌려줬다
- 속을 가리고, 고치지 않고 더하고, 깰 때는 `SONAME`을 올린다. `abidiff`가 대부분을 찾지만 기본 인자는 못 본다
