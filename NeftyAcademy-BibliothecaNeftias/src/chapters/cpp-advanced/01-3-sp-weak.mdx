[`weak_ptr`의 기본](#/read/cpp-stl/mem-shared)은 "주인 수를 올리지 않고 지켜보다가, 쓸 때 `lock()`으로 잠깐 주인이 된다"였습니다. 문법은 그것이 전부입니다. 어려운 것은 **어디에 `shared_ptr`를 두고 어디에 `weak_ptr`를 두느냐**이고, 그것은 설계의 문제입니다.

## 방향을 정한다

`shared_ptr`로 이어진 객체들은 **가진다**는 화살표로 이어진 그림입니다. 그 화살표를 따라 한 바퀴 돌아 제자리로 올 수 있으면 그 고리는 영영 지워지지 않습니다. 그래서 규칙은 하나입니다. **가진다는 화살표는 한 방향으로만** 흐르게 하고, 거슬러 가는 화살표는 `weak_ptr`로 둡니다.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Node {
    std::string name;
    std::vector<std::shared_ptr<Node>> children;    // 아래로: 가진다
    std::weak_ptr<Node> parent;                     // 위로: 지켜본다

    explicit Node(std::string n) : name(std::move(n)) {}
    ~Node() { std::println("  ~Node {}", name); }
};

void attach(const std::shared_ptr<Node>& parent, const std::shared_ptr<Node>& child)
{
    child->parent = parent;
    parent->children.push_back(child);
}

// 부모를 거슬러 올라가며 경로를 만든다
std::string path_of(const Node& node)
{
    if (const auto up = node.parent.lock())
        return path_of(*up) + "/" + node.name;
    return node.name;
}

int main()
{
    std::weak_ptr<Node> watch;
    {
        const auto root = std::make_shared<Node>("root");
        const auto usb = std::make_shared<Node>("usb");
        const auto camera = std::make_shared<Node>("camera");
        attach(root, usb);
        attach(usb, camera);

        std::println("{}", path_of(*camera));
        std::println("주인 수: root {} usb {} camera {}", root.use_count(),
                     usb.use_count(), camera.use_count());
        watch = camera;
    }
    std::println("모두 지워졌나 {}", watch.expired());
}
```

```text
root/usb/camera
주인 수: root 1 usb 2 camera 2
  ~Node root
  ~Node usb
  ~Node camera
모두 지워졌나 true
```

부모가 자식을 갖고, 자식은 부모를 지켜봅니다. 뿌리를 놓으면 위에서부터 차례로 지워집니다.

| 관계 | 가지는 쪽 (`shared_ptr`, `unique_ptr`) | 지켜보는 쪽 (`weak_ptr`, 맨 포인터) |
| --- | --- | --- |
| 나무 | 부모 → 자식 | 자식 → 부모 |
| 이중 연결 리스트 | 앞 → 뒤 | 뒤 → 앞 |
| 관찰자 | 구독한 쪽이 구독권을 | 알리는 쪽 → 구독자 |
| 캐시 | 쓰는 쪽 → 항목 | 캐시 → 항목 |

위 예제의 자식은 **주인이 부모 하나뿐**입니다. 그렇다면 `children`은 `std::vector<std::unique_ptr<Node>>`로 충분하고, `parent`는 맨 포인터 `Node*`로 둘 수 있습니다. 부모가 자식보다 먼저 사라지지 않는다는 것이 구조에서 보장되기 때문입니다. `weak_ptr`가 정말 필요한 때는 **지켜보는 대상이 나보다 먼저 사라질 수 있을 때**입니다. 화살표를 그려 보고, `shared_ptr`가 꼭 필요한지부터 묻습니다.

## 람다가 만드는 순환

그림에 보이지 않는 화살표가 있습니다. **람다의 캡처**입니다.

```cpp nosan
#include <functional>
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Button {
    std::string name;
    std::function<void()> on_click;

    explicit Button(std::string n) : name(std::move(n)) {}
    ~Button() { std::println("  ~Button {}", name); }
};

int main()
{
    std::println("자기 자신을 붙든 콜백:");
    {
        const auto button = std::make_shared<Button>("ok");
        // 버튼이 콜백을 갖고, 콜백이 버튼을 갖는다
        button->on_click = [button] { std::println("  {} 눌림", button->name); };
        std::println("  주인 수 {}", button.use_count());
    }
    std::println("약하게 붙든 콜백:");
    {
        const auto button = std::make_shared<Button>("cancel");
        button->on_click = [weak = std::weak_ptr(button)] {
            if (const auto self = weak.lock())
                std::println("  {} 눌림", self->name);
        };
        button->on_click();
        std::println("  주인 수 {}", button.use_count());
    }
    std::println("끝");
}
```

```text
자기 자신을 붙든 콜백:
  주인 수 2
약하게 붙든 콜백:
  cancel 눌림
  주인 수 1
  ~Button cancel
끝
```

`ok` 버튼의 소멸자는 불리지 않았습니다. 객체가 **자기 멤버에 저장한 콜백**이 자기 자신의 `shared_ptr`를 캡처하면 고리가 됩니다. 타이머, 이벤트 처리기, 비동기 완료 콜백을 멤버로 들고 있는 클래스에서 흔한 누수입니다. 자기 자신을 가리키는 캡처는 `weak_ptr`로 하고, 부를 때 `lock()`으로 확인합니다.

콜백을 **남에게** 맡길 때는 사정이 다릅니다. 이벤트 루프나 스레드 풀에 넘긴 콜백이 `shared_ptr`를 캡처하는 것은 "콜백이 불릴 때까지 나를 살려 둔다"는 뜻이고, 콜백이 불리고 버려지면 고리가 끊깁니다. [다음 페이지](#/read/cpp-advanced/sp-from-this)에서 그 꼴을 봅니다.

## 저절로 빠지는 구독

알리는 쪽이 구독자를 `weak_ptr`로 들고 있으면, 구독자가 사라졌을 때 **해지를 부르지 않아도** 알림이 멈춥니다.

```cpp
#include <cstddef>
#include <functional>
#include <memory>
#include <print>
#include <utility>
#include <vector>

class Thermometer {
public:
    using Listener = std::function<void(double)>;

    // 구독권을 돌려준다. 구독권이 살아 있는 동안만 알림이 간다
    [[nodiscard]] std::shared_ptr<void> subscribe(Listener listener)
    {
        auto token = std::make_shared<Listener>(std::move(listener));
        listeners_.push_back(token);
        return token;
    }

    void publish(double value)
    {
        // 살아 있는 구독자에게 알리고, 사라진 것은 걷어 낸다
        std::erase_if(listeners_, [value](const std::weak_ptr<Listener>& weak) {
            if (const auto listener = weak.lock()) {
                (*listener)(value);
                return false;
            }
            return true;
        });
    }
    std::size_t count() const { return listeners_.size(); }

private:
    std::vector<std::weak_ptr<Listener>> listeners_;
};

int main()
{
    Thermometer thermometer;
    const auto display = thermometer.subscribe([](double v) {
        std::println("  화면: {}", v);
    });
    {
        const auto logger = thermometer.subscribe([](double v) {
            std::println("  기록: {}", v);
        });
        thermometer.publish(21.5);
        std::println("구독 {}", thermometer.count());
    }   // logger 의 구독권이 사라진다
    thermometer.publish(22.0);
    std::println("구독 {}", thermometer.count());
}
```

```text
  화면: 21.5
  기록: 21.5
구독 2
  화면: 22
구독 1
```

구독권의 타입이 `std::shared_ptr<void>`인 것은 [앞 페이지](#/read/cpp-advanced/sp-shared)에서 본 성질을 쓴 것입니다. 받는 쪽은 안에 무엇이 들었는지 모르고, 들고 있다가 놓기만 하면 됩니다. `[[nodiscard]]`는 반환값을 받지 않아 구독이 곧바로 사라지는 실수를 경고로 잡습니다.

## lock은 수명을 늘린다

`lock()`이 돌려준 `shared_ptr`는 진짜 주인입니다. 그것을 들고 있는 동안 객체는 사라지지 않습니다.

```cpp
#include <memory>
#include <print>

struct Job {
    ~Job() { std::println("  ~Job"); }
};

int main()
{
    auto job = std::make_shared<Job>();
    const std::weak_ptr<Job> watcher = job;
    {
        const auto pinned = watcher.lock();
        job.reset();                    // 마지막 "진짜" 주인이 놓았다
        std::println("job 을 놓았다. 아직 살아 있나 {}", !watcher.expired());
    }                                   // pinned 가 사라지며 지워진다
    std::println("pinned 가 사라진 뒤 {}", !watcher.expired());
}
```

```text
job 을 놓았다. 아직 살아 있나 true
  ~Job
pinned 가 사라진 뒤 false
```

두 가지 결론이 나옵니다.

- `lock()`의 결과는 **쓰는 동안만** 지역 변수로 들고 있습니다. 멤버에 저장해 두면 지켜보려던 것이 붙드는 것으로 바뀌고, 순환이 되살아납니다
- 객체가 지워지는 **때와 스레드**가 달라질 수 있습니다. 위에서 `Job`은 `job.reset()`이 아니라 `pinned`가 사라지는 곳에서 지워졌습니다. 다른 스레드가 `lock()`으로 붙들고 있었다면 소멸자는 그 스레드에서 돕니다. 소멸자가 특정 스레드에서만 해야 하는 일(화면 자원 해제 등)을 한다면 `shared_ptr`로 수명을 맡기기 전에 이것을 따져 봅니다

<Note>
`weak_ptr`를 `std::map`의 열쇠로 쓰려면 비교 기준으로 `std::owner_less<>`를 줍니다. 가리키는 주소가 아니라 **제어 블록**으로 순서를 매기므로, 대상이 지워진 뒤에도 같은 자리에서 찾아집니다. 누수를 찾는 데는 `-fsanitize=address`가 가장 빠릅니다. 프로그램이 끝날 때 남은 고리를 할당된 자리의 호출 경로와 함께 알려 줍니다.
</Note>

## 정리

- 가진다는 화살표는 한 방향으로만 흐르게 한다. 거슬러 가는 쪽은 `weak_ptr`로 두고, 주인이 하나뿐이면 `unique_ptr`와 맨 포인터로 충분한지 먼저 본다
- 멤버에 저장한 콜백이 자기 자신의 `shared_ptr`를 캡처하면 고리가 된다. 자기 자신은 약하게 캡처한다
- `lock()`의 결과는 진짜 주인이다. 쓰는 동안만 지역 변수로 들고, 객체가 지워지는 때와 스레드가 달라질 수 있음을 기억한다
