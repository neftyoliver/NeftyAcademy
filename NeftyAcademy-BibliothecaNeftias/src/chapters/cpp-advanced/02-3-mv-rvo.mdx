[「std::move와 복사 생략」](#/read/cpp-syntax/sm-elision)에서 "임시 객체는 반드시, 이름 있는 지역 변수는 대개 생략된다"고 했습니다. 앞의 것을 RVO, 뒤의 것을 NRVO(named RVO)라고 부릅니다. 여기서는 생략이 기계에서 무엇인지, 그리고 **"대개"가 깨지는 자리**를 봅니다.

## 호출자가 자리를 준다

작은 구조체는 레지스터에 실려 돌아옵니다. 그보다 큰 것은 **호출자가 스택에 자리를 잡아 그 주소를 넘기고**, 함수는 거기에 씁니다. 소스에는 보이지 않는 인자가 하나 더 있는 셈입니다.

| 돌려주는 타입 | x86-64 | AArch64 (라즈베리 파이) |
| --- | --- | --- |
| 16바이트까지의 단순한 구조체 | `rax`, `rdx` (실수는 `xmm0`, `xmm1`) | `x0`, `x1` (실수는 `d0`, `d1`) |
| 그보다 큰 구조체 | 호출자가 준 주소 (`rdi`) | 호출자가 준 주소 (`x8`) |
| 소멸자나 복사 생성자를 직접 가진 타입 | 크기와 상관없이 주소 | 크기와 상관없이 주소 |

GCC 14 `-O2`가 만든 코드로 확인한 것입니다(8, 16, 17, 32바이트 구조체와 소멸자를 가진 4바이트 구조체). `std::string`과 `std::vector`는 셋째 줄에 듭니다. 생략은 이 구조 위에서 "지역 변수를 **처음부터 그 주소에** 만든다"는 뜻입니다.

```cpp
#include <array>
#include <cstdint>
#include <print>

struct Big {
    std::array<long, 32> values{};
};

std::uintptr_t seen_in_callee = 0;

Big make()
{
    Big result;                     // 이름 있는 지역 변수
    result.values[0] = 42;
    seen_in_callee = reinterpret_cast<std::uintptr_t>(&result);
    return result;
}

int main()
{
    Big received = make();
    auto here = reinterpret_cast<std::uintptr_t>(&received);
    std::println("같은 자리인가: {}", seen_in_callee == here);
}
```

```text
같은 자리인가: true
```

`make` 안의 `result`와 `main`의 `received`는 주소가 같습니다. 객체가 하나뿐이므로 복사할 것도 옮길 것도 없습니다. GCC에 `-fno-elide-constructors`를 주면 `false`가 됩니다.

## 생략되는 반환과 안 되는 반환

```cpp
#include <print>
#include <utility>

struct Tracer {
    Tracer() { std::println("    생성"); }
    Tracer(const Tracer&) { std::println("    복사"); }
    Tracer(Tracer&&) noexcept { std::println("    이동"); }
    ~Tracer() {}
};

Tracer plain() { return Tracer(); }
Tracer named() { Tracer t; return t; }

Tracer two_names(bool flag)
{
    Tracer a;
    Tracer b;
    if (flag) return a;
    return b;
}

Tracer early(bool flag)
{
    if (flag) return Tracer();
    Tracer t;
    return t;
}

Tracer from_param(Tracer t) { return t; }

Tracer ternary(bool flag)
{
    Tracer a;
    Tracer b;
    return flag ? a : b;
}

struct Holder {
    Tracer member;
    Tracer get() const { return member; }
    Tracer take() && { return std::move(member); }
};

int main()
{
    std::println("1. 임시 객체");           Tracer t1 = plain();
    std::println("2. 지역 변수 하나");      Tracer t2 = named();
    std::println("3. 갈래마다 다른 변수");  Tracer t3 = two_names(true);
    std::println("4. 임시 객체와 변수");    Tracer t4 = early(false);
    std::println("5. 매개변수");            Tracer t5 = from_param(Tracer());
    std::println("6. 조건 연산자");         Tracer t6 = ternary(true);
    std::println("7. 멤버");                Holder h; Tracer t7 = h.get();
    std::println("8. 사라질 객체의 멤버");  Tracer t8 = Holder().take();
}
```

```text
1. 임시 객체
    생성
2. 지역 변수 하나
    생성
3. 갈래마다 다른 변수
    생성
    생성
    이동
4. 임시 객체와 변수
    생성
    이동
5. 매개변수
    생성
    이동
6. 조건 연산자
    생성
    생성
    복사
7. 멤버
    생성
    복사
8. 사라질 객체의 멤버
    생성
    이동
```

| 번호 | 일어난 일 | 까닭 |
| --- | --- | --- |
| 1 | 생략 | [prvalue](#/read/cpp-advanced/mv-categories)다. 규칙이므로 어느 컴파일러에서나 같다 |
| 2 | 생략 (NRVO) | 허용일 뿐이지만 GCC와 Clang은 `-O0`에서도 한다 |
| 3 | 이동 | 돌려줄 자리는 하나인데 거기에 만들 후보가 둘이다 |
| 4 | 이동 (Clang 20은 생략) | 컴파일러마다 다르다 |
| 5 | 이동 | 매개변수는 호출자가 다른 자리에 이미 만들었다 |
| 6 | **복사** | `flag ? a : b`는 이름이 아니라 식이다 |
| 7 | **복사** | 멤버는 함수가 끝나도 남는다. 가져가면 안 된다 |
| 8 | 이동 | `*this`가 사라질 객체임을 알고 직접 `std::move`를 적었다 |

3번을 생략되게 하려면 변수를 하나로 줄입니다. `Tracer result;`를 하나 두고 갈래마다 그것을 채운 뒤 `return result;` 하나로 끝냅니다. 6번은 `if`로 풀어 쓰면 3번처럼 이동이 됩니다.

## 저절로 이동되는 조건

3번과 5번에서 `std::move`를 적지 않았는데 이동이 되었습니다. `return` 뒤에 **지역 변수나 매개변수의 이름만** 적으면, 생략하지 못할 때 컴파일러가 그것을 우측값으로 다룹니다. 이름 "만"이 조건입니다.

| `return` 뒤에 적은 것 | 결과 |
| --- | --- |
| 지역 변수나 값 매개변수의 이름 | 생략 또는 이동 |
| 반환 타입과 다른 타입의 지역 변수 (`optional<T>`를 돌려주며 `return t;`) | 이동 |
| `T&&` 매개변수의 이름 | C++20부터 이동. GCC 14의 `-std=c++17`에서는 복사 |
| 지역 변수를 가리키는 참조 (`T& r = t; return r;`) | 복사 |
| 구조체를 푼 구조적 바인딩의 이름 | 복사 |
| `pair`·`tuple`을 푼 구조적 바인딩의 이름 | GCC 14는 이동, Clang 20은 복사 |
| `static` 변수, 멤버, 람다가 값으로 캡처한 변수 | 복사 |
| `const` 지역 변수 | 생략되면 그대로. 생략되지 않으면 복사 |

모두 위의 `Tracer`로 찍어 확인한 결과입니다. 표의 아래쪽에 드는 것을 옮겨서 돌려주려면 `return std::move(x);`라고 직접 적습니다. 반대로 위의 두 줄에 `std::move`를 적으면 손해이거나 헛일이고, 컴파일러가 알려 줍니다.

```text
warning: moving a local object in a return statement prevents copy elision
         [-Wpessimizing-move]
warning: redundant move in return statement [-Wredundant-move]
```

앞의 것은 지역 변수에 적었을 때(`-Wall`), 뒤의 것은 매개변수에 적었을 때(`-Wextra`) 나옵니다.

<Note>
`return {a, b};`는 반환할 객체를 중괄호 안의 값으로 **바로** 초기화합니다. 임시 객체를 만들어 옮기는 것이 아닙니다. `return std::pair(a, b);`도 prvalue라 같습니다. 다만 `a`와 `b` 자신은 그 안으로 복사되므로, 다 쓴 것이면 `return {std::move(a), std::move(b)};`라고 적습니다.
</Note>

## 그래도 바깥 변수에 채우는 쪽이 빠를 때

생략은 **복사**를 없앨 뿐, 객체를 **만드는** 비용은 그대로입니다. 반복문 안에서 부르는 함수가 매번 글자열을 새로 만들어 돌려주면 매번 메모리를 할당합니다. 바깥의 변수를 넘겨 채우게 하면 한 번 잡은 메모리를 다시 씁니다.

| 55자쯤 되는 글자열을 500만 번 | 걸린 시간 | 한 번에 |
| --- | --- | --- |
| `std::string s = make_line(i);` | 350 ms | 70 ns |
| `s = make_line(i);` (바깥의 `s`에 대입) | 350 ms | 70 ns |
| `fill_line(s, i);` (`std::string&`로 받아 채운다) | 75 ms | 15 ns |

x86-64 서버 VM, GCC 14 `-O2`에서 잰 값입니다. 둘째 줄이 첫째 줄과 같은 것은, 이동 대입이 `s`가 쥐고 있던 메모리를 버리고 새것을 받아 오기 때문입니다. `int` 1000개짜리 `std::vector`로 100만 번 하면 145 ms와 100 ms로, 채우는 일이 클수록 차이는 줄어듭니다.

`std::getline(in, line)`, `std::to_chars(first, last, value)`, `std::format_to(out, …)`가 받아서 채우는 꼴인 까닭이 이것입니다. 기본은 값으로 돌려주는 것이고, **같은 버퍼를 되풀이해 쓰는 뜨거운 반복문**에서만 채우는 꼴을 고릅니다.

## 정리

- 큰 객체와 소멸자를 가진 객체는 호출자가 준 주소에 만들어진다. 생략은 지역 변수를 처음부터 거기에 만드는 것이다
- 이름 하나를 그대로 돌려주면 생략되거나 이동된다. 조건 연산자, 멤버, 참조, 구조적 바인딩은 복사된다
- 생략은 만드는 비용까지 없애지 못한다. 메모리를 다시 쓸 수 있는 반복문에서는 채우는 꼴이 빠르다
