export const summary = '연산이 값 대신 식을 돌려주게 해서 임시 객체를 없애는 기법, 잰 값, auto가 무는 곳';

`d = a + b * 2.0 + c`를 벡터 타입에 대해 쓰고 싶습니다. `operator+`가 새 벡터를 돌려주면 수식처럼 읽히지만 연산마다 임시 벡터가 생깁니다. **표현식 템플릿**은 연산이 계산한 값 대신 "무엇을 계산할지"를 적은 작은 객체를 돌려주게 하고, 대입할 때 한 번에 계산합니다.

## 식을 타입으로 적는다

```cpp
#include <concepts>
#include <cstddef>
#include <cstdlib>
#include <new>
#include <print>
#include <type_traits>
#include <vector>

static long allocations = 0;
void* operator new(std::size_t size)
{
    ++allocations;
    return std::malloc(size);
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

// 1. 곧이곧대로: 연산마다 새 벡터를 만든다
struct Plain {
    std::vector<double> data;
};
Plain operator+(const Plain& a, const Plain& b)
{
    Plain result{std::vector<double>(a.data.size())};
    for (std::size_t i = 0; i < a.data.size(); ++i)
        result.data[i] = a.data[i] + b.data[i];
    return result;
}
Plain operator*(const Plain& a, double k)
{
    Plain result{std::vector<double>(a.data.size())};
    for (std::size_t i = 0; i < a.data.size(); ++i)
        result.data[i] = a.data[i] * k;
    return result;
}

// 2. 표현식 템플릿: 연산은 할 일을 적은 작은 객체를 돌려준다
struct ExprTag {};
template <typename T>
concept Expr = std::derived_from<T, ExprTag>;

// 잎(Vec)은 참조로, 중간 마디는 값으로 든다
template <typename E>
using Operand = std::conditional_t<E::is_leaf, const E&, E>;

template <Expr L, Expr R>
struct Sum : ExprTag {
    static constexpr bool is_leaf = false;
    Operand<L> left;
    Operand<R> right;
    double operator[](std::size_t i) const { return left[i] + right[i]; }
};
template <Expr E>
struct Scaled : ExprTag {
    static constexpr bool is_leaf = false;
    Operand<E> inner;
    double factor;
    double operator[](std::size_t i) const { return inner[i] * factor; }
};

class Vec : public ExprTag {
public:
    static constexpr bool is_leaf = true;
    explicit Vec(std::size_t n, double v = 0) : data_(n, v) {}

    // 식을 대입받을 때 한 번에 계산한다
    template <Expr E>
    Vec& operator=(const E& expr)
    {
        for (std::size_t i = 0; i < data_.size(); ++i)
            data_[i] = expr[i];
        return *this;
    }
    double operator[](std::size_t i) const { return data_[i]; }

private:
    std::vector<double> data_;
};

template <Expr L, Expr R>
Sum<L, R> operator+(const L& l, const R& r) { return {{}, l, r}; }
template <Expr E>
Scaled<E> operator*(const E& e, double k) { return {{}, e, k}; }

int main()
{
    const std::size_t n = 1000;
    Plain pa{std::vector<double>(n, 1)}, pb{std::vector<double>(n, 2)};
    Plain pc{std::vector<double>(n, 3)}, pd{std::vector<double>(n)};
    Vec a(n, 1), b(n, 2), c(n, 3), d(n);

    long before = allocations;
    pd = pa + pb * 2.0 + pc;
    std::println("곧이곧대로: {}, 할당 {}번", pd.data[0], allocations - before);

    before = allocations;
    d = a + b * 2.0 + c;
    std::println("표현식 템플릿: {}, 할당 {}번", d[0], allocations - before);

    auto expr = a + b * 2.0 + c;   // 아직 아무것도 계산하지 않았다
    std::println("식의 크기 {}바이트, 500번째 원소 {}", sizeof(expr), expr[500]);
}
```

```text
곧이곧대로: 8, 할당 3번
표현식 템플릿: 8, 할당 0번
식의 크기 40바이트, 500번째 원소 8
```

`a + b * 2.0 + c`의 타입은 `Vec`이 아니라 `Sum<Sum<Vec, Scaled<Vec>>, Vec>`입니다. **식의 나무가 타입에 그대로 적혀 있습니다.** 객체에는 잎을 가리키는 참조 셋과 `2.0`이 들어 있을 뿐입니다. 40바이트가 그것입니다.

계산은 `Vec::operator=`의 루프에서 일어납니다. `expr[i]`는 `Sum`의 `operator[]`를 부르고 그것이 다시 양쪽의 `operator[]`를 부르지만, 모두 타입이 정해진 작은 함수라 인라인되어 `a[i] + b[i] * 2.0 + c[i]` 한 줄이 됩니다.

`operator+`를 `Expr` 콘셉트로 묶어 둔 것도 중요합니다. 제약 없는 `template <typename L, typename R> operator+`는 세상의 모든 타입에 끼어듭니다.

## 잰 값

`d = a + b * 2.0 + c` 한 번의 시간입니다. x86-64, GCC 14, `-O2`입니다.

| 원소 수 | 곧이곧대로 | 표현식 템플릿 | 손으로 쓴 루프 |
| --- | --- | --- | --- |
| 1,000 | 1.0 µs | 0.4 µs | 0.4 µs |
| 1,000,000 | 3,570 µs | 1,230 µs | 1,240 µs |

표현식 템플릿은 손으로 쓴 루프와 같습니다. 곧이곧대로 쓴 쪽은 세 배가 듭니다. 임시 벡터 셋을 잡고, 같은 메모리를 네 번 훑기 때문입니다. Clang 20에서도 같은 비율이었습니다.

## auto가 무는 곳

식 객체는 잎을 **참조로** 들고 있습니다. 그래서 식을 변수에 담아 두면 위험합니다.

```cpp nocheck
Vec make();

Vec a(4, 1.0);
auto e = a + make();        // make()가 돌려준 임시 객체는 이 줄에서 사라진다
std::println("{}", e[0]);   // 사라진 것을 읽는다
```

```text nocheck
==6356==ERROR: AddressSanitizer: stack-use-after-scope on address 0x7efcd15000a0
READ of size 8 at 0x7efcd15000a0 thread T0
    #1 ... in Vec::operator[](unsigned long) const
    #2 ... in Sum<Vec, Vec>::operator[](unsigned long) const
    #3 ... in main
```

`Vec e = a + make();`였다면 그 줄에서 계산이 끝나므로 문제가 없습니다. `auto`가 식의 타입을 그대로 받아 계산을 미룬 것이 탈입니다. GCC 14는 `-O2 -Wall`에서 `-Wdangling-pointer`로 경고했고 실행하면 세그멘테이션 오류로 죽었습니다. Clang 20은 경고 없이 틀린 값 `1`을 찍었습니다.

| 함정 | 생기는 일 | 대비 |
| --- | --- | --- |
| `auto e = a + b;` | 계산되지 않은 식이 담긴다. 잎이 사라지면 매달린 참조 | 결과 타입을 적는다. `Vec e = a + b;` |
| `auto e = a + b;`를 여러 번 읽는다 | 읽을 때마다 다시 계산한다 | 위와 같다 |
| 왼쪽과 오른쪽에 같은 변수 | 원소끼리의 연산은 괜찮다. 행렬 곱처럼 다른 자리를 읽는 연산은 쓰면서 읽게 된다 | 그런 연산은 임시 객체에 계산한 뒤 옮긴다 |
| 오류 메시지 | 타입 이름이 식만큼 길어진다 | 콘셉트로 입구에서 막는다 |

예제의 `Operand`가 잎만 참조로 들고 중간 마디는 값으로 드는 것도 같은 문제 때문입니다. `b * 2.0`이 만든 `Scaled` 객체는 임시 객체라서, 바깥의 `Sum`이 그것을 참조로 들면 식을 변수에 담는 순간 매달립니다.

## 지금은 어디에 있는가

직접 만들 일은 드뭅니다. 이미 쓰고 있는 것들이 이 기법입니다.

| 어디 | 무엇 | 확인한 것 |
| --- | --- | --- |
| [범위의 뷰](#/read/cpp-stl/rng-views) | `views::transform`, `views::zip_transform`이 돌려주는 것이 식 객체다 | 같은 계산이 1,450 µs, 할당 0번 (GCC 14) |
| `std::valarray` | 표준이 이 기법을 쓰도록 허락한 수치 배열 | 1,460 µs, 할당 0번. libc++도 0번 |
| Eigen, Blaze, xtensor | 선형 대수 라이브러리. 식을 보고 더 빠른 루틴으로 바꿔 부르기도 한다 | 재지 않았다 |

"뷰를 변수에 담아 두면 밑의 컨테이너보다 오래 살 수 있다"는 [뷰의 함정](#/read/cpp-stl/rng-views)이 위의 `auto` 함정과 같은 것입니다. 식을 들고 다니는 타입은 모두 이 성질을 가집니다.

<Note>
직접 만들 만한 때는 수식 모양이 중요한 작은 영역 언어입니다. 단위가 붙은 물리량, 행렬과 벡터, 고정 소수점 필터 같은 것입니다. 그럴 때도 먼저 `constexpr` 함수와 보통 루프로 충분하지 않은지 봅니다. 임시 객체의 값은 [이동](#/read/cpp-advanced/mv-rvo)이 들어오면서 예전보다 작아졌습니다.
</Note>

## 정리

- 표현식 템플릿은 연산의 결과로 식의 나무를 타입에 적은 작은 객체를 돌려주고, 대입할 때 한 번에 계산한다
- 임시 객체와 여러 번 훑기가 사라져 손으로 쓴 루프와 같아진다. 예제에서는 세 배였다
- 식 객체는 잎을 참조로 든다. `auto`로 받아 두지 말고 결과 타입으로 받는다
