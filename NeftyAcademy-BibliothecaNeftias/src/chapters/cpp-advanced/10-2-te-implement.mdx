export const summary = '상속을 래퍼 안에 숨겨, 물려받지 않은 타입들을 값으로 섞어 담는 타입을 직접 만든다';

[앞 페이지](#/read/cpp-advanced/te-compare)의 표에는 빈자리가 있었습니다. 목록이 열려 있으면서, 타입들이 부모를 물려받지 않고, 값으로 복사되는 길입니다. `std::function`이 "부를 수 있는 것"에 대해 하는 일이 그것입니다. 람다든 함수 포인터든 서명만 맞으면 담고, 값처럼 복사됩니다. 같은 일을 **내 인터페이스**에 대해 하는 기법을 타입 지우기(type erasure)라고 부릅니다.

## 상속을 안으로 숨긴다

```cpp
#include <concepts>
#include <memory>
#include <print>
#include <utility>
#include <vector>

// 기본: 멤버 함수를 부른다. 멤버가 없는 타입은 오버로드로 맞춘다
template <typename T>
double area_of(const T& shape)
{
    return shape.area();
}

class Shape {
public:
    // 넓이를 구할 수 있는 타입이면 무엇이든 받는다
    template <typename T>
        requires requires(const T& t) {
            { area_of(t) } -> std::convertible_to<double>;
        }
    Shape(T value) : self_(std::make_unique<Model<T>>(std::move(value)))
    {
    }

    Shape(const Shape& other) : self_(other.self_->clone()) {}
    Shape(Shape&&) noexcept = default;
    Shape& operator=(Shape other) noexcept
    {
        self_ = std::move(other.self_);
        return *this;
    }

    double area() const { return self_->area(); }

private:
    // 안쪽의 인터페이스. 바깥에서는 보이지 않는다
    struct Concept {
        virtual ~Concept() = default;
        virtual double area() const = 0;
        virtual std::unique_ptr<Concept> clone() const = 0;
    };
    // T를 감싸 인터페이스에 맞춘다. 타입마다 컴파일러가 만들어 준다
    template <typename T>
    struct Model final : Concept {
        T value;
        explicit Model(T v) : value(std::move(v)) {}
        double area() const override { return area_of(value); }
        std::unique_ptr<Concept> clone() const override
        {
            return std::make_unique<Model>(*this);
        }
    };

    std::unique_ptr<Concept> self_;
};

// 쓰는 쪽의 타입들. 아무것도 물려받지 않는다
struct Circle {
    double r;
    double area() const { return 3.14159 * r * r; }
};
struct Rect {
    double w, h;
    double area() const { return w * h; }
};
// 남의 라이브러리에서 온 타입. area()가 없다
struct LegacySquare {
    double side;
};
double area_of(const LegacySquare& s) { return s.side * s.side; }

int main()
{
    std::vector<Shape> shapes;
    shapes.push_back(Circle{1});
    shapes.push_back(Rect{2, 3});
    shapes.push_back(LegacySquare{4});

    std::vector<Shape> copy = shapes;   // 값이다. 통째로 복사된다
    copy[0] = Rect{10, 10};

    for (const Shape& shape : shapes)
        std::print("{:.2f} ", shape.area());
    std::println("/ 사본의 첫째 {:.2f}", copy[0].area());
    std::println("Shape의 크기 {}바이트", sizeof(Shape));
}
```

```text
3.14 6.00 16.00 / 사본의 첫째 100.00
Shape의 크기 8바이트
```

가상 함수와 상속은 그대로 있습니다. 다만 **쓰는 쪽의 타입이 아니라 래퍼가** 물려받습니다. 세 겹입니다.

| 겹 | 하는 일 | 누가 쓰는가 |
| --- | --- | --- |
| `Shape` | 값처럼 보이는 바깥 타입. 복사, 이동, 대입을 갖춘다 | 쓰는 사람이 보는 것은 이것뿐이다 |
| `Concept` | 순수 가상 함수로 적은 안쪽 인터페이스 | 한 번 쓴다 |
| `Model<T>` | `T`를 품고 `Concept`의 함수를 `T`의 것으로 잇는다 | 컴파일러가 타입마다 만든다 |

`Circle`을 `Shape`에 넣는 순간 생성자 템플릿이 `Model<Circle>`을 만듭니다. 그 뒤로 `Shape`는 `Circle`이라는 타입을 모릅니다. 타입이 지워졌다는 말이 여기서 나옵니다.

`area()`를 `area_of(value)`로 부른 것도 눈여겨볼 곳입니다. 멤버 함수가 없는 `LegacySquare`가 오버로드 하나로 들어왔습니다. 남의 타입을 **고치지 않고** 내 인터페이스에 맞출 수 있습니다. 상속으로는 안 되는 일입니다.

## 얻는 것과 치르는 것

| | 가상 함수를 그대로 | 타입 지우기 |
| --- | --- | --- |
| 타입이 갖출 것 | 부모를 물려받는다 | 필요한 함수가 있으면 된다. 없으면 바깥에서 맞춘다 |
| 다루는 꼴 | `unique_ptr<부모>`. 복사하려면 `clone()`을 손으로 부른다 | 값. `=`로 복사되고 컨테이너에 그냥 담긴다 |
| `int` 같은 기본 타입 | 담을 수 없다 | 바깥에서 맞춰 주면 담을 수 있다 |
| 인터페이스를 고칠 때 | 부모와 모든 자식 | `Concept`, `Model`, 바깥 함수의 세 곳. 쓰는 쪽 타입은 그대로다 |

값은 앞 페이지의 표에 한 줄을 더하면 보입니다. 도형 1만 개, GCC 14, `-O2`입니다.

| 방식 | 섞였을 때 호출 | 모았을 때 호출 | 1만 개의 복사 |
| --- | --- | --- | --- |
| 가상 함수와 `unique_ptr` | 6.8 ns | 2.2 ns | 복사할 수 없다 |
| 위의 `Shape` | 6.8 ns | 2.2 ns | 190~450 µs, 할당 10,001번 |
| `variant` | 2.6 ns | 0.54 ns | 6.8 µs, 할당 1번 |

호출은 가상 함수와 **똑같습니다.** 속이 가상 함수이니 당연합니다. 값처럼 쓰는 편리함의 값은 복사에서 치릅니다. 원소마다 `clone()`이 힙을 잡습니다. 이 할당을 없애는 것이 [다음 페이지](#/read/cpp-advanced/te-sbo)의 주제입니다.

## 같은 기법의 다른 모양

| 모양 | 속 | 본 곳 |
| --- | --- | --- |
| 가진다, 복사한다 | 위의 예제. `std::function`, `std::any` | [`function`](#/read/cpp-stl/voc-function), [`any`](#/read/cpp-stl/voc-any) |
| 가진다, 옮기기만 한다 | `clone()`이 없다. `std::move_only_function` | [스레드 풀의 일](#/read/cpp-advanced/asy-pool) |
| 가리키기만 한다 | 객체의 주소 하나와 함수 포인터 하나. `std::function_ref` | [`function_ref`](#/read/cpp-stl/voc-function) |
| 일부만 지운다 | `shared_ptr<T>`의 삭제자와 할당자. `T`는 남고 그것들만 지워진다 | [제어 블록](#/read/cpp-advanced/sp-shared) |

함수 인자로 받아 그 자리에서 쓰고 말 것이면 셋째 모양이 맞습니다. 할당도 복사도 없습니다.

<Note>
C++26 초안에는 `std::polymorphic<T>`가 있습니다. 부모 포인터처럼 자식을 담되 **값처럼 복사되는** 타입입니다. 위 예제에서 `unique_ptr<Concept>`와 `clone()`이 하던 일을 맡아 줍니다. 초안의 기능 확인 매크로는 `__cpp_lib_polymorphic`이고, 이 책의 GCC 14와 Clang 20에는 아직 없습니다.
</Note>

<Note kind="warn">
생성자 템플릿은 반드시 좁힙니다. 제약이 없으면 `Shape`로 바뀔 수 있는 것이 "모든 타입"이 되어, 엉뚱한 오버로드 고르기에 끼어들고 오류가 `Model` 깊숙한 곳에서 납니다. 위에서는 `requires`로 "넓이를 구할 수 있는 타입"만 받았습니다.
</Note>

## 정리

- 타입 지우기는 상속을 래퍼 안의 `Concept`와 `Model<T>`로 옮긴다. 쓰는 쪽 타입은 물려받지 않고, 바깥 타입은 값처럼 복사된다
- 호출의 값은 가상 함수와 같다. 복사할 때 원소마다 힙을 잡는 것이 더 드는 값이다
- 받아서 쓰기만 할 때는 가리키기만 하는 모양(`function_ref`)을, 목록이 닫혀 있으면 `variant`를 먼저 생각한다
