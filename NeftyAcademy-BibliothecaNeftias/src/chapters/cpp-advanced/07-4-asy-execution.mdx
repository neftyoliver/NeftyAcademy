[`future`가 못 하는 일](#/read/cpp-advanced/asy-future)은 셋이었습니다. 끝나면 이어서 하기, 여럿 가운데 먼저 끝난 것 고르기, 그만두게 하기입니다. C++26 초안의 `std::execution`은 이어 붙이기와 그만두기를 처음부터 갖춘 틀입니다. 다만 이 페이지는 다른 페이지와 사정이 다릅니다. **표준의 예제를 이 책의 환경에서 돌려 보지 못했습니다.** 그 까닭부터 적습니다.

## 지금의 사정

| 때 | 일어난 일 |
| --- | --- |
| 2024년&nbsp;6월 | 센더와 리시버(제안서 P2300)가 C++26 초안에 들어갔다 |
| 2025년&nbsp;6월 | 스코프(`counting_scope`), `parallel_scheduler`, 코루틴 타입 `task`가 더해졌다 |
| 2026년&nbsp;11월 | [C++26은 아직 발행되지 않았다](#/read/cpp-syntax/ver-26). 이 책의 컴파일러에는 구현이 없다 |

구현이 있는지는 기능 확인 매크로로 묻습니다.

```cpp
#include <print>
#include <version>

int main()
{
#ifdef __cpp_lib_senders
    std::println("센더: {}", __cpp_lib_senders);
#else
    std::println("센더: 없음");
#endif
#ifdef __cpp_lib_parallel_scheduler
    std::println("parallel_scheduler: {}", __cpp_lib_parallel_scheduler);

```

GCC 14의 libstdc++와 Clang 20의 libc++가 모두 이렇게 답합니다. 초안이 정한 값은 둘 다 `202506`입니다. 그래서 아래 "표준의 모습"에 실은 코드는 초안의 문구와 참조 구현의 예제를 따라 쓴 것이고, **돌려서 확인한 것이 아닙니다.** 원리는 축소판을 직접 만들어 돌려 보는 것으로 대신합니다.

<Note>
`<execution>` 헤더와 `std::execution` 이름공간은 C++17부터 있었습니다. [실행 정책](#/read/cpp-stl/alg-parallel)(`std::execution::par`)이 사는 곳입니다. 센더는 같은 헤더, 같은 이름공간에 더해집니다. 헤더가 있다고 센더가 있는 것은 아닙니다.
</Note>

## 네 가지 역할

| 이름 | 하는 일 | 지금까지 본 것 가운데 닮은 것 |
| --- | --- | --- |
| 스케줄러 | 일이 **어디서** 돌지를 가리키는 가벼운 손잡이 | [풀](#/read/cpp-advanced/asy-pool)을 가리키는 포인터 |
| 센더 | **아직 시작하지 않은** 일의 설명. 값처럼 만들고 이어 붙인다 | 인자를 묶어 둔 람다 |
| 리시버 | 일이 끝났을 때 불리는 곳. 갈래가 셋이다 | 콜백 세 개 |
| 연산 상태 | 센더와 리시버를 이은 것. 시작하면 돈다 | 돌고 있는 일 그 자체 |

리시버의 세 갈래는 `set_value`(값을 내고 끝남), `set_error`(실패), `set_stopped`(그만둠)입니다. 일은 이 셋 가운데 **정확히 하나**를 한 번 부르고 끝납니다.

## 손으로 만든 축소판

`int` 하나만 다루는 축소판입니다. 이름과 순서는 표준의 것을 따랐습니다.

```cpp
#include <exception>
#include <print>
#include <stdexcept>
#include <utility>

// 리시버: 일이 끝났을 때 불리는 세 갈래
struct Printer {
    void set_value(int v) { std::println("  값 {}", v); }
    void set_error(std::exception_ptr) { std::println("  오류"); }
    void set_stopped() { std::println("  그만둠"); }
};

// 센더 1: 값 하나를 내는 일
template <typename R>
struct JustOp {
    int value;
    R receiver;
    void start() { receiver.set_value(value); }
};
struct Just {
    int value;
    template <typename R>
    JustOp<R> connect(R r) const { return {value, std::move(r)}; }
};

// 센더 2: 앞 센더가 낸 값에 함수를 먹인다
template <typename R, typename F>
struct ThenReceiver {
    R next;
    F fn;
    void set_value(int v)
    {
        int result = 0;
        try {
            result = fn(v);
        } catch (...) {
            next.set_error(std::current_exception());
            return;
        }
        next.set_value(result);
    }
    void set_error(std::exception_ptr e) { next.set_error(e); }
    void set_stopped() { next.set_stopped(); }
};
template <typename S, typename F>
struct Then {
    S prev;
    F fn;
    template <typename R>
    auto connect(R r) const
    {
        return prev.connect(ThenReceiver<R, F>{std::move(r), fn});
    }
};

int main()
{
    auto add = [](int v) { std::println("  1을 더한다"); return v + 1; };
    auto twice = [](int v) { std::println("  두 배 한다"); return v * 2; };
    auto work = Then{Then{Just{20}, add}, twice};
    std::println("센더를 만들었다. {}바이트", sizeof(work));

    auto op = work.connect(Printer{});
    std::println("리시버와 이었다. 연산 상태 {}바이트", sizeof(op));
    op.start();

    auto fail = [](int) -> int { throw std::runtime_error("실패"); };
    auto broken = Then{Then{Just{20}, fail}, twice};
    std::println("실패하는 일을 시작한다");
    auto op2 = broken.connect(Printer{});
    op2.start();
}
```

```text
센더를 만들었다. 12바이트
리시버와 이었다. 연산 상태 8바이트
  1을 더한다
  두 배 한다
  값 42
실패하는 일을 시작한다
  오류
```

- **만들 때는 아무 일도 없습니다.** [`std::async`](#/read/cpp-advanced/asy-async)는 부르는 순간 돌기 시작했습니다. 센더는 `start`를 부를 때까지 12바이트짜리 값일 뿐이라, 넘기고 묶고 버려도 됩니다.
- **`connect`가 리시버를 겹겹이 쌉니다.** `Then`은 받은 리시버를 `ThenReceiver`로 싸서 앞 센더에게 넘깁니다. 값은 `Just`에서 나와 바깥 껍질부터 안쪽으로 지나 `Printer`에 닿습니다.
- **힙을 쓰지 않습니다.** 연산 상태는 8바이트짜리 지역 변수입니다. `promise`와 `future`는 libstdc++에서 힙을 두 번 잡았습니다.
- **실패는 제 갈래로 흐릅니다.** `fail`이 던지자 `twice`는 불리지 않았고, 오류가 끝까지 전해졌습니다.

표준의 것은 여기에 세 가지를 더합니다. 센더가 어떤 값과 오류로 끝나는지를 **컴파일 때** 계산하고, 리시버가 멈춤 토큰과 스케줄러를 알려 주는 **환경**을 갖고, 값을 여러 개 냅니다.

## 표준의 모습

```cpp nocheck
#include <execution>
#include <print>
#include <utility>

namespace ex = std::execution;

int main()
{
    ex::scheduler auto pool = ex::get_parallel_scheduler();
    auto square = [](int v) { return v * v; };

    // 일의 설명을 만든다. 아직 아무것도 돌지 않는다
    ex::sender auto work = ex::when_all(
        ex::starts_on(pool, ex::just(3) | ex::then(square)),
        ex::starts_on(pool, ex::just(4) | ex::then(square)));

    // 시작하고, 끝날 때까지 이 스레드를 막고 기다린다
    auto [a, b] = std::this_thread::sync_wait(std::move(work)).value();
    std::println("{}", a + b);
}
```

초안대로라면 두 제곱이 풀에서 따로 돌고 25가 찍힙니다. 이름들은 초안의 `<execution>` 개요에서 확인했습니다.

| 갈래 | 이름 | 하는 일 |
| --- | --- | --- |
| 만들기 | `just`, `just_error`, `just_stopped` | 곧바로 그 갈래로 끝나는 센더 |
| 만들기 | `schedule(sch)` | "`sch`에서 시작한다"는 센더 |
| 잇기 | `then`, `upon_error`, `upon_stopped` | 그 갈래로 끝났을 때 함수를 불러 결과를 값으로 낸다 |
| 잇기 | `let_value`, `let_error`, `let_stopped` | 함수가 돌려준 **센더**를 이어서 돌린다 |
| 묶기 | `when_all` | 모두 끝나기를 기다린다. 하나가 실패하면 나머지에게 멈추라고 한다 |
| 옮기기 | `starts_on`, `continues_on` | 시작하는 곳, 이어서 도는 곳을 바꾼다 |
| 기다리기 | `this_thread::sync_wait` | 시작하고 막고 기다린다. `optional<tuple<…>>`을 준다 |

`sync_wait`의 결과가 `optional`인 까닭이 세 갈래입니다. 값으로 끝나면 값이 든 `optional`, 그만두었으면 빈 `optional`, 실패했으면 예외가 던져집니다.

## future의 빈자리를 채우는 법

| `future`가 못 하던 일 | 센더에서는 |
| --- | --- |
| 끝나면 이어서 한다 | `then`과 `let_value`로 잇는다. 막고 기다리는 곳은 맨 끝의 `sync_wait` 하나다 |
| 먼저 끝난 것을 고른다 | **초안에 없다.** 모두를 기다리는 `when_all`만 있고, `when_any`는 참조 구현이 따로 둔다 |
| 그만두게 한다 | 멈춤 요청이 [`stop_token`](#/read/cpp-advanced/thr-jthread)과 같은 방식의 토큰으로 전해지고, 일은 `set_stopped`로 끝난다 |
| 어디서 돌지 정한다 | 스케줄러를 넘긴다. `parallel_scheduler`가 표준이 주는 풀이다 |
| 시작만 해 두고 잊는다 | `counting_scope`에 달아 둔다. 달린 일이 모두 끝나기를 기다릴 수 있다 |

`parallel_scheduler` 뒤의 풀이 어떻게 생겼는지는 표준이 정하지 않습니다. 일꾼의 수와 줄의 구조, 작업 훔치기를 하는지는 구현의 몫입니다. 코루틴으로 센더를 쓰는 `task`는 [「태스크 타입 만들기」](#/read/cpp-advanced/co-task)에서 코루틴을 본 뒤에 다시 만납니다.

<Note kind="warn">
지금 써 보려면 참조 구현인 엔비디아의 stdexec가 있습니다. 헤더만으로 된 라이브러리이고, 저장소의 안내는 C++20과 GCC 12, Clang 16, MSVC 14.43 이상을 요구합니다. 이름공간이 `stdexec`이고 `sync_wait`도 그 안에 있다는 점이 초안과 다릅니다. 이 책은 그것을 돌려 보지 못했으므로, 위의 코드와 표는 "초안에 이렇게 적혀 있다"까지만 보증합니다.
</Note>

## 정리

- 센더는 시작하지 않은 일의 설명이고, 리시버의 세 갈래(값, 오류, 그만둠) 가운데 하나로 끝난다. 이으면 연산 상태가 되고 힙을 쓰지 않는다
- `then`으로 잇고 `when_all`로 묶고 스케줄러로 돌 곳을 정한다. 멈춤 요청이 틀 안에 들어 있다
- C++26 초안의 것이고 이 책의 컴파일러에는 아직 없다. 이 페이지의 표준 코드는 돌려 보지 못했다
