export const summary = '부모가 자식의 타입을 인자로 받는 모양, 가상 함수와 잰 값, 함정, 명시적 this와 나눠 쓰는 법';

`class Session : public std::enable_shared_from_this<Session>`. [이 줄](#/read/cpp-advanced/sp-from-this)에서 자식은 자기 이름을 부모의 템플릿 인자로 넘깁니다. 이상하게 되풀이되는 모양이라 CRTP(Curiously Recurring Template Pattern)라는 이름이 붙었습니다. [`view_interface`](#/read/cpp-stl/rng-own)도 같은 모양입니다. 부모가 **자식이 누구인지 컴파일할 때 안다**는 것이 전부이고, 거기서 쓰임새가 나옵니다.

## 부모가 자식을 안다

```cpp
#include <print>

// 자식이 read_raw()와 scale()을 주면 나머지를 만들어 주는 부모
template <typename Derived>
class Thermometer {
public:
    double celsius() const { return self().read_raw() * self().scale(); }
    double fahrenheit() const { return celsius() * 9.0 / 5.0 + 32.0; }
    bool too_hot(double limit) const { return celsius() > limit; }

private:
    const Derived& self() const { return static_cast<const Derived&>(*this); }

    // 엉뚱한 자식을 막는다. Derived만 이 부모를 만들 수 있다
    Thermometer() = default;
    friend Derived;
};

class Thermistor : public Thermometer<Thermistor> {
public:
    int read_raw() const { return 2150; }
    double scale() const { return 0.01; }
};

class Thermocouple : public Thermometer<Thermocouple> {
public:
    int read_raw() const { return 3400; }
    double scale() const { return 0.25; }
};

// 자식마다 따로 세는 부모
template <typename Derived>
class Counted {
public:
    static int alive() { return alive_; }

protected:
    Counted() { ++alive_; }
    Counted(const Counted&) { ++alive_; }
    ~Counted() { --alive_; }

private:
    static inline int alive_ = 0;
};

class Session : public Counted<Session> {};
class Buffer : public Counted<Buffer> {};

// 어떤 온도계든 받는다. 가상 함수가 아니라 템플릿이다
template <typename T>
void show(const Thermometer<T>& sensor)
{
    std::println("{:.1f}도, 화씨 {:.1f}도, 과열 {}", sensor.celsius(),
                 sensor.fahrenheit(), sensor.too_hot(100.0));
}

int main()
{
    Thermistor inside;
    Thermocouple furnace;
    show(inside);
    show(furnace);
    std::println("크기 {}바이트", sizeof(Thermistor));

    Session a, b;
    Buffer c;
    std::println("세션 {}개, 버퍼 {}개", Session::alive(), Buffer::alive());
}
```

```text
21.5도, 화씨 70.7도, 과열 false
850.0도, 화씨 1562.0도, 과열 true
크기 1바이트
세션 2개, 버퍼 1개
```

요점은 `self()`입니다. `Thermometer<Thermistor>`는 자기가 `Thermistor`의 부모라는 것을 알므로 `this`를 자식으로 바꿔 자식의 함수를 부릅니다. 가상 함수 표도 없고 포인터도 없습니다. 크기가 1바이트인 것이 그 증거입니다.

부모의 본문에서 자식의 멤버를 쓸 수 있는 것은 **멤버 함수의 본문이 불릴 때에야 만들어지기** 때문입니다. 그때는 자식의 정의가 끝나 있습니다.

`Counted`는 다른 쓰임입니다. `Counted<Session>`과 `Counted<Buffer>`는 다른 클래스이므로 정적 변수도 따로입니다. 부모 하나를 물려받았는데 **자식마다 제 것**이 생깁니다.

## 가상 함수와 견주면

온도계 1만 개의 `celsius()`를 불러 더하는 루프입니다. x86-64, `-O2`이고 호출 한 번의 값입니다.

| 방식 | GCC 14 | Clang 20 |
| --- | --- | --- |
| 가상 함수. `unique_ptr<부모>` 1만 개, 모두 같은 타입 | 2.2 ns | 4.2 ns |
| 가상 함수. 두 타입이 무작위로 섞임 | 6.2 ns | 6.0 ns |
| CRTP. `vector<Thermistor>` | 0.66 ns | 0.56 ns |
| 가상 함수이지만 `final` 클래스를 값으로 담음 | 0.62 ns | 0.65 ns |

CRTP가 빠른 까닭은 가상 함수 표를 읽지 않아서가 아니라 **인라인되기 때문**입니다. 넷째 줄이 그것을 보여 줍니다. 타입이 정해져 있다는 것을 컴파일러가 알면 가상 함수도 인라인되어 같은 값이 됩니다. 반대로 타입이 섞이면 간접 분기의 예측이 빗나가 값이 세 배가 됩니다. 그 경우는 CRTP로 바꿀 수도 없습니다. 타입이 다르면 한 컨테이너에 담지 못하기 때문입니다.

## 함정

| 함정 | 생기는 일 | 대비 |
| --- | --- | --- |
| `class Typo : public Thermometer<Thermistor>` | `self()`가 엉뚱한 타입으로 바꾼다. 미정의 동작 | 부모의 생성자를 `private`로 두고 `friend Derived;` |
| 부모의 **선언**에서 `Derived::value_type`을 쓴다 | 그때 자식은 아직 정의되지 않았다. 컴파일 오류 | 본문 안에서만 쓰거나 반환 타입을 `auto`로 둔다 |
| 부모와 자식의 함수 이름이 같은데 자식이 안 썼다 | 부모의 함수가 자기를 다시 부른다 | 이름을 달리한다(`run`과 `do_run`). 두 컴파일러 모두 `-Winfinite-recursion`으로 알려 준다 |
| 여러 자식을 한 컨테이너에 | 부모가 서로 다른 타입이라 담을 수 없다 | [`variant`](#/read/cpp-stl/voc-variant)나 가상 함수 |

첫 줄의 지킴이가 있으면 틀린 자식을 만드는 순간 컴파일이 멈춥니다.

```text nocheck
error: use of deleted function 'Typo::Typo()'
note: 'Typo::Typo()' is implicitly deleted because the default definition
      would be ill-formed:
error: 'constexpr Thermometer<Derived>::Thermometer() [with Derived = Thermistor]'
       is private within this context
```

<Note kind="warn">
이 지킴이에는 값이 있습니다. `Thermistor{}`처럼 **중괄호로 만들 수 없게 됩니다.** 자식이 생성자를 선언하지 않으면 집합체이고, 중괄호 초기화는 부모 부분을 바깥에서 직접 만들려 하기 때문입니다. 예제가 `Thermistor inside;`로 쓴 까닭입니다.
</Note>

## 지금은 무엇으로 쓰는가

C++23의 [명시적 `this`](#/read/cpp-syntax/lam-recursive)는 첫째 쓰임을 템플릿 없는 부모로 대신합니다. `double celsius(this const auto& self)`라고 쓰면 `self`가 자식의 타입으로 추론됩니다.

| 하고 싶은 일 | CRTP | 명시적 `this` | 콘셉트와 자유 함수 |
| --- | --- | --- | --- |
| 자식의 함수로 다른 함수를 만들어 준다 | 된다 | 된다. 더 짧다 | 된다. 멤버가 아니게 된다 |
| 자식마다 따로인 정적 변수나 멤버 | 된다 | 안 된다. 부모가 하나다 | 안 된다 |
| 자식 타입이 드러난 멤버 (`weak_ptr<Derived>`) | 된다 | 안 된다 | 안 된다 |
| 누가 물려받는지 제한한다 | 된다 | 안 된다 | 콘셉트로 받는 쪽에서 한다 |
| 부모 참조로 불렀을 때 | 부모가 자식마다 달라 섞일 일이 없다 | `self`가 부모로 추론된다 | |

`enable_shared_from_this`가 여전히 CRTP인 까닭이 셋째 줄입니다. 새 코드에서 "함수 몇 개를 덤으로 얹는" 일은 명시적 `this`로 쓰고, 자식마다의 상태가 필요할 때 CRTP를 씁니다. 비교 연산자를 얹어 주던 CRTP는 [`<=>`](#/read/cpp-syntax/op-compare)가 나오면서 쓸 일이 없어졌습니다.

## 정리

- CRTP의 부모는 자식의 타입을 알므로 `this`를 자식으로 바꿔 부른다. 가상 함수 표가 없고 인라인된다
- 빠른 까닭은 인라인이다. 타입이 정해진 곳에서는 `final`인 가상 함수도 같은 값이었다
- 얹어 주는 함수는 명시적 `this`로, 자식마다의 상태와 자식 타입이 드러난 멤버는 CRTP로 쓴다
