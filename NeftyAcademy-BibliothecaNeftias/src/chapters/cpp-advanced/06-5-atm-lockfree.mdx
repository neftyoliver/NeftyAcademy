"락 없는(lock-free)" 자료 구조는 빠르다는 뜻이 아닙니다. **어느 스레드가 멈춰 있어도 나머지는 나아간다**는 뜻입니다. 뮤텍스를 쥔 스레드가 CPU에서 밀려나면 기다리는 스레드는 모두 섭니다. 락 없는 구조에는 그런 스레드가 없습니다. 이 쪽에서는 그 뜻을 정확히 하고, 실제로 만들어 쓸 만한 것 둘을 만듭니다.

## 세 단계

| 이름 | 약속 | 보기 |
| --- | --- | --- |
| 기다림 없는 (wait-free) | **모든** 스레드가 정해진 걸음 안에 끝낸다 | `fetch_add`, 아래의 고리 버퍼 |
| 락 없는 (lock-free) | 언제나 **누군가는** 나아간다. 한 스레드는 오래 헛돌 수도 있다 | [CAS 고리](#/read/cpp-advanced/atm-cas), 아래의 목록 |
| 잠그는 | 쥔 스레드가 멈추면 모두 멈춘다 | `std::mutex` |

CAS 고리가 락 없는 까닭은, 내 시도가 실패했다면 그것은 **다른 스레드가 성공했기 때문**이라서입니다. 누군가는 나아갔습니다. 뮤텍스를 직접 쓰지 않아도 안에서 돌며 기다리는 스핀락은 잠그는 쪽입니다.

## 한쪽씩만 쓰는 고리 버퍼

넣는 스레드가 **하나**, 빼는 스레드가 **하나**로 정해져 있으면 CAS조차 필요 없습니다. 센서를 읽는 스레드에서 처리하는 스레드로, 오디오 콜백에서 화면으로 값을 넘길 때의 꼴입니다.

```cpp
#include <atomic>
#include <cstddef>
#include <optional>
#include <print>
#include <thread>

// 넣는 스레드 하나, 빼는 스레드 하나만 쓰는 고리 버퍼. Capacity 는 2의 거듭제곱
template <typename T, std::size_t Capacity>
class SpscRing {
public:
    bool try_push(const T& item)
    {
        // 나만 고친다
        const std::size_t tail = tail_.load(std::memory_order_relaxed);
        if (tail - head_.load(std::memory_order_acquire) == Capacity) return false;
        slots_[tail % Capacity] = item;
        tail_.store(tail + 1, std::memory_order_release);   // 칸을 채운 뒤에 알린다
        return true;
    }

    std::optional<T> try_pop()
    {
        // 나만 고친다
        const std::size_t head = head_.load(std::memory_order_relaxed);
        if (head == tail_.load(std::memory_order_acquire)) return std::nullopt;
        T item = slots_[head % Capacity];
        head_.store(head + 1, std::memory_order_release);   // 칸을 비운 뒤에 알린다
        return item;
    }

private:
    alignas(64) std::atomic<std::size_t> head_{0};  // 빼는 쪽만 고친다
    alignas(64) std::atomic<std::size_t> tail_{0};  // 넣는 쪽만 고친다
    alignas(64) T slots_[Capacity];
};

int main()
{
    static SpscRing<long, 1024> ring;
    const long count = 1'000'000;
    long sum = 0;
    {
        std::jthread consumer([&] {
            for (long got = 0; got < count;) {
                if (auto item = ring.try_pop()) {
                    sum += *item;
                    ++got;
                }
            }
        });
        for (long i = 1; i <= count;) {
            if (ring.try_push(i)) ++i;      // 꽉 차 있으면 다시 시도한다
        }
    }
    std::println("{}", sum);
}
```

```text
500000500000
```

이 코드가 맞는 까닭은 세 가지입니다.

| 장치 | 하는 일 |
| --- | --- |
| `tail_`은 넣는 쪽만, `head_`는 빼는 쪽만 고친다 | 같은 변수를 두 스레드가 고치는 일이 없다. 그래서 CAS가 없다 |
| 칸을 채운 **뒤에** `tail_`을 [`release`로](#/read/cpp-advanced/atm-order) 올린다 | 빼는 쪽이 `acquire`로 새 `tail_`을 봤다면 그 칸의 내용도 보인다 |
| `head_`와 `tail_`을 [다른 캐시 줄에](#/read/cpp-advanced/atm-false-sharing) 둔다 | 넣는 쪽과 빼는 쪽이 서로의 줄을 빼앗지 않는다 |

번호는 줄어들지 않고 계속 커지며, 칸을 찾을 때만 `Capacity`로 나눈 나머지를 씁니다. 그래서 "꽉 참"과 "빔"을 뺄셈 하나로 가를 수 있습니다. ThreadSanitizer로 돌려 경합이 없음을 확인했습니다.

| 항목 2천만 개를 넘긴다 | 하나에 |
| --- | --- |
| 위의 고리 버퍼 | 12 ns |
| `std::mutex`로 지킨 `std::queue`를 같은 식으로(될 때까지 시도) 쓴다 | 290 ns |

x86-64 서버 VM(코어 2개), GCC 14 `-O2`에서 잰 값입니다. 스물네 배 차이의 대부분은 잠금 자체가 아니라, 두 스레드가 같은 뮤텍스와 같은 큐를 두고 [줄을 빼앗고 잠들고 깨우는](#/read/cpp-advanced/sync-mutex) 데서 나옵니다.

<Note kind="warn">
스레드가 둘씩이 되는 순간 이 버퍼는 틀립니다. 넣는 스레드가 둘이면 같은 `tail`을 읽고 같은 칸에 씁니다. "하나씩만"이라는 조건은 타입이 지켜 주지 않으므로 주석과 이름(`Spsc`)으로 밝혀 둡니다.
</Note>

## 여럿이 넣고, 통째로 가져간다

넣는 쪽이 여럿이면 CAS가 필요합니다. 목록의 머리에 새 마디를 붙이는 것은 CAS 고리의 가장 단순한 쓰임입니다.

```cpp
#include <atomic>
#include <print>
#include <thread>
#include <utility>
#include <vector>

template <typename T>
class Inbox {
public:
    struct Node {
        T value;
        Node* next;
    };

    ~Inbox() { destroy(take_all()); }

    void push(T value)
    {
        Node* node = new Node{std::move(value), head_.load()};
        // head_ 가 아직 node->next 이면 node 로 바꾼다.
        // 그사이 누가 넣었으면 실패하고, node->next 에 새 머리가 들어온다
        while (!head_.compare_exchange_weak(node->next, node)) {}
    }

    // 지금까지 쌓인 것을 한 번에 떼어 온다. 떼어 온 목록은 받은 쪽만 본다
    Node* take_all() { return head_.exchange(nullptr); }

    static void destroy(Node* node)
    {
        while (node != nullptr) {
            Node* next = node->next;
            delete node;
            node = next;
        }
    }

private:
    std::atomic<Node*> head_{nullptr};
};

int main()
{
    Inbox<int> inbox;
    long sum = 0;
    long count = 0;
    auto drain = [&] {
        auto* list = inbox.take_all();
        for (auto* node = list; node != nullptr; node = node->next) {
            sum += node->value;
            ++count;
        }
        Inbox<int>::destroy(list);
    };
    {
        std::vector<std::jthread> producers;
        for (int id = 0; id < 4; ++id) {
            producers.emplace_back([&inbox] {
                for (int i = 1; i <= 10'000; ++i) inbox.push(i);
            });
        }
        // 넣는 쪽이 도는 동안에도 가져간다
        for (int round = 0; round < 100; ++round) {
            drain();
            std::this_thread::yield();
        }
    }
    drain();                                            // 모두 끝난 뒤의 나머지
    std::println("받은 것 {}개, 합 {}", count, sum);
}
```

```text
받은 것 40000개, 합 200020000
```

빼는 쪽이 마디를 **하나씩** 떼어 가게 만들지 않은 것이 요점입니다. 하나씩 떼려면 "머리를 읽고, 그 다음 마디를 읽고, 머리를 다음 마디로 바꾼다"가 되는데, 머리를 읽은 직후에 다른 스레드가 그 마디를 떼어 **지워 버리면** 사라진 메모리를 읽습니다. 통째로 떼어 오면(`exchange`) 그 목록은 나만 가진 것이 되어 느긋하게 돌고 지울 수 있습니다. 순서는 넣은 것의 반대이므로, 필요하면 받은 쪽에서 뒤집습니다.

하나씩 떼는 것을 맞게 만드는 일이 [다음 쪽](#/read/cpp-advanced/atm-aba)의 주제이고, 락 없는 자료 구조가 어려운 까닭의 거의 전부입니다.

## 쓸 자리

| 상황 | 고를 것 |
| --- | --- |
| 다투지 않거나 가끔 다투는 자료 | `std::mutex`. 20 ns이고 틀리기 어렵다 |
| 읽기가 훨씬 많고 통째로 갈아 끼우는 자료 | [스냅숏](#/read/cpp-advanced/sync-shared). 잠금까지 없애려면 `std::atomic<std::shared_ptr<const T>>` |
| 한 스레드에서 다른 한 스레드로 흘려보내는 값 | 위의 고리 버퍼 |
| 여러 스레드가 한 스레드에게 보내는 일감, 로그 | 위의 목록 |
| 멈추면 안 되는 스레드(오디오 콜백, 인터럽트 처리기)가 끼어 있다 | 락 없는 구조가 **필요하다**. 잠금을 기다릴 수 없다 |
| 그 밖의 맵, 큐, 덱 | 검증된 라이브러리를 쓴다. 직접 만들지 않는다 |

`std::atomic<std::shared_ptr<T>>`는 이름과 달리 GCC 14에서 [`is_lock_free()`가 `false`](#/read/cpp-advanced/sp-shared)입니다. 포인터의 남는 비트를 깃발 삼아 아주 짧게 잠급니다. 읽는 쪽이 몹시 많아 그것조차 아까운 자리를 위해 C++26에 `<hazard_pointer>`와 `<rcu>`가 들어갔습니다. 이 책이 쓰는 GCC 14와 Clang 20에는 아직 없습니다.

## 정리

- 락 없다는 것은 멈춘 스레드가 남을 막지 않는다는 뜻이다. 빠르다는 뜻이 아니다
- 넣는 쪽 하나와 빼는 쪽 하나면 CAS 없이 고리 버퍼가 된다. 넣는 쪽이 여럿이면 CAS로 머리에 붙이고 통째로 가져간다
- 마디를 하나씩 떼는 순간 "지워도 되는가"라는 문제가 생긴다. 그 밖의 구조는 직접 만들지 않는다
