스마트 포인터와 래퍼는 도구입니다. 그 도구로 무엇을 그릴지, 곧 **어느 객체가 어느 객체를 지우는가**를 정하는 것이 소유권 설계입니다. 잘 정해진 프로그램은 "이 객체는 언제 사라지는가"에 코드를 보고 답할 수 있습니다.

## 소유는 나무로 그린다

객체마다 주인을 **하나** 정합니다. 주인의 주인을 따라 올라가면 `main`의 지역 변수나 전역 객체에 닿는 나무가 됩니다. 나무의 가지가 아닌 모든 연결은 "가리키기만 하는" 것입니다.

| 관계 | 적는 법 |
| --- | --- |
| 나의 일부다. 같이 태어나고 같이 사라진다 | 값 멤버 `Engine engine_;` |
| 내 것이지만 없을 수도, 바뀔 수도, 여럿일 수도 있다 | `std::optional<T>`, `std::unique_ptr<T>`, 컨테이너 |
| 내 것이 아니고, 나보다 오래 산다 | `T&` (늘 있다), `T*` (없을 수 있다) |
| 내 것이 아니고, 나보다 먼저 사라질 수 있다 | 핸들, 또는 [`std::weak_ptr<T>`](#/read/cpp-advanced/sp-weak) |
| 여럿이 가졌고, 누가 마지막일지 알 수 없다 | `std::shared_ptr<T>` |

위의 세 줄로 그릴 수 있으면 그렇게 그립니다. 값 멤버가 가장 싸고(할당이 없습니다), 수명이 가장 잘 보입니다. 아래 두 줄은 수명을 **실행 중에** 알아내야 하는 경우입니다.

## 빌린 것이 먼저 사라지게 한다

참조와 맨 포인터가 안전하려면 가리키는 쪽이 가리켜지는 쪽보다 **먼저** 사라져야 합니다. 함수 인자로 받아 쓰고 돌아가는 것은 언제나 그렇습니다. 문제는 멤버로 **보관할 때**이고, 그때는 선언 순서가 답입니다.

```cpp
#include <print>
#include <string>

struct Config {
    std::string name = "demo";
    Config() { std::println("+ Config"); }
    ~Config() { std::println("- Config"); }
};

class Logger {
public:
    explicit Logger(const Config& config) : config_(config)
    {
        std::println("+ Logger");
    }
    ~Logger() { std::println("- Logger (Config 는 아직 있다: {})", config_.name); }
    void write(const std::string& text) const
    {
        std::println("[{}] {}", config_.name, text);
    }

private:
    const Config& config_;      // 빌린 것
};

class Server {
public:
    explicit Server(Logger& logger) : logger_(logger) { std::println("+ Server"); }
    ~Server() { logger_.write("서버를 내린다"); }
    void run() { logger_.write("요청을 받는다"); }

private:
    Logger& logger_;            // 빌린 것
};

// 주인은 여기 하나다. 선언한 순서대로 만들어지고 반대 순서로 사라진다
struct App {
    Config config;
    Logger logger{config};
    Server server{logger};
};

int main()
{
    App app;
    app.server.run();
}
```

```text
+ Config
+ Logger
+ Server
[demo] 요청을 받는다
[demo] 서버를 내린다
- Logger (Config 는 아직 있다: demo)
- Config
```

`Server`의 소멸자가 `logger_`를 쓰고 `Logger`의 소멸자가 `config_`를 읽지만 탈이 없습니다. **뒤에 선언한 것이 앞에 선언한 것을 빌린다**는 규칙 하나를 지켰기 때문입니다. 프로그램의 굵은 부품을 이렇게 한 곳에 모아 두면 `shared_ptr` 없이도 수명이 맞습니다. 멤버의 줄을 바꾸면 깨지므로, 순서에 뜻이 있다는 주석을 `App`에 답니다.

스레드가 끼면 같은 규칙이 **끝내는 순서**가 됩니다.

```cpp
class Sampler {
public:
    Sampler() : worker_([this](std::stop_token stop) { run(stop); }) {}

private:
    void run(std::stop_token stop)
    {
        while (!stop.stop_requested()) {
            std::lock_guard lock(mutex_);
            samples_.push_back(1);
        }
    }

    std::vector<int> samples_;      // 스레드가 쓰는 것을 먼저 선언한다
    std::mutex mutex_;
    // 스레드는 맨 뒤: 가장 먼저 멈추고 끝나기를 기다린다
    std::jthread worker_;
};
```

[`std::jthread`](#/read/cpp-advanced/thr-jthread)의 소멸자는 멈추라고 알리고 끝날 때까지 기다립니다. 맨 뒤에 선언했으므로 그 일이 가장 먼저 일어나고, `samples_`와 `mutex_`는 스레드가 끝난 뒤에 사라집니다.

## 먼저 사라질 수 있는 것은 핸들로 가리킨다

타이머 콜백이 세션을 가리키는데, 콜백이 불리기 전에 세션이 닫힐 수 있습니다. 콜백이 `shared_ptr`로 세션을 붙들면 탈은 없지만 [세션이 언제 사라지는지 알 수 없게 됩니다](#/read/cpp-advanced/sp-from-this). 주인을 하나로 두고, 가리키는 쪽은 **번호표**만 들게 합니다.

```cpp
#include <cstdint>
#include <functional>
#include <optional>
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Handle {
    std::uint32_t index = 0;
    std::uint32_t generation = 0;       // 그 칸이 몇 번째로 쓰이는 중인가
};

template <typename T>
class Pool {
public:
    template <typename... Args>
    Handle create(Args&&... args)
    {
        std::uint32_t index;
        if (free_.empty()) {
            index = static_cast<std::uint32_t>(slots_.size());
            slots_.emplace_back();
        } else {
            index = free_.back();
            free_.pop_back();
        }
        slots_[index].value.emplace(std::forward<Args>(args)...);
        return {index, slots_[index].generation};
    }

    void destroy(Handle handle)
    {
        if (get(handle) == nullptr) return;
        slots_[handle.index].value.reset();
        // 이 칸을 가리키던 핸들은 모두 낡았다
        ++slots_[handle.index].generation;
        free_.push_back(handle.index);
    }

    T* get(Handle handle)       // 살아 있으면 포인터, 사라졌으면 nullptr
    {
        if (handle.index >= slots_.size()) return nullptr;
        Slot& slot = slots_[handle.index];
        if (slot.generation != handle.generation || !slot.value) return nullptr;
        return &*slot.value;
    }

private:
    struct Slot {
        std::optional<T> value;
        std::uint32_t generation = 0;
    };
    std::vector<Slot> slots_;
    std::vector<std::uint32_t> free_;
};

struct Session {
    std::string user;
};

int main()
{
    Pool<Session> sessions;                         // 세션의 주인은 이 풀 하나다
    std::vector<std::function<void()>> timers;      // 나중에 불릴 콜백들

    Handle kim = sessions.create("kim");
    Handle lee = sessions.create("lee");
    for (Handle h : {kim, lee}) {
        timers.push_back([&sessions, h] {           // 세션이 아니라 핸들을 붙든다
            if (Session* session = sessions.get(h))
                std::println("{} 에게 알림", session->user);
            else
                std::println("사라진 세션 (칸 {}, {}세대)", h.index, h.generation);
        });
    }

    sessions.destroy(kim);                          // 주인이 정한 때에 사라진다
    Handle park = sessions.create("park");          // 같은 칸을 다시 쓴다
    std::println("park 은 칸 {}, {}세대", park.index, park.generation);

    for (auto& timer : timers) timer();
}
```

```text
park 은 칸 0, 1세대
사라진 세션 (칸 0, 0세대)
lee 에게 알림
```

`kim`이 쓰던 0번 칸을 `park`이 다시 쓰지만, 옛 핸들은 세대가 달라 `nullptr`를 받습니다. 맨 포인터였다면 엉뚱한 세션에 알림을 보냈을 것입니다. `get`이 돌려준 포인터는 **그 자리에서 쓰고 버립니다.** 보관하면 맨 포인터와 같아집니다.

| | 핸들 + 풀 | `weak_ptr` + `shared_ptr` |
| --- | --- | --- |
| 가리키는 쪽의 크기 | 8바이트 | 16바이트 |
| 객체마다 드는 것 | 세대 번호와 빈칸 표시 | [제어 블록과 원자적 계수](#/read/cpp-advanced/sp-shared) |
| 객체가 놓이는 곳 | 한 벡터에 나란히 | 하나씩 따로 힙에 |
| 사라지는 때 | 주인이 `destroy`를 부를 때 | 마지막 `shared_ptr`가 놓을 때 |
| 쓰는 동안의 보호 | 없다. 같은 스레드에서 바로 쓴다 | `lock()`이 붙들어 준다 |

마지막 줄이 `shared_ptr`를 써야 하는 자리를 알려 줍니다. **다른 스레드가 쓰는 도중에** 사라질 수 있다면 번호표로는 막을 수 없고, 쓰는 동안 붙들어 줄 계수가 필요합니다.

<Note>
`shared_ptr`가 맞는 자리는 넓지 않습니다. 여러 스레드가 읽는 바뀌지 않는 데이터, 끝나는 때가 제각각인 비동기 작업이 함께 쓰는 상태, 캐시가 내준 값이 그렇습니다. "누가 주인인지 정하기 어려워서" 쓰기 시작하면 순환과 끝나지 않는 종료가 따라옵니다. 그럴 때는 주인을 한 단계 위에 새로 만드는 것이 대개 답입니다.
</Note>

## 정리

- 객체마다 주인을 하나 정해 나무로 그린다. 값 멤버, `unique_ptr`, 컨테이너가 가지이고 나머지는 가리키기만 한다
- 빌린 것을 멤버로 보관할 때는 빌리는 쪽을 뒤에 선언한다. 스레드는 맨 뒤에 둔다
- 먼저 사라질 수 있는 것은 세대 번호가 든 핸들로 가리키고, 쓰는 도중에 사라질 수 있을 때만 `shared_ptr`를 쓴다
