타입이 여럿인 것을 같은 코드로 다루는 길은 지금까지 셋을 봤습니다. [가상 함수](#/read/cpp-syntax/inh-virtual), [`variant`](#/read/cpp-stl/voc-variant), [템플릿](#/read/cpp-syntax/con-own)입니다. 따로따로 봤으므로 여기서는 **같은 문제**에 셋을 나란히 놓습니다. 넷째 길인 타입 지우기는 이 견줌을 바탕으로 [다음 페이지](#/read/cpp-advanced/te-implement)에서 만듭니다.

## 같은 문제를 세 가지로

```cpp
#include <memory>
#include <print>
#include <variant>
#include <vector>

// 상속 없는 값 타입 둘
struct Circle {
    double r;
    double area() const { return 3.14159 * r * r; }
};
struct Rect {
    double w, h;
    double area() const { return w * h; }
};

// 1. 가상 함수: 부모를 물려받고, 포인터로 다룬다
struct Shape {
    virtual ~Shape() = default;
    virtual double area() const = 0;
};
struct CircleShape : Shape {
    Circle value;
    explicit CircleShape(Circle c) : value(c) {}
    double area() const override { return value.area(); }
};
struct RectShape : Shape {
    Rect value;
    explicit RectShape(Rect r) : value(r) {}
    double area() const override { return value.area(); }
};

double total(const std::vector<std::unique_ptr<Shape>>& shapes)
{
    double sum = 0;
    for (const auto& shape : shapes)
        sum += shape->area();
    return sum;
}

// 2. variant: 타입의 목록을 적어 두고, 값으로 다룬다
using AnyShape = std::variant<Circle, Rect>;

double total(const std::vector<AnyShape>& shapes)
{
    double sum = 0;
    for (const auto& shape : shapes)
        sum += std::visit([](const auto& s) { return s.area(); }, shape);
    return sum;
}

// 3. 템플릿: 타입마다 따로 담고, 타입마다 따로 돈다
template <typename... Groups>
double total(const Groups&... groups)
{
    double sum = 0;
    auto add = [&](const auto& group) {
        for (const auto& shape : group)
            sum += shape.area();
    };
    (add(groups), ...);
    return sum;
}

int main()
{
    std::vector<std::unique_ptr<Shape>> pointers;
    pointers.push_back(std::make_unique<CircleShape>(Circle{1}));
    pointers.push_back(std::make_unique<RectShape>(Rect{2, 3}));
    pointers.push_back(std::make_unique<CircleShape>(Circle{2}));

    std::vector<AnyShape> values{Circle{1}, Rect{2, 3}, Circle{2}};

    std::vector<Circle> circles{Circle{1}, Circle{2}};
    std::vector<Rect> rects{Rect{2, 3}};

    std::println("가상 함수 {:.2f}", total(pointers));
    std::println("variant   {:.2f}", total(values));
    std::println("템플릿    {:.2f}", total(circles, rects));
    std::println("크기: 포인터 {}, variant {}, Circle {}, Rect {}",
                 sizeof(std::unique_ptr<Shape>), sizeof(AnyShape), sizeof(Circle),
                 sizeof(Rect));
}
```

```text
가상 함수 21.71
variant   21.71
템플릿    21.71
크기: 포인터 8, variant 24, Circle 8, Rect 16
```

| | 가상 함수 | `variant` | 템플릿 |
| --- | --- | --- | --- |
| 섞어 담기 | 포인터의 `vector` | 값의 `vector` | 안 된다. 타입마다 따로 담는다 |
| 객체가 사는 곳 | 하나하나 힙에 | `vector` 안에 나란히 | `vector` 안에 나란히 |
| 한 칸의 크기 | 포인터 8바이트와 힙의 객체 | 가장 큰 타입 더하기 번호 | 그 타입의 크기 |
| 타입이 정해지는 때 | 실행 중 | 실행 중. 목록은 컴파일할 때 | 컴파일할 때 |
| 순서 | 넣은 순서 | 넣은 순서 | 타입끼리 모인다. 넣은 순서는 잃는다 |

## 잰 값

도형 1만 개의 넓이를 더하는 데 든 시간을 하나로 나눈 것입니다. 타입은 셋이고 x86-64, `-O2`입니다.

| 방식 | 무작위로 섞임 | 타입별로 모아 둠 |
| --- | --- | --- |
| 가상 함수와 `unique_ptr` | 7.2 ns | 2.3 ns |
| `variant`와 `visit` | 2.6 ns | 0.54 ns |
| `variant`와 `get_if` 사슬 | 3.3 ns | 0.59 ns |
| 타입별 `vector` (템플릿) | 0.53 ns | 0.53 ns |

GCC 14의 결과입니다. 숫자를 가르는 것은 셋입니다.

- **어느 갈래로 갈지의 예측.** 섞여 있으면 가상 호출도 `visit`도 분기 예측이 빗나갑니다. 모아 두면 가상 호출은 세 배, `visit`는 다섯 배 빨라집니다. 템플릿은 갈래가 없으므로 섞임과 무관합니다.
- **메모리의 자리.** 가상 함수 쪽은 객체가 힙에 흩어져 있어 포인터를 따라가야 합니다. 만드는 데도 할당이 1만 번 들었습니다. `variant`는 한 줄로 놓여 있습니다.
- **인라인.** `visit`에 넘긴 람다는 갈래마다 인라인됩니다. 가상 호출은 그 자리에서 타입을 모르므로 안 됩니다.

Clang 20과 libc++에서는 `visit`가 달랐습니다. 섞였을 때 5.8 ns, 모았을 때 2.2 ns로 `get_if` 사슬(3.6 ns, 0.7 ns)보다 느렸습니다. `visit`를 구현하는 방법이 라이브러리마다 다르기 때문입니다. 안쪽 루프라면 재 보고 정합니다.

## 무엇을 더하기 쉬운가

| 더하려는 것 | 가상 함수 | `variant` | 템플릿 |
| --- | --- | --- | --- |
| 새 타입 | 클래스 하나를 더 쓴다. 기존 코드는 그대로다 | 목록을 고치고, 모든 `visit`를 다시 본다 | 타입을 쓰면 된다 |
| 새 연산 | 부모와 **모든 자식**을 고친다 | 방문자 하나를 더 쓴다 | 함수 하나를 더 쓴다 |
| 남이 나중에 타입을 더한다 (플러그인) | 된다 | 안 된다. 목록이 닫혀 있다 | 안 된다. 다시 컴파일해야 한다 |
| 빠뜨렸을 때 | 순수 가상 함수면 컴파일 오류 | 컴파일 오류 | 컴파일 오류 |

`variant`의 "모든 `visit`를 다시 본다"는 컴파일러가 해 줍니다. 목록에 `Line`을 더하고 방문자를 고치지 않으면 이렇게 됩니다. 윗줄이 libstdc++, 아랫줄이 libc++입니다.

```text nocheck
error: no type named 'type' in 'struct std::invoke_result<Area, Line&>'
error: static assertion failed ...
       `std::visit` requires the visitor to be exhaustive.
```

타입이 자주 늘면 가상 함수가, 연산이 자주 늘면 `variant`가 편합니다. 둘 다 편한 길은 없습니다.

## 고르는 기준

| 물음 | 그렇다면 |
| --- | --- |
| 타입의 목록이 컴파일할 때 닫혀 있고, 섞어 담을 일이 없는가 | 템플릿. 가장 빠르고 가장 단순하다 |
| 목록은 닫혀 있지만 한 컨테이너에 섞어 담아야 하는가 | `variant`. 값으로 다루고 할당이 없다 |
| 타입 하나가 다른 것들보다 훨씬 큰가 | `variant`는 모든 칸이 가장 큰 타입만큼 커진다. 큰 것만 포인터로 든다 |
| 나중에, 다른 사람이, 다시 컴파일하지 않고 타입을 더하는가 | 가상 함수 |
| 그러면서도 타입들이 부모를 물려받게 하고 싶지 않은가 | [타입 지우기](#/read/cpp-advanced/te-implement) |

<Note>
[CRTP 페이지](#/read/cpp-advanced/tmp-crtp)에서 잰 값과 이 표는 같은 이야기입니다. 거기서도 타입이 섞이면 가상 호출이 6 ns였고, 타입이 정해진 곳에서는 0.6 ns였습니다. "가상 함수는 느리다"가 아니라 "**갈래를 예측하지 못하고 인라인하지 못하는 호출**이 느리다"입니다. 장치마다 한 번 불리는 드라이버 함수에서는 어느 쪽이든 차이가 없습니다.
</Note>

## 정리

- 가상 함수는 열린 목록과 포인터, `variant`는 닫힌 목록과 값, 템플릿은 컴파일할 때 정해진 타입이다
- 섞인 1만 개에서 가상 함수 7.2 ns, `variant` 2.6 ns, 타입별로 나눈 템플릿 0.53 ns였다. 모아 두면 앞의 둘이 세 배 넘게 빨라진다
- 타입이 자주 늘면 가상 함수, 연산이 자주 늘면 `variant`가 고치기 쉽다
