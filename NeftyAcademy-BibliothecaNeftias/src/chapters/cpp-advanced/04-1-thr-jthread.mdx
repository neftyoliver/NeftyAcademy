스레드를 띄우고 `jthread`에게 `join`을 맡기는 데까지는 [STL 책의 맛보기](#/read/cpp-stl/conc-thread)에서 했습니다. 이 챕터부터 세 챕터는 그 너머입니다. 먼저 스레드 하나가 무엇이고 얼마짜리인지, 그리고 **자고 있는 스레드를 어떻게 깨워서 끝내는지**를 봅니다.

## 스레드 하나의 값

`std::thread`는 운영체제의 스레드 하나를 쥔 핸들입니다. 리눅스에서는 pthread이고, 커널에는 프로세스와 같은 종류의 일감으로 보입니다.

| 스레드 하나에 드는 것 | 잰 값 |
| --- | --- |
| 만드는 시간 | 23~28 µs (1000개를 만들며 평균) |
| 주소 공간 | 8,196 kB. 스택으로 **예약**한 8 MB와 그 끝의 보호 쪽 |
| 실제 메모리 | 8 kB. 스택은 건드린 만큼만 실제 메모리가 된다 |
| 멈춤 신호 한 번 확인 | 0.4 ns. `std::atomic<bool>`을 읽는 것과 같다 |

x86-64 서버 VM(코어 2개)에서 GCC 14 `-O2`로, 스레드 1000개를 띄워 놓고 `/proc/self/status`를 읽어 잰 값입니다. 스택의 크기 8 MB는 `ulimit -s`의 값을 따릅니다. 64비트에서는 예약만 하는 8 MB가 부담이 아니지만, 주소 공간이 3 GB쯤인 32비트 시스템에서는 스레드 수백 개로 주소가 바닥납니다.

`std::thread`에는 스택 크기나 이름을 정하는 길이 없습니다. 필요하면 `native_handle()`로 pthread 핸들을 꺼내 [운영체제의 함수](#/read/cpp-advanced/thr-hardware)를 부릅니다.

## 상태와 소멸

```cpp
#include <exception>
#include <print>
#include <stdexcept>
#include <string>
#include <thread>
#include <utility>

int parse_port(const std::string& text)
{
    if (text.empty() || text[0] < '0' || text[0] > '9')
        throw std::invalid_argument("포트 번호가 아니다");
    return std::stoi(text);
}

int main()
{
    std::thread empty;
    std::thread running([] {});
    std::println("빈 것 {} / 방금 만든 것 {}", empty.joinable(),
                 running.joinable());
    std::thread moved = std::move(running);
    std::println("옮겨 준 쪽 {} / 받은 쪽 {}", running.joinable(),
                 moved.joinable());
    moved.join();
    std::println("join 한 뒤 {}", moved.joinable());

    // 스레드 안에서 난 예외를 붙잡아 두었다가, 기다린 쪽에서 다시 던진다
    std::exception_ptr error;
    int port = 0;
    {
        std::jthread worker([&] {
            try {
                port = parse_port("eighty");
            } catch (...) {
                error = std::current_exception();
            }
        });
    }
    try {
        if (error) std::rethrow_exception(error);
        std::println("포트 {}", port);
    } catch (const std::exception& e) {
        std::println("스레드에서 온 예외: {}", e.what());
    }
}
```

```text
빈 것 false / 방금 만든 것 true
옮겨 준 쪽 false / 받은 쪽 true
join 한 뒤 false
스레드에서 온 예외: 포트 번호가 아니다
```

`joinable()`은 "이 객체가 스레드를 쥐고 있는가"입니다. 스레드의 함수가 **이미 끝났어도** `join`하기 전에는 `true`입니다. [옮기면 원본은 빈 것이 됩니다](#/read/cpp-advanced/mv-moved-from).

| 소멸될 때 | `std::thread` | `std::jthread` |
| --- | --- | --- |
| 스레드를 쥐고 있으면 | `std::terminate` | 멈춤 신호를 보내고 `join` |
| 쥐고 있지 않으면 | 아무 일도 없다 | 아무 일도 없다 |

`std::thread`가 조용히 `join`하지 않는 것은 일부러입니다. 저절로 기다리면 끝나지 않는 스레드 때문에 프로그램이 까닭 없이 멈추고, 저절로 떼어 놓으면 스레드가 사라진 지역 변수를 건드립니다. 둘 다 조용한 버그라서 표준은 시끄럽게 끝나는 쪽을 골랐습니다. `jthread`는 "멈추라고 알린 뒤에 기다린다"로 첫째 문제를 풀었습니다.

예제의 뒷부분은 예외입니다. 스레드의 함수 밖으로 예외가 나가면 [프로그램이 끝나므로](#/read/cpp-advanced/res-exception) 안에서 모두 잡습니다. `std::current_exception()`은 날고 있는 예외를 `std::exception_ptr`에 담아 주고, `std::rethrow_exception`이 다른 스레드에서 그것을 다시 던집니다. [`std::future`](#/read/cpp-advanced/asy-future)가 이 일을 대신 해 줍니다.

## 멈춤 신호의 세 조각

| 조각 | 하는 일 |
| --- | --- |
| `std::stop_source` | 신호를 **보낸다**: `request_stop()`. `jthread` 안에 하나 들어 있다 |
| `std::stop_token` | 신호가 왔는지 **본다**: `stop_requested()`. 복사해서 여러 곳에 줄 수 있다 |
| `std::stop_callback` | 신호가 오는 순간 **불릴 함수**를 걸어 둔다. 객체가 사라지면 풀린다 |

`while (!stop.stop_requested())`로 도는 스레드는 루프 안에서 자는 동안 신호를 보지 못합니다. 100 ms씩 자는 스레드는 멈추는 데 최대 100 ms가 걸립니다(재어 보면 90 ms였습니다). `std::condition_variable_any`의 `wait`에 토큰을 넘기면 **신호에도 깨어납니다.**

```cpp
#include <condition_variable>
#include <mutex>
#include <print>
#include <queue>
#include <stop_token>
#include <thread>

int main()
{
    std::mutex mutex;
    std::condition_variable_any ready;
    std::queue<int> jobs;
    int done = 0;
    {
        std::jthread worker([&](std::stop_token stop) {
            std::unique_lock lock(mutex);
            // 일이 생기거나 멈춤 신호가 올 때까지 잔다
            while (ready.wait(lock, stop, [&] { return !jobs.empty(); })) {
                jobs.pop();
                ++done;
            }
            // false 가 돌아왔다: 멈춤 신호가 왔고 남은 일도 없다
        });

        for (int job = 0; job < 3; ++job) {
            {
                std::lock_guard lock(mutex);
                jobs.push(job);
            }
            ready.notify_one();
        }
    }   // 소멸자: request_stop() 으로 자는 스레드를 깨우고, join() 으로 기다린다
    std::println("처리한 일 {}", done);

    std::stop_source source;
    std::stop_token token = source.get_token();
    std::stop_callback on_stop(token, [] { std::println("  콜백이 불렸다"); });
    std::println("신호 전 {}", token.stop_requested());
    source.request_stop();
    std::println("신호 후 {}", token.stop_requested());
    std::stop_callback late(token, [] { std::println("  늦게 걸면 바로 불린다"); });
}
```

```text
처리한 일 3
신호 전 false
  콜백이 불렸다
신호 후 true
  늦게 걸면 바로 불린다
```

토큰을 받는 `wait`는 조건이 참이면 `true`를, 멈춤 신호로 깨어났는데 조건이 거짓이면 `false`를 돌려줍니다. 신호가 먼저 와도 큐에 일이 남아 있으면 `true`이므로, 이 스레드는 **남은 일을 다 하고** 끝납니다. 그래서 언제 돌려도 3입니다. 이렇게 쓰면 멈추는 데 0.1 ms가 걸렸습니다. [조건 변수 자체](#/read/cpp-advanced/sync-condvar)는 다음 챕터에서 다룹니다.

`stop_callback`은 `request_stop()`을 부른 스레드에서, 그 자리에서 불립니다. 짧고 던지지 않는 일만 겁니다.

## 막힌 호출 깨우기

조건 변수가 아니라 **운영체제의 호출**(`read`, `accept`, `poll`)에서 자고 있는 스레드는 토큰을 알지 못합니다. `stop_callback`으로 그 호출이 깨어날 일을 만들어 줍니다. 리눅스에서는 깨우는 데만 쓰는 디스크립터를 하나 더 지켜보게 합니다.

```cpp
#include <poll.h>
#include <sys/eventfd.h>
#include <unistd.h>

#include <cstdint>
#include <print>
#include <stop_token>
#include <thread>

int main()
{
    int data[2];
    if (::pipe(data) != 0) return 1;        // data[0] 에서 읽고 data[1] 에 쓴다
    int wake = ::eventfd(0, EFD_CLOEXEC);   // 깨우는 데만 쓰는 디스크립터

    {
        std::jthread reader([&](std::stop_token stop) {
            // 멈춤 신호가 오면 wake 에 한 번 써서 poll 을 깨운다
            std::stop_callback poke(stop, [&] {
                std::uint64_t one = 1;
                [[maybe_unused]] auto n = ::write(wake, &one, sizeof one);
            });
            pollfd watched[2] = {{data[0], POLLIN, 0}, {wake, POLLIN, 0}};
            while (true) {
                ::poll(watched, 2, -1);     // 시간제한 없이 잔다
                if (watched[0].revents != 0) {      // 읽을 것이 있으면 먼저 읽는다
                    char byte = 0;
                    if (::read(data[0], &byte, 1) == 1)
                        std::println("받음: {}", byte);
                } else if (watched[1].revents != 0) {
                    break;                          // 깨우는 신호만 남았다
                }
            }
            std::println("읽는 스레드가 끝난다");
        });

        [[maybe_unused]] auto n = ::write(data[1], "ab", 2);
    }   // request_stop → 콜백이 poll 을 깨운다 → join
    std::println("main 이 끝난다");
    ::close(data[0]);
    ::close(data[1]);
    ::close(wake);
}
```

```text
받음: a
받음: b
읽는 스레드가 끝난다
main 이 끝난다
```

`poll`에 시간제한을 주고 주기적으로 깨어나 확인하는 방법보다 낫습니다. 할 일이 없을 때 CPU를 전혀 쓰지 않고, 멈출 때는 바로 멈춥니다. 디스크립터들은 [래퍼](#/read/cpp-advanced/res-wrapper)에 담아야 하지만 여기서는 줄였습니다.

<Note>
`jthread`가 토큰을 넣어 주는 것은 함수의 **첫 매개변수가 `std::stop_token`일 때**뿐입니다. 받지 않는 함수를 넘기면 `request_stop()`은 아무도 보지 않는 신호가 되고, 소멸자는 그 스레드가 스스로 끝날 때까지 기다립니다. 끝나지 않는 루프라면 프로그램이 거기서 멈춥니다.
</Note>

## 정리

- 스레드 하나는 수십 µs와 스택 8 MB의 주소 공간이다. `joinable`한 `std::thread`가 사라지면 프로그램이 끝난다
- 멈춤은 `stop_source`가 보내고 `stop_token`이 본다. 자는 스레드는 토큰을 받는 `wait`나 `stop_callback`으로 깨운다
- 스레드 밖으로 예외를 내보내지 않는다. `exception_ptr`에 담아 기다리는 쪽에서 다시 던진다
