export const summary = '실패의 종류를 가르고 길을 고른다. 예외와 expected를 실패 비율별로 잰 값, 프로그램의 층마다 쓸 것';

[예외](#/read/cpp-syntax/exc-basic)와 [`expected`](#/read/cpp-stl/voc-expected)의 쓰는 법은 앞의 책들에서 봤고, "어느 쪽을 기본으로 삼을지"는 미뤄 두었습니다. 답은 실패가 **어떤 종류인지**와 **얼마나 자주 나는지**에 달려 있습니다. 뒤쪽은 잴 수 있습니다.

## 실패는 한 가지가 아니다

| 종류 | 예 | 알리는 법 |
| --- | --- | --- |
| 버그. 지켜야 할 조건을 어겼다 | 범위 밖의 번호, 널 포인터 | 알리지 않고 고친다. `assert`로 멈춘다. C++26에는 [계약](#/read/cpp-advanced/safe-contracts)이 있다 |
| 흔한 실패. 부르는 쪽이 대비한다 | 입력 해석, 통신 시간 초과, 없는 파일 | 값으로. `optional`, `expected` |
| 드문 실패. 멀리 위에서 처리한다 | 메모리 부족, 깨진 설정 | 예외 |
| 계속할 수 없다 | 자료구조가 망가졌다 | `std::terminate` |

첫 줄을 오류 처리에 섞지 않는 것이 먼저입니다. 버그에 예외를 던지면 누군가 `catch (...)`로 삼키고, 프로그램은 틀린 상태로 계속 돕니다.

## 얼마나 자주 실패하는가

같은 일을 예외와 `expected`로 쓰고, 실패하는 비율을 바꿔 가며 잽니다. 실패는 함수 넷을 거슬러 올라갑니다.

```cpp nosan flags=-O2
#include <chrono>
#include <expected>
#include <print>

struct Error { int code; };

long cleanups = 0;
struct Guard { ~Guard() { ++cleanups; } };    // 함수마다 치울 것이 하나 있다

// every번에 한 번 실패한다. 0이면 실패하지 않는다
bool fails(int v, int every) { return every != 0 && v % every == 0; }

// ---- 예외로 알린다 ----
[[gnu::noinline]] int leaf_throw(int v, int every)
{
    if (fails(v, every)) throw Error{v};
    return v * 2;
}
[[gnu::noinline]] int mid_throw(int v, int every, int depth)
{
    Guard guard;
    return depth == 0 ? leaf_throw(v, every) : mid_throw(v, every, depth - 1) + 1;
}

// ---- 값으로 알린다 ----
[[gnu::noinline]] std::expected<int, Error> leaf_value(int v, int every)
{
    if (fails(v, every)) return std::unexpected(Error{v});
    return v * 2;
}
[[gnu::noinline]] std::expected<int, Error> mid_value(int v, int every, int depth)
{
    Guard guard;
    if (depth == 0) return leaf_value(v, every);
    auto r = mid_value(v, every, depth - 1);
    if (!r) return r;                         // 실패를 한 층 위로 올린다
    return *r + 1;
}

template <typename F>
double ns_each(int calls, F work)
{
    const auto start = std::chrono::steady_clock::now();
    for (int i = 1; i <= calls; ++i) work(i);
    const auto end = std::chrono::steady_clock::now();
    return std::chrono::duration<double, std::nano>(end - start).count() / calls;
}

int main()
{
    long ok = 0, failed = 0;
    struct Case { int every; const char* label; };
    const Case cases[] = {
        {0, "실패 없음"}, {1000, "천 번에 한 번"}, {10, "열 번에 한 번"}};
    for (auto [every, label] : cases) {
        const int calls = every == 10 ? 200'000 : 2'000'000;
        const double thrown = ns_each(calls, [&](int i) {
            try {
                ok += mid_throw(i, every, 3);
            } catch (const Error& e) {
                failed += e.code;
            }
        });
        const double returned = ns_each(calls, [&](int i) {
            const auto r = mid_value(i, every, 3);
            if (r) ok += *r;
            else failed += r.error().code;
        });
        std::println("{}: 예외 {:.1f} ns, expected {:.1f} ns", label, thrown,
                     returned);
    }
    std::println("{} {} {}", ok, failed, cleanups);
}
```

```text nocheck
실패 없음: 예외 7.9 ns, expected 7.8 ns
천 번에 한 번: 예외 10.8 ns, expected 7.6 ns
열 번에 한 번: 예외 278.0 ns, expected 7.2 ns
```

x86-64, GCC 14 `-O2`입니다. 비율을 더 잘게 나누고 오류 코드를 돌려주는 판도 넣으면 이렇습니다.

| 실패하는 비율 | 예외 | `expected` | 오류 코드와 출력 인자 |
| --- | --- | --- | --- |
| 없음 | 7.7 ns | 7.9 ns | 7.8 ns |
| 10,000번에 한 번 | 8.3 ns | 7.5 ns | 7.8 ns |
| 1,000번에 한 번 | 10.4 ns | 7.8 ns | 7.9 ns |
| 100번에 한 번 | 34 ns | 7.8 ns | 7.5 ns |
| 10번에 한 번 | 270 ns | 7.8 ns | 7.2 ns |
| 2번에 한 번 | 1,330 ns | 7.6 ns | 6.6 ns |

- **성공하는 길은 셋이 같습니다.** "예외는 안 던지면 공짜"와 "`expected`는 검사 때문에 느리다"는 둘 다 이 예제에서 차이로 드러나지 않았습니다.
- **예외 한 번이 2.6 µs입니다.** 함수 하나만 거슬러 갈 때 0.8~0.9 µs이고, 함수 하나가 늘 때마다 0.45 µs쯤 붙습니다(열한 개면 5.8 µs). libc++를 쓴 Clang 20에서는 세 배쯤 더 들었습니다.
- **천 번에 한 번부터 보입니다.** 그보다 드물면 차이가 없고, 열 번에 한 번이면 35배입니다.

<Note kind="warn">
프로세스의 **첫 예외**는 훨씬 비쌉니다. 같은 `throw`가 처음 한 번은 22~43 µs, 그 뒤로는 0.8 µs였습니다. 스택을 푸는 코드와 표가 그때 처음 쓰이기 때문으로 보입니다. 시간에 한도가 있는 코드가 예외를 피하는 까닭은 평균이 아니라 이런 최악의 경우입니다.
</Note>

값은 실행 파일에도 붙습니다. 파일 21개짜리 프로젝트의 코드와 예외용 표를 합친 크기가 `-O2`에서 151 KB인데, `-fno-exceptions`로 136 KB, 스택을 푸는 표까지 빼면(`-fno-asynchronous-unwind-tables`) 126 KB였습니다. 예외를 한 번도 던지지 않는 프로그램에서 17%입니다.

## 층마다 고른다

| 자리 | 쓰는 것 | 까닭 |
| --- | --- | --- |
| 실패가 일의 일부인 함수 (해석, 통신, 찾기) | `expected`, `optional` | 자주 실패해도 값이 같다. 부르는 쪽이 그 자리에서 본다 |
| 깊은 곳의 드문 실패 | 예외 | 사이의 함수들이 실패를 나르는 코드를 쓰지 않는다 |
| 생성자와 연산자 | 예외, 또는 `expected`를 돌려주는 [만드는 함수](#/read/cpp-advanced/des-interface) | 돌려줄 자리가 없다 |
| 예외를 끈 빌드, 시간이 정해진 루프 | `expected` | 걸리는 시간이 실패 여부에 달리지 않는다 |
| 소멸자, 이동, `swap` | 실패하지 않게 만든다 | [`noexcept`](#/read/cpp-syntax/exc-noexcept)가 아니면 컨테이너가 복사로 돌아선다 |
| C가 부르는 함수, 스레드의 맨 위 함수 | 모두 잡아 값으로 바꾼다 | [예외가 넘어갈 수 없는 경계](#/read/cpp-advanced/res-exception)다 |

두 방식은 [경계에서 서로 바꿀 수 있습니다](#/read/cpp-stl/voc-expected). 응용 프로그램이라면 안쪽의 해석과 통신은 `expected`로, 그것을 묶는 위층은 예외로 두고, 맨 위에서 한 번 잡아 기록하는 꼴이 흔합니다. 예외를 끈 펌웨어라면 처음부터 끝까지 `expected`입니다.

## 어느 쪽이든 지킬 것

- **오류의 말을 하나로 정합니다.** 모듈마다 `enum class` 하나나 [`std::error_code`](#/read/cpp-stl/err-system)를 쓰고, 아래층의 오류는 위층의 말로 바꿔 올립니다. `int`로 된 오류 번호 여러 벌이 섞이면 0이 성공인지조차 헷갈립니다.
- **못 본 척할 수 없게 합니다.** 예외는 잡지 않으면 프로그램이 끝납니다. 값으로 돌려주는 함수에는 [`[[nodiscard]]`](#/read/cpp-syntax/fn-attributes)를 붙입니다.
- **올리면서 무엇을 하다 실패했는지 덧붙입니다.** "숫자가 아님"보다 "설정 파일 12번째 줄의 volume: 숫자가 아님"이 쓸모 있습니다. [`source_location`](#/read/cpp-stl/err-location)이 자리를 채워 줍니다.
- **치우는 일은 소멸자에 둡니다.** `return`으로 일찍 나가는 길도 예외만큼 많습니다. [RAII](#/read/cpp-advanced/res-guard)는 어느 방식에서나 필요합니다.

## 정리

- 버그, 흔한 실패, 드문 실패, 계속할 수 없는 상태를 가른다. 버그는 오류 처리가 아니라 고칠 것이다
- 성공하는 길의 값은 같다. 예외 한 번은 2.6 µs여서, 천 번에 한 번보다 자주 실패하는 일에는 `expected`를 쓴다
- 안쪽의 흔한 실패는 값으로, 깊은 곳의 드문 실패는 예외로, 경계에서는 모두 잡아 값으로 바꾼다
