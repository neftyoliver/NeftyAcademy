export const summary = '프레임에 들어가는 것과 크기, 만들고 깨우는 값, 할당을 없애거나 풀로 바꾸는 길';

코루틴 하나는 프레임 하나입니다. 이 페이지에서는 그 프레임이 얼마나 큰지, 만들고 깨우는 데 얼마가 드는지, 힙 할당을 어떻게 줄이는지를 잽니다. 잰 곳은 x86-64이고 `-O2`입니다.

## 프레임에 들어가는 것

프라미스 타입에 `operator new`를 두면 컴파일러가 프레임을 잡을 때 그것을 부릅니다. 넘어오는 크기를 찍어 봅니다.

```cpp
#include <coroutine>
#include <cstdlib>
#include <exception>
#include <print>

struct Sized {
    struct promise_type {
        // 프레임을 잡을 때 컴파일러가 이 함수를 부른다
        static void* operator new(std::size_t size)
        {
            last_size = size;
            return std::malloc(size);
        }
        static void operator delete(void* p) { std::free(p); }
        static inline std::size_t last_size = 0;

        Sized get_return_object()
        {
            return Sized{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() noexcept { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };
    explicit Sized(std::coroutine_handle<promise_type> h) : handle(h) {}
    Sized(const Sized&) = delete;
    ~Sized() { handle.destroy(); }
    std::coroutine_handle<promise_type> handle;
};

void fill(char* buffer) { buffer[0] = 'x'; }

Sized empty() { co_return; }

int seen = 0;

Sized with_counter(int from)
{
    for (int n = from;; ++n) {
        seen = n;
        co_await std::suspend_always{};   // n이 멈춤을 건너 산다
    }
}

Sized buffer_across()
{
    char buffer[1024];
    fill(buffer);
    co_await std::suspend_always{};   // buffer가 멈춤을 건너 산다
    fill(buffer);
}

Sized buffer_before()
{
    {
        char buffer[1024];
        fill(buffer);   // 멈추기 전에 다 쓰고 블록을 닫는다
    }
    co_await std::suspend_always{};
}

template <typename F>
void show(const char* what, F make)
{
    Sized job = make();
    std::println("{}: {}바이트", what, Sized::promise_type::last_size);
}

int main()
{
    show("빈 코루틴", empty);
    show("인자 하나와 지역 변수 하나", [] { return with_counter(1); });
    show("버퍼가 멈춤을 건너 산다", buffer_across);
    show("버퍼를 멈추기 전에 다 쓴다", buffer_before);
}
```

```text
빈 코루틴: 40바이트
인자 하나와 지역 변수 하나: 56바이트
버퍼가 멈춤을 건너 산다: 1064바이트
버퍼를 멈추기 전에 다 쓴다: 1064바이트
```

GCC 14의 결과이고 `-O0`과 `-O2`가 같습니다. AArch64에서도 같았습니다. Clang 20은 다릅니다. `-O2` 열은 코루틴이 인라인되지 않게 막고 잰 것입니다. 막지 않으면 Clang은 이 프로그램에서 프레임을 아예 힙에 잡지 않았습니다. 그 이야기는 아래에서 합니다.

| 코루틴 | GCC 14 | Clang 20 `-O0` | Clang 20 `-O2` |
| --- | --- | --- | --- |
| 빈 코루틴 | 40 | 24 | 24 |
| 인자 하나와 지역 변수 하나 | 56 | 32 | 32 |
| 버퍼가 멈춤을 건너 산다 | 1,064 | 1,056 | 1,056 |
| 버퍼를 멈추기 전에 다 쓴다 | 1,064 | 24 | 24 |

빈 프레임에는 이어 돌릴 함수와 없앨 함수의 포인터 둘, 프라미스 객체, 멈춘 자리의 번호가 들어 있습니다. 거기에 인자와 지역 변수가 더해집니다.

마지막 줄이 눈여겨볼 곳입니다. Clang은 **멈춤을 건너 사는 변수만** 프레임에 넣습니다. GCC 14는 블록을 닫아 이미 사라진 버퍼까지 넣었습니다. GCC에서는 코루틴 본문에 큰 지역 배열을 두지 말고, 그런 일은 보통 함수로 빼냅니다. 보통 함수의 지역 변수는 스택에 있습니다.

## 얼마나 드는가

| 일 | GCC 14 | Clang 20 |
| --- | --- | --- |
| 인라인되지 않은 보통 함수 호출 | 0.8 ns | 0.6 ns |
| 코루틴을 깨우고 다시 멈추기 | 1.5~2.1 ns | 1.1~1.4 ns |
| 코루틴을 만들고 없애기 | 11 ns | 12 ns |
| 멈춰 있는 코루틴 100만 개의 메모리 | 68 MB | 53 MB |

만들고 없애는 11 ns는 거의 다 `malloc`과 `free`입니다. 깨우기는 함수 포인터를 거친 호출 하나와 멈춘 자리로의 분기입니다.

[스레드](#/read/cpp-advanced/thr-jthread)와 견주면 차이가 드러납니다. 스레드는 만드는 데 25 µs, 자던 것을 [깨워 넘겨받는 데 1~12 µs](#/read/cpp-advanced/sync-mutex)가 들었고, 하나마다 주소 공간 8 MB를 잡았습니다. 코루틴은 만드는 값이 2천 분의 1, 넘겨받는 값이 수백에서 수천 분의 1이고, 멈춰 있는 하나가 70바이트 안팎입니다. [`future`로는 감당하지 못하던](#/read/cpp-advanced/asy-future) "동시에 기다리는 일 수만 개"가 되는 까닭입니다.

다만 이 숫자는 **기다림을 바꿔 타는 값**일 뿐입니다. 코루틴이 계산을 빠르게 하지는 않습니다. [제너레이터의 원소마다 1.5 ns](#/read/cpp-advanced/co-generator)가 그랬듯, 원소마다 하는 일이 작으면 오히려 느려집니다.

## 할당을 줄이는 길

첫째 길은 컴파일러가 알아서 없애는 것입니다. 코루틴이 만든 함수 안에서만 살고 인라인되면, 프레임을 그 함수의 스택에 둘 수 있습니다.

| 프로그램 | GCC 14 `-O2`, `-O3` | Clang 20 `-O2` |
| --- | --- | --- |
| 값 셋을 내주는 제너레이터를 그 자리에서 다 씀 | 할당한다 | **없앴다** |
| 위의 `show`처럼 만들고 곧 없앰 | 할당한다 | **없앴다** |
| [예외를 담아 다시 던지는 제너레이터](#/read/cpp-advanced/co-generator) | 할당한다 | 할당한다 |

GCC 14는 한 번도 없애지 않았고, Clang 20은 타입이 조금 복잡해지자 없애지 못했습니다. 기대할 수는 있어도 **믿고 설계할 것은 아닙니다.**

둘째 길은 프레임을 내가 정한 곳에서 잡는 것입니다. 위에서 크기를 찍던 그 `operator new`에 풀을 답니다.

```cpp
#include <coroutine>
#include <cstdlib>
#include <exception>
#include <print>

// 같은 크기의 칸을 돌려 쓰는 풀
class FramePool {
public:
    static void* take(std::size_t size)
    {
        if (size > slot_size)
            return std::malloc(size);   // 큰 것은 그냥 힙에서
        if (free_ == nullptr) {
            ++mallocs;
            return std::malloc(slot_size);
        }
        Slot* slot = free_;
        free_ = slot->next;
        return slot;
    }
    static void give(void* p, std::size_t size)
    {
        if (size > slot_size) {
            std::free(p);
            return;
        }
        auto* slot = static_cast<Slot*>(p);
        slot->next = free_;
        free_ = slot;
    }
    static constexpr std::size_t slot_size = 64;
    static inline int mallocs = 0;

private:
    struct Slot {
        Slot* next;
    };
    static inline Slot* free_ = nullptr;
};

struct Pooled {
    struct promise_type {
        static void* operator new(std::size_t size)
        {
            return FramePool::take(size);
        }
        static void operator delete(void* p, std::size_t size)
        {
            FramePool::give(p, size);
        }
        Pooled get_return_object()
        {
            return Pooled{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() noexcept { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };
    explicit Pooled(std::coroutine_handle<promise_type> h) : handle(h) {}
    Pooled(const Pooled&) = delete;
    ~Pooled() { handle.destroy(); }
    std::coroutine_handle<promise_type> handle;
};

Pooled step(int& counter)
{
    ++counter;
    co_return;
}

int main()
{
    int counter = 0;
    for (int i = 0; i < 1000; ++i) {
        Pooled job = step(counter);
        job.handle.resume();
    }
    std::println("코루틴 {}개를 만들고 없앴다. malloc은 {}번", counter,
                 FramePool::mallocs);
}
```

```text
코루틴 1000개를 만들고 없앴다. malloc은 1번
```

만들고 돌리고 없애는 한 바퀴가 `malloc`으로는 10 ns, 이 풀로는 4.5 ns였습니다. 이 풀은 한 스레드에서만 쓸 수 있습니다. 풀과 아레나를 제대로 만드는 법은 [「아레나와 풀」](#/read/cpp-advanced/mm-arena)에서 다룹니다.

| 길 | 방법 | 확인한 것 |
| --- | --- | --- |
| 타입마다 풀 | 프라미스 타입의 `operator new`, `operator delete` | 위 예제 |
| 부를 때마다 할당자 | 코루틴의 첫 인자를 `std::allocator_arg`와 할당자로 받는다 | `std::pmr::generator`에 스택 버퍼를 넘기면 힙 할당 0번 |
| 실패를 예외 없이 | 프라미스 타입에 `get_return_object_on_allocation_failure()`를 둔다 | `noexcept`인 `operator new`가 `nullptr`를 주면 그 함수의 결과가 돌아온다 |

<Note kind="warn">
GCC 14는 `std::pmr::generator`를 쓰는 코드에 자기 헤더를 가리키는 `-Wmismatched-new-delete` 경고를 냅니다. 동작은 맞았고(ASan에서도 깨끗했습니다) 경고만 납니다. 셋째 줄은 예외를 끈 빌드(`-fno-exceptions`)에서 코루틴을 쓸 때 필요합니다.
</Note>

## 정리

- 프레임은 수십 바이트에 인자와 지역 변수를 더한 것이다. GCC 14는 멈춤을 건너지 않는 지역 변수도 넣는다
- 깨우기는 2 ns 안팎, 만들기는 `malloc` 한 번 값이다. 스레드보다 천 배쯤 싸지만 계산이 빨라지지는 않는다
- 할당을 컴파일러가 없애 주기를 믿지 말고, 필요하면 프라미스 타입의 `operator new`로 풀에서 잡는다
