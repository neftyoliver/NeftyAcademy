잠금이 둘 이상이 되는 순간 새로운 버그가 생깁니다. 두 스레드가 **서로가 쥔 것을 기다리며** 영원히 멈추는 교착(deadlock)입니다. 경합과 달리 값이 틀리지는 않습니다. 프로그램이 그냥 서 버립니다.

## 서로를 기다린다

```cpp
#include <chrono>
#include <latch>
#include <mutex>
#include <print>
#include <thread>

using namespace std::chrono_literals;

int main()
{
    std::timed_mutex a, b;
    std::latch both_hold(2);        // 둘 다 첫 뮤텍스를 쥘 때까지 기다리는 문
    // 둘 다 시도를 마칠 때까지 첫 뮤텍스를 놓지 않는다
    std::latch both_tried(2);
    bool first_got = true, second_got = true;
    {
        std::jthread first([&] {
            std::lock_guard hold(a);                    // a 를 쥐고
            both_hold.count_down();
            both_hold.wait();
            first_got = b.try_lock_for(30ms);           // b 를 기다린다
            both_tried.count_down();
            both_tried.wait();
        });
        std::jthread second([&] {
            std::lock_guard hold(b);                    // b 를 쥐고
            both_hold.count_down();
            both_hold.wait();
            second_got = a.try_lock_for(30ms);          // a 를 기다린다
            both_tried.count_down();
            both_tried.wait();
        });
    }
    std::println("첫째가 b 를 얻었나 {} / 둘째가 a 를 얻었나 {}", first_got,
                 second_got);
}
```

```text
첫째가 b 를 얻었나 false / 둘째가 a 를 얻었나 false
```

예제가 끝나도록 30 ms만 기다리게 했습니다. 보통의 `lock()`이었다면 둘 다 영원히 기다립니다. 실제 프로그램에서는 [`latch`](#/read/cpp-advanced/sync-semaphore)로 때를 맞추지 않으므로 **천 번에 한 번** 이렇게 엇갈리고, 그래서 시험에서는 통과하고 현장에서 멈춥니다.

교착은 네 가지가 모두 맞아야 생깁니다. 하나만 깨면 됩니다.

| 조건 | 깨는 방법 |
| --- | --- |
| 한 번에 한 스레드만 쥔다 | 잠금이 필요 없게 만든다: 자료를 넘겨주거나 [원자적 연산](#/read/cpp-advanced/atm-atomic)으로 |
| 쥔 채로 다른 것을 기다린다 | 여럿을 **한꺼번에** 잠근다: `std::scoped_lock` |
| 쥔 것을 빼앗을 수 없다 | 못 얻으면 쥔 것을 놓고 처음부터 다시: `try_lock` |
| 기다림이 고리를 이룬다 | 잠그는 **순서**를 정한다 |

## 순서를 정하거나, 한꺼번에 잠근다

모든 코드가 `a` 다음에 `b`를 잠그면 고리가 생길 수 없습니다. 뮤텍스가 정해져 있으면 문서에 순서를 적으면 됩니다. 어느 둘이 올지 모를 때는 `std::scoped_lock`에 맡깁니다.

```cpp
#include <functional>
#include <mutex>
#include <print>
#include <thread>
#include <utility>
#include <vector>

struct Account {
    std::mutex guard;
    long balance = 0;       // guard 가 지킨다
};

// 두 계좌를 함께 잠근다. 어느 쪽에서 어느 쪽으로 보내든 교착이 나지 않는다
void transfer(Account& from, Account& to, long amount)
{
    // 같은 뮤텍스를 두 번 잠그지 않는다
    if (&from == &to) return;
    std::scoped_lock lock(from.guard, to.guard);
    from.balance -= amount;
    to.balance += amount;
}

// 듣는 쪽을 부를 때는 잠금을 쥐지 않는다
class Button {
public:
    void on_click(std::function<void()> listener)
    {
        std::lock_guard lock(guard_);
        listeners_.push_back(std::move(listener));
    }

    void click()
    {
        std::vector<std::function<void()>> snapshot;
        {
            std::lock_guard lock(guard_);
            snapshot = listeners_;                  // 잠근 동안에는 복사만 한다
        }
        for (auto& listener : snapshot) listener(); // 부르는 것은 잠금 밖에서
    }

private:
    std::mutex guard_;
    std::vector<std::function<void()>> listeners_;
};

int main()
{
    Account kim, lee;
    kim.balance = lee.balance = 1'000'000;
    {
        std::jthread one([&] {
            for (int i = 0; i < 100'000; ++i) transfer(kim, lee, 3);
        });
        std::jthread two([&] {
            for (int i = 0; i < 100'000; ++i) transfer(lee, kim, 2);
        });
    }
    std::println("kim {} + lee {} = {}", kim.balance, lee.balance,
                 kim.balance + lee.balance);

    Button button;
    int clicks = 0;
    button.on_click([&] {
        ++clicks;
        // 듣는 쪽이 Button 을 다시 부른다
        if (clicks == 1) button.on_click([&] { ++clicks; });
    });
    button.click();
    button.click();
    std::println("clicks {}", clicks);
}
```

```text
kim 900000 + lee 1100000 = 2000000
clicks 3
```

`transfer(kim, lee)`와 `transfer(lee, kim)`은 두 뮤텍스를 반대 순서로 넘기지만 멈추지 않습니다. `scoped_lock`은 하나를 잠그고 나머지를 `try_lock`으로 시도하다가, 안 되면 **쥔 것을 놓고** 다른 것부터 다시 시작합니다. 표의 둘째와 셋째 조건을 함께 깨는 방법입니다. 같은 뮤텍스를 두 번 넘기는 것은 막아 주지 못하므로 첫 줄에서 걸러 냈습니다.

## 잠근 채로 남의 코드를 부르지 않는다

교착에 스레드 둘이 꼭 필요한 것은 아닙니다. `Button::click`이 `guard_`를 쥔 채로 듣는 쪽을 부르고, 듣는 쪽이 `button.on_click(…)`을 부르면 **같은 스레드가** 같은 뮤텍스를 다시 잠그려 합니다. [정의되지 않은 동작](#/read/cpp-advanced/sync-mutex)이고 리눅스에서는 그 자리에 멈춥니다. 콜백이 다른 클래스의 뮤텍스를 잠그면 두 클래스 사이에 잠금 순서가 생기고, 반대쪽에서도 부르면 고리가 됩니다.

위의 `click`은 잠근 동안에는 목록을 복사만 하고, 부르는 것은 밖에서 합니다. 콜백, 가상 함수, 템플릿 인자로 받은 함수처럼 **무엇을 할지 내가 모르는 코드**는 잠금 밖에서 부릅니다. 값은 하나 있습니다. 복사한 뒤에 구독을 끊은 쪽이 한 번 더 불릴 수 있으므로, 듣는 쪽이 [사라진 객체를 건드리지 않게](#/read/cpp-advanced/sp-weak) 해야 합니다.

## 찾아 주는 도구

교착은 다시 일으키기 어렵지만, **순서가 엇갈린 것 자체**는 한 번만 지나가도 보입니다. ThreadSanitizer는 잠근 순서를 기록해 두었다가 고리가 생기면 알립니다. 아래는 `a → b`로 잠그는 함수와 `b → a`로 잠그는 함수를 **차례로** 돌려서, 실제로는 멈추지 않은 실행에서 나온 보고입니다.

```text
WARNING: ThreadSanitizer: lock-order-inversion (potential deadlock)
  Cycle in lock order graph: M0 (0x55622b3b3040) => M1 (0x55622b3b3080) => M0

  Mutex M1 acquired here while holding mutex M0 in thread T1:
    #4 first() d2.cpp:9
  Mutex M0 acquired here while holding mutex M1 in thread T2:
    #4 second() d2.cpp:15
```

이미 멈춘 프로그램은 디버거를 붙여 스레드마다 어디에 서 있는지 봅니다.

```text
$ gdb -p <프로세스 번호> -batch -ex "thread apply all bt"
Thread 3 ... #1 __lll_lock_wait (futex=<b>)     #7 first () at d3.cpp:13
Thread 2 ... #1 __lll_lock_wait (futex=<a>)     #7 second () at d3.cpp:21
Thread 1 ... #4 std::thread::join()
```

`__lll_lock_wait`에 서 있는 스레드가 둘 이상이고 서로 다른 뮤텍스를 기다리고 있으면 교착입니다. 두 출력 모두 이 쪽의 예제를 실제로 돌려 얻은 것을 줄인 것입니다.

<Note>
잠금에 층을 매기는 방법도 있습니다. 뮤텍스마다 번호를 주고 "더 낮은 번호만 추가로 잠글 수 있다"고 정한 뒤, 디버그 빌드에서 `thread_local` 변수로 지금 쥔 가장 낮은 번호를 기억해 어기면 바로 멈추게 합니다. 큰 프로그램에서 순서를 문서가 아니라 코드로 지키는 방법입니다.
</Note>

## 정리

- 교착은 쥔 채로 다른 것을 기다리는 스레드들이 고리를 이룰 때 생긴다. 순서를 정하거나 `scoped_lock`으로 한꺼번에 잠근다
- 잠근 채로 콜백을 부르지 않는다. 목록을 복사해 잠금 밖에서 부른다
- ThreadSanitizer는 멈추지 않은 실행에서도 엇갈린 순서를 찾아 준다. 멈춘 프로그램은 디버거로 스레드마다의 자리를 본다
