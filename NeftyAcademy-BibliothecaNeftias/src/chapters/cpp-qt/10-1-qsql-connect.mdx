Qt SQL 모듈은 SQLite, PostgreSQL, MySQL/MariaDB, ODBC 같은 데이터베이스를 하나의 API로 다룹니다. 데이터베이스마다 **드라이버** 플러그인이 있고([「Qt의 구성과 라이선스」](#/read/cpp-qt/start-what)에서 SQLite 드라이버가 있는지 확인했습니다), 앱 코드는 `QSqlDatabase`로 연결하고 `QSqlQuery`로 SQL을 실행합니다. 데스크톱 앱의 로컬 저장소로는 서버가 필요 없는 SQLite가 가장 흔합니다.

## 책 목록 데이터베이스

```cpp qt=Sql
#include <QCoreApplication>
#include <QSqlDatabase>
#include <QSqlError>
#include <QSqlQuery>
#include <cstdio>

bool exec(QSqlQuery& q, const char* what) {
    if (q.exec()) return true;
    std::printf("%s 실패: %s\n", what, qPrintable(q.lastError().text()));
    return false;
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    // 연결 하나 = 이름 하나. SQLite는 파일 이름 대신 ":memory:"로 메모리에 연다
    QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE", "main");
    db.setDatabaseName(":memory:");
    if (!db.open()) return 1;

    QSqlQuery q(db);
    q.exec("CREATE TABLE books("
           "id INTEGER PRIMARY KEY, title TEXT UNIQUE, pages INT)");

    // 준비된 문장 + 자리표시자: 값은 따로 묶는다(SQL 주입 방지)
    q.prepare("INSERT INTO books(title, pages) VALUES(:title, :pages)");
    // 여러 줄은 거래로 묶으면 빠르고 안전하다
    db.transaction();
    for (auto [t, p] : {std::pair{"게임 엔진", 61}, {"Qt", 59}, {"STL", 40}}) {
        q.bindValue(":title", t);
        q.bindValue(":pages", p);
        exec(q, "추가");
    }
    db.commit();
    std::printf("마지막으로 넣은 id: %lld\n", q.lastInsertId().toLongLong());

    // 사용자가 넣은 글도 자리표시자로: 따옴표가 있어도 안전하다
    QString evil = "x'); DROP TABLE books; --";
    q.prepare("INSERT INTO books(title, pages) VALUES(?, ?)");
    q.addBindValue(evil);
    q.addBindValue(1);
    exec(q, "이상한 제목 추가");

    // 제약 위반: 같은 제목
    q.prepare("INSERT INTO books(title, pages) VALUES(?, ?)");
    q.addBindValue("Qt");
    q.addBindValue(10);
    exec(q, "중복 제목 추가");

    // 거래 되돌리기
    db.transaction();
    QSqlQuery(db).exec("DELETE FROM books");
    db.rollback();                              // 지운 것을 없던 일로

    // 읽기: next()로 한 줄씩
    q.exec("SELECT title, pages FROM books ORDER BY pages DESC");
    while (q.next())
        std::printf("  %s (%d쪽)\n",
                    qPrintable(q.value(0).toString()), q.value(1).toInt());
    q.exec("SELECT SUM(pages) FROM books");
    q.next();
    std::printf("합계 %d쪽\n", q.value(0).toInt());
}
```

## 연결

`QSqlDatabase::addDatabase("QSQLITE", "main")`은 SQLite 드라이버로 **이름이 "main"인 연결**을 만듭니다. 이름을 주지 않으면 기본 연결이 됩니다. SQLite는 파일 이름을 주면 그 파일을, `":memory:"`를 주면 메모리 안의 임시 데이터베이스를 엽니다. 서버형 데이터베이스는 `setHostName`, `setUserName`, `setPassword`를 더 설정합니다. 비밀번호는 코드에 적지 말고 사용자에게 받거나 운영체제의 비밀 저장소를 쓰세요.

## 준비된 문장

- `prepare("... VALUES(:title, :pages)")`로 SQL의 틀을 한 번 만들고, `bindValue`로 값을 묶어 여러 번 실행했습니다. 틀은 한 번만 해석되므로 빠릅니다
- 무엇보다 **안전합니다**. 값은 SQL 문장과 따로 전달되므로, 사용자가 `x'); DROP TABLE books; --` 같은 글을 넣어도 그냥 제목 글자로 저장되었습니다. 문자열을 이어 붙여 SQL을 만들면 이것이 그대로 실행되는 **SQL 주입** 취약점이 됩니다. 사용자 입력이 들어가는 SQL은 언제나 자리표시자를 씁니다
- `:이름` 대신 `?`를 쓰고 `addBindValue`로 순서대로 묶을 수도 있습니다

## 거래

- `transaction()`과 `commit()` 사이의 변경은 한 덩어리로 반영됩니다. SQLite는 거래 없이 한 줄씩 넣으면 줄마다 디스크에 쓰므로, 많은 줄을 넣을 때 거래로 묶으면 수십 배 빨라집니다
- `rollback()`은 거래 안의 변경을 없던 일로 합니다. 모든 줄을 지웠다가 되돌렸더니 네 권이 그대로 남았습니다. 여러 표를 함께 고치다 중간에 실패하면 되돌려서 데이터가 반쯤 바뀐 상태로 남지 않게 합니다

## 오류와 결과

`exec()`가 거짓이면 `lastError()`가 원인을 알려 줍니다. 같은 제목을 다시 넣자 UNIQUE 제약 위반이 보고되었습니다. 결과는 `next()`가 참인 동안 한 줄씩 읽고, `value(열 번호)`로 값을 꺼냅니다. 값은 [「QVariant」](#/read/cpp-qt/core-variant)로 오므로 `toInt()`, `toString()`으로 바꿉니다.

<Note>
`QSqlDatabase` 연결은 **만든 스레드에서만** 써야 합니다. 작업 스레드에서 데이터베이스를 쓰려면 그 스레드에서 다른 이름으로 연결을 새로 만드세요. 또 연결 객체를 클래스 멤버로 오래 들고 있기보다, 필요할 때 `QSqlDatabase::database("main")`으로 이름으로 꺼내 쓰는 것이 권장 방식입니다. 연결을 지우는 `removeDatabase`는 그 연결을 쓰는 `QSqlQuery`와 `QSqlDatabase` 객체가 모두 사라진 뒤에 불러야 경고가 나지 않습니다.
</Note>

## 정리

- QSqlDatabase로 드라이버와 이름을 정해 연결하고, SQLite는 파일이나 :memory:를 연다
- 사용자 값이 들어가는 SQL은 prepare와 자리표시자로 실행해 SQL 주입을 막고, 여러 줄은 거래로 묶는다
- exec 결과와 lastError로 오류를 확인하고, next와 value로 결과를 읽으며, 연결은 만든 스레드에서만 쓴다
