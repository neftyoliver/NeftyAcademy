요즘 노트북과 휴대폰 화면은 1인치에 화소가 아주 많아서, 운영체제가 모든 것을 150%, 200%로 키워 보여 줍니다. 그대로 100×50 화소짜리 버튼을 그리면 손톱만 하게 보일 것입니다. Qt 6은 이것을 기본으로 처리합니다. 코드에서 쓰는 크기와 좌표는 모두 **논리 화소**이고, Qt가 화면의 배율(**devicePixelRatio**)만큼 곱해 실제 **물리 화소**로 그립니다.

## 200% 화면 흉내 내기

화면 없는 환경에서 `QT_SCALE_FACTOR=2`로 배율 200% 모니터를 흉내 냈습니다.

```cpp qt=Widgets
#include <QApplication>
#include <QImage>
#include <QPainter>
#include <QWidget>
#include <cstdio>

int main(int argc, char** argv) {
    // 화면 배율 200%인 모니터를 흉내 낸다
    qputenv("QT_SCALE_FACTOR", "2");
    QApplication app(argc, argv);

    QWidget w;
    w.resize(100, 50);                         // 크기는 늘 '논리 화소'로 말한다
    w.show();
    app.processEvents();
    QPixmap shot = w.grab();
    std::printf("위젯 %dx%d(논리), 배율 %.1f, 실제로 떠진 그림 %dx%d(물리)\n",
                w.width(), w.height(), w.devicePixelRatioF(),
                shot.width(), shot.height());

    // 선명한 이미지를 직접 만들 때: 물리 크기로 만들고 배율을 알려 준다
    qreal dpr = w.devicePixelRatioF();
    QImage img(QSize(40, 20) * dpr, QImage::Format_ARGB32_Premultiplied);
    img.setDevicePixelRatio(dpr);
    img.fill(Qt::white);
    {
        QPainter p(&img);
        p.setPen(QPen(Qt::black, 1));          // 논리 1화소 선
        p.drawLine(0, 10, 39, 10);             // 논리 좌표로 그린다
    }
    QSizeF logical = img.deviceIndependentSize();
    std::printf("이미지 물리 %dx%d, 논리 %.0fx%.0f\n", img.width(), img.height(),
                logical.width(), logical.height());
    int dark = 0;                              // 선이 물리 화소 몇 줄인지 센다
    for (int y = 0; y < img.height(); ++y)
        if (qGray(img.pixel(5, y)) < 128) ++dark;
    std::printf("논리 1화소 선 = 물리 %d줄\n", dark);
}
```

```text
위젯 100x50(논리), 배율 2.0, 실제로 떠진 그림 200x100(물리)
이미지 물리 80x40, 논리 40x20
논리 1화소 선 = 물리 2줄
```

## 논리 화소로 생각한다

- 위젯을 100×50으로 만들었고, `width()`도 100을 돌려주었습니다. 그런데 위젯을 그림으로 뜨자 200×100이었습니다. 레이아웃, 글꼴 크기, 마우스 좌표는 모두 논리 화소라서, 배율이 바뀌어도 코드는 그대로입니다
- `QPainter`로 위젯에 그릴 때도 논리 좌표를 씁니다. Qt가 배율을 곱해 주므로, 1화소 선은 200% 화면에서 물리 2줄로 그려집니다. 그래서 선과 글자가 자동으로 선명합니다

## 이미지를 직접 만들 때

문제가 생기는 곳은 **비트맵**입니다. 40×20짜리 `QImage`에 그려서 위젯에 붙이면, Qt가 그것을 2배로 늘려 그리므로 흐릿해집니다. 선명하게 하려면 예제처럼 **물리 크기**(80×40)로 만들고 `setDevicePixelRatio(2)`로 배율을 알려 줍니다. 그러면 이미지는 논리적으로 40×20처럼 다뤄지면서, 안에는 두 배의 화소가 들어 있습니다. 그 위에 그리는 `QPainter`도 논리 좌표로 그리면 됩니다.

- 캐시용 `QPixmap`, 오프스크린 버퍼, 썸네일을 만들 때 모두 같은 규칙입니다
- 아이콘은 `icon.png`와 함께 `icon@2x.png`를 같은 폴더(자원 파일)에 두면 `QIcon`과 `QPixmap`이 배율에 맞는 것을 고릅니다. 가장 간단한 것은 크기에 상관없이 선명한 SVG 아이콘을 쓰는 것입니다

## 소수 배율

Windows에서는 125%, 150%, 175% 같은 배율이 흔합니다. Qt 6은 기본으로 이 배율을 반올림하지 않고 그대로 씁니다. 그래서 논리 좌표 1.0이 물리 1.5화소가 되는 일이 생기고, 1화소 선이나 사각형 테두리가 화소 경계에 걸쳐 흐릿하거나 두께가 들쭉날쭉해 보일 수 있습니다. 이런 위젯은 펜 두께를 `1 / devicePixelRatio`로 잡아 물리 1화소 선을 그리거나, 좌표를 0.5만큼 옮겨 화소 경계에 맞추는 식으로 다듬습니다. 앱 전체의 정책은 `QGuiApplication::setHighDpiScaleFactorRoundingPolicy`로 바꿀 수 있습니다.

<Note>
창이 배율이 다른 두 모니터 사이를 옮겨 가면 devicePixelRatio가 바뀝니다. 그 값으로 미리 만들어 둔 캐시 이미지는 다시 만들어야 하므로, `devicePixelRatioF()`가 바뀌는 것을 감지해(창의 `screenChanged` 시그널, 또는 Qt 6.6부터 생긴 `QEvent::DevicePixelRatioChange`) 캐시를 지웁니다. 화면 배율을 테스트할 때는 예제처럼 `QT_SCALE_FACTOR` 환경 변수를 쓰면 편합니다.
</Note>

## 정리

- Qt 6에서 코드의 크기와 좌표는 논리 화소이고, Qt가 devicePixelRatio를 곱해 물리 화소로 그린다
- 직접 만드는 비트맵은 물리 크기로 만들고 setDevicePixelRatio로 배율을 알려야 선명하며, 아이콘은 @2x 이미지나 SVG를 쓴다
- 소수 배율에서는 1화소 선이 흐려질 수 있어 다듬고, 모니터를 옮기면 배율이 바뀌므로 캐시를 다시 만든다
