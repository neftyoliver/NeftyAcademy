내 컴퓨터에서 잘 도는 Qt 앱을 다른 사람의 컴퓨터에 그냥 복사하면 대개 바로 죽습니다. 그 컴퓨터에는 Qt 라이브러리가 없거나, 있어도 다른 판이고, 무엇보다 **플러그인**이 없습니다. 배포란 앱이 실제로 쓰는 것들을 빠짐없이, 앱이 찾을 수 있는 자리에 함께 넣는 일입니다.

## 앱이 실제로 쓰는 것

창 하나 띄우는 앱이 실행 중에 무엇을 올렸는지 직접 보았습니다(리눅스의 `/proc/self/maps`).

```cpp qt=Widgets
#include <QApplication>
#include <QFile>
#include <QImageReader>
#include <QLabel>
#include <QSet>
#include <cstdio>

// 지금 이 프로세스에 실제로 올라온 Qt 라이브러리와 플러그인 목록(/proc/self/maps)
void loaded(const char* title) {
    QFile maps("/proc/self/maps");
    maps.open(QIODevice::ReadOnly);
    QSet<QString> libs, plugins;
    for (const QByteArray& line : maps.readAll().split('\n')) {
        QString path = QString::fromUtf8(line.mid(line.indexOf('/')));
        QString name = path.section('/', -1);
        if (path.contains("/plugins/")) plugins << path.section("/plugins/", 1);
        else if (name.startsWith("libQt6")) libs << name.section(".so", 0, 0);
    }
    QStringList l(libs.begin(), libs.end()), p(plugins.begin(), plugins.end());
    l.sort();
    p.sort();
    std::printf("%s\n  라이브러리: %s\n", title, qPrintable(l.join(" ")));
    for (const QString& plugin : p)
        std::printf("  플러그인: %s\n", qPrintable(plugin));
}

int main(int argc, char** argv) {
    QApplication app(argc, argv);
    loaded("QApplication을 만든 뒤");
    QLabel label("안녕");
    label.show();
    // 이미지 형식 목록을 묻기만 해도 이미지 플러그인들이 올라온다
    std::printf("읽을 수 있는 이미지 형식 수: %lld\n",
                (long long)QImageReader::supportedImageFormats().size());
    loaded("창을 띄우고 이미지 형식을 물은 뒤");
}
```

```text
QApplication을 만든 뒤
  라이브러리: libQt6Core libQt6DBus libQt6Gui libQt6Widgets
  플러그인: platforms/libqoffscreen.so
읽을 수 있는 이미지 형식 수: 12
창을 띄우고 이미지 형식을 물은 뒤
  라이브러리: libQt6Core libQt6DBus libQt6Gui libQt6Widgets
  플러그인: imageformats/libqgif.so
  플러그인: imageformats/libqico.so
  플러그인: imageformats/libqjpeg.so
  플러그인: platforms/libqoffscreen.so
```

- 링크한 것은 Widgets뿐인데 Core, Gui, DBus까지 올라왔습니다. 모듈이 기대는 모듈도 함께 가야 합니다
- `QApplication`을 만드는 순간 **플랫폼 플러그인**이 올라왔습니다(여기서는 화면 없는 실행용 offscreen, 보통의 리눅스 데스크톱에서는 xcb나 wayland, Windows는 qwindows). 이것이 없으면 "could not find or load the Qt platform plugin" 오류를 내며 시작조차 못 합니다
- 이미지 형식을 묻자 GIF, ICO, JPEG 플러그인이 올라왔습니다. PNG는 Gui 안에 들어 있어 플러그인이 필요 없지만, JPEG 사진을 여는 앱은 이 플러그인 없이는 조용히 실패합니다

어떤 플러그인을 찾고 있는지 모를 때는 `QT_DEBUG_PLUGINS=1`로 실행하면 Qt가 찾는 경로와 결과를 모두 로그로 보여 줍니다.

## 플랫폼별 도구

- **Windows**: `windeployqt app.exe`가 실행 파일을 분석해 필요한 Qt DLL, 플러그인 폴더, 번역 파일을 옆에 복사합니다. QML 앱은 `--qmldir 소스폴더`를 주어 쓰는 QML 모듈까지 챙기게 합니다. MSVC로 빌드했다면 Visual C++ 재배포 패키지도 필요합니다
- **macOS**: `macdeployqt App.app`이 Qt 프레임워크와 플러그인을 앱 번들 안에 넣고 경로를 고칩니다. `-dmg`로 디스크 이미지를 만들고, 배포 전에는 코드 서명과 Apple 공증이 필요합니다
- **리눅스**: 배포판 패키지(deb, rpm)로 시스템 Qt를 쓰거나, Qt를 함께 넣는 AppImage(linuxdeploy와 Qt 플러그인), Flatpak(KDE 런타임에 Qt가 있음)을 많이 씁니다

## CMake로 한 번에

Qt 6.3부터 `qt_generate_deploy_app_script`가 이 도구들을 CMake 설치 단계에 묶어 줍니다.

```cmake
install(TARGETS hello RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR})
qt_generate_deploy_app_script(TARGET hello OUTPUT_SCRIPT deploy_script)
install(SCRIPT ${deploy_script})
```

`cmake --install build --prefix dist`를 하면 `dist`에 앱과 필요한 Qt 파일이 모입니다. 다만 이 명령의 인자와 지원 플랫폼은 판마다 달라졌습니다. 이 책의 환경인 Qt 6.4에서는 인자 이름이 `FILENAME_VARIABLE`이었고, 리눅스에서는 "공유 Qt 라이브러리를 쓰는 리눅스는 지원하지 않는다"는 오류가 났습니다. 리눅스 지원은 그 뒤의 판에서 들어왔으므로, 쓰는 Qt 판의 문서를 확인하세요.

<Note>
배포한 앱이 Qt를 찾는 위치는 실행 파일 옆의 `qt.conf` 파일로 바꿀 수 있습니다. 또 [「Qt의 구성과 라이선스」](#/read/cpp-qt/start-what)에서 본 LGPL 조건을 지키려면, 사용자가 Qt 라이브러리를 바꿔 끼울 수 있도록 동적 링크한 라이브러리를 그대로 두어야 합니다. 배포한 결과는 Qt가 설치되지 않은 깨끗한 가상 기계에서 꼭 한 번 실행해 보세요. 개발 기계에서는 빠진 파일이 다른 경로에서 찾아져 문제가 숨습니다.
</Note>

## 정리

- 배포에는 링크한 모듈과 그것이 기대는 모듈, 그리고 실행 중에 올라오는 플랫폼·이미지 형식·SQL 드라이버 같은 플러그인이 모두 필요하다
- Windows는 windeployqt, macOS는 macdeployqt로 모으고, 리눅스는 배포판 패키지나 AppImage·Flatpak을 쓴다
- qt_generate_deploy_app_script로 CMake 설치 단계에 배포를 묶을 수 있지만 인자와 지원 플랫폼이 판마다 다르며, 깨끗한 기계에서 확인한다
