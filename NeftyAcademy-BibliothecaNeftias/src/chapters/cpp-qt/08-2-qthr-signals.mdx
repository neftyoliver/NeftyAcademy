[「QThread와 워커 객체」](#/read/cpp-qt/qthr-worker)에서 작업 스레드의 시그널이 메인 스레드에서 처리되는 것을 봤습니다. Qt는 그것을 어떻게 알았을까요? 규칙은 하나입니다. **슬롯은 받는 객체가 사는 스레드에서 실행된다.** 보내는 쪽과 받는 쪽이 같은 스레드면 그 자리에서 함수처럼 부르고, 다르면 받는 쪽 스레드의 이벤트 큐에 넣어 나중에 그 스레드가 실행합니다.

## 누가 어디서 실행되나

슬롯마다 자기가 실행된 스레드 이름을 기록하고, 마지막에 메인에서 한꺼번에 찍었습니다.

```cpp qt unordered
#include <QCoreApplication>
#include <QMutex>
#include <QStringList>
#include <QThread>
#include <cstdio>

QMutex logLock;
// 여러 스레드가 쓰는 기록(잠금으로 보호)
QStringList logLines;
void note(const QString& s) {
    QMutexLocker lk(&logLock);
    logLines << s + " @" + QThread::currentThread()->objectName();
}

class Sender : public QObject {
    Q_OBJECT
signals:
    void ping(const QString& tag);
};

class Receiver : public QObject {
    Q_OBJECT
public slots:
    void onPing(const QString& tag) { note("받음 " + tag); }
    int square(int x) { note("square 계산"); return x * x; }
};

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    QThread::currentThread()->setObjectName("main");
    QThread worker;
    worker.setObjectName("worker");
    Receiver r;
    r.moveToThread(&worker);
    worker.start();
    Sender s;                                     // main 스레드에 산다

    // 받는 쪽이 사는 스레드가 연결 방식을 정한다(AutoConnection)
    QObject::connect(&s, &Sender::ping, &r, &Receiver::onPing);    // 자동
    QObject::connect(&s, &Sender::ping, &r, &Receiver::onPing,
                     Qt::DirectConnection);                        // 직접
    // 자동 -> 큐로, 직접 -> 지금 여기서
    emit s.ping("A");

    // 결과가 필요하면: 막고 기다리는 큐 호출(같은 스레드끼리 쓰면 교착!)
    int result = 0;
    QMetaObject::invokeMethod(&r, "square", Qt::BlockingQueuedConnection,
                              Q_RETURN_ARG(int, result), Q_ARG(int, 12));
    note(QString("square 결과 %1").arg(result));

    // 람다의 문맥 객체도 스레드를 정한다
    QObject::connect(&s, &Sender::ping, &r,
                     [](const QString& t) { note("람다(문맥 r) " + t); });
    QObject::connect(&s, &Sender::ping, &app,
                     [](const QString& t) { note("람다(문맥 app) " + t); });
    emit s.ping("B");

    // worker 큐에 남은 일이 끝나길 기다린다
    QMetaObject::invokeMethod(&r, [] {}, Qt::BlockingQueuedConnection);
    QCoreApplication::processEvents();            // main 큐 비우기
    worker.quit();
    worker.wait();
    for (const QString& l : logLines) std::printf("%s\n", qPrintable(l));
}
#include "main.moc"
```

```text
받음 A @main
받음 A @worker
square 계산 @worker
square 결과 144 @main
받음 B @main
받음 B @worker
람다(문맥 app) B @main
람다(문맥 r) B @worker
```

여러 스레드가 동시에 기록하므로 줄의 순서는 실행할 때마다 조금씩 달라질 수 있습니다. 어느 스레드에서 실행되었는지는 언제나 같습니다.

## 연결 방식

- **AutoConnection**(기본): 시그널이 **발생하는 순간**, 받는 객체가 지금 스레드에 살면 직접, 아니면 큐로 연결합니다. 첫 연결의 "받음 A"는 `r`이 worker에 살기 때문에 worker에서 실행되었습니다
- **DirectConnection**: 언제나 보낸 스레드에서 바로 부릅니다. 둘째 연결의 "받음 A"는 main에서 실행되었습니다. worker에 사는 객체의 슬롯이 main에서 돌았으니, 그 객체의 데이터를 두 스레드가 동시에 만질 위험이 생깁니다. 무엇을 하는지 정확히 알 때만 씁니다
- **QueuedConnection**: 언제나 받는 객체 스레드의 큐에 넣습니다. 같은 스레드 안에서도 "지금 말고 이벤트 루프로 돌아간 뒤에"가 필요할 때 씁니다
- **BlockingQueuedConnection**: 큐에 넣고, 받는 스레드가 실행을 마칠 때까지 보낸 스레드가 **기다립니다**. 결과값을 받을 수 있어서 `square(12)`의 144를 main이 받았습니다. 보내는 쪽과 받는 쪽이 같은 스레드면 영원히 기다리는 교착이 되므로 주의하세요

## 큐 연결의 조건

큐로 보내는 시그널의 인자는 **복사되어** 이벤트에 담깁니다. 그래서 인자 타입은 복사할 수 있어야 하고, 참조로 넘긴 객체가 나중에 사라져도 안전합니다. `QString`, `QList`, `QImage` 같은 Qt 타입은 [「컨테이너와 암시적 공유」](#/read/cpp-qt/core-containers) 덕분에 복사가 싸므로 마음 놓고 넘겨도 됩니다. 반대로 포인터를 넘기면 포인터만 복사되므로, 그 대상의 수명과 동시 접근은 스스로 챙겨야 합니다.

## 람다의 문맥 객체

람다를 연결할 때 준 **문맥 객체**가 받는 객체 역할을 합니다. 같은 시그널에 이은 두 람다가, 문맥이 `r`인 것은 worker에서, 문맥이 `app`인 것은 main에서 실행되었습니다. 작업 스레드의 시그널을 받아 위젯을 갱신하는 람다라면 문맥 객체로 그 위젯(또는 메인 창)을 주어야 메인 스레드에서 실행됩니다. 문맥을 빼먹으면 직접 연결이 되어, 위젯을 작업 스레드에서 만지는 버그가 됩니다.

<Note>
모든 QObject는 사는 스레드가 있고, 큐 연결 슬롯과 타이머와 `deleteLater`는 그 스레드의 **이벤트 루프가 돌아야** 실행됩니다. 이벤트 루프 없이 `run()`만 재정의한 스레드에 객체를 옮기면 큐로 보낸 슬롯이 영원히 실행되지 않습니다. 또 공유 데이터를 여러 스레드가 직접 만진다면 예제의 `QMutex`와 `QMutexLocker`처럼 잠금이 필요합니다. 가능하면 데이터를 시그널 인자로 복사해 넘기고 공유를 피하는 것이 Qt다운 방식입니다.
</Note>

## 정리

- 슬롯은 받는 객체가 사는 스레드에서 실행되며, 기본 연결은 그 스레드가 다르면 자동으로 큐를 거친다
- 직접 연결은 보낸 스레드에서, 큐 연결은 받는 스레드의 이벤트 루프에서, 막는 큐 연결은 결과를 기다리며 실행된다
- 큐로 가는 인자는 복사되고, 람다는 문맥 객체가 실행 스레드를 정하므로 GUI 갱신에는 위젯을 문맥으로 준다
