[「데스크톱 배포 도구」](#/read/cpp-qt/dep-desktop)는 앱 옆에 Qt 라이브러리와 플러그인 폴더를 함께 놓는 방식이었습니다. 다른 길은 **정적 빌드**입니다. Qt 자체를 정적 라이브러리로 빌드하고 앱에 링크해, 실행 파일 **하나**에 모든 것을 넣습니다. 복사 한 번으로 배포가 끝나고, 시작할 때 라이브러리를 찾느라 쓰는 시간도 줄어듭니다.

## 정적 플러그인

정적 빌드에서 가장 헷갈리는 것은 플러그인입니다. 동적 빌드는 실행 중에 플러그인 폴더에서 `.so`나 `.dll`을 찾아 불러오지만, 정적 빌드에는 불러올 파일이 없습니다. 그래서 플러그인을 실행 파일 안에 넣고 **등록 목록에 올려야** 합니다. 그 장치를 이 책의 동적 Qt에서도 돌려 볼 수 있습니다. 앱이 정한 플러그인 인터페이스와 플러그인 하나를 실행 파일 안에 정적으로 넣었습니다.

```cpp qt
#define QT_STATICPLUGIN        // 이 파일의 플러그인을 실행 파일 안에 넣는다
#include <QCoreApplication>
#include <QJsonObject>
#include <QPluginLoader>
#include <QtPlugin>
#include <cstdio>

// 앱이 정한 플러그인 인터페이스
class TextFilter {
public:
    virtual ~TextFilter() = default;
    virtual QString apply(const QString& s) const = 0;
};
#define TextFilter_iid "academy.nefty.TextFilter/1.0"
Q_DECLARE_INTERFACE(TextFilter, TextFilter_iid)

// 플러그인 하나: 보통은 따로 빌드한 .so/.dll이지만 여기서는 실행 파일에 넣는다
class UpperFilter : public QObject, public TextFilter {
    Q_OBJECT
    Q_PLUGIN_METADATA(IID TextFilter_iid)
    Q_INTERFACES(TextFilter)
public:
    QString apply(const QString& s) const override { return s.toUpper(); }
};

Q_IMPORT_PLUGIN(UpperFilter)           // 정적 플러그인을 등록 목록에 올린다

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    // 정적 플러그인 목록: 정적 Qt라면 플랫폼 플러그인도 여기 있다
    const auto statics = QPluginLoader::staticPlugins();
    std::printf("정적 플러그인 %lld개\n", (long long)statics.size());
    for (const QStaticPlugin& p : statics)
        std::printf("  IID %s, 클래스 %s\n",
                    qPrintable(p.metaData().value("IID").toString()),
                    qPrintable(p.metaData().value("className").toString()));
    for (QObject* obj : QPluginLoader::staticInstances())
        if (auto* f = qobject_cast<TextFilter*>(obj))
            std::printf("적용: %s\n", qPrintable(f->apply("static qt")));
}
#include "main.moc"
```

```text
정적 플러그인 1개
  IID academy.nefty.TextFilter/1.0, 클래스 UpperFilter
적용: STATIC QT
```

- `QT_STATICPLUGIN`을 정의하고 `Q_PLUGIN_METADATA`를 쓰면, moc가 이 플러그인을 정적 플러그인으로 만드는 코드를 생성합니다
- `Q_IMPORT_PLUGIN(UpperFilter)`가 그것을 앱의 정적 플러그인 목록에 올립니다. 이 줄이 없으면 링커는 아무도 안 쓰는 코드로 보고 버릴 수 있고, 목록에도 나타나지 않습니다
- `QPluginLoader::staticPlugins()`가 메타데이터(IID, 클래스 이름)를, `staticInstances()`가 객체를 돌려줍니다. 인터페이스로 `qobject_cast`해 쓰는 방법은 동적 플러그인과 같습니다([「플러그인」](#/read/cpp-qt/qarch-plugins))

Qt를 정적으로 빌드하면 플랫폼 플러그인(qwindows, qcocoa, qxcb)과 이미지 형식 플러그인도 이 방식으로 들어갑니다. CMake로 정적 Qt에 링크하면 쓰는 모듈마다 기본 플러그인 묶음이 자동으로 들어갑니다. 플러그인마다 그것을 초기화하는 작은 C++ 파일(위 `Q_IMPORT_PLUGIN`과 같은 역할)이 대상의 소스에 더해지는 방식입니다. 더하거나 빼려면 `qt_import_plugins(app INCLUDE ... EXCLUDE ...)`를, 기본 묶음을 아예 끄려면 `NO_DEFAULT`를 씁니다. QML 앱은 쓰는 QML 모듈의 플러그인도 넣어야 하는데, 이 일은 `qt_import_qml_plugins`가 맡습니다.

## 정적 Qt 만들기

배포판 패키지나 공식 설치 프로그램의 Qt는 동적 빌드라서, 정적 빌드는 직접 만들어야 합니다(상용 사용자는 미리 빌드된 정적 Qt를 받을 수 있는 경우도 있습니다). Qt 소스에서 `configure -static -release -prefix …`로 설정하고 빌드합니다. 쓰지 않는 모듈은 `-skip`, 쓰지 않는 기능은 `-no-feature-…`로 빼면 실행 파일이 더 작아집니다.

| | 동적 배포 | 정적 빌드 |
| --- | --- | --- |
| 배포 | 파일과 폴더 여럿 | 실행 파일 하나 |
| 크기 | Qt 전체를 함께 | 쓰는 것만 링크 |
| Qt 갱신 | 라이브러리만 바꿔 끼움 | 앱을 다시 빌드 |
| 빌드 | 받은 Qt 그대로 | Qt를 직접 빌드 |

<Note>
정적 링크는 **라이선스**와 밀접합니다. LGPLv3로 Qt를 쓰는 앱은 사용자가 수정한 Qt로 바꿔 끼울 수 있어야 하므로, 정적 링크한다면 앱의 목적 파일 등 다시 링크할 수 있는 자료를 제공해야 하는 등의 조건이 따릅니다. 많은 회사가 정적 배포가 필요할 때 상용 라이선스를 고르는 이유입니다. 실제 제품에 적용하기 전에 라이선스 조건을 확인하세요. 이 설명은 법률 조언이 아닙니다.
</Note>

## 정리

- 정적 빌드는 Qt를 실행 파일 하나에 넣어 배포를 단순하게 하지만, Qt를 직접 빌드해야 하고 갱신할 때 앱을 다시 빌드한다
- 정적 빌드의 플러그인은 실행 파일 안에 들어가 Q_IMPORT_PLUGIN으로 등록되며, CMake가 기본 플러그인을 자동으로 등록한다
- LGPL로 쓰는 앱을 정적 링크하면 다시 링크할 수 있게 하는 조건이 따르므로 라이선스를 먼저 확인한다
