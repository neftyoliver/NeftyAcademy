`qDebug() << "여기까지 옴"`은 편하지만, 앱이 커지면 로그가 쏟아져 필요한 것을 찾을 수 없고, 출시판에서 끄려면 코드를 고쳐야 합니다. **로깅 범주**는 로그마다 `app.net`, `app.db` 같은 이름을 붙이고, 범주와 수준(debug, info, warning, critical)별로 **실행 중에** 켜고 끄게 해 줍니다. Qt 자신도 내부 로그를 `qt.network.ssl`, `qt.qpa.xcb` 같은 범주로 냅니다.

## 범주와 규칙

```cpp qt
#include <QCoreApplication>
#include <QLoggingCategory>
#include <cstdio>

// 범주 선언: 이름은 점으로 나눈 계층. 기본으로 debug는 꺼 둘 수 있다
Q_LOGGING_CATEGORY(lcNet, "app.net")
Q_LOGGING_CATEGORY(lcDb, "app.db", QtInfoMsg)       // info 이상만 기본으로 켜짐

void toStdout(QtMsgType type, const QMessageLogContext& ctx, const QString& msg) {
    // 포맷을 직접 정한다: 실제 앱은 여기서 파일이나 원격 수집기로 보낸다
    const char* level = "E";
    if (type == QtDebugMsg) level = "D";
    if (type == QtInfoMsg) level = "I";
    if (type == QtWarningMsg) level = "W";
    std::printf("[%s] %-7s %s\n", level, ctx.category, qPrintable(msg));
}

void work() {
    qCDebug(lcNet) << "연결 시도" << "127.0.0.1:8080";
    qCInfo(lcNet) << "연결됨";
    qCDebug(lcDb) << "SELECT 실행";                 // 기본으로 꺼진 수준
    qCWarning(lcDb) << "쿼리가 느림:" << 1200 << "ms";
}

int main(int argc, char** argv) {
    qInstallMessageHandler(toStdout);
    QCoreApplication app(argc, argv);

    std::printf("-- 기본 규칙\n");
    work();

    std::printf("-- app.net의 debug 끄기, app.db의 debug 켜기\n");
    QLoggingCategory::setFilterRules("app.net.debug=false\napp.db.debug=true");
    work();

    std::printf("-- app.* 전체를 경고 이상만\n");
    QLoggingCategory::setFilterRules("app.*.debug=false\napp.*.info=false");
    work();
    std::printf("app.db의 debug가 켜져 있나: %s\n",
                lcDb().isDebugEnabled() ? "예" : "아니오");
}
```

```text
[I] app.net 연결됨
[W] app.db  쿼리가 느림: 1200 ms
-- app.net의 debug 끄기, app.db의 debug 켜기
[I] app.net 연결됨
[D] app.db  SELECT 실행
[W] app.db  쿼리가 느림: 1200 ms
-- app.* 전체를 경고 이상만
[W] app.db  쿼리가 느림: 1200 ms
app.db의 debug가 켜져 있나: 아니오
```

## 범주 만들기

- `Q_LOGGING_CATEGORY(lcNet, "app.net")`는 범주 객체를 정의합니다. 여러 파일에서 쓰려면 머리 파일에 `Q_DECLARE_LOGGING_CATEGORY(lcNet)`을 둡니다
- 세 번째 인자로 기본으로 켜질 최소 수준을 줄 수 있습니다. `app.db`는 `QtInfoMsg`로 만들어서, 처음에는 debug 로그("SELECT 실행")가 나오지 않았습니다
- 로그는 `qCDebug(lcNet)`, `qCInfo`, `qCWarning`, `qCCritical`로 냅니다. 범주가 꺼져 있으면 `<<` 뒤의 식은 **계산조차 하지 않으므로**, 비싼 값을 로그에 넣어도 끈 상태에서는 비용이 거의 없습니다

## 규칙으로 켜고 끄기

규칙은 `범주.수준=true/false` 줄들입니다. 예제는 `setFilterRules`로 코드에서 바꿨지만, 보통은 코드를 고치지 않고 바깥에서 줍니다.

- 환경 변수: `QT_LOGGING_RULES="app.db.debug=true;qt.network.ssl=true"`
- 설정 파일: `~/.config/QtProject/qtlogging.ini`의 `[Rules]` 묶음
- 와일드카드: `app.*.debug=false`는 `app`으로 시작하는 모든 범주의 debug를 끕니다. 나중에 오는 규칙이 앞의 규칙을 덮습니다

사용자의 버그 보고를 받을 때 "이 환경 변수를 켜고 다시 실행해 주세요"라고 하면, 출시판에서도 자세한 로그를 받을 수 있습니다. TLS 연결 문제는 `qt.network.ssl`, 플러그인 불러오기 문제는 `QT_DEBUG_PLUGINS=1`이 단골입니다.

## 메시지 처리기

`qInstallMessageHandler`로 모든 로그가 지나는 함수를 바꿀 수 있습니다. 예제는 수준을 한 글자로, 범주 이름을 정렬해 표준 출력으로 보냈습니다. 실제 앱은 여기서 시각을 붙여 파일에 쓰고, 오래된 파일을 돌려 지우고, 경고 이상은 [「충돌 보고」](#/read/cpp-game-engine/ship-crash)의 발자국처럼 보고서에 남깁니다. 처리기를 바꾸지 않고 모양만 바꾸려면 `qSetMessagePattern("%{time} %{category} %{message}")`이나 `QT_MESSAGE_PATTERN` 환경 변수를 씁니다.

<Note>
처리기는 어느 스레드에서든 동시에 불릴 수 있으므로, 파일에 쓴다면 잠금이 필요합니다. 또 처리기 안에서 다시 로그를 내면 끝없이 돌 수 있습니다. 출시판에서 `QT_NO_DEBUG_OUTPUT`을 정의하면 `qDebug` 계열이 아예 컴파일되지 않습니다.
</Note>

## 정리

- 로깅 범주는 로그에 계층 이름을 붙이고, 범주와 수준별로 실행 중에 켜고 끄게 한다
- 꺼진 범주의 로그 식은 계산되지 않아 비용이 거의 없고, 규칙은 환경 변수나 설정 파일로 바깥에서 준다
- 메시지 처리기로 모든 로그의 목적지와 모양을 정하며, Qt 내부 범주를 켜서 라이브러리 문제를 진단한다
