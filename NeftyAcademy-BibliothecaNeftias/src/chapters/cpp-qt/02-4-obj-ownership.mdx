Qt 코드를 처음 보면 `new`는 잔뜩 있는데 `delete`가 거의 없어서 놀라게 됩니다. 메모리가 새는 것이 아닙니다. QObject는 **부모**를 가질 수 있고, 부모는 소멸할 때 자기 **자식**을 모두 지웁니다. 창 하나를 지우면 그 안의 패널, 버튼, 라벨이 모두 따라 사라집니다. 이 나무 구조가 Qt의 기본 메모리 관리 방식입니다.

## 나무 만들고 지우기

```cpp qt
#include <QCoreApplication>
#include <QObject>
#include <QPointer>
#include <QTimer>
#include <cstdio>

class Node : public QObject {
public:
    Node(const char* name, QObject* parent = nullptr) : QObject(parent) {
        setObjectName(name);
    }
    ~Node() override { std::printf("  소멸: %s\n", qPrintable(objectName())); }
};

void tree(const QObject* o, int depth = 0) {
    std::printf("  %*s%s\n", depth * 2, "", qPrintable(o->objectName()));
    for (auto* c : o->children()) tree(c, depth + 1);
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    std::printf("1) 나무 만들기\n");
    auto* window = new Node("창");
    auto* panel = new Node("패널", window);
    new Node("버튼1", panel);
    new Node("버튼2", panel);
    auto* status = new Node("상태줄", window);
    tree(window);

    std::printf("2) 상태줄을 패널 밑으로 옮기기\n");
    status->setParent(panel);
    std::printf("  창의 자식 수 %lld, 패널의 자식 수 %lld\n",
                (long long)window->children().size(),
                (long long)panel->children().size());

    std::printf("3) QPointer는 대상이 사라지면 저절로 null이 된다\n");
    QPointer<QObject> watch = status;
    QObject::connect(status, &QObject::destroyed,
                     [] { std::printf("  destroyed 시그널\n"); });
    delete status;                       // 부모에게서도 빠진다
    std::printf("  watch는 %s\n", watch ? "살아 있음" : "null");

    std::printf("4) 부모를 지우면 자식부터가 아니라 위에서 아래로 지운다\n");
    delete window;

    std::printf("5) deleteLater: 지금 말고 이벤트 루프로 돌아간 뒤에\n");
    auto* temp = new Node("임시");
    temp->deleteLater();
    std::printf("  deleteLater 부른 직후(아직 살아 있음)\n");
    QTimer::singleShot(0, &app, &QCoreApplication::quit);
    app.exec();
    std::printf("  이벤트 루프 끝\n");
}
```

## 규칙들

- **생성자에 부모를 넘기면** 그 부모의 `children()` 목록에 들어갑니다. 위젯은 레이아웃에 넣을 때 부모가 정해지기도 합니다([「첫 창」](#/read/cpp-qt/start-window))
- **setParent**로 부모를 바꾸면 옛 부모의 목록에서 빠지고 새 부모에 들어갑니다. 소유권이 옮겨 간 것입니다
- **자식을 직접 delete**해도 됩니다. 소멸하면서 부모의 목록에서 스스로 빠지므로 나중에 부모가 다시 지우는 일은 없습니다
- **소멸 순서**: 창을 지우자 "창"이 먼저 찍히고 그다음 자식들이 찍혔습니다. `Node`의 소멸자 본체가 먼저 돌고, 그다음 기반 클래스 `QObject`의 소멸자가 자식들을 지우기 때문입니다. 그래서 자식의 소멸자에서 부모의 파생 클래스 멤버를 건드리면 이미 사라진 것을 만지게 됩니다

## 약한 참조와 미뤄 지우기

- **QPointer**는 QObject를 가리키는 약한 포인터입니다. 대상이 어디서 지워지든 저절로 null이 되므로, 남이 소유한 객체를 오래 기억해야 할 때 맨 포인터 대신 씁니다. 소멸 직전에는 `destroyed` 시그널도 나옵니다
- **deleteLater**는 "이벤트 루프로 돌아간 다음에 지워 줘"라는 요청입니다. 슬롯 안에서 시그널을 보낸 바로 그 객체를 지워야 할 때(예: 응답이 끝난 네트워크 요청 객체), 바로 `delete`하면 호출 스택 위에서 아직 그 객체를 쓰고 있을 수 있어 위험합니다. 출력에서 "임시"는 이벤트 루프가 돈 뒤에야 소멸했습니다

<Note>
스택 객체와 부모 관계를 섞을 때는 선언 순서를 조심해야 합니다. 함수 안에서 `QObject child; QObject parent; child.setParent(&parent);`처럼 자식을 먼저 선언하면, 범위를 벗어날 때 나중에 선언한 `parent`가 먼저 소멸하면서 스택에 있는 `child`를 `delete`하려 해 프로그램이 망가집니다. 부모를 먼저 선언하거나, 자식은 `new`로 만드는 것이 안전합니다. 같은 이유로 부모가 있는 QObject를 `std::unique_ptr`로 감싸면 두 주인이 생깁니다. 하나를 고르세요.
</Note>

## 정리

- QObject는 부모를 가질 수 있고, 부모가 소멸하면 자식을 모두 지우므로 new로 만든 자식을 따로 delete하지 않는다
- 부모 클래스의 소멸자 본체가 먼저 돌고 그 뒤에 자식이 지워지며, 자식을 직접 지우면 부모 목록에서 스스로 빠진다
- 남의 객체는 QPointer로 약하게 가리키고, 시그널을 보낸 객체는 deleteLater로 지우며, 스택 객체의 선언 순서를 조심한다
