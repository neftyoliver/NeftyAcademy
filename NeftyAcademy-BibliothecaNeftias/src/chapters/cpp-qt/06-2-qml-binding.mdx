QML 속성에 `half: total / 2`라고 쓰면, `half`에 지금의 값 50을 넣고 끝나는 것이 아닙니다. "half는 언제나 total의 절반"이라는 **관계**를 맺습니다. `total`이 바뀌면 QML 엔진이 `half`를 다시 계산하고, `half`에 묶인 것들도 차례로 다시 계산합니다. 창 크기에 따라 배치가 바뀌고, 데이터에 따라 색이 바뀌는 화면을 이벤트 처리 코드 없이 만들 수 있는 이유입니다.

## 묶고, 끊고, 다시 묶기

```cpp qt=Qml
#include <QCoreApplication>
#include <QQmlComponent>
#include <QQmlEngine>
#include <cstdio>

void toStdout(QtMsgType, const QMessageLogContext&, const QString& msg) {
    std::printf("[console] %s\n", qPrintable(msg));
}

int main(int argc, char** argv) {
    qInstallMessageHandler(toStdout);
    QCoreApplication app(argc, argv);
    QQmlEngine engine;
    QQmlComponent comp(&engine);
    comp.setData(R"(
import QtQml

QtObject {
    id: root
    property real total: 100
    property real half: total / 2           // 바인딩: total이 바뀌면 다시 계산
    property bool wide: half > 60
    property real taxed: price * (1 + rate) // 아직 선언 전인 속성도 이름으로 묶인다
    property real price: 10
    property real rate: 0.1

    function show(tag) {
        console.log(tag, "total", total, "half", half, "wide", wide,
                    "taxed", taxed.toFixed(2))
    }
    Component.onCompleted: {
        show("처음")
        total = 150;  show("total=150")
        half = 5;     show("half=5 대입")       // 대입하면 바인딩이 끊긴다
        total = 300;  show("total=300")
        half = Qt.binding(() => total / 2)      // 바인딩을 다시 건다
        show("Qt.binding 뒤")
        rate = 0.2;   show("rate=0.2")
    }
}
)", QUrl("binding.qml"));
    QObject* root = comp.create();
    if (!root) { std::printf("%s\n", qPrintable(comp.errorString())); return 1; }
    root->setProperty("total", 40);              // C++에서 바꿔도 바인딩은 따라간다
    std::printf("C++에서 total=40: half=%g wide=%s\n",
                root->property("half").toDouble(),
                root->property("wide").toBool() ? "true" : "false");
    delete root;

    // 서로를 바꾸는 두 바인딩: 고리가 생기면 Qt가 끊고 경고한다
    QQmlComponent loop(&engine);
    loop.setData("import QtQml\n"
                 "QtObject { property int a: b + 1; property int b: a + 1 }",
                 QUrl("loop.qml"));
    delete loop.create();
}
```

```text
[console] 처음 total 100 half 50 wide false taxed 11.00
[console] total=150 total 150 half 75 wide true taxed 11.00
[console] half=5 대입 total 150 half 5 wide false taxed 11.00
[console] total=300 total 300 half 5 wide false taxed 11.00
[console] Qt.binding 뒤 total 300 half 150 wide true taxed 11.00
[console] rate=0.2 total 300 half 150 wide true taxed 12.00
C++에서 total=40: half=20 wide=false
[console] loop.qml:2:1: QML QtObject: Binding loop detected for property "a"
```

## 바인딩이 따라가는 것

- `total`을 150으로 바꾸자 `half`가 75로, `half > 60`에 묶인 `wide`가 `true`로 연쇄적으로 바뀌었습니다. 엔진은 식을 처음 계산할 때 **어떤 속성을 읽었는지** 기록해 두고, 그 속성들의 알림 시그널에 연결합니다. 그래서 의존 관계를 따로 적지 않아도 됩니다
- `taxed`는 아래에 선언된 `price`와 `rate`를 씁니다. 선언 순서는 상관없습니다. `rate`를 0.2로 바꾸자 12.00이 되었습니다
- C++에서 `setProperty("total", 40)`으로 바꿔도 `half`가 20으로 따라왔습니다. 바인딩은 C++ 속성의 NOTIFY 시그널에도 똑같이 연결되므로, [「C++ 타입을 QML에 내놓기」](#/read/cpp-qt/qml-cpp)에서 C++ 객체의 속성을 QML 화면에 묶을 수 있습니다

## 대입은 바인딩을 끊는다

`half = 5`처럼 자바스크립트에서 **대입**하면 그 속성의 바인딩은 사라지고 고정된 값 5가 됩니다. 그 뒤 `total`을 300으로 바꿔도 `half`는 5 그대로였습니다. 이것은 QML에서 가장 흔한 버그의 원인입니다. 버튼 처리기에서 `width = 100`이라고 한 번 쓰면, 그 위젯은 더 이상 창 크기를 따라가지 않습니다.

바인딩을 다시 걸려면 `Qt.binding(() => total / 2)`처럼 함수를 넘깁니다. 그러면 `half`가 곧바로 150이 되고 다시 `total`을 따라갑니다. 상태에 따라 값을 바꾸는 일은 대입보다 [「상태와 애니메이션」](#/read/cpp-qt/qml-states)의 상태나 `Binding` 요소의 `when` 조건으로 표현하는 편이 바인딩을 깨지 않아 안전합니다.

## 바인딩 고리

마지막 줄은 `a: b + 1`과 `b: a + 1`처럼 서로에게 기대는 바인딩입니다. 하나를 계산하면 다른 하나가 바뀌고, 그것이 다시 처음 것을 바꾸는 고리가 됩니다. 엔진은 고리를 발견하면 계산을 멈추고 "Binding loop detected" 경고를 냅니다. 경고는 파일과 줄 번호를 알려 주므로 꼭 확인하세요. 화면에서는 크기가 서로의 크기에 기대는 레이아웃(예: 부모 크기가 자식 크기에, 자식 크기가 부모 크기에)에서 자주 생깁니다.

<Note>
바인딩 식은 기댄 속성이 바뀔 때마다 다시 계산되므로, 무거운 계산이나 부작용(로그, 네트워크 요청)을 넣으면 안 됩니다. 식은 값을 계산해 돌려주기만 하고, 동작은 시그널 처리기에 둡니다. Qt 6의 QML 엔진은 타입이 분명한 바인딩을 미리 컴파일해 빠르게 실행하므로, 속성에 `property real`처럼 타입을 밝혀 두면 도움이 됩니다.
</Note>

## 정리

- 바인딩은 속성을 식으로 묶어, 식이 읽은 속성이 바뀔 때마다 엔진이 다시 계산하게 한다
- 자바스크립트에서 대입하면 바인딩이 끊기고, Qt.binding으로 다시 걸며, 상태 변화는 상태나 Binding 요소로 표현하는 편이 안전하다
- 서로에게 기대는 바인딩은 고리가 되어 경고가 나며, 바인딩 식에는 부작용을 넣지 않는다
