도면 편집기, 노드 그래프 편집기, 지도, 간단한 2D 게임처럼 움직이고 고를 수 있는 **물체가 수천 개** 있는 화면은 위젯 하나에 전부 그리면 관리가 힘듭니다. **그래픽스 뷰 프레임워크**는 물체 하나하나를 항목(`QGraphicsItem`)으로 두고, 항목들을 담는 장면(`QGraphicsScene`), 장면을 보는 창(`QGraphicsView`)으로 나눕니다. 고르기, 끌기, 충돌, 확대, 많은 항목 중 일부만 그리기가 이미 들어 있습니다.

## 주인공, 벽, 동전

```cpp qt=Widgets
#include <QApplication>
#include <QGraphicsEllipseItem>
#include <QGraphicsRectItem>
#include <QGraphicsScene>
#include <QGraphicsView>
#include <cstdio>

int main(int argc, char** argv) {
    QApplication app(argc, argv);
    QGraphicsScene scene(0, 0, 1000, 1000);    // 장면 좌표: 1000 x 1000

    auto* player = scene.addEllipse(-10, -10, 20, 20, QPen(Qt::black), Qt::blue);
    // 항목 좌표의 원점을 장면의 (100,100)에
    player->setPos(100, 100);
    player->setData(0, "주인공");
    auto* wall = scene.addRect(0, 0, 40, 200, QPen(Qt::NoPen), Qt::gray);
    wall->setPos(150, 0);
    wall->setData(0, "벽");
    auto* coin = scene.addEllipse(-5, -5, 10, 10, QPen(Qt::NoPen), Qt::yellow);
    coin->setPos(130, 100);
    coin->setData(0, "동전");

    auto names = [](const QList<QGraphicsItem*>& items) {
        QStringList out;
        for (auto* i : items) out << i->data(0).toString();
        return out.isEmpty() ? QString("없음") : out.join(", ");
    };
    // 1) 항목 좌표와 장면 좌표
    QPointF edge = player->mapToScene(10, 0);  // 원의 오른쪽 끝(항목 좌표 (10,0))
    std::printf("주인공 오른쪽 끝의 장면 좌표 (%.0f,%.0f)\n", edge.x(), edge.y());

    // 2) 오른쪽으로 걸어가며 부딪히는 것 확인
    for (int step = 0; step < 4; ++step) {
        player->moveBy(15, 0);
        std::printf("x=%.0f 에서 닿은 것: %s\n", player->x(),
                    qPrintable(names(player->collidingItems())));
    }

    // 3) 항목이 많아도 영역 질의는 빠르다(내부 BSP 나무)
    for (int i = 0; i < 10000; ++i)
        scene.addRect(0, 0, 4, 4)->setPos((i * 37) % 1000, (i * 91) % 1000);
    auto near = scene.items(QRectF(500, 500, 20, 20));
    std::printf("항목 %lld개 중 (500,500)~(520,520) 안: %lld개\n",
                (long long)scene.items().size(), (long long)near.size());

    // 4) 뷰는 장면을 보는 창: 같은 장면을 확대해서 본다
    QGraphicsView view(&scene);
    view.resize(400, 300);
    view.scale(2.0, 2.0);
    view.centerOn(player);
    view.show();
    app.processEvents();
    QPoint onScreen = view.mapFromScene(player->pos());
    QPointF back = view.mapToScene(onScreen);
    std::printf("뷰 2배 확대: 주인공은 화면 (%d,%d), 다시 장면으로 (%.0f,%.0f)\n",
                onScreen.x(), onScreen.y(), back.x(), back.y());
}
```

## 세 가지 좌표

- **항목 좌표**: 항목마다 자기 원점이 있습니다. 주인공 원은 자기 원점을 중심으로 (-10, -10)부터 20×20으로 그렸습니다. 자기 원점 중심으로 그려 두면 돌리거나 키울 때 중심이 그대로라서 편합니다
- **장면 좌표**: `setPos(100, 100)`은 항목의 원점을 장면의 (100, 100)에 놓습니다. 항목 좌표의 (10, 0), 곧 원의 오른쪽 끝은 장면에서 (110, 100)이었습니다. 항목에 부모 항목을 주면 [「QPainter」](#/read/cpp-qt/paint-painter)의 변환처럼 부모를 따라 함께 움직입니다
- **뷰 좌표**: 뷰는 장면의 일부를 화면 화소로 보여 줍니다. 2배로 확대하고 주인공을 가운데에 두었더니, 장면의 (160, 100)이 400×300 창의 (192, 142)에 보였습니다. `mapFromScene`과 `mapToScene`으로 오가며, 마우스 위치를 장면 좌표로 바꿀 때 씁니다

## 충돌과 영역 질의

`collidingItems()`는 이 항목과 모양이 겹치는 항목들을 돌려줍니다. 주인공이 오른쪽으로 걸어가며 동전에 닿고, 동전과 벽에 함께 닿고, 동전을 지나 벽에만 닿는 것이 보입니다. 기본으로 항목의 실제 모양(`shape()`)으로 판정하므로 원은 원으로 겹침을 봅니다.

작은 사각형 1만 개를 더 넣은 뒤 20×20 영역 안의 항목을 물었더니 10개가 나왔습니다. 장면은 항목들의 위치를 BSP 나무로 색인해 두기 때문에, 모든 항목을 훑지 않고 영역 근처만 봅니다. 뷰가 화면에 보이는 항목만 그리는 것도 이 색인 덕분입니다. [「공간 분할」](#/read/cpp-game-engine/scene-spatial)에서 본 것과 같은 생각입니다.

<Note>
항목은 `setFlags(QGraphicsItem::ItemIsMovable | ItemIsSelectable)` 한 줄로 마우스로 끌고 고를 수 있게 됩니다. 직접 만든 항목은 `QGraphicsItem`을 상속해 `boundingRect()`와 `paint()`를 구현하는데, `boundingRect`가 실제로 그리는 영역보다 작으면 다시 그리기가 덜 되어 자국이 남습니다. 새로 시작하는 프로젝트에서 GPU 가속과 애니메이션이 중요하다면 [「QML 문법」](#/read/cpp-qt/qml-syntax)부터 보는 Qt Quick도 같은 종류의 화면을 만드는 선택지입니다.
</Note>

## 정리

- 그래픽스 뷰는 항목, 장면, 뷰로 나뉘어 수천 개의 움직이고 고를 수 있는 물체를 다룬다
- 항목 좌표, 장면 좌표, 뷰 좌표가 있고 mapToScene과 mapFromScene으로 오간다
- collidingItems로 모양의 겹침을 확인하고, 장면의 BSP 색인 덕분에 영역 질의와 그리기가 많은 항목에서도 빠르다
