[「첫 창」](#/read/cpp-qt/start-window)에서 `app.exec()`가 이벤트 루프를 돌린다고 했습니다. Qt 앱의 모든 일은 결국 이 루프가 큐에서 **이벤트**를 하나씩 꺼내 해당 객체에 전달하는 것입니다. 마우스 클릭, 키 입력, 창 다시 그리기, 타이머, 네트워크 데이터 도착, 다른 스레드에서 온 시그널까지 모두 이벤트로 들어옵니다. 시그널과 슬롯이 객체 사이의 약속이라면, 이벤트는 운영체제와 Qt가 객체에게 "이런 일이 있었다"고 알리는 우편입니다.

## 우편함 들여다보기

```cpp qt
#include <QCoreApplication>
#include <QEvent>
#include <QObject>
#include <QTimer>
#include <cstdio>

// 사용자 정의 이벤트: 번호는 QEvent::User 이후를 쓴다
const QEvent::Type PingType = QEvent::Type(QEvent::registerEventType());
struct PingEvent : QEvent {
    int n;
    explicit PingEvent(int n) : QEvent(PingType), n(n) {}
};

class Worker : public QObject {
protected:
    bool event(QEvent* e) override {           // 모든 이벤트가 지나는 문
        if (e->type() == PingType) {
            std::printf("  Worker가 Ping %d 처리\n", static_cast<PingEvent*>(e)->n);
            return true;                       // 처리했음
        }
        return QObject::event(e);              // 나머지는 기본 처리(타이머 등)
    }
};

class Spy : public QObject {                   // 남의 이벤트를 먼저 엿보는 필터
protected:
    bool eventFilter(QObject*, QEvent* e) override {
        if (e->type() == PingType && static_cast<PingEvent*>(e)->n == 3) {
            std::printf("  필터가 Ping 3을 가로챔\n");
            return true;                       // true면 Worker까지 가지 않는다
        }
        return false;
    }
};

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    Worker w;
    Spy spy;
    w.installEventFilter(&spy);

    std::printf("postEvent 1, 2, 3 (큐에 넣기만 한다)\n");
    for (int i = 1; i <= 3; ++i)
        QCoreApplication::postEvent(&w, new PingEvent(i));   // 큐가 소유하고 지운다
    std::printf("sendEvent 9 (지금 바로 처리)\n");
    PingEvent now(9);
    QCoreApplication::sendEvent(&w, &now);

    int ticks = 0;
    QTimer timer;
    QObject::connect(&timer, &QTimer::timeout, [&] {
        std::printf("  타이머 %d\n", ++ticks);
        if (ticks == 3) app.quit();
    });
    timer.start(10);
    QTimer::singleShot(0, [] {
        std::printf("  singleShot(0): 루프가 한 바퀴 돈 뒤\n");
    });

    std::printf("exec 시작\n");
    app.exec();
    std::printf("exec 끝\n");
}
```

```text
postEvent 1, 2, 3 (큐에 넣기만 한다)
sendEvent 9 (지금 바로 처리)
  Worker가 Ping 9 처리
exec 시작
  Worker가 Ping 1 처리
  Worker가 Ping 2 처리
  필터가 Ping 3을 가로챔
  singleShot(0): 루프가 한 바퀴 돈 뒤
  타이머 1
  타이머 2
  타이머 3
exec 끝
```

## 보내는 두 가지 방법

- **postEvent**는 이벤트를 큐에 넣고 바로 돌아옵니다. 이벤트는 루프가 돌 때 처리되므로, 출력에서 Ping 1~3은 `exec 시작` 뒤에야 나왔습니다. 이벤트 객체는 `new`로 만들어 넘기고, 처리가 끝나면 Qt가 지웁니다. 다른 스레드의 객체에 안전하게 일을 맡기는 기본 수단이기도 합니다
- **sendEvent**는 그 자리에서 바로 처리하고 돌아옵니다. 함수 호출과 같아서 이벤트 객체를 스택에 둬도 됩니다. Ping 9가 1~3보다 먼저 처리된 이유입니다

## 받는 두 가지 방법

- **event() 재정의**: 객체에 오는 모든 이벤트는 `event()`를 지납니다. 원하는 종류만 처리하고 `true`를 돌려주고, 나머지는 반드시 부모 클래스의 `event()`에 넘겨야 합니다. 그렇지 않으면 타이머나 시그널 큐 처리까지 막힙니다. 위젯에서는 보통 `mousePressEvent`, `keyPressEvent`, `paintEvent`처럼 종류별 함수를 재정의하는데, 이것들도 `QWidget::event()`가 나눠 불러 주는 것입니다
- **이벤트 필터**: `installEventFilter`로 다른 객체의 이벤트를 먼저 엿볼 수 있습니다. `Spy`가 Ping 3에 `true`를 돌려주자 `Worker`에게는 아예 전달되지 않았습니다. 클래스를 상속하지 않고 남의 위젯의 키 입력을 가로채거나, 앱 전체에 단축키를 거는 데 씁니다

## 타이머와 루프

`QTimer`는 정해진 간격마다 `timeout` 시그널을 냅니다. 이것도 루프가 타이머 이벤트를 받아서 하는 일이므로, 루프가 돌지 않으면 타이머도 멈춥니다. `QTimer::singleShot(0, …)`은 "지금 큐에 있는 일을 마친 뒤 한 번"이라는 뜻으로, 이미 큐에 있던 Ping 이벤트들 다음에 실행되었습니다. 생성자에서 하기 이른 초기화를 미룰 때 자주 씁니다.

<Note>
슬롯이나 이벤트 처리 함수에서 3초 걸리는 계산이나 파일 읽기를 하면, 그동안 루프가 멈춰 창이 다시 그려지지 않고 클릭에도 반응하지 않습니다. 운영체제는 "응답 없음"을 띄웁니다. 오래 걸리는 일은 [「QThread와 워커 객체」](#/read/cpp-qt/qthr-worker)처럼 다른 스레드로 보내거나, 작은 조각으로 나눠 타이머로 이어 가세요. 중간중간 `QCoreApplication::processEvents()`를 부르는 방법도 있지만, 처리 중에 같은 슬롯이 다시 불리는 재진입 문제를 만들기 쉬워 권하지 않습니다.
</Note>

## 정리

- Qt 앱의 모든 반응은 이벤트 루프가 큐에서 이벤트를 꺼내 객체에 전달하는 것이다
- postEvent는 큐에 넣고 나중에, sendEvent는 지금 바로 처리하며, 받는 쪽은 event() 재정의나 이벤트 필터로 가로챈다
- 타이머도 루프 위에서 돌므로 루프를 오래 막으면 앱 전체가 멈추고, 긴 일은 다른 스레드로 보낸다
