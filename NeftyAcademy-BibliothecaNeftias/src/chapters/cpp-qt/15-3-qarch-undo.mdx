편집하는 앱이라면 실행 취소는 빠질 수 없습니다. 게임 엔진 책의 [「실행 취소」](#/read/cpp-game-engine/ed-undo)에서는 바꾸는 일 하나하나를 **명령 객체**로 만들고 스택에 쌓는 구조를 직접 짰습니다. Qt에는 이 구조가 `QUndoCommand`와 `QUndoStack`으로 들어 있습니다(Qt 6부터 QtGui 모듈에 있고, 스택을 목록으로 보여 주는 `QUndoView`만 Widgets에 있습니다). [「상태 관리」](#/read/cpp-qt/qarch-state)에서처럼 상태를 바꾸는 길을 하나로 모아 두었다면, 그 길을 명령으로 바꾸기만 하면 됩니다.

## 명령과 스택

도형 두 개가 있는 작은 편집기를 만들었습니다. 도형 추가와 이동이 각각 명령입니다.

```cpp qt=Gui
// 도형 편집기의 실행 취소: 바꾸는 일 하나하나를 명령 객체로 만든다
#include <QAction>
#include <QGuiApplication>
#include <QMap>
#include <QPoint>
#include <QUndoStack>
#include <cstdio>

struct Canvas { QMap<QString, QPoint> shapes; };   // 문서의 상태

class AddShape : public QUndoCommand {
public:
    AddShape(Canvas& c, const QString& name, QPoint pos)
        : QUndoCommand(name + " 추가"), c(c), name(name), pos(pos) {}
    void redo() override { c.shapes.insert(name, pos); }
    void undo() override { c.shapes.remove(name); }
private:
    Canvas& c;
    QString name;
    QPoint pos;
};

class MoveShape : public QUndoCommand {
public:
    MoveShape(Canvas& c, const QString& name, QPoint delta)
        : QUndoCommand(name + " 옮기기"), c(c), name(name),
          from(c.shapes.value(name)), to(from + delta) {}
    void redo() override { c.shapes[name] = to; }
    void undo() override { c.shapes[name] = from; }
    int id() const override { return 1; }            // 같은 id끼리만 합칠 수 있다
    bool mergeWith(const QUndoCommand* other) override {
        const auto* next = static_cast<const MoveShape*>(other);
        if (next->name != name) return false;
        to = next->to;                               // 끄는 동안의 이동을 하나로
        return true;
    }
private:
    Canvas& c;
    QString name;
    QPoint from, to;
};

int main(int argc, char* argv[]) {
    QGuiApplication app(argc, argv);
    Canvas canvas;
    QUndoStack stack;
    QAction* undoAction = stack.createUndoAction(&app, "실행 취소");

    auto show = [&](const char* what) {
        QString shapes;
        for (auto it = canvas.shapes.begin(); it != canvas.shapes.end(); ++it)
            shapes += QString(" %1(%2,%3)").arg(it.key()).arg(it->x()).arg(it->y());
        std::printf("%s:%s\n    명령 %d개, 현재 %d, 저장 상태%s, 메뉴 \"%s\"\n",
                    what, qPrintable(shapes), stack.count(), stack.index(),
                    stack.isClean() ? "와 같음" : "에서 바뀜",
                    qPrintable(undoAction->text()));
    };

    stack.push(new AddShape(canvas, "상자", {0, 0}));   // push가 redo()를 부른다
    stack.push(new AddShape(canvas, "원", {100, 0}));
    stack.setClean();                                   // 여기서 저장했다고 치자
    show("저장");

    for (int i = 0; i < 3; ++i)                         // 상자를 끌어서 옮긴다
        stack.push(new MoveShape(canvas, "상자", {10, 0}));
    show("상자를 세 번 옮김");

    stack.beginMacro("모두 아래로");                     // 여러 명령을 한 단계로
    stack.push(new MoveShape(canvas, "상자", {0, 50}));
    stack.push(new MoveShape(canvas, "원", {0, 50}));
    stack.endMacro();
    show("모두 아래로");

    stack.undo();
    show("실행 취소");
    stack.undo();
    show("실행 취소");

    stack.push(new AddShape(canvas, "별", {50, 50}));    // 되돌린 뒤 새 작업
    show("별 추가");
    std::printf("다시 실행할 것이 남았나: %s\n", stack.canRedo() ? "예" : "아니요");
}
```

실행 취소: 상자(0,0) 원(100,0)

- **명령이 하는 일**: `redo()`는 바꾸고 `undo()`는 정확히 되돌립니다. 되돌리는 데 필요한 값(`MoveShape`의 `from`)은 명령을 만들 때 챙겨 둡니다. `push`가 곧바로 `redo()`를 부르므로, 상태를 바꾸는 코드를 따로 부르지 않습니다
- **합치기**: 도형을 끄는 동안 이동 명령이 수십 개 생기는데, 실행 취소 한 번에 하나씩 되돌아가면 곤란합니다. `id()`가 같은 명령이 연달아 들어오면 스택이 `mergeWith`를 불러 보고, `true`를 돌려주면 새 명령을 버립니다. 세 번 옮겼는데 명령은 하나만 늘었습니다
- **매크로**: `beginMacro`와 `endMacro` 사이의 명령은 한 단계로 묶여 한 번에 되돌아갑니다. "모두 정렬"처럼 여러 대상을 한꺼번에 바꾸는 기능에 씁니다
- **저장 상태**: `setClean()`으로 저장한 위치를 표시해 두면, 되돌려서 그 위치로 돌아왔을 때 `isClean()`이 다시 참이 됩니다. `cleanChanged` 신호를 창 제목의 `*` 표시에 이으면 됩니다
- **가지치기**: 되돌린 뒤 새 명령을 넣으면 다시 실행할 수 있던 명령은 사라집니다. 명령 수가 4개에서 3개로 줄었습니다

`createUndoAction`과 `createRedoAction`이 만드는 동작은 스택을 따라 글자("실행 취소 상자 옮기기")와 사용 가능 여부가 저절로 바뀝니다. [「메인 윈도우, 메뉴, 도구 모음, 도킹」](#/read/cpp-qt/wid-mainwindow)에서처럼 메뉴와 도구 모음에 넣고 `QKeySequence::Undo` 단축키를 주면 끝입니다.

## 좋은 명령을 쓰는 법

- 명령은 위젯이 아니라 **문서**를 바꿉니다. 화면은 [「상태 관리」](#/read/cpp-qt/qarch-state)의 방식대로 문서의 신호를 받아 다시 그립니다. 그래야 실행 취소 후에도 화면이 저절로 맞습니다
- 명령은 문서를 참조하므로 스택이 문서보다 먼저 사라져야 합니다. 예제에서 `canvas`를 `stack`보다 먼저 선언한 것도 그 때문입니다(늦게 만든 것이 먼저 사라집니다)
- 명령이 쌓이면 메모리를 쓰므로 `setUndoLimit`으로 개수를 제한할 수 있고, 합친 결과 아무것도 바뀌지 않은 명령은 `setObsolete(true)`로 표시하면 스택에서 빠집니다
- 문서를 여러 개 여는 앱은 문서마다 스택을 두고 `QUndoGroup`으로 활성 문서의 스택을 메뉴에 잇습니다

<Note>
`QLineEdit`이나 `QPlainTextEdit` 같은 입력 위젯은 자기만의 실행 취소 기록을 따로 가지고 있습니다. 입력란에 포커스가 있을 때 Ctrl+Z가 입력란의 기록을 되돌릴지, 문서 전체의 스택을 되돌릴지 정해 두어야 사용자가 헷갈리지 않습니다. 보통은 글자를 입력하는 동안에는 입력란의 기록을 쓰고, 편집을 마칠 때 바뀐 값 전체를 하나의 명령으로 스택에 넣습니다.
</Note>

## 정리

- 바꾸는 일을 redo와 undo를 가진 QUndoCommand로 만들고 QUndoStack에 push하면 실행 취소와 다시 실행이 생긴다
- 연속된 작은 변경은 id와 mergeWith로 합치고, 여러 변경은 매크로로 한 단계로 묶는다
- setClean과 cleanChanged로 저장 여부를 알리고, createUndoAction이 만든 동작을 메뉴와 단축키에 단다
