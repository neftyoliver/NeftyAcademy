[「TCP와 UDP 소켓」](#/read/cpp-qt/qnet-sockets)의 TCP는 경계 없는 바이트 흐름이라 메시지 틀을 직접 만들어야 했습니다. **WebSocket**은 HTTP로 시작해 연결을 업그레이드한 뒤, 그 위에서 **메시지 단위로** 양쪽이 언제든 주고받는 프로토콜입니다. 웹 브라우저가 지원하므로 웹 화면과 Qt 앱, 또는 Qt 앱과 서버가 실시간으로 대화하는 데 잘 맞습니다. Qt WebSockets 모듈이 서버와 클라이언트를 모두 제공합니다.

## 작은 채팅 서버

```cpp qt=WebSockets
#include <QCoreApplication>
#include <QWebSocket>
#include <QWebSocketServer>
#include <cstdio>

using WS = QWebSocket;

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    // 서버보다 먼저 선언: 서버가 소멸하며 연결을 끊을 때 이 목록을 쓰기 때문이다
    QList<QWebSocket*> peers;
    // 채팅 서버: 받은 글을 연결된 모든 사람에게 다시 보낸다
    QWebSocketServer server("chat", QWebSocketServer::NonSecureMode);
    server.listen(QHostAddress::LocalHost, 0);
    QObject::connect(&server, &QWebSocketServer::newConnection, [&] {
        QWebSocket* p = server.nextPendingConnection();
        peers << p;
        QObject::connect(p, &WS::textMessageReceived, [&](const QString& m) {
            for (QWebSocket* q : peers) q->sendTextMessage("모두에게: " + m);
        });
        QObject::connect(p, &WS::binaryMessageReceived, [p](const QByteArray& b) {
            p->sendBinaryMessage(QByteArray::number(b.size()) + "바이트 받음");
        });
        QObject::connect(p, &WS::disconnected, [&, p] {
            peers.removeOne(p);
            p->deleteLater();
        });
    });

    QWebSocket client;
    QObject::connect(&client, &WS::connected, [&] {
        std::printf("연결됨: %s\n", qPrintable(client.requestUrl().scheme()));
        // 메시지 경계가 지켜진다
        client.sendTextMessage("안녕하세요");
        client.sendTextMessage("두 번째 줄");
        client.sendBinaryMessage(QByteArray(1000, 'x'));
        client.ping("p");
    });
    QObject::connect(&client, &WS::textMessageReceived, [&](const QString& m) {
        std::printf("받음(글): %s\n", qPrintable(m));
    });
    QObject::connect(&client, &WS::binaryMessageReceived, [&](const QByteArray& b) {
        std::printf("받음(이진 응답): %s\n", b.constData());
    });
    QObject::connect(&client, &WS::pong, [&](quint64, const QByteArray& payload) {
        std::printf("pong 받음, 실어 보낸 것 '%s'\n", payload.constData());
        client.close();
    });
    QObject::connect(&client, &WS::disconnected, &app, &QCoreApplication::quit);
    client.open(QUrl(QString("ws://127.0.0.1:%1").arg(server.serverPort())));
    return app.exec();
}
```

```text
연결됨: ws
받음(글): 모두에게: 안녕하세요
받음(글): 모두에게: 두 번째 줄
받음(이진 응답): 1000바이트 받음
pong 받음, 실어 보낸 것 'p'
```

## 메시지 단위

- 클라이언트가 글 메시지 두 개를 연달아 보냈지만, 서버는 정확히 두 번의 `textMessageReceived`를 받았고 각각 따로 돌려보냈습니다. TCP처럼 붙거나 쪼개질 걱정이 없습니다. 길이를 붙이거나 거래 읽기를 할 필요가 없습니다
- **글 메시지**(UTF-8)와 **이진 메시지**가 구분됩니다. 1000바이트짜리 이진 메시지가 한 덩어리로 도착했습니다. 보통 글 메시지에 [「JSON」](#/read/cpp-qt/core-json)을 담고, 이미지나 센서 데이터처럼 큰 것은 이진 메시지로 보냅니다
- `ping`을 보내면 상대가 자동으로 `pong`을 돌려줍니다. 연결이 살아 있는지, 왕복 시간이 얼마인지 확인하는 데 씁니다. 실어 보낸 내용('p')이 그대로 돌아왔습니다

## 서버와 클라이언트

- `QWebSocketServer`는 `NonSecureMode`(ws://)나 `SecureMode`(wss://, TLS)로 만들고 `listen`합니다. 새 연결은 `nextPendingConnection()`으로 꺼내 목록에 넣고, 끊기면 목록에서 빼고 `deleteLater`합니다
- `QWebSocket::open(url)`로 연결합니다. `connected` 뒤에야 메시지를 보낼 수 있습니다. 실제 서비스에서는 연결이 끊기면(`disconnected`) 잠시 기다렸다 다시 여는 재연결 로직을 넣습니다

<Note>
예제를 처음 썼을 때 주소 검사기가 **해제된 메모리 사용**을 잡아냈습니다. `peers` 목록을 서버보다 **나중에** 선언했더니, `main`이 끝날 때 목록이 먼저 소멸하고, 그다음 서버가 소멸하면서 남은 연결을 끊어 `disconnected` 처리기가 이미 사라진 목록을 고치려 한 것입니다. 지역 변수는 선언의 반대 순서로 소멸하므로, 람다가 기대는 것은 그 람다를 부를 수 있는 객체보다 **먼저** 선언해야 합니다. 이런 버그는 프로그램이 끝날 때만 나타나 놓치기 쉽습니다. 연결 상태를 묶은 클래스를 만들어 멤버로 두면 이런 순서 문제를 피하기 쉽습니다.
</Note>

## 정리

- WebSocket은 HTTP로 시작해 업그레이드한 양방향 연결로, 메시지 경계가 지켜지고 브라우저도 쓸 수 있다
- 글 메시지와 이진 메시지를 구분해 주고받으며, ping과 pong으로 연결을 확인한다
- 서버는 연결 목록을 관리하고 끊긴 연결을 정리하며, 처리기가 기대는 객체는 그 처리기를 부를 객체보다 먼저 선언한다
