## Qt MQTT 모듈

Qt에는 MQTT 클라이언트 모듈(Qt MQTT)이 있습니다. 오픈 소스판은 **GPLv3**, 그 밖에는 상용 라이선스로 제공되므로 [「Qt의 구성과 라이선스」](#/read/cpp-qt/start-what)의 조건을 확인하고 쓰세요. CMake에서는 `find_package(Qt6 REQUIRED COMPONENTS Mqtt)`와 `Qt6::Mqtt`로 붙입니다. 쓰는 모양은 다른 Qt 네트워크 클래스와 같습니다.

```cpp nocheck
#include <QMqttClient>

auto* client = new QMqttClient(this);
client->setHostname("broker.local");
client->setPort(1883);
connect(client, &QMqttClient::connected, this, [client] {
    client->subscribe(QMqttTopicFilter("sensors/#"), 1);
    client->publish(QMqttTopicName("sensors/room1/temp"), "21.5", 1);
});
connect(client, &QMqttClient::messageReceived, this,
        [](const QByteArray& message, const QMqttTopicName& topic) {
            qDebug() << topic.name() << message;
        });
client->connectToHost();
```

이 책의 실행 환경(우분투 24.04 패키지)에는 Qt MQTT가 들어 있지 않아 위 코드는 돌려 보지 못했습니다. 함수 이름과 시그니처는 Qt 6 공식 문서의 `QMqttClient` 항목을 따랐습니다.

## 모듈이 없을 때: C 라이브러리 잇기

Qt 모듈이 없거나 라이선스가 맞지 않으면, 검증된 C 라이브러리를 Qt에 붙이는 방법이 있습니다. 많은 C 네트워크 라이브러리가 자기 스레드에서 돌며 콜백을 부르는데, 그 콜백에서 위젯이나 Qt 객체를 바로 만지면 안 됩니다. 콜백에서는 데이터만 복사해 `QMetaObject::invokeMethod(…, Qt::QueuedConnection)`으로 **메인 스레드에 넘기는** 것이 요령입니다. 예제는 같은 기계에 Mosquitto 브로커를 띄우고, libmosquitto로 구독과 발행을 했습니다.

```cpp qt=Network flags=-lmosquitto
#include <QCoreApplication>
#include <QProcess>
#include <QTcpServer>
#include <QThread>
#include <cstdio>
#include <cstring>
#include <mosquitto.h>

// Qt MQTT 모듈이 없을 때: C 라이브러리 libmosquitto를 Qt 이벤트 루프에 잇는다
struct Bridge {
    QCoreApplication* app;
    int received = 0;
};

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);

    // 예제용 브로커를 빈 포트에 띄운다(실제로는 이미 돌고 있는 브로커에 붙는다)
    QTcpServer probe;
    probe.listen(QHostAddress::LocalHost, 0);
    int port = probe.serverPort();
    probe.close();
    QProcess broker;
    broker.start("mosquitto", {"-p", QString::number(port)});
    broker.waitForStarted();
    QThread::msleep(300);

    mosquitto_lib_init();
    Bridge bridge{&app};
    mosquitto* m = mosquitto_new("qt-demo", true, &bridge);
    mosquitto_connect_callback_set(m, [](mosquitto* m, void*, int rc) {
        // 와일드카드
        if (rc == 0) mosquitto_subscribe(m, nullptr, "sensors/#", 1);
    });
    mosquitto_subscribe_callback_set(m, [](mosquitto* m, void*, int, int,
                                           const int*) {
        const char* msgs[][2] = {{"sensors/room1/temp", "21.5"},
                                 {"sensors/room2/temp", "19.0"},
                                 {"sensors/room1/hum", "40"}};
        for (auto& [topic, payload] : msgs)
            mosquitto_publish(m, nullptr, topic, int(strlen(payload)), payload,
                              1, false);
    });
    // 이 콜백은 libmosquitto의 스레드에서 불린다 -> Qt 메인 스레드로 넘긴다
    mosquitto_message_callback_set(m, [](mosquitto*, void* ud,
                                         const mosquitto_message* msg) {
        auto* b = static_cast<Bridge*>(ud);
        QString topic = msg->topic;
        QByteArray payload(static_cast<const char*>(msg->payload), msg->payloadlen);
        QMetaObject::invokeMethod(b->app, [b, topic, payload] {
            bool onMain = QThread::currentThread() == b->app->thread();
            std::printf("  %s = %s (메인 스레드: %s)\n", qPrintable(topic),
                        payload.constData(), onMain ? "예" : "아니오");
            if (++b->received == 3) b->app->quit();
        }, Qt::QueuedConnection);
    });

    mosquitto_connect(m, "127.0.0.1", port, 30);
    // 네트워크는 libmosquitto 스레드가
    mosquitto_loop_start(m);
    std::printf("구독 sensors/# 와 발행 3건\n");
    int rc = app.exec();

    mosquitto_disconnect(m);
    mosquitto_loop_stop(m, false);
    mosquitto_destroy(m);
    mosquitto_lib_cleanup();
    broker.terminate();
    broker.waitForFinished();
    return rc;
}
```

```text
구독 sensors/# 와 발행 3건
  sensors/room1/temp = 21.5 (메인 스레드: 예)
  sensors/room2/temp = 19.0 (메인 스레드: 예)
  sensors/room1/hum = 40 (메인 스레드: 예)
```

- `mosquitto_loop_start`는 라이브러리 자체 스레드에서 네트워크를 돌립니다. 그래서 메시지 콜백은 그 스레드에서 불립니다
- 콜백은 주제와 내용을 `QString`, `QByteArray`로 **복사**한 뒤 람다에 담아 메인 스레드의 큐에 넣었습니다. 출력의 "메인 스레드: 예"가 그 결과입니다. 콜백이 돌려받은 `msg` 포인터는 콜백이 끝나면 무효이므로, 포인터를 넘기면 안 됩니다
- `sensors/#` 하나로 room1과 room2의 온도, room1의 습도를 모두 받았습니다. QoS 1로 발행해서 브로커가 적어도 한 번은 전달을 보장합니다

<Note>
라이브러리 스레드 대신 라이브러리의 소켓을 Qt 이벤트 루프에 직접 맡기는 방법도 있습니다. libmosquitto의 `mosquitto_socket()`으로 소켓 번호를 얻어 `QSocketNotifier`로 읽기를 지켜보고, 주기적으로 `mosquitto_loop_misc()`를 `QTimer`로 부르면 스레드 없이 메인 스레드 하나로 돕니다. 실제 장치와 쓸 때는 브로커 주소, 사용자 인증, TLS(포트 8883)를 설정해야 합니다.
</Note>

## 정리

- MQTT는 브로커를 가운데 두고 주제로 발행과 구독을 하며, + 와 # 와일드카드로 여러 주제를 받는다
- Qt MQTT 모듈의 QMqttClient는 다른 Qt 네트워크 클래스처럼 시그널로 동작하며, 오픈 소스판은 GPLv3이다
- C 라이브러리를 붙일 때는 라이브러리 스레드의 콜백에서 데이터를 복사해 큐 호출로 메인 스레드에 넘긴다
