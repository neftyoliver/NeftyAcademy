레벨에 고블린을 50마리 놓았는데, 나중에 고블린이 너무 빠르다는 말이 나왔다고 합시다. 50마리를 하나씩 고치는 대신 한 곳만 고치고 싶습니다. **프리팹**은 물체 몇 개(고블린 몸과 칼처럼 부모와 자식으로 묶인 것)의 기본값을 하나의 에셋으로 저장해 두고, 레벨에는 그 에셋을 가리키는 **인스턴스**를 놓는 방식입니다.

## 바꾼 값만 기억하기

핵심은 인스턴스가 모든 값을 복사하지 않고, 프리팹과 **다르게 바꾼 값(오버라이드)** 만 기억한다는 점입니다.

```cpp
#include <map>
#include <print>
#include <string>
#include <vector>

// 프리팹: 물체 몇 개의 기본값 묶음
struct Node {
    std::string name;
    std::map<std::string, float> props;   // 속성 이름 -> 값
    int parent = -1;                      // 프리팹 안에서의 번호
};
struct Prefab { std::string name; std::vector<Node> nodes; };

// 인스턴스: 프리팹을 가리키고, 바꾼 값(오버라이드)만 따로 기억한다
struct Instance {
    const Prefab* src;
    std::string label;
    std::map<std::pair<int, std::string>, float> overrides = {};

    float get(int node, const std::string& key) const {
        if (auto it = overrides.find({node, key}); it != overrides.end())
            return it->second;
        return src->nodes[node].props.at(key);
    }
    void set(int node, const std::string& key, float v) {
        overrides[{node, key}] = v;
    }
    void revert(int node, const std::string& key) {
        overrides.erase({node, key});
    }
};

void show(const Instance& in) {
    std::print("{:6}", in.label);
    for (int i = 0; i < int(in.src->nodes.size()); ++i)
        for (auto& [k, _] : in.src->nodes[i].props)
            std::print(" {}.{}={}", in.src->nodes[i].name, k, in.get(i, k));
    std::println("  (오버라이드 {}개)", in.overrides.size());
}

int main() {
    Prefab goblin{"고블린", {
        {"몸", {{"체력", 30}, {"속도", 4}}, -1},
        {"칼", {{"공격", 5}}, 0},
    }};

    Instance a{&goblin, "보통"}, b{&goblin, "대장"}, c{&goblin, "느림보"};
    b.set(0, "체력", 120);
    b.set(1, "공격", 12);
    c.set(0, "속도", 2);
    std::println("-- 처음");
    show(a); show(b); show(c);

    // 디자이너가 프리팹을 고치면, 바꾸지 않은 값만 따라간다
    goblin.nodes[0].props["속도"] = 5;
    goblin.nodes[1].props["공격"] = 6;
    std::println("-- 프리팹의 속도 5, 공격 6으로 수정");
    show(a); show(b); show(c);

    c.revert(0, "속도");
    std::println("-- 느림보의 속도 오버라이드 되돌림");
    show(c);
}
```

대장   몸.속도=4 몸.체력=120 칼.공격=12  (오버라이드 2개)

대장   몸.속도=5 몸.체력=120 칼.공격=12  (오버라이드 2개)
느림보 몸.속도=2 몸.체력=30 칼.공격=6  (오버라이드 1개)
-- 느림보의 속도 오버라이드 되돌림
느림보 몸.속도=5 몸.체력=30 칼.공격=6  (오버라이드 0개)

- 프리팹의 속도를 5로 고치자 **보통**과 **대장**은 따라갔지만, 속도를 직접 2로 정한 **느림보**는 그대로였습니다. 디자이너가 일부러 바꾼 값을 원본 수정이 덮어쓰면 안 되기 때문입니다
- 대장의 공격 12도 프리팹의 공격이 6이 되어도 남았습니다. 반면 대장이 건드리지 않은 속도는 5로 따라갔습니다. 값 단위로 따로 판단합니다
- **되돌리기**는 오버라이드를 지우는 것뿐입니다. 지우는 순간 프리팹의 현재 값이 보입니다. 편집기에서 바꾼 속성을 굵게 표시하고 "원래대로" 메뉴를 주는 기능이 이 구조 위에서 동작합니다

## 저장 파일에 남는 것

[「저장과 불러오기」](#/read/cpp-game-engine/scene-serialize)와 이어 보면, 레벨 파일에는 고블린 50마리의 모든 속성이 아니라 "이 GUID의 프리팹을 이 위치에, 오버라이드는 이것들" 정도만 남습니다. 파일이 작아지고, 프리팹을 고친 커밋과 레벨을 고친 커밋이 섞이지 않습니다.

오버라이드를 가리키는 열쇠는 예제의 `(노드 번호, 속성 이름)`이었는데, 실제로는 번호보다 프리팹 안에서 바뀌지 않는 **노드 ID**를 씁니다. 프리팹에 노드를 하나 끼워 넣으면 번호가 밀리면서 오버라이드가 엉뚱한 노드에 붙기 때문입니다. 속성 이름이 바뀌었을 때 오버라이드를 옮겨 주는 일도 [「리플렉션 만들기」](#/read/cpp-game-engine/scr-reflection)의 필드 정보가 있어야 할 수 있습니다.

## 중첩과 변형

프리팹 안에 다른 프리팹의 인스턴스가 들어갈 수 있으면(**중첩 프리팹**) 값을 찾는 순서가 길어집니다. 바깥 인스턴스의 오버라이드, 바깥 프리팹이 안쪽에 준 오버라이드, 안쪽 프리팹의 기본값 순서로 찾습니다. 프리팹을 바탕으로 몇 값만 바꾼 새 프리팹(**변형**)도 같은 원리입니다. 예제의 `get`이 하는 "있으면 내 값, 없으면 원본에 묻기"를 여러 층으로 이은 것입니다.

<Note>
인스턴스를 실제로 게임에 내보낼 때는 이 층들을 매번 따라가지 않습니다. 레벨을 불러오거나 [「가져오기와 굽기」](#/read/cpp-game-engine/res-import)에서 구울 때 값을 한 번 계산해 펼친 다음, 실행 중에는 보통 물체처럼 다룹니다. 오버라이드 구조는 편집과 저장을 위한 것이고, 실행 중 성능과는 상관이 없도록 두는 것이 보통입니다.
</Note>

## 정리

- 프리팹은 물체 묶음의 기본값을 한 에셋에 두고, 레벨에는 그것을 가리키는 인스턴스를 놓는다
- 인스턴스는 바꾼 값만 기억하므로, 원본을 고치면 건드리지 않은 값만 따라가고 되돌리기는 오버라이드를 지우는 것이다
- 오버라이드는 바뀌지 않는 노드 ID로 가리키고, 중첩과 변형은 값을 찾는 층이 늘어난 것이며, 실행 전에 한 번 펼친다
