요즘 게임의 한 프레임은 그림자, G-버퍼, 주변광 가림(SSAO), 조명, 반사, 블룸, 톤 매핑처럼 **패스** 수십 개로 이뤄집니다. 패스마다 텍스처를 쓰고 읽고, [「그래픽 API 감싸기」](#/read/cpp-game-engine/rend-abstraction)에서 본 요즘 API는 "이 텍스처를 다 쓴 뒤에 읽어라"는 **장벽**을 프로그램이 직접 넣어야 합니다. 패스가 늘수록 이것을 손으로 관리하기 어려워져, 많은 엔진이 **렌더 그래프**(frame graph)를 씁니다.

## 패스가 읽고 쓰는 것을 밝힌다

렌더 그래프에서 각 패스는 실행 함수와 함께 "무엇을 읽고 무엇을 쓰는지"를 적습니다. [「시스템과 실행 순서」](#/read/cpp-game-engine/ecs-systems)에서 ECS 시스템이 컴포넌트를 밝힌 것과 같은 생각입니다. 그러면 프레임마다 그래프를 **컴파일**해 세 가지를 저절로 얻습니다.

```cpp
#include <algorithm>
#include <map>
#include <print>
#include <set>
#include <string>
#include <vector>

struct Pass {
    std::string name;
    std::vector<std::string> reads, writes;
};

int main()
{
    // 이번 프레임에 할 일들. 적힌 순서가 곧 제출 순서
    std::vector<Pass> passes = {
        {"그림자",     {},                    {"shadow_map"}},
        {"G-버퍼",     {},       {"gbuf_albedo", "gbuf_normal", "depth"}},
        {"SSAO",       {"gbuf_normal", "depth"}, {"ao"}},
        {"조명",       {"gbuf_albedo", "gbuf_normal", "ao", "shadow_map"},
                       {"hdr"}},
        {"디버그 선",  {"depth"},              {"debug_lines"}},   // 읽는 이 없음
        {"톤 매핑",    {"hdr"},                {"backbuffer"}},
    };

    // 1) 화면(backbuffer)에서 거꾸로 따라가며 필요한 패스만 남긴다
    std::set<std::string> needed_res = {"backbuffer"};
    std::vector<bool> keep(passes.size(), false);
    for (int i = static_cast<int>(passes.size()) - 1; i >= 0; --i) {
        bool useful = std::ranges::any_of(
            passes[i].writes, [&](auto& r) { return needed_res.contains(r); });
        if (!useful) continue;
        keep[i] = true;
        for (auto& r : passes[i].reads) needed_res.insert(r);
    }
    std::print("남는 패스:");
    for (std::size_t i = 0; i < passes.size(); ++i)
        if (keep[i]) std::print(" {}", passes[i].name);
    std::println("  (디버그 선은 빠짐)");

    // 2) 장벽: 쓰고 난 자원을 처음 읽는 패스 앞에 "다 썼으니 읽어도 된다"
    std::map<std::string, std::string> last_writer;
    // 처음 쓰는 패스, 마지막 패스
    std::map<std::string, std::pair<int, int>> life;
    int step = 0;
    for (std::size_t i = 0; i < passes.size(); ++i) {
        if (!keep[i]) continue;
        for (auto& r : passes[i].reads)
            if (last_writer.contains(r)) {
                std::println("  장벽: {} (쓰기: {}) -> {}", r, last_writer[r],
                             passes[i].name);
                last_writer.erase(r);                    // 한 번만 넣는다
            }
        for (auto& r : passes[i].reads) life[r].second = step;
        for (auto& r : passes[i].writes) {
            last_writer[r] = passes[i].name;
            if (!life.contains(r)) life[r] = {step, step};
            life[r].second = step;
        }
        ++step;
    }

    // 3) 수명이 겹치지 않는 임시 자원은 같은 메모리를 번갈아 쓴다
    std::vector<std::pair<std::pair<int, int>, std::string>> order;
    for (auto& [name, span] : life)
        if (name != "backbuffer") order.push_back({span, name});   // 화면은 따로
    std::ranges::sort(order);                           // 먼저 시작하는 것부터
    std::vector<int> busy_until;                        // 메모리 칸마다 비는 시점
    for (auto& [span, name] : order) {
        auto [first, last] = span;
        std::size_t s = 0;
        while (s < busy_until.size() && busy_until[s] >= first) ++s;
        if (s == busy_until.size()) busy_until.push_back(0);
        busy_until[s] = last;
        std::println("  {:<12} 패스 {}~{} -> 메모리 칸 {}", name, first, last, s);
    }
    std::println("임시 자원 {}개를 메모리 칸 {}개에", order.size(),
                 busy_until.size());
}
```

```text
  장벽: gbuf_normal (쓰기: G-버퍼) -> SSAO
  장벽: depth (쓰기: G-버퍼) -> SSAO
  장벽: gbuf_albedo (쓰기: G-버퍼) -> 조명
  장벽: ao (쓰기: SSAO) -> 조명
  장벽: shadow_map (쓰기: 그림자) -> 조명
  장벽: hdr (쓰기: 조명) -> 톤 매핑
  shadow_map   패스 0~3 -> 메모리 칸 0
  depth        패스 1~2 -> 메모리 칸 1
  gbuf_albedo  패스 1~3 -> 메모리 칸 2
  gbuf_normal  패스 1~3 -> 메모리 칸 3
  ao           패스 2~3 -> 메모리 칸 4
  hdr          패스 3~4 -> 메모리 칸 1
임시 자원 6개를 메모리 칸 5개에
```

## 1. 쓸모없는 패스 빼기

화면(`backbuffer`)에서 거꾸로, "이것을 만들려면 무엇이 필요한가"를 따라갑니다. 톤 매핑은 hdr이 필요하고, hdr을 만드는 조명은 G-버퍼, ao, 그림자 맵이 필요하고… 이렇게 닿지 않는 패스는 실행하지 않습니다. 디버그 선은 아무도 읽지 않아서 빠졌습니다. 설정에서 SSAO를 끄면 SSAO 패스만이 아니라 그것만을 위해 만들던 자원도 함께 사라지는 식으로, 기능을 켜고 끄기가 쉬워집니다.

## 2. 장벽 넣기

어떤 자원을 **쓴 뒤 처음 읽는** 패스 앞에 장벽을 넣었습니다. G-버퍼가 쓴 법선을 SSAO가 읽기 전에, SSAO가 쓴 ao를 조명이 읽기 전에 장벽이 들어갑니다. SSAO와 조명이 둘 다 법선을 읽는 것처럼 읽기 다음의 읽기에는 장벽이 필요 없습니다. 실제 장벽에는 "어떤 단계에서 어떤 단계로, 어떤 용도에서 어떤 용도로(쓰기 대상 → 셰이더에서 읽기)"까지 적어야 하는데, 그래프가 패스의 종류와 자원의 용도를 알고 있어서 이것도 계산해 넣을 수 있습니다. 손으로 넣다 빠뜨리면 가끔씩만 그림이 깨지는, 찾기 아주 어려운 버그가 됩니다.

## 3. 임시 자원의 메모리 나눠 쓰기

자원마다 처음 쓰이는 패스와 마지막으로 쓰이는 패스를 알면, **수명이 겹치지 않는** 자원끼리는 같은 메모리를 번갈아 쓸 수 있습니다. depth는 패스 2에서 마지막으로 쓰이고, hdr은 패스 3에서 처음 생기므로 둘이 메모리 칸 1을 나눠 썼습니다. 임시 자원 6개를 칸 5개로 줄였고, 패스가 수십 개인 실제 프레임에서는 GPU 메모리를 훨씬 많이 아낍니다. 예제는 먼저 시작하는 것부터 비어 있는 칸에 넣는 단순한 방법을 썼습니다.

<Note>
예제는 모든 임시 자원의 크기가 같다고 가정했습니다. 실제로는 해상도와 형식이 달라서, 큰 메모리 덩어리 안에서 자원마다 위치를 정하는 할당 문제가 됩니다. 또 같은 메모리를 다른 자원이 이어 쓰려면 API에 "이제 이 메모리는 저 자원의 것"이라고 알리는 별명(aliasing) 장벽이 필요합니다. 수명 정보는 GPU가 패스 둘을 동시에 돌려도 되는지(비동기 계산 큐)를 정하는 데도 쓰입니다.
</Note>

## 정리

- 렌더 그래프는 패스마다 읽고 쓰는 자원을 밝혀 두고, 프레임마다 그래프를 컴파일해 실행 계획을 만든다
- 화면에서 거꾸로 따라가 쓸모없는 패스를 빼고, 쓴 자원을 처음 읽는 곳 앞에 장벽을 저절로 넣는다
- 자원의 첫·마지막 사용 패스로 수명을 구해, 겹치지 않는 임시 자원끼리 메모리를 나눠 쓴다
