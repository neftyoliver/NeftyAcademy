[「장면 그래프」](#/read/cpp-game-engine/scene-graph)에서 만든 장면은 메모리 안에만 있습니다. 편집기에서 만든 레벨을 파일로 남기고, 게임이 그 파일을 다시 읽어 같은 장면을 세우려면 **직렬화**가 필요합니다. 어려운 점은 셋입니다. 메모리 주소는 다음 실행에서 쓸모가 없고, 형식은 개발 내내 바뀌며, 사람이 읽기 좋은 형식과 기계가 빨리 읽는 형식이 다릅니다.

## 한 장면, 두 형식

성 위에 탑이, 탑 위에 깃발이 붙은 장면을 텍스트와 이진으로 저장했다가 다시 읽습니다.

```cpp
#include <cstdint>
#include <cstring>
#include <map>
#include <print>
#include <sstream>
#include <string>
#include <vector>

struct Transform { float x = 0, y = 0, z = 0; };
struct Entity {
    std::uint64_t guid;           // 저장해도 바뀌지 않는 이름표
    std::string name;
    Transform t;
    std::uint64_t parent = 0;     // 부모도 guid로 가리킨다
    float health = 100;           // 버전 2에서 새로 생긴 필드
};

// ---- 텍스트 형식: 사람이 읽고 diff로 볼 수 있다 ----
std::string to_text(const std::vector<Entity>& es) {
    std::ostringstream o;
    o << "version 2\n";
    for (auto& e : es)
        o << "entity " << e.guid << " " << e.name << " parent " << e.parent
          << " pos " << e.t.x << " " << e.t.y << " " << e.t.z
          << " health " << e.health << "\n";
    return o.str();
}

std::vector<Entity> from_text(const std::string& s) {
    std::istringstream in(s);
    std::string word;
    int version = 0;
    in >> word >> version;
    std::vector<Entity> es;
    while (in >> word) {           // word == "entity"
        Entity e;
        in >> e.guid >> e.name >> word >> e.parent
           >> word >> e.t.x >> e.t.y >> e.t.z;
        if (version >= 2) in >> word >> e.health;   // 옛 파일엔 없다
        es.push_back(e);
    }
    return es;
}

// ---- 이진 형식: 작고 빠르다 ----
template <class T> void put(std::vector<std::uint8_t>& b, const T& v) {
    auto p = reinterpret_cast<const std::uint8_t*>(&v);
    b.insert(b.end(), p, p + sizeof v);
}
template <class T> T get(const std::uint8_t*& p) {
    T v; std::memcpy(&v, p, sizeof v); p += sizeof v; return v;
}

std::vector<std::uint8_t> to_bin(const std::vector<Entity>& es) {
    std::vector<std::uint8_t> b;
    put<std::uint32_t>(b, 0x4E534345);           // 마법 수 "ECSN"
    put<std::uint16_t>(b, 2);                    // 버전
    put<std::uint32_t>(b, std::uint32_t(es.size()));
    for (auto& e : es) {
        put(b, e.guid);
        put<std::uint16_t>(b, std::uint16_t(e.name.size()));
        b.insert(b.end(), e.name.begin(), e.name.end());
        put(b, e.parent); put(b, e.t); put(b, e.health);
    }
    return b;
}

std::vector<Entity> from_bin(const std::vector<std::uint8_t>& b) {
    const std::uint8_t* p = b.data();
    if (get<std::uint32_t>(p) != 0x4E534345) return {};
    auto version = get<std::uint16_t>(p);
    auto n = get<std::uint32_t>(p);
    std::vector<Entity> es(n);
    for (auto& e : es) {
        e.guid = get<std::uint64_t>(p);
        auto len = get<std::uint16_t>(p);
        e.name.assign(reinterpret_cast<const char*>(p), len); p += len;
        e.parent = get<std::uint64_t>(p);
        e.t = get<Transform>(p);
        if (version >= 2) e.health = get<float>(p);
    }
    return es;
}

int main() {
    std::vector<Entity> scene = {
        {1001, "성", {0, 0, 0}, 0, 500},
        {1002, "탑", {4, 0, 2}, 1001, 200},
        {1003, "깃발", {0, 6, 0}, 1002, 1},
    };
    auto text = to_text(scene);
    std::print("{}", text);
    auto back = from_text(text);
    std::println("텍스트 왕복: {}개, 깃발 부모 {}", back.size(), back[2].parent);

    auto bin = to_bin(scene);
    auto back2 = from_bin(bin);
    std::println("이진 {}바이트 / 텍스트 {}바이트, 왕복 후 탑 x={}",
                 bin.size(), text.size(), back2[1].t.x);

    std::string v1 = "version 1\nentity 7 오래된상자 parent 0 pos 1 2 3\n";
    auto old = from_text(v1);
    std::println("버전 1 파일: {} health={} (기본값)", old[0].name, old[0].health);

    // guid로 부모를 다시 잇는다: 불러온 순서와 메모리 주소는 매번 다르다
    std::map<std::uint64_t, const Entity*> by_guid;
    for (auto& e : back2) by_guid[e.guid] = &e;
    const Entity* e = by_guid[1003];
    std::string chain = e->name;
    while (e->parent) { e = by_guid[e->parent]; chain += " -> " + e->name; }
    std::println("부모 사슬: {}", chain);
}
```

```text
version 2
entity 1001 성 parent 0 pos 0 0 0 health 500
entity 1002 탑 parent 1001 pos 4 0 2 health 200
entity 1003 깃발 parent 1002 pos 0 6 0 health 1
텍스트 왕복: 3개, 깃발 부모 1002
이진 124바이트 / 텍스트 155바이트, 왕복 후 탑 x=4
버전 1 파일: 오래된상자 health=100 (기본값)
부모 사슬: 깃발 -> 탑 -> 성
```

- **텍스트 형식**은 사람이 읽고, 버전 관리 도구에서 바뀐 줄만 볼 수 있습니다. 여러 사람이 한 레벨을 고칠 때 병합도 됩니다. 그래서 편집기가 저장하는 원본 장면은 텍스트(JSON, YAML, 자체 형식)인 경우가 많습니다
- **이진 형식**은 작고, 숫자를 문자로 바꾸고 되돌리는 일이 없어 빠릅니다. [「가져오기와 굽기」](#/read/cpp-game-engine/res-import)처럼 출시용 장면은 굽는 단계에서 이진으로 바꿉니다
- 이진 파일 맨 앞의 **마법 수**는 엉뚱한 파일을 읽으려 할 때 바로 거절하게 해 줍니다. 리틀 엔디언으로 저장되어 파일 첫 네 바이트가 `ECSN`으로 보입니다

## 버전 번호

마지막 줄 직전의 출력을 보면, `health` 필드가 없던 **버전 1 파일**도 읽혔고 빠진 값은 기본값 100이 되었습니다. 파일마다 버전을 적어 두고, 읽는 쪽이 "이 버전부터 생긴 필드"를 구분하는 방식입니다. 이것이 없으면 필드를 하나 더할 때마다 팀의 모든 레벨 파일이 깨집니다.

버전이 쌓이면 읽기 코드가 `if (version >= N)`으로 지저분해집니다. 흔한 해결책은 둘입니다.

- **이름 붙은 필드**: 텍스트라면 `health 200`처럼 이름과 값을 함께 쓰고, 모르는 이름은 건너뛰고, 없는 이름은 기본값을 씁니다. 순서에도 덜 민감해집니다. 예제의 텍스트 형식은 이름을 쓰지만 순서대로 읽기 때문에 이 장점을 다 살리지 못합니다
- **변환기 사슬**: 버전 1을 2로, 2를 3으로 바꾸는 작은 함수들을 두고, 읽은 뒤 최신 버전까지 차례로 통과시킵니다. 읽기 코드 자체는 최신 형식만 압니다

## 포인터 대신 GUID

`Entity`는 부모를 포인터가 아니라 `guid`로 가리킵니다. 불러올 때마다 물체가 놓이는 메모리 주소는 다르니, 주소를 저장하면 아무 뜻이 없습니다. 예제의 마지막 부분처럼 다 읽은 뒤 GUID에서 물체를 찾는 표를 만들고 관계를 다시 잇습니다.

[「핸들과 세대 인덱스」](#/read/cpp-game-engine/mem-handles)의 핸들도 실행 중에만 뜻이 있으므로 그대로 저장하지 않습니다. 저장할 때는 핸들을 GUID로, 불러올 때는 GUID를 새 핸들로 바꿉니다. GUID는 물체가 처음 만들어질 때 한 번 정해지고 이후 바뀌지 않아서, 다른 파일(다른 레벨, 저장 게임, 에셋 참조)에서도 같은 물체를 가리킬 수 있습니다.

## 손으로 쓰지 않으려면

필드가 생길 때마다 `to_text`, `from_text`, `to_bin`, `from_bin` 네 곳을 고치면 언젠가 하나를 빠뜨립니다. 그래서 엔진은 타입의 필드 목록을 한 번 적어 두고, 모든 형식이 그 목록을 따라 읽고 쓰게 만듭니다. 이 필드 목록이 [「리플렉션 만들기」](#/read/cpp-game-engine/scr-reflection)의 주제이고, 같은 목록을 편집기의 속성 창도 씁니다.

<Note>
예제의 텍스트 형식은 일부러 단순하게 만들어서 두 가지 함정이 남아 있습니다. 이름에 띄어쓰기가 있으면 깨지고, 실수는 기본 6자리로 쓰여서 `0.1f`처럼 정확히 적히지 않는 값이 저장할 때마다 조금씩 바뀔 수 있습니다. 실수를 텍스트로 저장할 때는 `std::to_chars`처럼 되읽었을 때 같은 값이 보장되는 가장 짧은 표현을 쓰고, 문자열은 따옴표와 이스케이프로 감쌉니다. 이진 형식도 `Transform`을 통째로 복사했기 때문에 구조체 배치와 엔디언이 같은 기계끼리만 통합니다.
</Note>

## 정리

- 편집용 원본은 사람이 읽고 병합할 수 있는 텍스트로, 출시용은 작고 빠른 이진으로 저장하는 경우가 많다
- 파일에 버전을 적고 이름 붙은 필드나 변환기 사슬로 옛 파일을 읽으며, 마법 수로 엉뚱한 파일을 거절한다
- 관계는 메모리 주소나 핸들이 아니라 바뀌지 않는 GUID로 저장하고, 불러온 뒤 GUID 표로 다시 잇는다
