게임은 "입력을 읽고, 세상을 한 걸음 움직이고, 그린다"를 1초에 수십~수백 번 되풀이하는 프로그램입니다. 이 되풀이가 **게임 루프**이고, [「층으로 나눈 구조」](#/read/cpp-game-engine/arch-layers)의 모든 층이 이 루프 안에서 차례로 불립니다. 가장 중요한 결정은 "한 걸음이 몇 초인가"입니다.

## 가장 단순한 루프

```cpp nocheck
while (running) {
    double dt = clock.seconds_since_last_frame();
    poll_input();
    update(dt);        // 세상을 dt초만큼 움직인다
    render();
}
```

`dt`를 그대로 쓰면 빠른 컴퓨터는 작은 걸음을 많이, 느린 컴퓨터는 큰 걸음을 조금 걷습니다. 얼핏 공평해 보이지만, 물리 계산은 걸음의 크기에 따라 결과가 달라집니다.

## 프레임 시간 vs 고정 간격

100m 높이에서 떨어지는 공을 3초 동안 계산해, 프레임 속도마다 결과를 견줘 봅니다.

```cpp
#include <algorithm>
#include <print>
#include <vector>

struct Body {
    double y = 100.0;   // 높이(m)
    double v = 0.0;     // 속도(m/s)
};

void step(Body& b, double dt)            // 반암시적 오일러 한 걸음
{
    b.v += -9.8 * dt;
    b.y += b.v * dt;
}

// 프레임 시간이 들쭉날쭉한 컴퓨터에서 3초 동안
Body run_variable(const std::vector<double>& frames)
{
    Body b;
    for (double dt : frames)
        step(b, dt);                     // 프레임 시간을 그대로 물리에 쓴다
    return b;
}

struct Fixed {
    Body body;
    int steps = 0;        // 지금까지 밟은 걸음 수
    int max_per_frame = 0;
    double alpha = 0.0;   // 남은 시간 / 한 걸음: 그림을 보간할 비율
};

Fixed run_fixed(const std::vector<double>& frames)
{
    constexpr double kStep = 1.0 / 60.0;
    Fixed f;
    double acc = 0.0;
    for (double dt : frames) {
        acc += std::min(dt, 0.25);       // 너무 긴 프레임은 잘라 낸다
        int n = 0;
        while (acc >= kStep) {           // 쌓인 시간만큼 고정 간격으로
            step(f.body, kStep);
            acc -= kStep;
            ++n;
        }
        f.steps += n;
        f.max_per_frame = std::max(f.max_per_frame, n);
    }
    f.alpha = acc / kStep;
    return f;
}

std::vector<double> frames_at(double fps)
{
    return std::vector<double>(static_cast<int>(3.0 * fps), 1.0 / fps);
}

int main()
{
    std::vector<double> jitter;          // 30~144fps를 오가는 3초
    const double pattern[] = {1 / 144.0, 1 / 30.0, 1 / 90.0, 1 / 60.0};
    for (double total = 0; total < 3.0;) {
        double dt = pattern[jitter.size() % 4];
        jitter.push_back(dt);
        total += dt;
    }

    std::println("          가변 간격     고정 간격");
    for (double fps : {30.0, 60.0, 144.0}) {
        Body a = run_variable(frames_at(fps));
        Fixed f = run_fixed(frames_at(fps));
        std::println("{:>3}fps    y={:.4f}    {}걸음 y={:.4f} 남은 비율 {:.2f}",
                     fps, a.y, f.steps, f.body.y, f.alpha);
    }
    Fixed f = run_fixed(jitter);
    std::println("들쭉날쭉  y={:.4f}    {}걸음 y={:.4f} 남은 비율 {:.2f}",
                 run_variable(jitter).y, f.steps, f.body.y, f.alpha);
}
```

```text
          가변 간격     고정 간격
 30fps    y=55.4100    180걸음 y=55.6550 남은 비율 0.00
 60fps    y=55.6550    180걸음 y=55.6550 남은 비율 0.00
144fps    y=55.7979    179걸음 y=56.1450 남은 비율 1.00
들쭉날쭉  y=55.5225    180걸음 y=55.6550 남은 비율 0.08
```

- **가변 간격**은 프레임 속도마다 공의 위치가 다릅니다(55.41, 55.66, 55.80). 정확한 값은 100 − ½·9.8·3² = 55.9m이고, 걸음이 클수록 오차가 큽니다. 같은 게임에서 30fps 컴퓨터와 144fps 컴퓨터의 점프 높이가 달라지는 셈입니다
- **고정 간격**은 언제나 1/60초씩만 걷습니다. 같은 걸음 수(180걸음)면 프레임 속도와 상관없이 **같은 y**가 나옵니다. 같은 입력에 같은 결과가 나오므로, 리플레이와 네트워크 동기화([「예측과 보정」](#/read/cpp-game-engine/net-prediction))도 이것을 바탕으로 합니다

## 누적기로 도는 루프

고정 간격 루프의 핵심은 `acc`(누적기)입니다.

1. 지난 프레임에서 흐른 시간을 `acc`에 더한다
2. `acc`가 한 걸음(1/60초) 이상이면 한 걸음 걷고 빼기를, 모자랄 때까지 되풀이한다
3. 남은 `acc`는 다음 프레임으로 넘긴다

30fps에서는 프레임마다 두 걸음씩, 144fps에서는 대부분 프레임에서 0걸음이고 가끔 한 걸음을 걷습니다. 144fps 줄이 **179걸음**인 것은 3초를 1/144초 단위로 더한 값이 부동소수점 반올림 때문에 180걸음 분량보다 아주 조금 모자라서, 마지막 한 걸음이 아직 남아 있기 때문입니다(남은 비율 1.00, 정확히는 0.99999…). 한 프레임 뒤에 그 걸음을 걷습니다. 그래서 고정 간격의 결정성은 "같은 시각"이 아니라 **같은 걸음 수**에 대해 성립합니다.

## 남은 시간으로 보간하기

144Hz 모니터에서 물리가 60Hz로만 움직이면, 같은 위치를 두세 프레임 연달아 그리게 되어 움직임이 끊겨 보입니다. 그래서 **남은 비율** α = acc / 한 걸음을 이용해, 직전 상태와 지금 상태 사이를 섞어 그립니다.

```cpp nocheck
State prev, curr;
while (running) {
    acc += std::min(frame_time(), 0.25);
    while (acc >= kStep) {
        prev = curr;
        curr = simulate(curr, kStep);
        acc -= kStep;
    }
    render(lerp(prev, curr, acc / kStep));   // 그림만 섞는다
}
```

그림은 실제보다 최대 한 걸음(1/60초 ≈ 16.7ms) 늦게 보이지만, 움직임이 부드러워집니다. 보간은 그림에만 쓰고, 게임 규칙의 판단은 언제나 `curr`로 합니다.

## 죽음의 소용돌이

한 걸음을 계산하는 데 실제로 1/60초보다 오래 걸리면 어떻게 될까요? 프레임이 길어지고, 그만큼 `acc`가 늘어 다음 프레임에 더 많은 걸음을 걸어야 하고, 그래서 프레임이 더 길어지는 악순환이 됩니다. 이것을 **죽음의 소용돌이**(spiral of death)라고 합니다. 위 예제의 `std::min(dt, 0.25)`가 막는 장치입니다. 한 프레임에 0.25초 넘게 흘렀으면(디버거에서 멈췄다 왔거나, 창을 끌고 있었거나) 넘는 시간은 버립니다. 게임이 잠깐 느려지는 대신 멈추지 않습니다. 한 프레임에 걷는 걸음 수에 상한(예: 5걸음)을 두는 방법도 씁니다.

<Note>
모든 것을 고정 간격으로 돌릴 필요는 없습니다. 물리와 게임 규칙은 고정 간격으로, 카메라의 부드러운 따라가기나 UI 애니메이션처럼 결정성이 필요 없는 것은 프레임 시간으로 돌리는 경우가 많습니다. 시간을 재는 방법 자체는 [「시간 재기」](#/read/cpp-game-engine/plat-time)에서 봅니다.
</Note>

## 정리

- 게임 루프는 입력, 갱신, 그리기를 되풀이하며, 프레임 시간을 그대로 갱신에 쓰면 프레임 속도에 따라 물리 결과가 달라진다
- 고정 간격 루프는 누적기에 시간을 모아 같은 크기의 걸음만 걸어서, 같은 걸음 수면 언제나 같은 결과를 낸다
- 남은 비율로 직전·지금 상태를 보간해 그리고, 한 프레임의 시간에 상한을 둬 죽음의 소용돌이를 막는다
