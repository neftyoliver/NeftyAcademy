물리 엔진이 매 프레임 가장 먼저 하는 일은 "무엇과 무엇이 닿았나"를 찾는 것입니다. 물체가 2천 개면 쌍은 약 2백만 개이고, 모양이 복잡할수록 쌍 하나를 정확히 검사하는 비용도 커집니다. 그래서 충돌 감지는 두 단계로 나뉩니다. **넓은 단계**는 대충이지만 빠르게 "닿았을지도 모르는 쌍"만 추리고, **좁은 단계**는 그 쌍만 정확한 모양으로 검사합니다.

## 좁은 단계와 넓은 단계

```cpp
#include <algorithm>
#include <cmath>
#include <cstdint>
#include <print>
#include <vector>

struct V { float x, y; };
V operator-(V a, V b) { return {a.x - b.x, a.y - b.y}; }
float dot(V a, V b) { return a.x * b.x + a.y * b.y; }

struct Circle { V c; float r; };
struct Contact { bool hit; V normal; float depth; };

// ---- 좁은 단계: 정확한 모양끼리 ----
Contact circle_circle(const Circle& a, const Circle& b) {
    V d = b.c - a.c;
    float dist = std::sqrt(dot(d, d)), rs = a.r + b.r;
    if (dist >= rs) return {false, {0, 0}, 0};
    if (dist == 0) return {true, {1, 0}, rs};     // 겹친 중심: 아무 방향
    return {true, {d.x / dist, d.y / dist}, rs - dist};
}

struct Box { V lo, hi; };
Contact box_circle(const Box& b, const Circle& c) {
    V p{std::clamp(c.c.x, b.lo.x, b.hi.x), std::clamp(c.c.y, b.lo.y, b.hi.y)};
    V d = c.c - p;                                 // 상자 위 가장 가까운 점에서
    float dist = std::sqrt(dot(d, d));
    if (dist >= c.r) return {false, {0, 0}, 0};
    if (dist == 0) return {true, {0, 1}, c.r};     // 중심이 상자 안(단순화)
    return {true, {d.x / dist, d.y / dist}, c.r - dist};
}

// ---- 넓은 단계: 훑고 자르기(sweep and prune) ----
std::uint32_t rng = 2463534242u;
float rnd() { rng ^= rng << 13; rng ^= rng >> 17; rng ^= rng << 5;
              return float(rng % 100000) / 100000.0f; }

int main() {
    auto p = [](const char* s, Contact k) {
        std::println("{}: {} 법선({:.2f},{:.2f}) 깊이 {:.2f}",
                     s, k.hit ? "충돌" : "없음", k.normal.x, k.normal.y, k.depth);
    };
    p("원-원", circle_circle({{0, 0}, 1}, {{1.5f, 0}, 1}));
    p("원-원", circle_circle({{0, 0}, 1}, {{3, 0}, 1}));
    p("상자-원", box_circle({{0, 0}, {4, 2}}, {{5, 3}, 1.5f}));

    const int N = 2000;
    std::vector<Circle> cs(N);
    for (auto& c : cs) c = {{rnd() * 1000, rnd() * 1000}, 3 + rnd() * 5};

    long tests = 0, hits = 0;
    for (int i = 0; i < N; ++i)
        for (int j = i + 1; j < N; ++j) {
            ++tests; hits += circle_circle(cs[i], cs[j]).hit;
        }
    std::println("모든 쌍: 검사 {} 충돌 {}", tests, hits);

    // x축 구간 [c.x-r, c.x+r]의 왼쪽 끝으로 정렬하고, 구간이 겹치는 것만 검사
    std::vector<int> order(N);
    for (int i = 0; i < N; ++i) order[i] = i;
    auto lo = [&](int i) { return cs[i].c.x - cs[i].r; };
    auto hi = [&](int i) { return cs[i].c.x + cs[i].r; };
    std::ranges::sort(order, {}, lo);
    long tests2 = 0, hits2 = 0;
    for (int a = 0; a < N; ++a)
        for (int b = a + 1; b < N && lo(order[b]) < hi(order[a]); ++b) {
            ++tests2; hits2 += circle_circle(cs[order[a]], cs[order[b]]).hit;
        }
    std::println("훑고 자르기: 검사 {} 충돌 {}", tests2, hits2);
}
```

원-원: 없음 법선(0.00,0.00) 깊이 0.00
상자-원: 충돌 법선(0.71,0.71) 깊이 0.09

## 좁은 단계: 닿았나, 어느 쪽으로, 얼마나

좁은 단계의 답은 예/아니오로 끝나지 않습니다. 다음 장 [「강체 시뮬레이션」](#/read/cpp-game-engine/phys-rigid)에서 두 물체를 떼어 놓으려면 **법선**(어느 방향으로 밀어야 하나)과 **깊이**(얼마나 파고들었나)가 필요합니다. 이 둘과 닿은 점을 합쳐 **접촉**이라고 부릅니다.

- **원과 원**: 중심 사이 거리가 반지름 합보다 작으면 닿았고, 법선은 중심을 잇는 방향, 깊이는 반지름 합에서 거리를 뺀 값입니다
- **상자와 원**: 원의 중심을 상자 안으로 잘라 넣은(`clamp`) 점이 상자 위에서 원에 가장 가까운 점입니다. 그 점과 원 중심 사이로 원과 원처럼 계산합니다. 예제에서 원은 상자 모서리 (4,2)에 대각선으로 닿아 법선이 45도가 되었습니다
- 중심이 정확히 겹치거나 원의 중심이 상자 안에 들어간 경우는 방향을 정할 수 없어서 따로 처리해야 합니다. 예제는 아무 방향이나 골랐지만, 실제로는 가장 얕게 빠져나갈 면을 찾습니다

볼록한 다각형끼리는 **분리축 정리**(SAT)를 씁니다. 두 볼록 도형을 어떤 축에 그림자처럼 투영했을 때 겹치지 않는 축이 하나라도 있으면 떨어져 있고, 검사할 축은 각 변의 법선이면 충분합니다. 모든 축에서 겹치면 가장 적게 겹친 축이 법선, 그 겹친 양이 깊이입니다. 더 일반적인 볼록 도형에는 GJK와 EPA 알고리즘을 씁니다.

## 넓은 단계: 훑고 자르기

모든 쌍을 검사하면 약 2백만 번이었습니다. **훑고 자르기**는 각 원을 x축에 투영한 구간의 왼쪽 끝으로 정렬한 다음, 구간이 겹치는 이웃만 검사합니다. 정렬된 순서에서 다음 원의 왼쪽 끝이 내 오른쪽 끝을 넘으면 그 뒤는 볼 필요가 없습니다. 검사가 4만 4천 번으로 줄었고, 찾은 충돌 784개는 같습니다.

넓은 단계는 **놓치면 안 되고, 넘치는 것은 괜찮습니다.** 후보에 섞인 가짜는 좁은 단계가 걸러 냅니다. 물체는 프레임마다 조금씩만 움직이므로 지난 프레임의 정렬 순서를 삽입 정렬로 고치면 거의 정렬된 상태라 빠릅니다. 이 밖에 [「공간 분할」](#/read/cpp-game-engine/scene-spatial)의 격자와 BVH도 넓은 단계로 쓰이며, 움직이는 물체가 많은 엔진은 조금 부풀린 상자로 BVH를 만들어 갱신 횟수를 줄입니다.

<Note>
빠른 총알처럼 한 프레임에 자기 크기보다 멀리 움직이는 물체는 프레임 시작과 끝 위치 어디에서도 벽과 겹치지 않아 그대로 뚫고 지나갈 수 있습니다(터널링). 이런 물체에는 이동 경로 전체를 쓸어 검사하는 **연속 충돌 감지**(CCD)를 따로 켭니다. 비용이 크므로 보통 빠른 물체에만 씁니다.
</Note>

## 정리

- 충돌 감지는 빠르고 넉넉한 넓은 단계로 후보 쌍을 추리고, 정확한 좁은 단계에서 그 쌍만 검사한다
- 좁은 단계는 법선과 깊이를 담은 접촉을 돌려주며, 볼록 다각형에는 분리축 정리나 GJK·EPA를 쓴다
- 넓은 단계는 놓치지만 않으면 되고, 훑고 자르기는 지난 프레임 순서를 고쳐 쓰며, 빠른 물체는 CCD로 터널링을 막는다
