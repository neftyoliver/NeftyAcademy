게임은 한 프레임 동안만 쓰고 버리는 메모리를 아주 많이 만듭니다. 이번 프레임에 그릴 물체 목록, 충돌 후보 쌍, 화면에 찍을 글자, 정렬용 임시 배열 같은 것입니다. 이런 것을 하나하나 `new`와 `delete`로 다루면 느리고 조각이 납니다. 엔진은 대신 **프레임 할당자**를 씁니다. 「C++ 고급」의 [「아레나와 풀」](#/read/cpp-advanced/mm-arena)에서 본 아레나를 게임 루프의 리듬에 맞춘 것입니다.

## 앞에서부터 잘라 주기

큰 덩어리 하나를 미리 잡아 두고, 달라는 만큼 앞에서부터 잘라 줍니다. 하나씩 돌려받지 않고, 프레임이 끝나면 **위치를 0으로 되돌려** 한 번에 비웁니다.

```cpp
#include <cstddef>
#include <cstdint>
#include <memory>
#include <new>
#include <print>

// 앞에서부터 잘라 주기만 하고, 하나씩 돌려받지 않는다
class LinearAllocator {
public:
    explicit LinearAllocator(std::size_t bytes)
        : buf_(std::make_unique<std::byte[]>(bytes)), cap_(bytes) {}

    void* alloc(std::size_t size, std::size_t align = alignof(std::max_align_t))
    {
        auto base = reinterpret_cast<std::uintptr_t>(buf_.get());
        std::uintptr_t p = (base + top_ + align - 1) & ~(align - 1);  // 맞춤
        std::size_t new_top = p - base + size;
        if (new_top > cap_)
            return nullptr;                    // 넘치면 실패를 알린다
        top_ = new_top;
        peak_ = top_ > peak_ ? top_ : peak_;
        return reinterpret_cast<void*>(p);
    }
    template <typename T, typename... Args>
    T* make(Args&&... args)                    // 소멸자는 부르지 않는다
    {
        void* p = alloc(sizeof(T), alignof(T));
        return p ? ::new (p) T(std::forward<Args>(args)...) : nullptr;
    }

    std::size_t marker() const { return top_; }     // 스택처럼 쓰기
    void rewind(std::size_t m) { top_ = m; }
    void reset() { top_ = 0; }                       // 프레임 끝에 한 번에
    std::size_t used() const { return top_; }
    std::ptrdiff_t offset(const void* p) const
    {
        return static_cast<const std::byte*>(p) - buf_.get();
    }
    std::size_t peak() const { return peak_; }

private:
    std::unique_ptr<std::byte[]> buf_;
    std::size_t cap_, top_ = 0, peak_ = 0;
};

struct alignas(16) Vec4 { float x, y, z, w; };

int main()
{
    LinearAllocator frame(1024);
    for (int f = 1; f <= 2; ++f) {
        char* text = static_cast<char*>(frame.alloc(10, 1));
        Vec4* v = frame.make<Vec4>(1.f, 2.f, 3.f, 4.f);
        std::println("프레임 {}: 글자는 {}번째, Vec4는 {}번째 바이트(16의 배수), "
                     "쓴 양 {}", f, frame.offset(text), frame.offset(v),
                     frame.used());

        auto m = frame.marker();               // 잠깐 쓰는 작업 공간
        frame.alloc(500);
        auto during = frame.used();
        frame.rewind(m);
        std::println("  작업 공간을 쓰는 동안 {}, 되감은 뒤 {}", during,
                     frame.used());
        frame.reset();
    }
    std::println("가장 많이 쓴 양 {}바이트", frame.peak());
    std::println("1KB를 넘게 달라면: {}",
                 frame.alloc(2000) == nullptr ? "nullptr" : "받음");
}
```

```text
프레임 1: 글자는 0번째, Vec4는 16번째 바이트(16의 배수), 쓴 양 32
  작업 공간을 쓰는 동안 532, 되감은 뒤 32
프레임 2: 글자는 0번째, Vec4는 16번째 바이트(16의 배수), 쓴 양 32
  작업 공간을 쓰는 동안 532, 되감은 뒤 32
가장 많이 쓴 양 532바이트
1KB를 넘게 달라면: nullptr
```

- **맞춤**: 10바이트 글자 다음의 `Vec4`는 16바이트 맞춤이 필요해서, 10번째가 아니라 16번째 바이트에 놓였습니다. `(주소 + 맞춤 − 1) & ~(맞춤 − 1)`은 맞춤이 2의 거듭제곱일 때 주소를 그 배수로 올리는 흔한 셈입니다. 맞춤을 무시하면 SIMD 명령이 쓰러지거나 느려집니다([「SIMD로 빠르게」](#/read/cpp-game-engine/math-simd))
- **스택처럼 되감기**: `marker()`로 지금 위치를 기억해 두고, 잠깐 쓰는 작업 공간을 쓴 뒤 `rewind()`로 되돌립니다. 함수 안에서 임시 배열이 필요할 때 이렇게 쓰는 것을 **스택 할당자**라고 부릅니다. 되감기는 반드시 거꾸로(나중에 잡은 것부터) 해야 합니다
- **넘침**: 정해 둔 크기를 넘으면 `nullptr`를 돌려줍니다. 실제 엔진은 여기서 큰 소리로 알리고(어서트), "가장 많이 쓴 양"을 기록해 두었다가 크기를 정하는 데 씁니다
- **소멸자는 없다**: `reset()`은 메모리를 되돌릴 뿐 객체의 소멸자를 부르지 않습니다. 그래서 프레임 할당자에는 `std::string`처럼 자기 메모리를 따로 가진 타입을 넣지 않고, 소멸자가 할 일이 없는 단순한 타입만 넣습니다

## 얼마나 빠른가

32바이트짜리 입자 1만 개를 프레임마다 만들고 버리기를 200프레임 동안 해 봤습니다.

```cpp norun
#include <chrono>
#include <cstddef>
#include <memory>
#include <new>
#include <print>
#include <vector>

struct Particle { float x, y, vx, vy, life, size, r, g; };   // 32바이트

int main()
{
    constexpr int kFrames = 200, kPerFrame = 10'000;
    using clk = std::chrono::steady_clock;
    volatile float sink = 0;

    // 1) 하나씩 new/delete
    auto t0 = clk::now();
    std::vector<Particle*> ptrs(kPerFrame);
    for (int f = 0; f < kFrames; ++f) {
        for (auto& p : ptrs) p = new Particle{1, 2, 3, 4, 5, 6, 7, 8};
        for (auto* p : ptrs) sink = sink + p->x;
        for (auto* p : ptrs) delete p;
    }
    auto t1 = clk::now();

    // 2) 프레임 할당자: 앞에서부터 잘라 주고 프레임 끝에 한 번에 비운다
    auto buf = std::make_unique<std::byte[]>(kPerFrame * sizeof(Particle));
    for (int f = 0; f < kFrames; ++f) {
        std::size_t top = 0;
        for (auto& p : ptrs) {
            p = ::new (buf.get() + top) Particle{1, 2, 3, 4, 5, 6, 7, 8};
            top += sizeof(Particle);
        }
        for (auto* p : ptrs) sink = sink + p->x;
    }
    auto t2 = clk::now();

    auto ns = [](auto d) {
        return std::chrono::duration<double, std::nano>(d).count() /
               (kFrames * kPerFrame);
    };
    std::println("new/delete  {:.1f}ns/개", ns(t1 - t0));
    std::println("프레임 할당 {:.1f}ns/개", ns(t2 - t1));
}
```

```text nocheck
new/delete  15.5ns/개
프레임 할당 2.8ns/개
```

GCC 14와 Clang 20(libc++) 양쪽에서 세 번씩 돌려 거의 같은 값이었습니다. 리눅스의 glibc `malloc`은 작은 크기에 대해 매우 빠른 편인데도 다섯 배 넘게 차이가 납니다. 프레임 할당은 "덧셈 한 번과 비교 한 번"이 전부이고, 만든 객체들이 메모리에 **나란히 붙어 있어서** 이어서 읽을 때 캐시도 잘 맞습니다. 해제는 프레임 끝의 `top = 0` 한 줄이라 개수와 상관없이 공짜입니다.

## 두 겹 버퍼

렌더러가 별도 스레드에서 **지난 프레임**의 그리기 명령을 처리하는 동안, 게임 스레드는 이번 프레임의 명령을 만듭니다. 이때 프레임 할당자를 하나만 쓰면 렌더러가 읽는 도중에 비워져 버립니다. 그래서 할당자를 둘 두고 프레임마다 번갈아 씁니다. 짝수 프레임은 A에, 홀수 프레임은 B에 쓰고, 다음 프레임을 시작할 때는 **두 프레임 전에 쓴 것**만 비웁니다. 그러면 할당된 메모리가 정확히 두 프레임 동안 살아 있습니다. 작업 큐를 쓰는 엔진([「작업 큐와 워커 스레드」](#/read/cpp-game-engine/job-queue))에서는 스레드마다 프레임 할당자를 따로 두어 잠금 없이 씁니다.

<Note kind="warn">
프레임 할당자에서 받은 포인터를 다음 프레임까지 들고 있으면, 그 자리에는 이미 다른 데이터가 들어와 있습니다. 넘침이나 해제 후 사용처럼 프로그램이 바로 쓰러지지 않아 찾기 어려운 버그가 됩니다. 디버그 빌드에서는 `reset()` 때 버퍼를 `0xCD` 같은 눈에 띄는 값으로 채워 두거나, 프레임 번호를 함께 기록해 늦게 쓰는 것을 잡습니다. 위 예제는 ASan과 UBSan을 켜고 돌렸지만, 이 버퍼는 할당자 혼자 쥐고 있는 하나의 큰 블록이라 ASan도 그 안의 늦은 사용은 모릅니다.
</Note>

## 정리

- 프레임 할당자는 큰 덩어리를 앞에서부터 잘라 주고 프레임 끝에 위치를 0으로 되돌려 한 번에 비우며, 하나씩 해제하지 않는다
- 잘라 줄 때 맞춤을 지키고, 표시와 되감기로 스택 할당자처럼 쓰며, 소멸자가 필요 없는 단순한 타입만 넣는다
- 하나씩 `new`/`delete`보다 몇 배 빠르고 데이터가 붙어 있어 캐시에도 좋으며, 다른 스레드가 읽는 데이터는 두 겹으로 번갈아 쓴다
