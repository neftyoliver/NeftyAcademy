조명까지 계산한 그림은 아직 화면에 바로 내보낼 수 없습니다. 햇빛 아래의 흰 벽은 그늘보다 수천 배 밝은데, 화면은 0에서 1(8비트로 0~255)까지밖에 표현하지 못하기 때문입니다. 렌더러의 마지막 단계인 **후처리**는 이 넓은 밝기 범위(HDR)를 화면에 맞추고, 카메라처럼 보이게 하는 효과를 더합니다.

## 톤 매핑: 넓은 범위를 0~1로

조명 결과는 16비트 부동소수점 텍스처에 담아 1보다 큰 값도 그대로 둡니다. 그다음 **톤 매핑 곡선**으로 0~1에 접어 넣습니다.

```cpp
#include <algorithm>
#include <cmath>
#include <print>
#include <vector>

float reinhard(float x) { return x / (1 + x); }
float aces(float x)                      // Narkowicz의 ACES 근사 곡선
{
    x *= 0.6f;
    float y = (x * (2.51f * x + 0.03f)) / (x * (2.43f * x + 0.59f) + 0.14f);
    return std::clamp(y, 0.f, 1.f);
}
float srgb(float lin)                    // 선형 값 -> 화면에 보낼 sRGB 값
{
    if (lin <= 0.0031308f) return 12.92f * lin;
    return 1.055f * std::pow(lin, 1 / 2.4f) - 0.055f;
}

int main()
{
    std::println("밝기    자르기  Reinhard  ACES 근사");
    for (float x : {0.1f, 0.5f, 1.f, 2.f, 4.f, 16.f})
        std::println("{:5.1f}  {:7.3f}  {:8.3f}  {:9.3f}", x, std::min(x, 1.f),
                     reinhard(x), aces(x));

    // 자동 노출: 화면 밝기의 "로그 평균"으로 장면이 얼마나 밝은지 본다
    std::vector<float> cave = {0.02f, 0.03f, 0.05f, 0.04f, 3.0f};   // 동굴과 횃불
    std::vector<float> beach = {8.f, 12.f, 10.f, 9.f, 40.f};        // 한낮 바닷가
    for (auto [name, img] : {std::pair{"동굴", cave}, std::pair{"바닷가", beach}}) {
        double s = 0;
        for (float v : img) s += std::log(1e-4 + v);
        float avg = float(std::exp(s / img.size()));
        float exposure = 0.18f / avg;    // 평균을 중간 회색(18%)으로 맞춘다
        std::println("{:<4} 로그 평균 밝기 {:.3f} -> 노출 x{:.3f}", name, avg,
                     exposure);
    }

    float g = srgb(0.18f);
    std::println("선형 0.18(중간 회색) -> sRGB {:.3f}, 8비트 {}", g,
                 std::lround(g * 255));
}
```

```text
  0.5    0.500     0.333      0.438

  4.0    1.000     0.800      0.934

```

- **자르기**는 1이 넘는 것을 모두 1로 만들어서, 밝기 2와 16이 똑같은 흰색이 됩니다. 밝은 부분의 결이 사라집니다
- **Reinhard**(x / (1 + x))는 아무리 밝아도 1에 다가갈 뿐 넘지 않아 결이 남지만, 밝기 1이 0.5가 되는 등 전체가 어둡고 밋밋해집니다
- **ACES 근사**(필름처럼 S자로 휜 곡선)는 어두운 쪽을 조금 더 어둡게, 중간을 또렷하게, 밝은 쪽을 부드럽게 눕힙니다. 영화 산업의 색 표준에서 온 곡선을 짧은 식으로 근사한 것이 게임에서 많이 쓰이고, 엔진마다 자기 곡선을 따로 다듬기도 합니다

## 자동 노출

동굴과 한낮 바닷가는 밝기가 수백 배 다릅니다. 사람 눈처럼 장면이 어두우면 노출을 올리고 밝으면 낮춰야 합니다. 화면 밝기의 **로그 평균**을 구하고, 그것이 사진의 기준인 중간 회색(18%)이 되도록 노출을 정했습니다. 동굴은 2.2배 밝게, 바닷가는 0.014배로 어둡게 맞춰집니다. 그냥 평균을 내면 동굴의 횃불 하나(3.0)가 평균을 크게 끌어올리지만, 로그 평균은 몇 개의 아주 밝은 점에 덜 휘둘립니다. 실제로는 이 값을 몇 초에 걸쳐 천천히 따라가게 해서, 동굴을 나설 때 눈이 부셨다가 적응하는 느낌을 냅니다. 화면 전체를 줄여 가며 평균을 내는 일은 GPU의 계산 셰이더에서 합니다.

## 블룸과 그 밖의 효과

**블룸**은 아주 밝은 부분이 주변으로 번져 보이는 효과입니다. 밝기가 어느 값을 넘는 부분만 뽑아, 해상도를 반씩 줄여 가며 흐리게 한 그림들을 만들고, 다시 키우며 원래 그림에 더합니다. 줄인 그림에서 흐리게 하면 넓게 번지는 것을 싸게 얻을 수 있습니다. 이 밖에 피사계 심도, 움직임 흐림, 색 보정(LUT), 비네팅 같은 효과가 후처리에 들어갑니다.

## 순서와 마지막 변환

| 순서 | 공간 |
| --- | --- |
| 조명 결과 | 선형 HDR |
| 블룸, 피사계 심도, 움직임 흐림 | 선형 HDR (밝기의 물리적 비율이 유지되는 곳) |
| 자동 노출 → 톤 매핑 | HDR → 0~1 |
| 색 보정, 안티에일리어싱 일부, UI 합성 | 0~1 |
| sRGB 변환 | 화면으로 |

밝기를 더하고 섞는 효과는 **선형 HDR** 공간에서 해야 결과가 자연스럽습니다. 마지막에 화면의 감마에 맞춰 **sRGB로 바꾸는데**, 선형 중간 회색 0.18이 sRGB로는 0.461, 8비트로 118이 됩니다. 이 변환을 빠뜨리거나 두 번 하면 그림 전체가 너무 어둡거나 밝게 뜹니다. 많은 엔진은 sRGB 형식의 화면 버퍼를 써서 하드웨어가 이 변환을 하게 합니다. [「머티리얼과 셰이더 관리」](#/read/cpp-game-engine/rend-materials)와 [「가져오기와 굽기」](#/read/cpp-game-engine/res-import)에서 텍스처의 sRGB·선형 구분이 중요했던 것도 이 계산을 맞추기 위해서입니다.

<Note>
HDR 모니터에 출력할 때는 톤 매핑의 목표가 0~1이 아니라 모니터가 낼 수 있는 밝기(수백~수천 니트)가 되고, sRGB 대신 PQ 같은 다른 전송 함수와 넓은 색 공간을 씁니다. 같은 장면을 일반 모니터와 HDR 모니터에 모두 내보내려면 톤 매핑을 두 갈래로 둡니다.
</Note>

## 정리

- 조명 결과는 HDR로 담고, 톤 매핑 곡선(Reinhard, ACES 근사 등)으로 밝은 쪽의 결을 살리며 0~1에 접어 넣는다
- 자동 노출은 화면 밝기의 로그 평균을 중간 회색에 맞추고 천천히 따라가며, 블룸은 밝은 부분을 줄인 그림에서 흐려 더한다
- 섞는 효과는 선형 HDR에서, 마지막에 한 번만 sRGB로 바꾸며, 그 변환을 빠뜨리거나 두 번 하지 않게 한다
