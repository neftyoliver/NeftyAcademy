플레이어 캐릭터를 [「강체 시뮬레이션」](#/read/cpp-game-engine/phys-rigid)의 강체로 만들면 사실적이지만 조작감이 나빠집니다. 비탈에서 미끄러지고, 상자에 부딪혀 빙글 돌고, 멈추라고 해도 관성으로 밀려갑니다. 그래서 대부분의 게임은 캐릭터를 물리에 맡기지 않고 코드가 위치를 직접 정하는 **키네마틱 캐릭터 컨트롤러**를 씁니다. 충돌은 검사하지만, 응답은 게임이 원하는 대로 정합니다.

## 타일 위의 캐릭터

한 칸짜리 턱, 두 칸짜리 벽이 있는 방에서 0.8×0.8 상자 캐릭터를 움직여 봅니다.

```cpp
#include <cmath>
#include <print>
#include <string>
#include <vector>

// 타일 지도: '#' 벽, '.' 빈칸. 한 칸 = 1 단위, y는 아래로 갈수록 커진다
std::vector<std::string> map = {
    "############",
    "#..........#",
    "#..........#",
    "#......#...#",
    "#...#..#...#",
    "############",
};
bool solid(int x, int y) { return map[y][x] == '#'; }

struct Box { double x, y, w = 0.8, h = 0.8; };   // 왼쪽 위 모서리
bool hits(const Box& b) {
    int x0 = int(std::floor(b.x)), x1 = int(std::floor(b.x + b.w - 1e-9));
    int y0 = int(std::floor(b.y)), y1 = int(std::floor(b.y + b.h - 1e-9));
    for (int ty = y0; ty <= y1; ++ty)
        for (int tx = x0; tx <= x1; ++tx)
            if (solid(tx, ty)) return true;
    return false;
}

// 축마다 따로 움직이고, 막히면 그 축만 멈춘다 -> 벽을 따라 미끄러진다
// 반환: 그 축에서 막혔는지
bool move_axis(Box& b, double d, bool horizontal) {
    double& c = horizontal ? b.x : b.y;
    const double step = 0.05;                     // 작은 걸음으로 나눠 뚫기 방지
    int n = int(std::ceil(std::fabs(d) / step));
    for (int i = 0; i < n; ++i) {
        double s = d / n;
        c += s;
        if (hits(b)) { c -= s; return true; }
    }
    return false;
}

struct Character {
    Box box{1.1, 3.2};
    double vy = 0, since_ground = 1;              // 땅을 떠난 뒤 흐른 시간
    bool grounded = false;

    void update(double dt, double input_x, bool jump) {
        const double speed = 4, gravity = 30, jump_v = -12, coyote = 0.1;
        // 1) 가로 이동, 막히면 한 칸 이하의 턱은 올라서 본다
        Box before = box;
        if (move_axis(box, input_x * speed * dt, true) && grounded) {
            box = before;
            box.y -= 1.0;                          // 턱 높이만큼 들어 올려
            if (!hits(box) && !move_axis(box, input_x * speed * dt, true))
                std::println("  턱 올라서기 x={:.2f}", box.x);
            else box = before, move_axis(box, input_x * speed * dt, true);
        }
        // 2) 세로: 중력, 점프(땅을 떠난 직후 잠깐도 허용)
        if (jump && since_ground < coyote) { vy = jump_v; since_ground = 1; }
        vy += gravity * dt;
        bool blocked = move_axis(box, vy * dt, false);
        grounded = blocked && vy > 0;
        if (blocked) vy = 0;
        since_ground = grounded ? 0 : since_ground + dt;
    }
};

int main() {
    Character c;
    const double dt = 1.0 / 60;
    for (int f = 0; f < 30; ++f) c.update(dt, 0, false);  // 착지
    std::println("착지: y={:.2f} 땅={}", c.box.y, c.grounded);

    for (int f = 0; f < 60; ++f) c.update(dt, 1, false);  // 오른쪽으로 1초
    std::println("1초 오른쪽: x={:.2f} y={:.2f}", c.box.x, c.box.y);

    for (int f = 0; f < 30; ++f) c.update(dt, 1, false);
    std::println("0.5초 더: x={:.2f} (두 칸 벽에 막힘)", c.box.x);

    c.update(dt, 1, true);
    double top = c.box.y;
    for (int f = 0; f < 70; ++f) {
        c.update(dt, 1, false);
        top = std::fmin(top, c.box.y);
    }
    std::println("점프: x={:.2f} y={:.2f} 가장 높이 y={:.2f}",
                 c.box.x, c.box.y, top);

    // 턱 끝에서 걸어 나간 뒤 k 프레임 늦게 점프를 누르면?
    for (int k : {3, 9}) {
        Character d;
        d.box = {4.1, 3.2};
        d.update(dt, 0, false);                   // 턱 위에 선다
        while (d.grounded) d.update(dt, 1, false);
        for (int f = 1; f < k; ++f) d.update(dt, 0, false);
        d.update(dt, 0, true);
        std::println("땅을 떠나고 {}프레임 뒤 점프: {}", k,
                     d.vy < 0 ? "됨" : "안 됨");
    }
}
```

```text
착지: y=4.20 땅=true
  턱 올라서기 x=3.23
1초 오른쪽: x=5.10 y=3.22
0.5초 더: x=6.20 (두 칸 벽에 막힘)
점프: x=9.93 y=4.20 가장 높이 y=1.90
땅을 떠나고 3프레임 뒤 점프: 됨
땅을 떠나고 9프레임 뒤 점프: 안 됨
```

## 축마다 따로, 막히면 미끄러지기

`move_axis`는 가로와 세로를 **따로** 움직이고, 막힌 축만 멈춥니다. 오른쪽으로 걷다가 벽에 닿으면 가로 이동은 멈추지만 세로(중력)는 계속되므로, 벽에 붙은 채로 미끄러져 내려옵니다. 두 축을 한꺼번에 움직였다가 막히면 둘 다 멈추게 되어, 벽에 대각선으로 기대면 공중에 걸리는 버그가 생깁니다.

움직임을 0.05 단위의 작은 걸음으로 나눈 것은 [「충돌 감지의 두 단계」](#/read/cpp-game-engine/phys-collision)의 터널링을 막기 위해서입니다. 실제 3차원 컨트롤러는 캡슐 모양을 이동 방향으로 쓸어 보내(sweep) 처음 닿는 지점까지 간 다음, 남은 이동량을 닿은 면에 투영해서 다시 쓸어 보내기를 몇 번 되풀이합니다. 이것이 흔히 말하는 **move and slide**이고, 비탈과 비스듬한 벽에서도 자연스럽게 미끄러집니다.

## 턱과 땅

- **턱 올라서기**: 땅 위에서 가로로 막히면 한 칸만큼 들어 올린 위치에서 다시 움직여 보고, 거기서 막히지 않으면 올라섭니다. x=3.23에서 한 칸 턱을 올랐고, 두 칸 벽 앞(x=6.20)에서는 들어 올려도 막혀서 멈췄습니다. 계단마다 점프를 누르게 하지 않으려는 장치입니다
- **땅 판정**: 아래로 움직이다 막히면 땅에 선 것으로 봅니다. 출력의 두 번째 줄 y=3.22는 턱 끝에서 걸어 나가 막 떨어지기 시작한 순간입니다. 3차원에서는 발 밑으로 짧게 쓸어 보낸 결과의 법선 각도로 "서 있을 수 있는 비탈인가"도 함께 판정합니다
- **점프**: 두 칸 벽은 점프로 넘었습니다. 가장 높을 때 상자 바닥(1.90 + 0.8 = 2.70)이 벽 꼭대기 y=3보다 위였습니다

## 코요테 시간

마지막 두 줄은 턱 끝에서 걸어 나간 뒤 점프를 늦게 누른 경우입니다. 3프레임(0.05초) 늦으면 되고, 9프레임(0.15초) 늦으면 안 됐습니다. 땅을 떠난 뒤 0.1초 동안은 아직 땅 위인 것처럼 점프를 받아 주는 **코요테 시간**입니다. 사람은 끝을 정확히 맞춰 누를 수 없어서, 이것이 없으면 "분명 눌렀는데 떨어졌다"는 느낌을 받습니다. 착지 직전에 누른 점프를 잠깐 기억했다가 착지하는 순간 실행하는 **점프 버퍼**도 같은 목적의 장치입니다.

<Note>
이런 장치들은 물리적으로는 "틀린" 동작입니다. 공중에서 점프하고, 순간적으로 최고 속도에 도달하고, 방향을 즉시 바꿉니다. 캐릭터 컨트롤러의 목표는 정확한 물리가 아니라 플레이어가 의도한 대로 움직이는 것이고, 그래서 이 부분은 엔진보다 게임 쪽 코드에서 많이 조정합니다. 엔진은 쓸어 보내기와 땅 판정 같은 질문에 정확히 답하는 도구를 제공합니다.
</Note>

## 정리

- 캐릭터는 강체 대신 키네마틱 컨트롤러로 움직여, 충돌은 검사하되 응답은 게임이 원하는 대로 정한다
- 축마다 따로 움직이거나 남은 이동량을 닿은 면에 투영해 벽을 따라 미끄러지고, 작은 턱은 들어 올려 넘는다
- 코요테 시간과 점프 버퍼처럼 물리적으로 틀린 장치가 조작감을 만든다
