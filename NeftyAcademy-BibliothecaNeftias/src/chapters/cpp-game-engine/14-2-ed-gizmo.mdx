편집기에서 화면의 물체를 클릭하면 선택되고, 물체 위에 뜬 빨강·초록·파랑 화살표(**기즈모**)를 끌면 그 축으로 움직입니다. 둘 다 같은 질문에서 시작합니다. 화면의 이 화소는 3차원 세계에서 어디를 가리키는가? 답은 점이 아니라 카메라에서 뻗어 나가는 **광선**입니다.

## 화소에서 광선으로

카메라는 (0,0,-10)에서 +z를 보고, 세로 시야 60도, 800×600 화면입니다. 물체는 각자의 경계 구로 대신합니다.

```cpp
#include <cmath>
#include <numbers>
#include <optional>
#include <print>
#include <string>
#include <vector>

struct V { double x, y, z; };
V operator+(V a, V b) { return {a.x + b.x, a.y + b.y, a.z + b.z}; }
V operator-(V a, V b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; }
V operator*(double s, V a) { return {s * a.x, s * a.y, s * a.z}; }
double dot(V a, V b) { return a.x * b.x + a.y * b.y + a.z * b.z; }
V norm(V a) { return (1 / std::sqrt(dot(a, a))) * a; }

// 카메라: (0,0,-10)에서 +z를 본다, 세로 시야 60도, 800x600 화면
const V eye{0, 0, -10};
const double W = 800, H = 600, fov = 60 * std::numbers::pi / 180;

V mouse_ray(double px, double py) {           // 화소 -> 세계의 방향
    double ndc_x = 2 * px / W - 1, ndc_y = 1 - 2 * py / H;  // -1~1, y는 위가 +
    double t = std::tan(fov / 2);
    return norm({ndc_x * t * W / H, ndc_y * t, 1});
}

struct Sphere { std::string name; V c; double r; };
std::optional<double> hit(V o, V d, const Sphere& s) {   // 광선-구 교차
    V oc = o - s.c;
    double b = dot(oc, d), c = dot(oc, oc) - s.r * s.r, disc = b * b - c;
    if (disc < 0) return {};
    double t = -b - std::sqrt(disc);
    return t > 0 ? std::optional{t} : std::nullopt;
}

// 마우스 광선과 가장 가까운, 축 직선 위의 점의 매개변수
double closest_on_axis(V p, V axis, V o, V d) {
    V w = p - o;
    double a = dot(axis, axis), b = dot(axis, d), c = dot(d, d);
    double e = dot(axis, w), f = dot(d, w);
    return (b * f - c * e) / (a * c - b * b);
}

int main() {
    std::vector<Sphere> scene = {
        {"앞의 상자", {0, 0, 0}, 1},
        {"뒤의 탑", {0, 0, 5}, 2},
        {"오른쪽 나무", {3, 1, 0}, 1},
    };
    for (auto [px, py] : {std::pair{400.0, 300.0}, {549.0, 248.0}, {400.0, 240.0},
                          {100.0, 100.0}}) {
        V d = mouse_ray(px, py);
        const Sphere* best = nullptr;
        double best_t = 1e30;
        for (auto& s : scene)
            if (auto t = hit(eye, d, s); t && *t < best_t) {
                best_t = *t;
                best = &s;
            }
        std::string what = "없음";
        if (best) what = std::format("{} (거리 {:.2f})", best->name, best_t);
        std::println("화소 ({:3.0f},{:3.0f}) -> {}", px, py, what);
    }

    // 고른 상자의 x축 화살표를 화소 400에서 520으로 끈다
    V obj = scene[0].c, axis{1, 0, 0};
    double s0 = closest_on_axis(obj, axis, eye, mouse_ray(400, 300));
    double s1 = closest_on_axis(obj, axis, eye, mouse_ray(520, 300));
    V moved = obj + (s1 - s0) * axis;
    std::println("x축 끌기 120화소: 상자 x {:.2f} -> {:.2f}", obj.x, moved.x);
    // 같은 120화소라도 멀리 있는 물체는 더 많이 움직인다
    obj = scene[1].c;
    s0 = closest_on_axis(obj, axis, eye, mouse_ray(400, 300));
    s1 = closest_on_axis(obj, axis, eye, mouse_ray(520, 300));
    std::println("x축 끌기 120화소: 탑 x {:.2f} -> {:.2f}", obj.x, obj.x + s1 - s0);
}
```

```text
화소 (400,300) -> 앞의 상자 (거리 9.00)
화소 (549,248) -> 오른쪽 나무 (거리 9.50)
화소 (400,240) -> 뒤의 탑 (거리 13.88)
화소 (100,100) -> 없음
x축 끌기 120화소: 상자 x 0.00 -> 2.31
x축 끌기 120화소: 탑 x 0.00 -> 3.46
```

## 고르기

`mouse_ray`는 투영의 반대 방향으로 갑니다. 화소를 -1~1의 정규화 좌표로 바꾸고(화면 y는 아래로 커지므로 뒤집습니다), 시야각의 탄젠트와 화면 비율을 곱하면 카메라 앞 거리 1의 평면 위 점이 나옵니다. 카메라에서 그 점으로 가는 방향이 광선입니다. 카메라가 돌아가 있다면 이 방향에 카메라 회전을 곱하면 됩니다. 일반적으로는 [「좌표계의 약속」](#/read/cpp-game-engine/math-conventions)의 투영 행렬과 뷰 행렬을 곱한 것의 역행렬로 화소를 거꾸로 보냅니다.

광선이 여러 물체를 지나면 **가장 가까운** 것을 고릅니다. 화면 한가운데(400,300)는 상자와 그 뒤의 탑을 모두 지나지만 거리 9인 상자가 골라졌고, 조금 위(400,240)를 누르니 상자 위를 지나 탑에 맞았습니다. 물체가 많으면 이 검사에 [「공간 분할」](#/read/cpp-game-engine/scene-spatial)의 BVH를 쓰고, 구로 후보를 고른 뒤 정확한 삼각형과 다시 교차시킵니다.

## 축 화살표 끌기

x축 화살표를 잡고 마우스를 오른쪽으로 120화소 끌면 물체는 x축 위로만 움직여야 합니다. 마우스가 가리키는 광선은 대개 x축과 만나지 않으므로, `closest_on_axis`로 **광선과 가장 가까운 축 위의 점**을 찾습니다. 두 직선 사이의 최단 거리 공식입니다. 끌기 시작할 때와 지금 그 점의 차이만큼 물체를 옮기면, 마우스 아래 화살표 끝이 계속 마우스를 따라오는 느낌이 납니다.

같은 120화소를 끌어도 앞의 상자(거리 10)는 2.31, 뒤의 탑(거리 15)은 3.46 움직였습니다. 먼 물체일수록 화소 하나가 세계에서 더 넓은 거리이기 때문입니다. 화소 수에 고정 배율을 곱하는 방식은 이것을 반영하지 못해 먼 물체를 끌 때 답답해집니다. 축이 화면을 향해 거의 똑바로 서 있으면 분모 `a·c - b²`가 0에 가까워져 물체가 튀므로, 그런 축은 기즈모에서 흐리게 표시하고 잡지 못하게 합니다.

<Note>
삼각형 수천만 개가 있는 장면에서 정확한 고르기를 하려면, 렌더러가 물체 id를 색 대신 써 넣은 **id 버퍼**를 따로 그려 두고 마우스 아래 화소의 값을 읽는 방법이 간단하고 정확합니다. GPU에서 값을 읽어 오는 데 한두 프레임 지연이 있지만 클릭에는 충분합니다. 기즈모 자체는 물체보다 늘 앞에 그려야 하므로 깊이 검사를 끄고 마지막에 그립니다.
</Note>

## 정리

- 화소는 투영을 거꾸로 적용해 카메라에서 뻗는 광선으로 바꾸고, 광선이 맞는 가장 가까운 물체를 고른다
- 축 끌기는 마우스 광선과 가장 가까운 축 위의 점의 변화량만큼 옮기며, 그래서 먼 물체는 같은 화소에도 더 많이 움직인다
- 화면을 향한 축은 잡지 못하게 하고, 큰 장면의 고르기에는 BVH나 id 버퍼를 쓴다
