출시한 게임은 개발자가 본 적 없는 수많은 기계에서 돕니다. 그중 어딘가에서 게임이 죽으면, 플레이어는 "튕겼어요"라고만 말합니다. 디버거도 없고 다시 재현할 방법도 없습니다. 그래서 게임은 죽는 순간 스스로 **충돌 보고서**를 남겨, 다음 실행 때나 별도 프로세스가 그것을 개발사 서버로 올리게 합니다.

## 죽는 순간 남기기

3번 레벨 데이터가 깨져 검사가 실패하는 상황을 만들었습니다. 예제가 끝까지 돌도록 자식 프로세스에서 죽고, 부모가 그것을 지켜봅니다.

```cpp
#include <csignal>
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <fcntl.h>
#include <execinfo.h>
#include <sys/wait.h>
#include <unistd.h>

// ---- 발자국: 최근에 한 일을 고리 버퍼에 남겨 둔다(할당 없이) ----
char crumbs[8][48];
int crumb_count = 0;
void crumb(const char* s) {
    std::strncpy(crumbs[crumb_count % 8], s, 47);
    ++crumb_count;
}

// ---- 시그널 처리기: 여기서는 malloc, printf 같은 것을 부르면 안 된다 ----
void write_str(const char* s) { (void)!write(STDOUT_FILENO, s, std::strlen(s)); }
void on_crash(int sig) {
    write_str(sig == SIGSEGV ? "!! SIGSEGV\n" : "!! SIGABRT\n");
    write_str("최근 발자국:\n");
    int first = crumb_count > 8 ? crumb_count - 8 : 0;
    for (int i = first; i < crumb_count; ++i) {
        write_str("  "); write_str(crumbs[i % 8]); write_str("\n");
    }
    void* frames[32];
    int n = backtrace(frames, 32);       // 주소만 모은다(이름 풀기는 나중에)
    write_str("호출 스택 주소 모음: ");
    write_str(n > 3 ? "있음\n" : "없음\n");
    // 실제로는 보고서 파일에 쓴다. 이름 풀기는 기호 파일이 있는 곳에서 나중에
    backtrace_symbols_fd(frames, n, open("/dev/null", O_WRONLY));
    signal(sig, SIG_DFL);                // 기본 동작으로 되돌리고 다시 죽는다
    raise(sig);
}

#define CHECK(cond)                                         \
    do {                                                    \
        if (!(cond)) { crumb("CHECK 실패: " #cond); std::abort(); } \
    } while (0)

void load_level(int id) {
    crumb("레벨 불러오기 시작");
    int enemies = id == 3 ? -1 : 10;     // 3번 레벨 데이터가 깨져 있다
    crumb("적 목록 읽음");
    CHECK(enemies >= 0);
    crumb("레벨 준비 끝");
}

int main() {
    pid_t child = fork();                // 예제가 끝까지 돌도록 자식에서 죽는다
    if (child == 0) {
        struct sigaction sa{};
        sa.sa_handler = on_crash;
        sigaction(SIGABRT, &sa, nullptr);
        sigaction(SIGSEGV, &sa, nullptr);
        void* warm[1];
        backtrace(warm, 1);              // 처음 부를 때의 내부 할당을 미리 치른다
        crumb("게임 시작");
        load_level(1);
        load_level(3);
        _exit(0);
    }
    int status = 0;
    waitpid(child, &status, 0);
    if (WIFSIGNALED(status))
        std::printf("부모: 자식이 시그널 %d(%s)로 끝남 -> 보고서 업로드 차례\n",
                    WTERMSIG(status), strsignal(WTERMSIG(status)));
}
```

```text
  게임 시작
  레벨 불러오기 시작
  적 목록 읽음
  레벨 준비 끝
  레벨 불러오기 시작
  적 목록 읽음
  CHECK 실패: enemies >= 0
호출 스택 주소 모음: 있음
부모: 자식이 시그널 6(Aborted)로 끝남 -> 보고서 업로드 차례
```

## 처리기 안에서는 아무것도 믿지 않는다

시그널 처리기는 프로그램이 이미 망가진 순간에 불립니다. 메모리 할당자가 잠금을 잡은 채로 죽었을 수도 있고, 힙이 깨졌을 수도 있습니다. 그래서 처리기 안에서는 **비동기 시그널 안전**한 함수만 씁니다. `printf`, `malloc`, `new`, `std::string`은 모두 안 됩니다. 예제는 `write`로 직접 출력했고, 발자국도 미리 잡아 둔 고정 배열에 담아 두었습니다.

`backtrace`는 처음 불릴 때 내부적으로 라이브러리를 불러오며 메모리를 할당할 수 있어서, 처리기를 등록하면서 한 번 미리 불러 두었습니다. 마지막에는 기본 동작으로 되돌리고 같은 시그널을 다시 일으켜, 운영체제가 보기에도 정상적으로 "시그널로 죽은" 프로세스가 되게 합니다. 부모가 시그널 6을 받은 것이 그 결과입니다.

## 발자국

호출 스택은 "어디서" 죽었는지를 알려 주지만 "무엇을 하다가"는 알려 주지 않습니다. **발자국**은 게임이 최근에 한 일을 짧은 문장으로 고리 버퍼에 남긴 것입니다. 보고서에 "1번 레벨은 무사히 준비했고, 3번 레벨을 불러오다 적 목록 검사에서 실패"가 그대로 남았습니다. 할당 없이 고정 크기 배열에 덮어쓰기만 하므로 평소 비용이 거의 없고, 죽는 순간에도 안전하게 읽을 수 있습니다.

## 주소만 모으고, 이름은 나중에

출시 빌드에는 함수 이름(디버그 기호)을 넣지 않습니다. 용량도 크고 역공학을 돕기 때문입니다. 그래서 보고서에는 호출 스택의 **주소**와 각 모듈의 빌드 ID만 담고, 개발사 서버가 빌드마다 따로 보관해 둔 기호 파일로 주소를 함수 이름과 줄 번호로 바꿉니다. 이것을 **기호화**라고 합니다. 빌드 ID가 맞지 않는 기호 파일로 풀면 엉뚱한 함수 이름이 나오므로, 출시하는 모든 빌드의 기호 파일을 빠짐없이 보관하는 것이 출시 절차의 일부입니다.

<Note>
실제로는 이 모든 것을 직접 만들기보다 Crashpad나 Breakpad 같은 라이브러리를 씁니다. 이들은 죽어 가는 게임 안에서 일을 최소화하려고, 미리 띄워 둔 별도의 감시 프로세스가 죽은 프로세스의 메모리를 읽어 미니덤프(스레드별 스택, 레지스터, 모듈 목록)를 만들게 합니다. 예제의 부모 프로세스가 그 감시 프로세스의 아주 단순한 모습입니다. Windows는 시그널 대신 구조적 예외 처리로 같은 일을 합니다.
</Note>

## 정리

- 출시한 게임은 죽는 순간 스스로 보고서를 남기며, 시그널 처리기 안에서는 비동기 시그널 안전한 함수만 쓴다
- 발자국 고리 버퍼는 죽기 직전에 무엇을 하고 있었는지를 할당 없이 남긴다
- 보고서에는 주소와 빌드 ID만 담고, 보관해 둔 기호 파일로 서버에서 기호화하며, 실제로는 감시 프로세스 방식의 라이브러리를 쓴다
