구조가 공개된 큰 프로그램들을 보면 같은 장치가 거듭 나옵니다. 프로그램이 할 수 있는 일마다 이름을 붙여 **등록부** 하나에 넣어 두고, 메뉴, 단축키, 검색 창, 스크립트, 확장이 모두 그 등록부를 봅니다. 아래는 그 장치를 줄인 것입니다.

```cpp
#include <algorithm>
#include <cctype>
#include <functional>
#include <iostream>
#include <map>
#include <string>
#include <vector>

struct Document {
    std::vector<std::string> lines{"alpha", "beta"};
    size_t cursor = 0;                               // 커서가 있는 줄
};

// 이름 붙은 명령 하나: 사람이 읽는 제목, 지금 쓸 수 있는지, 하는 일
struct Entry {
    std::string title;
    std::function<bool(const Document&)> enabled;
    std::function<void(Document&)> run;
};

// 등록부. 메뉴, 단축키, 검색 창, 스크립트가 모두 여기서 id로 명령을 찾는다
class Registry {
public:
    void add(const std::string& id, Entry e) { commands_[id] = std::move(e); }
    void bind(const std::string& chord, const std::string& id) {
        keys_[chord] = id;
    }

    bool run(const std::string& id, Document& d) {
        const Entry& e = commands_.at(id);
        if (!e.enabled(d)) return false;             // 메뉴라면 흐리게 보일 명령
        e.run(d);
        log.push_back(id);                           // 실행한 id를 적어 둔다
        return true;
    }
    bool key(const std::string& chord, Document& d) {
        return run(keys_.at(chord), d);
    }

    std::vector<std::string> search(const std::string& word) const {
        std::vector<std::string> found;
        for (const auto& [id, e] : commands_)
            if (e.title.find(word) != std::string::npos)
                found.push_back(e.title + " (" + id + ")");
        return found;
    }
    std::vector<std::string> log;

private:
    std::map<std::string, Entry> commands_;
    std::map<std::string, std::string> keys_;
};

void show(const char* what, const Document& d) {
    std::cout << what << ":";
    for (size_t i = 0; i < d.lines.size(); ++i)
        std::cout << (i == d.cursor ? " [" : " ") << d.lines[i]
                  << (i == d.cursor ? "]" : "");
    std::cout << "\n";
}

int main() {
    Registry reg;
    auto always = [](const Document&) { return true; };
    reg.add("edit.duplicateLine", {"줄 복제", always, [](Document& d) {
        d.lines.insert(d.lines.begin() + long(d.cursor), d.lines[d.cursor]);
    }});
    reg.add("edit.upperCase", {"줄을 대문자로", always, [](Document& d) {
        for (char& c : d.lines[d.cursor]) c = char(std::toupper(c));
    }});
    reg.add("cursor.down", {"아래 줄로",
        [](const Document& d) { return d.cursor + 1 < d.lines.size(); },
        [](Document& d) { ++d.cursor; }});
    reg.bind("Ctrl+D", "edit.duplicateLine");
    reg.bind("Ctrl+U", "edit.upperCase");
    reg.bind("Down", "cursor.down");

    Document doc;
    show("처음", doc);
    reg.run("edit.duplicateLine", doc);              // 메뉴 항목을 누름
    reg.key("Ctrl+U", doc);                          // 단축키
    for (int i = 0; i < 3; ++i)
        if (!reg.key("Down", doc)) std::cout << "  Down: 지금은 쓸 수 없음\n";
    show("메뉴와 단축키 뒤", doc);

    // 확장이 명령을 더한다. 등록부만 알면 되고 메뉴나 단축키의 코드는 고치지 않는다
    reg.add("sample.reverseLine", {"줄 뒤집기", always, [](Document& d) {
        std::reverse(d.lines[d.cursor].begin(), d.lines[d.cursor].end());
    }});
    reg.bind("Ctrl+R", "sample.reverseLine");
    for (const std::string& hit : reg.search("줄"))
        std::cout << "  찾음: " << hit << "\n";
    reg.key("Ctrl+R", doc);
    show("확장의 명령 뒤", doc);

    const std::vector<std::string> macro = reg.log;  // 적어 둔 id가 곧 매크로다
    Document again;
    std::cout << "기록:";
    for (const std::string& id : macro) {
        std::cout << " " << id;
        reg.run(id, again);
    }
    std::cout << "\n";
    show("기록을 새 문서에 다시 실행", again);
}
```

```text
처음: [alpha] beta
  Down: 지금은 쓸 수 없음
메뉴와 단축키 뒤: ALPHA alpha [beta]
  찾음: 아래 줄로 (cursor.down)
  찾음: 줄 복제 (edit.duplicateLine)
  찾음: 줄을 대문자로 (edit.upperCase)
  찾음: 줄 뒤집기 (sample.reverseLine)
확장의 명령 뒤: ALPHA alpha [ateb]
기록: edit.duplicateLine edit.upperCase cursor.down cursor.down sample.reverseLine
기록을 새 문서에 다시 실행: ALPHA alpha [ateb]
```

- **id로 부른다**: 메뉴 항목과 단축키는 함수가 아니라 `edit.duplicateLine` 같은 id를 압니다. 그래서 단축키를 바꾸는 일이 표 한 줄을 고치는 일이 되고, 사용자가 직접 바꾸게 해 줄 수도 있습니다
- **쓸 수 있는지 묻는다**: 명령마다 지금 쓸 수 있는지 답하는 함수가 있습니다. 마지막 줄에서는 "아래 줄로"가 실행되지 않았습니다. 메뉴는 같은 답으로 항목을 흐리게 그립니다
- **찾을 수 있다**: 명령에 사람이 읽는 제목이 있으므로, 낱말로 명령을 찾아 실행하는 검색 창을 따로 만들 것 없이 얻습니다
- **확장은 더하기만 한다**: `sample.reverseLine`을 등록하자 검색에 나오고 단축키에 묶였습니다. 메뉴와 단축키를 다루는 코드는 고치지 않았습니다
- **적어 두면 매크로**: 실행한 id의 목록을 새 문서에 다시 실행하니 같은 결과가 나왔습니다. 실제 명령은 인자를 받으므로 인자도 함께 적습니다

## 공개된 프로그램들의 등록부

| 프로그램 | 명령의 이름 | 부르는 길 |
| --- | --- | --- |
| VS Code | `editor.action.addCommentLine` 같은 명령 id | 명령 팔레트, 단축키, 메뉴, `executeCommand` |
| Blender | `mesh.subdivide` 같은 오퍼레이터 id | 메뉴와 단축키, 파이썬의 `bpy.ops` |
| GIMP | PDB(프로시저 데이터베이스)의 프로시저 | 메뉴, Script-Fu, 다른 플러그인 |
| OpenOffice, LibreOffice | `.uno:Bold` 같은 디스패치 명령 | 매크로의 디스패처 호출 |

- **VS Code**: 확장은 `registerCommand`로 id에 함수를 묶고, 누구든 `vscode.commands.executeCommand`로 id를 불러 실행합니다. 단축키 설정은 키와 id의 짝입니다
- **Blender**: 오퍼레이터는 C++로 쓴 것도 파이썬으로 쓴 것도 `bpy.ops.mesh.subdivide(number_cuts=3)`처럼 같은 길로 부릅니다. `poll()`이 지금 문맥에서 쓸 수 있는지 답하고, 문맥이 맞지 않는데 부르면 오류가 납니다
- **GIMP**: PDB에는 GIMP 소스에 정의된 내부 프로시저와 플러그인이 등록한 프로시저가 함께 들어 있습니다. Script-Fu에서는 `gimp-`로 시작하는 함수가 내부 프로시저에 묶입니다. 플러그인은 다른 프로세스에서 돌므로 PDB가 곧 프로세스 사이의 호출 규약입니다([「프로세스와 모듈」](#/read/cpp-complex-app/ana-modules))
- **OpenOffice와 LibreOffice**: 매크로 기록기는 사용자의 동작을 `executeDispatch(document, ".uno:Bold", ...)` 같은 디스패치 호출의 나열로 적습니다. OpenOffice의 문서는 디스패치 명령이 내부 장치이고 인자가 문서화되어 있지 않으니, 될 수 있으면 API를 부르라고 권합니다

## 등록부를 둘 때 정할 것

- **id는 공개된 약속이 된다**: 사용자의 단축키 설정, 매크로, 확장이 id를 적어 둡니다. 이름을 바꾸면 그것들이 깨지므로 한번 정한 id는 바꾸지 않습니다
- **인자와 문맥**: 명령은 인자(몇 번 나눌지)와 문맥(어느 창, 어느 선택)을 받아야 합니다. 문맥을 전역 상태에서 읽게 만들면 스크립트에서 부르기 어려워지므로, Blender는 문맥을 넘겨받는 꼴로 두고 덮어쓸 수 있게 합니다
- **실행 취소와는 다른 층이다**: 등록부의 명령은 사용자가 고르는 동작이고, [「문서, 명령, 뷰의 층」](#/read/cpp-complex-app/ana-layers)의 명령 객체는 문서에 일어난 변화입니다. "아래 줄로"처럼 문서를 바꾸지 않는 동작도 있고, 동작 하나가 변화 여럿을 만들기도 합니다([「트랜잭션」](#/read/cpp-complex-app/cmd-transaction))

<Note>
스크립트가 부른 명령을 실행 취소 기록에 넣을지도 정해야 합니다. Blender는 스크립트에서 부른 오퍼레이터를 기본으로는 기록에 넣지 않고, 호출할 때 인자로 요청해야 넣습니다. 스크립트가 부르는 오퍼레이터마다 기록이 하나씩 쌓이지 않게 하려는 것입니다.
</Note>

## 정리

- 큰 프로그램은 할 수 있는 일마다 id를 붙여 등록부에 두고, 메뉴, 단축키, 검색, 스크립트, 확장이 모두 그 id로 부른다
- VS Code의 명령 id, Blender의 오퍼레이터, GIMP의 PDB, OpenOffice와 LibreOffice의 디스패치 명령이 같은 장치다
- id는 한번 정하면 공개된 약속이 되고, 등록부의 명령(동작)과 실행 취소의 명령(변화)은 서로 다른 층이다
