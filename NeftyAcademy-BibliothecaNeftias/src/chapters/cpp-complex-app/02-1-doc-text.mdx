글을 문자열 하나로 두면 가운데에 한 글자를 넣을 때마다 그 뒤의 글자를 모두 옮겨야 합니다. 편집기의 자료 구조는 글자를 옮기지 않고, 어디에 무엇이 있는지 적은 표만 고치는 쪽으로 나아갔습니다. **피스 테이블**은 파일에서 읽은 원본 버퍼, 새로 친 글을 덧붙이는 추가 버퍼, 그리고 두 버퍼의 어느 부분을 어떤 차례로 읽을지 적은 조각 목록으로 이루어집니다.

```cpp
#include <iostream>
#include <string>
#include <string_view>
#include <vector>

// 조각 하나: 어느 버퍼의 어디서부터 몇 글자인지만 적는다
struct Piece { bool added; size_t start, len; };

class PieceTable {
public:
    explicit PieceTable(std::string original) : original_(std::move(original)) {
        if (!original_.empty()) pieces.push_back({false, 0, original_.size()});
    }
    void insert(size_t pos, std::string_view text) {
        size_t at = split(pos);
        Piece fresh{true, added_.size(), text.size()};
        added_ += text;                              // 새 글은 끝에 덧붙이기만 한다
        if (at > 0 && pieces[at - 1].added &&        // 방금 넣은 글에 이어 쓰면
            pieces[at - 1].start + pieces[at - 1].len == fresh.start)
            pieces[at - 1].len += fresh.len;         // 그 조각을 늘린다
        else
            pieces.insert(pieces.begin() + long(at), fresh);
    }
    void erase(size_t pos, size_t len) {         // 글자는 지우지 않고 조각만 뺀다
        size_t first = split(pos), last = split(pos + len);
        pieces.erase(pieces.begin() + long(first), pieces.begin() + long(last));
    }
    std::string text() const {
        std::string out;
        for (const Piece& p : pieces) out += view(p);
        return out;
    }
    std::string_view view(const Piece& p) const {
        const std::string& from = p.added ? added_ : original_;
        return std::string_view(from).substr(p.start, p.len);
    }
    size_t added_bytes() const { return added_.size(); }
    std::vector<Piece> pieces;                   // 문서의 차례는 이 목록이 정한다

private:
    // pos에서 조각이 갈리게 하고, pos에서 시작하는 조각의 번호를 돌려준다
    size_t split(size_t pos) {
        size_t i = 0;
        for (; i < pieces.size() && pos >= pieces[i].len; ++i) pos -= pieces[i].len;
        if (pos == 0) return i;
        Piece right{pieces[i].added, pieces[i].start + pos, pieces[i].len - pos};
        pieces[i].len = pos;
        pieces.insert(pieces.begin() + long(i) + 1, right);
        return i + 1;
    }
    std::string original_, added_;               // 둘 다 한번 쓴 곳은 고치지 않는다
};

void show(const char* what, const PieceTable& t) {
    std::cout << what << ": \"" << t.text() << "\"\n  ";
    for (const Piece& p : t.pieces)
        std::cout << (p.added ? "[추가 " : "[원본 ") << p.start << "+" << p.len
                  << "]";
    std::cout << "\n";
}

int main() {
    PieceTable doc("the quick brown fox");
    show("처음", doc);
    doc.insert(4, "very ");
    show("4번 자리에 넣음", doc);
    std::vector<Piece> before = doc.pieces;          // 되돌릴 때 쓸 것: 조각 목록뿐
    doc.erase(15, 6);
    show("15번부터 6글자 지움", doc);
    doc.insert(doc.text().size(), " jumps");
    show("끝에 넣음", doc);
    doc.pieces = before;
    show("조각 목록만 되돌림", doc);

    // 1MB 문서에 3글자를 1000번 넣는다: 한자리에서 이어 쓰기, 여기저기 고치기
    const size_t mega = 1'000'000;
    PieceTable typing(std::string(mega, 'a')), editing(std::string(mega, 'a'));
    for (size_t i = 0; i < 1000; ++i) {
        typing.insert(mega / 2 + i * 3, "xyz");
        editing.insert(i * 7919 % mega, "xyz");
    }
    std::cout << "이어 쓰기 1000번: 조각 " << typing.pieces.size()
              << "개, 추가 버퍼 " << typing.added_bytes() << "바이트\n"
              << "여기저기 1000번: 조각 " << editing.pieces.size()
              << "개, 추가 버퍼 " << editing.added_bytes() << "바이트\n";
}
```

```text
처음: "the quick brown fox"
  [원본 0+19]
4번 자리에 넣음: "the very quick brown fox"
  [원본 0+4][추가 0+5][원본 4+15]
15번부터 6글자 지움: "the very quick fox"
  [원본 0+4][추가 0+5][원본 4+6][원본 16+3]
끝에 넣음: "the very quick fox jumps"
  [원본 0+4][추가 0+5][원본 4+6][원본 16+3][추가 5+6]
조각 목록만 되돌림: "the very quick brown fox"
  [원본 0+4][추가 0+5][원본 4+15]
이어 쓰기 1000번: 조각 3개, 추가 버퍼 3000바이트
여기저기 1000번: 조각 2000개, 추가 버퍼 3000바이트
```

- **조각은 글자를 갖지 않는다**: 조각은 어느 버퍼의 어디서부터 몇 글자인지만 적습니다. 넣기는 조각을 둘로 가르고 그 사이에 새 조각을 끼우는 일이고, 지우기는 조각을 목록에서 빼는 일입니다. 글자는 한 번도 옮기지 않았습니다
- **버퍼는 고치지 않는다**: 원본은 읽기만 하고 추가 버퍼는 끝에 덧붙이기만 합니다. 지운 글도 버퍼에는 남아 있으므로, 조각 목록만 예전 것으로 되돌리자 "brown "이 돌아왔습니다. 실행 취소가 간직할 것이 작은 표뿐입니다
- **이어 쓰면 한 조각**: 방금 넣은 글 바로 뒤에 이어 넣으면 조각을 새로 만들지 않고 늘립니다. 그래서 한자리에서 1000번 친 문서는 조각이 3개이고, 여기저기 1000번 고친 문서는 2000개입니다
- **조각이 많아지면**: `split`은 조각을 처음부터 세어 가므로 조각 수만큼 느려집니다. 그래서 큰 편집기는 조각을 균형 트리에 담고, 노드마다 왼쪽 부분 트리의 글자 수를 적어 두어 자리를 빨리 찾습니다
- **줄을 찾는 일**: 편집기는 몇 번째 글자보다 몇 번째 줄을 더 자주 찾습니다. 그래서 VS Code는 버퍼마다 줄이 시작하는 자리를 미리 적어 두고, 조각마다 줄바꿈이 몇 개인지도 적어 둡니다

## 실제 프로그램

- **VS Code**: 예전에는 줄마다 문자열 하나를 둔 배열이었습니다. 35MB에 1370만 줄인 파일을 열면 줄 객체에만 600MB쯤이 들어 메모리가 모자랐고, 그래서 피스 테이블로 바꿨습니다. 조각은 레드-블랙 트리에 담고 노드마다 왼쪽 부분 트리의 글자 수와 줄바꿈 수를 적습니다. 아주 작은 파일에서는 줄 배열이 더 빨랐다고도 밝혔습니다
- **Word**: `.doc` 파일 형식의 명세에 피스 테이블이 그대로 나옵니다. 글자 번호로 조각을 찾으면 조각이 파일 속 글의 위치를 가리키고, 그 글이 16비트 유니코드인지 8비트 문자인지도 조각에 적혀 있습니다
- **Emacs**: 다른 길을 갑니다. 버퍼 가운데에 보이지 않는 빈 틈을 두어, 넣으면 틈을 채우고 지우면 틈이 넓어집니다. 틈은 고치는 자리에 있어야 하므로, 멀리 떨어진 곳을 고치면 그때 틈을 옮깁니다

## 로프

**로프**는 글을 잎에 조금씩 나눠 담은 균형 트리입니다. 잇기, 자르기, 복사가 글의 길이와 거의 무관한 시간에 끝나고, 복사본은 트리를 함께 씁니다. libstdc++에는 SGI STL에서 온 로프가 확장으로 들어 있습니다.

```cpp
#include <ext/rope>     // libstdc++에 든 SGI STL의 확장. 표준은 아니다
#include <iostream>

int main() {
    __gnu_cxx::crope doc("the quick brown fox");
    doc.insert(4, "very ");
    __gnu_cxx::crope snapshot = doc;      // 트리를 함께 쓰고 글자는 복사하지 않는다
    doc.erase(15, 6);
    doc.append(" jumps");
    std::cout << doc << "\n" << snapshot << "\n" << doc.substr(4, 10) << "\n";
}
```

```text
the very quick fox jumps
the very quick brown fox
very quick
```

복사본이 원래 글의 저장소를 함께 쓰므로 예전 판을 여러 개 간직해도 값이 쌉니다([「불변 모델과 변경 추적」](#/read/cpp-complex-app/doc-immutable)). 대신 글자 하나를 번호로 읽거나 바꾸는 일이 로그 시간이고, 처음부터 끝까지 훑는 일도 배열보다 몇 배 느립니다.

| 구조 | 넣고 지우기 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| 문자열 하나 | 뒤를 모두 옮김 | 단순하고 읽기가 가장 빠름 | 큰 글의 가운데를 고치기 |
| 갭 버퍼 | 틈에서 바로 | 한자리에서 이어 쓰기 | 멀리 건너뛰면 틈을 옮김 |
| 피스 테이블 | 조각 목록만 고침 | 원본을 건드리지 않음, 싼 실행 취소 | 조각이 늘면 트리가 필요함 |
| 로프 | 트리를 다시 엮음 | 싼 복사와 자르기 | 글자 하나 읽기가 느림 |

<Note>
이 예제의 자리는 바이트 번호입니다. 한글 한 글자는 UTF-8에서 3바이트이므로, 실제 편집기는 조각을 글자 가운데에서 가르지 않게 자리를 글자 경계에 맞춥니다. 화면의 한 글자가 코드 여러 개로 이루어지기도 해서, 커서가 설 수 있는 자리는 따로 셈합니다([「글꼴과 셰이핑」](#/read/cpp-complex-app/txt-shaping)).
</Note>

## 정리

- 피스 테이블은 고치지 않는 두 버퍼와 조각 목록으로 글을 나타내고, 넣고 지울 때 글자를 옮기지 않고 목록만 고친다
- 지운 글도 버퍼에 남으므로 실행 취소는 조각 목록만 되돌리면 되고, 조각이 많아지면 균형 트리에 담는다
- 갭 버퍼는 한자리의 이어 쓰기에, 로프는 싼 복사와 자르기에 강하며, 작은 글은 문자열 하나가 가장 빠르다
