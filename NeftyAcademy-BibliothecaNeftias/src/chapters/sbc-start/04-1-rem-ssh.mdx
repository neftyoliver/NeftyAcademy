SSH는 네트워크 너머의 컴퓨터에서 터미널을 여는 방법입니다. 주고받는 글자는 모두 암호로 싸여서 지나갑니다. 보드에서는 SSH 서버가 돌고, PC에서는 `ssh`라는 프로그램으로 거기에 붙습니다. 화면 없이 쓰는 보드에서 하는 일의 거의 전부가 이 길로 지나갑니다. `ssh`는 리눅스와 macOS에 들어 있고, Windows에도 10의 2018년 가을 판부터 들어 있어서 PowerShell에서 그대로 칩니다.

## 들어가기

```sh
ssh sora@sensor-01.local                         # 사용자@호스트
ssh sora@sensor-01.local 'vcgencmd measure_temp'  # 명령 하나만 시키고 돌아온다
```

들어간 뒤에는 보드의 셸입니다. `exit`를 치면 PC로 돌아옵니다.

- **처음의 지문 물음**: 보드마다 호스트 키라는 것이 있습니다. PC는 처음 보는 키를 만나면 지문을 보여 주며 믿겠느냐고 묻고, `yes`라고 답하면 `~/.ssh/known_hosts`에 적어 둡니다. 다음부터는 같은 키인지 조용히 확인합니다
- **키가 바뀌었다는 경고**: 카드에 OS를 새로 쓰면 보드의 호스트 키도 새로 만들어집니다. 이름은 같은데 키가 달라졌으므로 `ssh`가 경고하며 붙기를 거부합니다. 내가 새로 쓴 것이 맞다면 `ssh-keygen -R sensor-01.local`로 옛 기록을 지우고 다시 들어갑니다
- **까닭 없이 이 경고가 뜬다면**: 누군가 보드인 척하고 있을 수 있다는 뜻입니다. 경고를 버릇처럼 넘기지 않습니다

오류 문구는 어디서 막혔는지를 알려 줍니다.

| 문구 | 뜻 | 볼 곳 |
| --- | --- | --- |
| Connection timed out | 그 주소에서 답이 없다 | 주소, 보드의 전원과 네트워크 |
| Connection refused | 보드는 있는데 SSH 서버가 받지 않는다 | SSH를 켰는가 |
| Permission denied | 서버가 나를 들이지 않는다 | 사용자 이름, 암호, 키 |

## 암호 대신 키

암호로 들어가는 문은 암호를 맞히기만 하면 누구에게나 열립니다. 키 인증은 파일 한 쌍을 씁니다. 비밀키는 PC에만 두고, 공개키는 보드에 등록합니다. 보드는 붙으려는 쪽이 그 공개키에 맞는 비밀키를 가졌는지를 확인하고 들여보냅니다. 암호가 네트워크를 지나가지 않습니다.

```sh
ssh-keygen -t ed25519               # 키 쌍을 만든다. 둘 곳과 암호문을 묻는다
ssh-copy-id sora@sensor-01.local    # 공개키를 보드에 등록한다. 암호를 한 번 묻는다
ssh sora@sensor-01.local            # 이제 암호를 묻지 않는다
```

| 파일 | 있는 곳 | 성질 |
| --- | --- | --- |
| `~/.ssh/id_ed25519` | PC | 비밀키. 나만 읽을 수 있어야 하고 어디에도 보내지 않는다 |
| `~/.ssh/id_ed25519.pub` | PC | 공개키. 한 줄짜리 글이고 비밀이 아니다 |
| `~/.ssh/authorized_keys` | 보드 | 들어와도 되는 공개키를 한 줄에 하나씩 적은 파일 |

- **Ed25519**: 키의 종류입니다. 문서는 옛 기본값인 RSA보다 이것을 권합니다
- **암호문**: 비밀키 파일을 잠그는 암호입니다. 비워 두면 PC를 만지는 누구나 보드에 들어갈 수 있습니다. 매번 치기 번거로우면 `ssh-agent`에 한 번 풀어 맡깁니다. `eval "$(ssh-agent -s)"`로 띄우고 `ssh-add ~/.ssh/id_ed25519`로 넣습니다
- **Imager에서 한 번에**: [「모니터 없이 설정하기: Wi-Fi, SSH, 사용자」](#/read/sbc-start/os-headless)의 Remote Access에서 공개키를 골랐다면 등록은 이미 끝나 있습니다

Windows에는 `ssh-copy-id`가 없습니다. 공개키를 보드로 보내고, 들어가서 손으로 덧붙입니다.

```sh
# PC의 PowerShell에서
scp $env:USERPROFILE\.ssh\id_ed25519.pub sora@sensor-01.local:key.pub
ssh sora@sensor-01.local              # 들어가서 아래 세 줄을 친다
mkdir -p .ssh && chmod 700 .ssh
cat key.pub >> .ssh/authorized_keys && rm key.pub
chmod 644 .ssh/authorized_keys
```

## 암호로 들어가는 문 닫기

키로 들어가지는 것을 확인했다면 암호 인증을 꺼 둡니다. 보드에서 설정 파일을 하나 만듭니다.

```sh
echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/00-keys-only.conf
sudo systemctl restart ssh
sudo sshd -T | grep -i passwordauthentication    # passwordauthentication no
```

- **왜 따로 파일을 만드는가**: 데비안 계열의 SSH 서버는 `sshd_config.d` 안의 파일들을 먼저 읽고, 같은 설정이 여러 번 나오면 먼저 읽은 값을 씁니다. 이름이 `00`으로 시작하는 파일이 가장 먼저 읽힙니다
- **확인까지가 한 묶음이다**: `sshd -T`는 서버가 실제로 쓰게 될 설정을 찍어 줍니다. `yes`가 나온다면 다른 파일이 먼저 정한 것입니다
- **들어와 있는 창을 닫지 않는다**: 설정을 바꾼 뒤에는 새 터미널에서 들어가지는지 본 다음에 원래 창을 닫습니다. 잘못 바꿨을 때 돌아갈 길입니다
- **들어올 사람 정하기**: `/etc/ssh/sshd_config`에 `AllowUsers sora`를 적으면 그 사용자만 들어올 수 있습니다

## 주소를 줄여 쓰기

PC의 `~/.ssh/config`에 보드를 적어 두면 긴 주소를 매번 치지 않아도 됩니다.

```text
Host sensor
    HostName sensor-01.local
    User sora
    IdentityFile ~/.ssh/id_ed25519
```

이제 `ssh sensor`로 들어갑니다. `scp`, `rsync`, 편집기의 원격 기능도 이 파일을 읽으므로 뒤의 쪽들에서도 `sensor`라는 이름을 씁니다.

<Note>
이 쪽의 명령은 라즈베리파이의 문서와 OpenSSH의 매뉴얼에서 옮겼습니다. 글을 쓴 환경에는 `ssh`가 없어서 직접 돌려 보지 못했습니다. 설정 파일을 고치는 명령은 보드에 모니터나 시리얼 콘솔로 들어갈 길이 있을 때 처음 해 보는 편이 안전합니다.
</Note>

## 정리

- `ssh 사용자@호스트`로 들어간다. 처음의 지문 물음은 보드의 호스트 키를 기억해 두려는 것이다
- 키 쌍을 만들어 공개키를 보드의 `authorized_keys`에 등록하면 암호 없이, 암호보다 안전하게 들어간다
- 키로 들어가지는 것을 확인한 뒤 암호 인증을 끄고, `sshd -T`로 설정이 먹었는지 본다
