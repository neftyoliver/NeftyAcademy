카드가 망가지는 날은 옵니다. 그날 다시 켜기까지 걸리는 시간이 백업이 있고 없고의 차이입니다. 이미지 백업은 카드를 첫 섹터부터 끝까지 그대로 파일 하나로 떠 두는 것입니다. 새 카드에 그 파일을 쓰면 설정하던 날로 돌아갑니다.

## 두 가지 백업

| 방법 | 담는 것 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| 이미지 | 카드 전체. 파티션, OS, 설정, 자료 | 새 카드에 쓰면 바로 켜진다 | 크고 오래 걸려서 자주 못 한다 |
| 파일 | 내가 고른 폴더 | 작고 빨라서 날마다 할 수 있다 | OS와 설정은 다시 해야 한다 |

- **둘을 함께 쓴다**: 설정을 마친 날과 크게 바꾼 날에 이미지를 뜨고, 날마다 바뀌는 자료는 `rsync`로 PC에 가져옵니다([「파일 옮기기: scp, rsync, sshfs」](#/read/sbc-start/rem-files))
- **가장 좋은 백업은 다시 만들 수 있는 것**: 무엇을 깔고 무엇을 고쳤는지 적어 둔 글이나 스크립트가 있으면 이미지가 없어도 한 시간 안에 되살립니다

## PC에서 카드를 읽기

보드를 끄고 카드를 뽑아 PC의 카드 리더에 꽂습니다. 리눅스에서는 `dd`가 장치를 처음부터 끝까지 읽어 파일로 씁니다.

```sh
lsblk -d -o NAME,SIZE,MODEL                           # 카드가 어느 장치인지 찾는다
sudo dd if=/dev/sdb of=sensor-01.img bs=4M status=progress
sha256sum sensor-01.img > sensor-01.img.sha256        # 나중에 파일이 멀쩡한지 볼 값
```

- **장치 이름을 두 번 본다**: `if`가 읽는 곳, `of`가 쓰는 곳입니다. 크기와 모델 이름으로 카드가 맞는지 확인합니다. 둘을 바꿔 적으면 카드가 지워지고, `of`에 PC의 디스크를 적으면 PC가 지워집니다
- **꽂을 때 저절로 붙은 것은 떼고 읽는다**: 데스크톱이 카드의 파티션을 붙여 놓았다면 떼어 낸 다음에 읽습니다. 읽는 도중에 내용이 바뀌지 않아야 합니다
- **macOS**: `diskutil list`로 장치를 찾고 같은 명령을 씁니다. 블록 크기는 소문자로 `bs=4m`이라고 적습니다
- **Windows**: `dd`가 없습니다. 카드를 이미지 파일로 읽어 주는 프로그램을 따로 구하거나, 아래의 보드에서 뜨는 방법을 씁니다. [「Raspberry Pi Imager」](#/read/sbc-start/os-imager)에서 본 단계에는 카드를 읽어 파일로 만드는 일이 없습니다

## 이미지 안을 들여다보기

이미지는 카드와 크기가 같습니다. 32GB 카드를 읽으면 쓴 것이 4GB뿐이어도 32GB 가까운 파일이 나옵니다. 첫 섹터의 파티션 표를 읽으면 그 안이 어떻게 나뉘어 있는지 보입니다. 아래 예제는 그 표를 풉니다. 파일 이름을 주면 그 이미지를 읽고, 주지 않으면 본보기 표를 씁니다.

```c
// 이미지의 첫 섹터에서 파티션 표를 읽는다. 파일 이름을 주지 않으면 본보기를 쓴다
#include <stdint.h>
#include <stdio.h>
#include <string.h>

enum { SECTOR = 512, TABLE = 446, ENTRY = 16 };

static uint32_t le32(const uint8_t* p) {     // 작은 쪽 바이트가 먼저 오는 32비트
    return p[0] | p[1] << 8 | p[2] << 16 | (uint32_t)p[3] << 24;
}

static void put_le32(uint8_t* p, uint32_t v) {
    for (int i = 0; i < 4; ++i) p[i] = v >> (8 * i) & 0xff;
}

// 32GB 카드에 올린 Raspberry Pi OS를 닮은 본보기 표를 만든다
static void sample(uint8_t s[SECTOR]) {
    memset(s, 0, SECTOR);
    uint8_t* boot = s + TABLE;
    uint8_t* root = s + TABLE + ENTRY;
    boot[4] = 0x0c;                          // 종류: FAT32
    put_le32(boot + 8, 8192);                // 시작 섹터
    put_le32(boot + 12, 1048576);            // 섹터 수
    root[4] = 0x83;                          // 종류: 리눅스
    put_le32(root + 8, 1056768);
    put_le32(root + 12, 61277184);
    s[510] = 0x55;                           // 표가 있다는 표시
    s[511] = 0xaa;
}

int main(int argc, char** argv) {
    uint8_t s[SECTOR];
    sample(s);
    if (argc > 1) {
        FILE* f = fopen(argv[1], "rb");
        if (!f || fread(s, 1, SECTOR, f) != SECTOR) return 1;
        fclose(f);
    }
    if (s[510] != 0x55 || s[511] != 0xaa) {
        printf("파티션 표가 없다\n");
        return 1;
    }
    uint32_t end = 0;
    printf("번호  종류  시작 섹터    섹터 수     크기\n");
    for (int i = 0; i < 4; ++i) {
        const uint8_t* e = s + TABLE + i * ENTRY;
        uint32_t start = le32(e + 8), count = le32(e + 12);
        if (e[4] == 0) continue;             // 빈 칸
        printf("%d     0x%02x  %9u  %9u  %6uMiB\n", i + 1, e[4], start, count,
               count / 2048);
        if (start + count > end) end = start + count;
    }
    printf("마지막 파티션의 끝: %u섹터, %.2fGiB\n", end, end / 2097152.0);
}
```

```text
번호  종류  시작 섹터    섹터 수     크기
1     0x0c       8192    1048576     512MiB
2     0x83    1056768   61277184   29920MiB
마지막 파티션의 끝: 62333952섹터, 29.72GiB
```

- **첫 파티션이 부트**: 종류 0x0c는 FAT32이고 `config.txt`와 커널이 여기 있습니다. 둘째의 0x83이 리눅스의 루트입니다
- **섹터는 512바이트**: 2048섹터가 1MiB입니다. 예제는 이 셈으로 크기를 적습니다
- **같은 일을 하는 명령**: `fdisk -l sensor-01.img`가 같은 표를 보여 줍니다

## 줄이고 누르기

- **압축한다**: `xz -T0 sensor-01.img`는 코어를 모두 써서 누르고 `.xz`를 남깁니다. 한 번도 쓰지 않은 자리는 거의 사라지지만, 썼다가 지운 자리는 옛 내용이 남아 있어서 덜 줄어듭니다
- **Imager가 눌린 채로 읽는다**: 되돌릴 때 압축을 풀 필요 없이 Imager의 Use custom에서 그 파일을 고릅니다
- **조금 작은 카드에는 못 쓴다**: 같은 32GB라고 적힌 카드도 회사마다 섹터 수가 조금씩 다릅니다. 이미지가 한 섹터라도 크면 써지지 않습니다. 루트 파티션을 쓰는 만큼으로 줄여 주는 PiShrink 같은 스크립트를 쓰거나, 처음부터 작은 카드에서 설정하고 큰 카드로 옮깁니다
- **큰 카드로 옮긴 뒤**: 남는 자리는 `sudo raspi-config`의 Advanced Options > Expand Filesystem으로 채웁니다

## 되돌리기

```sh
sha256sum -c sensor-01.img.sha256                     # 파일이 그대로인지
sudo dd if=sensor-01.img of=/dev/sdb bs=4M conv=fsync status=progress
```

- **Imager가 더 안전하다**: 고른 장치가 카드인지 한 번 걸러 주고, 쓴 뒤에 검증도 합니다. `dd`는 묻지 않고 씁니다
- **되돌려 본 백업만 백업이다**: 남는 카드에 한 번 써서 켜 봅니다. 해 보지 않은 백업은 그날 가서야 쓸 수 있는지 알게 됩니다

## 보드를 켜 둔 채로

- **다른 카드로 복제하기**: 데스크톱의 Accessories에 있는 SD Card Copier는 돌고 있는 카드를 USB 카드 리더에 꽂은 다른 카드로 복제합니다
- **USB 드라이브에 뜨기**: 보드에 USB 드라이브를 꽂고 `sudo dd if=/dev/mmcblk0 of=/media/sora/usb/sensor-01.img bs=1M status=progress`처럼 그 드라이브 안의 파일로 뜹니다. `of`의 경로는 드라이브가 붙은 자리로 바꿉니다. PC가 Windows여도 쓸 수 있는 방법입니다
- **네트워크로 흘려보내기**: 리눅스나 macOS의 PC에서 `ssh sensor 'sudo dd if=/dev/mmcblk0 bs=4M' > sensor-01.img`로 보드의 카드를 PC의 파일로 받을 수 있습니다
- **돌고 있는 카드를 읽는 것의 한계**: 읽는 동안에도 OS가 쓰고 있어서 앞부분과 뒷부분의 시각이 다른 이미지가 됩니다. 쓰는 프로그램을 멈추고 뜨고, 중요한 백업은 꺼서 뜹니다

## 복제한 카드에서 바꿀 것

같은 이미지를 여러 보드에 쓰면 보드들이 서로 같은 것이 됩니다. 한 망에 함께 둘 것이라면 셋을 바꿉니다.

```sh
# SSH 호스트 키를 지우고 새로 만든다
sudo rm /etc/ssh/ssh_host_* && sudo dpkg-reconfigure openssh-server
# 기계 식별자를 지우고 새로 만든다
sudo rm /etc/machine-id && sudo systemd-machine-id-setup
```

- **호스트 이름**: `sudo raspi-config`의 System Options > Hostname에서 바꿉니다. 이름이 같으면 `sensor-01.local`이 어느 보드를 가리키는지 정해지지 않습니다
- **호스트 키가 같으면**: PC가 두 보드를 가려내지 못합니다. 보드마다 키가 다른 것이 [「SSH와 키 인증」](#/read/sbc-start/rem-ssh)에서 본 지문 확인의 바탕입니다
- **기계 식별자가 같으면**: 이 값으로 기계를 가려내는 프로그램들이 두 보드를 하나로 봅니다. 기록을 한곳에 모을 때에도 둘이 섞입니다
- **여러 대에 뿌리는 일**: 수십 대라면 손으로 하지 않습니다. 이 서가의 「교차 컴파일과 배포」가 다룹니다

<Note>
`dd`와 그 뒤의 명령들은 리눅스의 일반 도구이고 공식 문서에 실린 절차가 아닙니다. 검사 환경에는 카드가 없어서 읽고 쓰는 명령을 돌려 보지 못했습니다. 예제는 돌렸고, 본보기 표의 숫자는 Raspberry Pi OS의 카드를 닮게 지은 것입니다. 실제 카드의 값은 다를 수 있습니다. 호스트 키와 기계 식별자를 새로 만드는 두 줄은 데비안 계열에서 널리 쓰는 방법입니다.
</Note>

## 정리

- 이미지 백업은 카드 전체를 파일 하나로 뜬 것이고, 새 카드에 쓰면 그날의 상태로 켜진다
- `dd`는 `if`와 `of`의 장치 이름을 두 번 확인하고 쓴다. 되돌릴 때에는 Imager가 더 안전하다
- 같은 이미지를 여러 보드에 썼다면 호스트 이름, SSH 호스트 키, 기계 식별자를 바꾼다
