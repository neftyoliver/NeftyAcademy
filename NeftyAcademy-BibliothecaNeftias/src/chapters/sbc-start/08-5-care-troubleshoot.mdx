켜지지 않는 보드에는 화면도 SSH도 없습니다. 남은 단서는 LED와, 모니터가 있다면 HDMI의 진단 화면과, 케이블이 있다면 시리얼입니다. 무엇을 보고 무엇부터 바꿔 볼지를 차례로 정리합니다.

## LED로 멈춘 곳 가리기

| LED의 모습 | 뜻 | 볼 곳 |
| --- | --- | --- |
| 아무 불도 없다 | 전원이 오지 않는다 | 어댑터, 케이블, 콘센트 |
| 5가 빨강에 머문다 | 꺼진 채 기다리는 중이거나 부트로더가 못 넘어간다 | 전원 버튼을 누른다. 그래도 안 켜지면 아래의 진단 |
| 4의 빨강이 꺼지거나 떨린다 | 전압이 모자라다 | 전원과 케이블 |
| 초록이 같은 무늬를 되풀이한다 | 부팅에 실패했다 | 아래의 표 |
| 초록이 불규칙하게 깜박인다 | 켜지고 있거나 켜졌다 | 네트워크 쪽을 본다 |

- **불규칙한 깜박임은 좋은 신호다**: 카드를 읽고 쓰고 있다는 뜻입니다. 이 상태에서 안 보인다면 보드가 아니라 네트워크의 문제입니다([「이더넷, Wi-Fi, 블루투스」](#/read/sbc-start/per-network))
- **처음 켤 때는 오래 걸린다**: 새로 쓴 카드의 첫 부팅은 몇 분이 걸립니다. 그 사이에 뽑지 않습니다([「첫 부팅과 갱신」](#/read/sbc-start/os-first-boot))

## 깜박임 무늬 풀기

부팅에 실패하면 초록 LED가 긴 깜박임 몇 번과 짧은 깜박임 몇 번을 내고, 2초쯤 쉬었다가 되풀이합니다. 긴 것이 먼저 옵니다. 긴 것이 없이 짧은 것만 오는 무늬도 있습니다. 아래 예제는 문서의 표를 품고, 센 숫자를 뜻으로 바꿉니다.

```c
// 부팅에 실패했을 때 LED가 깜박이는 무늬를 뜻으로 바꾼다
#include <stdio.h>

struct code { int longs, shorts; const char* status; };

// 공식 문서의 표. 긴 깜박임이 먼저 오고 짧은 깜박임이 뒤따른다
static const struct code codes[] = {
    {0, 3, "부팅에 실패했다(까닭을 특정하지 못함)"},
    {0, 4, "start*.elf를 찾지 못했다"},
    {0, 7, "커널 이미지를 찾지 못했다"},
    {0, 8, "SDRAM이 고장 났다"},
    {0, 9, "SDRAM이 모자라다"},
    {0, 10, "HALT 상태다"},
    {1, 2, "SD카드에서 과전류를 감지했다"},
    {2, 1, "파티션이 FAT이 아니다"},
    {2, 2, "파티션을 읽지 못했다"},
    {2, 3, "확장 파티션이 FAT이 아니다"},
    {2, 4, "파일의 서명이나 해시가 맞지 않는다"},
    {3, 1, "SPI EEPROM에 오류가 있다"},
    {3, 2, "SPI EEPROM이 쓰기 금지되어 있다"},
    {3, 3, "I2C에 오류가 있다"},
    {3, 4, "보안 부팅의 설정이 올바르지 않다"},
    {4, 3, "RP1을 찾지 못했다"},
    {4, 4, "지원하지 않는 보드다"},
    {4, 5, "펌웨어에 치명적인 오류가 났다"},
    {4, 6, "전원에 문제가 있다(A형)"},
    {4, 7, "전원에 문제가 있다(B형)"},
};

// 긴 깜박임의 수로 무리를 나눠, 먼저 해 볼 일을 고른다
static const char* first_try(int longs, int shorts) {
    if (longs == 0 && shorts == 10) return "전원을 뺐다가 다시 꽂는다";
    if (longs == 0 && shorts >= 8)           // 메모리의 문제
        return "다른 카드와 전원으로도 같으면 보드의 고장이다";
    switch (longs) {
    case 0:  return "카드에 OS를 새로 써 본다";
    case 1:  return "카드를 바꾸고 슬롯에 이물이 없는지 본다";
    case 2:  return "카드에 OS를 새로 쓰거나 다른 카드를 쓴다";
    case 3:  return "부트로더를 되살리는 카드를 만들어 켠다";
    default: return "전원을 바꿔 보고 부트로더를 새것으로 올린다";
    }
}

static void explain(int longs, int shorts) {
    printf("길게 %d번, 짧게 %d번: ", longs, shorts);
    for (size_t i = 0; i < sizeof codes / sizeof codes[0]; ++i) {
        if (codes[i].longs != longs || codes[i].shorts != shorts) continue;
        printf("%s\n  -> %s\n", codes[i].status, first_try(longs, shorts));
        return;
    }
    printf("표에 없는 무늬다\n  -> 다시 세어 본다\n");
}

int main(void) {
    explain(0, 4);
    explain(0, 8);
    explain(2, 1);
    explain(3, 1);
    explain(4, 6);
    explain(1, 1);
}
```

```text
길게 0번, 짧게 4번: start*.elf를 찾지 못했다
  -> 카드에 OS를 새로 써 본다
길게 0번, 짧게 8번: SDRAM이 고장 났다
  -> 다른 카드와 전원으로도 같으면 보드의 고장이다
길게 2번, 짧게 1번: 파티션이 FAT이 아니다
  -> 카드에 OS를 새로 쓰거나 다른 카드를 쓴다
길게 3번, 짧게 1번: SPI EEPROM에 오류가 있다
  -> 부트로더를 되살리는 카드를 만들어 켠다
길게 4번, 짧게 6번: 전원에 문제가 있다(A형)
  -> 전원을 바꿔 보고 부트로더를 새것으로 올린다
길게 1번, 짧게 1번: 표에 없는 무늬다
  -> 다시 세어 본다
```

| 긴 깜박임 | 그 무리의 뜻 |
| --- | --- |
| 없음 | 켜는 데 필요한 파일이나 메모리의 문제 |
| 1번 | SD카드의 과전류 |
| 2번 | 카드의 파티션을 읽는 문제 |
| 3번 | 부트로더가 든 EEPROM의 문제. 4와 5 |
| 4번 | 보드와 펌웨어의 짝, 그리고 전원의 문제 |

- **두 번 센다**: 무늬는 되풀이되므로 한 바퀴를 놓쳐도 다음 바퀴에서 셉니다. 영상으로 찍어 천천히 돌려 보면 틀리지 않습니다
- **먼저 해 볼 일은 어림이다**: 예제의 화살표 줄은 이 책이 붙인 것이고 문서의 것이 아닙니다. 무리마다 가장 값싼 시도를 적었습니다
- **짧게 네 번의 풀이는 4까지의 것이다**: 5는 `start*.elf`라는 파일을 쓰지 않습니다. 표의 이 줄은 4와 그 앞의 보드에 맞는 풀이입니다

## 화면과 시리얼로 더 보기

- **HDMI의 진단 화면**: 4와 5는 부팅할 곳을 찾지 못하면 모니터에 진단 화면을 띄웁니다. 부트로더의 판, 부팅 순서, 카드가 보이는지가 나옵니다([「부트로더 EEPROM과 부팅 순서」](#/read/sbc-start/cfg-eeprom))
- **시리얼로 부트로더의 말 듣기**: 부트로더 설정에 `BOOT_UART=1`을 두면 켜지는 과정이 시리얼로 찍힙니다. 화면이 없는 장치에서 어디서 멈추는지를 글로 볼 수 있는 길입니다([「시리얼 콘솔」](#/read/sbc-start/rem-serial))
- **직전에 고친 설정**: `config.txt`를 고친 뒤에 켜지지 않는다면 카드를 PC에 꽂아 그 줄을 되돌립니다. 5는 이 파일이 비어 있어도 켜지지 않습니다([「config.txt와 cmdline.txt」](#/read/sbc-start/cfg-config-txt))

## 하나씩 바꿔 보기

- **붙은 것을 다 뗀다**: USB 장치, HAT, 카메라, 헤더의 선을 모두 떼고 전원과 카드만으로 켭니다. 켜진다면 뗀 것을 하나씩 다시 붙여 범인을 찾습니다
- **전원을 바꾼다**: 흔한 까닭입니다. 공식 전원이나 믿을 만한 다른 전원으로 켜 봅니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **카드를 바꾼다**: 다른 카드에 OS를 새로 써서 켭니다. 켜진다면 옛 카드의 문제입니다([「SD카드가 망가지는 이유」](#/read/sbc-start/care-sd)). 백업해 둔 이미지가 있다면 이때 씁니다([「이미지 통째로 백업하기」](#/read/sbc-start/care-backup))
- **부트로더를 되살린다**: 새 카드로도 안 켜지는 4와 5는 Imager로 부트로더를 다시 써 넣는 카드를 만들어 켭니다
- **한 번에 하나만**: 둘을 함께 바꾸면 어느 쪽이 까닭이었는지 알 수 없습니다. 바꾼 것과 그 결과를 적어 가며 합니다

## 켜지긴 하는데 이상할 때

```sh
vcgencmd get_throttled        # 전압과 열의 흔적
dmesg --level=err,warn        # 커널이 남긴 오류와 경고
journalctl -b -1 -p err       # 바로 앞 부팅에서 남은 오류
```

- **저절로 다시 시작한다**: 전압부터 봅니다. `get_throttled`의 저전압 비트가 서 있다면 전원입니다([「온도와 스로틀링 확인하기」](#/read/sbc-start/care-thermal))
- **갑자기 아무것도 써지지 않는다**: 카드의 파일 시스템이 읽기 전용으로 바뀐 것입니다. `dmesg`에 EXT4의 오류가 남아 있습니다
- **지난 부팅의 기록**: `journalctl -b -1`은 바로 앞 부팅의 기록을 봅니다. 기록을 램에만 두도록 바꿨다면 남아 있지 않습니다
- **글과 함께 묻는다**: 남에게 물을 때에는 보드의 모델, OS의 판, 전원, 붙은 것들, LED의 모습, 위 명령의 출력을 함께 적습니다. `raspinfo`가 이런 정보를 한꺼번에 모아 줍니다

<Note>
LED의 뜻과 깜박임의 표는 공식 문서에서 옮겼습니다. 예제의 표는 그 표의 뜻을 우리말로 줄여 적은 것이고, 먼저 해 볼 일과 무리의 풀이는 이 책이 붙인 어림입니다. 보드를 일부러 망가뜨려 무늬를 본 것은 아닙니다. `dmesg`와 `journalctl`은 리눅스의 일반 명령입니다.
</Note>

## 정리

- 불이 없으면 전원, 같은 무늬를 되풀이하면 부팅 실패, 불규칙하게 깜박이면 켜진 것이다
- 무늬는 긴 깜박임과 짧은 깜박임의 수로 읽고, 긴 것의 수가 문제의 무리를 가른다
- 붙은 것을 다 떼고 전원, 카드, 부트로더의 순서로 하나씩만 바꿔 본다
