보드의 한쪽 가장자리에 두 줄로 선 핀 마흔 개가 40핀 헤더입니다. 센서, LED, 모터 드라이버, 확장 보드가 모두 여기에 붙습니다. 처음에는 핀을 잘못 세는 사고가 잦습니다. 같은 핀을 가리키는 번호가 여러 가지이기 때문입니다.

## 헤더의 생김새

- **두 줄에 스무 개씩**: 핀 사이는 2.54mm입니다. 브레드보드와 점퍼선의 간격과 같습니다
- **1번 핀의 자리**: microSD 슬롯 쪽 끝의, 보드 안쪽 줄에 있는 핀입니다. 3.3V가 나옵니다
- **번호는 둘씩 건너간다**: 1번 맞은편의 바깥쪽 줄이 2번이고, 그 옆 칸이 3번과 4번입니다. 안쪽 줄이 홀수, 바깥쪽 줄이 짝수이고 반대쪽 끝이 39번과 40번입니다. 5와 4에서는 USB 단자 쪽입니다
- **핀의 종류**: 3.3V가 둘, 5V가 둘, GND가 여덟, 나머지 스물여덟이 GPIO입니다. 그 가운데 GPIO 0과 1은 확장 보드가 자기를 알리는 데 쓰도록 비워 둔 것이라([「HAT과 확장 보드」](#/read/sbc-start/hdr-hats)) 마음대로 쓰는 것은 GPIO 2부터 27까지 스물여섯입니다
- **5, 4, Zero 2 W가 같다**: 배치가 같아서 배선 그림 한 장이 세 보드에 모두 통합니다

## 세 가지 번호

| 방식 | 같은 핀의 예 | 만나는 곳 |
| --- | --- | --- |
| 핀 번호 | 11 | 배선 그림, 자리를 세어 꽂을 때. BOARD 방식이라고도 한다 |
| GPIO 번호 | GPIO 17 | 공식 문서, 리눅스의 도구, 이 서가의 코드. BCM 번호라고도 한다 |
| WiringPi 번호 | 0 | 옛 글과 옛 C 코드 |

핀 번호는 자리이고, GPIO 번호는 그 핀이 칩의 몇 번째 신호에 이어져 있는지입니다. 둘 사이에는 규칙이 없어서 지도를 봐야 합니다. 아래 예제는 그 지도를 표로 품고, 세 번호를 나란히 적습니다.

```c
// 40핀 헤더의 지도: 같은 핀에 붙은 세 가지 번호를 나란히 적는다
#include <stdio.h>

enum { V3 = -1, V5 = -2, GND = -3 };         // GPIO가 아닌 핀

// 핀 1~40에 나와 있는 것. 0 이상이면 GPIO 번호다
static const int header[41] = {
    0,
    V3, V5,  2, V5,  3, GND,  4, 14, GND, 15,
    17, 18, 27, GND, 22, 23, V3, 24, 10, GND,
     9, 25, 11,  8, GND,  7,  0,  1,  5, GND,
     6, 12, 13, GND, 19, 16, 26, 20, GND, 21,
};

// WiringPi 번호 0~31이 가리키는 GPIO 번호. 28~31은 40핀 헤더에 없다
static const int wiringpi[32] = {
    17, 18, 27, 22, 23, 24, 25,  4,  2,  3,  8,  7, 10,  9, 11, 14,
    15, 28, 29, 30, 31,  5,  6, 13, 19, 26, 12, 16, 20, 21,  0,  1,
};

static int pin_of(int gpio) {
    for (int pin = 1; pin <= 40; ++pin)
        if (header[pin] == gpio) return pin;
    return 0;
}

static int wiringpi_of(int gpio) {
    for (int w = 0; w < 32; ++w)
        if (wiringpi[w] == gpio) return w;
    return -1;
}

// 핀 하나의 이름과 WiringPi 번호를 글로 만든다
enum { TEXT = 16 };
static void describe(int pin, char name[TEXT], char wpi[TEXT]) {
    int what = header[pin];
    if (what >= 0) {
        snprintf(name, TEXT, "GPIO%d", what);
        snprintf(wpi, TEXT, "%d", wiringpi_of(what));
    } else {
        snprintf(name, TEXT, what == V3 ? "3V3" : what == V5 ? "5V" : "GND");
        snprintf(wpi, TEXT, "-");
    }
}

int main(void) {
    int count[4] = {0};                      // GPIO, 3V3, 5V, GND의 수
    printf("WiringPi   이름  핀 | 핀  이름    WiringPi\n");
    for (int pin = 1; pin <= 40; pin += 2) {
        char ln[TEXT], lw[TEXT], rn[TEXT], rw[TEXT];
        describe(pin, ln, lw);
        describe(pin + 1, rn, rw);
        printf("%8s %6s  %2d | %-2d  %-6s  %s\n", lw, ln, pin, pin + 1, rn, rw);
        for (int p = pin; p <= pin + 1; ++p)
            ++count[header[p] >= 0 ? 0 : -header[p]];
    }
    printf("\nGPIO %d개, 3.3V %d개, 5V %d개, GND %d개\n",
           count[0], count[1], count[2], count[3]);
    const int ask[] = {17, 4, 21};
    for (size_t i = 0; i < sizeof ask / sizeof ask[0]; ++i)
        printf("GPIO%d = 핀 %d = WiringPi %d\n", ask[i], pin_of(ask[i]),
               wiringpi_of(ask[i]));
}
```

       -    3V3   1 | 2   5V      -
       8  GPIO2   3 | 4   5V      -

       -    GND   9 | 10  GPIO15  16
       0 GPIO17  11 | 12  GPIO18  1

- **코드는 GPIO 번호, 배선은 핀 번호**: 코드의 주석에 `GPIO 17(핀 11)`처럼 둘을 함께 적어 두면 회로를 다시 꾸밀 때 지도를 또 찾지 않아도 됩니다
- **남의 글을 따라 할 때**: 그 글의 숫자가 어느 방식인지부터 봅니다. 파이썬의 옛 라이브러리는 두 방식을 골라 쓰게 되어 있어서 `BOARD`라는 낱말이 보이면 핀 번호입니다
- **WiringPi 번호는 옮겨 적는다**: 옛 C 코드의 0번은 GPIO 17입니다. 위 표에서 찾아 GPIO 번호로 바꿉니다
- **GND는 어느 것이나 같다**: 여덟 개가 모두 이어져 있으므로 선이 닿기 좋은 것을 씁니다

## 리눅스가 보는 번호: 칩과 줄

리눅스는 GPIO를 칩과 그 칩 안의 줄 번호로 가리킵니다. 헤더의 핀을 맡은 칩에서는 줄 번호가 GPIO 번호와 같습니다.

```sh
gpiodetect       # GPIO 칩의 목록
```

```text
gpiochip0 [pinctrl-bcm2711] (58 lines)
gpiochip1 [raspberrypi-exp-gpio] (8 lines)
```

- **4에서는**: 위가 문서에 실린 4의 출력입니다. `gpiochip0`의 17번 줄이 GPIO 17입니다. 줄이 58개인 것은 칩의 신호 가운데 헤더로 나오지 않고 보드 안에서 쓰이는 것도 있어서입니다
- **5에서는**: 칩이 다섯 개 나오고, 헤더를 맡은 것은 `pinctrl-rp1`이라는 이름표가 붙은 54줄짜리입니다([「라즈베리파이 5의 RP1」](#/read/sbc-start/hdr-rp1)). 2024년 7월의 커널부터 이것이 `gpiochip0`이고, 그 앞에는 `gpiochip4`였습니다. 옛 글의 `gpiochip4`는 `gpiochip0`으로 바꿔 읽습니다
- **줄에는 이름도 있다**: 5에서는 줄마다 `GPIO17` 같은 이름이 붙어 있고 0번과 1번은 `ID_SDA`, `ID_SCL`입니다. 이름은 보드와 커널에 따라 다르므로 `gpioinfo`로 확인하고 씁니다
- **옛 방식**: `/sys/class/gpio`에 숫자를 써 넣는 방식은 리눅스에서 없어질 예정입니다. 그런 글은 따라 하지 않습니다

이 번호로 핀을 켜고 읽는 코드는 「C 언어 중급」의 [「GPIO로 신호 주고받기」](#/read/c-mid/gpio)에 있습니다.

## 보드에서 지도 보기

```sh
pinout                    # 보드의 그림과 핀 지도. python3-gpiozero 패키지의 것
gpioinfo -c gpiochip0     # 줄마다의 이름과 그 줄을 쓰고 있는 프로그램
sudo pinctrl -p           # 헤더의 핀 순서대로 지금의 방향과 값과 기능
sudo pinctrl get 17       # GPIO17 하나만
```

- **`pinout`**: 지금 보드의 모델을 알아보고 그 보드의 지도를 그립니다. 종이 지도를 찾을 필요가 없습니다
- **`gpioinfo`**: 위는 libgpiod 2의 문법입니다. 1에서는 `gpioinfo gpiochip0`으로 칩 이름만 적습니다. 어느 판인지는 `gpioinfo --version`으로 봅니다
- **`pinctrl`**: 커널을 거치지 않고 칩을 직접 들여다보는 도구입니다. 라즈베리파이의 백서는 이것을 고장을 찾는 도구로 소개하고, 제품의 프로그램에서 부르는 용도로는 권하지 않습니다
- **권한**: 핀을 다루려면 `gpio` 그룹에 들어 있어야 합니다. 처음 만든 사용자는 이미 들어 있고, `groups`로 확인합니다

<Note>
예제의 지도는 공식 문서의 핀 표와 WiringPi 소스의 표를 옮긴 것이고, 프로그램은 이 서가의 검사 환경에서 돌렸습니다. 보드에 대고 맞춰 본 것은 아닙니다. 명령들은 보드가 없어 돌려 보지 못했고, `gpiodetect`의 출력은 라즈베리파이가 낸 백서에 실린 것입니다. 선을 꽂기 전에는 내 보드에서 `pinout`으로 한 번 더 확인합니다.
</Note>

## 정리

- 1번 핀은 microSD 쪽 끝의 안쪽 줄에 있고, 안쪽 줄이 홀수, 바깥쪽 줄이 짝수다
- 핀 번호는 자리, GPIO 번호는 칩의 신호 번호다. 코드에는 GPIO 번호를 쓰고 배선할 때 핀 번호로 바꾼다
- 리눅스는 칩과 줄 번호로 가리키고, 헤더를 맡은 칩에서는 줄 번호가 GPIO 번호와 같다
