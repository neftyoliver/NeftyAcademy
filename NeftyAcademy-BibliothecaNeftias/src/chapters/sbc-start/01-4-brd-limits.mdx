라즈베리파이는 리눅스가 도는 컴퓨터라서 PC에서 배운 것이 거의 그대로 통합니다. 통하지 않는 곳은 몇 군데뿐인데, 처음 옮겨 온 사람은 바로 거기서 넘어집니다. 이 쪽은 그 자리들을 모았습니다. 먼저 같은 C 소스가 두 기계에서 다르게 답하는 것부터 봅니다.

## 같은 소스, 다른 답

```c
// 같은 소스, 다른 기계: PC와 라즈베리파이에서 답이 달라지는 것을 묻는다
#include <limits.h>
#include <stdint.h>
#include <stdio.h>
#include <unistd.h>

int main(void) {
#if defined(__x86_64__)
    const char* arch = "x86-64";
#elif defined(__aarch64__)
    const char* arch = "64비트 Arm(aarch64)";
#else
    const char* arch = "그 밖";
#endif
    uint32_t probe = 1;
    printf("아키텍처      %s\n", arch);
    printf("포인터, long  %zu바이트, %zu바이트\n", sizeof(void*), sizeof(long));
    printf("바이트 순서   %s\n",
           *(unsigned char*)&probe ? "리틀 엔디언" : "빅 엔디언");
    printf("char          %s (CHAR_MIN = %d)\n",
           CHAR_MIN < 0 ? "부호가 있다" : "부호가 없다", CHAR_MIN);
    printf("페이지        %ld바이트\n", sysconf(_SC_PAGESIZE));

    char c = (char)0xff;                     // 파일에서 읽은 바이트 0xFF라고 하자
    printf("0xFF를 char에 담으면 %d, EOF와 %s\n", c,
           c == EOF ? "같다" : "다르다");
}
```

```text
아키텍처      x86-64
포인터, long  8바이트, 8바이트
바이트 순서   리틀 엔디언
char          부호가 있다 (CHAR_MIN = -128)
페이지        4096바이트
0xFF를 char에 담으면 -1, EOF와 같다
```

같은 소스를 64비트 Arm용으로 빌드해서 PC의 에뮬레이터(`qemu-aarch64`)로 돌리면 이렇게 나옵니다.

```text
아키텍처      64비트 Arm(aarch64)
포인터, long  8바이트, 8바이트
바이트 순서   리틀 엔디언
char          부호가 없다 (CHAR_MIN = 0)
페이지        4096바이트
0xFF를 char에 담으면 255, EOF와 다르다
```

- **실행 파일은 통하지 않는다**: PC는 x86-64이고 라즈베리파이는 64비트 Arm입니다. PC에서 빌드한 실행 파일을 보드로 복사해도 돌지 않습니다. 소스를 보드에서 다시 컴파일하거나, PC에서 Arm용으로 빌드합니다([「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross))
- **크기와 바이트 순서는 같다**: 둘 다 포인터와 `long`이 8바이트이고 리틀 엔디언입니다. 이 덕분에 옮겨 온 코드의 대부분은 손대지 않아도 됩니다
- **char의 부호가 다르다**: Arm 리눅스의 `char`는 부호가 없습니다. 바이트 0xFF를 `char`에 담아 `EOF`와 견주는 코드는 PC에서는 같다고, Arm에서는 다르다고 답합니다. Arm용으로 빌드할 때 컴파일러가 "늘 거짓인 비교"라고 경고해 주므로 경고를 켜 둡니다. 바이트는 `unsigned char`나 `uint8_t`로, `getchar`의 결과는 `int`로 받습니다
- **페이지 크기를 묻는다**: 예제의 둘째 출력은 PC의 에뮬레이터에서 돌린 것이라 4096입니다. 라즈베리파이 5의 기본 커널은 페이지가 16KB라서 보드에서는 16384가 나옵니다(이 값은 문서에서 확인했고, 보드에서 돌려 보지는 못했습니다). 4096을 숫자로 박아 둔 프로그램은 5에서 틀리므로 `sysconf`로 묻습니다

## 부팅과 장치

| 항목 | PC | 라즈베리파이 |
| --- | --- | --- |
| 첫 프로그램 | 메인보드의 UEFI | 4와 5는 보드의 EEPROM에 든 부트로더 |
| 설정하는 곳 | 펌웨어의 설정 화면 | 부트 파티션의 `config.txt` |
| 장치를 아는 법 | 장치가 스스로 알린다(PCI, ACPI) | 디바이스 트리가 적어 준다 |
| 시계 | 배터리가 달린 RTC | 5에만 RTC가 있고 배터리는 따로 단다 |
| 끄기 | 전원 버튼 | 5에만 전원 버튼이 있다 |

- **설정 화면이 없다**: PC의 [부팅](#/read/basics/boot)에서 보던 설정 화면 대신 글 파일을 고칩니다. 펌웨어가 리눅스보다 먼저 이 파일을 읽습니다([「config.txt와 cmdline.txt」](#/read/sbc-start/cfg-config-txt))
- **장치는 적어 줘야 안다**: I2C나 SPI에 붙인 센서는 스스로 알리지 않습니다. 무엇이 어디에 붙었는지를 디바이스 트리에 적어야 커널이 드라이버를 붙입니다([「dtoverlay로 기능 켜기」](#/read/sbc-start/cfg-overlays))
- **시계를 잊는다**: RTC가 없는 보드는 전원이 꺼지면 시각을 잊고, 부팅한 뒤 네트워크에서 다시 받습니다. 네트워크가 없으면 틀린 시각으로 돕니다. 로그의 시각이 뒤섞이고, 인증서의 기한을 보는 TLS 연결이 실패할 수 있습니다
- **그냥 뽑지 않는다**: 전원 버튼이 없는 보드는 `sudo poweroff`로 끈 다음 전원을 뽑습니다([「전원을 뽑기 전에」](#/read/sbc-start/care-shutdown))

## 느린 곳과 약한 곳

- **저장 장치**: microSD는 PC의 SSD보다 훨씬 느립니다. 쓰는 도중에 전원이 끊기면 파일 시스템이 깨질 수 있습니다([「SD카드가 망가지는 이유」](#/read/sbc-start/care-sd))
- **빌드**: 작은 프로그램은 보드에서 컴파일해도 됩니다. 큰 프로젝트는 PC에서 빌드해 넘기는 쪽이 빠릅니다
- **박자**: 리눅스는 CPU를 여러 프로그램에 나눠 줍니다. 프로그램이 핀을 바꾸려는 순간에 다른 일이 끼어들면 그만큼 늦어지고, 얼마나 늦을지는 약속되지 않습니다. 박자가 빠듯한 신호는 프로그램이 직접 만들지 않고 PWM이나 SPI 같은 전용 회로에 맡깁니다([「핀의 대체 기능: I2C, SPI, UART, PWM」](#/read/sbc-start/hdr-functions))
- **전원**: Zero를 뺀 보드는 전압이 4.63V 아래로 떨어지면 커널 로그에 경고를 남깁니다. 전원이 모자란 보드는 죽지 않고 이상하게 굽니다. 까닭 없이 다시 시작하거나 USB 장치가 끊기면 전원부터 의심합니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **열**: 뜨거워지면 스스로 클럭을 낮춥니다([「온도와 스로틀링 확인하기」](#/read/sbc-start/care-thermal))
- **핀**: 40핀 헤더는 3.3V이고 5V를 견디지 못합니다. PC에는 없는 위험입니다. 잘못 이으면 SoC가 망가집니다([「3.3V 논리와 전류 한계」](#/read/sbc-start/hdr-voltage))

<Note>
장치에 닿지 않는 부분은 PC에서 먼저 짜고 시험합니다. 센서 값을 계산하는 식, 글을 푸는 코드, 통신 규약은 PC에서도 똑같이 돕니다. 이 서가의 예제도 그렇게 나눠서, PC에서 돌려 확인한 것과 보드가 있어야 하는 것을 쪽마다 밝혀 둡니다. 다만 위의 차이들 때문에, PC에서 통과한 시험은 보드에서 한 번 더 돌립니다.
</Note>

## 정리

- 실행 파일은 아키텍처가 달라 통하지 않지만, 타입의 크기와 바이트 순서가 같아서 소스는 대부분 그대로 옮겨진다
- `char`의 부호와 페이지 크기는 PC와 다를 수 있으므로 가정하지 않고, 부호를 밝혀 쓰고 크기를 물어본다
- 설정 화면 대신 `config.txt`, 자동 탐색 대신 디바이스 트리를 쓰고, 저장 장치와 전원과 핀은 PC보다 약하다
