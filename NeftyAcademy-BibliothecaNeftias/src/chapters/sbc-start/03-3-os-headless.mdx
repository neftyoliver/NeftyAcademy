모니터와 키보드 없이 쓰는 보드는 처음 켜지는 순간부터 혼자 네트워크에 붙고, 내가 들어갈 문을 열어 두어야 합니다. 그러려면 누구로 들어갈지(사용자), 어디로 찾아갈지(이름과 네트워크), 어떻게 들어갈지(SSH)를 켜기 전에 정해 줘야 합니다. [「Raspberry Pi Imager」](#/read/sbc-start/os-imager)의 Customisation 단계가 그 일을 합니다.

## Customisation의 칸들

| 칸 | 정하는 것 | 화면 없이 쓸 때 |
| --- | --- | --- |
| Hostname | 네트워크에서 보일 이름 | 이 이름으로 보드를 찾는다 |
| Localisation | 시간대와 키보드 | Wi-Fi가 쓸 전파 규정도 여기서 정해진다 |
| User | 관리자의 이름과 암호 | SSH로 들어갈 계정이다 |
| Wi-Fi | 네트워크 이름(SSID)과 암호 | 이더넷을 쓴다면 비워도 된다 |
| Remote Access | SSH를 켜고 들어가는 방식을 고른다 | 반드시 켠다 |
| Raspberry Pi Connect | 브라우저로 들어가는 길 | 골라서 쓴다 |

- **호스트 이름**: 글자, 숫자, 하이픈만 씁니다. 보드는 이 이름을 네트워크에 알리므로 PC에서 `이름.local`로 찾을 수 있습니다. 보드가 여러 대라면 `sensor-01`처럼 겹치지 않게 짓습니다
- **Localisation**: 수도를 고르면 시간대와 키보드가 따라 채워집니다. 이 선택이 Wi-Fi의 규제 지역도 정하므로 실제로 쓰는 나라를 고릅니다
- **사용자**: 이름은 글자로 시작하고 소문자, 숫자, 밑줄, 하이픈만 씁니다. 옛 글에 나오는 `pi` 계정은 2022년 4월에 없어졌습니다. 여기서 정한 이름과 암호가 이 보드의 관리자 계정이고, `sudo`를 쓸 때에도 이 암호를 넣습니다
- **Wi-Fi**: Imager가 PC가 붙어 있는 네트워크의 이름을 미리 채워 줍니다. 이름을 감춘 네트워크라면 Hidden SSID를 켭니다. Zero 2 W는 2.4GHz만 쓰므로 5GHz 전용 네트워크에는 붙지 못합니다
- **Remote Access**: Enable SSH를 켜고 둘 가운데 하나를 고릅니다. 암호로 들어가는 방식은 위의 사용자 암호를 쓰고, 공개키로 들어가는 방식은 PC의 공개키를 붙여 넣습니다. 키를 만들고 쓰는 법은 [「SSH와 키 인증」](#/read/sbc-start/rem-ssh)에서 봅니다
- **Raspberry Pi Connect**: 여기서 받은 인증 키는 개인 계정이면 여섯 시간 뒤에 못 쓰게 됩니다. 카드를 쓰고 나서 그 안에 보드를 켜야 합니다

처음 켠 보드에 밖에서 들어가는 길은 SSH와 Raspberry Pi Connect뿐입니다. 둘 다 정하지 않고 카드를 쓰면 모니터를 붙여야 합니다.

## 카드에 쓰인 것

Imager는 고른 설정을 카드의 부트 파티션에 글 파일로 적어 둡니다. 지금의 Raspberry Pi OS(트릭시)는 처음 켜질 때 cloud-init이라는 도구로 그 파일을 읽어 적용합니다. 부트 파티션은 PC에서도 보이는 FAT 파티션이어서, 쓴 뒤에 카드를 다시 꽂으면 파일을 열어 볼 수 있습니다.

| 파일 | 든 것 |
| --- | --- |
| `user-data` | 호스트 이름, 시간대, 사용자, SSH. 네트워크를 뺀 모든 것 |
| `network-config` | 네트워크. Wi-Fi의 이름과 암호 |
| `meta-data` | cloud-init이 나머지 둘을 읽게 하는 파일. 손대지 않는다 |

`user-data`는 이런 꼴입니다. 첫 줄의 `#cloud-config`가 꼭 있어야 합니다.

```yaml
#cloud-config
hostname: sensor-01
timezone: Asia/Seoul
users:
  - name: sora
    passwd: "$6$abcdefgh$3rj1vTLX64btReFsM4MQ22otcD40l7vbtw7qCyr0dxc4kx..."
    lock_passwd: false
    ssh_authorized_keys:
      - ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... sora@pc
enable_ssh: true
rpi:
  i2c: true
```

`network-config`는 이런 꼴입니다.

```yaml
network:
  version: 2
  renderer: NetworkManager
  wifis:
    wlan0:
      dhcp4: true
      regulatory-domain: "KR"
      access-points:
        "my-home-wifi":
          password: "여기에 암호"
      optional: true
```

- **YAML은 들여쓰기가 문법이다**: 칸 수가 어긋나면 파일 전체가 읽히지 않습니다. 탭이 아니라 빈칸으로 맞춥니다
- **암호는 해시로 적는다**: `passwd`에는 암호 자체가 아니라 `openssl passwd -6`으로 만든 해시를 적습니다. `plain_text_passwd`라는 키로 암호를 그대로 적을 수도 있지만, 카드를 꽂는 누구나 읽게 됩니다
- **라즈베리파이만의 키**: `enable_ssh`와 `rpi` 아래의 `i2c`, `spi`, `serial`, `onewire`는 Raspberry Pi OS에만 있는 키입니다. 핀으로 쓰는 버스를 처음부터 켜 둘 수 있습니다
- **카드를 조심해서 다룬다**: 이 파일들은 누구나 읽을 수 있는 파티션에 있고, 집 네트워크에 붙는 데 필요한 것이 들어 있습니다

## 손으로 하는 길

Imager의 설정을 건너뛰었거나 다른 도구로 이미지를 썼다면 부트 파티션(`bootfs`)에 파일 둘을 만듭니다.

- **`ssh`**: 내용이 없는 빈 파일입니다. 이름에 확장자가 붙지 않게 합니다
- **`userconf.txt`**: `사용자이름:암호의해시` 한 줄입니다

```sh
openssl passwd -6     # 암호를 두 번 묻고 $6$ 으로 시작하는 해시를 찍는다
```

- **macOS**: 기본으로 깔린 것은 `-6`을 모르는 LibreSSL입니다. 문서는 OpenSSL로 이 명령을 돌리라고 적습니다
- **Wi-Fi는 이 길로 정하지 못한다**: 옛 글에 나오는 `wpa_supplicant.conf`를 넣는 방법은 북웜부터 통하지 않습니다. 문서는 Wi-Fi를 미리 정하지 않았다면 이더넷에 꽂으라고 적습니다

## 켜기

카드를 보드에 꽂고 전원을 넣습니다. 처음 켤 때는 설정을 적용하느라 평소보다 오래 걸립니다. 몇 분 기다린 뒤 [「첫 부팅과 갱신」](#/read/sbc-start/os-first-boot)의 순서대로 보드를 찾습니다.

<Note>
위의 두 파일은 2025년 11월에 라즈베리파이가 cloud-init을 소개하며 설명한 키들로 꾸민 본보기입니다. Imager가 실제로 쓰는 파일에는 줄이 더 많습니다. 본보기는 YAML 문법만 검사했고, 보드에서 처음 켜 보지는 못했습니다. 직접 고칠 때에는 Imager가 써 준 파일에서 필요한 줄만 바꾸는 편이 안전합니다.
</Note>

## 정리

- 화면 없이 쓸 보드는 켜기 전에 호스트 이름, 사용자, 네트워크, SSH를 Imager의 Customisation에서 정한다
- 설정은 부트 파티션의 `user-data`와 `network-config`에 적히고, 처음 켜질 때 cloud-init이 읽어 적용한다
- Imager 없이는 빈 `ssh` 파일과 `userconf.txt`로 SSH와 사용자를 만들 수 있지만, Wi-Fi는 정하지 못한다
