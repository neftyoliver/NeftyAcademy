헤더의 GPIO 핀은 칩의 다리에 거의 곧바로 이어져 있습니다. PC의 USB 단자처럼 사이에서 막아 주는 회로가 없어서, 핀에 잘못 건 전압과 전류는 그대로 칩으로 들어갑니다. 지킬 숫자는 둘입니다. 전압은 3.3V까지, 전류는 핀 하나에 16mA이고 모두 합해 50mA까지입니다.

## 3.3V 논리

- **HIGH는 3.3V, LOW는 0V**: 핀이 내는 것도, 핀이 받을 수 있는 것도 이 범위입니다
- **5V를 견디지 못한다**: 문서는 GPIO 핀에 5V를 대면 SoC가 영영 망가질 수 있다고 적습니다. 헤더에서 5V가 나오는 곳은 2번과 4번 핀이고, 그 맞은편이 3.3V 핀(1번)과 GPIO 2(3번)입니다. 선을 한 칸 잘못 꽂거나 쇠붙이가 두 줄을 함께 건드리면 그대로 사고가 됩니다
- **5V로 도는 부품**: 아두이노에 맞춰 나온 센서 모듈 가운데에는 신호를 5V로 내는 것이 있습니다. 붙이기 전에 그 부품의 출력 전압을 봅니다
- **선은 전원을 뺀 채로 꽂는다**: 문서도 확장 보드를 꽂기 전에 반드시 전원에서 떼라고 적습니다

핀이 전압을 HIGH와 LOW 가운데 어느 쪽으로 읽는지는 칩마다 조금 다릅니다.

| 보드(칩) | LOW로 읽는 전압 | HIGH로 읽는 전압 | 안에 든 풀 저항 |
| --- | --- | --- | --- |
| Zero 2 W(RP3A0) | 0.9V 아래 | 1.6V 위 | 50~65kΩ |
| 4, 400(BCM2711) | 0.8V 아래 | 2.0V 위 | 33~73kΩ |
| 5(RP1) | 0.8V 아래 | 2.0V 위 | 55kΩ쯤 |

두 문턱 사이의 전압은 어느 쪽으로 읽힐지 정해져 있지 않습니다. 아무것도 잇지 않은 입력 핀이 바로 그런 상태여서, 손을 가까이 대기만 해도 값이 바뀝니다.

## 풀업과 풀다운

- **풀 저항**: 핀을 큰 저항으로 3.3V나 GND에 약하게 묶어 두는 것입니다. 아무도 핀을 움직이지 않을 때의 값이 정해집니다. 칩 안에 들어 있어서 코드에서 켭니다. 「C 언어 중급」의 [「GPIO로 신호 주고받기」](#/read/c-mid/gpio)가 버튼에 풀업을 거는 예입니다
- **GPIO 2와 3은 다르다**: 이 둘에는 보드에 1.8kΩ 풀업이 납땜되어 있습니다. I2C에 쓰라고 달아 둔 것입니다. 끌 수 없으므로 풀다운이 필요한 회로에는 이 핀을 쓰지 않습니다
- **켜진 직후에는 모두 입력이다**: 전원이 들어오면 핀은 입력이고 칩이 정한 기본 풀이 걸려 있습니다. 문서가 가리키는 BCM2835 자료에 따르면 GPIO 0부터 8까지가 풀업, 9부터 27까지가 풀다운입니다
- **켜지는 동안의 값**: 내 프로그램이 핀을 출력으로 바꾸기까지 몇 초에서 수십 초가 걸립니다. HIGH에 켜지는 릴레이나 모터 드라이버는 그동안 꺼져 있도록 풀다운 쪽 핀에 달고, 핀과 GND 사이에 10kΩ쯤의 저항을 하나 더 답니다. LOW에 켜지는 모듈이라면 반대로 풀업 쪽입니다

## 전류의 한도

| 한도 | 값 |
| --- | --- |
| 핀 하나 | 16mA까지 |
| 모든 GPIO 핀의 합 | 50mA까지 |

- **핀은 신호를 내는 곳이다**: 전원이 아닙니다. LED 몇 개는 켤 수 있지만 모터나 릴레이의 코일은 돌리지 못합니다
- **드라이브 강도는 한도가 아니다**: 핀마다 2mA에서 16mA까지의 설정이 있지만, 문서는 이것이 핀이 내는 전류도 아니고 전류를 막아 주는 한도도 아니라고 적습니다. 그 전류까지는 HIGH와 LOW의 전압이 규격 안에 머문다는 뜻입니다. 4는 기본 4mA에 최대 8mA이고, 5의 RP1은 2, 4, 8, 12mA입니다
- **더 당기면**: 막아 주는 것이 없으므로 전류는 흐릅니다. HIGH의 전압이 내려앉고, 칩이 뜨거워지고, 심하면 망가집니다

## 저항 두 가지 계산하기

회로에 가장 먼저 들어가는 저항이 둘 있습니다. LED에 흐르는 전류를 정하는 저항과, 5V 신호를 3.3V 아래로 낮추는 분압 저항입니다. 앞의 것은 3.3V에서 LED가 가져가는 전압을 뺀 나머지를 바라는 전류로 나눈 값이고, 뒤의 것은 저항 둘의 비로 전압을 나눕니다.

```c
// 핀에 붙이는 저항 두 가지: LED의 전류를 정하는 저항과 5V 신호를 낮추는 분압
#include <stdio.h>

enum {
    VCC_MV = 3300,          // 핀이 HIGH일 때 내는 전압
    PIN_MAX_MA = 16,        // 핀 하나의 한도
    TOTAL_MAX_MA = 50,      // 모든 핀을 합한 한도
    HIGH_MIN_MV = 2000,     // 이보다 높아야 HIGH로 읽힌다(4와 5)
    IN_MAX_MV = 3465,       // 3.3V 전원이 5% 높을 때까지는 같은 것으로 친다
};

// 가게에서 파는 저항값(E12 계열) 가운데 ohms보다 크거나 같은 가장 가까운 것
static int e12_at_least(double ohms) {
    static const int e12[] = {10, 12, 15, 18, 22, 27, 33, 39, 47, 56, 68, 82};
    for (int decade = 1; decade <= 100000; decade *= 10)
        for (int i = 0; i < 12; ++i)
            if (e12[i] * decade >= ohms) return e12[i] * decade;
    return 0;
}

static const char* judge(double ma, int count, int left_mv) {
    if (ma > PIN_MAX_MA) return "핀 하나의 한도를 넘는다";
    if (ma * count > TOTAL_MAX_MA) return "모두 합한 한도를 넘는다";
    if (left_mv < 500) return "남는 전압이 적어 밝기가 고르지 않다";
    return "괜찮다";
}

struct led { const char* name; int vf_mv, want_ma, count; };

int main(void) {
    const struct led leds[] = {
        {"빨강", 1800, 5, 1},  {"초록", 2100, 5, 1}, {"파랑", 3000, 5, 1},
        {"빨강", 1800, 20, 1}, {"빨강", 1800, 5, 8}, {"빨강", 1800, 10, 8},
    };
    printf("LED        바라는 전류   저항   실제 전류  판정\n");
    for (size_t i = 0; i < sizeof leds / sizeof leds[0]; ++i) {
        const struct led* l = &leds[i];
        int left_mv = VCC_MV - l->vf_mv;     // 저항이 받는 전압
        int r = e12_at_least((double)left_mv / l->want_ma);
        double ma = (double)left_mv / r;
        printf("%s %d개       %2dmA  %4dΩ  %4.1fmA×%d  %s\n", l->name, l->count,
               l->want_ma, r, ma, l->count, judge(ma, l->count, left_mv));
    }

    const int dividers[][2] = {{1000, 2000}, {10000, 20000}, {1800, 3300},
                               {1000, 1000}, {2000, 1000},   {1000, 4700}};
    printf("\n5V 신호를 R1과 R2로 나눈 전압\n");
    for (size_t i = 0; i < sizeof dividers / sizeof dividers[0]; ++i) {
        int r1 = dividers[i][0], r2 = dividers[i][1];
        int mv = 5000 * r2 / (r1 + r2);      // R2에 걸리는 전압이 핀으로 간다
        printf("R1 %5dΩ  R2 %5dΩ  %4dmV  %s\n", r1, r2, mv,
               mv > IN_MAX_MV     ? "너무 높다"
               : mv < HIGH_MIN_MV ? "HIGH로 읽히지 않을 수 있다"
                                  : "괜찮다");
    }
}
```

초록 1개        5mA   270Ω   4.4mA×1  괜찮다

- **LED의 전압은 대표값이다**: 색과 종류마다 다릅니다. 부품의 자료에 적힌 순방향 전압을 넣어 다시 계산합니다
- **파랑과 흰색은 3.3V에 빠듯하다**: LED가 3V를 가져가면 저항에 남는 것이 0.3V뿐이라, 전압이 조금만 달라져도 전류가 크게 바뀝니다. 예제가 0.5V를 기준으로 삼은 것은 어림입니다
- **실제 전류는 계산보다 적다**: 핀은 전류를 낼수록 HIGH의 전압이 내려갑니다. 4의 규격으로는 4mA를 낼 때 2.6V까지 내려갈 수 있습니다. 계산은 안전한 쪽으로 틀립니다
- **분압은 느린 한 방향 신호에만**: 5V 부품의 출력을 핀으로 받을 때 씁니다. 10kΩ과 20kΩ처럼 큰 값은 전류를 덜 쓰지만 빠른 신호의 모서리가 뭉개집니다. 빠르거나 양쪽으로 오가는 신호에는 레벨 시프터 모듈을 씁니다
- **반대 방향**: 핀의 3.3V를 5V 부품이 HIGH로 읽는지는 그 부품의 자료에서 입력의 문턱 전압을 봐야 압니다
- **I2C는 풀업을 3.3V에**: I2C의 선은 누구도 HIGH를 밀어내지 않고 풀업이 끌어올립니다. 풀업이 3.3V에 묶여 있으면 5V 부품이 같은 선에 있어도 3.3V를 넘지 않습니다([「I2C」](#/read/c-mid/bus-i2c)). 모듈에 5V 쪽으로 가는 풀업이 달려 있지 않은지 봅니다

## 큰 부하를 다는 법

- **핀은 스위치만 움직인다**: 모터, 릴레이, LED 띠, 서보는 트랜지스터나 드라이버 모듈을 사이에 둡니다. 핀은 그 입력만 움직이고, 부하의 전류는 따로 마련한 전원에서 흐릅니다
- **GND는 하나로 잇는다**: 따로 둔 전원의 GND와 보드의 GND를 이어야 핀의 3.3V가 저쪽에서도 3.3V로 보입니다
- **코일에는 다이오드**: 릴레이와 모터는 끊는 순간 높은 전압을 되쏩니다. 릴레이 모듈에는 이것을 받아 주는 다이오드가 대개 들어 있고, 낱개 부품으로 꾸밀 때에는 직접 답니다
- **3.3V 핀**: 센서 몇 개를 먹이는 자리입니다. 문서에는 이 핀이 낼 수 있는 전류의 숫자가 없습니다. 많이 쓰는 부품은 5V 핀에서 받아 그쪽의 레귤레이터로 3.3V를 만듭니다
- **5V 핀**: 전원 단자와 이어져 있습니다. 쓸 수 있는 전류는 전원의 용량에서 보드와 USB 장치가 쓰는 만큼을 뺀 나머지입니다([「USB와 전력 예산」](#/read/sbc-start/per-usb))

<Note>
문턱 전압, 풀 저항, 16mA와 50mA, 드라이브 강도의 설명은 공식 문서의 표에서 옮겼습니다. Zero 2 W의 줄은 문서가 BCM2835 계열과 RP3A0을 묶어 적은 값입니다. 기본 풀의 방향은 문서가 직접 적지 않고 칩의 자료를 가리키므로, 내 보드에서는 `sudo pinctrl -p`로 확인합니다. LED의 전압, 분압, 다이오드는 전자 회로의 일반 지식이고, 예제는 숫자만 계산합니다. 회로를 꾸며 재 본 것은 아닙니다.
</Note>

## 정리

- GPIO 핀은 3.3V까지만 받는다. 5V 신호는 분압이나 레벨 시프터로 낮추고, 선은 전원을 뺀 채로 꽂는다
- 핀 하나에 16mA, 모두 합해 50mA까지다. LED에는 저항을 달고, 큰 부하는 드라이버와 따로 둔 전원에 맡긴다
- 아무것도 잇지 않은 입력은 값이 정해지지 않으므로 풀업이나 풀다운을 건다
