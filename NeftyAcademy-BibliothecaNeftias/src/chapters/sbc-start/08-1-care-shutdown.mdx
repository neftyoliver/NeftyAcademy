PC는 전원 버튼을 누르면 OS가 정리하고 꺼집니다. 4와 Zero 2 W에는 그 버튼이 없어서, 선을 뽑는 것이 곧 끄는 것처럼 보입니다. 그렇게 꺼도 대개는 다시 켜집니다. 문제는 대개가 아닌 날입니다.

## 그냥 뽑으면 생기는 일

- **쓴 것이 아직 램에 있다**: 리눅스는 파일에 쓰라는 요청을 받아도 곧바로 저장 장치에 쓰지 않고 모아 두었다가 씁니다. 프로그램이 다 썼다고 여긴 데이터가 몇 초에서 수십 초 동안 램에만 있습니다
- **쓰는 도중에 끊기면**: 파일이 반쯤만 남거나, 어느 파일이 어디에 있는지 적어 둔 파일 시스템의 장부가 어긋납니다. 카드 안에서 벌어지는 일은 더 나쁩니다([「SD카드가 망가지는 이유」](#/read/sbc-start/care-sd))
- **언제 쓰는지 알 수 없다**: 내 프로그램이 가만히 있어도 OS는 기록을 남기고 시계를 맞추고 패키지 목록을 새로 받습니다. 지금은 안 쓰고 있겠거니 하고 뽑는 것은 내기입니다

## 끄는 법

```sh
sudo poweroff            # 정리하고 끈다
sudo reboot              # 정리하고 다시 시작한다
sudo shutdown -h +10     # 10분 뒤에 끈다. 취소는 sudo shutdown -c
```

| 보드 | 다 꺼졌다는 표시 | 다시 켜는 법 |
| --- | --- | --- |
| 5 | 전원 버튼 옆의 LED가 빨강으로 바뀐다 | 전원 버튼을 누른다 |
| 4 Model B | 초록 LED가 잇달아 몇 번 깜박인 뒤 꺼진다. 빨강은 켜져 있다 | 전원선을 뺐다가 꽂는다 |
| Zero 2 W | 초록 LED가 꺼진다 | 전원선을 뺐다가 꽂는다 |

- **LED가 바뀐 뒤에 뽑는다**: 명령을 치고 몇 초 기다려 위의 표시를 본 다음에 선을 뺍니다
- **SSH에서 끄면**: 연결이 끊기는 것이 정상입니다. 보드가 안 보이는 자리에 있다면 `ping`이 답하지 않게 된 뒤로 열을 더 셉니다
- **꺼져도 전기는 조금 쓴다**: 5는 꺼진 뒤에도 1W쯤을 씁니다. 줄이는 설정은 [「부트로더 EEPROM과 부팅 순서」](#/read/sbc-start/cfg-eeprom)에 있습니다

## 5의 전원 버튼

- **Lite에서는 한 번**: 데스크톱이 없는 OS에서는 한 번 누르면 정리하고 꺼집니다
- **데스크톱에서는 두 번**: 한 번 누르면 끌지 묻는 창이 뜨고, 한 번 더 누르면 꺼집니다. 빠르게 두 번 눌러도 됩니다
- **길게 누르면 강제로 꺼진다**: 정리하지 않고 끊는 것이라 선을 뽑는 것과 같습니다. 보드가 멈춰서 아무것도 듣지 않을 때에만 씁니다
- **꺼진 채로 누르면 켜진다**: 전원이 꽂혀 있다면 버튼으로 다시 켭니다
- **버튼을 밖으로 빼기**: 보드의 J2라는 두 패드에 누르는 동안만 붙는 스위치를 달면 보드의 버튼과 똑같이 듭니다. 케이스 안에 보드를 넣을 때 씁니다

## 4와 Zero 2 W에 종료 버튼 달기

```text
dtoverlay=gpio-shutdown
```

- **배선**: 누르는 동안만 붙는 버튼을 GPIO 3(핀 5)과 GND(핀 6) 사이에 답니다. 오버레이의 기본 핀이 3이고, 이 핀에는 풀업이 달려 있어서 저항이 따로 필요 없습니다
- **누르면 꺼진다**: 오버레이가 버튼을 전원 키로 알리고, systemd가 그것을 받아 정리하고 끕니다
- **꺼진 뒤에 누르면 켜진다**: 꺼진 보드는 GPIO 3이 LOW로 당겨지면 다시 켜집니다. 그래서 같은 버튼 하나로 끄고 켭니다
- **I2C와 겹친다**: GPIO 3은 I2C의 SCL이기도 합니다([「핀의 대체 기능: I2C, SPI, UART, PWM」](#/read/sbc-start/hdr-functions)). I2C를 쓴다면 `dtoverlay=gpio-shutdown,gpio_pin=17`처럼 다른 핀으로 옮깁니다. 이때는 끄는 일만 되고, 켜는 일은 전원선으로 해야 합니다

## 꺼질 때 내 프로그램이 할 일

`poweroff`를 치면 systemd가 돌고 있는 프로그램들에 SIGTERM이라는 신호를 보내 끝내 달라고 하고, 기다려도 끝나지 않으면 강제로 끝냅니다. 그 사이가 프로그램이 쓰던 것을 마무리할 시간입니다. 아래 예제는 신호를 받으면 하던 기록을 마치고 저장 장치까지 쓴 뒤 끝납니다.

```c
// 끄라는 신호(SIGTERM)를 받으면 하던 기록을 마치고 스스로 끝낸다
#define _POSIX_C_SOURCE 200809L
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

static volatile sig_atomic_t stop = 0;       // 신호 처리기가 고치는 것은 이것뿐이다

static void on_term(int) { stop = 1; }

int main(void) {
    struct sigaction sa = {.sa_handler = on_term};
    sigaction(SIGTERM, &sa, nullptr);        // 시스템이 꺼질 때 받는 신호
    sigaction(SIGINT, &sa, nullptr);         // Ctrl+C도 같은 길로 보낸다

    FILE* log = fopen("readings.csv", "w");
    if (!log) return 1;
    int lines = 0;
    while (!stop) {
        ++lines;
        fprintf(log, "%d,%.1f\n", lines, 20.0 + lines * 0.5);   // 센서 값 한 줄
        printf("기록 %d\n", lines);
        if (lines == 3) raise(SIGTERM);      // 본보기로, 셋째 줄 뒤에 신호가 온다
    }
    fflush(log);                             // 프로그램의 버퍼를 커널로 넘긴다
    fsync(fileno(log));                      // 커널이 그것을 카드까지 쓰게 한다
    fclose(log);
    printf("신호를 받았다. %d줄을 카드까지 쓰고 끝낸다\n", lines);
}
```

```text
기록 1
기록 2
기록 3
신호를 받았다. 3줄을 카드까지 쓰고 끝낸다
```

- **처리기는 깃발만 세운다**: 신호 처리기는 프로그램이 무엇을 하고 있든 끼어들어 실행됩니다. 그 안에서는 변수 하나만 고치고, 정리는 본래의 흐름이 그 변수를 보고 합니다
- **`fflush`와 `fsync`는 다르다**: 앞의 것은 프로그램 안의 버퍼를 커널에 넘기고, 뒤의 것은 커널이 그것을 저장 장치에 다 쓸 때까지 기다립니다. 전원이 끊겨도 남는 것은 뒤의 것이 끝난 데이터입니다
- **기다려 주는 시간에는 끝이 있다**: systemd가 기다리는 시간은 기본이 90초입니다. 그 안에 끝내지 못할 정리는 평소에 조금씩 해 둡니다
- **더 깊이는**: 프로그램을 서비스로 만드는 법은 이 서가의 「임베디드 리눅스 시스템」에서, 신호의 자세한 규칙은 「리눅스 시스템 호출」에서 다룹니다

## 전원이 갑자기 끊기는 자리라면

- **아무도 명령을 쳐 주지 않는다**: 현장에 둔 장치는 정전과 뽑힌 플러그를 겪습니다. 그런 장치는 끊겨도 깨지지 않게 꾸밉니다
- **읽기 전용으로 돌린다**: `raspi-config`의 Performance Options > Overlay File System은 카드에 쓰지 않고 램에만 쓰게 합니다. 꺼지면 바뀐 것이 사라지는 대신 카드는 그대로입니다. 꾸미는 법은 「임베디드 리눅스 시스템」에서 다룹니다
- **남겨야 할 데이터는 따로**: 센서의 기록처럼 남아야 하는 것은 다른 파티션이나 서버로 보내고, 쓰는 방법을 조심합니다([「SD카드가 망가지는 이유」](#/read/sbc-start/care-sd))

<Note>
명령과 버튼의 동작, 오버레이의 값은 공식 문서와 overlays README에서 옮겼습니다. 보드가 없어 버튼을 눌러 보지는 못했습니다. 예제는 이 서가의 검사 환경에서 돌렸고, 신호를 밖에서 보내는 대신 스스로에게 보내게 했습니다. 실제로는 `sudo systemctl stop`이나 `kill`이 그 신호를 보냅니다. systemd가 기다리는 90초는 systemd의 기본값이고 서비스마다 바꿀 수 있습니다.
</Note>

## 정리

- 리눅스는 쓰기를 모아 두었다가 하므로, `sudo poweroff`로 끄고 LED가 바뀐 뒤에 선을 뽑는다
- 5는 전원 버튼으로, 4와 Zero 2 W는 `gpio-shutdown` 오버레이와 GPIO 3의 버튼으로 끄고 켠다
- 내 프로그램은 SIGTERM을 받으면 하던 쓰기를 `fsync`까지 마치고 끝낸다
