SSH는 네트워크가 되어야 통합니다. Wi-Fi 암호를 잘못 넣었거나 보드가 켜지다 멈췄다면 SSH로는 무슨 일인지 알 길이 없습니다. 시리얼 콘솔은 네트워크와 상관없이 선 세 가닥으로 보드의 글자 화면을 PC로 가져옵니다. 커널이 켜지며 찍는 글이 그대로 보이고, 다 켜지면 로그인해서 명령을 칠 수 있습니다. 준비물은 [「케이블, 케이스, USB-시리얼 어댑터」](#/read/sbc-start/prt-cables)에서 고른 3.3V 어댑터입니다.

## 보드 쪽: 어디로 나오고 어떻게 켜나

| 보드 | 콘솔이 나오는 자리 | 리눅스에서의 이름 |
| --- | --- | --- |
| 5 | 두 micro HDMI 사이의 3핀 단자(UART라고 적혀 있다) | `/dev/ttyAMA10` |
| 4, Zero 2 W | 40핀 헤더의 8번 핀(TX)과 10번 핀(RX) | `/dev/ttyS0` |

- **`/dev/serial0`**: 보드마다 다른 이름을 감춰 주는 링크입니다. 어느 보드에서든 주로 쓰는 UART를 가리킵니다
- **콘솔을 붙이는 줄**: 부트 파티션의 `cmdline.txt`에 `console=serial0,115200`이 있으면 커널이 이 UART에 글을 찍고 로그인을 받습니다. 속도는 115200입니다
- **4와 Zero 2 W는 켜야 한다**: `config.txt`에 `enable_uart=1`을 적습니다. 이 보드들의 주 UART는 미니 UART라는 간단한 회로인데, 그 속도가 칩의 클럭을 따라가기 때문에 이 설정이 클럭을 고정해 줍니다
- **5는 단자가 따로 있다**: 5에서는 3핀 단자가 기본으로 주 UART입니다. `enable_uart=1`을 적으면 단자에 케이블이 꽂혀 있지 않을 때 콘솔이 헤더의 8번, 10번 핀으로 나옵니다

네트워크가 안 되는 보드에서는 이 설정을 보드 안에서 바꿀 수 없습니다. 카드를 뽑아 PC에 꽂으면 부트 파티션이 보이므로, 거기의 `config.txt`와 `cmdline.txt`를 편집기로 고칩니다. 보드에 들어갈 수 있을 때에는 `sudo raspi-config`의 Interface Options에 있는 Serial Port에서 켭니다.

## 선 잇기

| 어댑터 | 보드(4, Zero 2 W) |
| --- | --- |
| TX(내보내는 선) | 10번 핀(RX, GPIO 15) |
| RX(받는 선) | 8번 핀(TX, GPIO 14) |
| GND | 6번 핀(GND) |

- **엇갈려야 한다**: 한쪽의 TX가 다른 쪽의 RX로 갑니다
- **전원 선은 잇지 않는다**: 어댑터의 5V나 3.3V 선은 비워 둡니다
- **5와 Debug Probe**: Debug Probe의 U 포트와 5의 UART 단자를 3핀 케이블로 잇습니다. 방향이 정해진 단자라 엇갈릴 일이 없습니다
- **Debug Probe를 헤더에 꽂을 때**: 핀에 꽂는 케이블은 주황이 TX(프로브가 내보냄), 노랑이 RX(프로브가 받음), 검정이 GND입니다. 주황을 10번 핀에, 노랑을 8번 핀에 꽂습니다

## PC에서 열기

어댑터를 PC에 꽂으면 시리얼 포트가 하나 생깁니다. 터미널 프로그램으로 그 포트를 115200의 속도로 엽니다.

```sh
ls /dev/ttyUSB* /dev/ttyACM*               # 리눅스: 방금 생긴 포트를 찾는다
sudo apt install minicom
minicom -b 115200 -o -D /dev/ttyUSB0       # 나갈 때는 Ctrl-A 를 누르고 X
```

| PC의 OS | 포트의 이름 | 여는 프로그램 |
| --- | --- | --- |
| 리눅스 | `/dev/ttyUSB0`, Debug Probe는 `/dev/ttyACM0` | `minicom` |
| macOS | `/dev/cu.usbmodem`으로 시작하는 이름 | `minicom` |
| Windows | 장치 관리자의 포트 항목에 보이는 COM 번호 | PuTTY 같은 터미널 프로그램 |

- **권한이 없다고 하면**: 리눅스에서는 시리얼 포트를 `dialout` 그룹이 씁니다. `sudo usermod -aG dialout $USER`로 나를 그룹에 넣고 로그아웃했다가 다시 들어옵니다
- **보드를 나중에 켠다**: 프로그램을 열어 둔 채로 보드의 전원을 넣으면 켜지는 과정이 처음부터 보입니다
- **로그인**: 글이 다 지나가고 `login:`이 뜨면 Imager에서 정한 사용자와 암호를 넣습니다. 그다음은 SSH로 들어온 것과 같은 셸입니다

## 안 될 때

| 증상 | 볼 것 |
| --- | --- |
| 아무것도 나오지 않는다 | TX와 RX가 뒤바뀌었는가, GND를 이었는가, 콘솔을 켰는가 |
| 깨진 글자가 나온다 | 속도가 115200인가, 4와 Zero 2 W에 `enable_uart=1`을 적었는가 |
| 보이기는 하는데 쳐지지 않는다 | 어댑터의 TX 선, 터미널 프로그램의 흐름 제어 설정 |

`minicom`에서 글자가 쳐지지 않으면 Ctrl-A를 누르고 O를 눌러 Serial port setup의 Hardware Flow Control을 꺼 봅니다. 선 세 가닥만 이은 연결에는 흐름 제어에 쓰는 선이 없습니다.

## 콘솔을 끄고 내 프로그램이 쓰기

헤더의 UART에 GPS 같은 장치를 붙여 내 프로그램이 읽으려면, 콘솔이 그 포트를 쥐고 있으면 안 됩니다. `raspi-config`의 Serial Port는 두 가지를 차례로 묻습니다.

- **시리얼로 로그인 셸을 받을 것인가**: 아니오라고 답합니다. 콘솔이 포트를 놓습니다
- **시리얼 포트 하드웨어를 켤 것인가**: 예라고 답합니다. 포트는 켜진 채로 남아 프로그램이 `/dev/serial0`을 열 수 있습니다

포트를 여는 코드는 [「UART」](#/read/c-mid/bus-uart)에 있습니다. 콘솔을 끄면 이 쪽의 비상구도 닫힌다는 것을 기억합니다.

<Note>
핀 번호, 장치 이름, 설정은 문서에서 옮겼고 보드에 이어 보지는 못했습니다. 흐름 제어와 `dialout` 이야기는 리눅스의 터미널 프로그램에서 흔히 겪는 일을 적은 것이라, 내 어댑터에서는 필요 없을 수 있습니다. 선을 꽂거나 옮길 때에는 보드의 전원을 뽑습니다.
</Note>

## 정리

- 시리얼 콘솔은 네트워크 없이 선 세 가닥으로 보드의 글자 화면에 들어가는 길이다
- 5는 3핀 UART 단자로, 4와 Zero 2 W는 헤더의 8번과 10번 핀으로 나오며 뒤의 둘은 `enable_uart=1`로 켠다
- 어댑터는 3.3V여야 하고, TX와 RX를 엇갈려 이은 뒤 PC에서 115200으로 연다
