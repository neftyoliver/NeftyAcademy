PC에서는 켤 때 키를 눌러 펌웨어의 설정 화면에 들어갑니다. 라즈베리파이에는 그 화면이 없고, 부트 파티션의 글 파일 둘이 그 일을 합니다. `config.txt`는 리눅스가 켜지기 전에 펌웨어가 읽는 하드웨어 설정이고, `cmdline.txt`는 커널에 넘기는 한 줄입니다. [「raspi-config」](#/read/sbc-start/cfg-raspi-config)가 고치는 것도 대부분 이 두 파일입니다.

## config.txt의 자리와 문법

- **자리**: 보드에서는 `/boot/firmware/config.txt`입니다. 카드를 PC에 꽂으면 부트 파티션의 맨 위에 보입니다. 이 파티션은 FAT이라 Windows에서도 열립니다
- **옛 글의 경로**: 북웜보다 앞선 판에서는 `/boot/config.txt`였습니다. 옛 글의 명령을 따라 할 때 경로를 바꿔 읽습니다
- **문법**: 한 줄에 `이름=값` 하나를 적습니다. `#`으로 시작하는 줄은 주석이고, 한 줄은 98자까지입니다
- **읽는 때**: 켜질 때 한 번 읽습니다. 고친 뒤에는 다시 시작해야 적용됩니다
- **지금 값 묻기**: `vcgencmd get_config usb_max_current_enable`처럼 이름을 주면 펌웨어가 쓰고 있는 값을 알려 줍니다

| 줄 | 하는 일 |
| --- | --- |
| `dtparam=i2c_arm=on` | 헤더의 I2C 버스를 켠다 |
| `dtparam=spi=on` | 헤더의 SPI 버스를 켠다 |
| `enable_uart=1` | 주 UART를 켠다 |
| `dtoverlay=vc4-kms-v3d` | 그래픽 드라이버를 올린다 |
| `camera_auto_detect=1` | 꽂힌 카메라를 알아서 찾는다 |
| `arm_boost=1` | 4의 클럭을 1.8GHz까지 올린다 |
| `usb_max_current_enable=1` | 5의 USB 전류 한도를 1.6A로 올린다 |
| `dtparam=pciex1` | 5의 PCIe 단자를 켠다 |

`dtparam`과 `dtoverlay`로 시작하는 줄은 [「dtoverlay로 기능 켜기」](#/read/sbc-start/cfg-overlays)에서 따로 봅니다.

## 보드를 가리는 조건 필터

대괄호로 싼 줄은 필터입니다. 그 아래의 줄들은 필터에 맞는 보드에서만 적용됩니다. 카드 한 장을 여러 보드에 번갈아 꽂거나 같은 이미지를 여러 보드에 복사해 쓸 때, 파일 하나로 보드마다 다른 설정을 줄 수 있습니다. 아래 예제는 이 규칙을 흉내 내서, 같은 파일이 세 보드에서 어떻게 읽히는지 보여 줍니다.

```c
// config.txt 의 조건 필터를 흉내 낸다: 어느 줄이 어느 보드에 적용되는지 가른다
#include <stdio.h>
#include <string.h>

static const char* config[] = {
    "dtparam=i2c_arm=on",
    "[pi5]",
    "dtparam=pciex1",
    "usb_max_current_enable=1",
    "[pi4]",
    "arm_boost=1",
    "[pi0]",
    "enable_uart=1",
    "[none]",
    "dtoverlay=disable-bt",
    "[all]",
    "dtparam=spi=on",
};

struct board {
    const char* name;
    const char* reads[4];                    // 이 보드가 읽는 모델 필터들
};

static bool reads(const struct board* b, const char* filter) {
    for (int i = 0; i < 4 && b->reads[i]; ++i)
        if (strcmp(b->reads[i], filter) == 0) return true;
    return false;
}

int main(void) {
    const struct board boards[] = {
        {"5", {"pi5"}},
        {"400", {"pi400", "pi4"}},
        {"Zero 2 W", {"pi02", "pi0w", "pi0"}},
    };
    for (size_t b = 0; b < sizeof boards / sizeof boards[0]; ++b) {
        bool on = true;                      // 필터 앞의 줄은 모든 보드의 것
        printf("%s\n", boards[b].name);
        for (size_t i = 0; i < sizeof config / sizeof config[0]; ++i) {
            const char* line = config[i];
            if (line[0] != '[') {
                if (on) printf("  %s\n", line);
                continue;
            }
            char name[16] = "";              // [pi5] 에서 pi5 만 떼어 낸다
            sscanf(line, "[%15[^]]", name);
            // [all] 은 모두에게, [none] 은 아무에게도, 나머지는 읽는 보드에게만
            on = strcmp(name, "all") == 0 || reads(&boards[b], name);
        }
    }
}
```

```text
5
  dtparam=i2c_arm=on
  dtparam=pciex1
  usb_max_current_enable=1
  dtparam=spi=on
400
  dtparam=i2c_arm=on
  arm_boost=1
  dtparam=spi=on
Zero 2 W
  dtparam=i2c_arm=on
  enable_uart=1
  dtparam=spi=on
```

- **필터는 다음 필터가 나올 때까지 이어진다**: `[pi5]` 아래의 두 줄은 5에서만 적용됩니다
- **위 세대의 필터도 읽는다**: 400은 `[pi400]`과 함께 `[pi4]`도 읽고, Zero 2 W는 `[pi02]`와 함께 `[pi0w]`와 `[pi0]`도 읽습니다. `[pi4]`는 4 Model B, 400, CM4에 모두 적용됩니다
- **`[all]`로 풀어 준다**: 앞의 필터를 모두 지웁니다. 필터로 묶은 줄들 뒤에는 `[all]`을 적어 두는 버릇을 들입니다. 빠뜨리면 파일 끝에 덧붙인 줄이 마지막 필터에 갇힙니다
- **`[none]`**: 아래의 줄을 어느 보드에도 적용하지 않습니다. 줄마다 `#`을 붙이지 않고 한 덩어리를 꺼 둘 때 씁니다
- **다른 종류의 필터**: 보드의 일련번호를 적는 `[0x12345678]`, 핀의 상태를 보는 `[gpio4=1]`도 있습니다. 종류가 다른 필터를 이어 쓰면 둘 다 맞을 때에만 적용됩니다

## cmdline.txt

`/boot/firmware/cmdline.txt`는 커널이 켜질 때 받는 인자들입니다. 빈칸으로 띄운 낱말들이 한 줄에 이어져 있습니다.

| 낱말 | 뜻 |
| --- | --- |
| `console=serial0,115200` | 켜지며 찍는 글을 시리얼 포트로 보낸다 |
| `console=tty1` | 같은 글을 화면으로도 보낸다 |
| `root=` | 루트 파일 시스템이 있는 파티션 |
| `rootfstype=ext4` | 그 파티션의 형식 |
| `quiet` | 심각한 것만 찍는다 |

- **모두 한 줄이어야 한다**: 문서는 줄을 바꾸면 커널이 첫 줄 뒤의 것을 모두 무시한다고 적습니다. 편집기가 줄 끝에서 저절로 꺾어 보여 주는 것과 진짜 줄 바꿈을 헷갈리지 않습니다
- **실제로 받은 줄**: `cat /proc/cmdline`으로 봅니다. 펌웨어가 몇 가지를 덧붙여 넘기므로 파일과 똑같지는 않습니다
- **자주 고치는 것**: 시리얼 콘솔을 쓰려고 `console=serial0,115200`을 넣거나 빼는 일([「시리얼 콘솔」](#/read/sbc-start/rem-serial)), 켜지는 과정을 다 보려고 `quiet`를 빼는 일입니다

## 망쳤을 때

- **고치기 전에 복사해 둔다**: `sudo cp /boot/firmware/config.txt /boot/firmware/config.txt.bak`
- **한 번에 하나만 바꾼다**: 한 줄을 바꾸고 다시 켜서 확인합니다. 여러 줄을 한꺼번에 바꾸면 어느 줄이 문제인지 알 수 없습니다
- **켜지지 않으면 카드를 PC로**: 설정을 잘못 적어 보드가 켜지지 않아도 카드는 멀쩡합니다. PC에 꽂아 부트 파티션의 파일을 되돌립니다
- **5의 config.txt는 비워 두지 않는다**: 문서는 5에서 이 파일이 비어 있으면 안 된다고 적습니다

<Note>
예제는 모델 필터와 `[all]`, `[none]`만 흉내 낸 것입니다. 실제 펌웨어에는 필터의 종류가 더 있고, 예제의 설정 줄도 한 파일에 함께 둘 까닭이 있어서가 아니라 규칙을 보이려고 고른 것입니다. 보드에서 돌려 확인하지는 못했으므로, 내 파일이 뜻대로 읽혔는지는 `vcgencmd get_config`로 값을 물어 확인합니다.
</Note>

## 정리

- `config.txt`는 펌웨어가 켜질 때 읽는 `이름=값`의 목록이고, 고친 뒤에는 다시 시작해야 한다
- 대괄호 필터 아래의 줄은 맞는 보드에서만 적용되고, `[all]`이 필터를 푼다
- `cmdline.txt`는 커널이 받는 한 줄이다. 줄을 바꾸지 않는다
