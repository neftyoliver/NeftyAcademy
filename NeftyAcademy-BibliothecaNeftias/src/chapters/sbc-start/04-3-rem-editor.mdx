## VS Code Remote - SSH

VS Code는 화면을 그리는 부분과 일을 하는 부분으로 나뉘어 있습니다. Remote - SSH 확장은 일을 하는 부분(VS Code Server)을 보드에 깔고, PC의 창이 SSH로 거기에 붙게 합니다. 파일을 열고 저장하는 것, 터미널, 확장이 모두 보드에서 돕니다.

1. PC의 VS Code에 Remote - SSH 확장을 깝니다
2. 터미널에서 `ssh sensor`로 들어가지는지 먼저 확인합니다([「SSH와 키 인증」](#/read/sbc-start/rem-ssh))
3. 명령 팔레트에서 "Remote-SSH: Connect to Host..."를 골라 같은 호스트를 넣습니다
4. 처음 붙을 때 VS Code Server가 보드에 깔립니다. 보드가 직접 받고, 안 되면 PC가 받아 넘겨줍니다
5. File 메뉴의 Open으로 보드의 폴더를 엽니다

- **터미널은 보드의 셸이다**: 붙은 창에서 여는 터미널은 보드에서 돕니다. 빌드와 실행을 그 자리에서 합니다
- **확장도 보드에 깐다**: 테마 같은 것은 PC에 남고, C 언어 지원 같은 확장은 보드 쪽에 깔아야 합니다. 확장 목록에서 Install을 누르면 알맞은 쪽에 깔립니다
- **포트 넘겨받기**: 보드에서 띄운 웹 서버를 PC의 브라우저로 보고 싶으면 "Forward a Port"로 보드의 포트를 PC의 `localhost`에 잇습니다
- **끝내기**: File 메뉴의 Close Remote Connection입니다

요구 사양이 이 방식의 조건입니다.

- **램 1GB가 최소다**: 문서는 원격 쪽에 램 1GB가 필요하고, 2GB와 코어 둘 이상을 권한다고 적습니다. 512MB인 Zero 2 W는 이 조건에 못 미칩니다
- **보드의 자원을 쓴다**: 서버와 확장이 보드의 램과 CPU로 돕니다. 램이 빠듯한 보드에서는 내 프로그램이 쓸 몫이 줄어듭니다
- **Arm에서 안 되는 확장이 있다**: 문서는 x86용 코드를 품은 확장이 Arm 호스트에서 돌지 않을 수 있다고 적습니다

## CLion: Remote with local sources

CLion의 이 방식은 반대로 갑니다. IDE는 PC에서 돌고 소스도 PC에 둡니다. CLion이 소스를 보드로 맞춰 보내고, 빌드와 디버깅과 실행만 보드에서 합니다. JetBrains의 문서는 라즈베리파이 같은 싱글 보드 컴퓨터도 대상이 된다고 적습니다.

1. 보드에 빌드 도구를 깝니다. `sudo apt install build-essential cmake gdb rsync`
2. Settings의 Build, Execution, Deployment 아래 Toolchains에서 더하기를 눌러 Remote Host를 고릅니다
3. Credentials에서 보드의 SSH 접속 정보를 고르거나 새로 만듭니다. CLion이 보드에서 CMake와 GDB를 찾습니다
4. 같은 자리의 CMake에서 프로필의 Toolchain을 방금 만든 것으로 바꿉니다

- **맞추는 방법**: macOS와 리눅스에서는 `rsync`로 맞춥니다. Windows에서는 기본이 `tar`로 묶어 보내는 방식이라 더 느리고, 배포 설정에서 rsync를 쓰도록 바꿀 수 있습니다
- **보드의 헤더를 가져온다**: CLion은 보드의 헤더 경로를 PC로 가져와서, 보드에 깔린 라이브러리의 선언으로 바로 갈 수 있게 합니다. 보드에 라이브러리를 새로 깔았다면 Tools 메뉴의 Resync with Remote Hosts를 한 번 누릅니다
- **Makefile 프로젝트**: CMake 대신 Makefile 쪽 설정에서 같은 툴체인을 고릅니다
- **이름이 비슷한 다른 기능**: JetBrains에는 IDE의 뒷부분까지 원격에서 돌리는 Remote Development도 있습니다. 이쪽은 코어 넷과 램 8GB를 요구하고, 문서가 라즈베리파이 같은 보드는 대상이 아니라고 적습니다

## 편집기를 붙이지 않는 길

- **PC에서 고치고 보낸다**: 어떤 편집기로든 PC에서 고치고 [「파일 옮기기: scp, rsync, sshfs」](#/read/sbc-start/rem-files)의 세 줄로 보내서 돌립니다. 보드에 아무것도 깔지 않아도 되고, 가장 약한 보드에서도 됩니다
- **보드에서 바로 고친다**: 설정 파일의 한두 줄은 SSH로 들어가 `nano`로 고치는 것이 가장 빠릅니다

## 보드에 맞게 고르기

| 보드 | 권하는 길 |
| --- | --- |
| 램 2GB 이상의 5와 4 | VS Code Remote - SSH, 또는 CLion의 원격 툴체인 |
| Zero 2 W | PC에서 교차 컴파일해서 보낸다 |
| 어느 보드든 설정 한두 줄 | SSH로 들어가 `nano` |

보드에서 빌드하는 방식은 설정이 쉽지만 보드가 느릴수록 기다리는 시간이 깁니다. 프로젝트가 커지면 [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)로 넘어가 PC에서 빌드합니다.

## 정리

- VS Code Remote - SSH는 편집기의 일하는 부분을 보드에서 돌린다. 보드에 램 1GB 이상이 있어야 한다
- CLion의 Remote with local sources는 소스를 PC에 두고 보드로 맞춰 보낸 뒤 보드에서 빌드하고 디버깅한다
- 약한 보드에서는 PC에서 고치고 교차 컴파일해서 보내는 길이 가장 가볍다
