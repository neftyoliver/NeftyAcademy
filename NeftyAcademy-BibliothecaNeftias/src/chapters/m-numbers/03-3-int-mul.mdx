음수에 음수를 곱하면 왜 양수일까요. 누가 그렇게 정한 것은 맞지만, 마음대로 정한 것은 아닙니다. 자연수에서 성립하던 법칙을 정수에서도 지키려면 답이 하나로 정해집니다. 이 쪽은 그 까닭을 세 가지로 봅니다.

## 양수와 음수의 곱

곱셈은 같은 수를 거듭 더하는 것이었습니다. 음수를 거듭 더해도 됩니다.

$$
3 \times (-2) = (-2) + (-2) + (-2) = -6
$$

$(-2) \times 3$은 "$-2$번 더한다"로는 읽을 수 없습니다. 교환법칙을 지키려면 $3 \times (-2)$와 같은 $-6$이어야 합니다. 곱하는 수를 하나씩 줄여 가는 규칙으로 보아도 같은 답이 나옵니다.

| 곱 | 값 | 바로 윗줄과의 차 |
| --- | --- | --- |
| $2 \times 3$ | 6 | |
| $1 \times 3$ | 3 | 3 줄었다 |
| $0 \times 3$ | 0 | 3 줄었다 |
| $(-1) \times 3$ | $-3$ | 3 줄었다 |
| $(-2) \times 3$ | $-6$ | 3 줄었다 |

## 음수와 음수의 곱: 이어지는 규칙

같은 표를 $-2$를 곱하는 것으로 만듭니다. 이번에는 2씩 늘어납니다.

| 곱 | 값 | 바로 윗줄과의 차 |
| --- | --- | --- |
| $2 \times (-2)$ | $-4$ | |
| $1 \times (-2)$ | $-2$ | 2 늘었다 |
| $0 \times (-2)$ | 0 | 2 늘었다 |
| $(-1) \times (-2)$ | 2 | 2 늘었다 |
| $(-2) \times (-2)$ | 4 | 2 늘었다 |

규칙이 0을 지나서도 이어지려면 $(-1) \times (-2) = 2$여야 합니다.

## 음수와 음수의 곱: 분배법칙이 정한다

규칙이 이어진다는 것은 짐작입니다. 분배법칙을 지키기로 하면 짐작이 아니라 증명이 됩니다.

<Thm title="음수와 음수의 곱">
정수의 셈에서 분배법칙이 성립하면 $(-a)(-b) = ab$입니다.
</Thm>

<Proof>

두 수 $(-a)(-b)$와 $ab$가 모두 $(-a)b$의 반대인 수임을 보입니다.

$$
\begin{aligned}
(-a)(-b) + (-a)b &= (-a)\bigl((-b) + b\bigr) \\
&= (-a) \times 0 = 0 \\
ab + (-a)b &= \bigl(a + (-a)\bigr)b \\
&= 0 \times b = 0
\end{aligned}
$$

어떤 수에 더해서 0이 되는 수는 하나뿐입니다. 그러므로 $(-a)(-b) = ab$입니다.

</Proof>

음수와 음수의 곱을 음수로 정하면 분배법칙이 깨집니다. 법칙을 지키는 답은 양수 하나뿐입니다.

## 음수와 음수의 곱: 뒤집기

수직선에서 $-1$을 곱하는 것은 0을 가운데 두고 뒤집는 것입니다. 2는 $-2$로, $-2$는 2로 갑니다.

<Figure caption="−1을 곱하면 0의 맞은편으로 갑니다. 두 번 곱하면 제자리로 돌아옵니다">
  <NumLine x={[-4.6, 4.6]} step={1} points={[{ at: 2, color: 1 }, { at: -2, color: 0 }]} jumps={[{ from: 2, to: -2, label: '×(−1)', color: 0, level: 1 }, { from: -2, to: 2, label: '×(−1)', color: 1, level: 0 }]} />
</Figure>

두 번 뒤집으면 제자리입니다. 그래서 $(-1) \times (-1) = 1$입니다. 뒤집기를 반 바퀴 돌리기로 보면, 반의 반 바퀴만 돌리는 곱셈도 생각할 수 있습니다. 그것이 허수입니다([「곱셈은 돌리고 늘리는 일」](#/read/m-complex-numbers/rotation)).

## 부호의 규칙

| 두 수의 부호 | 곱의 부호 | 보기 |
| --- | --- | --- |
| 같다 | 양 | $(-3) \times (-4) = 12$ |
| 다르다 | 음 | $(-3) \times 4 = -12$ |

- **절댓값은 절댓값끼리 곱한다**: 부호는 따로 정합니다
- **여러 수의 곱**: 음수가 짝수 개이면 양수, 홀수 개이면 음수입니다([「짝수와 홀수」](#/read/m-numbers/div-parity))
- **거듭제곱**: $(-2)^2 = 4$이고 $(-2)^3 = -8$입니다. 괄호 없이 $-2^2$이라고 적으면 $2^2$의 반대인 $-4$입니다. 지수를 먼저 셈하기로 약속했기 때문입니다
- **곱이 0이면**: $ab = 0$이면 $a$와 $b$ 가운데 적어도 하나는 0입니다. 방정식을 인수분해로 푸는 바탕입니다([「이차방정식」](#/read/m-equations/quadratic))

## 나눗셈

나눗셈은 곱셈을 거꾸로 묻는 것입니다. $a \div b$는 $b$에 곱해서 $a$가 되는 수입니다. 부호의 규칙은 곱셈과 같습니다.

$$
(-12) \div 3 = -4, \qquad (-12) \div (-3) = 4
$$

- **0을 나누기**: $0 \div 5 = 0$입니다. 5에 곱해서 0이 되는 수는 0입니다
- **0으로 나누기**: 할 수 없습니다. $5 \div 0$은 0에 곱해서 5가 되는 수인데 그런 수는 없습니다. $0 \div 0$은 0에 곱해서 0이 되는 수인데 모든 수가 그렇습니다. 어느 쪽이든 답을 하나로 정할 수 없습니다
- **나누어떨어지지 않으면**: $7 \div 2$의 답은 정수 안에 없습니다. 다음 장에서 수를 한 번 더 넓힙니다([「분수의 세 얼굴」](#/read/m-numbers/rat-fraction))

## 음수의 몫과 나머지

나머지를 0 이상으로 잡는 나눗셈 정리는 음수에서도 성립합니다([「몫과 나머지」](#/read/m-numbers/div-remainder)). $-17 = 5 \times (-4) + 3$이므로 몫은 $-4$, 나머지는 3입니다. 그런데 프로그래밍 언어의 나눗셈은 언어마다 다르게 정해져 있습니다.

```python
print(-17 // 5, -17 % 5)
```

```text
-4 3
```

```c
#include <stdio.h>

int main(void) {
    int q = -17 / 5;
    int r = -17 % 5;
    printf("%d %d\n", q, r);
}
```

```text
-3 -2
```

파이썬은 몫을 작은 쪽으로 내리고, C는 0 쪽으로 버립니다. 어느 쪽이든 $a = bq + r$은 성립합니다. $5 \times (-3) + (-2) = -17$입니다. 음수가 섞인 나머지를 쓸 때에는 언어의 규칙을 먼저 확인해야 합니다.

<Note>
두 표의 값과 차, 증명의 두 식(−20부터 20까지의 모든 $a$, $b$), 부호의 규칙, $(-2)^2$, $(-2)^3$, $-2^2$, 나눗셈의 두 식은 프로그램으로 확인했습니다. 파이썬 코드와 C 코드는 실제로 돌린 출력입니다(C는 GCC 14, C23). C의 정수 나눗셈이 0 쪽으로 버린다는 것은 C99부터 표준에 정해져 있습니다. 증명에서 쓴 "더해서 0이 되는 수는 하나뿐"은 덧셈의 결합법칙에서 나옵니다. $x$와 $y$가 모두 $c$의 반대인 수이면 $x = x + (c + y) = (x + c) + y = y$입니다.
</Note>

## 요점

- 부호가 같은 두 수의 곱은 양수, 다른 두 수의 곱은 음수이다. 절댓값은 절댓값끼리 곱한다
- 음수와 음수의 곱이 양수인 것은 분배법칙을 지키는 답이 그것 하나뿐이기 때문이다
- 0으로는 나눌 수 없다. 답이 없거나, 모든 수가 답이 되어 하나로 정할 수 없다
