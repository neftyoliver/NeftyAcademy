인자 하나로 부를 수 있는 생성자는 생성자이면서 동시에 **변환 규칙**입니다. `Loose(int)`가 있으면 컴파일러는 `int`가 필요한 자리가 아니라 `Loose`가 필요한 자리에도 `int`를 받아 줍니다. 편할 때도 있지만 대개는 사고의 씨앗입니다.

## 저절로 일어나는 변환

```cpp
#include <print>

struct Loose {
    Loose(int ms) : ms(ms) {}           // explicit 없음: int가 저절로 Loose가 된다
    int ms;
};

struct Strict {
    explicit Strict(int ms) : ms(ms) {}
    int ms;
};

void wait_loose(Loose d) { std::println("{}ms", d.ms); }
void wait_strict(Strict d) { std::println("{}ms", d.ms); }

int main()
{
    wait_loose(500);            // 된다. 500이 무엇인지 드러나지 않는다
    wait_loose('a');            // 이것도 된다: char → int → Loose
    // wait_strict(500);        // 오류
    wait_strict(Strict{500});   // 타입을 적어야 한다
}
```

```text
500ms
97ms
500ms
```

`wait_loose('a')`가 컴파일되는 것이 문제입니다. 컴파일러는 인자를 맞추려고 표준 변환 하나(`char` → `int`)와 사용자 정의 변환 하나(`int` → `Loose`)를 이어 붙입니다. 타입을 만들어 단위를 지키려던 뜻이 사라집니다.

## explicit

`explicit`을 붙인 생성자는 **적어서 부를 때만** 쓰입니다.

| 코드 | `explicit` 없음 | `explicit` |
| --- | --- | --- |
| `Strict a(500);` | 된다 | 된다 |
| `Strict b{500};` | 된다 | 된다 |
| `Strict c = 500;` | 된다 | 오류 |
| `wait(500);` | 된다 | 오류 |
| `return 500;` (반환 타입이 `Strict`) | 된다 | 오류 |
| `static_cast<Strict>(500)` | 된다 | 된다 |

**인자 하나짜리 생성자에는 기본으로 `explicit`을 붙입니다.** 빼는 것은 "이 둘은 같은 것의 다른 표기"라고 할 만할 때뿐입니다.

| 암시적 변환이 자연스러운 경우 | 예 |
| --- | --- |
| 문자열 상수 → 문자열 | `std::string s = "abc";` |
| 소유하는 것 → 그것을 보는 뷰 | `std::string` → `std::string_view`, `std::vector` → `std::span` |
| 정밀도만 다른 같은 수 | `float` → `double`을 감싼 타입 |

`std::vector<int> v = 10;`이 안 되는 것도 `std::vector`의 크기 생성자가 `explicit`이기 때문입니다. 10이 벡터로 바뀌는 것은 누구도 바라지 않습니다.

## 인자가 여럿이어도

기본 인자 때문에 인자 하나로 부를 수 있으면 변환 생성자입니다. 그리고 중괄호 목록에서는 인자가 여럿인 생성자도 암시적으로 쓰입니다.

```cpp nocheck
struct Size {
    Size(int w, int h = 1);         // Size s = 5; 가 된다
};

struct Point {
    Point(int x, int y);
};
void draw(Point p);
draw({1, 2});                       // Point가 암시적으로 만들어진다
```

`draw({1, 2})`가 편하다고 느껴지면 그대로 두고, 막고 싶으면 `explicit`을 붙입니다.

## 변환은 한 번만 이어진다

컴파일러가 스스로 끼워 넣는 사용자 정의 변환은 **한 번**까지입니다.

```cpp nocheck
struct A { A(int); };
struct B { B(A); };

void f(B);
f(1);           // 오류: int → A → B 는 두 번이다
f(A(1));        // 된다
```

## 반대 방향의 변환

생성자는 "다른 타입 → 내 타입"입니다. "내 타입 → 다른 타입"은 변환 연산자로 정의하고, 거기에도 `explicit`을 붙일 수 있습니다([「변환 연산자」](#/read/cpp-syntax/op-conversion)). `if (ptr)`처럼 `unique_ptr`를 조건에 쓸 수 있는 것이 `explicit operator bool` 덕분입니다.

<Note kind="tip">
컴파일러 경고로는 잡히지 않으므로 습관으로 들여야 합니다. clang-tidy의 `google-explicit-constructor` 검사가 빠뜨린 `explicit`을 찾아 줍니다.
</Note>

## 정리

- 인자 하나로 부를 수 있는 생성자는 암시적 변환 규칙이 된다
- 그런 생성자에는 `explicit`을 기본으로 붙인다
- 빼는 것은 두 타입이 사실상 같은 것을 나타낼 때만
