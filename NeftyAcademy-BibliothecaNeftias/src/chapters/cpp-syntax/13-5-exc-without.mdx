모든 실패가 예외감은 아닙니다. "설정 파일에 그 키가 없다", "입력이 숫자가 아니다"는 흔히 일어나고 부른 곳이 바로 처리합니다. 이런 실패는 **반환값의 타입**에 담습니다.

## optional과 expected

```cpp
#include <charconv>
#include <expected>
#include <optional>
#include <print>
#include <string>
#include <string_view>
#include <system_error>

enum class ParseError { empty, not_a_number, out_of_range };

std::expected<int, ParseError> parse_pin(std::string_view text)
{
    if (text.empty())
        return std::unexpected(ParseError::empty);

    int value = 0;
    const char* last = text.data() + text.size();
    auto [end, ec] = std::from_chars(text.data(), last, value);
    if (ec != std::errc{} || end != last)
        return std::unexpected(ParseError::not_a_number);
    if (value < 0 || value > 27)
        return std::unexpected(ParseError::out_of_range);
    return value;
}

std::optional<std::string> find_name(int pin)
{
    if (pin == 17)
        return "LED";
    return std::nullopt;
}

int main()
{
    for (std::string_view text : {"17", "abc", "99", ""}) {
        if (auto pin = parse_pin(text))
            std::println("'{}' -> {}", text, *pin);
        else
            std::println("'{}' -> 오류 {}", text, static_cast<int>(pin.error()));
    }

    std::println("{}", find_name(17).value_or("이름 없음"));
    std::println("{}", find_name(4).value_or("이름 없음"));

    auto doubled = parse_pin("12").transform([](int p) { return p * 2; });
    std::println("{}", doubled.value_or(-1));
}
```

```text
'17' -> 17
'abc' -> 오류 1
'99' -> 오류 2
'' -> 오류 0
LED
이름 없음
24
```

| 타입 | 담는 것 | 헤더 |
| --- | --- | --- |
| `std::optional<T>` | `T` 값, 또는 "없음" | `<optional>` (C++17) |
| `std::expected<T, E>` | `T` 값, 또는 **왜 없는지**를 말하는 `E` | `<expected>` (C++23) |

둘 다 값을 **안에 품습니다.** 힙 할당이 없고, 크기는 `T`(또는 `T`와 `E` 가운데 큰 쪽)에 표시 하나를 더한 정도입니다.

## 쓰는 법

| 식 | 뜻 |
| --- | --- |
| `if (r)`, `r.has_value()` | 값이 있는가 |
| `*r`, `r->멤버` | 값을 꺼낸다. 없는데 꺼내면 **정의되지 않은 동작** |
| `r.value()` | 값을 꺼낸다. 없으면 예외 (`bad_optional_access`, `bad_expected_access`) |
| `r.value_or(기본값)` | 있으면 그 값, 없으면 기본값 |
| `r.error()` | (`expected`만) 오류 값 |
| `return std::nullopt;` / `return std::unexpected(오류);` | 실패를 돌려준다 |
| `return 값;` | 성공을 돌려준다. 저절로 감싸진다 |

`if (auto pin = parse_pin(text))`처럼 `if` 안에서 받으면 검사를 건너뛸 수 없고, 변수가 그 `if` 안에서만 보입니다.

## 이어 붙이기

C++23부터 둘 다 "값이 있을 때만 다음 단계를 한다"를 이어 쓰는 멤버가 있습니다.

| 멤버 | 넘기는 함수 | 값이 없으면 |
| --- | --- | --- |
| `transform(f)` | `T`를 받아 **값**을 돌려준다 | 건너뛴다. 없음(오류)이 그대로 전해진다 |
| `and_then(f)` | `T`를 받아 **`optional`/`expected`** 를 돌려준다 | 건너뛴다 |
| `or_else(f)` | 없을 때 부른다. 대신할 것을 돌려준다 | `f`를 부른다 |
| `transform_error(f)` | (`expected`만) 오류의 타입을 바꾼다 | |

```cpp nocheck
auto name = parse_pin(text)                 // expected<int, ParseError>
    .and_then(check_reserved)               // int → expected<int, ParseError>
    .transform(to_bcm_number)               // int → int
    .transform([](int n) { return std::format("GPIO{}", n); });
```

단계 어느 곳에서 실패하든 그 오류가 끝까지 전해지고, 뒤의 단계는 불리지 않습니다. `if`를 단계마다 쓰는 것과 같은 일을 합니다.

## 무엇으로 알릴까

| 상황 | 방법 |
| --- | --- |
| 없을 수 있고, 까닭이 하나뿐이거나 중요하지 않다 | `std::optional<T>` |
| 실패의 까닭을 부른 곳이 알아야 한다 | `std::expected<T, E>` |
| 돌려줄 값이 없고 성공·실패만 있다 | `std::expected<void, E>`, 또는 `bool` |
| 드물고, 부른 곳이 처리할 수 없고, 여러 층을 올라가야 한다 | [예외](#/read/cpp-syntax/exc-basic) |
| 생성자의 실패 | 예외. 또는 생성자를 숨기고 `expected`를 돌려주는 [생성 함수](#/read/cpp-syntax/class-static) |
| 있을 수 없는 일 (버그) | `assert` |

`E`로는 위처럼 `enum class`를 쓰거나, OS 오류를 그대로 전할 때는 `std::error_code`(`<system_error>`, `errno`를 감싼 것)를 씁니다.

| | 예외 | `expected` |
| --- | --- | --- |
| 검사를 잊으면 | 위로 올라간다. 묻히지 않는다 | `*r`을 바로 쓰면 정의되지 않은 동작. [`[[nodiscard]]`](#/read/cpp-syntax/fn-attributes)가 버리는 것은 막아 준다 |
| 성공하는 길의 비용 | 거의 없다 | 반환할 때마다 검사 한 번 |
| 실패하는 길의 비용 | 크다 | 성공과 같다 |
| 서명에 드러나는가 | 아니다 | 그렇다 |
| `-fno-exceptions`에서 | 쓸 수 없다 | 쓸 수 있다 |

실패가 흔하면 `expected`, 드물면 예외가 대체로 맞습니다. 한 프로젝트 안에서는 층마다 정해 두고 섞지 않는 편이 읽기 좋습니다.

<Note>
`<expected>`는 GCC 12, Clang 16(libc++), Visual Studio 2022 17.3부터 있습니다. `expected`의 이어 붙이는 멤버들은 그보다 조금 뒤인 GCC 13, libc++ 17부터입니다. 그 전의 컴파일러를 써야 하면 같은 인터페이스의 `tl::expected` 라이브러리가 있습니다.
</Note>

## 정리

- `std::optional<T>`는 값 또는 없음, `std::expected<T, E>`는 값 또는 오류
- `if (auto r = f())`로 받아 검사하고 `*r`로 꺼낸다. `value_or`, `transform`, `and_then`으로 이어 쓴다
- 흔하고 바로 처리하는 실패는 반환 타입으로, 드물고 멀리 올라가는 실패는 예외로
