오래된 라이브러리, 벤더가 준 예제, 십 년 넘은 사내 코드는 C++11 이전의 문법으로 쓰여 있습니다. 새로 그렇게 쓸 일은 없지만 **읽을 줄은 알아야** 합니다. 이 챕터는 일부러 짧습니다.

## C++98의 모양

```cpp
#include <algorithm>
#include <cstdio>
#include <cstring>
#include <iostream>
#include <map>
#include <string>
#include <vector>

// 함수 객체: 람다가 없던 때에는 클래스를 따로 썼다
struct LongerThan {
    explicit LongerThan(std::size_t n) : n_(n) {}
    bool operator()(const std::string& s) const { return s.size() > n_; }
    std::size_t n_;
};

typedef std::map<std::string, std::vector<int> > Table;     // > > 사이의 빈칸

class Device {
public:
    Device() : buffer_(new char[16]) { std::strcpy(buffer_, "idle"); }
    ~Device() { delete[] buffer_; }
    const char* state() const { return buffer_; }

private:
    Device(const Device&);              // 선언만 하고 정의하지 않는다: 복사 금지
    Device& operator=(const Device&);
    char* buffer_;
};

int main()
{
    Table table;
    table["led"].push_back(17);
    table["button"].push_back(27);

    for (Table::const_iterator it = table.begin(); it != table.end(); ++it)
        std::cout << it->first << ' ' << it->second[0] << '\n';

    std::vector<std::string> names;
    names.push_back("gpio");
    names.push_back("i2c");
    std::cout << std::count_if(names.begin(), names.end(), LongerThan(3)) << '\n';

    Device* device = new Device;
    std::printf("%s\n", device->state());
    delete device;

    int* missing = NULL;
    std::cout << (missing == 0) << '\n';
}
```

```text
button 27
led 17
1
idle
1
```

`-std=c++98`로도, `-std=c++23`으로도 경고 없이 컴파일됩니다. C++은 옛 코드를 거의 깨뜨리지 않습니다.

## 읽는 법

| 옛 코드에서 보이는 것 | 뜻 | 지금은 |
| --- | --- | --- |
| `Table::const_iterator it = t.begin()` | 반복자의 타입을 다 적는다 | [`auto`, 범위 `for`](#/read/cpp-syntax/ft-vector) |
| `struct LongerThan { bool operator()(…) }` | 알고리즘에 넘길 함수 객체 | [람다](#/read/cpp-syntax/fn-lambda) |
| `typedef A B;` | 타입 별칭 | [`using B = A;`](#/read/cpp-syntax/tpl-alias) |
| `vector<int> >` | `>>`가 시프트로 읽히던 때의 빈칸 | 붙여 쓴다 |
| `private:`에 선언만 한 복사 생성자 | 복사 금지 | [`= delete`](#/read/cpp-syntax/sm-rules) |
| `new` / `delete`, `new[]` / `delete[]` | 손으로 하는 수명 관리 | [`unique_ptr`, `vector`, `string`](#/read/cpp-syntax/ft-ownership) |
| `NULL`, `0` | 널 포인터 | [`nullptr`](#/read/cpp-syntax/types-builtin) |
| `v.push_back(…)`을 여러 줄 | 초기화 목록이 없었다 | [`std::vector<int> v{1, 2, 3};`](#/read/cpp-syntax/types-init) |
| `enum Color { RED };`, `static const int N = 8;` | 범위 없는 열거형, 클래스 안 상수 | [`enum class`](#/read/cpp-syntax/types-enum), [`constexpr`](#/read/cpp-syntax/ct-constexpr) |
| `virtual void f();` (자식에서 `override` 없이) | 재정의인지 새 함수인지 알 수 없다 | [`override`](#/read/cpp-syntax/inh-virtual) |
| `void f() throw();`, `throw(std::bad_alloc)` | 예외 명세 | [`noexcept`](#/read/cpp-syntax/exc-noexcept) |
| `std::auto_ptr<T>` | 복사하면 소유권이 **옮겨 가는** 스마트 포인터 | `std::unique_ptr` |
| `std::bind1st`, `std::mem_fun`, `std::ptr_fun` | 함수를 조립하던 도구 | 람다 |
| `std::tr1::shared_ptr`, `boost::shared_ptr`, `boost::bind` | 표준에 들어오기 전의 것 | `std::`의 같은 이름 |
| `std::endl` | 줄을 바꾸고 **버퍼를 비운다** | `'\n'` |

같은 프로그램을 지금의 문법으로 쓰면 절반 길이가 됩니다. `Device`의 소멸자와 복사 금지 선언은 `std::string` 멤버 하나로 사라지고, `LongerThan`은 람다 한 줄이 됩니다.

## 새 표준으로 올릴 때

옛 코드를 `-std=c++17` 이상으로 컴파일하면 걸리는 것은 많지 않습니다.

| 걸리는 것 | 까닭 | 고치기 |
| --- | --- | --- |
| `std::auto_ptr`, `std::bind1st`, `std::random_shuffle` | C++17에서 삭제 | `unique_ptr`, 람다, `std::shuffle` |
| `throw(타입)` 명세 | C++17에서 삭제 | 지운다. 던지지 않는다는 뜻이면 `noexcept` |
| `register` | C++17에서 삭제 | 지운다 |
| `char* p = "text";` | C++11부터 오류 | `const char*` |
| 변수 이름으로 쓴 `nullptr`, `constexpr`, `concept`, `requires`, `char8_t` 등 | 키워드가 되었다 | 이름을 바꾼다 |
| `u8"…"` 리터럴 | C++20부터 타입이 `const char8_t[]` | `-fno-char8_t`, 또는 코드를 고친다 |
| `a == b`가 모호해졌다는 오류 | C++20의 [비교 연산자 다시 쓰기](#/read/cpp-syntax/op-compare)와 옛 `operator==`가 부딪친다 | `operator==`를 `const` 멤버로 바로잡는다 |

대부분은 컴파일러가 정확한 줄을 알려 줍니다.

## 한꺼번에 고치지 않는다

돌아가는 옛 코드를 통째로 새 문법으로 바꾸는 것은 대개 손해입니다. 위험한 것부터 고칩니다.

| 순서 | 고칠 것 | 까닭 |
| --- | --- | --- |
| 1 | 맨 `new`/`delete` → 스마트 포인터와 컨테이너 | 누수와 [수명 버그](#/read/cpp-syntax/ubc-lifetime)의 근원 |
| 2 | 재정의에 `override` 붙이기 | 조용히 어긋난 가상 함수를 찾아 준다 |
| 3 | `NULL` → `nullptr`, C 방식 변환 → 이름 있는 변환 | 오버로드와 변환의 사고를 줄인다 |
| 4 | 나머지(`auto`, 범위 `for`, 람다, `using`) | 읽기 좋아질 뿐이다. 그 파일을 고칠 일이 있을 때 함께 |

clang-tidy의 `modernize-*` 검사가 2~4를 **자동으로 고쳐** 줍니다(`modernize-use-override`, `modernize-use-nullptr`, `modernize-loop-convert`, `modernize-use-auto`, `modernize-use-using`, `modernize-make-unique` 등). 고치기 전에 테스트가 있어야 하고, 한 번에 검사 하나씩 적용하는 것이 안전합니다.

<Note>
`std::auto_ptr`은 `a = b;`가 `b`를 비워 버리는 타입이었습니다. 복사처럼 보이는 문법이 이동을 했고, 컨테이너에 넣으면 정렬 도중에 원소가 사라졌습니다. [우측값 참조](#/read/cpp-syntax/sm-rvalue)가 없던 언어에서 이동을 흉내 낸 결과입니다. C++11이 이동을 언어에 넣은 까닭을 가장 잘 보여 주는 유물입니다.
</Note>

## 정리

- 옛 코드는 지금도 컴파일된다. 반복자 타입, 함수 객체 클래스, 맨 `new`/`delete`, `NULL`이 표지다
- 새 표준으로 올릴 때 걸리는 것은 `auto_ptr`, `throw()` 명세, `register` 정도다
- 위험한 것(수명 관리)부터 고치고, 모양만 낡은 것은 clang-tidy에 맡긴다
