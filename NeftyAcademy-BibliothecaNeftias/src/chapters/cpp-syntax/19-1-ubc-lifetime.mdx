C++ 프로그램의 심각한 버그 가운데 가장 큰 몫이 이것입니다. 객체는 사라졌는데 그것을 가리키는 포인터, 참조, 뷰가 **남아서 쓰입니다.** [C에서 본 정의되지 않은 동작](#/read/c-basic/ub-what)에, C++은 참조와 뷰와 람다라는 새 길을 더했습니다.

## 여섯 가지 길

```cpp nocheck
// 1. 지역 변수의 참조나 포인터를 돌려준다
const std::string& name()
{
    std::string local = "gpio";
    return local;               // 돌려주는 순간 local은 죽는다
}

// 2. 지운 뒤에 쓴다
auto p = std::make_unique<Sensor>();
Sensor* raw = p.get();
p.reset();
raw->read();                    // 이미 해제된 메모리

// 3. 임시 객체를 가리키는 뷰
std::string_view view = make_name();        // 문자열은 이 줄에서 죽는다

// 4. 컨테이너가 옮겨 간 뒤의 참조
int& first = values[0];
values.push_back(1);            // 재할당되면 first는 옛 메모리를 가리킨다

// 5. 람다가 품은 참조
auto later = [&count] { return count; };    // count보다 오래 살면

// 6. 객체보다 오래 사는 this
timer.every(1s, [this] { tick(); });        // 이 객체가 먼저 죽으면
```

모양은 달라도 뿌리는 하나입니다. **가리키는 쪽이 가리켜지는 쪽보다 오래 삽니다.**

## 그럴듯하게 돌아간다

이 버그가 고약한 것은 대개 **티가 나지 않기** 때문입니다.

| 일어나는 일 | 까닭 |
| --- | --- |
| 옳은 값이 읽힌다 | 해제된 메모리에 옛 바이트가 그대로 남아 있다 |
| 가끔만 틀린다 | 그 자리를 다른 객체가 다시 쓴 뒤에야 값이 바뀐다 |
| 디버그 빌드에서는 되고 릴리스에서 죽는다 | 최적화가 스택 배치와 순서를 바꾼다 |
| 엉뚱한 곳에서 죽는다 | 죽은 포인터로 **쓴** 것이 남의 객체를 망가뜨리고, 한참 뒤에 그 객체가 쓰일 때 드러난다 |

"돌려 보니 되더라"는 아무것도 증명하지 못합니다. 컴파일러는 수명이 끝난 객체에 대한 접근이 **없다고 가정**하고 최적화하므로, 결과는 컴파일러 버전과 옵션에 따라 얼마든지 달라집니다.

## 옮겨진 뒤

[`std::move`된 객체](#/read/cpp-syntax/sm-move)는 죽지 않았습니다. 수명은 이어지고 소멸자도 불립니다. 다만 **값이 정해져 있지 않습니다.**

| 옮겨진 객체에 해도 되는 일 | 하면 안 되는 일 |
| --- | --- |
| 소멸 (저절로 된다) | 값이 남아 있으리라 기대하기 |
| 새 값을 대입하기 | 사전 조건이 있는 함수 부르기 (`front()`, `*ptr`) |
| `clear()`, `empty()` 등 조건 없는 함수 | |

표준 라이브러리 타입에서 이것은 정의되지 않은 동작이 아니라 **논리 버그**입니다. `std::unique_ptr`은 옮겨지면 `nullptr`이 된다고 정해져 있고, 그것을 `*`로 읽으면 그때 정의되지 않은 동작이 됩니다. clang-tidy의 `bugprone-use-after-move`가 찾아 줍니다.

## 초기화하지 않은 값

객체가 **아직 값을 갖지 않았을 때** 읽는 것도 수명 문제의 사촌입니다.

```cpp nocheck
int count;              // 값이 정해지지 않았다
if (ready)
    count = 10;
total += count;         // ready가 거짓이면 쓰레기를 읽는다
```

지역 변수는 선언할 때 초기화합니다(`int count = 0;` 또는 `int count{};`). 클래스 멤버는 [선언에 기본값](#/read/cpp-syntax/class-ctor)을 적습니다. `-Wall`의 `-Wuninitialized`와 `-Wmaybe-uninitialized`가 일부를 잡습니다. C++26은 이 읽기를 "정의되지 않은 동작"에서 한 단계 낮은 **잘못된 동작**(erroneous behavior)으로 바꿉니다. 값은 여전히 믿을 수 없지만 컴파일러가 그것을 빌미로 코드를 지워 버리지는 못합니다([「C++26」](#/read/cpp-syntax/ver-26)).

## 구조로 막는다

검사 도구보다 먼저, **죽은 것을 가리킬 수 없는 꼴**로 코드를 짭니다.

| 지침 | 막는 것 |
| --- | --- |
| 함수는 **값으로** 돌려준다 | 1. [복사는 생략되거나 이동이다](#/read/cpp-syntax/sm-elision) |
| 소유는 `unique_ptr`과 컨테이너가 한다. 맨 포인터는 "빌려 보기"에만 | 2 |
| `string_view`, `span`은 **매개변수로만.** 변수와 멤버로 보관하지 않는다 | 3 |
| 컨테이너를 고치는 동안에는 그 원소의 참조와 반복자를 들고 있지 않는다 | 4 |
| 보관될 람다는 값으로 캡처한다 | 5 |
| 콜백을 등록한 객체는 소멸자에서 등록을 푼다 | 6 |
| 참조 멤버를 가진 클래스를 만들지 않는다. 꼭 필요하면 수명을 주석으로 적는다 | 전부 |
| 수명이 얽히면 `shared_ptr`과 `weak_ptr`로 **수명 자체를 공유**한다 | 2, 6 |

마지막 줄은 최후의 수단입니다. 누가 주인인지 분명한 설계가 먼저입니다.

## 도구

| 도구 | 잡는 것 |
| --- | --- |
| `-Wall -Wextra` | `-Wreturn-local-addr`(1), `-Wdangling-reference`(3의 일부, GCC 13부터), `-Wuse-after-free`(2의 일부), `-Wuninitialized` |
| Clang `-Wall` | `-Wreturn-stack-address`, `-Wdangling`, `-Wdangling-gsl`. `string_view` 쪽은 GCC보다 잘 잡는다 |
| [AddressSanitizer](#/read/cpp-syntax/ubc-tools) | 실행 중에 1~6 대부분. 그 줄이 **실행되어야** 잡힌다 |
| clang-tidy | `bugprone-dangling-handle`, `bugprone-use-after-move` 등 |

컴파일러 경고는 한 함수 안에서 보이는 것만 잡습니다. 수명이 함수 경계를 넘으면 조용해집니다. 그래서 **새니타이저를 켠 채로 도는 테스트**가 실질적인 방어선입니다.

<Note>
"가리키는 것이 가리켜지는 것보다 오래 살 수 없다"를 컴파일러가 증명하게 만든 언어가 Rust입니다. C++에서는 그 규칙을 사람이 지키고 도구가 돕습니다. 위 표의 지침들은 Rust의 대여 규칙을 손으로 따르는 것과 거의 같습니다.
</Note>

## 정리

- 수명 버그는 가리키는 쪽이 가리켜지는 쪽보다 오래 사는 것. 참조, 포인터, 뷰, 반복자, 람다가 모두 길이 된다
- 대개 그럴듯하게 돌아간다. 돌아간다고 옳은 것이 아니다
- 값으로 돌려주고, 소유를 분명히 하고, 뷰는 매개변수로만. 그 위에 새니타이저 테스트를 얹는다
