export const summary = '다른 파일의 전역 변수가 아직 만들어지지 않았을 때, 세 가지 해결, 끝날 때의 같은 문제';

전역 변수의 생성자는 `main` 전에 실행됩니다. 한 파일 안에서는 **적힌 순서대로**입니다. 그런데 **서로 다른 파일**의 전역 변수 사이에는 순서가 정해져 있지 않습니다.

## 재현

```cpp nocheck
// config.cpp
#include <vector>

std::vector<int> default_pins{17, 27, 22};      // main 전에 생성자가 실행된다
```

```cpp nocheck
// monitor.cpp
#include <cstddef>
#include <vector>

extern std::vector<int> default_pins;

// default_pins가 이미 만들어져 있을까?
std::size_t pin_count = default_pins.size();
```

```cpp nocheck
// main.cpp
#include <cstddef>
#include <print>

extern std::size_t pin_count;

int main()
{
    std::println("{}", pin_count);
}
```

```text
$ g++ -std=c++23 config.cpp monitor.cpp main.cpp && ./a.out
3
$ g++ -std=c++23 monitor.cpp config.cpp main.cpp && ./a.out
0
```

파일을 적는 **순서만** 바꿨습니다. 둘째 빌드에서는 `monitor.cpp`의 초기화가 먼저 돌았고, 그때 `default_pins`는 아직 생성자가 불리지 않은, 0으로 채워진 메모리였습니다. `size()`는 0을 돌려주었습니다. 운이 좋은 경우입니다. `default_pins.at(0)`이었다면 `main`에 들어가기도 전에 죽습니다.

GCC는 링크할 때 적힌 순서로 초기화하지만, 그것은 약속된 동작이 아닙니다. 빌드 도구가 파일 순서를 바꾸거나 라이브러리로 묶는 순간 달라집니다.

## 두 단계

정적 변수의 초기화는 두 번에 나뉩니다.

| 단계 | 언제 | 해당하는 것 | 순서 문제 |
| --- | --- | --- | --- |
| 정적 초기화 | 컴파일할 때. 실행 파일에 박혀 있다 | 상수로 초기화되는 것, 나머지는 0으로 | **없다** |
| 동적 초기화 | `main` 전에 코드가 실행된다 | 생성자나 함수 호출이 필요한 것 | 파일 사이에 있다 |

문제는 둘째 단계에만 있습니다. 해결은 "첫 단계로 옮기거나, 순서를 스스로 정하거나"입니다.

## 해결 1: 컴파일할 때 초기화

값이 컴파일할 때 정해질 수 있으면 [`constexpr`이나 `constinit`](#/read/cpp-syntax/ct-consteval)으로 만듭니다. 실행 파일에 값이 이미 들어 있으므로 순서가 없습니다.

```cpp nocheck
// config.h
#pragma once
#include <array>

inline constexpr std::array default_pins{17, 27, 22};
```

`std::vector`는 힙을 쓰므로 이렇게 할 수 없고, `std::array`는 됩니다. 고칠 수 있어야 하면 `constinit`을 씁니다. 컴파일할 때 초기화되지 **못하면 오류**가 나므로, "이 전역은 순서 문제가 없다"를 컴파일러가 보증해 줍니다.

## 해결 2: 함수 안의 static

[`static` 지역 변수](#/read/cpp-syntax/life-storage)는 **처음 불릴 때** 초기화됩니다. 전역 변수를 "그 변수를 돌려주는 함수"로 바꾸면 쓰는 쪽이 먼저 불러도 그 순간에 만들어집니다.

```cpp nocheck
// config.cpp
#include <vector>

const std::vector<int>& default_pins()
{
    static const std::vector<int> pins{17, 27, 22};     // 처음 불릴 때 만들어진다
    return pins;
}
```

```cpp nocheck
// monitor.cpp
const std::vector<int>& default_pins();

std::size_t pin_count = default_pins().size();          // 언제 불러도 3
```

어느 순서로 빌드해도 3이 나옵니다. 스레드에도 안전합니다. 전역 객체가 꼭 필요할 때의 표준적인 꼴입니다.

## 해결 3: 전역을 두지 않는다

가장 근본적인 해결입니다. 필요한 객체를 `main`에서 만들고, 쓰는 쪽에 **인자로 넘깁니다.**

```cpp nocheck
int main()
{
    Config config = load_config();
    Monitor monitor(config);        // 순서가 코드에 드러난다
    monitor.run();
}
```

순서가 눈에 보이고, 시험할 때 다른 `Config`를 끼워 넣을 수 있고, 초기화 실패를 `main`에서 [예외로 잡을](#/read/cpp-syntax/exc-basic) 수 있습니다. 전역 생성자가 던진 예외는 잡을 곳이 없어 프로그램이 그대로 끝납니다.

## 끝날 때도 같다

정적 객체는 `main`이 끝난 뒤 **만들어진 거꾸로 순서**로 소멸합니다. 다른 파일의 전역 객체 사이에서는 이 순서도 알 수 없습니다. 어떤 전역 객체의 소멸자가 **이미 소멸한** 다른 전역 객체를 쓰면 같은 사고가 납니다. 전역 로거가 흔한 희생자입니다. 다른 객체들의 소멸자가 마지막 로그를 남기려 할 때 로거는 이미 없습니다.

| 대책 | 방법 |
| --- | --- |
| 소멸자에서 다른 전역을 쓰지 않는다 | 가장 깔끔하다 |
| 일부러 소멸시키지 않는다 | `static Logger* log = new Logger;` 프로그램이 끝날 때 OS가 메모리를 거둔다 |
| `main`에서 만든다 | 지역 변수의 소멸 순서는 정해져 있다 |

## 찾기

AddressSanitizer에 옵션을 주면 초기화 중에 **아직 초기화되지 않은 다른 파일의 전역**을 건드리는 것을 잡습니다.

```text
$ g++ -std=c++23 -g -fsanitize=address monitor.cpp config.cpp main.cpp
$ ASAN_OPTIONS=check_initialization_order=1 ./a.out
ERROR: AddressSanitizer: initialization-order-fiasco on address 0x5604c36a9e68
    #0 std::vector<int>::size() const
    #1 __static_initialization_and_destruction_0 monitor.cpp:7
0x5604c36a9e68 is located 8 bytes inside of global variable 'default_pins'
defined in 'config.cpp:3:18'
```

<Note>
같은 실험을 `std::string app_name = "blink";`으로 하면 GCC 14에서는 문제가 드러나지 않습니다. C++20부터 `std::string`의 생성자가 `constexpr`이라서, 짧은 문자열은 컴파일러가 컴파일할 때 초기화해 버리기 때문입니다. 표준이 보장하는 동작은 아닙니다. 기대려면 `constinit std::string app_name = "blink";`이라고 적어 컴파일러에게 확인시킵니다. 긴 문자열은 힙이 필요해서 `constinit`이 오류가 됩니다.
</Note>

## 정리

- 다른 파일의 전역 변수 사이에는 초기화 순서가 없다. 먼저 쓰면 0으로 채워진 메모리를 본다
- 상수로 만들 수 있으면 `constexpr`/`constinit`, 아니면 함수 안의 `static`, 가장 좋은 것은 `main`에서 만들어 넘기기
- 소멸도 거꾸로 순서로 같은 문제를 겪는다
