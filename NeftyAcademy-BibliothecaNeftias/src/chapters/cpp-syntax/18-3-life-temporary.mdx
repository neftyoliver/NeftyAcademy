export const summary = '이름 없는 객체는 문장 끝에서 사라진다, 참조로 연장되는 경우와 아닌 경우, 흔한 함정 넷';

`make("temp")`처럼 함수가 돌려준 값, `a + b`의 결과, `std::string("x")`처럼 그 자리에서 만든 객체는 **이름이 없습니다.** 이런 임시 객체의 수명은 짧고, 그 규칙을 모르면 죽은 객체를 가리키게 됩니다.

## 문장 끝까지

```cpp
#include <cstddef>
#include <print>
#include <string>
#include <utility>

struct Trace {
    std::string name;
    explicit Trace(std::string n) : name(std::move(n))
    {
        std::println("+ {}", name);
    }
    ~Trace() { std::println("- {}", name); }
    const std::string& label() const { return name; }
};

Trace make(const char* name) { return Trace{name}; }

int main()
{
    std::println("1");
    make("temp");                               // 이 줄의 끝(;)에서 사라진다
    std::println("2");
    const Trace& kept = make("kept");           // 참조에 직접 묶으면 참조만큼 산다
    std::println("3 {}", kept.label());
    std::size_t n = make("expr").label().size();    // 식이 끝날 때까지는 살아 있다
    std::println("4 {}", n);
}
```

```text
1
+ temp
- temp
2
+ kept
3 kept
+ expr
- expr
4 4
- kept
```

임시 객체는 그것이 만들어진 **식 전체가 끝날 때**, 곧 세미콜론에서 사라집니다. `make("expr").label().size()`처럼 한 식 안에서 이어 쓰는 동안은 안전합니다.

## 참조에 묶으면 연장된다

임시 객체를 `const T&`나 `T&&` **지역 참조에 직접** 묶으면, 임시 객체의 수명이 그 참조의 수명만큼 늘어납니다. 위의 `kept`가 `main`이 끝날 때까지 산 까닭입니다.

"직접"이 중요합니다. 연장되는 것은 **그 임시 객체 자체**(또는 그 멤버)를 묶었을 때뿐입니다.

| 코드 | 연장되는가 |
| --- | --- |
| `const Trace& r = make("a");` | 된다 |
| `const std::string& s = make("a").name;` | 된다. 멤버를 직접 묶으면 전체가 연장된다 |
| `const std::string& s = make("a").label();` | **안 된다.** 함수가 돌려준 참조는 임시 객체가 아니다 |
| `std::string_view v = make_name();` | 안 된다. `string_view`는 참조가 아니라 포인터를 품은 객체다 |
| 함수의 인자로 받은 `const T&`를 돌려주기 | 안 된다 |
| 클래스의 참조 멤버에 묶기 | 안 된다 |

컴파일러는 함수 `label()`의 안을 들여다보지 않습니다. 돌려준 참조가 임시 객체의 속을 가리키는지 알 수 없으므로 연장하지 않습니다.

## 함정 넷

```cpp nocheck
std::string make_name();
Config load();                  // items()가 멤버 vector의 참조를 돌려준다

std::string_view view = make_name();            // 1. 문자열은 이 줄에서 죽는다
const char* text = make_name().c_str();         // 2. 같다
for (const auto& name : load().items()) { }     // 3. Config가 루프 전에 죽는다
const auto& items = load().items();             // 4. 같다
```

넷 모두 다음 줄에서 죽은 메모리를 읽습니다. 직접 돌려 본 결과입니다.

| | GCC 14 `-Wall` | Clang 19 `-Wall` | AddressSanitizer |
| --- | --- | --- | --- |
| 1. `string_view` ← 임시 `string` | 조용하다 | 경고 | 잡는다 |
| 2. `c_str()` ← 임시 `string` | 조용하다 | 경고 | 잡는다 |
| 3. 범위 `for` ← 임시 객체의 멤버 | 경고 (`-Wdangling-reference`) | (아래 참조) | 잡는다 |
| 4. 참조 ← 임시 객체의 멤버 함수 결과 | 경고 | 조용하다 | 잡는다 |

컴파일러마다 잡는 것이 다릅니다. **새니타이저를 켠 테스트**가 필요한 까닭입니다.

고치는 법은 같습니다. **임시 객체에 이름을 줍니다.**

```cpp nocheck
std::string name = make_name();         // 값으로 받는다. 복사는 생략되거나 이동이다
std::string_view view = name;

Config config = load();
for (const auto& item : config.items()) { }
```

## 범위 for

셋째 함정은 유난히 자주 밟혀서 C++23이 **규칙을 바꿨습니다.** 범위 `for`의 콜론 오른쪽에서 만들어진 임시 객체는 이제 모두 루프가 끝날 때까지 삽니다.

| 컴파일러 | `-std=c++23`에서 |
| --- | --- |
| GCC 14 | 옛 규칙. 여전히 위험하다 |
| GCC 15 이상, Clang 19 이상 | 새 규칙. 안전하다 |

이 책의 기준인 GCC 14에서는 아직 위험하므로, 콜론 오른쪽에 `임시객체.멤버함수()` 꼴을 쓰지 않습니다. C++20의 초기화 문을 써서 이름을 줄 수도 있습니다.

```cpp nocheck
for (auto config = load(); const auto& item : config.items()) { }
```

## 인자로 넘길 때

함수의 인자로 넘긴 임시 객체는 **함수 호출이 든 식이 끝날 때까지** 삽니다. 그래서 이것은 안전합니다.

```cpp nocheck
void show(std::string_view text);

show(make_name());                      // show가 도는 동안 문자열은 살아 있다
show(std::string("a") + "b");           // 이것도
```

[`std::string_view`](#/read/cpp-syntax/ft-string)와 [`std::span`](#/read/cpp-syntax/ft-array-span)을 **매개변수로** 쓰는 것이 안전하고, **변수나 멤버로** 보관하는 것이 위험한 까닭이 이것입니다. 받는 함수가 그것을 어딘가에 저장해 두면 다시 위험해집니다.

## 조건 연산자와 초기화 리스트

| 코드 | 주의 |
| --- | --- |
| `const std::string& s = flag ? a : std::string("x");` | 두 갈래의 종류가 달라 결과가 **임시 복사본**이 된다. `a`를 가리키지 않는다 |
| `std::initializer_list<int> list = {1, 2, 3};` | 뒤의 배열은 `list`만큼 산다. `list`를 **복사해 돌려주면** 배열은 따라가지 않는다 |
| `auto&& x = f();` | `f`가 값을 돌려주면 연장된다. 참조를 돌려주면 그 참조일 뿐이다 |

<Note kind="tip">
"임시 객체를 묶은 참조"는 되도록 만들지 않는 것이 가장 쉽습니다. 함수가 돌려준 것은 **값으로 받습니다**(`auto x = f();`). [복사는 일어나지 않습니다](#/read/cpp-syntax/sm-elision). `const auto& x = f();`는 `f`가 값을 돌려줄 때는 이득이 없고, 참조를 돌려줄 때는 그 참조가 언제까지 유효한지를 따져야 합니다.
</Note>

## 정리

- 임시 객체는 그것이 만들어진 식이 끝날 때 사라진다
- `const T&` 지역 참조에 **직접** 묶으면 연장된다. 함수가 돌려준 참조, `string_view`, 멤버 참조는 아니다
- 임시 객체에서 얻은 포인터나 뷰를 다음 줄로 가져가지 않는다. 이름을 주면 해결된다
