참조가 생겼다고 포인터가 사라지지는 않습니다. 둘은 하는 말이 다릅니다. 타입만 보고 "이것은 없을 수도 있는가, 다른 것으로 바뀔 수 있는가, 내가 지워야 하는가"를 알 수 있게 고릅니다.

## 고르는 기준

| 말하고 싶은 것 | 타입 |
| --- | --- |
| 반드시 있고, 빌려 쓴다 | `T&`, `const T&` |
| 없을 수도 있고, 빌려 쓴다 | `T*`, `const T*` |
| 도중에 다른 것을 가리켜야 한다 | `T*` |
| 여러 칸을 빌려 쓴다 | `std::span<T>`, `std::string_view` |
| 내가 주인이다 | 값, `std::unique_ptr<T>` |
| C API와 주고받는다 | `T*` |

```cpp
#include <print>
#include <string>
#include <vector>

struct device {
    std::string name;
    int pin;
};

// 못 찾을 수 있다 → 포인터
device* find(std::vector<device>& all, const std::string& name)
{
    for (device& d : all)
        if (d.name == name)
            return &d;
    return nullptr;
}

// 반드시 있다 → 참조
void move_pin(device& d, int pin) { d.pin = pin; }

int main()
{
    std::vector<device> all = {{"led", 17}, {"button", 27}};

    if (device* d = find(all, "led"))       // 선언하면서 널 검사
        move_pin(*d, 18);
    std::println("{}", all[0].pin);
    std::println("{}", find(all, "buzzer") == nullptr);
}
```

```text
18
true
```

`find`는 못 찾으면 돌려줄 것이 없으므로 포인터가 맞습니다. `move_pin`은 장치 없이는 할 일이 없으므로 참조가 맞습니다. `move_pin(*d, 18)`의 `*d`가 포인터에서 참조로 넘어가는 자리이고, 그 앞의 `if`가 "여기서부터는 반드시 있다"를 보장합니다.

## 참조로 할 수 없는 일

| 하려는 일 | 참조로는 | 대신 |
| --- | --- | --- |
| 컨테이너에 담기 | `std::vector<int&>`는 없다 | `std::vector<int*>`, `std::reference_wrapper<int>` |
| 나중에 묶기 | 선언할 때만 묶는다 | 포인터 |
| 구조체의 멤버로 | 되지만 그 구조체를 대입할 수 없게 된다 | 포인터 멤버 |
| 배열을 훑기 | 산술이 없다 | 포인터, 반복자, `std::span` |

클래스의 멤버로 다른 객체를 가리켜야 할 때는 대개 포인터를 씁니다. 참조 멤버는 다시 묶을 수 없어서 `a = b;` 같은 대입이 컴파일되지 않습니다.

## 날 포인터의 뜻이 좁아졌다

C에서 `T*`는 온갖 뜻으로 쓰였습니다. 모던 C++에서는 다른 뜻마다 더 정확한 타입이 생겼고, `T*`에는 한 가지만 남았습니다.

| C에서 `T*`가 뜻하던 것 | 모던 C++ |
| --- | --- |
| 배열의 시작 | `std::span<T>`, `std::vector<T>&` |
| 문자열 | `std::string_view`, `std::string` |
| 출력 인자 | 반환값, `T&` |
| 내가 `free`해야 하는 메모리 | `std::unique_ptr<T>`, 컨테이너 |
| 없을 수도 있는 값 | `std::optional<T>` |
| **없을 수도 있는, 빌려 온 객체 하나** | `T*` |

그래서 요즘 코드에서 `T*`를 보면 "소유하지 않는다, `nullptr`일 수 있다"로 읽습니다. `delete`해야 하는 날 포인터가 보이면 그것은 고쳐야 할 코드입니다.

## 널을 다루는 습관

```cpp nocheck
void use(const Config* config)
{
    if (!config)
        return;                 // 포인터는 쓰기 전에 확인한다
    apply(*config);             // 확인한 뒤에는 참조로 넘긴다
}
```

포인터로 받았으면 함수의 첫머리에서 한 번 확인하고, 그 아래로는 참조로 내려보냅니다. 널 검사가 코드 곳곳에 흩어지지 않습니다.

<Note>
참조에도 널을 넣을 수는 있습니다. `int* p = nullptr; int& r = *p;`가 컴파일됩니다. 하지만 `*p`를 하는 순간 이미 정의되지 않은 동작입니다. 참조가 널이 아니라는 약속은 참조를 **만드는 쪽**이 지켜야 합니다.
</Note>

## 정리

- 반드시 있으면 참조, 없을 수 있으면 포인터
- 날 포인터는 "소유하지 않는, 널일 수 있는 것 하나"만 뜻하게 쓴다
- 포인터는 받자마자 확인하고, 그 뒤로는 참조로 넘긴다
