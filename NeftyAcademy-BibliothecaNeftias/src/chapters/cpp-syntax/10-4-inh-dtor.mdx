export const summary = '부모 포인터로 지울 때 자식의 소멸자가 불리게 하기, 두 가지 선택, 복사 막기';

부모 타입의 포인터로 자식 객체를 지우면 어느 소멸자가 불릴까요. 멤버 함수와 규칙이 같습니다. 소멸자가 `virtual`이어야 **객체의 실제 타입**의 소멸자가 불립니다.

## 가상 소멸자

```cpp
#include <memory>
#include <print>

class Stream {
public:
    virtual ~Stream() { std::println("Stream 정리"); }
    virtual void write(const char* text) = 0;
};

class FileStream : public Stream {
public:
    FileStream() { std::println("파일 엶"); }
    ~FileStream() override { std::println("파일 닫음"); }
    void write(const char* text) override { std::println("파일에: {}", text); }
};

int main()
{
    std::unique_ptr<Stream> s = std::make_unique<FileStream>();
    s->write("hello");
}       // s가 사라진다. Stream*로 지우지만 ~FileStream부터 불린다
```

```text
파일 엶
파일에: hello
파일 닫음
Stream 정리
```

`unique_ptr<Stream>`은 자기가 아는 타입, 곧 `Stream*`로 `delete`를 합니다. 소멸자가 가상이어서 가상 함수 표를 거쳐 `~FileStream`이 먼저 불리고, 이어서 [부모의 소멸자](#/read/cpp-syntax/inh-public)가 불렸습니다.

## virtual이 없으면

`~Stream`의 `virtual`과 `~FileStream`의 `override`를 지우면 결과는 이렇게 됩니다.

```text
파일 엶
파일에: hello
Stream 정리
```

"파일 닫음"이 없습니다. 파일은 닫히지 않았고, `FileStream`의 멤버들도 치워지지 않았습니다. 표준은 이것을 **정의되지 않은 동작**으로 정합니다. 위 출력조차 보장되지 않습니다.

| 도구 | 잡아 주는 것 |
| --- | --- |
| `-Wall` (`-Wdelete-non-virtual-dtor`) | 코드에 직접 쓴 `delete p;`. `unique_ptr` 안에서 일어나는 `delete`는 Clang 19는 알려 주고 GCC 14는 알려 주지 않는다 |
| `-Wnon-virtual-dtor` | 가상 함수가 있는데 소멸자가 가상이 아닌 클래스의 정의 자체. `-Wall`에 들어 있지 않아 따로 켠다 |
| AddressSanitizer | 자식이 부모보다 클 때, 실행 중에 "할당한 크기와 지우는 크기가 다르다"고 알린다 |

위 예제는 GCC에서 `-Wall`로도, AddressSanitizer로도 조용합니다(두 클래스의 크기가 같아서). `-Wnon-virtual-dtor`를 켜 두는 것이 가장 확실합니다.

## 두 가지 선택

부모로 쓸 클래스의 소멸자는 둘 가운데 하나여야 합니다.

| 소멸자 | 뜻 | 쓰는 곳 |
| --- | --- | --- |
| `public`이고 `virtual` | 부모 포인터로 지워도 된다 | 대부분의 다형적 클래스 |
| `protected`이고 `virtual` 아님 | 부모 포인터로는 **지울 수 없다** (컴파일 오류) | 소유하지 않고 부르기만 하는 인터페이스 |

```cpp nocheck
class Listener {
public:
    virtual void notify(int event) = 0;

protected:
    ~Listener() = default;      // 바깥에서 delete listener; 는 컴파일되지 않는다
};
```

두 번째는 "이 타입으로는 객체의 수명을 다루지 않는다"는 것을 타입으로 못 박는 방법입니다. 헷갈리면 첫 번째를 고릅니다. 가상 함수가 이미 하나라도 있다면 객체에 vptr이 있으므로 가상 소멸자의 추가 비용은 없습니다.

<Note kind="warn">
가상 함수가 없는 클래스는 부모로 쓰라고 만든 것이 아닙니다. `std::string`, `std::vector` 같은 표준 컨테이너의 소멸자는 가상이 아닙니다. 이들을 `public`으로 상속해 부모 포인터로 지우면 같은 문제가 생깁니다. 기능을 덧붙이고 싶으면 멤버로 가지거나 자유 함수를 씁니다.
</Note>

## 복사와 이동

소멸자를 직접 선언하면 [이동 연산이 저절로 만들어지지 않습니다](#/read/cpp-syntax/sm-rules). 다형적으로 쓰는 클래스는 값으로 복사하면 [잘리기](#/read/cpp-syntax/inh-slicing)도 하므로, 부모에서 복사를 아예 막는 것이 흔한 꼴입니다.

```cpp nocheck
class Stream {
public:
    Stream() = default;
    virtual ~Stream() = default;

    Stream(const Stream&) = delete;
    Stream& operator=(const Stream&) = delete;

    virtual void write(const char* text) = 0;
};
```

복사 생성자를 선언하면 기본 생성자도 사라지므로 `Stream() = default;`를 함께 적습니다. 자식들은 이것만으로 복사와 이동이 모두 막힙니다.

## shared_ptr은 조금 다르다

```cpp nocheck
std::shared_ptr<Stream> s = std::make_shared<FileStream>();
```

`shared_ptr`은 만들어질 때의 **실제 타입으로 지우는 방법**을 함께 기억합니다. 그래서 소멸자가 가상이 아니어도 `~FileStream`이 불립니다. 알아 두면 좋은 사실일 뿐 기댈 것은 아닙니다. 누군가 `unique_ptr`이나 맨 `delete`로 바꾸는 순간 깨집니다.

## 정리

- 부모 포인터로 지울 클래스의 소멸자는 `virtual`. 없으면 정의되지 않은 동작
- 부모의 소멸자는 "`public` + `virtual`" 아니면 "`protected` + 가상 아님"
- 다형적 부모에서는 복사를 `= delete`로 막아 두는 것이 안전하다
