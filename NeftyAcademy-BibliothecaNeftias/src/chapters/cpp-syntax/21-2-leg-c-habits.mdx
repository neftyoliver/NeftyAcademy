C++ 컴파일러로 컴파일되지만 속은 C인 코드가 많습니다. 임베디드 쪽이 특히 그렇습니다. [책의 첫머리](#/read/cpp-syntax/from-c-diff)에서 C의 습관과 그것을 대신하는 도구를 표로 보았고, 여기서는 그런 코드를 **만났을 때** 무엇이 위험하고 무엇은 그냥 두어도 되는지를 정리합니다.

## C처럼 쓴 C++

```cpp
#include <cstdio>
#include <cstdlib>
#include <cstring>

#define MAX_NAME 32
#define SQUARE(x) ((x) * (x))

struct Sensor {
    char name[MAX_NAME];
    int* samples;
    int count;
};

int sensor_init(Sensor* s, const char* name, int count)     // 0이면 성공
{
    std::memset(s, 0, sizeof *s);
    std::strncpy(s->name, name, MAX_NAME - 1);
    s->samples = (int*)std::malloc(sizeof(int) * count);
    if (s->samples == NULL)
        return -1;
    s->count = count;
    for (int i = 0; i < count; i++)
        s->samples[i] = SQUARE(i);
    return 0;
}

void sensor_free(Sensor* s)
{
    std::free(s->samples);
    s->samples = NULL;
}

int sensor_sum(const Sensor* s, int* out)                   // 결과는 out으로
{
    if (s == NULL || out == NULL)
        return -1;
    *out = 0;
    for (int i = 0; i < s->count; i++)
        *out += s->samples[i];
    return 0;
}

int main()
{
    Sensor s;
    int sum;
    int rc = -1;

    if (sensor_init(&s, "temp", 4) != 0)
        goto done;
    if (sensor_sum(&s, &sum) != 0)
        goto cleanup;
    std::printf("%s %d\n", s.name, sum);
    rc = 0;

cleanup:
    sensor_free(&s);
done:
    return rc;
}
```

```text
temp 14
```

틀린 코드가 아닙니다. 잘 쓴 C입니다. 다만 지켜야 할 약속이 모두 **사람의 몫**입니다. `sensor_init` 뒤에는 `sensor_free`를 불러야 하고, 반환값을 확인해야 하고, `goto`의 순서를 맞춰야 하고, `name`이 31자를 넘지 않아야 합니다.

## 같은 일을 C++로

```cpp
#include <numeric>
#include <print>
#include <string>
#include <utility>
#include <vector>

class Sensor {
public:
    Sensor(std::string name, int count) : name_(std::move(name))
    {
        for (int i = 0; i < count; ++i)
            samples_.push_back(i * i);
    }

    const std::string& name() const { return name_; }
    int sum() const { return std::accumulate(samples_.begin(), samples_.end(), 0); }

private:
    std::string name_;
    std::vector<int> samples_;
};

int main()
{
    Sensor sensor("temp", 4);
    std::println("{} {}", sensor.name(), sensor.sum());
}
```


| C 판에서 사람이 지키던 것 | C++ 판에서 |
| --- | --- |
| `init`과 `free`의 짝 | [생성자와 소멸자](#/read/cpp-syntax/class-dtor). 잊을 수 없다 |
| 반환값 확인 | 실패는 [예외나 `expected`](#/read/cpp-syntax/exc-without). 결과는 [값으로 돌려준다](#/read/cpp-syntax/sm-elision) |
| `goto cleanup` | [스택이 풀리며](#/read/cpp-syntax/exc-unwind) 저절로 |
| 이름 길이 제한, 널 끝 | `std::string` |
| `malloc` 크기 계산과 형 변환 | `std::vector` |
| `NULL` 검사 | 참조와 멤버 함수. 널이 올 수 없다 |
| `SQUARE(i++)`의 함정 | 보통 함수나 `constexpr` 함수 |

## 위험한 습관

C에서는 괜찮았지만 **C++의 타입에 하면 깨지는** 것들입니다. 옛 코드를 고칠 때 먼저 찾아야 합니다.

| 습관 | C++에서의 문제 |
| --- | --- |
| `memset(&obj, 0, sizeof obj)` | `obj`에 `std::string`, `std::vector`, 가상 함수가 있으면 그 속을 0으로 덮어 망가뜨린다 |
| `memcpy(&a, &b, sizeof a)`로 객체 복사 | 같다. [복사 생성자](#/read/cpp-syntax/sm-copy)가 불리지 않아 두 객체가 같은 힙 메모리를 가리킨다 |
| `malloc`으로 객체 만들기 | [생성자가 불리지 않는다](#/read/cpp-syntax/life-new). 그 안의 `std::string`은 쓰레기다 |
| `realloc`으로 객체 배열 늘리기 | 원소가 [옮겨질 때](#/read/cpp-syntax/sm-move) 이동 생성자가 불리지 않는다 |
| `union`으로 타입 바꿔 읽기 | [정의되지 않은 동작](#/read/cpp-syntax/ubc-aliasing) |
| `(T*)ptr` | [무슨 변환인지 모른다](#/read/cpp-syntax/cast-static). `const`도 말없이 떼어 낸다 |
| `longjmp` | 건너뛴 객체들의 소멸자가 불리지 않는다 |

이것들이 안전한 타입은 [`std::is_trivially_copyable`](#/read/cpp-syntax/ct-assert)인 타입뿐입니다. `static_assert`로 확인해 둘 수 있습니다. GCC는 그렇지 않은 타입에 `memset`이나 `memcpy`를 쓰면 `-Wclass-memaccess`로 경고합니다(`-Wall`에 들어 있습니다).

## 낡았을 뿐인 습관

틀리지는 않고, 더 나은 방법이 있는 것들입니다. 급하지 않습니다.

| 습관 | 더 나은 것 |
| --- | --- |
| 변수를 블록 맨 위에 모아 선언 | 쓰는 자리에서 초기화와 함께 |
| `#define` 상수 | `constexpr` |
| `typedef struct { … } Name;` | `struct Name { … };` |
| `for (int i = 0; i < n; i++)`로 컨테이너 돌기 | 범위 `for` |
| `printf` | `std::println`. 다만 `printf`도 GCC가 서식을 검사해 주므로 위험하지는 않다 |
| `bool`을 `int`로, `true`를 `1`로 | `bool` |

## C 방식이 여전히 옳은 자리

| 자리 | 까닭 |
| --- | --- |
| C 라이브러리와의 경계 | [`extern "C"`](#/read/cpp-syntax/from-c-mangling) 함수, 단순한 구조체, 포인터와 길이. 예외가 이 경계를 넘으면 안 된다 |
| 다른 언어에서 부를 API | C의 호출 규약이 공용어다 |
| 하드웨어 레지스터, 통신 형식 | 배치가 정해진 단순한 구조체와 [`memcpy`](#/read/cpp-syntax/cast-reinterpret) |
| 인터럽트 처리기, 시그널 처리기 | 할당, 예외, 잠금을 쓸 수 없다. 플래그를 세우고 나온다 |
| 리눅스 시스템 호출 | `open`, `read`, `ioctl`은 C 인터페이스다. 얇은 클래스로 한 번 감싸고 그 위에서 C++로 쓴다 |

마지막 줄이 소형 기기 프로그래밍의 흔한 꼴입니다. 파일 디스크립터를 쥐는 작은 클래스를 만들어 소멸자에서 `close`하게 하면, C API의 수명 관리가 그 한 곳에 모입니다.

<Note>
"C++에서는 C 표준 라이브러리를 쓰면 안 된다"는 것은 오해입니다. `<cstring>`, `<cmath>`, `<cstdio>`는 C++ 표준의 일부이고, `std::memcpy`와 `std::snprintf`는 지금도 제자리가 있습니다. 문제는 함수가 아니라 **수명과 소유를 손으로 관리하는 방식**입니다.
</Note>

## 정리

- C처럼 쓴 C++은 틀린 것이 아니라, 약속을 사람이 지켜야 하는 코드다
- `memset`, `memcpy`, `malloc`, `realloc`을 생성자가 있는 타입에 쓰는 것은 위험하다. 먼저 찾는다
- C API의 경계, 하드웨어 배치, 인터럽트 처리기에서는 C 방식이 옳다. 얇게 감싸서 쓴다
