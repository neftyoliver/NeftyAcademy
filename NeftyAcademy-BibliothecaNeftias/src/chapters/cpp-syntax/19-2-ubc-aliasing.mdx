`int`가 든 메모리를 `float*`로 읽는 코드는 C에서 흔했고 대개 돌아갔습니다. C++(과 요즘의 C)에서는 정의되지 않은 동작이고, 최적화를 켜면 실제로 틀린 결과가 나옵니다.

## 최적화가 믿는 것

```cpp nocheck
#include <print>

int write_both(int* i, float* f)
{
    *i = 1;
    *f = 2.0f;      // 컴파일러는 이것이 *i를 바꾸지 않는다고 믿는다
    return *i;
}

int main()
{
    int value = 0;
    int result = write_both(&value, reinterpret_cast<float*>(&value));
    std::println("{} {}", result, value);
}
```

```text
$ g++ -std=c++23 -O0 alias.cpp && ./a.out
1073741824 1073741824
$ g++ -std=c++23 -O2 alias.cpp && ./a.out
1 1073741824
```

GCC 14에서의 실제 결과입니다(Clang 19도 `-O2`에서 같습니다). `-O2`에서 `write_both`는 메모리를 다시 읽지 않고 **1을 그대로 돌려줍니다.** 메모리에는 `2.0f`의 비트(1073741824)가 들어 있는데도 그렇습니다.

컴파일러의 논리는 이렇습니다. "`int*`와 `float*`는 타입이 다르다. 타입이 다른 포인터는 같은 객체를 가리킬 수 없다. 그러니 `*f`에 써도 `*i`는 그대로다." 이 가정이 **엄격한 별칭 규칙**(strict aliasing)입니다.

## 규칙

어떤 타입의 객체는 **그 타입으로만** 읽고 쓸 수 있습니다. 예외는 좁습니다.

| 객체의 타입이 `T`일 때 써도 되는 포인터·참조 | 예 |
| --- | --- |
| `T` 자신, `const`/`volatile`이 붙은 것 | `const int*`로 `int` 읽기 |
| 부호만 다른 정수 | `unsigned*`로 `int` 읽기 |
| `char`, `unsigned char`, `std::byte` | **무엇이든** 바이트 단위로 읽고 쓸 수 있다 |
| 부모 클래스 | `Base&`로 `Derived` 객체 보기 |

`char` 계열이 특별합니다. 그래서 [`std::memcpy`](#/read/cpp-syntax/cast-reinterpret)와 `std::as_bytes`가 됩니다. 거꾸로 `char` 배열을 `int*`로 읽는 것은 안 됩니다. 그 자리에 `int` 객체가 없기 때문입니다.

## 왜 이런 규칙이 있나

이 가정이 없으면 컴파일러는 포인터로 무언가를 쓸 때마다 "다른 모든 값이 바뀌었을 수 있다"고 보고 메모리에서 다시 읽어야 합니다.

```cpp nocheck
void scale(float* out, const int* count, float factor)
{
    for (int i = 0; i < *count; ++i)        // *count를 매번 다시 읽어야 하는가?
        out[i] *= factor;
}
```

`out[i]`에 쓰는 것이 `*count`를 바꿀 수 없다고 믿을 수 있어야 `*count`를 레지스터에 한 번만 올리고, 루프를 SIMD로 바꿀 수 있습니다. 숫자 계산 코드의 성능이 여기에 달려 있습니다.

같은 까닭으로 `std::uint8_t*`로 쓰는 루프는 손해를 봅니다. `uint8_t`는 `unsigned char`이고, `char` 계열은 무엇이든 가리킬 수 있으므로 컴파일러가 아무것도 가정하지 못합니다.

## union

C++에서 `union`은 **마지막으로 쓴 멤버**(활성 멤버)만 읽을 수 있습니다.

```cpp nocheck
union Word {
    std::uint32_t u;
    float f;
};

Word w;
w.f = 1.0f;
auto bits = w.u;        // C에서는 허용, C++에서는 정의되지 않은 동작
```

C99는 이 "타입 바꿔 읽기"를 허용하지만 C++ 표준은 허용하지 않습니다. GCC와 Clang은 확장으로 받아 주지만(문서에 그렇게 적혀 있습니다), MSVC와 다른 컴파일러까지 보장되는 것은 아닙니다.

| 하려는 일 | C++의 도구 |
| --- | --- |
| 비트를 다른 타입으로 읽는다 | [`std::bit_cast`](#/read/cpp-syntax/cast-reinterpret), `std::memcpy` |
| "이 가운데 하나"를 담는다 | `std::variant<A, B>`. 무엇이 들었는지 스스로 기억하고, 틀리게 꺼내면 예외 |
| 값이 있거나 없다 | `std::optional<T>` |
| 메모리를 아끼려고 겹쳐 둔다 | `union` + 무엇이 들었는지 적는 열거형. 읽는 쪽이 지킨다 |

`union`에 `std::string`처럼 생성자가 있는 타입을 넣으면 생성과 소멸을 손으로 불러야 합니다. 그런 일은 `std::variant`가 대신 해 줍니다.

## 실제로 밟는 자리

| 코드 | 문제 | 옳은 방법 |
| --- | --- | --- |
| `*reinterpret_cast<std::uint32_t*>(&f)` | `float`를 `uint32_t`로 읽는다 | `std::bit_cast<std::uint32_t>(f)` |
| `auto* h = reinterpret_cast<const Header*>(buffer);` | 바이트 버퍼에 `Header` 객체가 없다. 정렬도 안 맞을 수 있다 | `Header h; std::memcpy(&h, buffer, sizeof h);` |
| `auto* words = reinterpret_cast<std::uint16_t*>(bytes);` | 바이트 배열을 16비트씩 읽는다 | 바이트 둘을 시프트로 합친다. 또는 `memcpy` |
| `sockaddr*`와 `sockaddr_in*` 사이의 변환 | POSIX API가 요구한다 | 그대로 쓴다. 채울 때는 `sockaddr_in` 변수에 채우고 넘길 때만 변환한다 |

`memcpy`는 느려 보이지만, 크기가 상수인 작은 `memcpy`는 컴파일러가 **명령 한두 개로** 바꿉니다. 함수 호출이 남지 않습니다.

## 도구

| 도구 | 효과 |
| --- | --- |
| `-Wstrict-aliasing` | `-Wall`에 들어 있지만 위 예제는 잡지 못했다. `-Wstrict-aliasing=1`(가장 예민한 단계)로는 잡았다. 오탐이 는다 |
| `-fno-strict-aliasing` | 규칙에 기댄 최적화를 **끈다.** 위 예제가 `-O2`에서도 `1073741824`를 돌려준다. 리눅스 커널이 이 옵션으로 빌드된다 |
| AddressSanitizer, UBSan | 이 위반은 잡지 못한다 |
| `[[gnu::may_alias]]` | 이 타입의 포인터는 무엇이든 가리킬 수 있다고 알린다 (GCC, Clang) |

오래된 C 코드를 가져와 쓰는데 타입 바꿔 읽기가 곳곳에 있다면, 그 파일들만 `-fno-strict-aliasing`으로 컴파일하는 것이 현실적인 타협입니다. 새로 쓰는 코드는 규칙을 지킵니다.

<Note>
하드웨어 레지스터를 `volatile std::uint32_t*`로 읽고 쓰는 것은 별칭 문제가 아닙니다. 그 주소에는 처음부터 `uint32_t`로만 접근합니다. 문제가 되는 것은 **같은 메모리를 서로 다른 두 타입으로** 볼 때입니다.
</Note>

## 정리

- 객체는 자기 타입(과 `char` 계열)으로만 읽고 쓴다. 컴파일러는 이것을 믿고 최적화한다
- 어기면 최적화 수준에 따라 결과가 달라진다. 새니타이저도 잡지 못한다
- 비트를 바꿔 읽을 때는 `std::bit_cast`나 `memcpy`, 여럿 가운데 하나를 담을 때는 `std::variant`
