타입을 정렬하거나 `std::map`의 열쇠로 쓰려면 비교가 필요합니다. C++20 전에는 `==`, `!=`, `<`, `<=`, `>`, `>=` 여섯을 하나하나 썼습니다. 지금은 한 줄입니다.

## 기본 비교

```cpp
#include <algorithm>
#include <compare>
#include <print>
#include <string>
#include <vector>

struct Date {
    int year = 0, month = 0, day = 0;
    auto operator<=>(const Date&) const = default;      // 여섯 비교가 모두 생긴다
};

struct Reading {
    std::string sensor;
    double value = 0;

    // 값으로만 견준다
    std::partial_ordering operator<=>(const Reading& o) const
    {
        return value <=> o.value;
    }
    bool operator==(const Reading& o) const { return value == o.value; }
};

int main()
{
    Date a{2026, 11, 20}, b{2026, 12, 1};
    std::println("{} {} {}", a < b, a == b, a >= Date{2026, 11, 20});
    std::println("{}", (a <=> b) < 0);

    std::vector<Date> all = {{2027, 1, 1}, {2026, 12, 1}, {2026, 11, 20}};
    std::sort(all.begin(), all.end());
    std::println("{}-{}-{}", all[0].year, all[0].month, all[0].day);

    Reading r1{"a", 20.5}, r2{"b", 21.0};
    std::println("{} {}", r1 < r2, r1 == r2);
}
```

```text
true false true
true
2026-11-20
true false
```

`<=>`는 **세 방향 비교 연산자**이고, 생김새 때문에 우주선 연산자라고 부릅니다. `a <=> b`는 "작다, 같다, 크다" 가운데 하나를 나타내는 값을 돌려주고, 그 값을 0과 견줘 씁니다. C의 `strcmp`가 음수, 0, 양수를 돌려주던 것과 같은 생각입니다.

`= default`로 적으면 컴파일러가 **멤버를 선언한 순서대로** 견줍니다. `year`가 다르면 거기서 끝나고, 같으면 `month`를, 그것도 같으면 `day`를 봅니다. 사전식 비교입니다. 멤버의 선언 순서가 곧 비교의 우선순위가 됩니다.

## 컴파일러가 식을 바꿔 써 준다

`<=>`만 정의해도 `<`, `<=`, `>`, `>=`가 되는 것은 컴파일러가 식을 바꿔 쓰기 때문입니다.

| 쓴 것 | 컴파일러가 시도하는 것 |
| --- | --- |
| `a < b` | `(a <=> b) < 0` |
| `a >= b` | `(a <=> b) >= 0` |
| `a != b` | `!(a == b)` |
| `5 == a` | `a == 5` (좌우를 바꿔 본다) |

`==`와 `!=`는 `<=>`가 아니라 `operator==`에서 나옵니다. `<=>`를 `= default`로 적으면 `==`도 함께 만들어집니다. `<=>`를 직접 썼다면 `==`도 직접 적어야 합니다(위의 `Reading`).

둘을 따로 두는 것은 성능 때문입니다. 문자열이 같은지는 길이만 달라도 바로 알 수 있지만, 순서를 알려면 글자를 견줘야 합니다.

## 순서의 세 종류

`<=>`가 돌려주는 타입은 그 순서가 얼마나 엄격한지를 나타냅니다.

| 타입 | 뜻 | 예 |
| --- | --- | --- |
| `std::strong_ordering` | 같으면 완전히 같다 | 정수, `std::string`, 위의 `Date` |
| `std::weak_ordering` | 순서로는 같아도 구분은 된다 | 대소문자를 무시한 비교에서 `"Abc"`와 `"abc"` |
| `std::partial_ordering` | 견줄 수 없는 짝이 있다 | 실수. `NaN`은 어느 것과도 순서가 없다 |

`= default`에 `auto`를 쓰면 멤버들 가운데 가장 느슨한 것이 됩니다. `double` 멤버가 하나라도 있으면 `partial_ordering`입니다.

## 비교가 필요 없는 타입

같은지만 따지고 순서는 뜻이 없는 타입도 많습니다. 그럴 때는 `==`만 둡니다.

```cpp nocheck
struct Color {
    std::uint8_t r, g, b;
    bool operator==(const Color&) const = default;      // ==와 !=만
};
```

"파랑이 빨강보다 작은가"에 답이 없다면 `<`를 만들지 않는 것이 옳습니다. 정렬이 필요한 자리에서는 그때그때 기준을 [람다](#/read/cpp-syntax/fn-lambda)로 줍니다.

## 표준 라이브러리가 요구하는 것

| 쓰려는 것 | 필요한 연산 |
| --- | --- |
| `std::sort`, `std::set`, `std::map`의 열쇠 | `<` (또는 비교 함수를 따로 준다) |
| `std::find`, `std::unordered_map`의 열쇠 | `==` (해시 맵은 해시 함수도) |
| `std::ranges::sort` | 여섯 비교 모두 (`<=>`와 `==`가 있으면 된다) |

`<`는 **일관돼야** 합니다. `a < b`이고 `b < c`면 `a < c`여야 하고, `a < a`는 거짓이어야 합니다. 어기면 `std::sort`가 범위 밖을 읽는 정의되지 않은 동작이 됩니다. 멤버 일부만 견주는 비교를 손으로 쓸 때 자주 틀리므로, 될 수 있으면 `= default`에 맡깁니다.

<Note kind="warn">
`Reading`처럼 "일부 멤버만 같으면 같다"고 정의한 `==`는 조심해서 써야 합니다. `r1 == r2`가 참인데 `r1.sensor != r2.sensor`인 상황은 읽는 사람을 놀라게 합니다. 값만 견주고 싶다면 `r1.value == r2.value`라고 쓰는 편이 정직합니다.
</Note>

## 정리

- `auto operator<=>(const T&) const = default;` 한 줄로 여섯 비교가 생긴다
- 기본 비교는 멤버를 선언 순서대로 견준다
- 순서가 뜻이 없는 타입에는 `operator==`만 `= default`로 둔다
