[오버로딩](#/read/cpp-syntax/fn-overload)으로 `int`용, `double`용 함수를 따로 쓰다 보면 본문이 글자 하나 다르지 않다는 것을 알게 됩니다. 템플릿은 그 본문을 **한 번만** 쓰고 타입 자리를 빈칸으로 두는 문법입니다.

## 함수 템플릿

```cpp
#include <print>
#include <string>

template <typename T>
T max_of(T a, T b)
{
    return a < b ? b : a;
}

int main()
{
    std::println("{}", max_of(3, 7));               // T = int
    std::println("{}", max_of(2.5, 1.5));           // T = double
    std::println("{}", max_of<std::string>("pi", "zero"));  // T를 직접 정한다
    std::println("{}", max_of<double>(3, 7.5));     // 3이 3.0으로 바뀐다
    // max_of(3, 7.5);      // 오류: T가 int인지 double인지 정할 수 없다
}
```

```text
7
2.5
zero
7.5
```

`template <typename T>`가 "아래에서 `T`는 아직 정해지지 않은 타입"이라고 알립니다. `typename` 자리에 `class`를 써도 뜻이 같습니다. 옛 코드에서 자주 봅니다.

- 부를 때 인자를 보고 컴파일러가 `T`를 정한다 ([인자 추론](#/read/cpp-syntax/tpl-deduction))
- `max_of<double>(…)`처럼 꺾쇠 안에 직접 적을 수도 있다
- 추론할 때는 `int`를 `double`로 바꿔 주는 변환을 **하지 않는다.** 그래서 `max_of(3, 7.5)`는 오류다

<Note kind="warn">
`max_of("pi", "zero")`는 컴파일됩니다. `T`가 `const char*`로 정해지고, **글자가 아니라 두 포인터의 주소**를 견줍니다. 템플릿은 "그 타입에서 `<`가 뜻하는 것"을 그대로 따릅니다.
</Note>

## 인스턴스화

템플릿 자체는 코드가 아니라 **틀**입니다. `max_of(3, 7)`을 만나면 컴파일러가 `T`에 `int`를 넣은 진짜 함수 `max_of<int>`를 찍어 냅니다. 이것을 인스턴스화라고 합니다.

| 사실 | 결과 |
| --- | --- |
| 쓰인 타입마다 함수가 하나씩 생긴다 | 위 프로그램에는 `max_of<int>`, `max_of<double>`, `max_of<std::string>` 셋이 들어 있다 |
| 쓰이지 않으면 아무것도 생기지 않는다 | 템플릿만 잔뜩 있는 헤더는 실행 파일을 키우지 않는다 |
| 찍어 낸 함수는 손으로 쓴 것과 같다 | 실행 중의 비용이 없다. 인라인도 똑같이 된다 |
| 타입마다 기계어가 따로다 | 큰 템플릿을 여러 타입으로 쓰면 실행 파일이 커진다 |

C의 매크로 `#define MAX(a, b) ((a) < (b) ? (b) : (a))`와 닮았지만, 템플릿은 타입을 검사하고 인자를 한 번만 계산하며 이름이 네임스페이스에 속합니다.

## 정의는 헤더에

컴파일러가 `max_of<int>`를 찍어 내려면 **부르는 곳에서 본문이 보여야** 합니다. 그래서 템플릿은 선언과 정의를 모두 헤더에 둡니다.

```cpp nocheck
// util.h
template <typename T>
T max_of(T a, T b)          // 본문까지 헤더에 쓴다
{
    return a < b ? b : a;
}
```

본문을 `.cpp`에 숨기면 다른 파일에서 부를 때 "정의되지 않은 참조" 링크 오류가 납니다. 여러 `.cpp`가 같은 `max_of<int>`를 찍어 내도 링커가 하나만 남기므로 [한 번 정의 규칙](#/read/cpp-syntax/fn-inline)에 걸리지 않습니다.

## 타입이 갖춰야 할 것

`max_of`의 본문은 `a < b`를 씁니다. `<`가 없는 타입으로 부르면 오류가 나는데, 오류가 나는 곳은 **부른 줄이 아니라 템플릿 본문 안**입니다.

```text
error: no match for 'operator<' (operand types are 'Pin' and 'Pin')
    7 |     return a < b ? b : a;
```

이 예는 짧지만 표준 라이브러리 깊숙한 곳에서 터지면 수십 줄이 됩니다. "이 템플릿은 견줄 수 있는 타입만 받는다"를 서명에 적어 두는 것이 [콘셉트](#/read/cpp-syntax/con-requires)입니다.

## auto 매개변수

C++20부터는 매개변수 타입에 `auto`를 쓰면 그것이 곧 함수 템플릿입니다.

```cpp
#include <print>
#include <string>

auto add(auto a, auto b)        // template <typename T, typename U> 와 같다
{
    return a + b;
}

int main()
{
    std::println("{}", add(1, 2.5));
    std::println("{}", add(std::string("ab"), "cd"));
}
```

```text
3.5
abcd
```

`auto`마다 **서로 다른** 타입 매개변수가 됩니다. 그래서 `add(1, 2.5)`가 됩니다. 두 인자가 같은 타입이어야 한다면 `template <typename T>`로 적어야 합니다.

## 오버로딩과 함께

템플릿과 보통 함수가 똑같이 잘 맞으면 **보통 함수가 이깁니다.**

```cpp nocheck
template <typename T> T max_of(T a, T b);               // (1)
const char* max_of(const char* a, const char* b);       // (2) strcmp로 견준다

max_of("pi", "zero");       // (2)가 불린다
max_of(3, 7);               // (1)에서 T = int
```

특정 타입만 다르게 처리하고 싶을 때는 이렇게 오버로드를 하나 더 둡니다.

## 정리

- `template <typename T>`로 타입을 빈칸으로 둔다. 쓰인 타입마다 컴파일러가 함수를 찍어 낸다
- 본문이 보여야 찍어 낼 수 있으므로 정의를 헤더에 둔다
- 매개변수의 `auto`는 짧게 쓴 템플릿이다
