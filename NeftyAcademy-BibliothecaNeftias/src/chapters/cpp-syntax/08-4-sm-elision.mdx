`std::move`는 "가져가도 좋다"는 표시이고, 실제로 이동이 일어날지는 받는 쪽에 달렸습니다. 한편 함수가 값을 돌려줄 때는 `std::move` 없이도 복사가 일어나지 않고, 많은 경우 이동조차 일어나지 않습니다.

## 무엇이 불리는지 찍어 보기

```cpp
#include <print>
#include <utility>

struct Tracer {
    Tracer() { std::println("생성"); }
    Tracer(const Tracer&) { std::println("복사"); }
    Tracer(Tracer&&) noexcept { std::println("이동"); }
};

Tracer make()
{
    Tracer t;           // 이름 있는 지역 변수
    return t;           // 부른 쪽의 자리에 바로 만들어진다
}

int main()
{
    std::println("-- 1");
    Tracer a = make();
    std::println("-- 2");
    Tracer b = a;                   // 복사: a는 계속 쓰인다
    std::println("-- 3");
    Tracer c = std::move(a);        // 이동: a는 이제 안 쓴다는 표시
    std::println("-- 4");
    const Tracer fixed;
    Tracer d = std::move(fixed);    // const는 이동할 수 없다. 조용히 복사된다

    (void)b, (void)c, (void)d;      // "쓰지 않는 변수" 경고를 끈다
}
```

```text
-- 1
생성
-- 2
복사
-- 3
이동
-- 4
생성
복사
```

## 복사 생략

1번에서 `생성`이 한 번만 찍혔습니다. `make` 안의 `t`를 만들고, 그것을 `a`로 복사하거나 이동한 것이 아닙니다. 컴파일러가 **`t`를 처음부터 `a`의 자리에 만들었습니다.** 이것을 복사 생략이라고 합니다.

| 경우 | 예 | 생략 |
| --- | --- | --- |
| 임시 객체를 그대로 돌려준다 | `return Tracer();` | C++17부터 **반드시** 일어난다 |
| 임시 객체로 초기화한다 | `Tracer a = Tracer();` | C++17부터 반드시 일어난다 |
| 이름 있는 지역 변수를 돌려준다 | `return t;` | 허용된다. 컴파일러가 대개 한다 (NRVO) |

마지막 경우에 컴파일러가 생략하지 못하면(분기마다 다른 변수를 돌려줄 때 등) `t`는 **저절로 우측값으로 다뤄져** 이동됩니다. 어느 쪽이든 복사는 없습니다. 그래서 [큰 객체도 값으로 돌려줍니다](#/read/cpp-syntax/ref-return).

## return std::move(x)는 쓰지 않는다

```cpp nocheck
Tracer make()
{
    Tracer t;
    return std::move(t);    // 나쁘다: 생략을 막고 이동을 강제한다
}
```

`return t;`라고만 쓰면 생략되거나, 안 되면 이동됩니다. `std::move`를 붙이면 "이름 있는 지역 변수를 그대로 돌려준다"는 꼴이 깨져서 생략이 불가능해지고 이동이 반드시 일어납니다. 컴파일러가 `-Wpessimizing-move`로 알려 줍니다.

## const는 이동되지 않는다

4번에서 `std::move(fixed)`는 `const Tracer&&`가 됩니다. 이동 생성자는 `Tracer&&`를 받으므로 맞지 않고, `const Tracer&`를 받는 복사 생성자가 불립니다. 오류도 경고도 없이 복사됩니다.

- 나중에 옮길 변수는 `const`로 선언하지 않는다
- 값으로 돌려주는 함수의 반환 타입에 `const`를 붙이지 않는다 (`const std::string f();`)

## std::move를 쓰는 자리

| 자리 | 예 |
| --- | --- |
| 다 쓴 변수를 컨테이너에 넣을 때 | `lines.push_back(std::move(line));` |
| 값으로 받은 인자를 멤버에 보관할 때 | `: name_(std::move(name))` |
| 복사가 안 되는 타입을 넘길 때 | `take(std::move(unique));` |
| 이동 생성자 안에서 멤버를 옮길 때 | `: buffer_(std::move(other.buffer_))` |

| 쓰지 않는 자리 | 까닭 |
| --- | --- |
| `return 지역변수;` | 생략을 막는다 |
| 임시 객체에 | 이미 우측값이다. `f(std::move(make()))`는 헛일 |
| 뒤에서 또 쓸 변수에 | 옮겨진 뒤의 값은 믿을 수 없다 |
| `const` 객체에 | 복사가 된다 |

## 옮긴 뒤에 쓰는 실수

```cpp
#include <print>
#include <string>
#include <utility>
#include <vector>

int main()
{
    std::vector<std::string> lines;
    std::string line = "first";

    lines.push_back(std::move(line));
    // 여기서 line을 읽으면 안 된다. 다시 쓰려면 새 값을 넣는다
    line = "second";
    lines.push_back(std::move(line));

    std::println("{} {} {}", lines.size(), lines[0], lines[1]);
}
```

```text
2 first second
```

옮긴 뒤의 변수를 읽는 실수는 컴파일러가 잡아 주지 않습니다. clang-tidy의 `bugprone-use-after-move`가 찾아 줍니다.

<Note>
생략은 최적화 옵션과 상관없이 일어납니다. `-O0`에서도 위 결과가 같습니다. GCC와 Clang에서 `-fno-elide-constructors`를 주면 NRVO를 끌 수 있어서, 생략이 없을 때 무엇이 불리는지 확인해 볼 수 있습니다.
</Note>

## 정리

- 값을 돌려줄 때는 `return x;`. 컴파일러가 생략하거나 이동한다
- `std::move`는 다 쓴 변수를 넘길 때만. `return`과 `const`에는 붙이지 않는다
- 옮긴 변수는 새 값을 넣기 전에는 읽지 않는다
