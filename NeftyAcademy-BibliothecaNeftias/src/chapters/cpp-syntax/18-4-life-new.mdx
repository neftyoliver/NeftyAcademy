export const summary = 'new가 하는 두 가지 일, 메모리와 객체를 따로 다루기, 힙 없이 컨테이너 쓰기';

`new`와 `delete`를 [직접 쓰지는 않지만](#/read/cpp-syntax/ft-ownership), `std::vector`와 `std::make_unique`의 안에서는 그것이 돌고 있습니다. 무슨 일을 하는지 알면 컨테이너의 동작이 이해되고, 힙을 쓸 수 없는 환경에서 무엇을 할 수 있는지가 보입니다.

## 두 가지 일

```cpp
#include <array>
#include <cstddef>
#include <memory>
#include <memory_resource>
#include <new>
#include <print>
#include <vector>

struct Sample {
    int channel;
    double value;
    Sample(int c, double v) : channel(c), value(v)
    {
        std::println("+ Sample {}", channel);
    }
    ~Sample() { std::println("- Sample {}", channel); }
};

int main()
{
    // 1. new와 delete
    Sample* a = new Sample(1, 0.5);
    delete a;

    // 2. placement new: 이미 있는 메모리에 생성만 한다
    alignas(Sample) std::byte storage[sizeof(Sample)];
    Sample* b = new (storage) Sample(2, 1.5);
    std::println("{}", static_cast<void*>(b) == static_cast<void*>(storage));
    b->~Sample();                       // 소멸자를 직접 부른다. 해제는 없다

    // 3. 같은 일을 하는 표준 함수
    Sample* c = std::construct_at(reinterpret_cast<Sample*>(storage), 3, 2.5);
    std::destroy_at(c);

    // 4. 스택의 버퍼에서 메모리를 받는 vector
    std::array<std::byte, 256> buffer;
    std::pmr::monotonic_buffer_resource pool(buffer.data(), buffer.size(),
                                             std::pmr::null_memory_resource());
    std::pmr::vector<int> values(&pool);
    for (int i = 0; i < 8; ++i)
        values.push_back(i * i);
    std::println("{} {}", values.size(), values.back());
}
```

```text
+ Sample 1
- Sample 1
+ Sample 2
true
- Sample 2
+ Sample 3
- Sample 3
8 49
```

`new Sample(1, 0.5)`는 두 단계입니다.

| 단계 | 하는 일 | 실패하면 |
| --- | --- | --- |
| 1. 할당 | `operator new(sizeof(Sample))`로 메모리를 얻는다 (보통 `malloc`) | `std::bad_alloc` 예외 |
| 2. 생성 | 그 메모리에서 생성자를 부른다 | 생성자의 예외. 1의 메모리는 자동으로 돌려준다 |

`delete a`는 거꾸로입니다. 소멸자를 부르고, `operator delete`로 메모리를 돌려줍니다.

C의 `malloc`은 1만 합니다. 그래서 `malloc`으로 얻은 메모리에는 **객체가 없고**, `std::string` 멤버가 든 구조체를 `malloc`으로 만들어 쓰면 안 됩니다.

## 짝을 맞춘다

| 얻은 방법 | 돌려주는 방법 |
| --- | --- |
| `new T` | `delete p` |
| `new T[n]` | `delete[] p` |
| `malloc` | `free` |

엇갈리면 정의되지 않은 동작입니다. `new T[n]`은 원소 개수를 어딘가에 적어 두고 `delete[]`가 그것을 읽어 소멸자를 `n`번 부릅니다. `delete`로 지우면 그 약속이 깨집니다. `std::vector`와 `std::make_unique<T[]>(n)`을 쓰면 신경 쓸 일이 없습니다.

`new (std::nothrow) T`는 실패하면 예외 대신 `nullptr`을 돌려줍니다. 예외를 끈 환경에서 씁니다.

## placement new

`new (주소) T(인자)`는 **할당을 건너뛰고** 주어진 주소에서 생성자만 부릅니다. 메모리는 미리 마련해 둔 것이어야 하고, 두 가지를 맞춰야 합니다.

- 크기: `sizeof(T)` 이상
- [정렬](#/read/cpp-syntax/life-alignment): `alignas(T)`

이렇게 만든 객체는 `delete`하지 않습니다. 메모리를 `new`로 얻은 것이 아니기 때문입니다. **소멸자만** 직접 부릅니다(`b->~Sample()`). 소멸자를 직접 부르는 거의 유일한 경우입니다.

C++20의 `std::construct_at(p, 인자…)`와 `std::destroy_at(p)`가 같은 일을 하는 함수입니다. 문법이 평범하고 [`constexpr`](#/read/cpp-syntax/ct-constexpr) 안에서도 쓸 수 있습니다.

## 어디에 쓰이나

**메모리를 얻는 일과 객체를 만드는 일을 떼어 놓아야** 하는 모든 곳입니다.

| 쓰는 곳 | 까닭 |
| --- | --- |
| `std::vector` | `reserve(100)`은 메모리만 얻는다. 객체는 `push_back`할 때 그 자리에 하나씩 만든다. [`capacity`와 `size`](#/read/cpp-syntax/ft-vector)의 차이가 이것이다 |
| `std::optional`, `std::variant`, `std::expected` | 자기 안에 자리를 품고 있다가, 값이 생길 때 거기에 만든다 |
| 객체 풀 | 같은 크기의 칸을 미리 잡아 두고 돌려 쓴다. 할당 시간이 일정하다 |
| 힙이 없는 환경 | 정적 버퍼에 객체를 만든다 |

`emplace_back(인자…)`가 `push_back(T(인자…))`보다 나은 까닭도 여기 있습니다. 임시 객체를 만들어 옮기지 않고, 벡터의 그 칸에서 **바로** 생성자를 부릅니다.

## 힙 없이 컨테이너 쓰기

표준 컨테이너는 메모리를 **할당자**에게서 받습니다. C++17의 `std::pmr`(`<memory_resource>`)은 할당자를 실행 중에 바꿔 끼울 수 있게 합니다.

| 자원 | 동작 |
| --- | --- |
| `std::pmr::monotonic_buffer_resource` | 주어진 버퍼를 앞에서부터 잘라 준다. 해제는 아무 일도 안 한다. 자원이 사라질 때 한꺼번에 버린다 |
| `std::pmr::unsynchronized_pool_resource` | 크기별 풀. 해제한 칸을 다시 쓴다 |
| `std::pmr::null_memory_resource()` | 늘 실패한다(`bad_alloc`). "여기서 더는 안 된다"를 표시한다 |

위 예제의 `values`는 `std::vector<int>`와 쓰는 법이 똑같지만 힙을 한 번도 건드리지 않습니다. 256바이트 버퍼가 바닥나면 둘째 인자로 준 `null_memory_resource` 때문에 예외가 납니다. 둘째 인자를 생략하면 **조용히 힙으로 넘어갑니다.** 힙을 쓰면 안 되는 코드에서는 위처럼 막아 둡니다.

한 번의 요청이나 한 주기 동안 쓰고 통째로 버리는 임시 데이터에 잘 맞습니다. 주기마다 `pool.release()`로 버퍼를 처음부터 다시 씁니다. 제어 루프 안에서 `std::pmr::string`과 `std::pmr::vector`를 써도 할당 시간이 일정합니다.

## 정렬된 할당

`new`가 주는 메모리는 `alignof(std::max_align_t)`(64비트에서 16)에 맞춰져 있습니다. 그보다 큰 정렬이 필요한 타입(`alignas(64)`)은 C++17부터 `new`가 알아서 정렬된 할당 함수를 고릅니다. 날것의 메모리가 필요하면 `std::aligned_alloc(정렬, 크기)`(`<cstdlib>`)을 쓰고 `std::free`로 돌려줍니다.

<Note kind="warn">
같은 저장소에 객체를 다시 만들 때는 **먼저 있던 객체의 소멸자를 부른 뒤**에 만듭니다. 그리고 옛 포인터 `b`가 아니라 새로 받은 포인터 `c`를 씁니다. 타입이 같으면 대개 옛 포인터도 통하지만, `const` 멤버나 참조 멤버가 있으면 컴파일러가 "그 값은 안 바뀐다"고 믿고 최적화할 수 있습니다.
</Note>

## 정리

- `new`는 메모리 할당과 생성자 호출, `delete`는 소멸자 호출과 메모리 해제
- placement new와 `std::construct_at`은 이미 있는 메모리에 객체만 만든다. 소멸자는 직접 부른다
- `std::pmr`의 버퍼 자원을 쓰면 표준 컨테이너를 힙 없이 쓸 수 있다
