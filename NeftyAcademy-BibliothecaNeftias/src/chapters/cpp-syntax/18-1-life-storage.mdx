모든 객체는 **언제 만들어지고 언제 사라지는지**가 정해져 있습니다. 그것을 정하는 것이 저장 기간이고, 네 가지가 있습니다.

## 네 가지

```cpp
#include <memory>
#include <print>
#include <thread>

struct Trace {
    const char* name;
    explicit Trace(const char* n) : name(n) { std::println("+ {}", name); }
    ~Trace() { std::println("- {}", name); }
};

Trace global{"전역"};                       // 정적: main 전에 만들어진다

thread_local int calls = 0;                 // 스레드: 스레드마다 하나씩

void visit()
{
    static Trace once{"static 지역"};       // 정적: 처음 지나갈 때 한 번만
    Trace local{"지역"};                    // 자동: 블록이 끝나면 사라진다
    ++calls;
}

int main()
{
    std::println("main 시작");
    visit();
    visit();

    auto heap = std::make_unique<Trace>("동적");    // 동적: 지울 때까지
    heap.reset();

    std::thread worker([] {
        ++calls;
        std::println("worker의 calls = {}", calls);
    });
    worker.join();
    std::println("main의 calls = {}", calls);
    std::println("main 끝");
}
```

```text
+ 전역
main 시작
+ static 지역
+ 지역
- 지역
+ 지역
- 지역
+ 동적
- 동적
worker의 calls = 1
main의 calls = 2
main 끝
- static 지역
- 전역
```

| 저장 기간 | 해당하는 것 | 사는 동안 |
| --- | --- | --- |
| 자동 | 지역 변수, 매개변수 | 선언을 지나갈 때부터 블록이 끝날 때까지 |
| 정적 | 전역 변수, `static` 변수, `static` 멤버 | `main` 전부터 `main`이 끝난 뒤까지. 지역 `static`은 처음 지나갈 때부터 |
| 동적 | `new`, `make_unique`, 컨테이너의 원소 | 요청할 때부터 지울 때까지 |
| 스레드 | `thread_local` 변수 | 스레드가 처음 쓸 때부터 스레드가 끝날 때까지 |

메모리는 차례로 스택, 실행 파일의 데이터 구역, 힙, 스레드마다 따로 잡힌 구역에 놓입니다. 정적 객체는 만들어진 거꾸로 순서로 사라집니다.

## 자동

스택에 놓입니다. 만들고 없애는 비용이 스택 포인터를 옮기는 것뿐이라 가장 쌉니다. 크기는 컴파일할 때 정해져야 하고, 스택 전체의 크기에는 한도가 있습니다(리눅스 주 스레드는 보통 8MB, `ulimit -s`). 큰 배열은 지역 변수로 두지 않습니다.

블록을 벗어나면 사라지므로, 지역 변수의 주소나 참조를 [밖으로 내보내면](#/read/cpp-syntax/ref-return) 안 됩니다.

## 정적

프로그램이 도는 내내 있습니다. 실행 파일 안에 자리가 미리 잡혀 있습니다.

| 구역 | 들어가는 것 |
| --- | --- |
| `.rodata` | `const`, `constexpr` 상수, 문자열 리터럴. 읽기 전용 |
| `.data` | 0이 아닌 초기값이 있는 변수 |
| `.bss` | 0으로 시작하는 변수. 실행 파일에서 자리를 차지하지 않는다 |

초기화는 두 단계입니다. 컴파일할 때 값이 정해지는 것은 **실행 파일에 박혀** 있고, 생성자를 돌려야 하는 것(`Trace global`)은 `main` 전에 코드가 실행됩니다. 뒤쪽이 [초기화 순서 문제](#/read/cpp-syntax/life-static-init)의 근원입니다.

## static 지역 변수

함수 안의 `static` 변수는 정적 저장 기간이지만 초기화는 **처음 그 줄을 지나갈 때** 일어납니다. 위에서 `visit()`을 두 번 불렀어도 "static 지역"은 한 번만 만들어졌습니다.

- 여러 스레드가 동시에 처음 지나가도 **한 번만** 초기화된다. C++11부터 언어가 보장한다
- 그 보장을 위해 지나갈 때마다 "이미 했는가"를 확인하는 명령 몇 개가 든다
- 초기값이 상수면 확인도 없다. 실행 파일에 박힌다

"필요할 때 한 번 만들어지는 전역 객체"를 얻는 안전한 방법입니다.

## 동적

수명을 **직접** 정합니다. 블록과 상관없이 살 수 있고, 크기를 실행 중에 정할 수 있습니다. 대가는 할당에 드는 시간, 단편화, 그리고 지우는 것을 잊을 가능성입니다.

`new`와 `delete`를 [직접 쓰지 않고](#/read/cpp-syntax/ft-ownership), 동적 객체를 **자동 객체가 쥐게** 합니다. `std::unique_ptr`, `std::vector`, `std::string`이 그런 자동 객체입니다. 그러면 동적 객체의 수명이 그것을 쥔 객체의 수명을 따라가고, 블록이 끝날 때 함께 정리됩니다. [`new`가 하는 일](#/read/cpp-syntax/life-new)은 뒤에서 봅니다.

## 스레드

`thread_local` 변수는 스레드마다 사본이 하나씩 있습니다. 위에서 `main`의 `calls`는 2, `worker`의 `calls`는 1입니다. 서로의 것을 건드리지 않으므로 잠금이 필요 없습니다. `errno`가 이렇게 만들어져 있습니다. 스레드별 캐시, 난수 생성기, 재진입 방지 표시에 씁니다.

## 수명과 저장 기간

**저장 기간**은 메모리가 있는 기간이고, **수명**은 그 메모리에 쓸 수 있는 객체가 있는 기간입니다. 수명은 생성자가 끝날 때 시작해서 소멸자가 시작될 때 끝납니다.

| 상황 | 메모리 | 객체 |
| --- | --- | --- |
| 생성자가 도는 중 | 있다 | 아직 완성되지 않았다 |
| [`std::move`된 뒤](#/read/cpp-syntax/sm-move) | 있다 | 살아 있다. 값만 비었다 |
| 소멸자가 끝난 뒤, 메모리 해제 전 | 있다 | **없다** |
| `vector`의 `capacity`와 `size` 사이 | 있다 | 없다. 날것의 메모리 |

메모리가 있다고 객체가 있는 것은 아닙니다. 수명이 끝난 객체를 건드리는 것이 C++에서 가장 흔한 [정의되지 않은 동작](#/read/cpp-syntax/ubc-lifetime)입니다.

<Note>
마이크로컨트롤러에서는 동적 할당을 아예 쓰지 않는 것이 흔한 규칙입니다. 단편화로 인한 실패를 미리 알 수 없기 때문입니다. 모든 객체를 정적으로 두고, 크기가 변하는 것은 [고정 크기 버퍼](#/read/cpp-syntax/tpl-nontype) 안에서 다룹니다. 라즈베리 파이 급에서는 힙을 써도 되지만, 주기적으로 도는 제어 루프 **안에서** 할당하지 않는 것은 여전히 좋은 습관입니다.
</Note>

## 정리

- 자동(스택, 블록까지), 정적(프로그램 내내), 동적(지울 때까지), 스레드(스레드마다)
- `static` 지역 변수는 처음 지나갈 때 한 번, 스레드에 안전하게 초기화된다
- 메모리가 있는 것과 객체가 살아 있는 것은 다르다
