C의 `(타입)값`은 무엇이든 바꿔 줍니다. 숫자를 숫자로, 포인터를 다른 포인터로, `const`를 떼는 것까지 같은 문법입니다. C++은 그것을 **목적별로 넷**으로 나눴습니다. 길고 눈에 띄는 이름은 일부러 그렇게 지은 것입니다.

| 변환 | 하는 일 | 위험 |
| --- | --- | --- |
| `static_cast<T>(v)` | 서로 관계있는 타입 사이의 변환 | 낮다 |
| `const_cast<T>(v)` | `const`, `volatile`을 붙이거나 뗀다 | 뗀 뒤에 고치면 위험하다 |
| [`reinterpret_cast<T>(v)`](#/read/cpp-syntax/cast-reinterpret) | 비트를 다른 타입으로 읽는다 | 높다 |
| [`dynamic_cast<T>(v)`](#/read/cpp-syntax/inh-rtti) | 실제 타입을 확인하고 내려간다 | 낮다 (실행 중 비용이 있다) |

## static_cast

```cpp
#include <cstdint>
#include <print>
#include <utility>

enum class Mode : std::uint8_t { input = 0, output = 1 };

// 인자를 고치지는 않는 옛 함수
void legacy_print(char* text) { std::println("{}", text); }

int main()
{
    int total = 7, count = 2;
    std::println("{} {}", total / count, static_cast<double>(total) / count);

    int raw = 300;
    auto low = static_cast<std::uint8_t>(raw);      // 일부러 아래 8비트만 남긴다
    std::println("{}", low);

    Mode m = static_cast<Mode>(1);                  // 정수 → enum class
    std::println("{} {}", static_cast<int>(m), std::to_underlying(m));

    double sample = 3.7;
    void* user_data = &sample;                      // C 콜백에 넘기는 꼴
    auto* back = static_cast<double*>(user_data);   // 넣을 때와 같은 타입으로
    std::println("{}", *back);

    const char* name = "gpio";
    legacy_print(const_cast<char*>(name));          // const를 뗀다
}
```

```text
3 3.5
44
1 1
3.7
gpio
```

`static_cast`는 컴파일러가 **변환하는 법을 아는** 경우에만 됩니다.

| 쓰임 | 예 |
| --- | --- |
| 숫자 타입 사이 | `static_cast<double>(total)`, `static_cast<std::uint8_t>(raw)` |
| 열거형과 정수 | `static_cast<Mode>(1)`. 거꾸로는 `std::to_underlying(m)`(C++23)이 더 낫다 |
| `void*`에서 원래 타입으로 | `static_cast<double*>(user_data)` |
| [`explicit` 생성자, `explicit` 변환 연산자](#/read/cpp-syntax/class-explicit) 부르기 | `static_cast<bool>(file)` |
| 부모 포인터를 자식으로 (확인 없이) | 실제 타입을 확실히 알 때만. 모르면 `dynamic_cast` |

`int*`를 `double*`로 바꾸는 것처럼 관계없는 포인터 사이는 **컴파일 오류**입니다. C 방식 변환이었다면 조용히 통과했을 자리입니다.

암시적으로도 되는 변환에 굳이 `static_cast`를 적는 것은 "여기서 값이 잘릴 수 있다는 것을 알고 있다"는 표시입니다. `-Wconversion`의 경고도 함께 사라집니다.

## const_cast

`const`를 떼는 **유일한** 변환입니다. 다른 셋은 `const`를 떼지 못합니다.

| 상황 | 결과 |
| --- | --- |
| 원래 `const`가 아닌 객체를 `const` 포인터로 보고 있다가, 떼고 고친다 | 괜찮다 |
| 원래부터 `const`로 선언된 객체를, 떼고 고친다 | **정의되지 않은 동작** |
| 떼기만 하고 고치지 않는다 | 괜찮다 |

위 예제는 셋째입니다. 인자를 `char*`로 받지만 실제로는 읽기만 하는 옛 C 함수를 부를 때가 `const_cast`의 거의 유일한 정당한 쓰임입니다. 문자열 리터럴 `"gpio"`는 읽기 전용 메모리에 있어서, `legacy_print`가 정말로 글자를 고치면 프로그램이 죽습니다.

`const`를 **붙이는** 쪽은 변환이 필요 없지만, 오버로드를 고르려고 일부러 붙일 때는 `std::as_const(v)`(`<utility>`)가 있습니다.

<Note kind="warn">
`const_cast`가 필요해졌다면 대개 설계 어딘가에서 `const`가 잘못 붙었거나 빠진 것입니다. 캐시처럼 "`const` 함수 안에서 고쳐야 하는 멤버"는 [`mutable`](#/read/cpp-syntax/class-const)이 맞는 도구입니다.
</Note>

## C 방식 변환이 하는 일

`(T)v`와 `T(v)`는 아래를 **차례로 시도해서 처음 되는 것**을 합니다.

1. `const_cast`
2. `static_cast`
3. `static_cast` 뒤에 `const_cast`
4. `reinterpret_cast`
5. `reinterpret_cast` 뒤에 `const_cast`

무엇이 골라졌는지 코드에 드러나지 않습니다. 더 나쁜 것은, 타입의 정의가 바뀌면 같은 줄이 **말없이 다른 변환**이 된다는 점입니다. 어제는 2번(안전한 숫자 변환)이었던 것이 오늘은 4번(비트 다시 읽기)이 됩니다.

| | C 방식 | 이름 있는 변환 |
| --- | --- | --- |
| 무슨 변환인지 | 읽는 사람이 추측한다 | 이름에 적혀 있다 |
| 찾기 | 괄호를 검색할 수 없다 | `_cast`로 검색된다 |
| `const` | 말없이 뗀다 | `const_cast`를 써야만 뗀다 |

GCC와 Clang의 `-Wold-style-cast`가 C 방식 변환을 모두 찾아 줍니다.

## 중괄호로 만들기

숫자를 다른 숫자 타입으로 바꿀 때 값이 **잘리면 안 되는** 경우에는 `T{v}`가 가장 안전합니다. [좁아지는 변환](#/read/cpp-syntax/types-init)이면 컴파일 오류가 됩니다.

```cpp nocheck
int raw = 300;
std::uint8_t a{raw};                        // 오류: 좁아진다
auto b = static_cast<std::uint8_t>(raw);    // 된다: 자르겠다고 밝혔다
std::int64_t c{raw};                        // 된다: 넓어진다
```

## 정리

- C 방식 변환 대신 목적에 맞는 이름 있는 변환을 쓴다. 대부분은 `static_cast`
- `const_cast`는 `const`를 떼는 유일한 길. 원래 `const`인 객체를 고치면 정의되지 않은 동작
- 값이 잘리면 안 되는 숫자 변환은 `T{v}`로 컴파일러에게 확인시킨다
