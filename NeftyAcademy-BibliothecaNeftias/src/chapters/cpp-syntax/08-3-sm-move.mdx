`std::vector<int>`의 속은 힙 메모리를 가리키는 포인터 몇 개입니다. 복사는 원소를 전부 새로 만들지만, **이동**은 그 포인터만 넘겨받습니다. 원본은 비고, 원소는 하나도 복사되지 않습니다.

## 이동 생성자와 이동 대입 연산자

```cpp
#include <cstddef>
#include <print>
#include <utility>
#include <vector>

class Buffer {
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer&) = delete;             // 이 예제에서는 복사를 막아 둔다
    Buffer& operator=(const Buffer&) = delete;

    Buffer(Buffer&& other) noexcept
        : size_(std::exchange(other.size_, 0)),
          data_(std::exchange(other.data_, nullptr))
    {
        std::println("이동 생성");
    }
    Buffer& operator=(Buffer&& other) noexcept
    {
        if (this != &other) {
            delete[] data_;
            size_ = std::exchange(other.size_, 0);
            data_ = std::exchange(other.data_, nullptr);
        }
        std::println("이동 대입");
        return *this;
    }

    std::size_t size() const { return size_; }

private:
    std::size_t size_;
    int* data_;
};

Buffer make(std::size_t n) { return Buffer(n); }

int main()
{
    Buffer a = make(8);             // 임시 객체에서 바로 만들어진다 (이동도 없다)
    Buffer b = std::move(a);        // 이동 생성: a의 메모리를 가져온다
    std::println("{} {}", a.size(), b.size());

    Buffer c(2);
    c = std::move(b);               // 이동 대입
    std::println("{} {}", b.size(), c.size());

    std::vector<Buffer> list;
    list.push_back(Buffer(4));      // 임시 객체를 벡터 안으로 이동
}
```

```text
이동 생성
0 8
이동 대입
0 8
이동 생성
```

`std::exchange(x, 새값)`은 `x`에 새 값을 넣고 **옛 값을 돌려줍니다.** "가져오고 비우기"를 한 줄로 씁니다.

이동 생성자가 하는 일은 셋입니다.

1. 상대의 포인터를 내 것으로 삼는다
2. 상대의 포인터를 `nullptr`로 만든다 (그래야 상대의 소멸자가 같은 메모리를 지우지 않는다)
3. 메모리 할당이 없으므로 실패할 일이 없다 → `noexcept`

## 옮겨진 뒤의 객체

`std::move(a)` 뒤의 `a`는 사라지지 않습니다. 범위가 끝나면 소멸자가 불립니다. 그래서 옮겨진 객체는 **소멸자가 탈 없이 돌 수 있는 상태**여야 합니다. 위에서는 크기 0, 포인터 `nullptr`입니다.

| 옮겨진 객체에 해도 되는 일 | 하면 안 되는 일 |
| --- | --- |
| 그냥 두기 (소멸) | 값이 남아 있다고 믿고 읽기 |
| 새 값을 대입하기 | |
| `clear()`처럼 상태를 묻지 않는 함수 | |

표준 라이브러리 타입은 옮겨진 뒤 "유효하지만 무엇이 들었는지는 정해지지 않은" 상태입니다. `std::unique_ptr`는 `nullptr`가 된다고 보장하고, `std::string`과 `std::vector`는 대개 비지만 보장은 아닙니다.

## noexcept를 붙여야 하는 까닭

`std::vector`가 꽉 차서 더 큰 메모리로 옮겨 갈 때, 원소를 **이동**하면 빠릅니다. 그런데 이동 도중에 예외가 나면 원소의 절반은 새 메모리에, 절반은 옛 메모리에 있게 되어 되돌릴 수 없습니다. 그래서 `vector`는 원소의 이동 생성자가 `noexcept`일 때만 이동하고, 아니면 **복사**합니다.

이동 생성자와 이동 대입 연산자에는 늘 `noexcept`를 붙입니다. 포인터를 바꿔치기하는 것뿐이라 실제로 던질 일도 없습니다.

## 받아서 보관하는 인자

```cpp
#include <print>
#include <string>
#include <utility>

class Device {
public:
    // 값으로 받아 멤버로 옮긴다
    explicit Device(std::string name) : name_(std::move(name)) {}
    const std::string& name() const { return name_; }

private:
    std::string name_;
};

int main()
{
    std::string label = "temperature-sensor-in-the-living-room";
    Device a(label);                    // 복사 1번 + 이동 1번
    Device b(std::move(label));         // 이동 2번. 복사 없음
    Device c("fan");                    // 임시 문자열을 만들어 이동
    std::println("{} {} {}", a.name().size(), b.name().size(), c.name());
}
```

```text
37 37 fan
```

보관할 인자를 값으로 받으면, 부르는 쪽이 좌측값을 주면 복사가, 우측값을 주면 이동이 일어납니다. `const std::string&` 판과 `std::string&&` 판을 둘 다 만드는 것과 거의 같은 효과를 함수 하나로 얻습니다. [「생성자와 멤버 초기화 리스트」](#/read/cpp-syntax/class-ctor)에서 쓴 방식입니다.

## 이것도 쓰지 않는 것이 답이다

위의 `Buffer`는 원리를 보이려고 손으로 썼습니다. 멤버를 `std::vector<int>`나 `std::unique_ptr<int[]>`로 두면 컴파일러가 이동 생성자와 이동 대입 연산자를 만들어 주고, 그것들은 멤버를 하나씩 이동하며 `noexcept`까지 알아서 붙습니다.

<Note>
`int`, 포인터, `std::array<int, 4>`처럼 속에 가리키는 것이 없는 타입은 이동과 복사가 같습니다. 이동이 빨라지는 것은 힙 메모리 같은 "바깥의 것"을 쥔 타입뿐입니다.
</Note>

## 정리

- 이동은 자원의 주인을 바꾸는 것. 원본은 비워서 소멸자가 탈 없게 한다
- 옮겨진 객체는 소멸하거나 새로 대입할 수만 있다고 생각한다
- 이동 연산에는 `noexcept`. 없으면 `std::vector`가 복사로 돌아선다
