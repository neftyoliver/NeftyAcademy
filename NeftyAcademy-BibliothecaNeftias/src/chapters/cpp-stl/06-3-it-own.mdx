내가 만든 컨테이너도 반복자만 내주면 범위 기반 for, 표준 알고리즘, 레인지의 뷰가 모두 그대로 돕니다. [「컨테이너, 반복자, 알고리즘」](#/read/cpp-stl/ov-parts)에서 본 설계의 값어치가 여기서 나옵니다. 가장 오래된 것부터 덮어쓰는 링 버퍼에 반복자를 붙여 봅니다.

## 링 버퍼에 반복자 붙이기

```cpp
#include <algorithm>
#include <array>
#include <cstddef>
#include <iterator>
#include <numeric>
#include <print>
#include <ranges>
#include <utility>

template <typename T, std::size_t N>
class Ring {
public:
    void push(T value)
    {
        items_[(start_ + size_) % N] = std::move(value);
        if (size_ < N)
            ++size_;
        else
            start_ = (start_ + 1) % N;      // 꽉 찼으면 가장 오래된 것을 덮어썼다
    }

    class iterator {
    public:
        using value_type = T;                       // 1. 가리키는 것의 타입
        // 2. 두 반복자의 거리를 담을 타입
        using difference_type = std::ptrdiff_t;

        iterator() = default;                       // 3. 인자 없이 만들 수 있다
        iterator(const Ring* ring, std::size_t offset)
            : ring_(ring), offset_(offset)
        {
        }

        const T& operator*() const                  // 4. 읽기
        {
            return ring_->items_[(ring_->start_ + offset_) % N];
        }
        iterator& operator++()                      // 5. 앞으로: ++it
        {
            ++offset_;
            return *this;
        }
        iterator operator++(int)                    //    it++ 도 있어야 한다
        {
            iterator old = *this;
            ++offset_;
            return old;
        }
        bool operator==(const iterator&) const = default;   // 6. 같은 자리인가

    private:
        const Ring* ring_ = nullptr;
        std::size_t offset_ = 0;        // 가장 오래된 것에서 몇째인가
    };

    iterator begin() const { return {this, 0}; }
    iterator end() const { return {this, size_}; }

private:
    std::array<T, N> items_{};
    std::size_t start_ = 0;     // 가장 오래된 원소의 자리
    std::size_t size_ = 0;
};

// 요건을 다 갖췄는지 컴파일러에게 확인시킨다
static_assert(std::forward_iterator<Ring<int, 4>::iterator>);
static_assert(std::ranges::forward_range<Ring<int, 4>>);

int main()
{
    Ring<int, 4> recent;
    for (int v = 1; v <= 6; ++v)
        recent.push(v);

    for (int v : recent)                            // 범위 기반 for
        std::print("{} ", v);
    std::println("");

    // 레인지 알고리즘
    std::println("최대 {}", std::ranges::max(recent));
    // 옛 알고리즘
    std::println("합 {}", std::accumulate(recent.begin(), recent.end(), 0));

    for (int v : recent | std::views::filter([](int x) { return x % 2 == 1; }))
        std::print("{} ", v);                       // 뷰
    std::println("");
}
```

```text
3 4 5 6
최대 6
합 18
3 5
```

1부터 6까지 넣었고 칸은 넷이므로 3, 4, 5, 6이 남았습니다. 배열 안에서는 `5 6 3 4`의 순서로 놓여 있지만, 반복자가 자리를 계산해 주므로 밖에서는 오래된 것부터 차례로 보입니다. 링 버퍼를 쓰는 쪽은 `%` 계산을 몰라도 됩니다.

## 전진 반복자의 요건

위의 번호가 [전진 반복자](#/read/cpp-stl/it-category)가 되는 데 필요한 전부입니다.

| 요건 | 빠뜨리면 |
| --- | --- |
| `value_type`, `difference_type` | 알고리즘이 원소의 타입을 알 수 없다 |
| 인자 없는 생성자 | 전진 반복자가 아니라 입력 반복자로만 인정된다 |
| `operator*` | 반복자가 아니다 |
| `++it`와 `it++` 둘 다 | 반복자가 아니다 |
| `==` | 끝과 견줄 수 없다 |
| 복사할 수 있고, 사본으로 다시 돌아도 같은 값이 나온다 | 전진 반복자가 아니다 |

무엇을 빠뜨렸는지는 눈으로 찾기 어렵습니다. 그래서 `static_assert(std::forward_iterator<…>)` 한 줄을 반드시 둡니다. 빠진 것이 있으면 컴파일러가 어느 요건이 깨졌는지 짚어 줍니다.

<Note>
C++20 전에는 반복자 안에 `iterator_category`, `pointer`, `reference`까지 다섯 타입을 적어야 옛 알고리즘이 받아 주었습니다. 지금은 위처럼 둘만 적어도 됩니다. 위 예제에서 옛 알고리즘인 `std::accumulate`가 그대로 돈 것이 그 때문입니다. 표준 라이브러리가 연산자를 보고 나머지를 추론합니다. C++17 이하로도 컴파일해야 하는 코드라면 다섯을 모두 적습니다.
</Note>

## 범주를 올리려면

| 되고 싶은 범주 | 더할 것 |
| --- | --- |
| 양방향 | `--it`, `it--` |
| 임의 접근 | `it += n`, `it + n`, `n + it`, `it -= n`, `it - n`, `it2 - it1`, `it[n]`, `<=>` |
| 연속 | 위에 더해, 원소가 실제로 줄지어 있어야 한다 |

링 버퍼의 반복자는 `offset_` 하나로 자리를 나타내므로 임의 접근까지 올릴 수 있습니다. 그러면 `std::ranges::sort`도 돌고 `std::ranges::distance`가 O(1)이 됩니다. 연속은 될 수 없습니다. 배열의 끝에서 처음으로 넘어가는 곳이 있기 때문입니다. 필요한 만큼만 올리면 됩니다. 연산자를 많이 적을수록 틀릴 곳도 늘어납니다.

고칠 수 있는 반복자와 읽기만 하는 반복자를 둘 다 내주려면(`iterator`와 `const_iterator`) 같은 코드를 두 번 쓰지 않게 템플릿으로 묶습니다. 위 예제는 읽기만 하는 것 하나로 줄였습니다.

## 더 짧은 길

차례로 값을 내주기만 하면 되고 범주가 중요하지 않다면, 반복자 클래스를 쓰지 않는 길이 둘 있습니다.

| 길 | 꼴 | 다루는 곳 |
| --- | --- | --- |
| 있던 뷰를 엮는다 | `std::views::iota(0u, size_) \| std::views::transform(…)` | [「파이프로 잇기」](#/read/cpp-stl/rng-pipe) |
| 코루틴 제너레이터 | `std::generator<int>`에서 `co_yield` | [「뷰 직접 만들기」](#/read/cpp-stl/rng-own) |

둘 다 코드는 훨씬 짧고, 얻는 것은 입력 범위나 그에 가까운 것입니다. 한 번 훑으면 되는 자리에는 이쪽이 낫습니다.

## 정리

- 반복자를 내주면 내 컨테이너에서 범위 기반 for, 알고리즘, 뷰가 모두 돈다
- 전진 반복자는 타입 둘, 기본 생성자, `*`, 두 가지 `++`, `==`로 된다. `static_assert`로 확인한다
- 범주는 필요한 만큼만 올린다. 한 번 훑기만 하면 뷰나 제너레이터가 더 짧다
