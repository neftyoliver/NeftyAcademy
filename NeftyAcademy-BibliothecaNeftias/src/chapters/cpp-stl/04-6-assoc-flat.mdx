[`map`](#/read/cpp-stl/assoc-map)은 원소마다 노드를 따로 잡습니다. 넣고 지우기는 싸지만 메모리가 많이 들고 찾을 때 흩어진 노드를 따라갑니다. 열쇠를 **정렬된 배열**에 담고 이진 탐색으로 찾으면 그 반대가 됩니다. C++23은 이 구조를 `std::flat_map`과 `std::flat_set`이라는 이름으로 넣었습니다.

## 숫자로 보는 차이

`int` 열쇠와 `int` 값 100만 쌍을 담았을 때 힙에서 쓴 양입니다.

| 컨테이너 | 힙 사용 | 쌍 하나에 |
| --- | --- | --- |
| `map<int, int>` | 48.0MB | 48바이트 |
| `unordered_map<int, int>` | 43.6MB | 약 44바이트 |
| 정렬된 `vector<pair<int, int>>` | 8.0MB | 8바이트 |

64비트 glibc에서 [`mallinfo2`로 잰](#/read/cpp-stl/ov-allocator) 값입니다. 자료 자체는 8바이트인데 노드 기반 컨테이너는 그 여섯 배를 씁니다. 램이 512MB인 보드에서는 이 차이가 설계를 가릅니다.

찾는 속도는 [앞에서 잰 값](#/read/cpp-stl/assoc-unordered)에 정렬된 `vector`를 더하면 이렇습니다.

| 원소 수 | `map` | 정렬된 `vector` | `unordered_map` |
| --- | --- | --- | --- |
| 100 | 5ns | 7ns | 4ns |
| 1만 | 82ns | 67ns | 11ns |
| 100만 | 1,400ns | 180ns | 50ns |

원소가 적을 때는 셋이 비슷하고, 많아지면 정렬된 `vector`가 `map`을 크게 앞섭니다. 비교 횟수는 둘 다 O(log n)으로 같지만, 배열은 한 덩어리여서 캐시에 잘 실립니다.

값을 치르는 곳은 넣기입니다. 무작위 열쇠 10만 개로 표를 만드는 데 걸린 시간입니다.

| 만드는 법 | 걸린 시간 |
| --- | --- |
| `map`에 하나씩 넣기 | 18ms |
| 정렬된 `vector`의 제자리에 하나씩 끼우기 | 523ms |
| `vector`에 다 넣고 한 번 정렬하기 | 6ms |

가운데에 끼울 때마다 뒤의 원소를 모두 밀기 때문에 둘째가 느립니다. 그래서 이 구조의 쓰임은 분명합니다. **한 번에 만들고, 그 뒤로는 찾기만 하는 표**입니다. 설정, 명령어 표, 보정표, 번호와 이름의 대응이 그렇습니다.

## 직접 만들기

필요한 것은 `vector`와 [`lower_bound`](#/read/cpp-stl/alg-sort)뿐이어서 어느 컴파일러에서나 됩니다.

```cpp
#include <algorithm>
#include <print>
#include <string>
#include <utility>
#include <vector>

class PinTable {
public:
    void add(int number, std::string name)      // 모으는 동안에는 뒤에 붙이기만
    {
        items_.emplace_back(number, std::move(name));
    }
    void finish()                               // 다 모았으면 한 번 정렬한다
    {
        std::ranges::sort(items_, {}, &Item::first);
    }
    const std::string* find(int number) const
    {
        const auto it = std::ranges::lower_bound(items_, number, {}, &Item::first);
        return it != items_.end() && it->first == number ? &it->second : nullptr;
    }

private:
    using Item = std::pair<int, std::string>;
    std::vector<Item> items_;
};

int main()
{
    PinTable pins;
    pins.add(27, "button");
    pins.add(4, "fan");
    pins.add(17, "led");
    pins.finish();

    for (int number : {17, 5}) {
        if (const std::string* name = pins.find(number))
            std::println("{} -> {}", number, *name);
        else
            std::println("{} -> 없음", number);
    }
}
```

```text
17 -> led
5 -> 없음
```

내용이 컴파일할 때 정해져 있으면 [「array」](#/read/cpp-stl/seq-array)에서 본 것처럼 `constexpr std::array`로 두고 `static_assert`로 정렬을 확인합니다. 그러면 힙도 쓰지 않습니다.

## std::flat_map

`std::flat_map`은 위의 일을 `map`과 같은 인터페이스로 감싼 어댑터입니다. `[]`, `insert`, `find`, `contains`, `lower_bound`, `erase`를 그대로 씁니다.

```cpp libcxx
#include <flat_map>
#include <print>
#include <string>
#include <utility>
#include <vector>

int main()
{
    std::flat_map<int, std::string> pins;
    pins[27] = "button";
    pins[4] = "fan";
    pins[17] = "led";
    for (const auto& [number, name] : pins)     // 열쇠 순서로 나온다
        std::print("{}={} ", number, name);
    std::println("");

    // 열쇠와 값이 서로 다른 배열에 들어 있다
    std::println("keys {} {} {} / values {}", pins.keys()[0], pins.keys()[1],
                 pins.keys()[2], pins.values()[0]);

    const auto it = pins.lower_bound(10);
    const auto index = it - pins.begin();
    std::println("10 이상인 첫 열쇠 {}, 앞에서 {}번째", it->first, index);

    // 이미 정렬된 자료가 있으면 정렬을 건너뛰고 그대로 넘겨받는다
    std::vector<int> numbers = {1, 5, 9};
    std::vector<std::string> names = {"a", "b", "c"};
    std::flat_map<int, std::string> ready(std::sorted_unique, std::move(numbers),
                                          std::move(names));
    std::println("{}", ready.at(5));
}
```

```text
4=fan 17=led 27=button
keys 4 17 27 / values fan
10 이상인 첫 열쇠 17, 앞에서 1번째
b
```

`map`과 달라지는 점은 구조에서 나옵니다.

| | `map` | `flat_map` |
| --- | --- | --- |
| 넣기, 지우기 | O(log n) | O(n). 뒤를 민다 |
| 넣었을 때 반복자와 참조 | 죽지 않는다 | [`vector`처럼](#/read/cpp-stl/seq-invalidation) 죽는다 |
| 반복자 | 한 칸씩 앞뒤로 | 건너뛸 수 있다 (`it - begin()`) |
| 속의 저장소 | 노드 | 열쇠의 배열과 값의 배열, 둘 |

열쇠와 값이 따로 있으므로 원소는 `pair<const Key, Value>` 한 덩어리가 아닙니다. 반복자가 내주는 것은 열쇠의 참조와 값의 참조를 묶은 것이고, 그래서 `auto& entry = *it;`처럼 참조로 받는 코드는 컴파일되지 않습니다. 위처럼 구조적 바인딩으로 받으면 됩니다.

<Note kind="warn">
`<flat_map>`과 `<flat_set>`은 GCC 15부터 있습니다. 이 책이 기준으로 삼는 GCC 14에는 없어서, 위 예제는 Clang 20과 libc++로 확인했습니다. libc++ 20에는 `flat_map`만 있고 `flat_set`은 그 뒤 판에 들어갔습니다. 라즈베리파이 OS의 기본 컴파일러에서 쓰려면 [「헤더 지도」](#/read/cpp-stl/ov-headers)의 `__has_include`로 갈라 쓰거나, 앞 절처럼 직접 만든 것을 씁니다.
</Note>

## 고르는 기준

| 상황 | 고르는 것 |
| --- | --- |
| 한 번 만들고 찾기만 한다 | 정렬된 `vector`, `flat_map` |
| 원소가 수십 개쯤이다 | 정렬된 `vector`, `flat_map`. 넣는 값도 작다 |
| 계속 넣고 지운다. 원소가 많다 | `map`, `unordered_map` |
| 원소를 가리키는 포인터를 밖에 둔다 | `map`, `unordered_map` |

## 정리

- 정렬된 배열에 이진 탐색은 `map`과 같은 O(log n)이면서 메모리를 몇 분의 일만 쓰고, 클수록 더 빠르다
- 값은 넣기에서 치른다. 다 모아 한 번 정렬하고, 그 뒤로는 찾기만 하는 표에 쓴다
- `std::flat_map`은 GCC 15부터다. 그 전에는 `vector`와 `lower_bound`로 직접 만든다
