`sleep(100)`의 100은 초일까요, 밀리초일까요. `<chrono>`는 이 물음이 생기지 않게 합니다. [「사용자 정의 리터럴」](#/read/cpp-syntax/types-literal)에서 `1500ms` 같은 접미어를 잠깐 봤습니다. 그 뒤에 있는 타입 둘, **기간**(`duration`)과 **시각**(`time_point`)을 봅니다.

## 기간은 수와 단위

`std::chrono::duration<Rep, Period>`는 수 하나(`Rep`)와, 그 수의 1이 몇 초인지(`Period`)로 되어 있습니다. 단위는 타입에만 있고 객체에는 수만 들어 있습니다.

| 타입 | 한 눈금 | 접미어 |
| --- | --- | --- |
| `nanoseconds`, `microseconds`, `milliseconds` | 10⁻⁹초, 10⁻⁶초, 10⁻³초 | `ns`, `us`, `ms` |
| `seconds`, `minutes`, `hours` | 1초, 60초, 3600초 | `s`, `min`, `h` |
| `days`, `weeks` (C++20) | 86400초, 7일 | 없다. `days{3}`으로 쓴다 |
| `months`, `years` (C++20) | 평균 길이 | 없다 |

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;
using namespace std::chrono_literals;

int main()
{
    const auto timeout = 1500ms;
    std::println("{} / count {} / {}바이트", timeout, timeout.count(),
                 sizeof timeout);

    // 단위가 달라도 계산된다. 결과는 더 잔 단위
    std::println("{} {}", 2s + 500ms, 1h + 30min);
    std::println("{} {}", 90min == 1h + 30min, 59s < 1min);

    // 기간 / 수 = 기간, 기간 / 기간 = 수
    std::println("{} {} {}", 3s / 2, 10s / 4s, 10s % 4s);

    std::println("{} {}", days{1}, duration_cast<hours>(days{1}));
    const auto limit = duration_cast<years>(nanoseconds::max());
    std::println("나노초로 셀 수 있는 최대: {}년", limit.count());
}
```

```text
1500ms / count 1500 / 8바이트
2500ms 90min
true true
1s 2 2s
1d 24h
나노초로 셀 수 있는 최대: 292년
```

`2s + 500ms`는 2.5초가 아니라 `2500ms`입니다. 두 단위를 다 정확히 나타낼 수 있는 단위로 컴파일러가 맞춥니다. 실행 시간에 드는 것은 곱셈 한 번이고, 단위가 같으면 그것도 없습니다. 객체는 64비트 정수 하나입니다.

`3s / 2`가 `1s`인 것은 정수 나눗셈이기 때문입니다. 표준 단위의 `Rep`은 모두 정수입니다.

<Note kind="warn">
`months`와 `years`는 **평균 길이**입니다. `years{1}`은 정확히 31,556,952초(365.2425일)이고 `months{1}`은 그 12분의 1입니다. "한 달 뒤 같은 날"을 구하려고 시각에 `months{1}`을 더하면 날짜도 시각도 어긋납니다. 달력 위에서 달을 세는 법은 [「달력과 시간대」](#/read/cpp-stl/chr-calendar)에서 봅니다.
</Note>

## 잃는 변환은 적어야 한다

| 변환 | 예 | 방법 |
| --- | --- | --- |
| 잔 단위로 | 초 → 밀리초 | 저절로 된다 |
| 실수 기간으로 | 밀리초 → `duration<double>` | 저절로 된다 |
| 굵은 단위로 | 밀리초 → 초 | **적어야 한다** |

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;
using namespace std::chrono_literals;

int main()
{
    const milliseconds fine = 2s;           // 잃는 것이 없다
    // const seconds coarse = 1500ms;       // 컴파일 오류: 0.5초를 잃는다
    std::println("{}", fine);

    std::println("{:>7} | cast floor ceil round", "");
    for (const auto d : {1500ms, 2500ms, -1500ms}) {
        std::println("{:>7} | {:>4} {:>5} {:>4} {:>5}", d,
                     duration_cast<seconds>(d), floor<seconds>(d),
                     ceil<seconds>(d), round<seconds>(d));
    }

    // 실수 기간은 잃는 것이 없으므로 저절로 된다
    const duration<double> in_seconds = 1500ms;
    const duration<double, std::milli> in_ms = 250us;
    std::println("{} {}", in_seconds, in_ms);
}
```

```text
2000ms
        | cast floor ceil round
 1500ms |   1s    1s   2s    2s
 2500ms |   2s    2s   3s    2s
-1500ms |  -1s   -2s  -1s   -2s
1.5s 0.25ms
```

| 함수 | 방향 |
| --- | --- |
| `duration_cast<D>(d)` | 0 쪽으로 버린다 |
| `floor<D>(d)` | 작은 쪽으로 |
| `ceil<D>(d)` | 큰 쪽으로 |
| `round<D>(d)` | 가까운 쪽으로. 한가운데면 짝수로 |

타임아웃을 굵은 단위로 바꿀 때 `duration_cast`를 쓰면 **기다리는 시간이 줄어듭니다.** 1500ms를 약속했는데 1초만 기다립니다. "적어도 이만큼"이 뜻이라면 `ceil`입니다. `round`가 2500ms를 2초로 만든 것은 한가운데 값을 짝수로 보내는 규칙 때문입니다.

## 내 단위

`Period`는 [`std::ratio`](#/read/cpp-stl/num-complex)로 줍니다. 기기의 타이머 눈금을 그대로 타입으로 만들 수 있습니다.

```cpp
#include <chrono>
#include <cstdint>
#include <print>
#include <ratio>

using namespace std::chrono;
using namespace std::chrono_literals;

// 10ms 마다 1씩 오르는 32비트 틱 카운터
using ticks = duration<std::int32_t, std::ratio<1, 100>>;

int main()
{
    const ticks elapsed{250};
    std::println("{} = {}", elapsed, duration_cast<milliseconds>(elapsed));
    std::println("{}", ceil<ticks>(1234ms));
    std::println("{}", elapsed + 1s);
    std::println("{}바이트", sizeof(ticks));
}
```

```text
250cs = 2500ms
124cs
350cs
4바이트
```

1/100초는 센티초라서 `cs`로 찍힙니다. `elapsed + 1s`가 그대로 되고, 틱과 밀리초를 헷갈려 곱하거나 나누는 일이 없습니다. RTOS의 틱 수나 하드웨어 타이머 값을 받는 자리에서 한 번 이 타입으로 감싸 두면, 그 뒤의 코드는 단위를 신경 쓰지 않습니다.

## 시각

`std::chrono::time_point`는 "어떤 [시계](#/read/cpp-stl/chr-clocks)의 기준 시점에서 얼마만큼 지났는가"입니다. 속에는 기간 하나가 들어 있습니다.

| 식 | 결과 |
| --- | --- |
| 시각 − 시각 | 기간 |
| 시각 ± 기간 | 시각 |
| 시각 + 시각 | 컴파일 오류. 뜻이 없다 |
| 다른 시계의 시각끼리 | 컴파일 오류 |

```cpp
#include <chrono>
#include <print>
#include <thread>

using namespace std::chrono;
using namespace std::chrono_literals;

int main()
{
    const auto start = steady_clock::now();
    std::this_thread::sleep_for(20ms);
    const auto took = steady_clock::now() - start;
    std::println("20ms 넘게 걸렸다 {}", took >= 20ms);

    // 마감 시각을 정해 놓고 그때까지 되풀이한다
    const auto deadline = steady_clock::now() + 50ms;
    int polls = 0;
    while (steady_clock::now() < deadline) {
        ++polls;
        std::this_thread::sleep_for(10ms);
    }
    std::println("적어도 한 번 돌았다 {}", polls >= 1);

    // 날짜가 붙는 시각은 system_clock
    const sys_seconds unix_epoch{};
    std::println("{}", unix_epoch);
    std::println("{}", sys_seconds{1'800'000'000s});
}
```

```text
20ms 넘게 걸렸다 true
적어도 한 번 돌았다 true
1970-01-01 00:00:00
2027-01-15 08:00:00
```

**마감 시각**을 쓰는 것이 요령입니다. "50ms 동안 재시도"를 남은 시간을 빼 가며 세면 루프 안에서 걸린 시간만큼 밀립니다. 마감을 한 번 정하고 `now() < deadline`으로 견주면 밀리지 않습니다. 여러 단계에 걸친 타임아웃도 마감 시각 하나를 인자로 넘기면 됩니다.

## 함수 인자로 받기

```cpp nocheck
void wait_ready(int timeout_ms);                        // 단위가 이름에만 있다
void wait_ready(std::chrono::milliseconds timeout);     // 단위가 타입에 있다

wait_ready(2s);         // 2000ms 로 바뀌어 들어간다
wait_ready(500ms);
wait_ready(100);        // 컴파일 오류. 100 이 무엇인지 밝혀야 한다
```

기간을 받는 함수는 `int`가 아니라 `std::chrono` 타입으로 받습니다. 부르는 쪽은 편한 단위로 쓰고, 맨 숫자는 들어오지 못합니다. `.count()`로 수를 꺼내는 것은 `poll`이나 `select` 같은 C 함수에 넘기는 **마지막 한 줄**에서만 합니다. 중간에 꺼내면 단위가 다시 사람 머릿속으로 돌아갑니다.

## 정리

- `duration`은 수 하나이고 단위는 타입에 있다. 단위가 달라도 계산되고, 값을 잃는 변환만 `duration_cast`, `floor`, `ceil`, `round`로 적는다
- `time_point`는 시계의 기준 시점에서 잰 기간이다. 시각끼리 빼면 기간이 되고, 타임아웃은 마감 시각으로 다룬다
- 기간을 받는 함수는 `milliseconds` 같은 타입으로 받는다. `.count()`는 C 함수에 넘기는 자리에서만 쓴다
