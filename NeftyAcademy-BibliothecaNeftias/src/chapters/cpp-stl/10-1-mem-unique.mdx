[「unique_ptr로 보는 소유권」](#/read/cpp-syntax/ft-ownership)에서 `std::make_unique`로 만들고, `std::move`로 넘기고, 참조로 빌려 주는 법을 봤습니다. 여기서는 나머지 멤버 함수와, 컨테이너·배열·C 자원에 쓰는 모습을 봅니다.

## 멤버 함수

| 멤버 | 하는 일 | 객체를 지우나 |
| --- | --- | --- |
| `p.get()` | 든 포인터를 보여 준다 | 아니다 |
| `p.reset(q)` | 가진 것을 지우고 `q`의 주인이 된다. `q`를 빼면 비운다 | 지운다 |
| `p.release()` | 주인 노릇을 그만두고 포인터를 돌려준다 | **아니다** |
| `p.swap(q)` | 두 주인이 가진 것을 맞바꾼다 | 아니다 |
| `if (p)` | 비어 있지 않은가 | 아니다 |

```cpp
#include <memory>
#include <print>

struct Probe {
    int id;

    explicit Probe(int i) : id(i) { std::println("  Probe {} 생성", id); }
    ~Probe() { std::println("  Probe {} 소멸", id); }
};

int main()
{
    auto p = std::make_unique<Probe>(1);
    Probe* raw = p.get();           // 빌려 본다. 주인은 여전히 p
    std::println("get: {}", raw->id);

    std::println("reset");
    p.reset(new Probe(2));          // 1 을 지우고 2 의 주인이 된다

    std::println("release");
    Probe* loose = p.release();     // 지우지 않고 손을 뗀다
    std::println("p 는 {}", p ? "있음" : "비었음");
    delete loose;                   // 이제 내가 지워야 한다

    auto a = std::make_unique<Probe>(3);
    auto b = std::make_unique<Probe>(4);
    a.swap(b);
    std::println("swap 뒤 a {} b {}", a->id, b->id);
    a = nullptr;                    // a.reset() 과 같다
    std::println("main 끝");
}
```

```text
  Probe 1 생성
get: 1
reset
  Probe 2 생성
  Probe 1 소멸
release
p 는 비었음
  Probe 2 소멸
  Probe 3 생성
  Probe 4 생성
swap 뒤 a 4 b 3
  Probe 4 소멸
main 끝
  Probe 3 소멸
```

`reset(new Probe(2))`에서는 새 객체가 **먼저** 만들어지고 옛 객체가 그다음에 지워집니다. 둘이 잠깐 함께 살아 있으므로, 큰 버퍼를 갈아 끼울 때는 메모리가 두 배 필요합니다. 아깝다면 `p.reset()`으로 먼저 비우고 새로 만듭니다.

`release()`는 이름과 달리 아무것도 지우지 않습니다. "놓아준다"는 뜻입니다. 돌려받은 포인터를 버리면 그 객체는 영영 지워지지 않고, GCC 14는 경고도 하지 않습니다. 쓰는 자리는 하나입니다. 소유권을 넘겨받는 C 함수에 건넬 때입니다.

## 컨테이너에 담기

여러 종류의 객체를 한 줄로 세우려면 [기반 클래스의 포인터](#/read/cpp-syntax/inh-virtual)를 담아야 하고, 그 포인터의 주인으로 `unique_ptr`를 씁니다.

```cpp
#include <algorithm>
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Device {
    virtual ~Device() = default;
    virtual std::string name() const = 0;
    virtual int poll_ms() const = 0;
};

struct Thermometer : Device {
    std::string name() const override { return "온도계"; }
    int poll_ms() const override { return 1000; }
};

struct Button : Device {
    std::string name() const override { return "버튼"; }
    int poll_ms() const override { return 10; }
};

struct Display : Device {
    std::string name() const override { return "화면"; }
    int poll_ms() const override { return 100; }
};

int main()
{
    std::vector<std::unique_ptr<Device>> devices;
    devices.push_back(std::make_unique<Thermometer>());
    devices.push_back(std::make_unique<Button>());
    devices.push_back(std::make_unique<Display>());

    // 원소를 복사할 수 없으므로 참조로 돈다
    for (const auto& d : devices)
        std::println("{} {}ms", d->name(), d->poll_ms());

    // 정렬은 포인터 8바이트씩만 옮긴다
    std::ranges::sort(devices, {}, [](const auto& d) { return d->poll_ms(); });
    std::println("가장 자주: {}", devices.front()->name());

    // 하나를 꺼내 주인을 바꾼다
    std::unique_ptr<Device> taken = std::move(devices.back());
    devices.pop_back();
    std::println("꺼낸 것: {}, 남은 수 {}", taken->name(), devices.size());

    std::erase_if(devices, [](const auto& d) { return d->poll_ms() < 50; });
    std::println("남은 수 {}", devices.size());
}
```

```text
온도계 1000ms
버튼 10ms
화면 100ms
가장 자주: 버튼
꺼낸 것: 온도계, 남은 수 2
남은 수 1
```

`erase_if`로 빠진 원소와, `devices`가 사라질 때 남아 있던 원소는 저절로 지워집니다. `Device`의 소멸자가 [가상](#/read/cpp-syntax/inh-dtor)이어야 파생 클래스의 소멸자까지 불립니다.

걸리는 곳이 둘 있습니다.

- **중괄호로 채울 수 없다.** `std::vector<std::unique_ptr<Device>> v{std::make_unique<Button>()};`는 컴파일 오류입니다. 중괄호 목록의 원소는 복사해서 들어가는데 `unique_ptr`는 복사가 안 됩니다. `push_back`이나 `emplace_back`으로 하나씩 넣습니다
- **벡터를 복사할 수 없다.** `auto copy = devices;`는 오류이고 `std::move(devices)`만 됩니다. 이런 벡터를 멤버로 둔 클래스도 [복사가 저절로 막힙니다](#/read/cpp-syntax/sm-rules)

종류가 하나뿐이면 포인터가 필요 없습니다. `std::vector<Thermometer>`처럼 값을 바로 담는 쪽이 할당이 적고 [메모리에 나란히 놓여](#/read/cpp-stl/seq-vector) 빠릅니다.

## 배열

`unique_ptr<T[]>`는 `new T[n]`으로 얻은 배열의 주인입니다. 지울 때 `delete[]`를 쓰고, `*`와 `->` 대신 `[]`가 있습니다.

```cpp
#include <cstddef>
#include <memory>
#include <print>
#include <vector>

int main()
{
    const std::size_t n = 5;
    auto squares = std::make_unique<int[]>(n);      // 0 으로 채운 int 5 칸
    for (std::size_t i = 0; i < n; ++i)
        squares[i] = static_cast<int>(i * i);
    for (std::size_t i = 0; i < n; ++i)
        std::print("{}{}", i ? " " : "", squares[i]);
    std::println("");
    std::println("{} {}", sizeof squares, sizeof(std::vector<int>));
}
```

```text
0 1 4 9 16
8 24
```

길이를 스스로 기억하지 않고, 늘릴 수도 없고, 범위 기반 `for`도 안 됩니다. 그 대신 포인터 하나 크기입니다. 대부분은 `std::vector`가 맞고, 이것은 **길이가 실행 중에 한 번 정해지고 다른 곳에 이미 적혀 있는** 버퍼에 씁니다. 가로·세로를 따로 가진 화면 버퍼, C 함수에 넘길 임시 버퍼가 그렇습니다. 0으로 채우는 시간도 아까울 때 쓰는 `make_unique_for_overwrite`는 [「make_unique와 make_shared」](#/read/cpp-stl/mem-make)에서 봅니다.

## 삭제자

`unique_ptr`가 하는 일은 "사라질 때 정해진 방법으로 돌려준다"입니다. 그 방법이 꼭 `delete`일 필요는 없습니다. 둘째 템플릿 인자인 **삭제자**(deleter)를 바꾸면 `fclose`, `free`, 라이브러리의 `xxx_destroy` 같은 것을 맡길 수 있습니다.

```cpp
#include <cstdio>
#include <memory>
#include <print>

struct FileCloser {
    void operator()(std::FILE* f) const
    {
        std::println("  fclose 호출");
        std::fclose(f);
    }
};

using File = std::unique_ptr<std::FILE, FileCloser>;

File open_temp()
{
    return File(std::tmpfile());    // 실패하면 빈 File 이 된다
}

int main()
{
    {
        File f = open_temp();
        if (!f) {
            std::println("열지 못했다");
            return 1;
        }
        std::fputs("21.5\n", f.get());      // C 함수에는 get() 으로 넘긴다
        std::rewind(f.get());
        char line[16] = {};
        std::fgets(line, sizeof line, f.get());
        std::print("읽은 줄: {}", line);
    }
    std::println("블록 끝");

    using FnFile = std::unique_ptr<std::FILE, int (*)(std::FILE*)>;
    std::println("{} {} {}", sizeof(std::FILE*), sizeof(File), sizeof(FnFile));
}
```

```text
읽은 줄: 21.5
  fclose 호출
블록 끝
8 8 16
```

중간에 `return`하든 예외가 나든 `fclose`는 불립니다. [`goto cleanup`](#/read/cpp-syntax/leg-c-habits)으로 하던 일을 타입이 대신합니다. 비어 있을 때는 삭제자가 불리지 않으므로 `fclose(nullptr)` 걱정도 없습니다.

| 삭제자를 주는 법 | 크기 | 비고 |
| --- | --- | --- |
| 멤버가 없는 함수 객체 타입 | 8 | 타입에 들어 있어 자리를 차지하지 않는다 |
| 람다의 타입: `decltype([](std::FILE* f) { ... })` | 8 | C++20부터. 위와 같다 |
| 함수 포인터: `File(f, &close_file)` | 16 | 포인터를 객체마다 들고 다닌다 |

<Note kind="warn">
`std::unique_ptr<std::FILE, int (*)(std::FILE*)>(f, &std::fclose)`처럼 표준 함수의 주소를 바로 넘기는 코드가 흔하지만, C++20부터 표준 라이브러리 함수는 몇 개를 빼고는 주소를 얻어도 된다는 보장이 없습니다. 위처럼 함수 객체나 람다로 한 번 감쌉니다. 크기도 그쪽이 작습니다.
</Note>

## 흔한 실수

| 코드 | 일어나는 일 |
| --- | --- |
| `std::unique_ptr<T> a(raw), b(raw);` | 두 주인이 같은 객체를 두 번 지운다 |
| `delete p.get();` | 위와 같다. `get()`은 빌려 보는 것이다 |
| `p.release();` | 결과를 버리면 아무도 지우지 않는다 |
| `T* q = make().get();` | 임시 주인이 문장 끝에서 사라진다. `q`는 [죽은 객체](#/read/cpp-syntax/ubc-lifetime)를 가리킨다 |
| `std::unique_ptr<int> p(new int[8]);` | `delete`와 `delete[]`가 어긋난다 |

앞의 넷은 `new`와 맨 포인터가 섞일 때 생깁니다. `make_unique`로만 만들고 `get()`의 결과를 오래 들고 있지 않으면 만나지 않습니다.

<Note>
`unique_ptr<Impl>`을 멤버로 두고 `Impl`의 정의를 `.cpp`에 숨기면 "불완전한 타입"이라는 오류를 만납니다. 까닭과 고치는 법은 [「전방 선언과 pimpl」](#/read/cpp-syntax/mod-pimpl)에 있습니다. 삭제자가 상태를 가질 때와 삭제자로 타입을 지우는 기법은 [「unique_ptr과 삭제자」](#/read/cpp-advanced/sp-unique)에서 다룹니다.
</Note>

## 정리

- `reset`은 지우고, `release`는 지우지 않고 손만 뗀다. `get`은 빌려 볼 뿐이다
- `vector<unique_ptr<Base>>`는 여러 종류의 객체를 담는 기본 형태다. 중괄호로 채우거나 복사할 수는 없다
- 삭제자를 바꾸면 `FILE*` 같은 C 자원도 맡길 수 있고, 멤버 없는 함수 객체로 주면 크기는 포인터 하나 그대로다
