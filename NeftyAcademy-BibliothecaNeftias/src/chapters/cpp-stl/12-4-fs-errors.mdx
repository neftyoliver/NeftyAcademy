파일을 다루는 일은 실패가 일상입니다. 파일이 없고, 권한이 없고, 디스크가 차고, 카드가 뽑힙니다. `<filesystem>`의 함수는 거의 모두 **두 가지 판**으로 있어서, 실패를 예외로 받을지 값으로 받을지를 부르는 쪽이 고릅니다.

## 두 가지 판

```cpp
#include <cstdint>
#include <filesystem>
#include <print>
#include <system_error>

namespace fs = std::filesystem;

int main()
{
    const fs::path missing = "/no/x.txt";

    // 1. 인자가 경로뿐인 판: 실패하면 예외를 던진다
    try {
        std::println("{}", fs::file_size(missing));
    } catch (const fs::filesystem_error& e) {
        std::println("what  {}", e.what());
        std::println("path1 {}", e.path1().string());
        std::println("code  {} / {}", e.code().value(), e.code().message());
    }

    // 2. 끝에 error_code 를 받는 판: 던지지 않고 ec 에 적는다
    std::error_code ec;
    const std::uintmax_t size = fs::file_size(missing, ec);
    const bool failed = size == static_cast<std::uintmax_t>(-1);
    std::println("{} {} {}", failed, ec.value(), ec.message());

    // 성공하면 ec 는 지워진다
    const std::uintmax_t ok = fs::file_size("/etc/hostname", ec);
    std::println("{} {}", ok > 0, static_cast<bool>(ec));
}
```

```text
what  filesystem error: cannot get file size: No such file or directory [/no/x.txt]
path1 /no/x.txt
code  2 / No such file or directory
true 2 No such file or directory
true false
```

| | 던지는 판 | `error_code` 판 |
| --- | --- | --- |
| 모양 | `fs::file_size(p)` | `fs::file_size(p, ec)` |
| 실패하면 | `fs::filesystem_error` 예외 | `ec`에 까닭을 적고, 반환값은 정해진 "실패" 값 |
| 성공하면 | 값 | 값을 주고 `ec`를 지운다 |
| `noexcept` | 아니다 | 대개 그렇다 |

`fs::filesystem_error`는 [`std::system_error`](#/read/cpp-stl/err-system)를 상속하고, 관련된 경로를 `path1()`, `path2()`로 내줍니다(`rename`이나 `copy`처럼 경로가 둘인 함수는 둘 다 들어 있습니다). `what()`의 글은 구현마다 다르므로 사람에게 보여 주는 데만 쓰고, 판단은 `code()`로 합니다.

`error_code` 판의 **실패 값**은 함수마다 다릅니다. `file_size`는 `uintmax_t`의 최댓값, `bool`을 주는 함수는 `false`, `path`를 주는 함수는 빈 경로입니다. 반환값으로 판단하지 말고 <strong>`if (ec)`</strong>를 봅니다. `ec`는 부를 때마다 새로 적히므로 같은 변수를 계속 써도 됩니다.

## 까닭을 견주기

`ec.value()`는 운영체제의 오류 번호입니다. 리눅스의 2는 `ENOENT`이지만 윈도우에서는 다른 번호가 나옵니다. 번호를 직접 견주지 않고 `std::errc`의 이름과 견줍니다.

```cpp
#include <filesystem>
#include <print>
#include <system_error>

namespace fs = std::filesystem;

int main()
{
    std::error_code ec;
    // 반환값은 버리고 ec 만 본다
    static_cast<void>(fs::file_size("/no/such/file.txt", ec));
    std::println("{}", ec == std::errc::no_such_file_or_directory);
    std::println("{}", ec == std::errc::permission_denied);

    fs::create_directory("/no/such/parent/child", ec);
    std::println("{}", ec == std::errc::no_such_file_or_directory);

    fs::remove("/etc/hostname/inside", ec);
    std::println("{} ({})", ec == std::errc::not_a_directory, ec.message());

    // 없는 것은 exists 에게 오류가 아니다
    const bool there = fs::exists("/no/such/file.txt", ec);
    std::println("{} {}", there, static_cast<bool>(ec));
}
```

```text
true
false
true
true (Not a directory)
false false
```

| 자주 견주는 `std::errc` | 뜻 |
| --- | --- |
| `no_such_file_or_directory` | 없다 |
| `permission_denied` | 권한이 없다 |
| `file_exists` | 이미 있다 |
| `not_a_directory`, `is_a_directory` | 종류가 맞지 않는다 |
| `directory_not_empty` | 비지 않은 디렉터리를 지우려 했다 |
| `no_space_on_device` | 공간이 없다 |
| `cross_device_link` | 다른 파일 시스템으로 `rename`하려 했다 |

마지막 줄을 눈여겨봅니다. `fs::exists`에게 "없다"는 **답**이지 오류가 아닙니다. `ec`는 비어 있습니다. `exists`가 `ec`를 채우는 것은 "있는지조차 알 수 없을 때"(중간 디렉터리에 들어갈 권한이 없다)입니다.

## 왜 열리지 않는가

[「파일 스트림」](#/read/cpp-stl/io-file)에서 스트림은 열기에 실패한 까닭을 알려 주지 않는다고 했습니다. 사람에게 보여 줄 까닭이 필요하면 `<filesystem>`으로 묻습니다.

```cpp
#include <filesystem>
#include <fstream>
#include <print>
#include <string>
#include <system_error>

namespace fs = std::filesystem;

// 읽을 수 없는 까닭을 말로 돌려준다. 읽을 수 있으면 빈 문자열
std::string why_not_readable(const fs::path& path)
{
    std::error_code ec;
    const fs::file_status status = fs::status(path, ec);
    if (ec)
        return ec.message();
    if (fs::is_directory(status))
        return "디렉터리다";
    if (!fs::is_regular_file(status))
        return "보통 파일이 아니다";
    std::ifstream in(path);
    if (!in)
        return "열 수 없다. 권한을 확인할 것";
    return "";
}

int main()
{
    const char* paths[] = {
        "/no/such/file.txt",
        "/tmp",
        "/dev/null",
        "/etc/hostname/x",
        "/etc/hostname",
    };
    for (const char* path : paths)
        std::println("{:18} [{}]", path, why_not_readable(path));
}
```

```text
/no/such/file.txt  [No such file or directory]
/tmp               [디렉터리다]
/dev/null          [보통 파일이 아니다]
/etc/hostname/x    [Not a directory]
/etc/hostname      []
```

`fs::status`를 한 번 불러 놓고 그 결과에 `is_directory`, `is_regular_file`을 묻는 것이 요령입니다. 경로를 넘기면 물을 때마다 운영체제를 부릅니다. 권한은 `status.permissions()`의 비트로 볼 수도 있지만, 그 비트만으로는 읽을 수 있는지 알 수 없습니다(관리자, 그룹, ACL). 그래서 마지막에는 **실제로 열어 봅니다.** 그리고 이 함수의 답은 [그 순간의 것](#/read/cpp-stl/fs-ops)입니다. 진단에 쓰고, 이 답을 믿고 다음 동작을 정하지는 않습니다.

## 어느 쪽을 쓸까

| 상황 | 쓰는 판 |
| --- | --- |
| 실패가 예상 밖이다 (방금 만든 파일의 크기, 설치된 자료 읽기) | 던지는 판. 코드가 짧고 놓치지 않는다 |
| 실패가 흔하다 (있는지 떠보기, 여러 후보 경로를 차례로 시도) | `error_code` 판 |
| 루프 안에서 수천 번 부른다 | `error_code` 판. 예외는 [던질 때 비싸다](#/read/cpp-syntax/exc-unwind) |
| 소멸자, `noexcept` 함수, 정리 코드 | `error_code` 판 |
| 예외를 끈 빌드(`-fno-exceptions`) | `error_code` 판만 쓸 수 있다 |

한 가지 버릇을 조심합니다. `error_code` 판을 부르고 `ec`를 **보지 않는** 코드는 실패를 조용히 삼킵니다. 정리 코드에서 `fs::remove(temp, ec);`처럼 일부러 무시하는 것은 괜찮지만, 그 밖에는 부른 다음 줄에 `if (ec)`가 있어야 합니다. 던지는 판은 잊어도 프로그램이 멈추고, `error_code` 판은 잊으면 아무 일도 없었던 것처럼 넘어갑니다.

<Note>
`std::error_code`가 번호와 범주로 이루어져 있다는 것, `ec == std::errc::...`가 번호가 달라도 참이 되는 원리, 내 오류 번호를 같은 틀에 넣는 법은 [「system_error와 error_code」](#/read/cpp-stl/err-system)에서 다룹니다.
</Note>

## 정리

- `<filesystem>`의 함수는 예외를 던지는 판과 끝에 `error_code`를 받는 판이 짝으로 있다. 뒤의 것은 반환값이 아니라 `if (ec)`로 판단한다
- 까닭은 `ec == std::errc::no_such_file_or_directory`처럼 이름으로 견준다. `exists`에게 "없다"는 오류가 아니다
- 예상 밖의 실패에는 던지는 판을, 흔한 실패와 루프·소멸자·예외 없는 빌드에는 `error_code` 판을 쓴다
