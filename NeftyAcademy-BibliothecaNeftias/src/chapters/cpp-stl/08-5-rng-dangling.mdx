뷰와 레인지 알고리즘은 원소를 **가리킵니다.** 가리키는 것이 먼저 사라지면 [죽은 것을 가리키게](#/read/cpp-syntax/ubc-lifetime) 됩니다. 표준은 흔한 경우 몇 가지를 컴파일할 때 막아 두었고, 나머지는 사람이 지켜야 합니다. 어디까지 막아 주는지 압니다.

## 임시 레인지와 dangling

```cpp nocheck
std::vector<int> make_values();

auto it = std::ranges::find(make_values(), 2);  // 임시 vector 는 이 줄에서 사라진다
int value = *it;                                // 오류
```

```text
error: no match for 'operator*' (operand type is 'std::ranges::dangling')
```

`find`가 돌려준 것은 반복자가 아니라 `std::ranges::dangling`이라는 **빈 타입**입니다. 아무 연산도 없어서 쓰려는 순간 컴파일 오류가 납니다. 레인지 알고리즘은 받은 것이 곧 사라질 임시 객체이고 반복자를 돌려줘야 하는 경우에, 반복자 자리를 이 타입으로 바꿔 돌려줍니다. 옛 `std::find(make_values().begin(), …)`는 이런 보호가 없습니다.

반복자가 필요 없는 알고리즘은 임시 객체에도 그대로 됩니다. `std::ranges::count(make_values(), 2)`나 `std::ranges::any_of(make_values(), 조건)`은 값을 돌려주므로 문제가 없습니다.

## 빌린 레인지

임시 객체여도 괜찮은 레인지가 있습니다. 원소를 **자기가 들고 있지 않은** 것들입니다.

```cpp
#include <algorithm>
#include <print>
#include <ranges>
#include <span>
#include <string_view>
#include <vector>

int main()
{
    // string_view 는 임시 객체지만 글자는 다른 곳(문자열 상수)에 산다
    const auto it = std::ranges::find(std::string_view("raspberry"), 'p');
    std::println("{}", *it);

    std::println("string_view  {}", std::ranges::borrowed_range<std::string_view>);
    std::println("span<int>    {}", std::ranges::borrowed_range<std::span<int>>);
    std::println("vector<int>  {}", std::ranges::borrowed_range<std::vector<int>>);
    std::println("vector<int>& {}", std::ranges::borrowed_range<std::vector<int>&>);
}
```

```text
p
string_view  true
span<int>    true
vector<int>  false
vector<int>& true
```

`std::string_view`, `std::span`, `std::ranges::subrange`, `std::views::iota` 같은 것이 **빌린 레인지**입니다. 레인지 객체가 사라져도 그것이 내준 반복자는 여전히 쓸 수 있습니다. 이름 있는 컨테이너(좌측값 참조)도 그렇게 취급됩니다. 그래서 `std::ranges::find(v, 2)`는 평범하게 반복자를 돌려줍니다.

## 임시 객체를 넘겨받는 뷰

임시 컨테이너에 파이프를 거는 것은 됩니다. 뷰가 그 컨테이너를 **넘겨받아 들고** 있기 때문입니다.

```cpp
#include <print>
#include <ranges>
#include <utility>
#include <vector>

std::vector<int> make_values() { return {1, 2, 3, 4, 5, 6}; }

// 함수 안의 컨테이너를 뷰에 넘겨주고 돌려준다: 안전하다
auto evens()
{
    std::vector<int> local = {1, 2, 3, 4};
    return std::move(local) | std::views::filter([](int x) { return x % 2 == 0; });
}

int main()
{
    auto big = make_values() | std::views::filter([](int x) { return x > 3; });
    for (int x : big)           // big 이 vector 를 들고 있다
        std::print("{} ", x);
    std::println("");

    for (int x : evens())
        std::print("{} ", x);
    std::println("");
}
```

```text
4 5 6
2 4
```

우측값(임시 객체나 `std::move`한 것)에 파이프를 걸면 뷰가 주인이 됩니다. 이름 있는 컨테이너에 걸면 뷰는 가리키기만 합니다. `|`의 왼쪽이 무엇인가에 따라 소유가 갈립니다.

## 컴파일러가 못 막는 경우

위의 `evens`에서 `std::move`를 빼면 이렇게 됩니다.

```cpp nocheck
auto evens_bad()
{
    std::vector<int> local = {1, 2, 3, 4};
    return local | std::views::filter([](int x) { return x % 2 == 0; });
}   // local 은 여기서 사라진다. 돌려준 뷰는 그것을 가리키고 있다

for (int x : evens_bad())       // 죽은 vector 를 읽는다
    std::print("{} ", x);
```

```text
==8679==ERROR: AddressSanitizer: stack-use-after-return on address ...
```

GCC 14도 Clang 20도 `-Wall -Wextra`에서 경고하지 않습니다. `-fsanitize=address`로 돌려야 드러납니다. 같은 모양의 실수가 넷 있습니다.

| 코드 | 죽는 것 |
| --- | --- |
| 지역 컨테이너에 건 뷰를 돌려준다 | 컨테이너 |
| 뷰 속의 람다가 지역 변수를 참조로 잡았다 (`[&]`) | 그 지역 변수 |
| 뷰를 만든 뒤 원래 `vector`에 `push_back`한다 | [다시 할당된](#/read/cpp-stl/seq-invalidation) 옛 메모리 |
| 뷰를 멤버 변수로 들고 있다 | 가리키던 것이 객체보다 먼저 사라질 때 |

범위 기반 for의 콜론 오른쪽에 `임시객체.멤버()`를 쓰는 것도 같은 문제였고, C++23이 규칙을 바꿨지만 GCC 14는 아직 옛 규칙입니다. [「임시 객체의 수명」](#/read/cpp-syntax/life-temporary)에 적어 두었습니다.

<Note>
규칙을 하나로 줄이면 이렇습니다. **뷰는 만든 식 안에서 다 쓰고, 밖으로 내보낼 것은 컨테이너로 굳힙니다.** 함수의 반환값, 멤버 변수, 다른 스레드로 넘기는 것은 [`std::ranges::to`](#/read/cpp-stl/rng-algorithms)로 `vector`를 만들어 넘깁니다. 복사 한 번의 값으로 수명 걱정이 통째로 사라집니다.
</Note>

## 정리

- 레인지 알고리즘은 임시 컨테이너에서 얻은 반복자를 `std::ranges::dangling`으로 바꿔 쓰지 못하게 한다
- `string_view`, `span`처럼 원소를 들고 있지 않은 빌린 레인지는 임시 객체여도 괜찮다
- 우측값에 건 뷰는 그것을 소유한다. 이름 있는 컨테이너에 건 뷰는 가리킬 뿐이고, 그 수명은 컴파일러가 봐주지 않는다
