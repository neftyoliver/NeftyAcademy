[「std::string」](#/read/cpp-stl/str-string)에서 빈 문자열의 용량이 15라는 것을 봤습니다. `std::string`은 짧은 글자를 힙에 두지 않고 **자기 몸 안에** 담습니다. 작은 문자열 최적화(SSO, small string optimization)라고 부르고, 세 구현이 모두 하지만 방법과 크기가 다릅니다.

## 객체 안에 담기

```cpp
#include <cstddef>
#include <cstdint>
#include <cstdlib>
#include <new>
#include <print>
#include <string>

static int allocations = 0;
void* operator new(std::size_t n)
{
    ++allocations;
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

// 글자가 놓인 곳이 string 객체의 안쪽인가
bool is_inside(const std::string& s)
{
    const auto begin = reinterpret_cast<std::uintptr_t>(&s);
    const auto data = reinterpret_cast<std::uintptr_t>(s.data());
    return data >= begin && data < begin + sizeof s;
}

int main()
{
    std::println("sizeof {}", sizeof(std::string));
    for (const std::size_t length : {0u, 15u, 16u, 100u}) {
        allocations = 0;
        const std::string s(length, 'x');
        std::println("{:3}글자: 객체 안 {:5} 용량 {:3} 할당 {}", length,
                     is_inside(s), s.capacity(), allocations);
    }

    const std::string s = "abc";
    const auto offset = s.data() - reinterpret_cast<const char*>(&s);
    std::println("글자는 객체의 처음에서 {}바이트 뒤에 있다", offset);
}
```

```text
sizeof 32
  0글자: 객체 안 true  용량  15 할당 0
 15글자: 객체 안 true  용량  15 할당 0
 16글자: 객체 안 false 용량  16 할당 1
100글자: 객체 안 false 용량 100 할당 1
글자는 객체의 처음에서 16바이트 뒤에 있다
```

libstdc++의 `string`은 32바이트이고, 이렇게 생겼습니다.

```cpp nocheck
struct string_layout {              // libstdc++, 64비트
    // 글자의 시작. 짧을 때는 아래의 buffer 를 가리킨다
    char* pointer;
    std::size_t size;
    union {
        char buffer[16];            // 짧을 때: 글자 15개와 끝의 '\0'
        std::size_t capacity;       // 길 때: 힙 블록의 용량
    };
};
```

길 때에만 필요한 `capacity` 자리가 짧을 때는 비므로, 그 자리와 여분 8바이트를 글자 버퍼로 씁니다. "지금 짧은가"는 `pointer`가 자기 `buffer`를 가리키는지로 압니다. 그래서 `s.data()`와 `s.size()`는 길이에 상관없이 갈래 없이 읽힙니다.

libc++는 다르게 짰습니다. 포인터를 늘 두지 않고, 첫 바이트의 비트 하나로 "길다, 짧다"를 표시합니다.

| | libstdc++ 14 | libc++ 20 |
| --- | --- | --- |
| `sizeof(std::string)` | 32 | 24 |
| 객체 안에 담기는 글자 수 | 15 | 22 |
| 글자가 놓이는 자리 | 16바이트 뒤 | 1바이트 뒤 |
| `data()`를 읽을 때 | 포인터를 그대로 읽는다 | 길고 짧음을 먼저 가린다 |

libc++ 쪽이 더 작은 몸에 더 많이 담습니다. 그 대신 글자에 닿을 때마다 갈래가 하나 있습니다. 어느 쪽이 낫다기보다 무엇을 아낄지의 선택입니다. MSVC는 32바이트에 15글자로 알려져 있습니다(이 책에서 돌려 보지는 못했습니다).

## 15와 16 사이

한 글자 차이로 힙 할당이 생기고, 그 차이는 큽니다.

| 한 일 | 15글자 | 16글자 |
| --- | --- | --- |
| 만들고 버리기 1,000만 번 | 10 ms | 95 ms |
| 100만 개짜리 `vector<string>` 복사 | 10 ms | 35 ms |

x86-64, GCC 14 `-O2`에서 잰 값입니다. 열쇠나 이름처럼 **수가 많고 짧은** 문자열이 이 경계의 어느 쪽에 있느냐에 따라 프로그램의 성격이 달라집니다. `"temperature"`(11글자)는 안쪽이고 `"kitchen-temperature"`(19글자)는 바깥쪽입니다. 경계가 구현마다 달라서, libc++에서는 19글자도 안쪽입니다.

값이 작아 보여도 객체는 작지 않다는 점도 함께 기억합니다. 빈 `std::string` 100만 개를 담은 벡터는 글자가 하나도 없어도 32MB입니다. 대부분이 비어 있거나 겹치는 문자열을 수백만 개 다룬다면 [`string_view`](#/read/cpp-stl/str-view)와 한 덩어리의 글자 저장소, 또는 번호로 바꾼 표를 생각합니다.

## 옮기면 주소가 바뀐다

`std::move`는 보통 포인터만 넘겨줍니다. 짧은 문자열에는 넘겨줄 포인터가 없습니다. 글자가 몸 안에 있으니 **글자를 복사**해야 합니다.

```cpp
#include <print>
#include <string>
#include <string_view>
#include <utility>

int main()
{
    std::string short_one = "short";
    const char* short_before = short_one.data();
    const std::string_view view = short_one;        // 원본의 몸 안을 본다
    const std::string short_moved = std::move(short_one);
    std::println("짧은 것: 글자의 주소가 그대로인가 {}",
                 short_moved.data() == short_before);
    std::println("  옮긴 뒤 원본의 길이 {}, view 의 첫 글자 코드 {}",
                 short_one.size(), static_cast<int>(view[0]));

    std::string long_one(40, 'L');
    const char* long_before = long_one.data();
    const std::string long_moved = std::move(long_one);
    std::println("긴 것:   글자의 주소가 그대로인가 {}",
                 long_moved.data() == long_before);
}
```

```text
짧은 것: 글자의 주소가 그대로인가 false
  옮긴 뒤 원본의 길이 0, view 의 첫 글자 코드 0
긴 것:   글자의 주소가 그대로인가 true
```

긴 문자열은 힙 블록이 그대로 넘어가므로 글자의 주소가 같습니다. 짧은 문자열은 새 객체의 몸 안으로 글자가 옮겨 가고, 원본은 비워집니다. 원본을 보고 있던 `string_view`는 이제 빈 버퍼를 봅니다. 여기서 나오는 규칙입니다.

- **문자열을 옮기면 그 글자를 가리키던 포인터와 `string_view`는 못 쓴다고 봅니다.** 긴 문자열에서는 우연히 살아 있지만, 길이에 따라 맞기도 틀리기도 하는 코드가 됩니다
- `vector<string>`이 [재할당](#/read/cpp-stl/impl-vector)되면 원소가 새 블록으로 옮겨지므로, 짧은 문자열의 글자를 가리키던 `string_view`도 함께 죽습니다. [「반복자 무효화 규칙」](#/read/cpp-stl/seq-invalidation)에서 예외로 적어 둔 것이 이것입니다
- 짧은 문자열의 이동은 "공짜"가 아니라 16바이트 복사입니다. 그래도 힙 할당보다는 훨씬 쌉니다

libstdc++의 `string`이 **자기 안을 가리키는 포인터**를 갖는다는 점은 한 가지 결과를 더 낳습니다. 객체의 바이트를 `memcpy`로 다른 곳에 옮기면, 옮겨진 객체의 포인터는 여전히 옛 자리를 가리킵니다. 그래서 `std::string`은 [그대로 복사해도 되는 타입](#/read/cpp-stl/tr-type-traits)이 아니고, `std::string`을 품은 구조체를 `memcpy`나 `realloc`으로 옮기는 C식 코드는 짧은 문자열에서 깨집니다.

## 줄여도 남는 힙

```cpp
#include <print>
#include <string>

int main()
{
    std::string s(100, 'x');
    s.resize(3);                    // 세 글자만 남긴다
    std::println("줄인 뒤           길이 {} 용량 {}", s.size(), s.capacity());
    s.shrink_to_fit();
    std::println("shrink_to_fit 뒤 길이 {} 용량 {}", s.size(), s.capacity());

    // 자라는 순서
    std::string grow;
    std::size_t capacity = grow.capacity();
    std::print("[{}]", capacity);
    for (int i = 0; i < 200; ++i) {
        grow.push_back('x');
        if (grow.capacity() != capacity) {
            capacity = grow.capacity();
            std::print("[{}]", capacity);
        }
    }
    std::println("");
}
```

```text
줄인 뒤           길이 3 용량 100
shrink_to_fit 뒤 길이 3 용량 15
[15][30][60][120][240]
```

한 번 힙으로 나간 문자열은 줄어들어도 스스로 돌아오지 않습니다. `shrink_to_fit()`을 불러야 몸 안으로 돌아옵니다. 한 줄씩 읽어 들이는 버퍼처럼 **다시 길어질** 문자열에는 이 성질이 좋습니다. 처음 몇 번만 할당하고 그 뒤로는 그 용량을 계속 씁니다. 긴 문자열을 한 번 담았다가 짧게 줄여 오래 들고 있는 객체가 수천 개라면 줄인 뒤에 `shrink_to_fit()`을 붙입니다.

<Note>
"작으면 객체 안에"라는 요령은 `string`만의 것이 아닙니다. [`std::function`](#/read/cpp-stl/voc-function)은 16바이트까지의 캡처를, [`std::any`](#/read/cpp-stl/voc-any)는 작은 값을 몸 안에 담습니다. `std::vector`에는 없습니다. 벡터는 옮겨도 원소의 주소가 그대로라고 보장하기 때문입니다. 작은 개수는 몸 안에 담는 벡터가 필요하면 [고정 용량 벡터](#/read/cpp-stl/mem-uninit)나 Boost의 `small_vector` 같은 것을 씁니다.
</Note>

## 정리

- `std::string`은 짧은 글자를 객체 안에 담는다. libstdc++는 32바이트에 15글자, libc++는 24바이트에 22글자다
- 경계를 넘으면 힙 할당이 생기고, 만들고 버리는 값이 열 배쯤 된다. 수가 많은 짧은 문자열은 어느 쪽에 있는지 알고 쓴다
- 짧은 문자열은 옮기면 글자의 주소가 바뀐다. 문자열을 옮긴 뒤에는 그 글자를 가리키던 포인터와 `string_view`를 쓰지 않는다
