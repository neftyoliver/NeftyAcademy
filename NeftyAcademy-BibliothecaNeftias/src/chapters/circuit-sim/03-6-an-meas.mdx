파형을 눈으로 읽는 대신 숫자로 뽑아 두면, 값을 바꿔 다시 돌렸을 때 무엇이 달라졌는지를 바로 견줄 수 있습니다. 앞 쪽들에서 조금씩 써 온 `.meas`를 여기에 한데 모읍니다.

## 한 파형에서 뽑은 숫자들

```spice
1kHz 네모파가 RC를 지난 파형의 숫자
V1 in 0 PULSE(0 3.3 0 1u 1u 499u 1m)
R1 in out 1k
C1 out 0 100n
.tran 1u 5m
.meas tran vmax MAX v(out)
.meas tran vavg AVG v(out)
+ FROM=1m TO=5m
.meas tran v_at FIND v(out) AT=1.1m
.meas tran t_cross
+ WHEN v(out)=1.65 RISE=2
.meas tran trise
+ TRIG v(out) VAL=0.33 RISE=2
+ TARG v(out) VAL=2.97 RISE=2
.meas tran delay
+ TRIG v(in) VAL=1.65 RISE=2
+ TARG v(out) VAL=1.65 RISE=2
.meas tran period
+ TRIG v(out) VAL=1.65 RISE=2
+ TARG v(out) VAL=1.65 RISE=3
.meas tran freq PARAM='1/period'
.end
```

```text
$ ngspice -b measure.cir
vmax    = 3.277805e+00 at= 3.500000e-03
vavg    = 1.650000e+00 from= 1.000000e-03 to= 5.000000e-03
v_at    = 2.088132e+00
t_cross = 1.06914e-03
trise   = 2.197205e-04 targ= 1.230081e-03 trig= 1.010361e-03

period  = 1.000000e-03 targ= 2.069138e-03 trig= 1.069139e-03
freq    = 1.00000e+03
```

| 꼴 | 뽑는 것 | 보기 |
| --- | --- | --- |
| `MAX`, `MIN`, `PP`, `AVG`, `RMS`, `INTEG` | 구간에서 셈한 값 하나 | `AVG v(out) FROM=1m TO=5m` |
| `FIND … AT=`, `WHEN …` | 어느 때의 값, 어느 값이 되는 때 | `WHEN v(out)=1.65 RISE=2` |
| `TRIG … TARG …` | 두 사건 사이의 시간 | 10%에서 90%까지 |
| `PARAM='식'` | 앞선 결과로 셈한 값 | `PARAM='1/period'` |

- **줄의 머리**: `.meas tran 이름` 다음에 꼴을 적습니다. `tran` 자리에 `dc`나 `ac`를 적으면 그 해석의 결과에서 뽑습니다
- **`RISE=2`**: 오르면서 그 값을 지나는 둘째 번이라는 뜻입니다. 내리면서 지나는 것은 `FALL=`, 방향을 가리지 않으면 `CROSS=`이고, 마지막 것은 `LAST`라고 적습니다. 첫 주기는 0V에서 출발해 나머지와 달라서 둘째 것부터 쟀습니다
- **`trise`**: 10%에서 90%까지 0.2197ms입니다. 시정수 0.1ms(1kΩ × 100nF)의 2.2배입니다. `targ=`와 `trig=`는 두 사건이 일어난 시각이고, 그림의 두 커서가 그 자리입니다
- **`delay`**: 입력이 절반 높이를 지난 뒤 출력이 절반 높이를 지날 때까지 68.6µs입니다. `TRIG`와 `TARG`에 서로 다른 마디를 적었습니다
- **`PARAM`**: 앞에서 얻은 `period`로 주파수를 셈했습니다. 식은 작은따옴표 안에 적습니다
- **오실로스코프의 자동 측정과 같은 일이다**: 장비의 화면에서 커서로 하던 일을 글로 적어 둔 것입니다([「시뮬레이터의 파형을 오실로스코프처럼 읽기」](#/read/scope/pr-sim))

## 실패를 알아채는 법

```spice
측정이 실패할 때
V1 in 0 PULSE(0 3.3 0 1u 1u 499u 1m)
R1 in out 1k
C1 out 0 100n
.tran 1u 5m
.meas tran never WHEN v(out)=5
.meas tran toolate FIND v(out) AT=6m
.meas tran ok MAX v(out)
.end
```

```text
$ ngspice -b fail.cir
Error: measure  never  when(WHEN) : out of interval
Error: measure  toolate  find(AT) : out of interval
ok = 3.277805e+00 at= 3.500000e-03
```

- **실패한 측정은 결과 줄이 없다**: 오류가 한 줄 나오고 나머지 측정은 그대로 이어집니다. 결과를 옮겨 적을 때 줄의 수가 맞는지 봅니다
- **닿지 않는 값과 범위 밖의 때**: `out`은 5V에 닿지 않고, 해석은 5ms에서 끝났습니다
- **끝점과 시작점**: `.dc V1 0 5 0.01`의 `AT=5`, `uic`로 돌린 과도 해석의 `AT=0`도 같은 오류를 냅니다. 조금 안쪽의 값을 적습니다
- **`VAL=`에는 앞선 결과를 못 쓴다**: `VAL='0.1*vmax'`처럼 측정의 이름을 적으면 `Undefined parameter`라는 오류로 통째로 멈춥니다. `.param`으로 붙인 이름은 쓸 수 있습니다. `.param vcc=3.3`을 두고 `VAL='0.1*vcc'`라고 적습니다
- **`DERIV`**: 설명서에는 기울기를 뽑는 꼴로 나오지만 ngspice 42는 `currently not supported`라고 답합니다
- **주파수 훑기에서는**: `vdb`, `vp`를 쓰고 `.save` 줄을 더합니다([「주파수 훑기 (.ac)와 보드 선도」](#/read/circuit-sim/an-ac))

## 프로그램마다 다른 곳

- **뼈대는 같다**: LTspice의 도움말도 `FIND … AT=`, `WHEN`, `TRIG … TARG`, `AVG`와 `MAX` 같은 꼴을 적어 두었습니다
- **결과가 나오는 곳이 다르다**: LTspice에서는 결과가 로그 파일에 적히고, View 메뉴의 SPICE Error Log에서 봅니다
- **식을 적는 법이 다르다**: LTspice의 도움말에는 `PARAM 3*res1/res2`처럼 따옴표 없이 적은 보기와, `V(out)*I(Vout)`처럼 곱을 바로 적은 보기가 있습니다. 구간도 `FROM=`과 `TO=`가 아니라 `TRIG`와 `TARG`로 정하는 꼴로 나옵니다
- **옮길 때는 한 줄씩 확인한다**: `.meas`는 두 프로그램에 모두 있지만 그대로 통하는 줄과 고쳐야 하는 줄이 섞여 있습니다

<Note>
넷리스트 둘과 그림은 ngspice 42로 돌린 결과이고, 측정의 이름을 `VAL=`에 적은 경우, `.param`의 이름을 적은 경우, `DERIV`도 따로 돌려 확인했습니다. 출력의 빈칸은 화면에 맞게 줄였습니다. LTspice의 이야기는 도움말에서 옮긴 것이고 제가 돌려 보지는 못했습니다. ngspice에서 통하는 `.meas` 줄이 LTspice에서 그대로 통하는지는 줄마다 다를 수 있습니다.
</Note>

## 정리

- `.meas`는 구간의 값, 어느 때의 값, 두 사건 사이의 시간, 앞선 결과로 셈한 값을 뽑는다
- 실패한 측정은 `Error: measure …` 한 줄만 남기고 결과 줄이 없다. 줄의 수를 센다
- `.meas`는 ngspice와 LTspice에 모두 있지만 식을 적는 법과 결과가 나오는 곳이 다르다
