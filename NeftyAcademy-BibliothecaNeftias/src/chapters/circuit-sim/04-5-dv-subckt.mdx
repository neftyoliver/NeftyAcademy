앞의 두 쪽에서 모델을 파일에 두고 불러 썼습니다. 이 쪽은 그런 묶음을 직접 만들어 보고, 제조사가 준 파일을 읽어 넷리스트로 가져오는 법을 봅니다.

## 묶어서 이름 붙이기

```spice
하위 회로를 만들어 두 번 쓰기
V1 in 0 DC 0 AC 1
X1 in mid RCLP r=1k c=1u
X2 mid out RCLP r=100k c=10n
.subckt RCLP a b r=1k c=100n
R1 a b {r}
C1 b 0 {c}
.ends
.ac dec 20 1 100k
.save v(mid) v(out)
.meas ac f_mid WHEN vdb(mid)=-3
.meas ac db_10k FIND vdb(out) AT=10k
.end
```

```text
$ ngspice -b stages.cir
Warning: can't parse 'vd': ignored
f_mid  = 1.57189e+02
db_10k = -7.192944e+01
```

- **`.subckt 이름 핀들`에서 `.ends`까지가 부품 하나다**: 이 묶음을 하위 회로라고 합니다. 핀은 밖과 이어지는 마디입니다. `RCLP`는 저항 하나와 커패시터 하나로 된 필터이고 핀은 `a`와 `b`입니다
- **`X`로 시작하는 줄이 그 부품을 놓는다**: `X1 in mid RCLP`는 핀 `a`를 `in`에, 핀 `b`를 `mid`에 잇습니다. 마디를 핀의 차례대로 적고 맨 뒤에 이름을 적습니다
- **안쪽의 이름은 안에서만 통한다**: 두 번 놓아도 `R1`끼리 겹치지 않습니다. ngspice는 속에서 `r.x1.r1`, `r.x2.r1`처럼 이름을 붙입니다. `0`만은 어디에 적어도 같은 접지입니다
- **값을 넘겨줄 수 있다**: `.subckt` 줄의 `r=1k c=100n`은 기본값이고, `X` 줄에 적은 값이 그것을 덮습니다
- **두 단을 이으니 두 배로 가파르다**: 10kHz에서 −72dB입니다. 한 단만 두면 −36dB입니다. 첫 단의 꺾이는 주파수가 혼자일 때의 159Hz에서 157Hz로 조금 내려온 것은 둘째 단이 짐이 되었기 때문입니다

## 제조사의 파일 읽기

```spice file=1N4148.lib
* 1N4148, Nexperia
* 마디 1이 애노드, 2가 캐소드
.SUBCKT 1N4148 1 2
R1 1 2 5.827E+9
D1 1 2 1N4148
.MODEL 1N4148 D
+ IS = 4.352E-9
+ N = 1.906
+ BV = 110
+ IBV = 0.0001
+ RS = 0.6458
+ CJO = 7.048E-13
+ VJ = 0.869
+ M = 0.03
+ FC = 0.5
+ TT = 3.48E-9
.ENDS
```

- **Nexperia가 내놓은 1N4148의 모델이다**: 위는 그 파일에서 머리의 주석을 빼고 옮긴 것입니다. 앞의 쪽들에서 쓴 숫자가 여기서 왔습니다
- **머리의 주석부터 읽는다**: 핀의 차례, 어느 프로그램에 맞춰 썼는지, 부품의 한계가 거기에 있습니다. 이 파일에는 PSPICE용이라는 것과, 10mA에서 1V 이하, 거꾸로 20V에서 25nA 이하라는 숫자가 적혀 있습니다
- **핀의 차례가 포장과 다를 수 있다**: 이 파일의 주석은 포장의 핀 번호와 모델의 핀 차례가 맞지 않는다고 따로 알려 둡니다. 포장에서는 1번이 캐소드인데 모델에서는 마디 1이 애노드입니다. 데이터시트의 핀 번호만 보고 이으면 거꾸로 이어집니다
- **다이오드 하나가 아니다**: 5.8GΩ이 나란히 들어 있습니다. 주석에 따르면 실제로 든 부품이 아니라, 거꾸로 걸렸을 때의 모습을 맞추려고 넣은 것입니다. 그래서 이 모델은 `D`가 아니라 `X`로 불러야 합니다

## 가져와 쓰기

```spice with=1N4148.lib
제조사의 하위 회로 모델 쓰기
I1 0 a 10m
X1 a 0 1N4148
V2 k 0 20
X2 0 k 1N4148
.include 1N4148.lib
.op
.end
```

```text
$ ngspice -b vendor.cir
k           2.000000e+01
a           7.285563e-01
v2#branch   -7.80430e-09
```

| 실수 | ngspice 42가 한 일 |
| --- | --- |
| `D1 a 0 1N4148`로 부름 | `could not find a valid modelname` 오류 |
| `.include` 줄을 빠뜨림 | `unknown subckt: x1 a 0 1n4148` 오류 |
| `X1 a 1N4148`로 마디 하나를 빠뜨림 | 오류 없이 `a`가 33억 V |
| `X1 0 a 1N4148`로 거꾸로 이음 | 오류 없이 `a`가 110V |

- **`.include 파일이름`**: 그 파일의 내용이 그 자리에 적힌 것과 같아집니다. 여기서는 넷리스트와 같은 폴더에 두고 이름만 적었습니다
- **머리의 숫자를 되짚어 본다**: 10mA를 흘리면 0.729V, 거꾸로 20V를 걸면 7.8nA입니다. 파일의 머리에 적힌 한계 안에 듭니다. 모델을 받으면 이렇게 숫자 한두 개를 확인해서, 제대로 가져왔는지와 핀을 맞게 이었는지를 봅니다
- **마디의 수와 차례는 ngspice가 봐주지 않는다**: 표의 아래 두 줄은 오류가 나지 않습니다. 110V는 거꾸로 걸린 다이오드가 `BV`에서 무너질 때까지 전류원이 전압을 밀어 올린 값입니다. 터무니없는 숫자가 나오면 핀의 차례부터 봅니다

## 방언 맞추기

```spice file=comp.lib
* PSpice의 꼴로 적힌 비교기
.subckt COMP in out
E1 out 0 VALUE={IF(V(in)>1, 3.3, 0)}
.ends
```

```spice with=comp.lib fails
PSpice 꼴의 하위 회로를 가져오기
V1 in 0 2
X1 in out COMP
R1 out 0 10k
.include comp.lib
.op
.end
```

```text
$ ngspice -b dialect.cir
Error: no such function 'if'
```

고치는 것은 설정 파일 한 줄입니다. 넷리스트와 같은 폴더에 `.spiceinit`라는 이름으로 둡니다.

```text file=.spiceinit
set ngbehavior=ps
```

```spice with=comp.lib,.spiceinit
같은 넷리스트를 설정 파일과 함께
V1 in 0 2
X1 in out COMP
R1 out 0 10k
.include comp.lib
.op
.end
```

```text
$ ngspice -b dialect.cir
Note: Compatibility modes selected: ps
out         3.300000e+00
in          2.000000e+00
```

- **제조사의 파일은 대개 PSpice나 LTspice에 맞춰 쓰여 있다**: `IF(…)`처럼 그 프로그램의 꼴로 적힌 식을 ngspice는 기본 설정에서 읽지 못합니다
- **`set ngbehavior=ps`**: 가져온 파일을 PSpice의 꼴로 읽으라는 설정입니다. LTspice의 꼴은 `lt`이고, 둘을 함께 쓰려면 `ltps`라고 적습니다
- **끝에 `a`를 붙이면 넷리스트 전체에 적용된다**: `ps`는 `.include`로 가져온 파일에만 적용됩니다. 같은 `IF(…)`를 넷리스트에 바로 적으면 `ps`로는 여전히 오류이고 `psa`라야 읽힙니다
- **앞에서 본 `4k7`도 이 설정이 바꾼다**: `lt`를 켜면 넷리스트에 바로 적은 `4k7`까지 4.7k로 읽힙니다([「접미사와 단위의 함정」](#/read/circuit-sim/nl-units)). 숫자를 읽는 법까지 달라지므로 필요할 때만 켭니다
- **KiCad는 이 설정을 화면에서 고른다**: 같은 ngspice를 쓰기 때문에 같은 설정이 있습니다([「회로도와 시뮬레이션 모델 붙이기」](#/read/circuit-sim/kc-schematic))

<Note>
넷리스트 넷과 표의 네 줄은 ngspice 42로 돌려 확인했고, 한 단만 둔 경우와 `psa`도 따로 돌려 보았습니다. 1N4148의 파일은 Nexperia가 내놓은 것에서 주석을 줄이고 옮겼습니다. 비교기의 파일은 방언을 보이려고 제가 PSpice의 꼴로 쓴 것입니다. 33억 V와 110V는 이 판에서 나온 숫자이고, 다른 판은 오류를 낼 수도 있습니다. 그 경우는 확인하지 못했습니다.
</Note>

## 정리

- `.subckt 이름 핀들 … .ends`로 묶고 `X1 마디들 이름`으로 놓는다. 안쪽의 이름은 안에서만 통하고 값을 넘겨줄 수 있다
- 제조사의 모델은 머리의 주석에서 핀의 차례와 한계를 읽고, `.include`로 가져온 뒤 숫자 한두 개를 되짚어 확인한다
- PSpice나 LTspice의 꼴로 적힌 파일은 `.spiceinit`의 `set ngbehavior=`로 읽게 한다
