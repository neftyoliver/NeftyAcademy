KiCad에서 시뮬레이션을 하는 까닭은 돌려 본 바로 그 회로도가 기판이 되기 때문입니다. 다만 시뮬레이션이 바라는 것과 기판이 바라는 것은 다릅니다. 시뮬레이션에는 전압원이 있어야 하고, 기판에는 전압원 대신 커넥터가 있습니다. 이 쪽은 4장의 트랜지스터 스위치를 기판까지 가져가면서, 회로도 하나가 두 일을 다 하게 만드는 법을 봅니다.

## 두 쪽이 바라는 것

| | 시뮬레이션 | 기판 |
| --- | --- | --- |
| 부품마다 있어야 하는 것 | 모델 | 풋프린트 |
| 전원과 신호가 들어오는 곳 | 전압원 기호 | 커넥터 |
| 없어야 하는 것 | 모델이 없는 부품 | 실물이 없는 기호 |

- **기호 하나에 둘을 붙인다**: 속성 창의 Footprint 필드에는 기판에 놓일 모양을, Simulation Model…에는 셈할 모델을 붙입니다
- **부품 기호에서 시작한다**: 제가 쓴 판에서 `Transistor_BJT` 라이브러리의 `2N3904`에는 TO-92 풋프린트가 미리 적혀 있고 모델이 없었습니다. `Simulation_SPICE`의 `NPN`에는 모델이 있고 풋프린트가 없었습니다. 기판까지 갈 회로도라면 앞의 것을 놓고 모델을 붙입니다. 핀 번호가 실제 포장의 것이기 때문입니다
- **풋프린트를 붙이는 곳**: 속성 창의 Footprint 필드에 바로 적거나, Tools 메뉴의 Assign Footprints…로 한꺼번에 붙입니다

## 한 회로도에서 넷리스트 둘

| 부품 | 속성 창에서 켠 것 | 들어가는 넷리스트 |
| --- | --- | --- |
| 전압원 V1, V2 | Exclude from board, Exclude from bill of materials | 시뮬레이션에만 |
| 커넥터 J1, J2 | Exclude from simulation | 기판에만 |
| R1, R2, D1, Q1 | 없음 | 둘 다 |

V1은 J1과 같은 그물에, V2는 J2와 같은 그물에 나란히 붙였습니다. 이 회로도에서 뽑은 시뮬레이션용 넷리스트와 그 결과입니다.

```spice with=2N3904.lib,models.lib
.title KiCad schematic
.include "2N3904.lib"
.include "models.lib"
.op
V1 /vcc GND DC 5
V2 /in GND DC 3.3
D1 /a /c RED
Q1 /c /b GND Q2N3904
R1 /in /b 4.7k
R2 /vcc /a 150
.end
```

```text
$ ngspice -b board.cir
/b          7.555048e-01
/c          1.351982e-01
/a          2.075976e+00
/in         3.300000e+00
/vcc        5.000000e+00
v1#branch   -1.94935e-02
```

- **시뮬레이션 쪽**: 커넥터 J1과 J2는 넷리스트에 없습니다. `c`는 0.135V, LED의 전류는 19.5mA로 4장의 답과 같습니다([「트랜지스터 스위치」](#/read/circuit-sim/dv-bjt))
- **기판 쪽**: 같은 회로도에서 기판용 넷리스트를 뽑으니 부품은 D1, J1, J2, Q1, R1, R2의 여섯이었고 V1과 V2는 없었습니다. 그물은 `/a`, `/b`, `/c`, `/in`, `/vcc`, `GND`의 여섯이었습니다
- **커넥터를 빼지 않으면 돌지 않는다**: Exclude from simulation을 켜지 않고 뽑으니 `J2 __J2`라는 줄이 나왔고, ngspice는 `Unable to find definition of model`이라며 멈췄습니다. SPICE에서 `J`로 시작하는 줄은 JFET이라는 트랜지스터의 줄입니다
- **전압원을 빼지 않으면 기판 쪽에 섞여 나온다**: 전압원 기호에는 풋프린트가 없습니다. Exclude from board를 켜지 않고 뽑으니 V1이 풋프린트 없는 부품으로 기판용 넷리스트에 들어 있었습니다
- **뺀 기호는 화면에서 구별된다**: 설명서에 따르면 시뮬레이션에서 뺀 기호는 회색 테두리로 그려집니다

## 넘기기 전에

- **전기 규칙 검사**: Inspect 메뉴의 Electrical Rules Checker를 열고 Run ERC를 누릅니다. 이어지지 않은 핀, 이름표만 있고 이어지지 않은 선 같은 것을 찾아 줍니다
- **전원 핀의 오류**: 전원이 커넥터로 들어오는 기판에서는 전원 입력 핀에 전원이 없다는 오류가 흔히 납니다. `power` 라이브러리의 `PWR_FLAG`를 그 그물에 붙여서 전원이 들어오는 곳임을 알려 줍니다
- **기판으로 넘긴다**: Tools 메뉴의 Update PCB from Schematic…이고 키는 `F8`입니다. Exclude from board를 켠 기호는 넘어가지 않습니다
- **부품을 바꿨으면 다시 돌린다**: 구하기 쉬운 부품으로 바꾸면서 풋프린트만 고치고 모델을 그대로 두면, 돌려 본 회로와 만드는 회로가 달라집니다

## 시뮬레이션이 말해 주지 않는 것

- **기판의 선**: 회로도의 선은 저항이 0입니다. 기판의 선에는 저항과 인덕턴스가 있고 선끼리 커패시턴스로 이어져 있지만 넷리스트에는 없습니다
- **전압원의 뒤**: V2는 얼마를 끌어가도 3.3V를 지키는 이상적인 전원입니다. 실제 핀은 낼 수 있는 전류에 한계가 있습니다([「이상적인 부품이 숨기는 것」](#/read/circuit-sim/ts-ideal))
- **부품마다의 차이**: 모델은 대푯값 하나로 셈합니다. 실제 부품은 하나하나 다릅니다([「부품 오차와 몬테카를로」](#/read/circuit-sim/ts-tolerance))
- **만든 뒤의 확인**: 기판을 만들었으면 같은 자리를 재서 시뮬레이션의 숫자와 견줍니다([「측정과 견주기」](#/read/circuit-sim/ts-compare))

<Note>
메뉴와 속성의 이름은 KiCad 10의 설명서에서 옮긴 것이고, 제가 화면에서 눌러 본 것은 아닙니다. 두 넷리스트는 KiCad 7.0.11의 `kicad-cli`로 뽑았습니다. 회로도 파일은 화면에서 그리지 않고 스크립트로 만들었으며, 그 판에서는 시뮬레이션에서 빼는 표시가 `Sim.Enable`이라는 필드에 0으로 적힙니다. 시뮬레이션용 넷리스트는 ngspice 42로 돌렸고, `.include`의 경로는 파일 이름만 남겼습니다. 기판 쪽은 넷리스트에 적힌 부품과 그물만 확인했고, 기판을 실제로 그리거나 ERC를 돌려 보지는 못했습니다. 저항, LED, 커넥터의 풋프린트는 제가 골라 적은 이름입니다.
</Note>

## 정리

- 기판까지 갈 회로도에서는 부품 기호에 풋프린트와 모델을 둘 다 붙인다
- 전압원은 기판과 부품 목록에서 빼고, 커넥터처럼 모델이 없는 부품은 시뮬레이션에서 뺀다. 그러면 회로도 하나에서 두 넷리스트가 나온다
- 넘기기 전에 ERC를 돌리고, 부품을 바꿨으면 모델도 바꿔 다시 돌린다. 기판의 선과 부품의 오차는 넷리스트에 없다
