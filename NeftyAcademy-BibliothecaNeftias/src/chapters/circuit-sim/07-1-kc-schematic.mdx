KiCad는 기판을 만드는 도구이고, 그 안의 시뮬레이터는 ngspice입니다. 회로도를 그리는 일은 LTspice와 비슷합니다. 다른 점은 기호가 기판에 올라갈 부품을 뜻한다는 것입니다. 그래서 어떤 모델로 셈할지를 부품마다 따로 붙여 줍니다. 이 쪽에서는 3장의 LED 회로를 KiCad의 회로도로 옮기고, 붙인 모델이 넷리스트의 어떤 줄이 되는지를 봅니다.

## 그리는 차례

<Figure caption="KiCad에 그릴 회로. 3장에서 넷리스트로 적은 LED 회로와 같다">
  <Circuit spec="V 0,2 0,0 V1 3.3V; W 0,0 1,0; O 1,0 ^vcc; R 1,0 3,0 R1 330Ω; O 3,0 ^a; E 3,0 3,2 D1; W 3,2 0,2; G 0,2" label="3.3볼트 전원 V1에서 이름표 vcc가 붙은 선이 나와 330옴 저항 R1을 지나고, 이름표 a가 붙은 선에서 LED D1이 접지로 내려가는 회로도" />
</Figure>

- **기호를 놓는다**: `A`를 누르고 기호를 고릅니다. 저항은 `Device` 라이브러리의 `R`, LED는 같은 라이브러리의 `LED`입니다
- **전원과 접지**: 전압원은 `Simulation_SPICE` 라이브러리의 `VDC`, `VPULSE`, `VSIN` 같은 기호입니다. 접지는 `P`로 놓는 전원 기호 `GND`이거나 `Simulation_SPICE`의 `0`입니다
- **선과 이름표**: `W`로 선을 긋고 `L`로 이름표를 붙입니다
- **값**: 기호를 고르고 `E`를 누르면 속성 창이 뜹니다. 저항의 Value에 `330`을 적습니다
- **지시문**: `T`로 글을 놓고 `.op`라고 적습니다. 점으로 시작하는 글이 넷리스트의 줄이 됩니다
- **돌리는 곳은 따로 있다**: Inspect 메뉴의 Simulator가 시뮬레이터 창을 엽니다([「시뮬레이터 창」](#/read/circuit-sim/kc-run))

## 모델을 붙이는 세 길

| 길 | 쓰는 곳 | 기호에 남는 필드 |
| --- | --- | --- |
| 값만 적는다 | 저항, 커패시터, 인덕터 | `Value` |
| 내장 모델 | 전원, 숫자 몇 개로 적는 반도체 | `Sim.Device`, `Sim.Type`, `Sim.Params` |
| 파일의 모델 | 제조사의 `.model`과 `.subckt` | `Sim.Library`, `Sim.Name`, `Sim.Pins` |

- **붙이는 창**: 속성 창의 Simulation Model… 단추가 Simulation Model Editor를 엽니다. 고른 것은 기호의 필드에 글로 남습니다
- **값만 적는 부품**: 핀이 둘이고 이름이 R, L, C로 시작하는 기호는 Value만 적으면 됩니다. 이상적인 소자로 셈합니다
- **내장 모델**: Built-in SPICE model을 고르고 종류를 고른 다음 숫자를 채웁니다. `VDC` 같은 전원 기호에는 이 필드가 미리 채워져 있어서 값만 적으면 됩니다
- **파일의 모델**: SPICE model from file을 고르고, 파일과 그 안의 모델 이름을 고릅니다. 경로는 프로젝트 폴더를 기준으로 적을 수 있습니다
- **모델이 없는 기호는 돌지 않는다**: 제가 쓴 판의 `LED` 기호에는 모델이 붙어 있지 않았습니다. 그대로 넷리스트를 뽑으니 모델을 읽지 못했다는 오류와 함께 `D1 __D1`이라는, 마디가 없는 줄이 나왔습니다

LED에 3장의 모델을 파일로 붙여 봅니다. 파일은 프로젝트 폴더에 둡니다.

```spice file=models.lib
* 3장의 LED 모델
.model RED D(IS=1e-18 N=1.9 RS=5)
```

D1의 필드에 `Sim.Library`는 `models.lib`, `Sim.Name`은 `RED`, `Sim.Pins`는 `1=K 2=A`가 남습니다. 이 회로도에서 KiCad가 뽑은 넷리스트와, 그것을 ngspice로 돌린 결과입니다.

```spice with=models.lib
.title KiCad schematic
.include "models.lib"
.op
R1 /vcc /a 330
D1 /a GND RED
V1 /vcc GND DC 3.3
.end
```

```text
$ ngspice -b led.cir
/a          1.794740e+00
/vcc        3.300000e+00
v1#branch   -4.56140e-03
```

- **3장의 답과 같다**: `a`가 1.794740V, 전류가 4.56mA입니다([「동작점 (.op)」](#/read/circuit-sim/an-op))
- **이름표에는 빗금이 붙는다**: 맨 위 시트에 붙인 이름표 `vcc`는 넷리스트에서 `/vcc`가 됩니다. 전원 기호 `GND`는 `GND` 그대로 나오고, ngspice는 이것을 마디 `0`으로 읽습니다
- **`.include`에는 온전한 경로가 적힌다**: KiCad는 `models.lib`의 자리를 폴더까지 다 적어 넣었습니다. 위에서는 파일 이름만 남겼습니다
- **줄의 차례는 그린 차례가 아니다**: 답과는 상관이 없습니다

## 핀의 짝

기호의 핀 번호와 모델의 마디 차례는 서로 다른 약속입니다. `LED` 기호는 1번 핀이 캐소드(K), 2번 핀이 애노드(A)이고, 넷리스트의 `D` 줄은 애노드를 먼저 적습니다. `Sim.Pins`의 `1=K 2=A`가 그 짝을 적은 것이고, Simulation Model Editor의 Pin Assignments 탭에서 고릅니다.

| `Sim.Pins` | 넷리스트의 줄 | 결과 |
| --- | --- | --- |
| `1=2 2=1` | `XD1 /a GND 1N4148` | `a`가 0.728V |
| `1=1 2=2` | `XD1 GND /a 1N4148` | `a`가 5.000V |
| `1=E 2=B 3=C` | `Q1 /c /b GND Q2N3904` | `c`가 0.135V |

위의 두 줄은 4장의 `1N4148.lib`에 든 하위 회로를 다이오드 기호에 붙인 것이고, 셋째 줄은 `2N3904.lib`의 모델을 트랜지스터 기호에 붙인 것입니다.

- **짝을 틀려도 오류가 없다**: 둘째 줄은 다이오드가 거꾸로 이어진 것입니다. 전류가 흐르지 않아 `a`가 전원 전압인 5V가 되었고, 경고는 없었습니다([「.subckt와 제조사 모델 가져오기」](#/read/circuit-sim/dv-subckt))
- **하위 회로의 핀은 번호뿐이다**: Nexperia의 `1N4148`은 마디 1이 애노드입니다. 기호의 1번 핀은 캐소드이므로 `1=2 2=1`로 엇갈리게 짝짓습니다
- **부품 기호의 핀 번호는 포장의 핀 번호다**: `Transistor_BJT` 라이브러리의 `2N3904`는 1번이 이미터, 2번이 베이스, 3번이 컬렉터입니다. 넷리스트의 `Q` 줄은 컬렉터, 베이스, 이미터의 차례입니다. 짝을 맞춰 붙이니 4장과 같은 0.135V가 나왔습니다([「트랜지스터 스위치」](#/read/circuit-sim/dv-bjt))
- **이름 앞에 글자가 붙기도 한다**: 하위 회로를 붙인 `D1`은 넷리스트에서 `XD1`이 됩니다. SPICE가 이름의 첫 글자로 소자의 종류를 가르기 때문입니다

## 값을 적는 법이 넷리스트와 다르다

| Value에 적은 것 | 넷리스트에 나온 것 |
| --- | --- |
| `1M` | `1Meg` |
| `1m` | `1m` |
| `4k7` | `4.7k` |
| `10R` | `10` |
| `10uF` | `10u` |
| `1F` | `1F` |

- **KiCad의 필드는 대문자와 소문자를 가른다**: `M`은 메가이고 `m`은 밀리입니다. 넷리스트를 만들 때 KiCad가 `1M`을 `1Meg`으로 바꿔 적습니다. 넷리스트에서는 `1M`이 밀리였습니다([「접미사와 단위의 함정」](#/read/circuit-sim/nl-units))
- **글로 적은 지시문은 바꿔 주지 않는다**: 지시문은 그대로 ngspice에 넘어갑니다. 그 안에서는 넷리스트의 표기를 따라야 하므로 메가는 `Meg`입니다
- **`4k7`과 `10R`**: 숫자 사이에 접미사를 끼우는 표기를 KiCad가 풀어서 적어 줍니다
- **`1F`는 그대로 나갔다**: 커패시터에 적은 `1F`가 바뀌지 않고 넷리스트에 들어갔고, ngspice는 이것을 1펨토패럿으로 읽습니다. 단위의 글자는 적지 않는 편이 안전합니다

## 지시문, 호환 방식, LTspice의 회로도

- **글로 넣을 수 있는 것**: 점으로 시작하는 줄과, 인덕터의 결합을 적는 `K` 줄입니다. 부품을 글로 더할 수는 없습니다
- **호환 방식을 화면에서 고른다**: 해석을 정하는 창에 Compatibility mode가 있습니다. PSpice, LTspice, 둘 다, HSpice의 꼴 가운데서 고르고, User configuration은 `.spiceinit` 파일을 따릅니다. 4장에서 `set ngbehavior=`로 적던 설정입니다
- **LTspice의 회로도를 읽어 들인다**: File 메뉴의 Import에 있는 Non-KiCad Schematic…이 `.asc` 파일을 KiCad의 회로도로 바꿉니다. 접지는 `GND` 기호가 되고, 10.0.6판부터는 `.tran` 줄을 ngspice가 받는 꼴로 바꿔 줍니다. 지시문과 LTspice만의 소자는 다 옮겨지지 않을 수 있다고 설명서에 적혀 있으므로, 읽어 들인 뒤에 넷리스트를 확인합니다

<Note>
이 쪽의 창과 메뉴의 이름은 KiCad 10의 설명서에서 옮긴 것이고, 제가 화면에서 눌러 본 것은 아닙니다. 넷리스트는 KiCad 7.0.11의 명령줄 도구 `kicad-cli`로 뽑아 ngspice 42로 돌렸습니다. 회로도 파일은 화면에서 그리지 않고 파일의 형식대로 스크립트로 만들었습니다. 값의 표와 핀의 표도 그렇게 얻었습니다. 넷리스트에서 `.include` 줄의 경로는 파일 이름만 남기고 줄 끝의 빈칸은 지웠습니다. KiCad 10이 같은 줄을 내놓는지, 10의 `LED` 기호에 모델이 붙어 있는지는 확인하지 못했습니다. 모델의 숫자는 3장과 4장의 것입니다.
</Note>

## 정리

- KiCad에서는 기호마다 모델을 붙인다. 저항 같은 것은 값만, 전원은 내장 모델, 제조사의 부품은 파일의 모델을 `Sim.Library`와 `Sim.Name`으로 붙인다
- 기호의 핀과 모델의 마디는 `Sim.Pins`로 짝짓는다. 틀려도 오류 없이 틀린 답이 나오므로 넷리스트의 줄을 확인한다
- 필드에 적는 값은 `M`이 메가다. KiCad가 넷리스트의 표기로 바꿔 주지만, 글로 적은 지시문은 바꾸지 않는다
