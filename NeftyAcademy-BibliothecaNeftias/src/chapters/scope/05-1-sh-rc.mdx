이 장에서는 자주 만나는 파형 여섯 가지를 놓고, 모양에서 회로의 사정을 읽어 냅니다. 첫 번째는 가장 흔한 곡선입니다. 저항 뒤에 커패시터가 있으면 전압은 곧게 뛰지 못하고, 휘어지며 뒤따라갑니다. 이 곡선을 알아보면 무엇이 신호를 느리게 만드는지 화면에서 읽을 수 있습니다.

## 곡선의 생김새

<Figure caption="10kΩ과 100nF. CH1은 저항 앞의 네모파, CH2는 커패시터의 전압이고 0V의 자리는 같다. 커서는 오르기 시작한 때와 1ms 뒤, 그리고 0V와 2.09V">
  <Scope tdiv={1e-3} dt={2.5e-5} traces={[{ name: 'CH1 저항 앞', data: rcIn, vdiv: 1, pos: -2 }, { name: 'CH2 커패시터', data: rcOut, vdiv: 1, pos: -2 }]} cursorsT={[1e-3, 2e-3]} cursorsV={[0, 2.086]} />
</Figure>

```python
import math

v, r, c = 3.3, 10e3, 100e-9
tau = r * c
print(f"시정수 {tau * 1e3:.1f}ms")
for k in range(1, 6):
    left = math.exp(-k)
    print(f"{k}τ 뒤: {v * (1 - left):.3f}V ({100 * (1 - left):.1f}%)")
rise = math.log(9) * tau
print(f"10%에서 90%까지 {rise * 1e3:.2f}ms (시정수의 {math.log(9):.2f}배)")
```

```text
시정수 1.0ms
1τ 뒤: 2.086V (63.2%)
2τ 뒤: 2.853V (86.5%)
3τ 뒤: 3.136V (95.0%)
4τ 뒤: 3.240V (98.2%)
5τ 뒤: 3.278V (99.3%)
10%에서 90%까지 2.20ms (시정수의 2.20배)
```

- **처음이 가장 가파르고 갈수록 눕는다**: 커패시터를 채우는 전류는 남은 전압 차이에 비례합니다. 찰수록 차이가 줄어 느려집니다
- **시정수는 저항과 커패시턴스의 곱이다**: 10kΩ에 100nF면 1ms입니다. 그리스 글자 τ(타우)로 적습니다
- **한 시정수에 63%**: 시정수만큼 지나면 끝 전압의 63%까지 옵니다. 다섯 배가 지나면 99%를 넘으므로 다 찬 것으로 칩니다
- **내려갈 때도 같은 모양이다**: 한 시정수 뒤에 37%가 남습니다. 그림의 오른쪽 반이 그 모습입니다

## 화면에서 시정수 읽기

- **63%에 커서를 놓는다**: 끝 전압의 63%인 2.09V에 가로 커서를 놓고, 곡선이 그 선을 지나는 곳에 세로 커서를 놓습니다. 오르기 시작한 때에서 거기까지가 시정수입니다. 그림에서는 한 칸, 1ms입니다
- **상승 시간을 2.2로 나눈다**: 자동 측정의 상승 시간(10%에서 90%까지)이 2.2ms로 나오면 시정수는 1ms입니다
- **끝 전압부터 읽는다**: 63%는 전원 전압이 아니라 곡선이 끝내 가 닿는 전압의 63%입니다. 넉넉히 기다린 뒤의 높이를 먼저 잽니다
- **부품을 거꾸로 셈한다**: 저항을 알면 시정수를 저항으로 나눠 커패시턴스를 얻습니다. 회로도에 없는 커패시턴스(긴 선, 핀, 프로브)의 크기를 이렇게 어림합니다

## 한쪽 변만 휜다

| 화면 | 뜻 |
| --- | --- |
| 올라가는 변만 휘고 내려가는 변은 곧다 | 풀업 저항이 올리고 트랜지스터가 끌어내리는 선(오픈 드레인)이다 |
| 두 변이 모두 휜다 | 신호가 지나는 길에 저항이 있고 그 뒤에 커패시턴스가 있다 |
| 다 오르기 전에 다시 내려간다 | 반 주기가 시정수의 다섯 배보다 짧다 |

<Figure caption="4.7kΩ 풀업이 올리는 오픈 드레인 선. CH1은 선의 커패시턴스가 100pF일 때, CH2는 400pF일 때">
  <Scope tdiv={2e-6} dt={5e-8} traces={[{ name: 'CH1 100pF', data: od100, vdiv: 1, pos: 0 }, { name: 'CH2 400pF', data: od400, vdiv: 1, pos: -4 }]} />
</Figure>

```python
import math

def rise_30_70(r, c):               # I2C 규격이 상승 시간을 재는 구간
    return math.log(0.7 / 0.3) * r * c

def fits(t):
    if t <= 300e-9:
        return "고속 모드까지"
    return "표준 모드만" if t <= 1000e-9 else "한도 초과"

for r, c in ((4700, 100e-12), (4700, 400e-12), (1800, 400e-12)):
    t = rise_30_70(r, c)
    print(f"{r / 1e3:.1f}kΩ, {c * 1e12:.0f}pF: {t * 1e9:5.0f}ns → {fits(t)}")
```

```text
4.7kΩ, 100pF:   398ns → 표준 모드만
4.7kΩ, 400pF:  1593ns → 한도 초과
1.8kΩ, 400pF:   610ns → 표준 모드만
```

- **내려갈 때는 트랜지스터가 당긴다**: 저항이 수십 Ω이라 곧게 떨어집니다. 올라갈 때는 4.7kΩ이 커패시턴스를 채워야 해서 휩니다
- **400pF에서는 상어 지느러미다**: 3.07V까지 오르다가 다시 끌려 내려갑니다. 장치를 여럿 달거나 선이 길어지면 커패시턴스가 이렇게 커집니다
- **I2C에는 한도가 있다**: 규격은 30%에서 70%까지 오르는 시간을 표준 모드(100kbit/s)에서 1000ns, 고속 모드(400kbit/s)에서 300ns 안으로 정합니다. 화면의 커서로 그대로 잴 수 있습니다([「I2C: 시작, 주소, ACK」](#/read/scope/bs-i2c))
- **풀업을 줄이면 빨라진다**: 라즈베리파이의 GPIO 2와 3에 달린 1.8kΩ이면 400pF에서도 610ns입니다. 그 대신 LOW로 당길 때 흐르는 전류가 늘어납니다
- **프로브도 한몫 보탠다**: 10배 프로브의 10pF 안팎이 선에 더해집니다. 1배로 보면 100pF가 더해져 재는 것 때문에 느려집니다([「프로브가 회로를 바꾼다」](#/read/scope/pb-loading))

<Note>
두 그림은 ngspice 42로 돌린 결과입니다. 오픈 드레인 선은 20Ω의 이상적인 스위치로 흉내 냈고, 진짜 핀이 끌어내리는 모양과 선의 인덕턴스는 들어 있지 않습니다. 선의 커패시턴스 100pF와 400pF는 견주어 보려고 고른 값입니다. I2C의 숫자는 NXP의 규격과 그 설명 자료에서 옮겼습니다. 장비를 찍은 화면이 아니라는 점은 앞 장과 같습니다.
</Note>

## 정리

- 저항 뒤의 커패시터는 변을 휘게 한다. 한 시정수(저항 × 커패시턴스)에 63%, 다섯 배면 다 찬다
- 시정수는 63%에 놓은 커서나 상승 시간을 2.2로 나눈 값으로 읽고, 거기서 숨은 커패시턴스를 어림한다
- 올라가는 변만 휘면 풀업이 올리는 선이다. 풀업이 크거나 커패시턴스가 크면 다 오르지 못한다
