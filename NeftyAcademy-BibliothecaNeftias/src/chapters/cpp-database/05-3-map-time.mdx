시각과 돈은 같은 글자가 다른 뜻이 되기 쉬운 값입니다. "9시"는 어느 도시의 9시인지 알아야 한 순간이 되고, 0.1은 이진 부동소수점으로 정확히 담기지 않습니다. 이 쪽에서는 시각은 순간으로, 돈은 정확한 수로 담는 법을 봅니다.

## 시각은 순간으로 담는다

PostgreSQL의 `timestamptz`(timestamp with time zone)는 이름과 달리 시간대를 저장하지 않습니다. 들어온 시각을 UTC 기준의 한 순간으로 바꿔 저장하고, 글자로 보여 줄 때만 세션의 `TimeZone` 설정으로 표기합니다. `timestamp`(without time zone)는 날짜와 시각 글자만 담는 벽시계 값입니다. C++에서 순간은 `std::chrono::sys_time`, 어느 도시의 벽시계로 본 순간은 `std::chrono::zoned_time`이 맡습니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <chrono>
#include <cstdio>
#include <format>
#include <sstream>
#include <string>

namespace ch = std::chrono;
using namespace std::chrono_literals;
using Instant = ch::sys_time<ch::microseconds>;      // UTC 위의 한 순간

std::string one(PGconn* c, const std::string& sql) {   // 첫 행의 첫 열
    PGresult* r = PQexec(c, sql.c_str());
    std::string v = PQntuples(r) > 0 ? PQgetvalue(r, 0, 0) : "";
    PQclear(r);
    return v;
}

int main() {
    PGconn* c = PQconnectdb("host=localhost dbname=academy user=academy "
                            "password=academy");
    one(c, "CREATE TEMP TABLE ev (tz timestamptz, naive timestamp);"
           "INSERT INTO ev VALUES ('2026-11-22 09:00:00+09', "
           "'2026-11-22 09:00:00+09')");
    std::printf("timestamp 열에 남은 값: %s\n",
                one(c, "SELECT naive FROM ev").c_str());
    std::printf("세션 시간대       timestamptz"
                "             timestamp를 timestamptz로\n");
    const char* zones[] = {"UTC", "Asia/Seoul", "America/New_York"};
    for (const char* z : zones) {
        one(c, std::string("SET TimeZone = '") + z + "'");
        std::string tz = one(c, "SELECT tz FROM ev");
        std::string cast = one(c, "SELECT naive::timestamptz FROM ev");
        std::printf("%-16s  %s  %s\n", z, tz.c_str(), cast.c_str());
    }

    one(c, "SET TimeZone = 'UTC'");              // 받을 글자의 꼴을 하나로 고정한다
    Instant t;
    std::istringstream in(one(c, "SELECT tz FROM ev"));
    in >> ch::parse("%F %T%z", t);
    auto sec = ch::floor<ch::seconds>(t);
    std::printf("C++가 받은 순간: %s\n", std::format("{:%F %T} UTC", sec).c_str());
    for (const char* z : {"Asia/Seoul", "America/New_York"})
        std::printf("  %s\n",
                    std::format("{:%F %T %Z}", ch::zoned_time{z, sec}).c_str());

    std::string iso = std::format("{:%FT%TZ}", t);         // 보낼 때도 UTC로
    const char* params[] = {iso.c_str()};
    PGresult* r = PQexecParams(c, "SELECT $1::timestamptz = tz FROM ev", 1, nullptr,
                               params, nullptr, nullptr, 0);
    std::printf("되돌려 보내기 %s → 같은 순간 %s\n", iso.c_str(),
                PQgetvalue(r, 0, 0));
    PQclear(r);

    // 뉴욕의 서머타임이 끝나는 밤에는 01:00~02:00이 두 번 지나간다
    auto wall = ch::local_days{2026y / 11 / 1} + 1h + 30min;
    try {
        ch::zoned_time z{"America/New_York", wall};
    } catch (const ch::ambiguous_local_time& e) {
        std::printf("%s\n", e.what());
    }
    PQfinish(c);
}
```

UTC               2026-11-22 00:00:00+00  2026-11-22 09:00:00+00

  2026-11-21 19:00:00 EST

- **timestamptz는 한 순간**: 세 줄의 표기는 다르지만 모두 UTC 00시라는 같은 순간입니다
- **timestamp는 벽시계 글자**: `+09`는 소리 없이 버려지고 "9시"만 남았습니다. 이것을 timestamptz로 바꾸면 세션 시간대의 9시로 읽혀서 세 줄이 서로 다른 순간이 됩니다. 같은 데이터가 서버나 연결의 설정에 따라 다른 뜻이 되는 것입니다
- **받을 때와 보낼 때**: 세션을 UTC로 고정하면 받는 글자의 꼴이 하나가 되어 `std::chrono::parse`의 `%z`로 풀 수 있습니다. 연결 문자열에 `options='-c TimeZone=UTC'`를 주면 처음부터 고정됩니다. 보낼 때도 `Z`를 붙인 ISO 8601 글자로 보내면 서버 설정과 상관없이 같은 순간이 됩니다. 마이크로초 정밀도는 timestamptz와 같습니다
- **벽시계는 모호하다**: 뉴욕에서 서머타임이 끝나는 밤의 01:30은 두 번 오므로 `zoned_time`이 `ambiguous_local_time` 예외로 알려 줍니다. 봄에 건너뛰는 시각은 `nonexistent_local_time`입니다. "매주 월요일 9시 회의"처럼 벽시계 자체가 뜻인 미래 약속만 timestamp에 시간대 이름을 함께 담고, 일어난 일의 시각은 순간으로 담습니다

SQLite에는 시각 형이 없으므로 UTC 기준의 정수(유닉스 시각)나 `Z`를 붙인 ISO 8601 글자로 담습니다. 글자는 모두 같은 꼴일 때만 사전 순서가 시간 순서와 같습니다.

## 돈은 double에 담지 않는다

0.1은 이진 부동소수점으로 정확히 나타낼 수 없어서, 더할수록 오차가 쌓입니다. 돈은 가장 작은 단위의 정수(센트, 원)로 담거나 정확한 십진수인 `numeric`으로 담습니다. [「테이블과 키」](#/read/cpp-database/db-tables)에서 가격을 정수로 둔 것이 첫 번째 방법입니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <charconv>
#include <cstdio>
#include <format>
#include <stdexcept>
#include <string>
#include <string_view>

std::string one(PGconn* c, const char* sql) {          // 첫 행의 첫 열
    PGresult* r = PQexec(c, sql);
    std::string v = PQntuples(r) > 0 ? PQgetvalue(r, 0, 0) : "";
    PQclear(r);
    return v;
}

// numeric(12,2)가 보낸 "-3.50"을 정수 센트 -350으로. double을 거치지 않는다
long long to_cents(std::string_view s) {
    bool neg = s.starts_with('-');
    if (neg) s.remove_prefix(1);
    auto dot = s.find('.');
    if (dot == s.npos || s.size() - dot != 3)
        throw std::invalid_argument("소수 둘째 자리까지가 아님");
    long long whole = 0, frac = 0;
    std::from_chars(s.data(), s.data() + dot, whole);
    std::from_chars(s.data() + dot + 1, s.data() + s.size(), frac);
    return (neg ? -1 : 1) * (whole * 100 + frac);
}

int main() {
    PGconn* c = PQconnectdb("host=localhost dbname=academy user=academy "
                            "password=academy");
    double d = 0;
    long long cents = 0;
    for (int i = 0; i < 10; ++i) {
        d += 0.1;
        cents += 10;
    }
    std::printf("0.1을 열 번 더하기\n");
    std::printf("  C++ double    %s\n", std::format("{}", d).c_str());
    std::printf("  C++ 정수 센트 %lld.%02lld\n", cents / 100, cents % 100);
    for (const char* type : {"float8", "numeric"}) {
        auto sql = std::format("SELECT sum(0.1::{}) FROM generate_series(1, 10)",
                               type);
        std::printf("  PG %-10s %s\n", type, one(c, sql.c_str()).c_str());
    }

    std::printf("numeric(12,2)에 넣기\n");
    one(c, "CREATE TEMP TABLE price (src text, p numeric(12,2));"
           "INSERT INTO price VALUES ('19.99', 19.99), ('''19.999''', '19.999'),"
           " ('-3.5', -3.5)");
    PGresult* r = PQexec(c, "SELECT src, p FROM price");
    long long total = 0;
    for (int i = 0; i < PQntuples(r); ++i) {
        long long v = to_cents(PQgetvalue(r, i, 1));
        total += v;
        std::printf("  %-8s → %-6s → %lld센트\n", PQgetvalue(r, i, 0),
                    PQgetvalue(r, i, 1), v);
    }
    PQclear(r);
    std::printf("  센트 합 %lld, DB의 sum %s\n", total,
                one(c, "SELECT sum(p) FROM price").c_str());

    long long base = 1999;                           // 15%는 299.85센트
    std::printf("1999센트의 15%%: 정수 나눗셈 %lld, 반올림 %lld\n", base * 15 / 100,
                (base * 15 + 50) / 100);
    PQfinish(c);
}
```

```text
0.1을 열 번 더하기
  C++ double    0.9999999999999999
  C++ 정수 센트 1.00
  PG float8     0.9999999999999999
  PG numeric    1.0
numeric(12,2)에 넣기
  19.99    → 19.99  → 1999센트
  '19.999' → 20.00  → 2000센트
  -3.5     → -3.50  → -350센트
  센트 합 3649, DB의 sum 36.49
1999센트의 15%: 정수 나눗셈 299, 반올림 300
```

- **double의 합**: C++와 PostgreSQL의 float8이 똑같이 0.9999999999999999를 냈습니다. SQLite는 3.43부터 `sum`이 오차를 보정하며 더해서 같은 합이 1.0이 나옵니다. 같은 double 계산도 DB마다 답이 다를 수 있다는 뜻입니다
- **정수 센트**: 어느 DB에서나 정확하고, BIGINT로 센트를 세면 약 9.2경 달러까지 담습니다. 십진 형이 없는 SQLite에서는 이것이 답입니다. NUMERIC 친화도의 열도 `'19.99'`를 REAL로 저장합니다
- **numeric(12,2)**: 계산은 정확하지만, 소수 자리가 넘치는 값은 넣을 때 조용히 반올림되었습니다(`'19.999'`가 20.00). C++에서는 글자로 받아 `to_cents`처럼 정수로 바꿉니다. `std::stod`를 거치면 다시 이진 소수가 됩니다
- **나눗셈의 규칙**: 299.85센트를 정수 나눗셈은 0 쪽으로 버려 299로 만듭니다. 반올림할지, 어느 쪽으로 할지는 코드에 적어 정합니다. 50을 더하고 나누는 방식은 양수에서만 맞습니다

<Note>
MySQL과 MariaDB의 `DATETIME`은 벽시계 값이고, `TIMESTAMP`는 세션 시간대에서 UTC로 바꿔 저장합니다. 다만 `TIMESTAMP`는 32비트 초로 담겨 2038년 1월 19일 03:14:07 UTC가 끝입니다. MariaDB는 11.5부터 64비트 플랫폼에서 2106년까지로 늘렸지만, MySQL에는 아직 이 한계가 남아 있습니다.
</Note>

## 정리

- 일어난 일의 시각은 timestamptz와 std::chrono::sys_time으로 담고, 주고받을 때는 UTC로 고정하며, 도시의 시각은 보여 줄 때만 zoned_time으로 만든다
- timestamp는 시간대 없는 벽시계 글자라서 설정에 따라 뜻이 바뀌고, 서머타임의 벽시계 시각은 없거나 두 번 있을 수 있다
- 돈은 정수 센트나 numeric으로 담고, numeric은 글자로 받아 정수로 바꾸며, 나눗셈의 반올림 규칙은 코드에 적어 정한다
