계좌 이체는 두 문장입니다. 한쪽에서 빼고 다른 쪽에 더합니다. 그 사이에 프로그램이 죽거나 오류가 나면 돈이 사라지거나 생겨납니다. **트랜잭션**은 여러 문장을 하나로 묶어 모두 반영되거나 하나도 반영되지 않게 합니다. 트랜잭션이 지키는 네 가지를 머리글자로 ACID라고 부릅니다.

- **원자성**(Atomicity): 전부 되거나 전부 안 됩니다
- **일관성**(Consistency): 끝나면 제약을 모두 만족하는 상태입니다
- **격리성**(Isolation): 동시에 도는 트랜잭션이 서로의 중간 상태를 보지 않습니다
- **지속성**(Durability): 커밋이 끝나면 전원이 꺼져도 남습니다

## 격리 수준

격리를 완벽하게 하면 동시에 돌 수 있는 일이 줄어들기 때문에, SQL 표준은 네 단계의 **격리 수준**을 두고 단계마다 허락하는 이상 현상을 정합니다. 낮은 쪽부터 READ UNCOMMITTED(커밋하지 않은 값까지 보임), READ COMMITTED(커밋된 값만 보이지만 같은 행을 다시 읽으면 바뀔 수 있음), REPEATABLE READ(다시 읽어도 같음), SERIALIZABLE(차례로 하나씩 실행한 것과 같은 결과)입니다. 기본값은 데이터베이스마다 달라서 PostgreSQL은 READ COMMITTED, MySQL의 InnoDB는 REPEATABLE READ이고, 쓰는 연결을 하나씩만 허락하는 SQLite는 늘 SERIALIZABLE입니다([「트랜잭션」](#/read/cpp-database/sqlite-tx)).

PostgreSQL에서 두 연결로 직접 확인해 보았습니다. libpq의 자세한 사용법은 [「PostgreSQL」](#/read/cpp-database/cs-postgres)에서 봅니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <cstdio>
#include <string>

const char* kInfo = "host=localhost dbname=academy user=academy password=academy";

struct Conn {                            // libpq 연결 하나 (자세한 것은 3장)
    PGconn* c = PQconnectdb(kInfo);
    Conn() { q("SET client_min_messages = warning"); }
    ~Conn() { PQfinish(c); }
    std::string q(const char* sql) {     // 첫 칸의 값, 또는 오류 코드와 메시지
        PGresult* r = PQexec(c, sql);
        std::string out;
        ExecStatusType st = PQresultStatus(r);
        if (st == PGRES_TUPLES_OK && PQntuples(r) > 0) out = PQgetvalue(r, 0, 0);
        if (st != PGRES_TUPLES_OK && st != PGRES_COMMAND_OK)
            out = std::string("오류 ") + PQresultErrorField(r, PG_DIAG_SQLSTATE) +
                  "\n    " + PQresultErrorField(r, PG_DIAG_MESSAGE_PRIMARY);
        PQclear(r);
        return out;
    }
};

std::string set_a(Conn& c, int v) {     // 앱이 계산한 값을 그대로 쓴다
    return c.q(("UPDATE tx_acc SET bal = " + std::to_string(v) +
                " WHERE id = 'A'").c_str());
}
const char* ok(const std::string& s) { return s.empty() ? "성공" : s.c_str(); }

void reset(Conn& c) {
    c.q("DROP TABLE IF EXISTS tx_acc; DROP TABLE IF EXISTS tx_doc;"
        "CREATE TABLE tx_acc (id TEXT PRIMARY KEY, bal INT CHECK (bal >= 0));"
        "INSERT INTO tx_acc VALUES ('A', 100), ('B', 0);"
        "CREATE TABLE tx_doc (name TEXT PRIMARY KEY, on_call BOOL);"
        "INSERT INTO tx_doc VALUES ('alice', true), ('bob', true);");
}

int main() {
    Conn t1, t2;
    reset(t1);
    std::printf("[원자성] A에서 B로 150 옮기기\n");
    t1.q("BEGIN");
    t1.q("UPDATE tx_acc SET bal = bal + 150 WHERE id = 'B'");
    std::printf("  A 빼기: %s\n", t1.q("UPDATE tx_acc SET bal = bal - 150 "
                                       "WHERE id = 'A'").c_str());
    std::printf("  다음 문장: %s\n", t1.q("SELECT 1").c_str());
    t1.q("ROLLBACK");
    std::printf("  ROLLBACK 뒤 B = %s\n", t1.q("SELECT bal FROM tx_acc "
                                              "WHERE id = 'B'").c_str());

    for (const char* level : {"READ COMMITTED", "REPEATABLE READ"}) {
        reset(t1);
        std::printf("[같은 행을 두 번 읽기: %s]\n", level);
        t1.q((std::string("BEGIN ISOLATION LEVEL ") + level).c_str());
        std::string a = t1.q("SELECT bal FROM tx_acc WHERE id = 'A'");
        t2.q("UPDATE tx_acc SET bal = 50 WHERE id = 'A'");     // 다른 연결이 바꿈
        std::string b = t1.q("SELECT bal FROM tx_acc WHERE id = 'A'");
        t1.q("COMMIT");
        std::printf("  처음 %s, 다시 %s\n", a.c_str(), b.c_str());

        reset(t1);
        std::printf("[읽고 더해서 쓰기를 둘이 동시에: %s]\n", level);
        t1.q((std::string("BEGIN ISOLATION LEVEL ") + level).c_str());
        t2.q((std::string("BEGIN ISOLATION LEVEL ") + level).c_str());
        int v1 = std::stoi(t1.q("SELECT bal FROM tx_acc WHERE id = 'A'"));
        int v2 = std::stoi(t2.q("SELECT bal FROM tx_acc WHERE id = 'A'"));
        set_a(t1, v1 + 10);
        t1.q("COMMIT");
        std::string w2 = set_a(t2, v2 + 10);
        t2.q("COMMIT");
        std::printf("  둘째 쓰기: %s\n", ok(w2));
        std::printf("  결과 %s (기대 120)\n", t1.q("SELECT bal FROM tx_acc "
                                                "WHERE id = 'A'").c_str());
    }

    for (const char* level : {"REPEATABLE READ", "SERIALIZABLE"}) {
        reset(t1);
        std::printf("[당직 의사 둘이 동시에 빠지기: %s]\n", level);
        for (Conn* c : {&t1, &t2})
            c->q((std::string("BEGIN ISOLATION LEVEL ") + level).c_str());
        const char* count = "SELECT count(*) FROM tx_doc WHERE on_call";
        std::printf("  둘 다 확인: %s명, %s명 당직\n", t1.q(count).c_str(),
                    t2.q(count).c_str());
        t1.q("UPDATE tx_doc SET on_call = false WHERE name = 'alice'");
        t2.q("UPDATE tx_doc SET on_call = false WHERE name = 'bob'");
        std::string c1 = t1.q("COMMIT"), c2 = t2.q("COMMIT");
        std::printf("  alice 커밋: %s\n  bob 커밋: %s\n", ok(c1), ok(c2));
        std::printf("  남은 당직 %s명\n", t1.q(count).c_str());
    }
}
```

```text
[읽고 더해서 쓰기를 둘이 동시에: READ COMMITTED]
  둘째 쓰기: 성공
  결과 110 (기대 120)
[같은 행을 두 번 읽기: REPEATABLE READ]
  처음 100, 다시 100
[읽고 더해서 쓰기를 둘이 동시에: REPEATABLE READ]
  둘째 쓰기: 오류 40001
    could not serialize access due to concurrent update
  결과 110 (기대 120)
[당직 의사 둘이 동시에 빠지기: REPEATABLE READ]
  둘 다 확인: 2명, 2명 당직
  alice 커밋: 성공
  bob 커밋: 성공
  남은 당직 0명
[당직 의사 둘이 동시에 빠지기: SERIALIZABLE]
  둘 다 확인: 2명, 2명 당직
  alice 커밋: 성공
  bob 커밋: 오류 40001
    could not serialize access due to read/write dependencies among transactions
  남은 당직 1명
```

- **원자성**: B에 더한 뒤 A에서 빼다가 잔액 제약에 걸렸습니다. PostgreSQL은 오류가 난 트랜잭션을 실패 상태로 두어, 그 뒤의 문장은 `ROLLBACK`할 때까지 모두 거절합니다(25P02). 되돌리자 B는 0 그대로였습니다
- **다시 읽기**: READ COMMITTED에서는 트랜잭션 도중 다른 연결이 커밋한 값이 보였고, REPEATABLE READ에서는 첫 질의 때 찍어 둔 스냅숏을 끝까지 보았습니다
- **잃어버린 갱신**: 둘이 100을 읽고 각자 110을 써서, 한쪽의 더하기가 사라졌습니다. REPEATABLE READ에서는 PostgreSQL이 동시에 고친 것을 알아채고 둘째 쓰기를 40001로 거절했으므로, 프로그램이 트랜잭션을 다시 하면 됩니다([「재시도」](#/read/cpp-database/tx-retry)). 처음부터 `SET bal = bal + 10`처럼 데이터베이스 안에서 계산하면 이 문제가 생기지 않습니다
- **쓰기 치우침**: 의사 둘이 각자 "당직이 둘이니 나는 빠져도 된다"고 확인하고 서로 다른 행을 고쳤습니다. 스냅숏만 보는 REPEATABLE READ는 둘 다 받아 당직이 0명이 되었고, SERIALIZABLE은 읽은 것과 쓴 것의 얽힘을 찾아 나중에 커밋한 쪽을 40001로 거절했습니다

<Note>
이 책의 PostgreSQL 예제는 내 컴퓨터(localhost)의 PostgreSQL에 `academy` 사용자와 같은 이름의 데이터베이스가 있다고 가정합니다. 관리자로 `CREATE ROLE academy LOGIN PASSWORD 'academy';`와 `CREATE DATABASE academy OWNER academy;`를 실행해 두면 됩니다. 연습용 암호이므로 실제 서비스에서는 쓰지 않습니다.
</Note>

## 수준 고르기

대부분의 프로그램은 기본값으로 충분하지만, "읽고 판단하고 쓰는" 일은 격리 수준을 따져야 합니다. 행 하나를 고치는 계산은 데이터베이스 안에서 하거나 `SELECT ... FOR UPDATE`로 그 행을 잠그고([「낙관적 잠금」](#/read/cpp-database/tx-optimistic)), 여러 행을 보고 판단하는 규칙은 SERIALIZABLE로 돌린 뒤 40001이 나면 다시 합니다. 격리 수준을 높이면 거절과 대기가 늘어나므로, 거절을 다시 하기로 처리할 준비가 되어 있어야 합니다.

## 정리

- 트랜잭션은 여러 문장을 전부 되거나 전부 안 되게 묶으며, PostgreSQL은 오류가 난 트랜잭션의 나머지 문장을 ROLLBACK할 때까지 거절한다
- 격리 수준이 낮으면 다시 읽을 때 값이 바뀌고, 읽고 계산해서 쓰는 일에서 갱신을 잃으며, 스냅숏 격리에서도 쓰기 치우침이 생긴다
- 데이터베이스 안에서 계산하거나 행을 잠그고, 여러 행에 걸친 규칙은 SERIALIZABLE로 돌리며, 40001 같은 거절은 트랜잭션을 다시 해서 처리한다
