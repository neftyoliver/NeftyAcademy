정수는 [「정수의 표현과 2의 보수」](#/read/basics/math-integers)에서 본 대로 정확하게 적힙니다. 3.14나 0.000001, 빛의 속도처럼 소수점이 있거나 아주 크고 작은 수는 다릅니다. 이 쪽은 컴퓨터가 이런 수를 **어림해서** 적는 방법과, 그 어림 때문에 생기는 일을 봅니다. 실제 비트 배치는 다음 장의 [「IEEE 754」](#/read/basics/std-ieee754)에서 다룹니다.

## 2진수의 소수점 아래

10진수에서 소수점 아래 자리의 무게는 1/10, 1/100, 1/1000입니다. 2진수에서는 1/2, 1/4, 1/8로 절반씩 작아집니다.

```text
0.101(2) = 1×(1/2) + 0×(1/4) + 1×(1/8)
         = 0.5 + 0.125
         = 0.625
```

그런데 1/2, 1/4, 1/8…을 더해서 만들 수 있는 수는 **분모가 2의 거듭제곱인 분수**뿐입니다. 0.5, 0.25, 0.75는 정확히 적히지만, 0.1(1/10)은 분모에 5가 들어 있어서 2진수로는 끝없이 이어집니다.

```text
0.1(10) = 0.000110011001100110011…(2)   (0011이 끝없이 되풀이)
```

10진수에서 1/3이 0.333…으로 끝나지 않는 것과 같은 일입니다. 칸은 유한하므로 어딘가에서 잘라야 하고, 그래서 컴퓨터 안의 0.1은 0.1에 **아주 가까운 다른 수**입니다.

## 소수점이 움직이는 표기

과학 시간에 큰 수를 3.0 × 10⁸처럼 적습니다. 의미 있는 숫자(3.0)와 크기(10⁸)를 나눠 적는 방법입니다. 컴퓨터도 실수를 이렇게 적되, 밑을 2로 합니다.

| 부분 | 뜻 | 10진 예 | 2진 예 (6.5) |
| --- | --- | --- | --- |
| 부호 | 양수인가 음수인가 | + | + |
| 가수 | 의미 있는 숫자들 | 3.0 | 1.101(2) |
| 지수 | 소수점을 몇 자리 옮기나 | 8 | 2 |

6.5는 2진수로 110.1이고, 소수점을 왼쪽으로 두 자리 옮기면 1.101 × 2²입니다. 지수만 바꾸면 같은 가수로 아주 큰 수도 아주 작은 수도 적을 수 있습니다. 소수점의 위치가 수마다 떠다닌다고 해서 **부동소수점**(floating point)이라고 부릅니다.

C의 `float`는 32비트에 가수 24자리(2진수), `double`은 64비트에 가수 53자리를 담습니다. 10진수로 치면 `float`는 약 7자리, `double`은 약 15~16자리가 믿을 만한 숫자입니다.

## 어림이 드러나는 곳

```c
#include <stdio.h>

int main(void)
{
    // 10진수로는 딱 떨어지지만 2진수로는 끝없이 이어지는 수
    double a = 0.1, b = 0.2;
    printf("0.1 + 0.2 = %.17f\n", a + b);
    printf("0.1 + 0.2 == 0.3 ? %s\n", a + b == 0.3 ? "같다" : "다르다");
    printf("0.1 을 20자리까지: %.20f\n", 0.1);

    // 2진수로 딱 떨어지는 수는 정확하다
    printf("0.5 + 0.25 = %.17f\n", 0.5 + 0.25);

    // float의 유효 숫자는 2진수 24자리
    float f = 16777216.0f;          // 2의 24제곱
    printf("16777216 + 1 = %.1f (float)\n", f + 1.0f);

    // 0.1을 천만 번 더하기
    float sf = 0.0f;
    double sd = 0.0;
    for (int i = 0; i < 10000000; i++) {
        sf += 0.1f;
        sd += 0.1;
    }
    printf("0.1을 천만 번: float %.1f, double %.6f\n", sf, sd);
    return 0;
}
```

```text
0.1 + 0.2 = 0.30000000000000004
0.1 + 0.2 == 0.3 ? 다르다
0.1 을 20자리까지: 0.10000000000000000555
0.5 + 0.25 = 0.75000000000000000
16777216 + 1 = 16777216.0 (float)
0.1을 천만 번: float 1087937.0, double 999999.999839
```

한 줄씩 보면 이렇습니다.

- **0.1 + 0.2는 0.3이 아니다.** 0.1도 0.2도 조금씩 어긋난 값이라, 더한 결과도 0.3을 어림한 값과 마지막 자리가 다릅니다. 그래서 실수를 `==`로 비교하면 안 되고, 차이가 아주 작은지를 봐야 합니다
- **0.1의 진짜 값**은 0.1000000000000000055…입니다. 평소에는 `printf`가 짧게 반올림해 보여 줘서 드러나지 않습니다
- **0.5 + 0.25는 정확하다.** 둘 다 분모가 2의 거듭제곱입니다
- **16,777,216에 1을 더해도 그대로다.** `float`의 가수는 24자리라 2²⁴을 넘으면 1 단위의 차이를 담을 자리가 없습니다. 더한 1이 반올림으로 사라졌습니다
- **작은 어긋남이 쌓인다.** 0.1을 천만 번 더하면 100만이어야 하는데 `float`는 1,087,937로 9% 가까이 틀립니다. 합이 커질수록 더하는 0.1이 상대적으로 작아져 반올림 오차가 커지기 때문입니다. `double`은 훨씬 낫지만 역시 딱 100만은 아닙니다

같은 프로그램을 Clang 20으로, 그리고 AArch64로 컴파일해 흉내 내어 돌려도 결과가 같습니다. 실수의 형식과 반올림 규칙이 표준으로 정해져 있기 때문이고, 그 표준이 IEEE 754입니다.

<Note kind="warn">
돈은 실수로 계산하면 안 됩니다. 0.1원짜리 어긋남이 쌓여 장부가 맞지 않게 됩니다. 은행과 회계 프로그램은 금액을 가장 작은 단위(원, 센트)의 **정수**로 세거나, 10진수를 그대로 다루는 방식을 씁니다.
</Note>

## 고정소수점

소수점 위치를 **고정해 두고 정수로 계산하는** 방법도 있습니다. 예를 들어 온도를 0.01도 단위의 정수로 저장하면, 23.45도는 정수 2345입니다. 계산은 정수 연산이라 빠르고 정확하며, 범위가 좁다는 것만 감수하면 됩니다.

실수 계산 회로(FPU)가 없는 작은 마이크로컨트롤러에서는 실수 연산을 소프트웨어로 흉내 내야 해서 아주 느립니다. 그래서 센서 값을 고정소수점으로 다루는 일이 흔합니다. 소형 기기 서가의 「측정값 다루기」에서 이 방법을 씁니다.

<Note>
실수는 "정확한 수"가 아니라 "정해진 자리수로 어림한 수"라고 기억하면 대부분의 함정을 피할 수 있습니다. 어림의 크기는 수 자체의 크기에 비례합니다. 1 근처에서는 아주 촘촘하고, 수가 커질수록 듬성듬성해집니다.
</Note>

## 정리

- 2진수의 소수점 아래로는 분모가 2의 거듭제곱인 수만 정확히 적히고, 0.1 같은 수는 끝없이 이어져 어림된다
- 부동소수점은 부호, 가수, 지수로 수를 적는 2진 과학 표기이고, `float`는 약 7자리, `double`은 약 15자리가 믿을 만하다
- 실수는 `==`로 비교하지 말고, 돈처럼 정확해야 하는 값은 정수나 고정소수점으로 다룬다
