윈도우에서는 파일이 `C:\Users\…`에 있고, USB 메모리를 꽂으면 `D:`나 `E:`가 생깁니다. 그래서 "C 드라이브"가 하드디스크의 다른 이름처럼 쓰입니다. 리눅스에는 C 드라이브가 없고 모든 것이 `/`에서 시작합니다. 이 쪽은 디스크와 파티션, 파일 시스템, 드라이브 문자를 떼어 보고, 두 OS가 이것들을 어떻게 다르게 보여 주는지 봅니다.

## 왜 하필 C인가

1980년대 IBM PC에는 하드디스크가 없거나 비쌌고, 플로피디스크 드라이브가 한두 개 달려 있었습니다. MS-DOS는 첫 번째 플로피 드라이브를 `A:`, 두 번째를 `B:`로 불렀습니다. 나중에 하드디스크가 붙자 다음 글자인 `C:`를 받았습니다.

플로피디스크는 사라졌지만 윈도우는 지금도 이 관습을 지켜서, OS가 설치된 곳을 `C:`로 두고 A와 B는 비워 둡니다. C라는 글자에 특별한 뜻은 없습니다. **세 번째로 남은 글자**였을 뿐입니다.

## 디스크, 파티션, 파일 시스템

"드라이브"라는 한 단어 뒤에는 세 가지 다른 것이 있습니다.

| 층 | 무엇인가 | 예 |
| --- | --- | --- |
| 디스크 | 실제 저장 장치 하나 | SSD 1TB, USB 메모리, SD 카드 |
| 파티션 | 디스크를 나눈 구역. 디스크 맨 앞의 표에 적힌다 | 1TB를 OS용 200GB와 자료용 800GB로 |
| 파일 시스템 | 파티션 안에 파일과 폴더를 정리하는 방식 | NTFS, FAT32, exFAT, ext4, APFS |

디스크 하나를 여러 파티션으로 나눌 수 있고, 파티션마다 다른 파일 시스템을 쓸 수 있습니다. 윈도우와 리눅스를 한 디스크에 함께 설치하면 파티션이 적어도 셋(부팅용, 윈도우용, 리눅스용)이 됩니다. [「루분투 설치」](#/read/basics/lubuntu)에서 설치기가 디스크를 나눈 것이 이 일입니다.

윈도우의 드라이브 문자는 **파티션(정확히는 파일 시스템이 든 구역)마다** 붙습니다. 그러니 디스크가 하나라도 `C:`와 `D:`가 생길 수 있고, 반대로 디스크가 둘이어도 파티션을 나누지 않았다면 `C:`와 `D:` 둘입니다. "C 드라이브가 꽉 찼다"는 말은 **OS가 든 파티션**이 꽉 찼다는 뜻이지, 디스크 전체가 꽉 찼다는 뜻이 아닐 수 있습니다.

파일 시스템이 하는 일은 [「파일 시스템」](#/read/basics/os-filesystem)에서 자세히 봅니다. 여기서는 OS마다 기본으로 쓰는 것만 짚어 둡니다.

| 파일 시스템 | 주로 쓰는 곳 | 다른 OS에서 |
| --- | --- | --- |
| NTFS | 윈도우 | 맥은 읽기만, 리눅스는 읽고 쓰기 가능 |
| ext4 | 리눅스 | 윈도우와 맥은 따로 도구가 있어야 한다 |
| APFS | macOS | 다른 OS에서 거의 못 쓴다 |
| FAT32, exFAT | USB 메모리, SD 카드 | 거의 모든 OS가 읽고 쓴다 |

USB 메모리를 FAT32나 exFAT으로 포맷해 파는 까닭이 맨 아래 줄입니다. FAT32는 파일 하나가 4GB를 넘을 수 없어서, 큰 동영상을 옮기려면 exFAT을 씁니다.

## 리눅스: 한 그루의 나무

리눅스에는 드라이브 문자가 없습니다. 모든 파일과 폴더가 `/`(루트)라는 **뿌리 하나에서 뻗은 나무** 안에 있습니다. 다른 디스크나 파티션은 이 나무의 한 폴더에 **붙여서**(마운트) 씁니다. 붙인 뒤에는 그 폴더 안으로 들어가는 것이 곧 그 디스크로 들어가는 것입니다.

| 윈도우 | 리눅스 |
| --- | --- |
| `C:\` | `/` |
| `C:\Users\nefty` | `/home/nefty` |
| `D:\` (두 번째 파티션) | `/data` 같은 원하는 폴더에 마운트 |
| `E:\` (USB 메모리) | `/media/nefty/USB이름` 같은 곳에 자동으로 마운트 |

어느 디스크가 어디에 붙어 있는지는 `lsblk`나 `df -h`로 봅니다. 이 책의 검사 기계에서 `lsblk`를 하면 첫 줄이 이렇게 나옵니다.

```text nocheck
NAME    SIZE TYPE MOUNTPOINT
vda     256G disk /
```

`vda`라는 256GB 디스크(가상 디스크)가 통째로 `/`에 붙어 있다는 뜻입니다. 이 기계에는 이 밖에도 작은 가상 디스크 몇 개가 `/opt` 아래의 폴더들에 붙어 있습니다. 라즈베리파이라면 보통 SD 카드(`mmcblk0`)가 두 파티션으로 나뉘어, 작은 FAT32 파티션이 부팅용으로 `/boot/firmware`에, 큰 ext4 파티션이 `/`에 붙어 있습니다.

<Note kind="tip">
리눅스의 장치 이름에도 규칙이 있습니다. SATA와 USB 디스크는 `sda`, `sdb`…, 그 안의 파티션은 `sda1`, `sda2`…입니다. NVMe SSD는 `nvme0n1`, 그 파티션은 `nvme0n1p1`입니다. SD 카드는 `mmcblk0`과 `mmcblk0p1`입니다. 장치 자체는 `/dev/sda`처럼 `/dev` 아래에 파일로 나타납니다. "모든 것은 파일"이라는 유닉스의 생각이 여기서도 보입니다.
</Note>

<Note kind="warn">
SD 카드에 OS 이미지를 굽거나 디스크를 포맷하는 명령에 장치 이름을 잘못 적으면, 다른 디스크의 내용이 통째로 지워집니다. `sdb`라고 적을 것을 `sda`라고 적는 한 글자 실수로 시스템 디스크를 날리는 일이 흔합니다. 명령을 실행하기 전에 `lsblk`로 크기와 이름을 꼭 확인하세요.
</Note>

## 정리

- C 드라이브의 C는 A와 B를 플로피 드라이브가 쓰던 시절에 하드디스크가 받은 세 번째 글자일 뿐이다
- 디스크는 실제 장치, 파티션은 그것을 나눈 구역, 파일 시스템은 구역 안의 정리 방식이고, 윈도우의 드라이브 문자는 파티션마다 붙는다
- 리눅스는 드라이브 문자 없이 `/`에서 뻗은 나무 하나에 디스크와 파티션을 폴더로 붙여(마운트) 쓴다
