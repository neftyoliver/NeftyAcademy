컴퓨터 안의 스위치는 켜짐과 꺼짐 두 가지뿐이라([「진공관에서 트랜지스터, 집적회로로」](#/read/basics/history-transistor)), 컴퓨터는 모든 수를 0과 1로 적습니다. 이 쪽은 그 적는 법인 2진수와, 사람이 2진수를 줄여 읽는 데 쓰는 16진수를 다룹니다. 계산은 손으로 따라 해 보는 것이 가장 빨리 익습니다.

## 자리의 무게

우리가 쓰는 10진수에서 `352`는 "3, 5, 2"가 아니라 이런 뜻입니다.

```text
352 = 3 × 100 + 5 × 10 + 2 × 1
    = 3 × 10² + 5 × 10¹ + 2 × 10⁰
```

오른쪽부터 자리마다 무게가 1, 10, 100으로 10배씩 커집니다. 한 자리에 쓸 수 있는 숫자는 0부터 9까지 열 개입니다. 이렇게 **자리에 따라 무게가 정해지는** 적는 법을 위치 기수법이라 하고, 무게가 몇 배씩 커지는지(10)를 밑이라고 부릅니다.

밑을 2로 바꾸면 2진수입니다. 숫자는 0과 1 두 개뿐이고, 자리의 무게는 1, 2, 4, 8, 16으로 두 배씩 커집니다.

```text
101010(2) = 1×32 + 0×16 + 1×8 + 0×4 + 1×2 + 0×1
          = 32 + 8 + 2
          = 42
```

2진수의 한 자리를 **비트**라고 합니다. 비트 여덟 개가 1바이트입니다([「비트와 바이트, GB와 GiB」](#/read/basics/terms-bits-bytes)).

## 몇 비트로 몇까지

비트 n개로 적을 수 있는 수는 2ⁿ가지입니다. 0부터 세므로 가장 큰 수는 2ⁿ − 1입니다.

| 비트 | 가짓수 | 0부터 셀 때 가장 큰 수 |
| --- | --- | --- |
| 1 | 2 | 1 |
| 4 | 16 | 15 |
| 8 | 256 | 255 |
| 16 | 65,536 | 65,535 |
| 32 | 4,294,967,296 | 4,294,967,295 |

8비트가 255까지인 까닭입니다. `11111111`에 1을 더하면 9자리 `100000000`이 되는데, 8비트 칸에는 아홉 번째 자리가 없으니 0으로 돌아갑니다. 이 넘침은 [「정수의 표현과 2의 보수」](#/read/basics/math-integers)에서 다시 봅니다.

## 10진수를 2진수로

2로 나누고 나머지를 적기를 몫이 0이 될 때까지 되풀이한 뒤, 나머지를 **아래에서 위로** 읽습니다. 42를 바꿔 봅니다.

```text
42 ÷ 2 = 21  나머지 0
21 ÷ 2 = 10  나머지 1
10 ÷ 2 =  5  나머지 0
 5 ÷ 2 =  2  나머지 1
 2 ÷ 2 =  1  나머지 0
 1 ÷ 2 =  0  나머지 1
아래에서 위로: 101010
```

2로 나눈 나머지는 그 수가 홀수인지 짝수인지, 곧 맨 오른쪽 비트입니다. 2로 나누는 것은 비트를 오른쪽으로 한 칸 미는 것과 같아서, 다음 나머지가 그다음 비트가 됩니다.

## 16진수

2진수는 자리가 너무 많아 사람이 읽기 어렵습니다. 32비트 수 하나가 0과 1 서른두 개입니다. 그래서 **네 비트씩 묶어 한 글자로** 적는 16진수를 씁니다. 네 비트는 0부터 15까지 열여섯 가지이므로, 9 다음에는 A부터 F까지 영문자를 빌려 씁니다.

| 2진수 | 16진수 | 10진수 |
| --- | --- | --- |
| 0000 | 0 | 0 |
| 0001 | 1 | 1 |
| 0010 | 2 | 2 |
| 0011 | 3 | 3 |
| 0100 | 4 | 4 |
| 0101 | 5 | 5 |
| 0110 | 6 | 6 |
| 0111 | 7 | 7 |
| 1000 | 8 | 8 |
| 1001 | 9 | 9 |
| 1010 | A | 10 |
| 1011 | B | 11 |
| 1100 | C | 12 |
| 1101 | D | 13 |
| 1110 | E | 14 |
| 1111 | F | 15 |

바꾸는 법은 오른쪽부터 네 비트씩 끊어 표를 보는 것뿐입니다.

```text
1100 1000(2)  →  C 8  →  0xC8
0xC8 = 12 × 16 + 8 = 200
```

16진수 두 글자가 정확히 1바이트입니다. 그래서 메모리 주소, 색깔(`#FF8800`), 기계어 바이트([「명령어를 실행하는 주기」](#/read/basics/arch-cycle)의 `75 f7`)처럼 바이트를 그대로 보여 줄 때 16진수를 씁니다. 앞에 붙은 `0x`는 "이것은 16진수"라는 표시입니다.

<Note kind="tip">
8진수(밑 8)도 있습니다. 세 비트를 한 글자로 묶습니다. 지금은 거의 리눅스 파일 권한(`chmod 755`)에서만 만납니다. 7은 `rwx` 세 비트가 모두 켜진 `111`입니다. [「리눅스 명령어와 POSIX」](#/read/basics/commands)에서 `chmod +x`로 켠 권한 비트를 숫자로 한꺼번에 적는 방식입니다.
</Note>

## C로 확인하기

C에서는 `0x`로 16진수, `0`으로 8진수, C23부터는 `0b`로 2진수를 바로 적을 수 있습니다. `printf`는 `%X`로 16진수, `%o`로 8진수를 찍지만 2진수는 직접 찍어야 합니다.

```c
#include <stdio.h>

// n을 2진수로 bits자리 찍는다
static void print_bin(unsigned n, int bits)
{
    for (int i = bits - 1; i >= 0; i--) {
        putchar((n >> i) & 1 ? '1' : '0');
        if (i % 4 == 0 && i != 0)
            putchar('_');
    }
}

int main(void)
{
    unsigned values[] = {5, 10, 42, 200, 255};
    for (int i = 0; i < 5; i++) {
        unsigned v = values[i];
        printf("%3u  0x%02X  0%03o  ", v, v, v);
        print_bin(v, 8);
        putchar('\n');
    }
    printf("%d %d %d\n", 0b101010, 0x2A, 052);
    return 0;
}
```

```text
  5  0x05  0005  0000_0101
 10  0x0A  0012  0000_1010
 42  0x2A  0052  0010_1010
200  0xC8  0310  1100_1000
255  0xFF  0377  1111_1111
42 42 42
```

`print_bin`의 `(n >> i) & 1`은 n을 오른쪽으로 i칸 밀고 맨 끝 비트만 남기는 식입니다. 위에서 손으로 한 "2로 나눈 나머지"를 비트 연산으로 한 것입니다. 마지막 줄은 같은 수 42를 세 가지로 적은 것이라 모두 42가 나옵니다.

<Note kind="warn">
C에서 `052`처럼 0으로 시작하는 수는 8진수입니다. 날짜나 번호를 자리 맞추려고 `010`이라고 쓰면 10이 아니라 8이 됩니다. 실수로 자주 밟는 함정입니다.
</Note>

## 정리

- 위치 기수법에서 자리의 무게는 밑의 거듭제곱이고, 2진수는 무게가 1, 2, 4, 8…로 두 배씩 커진다
- 비트 n개는 2ⁿ가지를 나타내므로 8비트는 0~255이고, 10진수는 2로 나눈 나머지를 거꾸로 읽어 2진수로 바꾼다
- 16진수는 네 비트를 한 글자로 묶은 것이라 두 글자가 1바이트이고, 주소와 바이트를 보여 줄 때 쓴다
