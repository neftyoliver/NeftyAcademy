[「2진수와 16진수」](#/read/basics/math-bases)에서는 0과 양수만 적었습니다. 이 쪽은 음수를 적는 방법을 봅니다. 답은 **2의 보수**라는 하나의 약속이고, 지금의 거의 모든 CPU가 이것을 씁니다. [「불 대수와 논리 게이트」](#/read/basics/math-boolean)에서 만든 덧셈기가 음수까지 그대로 계산할 수 있는 것이 이 약속의 장점입니다.

## 부호 없는 정수

8비트 칸은 256가지 무늬를 담습니다. 이것을 그대로 0부터 255까지로 읽으면 부호 없는 정수입니다. C에서는 `unsigned char`, `uint8_t`, `unsigned int` 같은 타입이 이것입니다.

255(`11111111`)에 1을 더하면 9비트짜리 `100000000`이 되고, 칸에 들어가지 않는 맨 앞자리가 떨어져 나가 0이 됩니다. 자동차 주행 거리계가 99999 다음에 00000이 되는 것과 같습니다. 부호 없는 정수는 이렇게 **한 바퀴 돌아오는** 것이 규칙으로 정해져 있습니다.

## 음수를 어떻게 적을까

가장 먼저 떠오르는 방법은 맨 앞 비트 하나를 부호로 쓰는 것입니다. 0이면 양수, 1이면 음수. 그런데 이렇게 하면 `00000000`(+0)과 `10000000`(−0)이 따로 생기고, 덧셈 회로가 부호를 보고 더할지 뺄지를 따로 판단해야 합니다.

2의 보수는 다른 생각에서 출발합니다. −1은 **1을 더하면 0이 되는 수**입니다. 8비트에서 `11111111`에 1을 더하면 한 바퀴 돌아 `00000000`이 되므로, `11111111`을 −1로 정합니다. 같은 식으로 `11111110`은 −2, `11111011`은 −5입니다.

| 비트 무늬 | 부호 없이 읽으면 | 2의 보수로 읽으면 |
| --- | --- | --- |
| `0000 0101` | 5 | 5 |
| `0111 1111` | 127 | 127 |
| `1000 0000` | 128 | −128 |
| `1111 1011` | 251 | −5 |
| `1111 1111` | 255 | −1 |

맨 앞 비트가 1이면 음수라는 점은 같지만, 0은 하나뿐이고 범위는 −128부터 127까지입니다. 음수 쪽이 하나 더 많습니다. 2의 보수로 읽을 때는 맨 앞 자리의 무게를 +128 대신 **−128**로 보면 됩니다. `1111 1011`은 −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5입니다.

## 부호 바꾸기

어떤 수의 부호를 바꾸려면 **모든 비트를 뒤집고 1을 더합니다.**

```text
 5        = 0000 0101
 뒤집기    = 1111 1010
 1 더하기  = 1111 1011  = −5
```

이것이 통하는 까닭은 간단합니다. 어떤 수와 그것을 뒤집은 수를 더하면 모든 자리가 1, 곧 −1이 됩니다. 그러니 뒤집은 수는 "−1 − 그 수"이고, 여기에 1을 더하면 "−그 수"입니다. 뺄셈 A − B는 A + (B를 뒤집고 1 더한 것)이므로, CPU는 **덧셈기 하나로 뺄셈까지** 합니다.

## C로 확인하기

같은 비트 무늬를 부호 없는 수와 부호 있는 수로 읽어 봅니다. 마지막 줄은 아래의 엔디언 이야기에서 씁니다.

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

static void bits8(uint8_t b)
{
    for (int i = 7; i >= 0; i--)
        putchar((b >> i) & 1 ? '1' : '0');
}

int main(void)
{
    // 같은 8비트 무늬를 부호 없는 수와 부호 있는 수로 읽는다
    int8_t values[] = {5, 1, 0, -1, -5, 127, -128};
    for (int i = 0; i < 7; i++) {
        int8_t s = values[i];
        uint8_t u = (uint8_t)s;
        bits8(u);
        printf("  부호 없이 %3u  부호 있게 %4d\n", u, s);
    }

    // 뒤집고 1 더하면 부호가 바뀐다
    int8_t x = 5;
    int8_t neg = (int8_t)(~x + 1);
    printf("~5 + 1 = %d\n", neg);

    // 부호 없는 수는 넘치면 0으로 돌아간다
    uint8_t big = 255;
    big = (uint8_t)(big + 1);
    printf("255 + 1 = %u (uint8_t)\n", big);

    // 메모리에 놓이는 바이트 순서
    uint32_t word = 0x12345678;
    unsigned char raw[4];
    memcpy(raw, &word, 4);
    printf("0x12345678 → %02x %02x %02x %02x\n", raw[0], raw[1], raw[2], raw[3]);
    return 0;
}
```

```text
00000101  부호 없이   5  부호 있게    5
00000001  부호 없이   1  부호 있게    1
00000000  부호 없이   0  부호 있게    0
11111111  부호 없이 255  부호 있게   -1
11111011  부호 없이 251  부호 있게   -5
01111111  부호 없이 127  부호 있게  127
10000000  부호 없이 128  부호 있게 -128
~5 + 1 = -5
255 + 1 = 0 (uint8_t)
0x12345678 → 78 56 34 12
```

`int8_t`의 −1과 `uint8_t`의 255는 메모리 안에서 똑같은 `11111111`입니다. 바이트 자체에는 부호가 없고, **타입이 그 무늬를 어떻게 읽을지 정합니다.**

## 넘침

부호 있는 정수도 칸을 넘치면 한 바퀴 돌아 엉뚱한 값이 됩니다. 8비트에서 127 + 1은 `1000 0000`, 곧 −128입니다. 32비트 `int`의 가장 큰 수 2,147,483,647에 1을 더하면 −2,147,483,648이 됩니다.

그런데 C 언어에서는 **부호 있는 정수의 넘침이 정의되지 않은 동작**입니다. 기계는 대개 한 바퀴 돌지만, 컴파일러는 "넘치는 일은 없다"고 가정하고 코드를 고쳐 쓸 수 있어서 결과를 믿을 수 없습니다. `int n = INT_MAX; n = n + 1;`을 GCC의 `-fsanitize=undefined`로 컴파일해 돌리면 실행 중에 잡아 줍니다(긴 줄은 접어 옮김).

```text nocheck
ov.c:7:7: runtime error: signed integer overflow: 2147483647 + 1 cannot be
  represented in type 'int'
-2147483648
```

부호 없는 정수의 넘침은 한 바퀴 도는 것이 규칙이라 정의된 동작입니다. 자세한 것은 [「정수형」](#/read/c-basic/types-integers)에서 다룹니다.

<Note kind="warn">
게임에서 돈이나 점수가 어느 순간 음수로 뒤집히는 버그 이야기는 대개 이 넘침입니다. 2014년에는 유튜브 조회수 표시가 32비트 정수(최대 약 21억)를 넘을 뻔해서 64비트로 바꾼 일도 있었습니다.
</Note>

## 바이트의 순서

32비트 정수 `0x12345678`은 4바이트입니다. 이 네 바이트를 메모리의 네 칸에 어떤 순서로 놓을지에도 약속이 필요합니다.

| 방식 | 낮은 주소부터 | 쓰는 곳 |
| --- | --- | --- |
| 리틀 엔디언 | `78 56 34 12` (작은 자리부터) | x86-64, 대부분의 ARM 기기 |
| 빅 엔디언 | `12 34 56 78` (큰 자리부터) | 네트워크 프로토콜, 일부 옛 CPU |

위 프로그램의 마지막 줄이 `78 56 34 12`이므로 검사 기계(x86-64)는 리틀 엔디언입니다. AArch64(라즈베리파이 64비트)로 컴파일해 흉내 내어 돌려도 같은 줄이 나옵니다. 한 기계 안에서는 신경 쓸 일이 없지만, 파일이나 네트워크로 바이트를 주고받을 때는 순서를 맞춰야 합니다. 인터넷의 표준 순서는 빅 엔디언이라 "네트워크 바이트 순서"라고도 부릅니다.

## 정리

- 부호 없는 정수는 비트 무늬를 그대로 0부터 읽고, 넘치면 한 바퀴 돌아 0이 된다
- 2의 보수는 맨 앞 자리의 무게를 음수로 보는 약속이라, 뒤집고 1을 더하면 부호가 바뀌고 덧셈기 하나로 뺄셈까지 한다
- C에서 부호 있는 정수의 넘침은 정의되지 않은 동작이고, 여러 바이트로 된 수는 엔디언에 따라 메모리에 놓이는 순서가 다르다
