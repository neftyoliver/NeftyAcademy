CPU는 레지스터와 캐시 바깥의 모든 것, 곧 램과 저장 장치, 키보드, 화면, 네트워크 카드에 **전선을 통해** 닿습니다. 이 전선들의 묶음과 그 위의 약속을 버스라고 합니다. 이 쪽은 CPU가 장치와 이야기하는 세 가지 방법(주소, 인터럽트, DMA)을 보고, PC와 라즈베리파이에서 실제로 쓰는 버스를 봅니다.

## 버스

버스는 여러 부품이 함께 쓰는 길입니다. 옛 컴퓨터의 버스는 말 그대로 기판 위의 평행한 전선 수십 가닥이었고, 쓰임에 따라 셋으로 나눴습니다.

| 선 | 실어 나르는 것 |
| --- | --- |
| 주소 버스 | 어느 칸과 이야기할지(주소) |
| 데이터 버스 | 오가는 값 |
| 제어 버스 | 읽을지 쓸지, 언제인지 |

CPU가 "주소 0x1000을 읽겠다"고 주소 선과 제어 선에 올리면, 그 주소를 맡은 부품이 데이터 선에 값을 올려 줍니다. [「8086에서 x86-64까지」](#/read/basics/history-x86)의 8086이 1MB까지만 쓸 수 있었던 것은 주소 선이 20가닥이었기 때문입니다.

지금의 버스는 대부분 선 몇 가닥으로 신호를 아주 빠르게 차례로 보내는 **직렬** 방식입니다. 선이 많으면 가닥마다 신호가 도착하는 때가 조금씩 어긋나서, 빨라질수록 맞추기가 어려워지기 때문입니다.

## 장치도 주소로 다룬다

CPU 입장에서 장치를 다루는 가장 흔한 방법은 **장치의 레지스터를 메모리 주소처럼** 보는 것입니다. 주소의 일부를 램이 아니라 장치에 배정해 두고, 그 주소에 값을 쓰면 장치에 명령이 가고, 읽으면 장치의 상태가 나옵니다. 이것을 메모리 맵 입출력(MMIO)이라고 합니다.

리눅스에서는 이 배정표를 볼 수 있습니다. 아래는 이 책의 검사 기계에서 `sudo cat /proc/iomem`을 한 결과의 앞부분입니다(일부만 옮김).

```text
00001000-0009fbff : System RAM
000f0000-000fffff : System ROM
00100000-bfffffff : System RAM
  01000000-0220bbc7 : Kernel code
c0001000-eebfffff : PCI Bus 0000:00
fec00000-fec003ff : IOAPIC 0
100000000-23fffffff : System RAM
```

- `System RAM`이 실제 램이 놓인 주소입니다. 그 안에 리눅스 커널의 코드(`Kernel code`)도 있습니다
- `c0001000`부터 `eebfffff`까지는 램이 아니라 **PCI 장치들**에 배정된 구간입니다. 램이 3GB 아래에서 끊겼다가 `100000000`(4GB)부터 다시 이어지는 것은 이 자리를 장치에 내주었기 때문입니다
- `System ROM`은 [「설치 도구와 부팅」](#/read/basics/boot)의 펌웨어가 놓인 자리입니다. 8086 시절과 같은 1MB 바로 아래입니다

x86에는 이것 말고도 장치만을 위한 별도의 번호 공간(I/O 포트)과 그것을 읽고 쓰는 전용 명령 `in`, `out`이 8086 때부터 있습니다. ARM에는 이런 것이 없고 모든 장치를 메모리 주소로 다룹니다. 라즈베리파이의 GPIO 핀도 어느 주소에 비트를 쓰면 켜지고 꺼집니다.

## 인터럽트

키보드를 언제 누를지 CPU는 모릅니다. CPU가 계속 "눌렸나?"를 물어볼 수도 있지만(폴링), 그러면 아무 일 없는 시간에도 CPU를 씁니다. 그래서 장치가 일이 생겼을 때 CPU에 **신호를 보내 하던 일을 잠깐 멈추게** 하는 방법을 씁니다. 이것이 인터럽트입니다.

1. 장치가 인터럽트 선에 신호를 올린다
2. CPU는 지금 명령을 마치고, 하던 일의 상태를 저장한다
3. 그 인터럽트 번호에 맞는 처리 코드(대개 OS의 장치 드라이버)로 뛰어간다
4. 처리가 끝나면 저장한 상태를 되살려 하던 일로 돌아간다

리눅스에서는 `/proc/interrupts`에 인터럽트 번호마다 CPU가 몇 번 받았는지가 쌓입니다. 네트워크 카드나 디스크가 바쁘면 그 줄의 숫자가 빠르게 올라갑니다. 인터럽트를 받는 코드는 [「장치 드라이버」](#/read/basics/os-drivers)에서 다시 봅니다.

## DMA

디스크에서 1GB를 읽어 램에 넣을 때, CPU가 4바이트나 8바이트씩 직접 옮기면 CPU는 그동안 다른 일을 못 합니다. 그래서 장치가 **CPU를 거치지 않고 램에 직접 쓰게** 합니다. 이것이 DMA(직접 메모리 접근)입니다.

CPU는 "이 주소부터 이만큼을 램의 저 자리로 옮겨라"라고 장치에 일러 두기만 하고 다른 일을 합니다. 옮기기가 끝나면 장치가 인터럽트로 알려 줍니다. 디스크, 네트워크 카드, 그래픽 카드, USB 컨트롤러가 모두 이렇게 일합니다.

<Note kind="warn">
DMA를 하는 장치는 램의 아무 곳에나 쓸 수 있으므로, 악의적인 장치를 꽂으면 OS의 메모리를 몰래 읽고 고칠 수도 있습니다. 그래서 요즘 컴퓨터에는 장치마다 닿을 수 있는 램의 범위를 제한하는 장치(IOMMU)가 들어 있습니다.
</Note>

## PC의 버스들

| 버스 | 무엇을 잇나 | 생김새 |
| --- | --- | --- |
| 메모리 버스 | CPU와 램 | 램 막대를 꽂는 슬롯. 메모리 컨트롤러가 CPU 안에 있다 |
| PCIe | 그래픽 카드, NVMe SSD, 네트워크 카드 | 길이가 다른 슬롯(x1, x4, x16)과 M.2 자리 |
| SATA | 2.5·3.5인치 SSD, HDD, 광학 드라이브 | 납작한 7핀 선 |
| USB | 키보드, 마우스, 저장 장치, 카메라 | 바깥의 포트. 장치를 꽂고 뽑을 수 있다 |

PCIe는 장치와 컨트롤러가 **레인**이라는 직렬 통로로 이어집니다. x1은 레인 하나, x16은 레인 열여섯입니다. 레인 하나의 빠르기는 세대마다 거의 두 배가 됐습니다. 3세대가 한 방향으로 약 1GB/s, 4세대가 약 2GB/s, 5세대가 약 4GB/s입니다. 그래픽 카드가 x16 슬롯에 꽂히는 것은 레인을 많이 쓰기 위해서입니다.

리눅스에서 PCIe(PCI) 장치의 목록은 `lspci`로 봅니다. 이 책의 검사 기계는 가상 기계라서 실제 부품 대신 가상 장치가 보입니다.

```text
00:00.0 Host bridge: Intel Corporation Device 0d57
00:02.0 Mass storage controller: Red Hat, Inc. Virtio 1.0 block device (rev 01)
00:08.0 Ethernet controller: Red Hat, Inc. Virtio 1.0 network device (rev 01)
```

## 작은 기기의 버스

라즈베리파이 같은 작은 기기는 센서나 화면을 잇는 데 선이 몇 가닥뿐인 느린 버스를 씁니다.

| 버스 | 선 | 흔한 쓰임 |
| --- | --- | --- |
| UART(시리얼) | 보내기, 받기 2가닥 | 디버깅 콘솔, GPS 모듈 |
| I2C | 데이터, 클럭 2가닥 | 온도·습도 센서, 작은 화면 |
| SPI | 4가닥 | 빠른 센서, 화면, SD 카드 |

이 버스들은 「컴퓨터 프로그래밍 중급」의 [「UART」](#/read/c-mid/bus-uart), [「I2C」](#/read/c-mid/bus-i2c), [「SPI」](#/read/c-mid/bus-spi)와 소형 기기 서가의 책들에서 직접 다뤄 봅니다.

## 정리

- CPU는 버스를 통해 램과 장치에 닿고, 지금의 버스는 대부분 선 몇 가닥으로 빠르게 보내는 직렬 방식이다
- 장치는 주소(MMIO)로 명령을 받고, 일이 생기면 인터럽트로 CPU를 부르고, 큰 데이터는 DMA로 램에 직접 옮긴다
- PC는 PCIe, SATA, USB로, 작은 기기는 UART, I2C, SPI로 장치를 잇는다
