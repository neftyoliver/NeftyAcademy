[「실수의 표현」](#/read/basics/math-floats)에서 실수는 부호, 가수, 지수로 적는다고 했습니다. 그 세 부분을 비트 몇 개씩에 어떤 순서로 담을지, 반올림은 어떻게 할지, 0으로 나누면 무엇이 나올지를 정한 표준이 IEEE 754입니다. 1985년에 처음 나왔고, 지금은 거의 모든 CPU와 GPU, 프로그래밍 언어가 이것을 따릅니다.

## 표준이 생기기 전

1970년대까지는 컴퓨터 회사마다 실수 형식이 달랐습니다. 비트 배치도, 반올림 방식도, 넘쳤을 때의 동작도 제각각이라 같은 프로그램이 기계마다 다른 답을 냈습니다. 인텔이 8087 실수 계산 칩을 만들면서 수학자 윌리엄 카핸과 함께 형식을 다듬었고, 이것이 IEEE 754의 바탕이 됐습니다. 카핸은 이 일로 1989년 튜링상을 받았습니다.

## 비트 배치

| 형식 | C 타입 | 부호 + 지수 + 가수 |
| --- | --- | --- |
| 단정밀도(32비트) | `float` | 1 + 8 + 23비트 |
| 배정밀도(64비트) | `double` | 1 + 11 + 52비트 |

맨 앞이 부호(0은 양수, 1은 음수), 그다음이 지수, 나머지가 가수입니다. 두 가지 꾀가 들어 있습니다.

- **숨은 1.** 0이 아닌 수를 2진 과학 표기로 적으면 맨 앞은 언제나 1입니다(1.101 × 2²처럼). 그러니 그 1은 저장하지 않고 소수점 아래만 담습니다. 23비트 칸으로 24자리를 얻는 셈입니다
- **치우친 지수.** 지수는 음수도 될 수 있는데, 부호를 따로 두지 않고 **127을 더한 값**(배정밀도는 1023)을 저장합니다. 저장된 값이 127이면 실제 지수는 0, 130이면 3입니다

6.5를 따라가 봅니다. 6.5 = 110.1(2) = 1.101 × 2²입니다.

```text
부호 0  (양수)
지수 2 + 127 = 129 = 1000 0001
가수 1.101 에서 앞의 1을 뺀 101, 뒤를 0으로 채움
     101 0000 0000 0000 0000 0000

0 10000001 10100000000000000000000  =  0x40D00000
```

## C로 비트를 들여다보기

`float`의 바이트를 `memcpy`로 같은 크기의 정수에 옮기면 비트를 그대로 볼 수 있습니다.

```c
#include <math.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

// float 하나를 부호, 지수, 가수 비트로 나눠 찍는다
static void show(const char *label, float f)
{
    uint32_t u;
    memcpy(&u, &f, sizeof u);
    unsigned sign = u >> 31;
    unsigned exp = (u >> 23) & 0xFF;
    unsigned frac = u & 0x7FFFFF;
    printf("%-9s %08X  부호 %u  지수 %3u  가수 %06X\n", label, u, sign, exp, frac);
}

int main(void)
{
    show("1", 1.0f);
    show("6.5", 6.5f);
    show("-6.5", -6.5f);
    show("0.1", 0.1f);
    show("0", 0.0f);
    show("-0", -0.0f);
    show("inf", INFINITY);
    show("nan", NAN);
    show("min", 1.4e-45f);

    float zero = 0.0f;
    float nan = zero / zero;
    printf("1/0 = %f, -1/0 = %f\n", 1.0f / zero, -1.0f / zero);
    printf("nan == nan ? %d,  0 == -0 ? %d\n", nan == nan, 0.0f == -0.0f);
    return 0;
}
```

```text
1         3F800000  부호 0  지수 127  가수 000000
6.5       40D00000  부호 0  지수 129  가수 500000
-6.5      C0D00000  부호 1  지수 129  가수 500000
0.1       3DCCCCCD  부호 0  지수 123  가수 4CCCCD
0         00000000  부호 0  지수   0  가수 000000
-0        80000000  부호 1  지수   0  가수 000000
inf       7F800000  부호 0  지수 255  가수 000000
nan       7FC00000  부호 0  지수 255  가수 400000
min       00000001  부호 0  지수   0  가수 000001
1/0 = inf, -1/0 = -inf
nan == nan ? 0,  0 == -0 ? 1
```

- **1**은 1.0 × 2⁰이라 지수가 0 + 127 = 127이고 가수는 비어 있습니다
- **6.5와 −6.5**는 맨 앞 비트 하나만 다릅니다. 부호를 바꾸는 데 2의 보수가 필요 없습니다
- **0.1**의 가수 `4CCCCD`는 2진수로 `100 1100 1100 1100 1100 1101`입니다. `1100`이 되풀이되다가 마지막에 반올림으로 `1101`이 됐습니다. 「실수의 표현」에서 본 끝없는 0.1을 23비트에서 자른 흔적입니다

## 특별한 값

지수 칸이 모두 0이거나 모두 1인 경우는 보통의 수가 아니라 특별한 뜻으로 씁니다.

| 지수 칸 | 가수 칸 | 뜻 |
| --- | --- | --- |
| 모두 0 | 0 | 0 (부호에 따라 +0과 −0) |
| 모두 0 | 0이 아님 | 비정규 수: 숨은 1 없이 아주 작은 수 |
| 모두 1 | 0 | 무한대 (+∞, −∞) |
| 모두 1 | 0이 아님 | NaN: 수가 아님 |

- **무한대.** 1을 0으로 나누면 프로그램이 멈추지 않고 `inf`가 나옵니다. 정수 나눗셈에서 0으로 나누면 프로그램이 죽는 것과 다릅니다. 너무 커서 넘친 값도 무한대가 됩니다
- **NaN.** 0/0이나 음수의 제곱근처럼 답이 없는 계산의 결과입니다. NaN은 **자기 자신과도 같지 않다**는 규칙이 있어서 `nan == nan`이 0(거짓)입니다. 그래서 `x != x`로 NaN인지 알아낼 수 있고, C에서는 `isnan(x)`을 씁니다
- **−0.** +0과 비교하면 같지만 비트는 다릅니다. `1/−0`은 −∞가 되어 차이가 드러납니다
- **비정규 수.** 표의 `min` 줄이 `float`로 적을 수 있는 가장 작은 양수, 약 1.4 × 10⁻⁴⁵입니다. 0 바로 위의 틈을 메우기 위해 숨은 1을 버리고 정밀도를 조금씩 내주는 수입니다

<Note kind="warn">
NaN은 퍼집니다. NaN이 섞인 계산의 결과는 거의 모두 NaN이 됩니다. 게임에서 캐릭터가 갑자기 사라지거나, 그래프가 한순간에 텅 비는 버그는 어딘가에서 생긴 NaN 하나가 퍼진 경우가 많습니다. 처음 NaN이 생긴 곳을 찾아야 고칠 수 있습니다.
</Note>

## 반올림

계산 결과가 가수 칸에 다 들어가지 않으면 반올림합니다. 기본 규칙은 **가장 가까운 값으로, 딱 중간이면 짝수 쪽으로**입니다. 0.5를 늘 올리면 많이 더할수록 결과가 한쪽으로 치우치기 때문에, 짝수 쪽(마지막 비트가 0인 쪽)으로 보내서 올림과 내림이 반반이 되게 합니다.

IEEE 754는 덧셈, 뺄셈, 곱셈, 나눗셈, 제곱근의 결과가 "정확한 답을 이 규칙으로 반올림한 값"과 같아야 한다고 정합니다. 그래서 [「실수의 표현」](#/read/basics/math-floats)의 예제가 x86-64에서도 ARM64에서도 같은 답을 냈습니다.

<Note>
2008년 개정판부터 16비트 반정밀도(지수 5비트, 가수 10비트)도 표준에 들어 있습니다. 그래픽과 인공지능 계산에서 많이 쓰고, 인공지능 쪽에서는 지수를 `float`와 같은 8비트로 두고 가수를 7비트로 줄인 bfloat16도 씁니다. 이것은 IEEE 표준이 아닌 구글의 형식입니다.
</Note>

## 정리

- IEEE 754의 `float`는 부호 1, 지수 8, 가수 23비트, `double`은 1, 11, 52비트이고, 숨은 1과 127을 더한 치우친 지수를 쓴다
- 지수 칸이 모두 0이면 0과 비정규 수, 모두 1이면 무한대와 NaN이며, NaN은 자기 자신과도 같지 않다
- 기본 반올림은 가장 가까운 값, 중간이면 짝수 쪽이고, 이 규칙이 정해져 있어서 어느 CPU에서나 같은 답이 나온다
