한 라인에서 여러 제품을 만들면 제품마다 오븐 온도, 컨베이어 속도, 굽는 시간 같은 설정값이 다릅니다. 이 설정값의 묶음을 **레시피**라고 합니다. 제품을 바꿀 때 작업자가 값을 하나하나 입력하면 실수가 생기므로, 검증된 레시피를 골라 한 번에 내려보냅니다. 배치 공정에서는 ISA-88 표준이 레시피를 일반·현장·마스터·제어 레시피로 나누어 체계화했지만, 여기서는 그 바탕이 되는 기본기를 봅니다.

## 레시피 다루기

레시피를 JSON으로 저장하고, 판(version)끼리 비교하고, 허용 범위를 검사하고, PLC에 내려보내는 과정을 짰습니다. JSON은 Qt의 `QJsonDocument`로 읽었습니다.

```cpp qt=Core
// 레시피: JSON으로 저장하고, 검사하고, 판끼리 비교하고, PLC에 한꺼번에 내려보낸다
#include <QCoreApplication>
#include <QJsonDocument>
#include <QJsonObject>
#include <cstdio>
#include <map>
#include <string>
#include <vector>

struct Limit { double min, max; const char* unit; };
const std::map<std::string, Limit> limits = {
    {"oven_temp", {150, 250, "°C"}}, {"belt_speed", {0.1, 2.0, "m/s"}},
    {"bake_time", {60, 900, "s"}}};

struct Recipe { std::string id; int version; std::map<std::string, double> p; };

Recipe parse(const char* json) {
    const QJsonObject o = QJsonDocument::fromJson(json).object();
    Recipe r{o["id"].toString().toStdString(), o["version"].toInt(), {}};
    const QJsonObject params = o["params"].toObject();
    for (auto it = params.begin(); it != params.end(); ++it)
        r.p[it.key().toStdString()] = it.value().toDouble();
    return r;
}

std::vector<std::string> validate(const Recipe& r) {
    std::vector<std::string> errors;
    for (const auto& [name, lim] : limits) {
        auto it = r.p.find(name);
        if (it == r.p.end()) errors.push_back(name + " 없음");
        else if (it->second < lim.min || it->second > lim.max)
            errors.push_back(name + " 범위 밖");
    }
    for (const auto& [name, v] : r.p)
        if (!limits.contains(name)) errors.push_back(name + " 모르는 항목");
    return errors;
}

struct Plc {                                     // PLC 쪽: 준비 영역과 실제 영역
    std::map<std::string, double> staging, active;
    bool running = false;
    int checksum(const std::map<std::string, double>& m) const {
        int s = 0;
        for (const auto& [k, v] : m) s = s * 31 + int(v * 100);
        return s;
    }
    // 전부 받았는지, 지금 바꿔도 되는지
    const char* commit(int sentChecksum) {
        if (running) return "거부: 운전 중";
        if (checksum(staging) != sentChecksum) return "거부: 체크섬 불일치";
        active = staging;
        return "적용됨";
    }
};

const char* download(Plc& plc, const Recipe& r, bool loseOneWrite = false) {
    plc.staging = r.p;                           // 1) 준비 영역에 하나씩 쓰고
    // 통신 오류로 하나가 빠짐
    if (loseOneWrite) plc.staging.erase("bake_time");
    return plc.commit(plc.checksum(r.p));        // 2) 체크섬과 함께 적용을 요청한다
}

int main(int argc, char* argv[]) {
    QCoreApplication app(argc, argv);
    const Recipe v3 = parse(R"({"id":"CRACKER-A","version":3,"params":
        {"oven_temp":210,"belt_speed":0.8,"bake_time":300}})");
    const Recipe v4 = parse(R"({"id":"CRACKER-A","version":4,"params":
        {"oven_temp":215,"belt_speed":0.8,"bake_time":280}})");
    const Recipe draft = parse(R"({"id":"CRACKER-A","version":5,"params":
        {"oven_temp":290,"belt_speed":0.8,"bake_tim":280}})");

    std::printf("%s v%d → v%d 바뀐 값:", v3.id.c_str(), v3.version, v4.version);
    for (const auto& [name, v] : v4.p)
        if (v3.p.at(name) != v)
            std::printf(" %s %g→%g", name.c_str(), v3.p.at(name), v);
    std::printf("\nv%d 초안 검사:", draft.version);
    for (const auto& e : validate(draft)) std::printf(" [%s]", e.c_str());
    std::printf("\n");

    Plc plc;
    plc.running = true;
    std::printf("운전 중에 v4 내려보내기: %s\n", download(plc, v4));
    plc.running = false;
    std::printf("쓰기 하나가 빠진 채로: %s\n", download(plc, v4, true));
    const char* result = download(plc, v4);
    std::printf("다시 내려보내기: %s, 오븐 설정 %g°C\n", result,
                plc.active["oven_temp"]);
}
```

```text
CRACKER-A v3 → v4 바뀐 값: bake_time 300→280 oven_temp 210→215
v5 초안 검사: [bake_time 없음] [oven_temp 범위 밖] [bake_tim 모르는 항목]
운전 중에 v4 내려보내기: 거부: 운전 중
쓰기 하나가 빠진 채로: 거부: 체크섬 불일치
다시 내려보내기: 적용됨, 오븐 설정 215°C
```

- **판 관리와 비교**: 레시피는 덮어쓰지 않고 판을 올려 새로 저장합니다. 품질 문제가 생기면 "그날 어떤 판으로 만들었고, 이전 판과 무엇이 달랐는가"를 바로 답할 수 있어야 하기 때문입니다. v3과 v4의 차이는 굽는 시간과 오븐 온도였습니다
- **범위 검사는 저장할 때와 보낼 때 모두**: 허용 범위는 레시피 밖의 별도 표에 둡니다. 초안의 오븐 온도 290도는 범위를 넘었고, 오타 `bake_tim` 때문에 굽는 시간이 빠진 것과 모르는 항목이 생긴 것도 잡혔습니다. 오타 하나가 "굽는 시간 0초"로 내려가지 않게 하는 것이 이 검사의 몫입니다
- **한꺼번에 적용**: 값을 PLC가 쓰는 자리에 하나씩 바로 쓰면, 중간에 통신이 끊겼을 때 반은 새 값, 반은 옛 값인 레시피로 기계가 돌게 됩니다. 그래서 준비 영역에 모두 쓴 뒤 체크섬과 함께 "적용"을 요청하고, PLC가 모두 받았는지 확인한 뒤에 한 번에 바꿉니다. 쓰기 하나가 빠졌을 때 체크섬이 맞지 않아 거부되었습니다
- **바꿔도 되는 때**: 운전 중에는 적용을 거부했습니다. 언제 레시피를 바꿀 수 있는지(정지 중, 배치 사이)는 PLC가 판단합니다

<Note>
실제로는 위의 단순한 체크섬 대신 CRC를 쓰고, 레시피를 바꾼 사람과 시각, 이전 값과 새 값을 기록합니다. 식품, 제약처럼 규제가 있는 산업에서는 레시피 변경에 승인 절차와 전자 서명까지 요구됩니다([「사용자와 권한」](#/read/cpp-industrial/hmi-users)). 레시피가 많아지면 파일보다 데이터베이스에 두는 편이 판 관리와 검색에 편합니다.
</Note>

## 정리

- 레시피는 제품별 설정값의 묶음이며, 덮어쓰지 않고 판을 올려 저장해 판끼리 비교할 수 있게 한다
- 허용 범위는 별도의 표에 두고 저장할 때와 보낼 때 모두 검사하며, 빠진 항목과 모르는 항목도 잡는다
- PLC에는 준비 영역에 모두 쓴 뒤 체크섬과 함께 한 번에 적용하고, 적용해도 되는 때인지는 PLC가 판단한다
