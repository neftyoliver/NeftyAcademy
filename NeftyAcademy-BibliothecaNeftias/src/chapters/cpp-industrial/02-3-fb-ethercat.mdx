여러 축을 1밀리초보다 짧은 주기로 함께 움직여야 하는 기계(포장기, 반도체 장비, 로봇)에서는 Modbus처럼 장비마다 요청을 보내고 답을 기다리는 방식으로는 시간이 모자랍니다. EtherCAT은 2003년 Beckhoff가 내놓고 지금은 EtherCAT Technology Group이 관리하는 산업용 이더넷으로, 이 문제를 독특한 방법으로 풉니다. 장비마다 프레임을 따로 보내지 않고, **프레임 하나가 모든 장비를 차례로 지나가게** 합니다.

## 지나가며 처리하기

EtherCAT 슬레이브들은 줄줄이 이어져 있고, 마스터(보통 PC)가 보낸 이더넷 프레임(이더타입 `88A4`)이 첫 슬레이브부터 끝까지 갔다가 되돌아옵니다. 각 슬레이브의 전용 칩은 프레임을 받아 저장했다가 넘기는 것이 아니라, **비트가 지나가는 동안** 자기 몫의 출력을 읽어 가고 자기 입력을 그 자리에 써 넣습니다. 슬레이브 하나가 더하는 지연은 매우 짧습니다.

마스터 쪽에서 보면 모든 장비의 입출력이 하나의 메모리 덩어리, **프로세스 이미지**로 보입니다. 각 슬레이브는 그 안에서 자기 자리를 설정받고(FMMU), 마스터는 매 주기 이 이미지 전체를 LRW(논리 주소 읽기·쓰기) 데이터그램 하나로 보냅니다. 슬레이브 셋으로 그 한 주기를 흉내 냈습니다.

```cpp
// EtherCAT의 한 주기: 프레임 하나가 슬레이브들을 지나며 출력을 주고 입력을 받는다
#include <algorithm>
#include <cstdint>
#include <cstdio>
#include <cstring>
#include <vector>

struct Datagram {                    // LRW(논리 주소 읽기·쓰기) 데이터그램 하나
    uint32_t logical = 0;            // 프로세스 이미지의 시작 논리 주소
    std::vector<uint8_t> data;       // 출력 7바이트 + 입력 7바이트
    uint16_t wkc = 0;                // 작업 카운터
};

// 슬레이브가 프로세스 이미지에서 맡은 자리(FMMU)
struct Slave {
    const char* name;
    int outAt, outLen;               // 마스터 → 슬레이브
    int inAt, inLen;                 // 슬레이브 → 마스터
    std::vector<uint8_t> outputs, inputs;

    void process(Datagram& g) {      // 프레임이 지나가는 동안 하드웨어가 하는 일
        bool rd = false, wr = false;
        if (outLen) {                // 출력을 꺼내 가고
            outputs.assign(g.data.begin() + outAt, g.data.begin() + outAt + outLen);
            wr = true;
        }
        if (inLen) {                 // 입력을 그 자리에 써 넣는다
            std::memcpy(&g.data[inAt], inputs.data(), inLen);
            rd = true;
        }
        g.wkc += (rd ? 1 : 0) + (wr ? 2 : 0);    // 읽기 +1, 쓰기 +2
    }
};

int main() {
    std::vector<Slave> line = {      // 케이블로 이어진 순서대로
        {"디지털 출력 8점", 0, 1, 0, 0, {}, {}},
        {"디지털 입력 8점", 0, 0, 7, 1, {}, {0x05}},
        {"서보 드라이브", 1, 6, 8, 6, {}, {0x37, 0x06, 0xE6, 0x03, 0x00, 0x00}},
    };
    const int expectedWkc = 2 + 1 + 3;
    // 이더넷·EtherCAT 머리, 데이터그램, FCS
    const int frameBytes = 14 + 2 + 10 + 14 + 2 + 4;
    std::printf("프레임 %d바이트(최소 64로 채움), 100Mbit/s에서 %.2fµs\n",
                frameBytes, std::max(frameBytes, 64) * 8 / 100.0);

    for (int cycle = 1; cycle <= 2; ++cycle) {
        Datagram g;
        g.data.assign(14, 0);
        g.data[0] = 0x0F;                            // 디지털 출력 0~3 켬
        g.data[1] = 0x0F; g.data[2] = 0x00;          // 서보 제어 워드 000F
        g.data[3] = 0xE8; g.data[4] = 0x03;          // 서보 목표 위치 1000
        // 2주기: 3번 앞 케이블 빠짐
        const size_t reached = cycle == 1 ? line.size() : 2;
        for (size_t i = 0; i < reached; ++i) line[i].process(g);

        const int status = g.data[8] | g.data[9] << 8;
        const int pos = g.data[10] | g.data[11] << 8;
        std::printf("주기 %d: WKC %u (기대 %d)", cycle, g.wkc, expectedWkc);
        if (g.wkc == expectedWkc)
            std::printf(" → 입력 %02X, 서보 상태 %04X, 위치 %d\n",
                        g.data[7], status, pos);
        else
            std::printf(" → 입력을 믿을 수 없음, 안전하게 멈춘다\n");
        if (cycle == 1) {
            const auto& o = line[2].outputs;
            std::printf("  서보가 받은 출력: 제어 워드 %02X%02X, 목표 %d\n",
                        o[1], o[0], o[2] | o[3] << 8);
        }
    }
}
```

```text
프레임 46바이트(최소 64로 채움), 100Mbit/s에서 5.12µs
주기 1: WKC 6 (기대 6) → 입력 05, 서보 상태 0637, 위치 998
  서보가 받은 출력: 제어 워드 000F, 목표 1000
주기 2: WKC 3 (기대 6) → 입력을 믿을 수 없음, 안전하게 멈춘다
```

- **한 프레임, 한 주기**: 출력 7바이트와 입력 7바이트가 프레임 하나에 들어갑니다. 100Mbit/s에서 프레임을 내보내는 데 약 5µs(앞뒤의 프리앰블과 간격은 뺐습니다)이므로, 슬레이브가 수십 대여도 주기를 수백 마이크로초 아래로 줄일 수 있습니다
- **작업 카운터(WKC)**: 데이터그램을 처리한 슬레이브마다 숫자를 더합니다(읽기 +1, 쓰기 +2, 둘 다 +3). 돌아온 WKC가 기대값과 같아야 모든 장비가 이번 주기에 참여했다는 뜻입니다
- **끊어지면 알 수 있다**: 2주기에서는 서보 앞의 케이블이 빠졌다고 했습니다. 실제 슬레이브는 다음 포트가 끊기면 프레임을 스스로 되돌려 보내므로, 서보는 프레임을 받지 못했고 WKC가 3에 그쳤습니다. 마스터는 이번 입력을 쓰지 않고 정해진 안전 동작을 합니다
- **바이트를 해석하는 것은 마스터의 일**: 서보의 상태 워드 `0637`과 제어 워드 `000F`는 [「CAN과 CANopen」](#/read/cpp-industrial/fb-can)에서 본 CiA 402 드라이브 프로필의 값입니다. EtherCAT 서보도 같은 프로필을 씁니다

## 상태와 설정

EtherCAT 슬레이브는 INIT → PRE-OP → SAFE-OP → OP 상태를 차례로 거칩니다. PRE-OP에서는 메일박스로 설정을 주고받을 수 있고, SAFE-OP에서는 입력은 읽히지만 출력은 안전한 값으로 묶여 있으며, OP가 되어야 출력이 실제로 움직입니다. 메일박스 위에는 여러 프로토콜이 올라가는데, 가장 흔한 CoE(CANopen over EtherCAT)는 CANopen의 객체 사전과 SDO를 그대로 씁니다. 그래서 CANopen 드라이브를 다뤄 봤다면 EtherCAT 드라이브의 설정도 낯설지 않습니다.

장비 제조사는 슬레이브의 정보(객체 사전, 프로세스 데이터, 지원 기능)를 ESI라는 XML 파일로 줍니다. 설정 도구가 이 파일들을 읽어 네트워크 구성을 만들고, 마스터는 그 구성대로 슬레이브에 자리를 나눠 줍니다.

## 시각 맞추기

여러 축을 함께 움직이려면 모든 슬레이브가 같은 순간에 출력을 내고 입력을 재야 합니다. EtherCAT의 **분산 클록**(DC)은 각 슬레이브의 칩에 시계를 두고, 프레임이 지나가는 시각을 이용해 전송 지연을 재고 보정합니다. 그 결과 슬레이브들의 시계 차이는 1µs보다 훨씬 작게 유지됩니다. 이 시계에 맞춰 출력이 일제히 바뀌므로, 마스터 PC의 지터가 조금 있어도 축들의 동작은 맞습니다([「여러 축 맞추기」](#/read/cpp-industrial/mot-multi-axis)).

<Note>
마스터를 직접 짜는 일은 드뭅니다. 리눅스에서는 오픈 소스 SOEM(GPLv3 또는 상용 라이선스)이나 IgH EtherCAT Master를 많이 쓰고, 상용 제품도 여럿 있습니다. 어느 쪽이든 마스터 PC는 매 주기 프레임을 정확한 시각에 보내야 하므로, [「주기 작업」](#/read/cpp-industrial/rt-cyclic)에서 다루는 실시간 루프 위에서 돌립니다. 보통의 네트워크 카드와 이더넷 선을 그대로 쓰지만, 같은 포트에 사무용 트래픽을 섞지는 않습니다.
</Note>

## 정리

- EtherCAT은 프레임 하나가 줄지어 이어진 슬레이브를 차례로 지나가며, 각 슬레이브가 지나가는 비트에서 출력을 읽고 입력을 써 넣는다
- 마스터는 모든 입출력을 프로세스 이미지 하나로 보고 LRW로 한 번에 주고받으며, 작업 카운터로 모든 슬레이브가 참여했는지 확인한다
- 슬레이브는 INIT부터 OP까지의 상태를 거치고, CoE로 CANopen식 설정을 하며, 분산 클록으로 1µs보다 훨씬 작은 차이로 시각을 맞춘다
