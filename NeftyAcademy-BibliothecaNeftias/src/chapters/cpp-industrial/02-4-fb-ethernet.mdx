공장의 이더넷 필드버스는 사실상 PLC 제조사의 세력권을 따라 나뉩니다. 지멘스 PLC가 많은 곳에서는 **PROFINET**, 로크웰(Allen-Bradley) PLC가 많은 곳에서는 **EtherNet/IP**를 만나게 됩니다. 둘 다 보통의 이더넷 장비 위에서 돌고, 같은 선 위에 일반 TCP/IP 통신도 함께 흐릅니다. 생김새는 다르지만 구조는 닮았습니다. 정해진 주기로 흐르는 **입출력 데이터**와, 필요할 때만 오가는 **설정·진단 메시지**가 따로 있습니다.

| 항목 | PROFINET | EtherNet/IP |
| --- | --- | --- |
| 관리 단체 | PI(PROFIBUS & PROFINET International) | ODVA |
| 주기 데이터 | 이더넷 2계층 프레임(이더타입 8892) | UDP 2222번 포트 |
| 비주기 메시지 | 레코드 읽기·쓰기, 알람 | TCP 44818번 포트의 명시적 메시지 |
| 장비 설명 파일 | GSDML(XML) | EDS |

## PROFINET

PROFINET에서는 PLC를 IO 컨트롤러, 현장 장비를 IO 디바이스라고 부릅니다. 장비는 IP 주소보다 먼저 **장치 이름**("press-left-valve" 같은)을 받고, 컨트롤러는 시작할 때 이 이름으로 장비를 찾아 IP를 정하고 연결을 맺습니다. 그 뒤로는 양쪽이 설정한 주기마다 입출력 데이터를 IP 없이 이더넷 프레임으로 직접 보냅니다(RT). 데이터에는 값마다 "이 값은 유효하다"는 상태 바이트가 붙어서, 받는 쪽이 값을 믿어도 되는지 압니다. 더 짧고 정확한 주기가 필요한 모션 제어에는 전용 하드웨어로 시간을 나누어 쓰는 IRT가 있습니다.

## EtherNet/IP와 CIP

EtherNet/IP의 "IP"는 인터넷 프로토콜이 아니라 Industrial Protocol입니다. 그 위의 언어는 **CIP**(Common Industrial Protocol)이며, 장비를 **클래스, 인스턴스, 속성**으로 된 객체의 모음으로 봅니다. 예를 들어 모든 장비에 있는 Identity 객체(클래스 01)의 속성 7은 제품 이름입니다. 그 속성을 읽는 명시적 메시지를 바이트로 짜고, 주기 연결의 시간 초과를 흉내 냈습니다.

```cpp
// EtherNet/IP: CIP 명시적 메시지를 바이트로 짜고, 주기 연결의 시간 초과를 흉내 낸다
#include <cstdint>
#include <cstdio>
#include <string>
#include <vector>

using Bytes = std::vector<uint8_t>;
void put16(Bytes& b, uint16_t v) {              // 낮은 바이트부터(Modbus와 반대)
    b.push_back(v & 0xFF);
    b.push_back(v >> 8);
}
void put32(Bytes& b, uint32_t v) { put16(b, v & 0xFFFF); put16(b, v >> 16); }

void dump(const char* label, const Bytes& b, size_t from, size_t n) {
    std::printf("%s:", label);
    for (size_t i = from; i < from + n; ++i) std::printf(" %02X", b[i]);
    std::printf("\n");
}

int main() {
    // CIP 요청: Identity 객체(클래스 01) 인스턴스 1의 속성 7(제품 이름)을 읽는다
    const Bytes cip = {0x0E,                     // 서비스: Get_Attribute_Single
                       0x03,                     // 경로 길이(16비트 단어 3개)
                       0x20, 0x01,               // 클래스 01
                       0x24, 0x01,               // 인스턴스 1
                       0x30, 0x07};              // 속성 7
    Bytes item;                                  // 공통 패킷 형식: 항목 2개
    put32(item, 0);                              // 인터페이스 핸들
    put16(item, 10);                             // 제한 시간(초)
    put16(item, 2);                              // 항목 수
    put16(item, 0x0000); put16(item, 0);         // 빈 주소 항목(연결 없음)
    // 연결 없는 데이터 항목
    put16(item, 0x00B2); put16(item, uint16_t(cip.size()));
    item.insert(item.end(), cip.begin(), cip.end());

    Bytes msg;                                   // 캡슐화 머리 24바이트
    put16(msg, 0x006F);                          // 명령: SendRRData
    put16(msg, uint16_t(item.size()));           // 뒤따르는 길이
    // 세션 핸들(RegisterSession으로 받음)
    put32(msg, 0x12345678);
    put32(msg, 0);                               // 상태
    for (int i = 0; i < 8; ++i) msg.push_back(0); // 보낸 쪽 문맥(응답에 그대로 옴)
    put32(msg, 0);                               // 옵션
    msg.insert(msg.end(), item.begin(), item.end());

    std::printf("TCP 44818로 보낼 %zu바이트\n", msg.size());
    dump("명령·길이·세션", msg, 0, 8);           // 캡슐화 머리 24바이트
    dump("상태·문맥·옵션", msg, 8, 16);
    dump("CPF 항목", msg, 24, 16);
    dump("CIP 요청", msg, 40, cip.size());

    // 장비가 돌려준 CIP 응답(앞의 머리는 생략): 서비스 | 0x80, 상태 0, 문자열
    const Bytes reply = {0x8E, 0x00, 0x00, 0x00, 0x0F, 'D', 'e', 'm', 'o', ' ',
                         'D', 'r', 'i', 'v', 'e', ' ', '2', '0', '0', '0'};
    const std::string name(reply.begin() + 5, reply.begin() + 5 + reply[4]);
    std::printf("응답 서비스 %02X, 상태 %u, 제품 이름 \"%s\"\n",
                reply[0], reply[2], name.c_str());

    // 암시적(주기) 연결: RPI 10ms, 시간 초과 배수 4 → 40ms 동안 못 받으면 끊김
    const int rpi = 10, timeout = rpi * 4;
    int lastRx = 0;
    for (int t = 0; t <= 120; t += 5) {
        // 50ms 뒤로 패킷이 끊긴다
        const bool arrives = t % rpi == 0 && t <= 50;
        if (arrives) lastRx = t;
        if (t - lastRx > timeout) {
            std::printf("%dms: %dms 동안 입력 없음 → 연결 끊김, 출력은 안전값\n",
                        t, t - lastRx);
            break;
        }
    }
}
```

```text
TCP 44818로 보낼 48바이트
명령·길이·세션: 6F 00 18 00 78 56 34 12
상태·문맥·옵션: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
CPF 항목: 00 00 00 00 0A 00 02 00 00 00 00 00 B2 00 08 00
CIP 요청: 0E 03 20 01 24 01 30 07
응답 서비스 8E, 상태 0, 제품 이름 "Demo Drive 2000"
95ms: 45ms 동안 입력 없음 → 연결 끊김, 출력은 안전값
```

- **세 겹**: 맨 앞은 EtherNet/IP의 캡슐화 머리(명령 `6F` SendRRData, 길이, 세션 핸들), 다음은 주소와 데이터 항목을 담는 공통 패킷 형식, 마지막이 CIP 요청입니다. 세션 핸들은 처음 연결할 때 RegisterSession 명령으로 받습니다
- **경로**: CIP 요청의 `20 01 24 01 30 07`은 "클래스 1, 인스턴스 1, 속성 7"을 가리키는 경로입니다. 서비스 `0E`는 속성 하나 읽기입니다
- **바이트 순서**: Modbus와 달리 EtherNet/IP는 낮은 바이트를 먼저 보냅니다. 세션 핸들 `12345678`이 `78 56 34 12`로 나갔습니다
- **응답**: 서비스 번호에 `0x80`을 더한 `8E`와 상태 0(성공), 그리고 길이가 앞에 붙은 문자열이 왔습니다. 이 응답 바이트는 설명을 위해 만든 것입니다
- **주기 연결의 감시**: 입출력 데이터는 Forward Open으로 맺은 연결 위에서 RPI(요청 패킷 간격)마다 흐릅니다. 정해진 배수(여기서는 4배, 40ms) 동안 아무것도 오지 않으면 연결이 끊긴 것으로 보고, 장비는 출력을 안전한 값으로 돌립니다. PROFINET도 같은 방식의 감시 시간을 둡니다

<Note>
실무에서는 바이트를 손으로 짜지 않고 스택을 씁니다. 오픈 소스로는 EtherNet/IP의 OpENer(장비 쪽)와 EIPScanner(C++, 스캐너 쪽), PROFINET 장비 쪽의 p-net 등이 있습니다. 일본 제조사 장비가 많은 곳에서는 CC-Link IE도 만납니다. 어떤 프로토콜이든 Wireshark에 해석기가 들어 있으므로, 통신이 안 될 때는 먼저 패킷을 떠서 보는 것이 가장 빠릅니다.
</Note>

## 정리

- PROFINET과 EtherNet/IP는 보통의 이더넷 위에서 주기 입출력 데이터와 비주기 설정·진단 메시지를 나누어 다룬다
- PROFINET은 장치 이름으로 장비를 찾고 주기 데이터를 2계층 프레임으로 보내며, EtherNet/IP는 CIP 객체(클래스, 인스턴스, 속성)를 TCP 44818과 UDP 2222로 다룬다
- 주기 연결은 정해진 시간 동안 데이터가 오지 않으면 끊긴 것으로 보고 출력을 안전한 값으로 돌린다
