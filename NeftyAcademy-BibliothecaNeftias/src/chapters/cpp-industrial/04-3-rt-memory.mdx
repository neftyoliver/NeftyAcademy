실시간 우선순위와 실시간 커널을 갖추어도, 주기 안의 코드가 스스로 늦어지면 소용이 없습니다. 그 가장 흔한 원인이 **메모리**입니다. 리눅스는 프로그램이 메모리를 잡을 때가 아니라 처음 만질 때 실제 페이지를 줍니다. 그리고 `malloc`과 `new`는 잠금을 쥐고, 때로는 운영 체제에 메모리를 더 달라고 합니다. 둘 다 언제 얼마나 걸릴지 알 수 없습니다.

## 페이지 폴트를 미리 치르기

64MB를 잡아 페이지마다 한 바이트씩 처음 만질 때와 두 번째 만질 때를 재고, 같은 일을 메모리를 고정한 뒤에 해 보았습니다. 이 책의 검사 기계에서 잰 값입니다.

```cpp norun
// 처음 만지는 메모리의 페이지 폴트와, mlockall로 그것을 미리 치르는 방법
#include <malloc.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <cstdio>
#include <cstdlib>
#include <ctime>

long faults() {
    rusage u;
    getrusage(RUSAGE_SELF, &u);
    return u.ru_minflt;
}
double ms() {
    timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec * 1e3 + t.tv_nsec / 1e6;
}
void report(const char* what, double t0, long f0) {
    std::printf("%s: %.1fms, 페이지 폴트 %ld번\n", what, ms() - t0, faults() - f0);
}
void touch(char* p, size_t n) {
    for (size_t i = 0; i < n; i += 4096) p[i] = 1;   // 페이지마다 한 바이트
}

int main() {
    const size_t n = 64 << 20;                        // 64MB
    char* a = static_cast<char*>(std::malloc(n));
    double t = ms(); long f = faults();
    touch(a, n);
    report("처음 만질 때", t, f);
    t = ms(); f = faults();
    touch(a, n);
    report("두 번째 만질 때", t, f);
    std::free(a);

    // 실시간 프로그램의 시작 부분에서 하는 일
    // 지금과 앞으로의 메모리를 모두 고정
    mlockall(MCL_CURRENT | MCL_FUTURE);
    // 풀어 준 메모리를 운영 체제에 돌려주지 않음
    mallopt(M_TRIM_THRESHOLD, -1);
    mallopt(M_MMAP_MAX, 0);                           // 큰 할당도 mmap 대신 힙에서
    t = ms(); f = faults();
    char* b = static_cast<char*>(std::malloc(n));
    report("고정한 뒤 malloc", t, f);
    t = ms(); f = faults();
    touch(b, n);
    report("고정한 뒤 처음 만질 때", t, f);
    std::free(b);
}
```

```text nocheck
처음 만질 때: 22.2ms, 페이지 폴트 16383번
두 번째 만질 때: 0.6ms, 페이지 폴트 0번
고정한 뒤 malloc: 14.1ms, 페이지 폴트 16385번
고정한 뒤 처음 만질 때: 0.4ms, 페이지 폴트 0번
```

- **처음 만지는 값**: 같은 일이 처음에는 22ms, 두 번째에는 0.6ms였습니다. 페이지(4KB) 하나를 처음 만질 때마다 커널로 들어가 실제 메모리를 마련하는 페이지 폴트가 일어났기 때문입니다. 주기 안에서 새 버퍼를 처음 만지면 이 비용이 그 주기에 떨어집니다
- **`mlockall`**: `MCL_CURRENT | MCL_FUTURE`는 지금 가진 메모리와 앞으로 잡을 메모리를 모두 물리 메모리에 고정합니다. 고정한 뒤의 `malloc`은 그 자리에서 페이지를 모두 마련했고(14ms), 그 뒤에 처음 만질 때는 폴트가 없었습니다. 비용이 사라진 것이 아니라 **시작할 때로 옮겨진** 것입니다. 고정된 메모리는 스왑으로 밀려나지도 않습니다
- **`mallopt`**: glibc의 `malloc`은 풀어 준 메모리를 운영 체제에 돌려주거나 큰 할당을 `mmap`으로 따로 받는데, 그러면 다음 할당에서 다시 폴트가 생깁니다. 두 설정으로 이것을 막아, 한 번 마련한 힙을 계속 쓰게 했습니다
- 스택도 같습니다. 실시간 스레드는 시작할 때 쓸 만큼의 스택을 미리 한 번 만져 둡니다

## 숨은 할당 찾기

메모리를 고정해도 주기 안에서 `new`를 부르면 할당자의 잠금을 다툴 수 있고, 할당자가 새 메모리를 마련할 때 얼마나 걸릴지 모릅니다. 그래서 실시간 구간에서는 힙 할당을 아예 하지 않는 것이 원칙입니다. 문제는 C++ 코드에서 할당이 잘 보이지 않는다는 것입니다. `operator new`를 바꿔 끼워 실시간 구간 안의 할당을 세어 보았습니다.

```cpp
// 실시간 구간 안에서 일어나는 힙 할당을 센다: operator new를 바꿔 끼운다
#include <atomic>
#include <cstdio>
#include <cstdlib>
#include <functional>
#include <map>
#include <new>
#include <string>
#include <vector>

thread_local bool inRt = false;                  // 이 스레드가 지금 실시간 구간인가
std::atomic<int> rtAllocs{0};

// noinline: 펼쳐 넣으면 GCC가 new로 받은 것을 free한다고 잘못 경고한다
[[gnu::noinline]] void* operator new(std::size_t n) {
    // 실제 제품에서는 여기서 기록하거나 멈춘다
    if (inRt) ++rtAllocs;
    if (void* p = std::malloc(n ? n : 1)) return p;
    throw std::bad_alloc();
}
[[gnu::noinline]] void operator delete(void* p) noexcept { std::free(p); }
[[gnu::noinline]] void operator delete(void* p, std::size_t) noexcept {
    std::free(p);
}

template <class F> void check(const char* what, F&& body) {
    rtAllocs = 0;
    inRt = true;
    body();
    inRt = false;
    std::printf("%s: 할당 %d번\n", what, rtAllocs.load());
}

int main() {
    std::vector<double> samples;
    check("vector에 100개 push_back", [&] {
        for (int i = 0; i < 100; ++i) samples.push_back(i);
    });
    std::vector<double> reserved;
    reserved.reserve(100);                       // 실시간 구간 밖에서 미리
    check("미리 reserve한 vector에 100개", [&] {
        for (int i = 0; i < 100; ++i) reserved.push_back(i);
    });
    check("긴 문자열 만들기", [&] {
        std::string msg = "oven temperature is now " + std::to_string(181);
        (void)msg;
    });
    check("char 배열에 snprintf", [&] {
        char msg[64];
        std::snprintf(msg, sizeof msg, "oven temperature is now %d", 181);
    });
    std::function<double()> handler;
    check("큰 캡처를 std::function에 담기", [&] {
        double a[8] = {};
        handler = [a] { return a[0]; };
    });
    std::map<int, double> lastValues;
    check("map에 새 키 3개", [&] {
        for (int k = 0; k < 3; ++k) lastValues[k] = 1.0;
    });
    check("map의 있는 키 3개 고치기", [&] {
        for (int k = 0; k < 3; ++k) lastValues[k] = 2.0;
    });
}
```

```text
vector에 100개 push_back: 할당 8번
미리 reserve한 vector에 100개: 할당 0번
긴 문자열 만들기: 할당 1번
char 배열에 snprintf: 할당 0번
큰 캡처를 std::function에 담기: 할당 1번
map에 새 키 3개: 할당 3번
map의 있는 키 3개 고치기: 할당 0번
```

- `vector`는 커질 때마다 새로 할당합니다. 실시간 구간 밖에서 `reserve`로 미리 잡아 두면 0번입니다
- 짧은 문자열은 객체 안에 담기지만 긴 문자열은 힙을 씁니다. 실시간 구간의 메시지는 고정 크기 배열에 `snprintf`로 씁니다
- `std::function`은 담는 함수 객체가 크면 힙에 둡니다. `map`은 새 키마다 노드를 하나씩 할당하지만, 있는 키의 값을 고치는 것은 할당하지 않습니다

이 검사기를 시험 빌드에 넣어 두면, 누군가 주기 코드에 할당을 끼워 넣는 순간 알 수 있습니다. 실제 제품에서는 세는 대신 기록을 남기거나 시험 중에 멈추게 합니다.

<Note>
같은 원리로 실시간 구간에서는 파일과 콘솔 입출력, 블로킹되는 시스템 호출, 다른 스레드와 다투는 잠금, 예외 던지기도 피합니다. 할당이 꼭 필요한 자료 구조는 시작할 때 크기를 정한 풀이나 고정 용량 컨테이너(C++26의 `std::inplace_vector` 같은)로 바꿉니다. 로그는 주기 안에서 고정 크기 큐에 넣기만 하고, 쓰기는 보통 스레드가 맡습니다([「주기 작업」](#/read/cpp-industrial/rt-cyclic)).
</Note>

## 정리

- 처음 만지는 페이지마다 폴트가 생기므로, 실시간 프로그램은 시작할 때 mlockall로 메모리를 고정하고 쓸 메모리와 스택을 미리 만져 둔다
- glibc의 malloc은 mallopt로 메모리를 운영 체제에 돌려주지 않게 조정하고, 실시간 구간에서는 힙 할당을 하지 않는다
- 숨은 할당은 operator new를 바꿔 끼워 찾고, 미리 잡은 버퍼, reserve, 고정 크기 배열로 없앤다
