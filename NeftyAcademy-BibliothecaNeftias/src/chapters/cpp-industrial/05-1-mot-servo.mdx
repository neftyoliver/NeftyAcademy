장비의 축(컨베이어의 위치, 로봇 관절, 공작 기계의 테이블)을 정확히 움직이는 것은 **서보 시스템**입니다. 서보 모터, 모터 축의 각도를 재는 **엔코더**, 그리고 모터에 전류를 흘려 넣는 **서보 드라이브**(서보 앰프)로 이루어집니다. PC나 PLC의 프로그램은 드라이브에게 "어디로" 또는 "얼마나 빠르게"를 알려 주고, 실제로 전류를 조절하는 일은 드라이브가 합니다.

## 겹친 제어 루프

드라이브 안에는 제어 루프가 양파처럼 겹쳐 있습니다. 가장 안쪽의 **전류(토크) 루프**가 가장 빠르게 돌며 모터 전류를 맞추고, 그 바깥의 **속도 루프**가 속도를, 가장 바깥의 **위치 루프**가 위치를 맞춥니다. 바깥 루프는 안쪽 루프에 목표를 내려 주는 구조이고, 안쪽일수록 빨라야 합니다. 어느 루프까지를 드라이브가 닫고 어디부터를 마스터가 맡는지가 **운전 모드**입니다.

| 모드 | 마스터가 매 주기 보내는 것 | 드라이브가 하는 일 |
| --- | --- | --- |
| 주기 동기 위치(CSP) | 목표 위치 | 위치, 속도, 전류 루프 |
| 주기 동기 속도(CSV) | 목표 속도 | 속도, 전류 루프 |
| 주기 동기 토크(CST) | 목표 토크 | 전류 루프 |
| 프로필 위치(PP) | 가끔 목적지 하나 | 궤적까지 스스로 만든다 |

여러 축을 맞춰 움직이는 기계는 대개 CSP를 씁니다. 마스터가 모든 축의 궤적을 계산해 [「EtherCAT」](#/read/cpp-industrial/fb-ethercat) 같은 버스로 매 주기 목표 위치를 보내는 방식입니다.

## 드라이브를 깨우기

CANopen과 EtherCAT의 서보 드라이브는 거의 모두 CiA 402 프로필을 따릅니다. 드라이브는 전원을 넣는다고 바로 움직이지 않고, 정해진 상태들을 차례로 거쳐야 모터에 힘이 들어갑니다. 마스터는 매 주기 **상태 워드**(6041)를 읽어 지금 상태를 알아내고, 다음 상태로 가는 **제어 워드**(6040)를 씁니다. 그 상태 기계를 마스터 쪽 코드로 짜고, 드라이브를 흉내 내어 돌려 보았습니다.

```cpp
// CiA 402 상태 기계: 상태 워드를 읽고 제어 워드를 골라 운전 가능 상태로 만든다
#include <cstdint>
#include <cstdio>

enum class St { NotReady, SwitchOnDisabled, ReadyToSwitchOn, SwitchedOn,
                OperationEnabled, QuickStop, Fault };
const char* name(St s) {
    static const char* n[] = {"켜지는 중", "켜기 금지", "켜기 준비", "켜짐",
                              "운전 가능", "급정지", "고장"};
    return n[int(s)];
}

// 표준이 정한 비트 모양으로 상태를 읽는다
St decode(uint16_t sw) {
    if ((sw & 0x4F) == 0x00) return St::NotReady;
    if ((sw & 0x4F) == 0x40) return St::SwitchOnDisabled;
    if ((sw & 0x6F) == 0x21) return St::ReadyToSwitchOn;
    if ((sw & 0x6F) == 0x23) return St::SwitchedOn;
    if ((sw & 0x6F) == 0x27) return St::OperationEnabled;
    if ((sw & 0x6F) == 0x07) return St::QuickStop;
    return St::Fault;                            // 0x08, 0x0F
}

// 마스터 쪽: 운전 가능까지 한 걸음씩. 고장 리셋은 작업자가 확인했을 때만
uint16_t nextControlword(St s, bool operatorReset) {
    switch (s) {
    case St::SwitchOnDisabled: return 0x0006;    // Shutdown
    case St::ReadyToSwitchOn:  return 0x0007;    // Switch on
    case St::SwitchedOn:       return 0x000F;    // Enable operation
    case St::OperationEnabled: return 0x000F;    // 그대로 유지
    // 비트 7 상승
    case St::Fault:            return operatorReset ? 0x0080 : 0x0000;
    default:                   return 0x0000;
    }
}

class Drive {                                    // 드라이브 쪽을 흉내 낸다
    St s = St::NotReady;
    uint16_t lastCw = 0;
public:
    bool injectFault = false;
    uint16_t statusword() const {
        static const uint16_t sw[] = {0x0000, 0x0040, 0x0021, 0x0023,
                                      0x0027, 0x0007, 0x0008};
        return sw[int(s)];
    }
    void cycle(uint16_t cw) {
        const bool resetEdge = (cw & 0x80) && !(lastCw & 0x80);
        if (injectFault && s == St::OperationEnabled) {
            s = St::Fault;
            injectFault = false;
        } else if (s == St::NotReady) {
            s = St::SwitchOnDisabled;            // 자체 점검이 끝났다
        } else if (s == St::Fault) {
            if (resetEdge) s = St::SwitchOnDisabled;
        } else if ((cw & 0x87) == 0x06 && s == St::SwitchOnDisabled) {
            s = St::ReadyToSwitchOn;
        }
        else if ((cw & 0x8F) == 0x07 && s == St::ReadyToSwitchOn)
            s = St::SwitchedOn;
        else if ((cw & 0x8F) == 0x0F && s == St::SwitchedOn)
            s = St::OperationEnabled;
        lastCw = cw;
    }
};

int main() {
    // 엔코더 2^20 펄스/회전, 감속기 5:1, 볼스크루 리드 10mm → 1mm는 몇 펄스인가
    const double countsPerMm = (1 << 20) * 5.0 / 10.0;
    std::printf("1mm = %.0f 펄스, 1 펄스 = %.2fnm\n",
                countsPerMm, 1e6 / countsPerMm);

    Drive drive;
    // 버스 주기마다: 읽고 → 고르고 → 쓴다
    for (int cycle = 0; cycle < 14; ++cycle) {
        // 따라가기 오차가 커졌다고 치자
        if (cycle == 6) drive.injectFault = true;
        const uint16_t sw = drive.statusword();
        const St s = decode(sw);
        // 9주기에 작업자가 확인
        const uint16_t cw = nextControlword(s, cycle == 9);
        std::printf("주기 %2d: 상태 워드 %04X(%s) → 제어 워드 %04X\n",
                    cycle, sw, name(s), cw);
        drive.cycle(cw);
    }
}
```

주기  0: 상태 워드 0000(켜지는 중) → 제어 워드 0000
주기  1: 상태 워드 0040(켜기 금지) → 제어 워드 0006
주기  2: 상태 워드 0021(켜기 준비) → 제어 워드 0007
주기  3: 상태 워드 0023(켜짐) → 제어 워드 000F
주기  4: 상태 워드 0027(운전 가능) → 제어 워드 000F
주기  5: 상태 워드 0027(운전 가능) → 제어 워드 000F
주기  6: 상태 워드 0027(운전 가능) → 제어 워드 000F
주기  7: 상태 워드 0008(고장) → 제어 워드 0000
주기  8: 상태 워드 0008(고장) → 제어 워드 0000
주기  9: 상태 워드 0008(고장) → 제어 워드 0080
주기 10: 상태 워드 0040(켜기 금지) → 제어 워드 0006
주기 11: 상태 워드 0021(켜기 준비) → 제어 워드 0007

- **단위 환산**: 2^20 펄스 엔코더에 5:1 감속기와 리드 10mm 볼스크루를 달면 1mm가 524288펄스, 한 펄스가 약 2nm입니다. 프로그램 안에서는 mm 같은 사용자 단위로 생각하고, 버스로 보낼 때만 펄스로 바꿉니다
- **상태 워드는 비트 모양으로 읽는다**: 상태 워드에는 상태 말고도 목표 도달, 경고 같은 비트가 섞여 있으므로, 표준이 정한 마스크(`0x4F`, `0x6F`)를 씌워 비교합니다. 앞 장에서 본 `0637`도 `0x6F`를 씌우면 `0x27`, 곧 운전 가능입니다
- **한 걸음씩**: Shutdown(`0006`) → Switch on(`0007`) → Enable operation(`000F`) 순서로 한 주기에 한 단계씩 갑니다. 단계를 건너뛰는 제어 워드는 드라이브가 무시합니다
- **고장 리셋은 사람이 확인한 뒤에**: 고장이 나면 마스터는 전압을 끄는 `0000`을 보내며 기다리고, 작업자가 원인을 보고 리셋을 눌렀을 때(9주기) 비트 7을 올려 리셋했습니다. 고장이 나자마자 자동으로 리셋하는 코드는 같은 고장을 끝없이 되풀이하게 만들고, 사람이 원인을 볼 기회를 없앱니다

<Note>
드라이브가 가장 흔히 내는 고장은 **따라가기 오차**(following error)입니다. 목표 위치와 실제 위치의 차이가 정한 값을 넘으면, 축이 무언가에 걸렸거나 궤적이 모터의 능력을 넘었다고 보고 멈춥니다. 그리고 상태 기계와는 별도로, 사람의 안전을 위한 정지는 드라이브의 안전 토크 차단(STO) 입력이 맡습니다([「안전과 인증」](#/read/cpp-industrial/land-safety)). 소프트웨어가 어떤 제어 워드를 보내든 STO가 걸리면 모터에 힘이 들어가지 않습니다.
</Note>

## 정리

- 서보 시스템은 모터, 엔코더, 드라이브로 되며, 드라이브 안에는 전류, 속도, 위치 루프가 안쪽일수록 빠르게 겹쳐 있다
- 운전 모드는 어느 루프까지 드라이브가 닫는지를 정하며, 여러 축을 맞추는 기계는 마스터가 매 주기 목표 위치를 보내는 CSP를 많이 쓴다
- CiA 402 드라이브는 상태 워드를 마스크로 읽고 제어 워드로 한 단계씩 운전 가능까지 올리며, 고장 리셋은 사람이 확인한 뒤에 한다
