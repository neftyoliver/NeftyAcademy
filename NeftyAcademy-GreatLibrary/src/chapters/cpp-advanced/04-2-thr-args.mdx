스레드에 넘긴 인자는 복사된다는 것, 원본을 고치게 하려면 `std::ref`를 쓴다는 것은 [맛보기](#/read/cpp-stl/conc-thread)에서 봤습니다. 스레드의 버그는 절반이 여기서 나옵니다. 인자가 **언제, 어느 스레드에서** 복사되고 바뀌는지, 그리고 그 사이에 원본이 살아 있는지입니다.

## 인자는 두 번 건너간다

스레드의 생성자는 인자를 **부른 스레드에서** 스레드 전용의 보관소로 복사하거나 옮깁니다. 새 스레드는 그 보관소의 것을 **우측값으로** 함수에 넘깁니다.

```cpp
#include <functional>
#include <print>
#include <thread>
#include <utility>

std::thread::id main_id;

const char* where()
{
    return std::this_thread::get_id() == main_id ? "부른 스레드" : "새 스레드";
}

struct Tracer {
    Tracer() = default;
    Tracer(const Tracer&) { std::println("  복사 ({})", where()); }
    Tracer(Tracer&&) noexcept { std::println("  이동 ({})", where()); }
};

void by_value(Tracer) {}
void by_const_ref(const Tracer&) {}

int main()
{
    main_id = std::this_thread::get_id();
    Tracer t;
    std::println("1. 값으로 받는 함수에 좌측값");
    { std::jthread worker(by_value, t); }
    std::println("2. const& 로 받는 함수에 좌측값");
    { std::jthread worker(by_const_ref, t); }
    std::println("3. const& 로 받는 함수에 std::cref");
    { std::jthread worker(by_const_ref, std::cref(t)); }
    std::println("4. 값으로 받는 함수에 std::move");
    { std::jthread worker(by_value, std::move(t)); }
}
```

```text
1. 값으로 받는 함수에 좌측값
  복사 (부른 스레드)
  이동 (새 스레드)
2. const& 로 받는 함수에 좌측값
  복사 (부른 스레드)
3. const& 로 받는 함수에 std::cref
4. 값으로 받는 함수에 std::move
  이동 (부른 스레드)
  이동 (새 스레드)
```

| 눈여겨볼 것 | 뜻 |
| --- | --- |
| 복사는 부른 스레드에서 끝난다 | 생성자가 돌아온 뒤에는 원본이 사라져도 된다. 복사하다 난 예외도 부른 쪽에서 난다 |
| 2번: `const&`로 받아도 복사된다 | 함수는 **보관소의 사본**을 가리킨다. 그 뒤에 원본을 바꿔도 스레드는 보지 못한다 |
| 3번: `std::cref`는 복사하지 않는다 | 원본이 스레드보다 오래 산다는 것을 **내가** 보증해야 한다 |
| 4번: 다 쓴 것은 `std::move` | 큰 객체를 넘길 때 복사가 이동이 된다 |

## 참조로 받는 함수

`const`가 아닌 참조로 받는 함수에 `std::ref` 없이 넘기면 컴파일이 되지 않습니다.

```cpp nocheck
void bump(int& n) { ++n; }

int n = 0;
std::jthread worker(bump, n);
```

```text
error: static assertion failed: std::jthread arguments must be invocable
       after conversion to rvalues
```

보관소의 값은 우측값으로 넘어가고, 우측값은 `int&`에 [묶이지 않기](#/read/cpp-advanced/mv-categories) 때문입니다. 고쳐진 값이 아무도 보지 못하는 사본에 쓰이는 일을 타입이 막아 줍니다. `std::ref(n)`이라고 적으면 되지만, 그 순간부터 `n`의 수명은 내 책임입니다. 결과를 받아 오려는 것이면 [`future`](#/read/cpp-advanced/asy-future)가 더 안전합니다.

## 변환은 새 스레드에서 일어난다

함수가 받는 타입과 넘긴 타입이 다르면 변환이 필요합니다. 보관소에는 **넘긴 타입 그대로** 들어가고, 변환은 새 스레드가 함수를 부를 때 합니다.

```cpp
#include <functional>
#include <memory>
#include <print>
#include <stop_token>
#include <string>
#include <thread>
#include <utility>

std::thread::id main_id;

const char* where()
{
    return std::this_thread::get_id() == main_id ? "부른 스레드" : "새 스레드";
}

struct Name {
    std::string text;
    Name(const char* raw) : text(raw) { std::println("  변환한 곳: {}", where()); }
};

void greet(const Name& name) { std::println("  안녕, {}", name.text); }

class Counter {
public:
    void add(int amount) { total_ += amount; }
    void run(std::stop_token stop)
    {
        while (!stop.stop_requested()) std::this_thread::yield();
        std::println("  run 이 멈춤 신호를 봤다");
    }
    int total() const { return total_; }

private:
    int total_ = 0;
};

void consume(std::unique_ptr<int> value) { std::println("  받은 값 {}", *value); }

int main()
{
    main_id = std::this_thread::get_id();

    char buffer[] = "kim";
    std::println("1. 글자 배열을 그대로 넘긴다");
    { std::jthread worker(greet, buffer); }
    std::println("2. 넘기기 전에 바꾼다");
    { std::jthread worker(greet, Name(buffer)); }

    std::println("3. 멤버 함수");
    Counter counter;
    { std::jthread worker(&Counter::add, &counter, 5); }
    std::println("  합계 {}", counter.total());
    { std::jthread worker(std::bind_front(&Counter::run, &counter)); }

    std::println("4. 소유권을 넘긴다");
    auto value = std::make_unique<int>(42);
    { std::jthread worker(consume, std::move(value)); }
    std::println("  넘긴 뒤 비었다 {}", value == nullptr);
}
```

```text
1. 글자 배열을 그대로 넘긴다
  변환한 곳: 새 스레드
  안녕, kim
2. 넘기기 전에 바꾼다
  변환한 곳: 부른 스레드
  안녕, kim
3. 멤버 함수
  합계 5
  run 이 멈춤 신호를 봤다
4. 소유권을 넘긴다
  받은 값 42
  넘긴 뒤 비었다 true
```

1번에서 보관소에 들어간 것은 `buffer`를 가리키는 **포인터**입니다. 글자를 읽어 `Name`을 만드는 일은 새 스레드가 나중에 합니다. 여기서는 `jthread`가 바로 `join`하므로 탈이 없지만, 스레드가 `buffer`보다 오래 살면 사라진 배열을 읽습니다. 지역 `char` 배열, `string_view`, `span`을 넘길 때마다 생기는 일이고, 2번처럼 **넘기기 전에 주인이 있는 타입으로 바꾸면** 사라집니다.

3번의 `&counter`도 포인터입니다. 멤버 함수를 스레드로 돌린다는 것은 그 객체를 빌려준다는 뜻이므로, 객체가 스레드보다 오래 살아야 합니다. [스레드를 객체의 마지막 멤버로 두면](#/read/cpp-advanced/res-ownership) 그 순서가 저절로 맞습니다. `stop_token`을 받는 멤버 함수는 `std::bind_front`나 람다로 감쌉니다. `jthread`는 토큰을 **첫 인자**로 넣는데, 멤버 함수의 첫 인자는 객체이기 때문입니다.

4번은 가장 깨끗한 꼴입니다. [`unique_ptr`를 옮겨 넘기면](#/read/cpp-advanced/sp-passing) 그 객체의 주인이 새 스레드가 되고, 부른 쪽에는 건드릴 것이 남지 않습니다.

## 람다의 캡처가 곧 인자다

람다를 넘길 때는 캡처가 같은 질문을 받습니다. 값으로 잡은 것은 람다와 함께 보관소로 건너가고, 참조로 잡은 것은 빌린 것입니다.

```cpp
#include <print>
#include <thread>
#include <vector>

int main()
{
    std::vector<int> squares(4);            // 스레드들보다 먼저 선언한다
    {
        std::vector<std::jthread> workers;
        for (int i = 0; i < 4; ++i) {
            // i 는 값으로 잡는다(돌 때마다 바뀐다)
            // 결과를 쓸 벡터는 참조로 잡는다(끝까지 살아 있다)
            workers.emplace_back([i, &squares] { squares[i] = i * i; });
        }
    }   // 여기서 모두 join 된다
    std::println("{} {} {} {}", squares[0], squares[1], squares[2], squares[3]);
}
```

```text
0 1 4 9
```

| 캡처 | 써도 되는 때 |
| --- | --- |
| `[x]` 값 | 언제나. 기본으로 삼는다 |
| `[p = std::move(p)]` 옮겨서 | 복사가 안 되거나 비싼 것 |
| `[&x]` 참조 | `x`가 스레드 객체보다 **먼저 선언되어** 나중에 사라질 때만 |
| `[&]`, `[=]` 한꺼번에 | 쓰지 않는다. 무엇을 빌렸는지 보이지 않는다. `[=]`는 `this`를 포인터로 잡는다 |

위 예제에서 `[&i]`라고 쓰면 스레드가 `i`를 읽을 때는 이미 다음 값으로 바뀌었거나 반복문이 끝나 사라진 뒤입니다. 스레드마다 **자기 칸에만** 쓰게 한 것도 눈여겨봅니다. 서로 다른 원소에 쓰는 것은 경합이 아닙니다.

<Note kind="warn">
`detach()`한 스레드에는 참조 캡처도, `std::ref`도, 포인터 인자도 쓸 수 없습니다. 빌려준 것이 스레드보다 오래 산다고 말해 줄 것이 아무것도 없기 때문입니다. `detach`를 써야 한다면 스레드가 쓰는 것을 모두 값이나 `shared_ptr`로 **가지고 가게** 합니다.
</Note>

## 정리

- 인자는 부른 스레드에서 보관소로 복사되고, 새 스레드에서 우측값으로 함수에 넘어간다. `const&`로 받아도 사본이다
- 타입 변환은 새 스레드에서 일어난다. 포인터나 `string_view`를 넘기지 말고, 넘기기 전에 주인이 있는 타입으로 바꾼다
- 참조로 넘기거나 잡은 것은 스레드 객체보다 먼저 선언한다. 옮겨서 넘기면 수명을 따질 일이 없다
