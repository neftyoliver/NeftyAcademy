원자적 변수로 깃발을 세울 수는 있었지만, 그 깃발이 설 때까지 **기다리는** 방법은 돌면서 확인하는 것뿐이었습니다. 그래서 기다려야 하면 [뮤텍스와 조건 변수](#/read/cpp-advanced/sync-condvar)를 가져왔습니다. C++20은 원자적 변수에 기다림을 넣었습니다. [뮤텍스가 커널에 맡기던 바로 그 일](#/read/cpp-advanced/sync-mutex)을 직접 쓸 수 있게 한 것입니다.

## wait와 notify

| 함수 | 하는 일 |
| --- | --- |
| `x.wait(old)` | `x`가 `old`와 **다른 값이 될 때까지** 잔다. 이미 다르면 바로 돌아온다 |
| `x.notify_one()` | `x`에서 자고 있는 스레드 하나를 깨운다 |
| `x.notify_all()` | 모두 깨운다 |

```cpp
#include <atomic>
#include <mutex>
#include <print>
#include <thread>
#include <vector>

// 4바이트짜리 뮤텍스. 0 = 풀림, 1 = 잠김, 2 = 잠김(기다리는 스레드가 있을 수 있다)
class WaitMutex {
public:
    void lock()
    {
        int expected = 0;
        // 비어 있으면 끝
        if (state_.compare_exchange_strong(expected, 1)) return;
        // 2 로 바꿔 "기다리는 쪽이 있다"고 적는다.
        // 바꾸기 전의 값이 0 이었으면 내가 잠근 것이다. 아니면 2 인 동안 잔다
        while (state_.exchange(2) != 0) state_.wait(2);
    }

    void unlock()
    {
        // 기다리는 쪽이 있을 수 있을 때만 깨운다
        if (state_.exchange(0) == 2) state_.notify_one();
    }

private:
    std::atomic<int> state_{0};
};

int main()
{
    // 1. 값이 바뀔 때까지 잔다
    std::atomic<int> stage = 0;
    int seen = -1;
    {
        std::jthread waiter([&] {
            stage.wait(0);              // stage 가 0 이 아니게 될 때까지 잔다
            seen = stage.load();
        });
        stage.store(7);
        stage.notify_one();             // 바꾼 "뒤에" 깨운다
    }
    std::println("기다린 쪽이 본 값 {}", seen);

    // 2. 그것으로 만든 뮤텍스
    WaitMutex guard;
    long counter = 0;
    {
        std::vector<std::jthread> workers;
        for (int i = 0; i < 4; ++i) {
            workers.emplace_back([&] {
                for (int n = 0; n < 100'000; ++n) {
                    std::lock_guard lock(guard);    // lock 과 unlock 만 있으면 된다
                    ++counter;
                }
            });
        }
    }
    std::println("{} / 크기 {} (std::mutex {})", counter, sizeof(WaitMutex),
                 sizeof(std::mutex));
}
```

```text
기다린 쪽이 본 값 7
400000 / 크기 4 (std::mutex 40)
```

## 놓치지 않는 까닭

조건 변수에서는 [조건을 보고 잠들기까지의 틈](#/read/cpp-advanced/sync-condvar)에 알림이 지나가 버릴 수 있었고, 그 틈을 뮤텍스로 막았습니다. `wait(old)`에는 뮤텍스가 없는데도 그 문제가 없습니다. **"값이 아직 `old`인가"를 확인하는 일과 잠드는 일이 한 동작**이기 때문입니다. 예제의 1번에서 `store(7)`과 `notify_one()`이 `wait(0)`보다 먼저 일어나도 됩니다. 그때는 값이 이미 0이 아니므로 `wait`가 잠들지 않고 돌아옵니다.

지킬 것은 하나입니다. **값을 바꾼 뒤에 깨웁니다.** 값을 그대로 둔 채 `notify`만 하면 깨어난 스레드는 "아직 `old`"임을 보고 다시 잡니다. `wait`는 까닭 없이 깨어나도 값을 다시 확인하므로, 돌아왔다면 값은 정말로 달랐던 것입니다.

| | 조건 변수 | 원자적 변수의 `wait` |
| --- | --- | --- |
| 기다리는 조건 | 무엇이든 (큐가 비지 않았다, 둘 다 준비됐다) | 값 하나가 `old`와 다르다 |
| 더 드는 것 | 뮤텍스 40바이트, 조건 변수 48바이트 | 없다. 그 변수뿐이다 |
| 시간을 정해 기다리기 | `wait_for`, `wait_until` | 없다 |
| 멈춤 신호에 깨어나기 | [`condition_variable_any`](#/read/cpp-advanced/thr-jthread) | 없다 |

값이 A에서 B로 바뀌었다가 **A로 돌아오면** 그사이에 깨어나지 못한 스레드는 변화를 보지 못할 수 있습니다. [ABA](#/read/cpp-advanced/atm-aba)와 같은 일입니다. 깃발보다는 올라가기만 하는 번호나 상태를 기다리는 데 씁니다.

## 4바이트 뮤텍스

`WaitMutex`는 리눅스의 뮤텍스가 하는 일을 그대로 옮긴 것입니다.

| 상태 | 뜻 | 잠글 때 | 풀 때 |
| --- | --- | --- | --- |
| 0 | 풀려 있다 | CAS로 1로 바꾸고 끝. 커널에 가지 않는다 | |
| 1 | 잠겨 있고 기다리는 스레드가 없다 | 2로 바꾸고 잔다 | 0으로 바꾸고 끝. 커널에 가지 않는다 |
| 2 | 잠겨 있고 기다리는 스레드가 있을 수 있다 | 잔다 | 0으로 바꾸고 하나를 깨운다 |

상태가 셋인 까닭이 요점입니다. 다투지 않을 때는 잠그기도 풀기도 원자적 연산 한 번이고, **깨우는 호출은 누가 기다릴 때만** 합니다.

| 잠그고 풀기 한 번 | 스레드 1개 | 2개 | 4개 (코어 2개) |
| --- | --- | --- | --- |
| `WaitMutex` | 18 ns | 33 ns | 54 ns |
| `std::mutex` | 21 ns | 83 ns | 50 ns |

x86-64 서버 VM, GCC 14 `-O2`에서 잰 값입니다. 스무 줄짜리가 표준 뮤텍스와 같은 자리에 섭니다. 다툴 때의 수치는 돌릴 때마다 크게 흔들리므로 어느 쪽이 빠르다고 읽을 것은 아닙니다. 그렇다고 이것으로 `std::mutex`를 바꿔 쓸 까닭은 없습니다. 시간을 정해 기다리기, ThreadSanitizer와 디버거의 지원, 우선순위 상속 같은 것이 없습니다. 쓸모는 크기에 있습니다. 객체 수백만 개에 잠금을 하나씩 둬야 할 때 40바이트와 4바이트의 차이입니다.

## 기다림의 값

| 한 스레드에서 다른 스레드로 차례를 넘긴다 | GCC 14 | Clang 20 |
| --- | --- | --- |
| `std::atomic<int>`의 `wait`와 `notify_one` | 0.5~1.0 µs | 0.06 µs |
| [뮤텍스와 조건 변수](#/read/cpp-advanced/sync-semaphore) | 12 µs | 12 µs |

두 구현 모두 `wait`가 곧바로 잠들지 않고 **먼저 잠깐 돌며** 값이 바뀌는지 봅니다. 상대가 바로 답하는 이 시험에서는 잠들 일이 거의 없어 빠르게 나옵니다. libc++가 더 오래 돌며 기다립니다. [세마포어와 래치](#/read/cpp-advanced/sync-semaphore)가 조건 변수보다 빨랐던 것도, 그것들이 이 `wait` 위에 만들어져 있기 때문입니다. 상대가 오래 걸리면 결국 커널에서 잠들고 깨우는 값을 치릅니다.

<Note>
리눅스의 커널이 기다리게 해 주는 것은 4바이트 정수입니다. `std::atomic<int>`는 그 변수에서 바로 기다립니다. `std::atomic<long>`이나 `std::atomic<bool>`처럼 크기가 다른 타입은 라이브러리가 따로 둔 기다림 자리를 주소로 찾아 씁니다. 재어 본 값은 같았지만, 자주 기다리는 변수라면 `int`로 두는 편이 군더더기가 없습니다.
</Note>

## 정리

- `x.wait(old)`는 값이 `old`와 달라질 때까지 잔다. 확인과 잠들기가 한 동작이라 알림을 놓치지 않는다
- 깨우는 쪽은 값을 바꾼 뒤에 `notify`한다. 조건이 값 하나로 적히지 않으면 조건 변수를 쓴다
- 세마포어, 래치, 뮤텍스가 모두 이 위에 만들어진다. 직접 쓸 일은 크기나 속도가 정말 아쉬울 때다
