export const summary = 'noexcept 한 단어의 값, 그것을 묻는 연산, 조용히 사라지는 길, 표준 타입 가운데 아닌 것';

`std::vector`가 이동 생성자에 `noexcept`가 있을 때만 원소를 옮긴다는 것은 [「noexcept」](#/read/cpp-syntax/exc-noexcept)에서 봤습니다. 여기서는 그 차이가 얼마인지, 어느 연산이 그것을 묻는지, 그리고 **적은 줄 알았던 `noexcept`가 사라지는 길**을 봅니다.

## 한 단어의 값

```cpp
#include <print>
#include <type_traits>
#include <utility>
#include <vector>

struct Counts {
    int copies = 0;
    int moves = 0;
};

template <bool Promise>
struct Frame {
    static inline Counts counts;
    std::vector<unsigned char> pixels;

    Frame() : pixels(1024) {}
    Frame(const Frame& other) : pixels(other.pixels) { ++counts.copies; }
    Frame(Frame&& other) noexcept(Promise) : pixels(std::move(other.pixels))
    {
        ++counts.moves;
    }
};

template <typename T>
void fill()
{
    std::vector<T> frames;
    for (int i = 0; i < 1000; ++i) frames.push_back(T());
    std::println("noexcept {:<5} 복사 {:>4}번, 이동 {:>4}번",
                 std::is_nothrow_move_constructible_v<T>, T::counts.copies,
                 T::counts.moves);
}

int main()
{
    fill<Frame<false>>();
    fill<Frame<true>>();
}
```

```text
noexcept false 복사 1023번, 이동 1000번
noexcept true  복사    0번, 이동 2023번
```

`push_back`에 넘긴 임시 객체는 어느 쪽이든 이동됩니다(1000번). 갈리는 것은 **용량이 차서 새 메모리로 옮겨 갈 때**입니다. 용량이 1, 2, 4, …, 512에서 찰 때마다 있던 원소를 모두 옮기므로 1023번이고, `noexcept`가 없으면 그것이 전부 복사입니다. libstdc++와 libc++에서 횟수가 같습니다.

| 16 KB짜리 원소 10,000개를 `push_back` | 복사 | 이동 | 걸린 시간 |
| --- | --- | --- | --- |
| 이동 생성자에 `noexcept` 없음 | 16,383번 | 10,000번 | 160 ms |
| `noexcept` 있음 | 0번 | 26,383번 | 75 ms |

x86-64 서버 VM, GCC 14 `-O2`에서 잰 값입니다. 복사 한 번이 16 KB를 새로 할당해 베끼는 일이므로 원소가 클수록 벌어집니다.

## 어느 연산이 묻는가

| `std::vector`의 연산 | 원소를 옮기는 방법 |
| --- | --- |
| 용량을 넘는 `push_back`·`emplace_back`, `reserve`, `resize`, `shrink_to_fit` | `noexcept`면 이동, 아니면 복사 |
| 재할당 없는 `insert`, `erase` | 묻지 않고 이동 대입 |
| `std::sort`, `std::rotate` 같은 알고리즘 | 묻지 않고 이동 |

`noexcept`가 없는 타입으로 찍어 확인한 결과입니다. 윗줄의 연산은 "실패하면 아무 일도 없었던 것과 같다"는 [강한 보장](#/read/cpp-syntax/exc-safety)을 약속합니다. 옮기다가 예외가 나면 절반은 새 메모리에, 절반은 옛 메모리에 있어 되돌릴 수 없으므로, 던질 수 있는 이동은 쓰지 못합니다. 아랫줄의 연산은 그 약속을 하지 않으므로 묻지 않습니다.

그 판단을 해 주는 것이 `std::move_if_noexcept`입니다. 이동 생성자가 `noexcept`이면 `T&&`를, 아니면 `const T&`를 돌려줍니다.

```cpp
// 새 메모리로 옮긴다. 도중에 예외가 나면 만든 것을 지우고 다시 던진다.
// 그때 원본은 그대로 남아 있다
template <typename T>
T* relocate(T* first, T* last, T* target)
{
    T* out = target;
    try {
        for (; first != last; ++first, ++out)
            std::construct_at(out, std::move_if_noexcept(*first));
    } catch (...) {
        std::destroy(target, out);
        throw;
    }
    return out;
}
```

복사로 옮기던 중이면 원본이 멀쩡하므로 `catch`에서 되돌릴 수 있습니다. 이동이었다면 `noexcept`이므로 `catch`에 올 일이 없습니다. 벡터처럼 원소를 한 덩어리에 담는 컨테이너를 직접 만들 때 쓰는 꼴입니다.

## 조용히 사라지는 길

컴파일러가 만들어 주는 이동 생성자는 **모든 멤버의 이동이 `noexcept`일 때만** `noexcept`입니다. 그리고 [어떤 선언은 이동 생성자를 아예 없앱니다](#/read/cpp-syntax/sm-rules).

```cpp
#include <deque>
#include <print>
#include <type_traits>
#include <utility>

int copies = 0, moves = 0;

struct Probe {
    Probe() = default;
    Probe(const Probe&) { ++copies; }
    Probe(Probe&&) noexcept { ++moves; }
};

struct Plain { Probe p; };

struct WithDestructor {
    Probe p;
    // 소멸자를 적으면 이동 생성자가 만들어지지 않는다
    ~WithDestructor() {}
};

struct WithConst { const Probe p; };            // const 멤버는 옮길 수 없다

// 멤버 하나가 약속하지 않으면 전체가 그렇다
struct WithDeque {
    Probe p;
    std::deque<int> backlog;
};

struct Forgot {
    Probe p;
    Forgot() = default;
    Forgot(Forgot&& other) : p(std::move(other.p)) {}       // noexcept 를 잊었다
};

struct Promised {
    Probe p;
    std::deque<int> backlog;
    Promised() = default;
    Promised(Promised&&) noexcept = default;    // 내가 약속한다
};

template <typename T>
void report(const char* name)
{
    copies = moves = 0;
    T a;
    [[maybe_unused]] T b = std::move(a);
    std::println("{:<15} std::move 하면 {}   noexcept {}", name,
                 moves > 0 ? "이동" : "복사",
                 std::is_nothrow_move_constructible_v<T>);
}

int main()
{
    report<Plain>("Plain");
    report<WithDestructor>("WithDestructor");
    report<WithConst>("WithConst");
    report<WithDeque>("WithDeque");
    report<Forgot>("Forgot");
    report<Promised>("Promised");
}
```

```text
Plain           std::move 하면 이동   noexcept true
WithDestructor  std::move 하면 복사   noexcept false
WithConst       std::move 하면 복사   noexcept false
WithDeque       std::move 하면 이동   noexcept false
Forgot          std::move 하면 이동   noexcept false
Promised        std::move 하면 이동   noexcept true
```

`WithDestructor`와 `WithConst`는 `std::move`를 적어도 **복사**됩니다. 오류도 경고도 없습니다. 로그 한 줄을 찍으려고 소멸자를 적는 순간 그 타입을 담은 벡터가 느려집니다. `WithDeque`는 옮겨지기는 하지만 벡터 안에서는 복사됩니다.

`Promised`처럼 `= default` 앞에 `noexcept`를 적으면 멤버가 약속하지 않은 것을 **내가** 약속하게 됩니다. 그 이동이 정말 던지면 프로그램은 [`std::terminate`로 끝납니다](#/read/cpp-syntax/exc-noexcept). 메모리가 모자랄 때 끝나도 되는 프로그램이라면 받아들일 만한 거래입니다.

## 표준 타입 가운데 아닌 것

| 타입 | 이동 생성 | 이동 대입 |
| --- | --- | --- |
| `std::deque`, 그것을 쓰는 `std::stack`·`std::queue` | libstdc++는 아님, libc++는 `noexcept` | `noexcept` |
| `std::fstream`, `std::ostringstream` 같은 스트림 | 아님 | 아님 |
| `std::pmr::string`, `std::pmr::vector` | `noexcept` | 아님 |
| `string`, `vector`, `list`, `map`, `unordered_map`, 스마트 포인터, `function`, `any`, `thread` | `noexcept` | `noexcept` |

GCC 14의 libstdc++와 Clang 20의 libc++에서 `std::is_nothrow_move_constructible_v`로 물은 결과입니다. `optional`, `variant`, `pair`, `tuple`, `array`는 담은 타입을 따릅니다. libstdc++의 `deque`는 옮겨진 쪽도 쓸 수 있는 상태로 두려고 이동 생성자에서 메모리를 할당합니다. 위 예제의 `WithDeque`가 libc++에서는 `true`로 나오는 까닭입니다. `pmr` 컨테이너의 이동 대입은 [두 컨테이너의 자원이 다르면](#/read/cpp-stl/mem-allocator) 원소를 하나씩 옮겨야 해서 약속하지 못합니다.

<Note kind="warn">
마이크로소프트의 표준 라이브러리에서는 `std::list`, `std::map`, `std::unordered_map` 계열도 이동 생성자가 `noexcept`가 아니라고 알려져 있습니다(끝을 나타내는 노드를 힙에 두기 때문입니다). 이 책을 쓰며 돌려 보지는 못했습니다. 여러 컴파일러로 빌드하는 코드라면 아래의 `static_assert`가 컴파일러마다 답을 알려 줍니다.
</Note>

## 약속을 적어 두고 지키게 한다

벡터에 담을 타입 바로 아래에 두 줄을 적어 둡니다.

```cpp nocheck
static_assert(std::is_nothrow_move_constructible_v<Packet>);
static_assert(std::is_nothrow_move_assignable_v<Packet>);
```

누군가 `Packet`에 소멸자를 적거나 `std::deque` 멤버를 더하면 느려지는 대신 **컴파일이 멈춥니다.** 템플릿에서는 담은 타입에 맡깁니다. `noexcept(std::is_nothrow_move_constructible_v<T>)`처럼 [조건을 적습니다](#/read/cpp-syntax/exc-noexcept).

## 정리

- 벡터는 재할당할 때 이동 생성자가 `noexcept`인 원소만 옮긴다. 아니면 그때마다 전부 복사한다
- 소멸자를 적거나 `const` 멤버를 두면 이동이 복사가 되고, 약속하지 않는 멤버 하나가 전체의 `noexcept`를 없앤다
- 담을 타입 옆에 `static_assert`로 적어 두면 깨지는 순간 컴파일러가 알려 준다
