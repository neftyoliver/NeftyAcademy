export const summary = '식마다 붙는 범주 셋, prvalue가 객체가 되는 때, 참조와 멤버 함수가 범주로 고르는 법';

[「우측값 참조」](#/read/cpp-syntax/sm-rvalue)에서 좌측값과 우측값을 갈랐고, 표준이 그것을 셋으로 나눈다는 것은 이름만 보았습니다. 이동, 전달, 복사 생략의 규칙은 모두 그 셋으로 적혀 있습니다. 이 챕터의 나머지를 읽기 전에 여기서 정확히 해 둡니다.

## 범주는 식의 성질이다

값 범주는 변수나 타입이 아니라 **식(expression)에** 붙습니다. `std::string&& r`이라는 변수의 타입은 우측값 참조이지만, `r`이라는 식은 좌측값입니다. 같은 객체도 `s`라고 쓰면 lvalue이고 `std::move(s)`라고 쓰면 xvalue입니다.

식마다 두 가지를 묻습니다. **자리가 있는가**(어느 객체인지 가리킬 수 있는가), 그리고 **속을 가져가도 되는가**.

| | 가져가면 안 된다 | 가져가도 된다 |
| --- | --- | --- |
| 자리가 있다 | lvalue | xvalue |
| 자리가 없다 | (없다) | prvalue |

자리가 있는 둘을 묶어 glvalue, 가져가도 되는 둘을 묶어 rvalue라고 합니다. 지금까지 "우측값"이라고 부른 것이 rvalue입니다. `T&&` 인자는 rvalue를 받고, 그 안에서 xvalue와 prvalue가 갈리는 곳이 [복사 생략](#/read/cpp-advanced/mv-rvo)입니다.

## 식마다 찍어 보기

괄호를 한 겹 더 싼 `decltype((식))`은 식의 범주를 타입에 실어 돌려줍니다. lvalue면 `T&`, xvalue면 `T&&`, prvalue면 `T`입니다. 그것을 글자로 바꿔 찍습니다.

```cpp
#include <print>
#include <string>
#include <utility>

template <typename T>
constexpr const char* category = "prvalue";
template <typename T>
constexpr const char* category<T&> = "lvalue";
template <typename T>
constexpr const char* category<T&&> = "xvalue";

#define SHOW(expr) std::println("{:<26} {}", #expr, category<decltype((expr))>)

struct Sensor {
    std::string name;
    int pin = 0;
    std::string& label() { return name; }
    std::string&& take() { return std::move(name); }
    std::string copy() const { return name; }
};

Sensor make() { return {"임시", 1}; }

int main()
{
    Sensor s{"온도", 4};
    Sensor&& r = make();
    int numbers[3] = {1, 2, 3};

    SHOW(s);
    SHOW(r);
    SHOW(s.name);
    SHOW(++numbers[0]);
    SHOW(s.label());
    SHOW("literal");
    std::println("--");
    SHOW(std::move(s));
    SHOW(s.take());
    SHOW(std::move(s).name);
    SHOW(make().name);
    std::println("--");
    SHOW(make());
    SHOW(s.copy());
    SHOW(numbers[0]++);
    SHOW(&s);
    SHOW([] { return 1; });
    SHOW(true ? s : r);
    SHOW(true ? s : make());
}
```

```text
s                          lvalue
r                          lvalue
s.name                     lvalue
++numbers[0]               lvalue
s.label()                  lvalue
"literal"                  lvalue
--
std::move(s)               xvalue
s.take()                   xvalue
std::move(s).name          xvalue
make().name                xvalue
--
make()                     prvalue
s.copy()                   prvalue
numbers[0]++               prvalue
&s                         prvalue
[] { return 1; }           prvalue
true ? s : r               lvalue
true ? s : make()          prvalue
```

| 규칙 | 보기 |
| --- | --- |
| 함수 호출은 반환 타입을 따른다 | `T&` → lvalue, `T&&` → xvalue, `T` → prvalue |
| 멤버는 객체의 범주를 물려받는다 | `s.name`은 lvalue, `std::move(s).name`과 `make().name`은 xvalue |
| 글자열 리터럴은 lvalue다 | 정적 저장소에 있는 배열이라 주소가 있다. 다른 리터럴(`42`, `true`)은 prvalue |
| 앞에 붙는 `++`와 뒤에 붙는 `++` | `++x`는 `x` 자신(lvalue), `x++`는 옛 값의 사본(prvalue) |
| 조건 연산자 | 양쪽이 같은 타입의 lvalue면 lvalue. 한쪽이 prvalue면 prvalue가 되고 **다른 쪽은 복사된다** |

조건 연산자의 결과는 lvalue여도 **이름이 아닙니다.** 이 점이 [반환에서](#/read/cpp-advanced/mv-rvo) 다시 나옵니다. `return flag ? a : b;`는 생략도 이동도 되지 않고 복사됩니다.

## prvalue는 아직 객체가 아니다

C++17부터 prvalue는 "임시 객체"가 아닙니다. **객체를 어떻게 초기화할지 적어 둔 것**이고, 초기화할 대상이 정해지면 그 자리에 바로 만듭니다.

```cpp
#include <mutex>
#include <print>

struct Tracer {
    Tracer() { std::println("  생성"); }
    Tracer(const Tracer&) { std::println("  복사"); }
    Tracer(Tracer&&) noexcept { std::println("  이동"); }
    ~Tracer() { std::println("  소멸"); }
    int value = 7;
};

struct Pinned {                         // 복사도 이동도 못 하는 타입
    explicit Pinned(int id) : id(id) {}
    Pinned(const Pinned&) = delete;
    Pinned(Pinned&&) = delete;
    std::mutex lock;
    int id;
};

Pinned make_pinned(int id) { return Pinned(id); }

int main()
{
    std::println("1. 겹겹이 싼 prvalue");
    Tracer a = Tracer(Tracer(Tracer()));
    std::println("2. 멤버만 읽고 버린다");
    int v = Tracer().value;
    std::println("3. 참조에 묶는다");
    const Tracer& ref = Tracer();
    std::println("4. 옮길 수 없는 타입을 값으로 받는다");
    Pinned p = make_pinned(3);
    std::println("끝 {} {} {}", v, ref.value + a.value, p.id);
}
```

```text
1. 겹겹이 싼 prvalue
  생성
2. 멤버만 읽고 버린다
  생성
  소멸
3. 참조에 묶는다
  생성
4. 옮길 수 없는 타입을 값으로 받는다
끝 7 14 3
  소멸
  소멸
```

1번은 세 겹이어도 생성이 한 번입니다. 최적화가 아니라 **규칙**이어서 `-O0`에서도, 복사·이동 생성자가 지워져 있어도 같습니다. 4번이 그 증거입니다. `Pinned`는 옮길 수 없지만 값으로 돌려받을 수 있습니다(C++14로 컴파일하면 `use of deleted function` 오류입니다).

2번과 3번처럼 **객체가 꼭 있어야 하는 순간**에는 임시 객체가 만들어집니다. 참조에 묶을 때, 멤버를 읽을 때, 값을 쓰지 않고 버릴 때입니다. 이것을 임시 객체 구체화(temporary materialization)라 하고, 그렇게 생긴 객체를 가리키는 식이 xvalue입니다. 위 표에서 `make()`는 prvalue인데 `make().name`이 xvalue였던 까닭입니다. 그 임시 객체가 언제까지 사는지는 [「임시 객체의 수명」](#/read/cpp-syntax/life-temporary)에서 다뤘습니다.

## 참조는 범주를 보고 묶인다

| 매개변수 | 묶이는 인자 | 여럿이 받을 수 있을 때 |
| --- | --- | --- |
| `T&` | 바꿀 수 있는 lvalue | 그 인자에는 이것이 먼저 |
| `const T&` | 무엇이든 | 다른 판이 없을 때 받는다 |
| `T&&` | 바꿀 수 있는 rvalue | 그 인자에는 이것이 먼저 |
| `const T&&` | rvalue (`const` 포함) | `const` rvalue에는 `const T&`보다 먼저 |

```cpp
#include <print>
#include <string>
#include <utility>

void f(std::string&) { std::println("T&"); }
void f(const std::string&) { std::println("const T&"); }
void f(std::string&&) { std::println("T&&"); }
void f(const std::string&&) { std::println("const T&&"); }

int main()
{
    std::string name = "n";
    const std::string fixed = "f";
    f(name);
    f(fixed);
    f(std::string("t"));
    f(std::move(fixed));
}
```

```text
T&
const T&
T&&
const T&&
```

`std::move(fixed)`는 `const std::string&&`입니다. `T&&`에는 묶이지 못하므로 `const T&&` 판이 없으면 `const T&`로 가서 [조용히 복사됩니다](#/read/cpp-syntax/sm-elision). `const T&&`는 속을 가져갈 수 없어서 쓸 일이 드물고, 거의 **임시 객체를 막는 데**만 씁니다.

```cpp nocheck
void watch(const std::string& text);        // 참조를 보관해 두고 나중에 읽는다
void watch(const std::string&&) = delete;   // 임시 객체는 받지 않는다

watch(name);                    // 된다
watch(std::string("temp"));     // 오류: use of deleted function
```

`std::ref`와 `std::as_const`가 이 방법으로 임시 객체를 거절합니다.

## 멤버 함수도 범주로 고른다

멤버 함수 뒤의 `&`와 `&&`는 **`*this`의 범주**로 오버로드를 가릅니다. `const`를 붙이는 그 자리입니다.

```cpp
#include <print>
#include <string>
#include <utility>

class Report {
public:
    explicit Report(std::string text) : text_(std::move(text)) {}

    // *this 가 lvalue 일 때: 들여다보게만 한다
    const std::string& text() const& { return text_; }
    // *this 가 rvalue 일 때: 어차피 사라질 객체이므로 속을 내준다
    std::string text() && { return std::move(text_); }

private:
    std::string text_;
};

Report build() { return Report("a report long enough to live on the heap"); }

void which(const std::string&) { std::println("const& 를 받았다"); }
void which(std::string&&) { std::println("&& 를 받았다"); }

int main()
{
    Report kept("kept");
    which(kept.text());             // lvalue 객체
    which(build().text());          // prvalue 객체
    which(std::move(kept).text());  // xvalue 객체

    std::string taken = build().text();     // 복사 없이 꺼낸다
    std::println("{}", taken.size());
}
```

```text
const& 를 받았다
&& 를 받았다
&& 를 받았다
40
```

`&&` 판이 없으면 `build().text()`는 `const&` 판으로 가고, `taken`은 복사로 만들어집니다. `std::optional::value()`가 이렇게 한정자별로 나뉘어 있습니다. 한 이름의 오버로드에는 한정자를 모두 붙이거나 모두 붙이지 않아야 하고, C++23의 [명시적 `this`](#/read/cpp-syntax/lam-recursive)로는 한 벌로 줄일 수 있습니다.

<Note>
클래스 타입은 임시 객체에도 대입이 됩니다. `build() = other;`와 `(a + b) = "c";`가 컴파일됩니다. 대입 연산자를 `Report& operator=(const Report&) & = default;`처럼 `&`로 한정하면 lvalue에만 대입할 수 있습니다.
</Note>

## 정리

- 범주는 식에 붙는다. 자리가 있고 못 가져가면 lvalue, 자리가 있고 가져가도 되면 xvalue, 자리가 없으면 prvalue
- prvalue는 초기화 방법이다. 대상이 정해지면 그 자리에 바로 만들어지고, 객체가 꼭 필요할 때만 임시 객체가 된다
- 참조 매개변수와 `&`·`&&` 한정자는 인자와 `*this`의 범주를 보고 오버로드를 고른다
