[「소멸자와 RAII」](#/read/cpp-syntax/class-dtor)의 `File`은 소멸자에서 닫고 복사를 막는 데서 멈췄습니다. 실제로 쓰려면 함수가 돌려줄 수 있어야 하고, 컨테이너에 담을 수 있어야 하고, 닫다가 난 오류를 볼 길도 있어야 합니다. 메모리가 아닌 자원을 쥐는 클래스를 끝까지 만들어 봅니다.

## 정할 것 다섯 가지

| 정할 것 | 고른 답 | 까닭 |
| --- | --- | --- |
| 빈 상태 | 있다 (`-1`) | [옮겨진 뒤에 남을 값](#/read/cpp-advanced/mv-moved-from)이 필요하다. 여는 데 실패한 것도 같은 값이다 |
| 복사 | 없다 | 닫는 것은 한 번이어야 한다 |
| 이동 | 있다. `noexcept` | 함수가 돌려주고 [`vector`에 담는다](#/read/cpp-advanced/mv-noexcept) |
| 닫다가 실패하면 | 소멸자는 삼키고, `close()`는 알려 준다 | [소멸자는 던지지 않는다](#/read/cpp-syntax/exc-unwind) |
| 날것 꺼내기 | `get()`은 빌려주고 `release()`는 넘겨준다 | C 함수에 넘겨야 한다 |

`std::unique_ptr`가 한 선택과 같습니다. 이름도 같게 지으면 읽는 사람이 새로 배울 것이 없습니다.

## 파일 디스크립터 래퍼

```cpp
#include <fcntl.h>
#include <unistd.h>

#include <cerrno>
#include <filesystem>
#include <iterator>
#include <print>
#include <system_error>
#include <utility>
#include <vector>

class Fd {
public:
    Fd() = default;
    explicit Fd(int fd) noexcept : fd_(fd) {}
    Fd(Fd&& other) noexcept : fd_(other.release()) {}
    Fd& operator=(Fd&& other) noexcept
    {
        reset(other.release());     // 자기 자신이어도 탈이 없다
        return *this;
    }
    ~Fd() { reset(); }

    explicit operator bool() const noexcept { return fd_ != -1; }
    int get() const noexcept { return fd_; }

    // 주인 노릇을 그만둔다. 닫을 책임이 부른 쪽으로 넘어간다
    [[nodiscard]] int release() noexcept { return std::exchange(fd_, -1); }

    // 쥔 것을 닫고 새것을 쥔다
    void reset(int fd = -1) noexcept
    {
        if (fd_ != -1) ::close(fd_);
        fd_ = fd;
    }

    // 닫다가 난 오류를 알고 싶으면 소멸자에 맡기지 않고 직접 부른다
    std::error_code close() noexcept
    {
        if (fd_ == -1) return {};
        if (::close(std::exchange(fd_, -1)) == 0) return {};
        return {errno, std::generic_category()};
    }

private:
    int fd_ = -1;
};

Fd open_read(const char* path) { return Fd(::open(path, O_RDONLY | O_CLOEXEC)); }

long open_count()       // 이 프로세스가 열어 둔 디스크립터의 수
{
    namespace fs = std::filesystem;
    return std::distance(fs::directory_iterator("/proc/self/fd"), {});
}

int main()
{
    const long before = open_count();
    {
        Fd a = open_read("/dev/null");
        // 주인이 바뀐다. 닫는 것은 한 번이다
        Fd b = std::move(a);
        std::vector<Fd> many;
        for (int i = 0; i < 3; ++i) many.push_back(open_read("/dev/zero"));
        std::println("a {} / b {} / 열린 것 +{}", bool(a), bool(b),
                     open_count() - before);

        b = open_read("/dev/zero");             // 쥐고 있던 것은 닫히고 새것을 쥔다
        many.erase(many.begin());
        std::println("열린 것 +{}", open_count() - before);

        Fd missing = open_read("/no/such/file");
        std::println("없는 파일 {} / 닫기 오류 {}", bool(missing),
                     b.close().value());
    }
    std::println("범위를 나온 뒤 +{}", open_count() - before);
    std::println("크기 {} (int {})", sizeof(Fd), sizeof(int));
}
```

```text
a false / b true / 열린 것 +4
열린 것 +3
없는 파일 false / 닫기 오류 0
범위를 나온 뒤 +0
크기 4 (int 4)
```

| 줄 | 눈여겨볼 것 |
| --- | --- |
| `reset(other.release())` | 이동 대입 전체가 이 한 줄이다. `release`가 먼저 상대를 비우므로 [자기 자신에게 대입해도](#/read/cpp-advanced/mv-moved-from) 닫지 않는다 |
| `[[nodiscard]] release()` | 돌려받은 번호를 버리면 샌다. 버리는 코드에 경고가 나게 한다 |
| `explicit operator bool` | `if (fd)`는 되고 `int n = fd;` 같은 엉뚱한 변환은 안 된다 |
| `close()` | 쓰기용 파일은 닫을 때 오류가 드러나기도 한다. 그것을 봐야 하는 곳에서만 부른다 |

크기는 `int`와 같습니다. 멤버가 하나뿐이고 가상 함수가 없으므로 감싼 값 말고는 아무것도 없습니다. 다만 소멸자가 있는 타입이라 값으로 넘기면 [레지스터가 아니라 메모리로](#/read/cpp-advanced/mv-rvo) 다닙니다. 쓰기만 하는 함수에는 `fd.get()`으로 번호를 넘깁니다.

## 틀 하나로 여러 자원

소켓, 메모리 매핑, GPIO 줄마다 위 클래스를 다시 쓰지 않습니다. 다른 것은 **핸들의 타입, 빈 값, 닫는 법** 셋뿐이므로 그것만 밖으로 뺍니다.

```cpp
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <unistd.h>

#include <cstddef>
#include <fstream>
#include <print>
#include <string_view>
#include <utility>

template <typename Policy>
class UniqueHandle {
public:
    using Handle = typename Policy::Handle;

    UniqueHandle() = default;
    explicit UniqueHandle(Handle handle) noexcept : handle_(handle) {}
    UniqueHandle(UniqueHandle&& other) noexcept : handle_(other.release()) {}
    UniqueHandle& operator=(UniqueHandle&& other) noexcept
    {
        reset(other.release());
        return *this;
    }
    ~UniqueHandle() { reset(); }

    explicit operator bool() const noexcept { return handle_ != Policy::invalid(); }
    Handle get() const noexcept { return handle_; }
    [[nodiscard]] Handle release() noexcept
    {
        return std::exchange(handle_, Policy::invalid());
    }
    void reset(Handle handle = Policy::invalid()) noexcept
    {
        if (handle_ != Policy::invalid()) Policy::close(handle_);
        handle_ = handle;
    }

private:
    Handle handle_ = Policy::invalid();
};

struct FdPolicy {
    using Handle = int;
    static Handle invalid() noexcept { return -1; }
    static void close(Handle fd) noexcept
    {
        ::close(fd);
        std::println("  close");
    }
};

struct Region {
    void* address;
    std::size_t length;
    bool operator==(const Region&) const = default;
};

struct MappingPolicy {
    using Handle = Region;
    static Handle invalid() noexcept { return {MAP_FAILED, 0}; }
    static void close(Handle region) noexcept
    {
        ::munmap(region.address, region.length);
        std::println("  munmap");
    }
};

using Fd = UniqueHandle<FdPolicy>;
using Mapping = UniqueHandle<MappingPolicy>;

// 자원을 쥔 멤버만 있다. 소멸자도 이동도 적지 않는다
class MappedFile {
public:
    explicit MappedFile(const char* path) : fd_(::open(path, O_RDONLY | O_CLOEXEC))
    {
        struct stat info {};
        if (!fd_ || ::fstat(fd_.get(), &info) != 0) return;
        auto length = static_cast<std::size_t>(info.st_size);
        void* address =
            ::mmap(nullptr, length, PROT_READ, MAP_PRIVATE, fd_.get(), 0);
        map_.reset({address, length});
    }

    std::string_view text() const
    {
        if (!map_) return {};
        return {static_cast<const char*>(map_.get().address), map_.get().length};
    }

private:
    Fd fd_;             // 먼저 선언한 멤버가 먼저 만들어지고
    Mapping map_;       // 나중에 선언한 멤버가 먼저 정리된다
};

int main()
{
    std::ofstream("/tmp/na-mapped.txt") << "mapped text";
    {
        MappedFile file("/tmp/na-mapped.txt");
        MappedFile moved = std::move(file);     // 컴파일러가 만든 이동
        std::println("[{}] [{}]", file.text(), moved.text());
    }
    std::println("크기 {} {}", sizeof(Fd), sizeof(Mapping));
}
```

```text
[] [mapped text]
  munmap
  close
크기 4 16
```

`MappedFile`에는 소멸자도 이동 생성자도 없습니다. 날 자원은 `UniqueHandle`만 쥐고, 그 위의 클래스는 [0의 규칙](#/read/cpp-syntax/sm-rules)을 따릅니다. 컴파일러가 만든 이동이 멤버를 하나씩 옮기고, 멤버가 스스로 비우므로 `file`은 올바르게 빈 상태가 됩니다.

정리는 **선언의 반대 순서**입니다. 얻은 순서대로 선언하면 놓아주는 순서는 저절로 그 반대가 됩니다. 데이터베이스 연결과 그 위에서 만든 질의문처럼 뒤의 자원이 앞의 자원에 기대는 경우에는 이 순서가 곧 정확성입니다. 멤버의 줄을 바꾸는 것만으로 버그가 생기므로, 순서에 뜻이 있으면 위처럼 주석을 답니다.

<Note>
`std::unique_ptr`에 [삭제자](#/read/cpp-advanced/sp-unique)를 다는 방법은 핸들이 **포인터**일 때만 됩니다. 빈 값이 `nullptr`이어야 해서, `int`인 디스크립터(0도 유효한 번호입니다)에는 쓸 수 없습니다. 위의 틀과 같은 일을 하는 `std::experimental::unique_resource`가 `<experimental/scope>`에 있습니다. 표준 본문이 아니라 라이브러리 기술 명세(Library Fundamentals TS v3)이고, GCC는 13부터 싣고 있으며 Clang 20의 libc++에는 없습니다.
</Note>

## 정리

- 래퍼를 만들 때는 빈 상태, 복사, 이동, 닫기 실패, 날것 꺼내기를 정한다. `unique_ptr`의 답과 이름을 따르면 된다
- 이동 대입은 `reset(other.release())` 한 줄이고, 래퍼의 크기는 감싼 핸들과 같다
- 날 자원은 작은 래퍼만 쥔다. 그 위의 클래스는 멤버를 얻는 순서대로 선언하고 소멸자를 적지 않는다
