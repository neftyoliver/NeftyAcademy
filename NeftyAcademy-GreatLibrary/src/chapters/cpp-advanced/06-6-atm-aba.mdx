[비교 후 교환](#/read/cpp-advanced/atm-cas)은 "값이 내가 본 그대로인가"를 묻습니다. 정수를 셀 때는 그것으로 충분합니다. 포인터에서는 다릅니다. 값이 A에서 B로 갔다가 **다시 A로** 돌아와도 CAS는 성공하고, 그사이에 A가 가리키던 세상은 바뀌어 있습니다. 이것이 ABA 문제이고, [마디를 하나씩 떼는 구조](#/read/cpp-advanced/atm-lockfree)를 어렵게 만드는 주범입니다.

## 한 걸음씩 따라가 본다

스레드 둘이 엇갈리는 순서를 한 스레드에서 손으로 그대로 밟아 봅니다. 마디는 풀에서 빌리고 돌려준다고 치고, 돌려준 마디에는 `alive = false`를 적습니다.

```cpp
#include <atomic>
#include <print>

struct Node {
    char name;
    Node* next = nullptr;
    bool alive = true;      // 풀에 돌려준 마디는 false
};

std::atomic<Node*> head{nullptr};

void push(Node* node)
{
    node->alive = true;
    node->next = head.load();
    while (!head.compare_exchange_weak(node->next, node)) {}
}

Node* pop()
{
    Node* old = head.load();
    while (old != nullptr && !head.compare_exchange_weak(old, old->next)) {}
    if (old != nullptr) old->alive = false;     // 풀에 돌려준다
    return old;
}

int main()
{
    Node a{'A'}, b{'B'}, c{'C'};
    push(&c);
    push(&b);
    push(&a);                                   // 머리 → A → B → C

    // 스레드 1 이 pop 을 시작했다: 머리와 그 다음을 읽은 데서 멈춘다
    Node* seen_head = head.load();              // A
    Node* seen_next = seen_head->next;          // B

    // 그사이 스레드 2 가 A 와 B 를 빼고, A 를 다시 넣는다
    pop();                                      // A 가 나간다
    pop();                                      // B 가 나간다 (풀로 돌아갔다)
    // 같은 주소의 A 가 다시 머리다: 머리 → A → C
    push(&a);

    // 스레드 1 이 이어서 한다: "머리가 아직 A 면 B 로 바꾼다"
    bool swapped = head.compare_exchange_strong(seen_head, seen_next);
    Node* now = head.load();
    std::println("CAS 가 성공했나: {}", swapped);
    std::println("지금 머리: {} (살아 있는 마디인가: {})", now->name, now->alive);
    std::print("머리부터 따라가면:");
    for (Node* node = now; node != nullptr; node = node->next)
        std::print(" {}", node->name);
    std::println("");
}
```

```text
CAS 가 성공했나: true
지금 머리: B (살아 있는 마디인가: false)
머리부터 따라가면: B C
```

스레드 1이 본 것은 "머리는 A"뿐이었고, 돌아와 보니 머리는 여전히 A였습니다. 그래서 CAS는 성공했습니다. 하지만 스레드 1이 들고 있던 "A의 다음은 B"는 **낡은 사실**이었습니다. 결과로 목록에 있던 A는 사라졌고, 이미 풀로 돌아간 B가 머리가 되었습니다. 풀이 B를 다른 곳에 빌려주면 두 곳이 같은 마디를 씁니다. 풀이 아니라 `delete`였다면 머리가 지워진 메모리를 가리킵니다.

같은 주소가 돌아오는 일은 드물지 않습니다. 할당자는 방금 돌려받은 블록을 **가장 먼저** 다시 내줍니다.

## 번호표를 붙인다

머리에 포인터만 두지 않고 **바뀐 횟수**를 함께 둡니다. A가 돌아와도 횟수가 달라져 있으므로 CAS가 실패합니다. 둘을 한 번에 견주어야 하므로 하나의 원자적 값에 담습니다. 포인터 대신 배열의 번호를 쓰면 번호 32비트와 횟수 32비트가 [잠금 없이 되는 8바이트](#/read/cpp-advanced/atm-atomic)에 들어갑니다.

```cpp
#include <array>
#include <atomic>
#include <cstdint>
#include <print>
#include <thread>
#include <vector>

// 빈칸의 번호를 쌓아 두는 스택. 번호와 "바뀐 횟수"를 한 값에 담는다
class IndexStack {
public:
    static constexpr std::uint32_t none = 0xffffffff;

    explicit IndexStack(std::uint32_t count) : next_(count)
    {
        for (std::uint32_t i = 0; i < count; ++i) push(i);
    }

    void push(std::uint32_t index)
    {
        std::uint64_t old_head = head_.load();
        std::uint64_t new_head;
        do {
            next_[index].store(index_of(old_head));
            new_head = pack(index, tag_of(old_head) + 1);   // 바뀔 때마다 올린다
        } while (!head_.compare_exchange_weak(old_head, new_head));
    }

    std::uint32_t pop()
    {
        std::uint64_t old_head = head_.load();
        std::uint64_t new_head;
        do {
            std::uint32_t index = index_of(old_head);
            if (index == none) return none;
            // 이 칸이 그사이 빠졌다가 다시 들어왔다면 지금 읽는 next 는 낡았다.
            // 그때는 횟수가 달라져 있어 아래의 CAS 가 실패한다
            new_head = pack(next_[index].load(), tag_of(old_head) + 1);
        } while (!head_.compare_exchange_weak(old_head, new_head));
        return index_of(old_head);
    }

private:
    static std::uint64_t pack(std::uint32_t index, std::uint32_t tag)
    {
        return (std::uint64_t{tag} << 32) | index;
    }
    static std::uint32_t index_of(std::uint64_t head)
    {
        return static_cast<std::uint32_t>(head);
    }
    static std::uint32_t tag_of(std::uint64_t head)
    {
        return static_cast<std::uint32_t>(head >> 32);
    }

    std::atomic<std::uint64_t> head_{pack(none, 0)};
    std::vector<std::atomic<std::uint32_t>> next_;
};

int main()
{
    IndexStack free_slots(8);
    {
        std::vector<std::jthread> workers;
        for (int id = 0; id < 4; ++id) {
            workers.emplace_back([&] {
                for (int i = 0; i < 50'000; ++i) {
                    std::uint32_t a = free_slots.pop();     // 칸 둘을 빌렸다가
                    std::uint32_t b = free_slots.pop();
                    if (a != IndexStack::none) free_slots.push(a);  // 돌려준다
                    if (b != IndexStack::none) free_slots.push(b);
                }
            });
        }
    }
    std::array<int, 8> seen{};
    int count = 0;
    for (auto index = free_slots.pop(); index != IndexStack::none;
         index = free_slots.pop()) {
        ++seen[index];
        ++count;
    }
    bool each_once = true;
    for (int times : seen) each_once = each_once && times == 1;
    std::println("남은 칸 {}개, 모두 한 번씩인가 {}", count, each_once);
}
```

```text
남은 칸 8개, 모두 한 번씩인가 true
```

네 스레드가 칸 여덟 개를 5만 번씩 빌리고 돌려준 뒤에도 여덟 칸이 한 번씩 그대로 있습니다. `tag_of(old_head) + 1`을 `0`으로 바꿔 번호표를 없애고 열 번 돌려 보니 **열 번 모두 끝나지 않았습니다.** 목록이 고리가 되어 `pop`이 영원히 돕니다. 횟수를 바꿔 돌린 때에는 끝나기는 했지만 칸이 둘만 남기도 했습니다.

이 구조가 맞는 데는 번호표 말고 하나가 더 있습니다. 마디가 **배열의 칸**이어서 `next_[index]`를 읽는 것이 언제나 안전합니다. 그 칸이 방금 빠져나갔더라도 메모리는 그대로 있고, 낡은 값을 읽었다는 것은 CAS가 걸러 줍니다. 포인터로 가리키고 `delete`하는 구조였다면 읽는 것 자체가 사라진 메모리를 건드립니다.

## 언제 지워도 되는가

그래서 락 없는 구조의 진짜 문제는 ABA보다 넓습니다. **다른 스레드가 아직 보고 있을지 모르는 마디를 언제 지울 수 있는가**입니다.

| 방법 | 생각 | 치르는 값 |
| --- | --- | --- |
| 지우지 않는다 | 마디를 풀이나 배열에 두고 다시 쓴다. 위의 `IndexStack` | 메모리가 줄지 않는다. 번호표가 필요하다 |
| 통째로 떼어 온다 | 뗀 목록은 나만 본다. [앞 쪽의 `Inbox`](#/read/cpp-advanced/atm-lockfree) | 하나씩 뺄 수 없다 |
| 세어 둔다 | 마디마다 몇이 보고 있는지 센다: `std::atomic<std::shared_ptr<T>>` | 읽을 때마다 계수를 고친다. [줄을 다툰다](#/read/cpp-advanced/atm-false-sharing) |
| 위험 포인터 | 읽는 쪽이 "이것을 보고 있다"고 적어 둔다. 지우는 쪽은 적힌 것을 미룬다 | 읽을 때마다 쓰기 한 번. C++26의 `<hazard_pointer>` |
| RCU | 읽는 구간을 표시한다. 그때 읽던 쪽이 모두 구간을 나간 뒤에 지운다 | 읽기는 거의 공짜. 지우기가 늦어진다. C++26의 `<rcu>` |

위의 둘은 직접 만들 수 있고, 아래의 셋은 라이브러리의 일입니다. C++26의 두 헤더는 이 책이 쓰는 GCC 14와 Clang 20에 아직 없어 돌려 보지 못했습니다.

<Note>
포인터와 횟수를 16바이트 구조체로 묶어 `std::atomic`에 넣는 방법도 있습니다. x86-64에는 16바이트를 한 번에 견주고 바꾸는 명령이 있지만, [GCC 14는 그것을 잠금 없는 것으로 치지 않았고](#/read/cpp-advanced/atm-atomic) Clang 20은 `-mcx16`을 줘야 했습니다. 컴파일러와 옵션에 기대지 않으려면 위처럼 번호를 쓰거나, 포인터의 남는 비트에 작은 횟수를 끼워 넣습니다.
</Note>

## 정리

- CAS는 값이 같은지만 본다. 포인터가 A로 돌아왔어도 A의 다음은 달라져 있을 수 있다
- 바뀐 횟수를 값에 함께 담으면 돌아온 A를 가려낼 수 있다. 마디를 배열의 칸으로 두면 낡은 읽기도 안전하다
- 남이 보고 있을지 모르는 마디는 함부로 지울 수 없다. 지우지 않거나, 통째로 떼거나, 그 일을 하는 라이브러리를 쓴다
