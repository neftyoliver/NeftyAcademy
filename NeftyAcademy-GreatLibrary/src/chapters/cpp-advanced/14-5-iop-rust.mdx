Rust와 C++은 서로의 타입을 모릅니다. `String`과 `std::string`은 속이 다르고, 두 언어 모두 제 타입의 배치를 바깥에 약속하지 않습니다. 둘이 만나는 곳은 [C ABI](#/read/cpp-advanced/iop-c-abi)입니다. 앞에서 C로 내놓은 `thermo` 라이브러리가 고칠 것 없이 Rust에서 쓰입니다. 이 페이지의 코드는 rustc 1.97(2024 에디션)과 GCC 14로 돌렸습니다.

## Rust에서 C++을 부르기

```rust
// main.rs: C++로 만든 thermo 라이브러리를 Rust에서 쓴다
use std::ffi::{c_char, c_int, CStr, CString};
use std::ptr::NonNull;

#[repr(C)]
struct RawThermo {
    _private: [u8; 0],          // 속을 모르는 타입. 포인터로만 다룬다
}

// thermo.h를 Rust의 말로 옮겨 적었다. 맞게 옮겼는지는 컴파일러가 확인하지 못한다
unsafe extern "C" {
    fn thermo_create(name: *const c_char, out: *mut *mut RawThermo) -> c_int;
    fn thermo_destroy(t: *mut RawThermo);
    fn thermo_add(t: *mut RawThermo, celsius: f64) -> c_int;
    fn thermo_average(t: *const RawThermo, out: *mut f64) -> c_int;
    fn thermo_last_error() -> *const c_char;
}

fn last_error() -> String {
    unsafe { CStr::from_ptr(thermo_last_error()) }.to_string_lossy().into_owned()
}

// unsafe는 이 타입 안에 가둔다. 밖에서는 보통의 Rust 타입이다
struct Thermo(NonNull<RawThermo>);

impl Thermo {
    fn new(name: &str) -> Result<Thermo, String> {
        let name = CString::new(name).map_err(|e| e.to_string())?;
        let mut raw = std::ptr::null_mut();
        if unsafe { thermo_create(name.as_ptr(), &mut raw) } != 0 {
            return Err(last_error());
        }
        NonNull::new(raw).map(Thermo).ok_or_else(last_error)
    }
    fn add(&mut self, celsius: f64) {
        unsafe { thermo_add(self.0.as_ptr(), celsius) };
    }
    fn average(&self) -> Result<f64, String> {
        let mut value = 0.0;
        match unsafe { thermo_average(self.0.as_ptr(), &mut value) } {
            0 => Ok(value),
            _ => Err(last_error()),
        }
    }
}

impl Drop for Thermo {
    fn drop(&mut self) {
        unsafe { thermo_destroy(self.0.as_ptr()) };     // 만든 쪽이 없앤다
    }
}

fn main() {
    let mut room = Thermo::new("거실").unwrap();
    println!("{:?}", room.average());
    room.add(21.5);
    room.add(31.0);
    println!("{:?}", room.average());
}
```

```text nocheck
$ g++ -std=c++23 -O2 -c thermo.cpp && ar rcs libthermo.a thermo.o
$ rustc --edition 2024 -O main.rs -L . -l static=thermo -l dylib=stdc++ -o app
$ ./app
Err("thermo_average: no samples")
Ok(26.25)
```

구조가 [C++ 껍데기](#/read/cpp-advanced/iop-c-abi)와 같습니다. 핸들을 타입 하나로 감싸고, 소멸자 자리에 `Drop`이, 예외 자리에 `Result`가 왔습니다. `unsafe`는 이 타입 안에만 있고 `main`에는 없습니다.

`unsafe extern "C"` 블록은 헤더를 손으로 옮긴 것입니다. [`ctypes`의 `argtypes`](#/read/cpp-advanced/iop-python)와 같은 처지입니다. `thermo_add`의 `f64`를 `i32`로 잘못 옮겨 봤더니 경고 없이 컴파일됐고 평균이 `1.1e161`로 나왔습니다. C++ 표준 라이브러리를 직접 이어 준 것(`-l dylib=stdc++`)도 눈여겨봅니다. 빼면 `undefined symbol: operator new(unsigned long)`으로 링크가 멈춥니다.

## C++에서 Rust를 부르기

```rust
// stats.rs → libstats.a: C++에서 부를 Rust 라이브러리
use std::panic::catch_unwind;
use std::slice;

#[repr(C)]                        // C와 같은 순서와 채움으로 놓는다
pub struct Stats {
    pub count: u64,
    pub mean: f64,
}

fn compute(values: &[f64]) -> Stats {
    assert!(!values.is_empty(), "no samples");        // 비었으면 패닉
    let sum: f64 = values.iter().sum();
    Stats { count: values.len() as u64, mean: sum / values.len() as f64 }
}

/// 0이면 성공. 패닉은 여기서 잡아 오류 번호로 바꾼다
#[unsafe(no_mangle)]
pub extern "C" fn stats_of(data: *const f64, len: usize, out: *mut Stats) -> i32 {
    if data.is_null() || out.is_null() {
        return 1;
    }
    // 포인터와 길이가 맞는지는 부르는 쪽을 믿는 수밖에 없다
    let values = unsafe { slice::from_raw_parts(data, len) };
    match catch_unwind(|| compute(values)) {
        Ok(stats) => {
            unsafe { out.write(stats) };
            0
        }
        Err(_) => 2,
    }
}

/// 잡지 않은 판. 패닉이 경계에 닿는다
#[unsafe(no_mangle)]
pub extern "C" fn mean_unguarded(data: *const f64, len: usize) -> f64 {
    let values = unsafe { slice::from_raw_parts(data, len) };
    compute(values).mean
}
```

```cpp nocheck
// main.cpp: Rust로 만든 라이브러리를 C++에서 쓴다
#include <cstddef>
#include <cstdint>
#include <print>
#include <vector>

extern "C" {
struct Stats {
    std::uint64_t count;
    double mean;
};
int stats_of(const double* data, std::size_t len, Stats* out);
double mean_unguarded(const double* data, std::size_t len);
}

int main(int argc, char**)
{
    const std::vector<double> samples = {21.5, 31.0};
    Stats stats{};
    if (stats_of(samples.data(), samples.size(), &stats) == 0)
        std::println("{}개, 평균 {}", stats.count, stats.mean);
    std::println("빈 입력: 반환 {}", stats_of(samples.data(), 0, &stats));
    if (argc > 1) std::println("{}", mean_unguarded(samples.data(), 0));
}
```

```text nocheck
$ rustc --edition 2024 --crate-type staticlib -O stats.rs -o libstats.a
$ g++ -std=c++23 -O2 main.cpp -L. -lstats -o app && ./app
2개, 평균 26.25

no samples
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

```

`#[unsafe(no_mangle)]`와 `extern "C"`가 [`extern "C"`](#/read/cpp-syntax/from-c-mangling)와 같은 일을 하고, `#[repr(C)]`가 구조체를 C의 규칙대로 놓습니다. 이번에는 C++ 쪽이 선언을 손으로 옮겨 적었습니다. 값은 따로 들지 않았습니다. 작은 Rust 함수를 2억 번 부른 시간이 다른 파일의 C++ 함수를 부른 시간과 같았습니다(1.0 ns).

## 경계를 넘는 타입

| Rust | C++ |
| --- | --- |
| `u8`, `i32`, `u64`, `f64`, `bool` | `std::uint8_t`, `std::int32_t`, `std::uint64_t`, `double`, `bool` |
| `usize`, `c_int`, `c_char` | `std::size_t`, `int`, `char` |
| `*const T`, `*mut T` | `const T*`, `T*` |
| `Option<NonNull<T>>` | 널일 수 있는 `T*` |
| `#[repr(C)] struct` | 같은 멤버를 같은 순서로 둔 구조체 |
| `extern "C" fn(i32) -> i32` | `int (*)(int)` |

`String`, `&str`, `Vec<T>`, 슬라이스, 값이 든 `enum`과 `std::string`, `std::vector`, 템플릿은 넘지 못합니다. **포인터와 길이로 풀어서** 넘기고, 받은 쪽에서 `slice::from_raw_parts`나 `std::span`으로 다시 묶습니다. 넘어온 포인터가 널이 아닌지, 길이가 맞는지는 어느 언어의 컴파일러도 보증하지 않습니다.

## 패닉과 예외

두 언어의 실패는 서로에게 건너가지 못합니다. 세 가지를 해 봤습니다.

| 한 일 | 일어난 일 |
| --- | --- |
| `stats_of`처럼 `catch_unwind`로 잡았다 | 오류 번호 2를 돌려주고 프로그램은 계속 돈다 |
| `mean_unguarded`에서 패닉이 났다 | `panic in a function that cannot unwind`를 찍고 중단됐다 |
| Rust가 부른 C++ 함수가 예외를 던졌다 | `fatal runtime error: Rust cannot catch foreign exceptions, aborting` |

[C 코드를 지나가던 예외](#/read/cpp-advanced/iop-c-abi)와 달리 여기서는 결과가 정해져 있습니다. 조용히 새지 않고 죽습니다. 그래도 죽지 않으려면 양쪽 모두 **경계의 함수 안에서 잡아 값으로 바꿉니다.** C++ 쪽은 `guarded`, Rust 쪽은 `catch_unwind`입니다.

## 손으로 옮기지 않기

선언을 양쪽에 손으로 적는 일은 틀리기 쉽습니다. 이 일을 맡는 도구가 있습니다.

| 도구 | 하는 일 |
| --- | --- |
| bindgen | C 헤더를 읽어 Rust 쪽 선언을 만든다 |
| cbindgen | Rust 코드를 읽어 C 헤더를 만든다 |
| cxx | 경계를 한곳에 적으면 두 언어의 코드를 함께 만든다. `std::string`, `unique_ptr`, 예외와 `Result`를 이어 준다 |

<Note kind="warn">
이 셋은 돌려 보지 못했습니다. 바깥의 크레이트를 내려받아 빌드하는 일이 이 책의 환경에서 막혀 있었습니다. 위의 코드는 모두 `rustc`와 `g++`만으로 돌린 것입니다.
</Note>

두 언어를 한 프로그램에 넣을 때 정할 것이 하나 더 있습니다. **메모리는 준 쪽이 돌려받습니다.** Rust의 `Box`를 C++의 `delete`로, C++의 `new`를 Rust의 `drop`으로 없애면 안 됩니다. 두 언어의 할당자가 같다는 약속이 없습니다. `thermo_destroy`처럼 없애는 함수를 함께 내놓습니다.

## 정리

- Rust와 C++은 C ABI에서 만난다. 수와 포인터와 `#[repr(C)]` 구조체만 넘고, 문자열과 배열은 포인터와 길이로 풀어 넘긴다
- 양쪽 모두 상대의 선언을 손으로 옮겨 적으며 컴파일러는 그것이 맞는지 모른다. `unsafe`는 타입 하나에 가둔다
- 패닉과 예외는 경계에서 프로그램을 중단시킨다. 경계의 함수 안에서 잡아 오류 번호로 바꾼다
