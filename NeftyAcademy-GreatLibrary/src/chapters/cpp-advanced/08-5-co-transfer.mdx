[앞 페이지의 `Task`](#/read/cpp-advanced/co-task)는 `await_suspend` 안에서 `resume()`을 불렀습니다. 돌기는 하지만 기다림이 길게 이어지면 스택이 넘칩니다. 그 까닭과, 표준이 마련해 둔 길인 **대칭 전달**을 봅니다.

## 안에서 깨우면 스택이 쌓인다

코루틴 `many`가 곧바로 끝나는 코루틴 `one`을 되풀이해서 기다린다고 합시다. 한 번 기다릴 때마다 호출이 이렇게 이어집니다.

1. `many`의 `co_await`가 `await_suspend`를 부르고, 그 안에서 `one`을 `resume()`한다.
2. `one`이 끝나며 `Finish::await_suspend`를 부르고, 그 안에서 `many`를 `resume()`한다.
3. 깨어난 `many`가 루프를 돌아 다시 1로 간다. **앞의 호출들은 아직 돌아오지 않았다.**

`resume()`은 보통의 함수 호출입니다. 불린 코루틴이 멈추거나 끝나야 돌아옵니다. 그래서 기다림 한 번마다 스택에 프레임이 몇 개씩 남습니다. 아래 예제는 같은 타입을 두 방식으로 만들어 스택이 얼마나 깊어지는지를 잽니다. `Flat`이 `false`면 안에서 깨우고, `true`면 핸들을 돌려줍니다.

```cpp nosan flags=-O2
#include <coroutine>
#include <cstdint>
#include <exception>
#include <print>

std::uintptr_t deepest = 0;

[[gnu::noinline]] void note_depth()
{
    auto here = reinterpret_cast<std::uintptr_t>(__builtin_frame_address(0));
    if (here < deepest)
        deepest = here;
}

template <bool Flat>
struct Step {
    struct promise_type {
        // 기다리는 코루틴. 없으면 아무 일도 하지 않는 코루틴을 둔다
        std::coroutine_handle<> waiter = std::noop_coroutine();

        Step get_return_object()
        {
            return Step{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }

        struct Finish {
            bool await_ready() const noexcept { return false; }
            auto await_suspend(
                std::coroutine_handle<promise_type> me) const noexcept
            {
                std::coroutine_handle<> waiter = me.promise().waiter;
                if constexpr (Flat)
                    return waiter;     // 기다리던 쪽으로 건너간다
                else
                    waiter.resume();   // 기다리던 쪽을 안에서 부른다
            }
            void await_resume() const noexcept {}
        };
        Finish final_suspend() noexcept { return {}; }
    };

    bool await_ready() const noexcept { return false; }
    auto await_suspend(std::coroutine_handle<> caller) const noexcept
    {
        handle.promise().waiter = caller;
        if constexpr (Flat)
            return std::coroutine_handle<>{handle};   // 이 단계로 건너간다
        else
            handle.resume();                          // 이 단계를 안에서 부른다
    }
    void await_resume() const noexcept {}

    explicit Step(std::coroutine_handle<promise_type> h) : handle(h) {}
    Step(const Step&) = delete;
    ~Step() { handle.destroy(); }

    std::coroutine_handle<promise_type> handle;
};

template <bool Flat>
Step<Flat> one()
{
    note_depth();
    co_return;
}

template <bool Flat>
Step<Flat> many(int count)
{
    for (int i = 0; i < count; ++i)
        co_await one<Flat>();
}

template <bool Flat>
void measure(const char* what, int count)
{
    auto top = reinterpret_cast<std::uintptr_t>(__builtin_frame_address(0));
    deepest = top;
    Step<Flat> job = many<Flat>(count);
    job.handle.resume();
    std::println("{}: {}번 기다리는 동안 스택 {}바이트", what, count,
                 top - deepest);
}

int main()
{
    measure<false>("안에서 resume()", 1000);
    measure<false>("안에서 resume()", 5000);
    measure<true>("핸들을 돌려줌", 1000);
    measure<true>("핸들을 돌려줌", 5000);
}
```

```text
안에서 resume(): 1000번 기다리는 동안 스택 16064바이트
안에서 resume(): 5000번 기다리는 동안 스택 80064바이트
핸들을 돌려줌: 1000번 기다리는 동안 스택 80바이트
핸들을 돌려줌: 5000번 기다리는 동안 스택 80바이트
```

GCC 14에 `-O2`를 준 결과입니다. 안에서 깨우면 기다림 한 번에 16바이트씩 쌓입니다. 적어 보이지만 끝이 없습니다. 스택이 8 MB인 이 환경에서 40만 번은 돌았고 60만 번에서 세그멘테이션 오류로 죽었습니다. 네트워크에서 받은 조각이 이미 버퍼에 있어 기다림이 곧바로 끝나는 일이 수십만 번 이어지면 이렇게 됩니다.

## 핸들을 돌려준다

`await_suspend`는 세 가지를 돌려줄 수 있습니다.

| 반환 타입 | 뜻 |
| --- | --- |
| `void` | 멈춘다. 제어는 이 코루틴을 `resume()`한 곳으로 돌아간다 |
| `bool` | `false`를 돌려주면 멈추지 않고 그대로 이어 돈다 |
| `std::coroutine_handle<>` | 멈추고, 돌려준 코루틴을 **이어서** 깨운다 |

셋째가 대칭 전달입니다. 컴파일러는 돌려받은 핸들의 `resume()`을 **꼬리 호출**로 만듭니다. 지금 함수의 스택 프레임을 치운 다음 건너뛰므로 호출이 쌓이지 않습니다. 부른 쪽과 불린 쪽이라는 관계 없이 코루틴에서 코루틴으로 넘어간다고 해서 대칭이라 부릅니다.

깨울 코루틴이 없을 때 돌려주는 것이 `std::noop_coroutine()`입니다. 깨워도 아무 일을 하지 않고 곧바로 멈추는 코루틴이라, 제어가 맨 처음 `resume()`을 부른 곳으로 돌아갑니다.

앞 페이지의 `Task`도 같은 두 곳을 고치면 됩니다.

| 곳 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| `Task::await_suspend` | `handle_.resume();` | `return handle_;` |
| `Finish::await_suspend` | `waiter.resume();` | `return waiter;` (없으면 `std::noop_coroutine()`) |

## 컴파일러와 옵션에 달렸다

"꼬리 호출로 만든다"가 늘 지켜지는 것은 아닙니다. 위 프로그램에서 기다림 한 번에 쌓인 스택을 옵션을 바꿔 가며 쟀습니다. 단위는 바이트입니다.

| 컴파일 | 안에서 `resume()` | 핸들을 돌려줌 |
| --- | --- | --- |
| GCC 14 `-O2` | 16 | **0** |
| GCC 14 `-O1` | 32 | 48 |
| GCC 14 `-Og` | 48 | 48 |
| GCC 14 `-O0` | 272 | 128 |
| GCC 14 `-O0 -foptimize-sibling-calls` | 272 | **0** |
| GCC 14 `-O2 -fsanitize=address` | 640 | 576 |
| GCC 14 `-O2 -fsanitize=thread` | 96 | 96 |
| Clang 20 `-O0` | 576 | **0** |
| Clang 20 `-O2` | 32 | **0** |
| Clang 20 `-O0 -fsanitize=address` | 960 | **0** |

Clang 20은 어떤 옵션에서도 쌓이지 않았습니다. GCC 14는 **형제 호출 최적화가 켜졌을 때만** 쌓이지 않았습니다. 그 최적화(`-foptimize-sibling-calls`)는 `-O2`부터 켜지고, `-O0`에 그 옵션만 더해도 0이 됩니다. ASan이나 TSan을 켜면 `-O2`에서도 쌓였습니다. GCC의 버그 목록에 100897번으로 올라 있는 문제입니다.

그래서 GCC에서는 **릴리스 빌드에서 멀쩡하던 코드가 디버그 빌드나 새니타이저 빌드에서 스택 넘침으로 죽을 수 있습니다.** 대비는 둘입니다.

| 대비 | 방법 |
| --- | --- |
| 디버그 빌드에 옵션을 더한다 | `-O0 -foptimize-sibling-calls`. 새니타이저 빌드에는 듣지 않는다 |
| 곧바로 끝나는 기다림이 끝없이 이어지지 않게 한다 | 몇백 번에 한 번은 [줄로 돌아간다](#/read/cpp-advanced/co-task)(`co_await loop.later()`). 스택이 바닥까지 풀린다 |

<Note>
C++26 초안의 [`std::execution`](#/read/cpp-advanced/asy-execution)에서 코루틴과 센더를 잇는 부분은 대칭 전달을 쓰지 않아, 곧바로 끝나는 일이 이어지면 스택이 쌓인다는 지적이 위원회 문서(P2583)에 있습니다. 이 책에서 돌려 확인하지는 못했습니다.
</Note>

## 정리

- `await_suspend` 안에서 `resume()`을 부르면 기다림마다 스택이 쌓인다. 곧바로 끝나는 기다림이 길게 이어지면 넘친다
- `await_suspend`가 핸들을 돌려주면 컴파일러가 꼬리 호출로 건너뛴다. 깨울 것이 없으면 `std::noop_coroutine()`을 돌려준다
- Clang 20은 늘, GCC 14는 `-O2`에서만 쌓이지 않았다. GCC의 디버그·새니타이저 빌드에서는 깊은 사슬을 피한다
