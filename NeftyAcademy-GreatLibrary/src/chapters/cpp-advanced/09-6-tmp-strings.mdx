문자열 리터럴은 [템플릿 인자로 직접 넘길 수 없다](#/read/cpp-syntax/tpl-nontype)고 했고, 우회가 있다는 말만 해 두었습니다. 그 우회가 이 페이지의 첫째 주제입니다. 이어서 `std::format`이 [서식을 컴파일할 때 검사하는](#/read/cpp-stl/str-format) 방법을 직접 만들어 보고, 컴파일할 때 만든 문자열을 실행 파일에 담는 법을 봅니다.

## 문자열을 템플릿 인자로

```cpp
#include <algorithm>
#include <cstddef>
#include <print>
#include <string_view>

// 길이가 타입에 든 문자열. 템플릿 인자가 될 조건을 갖췄다
template <std::size_t N>
struct FixedString {
    char data[N] = {};

    constexpr FixedString(const char (&text)[N]) { std::copy_n(text, N, data); }
    constexpr std::string_view view() const { return {data, N - 1}; }
};

// 이름이 타입의 일부인 카운터
template <FixedString Name>
struct Counter {
    static inline int value = 0;
    static constexpr std::string_view name = Name.view();
    static void hit() { ++value; }
    static void report() { std::println("{}: {}번", name, value); }
};

// "글"_fs 로 FixedString을 만든다
template <FixedString S>
constexpr auto operator""_fs()
{
    return S;
}

int main()
{
    Counter<"rx">::hit();
    Counter<"rx">::hit();
    Counter<"tx">::hit();
    Counter<"rx">::report();
    Counter<"tx">::report();

    constexpr auto label = "status"_fs;
    std::println("{} ({}바이트)", label.view(), sizeof(label));
}
```

```text
rx: 2번
tx: 1번
status (7바이트)
```

C++20부터 템플릿 인자로 올 수 있는 클래스 타입의 조건은 "멤버가 모두 `public`이고 그 멤버들도 그런 타입"입니다. `char` 배열 하나를 가진 `FixedString`이 여기에 듭니다. `Counter<"rx">`라고 쓰면 리터럴 `"rx"`의 타입 `const char[3]`에서 `N`이 3으로 추론되고, 생성자가 글자를 복사해 넣은 **값**이 템플릿 인자가 됩니다.

`Counter<"rx">`와 `Counter<"tx">`는 서로 다른 타입입니다. 그래서 정적 변수가 따로이고, 이름은 실행 중에 어디서도 넘기지 않았습니다. 컴파일한 파일의 기호 이름을 보면 글자가 타입에 들어가 있습니다.

```text nocheck
Counter<FixedString<3ul>{char [3]{(char)114, (char)120}}>::value
```

114와 120이 `r`과 `x`입니다. 쓰임새는 이름으로 구분되는 것들을 **타입으로** 만드는 일입니다. 단위(`Unit<"m/s">`), 설정 항목, 통계 카운터가 그렇습니다. 값은 다음과 같습니다.

| 치르는 값 | 까닭 |
| --- | --- |
| 이름마다 클래스가 하나씩 만들어진다 | 코드와 정적 변수가 이름 수만큼 는다 |
| 이름을 실행 중에 정할 수 없다 | 템플릿 인자는 상수여야 한다 |
| 오류 메시지와 기호 이름에 글자가 숫자로 나온다 | 위의 꼴 그대로다 |

## 서식을 컴파일할 때 검사한다

`std::println("{:d}", "text")`가 컴파일 오류가 되는 원리는 이렇습니다. 서식 문자열을 받는 인자의 타입에 **`consteval` 생성자**가 있고, 그 생성자가 글을 읽어 검사합니다.

```cpp
#include <cstddef>
#include <print>
#include <string_view>
#include <type_traits>

constexpr std::size_t count_slots(std::string_view text)
{
    std::size_t slots = 0;
    for (std::size_t i = 0; i + 1 < text.size(); ++i)
        if (text[i] == '{' && text[i + 1] == '}')
            ++slots;
    return slots;
}

// 인자의 수를 타입으로 들고 있는 서식 문자열
template <typename... Args>
struct Pattern {
    std::string_view text;

    template <std::size_t N>
    consteval Pattern(const char (&literal)[N]) : text(literal, N - 1)
    {
        if (count_slots(text) != sizeof...(Args))
            throw "자리의 수와 인자의 수가 다르다";
    }
};

// type_identity_t: 첫 인자에서는 Args를 추론하지 않는다
template <typename... Args>
void log(Pattern<std::type_identity_t<Args>...> pattern, const Args&... args)
{
    std::println("[log] 서식 \"{}\", 인자 {}개", pattern.text, sizeof...(args));
}

int main()
{
    log("temp {} humid {}", 21.5, 40);
    log("start");
    // log("temp {} humid {}", 21.5);   // 컴파일 오류
}
```

```text
[log] 서식 "temp {} humid {}", 인자 2개
[log] 서식 "start", 인자 0개
```

주석을 풀면 GCC 14가 이렇게 말합니다.

```text nocheck
error: call to consteval function 'Pattern<double>("temp {} humid {}")'
       is not a constant expression
error: expression '<throw-expression>' is not a constant expression
   24 |             throw "자리의 수와 인자의 수가 다르다";
```

장치는 셋입니다.

| 장치 | 하는 일 |
| --- | --- |
| `consteval` 생성자 | 리터럴이 `Pattern`으로 바뀌는 일이 [반드시 컴파일할 때](#/read/cpp-syntax/ct-consteval) 일어난다 |
| 생성자 안의 `throw` | 상수식 안에서 `throw`에 닿으면 컴파일 오류다. 메시지가 오류 출력에 보인다 |
| `std::type_identity_t<Args>` | `Args`는 뒤의 인자들에서만 추론되고, 첫 인자는 그 결과를 받아 쓴다 |

셋째가 없으면 컴파일러가 첫 인자 `Pattern<…>`에서도 `Args`를 추론하려다 실패합니다. `std::format_string<Args...>`도 같은 모양으로 선언되어 있습니다.

## 컴파일할 때 만든 문자열을 꺼낸다

C++20부터 `std::string`과 `std::vector`를 상수식 안에서 쓸 수 있습니다. 다만 **컴파일이 끝날 때 남아 있으면 안 됩니다.** 컴파일할 때 잡은 힙은 실행 파일로 갈 수 없기 때문입니다.

```cpp
#include <algorithm>
#include <array>
#include <cstddef>
#include <print>
#include <string>
#include <string_view>

// 컴파일할 때 std::string으로 마음껏 만든다
constexpr std::string make_header()
{
    std::string line;
    for (std::string_view field : {"time", "temp", "humid", "press"}) {
        if (!line.empty())
            line += ',';
        for (char c : field)
            line += static_cast<char>(c >= 'a' && c <= 'z' ? c - 'a' + 'A' : c);
    }
    return line;
}

// 만든 것을 길이가 정해진 배열로 옮겨 담는다
template <auto Make>
constexpr auto materialized = [] {
    std::array<char, Make().size() + 1> out{};
    std::ranges::copy(Make(), out.begin());
    return out;
}();

constexpr std::string_view header{
    materialized<[] { return make_header(); }>.data()};

static_assert(header == "TIME,TEMP,HUMID,PRESS");

int main()
{
    std::println("{} ({}글자)", header, header.size());
}
```

```text
TIME,TEMP,HUMID,PRESS (21글자)
```

`make_header()`를 **두 번** 부르는 것이 요령입니다. 한 번은 길이를 알아내 배열의 크기로 쓰고, 한 번은 내용을 복사합니다. 둘 다 컴파일할 때의 일이고, 실행 파일에는 `TIME,TEMP,HUMID,PRESS`가 읽기 전용 데이터로 들어 있을 뿐입니다. 이 옮겨 담기를 건너뛰고 `constexpr std::string`을 전역에 두면 GCC 14는 이렇게 막습니다.

```text nocheck
error: ... is not a constant expression because it refers to a result of
       'operator new'
```

<Note kind="warn">
컴파일할 때의 계산은 느립니다. 단순한 루프 1천만 번이 GCC 14에서 23초와 1.7 GB, Clang 20에서 11초였습니다. 한 바퀴에 1~2 µs로, 실행할 때의 천 배입니다. 그래서 컴파일러에는 한계가 걸려 있습니다. GCC 14는 루프 262,144번에서 멈추고(`-fconstexpr-loop-limit=`), Clang 20은 계산 걸음 수로 세어 1백만 번은 지나가고 1천만 번에서 멈췄습니다(`-fconstexpr-steps=`). 큰 표나 파일은 컴파일할 때 계산하지 말고 빌드 단계에서 만들어 넣습니다. C++26의 `#embed`가 그 길이고, Clang 20은 확장으로 받아들였으며 GCC 14에는 없습니다.
</Note>

## 정리

- `char` 배열을 가진 구조체는 템플릿 인자가 될 수 있다. `Counter<"rx">`처럼 이름을 타입에 넣는다
- 서식 검사는 `consteval` 생성자가 한다. 인자 타입은 `type_identity_t`로 뒤의 인자에서만 추론하게 한다
- 상수식 안의 `std::string`은 밖으로 못 나온다. 길이를 먼저 구해 `std::array`에 옮겨 담는다
