export const summary = 'forward의 정체, 전달되지 않는 인자, 생성자를 가로채는 템플릿, 인자 타입마다 늘어나는 함수';

추론되는 `T&&`가 좌측값과 우측값을 모두 받고, `std::forward<T>`가 받은 그대로 넘긴다는 것은 [「인자 추론과 CTAD」](#/read/cpp-syntax/tpl-deduction)에서 봤습니다. 표준은 이것을 전달 참조(forwarding reference)라 하고, 그 이름이 생기기 전에 퍼진 이름이 보편 참조(universal reference)입니다. 같은 것입니다. 여기서는 그 안쪽과 가장자리를 봅니다.

## T에 적히는 것과 forward

```cpp
#include <print>
#include <string>
#include <type_traits>
#include <utility>

template <typename T>
std::string spell()
{
    std::string out = std::is_const_v<std::remove_reference_t<T>> ? "const " : "";
    out += "string";
    if (std::is_lvalue_reference_v<T>) out += "&";
    if (std::is_rvalue_reference_v<T>) out += "&&";
    return out;
}

template <typename T>
constexpr T&& my_forward(std::remove_reference_t<T>& x) noexcept
{
    return static_cast<T&&>(x);         // forward 는 이 형 변환 한 줄이다
}

const char* store(const std::string&) { return "복사해서 보관"; }
const char* store(std::string&&) { return "옮겨서 보관"; }

template <typename T>
void relay(T&& x)
{
    std::println("T = {:<14} T&& = {:<15} {}", spell<T>(), spell<T&&>(),
                 store(my_forward<T>(x)));
}

int main()
{
    std::string name = "n";
    const std::string fixed = "f";
    relay(name);
    relay(fixed);
    relay(std::string("t"));
    relay(std::move(name));
    relay(std::move(fixed));
}
```

```text
T = string&        T&& = string&         복사해서 보관
T = const string&  T&& = const string&   복사해서 보관
T = string         T&& = string&&        옮겨서 보관
T = string         T&& = string&&        옮겨서 보관
T = const string   T&& = const string&&  복사해서 보관
```

`x`라는 식은 [이름이 있으므로 언제나 lvalue](#/read/cpp-advanced/mv-categories)입니다. 원래 무엇이었는지는 `T`에만 남아 있습니다. 그래서 `forward`에는 `T`를 손으로 적어 줘야 하고, `forward`가 하는 일은 `static_cast<T&&>`뿐입니다. `T`가 `string&`이면 `string& &&`가 접혀 `string&`(lvalue 그대로), `T`가 `string`이면 `string&&`(xvalue)가 됩니다. `const`도 `T`에 실려 그대로 건너갑니다. 마지막 줄이 복사인 것은 전달이 틀려서가 아니라 [`const`는 옮길 수 없어서](#/read/cpp-syntax/sm-elision)입니다.

## 직접 부르는 것과 똑같지는 않다

"완벽" 전달이라고 부르지만 건너가지 못하는 것이 있습니다. 첫째는 prvalue의 생략입니다.

```cpp
#include <print>
#include <utility>

struct Tracer {
    Tracer() = default;
    Tracer(const Tracer&) { std::println("  복사"); }
    Tracer(Tracer&&) noexcept { std::println("  이동"); }
};

void store(Tracer) {}

template <typename T>
void relay(T&& x) { store(std::forward<T>(x)); }

int main()
{
    std::println("직접 부른다");
    store(Tracer());            // prvalue 가 매개변수 자리에 바로 만들어진다
    std::println("거쳐서 부른다");
    relay(Tracer());            // 참조에 묶으려고 임시 객체가 되었다가 옮겨진다
}
```

```text
직접 부른다
거쳐서 부른다
  이동
```

참조로 받는 순간 prvalue는 [임시 객체가 됩니다](#/read/cpp-advanced/mv-categories). 그래서 포장을 한 겹 거칠 때마다 이동이 한 번 듭니다. 둘째는 **타입을 추론할 수 없거나, 추론한 타입이 원래 뜻과 다른** 인자입니다.

| 인자 | 직접 부를 때 | 전달 참조를 거치면 |
| --- | --- | --- |
| `{1, 2, 3}` | 매개변수 타입으로 초기화된다 | 오류. 중괄호만으로는 `T`를 정할 수 없다 |
| `0`, `NULL` | 널 포인터로 바뀐다 | `int`(`long`)로 추론되어 포인터 자리에서 오류 |
| 오버로드된 함수 이름 | 매개변수 타입을 보고 고른다 | 오류. 어느 것인지 정할 수 없다 |
| 비트 필드 | 값이 복사된다 | 오류. 비트 필드에는 참조를 묶을 수 없다 |

```cpp
#include <print>
#include <utility>
#include <vector>

void take_vec(const std::vector<int>& v) { std::println("{}", v.size()); }
void take_ptr(int* p) { std::println("{}", p == nullptr); }
void twice(int x) { std::println("{}", x * 2); }
void twice(double x) { std::println("{}", x * 2); }
void apply_int(void (*f)(int)) { f(21); }
void take_uint(unsigned v) { std::println("{}", v); }

struct Flags {
    unsigned ready : 1;
    unsigned level : 3;
};

template <typename F, typename... Args>
void call(F&& f, Args&&... args)
{
    std::forward<F>(f)(std::forward<Args>(args)...);
}

int main()
{
    Flags flags{1, 5};
    call(take_vec, std::vector{1, 2, 3});       // {1, 2, 3} 대신 타입을 적는다
    call(take_ptr, nullptr);                    // 0 대신 nullptr
    // 어느 twice 인지 적는다
    call(apply_int, static_cast<void (*)(int)>(twice));
    call(take_uint, +flags.level);              // + 를 붙여 값(prvalue)으로 만든다
}
```

```text
3
true
42
5
```

`std::make_unique<T>(…)`와 `emplace_back(…)`도 같은 제약을 받습니다. 이 둘은 인자를 [괄호로](#/read/cpp-stl/mem-make) 생성자에 넘기므로 `std::make_unique<std::vector<int>>(3, 7)`은 3과 7이 아니라 7이 세 개인 벡터입니다.

## 생성자를 가로채는 전달 참조

전달 참조는 **무엇이든** 받고, 받은 것과 타입이 정확히 맞습니다. 생성자에 쓰면 복사 생성자의 일을 빼앗습니다.

```cpp nocheck
class Person {
public:
    template <typename T>
    explicit Person(T&& name) : name_(std::forward<T>(name)) {}
private:
    std::string name_;
};

Person a("kim");
Person b(a);    // 오류: std::string 을 Person& 로 만들 수 없다
```

`a`는 `const`가 아닌 lvalue입니다. 복사 생성자 `Person(const Person&)`는 `const`를 붙여야 맞지만 템플릿은 `T = Person&`로 **그대로** 맞으므로 템플릿이 이깁니다. `const Person`을 넘기면 복사 생성자가 불려서, 어떤 때는 되고 어떤 때는 안 됩니다. 받을 것을 [콘셉트](#/read/cpp-syntax/con-requires)로 좁힙니다.

```cpp
#include <concepts>
#include <print>
#include <string>
#include <utility>

class Person {
public:
    // std::string 을 만들 수 있는 것만 받는다. Person 은 여기에 맞지 않는다
    template <typename T>
        requires std::constructible_from<std::string, T>
    explicit Person(T&& name) : name_(std::forward<T>(name)) {}

    const std::string& name() const { return name_; }

private:
    std::string name_;
};

int main()
{
    std::string label = "kim";
    Person a(label);                // 복사해서 보관
    Person b(std::move(label));     // 옮겨서 보관
    Person c("lee");                // const char* 에서 바로. 임시 string 도 없다
    Person d(a);                    // 복사 생성자가 불린다
    std::println("{} {} {} {}", a.name(), b.name(), c.name(), d.name());
}
```

```text
kim kim lee kim
```

보관할 인자가 하나뿐이면 [값으로 받아 옮기는 쪽](#/read/cpp-syntax/sm-move)이 더 간단합니다. 전달 참조 생성자는 `c`처럼 임시 객체 하나까지 아껴야 할 때 씁니다.

## 한 번만 전달한다

`std::forward<T>(x)`는 우측값으로 온 인자에 대해서는 `std::move(x)`입니다. 두 번 쓰면 두 번째는 [이미 옮겨 간 것](#/read/cpp-advanced/mv-moved-from)을 넘깁니다.

```cpp
#include <memory>
#include <print>
#include <utility>
#include <vector>

std::vector<std::unique_ptr<int>> first, second;

template <typename T>
void store_both(T&& item)
{
    first.push_back(std::forward<T>(item));
    second.push_back(std::forward<T>(item));    // 이미 옮겨 간 것을 또 넘긴다
}

int main()
{
    store_both(std::make_unique<int>(7));
    std::println("{} {}", first[0] != nullptr, second[0] != nullptr);
}
```

```text
true false
```

여러 곳에 넘겨야 하면 마지막 한 곳에만 `forward`를 쓰고 나머지에는 `item`을 그대로 넘깁니다. clang-tidy의 `bugprone-use-after-move`가 이 꼴을 "used after it was forwarded"로 알려 줍니다.

<Note>
돌려주는 것까지 그대로 넘기려면 반환 타입을 `decltype(auto)`로 적습니다. `auto`는 참조를 떼어 내고 값으로 돌려주지만, `decltype(auto)`는 부른 함수가 `int&`를 돌려주면 `int&`를 돌려줍니다. `return std::invoke(std::forward<F>(f), std::forward<Args>(args)...);`가 그 꼴입니다.
</Note>

## 인자의 타입마다 함수가 하나씩 생긴다

전달 참조의 `T`에는 값 범주와 `const`가 실리므로, 같은 `std::string`도 `string&`, `const string&`, `string`으로 세 벌이 만들어집니다. 글자열 리터럴은 더합니다. `"ab"`의 타입은 `const char[3]`, `"abc"`는 `const char[4]`여서 **길이가 다르면 다른 함수**입니다.

| 같은 일을 하는 `add` | 리터럴 8개(길이가 모두 다름)를 넘겼을 때 | 실행 코드 크기 |
| --- | --- | --- |
| `template <typename T> void add(T&& name)` | 함수 8개 (하나에 828바이트) | 10,401바이트 |
| `void add(std::string_view name)` | 함수 1개 | 4,146바이트 |

`names.emplace_back(…)` 한 줄을 감싼 함수를 GCC 14 `-O2`, x86-64에서 잰 값입니다. 전달 참조는 `make_unique`나 `emplace_back`처럼 **무엇이 올지 모르는 채로 그대로 넘겨야 하는** 포장에 씁니다. 받을 타입이 정해진 보통 함수는 `std::string_view`, `const T&`, 값 가운데서 고릅니다.

## 정리

- `std::forward<T>(x)`는 `static_cast<T&&>(x)`다. 원래의 범주와 `const`는 `T`에 적혀 있다
- 중괄호, `0`, 오버로드된 이름, 비트 필드는 전달되지 않고, prvalue의 생략도 건너가지 못한다
- 전달 참조 생성자는 콘셉트로 좁히고, `forward`는 한 번만 쓰고, 그대로 넘기는 포장에만 쓴다
