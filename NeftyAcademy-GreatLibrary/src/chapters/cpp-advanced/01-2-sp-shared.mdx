[「shared_ptr과 weak_ptr」](#/read/cpp-stl/mem-shared)에서 `shared_ptr`가 포인터 둘(객체, 제어 블록)이라는 것을 봤습니다. 주인의 수를 세는 것 말고 제어 블록이 하는 일이 더 있고, 그것이 `shared_ptr`를 `unique_ptr`와 다른 도구로 만듭니다.

## 지우는 방법을 기억한다

제어 블록은 `shared_ptr`가 **처음 만들어질 때** 생기고, 그때의 타입으로 "어떻게 지울지"를 적어 둡니다. 그 뒤에 포인터의 타입이 바뀌어도 그 기록은 그대로입니다.

```cpp
#include <memory>
#include <print>

struct Base {
    ~Base() { std::println("  ~Base"); }       // 가상이 아니다
};
struct Derived : Base {
    ~Derived() { std::println("  ~Derived"); }
};

int main()
{
    std::println("shared_ptr<Base> 에 담은 Derived");
    {
        const std::shared_ptr<Base> p = std::make_shared<Derived>();
    }
    std::println("shared_ptr<void> 에 담은 Derived");
    {
        const std::shared_ptr<void> p = std::make_shared<Derived>();
    }
}
```

```text
shared_ptr<Base> 에 담은 Derived
  ~Derived
  ~Base
shared_ptr<void> 에 담은 Derived
  ~Derived
  ~Base
```

소멸자가 가상이 아닌데도 `~Derived`가 불렸습니다. `shared_ptr<void>`조차 제대로 지웁니다. 제어 블록에 "이것은 `Derived`로 만들어졌다"가 들어 있기 때문입니다. 같은 일을 `unique_ptr<Base>`로 하면 `~Base`만 불리고, 그것은 [정의되지 않은 동작](#/read/cpp-advanced/sp-unique)입니다.

이 성질에서 쓰임새가 나옵니다.

- **타입을 숨긴 핸들.** 헤더에는 `std::shared_ptr<void>`나 `shared_ptr<Interface>`만 내놓고, 실제 타입과 지우는 방법은 `.cpp`에 둡니다
- **삭제자가 타입에 없다.** `std::shared_ptr<std::FILE>(f, closer)`의 타입은 삭제자가 무엇이든 `shared_ptr<FILE>`입니다. 삭제자를 바꿔도 인터페이스가 그대로입니다

그렇다고 가상 소멸자를 빼도 된다는 뜻은 아닙니다. 그 클래스를 누가 `unique_ptr`나 맨 포인터로 다룰지 알 수 없습니다. 다형적인 기반 클래스의 소멸자는 여전히 가상으로 둡니다.

## 별칭 생성자

제어 블록과 가리키는 대상은 **따로** 정할 수 있습니다. `shared_ptr<T>(주인, 포인터)`는 `주인`의 제어 블록을 함께 쓰면서 `포인터`를 가리키는 `shared_ptr`를 만듭니다.

```cpp
#include <memory>
#include <print>
#include <string>
#include <vector>

struct Device {
    std::string name;
    std::vector<int> samples;

    ~Device() { std::println("  ~Device {}", name); }
};

int main()
{
    auto device = std::make_shared<Device>("adc0", std::vector<int>{1, 2, 3});

    // samples 만 가리키지만, Device 전체의 주인 노릇을 한다
    const std::shared_ptr<std::vector<int>> samples(device, &device->samples);
    std::println("주인 수 {} {}", device.use_count(), samples.use_count());

    device.reset();
    std::println("device 를 놓았다. samples 의 크기 {}", samples->size());
}
```

```text
주인 수 2 2
device 를 놓았다. samples 의 크기 3
  ~Device adc0
```

`samples`를 받은 쪽은 `Device`라는 타입을 몰라도 됩니다. 그런데도 `samples`가 살아 있는 한 `Device` 전체가 살아 있습니다. 큰 객체의 한 부분만 다른 모듈에 넘기면서 수명을 묶을 때, 그리고 버퍼 하나를 잘라 여러 조각으로 나눠 줄 때(조각마다 원본 버퍼의 주인이 됩니다) 씁니다.

조심할 것은 이 생성자가 **아무 검사도 하지 않는다**는 점입니다. 둘째 인자로 전혀 상관없는 포인터를 줘도 컴파일됩니다. 주인이 살아 있는 동안 유효한 포인터만 넘깁니다.

## 계수는 언제 원자적인가

주인 수를 올리고 내리는 일은 여러 스레드가 동시에 해도 안전해야 하므로 원자적 연산입니다. 그런데 libstdc++는 **프로그램이 아직 스레드를 만든 적이 없으면** 보통의 덧셈으로 대신합니다. 재어 보면 차이가 큽니다.

```cpp
#include <chrono>
#include <memory>
#include <print>
#include <thread>

double copy_cost()
{
    const auto p = std::make_shared<int>(1);
    const int rounds = 20'000'000;
    long sink = 0;
    const auto start = std::chrono::steady_clock::now();
    for (int i = 0; i < rounds; ++i) {
        const std::shared_ptr<int> copy = p;        // 올리고, 블록 끝에서 내린다
        sink += *copy;
    }
    const auto took = std::chrono::steady_clock::now() - start;
    return std::chrono::duration<double, std::nano>(took).count() / rounds
         + (sink == 0);
}

int main()
{
    std::println("스레드를 만들기 전  {:5.1f} ns", copy_cost());
    std::thread worker([] {});
    worker.join();
    std::println("한 번 만들고 난 뒤  {:5.1f} ns", copy_cost());
}
```

```text nocheck
스레드를 만들기 전    1.0 ns
한 번 만들고 난 뒤   16.6 ns
```

x86-64, GCC 14 `-O2`에서 잰 값입니다. 스레드를 하나 만들었다가 끝낸 것만으로 복사 한 번이 16배 비싸졌고, 그 뒤로는 되돌아가지 않습니다. 두 가지를 알려 줍니다.

- **스레드 없는 작은 프로그램으로 `shared_ptr`를 재면 실제보다 훨씬 싸게 나옵니다.** 벤치마크가 실제 프로그램과 같은 조건인지 확인합니다
- 스레드를 쓰는 프로그램에서 `shared_ptr`의 복사는 16ns짜리 일입니다. 한 코어에서 그렇고, 여러 코어가 같은 계수를 건드리면 [캐시 줄을 주고받느라](#/read/cpp-advanced/atm-false-sharing) 더 듭니다

이것은 libstdc++의 구현이 그렇다는 것이고 표준이 정한 동작은 아닙니다.

## 제어 블록을 어디에 두나

| 만드는 법 | 할당 | 제어 블록 |
| --- | --- | --- |
| `std::make_shared<T>(...)` | 한 번 | 객체와 한 덩어리 |
| `std::shared_ptr<T>(new T)` | 두 번 | 따로 |
| `std::allocate_shared<T>(할당자, ...)` | 할당자에게 한 번 | 객체와 한 덩어리, 할당자가 준 메모리에 |

[`make_shared`의 득실](#/read/cpp-stl/mem-make)은 앞에서 봤습니다. 셋째가 힙을 피하는 길입니다. [`pmr` 자원](#/read/cpp-stl/mem-allocator)을 넘기면 객체와 제어 블록이 그 자원에서 나옵니다.

```cpp
#include <array>
#include <cstddef>
#include <cstdlib>
#include <memory>
#include <memory_resource>
#include <new>
#include <print>

static int allocations = 0;
void* operator new(std::size_t n)
{
    ++allocations;
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

int main()
{
    std::array<std::byte, 256> buffer;
    std::pmr::monotonic_buffer_resource arena(buffer.data(), buffer.size(),
                                              std::pmr::null_memory_resource());
    allocations = 0;
    const std::pmr::polymorphic_allocator<int> allocator(&arena);
    const auto value = std::allocate_shared<int>(allocator, 42);
    std::println("힙 할당 {}번, 값 {}", allocations, *value);
}
```

```text
힙 할당 0번, 값 42
```

`shared_ptr`의 타입은 여전히 `std::shared_ptr<int>`입니다. 할당자도 삭제자처럼 제어 블록 속에 숨습니다. 그래서 받는 쪽은 그것이 스택 버퍼에서 왔는지 알 수 없고, **모든 `shared_ptr`와 `weak_ptr`가 버퍼보다 먼저 사라지게** 하는 것은 만든 쪽의 책임입니다.

<Note>
`std::shared_ptr` 객체 **하나**를 여러 스레드가 함께 고치는 것은 계수가 원자적이어도 경합입니다. 설정을 통째로 갈아 끼우는 것처럼 그래야 할 때는 `std::atomic<std::shared_ptr<T>>`(C++20)를 씁니다. GCC 14에서 확인하니 이것은 `is_lock_free()`가 `false`입니다. 안에서 짧은 잠금을 씁니다. 읽는 쪽이 아주 많은 자리의 다른 방법은 [「락 없는 자료 구조의 기초」](#/read/cpp-advanced/atm-lockfree)에서 봅니다.
</Note>

## 정리

- 제어 블록은 만들어질 때의 타입으로 지우는 방법을 기억한다. `shared_ptr<Base>`나 `shared_ptr<void>`로 바뀌어도 원래 타입의 소멸자가 불린다
- 별칭 생성자는 한 객체의 일부를 가리키면서 전체를 붙든다. 제어 블록과 가리키는 대상은 따로 정해진다
- 계수를 고치는 값은 스레드가 생긴 뒤에야 제값이 된다. libstdc++에서 1ns가 16ns가 됐다
