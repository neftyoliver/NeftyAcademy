[「새니타이저와 경고」](#/read/cpp-syntax/ubc-tools)에서 새니타이저 넷의 이름과 켜는 법을 봤습니다. 날마다 쓰려면 세 가지를 더 알아야 합니다. 얼마나 느려지는가, 무엇을 **놓치는가**, 그리고 찾아낸 오류가 테스트를 실패시키게 하려면 무엇을 켜야 하는가입니다.

## 값

배열 계산, 할당이 많은 낱말 세기, 뮤텍스를 쓰는 스레드 둘, 이렇게 세 구간으로 된 프로그램을 빌드만 바꿔 돌렸습니다. x86-64, GCC 14 `-O2 -g`입니다.

| 빌드 | 배열 | 할당 | 스레드 |
| --- | --- | --- | --- |
| 그냥 | 0.21 s | 0.36 s | 0.24 s |
| `-fsanitize=address` | 0.23 s | 1.19 s | 0.25 s |
| `-fsanitize=undefined` | 0.28 s | 0.48 s | 0.22 s |
| `-fsanitize=address,undefined` | 0.40 s | 1.65 s | 0.22 s |
| `-fsanitize=thread` | 0.85 s | 1.90 s | 3.90 s |
| Valgrind (그냥 빌드한 것을) | 2.18 s | 4.42 s | 0.63 s |

- **ASan의 값은 할당에 붙습니다.** 배열을 도는 계산은 1.1배, `new`와 `delete`가 많은 구간은 3.3배입니다. 메모리는 23 MB에서 124 MB로 다섯 배가 됩니다(TSan 81 MB, Valgrind 192 MB).
- **UBSan은 1.3배쯤입니다.** ASan과 함께 켜도 2~5배 안이어서, 둘을 묶은 빌드를 평소의 테스트 빌드로 삼을 만합니다.
- **TSan은 스레드가 잠그고 푸는 구간에서 16배입니다.** 따로 빌드해 따로 돌립니다.
- **Valgrind는 10배 넘게 느립니다.** 다시 컴파일할 수 없는 것을 볼 때 씁니다.

## 넷이 함께 놓치는 것

```cpp norun
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <vector>

struct Record {
    char name[8];
    int id;
};

int main(int argc, char** argv)
{
    const std::size_t extra = argc > 1 ? std::strtoul(argv[1], nullptr, 10) : 4;

    // 1. 같은 객체 안에서 넘친다: name을 지나 id를 덮는다
    Record record{"sensor", 7};
    std::memset(record.name, 'x', sizeof record.name + extra);
    std::printf("1. id = %d\n", record.id);

    // 2. 멀리 건너뛴다: 한 배열의 번호로 다른 배열의 한가운데를 쓴다
    int* a = new int[8]{};
    int* b = new int[8]{};
    const std::ptrdiff_t far = b - a;          // 실행해 봐야 아는 거리
    a[far + 3] = 99;
    std::printf("2. b[3] = %d\n", b[3]);

    // 3. 크기는 넘고 용량은 넘지 않는다
    std::vector<int> v;
    v.reserve(8);
    v.push_back(1);
    v.data()[5] = 42;
    std::printf("3. v.size() = %zu\n", v.size());

    // 4. 초기화하지 않은 값으로 갈래를 정한다
    int limit;
    if (argc > 2) limit = std::atoi(argv[2]);
    std::printf("4. %s\n", limit > 100 ? "크다" : "작다");

    delete[] a;
    delete[] b;
}
```

```text nocheck
$ g++ -std=c++23 -g -fsanitize=address,undefined miss.cpp -o miss && ./miss; echo $?
1. id = 2021161080
2. b[3] = 99
3. v.size() = 1
4. 작다
0
```

오류 넷이 한 줄도 걸리지 않았고 종료 코드도 0입니다.

| 놓친 것 | 까닭 | 잡는 것 |
| --- | --- | --- |
| 1. 같은 객체 안에서 넘쳤다 | ASan은 객체와 객체 **사이**에만 독을 둔다. `name`과 `id` 사이에는 없다 | 길이를 아는 타입. `std::array`, `std::span` |
| 2. 번호가 멀리 건너뛰었다 | 독을 넘어 다른 객체의 한가운데에 닿으면 정상으로 보인다 | 컨테이너와 [`_GLIBCXX_ASSERTIONS`](#/read/cpp-stl/impl-debug) |
| 3. 크기는 넘고 용량은 안 넘었다 | 할당받은 메모리 안이다 | `-D_GLIBCXX_SANITIZE_VECTOR`. `container-overflow`로 잡혔다. libc++는 기본으로 잡는다 |
| 4. 초기화하지 않은 값을 읽었다 | ASan과 UBSan은 값이 쓰인 적이 있는지 따라가지 않는다 | `-O2 -Wall`의 경고, MSan, Valgrind |

넷째는 Clang의 MSan이 `use-of-uninitialized-value … miss.cpp:37`로, Valgrind가 `Conditional jump or move depends on uninitialised value(s)`로 알렸습니다. 다만 MSan은 표준 라이브러리까지 MSan으로 빌드해야 합니다. 그러지 않고 위의 낱말 세기를 돌렸더니 `std::string` 안에서 없는 오류를 알렸습니다. 리눅스에서는 Valgrind가 손이 덜 갑니다.

다섯째로 놓치는 것이 가장 큽니다. 새니타이저는 **실행된 코드만** 봅니다. 한 번도 지나가지 않은 갈래의 오류는 어떤 빌드에서도 조용합니다. 그 갈래를 지나가게 하는 일이 [테스트와 퍼징](#/read/cpp-advanced/tool-testing)입니다.

## 실패가 실패로 보이게

```cpp norun
#include <climits>
#include <cstdio>
int main(int argc, char**)
{
    int big = INT_MAX;
    big += argc;                    // 부호 있는 정수가 넘친다
    std::printf("%d\n", big);
}
```

```text nocheck
$ g++ -g -fsanitize=undefined ub.cpp -o ub && ./ub; echo $?
ub.cpp:6:9: runtime error: signed integer overflow: 2147483647 + 1 cannot be
represented in type 'int'
-2147483648
0
```

UBSan은 알리고 **계속 갑니다.** 종료 코드가 0이어서, 출력을 사람이 읽지 않는 CI에서는 통과로 셉니다. `-fno-sanitize-recover=all`로 빌드하거나 `UBSAN_OPTIONS=halt_on_error=1`로 돌리자 종료 코드가 1이 됐습니다. ASan은 처음부터 멈춥니다.

| 옵션 | 하는 일 |
| --- | --- |
| `-g -fno-omit-frame-pointer` | 보고서의 호출 스택에 파일과 줄 번호가 나온다 |
| `-fno-sanitize-recover=all` | UBSan이 첫 오류에서 멈춘다 |
| `ASAN_OPTIONS=detect_leaks=1` | 끝날 때 새는 메모리를 알린다. 리눅스에서는 기본으로 켜져 있다 |
| `UBSAN_OPTIONS=print_stacktrace=1` | UBSan도 호출 스택을 찍는다 |
| `TSAN_OPTIONS=halt_on_error=1` | [경쟁](#/read/cpp-advanced/atm-atomic)을 하나 찾으면 멈춘다 |

## 함께 켜는 조합

ASan과 UBSan은 한 빌드에 켭니다. TSan과 MSan은 다른 것과 함께 켜지 못합니다.

```text nocheck
$ g++ -fsanitize=address,thread -c a.cpp
cc1plus: error: '-fsanitize=thread' is incompatible with '-fsanitize=address'
$ clang++ -fsanitize=address,memory -c a.cpp
clang++: error: invalid argument '-fsanitize=address' not allowed with
'-fsanitize=memory'
```

그래서 테스트 빌드는 둘이 됩니다. [프리셋](#/read/cpp-syntax/mod-cmake)에 이름을 붙여 두고 [CI](#/read/cpp-advanced/tool-ci)에서 둘 다 돌립니다.

| 빌드 | 옵션 | 돌리는 것 |
| --- | --- | --- |
| 주소와 UB | `-fsanitize=address,undefined -fno-sanitize-recover=all` | 모든 테스트. 평소의 개발 빌드 |
| 스레드 | `-fsanitize=thread` | 스레드를 쓰는 테스트 |

<Note>
보드에서는 새니타이저를 돌릴 메모리가 없습니다. 그래서 [하드웨어를 뺀 로직](#/read/cpp-advanced/des-injection)을 PC에서 빌드해 여기의 빌드로 테스트합니다. 장치에 닿는 부분을 얇게 두는 까닭 가운데 하나가 이것입니다.
</Note>

## 정리

- ASan은 할당이 많은 코드에서 3배, UBSan은 1.3배, TSan은 잠금이 많은 코드에서 16배다. ASan과 UBSan을 묶어 평소에 쓴다
- 객체 안의 넘침, 멀리 건너뛴 번호, 용량 안의 벡터 접근, 초기화하지 않은 값은 ASan과 UBSan이 놓쳤다. 실행되지 않은 코드는 아무도 못 본다
- UBSan은 알리고 계속 간다. `-fno-sanitize-recover=all`을 줘야 테스트가 실패한다
