export const summary = '만들기·넘기기·훑기를 잰 값, unique_ptr가 공짜가 아닌 곳, 고르는 순서';

스마트 포인터의 값을 한자리에 모으고, 그것을 바탕으로 무엇을 고를지 정리합니다. 수치는 x86-64 서버, GCC 14 `-O2`, [스레드가 있는 프로그램](#/read/cpp-advanced/sp-shared)에서 잰 것입니다.

## 만들고 버리기

| 방법 | 한 번 | 하는 일 |
| --- | --- | --- |
| 스택의 값 | 0.6 ns | 스택 포인터를 옮긴다 |
| `new`와 `delete` | 12.8 ns | 힙 할당 한 번 |
| `std::make_unique` | 12.8 ns | 위와 같다 |
| `std::make_shared` | 14.8 ns | 힙 할당 한 번과 계수 |
| `std::shared_ptr<T>(new T)` | 29.7 ns | 힙 할당 두 번과 계수 |

`make_unique`는 손으로 쓴 `new`와 `delete`에 **아무것도 더하지 않습니다.** `make_shared`는 2ns를 더하고, 따로 할당하면 두 배가 됩니다. 그리고 가장 큰 차이는 맨 윗줄과 나머지 사이에 있습니다. **힙에 두는 것 자체가 20배입니다.** 스마트 포인터의 종류보다 "포인터가 필요한가"가 먼저입니다.

이 표를 재면서 알게 된 것이 하나 있습니다. 처음에는 `make_unique`가 0.5ns로 나왔습니다. 만든 객체가 함수 밖으로 나가지 않으니 컴파일러가 **할당을 통째로 지운** 것입니다. `unique_ptr`는 컴파일러가 속을 다 들여다볼 수 있을 만큼 얇습니다. `make_shared`는 같은 조건에서도 15ns 그대로였습니다. 제어 블록과 원자적 계수는 지워지지 않습니다. 위의 수치는 포인터를 밖으로 내보여 지우지 못하게 하고 다시 잰 것입니다.

## 넘기기

| 일 | 한 번 |
| --- | --- |
| `shared_ptr` 복사 (올리고 내리기) | 16.6 ns |
| `weak_ptr::lock()` (확인하고 올리고 내리기) | 23.2 ns |
| `shared_ptr` 이동, `unique_ptr` 이동 | 잴 수 없을 만큼 작다 |
| `*p`, `p->` | 맨 포인터와 같다 |

복사는 비싸고 이동은 공짜에 가깝습니다. [값으로 받은 `shared_ptr`를 멤버에 `std::move`로 넣으라](#/read/cpp-advanced/sp-passing)는 까닭이 이 표입니다.

`unique_ptr`가 맨 포인터보다 비싼 곳이 한 군데 있습니다. **함수에 값으로 넘길 때**입니다.

```cpp nocheck
int use_raw(int* p);
int use_unique(std::unique_ptr<int> p);

int call_raw(int* p) { return use_raw(p); }
int call_unique(std::unique_ptr<int> p) { return use_unique(std::move(p)); }
```

`-O2`로 컴파일한 어셈블리를 보면 `call_raw`는 `jmp` 명령 **하나**입니다. `call_unique`는 스무 줄이 넘습니다. 포인터를 스택에 내려놓고, 그 주소를 넘기고, 돌아온 뒤에 "아직 비지 않았으면 지운다"를 확인합니다. 리눅스의 호출 규약이 소멸자가 있는 객체를 레지스터로 넘기지 못하게 하기 때문입니다. 호출 한 번에 몇 ns이고 대부분의 코드에서는 보이지 않지만, "`unique_ptr`는 맨 포인터와 완전히 같다"는 말은 여기서 틀립니다. 아주 자주 불리는 안쪽 함수가 객체를 **쓰기만** 한다면 참조로 받는 것이 이쪽에서도 맞습니다.

## 훑기

객체 200만 개를 한 번씩 읽었습니다.

| 담은 방법 | 걸린 시간 |
| --- | --- |
| `std::vector<Item>` | 2.5 ms |
| `std::vector<std::unique_ptr<Item>>` | 10.7 ms |
| `std::vector<std::shared_ptr<Item>>` | 11.7 ms |

포인터로 담으면 네 배 느립니다. 스마트 포인터의 탓이 아니라 **한 번 더 건너가야** 하기 때문입니다. 값은 메모리에 나란히 있고, 포인터가 가리키는 객체는 힙 여기저기에 있습니다. 이 예제는 객체를 차례로 할당해서 그나마 가까이 모여 있는 경우입니다. 오래 돌아 힙이 흩어진 프로그램에서는 차이가 더 벌어집니다. 캐시 이야기는 [「캐시와 자료 배치」](#/read/cpp-advanced/perf-cache)에서 자세히 합니다.

## 크기

| 타입 | 자신 | 딸린 것 |
| --- | --- | --- |
| `T` | `sizeof(T)` | 없다 |
| `T*`, `T&` | 8 | 없다 |
| `std::unique_ptr<T>` | 8 | 힙의 객체. glibc에서는 블록 하나가 적어도 32바이트다 |
| `std::shared_ptr<T>`, `std::weak_ptr<T>` | 16 | 힙의 객체와 제어 블록 16~24바이트 |
| `enable_shared_from_this`를 물려받은 `T` | 16 더 | |

8바이트짜리 객체 하나를 `make_shared`로 만들면 포인터 16바이트에 힙 블록 32바이트(제어 블록 16, 객체 8, 할당기의 몫 8), 합쳐 48바이트입니다. 여섯 배입니다. 작은 객체를 수백만 개 다루는 자리에서는 이 배수가 메모리를 정합니다.

## 고르는 순서

위에서부터 내려오며, 처음 맞는 것을 씁니다.

| 물음 | 맞으면 |
| --- | --- |
| 값으로 둘 수 있는가 (크기가 정해져 있고, 다형성이 필요 없고, 옮겨도 된다) | 값. 멤버로, 지역 변수로, `vector<T>`로 |
| 없을 수도 있을 뿐인가 | [`std::optional<T>`](#/read/cpp-stl/voc-optional) |
| 종류가 몇 가지로 정해져 있는가 | [`std::variant`](#/read/cpp-stl/voc-variant) |
| 주인이 하나인가 | `std::unique_ptr<T>` |
| 주인이 정말 여럿이고, 누가 마지막일지 알 수 없는가 | `std::shared_ptr<T>` |

그리고 가리키기만 하는 쪽은 스마트 포인터를 쓰지 않습니다.

| 가리키기만 한다 | 쓰는 것 |
| --- | --- |
| 대상이 나보다 오래 산다는 것이 구조로 보장된다 | `T&`, `T*` |
| 대상이 먼저 사라질 수 있고, 그것을 알아야 한다 | `std::weak_ptr<T>` |
| 여러 원소를 본다 | [`std::span<T>`](#/read/cpp-stl/seq-span), [`std::string_view`](#/read/cpp-stl/str-view) |

`shared_ptr`를 기본으로 삼는 코드가 흔합니다. 누가 지울지 생각하지 않아도 되기 때문입니다. 치르는 것은 수치만이 아닙니다.

- **수명이 코드에서 사라집니다.** 객체가 언제 지워지는지를 읽어서 알 수 없고, 돌려 봐야 압니다
- **지워지는 스레드가 정해지지 않습니다.** [마지막으로 놓는 쪽](#/read/cpp-advanced/sp-weak)의 스레드에서 소멸자가 돕니다
- **순환이 가능해집니다.** `unique_ptr`만 쓰는 구조에서는 고리를 만들 수가 없습니다
- **공유된 것을 고치게 됩니다.** 여럿이 같은 객체를 고칠 수 있으면 잠금이 필요해집니다. 함께 가져야 한다면 `shared_ptr<const T>`로 고치지 못하게 나눠 갖는 것이 대개 맞습니다

<Note>
힙이 작거나 없는 기기에서는 표의 윗줄들이 더 중요해집니다. 값과 [고정 용량 컨테이너](#/read/cpp-stl/mem-uninit), 그리고 [풀에 되돌리는 `unique_ptr`](#/read/cpp-advanced/sp-unique)로 대부분을 짜고, `shared_ptr`는 원자적 연산과 제어 블록의 값을 알고서 꼭 필요한 곳에만 둡니다. 원자적 연산이 하드웨어에 없는 작은 CPU에서는 계수 한 번이 인터럽트를 잠깐 막는 일이 됩니다.
</Note>

## 정리

- 가장 큰 값은 힙에 두는 것 자체다. `make_unique`는 `new`와 같고, `make_shared`는 거기에 계수가, 따로 할당하면 할당이 한 번 더 붙는다
- `shared_ptr`의 복사는 16ns, 이동은 공짜에 가깝다. 포인터로 담은 컨테이너는 값으로 담은 것보다 네 배 느리게 훑어졌다
- 값, `optional`, `variant`, `unique_ptr`, `shared_ptr`의 순서로 내려오며 처음 맞는 것을 쓴다. 가리키기만 하는 쪽은 참조와 맨 포인터다
