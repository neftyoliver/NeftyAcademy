이 책은 소유권은 타입에 적고, 자원은 RAII에 맡기고, 재지 않고는 빠르다고 말하지 않았습니다. 그런 판단을 규칙의 목록으로 모아 둔 문서가 **C++ Core Guidelines**입니다. 2015년에 공개됐고 Bjarne Stroustrup과 Herb Sutter가 엮으며, 누구나 읽고 고칠 수 있게 GitHub에 있습니다.

## 짜임

2026년 11월 2일의 문서를 스크립트로 세어 보니 규칙이 열다섯 갈래에 445개였습니다. 클래스(C) 100개, 식과 문장(ES) 66개, 템플릿(T) 54개, 함수(F) 40개, 동시성(CP) 33개 순으로 많습니다. 번호는 `갈래.번호` 꼴이고, 이 책에서 까닭을 본 것이 많습니다.

| 규칙 | 뜻 | 이 책에서 |
| --- | --- | --- |
| R.1 | 자원은 핸들과 RAII로 저절로 관리한다 | [RAII 래퍼](#/read/cpp-advanced/res-wrapper) |
| C.20, C.21 | 기본 연산은 되도록 정의하지 않고, 하나를 정의하면 모두 정의한다 | [0의 규칙](#/read/cpp-advanced/des-zero) |
| F.7, R.30 | 수명에 관여하지 않는 함수는 `T*`나 `T&`로 받는다 | [넘기는 법](#/read/cpp-advanced/sp-passing) |
| I.4 | 인터페이스의 타입은 정확하고 강하게 | [인터페이스 설계](#/read/cpp-advanced/des-interface) |
| CP.20, CP.21 | 잠금은 객체에 맡기고, 여럿은 `scoped_lock`으로 | [교착](#/read/cpp-advanced/sync-deadlock) |
| CP.100 | 꼭 필요하지 않으면 락 없는 코드를 쓰지 않는다 | [락 없는 구조](#/read/cpp-advanced/atm-lockfree) |
| Per.6 | 재지 않고 성능을 말하지 않는다 | [벤치마크](#/read/cpp-advanced/perf-measure) |
| I.27 | ABI를 지켜야 하면 pimpl을 생각한다 | [pimpl](#/read/cpp-advanced/te-pimpl) |

규칙 하나는 까닭(Reason), 예, 그리고 **강제하는 법**(Enforcement)으로 이루어집니다. 마지막 것이 이 문서의 성격을 정합니다. 읽고 외우라는 문서가 아니라 도구가 대신 지켜 보게 하려는 문서입니다. 445개 가운데 강제하는 법이 적힌 규칙은 319개였고, 70개는 그 자리에 `???`만 있었습니다.

## 도구로 돌려 보기

```cpp
#include <cstdio>
#include <cstdlib>

#define MAX_SAMPLES 8

struct Log {
    int* samples;
    int count;
    Log() { samples = (int*)malloc(sizeof(int) * MAX_SAMPLES); }
    ~Log() { free(samples); }
};

int average(int* data, int n)
{
    long sum = 0;
    for (int i = 0; i < n; i++)
        sum += data[i];
    return sum / n;
}

int main()
{
    Log log;
    int raw[MAX_SAMPLES] = {21, 22, 24, 23, 22, 21, 20, 23};
    for (int i = 0; i < MAX_SAMPLES; i++)
        log.samples[i] = raw[i];
    log.count = MAX_SAMPLES;
    printf("평균 %d\n", average(raw, log.count));
}
```

```text
평균 22
```

`-Wall -Wextra -Wpedantic`에서 두 컴파일러 모두 경고가 없고 새니타이저도 조용합니다. [clang-tidy](#/read/cpp-advanced/tool-static) 20에는 이름이 `cppcoreguidelines-`로 시작하는 검사가 41개 있습니다. 그것만 켜고 돌리자 0.06초 만에 경고 26개가 나왔습니다.

```text nocheck
$ clang-tidy old.cpp -checks='-*,cppcoreguidelines-*' -- -std=c++23
old.cpp:6:8: warning: class 'Log' defines a non-default destructor but does not
    define a copy constructor, a copy assignment operator, a move constructor or a
    move assignment operator [cppcoreguidelines-special-member-functions]
old.cpp:9:29: warning: do not manage memory manually; consider a container or a
    smart pointer [cppcoreguidelines-no-malloc]
old.cpp:18:12: warning: narrowing conversion from 'long' to signed type 'int' is

```

검사별로 모으면 이렇습니다.

| 검사 | 규칙 | 경고 |
| --- | --- | --- |
| `no-malloc`, `owning-memory` | R.10, I.11, R.3 | 4 |
| `special-member-functions` | C.21 | 1 |
| `pro-type-member-init`, `prefer-member-initializer` | Type.6, C.49 | 2 |
| `pro-bounds-` 셋 | Bounds.1, 2, 3 | 4 |
| `pro-type-cstyle-cast`, `pro-type-vararg` | Type.4, Type.8 | 2 |
| `narrowing-conversions` | ES.46 | 1 |
| `macro-usage`, `macro-to-enum` | ES.31, Enum.1 | 3 |
| `avoid-c-arrays` | SL.con.1 | 1 |
| `avoid-magic-numbers` | ES.45 | 8 |

- **버그를 가리키는 경고가 있습니다.** C.21을 따라 `main`에 `Log backup = log;` 한 줄을 넣어 봤습니다. ASan은 `double-free`를 냈고, 최적화한 보통 빌드는 `평균 22`를 찍고 0으로 끝났습니다.
- **소음도 있습니다.** 가장 많은 여덟 개는 시험 데이터의 숫자마다 붙은 `avoid-magic-numbers`입니다. 검사는 골라서 켭니다.

같은 일을 규칙대로 쓰면 경고가 하나도 남지 않습니다.

```cpp
#include <gsl/gsl>

#include <array>
#include <numeric>
#include <print>
#include <span>
#include <vector>

int average(std::span<const int> data)
{
    Expects(!data.empty());                             // 미리 지킬 조건
    const long sum = std::accumulate(data.begin(), data.end(), 0L);
    return gsl::narrow<int>(sum / std::ssize(data));    // 값이 달라지면 던진다
}

int main()
{
    const std::array raw{21, 22, 24, 23, 22, 21, 20, 23};
    const std::vector<int> log(raw.begin(), raw.end());
    std::println("평균 {}", average(log));
}
```

```text
평균 22
```

## GSL

`<gsl/gsl>`은 규칙을 지키는 데 쓰라고 문서가 정해 둔 작은 라이브러리(Guidelines Support Library)입니다. 여기서는 Microsoft의 구현 4.0을 배포판 패키지 `libmsgsl-dev`로 깔아 썼습니다. 헤더뿐인 라이브러리입니다.

| 조각 | 하는 일 | 표준에서는 |
| --- | --- | --- |
| `not_null<T>` | 널이 아닌 포인터 | 없다 |
| `span<T>` | 번호를 늘 검사하는 `span` | `std::span`. 검사는 [경화](#/read/cpp-advanced/safe-hardening)를 켜야 한다 |
| `narrow<T>`, `narrow_cast<T>` | 값이 달라지면 던지는 변환, 일부러 자른다는 표시 | 없다 |
| `Expects`, `Ensures` | 거짓이면 프로그램을 끝낸다 | C++26 초안의 [계약](#/read/cpp-advanced/safe-contracts) |
| `finally` | 나갈 때 할 일 | [스코프 가드](#/read/cpp-advanced/res-guard) |

```cpp
#include <gsl/gsl>

#include <print>
#include <vector>

struct Sensor {
    int id;
};

// 널이 아니라는 약속이 타입에 있다. 받는 쪽은 검사를 적지 않는다
int read(gsl::not_null<const Sensor*> sensor) { return sensor->id; }

int main()
{
    const Sensor sensor{7};
    std::println("read: {}", read(&sensor));

    try {
        const long big = 3'000'000'000;
        std::println("{}", gsl::narrow<int>(big));
    } catch (const gsl::narrowing_error&) {
        std::println("narrow: 값이 달라져서 던졌다");
    }
    std::println("narrow_cast: {}", gsl::narrow_cast<int>(3'000'000'000));

    const auto bye = gsl::finally([] { std::println("finally: 나갈 때 불렸다"); });
    const std::vector<int> v{1, 2, 3};
    std::println("at: {}", gsl::at(v, 2));
}
```

```text
read: 7
narrow: 값이 달라져서 던졌다
narrow_cast: -1294967296
at: 3
finally: 나갈 때 불렸다
```

`read(nullptr)`은 지워진 생성자에 걸려 컴파일되지 않습니다. 널인 포인터 변수를 넘기면 그 자리에서 `terminate`가 불리고 종료 코드 134로 끝났습니다. 원소가 셋인 배열의 `[3]`을 읽자 `std::span`은 0을 찍고 계속 갔고, `gsl::span`은 끝냈습니다.

검사의 값을 쟀습니다. 원소 4,096개짜리 배열에서 원소 하나에 드는 시간(ns)이고, 여섯 번 가운데 가장 작은 값입니다.

| 일 (GCC 14) | 검사 없이 | GSL |
| --- | --- | --- |
| 차례로 읽기, `span` | 0.26 | 0.25 |
| 섞인 번호를 따라 읽기, `span` | 0.26 | 0.26 |
| 포인터 따라가기, `not_null` | 0.26 | 0.27 |
| `long`을 `int`로, `narrow` | 0.25 | 0.26 |
| 같은 일을 `-O3`로 | 0.13 | 0.27 |

`-O2`에서는 차이를 재기 어렵습니다. 번호가 범위 안이라는 것을 루프 조건이 말해 주면 검사가 지워지고, 남은 검사도 늘 같은 쪽으로 가는 [분기](#/read/cpp-advanced/perf-branch)라서 쌉니다. 값이 드러난 곳은 마지막 줄 하나입니다. 던질 수 있는 검사가 [벡터화](#/read/cpp-advanced/perf-simd)를 막았습니다. Clang 20의 `-O2`에서는 좁히기와 `not_null`이 0.22에서 0.27이 됐고 나머지는 같았습니다.

## 프로파일과 들여오기

문서는 규칙 가운데 도구가 기계적으로 가릴 수 있는 것을 **프로파일**로 묶습니다. 다 지키면 한 종류의 오류가 생기지 않는다고 말할 수 있게 하려는 묶음입니다. 타입(Type.1~8), 범위(Bounds.1~4), 수명(Lifetime.1)이 있고, 위 표의 `pro-type-`과 `pro-bounds-`가 앞의 둘을 옮긴 검사입니다. 수명은 [다음 페이지](#/read/cpp-advanced/safe-profiles)에서 봅니다.

- **버그를 가리키는 것부터 켭니다.** 소유권, 초기화, C.21이 먼저이고 취향에 가까운 것은 나중입니다. [CI](#/read/cpp-advanced/tool-ci)에서는 새로 생긴 경고만 막습니다.
- **예외는 그 줄에 까닭과 함께 적습니다.** `// NOLINTNEXTLINE(검사 이름): 까닭`이 그 표기입니다.

<Note>
문서는 예외를 `[[gsl::suppress("bounds.1")]]`로 적습니다. clang-tidy 20은 이 표기를 듣지 않아서 경고가 그대로 나왔고, `NOLINT`로 적어야 했습니다.
</Note>

## 정리

- Core Guidelines는 까닭과 강제하는 법이 붙은 규칙 445개다. 외우는 문서가 아니라 도구로 돌리는 문서다
- 컴파일러 경고가 없던 코드에서 clang-tidy가 26개를 찾았고 그중 하나는 이중 해제로 이어졌다. 여덟은 소음이었다. 검사는 골라서 켠다
- GSL의 `not_null`, `narrow`, `span`은 약속을 타입에 적는다. 잰 값은 `-O2`에서 차이가 없었고 벡터화가 막힌 한 곳에서만 두 배였다
