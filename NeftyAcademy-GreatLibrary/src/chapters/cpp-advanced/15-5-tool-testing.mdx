[정적 분석](#/read/cpp-advanced/tool-static)은 값에 달린 오류를 못 보고, [새니타이저](#/read/cpp-advanced/tool-sanitizers)는 실행된 코드만 봅니다. 코드를 실제로 지나가게 하는 일이 테스트입니다. 사람이 쓰는 테스트와 기계가 만드는 테스트를 차례로 봅니다.

## 단위 테스트

[의존성 주입](#/read/cpp-advanced/des-injection)에서 만든 `Thermostat`을 GoogleTest 1.14로 시험합니다. 그때 손으로 쓴 가짜 센서와 시계는 gmock이 만들어 줍니다.

```cpp nocheck
// tests/test_thermostat.cpp
#include "thermostat.h"

#include <gmock/gmock.h>
#include <gtest/gtest.h>

using namespace std::chrono_literals;
using testing::Return;

// 가짜 객체는 gmock이 만들어 준다. 어떤 함수를 흉내 낼지만 적는다
struct MockSensor : Sensor {
    MOCK_METHOD(double, celsius, (), (override));
};
struct MockClock : Clock {
    MOCK_METHOD(Time, now, (), (const, override));
};

// 테스트마다 새로 만들어지는 준비물
class ThermostatTest : public testing::Test {
protected:
    void at(std::chrono::seconds elapsed, double celsius)
    {
        ON_CALL(clock, now()).WillByDefault(Return(Time{} + elapsed));
        ON_CALL(sensor, celsius()).WillByDefault(Return(celsius));
    }

    testing::NiceMock<MockSensor> sensor;
    testing::NiceMock<MockClock> clock;
    Thermostat thermostat{sensor, clock, 20.0};
};

TEST_F(ThermostatTest, TurnsOnWhenCold)
{
    at(0s, 18.0);
    EXPECT_TRUE(thermostat.update());
}

TEST_F(ThermostatTest, KeepsStateForSixtySeconds)
{
    at(0s, 18.0);
    thermostat.update();
    at(30s, 21.5);
    EXPECT_TRUE(thermostat.update()) << "30초에는 아직 바꾸면 안 된다";
    at(60s, 21.5);
    EXPECT_FALSE(thermostat.update()) << "60초가 지났으면 꺼야 한다";
}

TEST_F(ThermostatTest, StaysOnWhileStillCold)
{
    at(0s, 18.0);
    thermostat.update();
    at(90s, 18.5);
    EXPECT_TRUE(thermostat.update());
}

TEST_F(ThermostatTest, ReadsSensorOncePerUpdate)
{
    EXPECT_CALL(sensor, celsius()).Times(1).WillOnce(Return(18.0));
    thermostat.update();
}
```

```cmake
find_package(GTest REQUIRED)
add_executable(test_thermostat tests/test_thermostat.cpp)
target_link_libraries(test_thermostat PRIVATE thermostat GTest::gmock_main)

include(GoogleTest)
gtest_discover_tests(test_thermostat)      # TEST 하나하나가 ctest의 테스트가 된다
```

```text nocheck

2/4 Test #2: ThermostatTest.KeepsStateForSixtySeconds ...   Passed    0.00 sec
3/4 Test #3: ThermostatTest.StaysOnWhileStillCold .......   Passed    0.00 sec
4/4 Test #4: ThermostatTest.ReadsSensorOncePerUpdate ....   Passed    0.00 sec

```

`TEST_F`는 테스트마다 `ThermostatTest` 객체를 새로 만듭니다. 앞 테스트가 남긴 상태가 다음 테스트에 닿지 않습니다. `EXPECT_CALL`은 값을 돌려주게 할 뿐 아니라 **몇 번 불렸는지**를 검사합니다.

조건의 `>=`를 `>`로 바꿔 버그를 심어 봤습니다.

```text nocheck
tests/test_thermostat.cpp:45: Failure
Value of: thermostat.update()
  Actual: true
Expected: false
60초가 지났으면 꺼야 한다
[  FAILED  ] ThermostatTest.KeepsStateForSixtySeconds (0 ms)
```

정확히 60초를 넣어 본 테스트가 잡았습니다. 61초를 넣었다면 지나쳤을 버그입니다.

| 좋은 단위 테스트 | 여기서는 |
| --- | --- |
| 빠르다 | 넷이 0.01초다. 저장할 때마다 돌릴 수 있다 |
| 결과가 정해져 있다 | 시계와 센서를 넣어 주므로 실제 시간과 온도에 달리지 않는다 |
| 경계를 본다 | 59초도 61초도 아닌 60초 |
| 실패하면 까닭이 보인다 | 테스트 하나가 한 가지만 보고, 메시지가 무엇을 기대했는지 말한다 |

[예외를 n번째에서 던져 보는 시험](#/read/cpp-advanced/res-exception)도 반복문째로 `TEST` 하나에 넣습니다.

## 커버리지가 알려 주는 것

`--coverage`로 빌드해 테스트를 돌리면 어느 줄과 갈래가 실행됐는지 남습니다. 위에서 셋째 테스트를 빼고 `gcov -b`를 돌린 결과입니다.

```text nocheck
File 'include/thermostat.h'
Lines executed:87.50% of 16
Taken at least once:68.75% of 16
        5:   27:        if (want != heating_ && (!switched_ || …)) {
branch  0 taken 5 (fallthrough)
branch  1 taken 0
```

`branch 1 taken 0`은 `want != heating_`이 거짓인 길, 곧 **이미 원하는 상태일 때**를 한 번도 지나가지 않았다는 뜻입니다. 그래서 `StaysOnWhileStillCold`를 더했고 갈래는 75%가 됐습니다.

실행되지 않았다는 두 줄은 인터페이스의 가상 소멸자입니다. 채우려고 애쓸 줄이 아닙니다. 커버리지는 **시험하지 않은 곳**을 알려 주는 도구이고, 100%가 "잘 시험했다"를 뜻하지는 않습니다. 줄을 지나가기만 하고 결과를 검사하지 않는 테스트도 숫자는 올립니다.

## 퍼징

사람은 자기가 떠올린 입력만 시험합니다. 퍼저는 입력을 조금씩 바꿔 가며 수만 번 넣고, 새로운 갈래에 닿은 입력을 간직해 거기서 다시 바꿉니다.

```cpp nocheck
// unescape.cpp
#include "unescape.h"

namespace {
int hex_value(char c)
{
    if (c >= '0' && c <= '9') return c - '0';
    if (c >= 'a' && c <= 'f') return c - 'a' + 10;
    if (c >= 'A' && c <= 'F') return c - 'A' + 10;
    return 0;
}
}

std::string unescape(std::string_view text)
{
    std::string out;
    for (std::size_t i = 0; i < text.size(); ++i) {
        if (text[i] != '\\' || i + 1 == text.size()) {
            out += text[i];
            continue;
        }
        const char kind = text[++i];
        if (kind == 'n') out += '\n';
        else if (kind == 't') out += '\t';
        else if (kind == 'x') {
            // 버그: 뒤에 두 글자가 남았는지 보지 않는다
            const int high = hex_value(text[i + 1]);
            const int low = hex_value(text[i + 2]);
            out += static_cast<char>(high * 16 + low);
            i += 2;
        } else out += kind;
    }
    return out;
}
```

손으로 쓴 테스트 다섯(`a\nb`, `\x41\x42`, 끝에 홀로 선 `\` 등)은 ASan과 UBSan을 켜고도 통과했습니다. 퍼저에 물릴 함수는 이것뿐입니다.

```cpp nocheck
// fuzz_unescape.cpp: 퍼저가 만든 바이트 열을 그대로 넣어 본다
#include "unescape.h"

#include <cstddef>
#include <cstdint>

extern "C" int LLVMFuzzerTestOneInput(const std::uint8_t* data, std::size_t size)
{
    const std::string_view text(reinterpret_cast<const char*>(data), size);
    const std::string result = unescape(text);
    if (result.size() > text.size()) __builtin_trap();   // 풀면 길어질 수 없다
    return 0;
}
```

```text nocheck
$ clang++ -g -O1 -fsanitize=fuzzer,address,undefined \
      unescape.cpp fuzz_unescape.cpp -o fuzz
$ ./fuzz
==9016==ERROR: AddressSanitizer: heap-buffer-overflow …
READ of size 1 at 0x7bac1e60074a thread T0
    #0 … in unescape(std::basic_string_view<char>) unescape.cpp:28:39
artifact_prefix='./'; Test unit written to ./crash-…
```

0.15초, 33,800번쯤 만에 찾았습니다. `./fuzz -minimize_crash=1 crash-…`로 줄이자 입력은 두 글자 `\x`가 됐습니다. 문자열이 `\x`로 끝나면 없는 두 글자를 읽습니다. 고친 뒤에는 16초 동안 269만 번을 넣어도 조용했습니다.

- **퍼저는 새니타이저와 함께 씁니다.** 퍼저가 입력을 만들고, 오류를 알아보는 것은 ASan과 UBSan입니다.
- **성질도 검사합니다.** 위의 `__builtin_trap()`처럼 "풀면 길어질 수 없다", "두 구현의 결과가 같다" 같은 것을 적어 두면 죽지 않는 버그도 걸립니다.
- **찾은 입력은 단위 테스트로 남깁니다.** `EXPECT_EQ(unescape("\\x"), "x")`가 같은 버그의 재발을 막습니다.
- **물릴 곳은 바깥에서 오는 입력을 해석하는 코드입니다.** 통신 프레임, 파일 형식, 명령줄입니다.

<Note>
`-fsanitize=fuzzer`(libFuzzer)는 Clang에만 있습니다. GCC 14는 `unrecognized argument to '-fsanitize=' option: 'fuzzer'`로 거절합니다. 제품은 GCC로 빌드하더라도 퍼징용 빌드만 Clang으로 하면 됩니다.
</Note>

## 정리

- 테스트마다 준비물을 새로 만들고, 가짜 객체로 시계와 센서를 정해 주고, 경계값을 넣는다. `>=`를 `>`로 바꾼 버그를 60초 정각의 테스트가 잡았다
- 커버리지는 시험하지 않은 갈래를 짚어 준다. 숫자를 채우는 것이 목표는 아니다
- 손으로 쓴 테스트 다섯이 통과한 함수에서 퍼저가 0.15초 만에 넘쳐 읽기를 찾았다. 찾은 입력은 단위 테스트로 남긴다
