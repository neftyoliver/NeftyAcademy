멤버 함수 안에서 "나를 가리키는 `shared_ptr`"가 필요할 때가 있습니다. 나중에 불릴 콜백에 나 자신을 넘겨, 그때까지 살아 있게 하려는 경우입니다. `std::shared_ptr<T>(this)`라고 쓰면 [제어 블록이 하나 더 생겨](#/read/cpp-stl/mem-shared) 두 번 지워집니다. 표준이 준 답이 `std::enable_shared_from_this`입니다.

## 쓰는 법

```cpp
#include <functional>
#include <memory>
#include <print>

class Session : public std::enable_shared_from_this<Session> {
public:
    // 생성자를 숨기고, shared_ptr 로만 만들어지게 한다
    static std::shared_ptr<Session> create(int id)
    {
        return std::shared_ptr<Session>(new Session(id));
    }
    ~Session() { std::println("  ~Session {}", id_); }

    // 나중에 불릴 콜백. 콜백이 살아 있는 동안 세션도 살아 있다
    std::function<void()> make_reply()
    {
        return [self = shared_from_this()] {
            std::println("  세션 {} 이 답한다", self->id_);
        };
    }

    // 세션이 그때까지 살아 있을 때만 일하는 콜백
    std::function<void()> make_optional_reply()
    {
        return [weak = weak_from_this()] {
            if (const auto self = weak.lock())
                std::println("  세션 {} 이 답한다", self->id_);
            else
                std::println("  세션이 이미 없다");
        };
    }

private:
    explicit Session(int id) : id_(id) {}
    int id_;
};

int main()
{
    std::function<void()> later;
    {
        const auto session = Session::create(7);
        later = session->make_reply();
        std::println("주인 수 {}", session.use_count());
    }
    std::println("블록을 나왔다");
    later();
    later = nullptr;                // 콜백을 버리면 세션도 지워진다

    std::function<void()> optional;
    {
        const auto session = Session::create(8);
        optional = session->make_optional_reply();
        optional();
    }
    optional();
}
```

```text
주인 수 2
블록을 나왔다
  세션 7 이 답한다
  ~Session 7
  세션 8 이 답한다
  ~Session 8
  세션이 이미 없다
```

| 멤버 함수 | 주는 것 | 쓰는 곳 |
| --- | --- | --- |
| `shared_from_this()` | 나를 가리키는 `shared_ptr`. 이미 있는 주인들과 제어 블록을 함께 쓴다 | "이 일이 끝날 때까지 나를 살려 둔다" |
| `weak_from_this()` (C++17) | 나를 지켜보는 `weak_ptr` | "그때 내가 살아 있으면 한다" |

네트워크 서버가 전형적인 쓰임입니다. 연결 하나가 세션 객체이고, "읽기가 끝나면 이 함수를 불러 달라"고 맡긴 콜백이 세션을 붙들고 있습니다. 누가 세션을 지울지 따로 관리하지 않아도, **걸려 있는 일이 하나도 없게 되는 순간** 저절로 지워집니다.

두 콜백 가운데 무엇을 쓸지는 뜻으로 정합니다. 답장을 꼭 마쳐야 하면 붙들고(`shared_from_this`), 주인이 떠났으면 그만둬도 되는 일(화면 갱신, 주기적 점검)은 지켜봅니다(`weak_from_this`). [멤버에 저장하는 콜백](#/read/cpp-advanced/sp-weak)에는 언제나 뒤의 것을 씁니다.

## 원리

`enable_shared_from_this<T>`는 `weak_ptr<T>` 하나를 멤버로 가진 기반 클래스입니다. 이 멤버를 채우는 것은 클래스 자신이 아니라 **`shared_ptr`의 생성자**입니다. `shared_ptr`가 객체를 처음 맡을 때 "이 타입이 `enable_shared_from_this`를 물려받았는가"를 보고, 그렇다면 그 `weak_ptr`가 방금 만든 제어 블록을 가리키게 합니다. `shared_from_this()`는 그 `weak_ptr`를 `shared_ptr`로 바꿔 돌려줄 뿐입니다.

여기서 조건이 모두 나옵니다.

```cpp
#include <memory>
#include <print>

struct Widget : std::enable_shared_from_this<Widget> {
    int value = 0;
};
struct Empty {};

int main()
{
    std::println("{} {} {}", sizeof(Empty), sizeof(int), sizeof(Widget));

    Widget on_stack;                // shared_ptr 가 맡은 적이 없다
    try {
        const auto self = on_stack.shared_from_this();
    } catch (const std::bad_weak_ptr& e) {
        std::println("예외: {}", e.what());
    }
    std::println("weak_from_this 는 만료된 것을 준다 {}",
                 on_stack.weak_from_this().expired());

    const auto owned = std::make_shared<Widget>();
    std::println("{}", owned->shared_from_this() == owned);
}
```

```text
1 4 24
예외: bad_weak_ptr
weak_from_this 는 만료된 것을 준다 true
true
```

| 조건 | 어기면 |
| --- | --- |
| 객체가 `shared_ptr`의 것이어야 한다 | 스택이나 `unique_ptr`의 객체에서 부르면 `std::bad_weak_ptr` 예외 |
| **생성자 안에서 부를 수 없다** | 생성자가 도는 동안에는 아직 `shared_ptr`가 맡기 전이다. 같은 예외가 난다 |
| `public`으로 상속해야 한다 | `class`의 기본인 `private` 상속이면 `shared_ptr`가 알아보지 못해 늘 예외가 난다 |
| 객체가 16바이트 커진다 | 위에서 `int` 하나짜리가 24바이트가 됐다 |

둘째 조건이 자주 걸립니다. "만들어지자마자 자기를 어딘가에 등록하는" 클래스는 생성자에서 `shared_from_this()`를 부르고 싶어집니다. 그럴 때는 위의 `create()`처럼 **공장 함수**를 두고, 객체를 `shared_ptr`로 만든 다음 줄에서 등록합니다.

## shared_ptr로만 만들게 하기

스택에 만든 객체에서 `shared_from_this()`를 부르면 실행 중에야 예외로 드러납니다. 처음부터 그렇게 만들 수 없게 막는 편이 낫습니다. 생성자를 `private`으로 두면 되는데, 그러면 `std::make_shared`도 생성자를 부를 수 없습니다. 열쇠 노릇을 하는 타입을 써서 풉니다.

```cpp
#include <memory>
#include <print>

class Session : public std::enable_shared_from_this<Session> {
    // 이 타입은 Session 안에서만 만들 수 있다
    struct Key {
        explicit Key() = default;
    };

public:
    // 생성자는 public 이지만, Key 가 없으면 부를 수 없다
    Session(Key, int id) : id_(id) {}

    static std::shared_ptr<Session> create(int id)
    {
        return std::make_shared<Session>(Key{}, id);    // 할당 한 번
    }
    int id() const { return id_; }

private:
    int id_;
};

int main()
{
    const auto session = Session::create(7);
    std::println("{} {}", session->id(), session->shared_from_this() == session);
    // Session direct(Session::Key{}, 1);     // 컴파일 오류: Key 는 private
}
```

```text
7 true
```

첫 예제의 `std::shared_ptr<Session>(new Session(id))`는 객체와 제어 블록을 따로 할당합니다. 이 열쇠 꼴은 [`make_shared`의 한 번짜리 할당](#/read/cpp-stl/mem-make)을 그대로 씁니다. 세션이 초당 수천 개 만들어지는 서버에서는 이 차이가 보입니다.

<Note kind="warn">
`shared_from_this()`로 콜백마다 자신을 붙드는 설계는 편한 만큼 **수명이 코드에서 보이지 않게** 됩니다. 세션이 언제 지워지는지가 "걸려 있는 콜백이 다 끝났을 때"가 되어, 끝나지 않는 콜백 하나가 세션을 영영 붙들 수 있습니다. 종료할 때 모든 연결을 끊는 일도 어려워집니다. 붙드는 콜백에는 반드시 끝나는 길(타임아웃, 취소)을 마련하고, 주인이 분명한 구조라면 [소유자가 수명을 정하고](#/read/cpp-advanced/res-ownership) 콜백은 약하게 지켜보는 쪽을 먼저 생각합니다.
</Note>

## 정리

- 멤버 함수 안에서 자기 자신의 `shared_ptr`는 `shared_from_this()`로 얻는다. `shared_ptr<T>(this)`는 두 번 지운다
- 객체가 `shared_ptr`의 것일 때만, 생성자가 끝난 뒤에만 쓸 수 있다. 공장 함수와 열쇠 타입으로 그렇게만 만들어지게 막는다
- 붙드는 콜백(`shared_from_this`)은 일이 끝날 때까지 객체를 살리고, 지켜보는 콜백(`weak_from_this`)은 살아 있을 때만 일한다
