export const summary = '할당자가 갖출 다섯 가지, n번째 할당을 실패시키는 할당자로 하는 시험, 상태 있는 할당자와 이동 대입';

컨테이너의 [숨은 템플릿 인자](#/read/cpp-stl/ov-allocator)인 할당자를 직접 만듭니다. 쓰임새는 둘을 봅니다. 하나는 [예외 안전을 시험할 때](#/read/cpp-advanced/res-exception) 약속한 "n번째 할당에서 실패하는 할당자"이고, 다른 하나는 상태를 가진 할당자가 컨테이너의 이동을 어떻게 바꾸는가입니다.

## 갖춰야 할 다섯 가지

C++11부터 할당자가 직접 갖출 것은 적습니다. 나머지는 `std::allocator_traits`가 기본값으로 채웁니다.

| 내가 쓰는 것 | 뜻 |
| --- | --- |
| `using value_type = T;` | 무엇의 할당자인가 |
| `T* allocate(std::size_t n)` | `T` `n`개가 들어갈 날 메모리. 생성자는 부르지 않는다 |
| `void deallocate(T* p, std::size_t n)` | 돌려받는다. `n`은 잡을 때의 그 값이다 |
| 다른 타입의 할당자에서 만드는 생성자 | `list<int>`는 `int`가 아니라 노드를 잡는다. 컨테이너가 할당자를 노드용으로 바꿔 만든다 |
| `==` | 한쪽이 잡은 것을 다른 쪽이 풀 수 있으면 같다 |

| `allocator_traits`가 채우는 것 | 기본값 |
| --- | --- |
| `construct`, `destroy` | 배치 `new`와 소멸자 호출 |
| 노드용으로 바꾸기(`rebind`) | `A<T>`를 `A<U>`로. 템플릿 인자가 **타입뿐일 때만** 저절로 된다 |
| 컨테이너를 복사, 이동, 교환할 때 할당자도 따라가는가 | 셋 다 "아니오" |
| 언제나 서로 같은가(`is_always_equal`) | 멤버 변수가 없으면 "예" |

## 실패를 주입하는 할당자

`budget.left`번까지만 성공하고 그다음에는 `std::bad_alloc`을 던집니다. 장부를 가리키는 포인터가 이 할당자의 **상태**입니다.

```cpp
#include <cstddef>
#include <functional>
#include <new>
#include <print>
#include <set>
#include <vector>

// 여러 할당자 사본이 함께 보는 장부
struct Budget {
    int left = -1;   // 앞으로 성공할 할당의 수. -1이면 끝이 없다
    int live = 0;    // 아직 돌려받지 못한 블록의 수
};

template <typename T>
class Failing {
public:
    using value_type = T;

    explicit Failing(Budget& budget) noexcept : budget_(&budget) {}
    template <typename U>
    Failing(const Failing<U>& other) noexcept : budget_(other.budget_) {}

    T* allocate(std::size_t n)
    {
        if (budget_->left == 0)
            throw std::bad_alloc();
        if (budget_->left > 0)
            --budget_->left;
        ++budget_->live;
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    void deallocate(T* p, std::size_t) noexcept
    {
        --budget_->live;
        ::operator delete(p);
    }
    template <typename U>
    bool operator==(const Failing<U>& other) const noexcept
    {
        return budget_ == other.budget_;
    }

private:
    template <typename U>
    friend class Failing;
    Budget* budget_;
};

// 넣은 순서와, 이미 있는지를 함께 기억한다. 둘의 크기는 늘 같아야 한다
struct Registry {
    explicit Registry(Budget& budget)
        : order(Failing<int>(budget)), seen(Failing<int>(budget))
    {
    }
    std::vector<int, Failing<int>> order;
    std::set<int, std::less<int>, Failing<int>> seen;
};

void add_plainly(Registry& r, int id)
{
    r.order.push_back(id);
    r.seen.insert(id);   // 여기서 실패하면 order에만 들어간 채 남는다
}

void add_safely(Registry& r, int id)
{
    auto [where, inserted] = r.seen.insert(id);
    try {
        r.order.push_back(id);
    } catch (...) {
        if (inserted)
            r.seen.erase(where);   // 넣은 것을 도로 뺀다
        throw;
    }
}

// 0번째, 1번째, 2번째 … 할당이 실패하게 하며, 끝까지 성공할 때까지 되풀이한다
template <typename F>
void test_every_failure(const char* name, F add)
{
    int points = 0, broken = 0, leaked = 0;
    for (;; ++points) {
        Budget budget;
        bool done = false;
        {
            Registry r(budget);
            for (int id : {1, 2, 3})
                add(r, id);
            budget.left = points;
            try {
                add(r, 4);
                add(r, 5);
                done = true;
            } catch (const std::bad_alloc&) {
                if (r.order.size() != r.seen.size())
                    ++broken;
            }
            budget.left = -1;
        }
        if (budget.live != 0)
            ++leaked;
        if (done)
            break;
    }
    std::println("{}: 실패 지점 {}곳, 어긋난 채 남음 {}번, 샘 {}번", name, points,
                 broken, leaked);
}

int main()
{
    test_every_failure("add_plainly", add_plainly);
    test_every_failure("add_safely", add_safely);
}
```

```text
add_plainly: 실패 지점 3곳, 어긋난 채 남음 2번, 샘 0번
add_safely: 실패 지점 3곳, 어긋난 채 남음 0번, 샘 0번
```

4와 5를 넣는 동안 할당은 세 번 일어납니다. `set`의 노드 둘과 `vector`가 자라는 한 번입니다. 그 세 곳을 차례로 실패시켰더니 `add_plainly`는 두 번이나 **두 컨테이너의 크기가 어긋난 채** 남았습니다. [앞서 본 시험](#/read/cpp-advanced/res-exception)은 원소의 복사를 실패시켰습니다. 이 할당자는 같은 방법을 **메모리 부족**으로 넓힙니다. libstdc++와 libc++에서 결과가 같았습니다.

`live`가 0인지를 보는 것은 새는 것을 잡는 검사입니다. [ASan](#/read/cpp-syntax/ubc-tools)이 없는 환경에서도 됩니다.

## 상태가 있을 때: 이동 대입

위의 `Failing`처럼 멤버 변수가 있으면 "두 할당자가 같은가"가 뜻을 가집니다. 다른 할당자를 쓰는 두 컨테이너 사이에서 이동 대입을 하면 어떻게 될까요.

```cpp
#include <cstddef>
#include <new>
#include <print>
#include <type_traits>
#include <utility>
#include <vector>

int allocations[3] = {};   // 할당자의 번호마다 센다

// Follow가 true면 이동 대입 때 할당자도 함께 넘어간다
template <typename T, bool Follow>
struct Tagged {
    using value_type = T;
    using propagate_on_container_move_assignment = std::bool_constant<Follow>;
    template <typename U>
    struct rebind {
        using other = Tagged<U, Follow>;
    };

    int id;

    explicit Tagged(int id) noexcept : id(id) {}
    template <typename U>
    Tagged(const Tagged<U, Follow>& other) noexcept : id(other.id) {}

    T* allocate(std::size_t n)
    {
        ++allocations[id];
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    void deallocate(T* p, std::size_t) noexcept { ::operator delete(p); }

    template <typename U>
    bool operator==(const Tagged<U, Follow>& other) const noexcept
    {
        return id == other.id;
    }
};

template <bool Follow>
void try_move_assign(const char* what)
{
    using Vec = std::vector<int, Tagged<int, Follow>>;
    Vec a(Tagged<int, Follow>(1));
    Vec b(1000, 7, Tagged<int, Follow>(2));
    const int* old_buffer = b.data();
    allocations[1] = 0;

    a = std::move(b);

    std::println("{}: a의 할당자 {}번, 버퍼를 {}, 새 할당 {}번, noexcept {}", what,
                 a.get_allocator().id,
                 a.data() == old_buffer ? "그대로 받음" : "새로 잡음",
                 allocations[1], std::is_nothrow_move_assignable_v<Vec>);
}

int main()
{
    try_move_assign<false>("따라가지 않음");
    try_move_assign<true>("따라감");
}
```

```text
따라가지 않음: a의 할당자 1번, 버퍼를 새로 잡음, 새 할당 1번, noexcept false
따라감: a의 할당자 2번, 버퍼를 그대로 받음, 새 할당 0번, noexcept true
```

할당자가 따라가지 않으면 `a`는 자기 할당자로 풀 수 없는 `b`의 버퍼를 받을 수 없습니다. 그래서 **새로 잡고 원소를 하나씩 옮깁니다.** 이동 대입이 복사만큼 비싸지고, 할당이 실패할 수 있으니 `noexcept`도 아닙니다. [`std::pmr`의 컨테이너가 이쪽](#/read/cpp-advanced/mv-noexcept)입니다.

| 특성 | "예"로 두면 | 기본값이 맞는 때 |
| --- | --- | --- |
| `propagate_on_container_move_assignment` | 이동 대입이 버퍼와 할당자를 함께 넘긴다 | 할당자가 **자리에 묶여** 있을 때. 이 버퍼의 컨테이너는 끝까지 이 버퍼에서 |
| `propagate_on_container_copy_assignment` | 복사 대입 때 할당자도 복사한다 | 위와 같다 |
| `propagate_on_container_swap` | `swap`이 할당자도 바꾼다. "아니오"인데 할당자가 다르면 `swap`은 미정의 동작이다 | 위와 같다 |

<Note kind="warn">
`Tagged<T, bool>`처럼 템플릿 인자에 **타입이 아닌 것**이 있으면 `rebind`를 직접 써야 합니다. 빼면 `vector`조차 컴파일되지 않습니다. GCC 14는 `no type named 'type' in 'struct std::__replace_first_arg<…>'`, Clang 20은 `This allocator has to implement rebind`라고 합니다. 64바이트에 맞춘 `Aligned<T, 64>` 같은 할당자를 만들 때 처음 부딪히는 곳입니다.
</Note>

## 정리

- 할당자는 `value_type`, `allocate`, `deallocate`, 변환 생성자, `==`만 쓰면 되고 나머지는 `allocator_traits`가 채운다
- 실패를 주입하는 할당자로 모든 할당 지점을 차례로 실패시키면 메모리 부족 때의 뒷정리를 시험할 수 있다
- 상태 있는 할당자는 기본으로 컨테이너를 따라가지 않는다. 그러면 이동 대입이 원소를 하나씩 옮기고 `noexcept`가 아니다
