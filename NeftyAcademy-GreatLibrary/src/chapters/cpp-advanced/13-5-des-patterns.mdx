디자인 패턴은 1994년의 책에서 이름을 얻었고, 그 책의 예제는 클래스와 가상 함수로 쓰여 있습니다. 그 뒤 C++에는 람다, `std::function`, `std::variant`, 템플릿이 들어왔습니다. 패턴이 풀던 문제는 그대로인데 적는 법이 달라졌습니다.

## 문법이 된 패턴

| 패턴 | 하려는 일 | 지금 적는 법 |
| --- | --- | --- |
| 전략 (Strategy) | 알고리즘의 한 부분을 갈아 끼운다 | [람다](#/read/cpp-syntax/fn-lambda)를 인자로. [`sort`의 비교 함수](#/read/cpp-stl/alg-sort)가 이것이다 |
| 명령 (Command) | 할 일을 값으로 들고 다닌다 | `std::function<void()>`. [스레드 풀의 일감](#/read/cpp-advanced/asy-pool) |
| 관찰자 (Observer) | 일이 생기면 알린다 | 콜백의 `vector`. 수명은 [`weak_ptr`](#/read/cpp-advanced/sp-weak)로 |
| 방문자 (Visitor) | 타입마다 다른 일을 한다 | [`variant`와 `visit`](#/read/cpp-stl/voc-variant) |
| 상태 (State) | 상태마다 다르게 군다 | `variant`와 `visit` (아래) |
| 반복자 (Iterator) | 하나씩 차례로 내준다 | 범위 기반 `for`, [제너레이터](#/read/cpp-advanced/co-generator) |
| 템플릿 메서드 | 뼈대는 두고 일부만 바꾼다 | 함수 인자, [CRTP](#/read/cpp-advanced/tmp-crtp) |
| 팩토리 | 무엇을 만들지 정하는 일을 맡긴다 | [`unique_ptr`를 돌려주는 함수](#/read/cpp-advanced/sp-passing) |
| 싱글턴 | 하나만 둔다 | 함수 안의 `static`. 대개는 [주입](#/read/cpp-advanced/des-injection)이 낫다 |
| 어댑터, 데코레이터 | 감싸서 모양이나 동작을 바꾼다 | 템플릿으로 감싸기, [타입 지우기](#/read/cpp-advanced/te-implement) |

두 개를 직접 써 봅니다.

## 상태: 클래스에서 variant로

바이트가 하나씩 들어오는 통신에서 프레임을 가려내는 상태 기계입니다. 책의 방식대로라면 상태마다 클래스를 두고, 바뀔 때마다 새 상태 객체를 만듭니다. `variant`로는 이렇게 됩니다.

```cpp
#include <cstdint>
#include <print>
#include <variant>
#include <vector>

// 프레임: 0x7E, 길이, 내용…, 내용의 합(1바이트)

// 상태마다 타입 하나. 그 상태에서만 뜻이 있는 값을 멤버로 갖는다
struct Idle {};
struct Length {};
struct Payload { std::uint8_t remaining, sum; };
struct Check { std::uint8_t sum; };
using State = std::variant<Idle, Length, Payload, Check>;

template <typename... Fs>
struct overloaded : Fs... { using Fs::operator()...; };

class Parser {
public:
    void on_byte(std::uint8_t b)
    {
        // 지금 상태와 들어온 바이트로 다음 상태를 정한다
        state_ = std::visit(overloaded{
            [&](Idle) -> State {
                if (b == 0x7E) return Length{};
                return Idle{};
            },
            [&](Length) -> State {
                if (b == 0) return Check{0};
                return Payload{b, 0};
            },
            [&](Payload p) -> State {
                p.sum = static_cast<std::uint8_t>(p.sum + b);
                if (--p.remaining == 0) return Check{p.sum};
                return p;
            },
            [&](Check c) -> State {
                (b == c.sum ? frames_ : errors_)++;
                return Idle{};
            },
        }, state_);
    }
    int frames() const { return frames_; }
    int errors() const { return errors_; }

private:
    State state_ = Idle{};
    int frames_ = 0;
    int errors_ = 0;
};

int main()
{
    const std::vector<std::uint8_t> bytes = {
        0x00, 0x7E, 2, 10, 20, 30,       // 앞의 잡음은 버린다. 10 + 20 = 30
        0x7E, 3, 1, 2, 3, 7,             // 합이 6이어야 하는데 7이 왔다
        0x7E, 0, 0,                      // 내용이 없는 프레임
    };
    Parser parser;
    for (std::uint8_t b : bytes) parser.on_byte(b);
    std::println("프레임 {}개, 오류 {}개", parser.frames(), parser.errors());
}
```

```text
프레임 2개, 오류 1개
```

`enum`과 `switch`로 쓴 것에 견주면 얻는 것이 둘입니다. `remaining`과 `sum`은 `Payload` 상태에만 있으므로 **다른 상태에서 읽을 수 없습니다.** 그리고 상태 하나를 빠뜨리면 컴파일되지 않습니다. `Check`의 람다를 지우자 GCC가 `no type named 'type' in 'struct std::invoke_result<overloaded<…>, Check&>'`라고 알렸습니다.

프레임 5,000개를 세 가지 방식으로 돌린 값입니다. x86-64이고 바이트 하나에 든 시간입니다.

| 방식 | 내용 16바이트 | 내용 2바이트 | Clang 20, 16바이트 |
| --- | --- | --- | --- |
| `enum`과 `switch` | 0.99 ns | 0.68 ns | 1.7 ns |
| `variant`와 `visit` | 0.74 ns | 0.49 ns | 3.4 ns |
| 상태마다 클래스, 바뀔 때마다 `make_unique` | 4.2 ns | 11.7 ns | 4.3 ns |

GCC 14에서 `variant` 판은 `switch`와 같거나 빠릅니다. 클래스 판은 상태가 바뀔 때마다 [할당](#/read/cpp-advanced/mm-new)하므로, 프레임이 짧아 자주 바뀌는 둘째 열에서 스무 배 안팎으로 벌어집니다. libc++의 `visit`는 [앞에서 본 대로](#/read/cpp-advanced/te-compare) 느려서 Clang에서는 `switch`가 두 배 빠릅니다.

## 명령: 클래스에서 람다로

실행한 일을 되돌리려면 "한 일"을 들고 있어야 합니다. 책의 방식은 `execute()`와 `undo()`를 가진 부모 클래스와, 명령마다 그것을 상속한 클래스입니다. 람다 둘이면 됩니다.

```cpp
#include <functional>
#include <print>
#include <string>
#include <utility>
#include <vector>

// 할 일과 되돌릴 일을 값으로 들고 다닌다
struct Command {
    std::function<void()> run;
    std::function<void()> undo;
};

class History {
public:
    void execute(Command command)
    {
        command.run();
        done_.push_back(std::move(command));
    }
    void undo()
    {
        if (done_.empty()) return;
        done_.back().undo();
        done_.pop_back();
    }

private:
    std::vector<Command> done_;
};

// 명령을 만드는 함수. 되돌릴 때 필요한 것은 람다가 캡처해 둔다
Command append(std::string& text, std::string tail)
{
    const std::size_t length = tail.size();
    return {
        [&text, tail = std::move(tail)] { text += tail; },
        [&text, length] { text.resize(text.size() - length); },
    };
}
Command set_target(double& target, double value)
{
    return {
        [&target, value] { target = value; },
        [&target, old = target] { target = old; },
    };
}

int main()
{
    std::string text = "온도";
    double target = 20.0;
    History history;

    history.execute(append(text, " 조절"));
    history.execute(set_target(target, 22.5));
    history.execute(append(text, " 시작"));
    std::println("{} / {}", text, target);

    history.undo();
    history.undo();
    std::println("{} / {}", text, target);
}
```

```text
온도 조절 시작 / 22.5
온도 조절 / 20
```

명령 클래스의 멤버 변수가 하던 일을 **캡처**가 합니다. 새 명령을 더하는 일은 클래스 하나가 아니라 함수 하나입니다.

<Note kind="warn">
캡처한 참조는 빌린 것입니다. `History`가 `text`보다 오래 살면 `undo()`가 [사라진 문자열](#/read/cpp-syntax/lam-capture)을 고칩니다. 명령을 스레드로 넘기거나 오래 보관한다면 값으로 캡처하거나 `shared_ptr`를 캡처합니다.
</Note>

## 이름은 남는다

적는 법이 한 줄이 되어도 이름은 쓸모가 있습니다. "여기는 전략을 받는다", "이것은 방문자다"라고 하면 설계가 한마디로 전해집니다. C++에서 자란 이름도 같은 구실을 합니다. [RAII](#/read/cpp-advanced/res-wrapper), [스코프 가드](#/read/cpp-advanced/res-guard), [pimpl](#/read/cpp-advanced/te-pimpl), CRTP, 타입 지우기가 그렇습니다.

패턴은 문제가 있을 때 꺼내는 것입니다. 구현이 하나뿐인 인터페이스, 한 곳에서만 만드는 객체의 팩토리는 읽을 것만 늘립니다. 두 번째 구현이 생길 때 넣어도 늦지 않습니다.

## 정리

- 전략과 명령은 람다로, 방문자와 상태는 `variant`와 `visit`로, 반복자는 범위와 제너레이터로 적는다
- `variant`로 쓴 상태 기계는 `switch`만큼 빠르고(GCC), 상태마다의 데이터를 가두며, 빠뜨린 상태를 컴파일러가 잡는다
- 상태마다 객체를 새로 만드는 고전적인 꼴은 할당 때문에 4~24배 느렸다. 이름은 설계를 전하는 말로 계속 쓴다
