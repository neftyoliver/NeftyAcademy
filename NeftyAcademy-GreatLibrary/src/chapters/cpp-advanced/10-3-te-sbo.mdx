[앞 페이지의 `Shape`](#/read/cpp-advanced/te-implement)는 무엇을 담든 힙을 잡았습니다. `double` 하나짜리 `Circle`도 그랬습니다. `std::function`이 [포인터 둘까지는 할당 없이 담는](#/read/cpp-stl/voc-function) 것처럼, 작은 것은 **객체 안의 버퍼에 직접** 만들면 됩니다. 작은 버퍼 최적화(small buffer optimization)입니다. `std::string`이 짧은 글을 안에 담는 것도 같은 기법입니다.

## 버퍼와 함수 표

버퍼 안에 무엇이 들었는지 모르므로 `unique_ptr`와 가상 함수에 기댈 수 없습니다. 복사, 이동, 소멸까지 **함수 포인터의 표**로 직접 만듭니다.

```cpp
#include <cstddef>
#include <cstdlib>
#include <new>
#include <print>
#include <type_traits>
#include <utility>
#include <vector>

static long allocations = 0;
void* operator new(std::size_t size)
{
    ++allocations;
    return std::malloc(size);
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

class Shape {
public:
    template <typename T>
        requires requires(const T& t) { t.area(); }
    Shape(T value)
    {
        if constexpr (fits<T>) {
            // 버퍼 안에 직접 만든다
            ::new (buffer_) T(std::move(value));
            ops_ = &inline_ops<T>;
        } else {
            // 힙에 만들고 버퍼에는 포인터만 둔다
            ::new (buffer_) T*(new T(std::move(value)));
            ops_ = &heap_ops<T>;
        }
    }
    Shape(const Shape& other) : ops_(other.ops_)
    {
        if (ops_)
            ops_->copy(other.buffer_, buffer_);
    }
    // 옮긴 뒤의 원본은 비워 둔다. 비우지 않으면 두 번 없앤다
    Shape(Shape&& other) noexcept : ops_(std::exchange(other.ops_, nullptr))
    {
        if (ops_)
            ops_->move(other.buffer_, buffer_);
    }
    Shape& operator=(Shape other) noexcept
    {
        reset();
        ops_ = std::exchange(other.ops_, nullptr);
        if (ops_)
            ops_->move(other.buffer_, buffer_);
        return *this;
    }
    ~Shape() { reset(); }

    double area() const { return ops_->area(buffer_); }

private:
    void reset() noexcept
    {
        if (ops_)
            ops_->destroy(buffer_);
        ops_ = nullptr;
    }

    static constexpr std::size_t buffer_size = 24;

    // 안에 넣을 수 있는 타입의 조건
    template <typename T>
    static constexpr bool fits = sizeof(T) <= buffer_size
                                 && alignof(T) <= alignof(std::max_align_t)
                                 && std::is_nothrow_move_constructible_v<T>;

    // 손으로 만든 가상 함수 표
    struct Ops {
        double (*area)(const void* self);
        void (*copy)(const void* from, void* to);
        void (*move)(void* from, void* to) noexcept;   // 옮기고 원본을 없앤다
        void (*destroy)(void* self) noexcept;
    };

    template <typename T>
    static constexpr Ops inline_ops = {
        [](const void* self) { return static_cast<const T*>(self)->area(); },
        [](const void* from, void* to) {
            ::new (to) T(*static_cast<const T*>(from));
        },
        [](void* from, void* to) noexcept {
            ::new (to) T(std::move(*static_cast<T*>(from)));
            static_cast<T*>(from)->~T();
        },
        [](void* self) noexcept { static_cast<T*>(self)->~T(); },
    };
    template <typename T>
    static constexpr Ops heap_ops = {
        [](const void* self) { return (*static_cast<T* const*>(self))->area(); },
        [](const void* from, void* to) {
            ::new (to) T*(new T(**static_cast<T* const*>(from)));
        },
        [](void* from, void* to) noexcept {
            ::new (to) T*(*static_cast<T**>(from));
        },
        [](void* self) noexcept { delete *static_cast<T**>(self); },
    };

    alignas(std::max_align_t) std::byte buffer_[buffer_size];
    const Ops* ops_;
};

struct Circle {
    double r;
    double area() const { return 3.14159 * r * r; }
};
struct Triangle {
    double a, b, c;
    double area() const { return 0.5 * a * b; }
};
struct Polygon {   // 24바이트를 넘는다
    double xs[8];
    double area() const { return xs[0] * xs[1]; }
};

template <typename T>
void try_one(const char* name, T value)
{
    long before = allocations;
    Shape first = value;
    Shape second = first;             // 복사
    Shape third = std::move(first);   // 이동
    second = third;                   // 대입
    std::println("{} {}바이트: 넓이 {:.2f}, 할당 {}번", name, sizeof(T),
                 second.area(), allocations - before);
}

int main()
{
    std::println("Shape의 크기 {}바이트", sizeof(Shape));
    try_one("Circle", Circle{1});
    try_one("Triangle", Triangle{3, 4, 5});
    try_one("Polygon", Polygon{{2, 5}});

    long before = allocations;
    std::vector<Shape> shapes;
    shapes.reserve(1000);
    for (int i = 0; i < 1000; ++i)
        shapes.push_back(Circle{1.0 + i});
    std::vector<Shape> copy = shapes;
    std::println("Circle 1000개를 담고 복사: 할당 {}번", allocations - before);
}
```

```text
Shape의 크기 32바이트
Circle 8바이트: 넓이 3.14, 할당 0번
Triangle 24바이트: 넓이 6.00, 할당 0번
Polygon 64바이트: 넓이 10.00, 할당 3번
Circle 1000개를 담고 복사: 할당 2번
```

`Circle` 천 개를 담고 통째로 복사하는 데 할당이 두 번, 곧 `vector` 둘의 것뿐입니다. 앞 페이지의 `Shape`였다면 이천 번입니다.

| 조각 | 하는 일 |
| --- | --- |
| `buffer_` | 24바이트의 날 메모리. 작은 것은 여기에 [배치 `new`](#/read/cpp-syntax/life-new)로 만들고, 큰 것은 포인터만 둔다 |
| `fits<T>` | 크기, 정렬, 그리고 **이동이 던지지 않는가**를 컴파일할 때 본다 |
| `Ops` | 타입마다 하나씩 있는 함수 포인터 표. 가상 함수 표를 손으로 쓴 것이다 |
| `inline_ops<T>`, `heap_ops<T>` | 같은 표의 두 판. 버퍼의 바이트를 `T`로 볼지 `T*`로 볼지가 다르다 |

조건의 셋째가 중요합니다. 버퍼 안의 것을 옮기려면 `T`의 이동 생성자를 불러야 합니다. 그것이 던질 수 있다면 `Shape`의 이동도 `noexcept`일 수 없고, 그러면 [`vector`가 자랄 때 옮기지 않고 복사합니다](#/read/cpp-advanced/mv-noexcept). 던질 수 있는 타입은 힙에 두면 포인터만 옮기면 되므로 언제나 `noexcept`입니다.

<Note kind="warn">
이 예제를 쓰면서 실제로 한 실수가 있습니다. 처음에는 이동 생성자가 원본의 `ops_`를 그대로 두었습니다. 옮긴 뒤 원본의 소멸자가 같은 것을 한 번 더 없앴고, ASan이 `heap-use-after-free`로 잡았습니다. 손으로 수명을 다루는 코드는 [옮겨진 뒤의 상태](#/read/cpp-advanced/mv-moved-from)까지 정해야 끝납니다. 새니타이저 없이는 쓰지 않습니다.
</Note>

## 잰 값

도형 1만 개(타입 셋, 모두 버퍼에 들어간다)로 [앞의 두 페이지](#/read/cpp-advanced/te-compare)와 같은 것을 쟀습니다. GCC 14, `-O2`입니다.

| 방식 | 섞였을 때 호출 | 모았을 때 호출 | 1만 개의 복사 |
| --- | --- | --- | --- |
| 힙에 두는 `Shape` | 6.6 ns | 2.1 ns | 190~370 µs, 할당 10,001번 |
| 작은 버퍼의 `Shape` | 5.8 ns | 2.1 ns | 43~175 µs, 할당 1번 |
| `variant` | 2.6 ns | 0.54 ns | 6.8 µs, 할당 1번 |

할당은 사라졌고 복사는 두 배에서 네 배 빨라졌습니다. **호출은 거의 그대로입니다.** 호출의 값은 포인터를 따라가는 데서가 아니라, 어느 함수로 갈지 예측하지 못하는 간접 호출에서 나오기 때문입니다. 이 벤치마크는 객체를 차례로 만들어 힙에서도 서로 붙어 있었습니다. 오래 돈 프로그램처럼 힙이 흩어져 있으면 차이가 더 벌어지겠지만, 그 경우는 재지 않았습니다.

복사가 `variant`보다 여전히 느린 것은 원소마다 표의 `copy`를 불러야 해서입니다. `variant`는 타입이 모두 단순하면 통째로 `memcpy`합니다.

## 버퍼를 얼마로 잡을까

| 버퍼를 키우면 | 버퍼를 줄이면 |
| --- | --- |
| 더 많은 타입이 할당 없이 들어간다 | 객체가 작아져 한 캐시 줄에 더 많이 들어간다 |
| 작은 것을 담아도 그 크기를 다 차지한다 | 조금 큰 타입이 힙으로 밀려난다 |
| 옮길 때 버퍼를 다 복사한다 | 포인터 하나만 옮긴다 |

정답은 **실제로 담을 타입들의 크기**에서 나옵니다. 흔히 담는 타입이 들어가는 가장 작은 크기로 잡고, `static_assert(sizeof(Circle) <= 24)`처럼 가정을 적어 둡니다. 표준 라이브러리가 고른 값은 이렇습니다. GCC 14에서 확인한 것입니다.

| 타입 | 객체의 크기 | 안에 담는 크기 |
| --- | --- | --- |
| `std::function` | 32바이트 | 16바이트까지. `memcpy`로 복사해도 되는 것만 |
| `std::move_only_function` | 40바이트 | 24바이트까지 |
| 이 페이지의 `Shape` | 32바이트 | 24바이트까지. 이동이 던지지 않는 것만 |

<Note>
함수 표를 손으로 쓰면 가상 함수로는 못 하던 조절이 됩니다. 자주 부르는 함수 포인터 하나를 표가 아니라 객체에 직접 두어 한 번 덜 거치게 하거나, 단순한 타입에는 `copy` 대신 `memcpy`를 쓰는 식입니다. 그만큼 틀릴 곳도 늘어납니다. 먼저 `variant`와 `std::function`으로 충분하지 않은지 봅니다.
</Note>

## 정리

- 작은 버퍼 최적화는 작은 것을 객체 안의 버퍼에 직접 만들고 큰 것만 힙에 둔다. 복사, 이동, 소멸을 함수 포인터 표로 직접 만든다
- 할당이 사라지고 복사가 빨라진다. 호출의 값은 거의 그대로다. 간접 호출이 그대로이기 때문이다
- 안에 넣는 조건에 "이동이 던지지 않는다"를 넣어야 바깥 타입의 이동이 `noexcept`가 된다
