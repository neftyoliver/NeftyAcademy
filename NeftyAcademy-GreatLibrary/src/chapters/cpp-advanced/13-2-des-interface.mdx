함수의 선언은 부르는 사람이 읽는 유일한 설명서일 때가 많습니다. 아래 선언은 다섯 가지를 물어보게 만듭니다.

```cpp
// 부르는 쪽: set_pwm(18, 2000, 0.5, false, 100);
bool set_pwm(int pin, int frequency, double duty, bool inverted, int timeout);
```

`18`과 `2000`의 자리를 바꿔도 컴파일됩니다. `duty`는 0.5인지 50인지, `timeout`은 밀리초인지 초인지 적혀 있지 않습니다. `false`가 무엇을 끄는지는 선언을 찾아봐야 알고, 돌려준 `bool`은 버려도 아무 일이 없습니다. 좋은 인터페이스는 이 물음들을 **타입으로** 답합니다.

## 타입으로 답하기

```cpp
#include <chrono>
#include <expected>
#include <optional>
#include <print>

// 같은 int지만 서로 섞이지 않는다
struct Pin {
    explicit constexpr Pin(int n) : number(n) {}
    int number;
};
struct Hertz {
    explicit constexpr Hertz(int v) : value(v) {}
    int value;
};

// 0.0~1.0만 담을 수 있다. 범위 검사는 만들 때 한 번만 한다
class Duty {
public:
    constexpr Duty() = default;
    static constexpr std::optional<Duty> from(double ratio)
    {
        if (ratio < 0.0 || ratio > 1.0) return std::nullopt;
        return Duty(ratio);
    }
    constexpr double ratio() const { return ratio_; }

private:
    explicit constexpr Duty(double ratio) : ratio_(ratio) {}
    double ratio_ = 0.0;
};

enum class Polarity { Normal, Inverted };

struct Pwm {                    // 설정은 이름을 붙여 넘긴다
    Hertz frequency{1000};
    Duty duty;
    Polarity polarity = Polarity::Normal;
};

enum class PwmError { NoSuchPin, Timeout };
using Millis = std::chrono::milliseconds;

[[nodiscard]] std::expected<void, PwmError>
set_pwm(Pin pin, const Pwm& pwm, Millis wait)
{
    if (pin.number < 0 || pin.number > 27)
        return std::unexpected(PwmError::NoSuchPin);
    std::println("핀 {}: {} Hz, {:.0f}%, {} 안에", pin.number, pwm.frequency.value,
                 pwm.duty.ratio() * 100, wait);
    return {};
}

// 이 인자들로 부르는 코드가 컴파일되는가
template <typename... Args>
constexpr bool accepts = requires(Args... args) { set_pwm(args...); };

void show(const char* call, bool compiles)
{
    std::println("{:<32}{}", call, compiles ? "된다" : "컴파일 오류");
}

int main()
{
    using namespace std::chrono_literals;

    const auto half = Duty::from(0.5);
    if (!half) return 1;
    const auto done =
        set_pwm(Pin{18}, {.frequency = Hertz{2000}, .duty = *half}, 100ms);
    std::println("성공 {}, 150%는 {}", done.has_value(),
                 Duty::from(1.5).has_value());

    show("set_pwm(Pin{18}, pwm, 100ms)", accepts<Pin, Pwm, Millis>);
    show("set_pwm(18, pwm, 100ms)", accepts<int, Pwm, Millis>);
    show("set_pwm(Hertz{18}, pwm, 100ms)", accepts<Hertz, Pwm, Millis>);
    show("set_pwm(Pin{18}, pwm, 100)", accepts<Pin, Pwm, int>);
    show("set_pwm(Pin{18}, pwm, 1s)", accepts<Pin, Pwm, std::chrono::seconds>);
    show("set_pwm(Pin{18}, pwm, 100us)",
         accepts<Pin, Pwm, std::chrono::microseconds>);
}
```

```text
핀 18: 2000 Hz, 50%, 100ms 안에
성공 true, 150%는 false
set_pwm(Pin{18}, pwm, 100ms)    된다
set_pwm(18, pwm, 100ms)         컴파일 오류
set_pwm(Hertz{18}, pwm, 100ms)  컴파일 오류
set_pwm(Pin{18}, pwm, 100)      컴파일 오류
set_pwm(Pin{18}, pwm, 1s)       된다
set_pwm(Pin{18}, pwm, 100us)    컴파일 오류
```

`accepts`는 그 인자들로 부르는 식이 컴파일되는지를 묻습니다. 틀린 호출 넷이 실행하기 전에 걸러졌습니다.

| 장치 | 막는 실수 |
| --- | --- |
| [`explicit` 생성자](#/read/cpp-syntax/class-explicit)를 가진 작은 타입 | 인자의 자리가 바뀌는 것, 뜻이 다른 수가 섞이는 것 |
| [`std::chrono`의 타입](#/read/cpp-stl/chr-duration) | 단위를 틀리는 것. 초는 밀리초로 바뀌지만, 값이 잘리는 마이크로초는 받지 않는다 |
| 만들 때 검사하는 타입 (`Duty::from`) | 범위 밖의 값이 안쪽까지 들어오는 것. `set_pwm`은 듀티의 범위를 다시 보지 않는다 |
| [`enum class`](#/read/cpp-syntax/types-enum) | `true`와 `false`의 뜻을 헷갈리는 것 |
| 설정 구조체와 [지정 초기화](#/read/cpp-syntax/types-init) | 긴 인자 목록. 안 적은 것은 기본값이다 |
| [`[[nodiscard]]`](#/read/cpp-syntax/fn-attributes)와 `expected` | 실패를 보지 않고 지나가는 것 |

셋째 줄이 가장 멀리 갑니다. 검사를 통과한 값만 `Duty`가 될 수 있으므로, `Duty`를 받는 함수는 다시 검사하지 않습니다. **검사는 바깥 경계에서 한 번, 안쪽은 타입이 보증합니다.** 마지막 줄의 결과를 버리면 GCC가 `ignoring return value of … declared with attribute 'nodiscard'`라고 경고합니다. 실패를 어떻게 돌려줄지는 [다음 페이지](#/read/cpp-advanced/des-errors)에서 고릅니다.

## 치르는 값

타입을 입혀도 기계어는 같습니다. `(int, int, double)`을 받는 함수와 `(Pin, Hertz, Duty)`를 받는 같은 함수를 `-O2`로 컴파일해 견줬더니, x86-64(명령 11개)와 AArch64(8개) 모두 **글자까지 같았습니다**. 멤버 하나짜리 구조체는 그 멤버와 똑같이 레지스터에 실립니다. 다만 [소멸자를 적으면](#/read/cpp-advanced/res-wrapper) 메모리로 넘어갑니다.

## 조용히 다른 함수가 불릴 때

오버로드는 부르는 쪽을 편하게 하지만, 고르는 규칙이 사람의 짐작과 어긋나는 곳이 있습니다.

```cpp
#include <concepts>
#include <print>
#include <string>
#include <string_view>

namespace before {
void log_value(std::string_view text) { std::println("글: {}", text); }
void log_value(bool flag) { std::println("참거짓: {}", flag); }
}

namespace after {
void log_value(std::string_view text) { std::println("글: {}", text); }
// 정확히 bool일 때만 고른다
void log_value(std::same_as<bool> auto flag) { std::println("참거짓: {}", flag); }
}

int main()
{
    const std::string status = "ready";
    before::log_value("ready");             // 글을 넘겼는데
    before::log_value(status);
    before::log_value(status.c_str());

    after::log_value("ready");
    after::log_value(status.c_str());
    after::log_value(status.empty());
}
```

```text
참거짓: true
글: ready
참거짓: true
글: ready
글: ready
참거짓: false
```

문자열 리터럴은 포인터로 바뀌고, 포인터에서 `bool`로 가는 것은 언어에 들어 있는 변환입니다. `string_view`로 가는 것은 생성자를 거치는 변환이라 순위가 낮습니다. 그래서 글을 넘겼는데 `bool` 판이 불립니다. GCC 14는 `-Wall -Wextra -Wconversion`에도 말이 없었고, Clang 20은 `-Wconversion`을 주면 `implicit conversion turns string literal into bool`이라고 알립니다.

`after`처럼 [콘셉트](#/read/cpp-syntax/con-standard)로 "정확히 이 타입"만 받게 하거나, 받고 싶지 않은 타입의 오버로드를 [`= delete`](#/read/cpp-syntax/fn-overload)로 지웁니다. 더 확실한 것은 이름을 달리하는 것입니다. `log_text`와 `log_flag`는 잘못 고를 수 없습니다.

## 그 밖에 선언이 말해 줄 것

| 알릴 것 | 적는 법 |
| --- | --- |
| 넘긴 것을 누가 갖는가 | [매개변수의 꼴](#/read/cpp-advanced/sp-passing). `T&`, `unique_ptr<T>`, `span<T>` |
| 객체를 바꾸는가, 던지는가 | `const`, `noexcept` |
| 미리 지킬 조건 | 타입으로 못 막는 것은 이름과 주석에 적고 `assert`로 확인한다. C++26에는 [계약](#/read/cpp-advanced/safe-contracts)이 있다 |
| 여러 값을 돌려준다 | `pair`가 아니라 멤버에 이름이 붙은 구조체 |

<Note>
한번 내놓은 선언은 바꾸기 어렵습니다. 쓰는 코드가 생긴 뒤에는 매개변수 하나를 더하는 것도 모두를 고치는 일이고, 라이브러리로 나간 뒤에는 [바이너리까지 깨집니다](#/read/cpp-advanced/iop-abi-stable). 설정 구조체는 그 점에서도 낫습니다. 멤버를 더해도 부르는 코드는 그대로입니다.
</Note>

## 정리

- 뜻이 다른 값에는 다른 타입을 준다. 자리가 바뀐 인자, 틀린 단위, 범위 밖의 값이 컴파일에서 걸린다
- 멤버 하나짜리 타입은 기계어가 그대로다. 값을 치르지 않는다
- 오버로드는 조용히 다른 판을 고를 수 있다. 리터럴이 `bool` 판으로 갔다. 콘셉트로 좁히거나 이름을 달리한다
