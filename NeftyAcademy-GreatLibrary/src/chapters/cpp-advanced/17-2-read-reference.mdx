[표준](#/read/cpp-advanced/read-standard)은 무엇이 약속인지를 말합니다. 그 약속이 언제 생겼는지, 내 컴파일러가 실제로 무엇을 하는지는 다른 두 도구가 답합니다. 질문 하나를 들고 셋을 차례로 지나가 봅니다. **`span`의 `[]`는 번호를 검사하는가?**

## cppreference에서

cppreference.com은 표준을 사람이 찾기 좋게 옮겨 적은 위키입니다. 자원봉사자들이 쓰고, 표준 그 자체는 아닙니다. 틀리거나 늦을 수 있고, 어긋나면 표준이 옳습니다. 페이지는 대개 아래의 자리들로 이루어집니다. `std::span`의 `operator[]` 페이지를 예로 읽습니다.

| 페이지의 자리 | 읽는 법 |
| --- | --- |
| 선언 옆의 `(since C++20)` | 이 선언이 들어온 표준. `(until C++26)`은 그 표준에서 바뀌거나 사라졌다는 뜻이다 |
| 설명이 둘로 갈린 곳 | C++26 전에는 범위 밖이 정의되지 않은 동작, C++26부터는 [경화된 구현](#/read/cpp-advanced/safe-hardening)이면 계약 위반이라고 나란히 적혀 있다 |
| Return value, Exceptions, Complexity | 표준의 Returns, Throws, Complexity를 옮긴 것 |
| Example | 그대로 돌아가는 예제 |
| Defect reports | 표준의 버그를 고친 기록. 고친 내용은 앞선 표준에도 거슬러 적용된다 |
| See also | 이웃 함수. 여기에 `at` `(C++26)`이 있다 |

첫 답이 나왔습니다. C++23까지는 검사한다는 약속이 없고, 검사하는 `at`은 C++26에 들어왔습니다. 표시가 맞는지 컴파일러에 물었습니다.

| 빌드 | `s.at(1)` | `__cpp_lib_span` |
| --- | --- | --- |
| GCC 14 `-std=c++23` | `has no member named 'at'` | `202002L` |
| GCC 14 `-std=c++26` | 컴파일된다 | `202311L` |

"since C++26"은 표준의 이야기이고, 내 손에 있는지는 컴파일러와 라이브러리의 버전, 그리고 `-std` 옵션이 정합니다. [기능 시험 매크로](#/read/cpp-advanced/read-standard)가 그것을 알려 줍니다. cppreference의 compiler support 표에는 기능마다 어느 컴파일러의 몇 버전부터인지가 모여 있습니다.

<Note>
오프라인 판은 날짜를 봅니다. 이 책의 장비에서 배포판 패키지 `cppreference-doc-en-html`을 깔아 보니 2017년 4월의 것이었고 `span` 페이지가 없었습니다.
</Note>

## 컴파일러의 출력에서

검사가 실제로 있는지는 기계어를 보면 압니다.

```cpp
#include <span>

int pick(std::span<const int> values, std::size_t i)
{
    return values[i];
}
```

```text nocheck
$ g++ -std=c++23 -O2 -c pick.cpp && objdump -d -C -M intel --no-show-raw-insn pick.o
   0:   endbr64
   4:   mov    eax,DWORD PTR [rdi+rdx*4]
   7:   ret
$ g++ -std=c++23 -O2 -D_GLIBCXX_ASSERTIONS -c pick.cpp && objdump ...
   0:   endbr64
   4:   cmp    rdx,rsi
   7:   jae    10 <pick(...)+0x10>
   9:   mov    eax,DWORD PTR [rdi+rdx*4]
   c:   ret
  10:   ...
  2e:   call   std::__glibcxx_assert_fail(...)
```

`span`은 포인터와 길이로 두 레지스터(`rdi`, `rsi`)에 실려 오고 `i`는 `rdx`에 있습니다. 첫 줄의 `endbr64`는 [기본으로 켜진 방어](#/read/cpp-advanced/safe-vulns)가 넣은 표시입니다. 첫 빌드는 읽고 돌아갈 뿐입니다. 둘째 빌드에는 `i`와 길이를 견주는 `cmp`와, 크거나 같으면 실패하는 쪽으로 뛰는 `jae`가 생겼습니다. 답은 "표준은 약속하지 않고, 이 라이브러리는 스위치를 켜면 검사한다"입니다.

**컴파일러 탐색기**(godbolt.org)는 이 일을 웹에서 해 줍니다. 왼쪽에 소스를 적으면 오른쪽에 어셈블리가 나오고, 소스의 줄과 명령이 같은 색으로 이어집니다. 2012년에 Matt Godbolt가 시작했고 지금은 서른이 넘는 언어와 컴파일러의 여러 버전을 고를 수 있습니다.

- **깔지 않은 컴파일러로 돌려 봅니다.** 이 책이 "돌려 보지 못했다"고 적은 GCC 16이나 MSVC가 거기 있습니다.
- **둘을 나란히 놓습니다.** 컴파일러 둘이나 옵션 둘의 출력을 옆에 두고 차이만 볼 수 있습니다.
- **링크로 건넵니다.** 소스와 옵션이 담긴 짧은 주소가 나옵니다. 버그 보고와 질문에 붙이기 좋습니다.

## 질문을 명령으로

탐색기가 보여 주는 것은 내 장비에서도 볼 수 있습니다. 이 책이 써 온 명령들입니다.

| 궁금한 것 | 명령 |
| --- | --- |
| 무슨 기계어가 됐나 | `objdump -d -C -M intel --no-show-raw-insn 파일.o` |
| 루프가 [벡터화](#/read/cpp-advanced/perf-simd)됐나 | `g++ -O3 -fopt-info-vec`. 안 된 까닭은 `-fopt-info-vec-missed`. Clang은 `-Rpass=loop-vectorize` |
| 최적화가 끝난 뒤의 모습 | `g++ -O2 -fdump-tree-optimized`, `clang++ -O2 -S -emit-llvm` |
| 어떤 기능이 켜져 있나 | `g++ -std=c++26 -dM -E -x c++ /dev/null` |
| [기본으로 켜진 방어](#/read/cpp-advanced/safe-vulns) | `g++ -Q --help=common`, `g++ --help=hardened` |

[경화 페이지](#/read/cpp-advanced/safe-hardening)에서 "단언이 벡터화를 풀었다"고 한 것은 둘째 줄로 확인한 것입니다. 단언을 켜자 `optimized: loop vectorized using 16 byte vectors`가 `missed: couldn't vectorize loop`로 바뀌었습니다. 셋째 줄은 더 높은 곳에서 보여 줍니다.

```cpp
#include <array>
#include <numeric>

int total()
{
    const std::array<int, 5> values{1, 2, 3, 4, 5};
    return std::accumulate(values.begin(), values.end(), 0);
}
```

| 컴파일러 | 최적화가 끝난 뒤 |
| --- | --- |
| GCC 14 `-O2` | 배열을 스택에 적고 다섯 바퀴 도는 루프가 남는다 |
| GCC 14 `-O3` | `return 15;` |
| Clang 20 `-O2` | `ret i32 15` |

<Note kind="warn">
이런 출력은 **그 컴파일러, 그 버전, 그 옵션**의 답입니다. 약속이 아닙니다. 위의 표처럼 옵션 하나에 달라지고, 버전이 오르면 또 달라집니다. 코드가 그 출력에 기대야 한다면 [재서](#/read/cpp-advanced/perf-measure) 확인하고, 기대는 까닭을 적어 둡니다.
</Note>

## 묻는 순서

1. **cppreference**에서 이름과 선언, 들어온 표준을 봅니다. 대부분의 질문은 여기서 끝납니다.
2. 글귀가 애매하거나 구현마다 답이 다르면 [표준의 그 절](#/read/cpp-advanced/read-standard)을 봅니다. cppreference의 설명은 표준의 항목을 옮긴 것이어서 찾아가기 쉽습니다.
3. 표준이 "정의되지 않은 동작"이나 "구현이 정한다"에서 멈추면 **컴파일러의 출력**을 봅니다.
4. 빠른지는 출력을 보고 짐작하지 않고 잽니다.

## 정리

- cppreference는 표준을 옮겨 적은 위키다. `(since C++26)` 같은 표시가 그 기능이 들어온 표준을 말하고, 내 컴파일러에 있는지는 `-std`와 기능 시험 매크로가 말한다
- 컴파일러가 실제로 한 일은 탐색기나 `objdump`의 어셈블리, 벡터화 보고, 최적화 뒤의 덤프로 본다. `span`의 `[]`는 단언을 켰을 때만 `cmp`와 `jae`가 생겼다
- 출력은 그 컴파일러와 옵션의 답이지 약속이 아니다. 같은 더하기가 GCC `-O2`에서는 루프였고 `-O3`와 Clang에서는 상수 15였다
