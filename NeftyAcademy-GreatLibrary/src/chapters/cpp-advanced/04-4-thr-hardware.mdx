스레드를 몇 개 만들지는 코드가 아니라 **기계**가 정합니다. 코어가 몇 개인지, 그 가운데 내 프로그램이 쓸 수 있는 것이 몇 개인지, 어느 스레드가 어느 코어에서 도는지를 묻고 정하는 방법을 봅니다. 표준이 주는 것은 숫자 하나뿐이고 나머지는 운영체제의 일입니다.

## 코어가 몇 개인가

```cpp
#include <pthread.h>
#include <sched.h>

#include <new>
#include <print>
#include <stop_token>
#include <thread>

// 이 프로세스가 돌 수 있는 CPU 의 수 (리눅스)
int usable_cpus()
{
    cpu_set_t set;
    CPU_ZERO(&set);
    if (sched_getaffinity(0, sizeof set, &set) != 0) return 1;
    return CPU_COUNT(&set);
}

// 스레드를 CPU 하나에 묶는다
bool pin_to(std::jthread& thread, int cpu)
{
    cpu_set_t set;
    CPU_ZERO(&set);
    CPU_SET(cpu, &set);
    return pthread_setaffinity_np(thread.native_handle(), sizeof set, &set) == 0;
}

int main()
{
    std::println("켜진 CPU {}, 쓸 수 있는 CPU {}",
                 std::thread::hardware_concurrency(), usable_cpus());
    std::println("캐시 줄로 잡은 크기 {}",
                 std::hardware_destructive_interference_size);

    int seen_cpu = -1;
    char name[16] = {};
    {
        std::jthread worker([&](std::stop_token stop) {
            while (!stop.stop_requested()) std::this_thread::yield();
            seen_cpu = sched_getcpu();          // 지금 돌고 있는 CPU 번호
            pthread_getname_np(pthread_self(), name, sizeof name);
        });
        pthread_setname_np(worker.native_handle(), "sampler");  // 15자까지
        std::println("묶였나 {}", pin_to(worker, 0));
    }
    std::println("스레드가 돈 CPU {}, 이름 {}", seen_cpu, name);
}
```

```text nocheck
켜진 CPU 2, 쓸 수 있는 CPU 2
캐시 줄로 잡은 크기 64
묶였나 true
스레드가 돈 CPU 0, 이름 sampler
```

코어 2개짜리 x86-64 서버 VM에서 나온 값입니다. 같은 프로그램을 `taskset -c 1 ./a.out`으로 CPU 하나에만 허용해 돌리면 첫 줄이 `켜진 CPU 2, 쓸 수 있는 CPU 1`이 됩니다.

| 묻는 법 | 답 | 조심할 것 |
| --- | --- | --- |
| `std::thread::hardware_concurrency()` | 켜져 있는 논리 CPU의 수 | 알 수 없으면 0이다. **내가 쓸 수 있는 수가 아니다** |
| `sched_getaffinity`와 `CPU_COUNT` | 이 프로세스에 허용된 CPU의 수 | 리눅스 전용. `taskset`과 컨테이너의 CPU 지정이 반영된다 |
| cgroup의 `cpu.max` | CPU 시간의 할당량 | `--cpus=1.5` 같은 제한은 위의 둘에 나타나지 않는다 |

GCC 14의 libstdc++와 Clang 20의 libc++ 모두 `taskset`으로 줄여도 `hardware_concurrency()`는 2를 돌려줬습니다. 코어 64개짜리 서버에서 CPU 둘만 받은 컨테이너가 스레드 64개를 띄우는 것이 이 때문입니다. 스레드 풀의 크기는 둘째 줄의 값으로 정합니다.

"논리 CPU"는 코어와 같지 않을 수 있습니다. 동시 멀티스레딩(하이퍼스레딩)이 켜진 x86은 코어 하나가 논리 CPU 둘로 보이고, 둘은 계산 장치를 나눠 씁니다. 큰 코어와 작은 코어가 섞인 칩도 있습니다. 어느 번호가 어느 코어인지는 `/sys/devices/system/cpu/cpu0/topology/` 아래에 있습니다. 라즈베리 파이 4와 5는 같은 코어 4개이고 논리 CPU도 4개입니다.

## 스레드를 더 만들면

| 같은 양의 계산을 나눈 스레드 수 | 걸린 시간 | 1개일 때의 몇 배 빠른가 |
| --- | --- | --- |
| 1 | 3,140 ms | 1.00 |
| 2 | 1,580 ms | 1.99 |
| 4 | 1,570 ms | 2.00 |
| 8 | 1,590 ms | 1.97 |
| 64 | 1,600 ms | 1.96 |

위의 VM(코어 2개)에서 서로 나눠 쓰는 것이 없는 계산을 돌린 결과입니다. 코어 수까지는 스레드 수만큼 빨라지고, 그 뒤로는 **전혀** 빨라지지 않습니다. 이 계산은 느려지지도 않았지만, 스레드마다 [스택과 만드는 시간](#/read/cpp-advanced/thr-jthread)이 들고, 자료를 나눠 쓰는 일이라면 다투는 스레드가 늘어 실제로 느려집니다.

| 스레드가 하는 일 | 알맞은 수 |
| --- | --- |
| 계산 | 쓸 수 있는 코어 수. 넘겨도 얻는 것이 없다 |
| 기다림 (파일, 네트워크, 장치) | 코어 수와 상관없다. 동시에 기다릴 일의 수만큼 |
| 둘이 섞인 프로그램 | 계산용 풀은 코어 수로 고정하고, 기다리는 스레드는 따로 둔다 |

## 캐시 줄의 크기

두 스레드가 서로 다른 변수를 고쳐도, 그 변수들이 같은 캐시 줄에 있으면 [서로를 느리게 만듭니다](#/read/cpp-advanced/atm-false-sharing). 떼어 놓으려면 줄의 크기를 알아야 하고, 표준이 그 값을 줍니다.

| `<new>`의 상수 | x86-64 | AArch64 |
| --- | --- | --- |
| `std::hardware_destructive_interference_size` (떼어 놓을 거리) | 64 | 256 |
| `std::hardware_constructive_interference_size` (함께 둘 크기) | 64 | 64 |

GCC 14의 값입니다. 이 값은 컴파일러가 그 아키텍처의 여러 칩을 보고 **넉넉하게** 잡은 것이지 지금 이 기계의 값이 아닙니다. 이 VM의 실제 줄 크기는 `/sys/devices/system/cpu/cpu0/cache/index0/coherency_line_size`에 64로 적혀 있습니다. `alignas(std::hardware_destructive_interference_size)`를 붙인 구조체는 x86-64에서 64바이트, AArch64에서 256바이트가 됩니다.

<Note kind="warn">
이 상수를 **헤더에서** 쓰면 GCC가 `-Winterference-size`로 경고합니다. 컴파일러 버전이나 `-mtune`에 따라 값이 달라질 수 있어서, 헤더를 나눠 쓰는 두 파일의 구조체 크기가 어긋날 수 있기 때문입니다. 밖으로 보이는 타입에는 `inline constexpr std::size_t cache_line = 64;`처럼 직접 정한 값을 씁니다.
</Note>

## 코어에 묶기

첫 예제의 `pin_to`가 묶는 방법입니다. 표준에는 없으므로 `native_handle()`로 pthread 핸들을 꺼내 리눅스의 함수를 부릅니다. 윈도우에서는 같은 자리에 `SetThreadAffinityMask`를 씁니다(이 책에서 돌려 보지는 못했습니다).

| 계산하는 스레드 둘을 | 걸린 시간 |
| --- | --- |
| 서로 다른 코어에 묶는다 | 1,200 ms |
| 같은 코어에 묶는다 | 2,400 ms |

잘못 묶으면 코어가 남아도 반으로 느려집니다. 묶지 않으면 스케줄러가 알아서 흩어 놓으므로, 묶는 것은 까닭이 있을 때만 합니다.

| 묶을 까닭 | 설명 |
| --- | --- |
| 주기가 일정해야 하는 스레드 | 다른 코어로 옮겨질 때마다 캐시가 식고 지연이 튄다. 모터 제어, 오디오 |
| 측정 | 벤치마크가 돌 때마다 같은 조건이 되게 한다 |
| 메모리가 CPU마다 따로 붙은 서버(NUMA) | 스레드를 자기 메모리가 있는 쪽에 둔다 |

이름은 까닭 없이도 붙입니다. `pthread_setname_np`로 붙인 이름(15자까지)은 `top -H`, `htop`, gdb의 `info threads`에 나옵니다. 스레드가 열 개인 프로그램에서 어느 것이 CPU를 다 쓰는지 한눈에 보입니다.

## 정리

- `hardware_concurrency()`는 기계의 논리 CPU 수다. 내 프로세스가 쓸 수 있는 수는 `sched_getaffinity`로 묻는다
- 계산하는 스레드는 코어 수를 넘겨도 빨라지지 않는다. 기다리는 스레드는 코어 수와 따로 센다
- 묶기와 이름 붙이기는 `native_handle()`로 운영체제의 함수를 부른다. 묶는 것은 까닭이 있을 때만 한다
