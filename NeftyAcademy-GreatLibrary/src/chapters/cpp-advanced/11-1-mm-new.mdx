이 책은 "할당이 몇 번 일어났는가"를 여러 번 세었습니다. 그때마다 예제 맨 위에 있던 `void* operator new(std::size_t)`가 그 장치입니다. 프로그램이 정의하면 **표준 라이브러리의 것을 대신하는** 드문 함수입니다. 이 페이지에서 그것을 제대로 봅니다. [`new`가 하는 두 가지 일](#/read/cpp-syntax/life-new) 가운데 메모리를 잡는 쪽입니다.

## new 식이 부르는 함수

`operator new`는 하나가 아닙니다. 모든 갈래를 바꿔 놓고 무엇이 불리는지 찍어 본 결과입니다. 두 컴파일러가 같았습니다.

| 식 | 잡을 때 | 풀 때 |
| --- | --- | --- |
| `new Sample` (16바이트) | `operator new(16)` | `operator delete(p, 16)` |
| `new int[4]` | `operator new[](16)` | `operator delete[](p)` |
| `new WithDtor[4]` (소멸자가 있다) | `operator new[](24)` | `operator delete[](p, 24)` |
| `new (std::nothrow) Sample` | `operator new(16, nothrow)` | `operator delete(p, 16)` |
| `new CacheLine` (`alignas(64)`) | `operator new(64, align_val_t{64})` | `operator delete(p, 64, align_val_t{64})` |

- **풀 때 크기가 함께 온다.** 컴파일러가 타입의 크기를 알기 때문입니다. 크기별로 풀을 나눈 할당기는 이것으로 어느 풀인지를 바로 압니다.
- **소멸자가 있는 타입의 배열은 8바이트를 더 잡는다.** `delete[]`가 소멸자를 몇 번 부를지 알아야 해서, 원소 앞에 개수를 적어 둡니다. `int`처럼 소멸자가 할 일이 없으면 적지 않고, 그래서 풀 때 크기도 모릅니다.
- **정렬이 16을 넘으면 다른 갈래로 간다.** 그 갈래를 바꾸지 않았다면 표준 라이브러리의 것이 불립니다. libstdc++의 `std::pmr` 기본 자원은 정렬이 작아도 이 갈래를 부릅니다. [할당을 세다가 놓친 적이 있습니다](#/read/cpp-advanced/mm-pmr).

바꾸지 않은 갈래는 기본 구현이 받습니다. 기본 `operator new[]`와 `nothrow` 판은 `operator new(size)`를 부르도록 되어 있으므로, **`operator new(size)`와 `operator delete(p)` 둘만 바꿔도** 대부분이 따라옵니다.

## 장부를 단다

```cpp
#include <algorithm>
#include <cstddef>
#include <cstdlib>
#include <map>
#include <new>
#include <print>
#include <string>
#include <vector>

// ---- 프로그램의 모든 new를 세는 장부 ----
struct Ledger {
    long count = 0;   // 할당한 횟수
    long bytes = 0;   // 요청한 바이트의 합
    long live = 0;    // 지금 살아 있는 바이트
    long peak = 0;    // live가 가장 컸을 때
};
static Ledger ledger;

// 블록 앞에 16바이트를 더 잡아 크기를 적어 둔다
static constexpr std::size_t header = 16;

void* operator new(std::size_t size)
{
    auto* base = static_cast<std::size_t*>(std::malloc(size + header));
    if (base == nullptr)
        throw std::bad_alloc();
    *base = size;
    ++ledger.count;
    ledger.bytes += static_cast<long>(size);
    ledger.live += static_cast<long>(size);
    ledger.peak = std::max(ledger.peak, ledger.live);
    return reinterpret_cast<std::byte*>(base) + header;
}
void operator delete(void* p) noexcept
{
    if (p == nullptr)
        return;
    auto* base =
        reinterpret_cast<std::size_t*>(static_cast<std::byte*>(p) - header);
    ledger.live -= static_cast<long>(*base);
    std::free(base);
}
void operator delete(void* p, std::size_t) noexcept { operator delete(p); }

// 이 객체가 살아 있는 동안의 할당을 알려 준다
class Spy {
public:
    explicit Spy(const char* what) : what_(what), start_(ledger)
    {
        ledger.peak = ledger.live;
    }
    ~Spy()
    {
        const long count = ledger.count - start_.count;
        const long bytes = ledger.bytes - start_.bytes;
        const long peak = ledger.peak - start_.live;
        std::println("{}: {}번, 모두 {}바이트, 한때 가장 많이 {}바이트", what_,
                     count, bytes, peak);
    }

private:
    const char* what_;
    Ledger start_;
};

int main()
{
    {
        Spy spy("push_back 1000번");
        std::vector<int> values;
        for (int i = 0; i < 1000; ++i)
            values.push_back(i);
    }
    {
        Spy spy("reserve 뒤 push_back 1000번");
        std::vector<int> values;
        values.reserve(1000);
        for (int i = 0; i < 1000; ++i)
            values.push_back(i);
    }
    {
        Spy spy("map에 100개");
        std::map<int, int> table;
        for (int i = 0; i < 100; ++i)
            table[i] = i;
    }
    {
        Spy spy("16글자 string");
        std::string name(16, 'x');
    }
}
```

```text
push_back 1000번: 11번, 모두 8188바이트, 한때 가장 많이 6144바이트
reserve 뒤 push_back 1000번: 1번, 모두 4000바이트, 한때 가장 많이 4000바이트
map에 100개: 100번, 모두 4000바이트, 한때 가장 많이 4000바이트
16글자 string: 1번, 모두 17바이트, 한때 가장 많이 17바이트
```

첫 줄의 6,144가 눈여겨볼 숫자입니다. `vector`가 자랄 때는 새 버퍼(4,096)와 옛 버퍼(2,048)가 **함께** 살아 있습니다. 끝난 뒤에 4,000바이트만 쓰는 컨테이너가 한때 그 한 배 반을 씁니다. 메모리가 빠듯한 곳에서 `reserve`가 속도보다 이 꼭대기 때문에 중요합니다.

마지막 줄은 libstdc++의 결과입니다. libc++에서는 0번입니다. 짧은 문자열을 안에 담는 한계가 libstdc++는 15글자, libc++는 22글자이기 때문입니다.

## 지킬 것

| 규칙 | 어기면 |
| --- | --- |
| 전역 이름공간에, `inline`이 아니게, 프로그램에 하나만 | 링크 오류이거나, 바꾼 것이 쓰이지 않는다 |
| `operator new`는 못 잡으면 `std::bad_alloc`을 던진다. `nullptr`를 돌려주지 않는다 | 부르는 쪽은 검사하지 않고 그대로 쓴다 |
| `operator delete`는 `nullptr`를 받아도 되고, 던지지 않는다 | `delete p;`는 `p`가 비었어도 부른다 |
| 안에서 **할당하는 것을 부르지 않는다** | `std::println`, `std::string`이 다시 `new`를 불러 끝없이 되풀이한다 |
| `new`를 바꾸면 `delete`도 바꾼다 | 내 방식으로 잡은 것을 남의 방식으로 푼다 |
| 여러 스레드가 쓰면 세는 변수를 [원자적으로](#/read/cpp-advanced/atm-atomic) | 위 예제는 한 스레드라서 그냥 두었다 |

예제의 `Spy`가 소멸자에서 **먼저 숫자를 읽고 나서** `std::println`을 부르는 것도 넷째 규칙 때문입니다. 찍는 일 자체가 할당을 하므로, 순서가 바뀌면 그것까지 세게 됩니다.

## malloc의 값

`operator new`의 기본 구현은 `malloc`을 부릅니다. glibc 2.39, x86-64에서 잰 것입니다.

| 잰 것 | 값 |
| --- | --- |
| 16바이트에서 256바이트를 잡고 바로 풀기 | 한 쌍에 10 ns |
| 4,096바이트를 잡고 바로 풀기 | 16 ns |
| 64바이트 100만 개를 잡아 두기 | 하나에 41 ns. 운영체제에서 새 메모리를 받아 온다 |
| 그 100만 개를 풀기 | 하나에 10 ns |
| 두 스레드가 동시에 각자 잡고 풀기 | 한 쌍에 11 ns. 스레드마다 캐시가 따로 있다 |
| 한 스레드가 잡은 것을 다른 스레드가 풀기 | 하나에 13 ns |

| 요청한 크기 | 실제로 쓸 수 있는 크기 |
| --- | --- |
| 1, 8, 24 | 24 |
| 25, 40 | 40 |
| 41 | 56 |
| 100 | 104 |

블록마다 8바이트의 머리표가 붙고 16바이트 단위로 올림됩니다. 1바이트를 달라고 해도 32바이트가 나갑니다. `map`의 노드 하나(40바이트)는 48바이트를 차지합니다. **작은 것을 많이** 잡는 프로그램에서 메모리와 시간이 새는 곳이 여기이고, [풀과 아레나](#/read/cpp-advanced/mm-arena)가 겨냥하는 것도 여기입니다.

<Note>
바꾸는 자리는 셋입니다. 전역 `operator new`(이 페이지), 클래스 안에 정의하는 `operator new`(그 클래스만. [코루틴의 프레임](#/read/cpp-advanced/co-cost)에서 썼습니다), 그리고 `malloc` 자체를 다른 구현으로 갈아 끼우는 것입니다. tcmalloc, jemalloc, mimalloc이 셋째에 해당하고 링크만 바꾸면 됩니다. 이 책에서는 그것들을 재 보지 않았습니다. 새는 메모리를 찾는 일은 직접 만들지 말고 [새니타이저](#/read/cpp-syntax/ubc-tools)에 맡깁니다.
</Note>

## 정리

- `new` 식은 타입에 따라 다른 `operator new`를 부른다. `operator new(size)`와 `operator delete(p)` 둘을 바꾸면 대부분이 따라온다
- 바꾼 함수 안에서는 할당하는 것을 부르지 않는다. 못 잡으면 던지고, `delete`는 `nullptr`를 받는다
- glibc의 `malloc`은 한 쌍에 10 ns이고 블록마다 8바이트가 더 든다. 작은 할당이 많을 때 값이 된다
