연산 증폭기는 넷리스트 한 줄로도 적을 수 있습니다. 그 한 줄짜리 모델은 셈을 확인하기에는 좋지만, 실제 부품이 가진 한계를 하나도 모릅니다. 같은 증폭기를 두 가지 모델로 돌려 그 차이를 봅니다.

## 한 줄짜리 연산 증폭기

<Figure caption="입력을 11배로 키우는 회로. 출력의 11분의 1이 fb로 되돌아와 − 입력에 들어간다">

</Figure>

```spice
이상적인 연산 증폭기: 11배 증폭
V1 in 0 0.1
E1 out 0 in fb 100k
R1 fb 0 1k
R2 out fb 10k
.dc V1 0.1 0.5 0.2
.print dc v(out)
.end
```

```text
$ ngspice -b ideal.cir
Index  v-sweep       v(out)
0      1.000000e-01  1.099879e+00
1      3.000000e-01  3.299637e+00
2      5.000000e-01  5.499395e+00
```

- **`E1 out 0 in fb 100k`**: `E`는 전압으로 조절되는 전압원입니다. `in`과 `fb`의 차이에 100,000을 곱한 전압을 `out`과 접지 사이에 냅니다. 연산 증폭기가 하는 일의 뼈대가 이 한 줄입니다
- **되먹임이 11배를 만든다**: 출력이 `fb`를 `in`과 같아질 때까지 끌고 갑니다. `fb`는 출력의 11분의 1이므로 출력은 입력의 11배입니다. 0.1V가 1.0999V가 되었습니다
- **전원을 모른다**: 0.5V를 넣으면 5.5V가 나옵니다. 이 회로를 3.3V로 돌릴 생각이었더라도 그렇습니다. 이 모델에는 전원 핀이 없습니다

## 전원과 속도를 아는 모델

```spice file=opamp.lib
* LM358 데이터시트에 맞춘 연산 증폭기
.subckt OPAMP p n vcc vee out
B1 0 x I=68u*tanh(14.7*(v(p)-v(n)))
R1 x 0 100Meg
C1 x 0 227p
D1 x hi DCL
D2 lo x DCL
Vhi vcc hi 1.5
Vlo lo vee 20m
E1 out 0 x 0 1
.model DCL D(N=0.01)
.ends
```

- **여러 줄을 한 덩어리로 묶었다**: `.subckt`에서 `.ends`까지가 부품 하나입니다. 핀은 +입력, −입력, 전원, 접지 쪽 전원, 출력의 다섯입니다. 묶는 법은 다음 쪽에서 봅니다
- **`B1`과 `R1`이 이득이다**: `B`는 식으로 적는 전원입니다. 두 입력의 차이에 비례하는 전류를 내고, 100MΩ이 그것을 100,000배의 전압으로 바꿉니다. `tanh`는 그 전류가 68µA를 넘지 못하게 합니다
- **`C1`이 속도다**: 100MΩ과 227pF이 7Hz에서 꺾이게 해서, 이득과 대역의 곱이 0.7MHz가 됩니다. 68µA로 227pF을 채우므로 출력은 1µs에 0.3V보다 빨리 변하지 못합니다
- **`D1`, `D2`, `Vhi`, `Vlo`가 전원이다**: 안쪽 전압이 전원보다 1.5V 낮은 곳과 접지보다 20mV 높은 곳을 벗어나지 못하게 묶습니다

## 두 모델을 견주기

<Figure caption="입력을 0V에서 0.3V까지 올릴 때의 출력. 가로 점선은 3.3V 전원에서 1.5V를 뺀 1.8V">

```spice with=opamp.lib
같은 증폭기를 두 모델로
V1 in 0 0.1
VCC vcc 0 3.3
E1 o1 0 in f1 100k
R1 f1 0 1k
R2 o1 f1 10k
X1 in f2 vcc 0 o2 OPAMP
R3 f2 0 1k
R4 o2 f2 10k
.include opamp.lib
.dc V1 0 0.3 0.01
.meas dc ideal_0 FIND v(o1) AT=0
.meas dc real_0 FIND v(o2) AT=0
.meas dc ideal_1 FIND v(o1) AT=0.1
.meas dc real_1 FIND v(o2) AT=0.1
.meas dc ideal_25 FIND v(o1) AT=0.25
.meas dc real_25 FIND v(o2) AT=0.25
.end
```

```text
$ ngspice -b compare.cir
ideal_0  = 0.000000e+00
real_0   = 1.515277e-02
ideal_1  = 1.099879e+00
real_1   = 1.099879e+00
ideal_25 = 2.749698e+00
real_25  = 1.805814e+00
```

- **가운데에서는 같다**: 0.1V를 넣으면 둘 다 1.0999V입니다. 한계에 닿지 않는 동안에는 한 줄짜리 모델로 충분합니다
- **위가 막힌다**: 0.25V를 넣으면 2.75V가 나와야 하는데 1.81V에서 멈춥니다. 전원이 3.3V이면 이 부품의 출력은 1.8V까지만 올라갑니다. 3.3V까지 가득 쓰는 신호를 만들려던 회로라면 여기서 틀어집니다
- **아래도 막힌다**: 0V를 넣어도 출력은 15mV입니다. 0에 가까운 작은 신호를 재는 회로에서는 이 15mV가 그대로 오차가 됩니다
- **부품을 고르는 물음이 된다**: 전원 끝까지 출력이 나오는 부품이 필요한지가 이 그림에서 정해집니다([「버퍼」](#/read/analog-digital/cd-buffer))

## 속도를 견주기

```spice with=opamp.lib
두 모델의 주파수 훑기
V1 in 0 DC 0.1 AC 1
VCC vcc 0 3.3
E1 o1 0 in f1 100k
R1 f1 0 1k
R2 o1 f1 10k
X1 in f2 vcc 0 o2 OPAMP
R3 f2 0 1k
R4 o2 f2 10k
.include opamp.lib
.ac dec 20 10 10Meg
.save v(o1) v(o2)
.meas ac ideal_1m FIND vm(o1) AT=1Meg
.meas ac real_1k FIND vm(o2) AT=1k
.meas ac real_f3 WHEN vm(o2)=7.778
.meas ac real_1m FIND vm(o2) AT=1Meg
.end
```

```text
$ ngspice -b speed.cir
Warning: can't parse 'vm': ignored
ideal_1m = 1.099879e+01
real_1k  = 1.099744e+01
real_f3  = 6.37271e+04
real_1m  = 6.994242e-01
```

- **한 줄짜리 모델은 어느 주파수에서나 11배다**: 1MHz에서도 10.999배입니다
- **전원을 아는 모델은 63.7kHz에서 꺾인다**: 0.7MHz를 이득 11로 나눈 주파수입니다. 1MHz에서는 0.7배로, 키우기는커녕 줄입니다
- **큰 계단은 더 느리다**: 같은 증폭기의 입력을 0.02V에서 0.15V로 갑자기 올리면, 출력은 1µs에 0.26V씩 오르다가 12µs 뒤에야 1.65V에 닿습니다. 주파수 훑기에는 나타나지 않고 과도 해석에만 나타나는 한계입니다

## 제조사의 모델을 쓸 때

- **제조사는 부품마다 모델 파일을 내놓는다**: 연산 증폭기의 모델은 모두 하위 회로 꼴이고, `X1 +입력 −입력 전원 … 이름`처럼 부릅니다. 핀의 차례는 부품마다 다르므로 파일 머리의 주석에서 확인합니다
- **모델마다 담은 것이 다르다**: 위의 모델은 데이터시트의 숫자 다섯(이득, 대역, 기울기, 출력의 위아래 끝)만 흉내 냅니다. 입력이 받아들이는 전압의 범위, 입력에 흐르는 전류, 오프셋 전압, 잡음은 들어 있지 않습니다. 제조사의 모델도 무엇을 담았는지가 제각각입니다
- **돌려서 확인한다**: 모델을 받으면 이 쪽에서 한 것처럼 입력을 훑어 출력이 어디서 막히는지, 주파수를 훑어 어디서 꺾이는지부터 보고 데이터시트와 견줍니다

<Note>
넷리스트 셋과 그림은 ngspice 42로 돌린 결과이고, 계단을 넣은 과도 해석(0.4V에서 0.8V까지의 기울기 0.264V/µs, 1.63V에 닿는 시각)도 따로 돌려 확인했습니다. `OPAMP`는 TI가 내놓은 모델이 아니라, TI의 LM358 데이터시트에 적힌 대푯값(이득 100V/mV, 0.7MHz, 0.3V/µs, 출력은 전원에서 1.5V 아래까지와 접지 위 5~20mV까지)에 맞춰 제가 만든 것입니다. 실제 LM358은 이 모델보다 복잡하게 굽니다. 제조사의 모델 파일은 제가 내려받아 돌려 보지 못했습니다.
</Note>

## 정리

- `E` 전원 한 줄로 적은 연산 증폭기는 되먹임의 셈을 확인하는 데 쓴다. 전원 전압과 속도는 모른다
- 실제 부품은 출력이 전원 끝까지 가지 못하고, 이득과 대역의 곱과 기울기에 한계가 있다. 그것을 담은 모델로 돌려야 보인다
- 모델을 받으면 입력과 주파수를 훑어 어디서 막히고 꺾이는지를 데이터시트와 견준다
