넷리스트의 숫자에는 `10k`, `100n`처럼 접미사를 붙여 씁니다. 편하지만 사람의 버릇과 어긋나는 곳이 몇 군데 있고, 그 대부분은 오류 없이 다른 값으로 읽힙니다. 이 쪽은 ngspice가 숫자를 어떻게 읽었는지 직접 확인해 가며 그 자리들을 짚습니다.

## 접미사 아홉 개

| 접미사 | 곱하는 값 | 보기 |
| --- | --- | --- |
| `T` | 10¹² | `1T`는 1TΩ |
| `G` | 10⁹ | `1G`는 1GΩ |
| `Meg` | 10⁶ | `1Meg`는 1MΩ |
| `k` | 10³ | `4.7k`는 4.7kΩ |
| `m` | 10⁻³ | `10m`은 10mH, 10ms |
| `u` | 10⁻⁶ | `1u`는 1µF, 1µs |
| `n` | 10⁻⁹ | `100n`은 100nF |
| `p` | 10⁻¹² | `22p`는 22pF |
| `f` | 10⁻¹⁵ | `1f`는 1fF |

- **대문자와 소문자를 가리지 않는다**: `K`와 `k`가 같고 `MEG`와 `Meg`가 같습니다. 그래서 `M`과 `m`도 같습니다
- **숫자에 붙여 쓴다**: `10 k`처럼 띄면 `unknown parameter (k)`라는 오류로 멈춥니다
- **지수로도 적는다**: `2.2e3`은 2200이고 `1e-6`은 `1u`와 같습니다
- **값이 있는 곳 어디에나 쓴다**: 소자의 값, `.tran 1u 5m`의 시간, `PULSE`의 숫자에 모두 같은 접미사를 씁니다
- **덜 쓰는 둘**: `mil`은 25.4×10⁻⁶이고 `a`는 10⁻¹⁸입니다. 쓸 일은 드물지만 아래에서 `a`가 한 번 발목을 잡습니다

## 읽힌 저항값 보기

```spice
1A를 흘려 읽힌 저항값 보기
I1 0 a 1
R1 a 0 1M
I2 0 b 1
R2 b 0 1Meg
I3 0 c 1
R3 c 0 4k7
I4 0 d 1
R4 d 0 1,5k
I5 0 e 1
R5 e 0 10kOhm
.op
.end
```

```text
$ ngspice -b suffix.cir
e           1.000000e+04
d           5.000000e+03
c           4.000000e+03
b           1.000000e+06
a           1.000000e-03
```

- **1A를 흘려 본다**: 저항에 1A를 흘리면 전압의 숫자가 곧 저항값입니다. ngspice가 숫자를 어떻게 읽었는지 이렇게 물어볼 수 있습니다
- **`1M`은 1mΩ이다**: 메가옴을 적으려던 것이 밀리옴이 되었습니다. 메가는 `Meg`입니다
- **`4k7`은 4kΩ이다**: 부품에 찍힌 `4k7`은 4.7kΩ이라는 뜻이지만, 접미사 뒤의 글자는 버려져서 7이 사라졌습니다
- **`1,5k`는 5kΩ이다**: 쉼표는 빈칸과 같은 구분자입니다. 1과 5k로 갈라졌고 뒤의 것이 값이 되었습니다. 소수점은 마침표로 적습니다
- **`10kOhm`은 10kΩ이다**: 접미사 뒤의 글자가 버려지는 덕분에 단위를 붙여도 뜻대로 읽힙니다. 그런데 이 너그러움이 다음 함정을 만듭니다

## 단위 글자가 접미사로 읽힐 때

```spice
단위 글자가 접미사로 읽히는 두 곳
V1 in 0 5V
C1 in 0 1F
C2 in 0 1
C3 in 0 100nF
I1 0 out 2A
I2 0 out 20mA
R1 out 0 1k
.op
.end
```

```text
$ ngspice -b units.cir
device          c3     c2     c1
capacitance  1e-07      1  1e-15
device     i2     i1
dc       0.02  2e-18
```

- **소자의 표에 읽힌 값이 나온다**: 배치 출력의 뒤쪽에 소자마다 `resistance`, `capacitance`, `dc` 같은 줄이 있습니다. ngspice가 읽은 값이 그대로 적혀 있습니다
- **`1F`는 1펨토패럿이다**: 숫자 바로 뒤의 `F`는 단위가 아니라 접미사 `f`로 읽힙니다. 1패럿은 `1`이라고 적습니다
- **`2A`는 2아토암페어다**: 숫자 바로 뒤의 `A`는 접미사 `a`로 읽혀 2×10⁻¹⁸A가 되었습니다. 2암페어는 `2`입니다
- **앞에 접미사가 있으면 괜찮다**: `100nF`는 100nF, `20mA`는 20mA, `5V`는 5V로 읽혔습니다. 접미사 뒤의 글자와, 접미사가 아닌 글자는 버려지기 때문입니다
- **가장 안전한 버릇**: 단위 글자를 아예 붙이지 않습니다. 소자의 첫 글자가 이미 단위를 정합니다

## 프로그램마다 다른 곳

- **`4k7`**: LTspice의 도움말은 `6K34`를 6.34K로 읽는다고 적어 두었습니다. ngspice 42도 LTspice에 맞추는 호환 방식(`set ngbehavior=lt`)을 켜면 `4k7`을 4.7kΩ으로 읽었고, 끄면 4kΩ으로 읽었습니다. 프로그램과 설정에 따라 값이 달라지는 표기이므로 `4.7k`로 적습니다
- **넷리스트의 `1M`은 어디서나 밀리다**: LTspice의 도움말도 `1M`을 1mΩ으로 읽는다고 따로 밝혀 두었습니다. ngspice의 호환 방식을 켜도 그대로입니다. KiCad의 회로도에서 부품의 값 칸에 적는 `1M`만은 메가입니다([「회로도와 시뮬레이션 모델 붙이기」](#/read/circuit-sim/kc-schematic))
- **마이크로 기호**: ngspice 42는 `10µ`의 마이크로 기호(U+00B5)를 `u`로 읽었습니다. 그런데 똑같이 생긴 그리스 글자 뮤(U+03BC)로 적은 것은 접미사로 읽지 못해 10이 되었습니다. 눈으로는 가릴 수 없으므로 늘 `u`를 씁니다
- **호환 방식 이야기**: `ngbehavior`는 제조사의 모델을 가져올 때 다시 나옵니다([「.subckt와 제조사 모델 가져오기」](#/read/circuit-sim/dv-subckt))

## 적는 버릇과 확인하는 버릇

```sh
ngspice -b units.cir 2>/dev/null |
  grep -E 'device|resistance|capacitance|inductance| dc '
```

- **소수점은 마침표, 접미사는 숫자에 붙여 하나만**: `4.7k`, `100n`, `1.5Meg`처럼 적습니다
- **메가는 `Meg`, 마이크로는 `u`**: 이 둘만 지켜도 가장 흔한 실수를 피합니다
- **단위 글자는 붙이지 않는다**: 특히 숫자 바로 뒤의 `F`와 `A`를 조심합니다
- **돌린 뒤 읽힌 값을 본다**: 위의 명령은 소자의 표에서 이름과 값의 줄만 뽑습니다. 값이 천 배, 백만 배 다르게 읽힌 곳이 한눈에 보입니다

<Note>
이 쪽의 넷리스트 둘과 글머리에 적은 값들(접미사 아홉 개와 `mil`, 띄어 쓴 `10 k`의 오류, 지수 표기, 호환 방식을 켠 `4k7`과 `1M`, 두 가지 마이크로 글자)은 모두 ngspice 42로 돌려 확인했습니다. `a`가 10⁻¹⁸이라는 것은 설명서의 표와 `2A`를 돌린 결과가 같습니다. LTspice의 이야기는 도움말에서 옮긴 것이고 제가 돌려 보지는 못했습니다. 다른 판의 ngspice가 `4k7`과 마이크로 기호를 똑같이 읽는지는 확인하지 못했습니다.
</Note>

## 정리

- 접미사는 대소문자를 가리지 않는다. `M`은 밀리이고 메가는 `Meg`다
- 숫자 바로 뒤의 `F`와 `A`는 단위가 아니라 펨토와 아토로 읽힌다. 단위 글자는 붙이지 않는다
- `4k7`, 쉼표, 그리스 글자 뮤는 오류 없이 다른 값이 된다. 배치 출력의 소자 표에서 읽힌 값을 확인한다
