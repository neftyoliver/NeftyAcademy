export const terms = ['endc'];

대화형에서 칠 명령을 넷리스트 안에 적어 둔 것이 `.control` 블록입니다. 값을 바꿔 가며 되풀이하거나 파형으로 셈을 할 때 씁니다. [「값 바꿔 가며 돌리기」](#/read/circuit-sim/an-param)에서 한 번 빌려 썼던 것을 여기서 제대로 봅니다.

## 명령을 차례로

```spice
명령을 차례로 내리기
V1 in 0 5
R1 in out 10k
R2 out 0 20k
.control
op
print v(out)
let ratio = v(out)/v(in)
print ratio
alter R2 = 10k
op
print v(out)
echo "끝"
.endc
.end
```

```text
$ ngspice -b commands.cir
v(out) = 3.333333e+00
ratio  = 6.666667e-01
v(out) = 2.500000e+00
끝
```

- **`.control`에서 `.endc`까지가 명령이다**: 넷리스트를 다 읽은 뒤에 위에서부터 차례로 합니다
- **해석은 점을 떼고 적는다**: `op`, `tran 10u 5m`, `dc V1 0 5 0.1`, `ac dec 20 1 100k`처럼 적습니다. 한 블록에서 여러 번, 여러 가지를 돌릴 수 있습니다
- **`print`와 `echo`**: `print`는 벡터와 식의 값을, `echo`는 글을 찍습니다
- **`let 이름 = 식`**: 새 벡터를 만듭니다. `ratio`는 출력이 입력의 몇 배인지입니다
- **`alter`**: 소자의 값을 고칩니다. 그 뒤의 해석부터 고친 값이 쓰입니다

## 파형으로 셈하기

```spice
파형으로 셈하기: 저항이 낸 열
V1 in 0 PULSE(0 3.3 0 1u 1u 1 2)
R1 in out 1k
C1 out 0 1u
.control
tran 10u 10m
print length(v(out))
let p = (v(in)-v(out))^2/1k
meas tran e_r INTEG p FROM=0 TO=10m
let e_c = 0.5*1u*maximum(v(out))^2
print e_c
quit
.endc
.end
```

```text
$ ngspice -b energy.cir
length(v(out)) = 1.019000e+03
e_r            = 5.44331e-06 from= 0.00000e+00 to= 1.00000e-02
e_c            = 5.444505e-06
```

- **과도 해석의 결과는 점마다 값이 든 벡터다**: `v(out)`에는 값이 1019개 들어 있습니다. `time`도 벡터입니다
- **`let`의 식은 점마다 셈한다**: `p`는 시각마다 저항에서 열로 나가는 전력입니다. 저항 양 끝의 전압을 제곱해 1kΩ으로 나눴습니다
- **`meas`도 명령으로 쓴다**: 점을 뗀 것 말고는 `.meas`와 같습니다. 전력을 시간으로 쌓아 에너지를 얻었습니다. 5.443µJ입니다
- **`maximum`, `mean`, `length` 같은 함수는 벡터 전체에서 값 하나를 낸다**: 커패시터에 쌓인 에너지 ½CV²를 셈하니 5.445µJ입니다. 커패시터를 채우는 동안 저항이 태운 에너지가 커패시터에 쌓인 에너지와 같다는, 손으로 셈하면 나오는 결과가 그대로 나왔습니다
- **끝에 `quit`**: 블록이 끝나면 ngspice를 닫습니다. 까닭은 아래에서 봅니다

## 되풀이하기

```spice
되풀이하며 표 만들기
V1 vcc 0 3.3
R1 vcc a 330
D1 a 0 RED
.model RED D(IS=1e-18 N=1.9 RS=5)
.control
foreach r 220 330 470 1k
  alter R1 = $r
  op
  let i_ma = -i(V1)*1000
  echo "R1 = $r  전류 = $&i_ma mA"
end
quit
.endc
.end
```

```text
$ ngspice -b table.cir
R1 = 220 전류 = 6.7071 mA
R1 = 330 전류 = 4.5614 mA
R1 = 470 전류 = 3.25198 mA
R1 = 1k 전류 = 1.57254 mA
```

- **`foreach 이름 값들 … end`**: 값마다 사이의 줄을 되풀이합니다. `$r`은 그때의 값이 글자 그대로 들어가는 자리입니다
- **`$&이름`**: 벡터의 값을 글 속에 넣습니다. `$r`은 `foreach`와 `set`이 만든 변수이고, `$&i_ma`는 `let`이 만든 벡터입니다. 둘은 다른 것입니다
- **`while`, `repeat`, `if`도 있다**: `while k <= 3 … end`, `if v(out) > 3 … else … end`처럼 씁니다
- **`.param`으로 붙인 이름을 바꿀 때**: `alterparam`을 쓰고 `reset`으로 회로를 다시 읽습니다

## 점 줄과 함께 쓸 때

```spice
점 줄과 run을 함께 적으면
V1 in 0 PULSE(0 3.3 0 1u 1u 1 2)
R1 in out 1k
C1 out 0 1u
.tran 10u 5m
.meas tran t63 WHEN v(out)=2.086
.control
run
print maximum(v(out))
.endc
.end
```

```text
$ ngspice -b twice.cir
t63             = 1.00050e-03
maximum(v(out)) = 3.277755e+00
t63             = 1.00050e-03
```

- **`run`은 점 줄의 해석을 돌린다**: `.tran`과 `.meas`를 그대로 두고 블록에서 `run`이라고 부를 수 있습니다
- **배치로 돌리면 두 번 돈다**: `-b`는 블록을 다 한 뒤에 점 줄의 해석을 한 번 더 돌립니다. `t63`이 두 번 찍혔습니다. 시간이 오래 걸리는 회로에서는 그만큼을 더 기다립니다
- **블록의 끝에 `quit`을 적는다**: 그러면 한 번만 돕니다. 대화형으로 돌렸을 때 프롬프트에 머물지 않고 빠져나오게도 합니다
- **`run`을 빼면 블록의 명령이 헛돈다**: 블록이 먼저이고 점 줄의 해석이 나중이라서, `run` 없이 `print`부터 적으면 아직 결과가 없다는 경고가 나옵니다

## 회로와 실험을 나누기

- **`.control`은 ngspice만 안다**: LTspice와 KiCad로 가져갈 넷리스트에 이 블록이 섞여 있으면 걸림돌이 됩니다
- **회로만 적은 파일을 따로 둔다**: 소자의 줄만 담은 `divider-core.cir`를 두고, 실험하는 파일에서 제목, `.include divider-core.cir`, `.control` 블록, `.end`를 적습니다. 회로는 한 곳에만 있고 실험은 여러 파일로 나눌 수 있습니다
- **가져오는 파일의 첫 줄은 제목이 아니다**: `.include`로 들어오는 파일은 첫 줄부터 회로로 읽힙니다. 첫 줄에는 `*`로 시작하는 주석을 둡니다

<Note>
넷리스트 넷은 ngspice 42로 돌린 결과이고, `while`과 `if`와 `repeat`, `run`을 뺀 경우, `quit`을 넣은 경우, 회로를 `.include`로 나눈 경우도 따로 돌려 확인했습니다. 출력에서는 `No. of Data Rows`와 처음 상태의 표 같은 줄을 뺐습니다. 배치에서 해석이 두 번 도는 것은 ngspice 42에서 본 일이고, 다른 판에서도 그런지는 확인하지 못했습니다.
</Note>

## 정리

- `.control`에서 `.endc`까지는 차례로 할 명령이다. 해석은 점을 떼고 적고, `let`으로 벡터를 만들고, `print`와 `echo`로 찍는다
- `foreach`로 되풀이하고, `$이름`은 변수, `$&이름`은 벡터의 값이다
- 점 줄의 해석과 블록을 함께 쓰면 배치에서 두 번 돈다. 블록의 끝에 `quit`을 적는다
