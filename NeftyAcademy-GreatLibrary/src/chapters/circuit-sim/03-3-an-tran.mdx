과도 해석은 시간을 잘게 나눠 한 걸음씩 풉니다. 오실로스코프의 화면과 같은 그림이 나오는 해석입니다. 줄은 짧지만, 어디에서 출발하는지와 걸음이 얼마나 큰지를 모르면 엉뚱한 그림을 믿게 됩니다.

## 출발은 동작점이다

```spice
전원을 DC로 적은 RC와 0V에서 올린 RC
V1 a 0 3.3
R1 a x 1k
C1 x 0 1u
V2 b 0 PULSE(0 3.3 0 1u 1u 1 2)
R2 b y 1k
C2 y 0 1u
.tran 10u 5m
.meas tran x_1ms FIND v(x) AT=1m
.meas tran y_1ms FIND v(y) AT=1m
.meas tran y_5ms FIND v(y) AT=5m
.end
```

```text
$ ngspice -b start.cir
Initial Transient Solution
x           3.3
y           0
x_1ms = 3.300000e+00
y_1ms = 2.085391e+00
y_5ms = 3.277755e+00
```

<Figure caption="같은 RC 회로 둘. CH1은 전원을 DC 3.3V로 적은 것, CH2는 전원을 0V에서 3.3V로 올린 것">
  <Scope tdiv={5e-4} dt={5e-6} traces={[{ name: 'CH1 마디 x', data: tranDc, vdiv: 1, pos: 0.3 }, { name: 'CH2 마디 y', data: tranPulse, vdiv: 1, pos: -3.7 }]} />
</Figure>

- **`.tran 10u 5m`**: 10µs 간격으로 5ms까지 풀라는 뜻입니다
- **먼저 동작점을 구한다**: 출력의 `Initial Transient Solution`이 그것입니다. 여기에서 시간이 흐르기 시작합니다
- **DC로 적은 전원은 이미 오래 켜져 있던 전원이다**: `x`는 처음부터 3.3V이고 끝까지 그대로입니다. 커패시터가 다 찬 상태에서 출발했으니 아무 일도 일어나지 않습니다
- **켜는 순간을 보려면 전원을 0V에서 올린다**: `y`는 0V에서 출발해, 시정수인 1ms(1kΩ × 1µF)에 2.085V까지 오르고 5ms에 3.278V가 됩니다. 오실로스코프로 본 그 곡선입니다([「RC 충전 곡선과 시정수」](#/read/scope/sh-rc))

## 처음 값을 정하는 세 가지

| 적는 법 | 하는 일 |
| --- | --- |
| 전원을 `PULSE`나 `PWL`로 0에서 올린다 | 동작점이 전원 0V에서 구해진다 |
| `.ic v(out)=0` | 동작점을 구할 때 그 마디를 그 전압에 묶어 두었다가 놓는다 |
| `C1 out 0 1u ic=0`과 `.tran … uic` | 동작점을 구하지 않고 적어 준 값에서 바로 출발한다 |

```spice
충전된 커패시터가 저항으로 비워진다
R1 out 0 1k
C1 out 0 1u ic=3.3
.tran 10u 5m uic
.meas tran v_1ms FIND v(out) AT=1m
.meas tran t37 WHEN v(out)=1.214
.end
```

```text
$ ngspice -b discharge.cir
v_1ms = 1.213995e+00
t37   = 9.99996e-04
```

- **`uic`**: 동작점을 건너뛰고 소자에 적은 `ic=`에서 출발합니다. 3.3V로 채워 둔 커패시터가 1ms 뒤에 1.214V, 곧 37%로 내려왔습니다
- **`ic=`은 `uic`가 있어야 쓰인다**: 3.3V 전원에 물린 RC에 `C1 out 0 1u ic=0`만 적고 `uic`를 빼면, 동작점이 3.3V로 구해져서 꿈쩍도 하지 않습니다. 오류도 경고도 없습니다
- **`.ic`는 `uic` 없이 쓴다**: 같은 회로에 `.ic v(out)=0`을 적으면 0V에서 충전을 시작합니다
- **`uic`에서 적지 않은 것은 0이다**: 전원이 여럿인 회로에서 `uic`를 쓰면 적어 주지 않은 마디가 모두 0V에서 출발합니다. 켜는 순간을 보는 데는 전원을 0에서 올리는 쪽이 덜 헷갈립니다

## 걸음의 크기

```spice
LC가 울리는 회로를 큰 걸음으로
V1 in 0 PULSE(0 1 0 1u 1u 1 2)
R1 in a 10
L1 a out 10m
C1 out 0 100n
.tran 50u 5m
.meas tran peak MAX v(out)
.meas tran period
+ TRIG v(out) VAL=1 RISE=2
+ TARG v(out) VAL=1 RISE=3
.end
```

```text
$ ngspice -b ring.cir
No. of Data Rows : 202
peak   = 1.955256e+00 at= 1.038691e-04
period = 2.110435e-04 targ= 4.739301e-04 trig= 2.628866e-04
```

<Figure caption="같은 회로의 같은 2ms. CH1은 가장 큰 걸음이 50µs, CH2는 1µs일 때다">
  <Scope tdiv={2e-4} dt={2e-6} traces={[{ name: 'CH1 50µs', data: lcCoarse, vdiv: 1, pos: 0.5 }, { name: 'CH2 1µs', data: lcFine, vdiv: 1, pos: -3.5 }]} />
</Figure>

| 가장 큰 걸음 | 푼 점의 수 | 울리는 주기 |
| --- | --- | --- |
| 50µs | 202 | 211.0µs |
| 10µs | 522 | 200.4µs |
| 5µs | 1021 | 199.1µs |
| 1µs | 5018 | 198.7µs |

- **`.tran`의 숫자는 넷까지 적는다**: `.tran 간격 끝 시작 가장큰걸음`입니다. 셋째는 그 시각부터의 결과만 남기라는 것이고(풀기는 0부터 풉니다), 넷째는 걸음이 그보다 커지지 않게 묶습니다
- **걸음은 시뮬레이터가 정한다**: 파형이 빨리 변하는 곳은 잘게, 느린 곳은 크게 딛습니다. `No. of Data Rows`가 실제로 푼 점의 수입니다. 넷째 숫자를 적지 않으면 가장 큰 걸음은 첫째 숫자와 (끝 − 시작) ÷ 50 가운데 작은 쪽입니다
- **이 회로의 답**: 손으로 셈하면 198.7µs마다 울립니다. 50µs 걸음으로는 한 주기에 점이 넷뿐이라 주기가 6% 길게 나왔고, 그림에서도 파형이 모가 나 있습니다
- **걸음을 줄이면 답이 한곳으로 모인다**: `.tran 50u 5m 0 1u`처럼 넷째 숫자를 줄여 가면 표와 같이 198.7µs에 다가갑니다
- **버릇**: 가장 빠른 변화의 한 주기에 수십 점이 들게 걸음을 잡고, 걸음을 반으로 줄여도 숫자가 그대로인지 한 번 확인합니다

<Note>
넷리스트 셋과 두 그림, 걸음의 표는 ngspice 42로 돌린 결과이고, `uic`를 뺀 경우와 `.ic`를 적은 경우도 따로 돌려 확인했습니다. 울리는 주기 198.7µs는 10Ω, 10mH, 100nF에서 제가 손으로 셈한 값입니다. 푼 점의 수는 판에 따라 조금 다를 수 있습니다. 소자의 값은 제가 고른 것입니다.
</Note>

## 정리

- 과도 해석은 동작점에서 출발한다. DC로 적은 전원은 이미 켜져 있던 전원이라 아무 일도 일어나지 않는다
- 처음 값은 전원을 0에서 올리거나, `.ic`로 마디를 묶거나, `ic=`과 `uic`로 정한다. `ic=`만 적으면 쓰이지 않는다
- 걸음이 크면 빠른 변화가 틀리게 나온다. 가장 큰 걸음을 줄여도 답이 그대로인지 확인한다
