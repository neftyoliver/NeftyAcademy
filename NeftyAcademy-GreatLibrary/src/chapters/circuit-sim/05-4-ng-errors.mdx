ngspice의 말은 세 가지로 나뉩니다. 넷리스트를 읽지 못해서 멈춘 것, 경고만 내고 지나간 것, 읽기는 했는데 답을 찾지 못한 것입니다. 앞 장들에서 일부러 낸 오류들을 한데 모으고, 답을 찾지 못하는 경우를 새로 봅니다.

## 넷리스트를 읽지 못했을 때

| ngspice 42의 말 | 까닭 |
| --- | --- |
| `unknown parameter (k)` | 숫자와 접미사를 띄어 썼다. 그 소자가 모르는 낱말이 줄에 있다 |
| `device already exists, bail out` | 같은 이름의 소자가 둘이다 |
| `could not find a valid modelname` | `.model`이 없다. 하위 회로를 `D`나 `Q`로 불렀다 |
| `unknown subckt: x1 …` | `.include`를 빠뜨렸거나 하위 회로의 이름이 틀렸다 |
| `Mismatch of .subckt ... .ends statements!` | `.ends`를 빠뜨렸다 |
| `Could not find include file` | 파일의 이름이나 자리가 틀렸다 |
| `Undefined parameter [이름]` | `{ }` 안에 `.param`으로 정하지 않은 이름을 썼다 |
| `no such function 'if'` | 다른 프로그램의 꼴로 적힌 식이다 |
| `unimplemented dot command '.step'` | ngspice가 모르는 점 줄이다 |
| `no simulations run` | 해석 줄이 없거나, 뽑을 것이 없거나, 앞의 오류로 멈췄다 |

```spice fails
하위 회로 안의 오류
V1 in 0 5
X1 in out DIV
.subckt DIV a b
R1 a b 10k
R2 b 0 20 k
.ends
.op
.end
```

```text
$ ngspice -b inside.cir
Error on line:
r.x1.r2 out 0 20 k
unknown parameter (k)
```

- **가장 먼저 나온 오류를 고친다**: 오류 하나가 뒤따르는 말을 여럿 낳습니다. 맨 끝의 `no simulations run`은 결과일 뿐입니다
- **오류의 줄은 ngspice가 풀어 쓴 줄이다**: 위에서 틀린 곳은 하위 회로 안의 `R2`인데, 오류에는 `r.x1.r2 out 0 20 k`로 나옵니다. `X1`을 풀어 그 안의 `R2`를 놓은 줄이라는 뜻이고, 마디도 바깥의 이름으로 바뀌어 있습니다
- **`Error on line 4 or its substitute`의 번호**: 주석과 이은 줄을 정리한 뒤의 번호라서 파일의 줄 번호와 다를 수 있습니다. 번호보다 그 아래에 찍힌 줄의 내용으로 찾습니다

## 경고만 내고 지나갈 때

- **`… is not a valid resistor instance line, ignored!`**: 그 줄을 버리고 돌렸습니다. 답은 다른 회로의 답입니다([「첫 넷리스트: 전압 분배기」](#/read/circuit-sim/nl-first))
- **`singular matrix: check node 이름`**: 그 마디의 전압을 정할 식이 없습니다. 접지가 없거나, 커패시터만 달린 마디이거나, 전압원과 인덕터만으로 닫힌 고리입니다
- **`Error: measure … out of interval`**: `.meas` 하나가 실패했고 그 결과 줄이 없습니다. 나머지는 그대로 돕니다([「.meas로 숫자 뽑기」](#/read/circuit-sim/an-meas))
- **`vector … is not available`**: `print`나 `let`에 없는 이름을 적었습니다. 마디 이름을 잘못 친 것입니다
- **끝난 값이 0이다**: 이 넷은 모두 오류로 치지 않습니다. 경고를 찾아 읽는 것은 사람의 몫입니다

## 답을 찾지 못했을 때

```spice fails
서로 맞물린 뒤집개 둘
B1 a 0 V = v(b) > 1.65 ? 0 : 3.3
B2 b 0 V = v(a) > 1.65 ? 0 : 3.3
.op
.end
```

```text
$ ngspice -b latch.cir
Note: Starting dynamic gmin stepping
Warning: Dynamic gmin stepping failed
Note: Starting true gmin stepping
Warning: True gmin stepping failed
Note: Starting source stepping
Warning: source stepping failed
Note: Transient op started
Error: Transient op failed, timestep too small
Error: The operating point could not be simulated successfully.
doAnalyses: OP:  Timestep too small; trouble with node "a"
```

- **이 회로는 답이 둘이다**: `a`가 3.3V이고 `b`가 0V이거나 그 반대입니다. 어느 쪽인지 정해 주는 것이 회로에 없어서, ngspice는 둘 사이를 오가다 포기합니다
- **ngspice는 네 가지를 차례로 해 본다**: 먼저 바로 풀어 보고, 안 되면 마디마다 작은 전도를 달았다가 줄여 가고(gmin stepping), 그다음 전원을 0에서 조금씩 올려 보고(source stepping), 마지막으로 짧은 과도 해석을 돌려 그 끝을 동작점으로 삼습니다(transient op). 위의 말들이 그 차례입니다
- **`.nodeset v(a)=3.3 v(b)=0`**: 어림의 출발점을 알려 주는 줄입니다. 이 한 줄을 더하면 경고 없이 `a`가 3.3V, `b`가 0V로 풀립니다. 답을 묶는 것이 아니라 어디서부터 찾을지를 알려 줄 뿐입니다

```spice fails
문턱에서 끝없이 뒤집히는 회로
B1 out 0 V = v(c) > 1.65 ? 0 : 3.3
R1 out c 10k
C1 c 0 100n
.tran 1u 5m uic
.meas tran vmax MAX v(out)
.end
```

```text
$ ngspice -b chatter.cir
doAnalyses: TRAN:  Timestep too small; time = 0.000693147, ...
```

```spice
문턱을 둘로 벌린 회로
V1 vcc 0 3.3
B1 out 0 V = v(p) > v(n) ? 3.3 : 0
R1 out p 10k
R2 p 0 10k
R3 vcc p 10k
R4 out n 10k
C1 n 0 100n
.tran 1u 10m uic
.meas tran period
+ TRIG v(out) VAL=1.65 RISE=2
+ TARG v(out) VAL=1.65 RISE=3
.end
```

```text
$ ngspice -b astable.cir
period = 1.386000e-03 targ= 4.563460e-03 trig= 3.177460e-03
```

- **`Timestep too small`은 걸음을 아무리 줄여도 다음 점을 찾지 못했다는 뜻이다**: 오류가 난 시각과 마디가 함께 나옵니다. 위의 줄은 화면에서 `timestep = 1.25e-18: trouble with node "out"`으로 이어집니다. 그 시각에 그 마디에서 무슨 일이 일어나는지를 봅니다
- **0.693ms에 무슨 일이 있나**: `c`가 1.65V에 닿는 순간입니다. 닿자마자 출력이 뒤집혀 `c`가 내려가고, 내려가자마자 다시 뒤집힙니다. 끝없이 빠르게 뒤집혀야 하는, 실제로는 있을 수 없는 회로를 적은 것입니다
- **회로를 현실에 맞게 고친다**: 실제 부품에는 문턱이 올라갈 때와 내려갈 때가 다른 성질(히스테리시스)이나 늦어짐이 있습니다. 둘째 넷리스트는 저항 셋으로 문턱을 1.1V와 2.2V로 벌렸습니다. 1.386ms마다 뒤집히는 회로가 되었고, 손으로 셈한 2 × 10kΩ × 100nF × ln 2와 같습니다
- **옵션은 마지막에 만진다**: `.options reltol=0.01`처럼 허용 오차를 느슨하게 하거나 `.options method=gear`로 푸는 법을 바꾸면 넘어가는 경우가 있습니다. 그러나 대개는 위처럼 회로에 빠진 것이 있습니다

## 경고 뒤에 나온 숫자

- **transient op가 낸 숫자는 동작점이 아닐 수 있다**: 접지로 가는 길이 없는 마디에 1mA를 흘려 넣는 회로는 경고 뒤에 0.01V라는 숫자를 냅니다. 1µF에 1mA를 10µs 동안 넣은 값입니다. 설명서에 적힌 transient op의 기본 길이가 10µs입니다. 더 오래 돌렸다면 다른 숫자가 나왔을 것입니다
- **`.option rshunt=1e12`**: 마디마다 접지로 1TΩ을 달아 줍니다. 커패시터만 달린 마디의 경고가 사라지고 0V로 풀립니다. 설명서가 직류 길이 없는 회로에 권하는 옵션입니다
- **`.option rseries=1e-4`**: 인덕터마다 0.1mΩ을 한 줄로 넣습니다. 전압원에 바로 물린 인덕터의 경고가 사라집니다. 답은 5V ÷ 0.1mΩ인 50kA입니다. 경고는 없어졌지만 회로가 말이 되는지는 여전히 사람이 봐야 합니다

## 고치는 차례

- **하나, 가장 먼저 나온 말을 읽는다**: 화면의 맨 끝이 아니라 맨 처음의 오류와 경고입니다
- **둘, 넷리스트가 뜻대로 읽혔는지 본다**: 제목, 마디 이름, 접지, 값과 접미사, 핀의 차례입니다. 2장의 실수들이 여기에 듭니다
- **셋, 회로가 말이 되는지 본다**: 직류가 흐를 길이 없는 마디, 저항이 0인 고리, 끝없이 빠른 변화가 없는지 봅니다. 실제 부품에 있는 작은 저항과 늦어짐을 적어 줍니다
- **넷, 출발점을 알려 준다**: 답이 여럿이면 `.nodeset`, 처음 상태를 정하려면 `.ic`나 `uic`를 씁니다([「과도 해석 (.tran)」](#/read/circuit-sim/an-tran))
- **다섯, 옵션을 만진다**: 그래도 안 될 때만 허용 오차와 푸는 법을 바꾸고, 바꾼 뒤의 답을 다른 방법으로 한 번 더 확인합니다

<Note>
넷리스트 넷과 표의 열 줄, `.nodeset`을 더한 경우, `rshunt`와 `rseries`를 준 경우는 모두 ngspice 42로 돌려 확인했습니다. 네 가지를 차례로 해 본다는 것과 transient op의 기본 길이, 옵션의 이름은 ngspice 43의 설명서에서 옮겼습니다. `reltol`과 `method=gear`는 설명서에 있는 옵션이지만, 이 쪽의 회로에서 그것으로 오류가 풀리는지는 돌려 보지 않았습니다. `timestep = 1.25e-18` 같은 숫자는 판과 컴퓨터에 따라 다를 수 있습니다.
</Note>

## 정리

- 넷리스트를 읽지 못한 오류는 맨 처음의 말과 그 아래 찍힌 줄로 찾는다. 경고는 끝난 값을 바꾸지 않으므로 직접 찾아 읽는다
- 답을 찾지 못하면 ngspice는 gmin stepping, source stepping, transient op를 차례로 해 본다. 그 뒤에 나온 숫자는 그대로 믿지 않는다
- 답이 여럿이면 `.nodeset`으로 출발점을 알려 주고, `Timestep too small`이면 그 시각과 마디에서 회로가 말이 되는지부터 본다
