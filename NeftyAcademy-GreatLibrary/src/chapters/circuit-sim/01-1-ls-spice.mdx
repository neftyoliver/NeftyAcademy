회로를 만들기 전에 컴퓨터에서 먼저 돌려 볼 수 있습니다. 이 책은 그 일을 하는 프로그램인 회로 시뮬레이터를 다룹니다. ngspice, LTspice, KiCad의 시뮬레이터는 생김새가 서로 다르지만 뿌리가 같습니다. 1973년에 나온 SPICE입니다. 뿌리를 알면 어느 프로그램을 쓰든 그 안에서 무슨 일이 벌어지는지 압니다.

## 시뮬레이터가 하는 일

회로를 글로 적은 것을 넷리스트라고 합니다. 저항 넷과 전원 하나를 적으면 아래와 같습니다. 그 밑은 ngspice가 내놓은 답입니다.

```spice
저항 넷과 전원 하나: 마디 전압 구하기
V1 in 0 9
R1 in mid 1k
R2 mid 0 2k
R3 mid out 1k
R4 out 0 3k
.op
.end
```

```text
$ ngspice -b divider.cir
Node                                  Voltage
----                                  -------
out                              3.857143e+00
mid                              5.142857e+00
in                               9.000000e+00
v1#branch                        -3.85714e-03
```

- **첫 줄은 제목이다**: 무엇을 적든 회로로 읽지 않습니다
- **한 줄이 부품 하나다**: `R1 in mid 1k`는 마디 `in`과 마디 `mid` 사이에 1kΩ이 있다는 뜻입니다. 마디는 선으로 이어진 한 덩어리에 붙인 이름이고, `0`은 접지입니다
- **`.op`는 시킬 일이다**: 전원을 켜고 모든 것이 자리 잡았을 때의 전압과 전류를 구하라는 뜻입니다
- **답은 마디마다의 전압이다**: `mid`가 5.14V, `out`이 3.86V입니다. 마지막 줄은 전원에 흐르는 전류 3.86mA입니다. 음수인 것은 SPICE가 전압원의 + 단자로 들어가는 방향을 양으로 세기 때문입니다

## 같은 회로를 손으로 풀면

```python
from fractions import Fraction as F

# 모르는 것은 mid와 out의 전압 둘이다. 마디마다 "나가는 전류의 합은 0"을 적는다
#   mid: (mid - 9)/1k + mid/2k + (mid - out)/1k = 0
#   out: (out - mid)/1k + out/3k = 0
g = [[F(1, 1000) + F(1, 2000) + F(1, 1000), -F(1, 1000)],
     [-F(1, 1000), F(1, 1000) + F(1, 3000)]]
i = [F(9, 1000), F(0)]

det = g[0][0] * g[1][1] - g[0][1] * g[1][0]
mid = (i[0] * g[1][1] - g[0][1] * i[1]) / det
out = (g[0][0] * i[1] - g[1][0] * i[0]) / det
print(f"mid = {mid} = {float(mid):.6f}V")
print(f"out = {out} = {float(out):.6f}V")
print(f"전원이 내는 전류 = {float((9 - mid) / 1000) * 1e3:.6f}mA")
```

```text
mid = 36/7 = 5.142857V
out = 27/7 = 3.857143V
전원이 내는 전류 = 3.857143mA
```

- **마디마다 식이 하나다**: 마디에서 나가는 전류를 모두 더하면 0이라는 식을, 전압을 모르는 마디마다 하나씩 적습니다. 모르는 전압이 둘이니 식도 둘입니다
- **시뮬레이터는 이 식을 세우고 푼다**: 넷리스트의 줄 하나가 식에 항을 더합니다. 마디가 천 개여도 하는 일은 같습니다
- **답이 같다**: 손으로 푼 36/7V와 27/7V가 ngspice의 답과 마지막 자리까지 같습니다
- **비례하지 않는 부품은 되풀이해서 푼다**: 다이오드와 트랜지스터는 전압과 전류가 비례하지 않아서 한 번에 풀리지 않습니다. 답을 어림하고 고치기를 되풀이합니다. 그 되풀이가 끝나지 않는 것이 수렴 실패입니다([「수렴 실패와 흔한 오류」](#/read/circuit-sim/ng-errors))
- **시간이 흐르는 회로는 잘게 나눠 푼다**: 커패시터와 인덕터가 있으면 시간을 잘게 나눠 한 걸음씩 풉니다([「과도 해석 (.tran)」](#/read/circuit-sim/an-tran))

## 1973년에서 지금까지

| 때 | 일 |
| --- | --- |
| 1973년 | 버클리의 Laurence Nagel과 Donald Pederson이 SPICE를 발표했다 |
| 1975년 | SPICE2가 나왔다. 포트란으로 쓴 마지막 판은 1983년의 2G.6이다 |
| 1989년 | C로 다시 쓴 SPICE3이 나왔다. 버클리의 마지막 판은 1993년의 3f.5다 |
| 그 뒤 | 3f.5를 이어받은 ngspice와, 회사들이 고쳐 만든 여러 프로그램이 쓰인다 |

- **이름의 뜻**: Simulation Program with Integrated Circuit Emphasis의 머리글자입니다. 집적 회로를 만들기 전에 셈으로 확인하려고 만든 프로그램입니다
- **널리 풀렸다**: 버클리는 이 프로그램을 테이프 값만 받고 나눠 주었습니다. 학교와 회사가 모두 이것으로 배우고 고쳐 썼고, 지금의 회로 시뮬레이터 대부분이 그 후손입니다
- **ngspice**: Spice3f5에 Xspice와 Cider라는 두 프로그램을 합친 공개 소프트웨어입니다. KiCad의 시뮬레이터 안에서 도는 것도 ngspice입니다
- **LTspice**: 1999년에 Linear Technology가 내놓았고 지금은 Analog Devices가 나눠 줍니다. 소스가 공개되어 있지는 않지만 값을 받지 않습니다

## 세 가지 해석

| 해석 | 묻는 것 | 넷리스트의 줄 |
| --- | --- | --- |
| 동작점 | 다 자리 잡았을 때의 전압과 전류는 얼마인가 | `.op` |
| 과도 해석 | 시간에 따라 어떻게 변하는가 | `.tran` |
| 주파수 훑기 | 주파수마다 얼마나 크게 지나가는가 | `.ac` |

- **처음부터 이 셋이었다**: 1973년의 첫 보고서가 든 해석이 직류 해석, 작은 신호 해석, 과도 해석입니다. 50년이 넘은 지금도 같은 셋을 씁니다
- **나머지는 이 셋을 되풀이한다**: `.dc`는 전원을 바꿔 가며 동작점을 여러 번 구합니다. 부품의 값을 바꿔 가며 돌리는 것도 같은 해석을 되풀이하는 것입니다([「DC 훑기 (.dc)」](#/read/circuit-sim/an-dc))
- **오실로스코프의 화면과 짝이 되는 것은 과도 해석이다**: 가로가 시간이고 세로가 전압인 그림이 나옵니다([「시뮬레이터의 파형을 오실로스코프처럼 읽기」](#/read/scope/pr-sim))

## 넷리스트가 공통어다

- **회로도를 그리는 프로그램도 넷리스트를 만든다**: LTspice와 KiCad에서 회로도를 그려 돌리면, 프로그램이 회로도를 넷리스트로 바꿔 시뮬레이터에 넘깁니다
- **글이라서 옮기고, 견주고, 물을 수 있다**: 넷리스트는 몇 줄의 글입니다. 다른 프로그램으로 옮기기 쉽고, 어제의 것과 무엇이 달라졌는지 견줄 수 있고, 남에게 통째로 보여 주며 물을 수 있습니다
- **이 책의 차례**: 2장에서 4장까지는 넷리스트, 해석, 부품의 모델을 ngspice로 돌려 가며 배웁니다. 5장은 ngspice, 6장은 LTspice, 7장은 KiCad의 쓰임이고, 8장은 결과를 얼마나 믿을지를 다룹니다. 넷리스트의 첫걸음은 [「회로 시뮬레이션 프로그램」](#/read/ee-intro/simulation)에서 한 번 디뎠습니다

## 정리

- 회로 시뮬레이터는 넷리스트에서 마디 전압의 방정식을 세워 푼다. 손으로 푼 답과 같은 답이 나온다
- SPICE는 1973년 버클리에서 나왔고, ngspice와 LTspice와 KiCad의 시뮬레이터가 모두 그 후손이다
- 해석은 동작점, 과도 해석, 주파수 훑기의 셋이 바탕이고, 넷리스트는 어느 프로그램에서나 통하는 글이다
