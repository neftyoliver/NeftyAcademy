그림으로 그린 회로도 결국은 넷리스트입니다. 그 넷리스트를 꺼내면 다른 프로그램에서 돌릴 수 있고, 남에게 글로 건넬 수 있습니다. 거꾸로 이 책의 넷리스트를 LTspice에 넣어 돌릴 수도 있습니다. 이 쪽은 두 방향으로 옮길 때 고칠 곳과, 파형을 숫자로 꺼내는 길을 봅니다.

## LTspice가 만든 넷리스트

- **화면에서 본다**: 회로도 창을 누른 다음 View 메뉴의 SPICE Netlist를 고릅니다
- **파일로 남는다**: 회로도를 돌리면 같은 폴더에 이름이 같고 확장자가 `.net`인 파일이 생깁니다
- **돌리지 않고 바꾸기만 한다**: 명령줄의 `-netlist`가 회로도를 넷리스트로 바꾸는 스위치라고 단축키 표에 적혀 있습니다

앞 쪽의 RC 회로를 그려서 꺼낸 넷리스트는 아래와 같은 꼴입니다. 이것을 그대로 ngspice에 넣어 봤습니다.

```spice fails
* C:\sim\rc.asc
* Generated by LTspice 26.0.2 for Windows.
V1 in 0 PULSE(0 3.3 0 1u 1u 499u 1m)
R1 in out 1k
C1 out 0 100n
.tran 5m
.meas tran vmax MAX v(out)
.backanno
.end
```

```text
$ ngspice -b rc.net
Error on line 6 or its substitute:
  .tran 5m
TSTOP is invalid, must be greater than zero.
```

- **첫 줄은 회로도의 경로다**: `*`로 시작하지만 첫 줄이므로 제목 노릇을 합니다. 둘째 줄에는 만든 프로그램과 판이 적힙니다
- **소자 줄은 그린 그대로다**: 부품의 이름, 이름표로 붙인 마디, 값이 2장에서 손으로 적던 꼴로 들어 있습니다. 이름표를 붙이지 않은 마디는 `N001` 같은 번호로 나옵니다
- **`.backanno`와 `.end`는 LTspice가 붙인다**: 단축키 표는 `.backanno`를 넷리스트를 만들 때 저절로 붙는 줄이라고 적어 두었습니다. 그린 사람이 놓은 지시문이 아닙니다
- **ngspice는 첫 오류에서 멈췄다**: `.tran 5m`을 걸음 5ms에 끝나는 시간이 없는 줄로 읽었습니다. 이 줄을 고치면 그다음 오류가 나옵니다

## ngspice로 가져갈 때 고칠 곳

| LTspice의 줄 | ngspice 42가 한 말과 고치는 법 |
| --- | --- |
| `.tran 5m` | `TSTOP is invalid`. `.tran 1u 5m`처럼 걸음을 적는다 |
| `.tran 0 5m` | `TSTEP is invalid`. 걸음을 0이 아닌 값으로 적는다 |
| `.backanno` | `unimplemented dot command`. 지운다 |
| `C1 out 0 1u Rser=0.1` | `unknown parameter (rser)`. 저항을 따로 그린다 |
| `.lib 파일이름` | `unimplemented dot command`. `.include 파일이름`으로 적는다 |
| `.step param …` | `unimplemented dot command`. `.control` 블록으로 옮긴다 |

- **위의 넷리스트는 두 줄을 고치면 돈다**: `.tran 5m`을 `.tran 1u 5m`으로 바꾸고 `.backanno`를 지우면 앞 쪽의 넷리스트와 같아지고, `vmax`가 3.277805V로 나옵니다
- **`Rser=`는 LTspice만 안다**: 커패시터, 인덕터, 전압원의 줄 끝에 직렬 저항을 붙여 적는 꼴입니다. ngspice에서는 그 저항을 소자 줄 하나로 따로 적습니다
- **딸려 오는 모델을 쓴 회로**: LTspice의 목록에서 모델을 고르면, 넷리스트에 그 컴퓨터에 깔린 LTspice 폴더의 모델 파일을 가리키는 `.lib` 줄이 들어갑니다. 다른 컴퓨터와 다른 프로그램에는 그 파일이 없습니다. 밖으로 가져갈 회로라면 `.model` 줄을 지시문으로 회로도에 적어 둡니다
- **호환 방식은 일부만 넘겨준다**: `set ngbehavior=ltpsa`를 켜면 ngspice 42가 `.backanno`를 지나쳤고, `.lib 파일이름`을 `.include`로 읽었습니다. `.tran 5m`과 `Rser=`는 그대로 오류였습니다([「.subckt와 제조사 모델 가져오기」](#/read/circuit-sim/dv-subckt))
- **LTspice의 모델에는 정격이 함께 적혀 있기도 하다**: LTspice의 다이오드 모델에는 `Vpk`, `Iave` 같은 정격을 적을 수 있습니다. 셈에는 쓰이지 않고, 한계를 넘겨 쓰는지 살피는 데에 쓰는 숫자입니다. 이런 모델 줄을 넣으면 ngspice 42는 `unrecognized parameter (iave) - ignored`라고 경고하고 나머지 숫자로 셈했습니다
- **`µ`는 그대로 둬도 된다**: LTspice가 만든 파일에는 마이크로가 `µ`로 적혀 있는 일이 많습니다. ngspice 42는 이 글자를 마이크로로 읽었습니다([「접미사와 단위의 함정」](#/read/circuit-sim/nl-units))

## 책의 넷리스트를 LTspice에서 돌리기

- **넷리스트 파일을 그대로 연다**: LTspice는 확장자가 `.cir`, `.net`, `.sp`인 파일을 넷리스트로 알아봅니다. 열면 글을 고치는 창이 뜨고, 회로도 없이 그 파일을 돌립니다
- **파형은 목록에서 고른다**: 누를 선이 없으므로, 처음 그릴 때 뜨는 창에서 `V(out)` 같은 이름을 고릅니다
- **그림은 생기지 않는다**: 넷리스트를 열어도 LTspice가 회로도를 그려 주지는 않습니다
- **그대로 통하는 줄**: 소자 줄, `.model`, `.subckt`, `.param`과 중괄호, `.include`, 걸음을 적은 `.tran`, `.ac`, `.dc`, `.op`입니다
- **빼고 가져갈 줄**: `.control`에서 `.endc`까지는 ngspice만의 것입니다. `.print`도 LTspice의 지시문 목록에 없습니다. 숫자는 `.meas`로 로그에 남기고, 파형은 창에서 봅니다
- **`.meas`는 로그를 확인한다**: 뼈대는 같지만 식과 구간을 적는 법이 조금 다릅니다. 옮긴 뒤 로그에 값이 나왔는지 봅니다([「.meas로 숫자 뽑기」](#/read/circuit-sim/an-meas))

## 파형을 숫자로 내보내기

- **글로 내보낸다**: 파형 창을 누른 다음 File 메뉴에서 내보내기를 고르고 파형을 고릅니다
- **파일의 꼴**: 첫 줄은 열의 이름이고, 그 아래는 줄마다 시간과 값입니다. `.ac`의 값은 `(크기dB,위상°)`처럼 괄호에 묶여 나옵니다
- **`.step`을 쓴 결과**: 단계마다 `Step Information:`으로 시작하는 줄이 사이에 끼어듭니다

괄호와 단위가 붙어 있어서 표 계산 프로그램에 바로 붙이기는 어렵습니다. 숫자만 골라내면 두 꼴을 한 함수로 읽을 수 있습니다.

```python
import re

NUM = re.compile(
    r'[-+]?\d+\.?\d*(?:e[-+]?\d+)?',
    re.I)

def read_export(text):
    rows = []
    # 첫 줄은 이름이라 건너뛴다
    for line in text.splitlines()[1:]:
        # .step의 단계를 알리는 줄
        if line.startswith('Step'):
            continue
        nums = [float(n) for n
                in NUM.findall(line)]
        if nums:
            rows.append(nums)
    return rows

tran = '\n'.join([
    'time\tV(out)',
    '0.000000e+000\t0.000000e+000',
    '1.000000e-004\t2.079904e+000',
])
ac = '\n'.join([
    'Freq.\tV(out)',
    '1.0e+002\t(-1.4451e+000dB,'
    + '-3.2142e+001°)',
    '1.0e+003\t(-1.6072e+001dB,'
    + '-8.0957e+001°)',
])

for t, v in read_export(tran):
    print(f'{t * 1e3:.1f}ms  {v:.3f}V')
for f, db, deg in read_export(ac):
    s = f'{f:.0f}Hz  {db:.2f}dB'
    print(f'{s}  {deg:.1f}°')
```

```text
0.0ms  0.000V
0.1ms  2.080V
100Hz  -1.45dB  -32.1°
1000Hz  -16.07dB  -81.0°
```

- **파일을 읽을 때**: `open(이름, errors='replace').read()`로 읽어 이 함수에 넘깁니다. `°` 같은 글자가 깨져도 숫자를 고르는 데에는 지장이 없습니다
- **거꾸로 넣을 수도 있다**: 줄마다 시간과 값이 적힌 글 파일을 전압원의 `PWL`에 파일로 물릴 수 있습니다. 머리줄은 없어야 합니다. 오실로스코프로 잰 파형을 회로에 넣어 돌릴 때 씁니다([「측정과 견주기」](#/read/circuit-sim/ts-compare))

## 남는 파일과 화면 없이 돌리기

| 파일 | 담긴 것 |
| --- | --- |
| `rc.asc` | 회로도 |
| `rc.net` | 회로도에서 만든 넷리스트 |
| `rc.raw` | 파형 |
| `rc.log` | 로그. `.meas`의 결과가 여기에 적힌다 |

- **`-b`**: 창을 띄우지 않고 돌리는 배치 방식입니다. 넷리스트를 주면 결과가 이름이 같은 `.raw`와 `.log`에 남습니다
- **`-run`**: 명령줄에 준 회로도를 Run을 누르지 않아도 바로 돌립니다
- **`-ascii`**: `.raw`를 글로 씁니다. 느려진다고 적혀 있습니다
- **이 스위치들은 윈도우의 `LTspice.exe`를 두고 적힌 것이다**: macOS의 26판에서도 같은지는 확인하지 못했습니다
- **파이썬으로 읽는다**: `.raw`와 `.log`를 읽는 spicelib 같은 라이브러리가 있습니다. ngspice에서는 같은 일을 `wrdata`로 했습니다([「파형을 파일로 내고 그리기」](#/read/circuit-sim/ng-plot))
- **남에게 줄 때**: LTspice를 쓰는 사람에게는 회로도, `.lib`로 가져온 모델 파일, 새로 만든 기호 파일을 한 폴더에 담아 줍니다. 그렇지 않은 사람에게는 넷리스트를 글로 줍니다
- **AI 도구와 잇는 길**: 26.1.0판의 고친 점 목록에는 다른 회사의 AI 도구가 쓰는 MCP 서버를 더했다는 줄이 있습니다

<Note>
이 쪽에서 제가 돌린 것은 ngspice 42와 파이썬뿐입니다. LTspice가 만든 넷리스트의 보기는 LTspice에서 꺼낸 것이 아니라, Analog Devices의 게시판에 올라온 넷리스트들의 꼴(경로를 적은 첫 줄, 판을 적은 둘째 줄, `.backanno`, `.end`)을 따라 제가 적은 것입니다. 표의 오류와 호환 방식의 결과는 그런 줄을 넣은 넷리스트를 ngspice 42에 하나씩 넣어 얻었습니다. 내보낸 글 파일의 보기도 다른 사람들이 적어 둔 꼴을 따라 만든 것이고, 숫자는 ngspice로 구했습니다. 실제 파일은 자릿수와 빈칸이 다를 수 있습니다. spicelib과 MCP 서버는 써 보지 못했습니다.
</Note>

## 정리

- LTspice가 만든 넷리스트는 소자 줄이 그대로이고, `.tran`의 짧은 꼴, `.backanno`, `Rser=`, `.lib`, `.step`을 고쳐야 ngspice에서 돈다
- 책의 넷리스트는 `.control` 블록과 `.print`를 빼면 `.cir` 파일로 LTspice에서 열어 돌릴 수 있다
- 파형은 글로 내보내 숫자만 골라 읽는다. 돌린 자리에는 `.net`, `.raw`, `.log`가 남는다
