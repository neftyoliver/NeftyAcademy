여섯 가운데 무엇으로 시작할지는 하려는 일이 정합니다. 하나만 골라야 하는 것도 아닙니다. 넷리스트를 익혀 두면 프로그램을 옮겨 다니기가 쉽기 때문입니다.

## 하려는 일로 고른다

| 하려는 일 | 맞는 프로그램 | 까닭 |
| --- | --- | --- |
| 넷리스트를 익히고, 되풀이해 돌리고, 글로 주고받는다 | ngspice | 넣는 것도 나오는 것도 글이다 |
| 회로도를 그려 곧바로 파형을 본다 | LTspice | 그리기, 돌리기, 보기가 한 창에 있다 |
| 기판까지 만들 회로를 확인한다 | KiCad | 기판으로 갈 회로도를 그대로 돌린다 |
| 회로가 도는 모습을 눈으로 익힌다 | Falstad의 시뮬레이터 | 전압과 전류가 색과 점으로 보인다 |
| 아두이노의 배선과 코드를 미리 맞춰 본다 | Tinkercad Circuits | 브레드보드 그림과 코드가 함께 돈다 |

- **값을 정하는 일에는 넷리스트를 받는 것을 쓴다**: 분배기의 저항, 필터의 커패시터, 트랜지스터를 켜는 저항을 정하려면 숫자를 믿을 수 있어야 합니다
- **둘을 함께 써도 된다**: Falstad의 시뮬레이터에서 회로의 움직임을 익히고, ngspice에서 값을 정하는 식입니다
- **남에게 물을 때에는 넷리스트로**: 회로도의 그림은 읽는 쪽이 선 하나를 잘못 볼 수 있습니다. 넷리스트는 한 글자도 다르지 않게 전해집니다. LTspice와 KiCad도 넷리스트를 내보냅니다([「넷리스트와 파형 내보내기」](#/read/circuit-sim/lt-export))

## 이 책이 ngspice로 시작하는 까닭

- **보이는 것이 전부다**: 넷리스트와 출력이 모두 글입니다. 책에 그대로 실을 수 있고, 책의 것을 그대로 쳐 넣어 같은 답이 나오는지 확인할 수 있습니다
- **KiCad의 엔진이다**: ngspice에서 통한 넷리스트는 KiCad의 시뮬레이터에서도 통합니다
- **어디서나 돈다**: 윈도우, macOS, 리눅스에서 돌고 라즈베리파이에도 깔립니다
- **화면은 그다음에 배운다**: 6장과 7장에서 같은 회로를 LTspice와 KiCad의 화면에 그려 봅니다. 그때에는 화면 뒤에서 어떤 넷리스트가 만들어지는지 이미 압니다

## 깔고 확인하기

```sh
# macOS에서 Homebrew로
brew install ngspice
# 라즈베리파이 OS, 데비안, 우분투
sudo apt install ngspice
# 깔린 판 확인
ngspice --version
```

```text
******
** ngspice-42 : Circuit level simulation program
** Compiled with KLU Direct Linear Solver
** The U. C. Berkeley CAD Group
** Copyright 1985-1994, Regents of the University of California.
** Copyright 2001-2023, The ngspice team.
```

- **윈도우**: ngspice의 누리집에서 실행 파일이 든 압축 파일을 받아 풉니다
- **LTspice**: Analog Devices의 누리집에서 설치 파일을 받습니다. macOS에서는 `brew install --cask ltspice`로도 깔립니다
- **KiCad**: KiCad의 누리집에서 받습니다. 시뮬레이터는 따로 깔 것 없이 함께 들어 있습니다
- **판이 달라도 따라 할 수 있다**: 이 책의 넷리스트는 42로 확인했습니다. 부품 줄과 해석의 줄은 오래된 문법이라 다른 판에서도 같고, 출력의 생김새는 판에 따라 조금 다를 수 있습니다

## 프로그램마다 다른 방언

| | 보기 |
| --- | --- |
| 어디서나 통한다 | 부품 줄, `.model`, `.subckt`, `.op`, `.tran`, `.ac`, `.dc`, `.param`, `.include` |
| ngspice에만 있다 | `.control`에서 `.endc`까지의 블록과 그 안의 명령 |
| LTspice에만 있다 | `.step`, 부품 줄 끝에 붙이는 `Rser=` 같은 값 |

```spice fails
LTspice의 방언을 ngspice에 넣으면
V1 in 0 5
R1 in out {R}
C1 out 0 1u
.param R=1k
.step param R list 1k 2k
.tran 0.1m 5m
.end
```

```text
$ ngspice -b step.cir
Error on line 6 or its substitute:
  .step param r list 1k 2k
 unimplemented dot command '.step'
```

- **`.step`은 LTspice의 명령이다**: 값을 바꿔 가며 되풀이하는 일을 ngspice에서는 `.control` 블록 안에서 합니다([「값 바꿔 가며 돌리기」](#/read/circuit-sim/an-param))
- **오류는 알아듣지 못한 줄을 그대로 보여 준다**: 줄 번호와 함께 그 줄이 소문자로 바뀌어 나옵니다. 방언 때문에 생긴 오류는 대개 이렇게 한눈에 드러납니다
- **`.meas`는 두 쪽에 다 있다**: 시간과 값을 뽑는 `.meas`는 ngspice와 LTspice가 모두 받습니다. 세세한 문법은 조금 다릅니다([「.meas로 숫자 뽑기」](#/read/circuit-sim/an-meas))
- **맞춰 주는 설정이 있다**: ngspice에는 LTspice나 PSpice에 맞춰 쓴 모델 파일을 읽을 때 켜는 호환 모드가 있습니다. 제조사의 모델을 가져올 때 다시 나옵니다([「.subckt와 제조사 모델 가져오기」](#/read/circuit-sim/dv-subckt))
- **KiCad도 방언을 옮겨 준다**: KiCad는 LTspice의 회로도를 읽어 들일 때 `.tran` 줄을 ngspice가 받는 꼴로 바꿉니다

<Note>
`ngspice --version`의 출력은 이 책을 쓴 환경의 것이고, 깔린 판에 따라 달라집니다. 까는 명령 가운데 제가 직접 돌려 본 것은 없고, Homebrew와 데비안의 꾸러미 이름은 참고 문서에서 확인했습니다. 방언의 표는 자주 부딪히는 것만 추린 것입니다. `.step` 말고도 LTspice에만 있는 줄을 ngspice에 넣으면 위와 같은 꼴의 오류가 납니다.
</Note>

## 정리

- 값을 정하는 일에는 넷리스트를 받는 프로그램을, 개념과 배선을 익히는 일에는 화면에서 꽂는 프로그램을 쓴다
- 이 책은 ngspice로 넷리스트와 해석을 배우고, 그다음에 LTspice와 KiCad의 화면으로 간다
- 부품 줄과 해석의 줄은 어디서나 통한다. `.control` 블록은 ngspice의, `.step`은 LTspice의 방언이다
