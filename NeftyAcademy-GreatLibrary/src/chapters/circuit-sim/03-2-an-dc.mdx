`.op`는 한 점의 답입니다. `.dc`는 전원 하나의 값을 처음부터 끝까지 조금씩 바꿔 가며 동작점을 되풀이해 구합니다. 입력을 바꿀 때 출력이 어떻게 따라오는지를 한 번에 봅니다.

## 분배기의 입력을 훑기

```spice
분배기의 입력 전압을 훑기
V1 in 0 5
R1 in out 10k
R2 out 0 20k
.dc V1 0 5 0.5
.print dc v(out)
.meas dc vin_high WHEN v(out)=2.0
.end
```

```text
$ ngspice -b sweep.cir
vin_high = 3.00000e+00
Index  v-sweep       v(out)
0      0.000000e+00  0.000000e+00
1      5.000000e-01  3.333333e-01
2      1.000000e+00  6.666667e-01
3      1.500000e+00  1.000000e+00
4      2.000000e+00  1.333333e+00
5      2.500000e+00  1.666667e+00
6      3.000000e+00  2.000000e+00
7      3.500000e+00  2.333333e+00
8      4.000000e+00  2.666667e+00
9      4.500000e+00  3.000000e+00
10     5.000000e+00  3.333333e+00
```

- **`.dc V1 0 5 0.5`**: 전원 `V1`을 0V에서 5V까지 0.5V씩 올립니다. 넷리스트에 적은 `V1`의 값 5는 이 해석 동안 쓰이지 않습니다
- **`.print dc v(out)`**: 표로 찍을 것을 고릅니다. `v(out)`은 마디의 전압이고, 전압원의 전류는 `i(V1)`처럼 적습니다. 표는 배치 실행에서 나옵니다
- **곧은 선이다**: 입력이 0.5V 늘 때마다 출력이 0.333V씩 늡니다. 저항만 있는 회로라서 기울기가 어디서나 2/3입니다
- **`.meas dc … WHEN v(out)=2.0`**: 출력이 2.0V가 되는 입력을 찾습니다. 3.0V입니다. 라즈베리파이의 핀이 HIGH로 읽는 문턱이 2.0V이므로([「논리 레벨과 문턱」](#/read/scope/bs-levels)), 5V 신호가 3.0V까지 내려가도 HIGH로 읽힌다는 뜻입니다

  <Plot x={dcVcc} xUnit="V" xName="전원 전압" yUnit="A" yName="LED의 전류" series={[{ name: '330Ω', data: dcI330 }, { name: '1kΩ', data: dcI1k }]} vmarks={[{ at: 3.3, label: '3.3V' }]} />
</Figure>

```spice
전원 전압에 따른 LED의 전류
V1 vcc 0 3.3
R1 vcc a 330
Vs a k 0
D1 k 0 RED
.model RED D(IS=1e-18 N=1.9 RS=5)
.dc V1 0 5 0.01
.meas dc i_at_33 FIND i(Vs) AT=3.3
.meas dc v_1ma WHEN i(Vs)=1m
.end
```

```text
$ ngspice -b led-curve.cir
i_at_33 = 4.561396e-03
v_1ma   = 2.03235e+00
```

- **`Vs`는 전류계다**: LED의 전류를 양수로 읽으려고 0V 전압원을 한 줄로 끼웠습니다([「소자 줄: R, C, L, V, I」](#/read/circuit-sim/nl-elements))
- **무릎이 있다**: 1.6V 아래에서는 전류가 거의 없다가 그 위에서 곧게 오릅니다. 오르는 기울기는 저항이 정합니다. 330Ω이면 1V에 3mA쯤, 1kΩ이면 1mA쯤입니다
- **`FIND … AT=3.3`**: 가로 값이 3.3일 때의 전류입니다. 4.561mA로, 앞 쪽에서 구한 동작점과 같습니다
- **`WHEN i(Vs)=1m`**: 전류가 1mA가 되는 전원 전압입니다. 2.03V입니다
- **끝 값은 `AT=`으로 못 잡을 수 있다**: 이 넷리스트에 `AT=5`를 적으면 `out of interval`이라는 오류가 납니다. 0.01을 거듭 더해 간 마지막 값이 5에 꼭 맞지 않기 때문으로 보입니다. `AT=4.99`처럼 안쪽 값을 적습니다

## 훑을 수 있는 것

- **전압원과 전류원**: `.dc I1 0 5m 1m`처럼 전류원도 같은 꼴로 훑습니다
- **저항과 온도**: `.dc R1 100 1k 100`은 저항값을, `.dc temp -20 80 20`은 회로의 온도를 훑습니다([「값 바꿔 가며 돌리기」](#/read/circuit-sim/an-param))
- **둘을 겹쳐서**: `.dc V1 0 5 0.05 R1 330 1000 670`처럼 뒤에 하나를 더 적으면, 둘째 것의 값마다 첫째 것을 처음부터 끝까지 훑습니다. 위 그림의 두 곡선을 이렇게 얻었습니다
- **시간은 없다**: 값마다 동작점을 구하는 것이므로 커패시터는 끊긴 곳이고 인덕터는 이어진 선입니다. 전원을 아주 천천히 올리는 것과 같습니다
- **걸음이 크면 굽은 곳을 놓친다**: 곧은 선은 몇 점이면 되지만, 무릎처럼 굽는 곳이 있으면 그 둘레에 점이 여럿 들도록 걸음을 줄입니다

<Note>
넷리스트 둘과 그림은 ngspice 42로 돌린 결과이고, 전류원·저항·온도·겹친 훑기와 `AT=5`의 오류도 따로 돌려 확인했습니다. 출력에서 표의 빈칸은 화면에 맞게 줄였고, 표 위아래의 긴 줄은 뺐습니다. LED의 모델 값은 앞 쪽과 같이 제가 맞춘 값입니다. 문턱 2.0V는 「오실로스코프 읽기」에서 본 값입니다.
</Note>

## 정리

- `.dc 전원 처음 끝 걸음`은 전원의 값을 바꿔 가며 동작점을 되풀이해 구한다. 저항과 온도도 훑을 수 있다
- `.print dc`는 표를 찍고, `.meas dc`의 `WHEN`과 `FIND … AT=`은 표에서 필요한 한 점을 뽑는다
- 저항만 있는 회로는 곧은 선이 나오고, 다이오드가 있으면 무릎이 있는 곡선이 나온다
