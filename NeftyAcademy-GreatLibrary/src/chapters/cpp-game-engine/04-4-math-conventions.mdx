[「벡터와 행렬」](#/read/cpp-game-engine/math-vectors)의 수식은 어떤 좌표계에서도 같지만, "어느 쪽이 위이고, 어느 쪽이 앞이며, 1이 몇 미터인가"는 수학이 정해 주지 않습니다. 이것은 **약속**이고, 도구와 라이브러리마다 약속이 다릅니다. 엔진은 자기 약속을 하나 정해 문서로 적고, 다른 약속과 만나는 경계에서 바꿉니다.

## 손잡이와 위쪽

- **오른손 / 왼손**: x를 오른쪽, y를 위로 두었을 때 z가 화면 밖(나를 향해)이면 오른손, 화면 안쪽이면 왼손 좌표계입니다. 외적 x × y의 방향과 회전의 양의 방향이 이것에 따라 바뀝니다
- **위쪽 축**: y가 위인 도구와 z가 위인 도구가 섞여 있습니다

| 도구·형식 | 손잡이 | 위쪽 | 길이 단위 |
| --- | --- | --- | --- |
| glTF 2.0 | 오른손 | +Y | 미터 |
| Blender | 오른손 | +Z | 미터(기본) |
| Unity | 왼손 | +Y | 미터 |
| Unreal Engine | 왼손 | +Z | 센티미터 |

Blender에서 만든 모델을 glTF로 내보내면 내보내기 도구가 Z-위를 Y-위로 돌려 줍니다. 그런데 두 형식을 직접 읽는 엔진이 이 차이를 잊으면 모델이 바닥에 누워 있거나, 좌우가 거울처럼 뒤집혀 나옵니다(손잡이가 바뀌면 삼각형의 감기 방향도 뒤집혀 앞뒷면이 바뀝니다). 에셋을 [「가져오기와 굽기」](#/read/cpp-game-engine/res-import)에서 엔진의 약속으로 한 번에 바꿔 두는 것이 정석입니다.

## 그래픽 API마다 다른 화면 좌표

카메라가 본 것을 화면으로 옮기는 투영 행렬도 API마다 약속이 다릅니다.

```cpp
#include <cmath>
#include <array>
#include <numbers>
#include <print>

struct V4 { float x, y, z, w; };

// 오른손 좌표계의 카메라 공간(카메라는 -z를 본다)에서 클립 공간으로
// gl: 깊이 -1..1, y 위로 / vk: 깊이 0..1, y 아래로
V4 project(float x, float y, float z, bool vulkan)
{
    const float fovy = std::numbers::pi_v<float> / 2, aspect = 1;
    const float n = 0.1f, f = 100;                    // 가까운 면, 먼 면
    float t = 1 / std::tan(fovy / 2);
    V4 c{};
    c.x = t / aspect * x;
    c.y = (vulkan ? -t : t) * y;
    if (vulkan) {
        c.z = f / (n - f) * z + n * f / (n - f);
    } else {
        c.z = (f + n) / (n - f) * z + 2 * f * n / (n - f);
    }
    c.w = -z;
    return c;
}

int main()
{
    auto clean = [](float f) { return std::fabs(f) < 1e-6f ? 0.f : f; };
    const std::array<std::array<float, 2>, 3> pts = {{{1, -1}, {0, -0.1f},
                                                      {0, -100}}};
    std::println("카메라 공간의 점 (0, y, z) -> 정규화 장치 좌표(NDC)");
    for (bool vk : {false, true})
        for (auto [y, z] : pts) {
            V4 c = project(0, y, z, vk);
            std::println("  {:<6} y {:4.1f}, z {:6.1f} -> y {:5.2f}, 깊이 {:5.2f}",
                         vk ? "Vulkan" : "OpenGL", y, z, clean(c.y / c.w),
                         clean(c.z / c.w));
        }

    std::println("float로 담은 위치의 눈금(바로 옆 float와의 차이)");
    for (float m : {1.f, 1000.f, 10000.f, 100000.f, 1000000.f}) {
        float gap = std::nextafter(m, 2 * m) - m;
        std::println("  {:>9.0f}m 지점: {:.7f}m", m, gap);
    }
}
```

```text
카메라 공간의 점 (0, y, z) -> 정규화 장치 좌표(NDC)
  OpenGL y  1.0, z   -1.0 -> y  1.00, 깊이  0.80
  OpenGL y  0.0, z   -0.1 -> y  0.00, 깊이 -1.00
  OpenGL y  0.0, z -100.0 -> y  0.00, 깊이  1.00
  Vulkan y  1.0, z   -1.0 -> y -1.00, 깊이  0.90
  Vulkan y  0.0, z   -0.1 -> y  0.00, 깊이  0.00
  Vulkan y  0.0, z -100.0 -> y  0.00, 깊이  1.00
float로 담은 위치의 눈금(바로 옆 float와의 차이)
          1m 지점: 0.0000001m
       1000m 지점: 0.0000610m
      10000m 지점: 0.0009766m
     100000m 지점: 0.0078125m
    1000000m 지점: 0.0625000m
```

- **y의 방향**: OpenGL의 NDC는 y가 위(+1이 화면 위)이고, Vulkan은 y가 아래입니다. 같은 행렬을 쓰면 Vulkan에서 그림이 위아래로 뒤집혀서, 위 예제처럼 투영 행렬의 y에 −를 붙이거나 뷰포트 높이를 음수로 줍니다
- **깊이 범위**: OpenGL은 가까운 면이 −1, 먼 면이 +1이고, Vulkan과 Direct3D는 0에서 1입니다. 범위가 다른 행렬을 쓰면 가까운 물체가 잘려 나갑니다
- **깊이는 고르지 않다**: 0.1m에서 100m까지 보는 카메라에서, 겨우 1m 앞의 점이 이미 깊이 0.9(Vulkan)입니다. 남은 99m를 0.9~1.0에 몰아 담는 셈이라 먼 곳의 깊이 정밀도가 모자라 면이 깜빡이는(z-fighting) 일이 생깁니다. 그래서 요즘 엔진은 가까운 면을 1, 먼 면을 0으로 뒤집는 **반전 깊이**(reversed-Z)를 float 깊이 버퍼와 함께 씁니다. 이것은 [「그래픽 API 감싸기」](#/read/cpp-game-engine/rend-abstraction)와 벌칸 책에서 이어집니다

## float는 멀어질수록 성기다

결과의 아래쪽은 float가 담을 수 있는 가장 작은 차이가 위치에 따라 어떻게 커지는지 보여 줍니다. 원점 근처에서는 0.1µm까지 담지만, 10km 떨어지면 약 1mm, 100km에서는 약 8mm, 1000km에서는 6cm 단위로밖에 움직일 수 없습니다. 넓은 세계에서 캐릭터가 떨리거나 물리가 이상해지는 까닭입니다. 대처는 셋입니다.

- 세계 위치를 **double**로 담고, 그릴 때 카메라 기준의 float로 바꾼다
- 플레이어가 멀리 가면 세상 전체를 옮겨 **원점을 다시 잡는다**
- 세계를 칸(셀)으로 나누고, 위치를 "칸 번호 + 칸 안의 float"로 담는다

## 엔진이 적어 둘 약속

| 정할 것 | 예 |
| --- | --- |
| 손잡이와 위·앞 축 | 오른손, +Y 위, −Z 앞 |
| 길이와 각도 단위 | 미터, 라디안(에디터 표시는 도) |
| 행렬의 곱 순서와 저장 순서 | 열 벡터, 열 우선 |
| 삼각형의 앞면 | 반시계 방향으로 감긴 면 |
| 오일러 각의 축 순서 | Y(yaw) → X(pitch) → Z(roll) |

이 표를 엔진의 첫 문서로 만들어 두고, 수학 라이브러리의 시험(`static_assert`)과 에셋 가져오기 코드가 모두 이 표를 따르게 합니다.

<Note>
"−Z가 앞"은 오른손 좌표계에서 OpenGL 관습을 따른 흔한 선택이지만, glTF는 모델의 앞쪽을 +Z로 둡니다. 어느 쪽이든 정하기 나름이고, 중요한 것은 **한 번 정하면 엔진 전체가 같은 것을 쓰는 것**입니다. 약속이 둘 섞이면 "이 모델만 거꾸로 서 있다" 같은 버그가 끝없이 나옵니다.
</Note>

## 정리

- 손잡이, 위쪽 축, 단위는 도구마다 다른 약속이므로, 엔진은 하나를 정해 적고 에셋을 가져올 때 한 번에 바꾼다
- 그래픽 API마다 화면 좌표의 y 방향과 깊이 범위가 달라 투영 행렬을 맞춰야 하며, 깊이는 고르지 않아 반전 깊이를 쓴다
- float는 원점에서 멀수록 성기므로 넓은 세계에서는 double, 원점 다시 잡기, 칸 나누기로 정밀도를 지킨다
