[「가져오기와 굽기」](#/read/cpp-game-engine/res-import)로 실행용 에셋을 만들었으니, 이제 게임이 그것을 읽어 들일 차례입니다. 열린 세계 게임은 플레이어가 걸어가는 동안 앞쪽의 지형과 건물을 계속 읽어 들여야 하고, 그동안 화면이 멈추면 안 됩니다. 그래서 로딩은 **그리기와 다른 스레드에서**, 여러 단계로 나눠 합니다.

## 세 단계

| 단계 | 하는 곳 | 하는 일 |
| --- | --- | --- |
| 읽기 | 입출력 스레드 | 디스크에서 바이트를 읽는다. 기다리는 시간이 대부분 |
| 풀기 | 작업 스레드 | 압축 풀기, 포인터 고치기, 데이터 다듬기 |
| 올리기 | 그리기 스레드(또는 GPU 전송 큐) | GPU 메모리로 복사하고 그래픽 객체를 만든다 |

게임 코드는 `load("hero.tex")`를 부르면 곧바로 [「핸들과 세대 인덱스」](#/read/cpp-game-engine/mem-handles)의 핸들을 받고, 매 프레임 "준비됐나"를 물어봅니다. 기다리느라 멈추지 않습니다.

## 순서와 예산 흉내 내기

스레드의 타이밍은 실행할 때마다 달라서, 먼저 단계와 순서 규칙만 프레임 단위로 흉내 내 봅니다.

```cpp
#include <deque>
#include <print>
#include <string>
#include <vector>

// 한 에셋이 거치는 단계. 읽기·풀기는 다른 스레드, 올리기는 그리기 스레드
enum class State { Queued, Reading, Decoding, WaitUpload, Ready };

struct Request {
    std::string name;
    int priority;          // 클수록 먼저
    int read_frames;       // 디스크에서 읽는 데 걸리는 프레임 수(흉내)
    int decode_frames;     // 압축을 푸는 데 걸리는 프레임 수
    State state = State::Queued;
    int left = 0;
};

int main()
{
    std::vector<Request> reqs = {
        {"tree.tex", 1, 2, 1},
        {"hero.mesh", 9, 1, 1},
        {"hero.tex", 9, 2, 3},
        {"bgm.ogg", 5, 2, 1},
    };
    // 한 프레임에 GPU로 올릴 수 있는 수
    constexpr int kUploadsPerFrame = 1;

    for (int frame = 1; frame <= 9; ++frame) {
        // 1) 읽는 스레드: 한 번에 하나씩, 우선순위가 높은 것부터
        Request* reading = nullptr;
        for (auto& r : reqs) if (r.state == State::Reading) reading = &r;
        if (!reading) {
            for (auto& r : reqs)
                if (r.state == State::Queued &&
                    (!reading || r.priority > reading->priority))
                    reading = &r;
            if (reading) {
                reading->state = State::Reading;
                reading->left = reading->read_frames;
            }
        }
        // 2) 진행: 읽기·풀기는 프레임마다 하나씩 줄어든다
        for (auto& r : reqs) {
            if (r.state != State::Reading && r.state != State::Decoding) continue;
            if (--r.left > 0) continue;
            if (r.state == State::Reading && r.decode_frames > 0) {
                r.state = State::Decoding;
                r.left = r.decode_frames;
            } else {
                r.state = State::WaitUpload;
            }
        }
        // 3) 그리기 스레드: 올릴 차례인 것을 프레임당 정해진 수만큼
        int uploads = 0;
        for (auto& r : reqs)
            if (r.state == State::WaitUpload && uploads < kUploadsPerFrame) {
                r.state = State::Ready;
                ++uploads;
            }
        // 4) 화면에는 준비된 것은 진짜를, 아닌 것은 대신할 것을
        std::print("프레임 {}:", frame);
        for (auto& r : reqs) {
            const char* mark = r.state == State::Ready      ? "진짜"
                               : r.state == State::Queued   ? "대기"
                               : r.state == State::Reading  ? "읽는 중"
                               : r.state == State::Decoding ? "푸는 중"
                                                            : "올릴 차례";
            std::print(" {}[{}]", r.name, mark);
        }
        std::println();
    }
}
```

```text
프레임 1: tree.tex[대기] hero.mesh[푸는 중] hero.tex[대기] bgm.ogg[대기]
프레임 2: tree.tex[대기] hero.mesh[진짜] hero.tex[읽는 중] bgm.ogg[대기]
프레임 3: tree.tex[대기] hero.mesh[진짜] hero.tex[푸는 중] bgm.ogg[대기]
프레임 4: tree.tex[대기] hero.mesh[진짜] hero.tex[푸는 중] bgm.ogg[읽는 중]
프레임 5: tree.tex[대기] hero.mesh[진짜] hero.tex[푸는 중] bgm.ogg[푸는 중]
프레임 6: tree.tex[읽는 중] hero.mesh[진짜] hero.tex[진짜] bgm.ogg[올릴 차례]
프레임 7: tree.tex[푸는 중] hero.mesh[진짜] hero.tex[진짜] bgm.ogg[진짜]
프레임 8: tree.tex[진짜] hero.mesh[진짜] hero.tex[진짜] bgm.ogg[진짜]
프레임 9: tree.tex[진짜] hero.mesh[진짜] hero.tex[진짜] bgm.ogg[진짜]
```

- **우선순위**: 요청은 먼 나무가 먼저 들어왔지만, 우선순위가 높은 주인공 메시와 텍스처를 먼저 읽고, 먼 나무는 맨 나중에 읽었습니다. 실제로는 카메라와의 거리, 화면에 보이는지로 우선순위를 매 프레임 다시 매깁니다
- **겹쳐 돌기**: 읽기와 풀기가 다른 스레드라, 4프레임에 텍스처를 푸는 동안 음악을 읽기 시작했습니다. 디스크가 노는 시간이 줄어듭니다
- **올리기 예산**: 6프레임에 텍스처와 음악이 함께 끝났지만, 한 프레임에 하나만 올리기로 정해 두어서 음악은 한 프레임 기다렸습니다. 큰 텍스처를 한 프레임에 여러 장 GPU로 보내면 그 프레임이 길어져 화면이 끊기므로, 개수나 바이트, 시간으로 예산을 둡니다
- **대신 보여 주기**: 준비되지 않은 동안 화면에는 회색 텍스처, 낮은 해상도 밉맵, 단순한 모양 같은 **대신할 것**을 그립니다. 텍스처는 작은 밉맵부터 먼저 올리고 큰 것을 나중에 올려 점점 선명해지게 하는 방법(스트리밍)도 많이 씁니다

## 진짜 스레드로

입출력·풀기 스레드 하나와, 끝난 것을 받아 가는 그리기 스레드의 뼈대입니다(「C++ 고급」의 [「조건 변수」](#/read/cpp-advanced/sync-condvar)).

```cpp flags=-pthread
#include <chrono>
#include <condition_variable>
#include <deque>
#include <mutex>
#include <print>
#include <stop_token>
#include <string>
#include <thread>
#include <utility>
#include <vector>

struct Loaded { std::string name; std::vector<unsigned char> bytes; };

// 읽기·풀기를 맡는 스레드 하나와, 끝난 것을 받아 가는 그리기 스레드
class Loader {
public:
    Loader() : worker_([this](std::stop_token st) { run(st); }) {}

    void request(std::string name)
    {
        {
            std::lock_guard lk(m_);
            todo_.push_back(std::move(name));
        }
        cv_.notify_one();
    }
    // 그리기 스레드가 프레임마다 부른다: 잠깐만 잠그고 끝난 것을 가져간다
    std::vector<Loaded> take_finished()
    {
        std::lock_guard lk(m_);
        return std::exchange(done_, {});
    }

private:
    void run(std::stop_token st)
    {
        while (true) {
            std::string name;
            {
                std::unique_lock lk(m_);
                if (!cv_.wait(lk, st, [&] { return !todo_.empty(); }))
                    return;                       // 멈추라는 요청
                name = std::move(todo_.front());
                todo_.pop_front();
            }
            Loaded l{name, read_and_decode(name)};   // 잠그지 않은 채 오래 일한다
            std::lock_guard lk(m_);
            done_.push_back(std::move(l));
        }
    }
    static std::vector<unsigned char> read_and_decode(const std::string& n)
    {
        return std::vector<unsigned char>(n.size() * 1000, 0xAB);   // 흉내
    }

    std::mutex m_;
    std::condition_variable_any cv_;
    std::deque<std::string> todo_;
    std::vector<Loaded> done_;
    std::jthread worker_;                         // 마지막 멤버: 먼저 멈추고 합류
};

int main()
{
    Loader loader;
    for (auto n : {"hero.mesh", "hero.tex", "bgm.ogg"}) loader.request(n);
    std::size_t got = 0;
    for (int frame = 0; got < 3; ++frame) {
        for (auto& l : loader.take_finished()) {
            ++got;                                // 여기서 GPU에 올린다
            std::println("{} 받음 ({}바이트)", l.name, l.bytes.size());
        }
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
}
```

```text
hero.mesh 받음 (9000바이트)
hero.tex 받음 (8000바이트)
bgm.ogg 받음 (7000바이트)
```

- 일하는 스레드는 잠금을 잡고 할 일을 하나 꺼낸 뒤 **잠금을 풀고** 오래 걸리는 일을 합니다. 잠금을 쥔 채 디스크를 읽으면 그리기 스레드가 `take_finished`에서 멈춥니다
- 그리기 스레드는 프레임마다 `take_finished`로 끝난 것을 **한꺼번에 가져갑니다**. 잠금을 아주 짧게만 잡습니다
- `std::jthread`와 `stop_token`을 받는 `wait` 덕분에, `Loader`가 부서질 때 일하는 스레드가 기다리던 중이어도 깨어나 끝나고 합류합니다. `jthread`를 **마지막 멤버**로 둔 것은, 멤버가 거꾸로 부서지므로 스레드가 큐와 뮤텍스보다 먼저 멈추게 하려는 것입니다([「서브시스템의 시작과 종료 순서」](#/read/cpp-game-engine/arch-subsystems)의 RAII 순서)
- 일하는 스레드가 하나라 받은 순서가 요청 순서와 같습니다. 이 프로그램은 ThreadSanitizer로도 돌려 경고가 없는 것을 확인했습니다

<Note>
요즘 PC와 콘솔은 매우 빠른 NVMe SSD와, 디스크에서 GPU로 바로 보내는 경로(DirectStorage 같은 API, 콘솔의 전용 압축 해제 하드웨어)를 가지고 있습니다. 그러면 병목이 디스크 읽기에서 CPU의 압축 풀기와 GPU 올리기로 옮겨 갑니다. 어느 단계가 막히는지는 기기마다 다르므로, 단계마다 걸린 시간을 기록해 두는 것이 중요합니다([「엔진 안의 프로파일러」](#/read/cpp-game-engine/ed-profiler)).
</Note>

## 정리

- 로딩은 읽기·풀기·올리기로 나눠 그리기 스레드 밖에서 하고, 게임 코드는 핸들을 곧바로 받아 준비됐는지 묻는다
- 우선순위로 중요한 것부터 읽고, 단계를 겹쳐 돌리며, GPU 올리기에는 프레임당 예산을 두고 그동안 대신할 것을 그린다
- 일하는 스레드는 잠금을 짧게만 쥐고 무거운 일은 잠금 밖에서 하며, 끝난 것은 그리기 스레드가 프레임마다 한꺼번에 가져간다
