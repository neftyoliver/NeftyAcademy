60fps 게임은 한 프레임에 16.67ms, 120fps는 8.33ms를 씁니다. 이 시간은 팀 전체가 나눠 쓰는 하나의 통장입니다. 누구도 자기 몫을 정해 두지 않으면, 모두가 "조금만 더" 쓰다가 출시 직전에 프레임이 무너지고, 누가 얼마나 넘었는지 아무도 모릅니다. **성능 예산**은 그 통장을 계통별로 미리 나눠 두고, 측정으로 계속 지키는 일입니다. 메모리, 로딩 시간, 다운로드 용량도 같은 방식으로 예산을 둡니다.

## 1분 동안의 프레임

계통 다섯에 예산을 나눠 주고(여유 1.67ms를 남김), 3600프레임을 측정했다고 칩니다. 물리는 10초마다 한 번 크게 튑니다.

```cpp
#include <algorithm>
#include <cstdint>
#include <print>
#include <string>
#include <vector>

std::uint32_t rng = 2026;
double rnd() { rng = rng * 1664525u + 1013904223u; return (rng >> 8) / 16777216.0; }

int main() {
    // 계통별 예산(60fps = 16.67ms 중 여유 1.67ms를 남긴다)
    struct Sys { std::string name; double budget_ms, base_ms, jitter_ms; };
    std::vector<Sys> systems = {
        // 이름 뒤 공백은 화면 폭 12칸에 맞춘 것
        {"게임 논리   ", 3.0, 2.2, 0.6}, {"물리        ", 3.0, 2.6, 0.8},
        {"애니메이션  ", 2.0, 1.4, 0.4}, {"그리기 준비 ", 5.0, 4.1, 1.0},
        {"소리·기타   ", 2.0, 1.0, 0.3},
    };
    const double frame_budget = 1000.0 / 60;

    std::vector<double> frames;
    std::vector<double> sys_worst(systems.size(), 0), sys_sum(systems.size(), 0);
    for (int f = 0; f < 3600; ++f) {                  // 1분
        double total = 0;
        for (std::size_t s = 0; s < systems.size(); ++s) {
            double t = systems[s].base_ms + rnd() * systems[s].jitter_ms;
            if (s == 1 && f % 600 == 599) t += 9;     // 10초마다 물리가 튄다
            total += t;
            sys_sum[s] += t;
            sys_worst[s] = std::max(sys_worst[s], t);
        }
        frames.push_back(total);
    }

    std::println("계통         예산   평균   최악");
    for (std::size_t s = 0; s < systems.size(); ++s)
        std::println("{} {:5.1f}  {:5.2f}  {:5.2f}{}", systems[s].name,
                     systems[s].budget_ms, sys_sum[s] / frames.size(), sys_worst[s],
                     sys_worst[s] > systems[s].budget_ms ? "  <- 넘음" : "");

    auto sorted = frames;
    std::ranges::sort(sorted);
    auto pct = [&](double p) {
        return sorted[std::size_t(p * (sorted.size() - 1))];
    };
    double avg = 0;
    for (double t : frames) avg += t;
    avg /= frames.size();
    long over = std::ranges::count_if(
        frames, [&](double t) { return t > frame_budget; });
    std::println("프레임 {}개, 예산 {:.2f}ms", frames.size(), frame_budget);
    std::println("  평균 {:.2f}  중앙 {:.2f}  95% {:.2f}  "
                 "99.9% {:.2f}  최악 {:.2f}",
                 avg, pct(0.5), pct(0.95), pct(0.999), sorted.back());
    std::println("  예산을 넘은 프레임 {}개", over);
}
```


## 평균은 거짓말을 한다

프레임 평균은 12.87ms로 예산보다 4ms 가까이 여유가 있어 보입니다. 95%의 프레임도 13.60ms 안이었습니다. 하지만 99.9% 지점은 21.77ms, 최악은 22.51ms였고, 1분에 6번 예산을 넘었습니다. 바로 10초마다 튀는 물리 프레임입니다. 플레이어가 느끼는 것은 평균이 아니라 이 **튀는 프레임**(히치)입니다. 매끄럽게 돌다가 가끔 한 번씩 멈칫하는 게임은 평균이 조금 낮더라도 늘 고른 게임보다 나쁘게 느껴집니다.

그래서 성능 보고서는 평균보다 **백분위**(95%, 99%, 99.9%)와 최악, 예산을 넘은 프레임 수를 앞에 둡니다. [「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)에서 프레임 시간의 흔들림이 물리 결과까지 흔든다는 것도 봤습니다.

## 계통별로 나누면 보이는 것

- **물리**는 평균 3.01ms로 예산 3.0ms를 겨우 넘었을 뿐이지만, 최악이 12.37ms였습니다. 평균만 보면 "조금 넘는다"인데, 실제로는 가끔 9ms가 튀는 문제입니다. [「엔진 안의 프로파일러」](#/read/cpp-game-engine/ed-profiler)로 그 프레임을 열어 보는 것이 다음 할 일입니다
- **그리기 준비**는 최악 5.10ms로 예산을 살짝 넘었지만 프레임 전체는 멀쩡했습니다. 전체 프레임만 봤다면 아무도 몰랐을 것입니다. 계통별 예산은 이렇게 **조금씩 새어 나가는** 것을 문제가 커지기 전에 잡아 줍니다

예산은 처음에 대충 정하고, 측정하면서 계통끼리 주고받으며 조정합니다. 중요한 것은 숫자가 정확한 것보다 **누구의 몫인지 정해져 있는 것**입니다. 넘으면 그 계통의 담당자가 줄이거나, 다른 계통과 협상해 예산을 옮겨 옵니다.

<Note>
예산은 사람이 가끔 확인해서는 지켜지지 않습니다. 매일 밤 정해진 장면(가장 무거운 전투, 가장 넓은 풍경)을 정해진 카메라 경로로 돌리는 자동 성능 테스트를 두고, 결과를 날짜별로 그래프에 쌓아 백분위가 예산을 넘거나 어제보다 크게 나빠지면 알림을 보냅니다. 어느 커밋에서 나빠졌는지 바로 알 수 있으면 고치는 비용이 훨씬 작습니다. 가장 낮은 사양의 대상 기기에서 재는 것도 잊지 않습니다.
</Note>

## 정리

- 프레임 시간, 메모리, 로딩 시간을 계통별 예산으로 나눠 누구의 몫인지 정해 둔다
- 플레이어는 평균이 아니라 튀는 프레임을 느끼므로, 백분위와 최악, 예산을 넘은 프레임 수로 판단한다
- 계통별 측정은 새어 나가는 비용을 일찍 잡아 주며, 자동 성능 테스트로 매일 예산을 지킨다
