[「변환과 계층」](#/read/cpp-game-engine/math-transform)에서 부모를 따라 움직이는 변환의 계층을 배열로 만들었습니다. 그 계층이 장면 전체로 커진 것이 **장면 그래프**입니다. 이 쪽은 장면 그래프를 엔진에서 실제로 쓸 때 부딪히는 일, 특히 **부모를 바꾸는 일**을 봅니다.

## 무엇을 계층으로 두나

옛 엔진들은 장면의 모든 것(물체, 조명, 카메라, 소리, 심지어 렌더 상태)을 하나의 커다란 나무로 두고, 나무를 훑으며 모든 일을 했습니다. 그런데 일마다 원하는 구조가 다릅니다.

| 일 | 원하는 구조 |
| --- | --- |
| 변환 | 부모-자식 계층(손에 든 칼은 손을 따라간다) |
| 컬링 | 공간에 따른 나눔([「공간 분할」](#/read/cpp-game-engine/scene-spatial)) |
| 그리기 | 머티리얼과 깊이로 정렬한 목록([「컬링과 정렬」](#/read/cpp-game-engine/rend-culling)) |
| 게임 규칙 | 컴포넌트로 고른 집합([「아키타입과 희소 집합」](#/read/cpp-game-engine/ecs-storage)) |

그래서 지금 엔진들은 장면 그래프를 **변환의 계층**으로만 쓰고, 다른 일은 각자 알맞은 구조를 따로 둡니다. 계층이 정말 필요한 것(붙어 다니는 물체)만 부모를 갖고, 대부분의 물체는 부모가 없는 뿌리로 둡니다. 계층이 깊고 넓을수록 갱신이 비싸지기 때문입니다.

## 부모 바꾸기: 세계 위치를 지키며

캐릭터가 상자를 집거나, 짐을 수레에 싣거나, 에디터에서 물체를 다른 폴더로 끌어 놓을 때 부모가 바뀝니다. 이때 지역 변환을 그대로 두면, 새 부모 기준으로 해석되어 물체가 엉뚱한 곳으로 튀어 갑니다. 화면에서 그 자리에 그대로 있게 하려면 **새 지역 = (새 부모의 세계)⁻¹ · 지금 세계**로 다시 계산합니다.

```cpp
#include <cmath>
#include <numbers>
#include <print>
#include <string>
#include <vector>

struct Xf { float x = 0, y = 0, a = 0, s = 1; };   // 평면 TRS(크기는 균등)

Xf mul(const Xf& p, const Xf& l)                  // world = p · l
{
    float c = std::cos(p.a), sn = std::sin(p.a);
    return {p.x + p.s * (c * l.x - sn * l.y), p.y + p.s * (sn * l.x + c * l.y),
            p.a + l.a, p.s * l.s};
}
Xf inv(const Xf& t)                               // t의 역변환
{
    float c = std::cos(-t.a), sn = std::sin(-t.a), is = 1 / t.s;
    return {is * (c * -t.x - sn * -t.y), is * (sn * -t.x + c * -t.y), -t.a, is};
}

struct Node { std::string name; int parent; Xf local; };

// 부모가 언제나 앞에 오도록 깊이 우선으로 다시 줄 세운다
std::vector<int> order(const std::vector<Node>& ns)
{
    std::vector<int> out;
    auto visit = [&](auto& self, int p) -> void {
        for (int i = 0; i < int(ns.size()); ++i)
            if (ns[i].parent == p) { out.push_back(i); self(self, i); }
    };
    visit(visit, -1);
    return out;
}

Xf world_of(const std::vector<Node>& ns, int i)
{
    if (ns[i].parent < 0) return ns[i].local;
    return mul(world_of(ns, ns[i].parent), ns[i].local);
}

void show(const std::vector<Node>& ns)
{
    for (int i : order(ns)) {
        Xf w = world_of(ns, i);
        int depth = 0;
        for (int p = ns[i].parent; p >= 0; p = ns[p].parent) ++depth;
        auto z = [](float f) { return std::abs(f) < 1e-4f ? 0.f : f; };
        std::println("  {:{}}{:<6} 세계 ({:6.2f}, {:6.2f})", "", depth * 2,
                     ns[i].name, z(w.x), z(w.y));
    }
}

int main()
{
    const float PI = std::numbers::pi_v<float>;
    std::vector<Node> ns = {
        {"땅", -1, {}},
        {"수레", 0, {5, 0, PI / 2, 1}},           // 90도 돌아 서 있다
        {"상자", 0, {8, 3, 0, 1}},
        {"사과", 2, {0, 1, 0, 1}},                // 상자 위
    };
    std::println("처음:");
    show(ns);

    // 상자를 수레에 싣는다: 세계 위치는 그대로, 부모만 바꾼다
    int box = 2, cart = 1;
    Xf w = world_of(ns, box);
    ns[box].local = mul(inv(world_of(ns, cart)), w);  // 새 부모 세계의 역 · 세계
    ns[box].parent = cart;
    std::println("상자를 수레의 자식으로 (지역 ({:.2f}, {:.2f})):",
                 ns[box].local.x, ns[box].local.y);
    show(ns);

    ns[cart].local.x += 10;                           // 수레가 굴러간다
    std::println("수레를 10 옮긴 뒤:");
    show(ns);
}
```

```text
처음:
  땅     세계 (  0.00,   0.00)
    수레   세계 (  5.00,   0.00)
    상자   세계 (  8.00,   3.00)
      사과   세계 (  8.00,   4.00)
상자를 수레의 자식으로 (지역 (3.00, -3.00)):
  땅     세계 (  0.00,   0.00)
    수레   세계 (  5.00,   0.00)
      상자   세계 (  8.00,   3.00)
        사과   세계 (  8.00,   4.00)
수레를 10 옮긴 뒤:
  땅     세계 (  0.00,   0.00)
    수레   세계 ( 15.00,   0.00)
      상자   세계 ( 18.00,   3.00)
        사과   세계 ( 18.00,   4.00)
```

- 수레는 90도 돌아 서 있어서, 상자의 새 지역 위치는 (3, −3)이라는 처음 보면 이상한 값이 됩니다. 수레의 x축이 세계의 위쪽을 보고 있기 때문입니다. 그래도 세계 위치 (8, 3)은 그대로입니다
- 상자의 자식인 사과는 아무것도 바꾸지 않았는데 함께 따라왔습니다. 사과의 지역 변환은 여전히 "상자 위 1"이기 때문입니다
- 그 뒤 수레를 옮기자 상자와 사과가 함께 움직였습니다

## 순서 다시 맞추기

[「변환과 계층」](#/read/cpp-game-engine/math-transform)의 빠른 갱신은 "부모가 언제나 자식보다 앞에" 있는 배열에 기대고 있었습니다. 위 예제에서 상자(2번)는 새 부모 수레(1번)보다 뒤에 있어서 우연히 괜찮았지만, 만약 새 부모가 배열에서 더 뒤에 있다면 순서가 깨집니다. 그래서 부모를 바꾸면 그 물체와 그 **자식 전체**(부분 나무)를 새 부모 뒤로 옮겨 순서를 다시 맞춥니다. 예제의 `order()`는 이것을 가장 단순하게, 뿌리부터 깊이 우선으로 줄을 다시 세웠습니다. 실제 엔진은 바뀐 부분 나무만 옮기고, 한 프레임에 부모 바꾸기가 많으면 프레임 끝에 한 번에 다시 정렬합니다.

<Note>
부모를 바꿀 때 지켜야 할 것을 정하는 것도 설계입니다. 위처럼 세계 변환을 지키는 경우가 보통이지만, 손에 칼을 쥐여 줄 때는 오히려 "손 기준의 정해진 자리"로 붙여야 합니다. 그래서 엔진은 대개 "세계 유지"와 "지역 유지" 두 가지 부모 바꾸기를 함께 둡니다. 또 자기 자손을 부모로 삼으면 고리가 생기므로, 부모 바꾸기 전에 새 부모가 자기 부분 나무 안에 있지 않은지 확인합니다.
</Note>

## 정리

- 장면 그래프는 변환의 계층으로만 쓰고, 컬링·그리기·게임 규칙은 각자 알맞은 구조를 따로 두며, 계층은 꼭 필요한 것만 쓴다
- 세계 위치를 지키며 부모를 바꾸려면 새 지역 = (새 부모의 세계)⁻¹ · 지금 세계로 다시 계산하고, 자식들은 그대로 따라온다
- 부모를 바꾸면 부분 나무를 새 부모 뒤로 옮겨 부모가 앞에 오는 순서를 지키고, 자기 자손을 부모로 삼는 고리를 막는다
