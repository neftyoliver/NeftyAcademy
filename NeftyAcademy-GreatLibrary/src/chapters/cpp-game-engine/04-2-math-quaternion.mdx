[「벡터와 행렬」](#/read/cpp-game-engine/math-vectors)에서 회전을 행렬로 표현했습니다. 하지만 엔진 속에서 물체의 **방향을 저장하고 섞는 일**에는 대개 **쿼터니언**을 씁니다. 네 개의 수로 회전 하나를 담는 이 도구를 왜 쓰는지, 어떻게 쓰는지 봅니다.

## 오일러 각의 문제

사람에게 가장 쉬운 회전 표현은 "좌우로 몇 도(yaw), 위아래로 몇 도(pitch), 옆으로 몇 도(roll)"인 **오일러 각**입니다. 에디터의 입력 칸은 거의 이것입니다. 그런데 엔진 속 표현으로는 두 가지 문제가 있습니다.

- **짐벌 잠금**: 세 축을 차례로 돌리는 방식이라, 가운데 회전(예: pitch)이 90도가 되면 첫째와 셋째 회전축이 같은 방향을 가리키게 됩니다. 그러면 yaw를 바꾸든 roll을 바꾸든 같은 방향으로만 돌고, 자유도 하나를 잃습니다. 비행기가 수직으로 올라갈 때 카메라가 갑자기 홱 도는 버그가 이것입니다
- **섞기가 어렵다**: (0°, 0°, 0°)와 (0°, 0°, 350°) 사이를 숫자로 섞으면 10도만 돌면 될 것을 350도 빙 돌아갑니다. 같은 방향을 나타내는 각도 조합도 여러 가지입니다

## 쿼터니언 만들기와 쓰기

단위 쿼터니언 q = (cos(θ/2), sin(θ/2)·축)은 "축을 중심으로 θ만큼 돈다"는 뜻입니다. 벡터 v는 q·v·q*(켤레)로 돌립니다.

```cpp
#include <cmath>
#include <numbers>
#include <print>

struct Vec3 { float x, y, z; };
struct Quat {
    float w, x, y, z;
    static Quat axis_angle(Vec3 a, float rad)       // a는 단위 벡터
    {
        float s = std::sin(rad / 2);
        return {std::cos(rad / 2), a.x * s, a.y * s, a.z * s};
    }
    Quat operator*(Quat b) const                    // 해밀턴 곱: b 다음에 this
    {
        return {w * b.w - x * b.x - y * b.y - z * b.z,
                w * b.x + x * b.w + y * b.z - z * b.y,
                w * b.y - x * b.z + y * b.w + z * b.x,
                w * b.z + x * b.y - y * b.x + z * b.w};
    }
    Quat conj() const { return {w, -x, -y, -z}; }
    float norm() const { return std::sqrt(w * w + x * x + y * y + z * z); }
    Vec3 rotate(Vec3 v) const                       // q · v · q*
    {
        Quat r = *this * Quat{0, v.x, v.y, v.z} * conj();
        return {r.x, r.y, r.z};
    }
};

float dot(Quat a, Quat b)
{
    return a.w * b.w + a.x * b.x + a.y * b.y + a.z * b.z;
}

Quat nlerp(Quat a, Quat b, float t)                 // 곧게 섞고 길이를 1로
{
    Quat r{a.w + (b.w - a.w) * t, a.x + (b.x - a.x) * t,
           a.y + (b.y - a.y) * t, a.z + (b.z - a.z) * t};
    float n = r.norm();
    return {r.w / n, r.x / n, r.y / n, r.z / n};
}

Quat slerp(Quat a, Quat b, float t)                 // 구면 위를 같은 빠르기로
{
    float d = dot(a, b);
    if (d < 0) { b = {-b.w, -b.x, -b.y, -b.z}; d = -d; }   // 짧은 쪽으로
    if (d > 0.9995f) return nlerp(a, b, t);
    float th = std::acos(d);
    float sa = std::sin((1 - t) * th) / std::sin(th);
    float sb = std::sin(t * th) / std::sin(th);
    return {a.w * sa + b.w * sb, a.x * sa + b.x * sb, a.y * sa + b.y * sb,
            a.z * sa + b.z * sb};
}

float deg_of(Quat q)                                // 원점에서 몇 도 돌았나
{
    float c = std::fmin(1.f, std::fabs(q.w));
    return 2 * std::acos(c) * 180 / std::numbers::pi_v<float>;
}
float clean(float f) { return std::fabs(f) < 1e-6f ? 0.f : f; }

int main()
{
    const float PI = std::numbers::pi_v<float>;
    Quat qz = Quat::axis_angle({0, 0, 1}, PI / 2);   // z축 90도
    Quat qx = Quat::axis_angle({1, 0, 0}, PI / 2);   // x축 90도
    Vec3 v = qz.rotate({1, 0, 0});
    std::println("z축 90도로 (1,0,0) -> ({:.2f}, {:.2f}, {:.2f})", clean(v.x),
                 clean(v.y), clean(v.z));
    Vec3 a = (qx * qz).rotate({1, 0, 0}), b = (qz * qx).rotate({1, 0, 0});
    std::println("z 다음 x: ({:.2f}, {:.2f}, {:.2f})", clean(a.x), clean(a.y),
                 clean(a.z));
    std::println("x 다음 z: ({:.2f}, {:.2f}, {:.2f})", clean(b.x), clean(b.y),
                 clean(b.z));

    Quat id{1, 0, 0, 0};
    Quat big = Quat::axis_angle({0, 0, 1}, PI * 0.9f);   // 162도
    std::println("t     slerp 각도  nlerp 각도");
    for (float t : {0.25f, 0.5f, 0.75f})
        std::println("{:.2f}  {:8.2f}  {:9.2f}", t, deg_of(slerp(id, big, t)),
                     deg_of(nlerp(id, big, t)));

    Quat q = id;                     // 작은 회전을 백만 번 곱하면
    Quat step = Quat::axis_angle({0.6f, 0.8f, 0}, 0.001f);
    for (int i = 0; i < 1'000'000; ++i) q = step * q;
    std::println("백만 번 곱한 뒤 길이 {:.6f}", q.norm());
}
```

```text
z축 90도로 (1,0,0) -> (0.00, 1.00, 0.00)
z 다음 x: (0.00, 0.00, 1.00)
x 다음 z: (0.00, 1.00, 0.00)
t     slerp 각도  nlerp 각도
0.25     40.50      34.75
0.50     81.00      81.00
0.75    121.50     127.25
백만 번 곱한 뒤 길이 1.004858
```

- **곱하는 순서**: `qx * qz`는 "z축으로 먼저 돌리고 그다음 x축으로"입니다(오른쪽 것이 먼저). (1,0,0)이 z축 90도로 (0,1,0)이 되고, 다시 x축 90도로 (0,0,1)이 됩니다. 순서를 바꾸면 결과가 (0,1,0)으로 달라집니다. 행렬과 같은 약속입니다
- **반각**: 축과 각에서 θ가 아니라 θ/2를 쓰는 것이 처음엔 이상해 보이지만, q·v·q*에서 q가 양쪽에 한 번씩 곱해지기 때문입니다. 그래서 q와 −q는 같은 회전입니다. 섞을 때 `dot < 0`이면 한쪽을 뒤집는 것이 이 때문이고, 그래야 짧은 쪽으로 돕니다
- 저장 공간은 float 4개(16바이트)로, 3×3 회전 행렬(36바이트)보다 작고 짐벌 잠금이 없습니다

## slerp와 nlerp

0도와 162도 사이를 섞어 봤습니다.

- **slerp**(구면 선형 보간)는 t에 정확히 비례해 돕니다. t = 0.25에서 40.5도, 0.75에서 121.5도로, 162도의 1/4과 3/4입니다
- **nlerp**(곧게 섞고 길이를 1로)는 계산이 훨씬 싸지만, 각도가 크면 가운데가 빠르고 양 끝이 느립니다. t = 0.25에서 34.75도로 6도쯤 어긋났습니다. 가운데(0.5)에서는 둘이 같습니다

애니메이션 블렌딩처럼 프레임마다 아주 많이 섞고, 섞는 두 방향이 대개 가까운 곳에서는 nlerp로 충분합니다(각이 작으면 차이가 거의 없습니다). 카메라가 큰 각도를 일정한 빠르기로 돌아야 할 때는 slerp를 씁니다([「블렌딩」](#/read/cpp-game-engine/anim-blend)).

## 길이가 샌다

마지막 줄은 아주 작은 회전을 백만 번 곱한 결과입니다. 수학적으로는 길이가 언제나 1이어야 하지만, float의 반올림이 쌓여 **1.0049**가 되었습니다. 길이가 1이 아닌 쿼터니언으로 벡터를 돌리면 회전과 함께 크기도 변합니다(1.0049²배). 그래서 매 프레임 회전을 곱해 가는 값(물체의 방향, 카메라)은 가끔, 혹은 매번 **다시 정규화**합니다. 정규화는 sqrt 하나와 나눗셈 넷이라 싼 편입니다.

<Note>
쿼터니언은 사람이 읽기 어렵습니다. 그래서 엔진은 보통 **에디터에는 오일러 각**, **엔진 속에는 쿼터니언**, **셰이더에 넘길 때는 행렬**로, 쓰는 곳마다 다른 표현을 씁니다. 그 사이를 바꾸는 함수(오일러 ↔ 쿼터니언 ↔ 행렬)가 수학 라이브러리의 단골 버그 자리라서, 바꿨다 되돌리면 같은 회전이 나오는지 시험을 꼭 둡니다. 오일러 각으로 바꿀 때는 축의 순서(XYZ, ZYX…)를 [「좌표계의 약속」](#/read/cpp-game-engine/math-conventions)에 적어 두어야 합니다.
</Note>

## 정리

- 오일러 각은 짐벌 잠금이 있고 섞기 어려워서, 엔진 속 방향은 축과 반각으로 만든 단위 쿼터니언으로 담는다
- 벡터는 q·v·q*로 돌리고, 곱은 오른쪽 것이 먼저 적용되며, q와 −q는 같은 회전이라 섞을 때 짧은 쪽을 고른다
- slerp는 일정한 빠르기로, nlerp는 싸지만 큰 각에서 빠르기가 고르지 않으며, 곱해 가는 쿼터니언은 다시 정규화한다
