ECS에서 동작은 모두 **시스템**에 있습니다. 시스템이 수십 개가 되면 "어떤 순서로 돌리나"가 큰 문제가 됩니다. 이동보다 충돌 검사가 먼저 돌면 한 프레임 늦은 위치로 검사하고, 두 시스템이 같은 컴포넌트를 동시에 고치면 결과가 엉킵니다. 이 쪽은 시스템이 **무엇을 읽고 무엇을 쓰는지** 밝혀 두고, 그것으로 순서와 병렬 실행을 정하는 방법을 봅니다.

## 읽기와 쓰기를 밝힌다

시스템마다 읽는 컴포넌트와 쓰는 컴포넌트를 적어 둡니다. 두 시스템이 **부딪히는** 것은 한쪽이 쓰는 것을 다른 쪽이 읽거나 쓸 때뿐입니다. 둘 다 읽기만 하면 동시에 돌려도 안전합니다.

```cpp
#include <algorithm>
#include <cstdint>
#include <print>
#include <string>
#include <vector>

enum : std::uint32_t {
    INPUT = 1, VEL = 2, POS = 4, HEALTH = 8, AI = 16, ANIM = 32, XFORM = 64,
    SOUND = 128
};

struct System {
    std::string name;
    std::uint32_t reads, writes;
};

// 적힌 순서를 지키면서, 부딪히지 않는 시스템끼리 같은 단계에 묶는다
std::vector<std::vector<std::string>> stages(const std::vector<System>& sys)
{
    std::vector<std::vector<std::string>> out;
    std::vector<std::uint32_t> st_reads, st_writes;
    std::vector<int> stage_of(sys.size(), 0);
    for (std::size_t i = 0; i < sys.size(); ++i) {
        // 앞의 시스템과 부딪히면 그 시스템보다 뒤 단계여야 한다
        int s = 0;
        for (std::size_t j = 0; j < i; ++j) {
            bool clash = (sys[i].writes & (sys[j].reads | sys[j].writes)) ||
                         (sys[i].reads & sys[j].writes);
            if (clash) s = std::max(s, stage_of[j] + 1);
        }
        stage_of[i] = s;
        if (s >= static_cast<int>(out.size())) out.resize(s + 1);
        out[s].push_back(sys[i].name);
    }
    return out;
}

int main()
{
    const std::vector<System> sys = {
        {"입력",       0,          INPUT},
        {"AI",         POS,        AI | VEL},
        {"조종",       INPUT,      VEL},
        {"이동",       VEL,        POS},
        {"피해",       POS,        HEALTH},
        {"애니메이션", VEL,        ANIM},
        {"변환",       POS | ANIM, XFORM},
        {"발소리",     ANIM,       SOUND},
    };
    auto st = stages(sys);
    for (std::size_t i = 0; i < st.size(); ++i) {
        std::print("단계 {}:", i + 1);
        for (auto& n : st[i]) std::print(" [{}]", n);
        std::println();
    }
}
```

```text
단계 1: [입력] [AI]
단계 2: [조종]
단계 3: [이동] [애니메이션]
단계 4: [피해] [변환] [발소리]
```

- 적힌 순서를 "먼저 돌아야 하는 것"의 약속으로 삼고, 각 시스템을 자기와 부딪히는 앞 시스템보다 **한 단계 뒤**에 놓았습니다
- `AI`는 위치를 읽고 속도를 쓰고, `입력`은 입력만 쓰니 둘은 부딪히지 않아 1단계에 함께 들어갔습니다. `조종`은 `AI`와 같은 속도를 쓰니 그다음 단계입니다
- 같은 단계의 시스템들은 서로 다른 스레드에서 **동시에** 돌릴 수 있습니다. 4단계의 피해, 변환, 발소리는 셋이 각자 다른 컴포넌트를 쓰고 앞 단계의 결과만 읽습니다. 이 단계들을 [「작업 큐와 워커 스레드」](#/read/cpp-game-engine/job-queue)에 넘기는 것이 엔진 병렬화의 기본 모양이고, 더 세밀한 의존은 [「의존 그래프」](#/read/cpp-game-engine/job-graph)에서 다룹니다

## 순서의 큰 틀

단계를 자동으로 계산하더라도, 사람이 정하는 큰 틀이 먼저 있습니다.

1. **입력과 네트워크 받기**: 이번 프레임의 명령을 모은다
2. **게임 규칙**: AI, 조종, 스크립트가 의도를 정한다(속도, 행동)
3. **물리**: [「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)의 고정 걸음으로 위치를 정한다
4. **반응**: 충돌의 결과로 피해, 소리, 효과
5. **변환과 애니메이션**: 세계 변환과 뼈의 자세를 계산한다
6. **그리기 준비**: 보이는 것을 골라 렌더러에 넘긴다

이 틀 안에서 각 시스템의 자리를 정하고, 같은 틀 안의 순서는 위처럼 읽기·쓰기로 자동 계산하는 엔진이 많습니다. "A는 반드시 B 다음"처럼 데이터로 드러나지 않는 순서는 따로 적어 둡니다.

## 훑는 도중에 구조를 바꾸지 않는다

시스템이 엔티티를 훑는 도중에 엔티티를 지우거나 만들면, 그 배열의 모양이 바뀌어 버립니다.

```cpp
#include <cstdint>
#include <print>
#include <vector>

struct World {
    std::vector<std::uint32_t> alive;         // 살아 있는 엔티티(촘촘한 목록)
    std::vector<int> hp;                      // alive와 같은 순서
    std::uint32_t next = 0;
    void spawn(int h) { alive.push_back(next++); hp.push_back(h); }
    void destroy_at(std::size_t i)            // 바꿔 빼기
    {
        alive[i] = alive.back(); hp[i] = hp.back();
        alive.pop_back(); hp.pop_back();
    }
};

// 구조를 바꾸는 일은 적어 두었다가 시스템이 끝난 뒤 한꺼번에
struct Commands {
    std::vector<std::uint32_t> kill;
    int spawns = 0;
    void flush(World& w)
    {
        for (auto e : kill)
            for (std::size_t i = 0; i < w.alive.size(); ++i)
                if (w.alive[i] == e) { w.destroy_at(i); break; }
        for (int i = 0; i < spawns; ++i) w.spawn(5);
        kill.clear();
        spawns = 0;
    }
};

int main()
{
    World w;
    for (int h : {3, 0, 0, 7, 0}) w.spawn(h);   // 1, 2, 4번이 체력 0

    // 잘못된 방법: 훑는 도중에 지우면 끝에서 당겨 온 개체를 건너뛴다
    World bad = w;
    int checked = 0;
    for (std::size_t i = 0; i < bad.alive.size(); ++i) {
        ++checked;
        if (bad.hp[i] <= 0) bad.destroy_at(i);  // i 자리에 다른 개체가 들어온다
    }
    std::print("훑으며 지우기: {}개 확인, 남은 것", checked);
    for (std::size_t i = 0; i < bad.alive.size(); ++i)
        std::print(" e{}(hp {})", bad.alive[i], bad.hp[i]);
    std::println();

    // 바른 방법: 명령으로 적어 두고 나중에
    Commands cmd;
    for (std::size_t i = 0; i < w.alive.size(); ++i)
        if (w.hp[i] <= 0) {
            cmd.kill.push_back(w.alive[i]);
            ++cmd.spawns;                       // 죽으면 슬라임 하나가 나온다
        }
    std::println("명령 버퍼: 지울 것 {}개, 만들 것 {}개", cmd.kill.size(),
                 cmd.spawns);
    cmd.flush(w);
    std::print("남은 엔티티:");
    for (std::size_t i = 0; i < w.alive.size(); ++i)
        std::print(" e{}(hp {})", w.alive[i], w.hp[i]);
    std::println();
}
```

```text
훑으며 지우기: 3개 확인, 남은 것 e0(hp 3) e4(hp 0) e3(hp 7)
명령 버퍼: 지울 것 3개, 만들 것 3개
남은 엔티티: e0(hp 3) e3(hp 7) e5(hp 5) e6(hp 5) e7(hp 5)
```

- 훑으면서 바로 지우자 다섯 개 중 **세 개만** 확인했고, 체력 0인 `e4`가 살아남았습니다. 1번 자리의 `e1`을 지울 때 끝의 `e4`가 그 자리로 당겨져 왔는데, 반복문은 이미 다음 자리로 넘어가 버렸기 때문입니다. [「아키타입과 희소 집합」](#/read/cpp-game-engine/ecs-storage)의 바꿔 빼기가 이 문제를 늘 일으킵니다
- 그래서 지우기·만들기·컴포넌트 붙이기처럼 **구조를 바꾸는 일은 명령 버퍼에 적어 두고**, 시스템이 끝난 뒤(또는 단계가 끝난 뒤) 한꺼번에 처리합니다. 죽은 셋이 지워지고, 그 자리에 슬라임 셋(`e5`~`e7`)이 생겼습니다
- 명령 버퍼는 병렬 실행에서도 필요합니다. 여러 스레드가 동시에 엔티티를 만들면 배열이 엉키므로, 스레드마다 자기 버퍼에 적고 나중에 한 스레드가 합칩니다

<Note>
명령을 나중에 처리하면, 이번 단계 안에서는 "지웠다고 적은 엔티티"가 아직 살아 있습니다. 같은 프레임의 뒤 시스템이 그 엔티티를 보고 또 피해를 주는 일이 생길 수 있으니, 지울 예정인 엔티티에는 `Dead` 같은 표시 컴포넌트를 바로 붙여 두고 다른 시스템이 건너뛰게 하는 방법을 함께 씁니다.
</Note>

## 정리

- 시스템마다 읽고 쓰는 컴포넌트를 밝혀 두면, 한쪽이 쓰는 것을 다른 쪽이 읽거나 쓸 때만 부딪힌다는 규칙으로 순서를 정할 수 있다
- 적힌 순서를 지키며 부딪히지 않는 시스템을 같은 단계로 묶으면 단계 안의 시스템은 동시에 돌릴 수 있다
- 훑는 도중의 지우기·만들기는 엔티티를 건너뛰게 하므로 명령 버퍼에 적어 두었다가 시스템이 끝난 뒤 한꺼번에 처리한다
