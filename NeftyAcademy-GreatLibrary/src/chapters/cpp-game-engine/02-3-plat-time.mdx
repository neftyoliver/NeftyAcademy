[「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)의 누적기는 "지난 프레임에서 몇 초가 흘렀나"를 정확히 알아야 돌아갑니다. 이 쪽은 그 시간을 어떤 시계로 재는지, 그리고 정해진 프레임 속도에 맞추려고 기다릴 때 무엇이 어긋나는지를 직접 재 봅니다.

## 어느 시계를 쓰나

C++에는 시계가 셋 있습니다(「C++ STL」의 [「시계의 종류」](#/read/cpp-stl/chr-clocks)).

| 시계 | 성질 | 게임에서 |
| --- | --- | --- |
| `steady_clock` | 뒤로 가지 않는다(단조) | 프레임 시간, 타이머, 프로파일링 |
| `system_clock` | 달력 시각. 사용자나 NTP가 바꿀 수 있다 | 세이브 파일의 날짜, 로그의 시각 |
| `high_resolution_clock` | 구현에 따라 위 둘 중 하나의 별명 | 쓰지 않는다 |

`system_clock`으로 프레임 시간을 재면, 사용자가 시계를 맞추거나 NTP가 시각을 고치는 순간 `dt`가 음수나 몇 시간이 되어 게임이 순간이동합니다. 프레임 시간에는 **언제나** `steady_clock`을 씁니다.

## 직접 재 보기

```cpp norun
#include <algorithm>
#include <chrono>
#include <print>
#include <thread>
#include <vector>

using namespace std::chrono;
using namespace std::chrono_literals;

// 가장 작은 눈금: 값이 바뀔 때까지 되풀이해 읽는다
template <typename Clock>
nanoseconds tick()
{
    auto a = Clock::now(), b = a;
    while (b == a) b = Clock::now();
    return duration_cast<nanoseconds>(b - a);
}

double ms(nanoseconds d) { return duration<double, std::milli>(d).count(); }

int main()
{
    std::println("steady_clock: 단조 {}, 눈금 {}ns", steady_clock::is_steady,
                 tick<steady_clock>().count());
    std::println("system_clock: 단조 {}, 눈금 {}ns", system_clock::is_steady,
                 tick<system_clock>().count());

    // 1ms 자 달라고 하면 실제로 얼마나 자나
    std::vector<double> slept;
    for (int i = 0; i < 200; ++i) {
        auto t0 = steady_clock::now();
        std::this_thread::sleep_for(1ms);
        slept.push_back(ms(steady_clock::now() - t0));
    }
    std::ranges::sort(slept);
    std::println("sleep_for(1ms): 가운데 {:.3f}ms, 99% {:.3f}ms, 최대 {:.3f}ms",
                 slept[100], slept[198], slept.back());

    // 120Hz로 프레임 맞추기: 남은 시간 대부분은 자고, 끝 1ms는 돌며 기다린다
    const auto period = duration_cast<nanoseconds>(duration<double>(1.0 / 120));
    std::vector<double> frames;
    auto next = steady_clock::now() + period;
    for (int f = 0; f < 240; ++f) {
        auto start = steady_clock::now();
        // ... 게임 갱신과 그리기(여기서는 일 없음) ...
        auto left = next - steady_clock::now();
        if (left > 1ms)
            std::this_thread::sleep_for(left - 1ms);
        while (steady_clock::now() < next) {}          // 남은 조금은 돌며
        next += period;
        frames.push_back(ms(steady_clock::now() - start));
    }
    std::ranges::sort(frames);
    std::println("120Hz 목표 {:.3f}ms: 가운데 {:.3f}ms, 최소 {:.3f}, 최대 {:.3f}",
                 ms(period), frames[120], frames.front(), frames.back());
}
```

검사용 컴퓨터(x86-64 코어 2개짜리 리눅스 가상 머신)에서 세 번 돌린 결과 가운데 두 번입니다. 시간을 재는 예제라 돌릴 때마다 숫자가 조금씩 다르고, 그래서 자동 검사는 컴파일까지만 합니다.

```text nocheck
steady_clock: 단조 true, 눈금 51ns
system_clock: 단조 false, 눈금 31ns
sleep_for(1ms): 가운데 1.080ms, 99% 1.174ms, 최대 1.211ms
120Hz 목표 8.333ms: 가운데 8.333ms, 최소 8.227, 최대 8.439

steady_clock: 단조 true, 눈금 47ns
system_clock: 단조 false, 눈금 30ns
sleep_for(1ms): 가운데 1.081ms, 99% 1.172ms, 최대 1.178ms
120Hz 목표 8.333ms: 가운데 8.333ms, 최소 6.627, 최대 10.039
```

- **눈금**: 두 번 읽어 값이 바뀌는 가장 작은 차이는 수십 ns였습니다. 읽는 데 드는 시간까지 들어간 값이지만, 프레임 시간(수 ms)을 재기에는 충분히 촘촘합니다
- **잠들기는 늘 늦게 깬다**: 1ms를 자라고 했더니 가운데값이 1.08ms, 가장 늦게는 1.2ms쯤이었습니다. `sleep_for`는 "적어도 그만큼" 자는 것이고, 운영체제가 언제 다시 깨워 줄지는 그 운영체제의 스케줄러에 달려 있습니다
- **자다가 돌며 기다리기**: 그래서 프레임을 맞출 때는 남은 시간에서 1ms쯤을 뺀 만큼만 자고, 마지막 조금은 시계를 계속 읽으며 **돌면서**(busy-wait) 기다립니다. 첫 실행에서는 프레임 시간이 8.23~8.44ms 사이로 목표 8.333ms에 잘 붙었습니다

## 늦은 프레임 다음

두 번째 실행에서는 한 프레임이 10.0ms로 늦었고, 바로 다음 프레임은 6.6ms로 짧았습니다. 이 예제가 다음 마감을 "지금 + 한 주기"가 아니라 **"지난 마감 + 한 주기"**(`next += period`)로 잡기 때문입니다. 한 번 늦으면 다음에 그만큼 따라잡아 **평균**은 정확히 120Hz를 지킵니다. 대신 프레임 간격이 순간 흔들립니다. 반대로 "지금 + 한 주기"로 잡으면 간격은 고르지만 늦은 만큼 시간이 영영 밀립니다. 화면 출력과 맞춰야 하는 그림 쪽은 보통 그래픽 API의 수직 동기(vsync)에 맡기고, 서버처럼 화면이 없는 곳에서 위 방법을 씁니다.

<Note>
윈도는 예전부터 기본 타이머 간격이 약 15.6ms라서, 아무 설정 없이 1ms를 자라고 하면 15ms 넘게 자는 일이 흔했습니다. 그래서 게임은 `timeBeginPeriod(1)`로 타이머 간격을 줄이거나, 고해상도 대기 타이머(`CreateWaitableTimerEx`의 고해상도 깃발)를 씁니다. 이 설정의 효과는 윈도 판마다 조금씩 달라져 왔으니, 출시할 판에서 위 예제처럼 직접 재 보는 것이 가장 확실합니다. 이 검사용 컴퓨터에서는 윈도를 돌려 보지 못했습니다.
</Note>

## 재는 값 다듬기

프레임 시간은 매 프레임 조금씩 흔들립니다. 화면 구석의 FPS 숫자는 최근 수십 프레임의 평균으로 보여 주고, 성능을 볼 때는 평균보다 **가장 느린 1%**(위 예제의 99% 값처럼)를 봅니다. 평균 60fps라도 가끔 50ms짜리 프레임이 끼면 사람은 "끊긴다"고 느끼기 때문입니다. 이 이야기는 [「성능 예산」](#/read/cpp-game-engine/ship-budget)에서 이어집니다.

## 정리

- 프레임 시간과 타이머는 뒤로 가지 않는 `steady_clock`으로 재고, 달력 시각이 필요할 때만 `system_clock`을 쓴다
- `sleep_for`는 늘 조금 늦게 깨므로, 프레임을 맞출 때는 대부분 자고 마지막 조금은 돌며 기다린다
- 마감을 지난 마감 기준으로 잡으면 평균을 지키고 지금 기준으로 잡으면 간격을 지키며, 성능은 평균보다 느린 쪽 끝을 본다
