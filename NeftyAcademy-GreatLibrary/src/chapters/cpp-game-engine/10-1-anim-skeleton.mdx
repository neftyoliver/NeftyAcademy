캐릭터 메시는 정점이 수만 개라서, 애니메이션마다 정점 위치를 전부 저장할 수는 없습니다. 대신 메시 안에 수십~수백 개의 **뼈**를 심고, 애니메이션은 뼈의 움직임만 저장합니다. 정점은 가까운 뼈 몇 개에 **가중치**로 붙어 있다가 뼈를 따라 움직입니다. 이 방식을 **스키닝**이라고 합니다.

## 팔 하나

어깨, 팔꿈치, 손끝으로 이어진 2차원 팔을 만들고, 팔꿈치를 0도, 90도, 150도로 굽혀 봅니다.

```cpp
#include <cmath>
#include <numbers>
#include <print>
#include <vector>

// 2차원 강체 변환: 회전 각도 + 이동
struct Xf {
    double c = 1, s = 0, tx = 0, ty = 0;           // [c -s tx; s c ty]
    static Xf make(double deg, double x, double y) {
        double r = deg * std::numbers::pi / 180;
        return {std::cos(r), std::sin(r), x, y};
    }
};
Xf operator*(const Xf& a, const Xf& b) {           // a(b(p))를 한 번에
    return {a.c * b.c - a.s * b.s, a.s * b.c + a.c * b.s,
            a.c * b.tx - a.s * b.ty + a.tx, a.s * b.tx + a.c * b.ty + a.ty};
}
Xf inverse(const Xf& a) {
    return {a.c, -a.s, -(a.c * a.tx + a.s * a.ty), a.s * a.tx - a.c * a.ty};
}
struct P { double x, y; };
P apply(const Xf& a, P p) {
    return {a.c * p.x - a.s * p.y + a.tx, a.s * p.x + a.c * p.y + a.ty};
}

struct Bone { int parent; Xf local; };            // 부모 기준 변환

std::vector<Xf> globals(const std::vector<Bone>& bones) {
    std::vector<Xf> g(bones.size());
    for (std::size_t i = 0; i < bones.size(); ++i)  // 부모가 늘 앞에 있다
        g[i] = bones[i].parent < 0 ? bones[i].local
                                   : g[bones[i].parent] * bones[i].local;
    return g;
}

struct Vertex { P p; int b0, b1; double w0; };     // 뼈 둘, 가중치 w0과 1-w0

int main() {
    // 어깨(원점) -> 위팔(길이 2) -> 아래팔(길이 2), 바인드 자세는 일자로 쭉
    std::vector<Bone> bind = {
        {-1, Xf::make(0, 0, 0)},
        {0, Xf::make(0, 2, 0)},
        {1, Xf::make(0, 2, 0)},                     // 손끝
    };
    auto bind_g = globals(bind);
    std::vector<Xf> inv_bind;
    for (auto& g : bind_g) inv_bind.push_back(inverse(g));

    std::vector<Vertex> skin = {
        {{1.0, 0.3}, 0, 0, 1.0},                    // 위팔 가운데: 위팔만
        {{2.0, 0.3}, 0, 1, 0.5},                    // 팔꿈치: 반반
        {{3.0, 0.3}, 1, 1, 1.0},                    // 아래팔 가운데: 아래팔만
    };

    for (double elbow : {0.0, 90.0, 150.0}) {
        auto pose = bind;
        pose[0].local = Xf::make(30, 0, 0);         // 어깨를 30도 들고
        pose[1].local = Xf::make(elbow, 2, 0);      // 팔꿈치를 굽힌다
        auto g = globals(pose);
        P hand = apply(g[2], {0, 0});
        std::println("팔꿈치 {:3.0f}도: 손끝 ({:5.2f},{:5.2f})",
                     elbow, hand.x, hand.y);
        std::print("  정점");
        for (auto& v : skin) {
            // 스킨 행렬 = 현재 전역 * 바인드 전역의 역
            P a = apply(g[v.b0] * inv_bind[v.b0], v.p);
            P b = apply(g[v.b1] * inv_bind[v.b1], v.p);
            P out{a.x * v.w0 + b.x * (1 - v.w0), a.y * v.w0 + b.y * (1 - v.w0)};
            std::print(" ({:5.2f},{:5.2f})", out.x, out.y);
        }
        // 팔꿈치 정점이 관절에서 얼마나 떨어졌나(바인드에선 0.3)
        P a = apply(g[0] * inv_bind[0], skin[1].p);
        P b = apply(g[1] * inv_bind[1], skin[1].p);
        P mid{(a.x + b.x) / 2, (a.y + b.y) / 2};
        P j = apply(g[1], {0, 0});
        std::println("  두께 {:.2f}", std::hypot(mid.x - j.x, mid.y - j.y));
    }
}
```

  정점 ( 0.72, 0.76) ( 1.53, 1.05) ( 0.97, 1.72)  두께 0.21

## 뼈대: 부모 기준에서 전역으로

뼈마다 **부모 기준 변환**(`local`)만 저장합니다. 팔꿈치 회전은 "위팔에 대해 몇 도"로 적혀 있어서, 어깨를 들면 팔꿈치와 손이 함께 따라옵니다. 전역 변환은 [「변환과 계층」](#/read/cpp-game-engine/math-transform)처럼 부모의 전역 변환에 자기 부모 기준 변환을 곱해 얻습니다. 출력의 첫 줄에서 팔꿈치를 펴고 어깨만 30도 들었더니, 손끝이 길이 4인 팔 끝답게 (4 cos 30°, 4 sin 30°) = (3.46, 2.00)에 있었습니다.

`globals`가 배열을 한 번만 앞에서 뒤로 훑는 것은 **부모가 항상 자식보다 앞에** 오도록 뼈를 정렬해 두었기 때문입니다. [「장면 그래프」](#/read/cpp-game-engine/scene-graph)처럼 포인터로 나무를 따라가지 않고, 정렬된 배열 하나를 순서대로 처리하므로 캐시에 친숙하고 SIMD로 묶기도 쉽습니다. 뼈대 데이터는 대부분 이렇게 저장합니다.

## 스키닝: 바인드 자세의 역

메시는 모델러가 팔을 쭉 편 **바인드 자세**에서 만들었습니다. 정점 좌표도 그 자세 기준입니다. 정점을 움직이려면 먼저 "바인드 자세의 이 뼈 기준으로 정점이 어디 있었나"로 되돌리고(바인드 전역의 역행렬), 그 상대 위치를 현재 뼈의 전역 변환에 실어 보냅니다. 그래서 뼈마다 **스킨 행렬 = 현재 전역 × 바인드 전역의 역**을 한 번 계산합니다. 바인드 역행렬은 바뀌지 않으므로 메시를 불러올 때 미리 구해 둡니다.

- 위팔 가운데 정점(위팔 가중치 1)은 팔꿈치를 아무리 굽혀도 (0.72, 0.76) 그대로입니다. 위팔은 움직이지 않았으니 당연합니다
- 아래팔 정점은 아래팔을 따라 팔꿈치를 중심으로 돌아갑니다
- 팔꿈치 정점은 두 뼈에 반반 붙어 있어서, 두 스킨 행렬로 옮긴 위치의 **평균**에 놓입니다. 이것이 **선형 블렌드 스키닝**(LBS)이고, GPU에서 정점 셰이더가 정점마다 뼈 4개 정도까지 이 계산을 합니다

## 팔꿈치가 가늘어진다

각 둘째 줄 끝의 두께는 팔꿈치 정점이 관절에서 얼마나 떨어져 있는지입니다. 바인드 자세에서는 0.30이었는데 90도에서 0.21, 150도에서 0.08로 줄었습니다. 두 위치를 직선으로 평균하면 원호의 안쪽, 곧 관절에 가까운 쪽으로 끌려오기 때문입니다. 관절을 많이 굽힐수록 살이 꺼지고, 3차원에서 비틀면 사탕 껍질처럼 쪼그라드는 것이 선형 블렌드 스키닝의 대표적인 결함입니다.

해결책으로는 두 변환을 [「쿼터니언과 회전」](#/read/cpp-game-engine/math-quaternion)의 확장인 **이중 쿼터니언**으로 섞어 회전을 회전답게 보간하는 방법이 있습니다. 비용이 조금 더 들고, 반대로 관절이 부풀어 보이는 경우가 생겨서, 두 방식을 섞거나 보정용 뼈를 더 심는 방법도 씁니다.

<Note>
예제는 2차원이고 뼈마다 크기 변환이 없습니다. 실제 뼈대에는 크기 변환도 있을 수 있는데, 크기가 고르지 않은 부모 아래에서 자식을 회전시키면 기울어짐(shear)이 생겨 계층 계산이 까다로워집니다. 그래서 많은 엔진이 뼈의 크기 변환을 고른 크기로 제한하거나 아예 막습니다.
</Note>

## 정리

- 뼈대는 부모 기준 변환만 저장하고, 부모가 앞에 오게 정렬한 배열을 한 번 훑어 전역 변환을 구한다
- 정점은 바인드 자세 기준이므로, 스킨 행렬은 현재 전역에 바인드 전역의 역을 곱한 것이고 가중치로 평균한다
- 선형 블렌드 스키닝은 관절을 굽히면 살이 꺼지며, 이중 쿼터니언이나 보정 뼈로 줄인다
