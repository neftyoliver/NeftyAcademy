ECS의 시스템들은 서로를 직접 부르지 않습니다. 그런데 "총알이 적을 맞혔다", "적이 죽었다" 같은 사건은 여러 시스템에 알려야 합니다. 피해 시스템은 체력을 깎고, 소리 시스템은 비명을 틀고, 퀘스트 시스템은 처치 수를 셉니다. 이 쪽은 사건을 시스템 사이에 전달하는 **이벤트**의 두 가지 방식과, 그중 ECS에 잘 맞는 큐 방식을 만들어 봅니다.

## 바로 부르기의 함정

가장 단순한 방법은 [「층으로 나눈 구조」](#/read/cpp-game-engine/arch-layers)에서 본 콜백 등록입니다. 충돌이 나면 등록된 함수들을 그 자리에서 부릅니다. 작은 규모에서는 좋지만, 게임이 커지면 문제가 생깁니다.

- **언제 불릴지 모른다**: 물리 시스템이 충돌을 처리하는 한가운데에서 피해 처리, 소리 재생, 퀘스트 갱신이 줄줄이 실행됩니다. 그 사이에 누가 엔티티를 지우면 물리 시스템이 훑던 배열이 바뀌어 [「시스템과 실행 순서」](#/read/cpp-game-engine/ecs-systems)의 건너뛰기 버그가 납니다
- **줄줄이 이어진다**: 맞음 → 죽음 → 폭발 → 주변이 맞음 → … 이벤트가 이벤트를 부르며 호출 깊이가 끝없이 깊어질 수 있습니다
- **병렬로 돌리기 어렵다**: 다른 스레드의 시스템이 내 콜백을 언제 부를지 모르니 모든 데이터에 잠금이 필요해집니다

## 큐에 쌓고 정해진 때에 읽기

그래서 ECS는 보통 이벤트를 **큐에 쌓아 두고**, 읽는 시스템이 자기 차례에 꺼내 보게 합니다. 보내는 쪽과 읽는 쪽이 서로를 모르고, 처리 시점이 시스템 순서로 정해집니다.

```cpp
#include <cstdint>
#include <print>
#include <vector>

// 이벤트 큐 하나. 두 겹이라 보낸 뒤 두 프레임 동안 살아 있다
template <typename T>
class EventQueue {
    struct Entry { std::uint64_t id; T value; };
    std::vector<Entry> prev_, curr_;
    std::uint64_t next_id_ = 1;

public:
    struct Reader { std::uint64_t seen = 0; };   // 읽은 곳까지의 책갈피

    void send(T v) { curr_.push_back({next_id_++, std::move(v)}); }

    template <typename F>
    int read(Reader& r, F&& f)                     // 아직 안 읽은 것만
    {
        int n = 0;
        for (auto* list : {&prev_, &curr_})
            for (const auto& e : *list)
                if (e.id > r.seen) { f(e.value); r.seen = e.id; ++n; }
        return n;
    }
    void end_frame() { prev_ = std::move(curr_); curr_.clear(); }
};

struct Hit { int target, damage; };
struct Died { int who; };

int main()
{
    EventQueue<Hit> hits;
    EventQueue<Died> deaths;
    EventQueue<Hit>::Reader damage_r;
    EventQueue<Died>::Reader sound_r, quest_r, late_r;
    int hp[3] = {10, 4, 10};

    for (int frame = 1; frame <= 4; ++frame) {
        std::println("-- 프레임 {}", frame);
        if (frame == 1) { hits.send({1, 5}); hits.send({2, 3}); }   // 충돌 시스템

        hits.read(damage_r, [&](const Hit& h) {                     // 피해 시스템
            hp[h.target] -= h.damage;
            std::println("  피해: e{} -> hp {}", h.target, hp[h.target]);
            if (hp[h.target] <= 0) deaths.send({h.target});
        });
        deaths.read(sound_r, [&](const Died& d) {                   // 매 프레임
            std::println("  소리: e{} 비명", d.who);
        });
        if (frame % 2 == 0)                                         // 두 프레임마다
            deaths.read(quest_r, [&](const Died& d) {
                std::println("  퀘스트: e{} 처치 기록", d.who);
            });
        if (frame == 4) {                                           // 너무 늦게
            int n = deaths.read(late_r, [](const Died&) {});
            std::println("  늦게 온 시스템이 읽은 것: {}개", n);
        }
        hits.end_frame();
        deaths.end_frame();
    }
}
```

```text
-- 프레임 1
  피해: e1 -> hp -1
  피해: e2 -> hp 7
  소리: e1 비명
-- 프레임 2
  퀘스트: e1 처치 기록
-- 프레임 3
-- 프레임 4
  늦게 온 시스템이 읽은 것: 0개
```

- **종류마다 큐**: `Hit`과 `Died`는 다른 큐에 쌓입니다. 이벤트는 작은 구조체 값이라 복사가 싸고, 같은 종류끼리 나란히 놓입니다
- **두 겹**: 큐가 "지난 프레임"과 "이번 프레임" 두 겹이라, 보낸 이벤트는 **두 프레임 동안** 읽을 수 있습니다. 퀘스트 시스템은 짝수 프레임에만 도는데도 1프레임에 생긴 죽음을 2프레임에 읽었습니다. 시스템 순서상 보내는 쪽보다 앞에 도는 시스템도 다음 프레임에 놓치지 않고 읽게 됩니다
- **책갈피**: 같은 이벤트가 두 프레임 동안 남아 있으니, 그냥 읽으면 소리 시스템이 비명을 두 번 틉니다. 그래서 읽는 시스템마다 "어디까지 읽었나"를 기억하는 책갈피(이벤트 번호)를 두고 안 읽은 것만 꺼냅니다. 소리는 정확히 한 번 났습니다
- **너무 늦으면 사라진다**: 4프레임에 처음 읽은 시스템은 아무것도 받지 못했습니다. 1프레임의 이벤트는 3프레임이 끝날 때 버려졌기 때문입니다. 두 겹 큐는 "늦어도 다음 프레임에는 읽는다"는 약속이고, 그보다 늦게 읽어야 하는 일(세이브 파일에 기록하기 등)은 이벤트를 받아 자기 상태로 옮겨 적어 둡니다

## 이벤트 대신 컴포넌트로

ECS다운 또 하나의 방법은 사건을 **컴포넌트로 붙이는** 것입니다. 맞은 엔티티에 `Damaged{5}` 컴포넌트를 붙이면, 피해 시스템이 그 컴포넌트를 가진 엔티티를 훑어 처리하고 떼어 냅니다. 대상 엔티티가 분명한 사건(맞음, 선택됨)에 잘 맞고, 이벤트 큐 없이 ECS의 질문만으로 처리됩니다. 대신 컴포넌트를 붙였다 떼는 비용이 들어서 [「아키타입과 희소 집합」](#/read/cpp-game-engine/ecs-storage)의 희소 집합처럼 붙이기가 싼 저장 방식에 어울립니다.

| 방식 | 잘 맞는 곳 |
| --- | --- |
| 바로 부르는 콜백 | 엔진 아래층의 드문 알림(창 크기 변경, 파일 바뀜) |
| 두 겹 이벤트 큐 | 여러 시스템이 듣는 게임 사건(맞음, 죽음, 아이템 획득) |
| 표시 컴포넌트 | 대상 엔티티가 분명하고 한 시스템이 처리하는 상태 |

<Note>
네트워크 게임에서는 이벤트에 "어느 고정 걸음에서 생겼나"를 함께 적어 둡니다. 되감아 다시 계산하는([「예측과 보정」](#/read/cpp-game-engine/net-prediction)) 동안 같은 이벤트를 두 번 보내거나, 소리와 효과를 두 번 내지 않도록 하기 위해서입니다.
</Note>

## 정리

- 그 자리에서 콜백을 부르면 처리 시점을 알 수 없고 줄줄이 이어지며 병렬화가 어려우므로, 게임 사건은 큐에 쌓아 정해진 때에 읽는다
- 이벤트는 종류마다 큐에 두 겹으로 쌓아 두 프레임 동안 살게 하고, 읽는 시스템마다 책갈피를 두어 정확히 한 번씩 읽는다
- 두 프레임보다 늦게 읽는 일은 자기 상태로 옮겨 두고, 대상이 분명한 사건은 표시 컴포넌트로 처리할 수도 있다
