## 두 세계 잇기

아래에서 `phys` 이름공간은 바깥 라이브러리라고 생각하고, 그 아래가 우리 엔진 쪽 코드입니다. 게임이 올리는 승강기 위로 상자가 떨어지고, 유령은 아무것과도 부딪히지 않습니다.

```cpp
#include <cstdint>
#include <set>
#include <print>
#include <string>
#include <vector>

// ===== 바깥 물리 라이브러리라고 생각할 부분 =====
namespace phys {
struct BodyId { std::uint32_t index; };
enum Motion { Static, Dynamic, Kinematic };
struct Body { float y, vy; float half; Motion motion; std::uint32_t layer; };
struct ContactListener {               // 라이브러리가 단계 안에서 부른다
    virtual void on_contact(BodyId a, BodyId b) = 0;
    virtual ~ContactListener() = default;
};

class World {
    std::vector<Body> bodies;
    std::uint32_t collide_mask[32] = {};   // 층마다 부딪힐 층들의 비트
    std::set<std::pair<std::uint32_t, std::uint32_t>> touching;
public:
    ContactListener* listener = nullptr;
    BodyId create(const Body& b) {
        bodies.push_back(b);
        return {std::uint32_t(bodies.size() - 1)};
    }
    void set_collides(int a, int b) {
        collide_mask[a] |= 1u << b; collide_mask[b] |= 1u << a;
    }
    Body& get(BodyId id) { return bodies[id.index]; }
    void step(float h) {                   // 1차원 상자들, 반암시적 오일러
        for (auto& b : bodies)
            if (b.motion == Dynamic) { b.vy -= 9.8f * h; b.y += b.vy * h; }
        std::set<std::pair<std::uint32_t, std::uint32_t>> now;
        for (std::uint32_t i = 0; i < bodies.size(); ++i)
            for (std::uint32_t j = i + 1; j < bodies.size(); ++j) {
                auto &a = bodies[i], &b = bodies[j];
                if (!(collide_mask[a.layer] & (1u << b.layer))) continue;
                float d = b.y > a.y ? b.y - a.y : a.y - b.y;
                float gap = d - a.half - b.half;
                if (gap > 1e-4f) continue;
                auto& top = b.y > a.y ? b : a;
                if (top.motion == Dynamic && top.vy <= 0) {
                    top.y -= gap; top.vy = 0;          // 위에 올려놓고 멈춤
                }
                now.insert({i, j});
                if (!touching.contains({i, j}) && listener)
                    listener->on_contact({i}, {j});    // 새로 닿을 때만 알림
            }
        touching = std::move(now);
    }
};
}  // namespace phys

// ===== 우리 엔진 쪽 =====
struct Entity {
    std::string name;
    float y = 0, prev_y = 0;               // 화면용 위치와 직전 물리 위치
    phys::BodyId body{};
};

struct Events : phys::ContactListener {    // 단계 안에서는 모아 두기만
    std::vector<std::pair<std::uint32_t, std::uint32_t>> queue;
    void on_contact(phys::BodyId a, phys::BodyId b) override {
        queue.push_back({a.index, b.index});
    }
};

int main() {
    enum Layer { Ground = 0, Crate = 1, Ghost = 2 };
    phys::World world;
    world.set_collides(Ground, Crate);     // 유령은 아무것과도 안 부딪힌다
    Events events;
    world.listener = &events;

    std::vector<Entity> es = {{"승강기"}, {"상자"}, {"유령"}};
    es[0].body = world.create({0, 0, 0.5f, phys::Kinematic, Ground});
    es[1].body = world.create({3, 0, 0.5f, phys::Dynamic, Crate});
    es[2].body = world.create({3, 0, 0.5f, phys::Dynamic, Ghost});
    std::vector<std::uint32_t> body_to_entity = {0, 1, 2};

    const float h = 1.0f / 60;
    float acc = 0, time = 0;
    float frames[] = {0.016f, 0.033f, 0.007f, 0.050f};
    for (int f = 0; f < 80; ++f) {
        float dt = frames[f % 4];
        time += dt;
        // 1) 게임 -> 물리: 게임이 움직이는 키네마틱 물체를 밀어 넣는다
        world.get(es[0].body).y = time > 1 ? (time - 1) * 0.5f : 0;
        // 2) 고정 걸음으로 물리 돌리기
        acc += dt;
        while (acc >= h) {
            for (auto& e : es) e.prev_y = world.get(e.body).y;
            world.step(h);
            acc -= h;
        }
        // 3) 물리 -> 게임: 결과를 읽어 오고, 남은 시간으로 보간
        float alpha = acc / h;
        for (auto& e : es)
            e.y = e.prev_y + (world.get(e.body).y - e.prev_y) * alpha;
        // 4) 모아 둔 충돌 사건을 단계 밖에서 게임 코드에 전달
        for (auto [a, b] : events.queue)
            std::println("{:.3f}초: 닿기 시작 {} - {}", time,
                         es[body_to_entity[a]].name, es[body_to_entity[b]].name);
        events.queue.clear();
    }
    for (auto& e : es) std::println("{}: y={:.2f}", e.name, e.y);
}
```

```text
0.636초: 닿기 시작 승강기 - 상자
승강기: y=0.56
상자: y=1.56
유령: y=-18.85
```

한 프레임은 네 단계입니다.

1. **게임에서 물리로**: 게임 코드가 직접 움직이는 물체(**키네마틱**, 여기서는 승강기)의 위치를 물리 세계에 밀어 넣습니다. 물리는 이 물체를 밀 수 없고, 이 물체는 다른 것을 밉니다. 1초 뒤 올라가기 시작한 승강기가 상자를 들어 올려, 끝에 상자가 승강기보다 정확히 1(두 상자의 반 높이 합) 위에 있습니다
2. **고정 걸음**: [「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)의 누적기로, 들쭉날쭉한 프레임 시간(7~50ms)을 1/60초 걸음으로 바꿔 물리를 돌립니다
3. **물리에서 게임으로**: 물리가 움직이는 물체(**다이내믹**)의 결과를 읽어 엔티티에 씁니다. 누적기에 남은 시간의 비율 `alpha`로 직전 물리 상태와 현재 상태 사이를 보간해서, 화면이 물리보다 자주 그려져도 움직임이 끊기지 않습니다
4. **사건 전달**: 충돌 알림을 게임 코드로 넘깁니다

## 충돌 사건은 모아 두었다가

라이브러리는 충돌 알림을 **물리 단계 안에서** 부릅니다. 그 순간에는 물리 세계가 계산 도중이라 물체를 지우거나 새로 만들면 안 되고, 라이브러리에 따라서는 여러 작업 스레드에서 동시에 부르기도 합니다. 그래서 `Events`는 알림을 큐에 넣기만 하고, 실제 게임 반응(소리, 피해, 파괴)은 단계가 끝난 뒤 한 스레드에서 처리합니다. [「이벤트와 메시지」](#/read/cpp-game-engine/ecs-events)의 지연 처리와 같은 생각입니다.

또 예제의 물리 세계는 **새로 닿을 때만** 알립니다. 상자는 0.636초부터 끝까지 승강기 위에 얹혀 있었지만 알림은 한 번이었습니다. 이렇게 하지 않으면 얹혀 있는 동안 매 걸음 "닿았다"가 쏟아집니다. 실제 라이브러리는 닿기 시작, 계속 닿음, 떨어짐을 구분해서 알려 줍니다.

## 층과 필터

유령은 바닥을 뚫고 계속 떨어졌습니다. 물체마다 **층**을 주고, 어느 층끼리 부딪힐지 표(`collide_mask`)로 정했기 때문입니다. 넓은 단계에서 이 표로 쌍을 먼저 거르면 계산도 줄어듭니다. 플레이어 총알은 플레이어와 부딪히지 않게, 장식용 파편은 서로 부딪히지 않게 하는 식으로 씁니다.

물리 물체와 엔티티를 잇는 것은 라이브러리의 `BodyId`와 우리 쪽의 대응표(`body_to_entity`)입니다. 라이브러리는 대개 물체마다 사용자 값 하나를 붙일 자리를 주므로, 거기에 [「핸들과 세대 인덱스」](#/read/cpp-game-engine/mem-handles)의 핸들을 넣어 두면 충돌 알림에서 바로 엔티티를 찾을 수 있습니다.

## 라이브러리 안의 적분기

라이브러리를 고를 때 한 번쯤 확인할 것이 적분 방식입니다. 질량 1, 강성 1인 용수철을 0.1초 걸음으로 돌리면, 정확한 답에서는 에너지가 계속 0.5여야 합니다.

```cpp
#include <cmath>
#include <print>

// 용수철 x'' = -x (질량 1, 강성 1). 정확한 에너지는 언제나 0.5
double energy(double x, double v) { return 0.5 * (x * x + v * v); }

int main() {
    const double dt = 0.1;
    double ex = 1, ev = 0;                 // 명시적 오일러
    double sx = 1, sv = 0;                 // 반암시적(심플렉틱) 오일러
    double vx = 1, vv = 0;                 // 속도 베를레
    for (int step = 1; step <= 1000; ++step) {
        double a = -ex;                    // 옛 위치, 옛 속도로 둘 다 갱신
        ex += ev * dt; ev += a * dt;

        sv += -sx * dt;                    // 속도 먼저, 새 속도로 위치
        sx += sv * dt;

        double a0 = -vx;                   // 반 걸음씩 나눠 갱신
        vx += vv * dt + 0.5 * a0 * dt * dt;
        vv += 0.5 * (a0 + -vx) * dt;

        if (step == 10 || step == 100 || step == 1000)
            std::println("{:4}걸음 에너지  명시적 {:9.4f}  "
                         "반암시적 {:.4f}  베를레 {:.4f}",
                         step, energy(ex, ev), energy(sx, sv), energy(vx, vv));
    }

}
```

```text
  10걸음 에너지  명시적    0.5523  반암시적 0.4790  베를레 0.4991
 100걸음 에너지  명시적    1.3524  반암시적 0.4778  베를레 0.4996
1000걸음 에너지  명시적 10479.5778  반암시적 0.5213  베를레 0.4997
```

- **명시적 오일러**는 옛 위치와 옛 속도로 둘 다 갱신해서, 이 용수철에서는 걸음마다 에너지가 정확히 `1 + dt²` 배가 됩니다. 0.5 × 1.01¹⁰⁰⁰ ≈ 10480으로 폭발했습니다
- **반암시적 오일러**는 속도를 먼저 갱신하고 새 속도로 위치를 갱신합니다. 줄 순서만 바꿨는데 에너지가 0.48~0.52 사이에 머뭅니다. 계산량이 같아서 게임 물리 엔진 대부분이 이 방식을 쓰고, 위의 `phys::World`와 [「강체 시뮬레이션」](#/read/cpp-game-engine/phys-rigid)의 공 떨어뜨리기도 이것이었습니다
- **속도 베를레**는 가속도를 걸음 앞뒤에서 평균해 더 정확하지만 힘을 두 번 계산해야 합니다. 위치만 쓰는 베를레 변형은 밧줄과 천처럼 제약을 위치로 직접 고치는 곳에서 많이 씁니다

<Note>
고정 걸음으로 돌리면 같은 입력에서 같은 결과가 나오지만, 이것은 같은 실행 파일과 같은 종류의 CPU에서만 확실합니다. 부동소수점 결과는 컴파일러 최적화(FMA 사용, `-ffast-math`), 수학 함수 구현, 스레드 사이의 처리 순서에 따라 마지막 자리가 달라질 수 있습니다. 리플레이나 [「상태 복제」](#/read/cpp-game-engine/net-replication)가 결정론에 기대야 한다면, 라이브러리가 결정론 모드를 지원하는지와 그 조건을 먼저 확인합니다.
</Note>

## 정리

- 물리 라이브러리를 붙일 때는 키네마틱 물체를 밀어 넣고, 고정 걸음으로 돌리고, 다이내믹 결과를 보간해 읽어 오는 순서를 지킨다
- 충돌 알림은 단계 안에서 큐에 모았다가 단계 밖에서 처리하고, 새로 닿기와 떨어지기를 구분하며, 층 표로 부딪힐 쌍을 거른다
- 라이브러리 안의 적분은 보통 반암시적 오일러이고, 결정론이 필요하면 그 조건을 따로 확인한다
