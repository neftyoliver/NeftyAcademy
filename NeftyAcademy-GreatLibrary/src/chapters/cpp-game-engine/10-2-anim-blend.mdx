[「뼈대와 스키닝」](#/read/cpp-game-engine/anim-skeleton)에서 뼈 자세가 정해지면 메시가 따라온다는 것을 봤습니다. 이제 그 자세를 어디서 가져오느냐입니다. 애니메이션 클립은 뼈마다 띄엄띄엄 찍힌 **키프레임**이고, 엔진은 매 프레임 키 사이를 보간하고 여러 클립을 섞어 하나의 자세를 만듭니다. 걷다가 달리기로 부드럽게 넘어가는 것도, 걸으면서 총을 위로 겨누는 것도 섞기입니다.

## 다리 뼈 하나로 보는 섞기

```cpp
#include <cmath>
#include <print>
#include <vector>

struct Key { double t, deg; };
struct Clip { double length; std::vector<Key> keys; };   // 반복하는 클립

// 키 사이를 선형 보간해서 시각 t의 각도를 구한다
double sample(const Clip& c, double t) {
    t = std::fmod(t, c.length);
    for (std::size_t i = 0; i + 1 < c.keys.size(); ++i) {
        auto &a = c.keys[i], &b = c.keys[i + 1];
        if (t <= b.t) return a.deg + (b.deg - a.deg) * (t - a.t) / (b.t - a.t);
    }
    return c.keys.back().deg;
}

// 각도 섞기: 짧은 쪽으로 돌아가게
double mix_angle(double a, double b, double w) {
    double d = std::remainder(b - a, 360.0);       // -180 ~ 180
    return a + d * w;
}

int main() {
    // 다리 각도: 걷기는 1초에 한 주기, 달리기는 0.6초에 한 주기(같은 모양)
    Clip walk{1.0, {{0, -20}, {0.5, 20}, {1.0, -20}}};
    Clip run{0.6, {{0, -40}, {0.3, 40}, {0.6, -40}}};

    std::println("섞음 비율 0.5, 같은 초로 재생 vs 정규화 시간으로 재생");
    for (double t : {0.0, 0.15, 0.3, 0.45, 0.6, 0.75}) {
        double raw = 0.5 * sample(walk, t) + 0.5 * sample(run, t);
        // 정규화 시간: 섞인 주기 길이로 위상 하나를 두 클립이 함께 쓴다
        double len = 0.5 * walk.length + 0.5 * run.length;   // 0.8초
        double phase = std::fmod(t, len) / len;
        double synced = 0.5 * sample(walk, phase * walk.length)
                      + 0.5 * sample(run, phase * run.length);
        std::println("  t={:.2f}  같은 초 {:6.1f}  정규화 {:6.1f}", t, raw, synced);
    }

    std::println("각도 170과 -170을 반반 섞기");
    std::println("  숫자 평균 {:.1f}, 짧은 쪽 {:.1f}",
                 0.5 * 170 + 0.5 * -170, mix_angle(170, -170, 0.5));

    // 가산 블렌딩: 기준 자세와의 차이만 저장해 다른 동작 위에 얹는다
    Clip aim_up{1.0, {{0, 25}, {1.0, 25}}}, aim_ref{1.0, {{0, 5}, {1.0, 5}}};
    for (double t : {0.0, 0.25, 0.5}) {
        double base = sample(walk, t);
        double add = sample(aim_up, t) - sample(aim_ref, t);   // +20도
        std::println("  걷기 {:6.1f} + 위 조준 차이 {:.1f} = {:6.1f}",
                     base, add, base + add);
    }
}
```

## 키 사이 보간

`sample`은 시각 t를 클립 길이로 감고, 앞뒤 키 사이를 직선으로 보간합니다. 실제 클립은 뼈마다 위치, 회전, 크기 키가 있고, 회전은 쿼터니언으로 보간합니다. 키를 모든 프레임에 저장하면 용량이 커서, 직선 보간으로 충분히 복원되는 키는 지우고 남은 값도 낮은 정밀도로 양자화해 압축합니다. 캐릭터가 많은 게임에서는 애니메이션 데이터가 메모리의 큰 몫을 차지하기 때문입니다.

## 정규화 시간으로 맞추기

걷기는 1초, 달리기는 0.6초에 한 걸음 주기입니다. 둘을 반반 섞으면서 **같은 초**로 재생하면, 예를 들어 t=0.6에서 걷기는 다리를 앞으로(+12도) 뻗고 있는데 달리기는 막 한 주기를 돌아 뒤로(-40도) 차고 있습니다. 섞인 각도는 주기도 크기도 들쭉날쭉해져서 다리가 허우적거리고, 발이 땅에서 미끄러집니다.

**정규화 시간**은 두 클립의 진행을 0~1의 위상 하나로 묶습니다. 섞인 주기 길이(여기서는 0.8초)로 위상을 진행시키고, 각 클립은 그 위상에 자기 길이를 곱한 시각을 재생합니다. 출력의 정규화 열은 0.8초에 한 주기로 -30에서 +30 사이를 고르게 오갑니다. 이렇게 하려면 두 클립의 걸음 시작이 같은 위상에 오도록(예: 왼발 착지가 0) 애니메이터와 약속해야 합니다.

## 회전은 짧은 쪽으로

각도 170도와 -170도는 20도밖에 떨어져 있지 않지만, 숫자로 평균하면 0도, 곧 반대 방향이 됩니다. `mix_angle`은 차이를 -180~180으로 감아서 짧은 쪽으로 돌아가 180도를 얻었습니다. 3차원에서도 같은 문제가 있습니다. 쿼터니언 `q`와 `-q`는 같은 회전이라서, 섞기 전에 두 쿼터니언의 내적이 음수면 한쪽 부호를 뒤집어야 짧은 쪽으로 보간됩니다. 보간 방법으로는 [「쿼터니언과 회전」](#/read/cpp-game-engine/math-quaternion)의 slerp보다, 성분을 직선 보간하고 정규화하는 nlerp를 많이 씁니다. 더 싸고, 여러 클립을 섞을 때 순서와 상관없이 같은 결과가 나오기 때문입니다.

## 가산 블렌딩

마지막 세 줄은 **가산** 섞기입니다. 위로 겨누는 자세를 통째로 저장하지 않고, 기준 자세와의 **차이**(+20도)만 저장했다가 어떤 동작 위에든 더합니다. 걷기가 어느 각도에 있든 20도만큼 위로 들렸습니다. 숨쉬기, 맞았을 때 움찔하기, 조준 방향처럼 다른 동작과 겹쳐 쓰는 것들을 이렇게 만들면, 동작마다 조합을 따로 만들 필요가 없습니다. 3차원 회전에서는 더하기 대신 차이 쿼터니언을 곱합니다.

<Note>
실제 엔진에서 섞기는 뼈 수백 개 × 클립 여러 개를 매 프레임 계산하는 일이라, 뼈별 데이터를 [「SIMD로 빠르게」](#/read/cpp-game-engine/math-simd)의 SoA 배치로 두고 여러 캐릭터를 작업 스레드에 나눠 처리합니다. 화면에서 먼 캐릭터는 애니메이션 갱신 빈도를 낮추기도 합니다.
</Note>

## 정리

- 클립은 압축된 키프레임이고, 매 프레임 키 사이를 보간해 뼈 자세를 얻는다
- 주기가 다른 클립은 정규화 시간으로 위상을 맞춰 섞어야 다리가 허우적거리지 않는다
- 회전은 짧은 쪽으로 섞고(쿼터니언 부호 확인, nlerp), 가산 블렌딩은 기준과의 차이만 다른 동작 위에 얹는다
