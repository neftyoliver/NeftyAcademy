[「프레임 할당자와 스택 할당자」](#/read/cpp-game-engine/mem-frame)는 한 프레임만 사는 것에 맞았습니다. 총알, 파편, 적, 소리 재생 핸들처럼 **얼마나 살지 모르고, 자주 생기고 사라지는** 같은 크기의 객체에는 **풀 할당자**를 씁니다. 「C++ 고급」의 [「아레나와 풀」](#/read/cpp-advanced/mm-arena)에서 본 풀을 엔진에서 쓰기 좋게 다듬고, 풀의 약점인 "늦은 사용"을 도구로 잡는 법을 더합니다.

## 빈 칸을 칸 안에 꿴다

칸이 비어 있는 동안은 그 칸의 메모리를 **다음 빈 칸을 가리키는 포인터**로 씁니다. 따로 장부가 필요 없고, 주기와 돌려받기가 모두 포인터 한두 개를 바꾸는 일입니다.

```cpp
#include <cstddef>
#include <memory>
#include <new>
#include <print>
#include <vector>

#if defined(__has_feature)
#if __has_feature(address_sanitizer)
#define POOL_ASAN 1
#endif
#endif
#if defined(__SANITIZE_ADDRESS__)
#define POOL_ASAN 1
#endif
#ifdef POOL_ASAN
#include <sanitizer/asan_interface.h>
#define POISON(p, n) ASAN_POISON_MEMORY_REGION(p, n)
#define UNPOISON(p, n) ASAN_UNPOISON_MEMORY_REGION(p, n)
#else
#define POISON(p, n) ((void)(p), (void)(n))
#define UNPOISON(p, n) ((void)(p), (void)(n))
#endif

// 같은 크기의 칸만 나눠 주는 풀. 빈 칸끼리는 칸 안에 적은 포인터로 이어진다
template <typename T>
class Pool {
    union Slot {
        Slot* next;                           // 비어 있을 때
        alignas(T) std::byte obj[sizeof(T)];  // 쓰는 중일 때
    };

public:
    explicit Pool(std::size_t n) : slots_(std::make_unique<Slot[]>(n)), n_(n)
    {
        for (std::size_t i = 0; i < n; ++i)   // 모든 칸을 빈 목록에 꿴다
            slots_[i].next = i + 1 < n ? &slots_[i + 1] : nullptr;
        free_ = &slots_[0];
        POISON(slots_.get(), sizeof(Slot) * n);
    }

    template <typename... Args>
    T* create(Args&&... args)
    {
        if (!free_)
            return nullptr;
        Slot* s = free_;
        UNPOISON(s, sizeof(Slot));
        free_ = s->next;                      // 빈 목록의 맨 앞을 떼어 준다
        ++live_;
        return ::new (s->obj) T(std::forward<Args>(args)...);
    }

    void destroy(T* p)
    {
        p->~T();
        auto* s = reinterpret_cast<Slot*>(p);
        s->next = free_;                      // 맨 앞에 다시 꽂는다
        free_ = s;
        --live_;
        POISON(s, sizeof(Slot));              // 이제 이 칸을 만지면 ASan이 잡는다
    }

    std::size_t index_of(const T* p) const
    {
        return reinterpret_cast<const Slot*>(p) - slots_.get();
    }
    std::size_t live() const { return live_; }

private:
    std::unique_ptr<Slot[]> slots_;
    std::size_t n_;
    Slot* free_ = nullptr;
    std::size_t live_ = 0;
};

struct Bullet {
    float x, y, vx, vy;
    int owner;
};

int main()
{
    Pool<Bullet> pool(4);
    std::vector<Bullet*> b;
    for (int i = 0; i < 5; ++i) {
        Bullet* p = pool.create(0.f, 0.f, 1.f, 0.f, i);
        if (p) {
            b.push_back(p);
            std::println("총알 {} -> 칸 {}", i, pool.index_of(p));
        } else {
            std::println("총알 {} -> 풀이 찼다", i);
        }
    }
    pool.destroy(b[1]);                       // 칸 1이 빈다
    pool.destroy(b[2]);                       // 칸 2가 빈다
    Bullet* again = pool.create(5.f, 5.f, 0.f, 1.f, 9);
    std::println("새 총알 -> 칸 {} (가장 나중에 빈 칸)", pool.index_of(again));
    std::println("살아 있는 총알 {}개, 칸 하나 {}바이트", pool.live(),
                 sizeof(Bullet));
}
```

```text
총알 0 -> 칸 0
총알 1 -> 칸 1
총알 2 -> 칸 2
총알 3 -> 칸 3
총알 4 -> 풀이 찼다
새 총알 -> 칸 2 (가장 나중에 빈 칸)
살아 있는 총알 3개, 칸 하나 20바이트
```

- `union Slot`이 칸 하나입니다. 비어 있으면 `next`, 쓰는 중이면 `obj`입니다. 칸의 크기는 `T`와 포인터 중 큰 쪽이고, 맞춤은 `T`를 따릅니다
- 칸 1과 2를 차례로 돌려준 뒤 새로 달라고 하자 **칸 2**가 나왔습니다. 빈 목록의 맨 앞에 꽂고 맨 앞에서 떼므로, 가장 최근에 빈 칸을 먼저 다시 씁니다. 방금까지 쓰던 칸이라 캐시에 남아 있을 가능성이 큽니다
- 칸이 다 차면 `nullptr`입니다. 엔진은 보통 이 상황을 "총알은 최대 1024개"처럼 **설계로 정한 상한**으로 받아들이고, 넘치면 가장 오래된 것을 없애는 식으로 처리합니다. 덩어리를 하나 더 붙여 늘어나는 풀도 있지만, 늘어날 수 있으면 메모리 예산을 세우기 어려워집니다

## 늦은 사용 잡기

풀의 가장 큰 위험은 **이미 돌려준 칸을 계속 쓰는 것**입니다. 그 칸은 곧 다른 총알에게 넘어가므로, 옛 포인터로 고친 값이 엉뚱한 총알을 망가뜨립니다. 칸의 메모리는 여전히 풀이 쥐고 있어서, 보통의 AddressSanitizer는 이것을 알지 못합니다.

그래서 위 풀은 칸을 돌려받을 때 `ASAN_POISON_MEMORY_REGION`으로 "이 메모리는 지금 아무도 쓰면 안 된다"고 ASan에게 알리고, 다시 줄 때 `ASAN_UNPOISON_MEMORY_REGION`으로 풀어 줍니다(ASan이 꺼진 빌드에서는 아무 일도 하지 않는 매크로). 일부러 돌려준 총알을 읽어 보면 이렇게 잡힙니다.

```text nocheck
==4274==ERROR: AddressSanitizer: use-after-poison on address 0x508000000038
READ of size 4 at 0x508000000038 thread T0
    #0 ... in std::basic_format_arg<...>::basic_format_arg<float>(float&)
```

`std::println("지운 총알의 x: {}", b[1]->x)` 한 줄을 넣고 `-g -fsanitize=address`로 빌드한 결과입니다(긴 줄은 줄였습니다). 같은 매크로로 [「프레임 할당자와 스택 할당자」](#/read/cpp-game-engine/mem-frame)의 비운 영역도 독을 칠 수 있습니다. 「C++ 고급」의 [「새니타이저」](#/read/cpp-advanced/tool-sanitizers)에서 본 도구를 직접 만든 할당자에까지 넓히는 방법입니다.

<Note>
포인터 대신 칸 번호를 넘기고, 칸마다 "몇 번째로 쓰이는 중인가"(세대)를 함께 적어 두면, ASan이 없는 출시 빌드에서도 늦은 사용을 알아챌 수 있습니다. 다음 쪽 [「핸들과 세대 인덱스」](#/read/cpp-game-engine/mem-handles)가 그 방법입니다.
</Note>

## 언제 풀을 쓰나

| 상황 | 고르는 것 |
| --- | --- |
| 한 프레임만 산다 | 프레임 할당자 |
| 같은 크기, 수명이 제각각, 자주 생기고 사라짐 | 풀 |
| 크기가 제각각, 오래 산다 | 일반 할당자(`malloc`, mimalloc 같은 대체 할당자) |
| 한꺼번에 생기고 한꺼번에 사라진다(레벨 하나) | 레벨 단위 아레나 |

풀에 든 객체를 매 프레임 **모두 훑어야** 한다면(모든 총알 움직이기), 빈 칸이 섞인 풀을 훑는 것보다 살아 있는 것만 촘촘히 모아 둔 배열이 빠릅니다. 이것이 [「엔진용 컨테이너」](#/read/cpp-game-engine/mem-containers)와 [「아키타입과 희소 집합」](#/read/cpp-game-engine/ecs-storage)의 출발점입니다.

## 정리

- 풀 할당자는 같은 크기의 칸을 미리 만들고, 빈 칸 안에 다음 빈 칸의 포인터를 적어 꿰어 O(1)로 주고받는다
- 가장 최근에 빈 칸을 먼저 다시 써서 캐시에 유리하고, 칸 수는 보통 설계로 정한 상한이다
- 돌려받은 칸은 ASan 독칠 매크로로 표시해 늦은 사용을 잡고, 매 프레임 모두 훑어야 하는 것은 촘촘한 배열에 둔다
