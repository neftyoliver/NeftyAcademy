렌더러가 프레임마다 가장 먼저 하는 일은 "무엇을 그리지 **않을지**"를 정하는 것입니다. 장면에 물체가 10만 개 있어도 화면에 보이는 것은 그 일부이고, 보이지 않는 것을 그리는 비용은 모두 낭비입니다. 그다음에는 남은 것을 **어떤 순서로** 그릴지 정합니다. 이 쪽은 그 두 단계를 봅니다.

## 그릴 것을 줄이는 단계

| 단계 | 버리는 것 | 비용 |
| --- | --- | --- |
| 거리·크기 | 너무 멀거나 화면에서 너무 작은 것 | 아주 쌈 |
| 시야 절두체 | 카메라가 보는 상자 밖의 것 | 쌈([「SIMD로 빠르게」](#/read/cpp-game-engine/math-simd)) |
| 공간 분할 | 큰 덩어리째 밖에 있는 것들 | 나무 구조 하나([「공간 분할」](#/read/cpp-game-engine/scene-spatial)) |
| 가림(occlusion) | 다른 물체 뒤에 완전히 가린 것 | 비쌈(깊이 버퍼를 다시 읽거나 GPU에서) |

싼 것부터 차례로 걸러 내서 비싼 검사는 남은 것에만 합니다. 거리에 따라 단순한 모양을 쓰는 **LOD**(level of detail)도 이 단계에서 고릅니다. 요즘 엔진은 컬링 자체를 GPU의 계산 셰이더에서 하고, 그리기 명령까지 GPU가 만들게 하기도 합니다(GPU 주도 렌더링).

## 왜 정렬하나

남은 그리기 명령을 정렬하는 까닭은 둘입니다.

- **상태 바꾸기 줄이기**: 셰이더·머티리얼·텍스처를 바꾸는 것은 그리기 한 번보다 비쌉니다. 같은 머티리얼끼리 모아 그리면 바꾸는 횟수가 줍니다
- **올바른 그림과 덜 그리기**: 불투명한 것은 **가까운 것부터** 그리면, 뒤의 것은 깊이 검사에서 픽셀 셰이더를 돌리기 전에 버려집니다. 투명한 것은 뒤의 색과 섞어야 해서 반대로 **먼 것부터** 그려야 겹친 모습이 맞습니다

## 64비트 정렬 열쇠

두 바람을 한 번의 정렬로 만족시키는 흔한 방법이, 그리기마다 **64비트 정수 열쇠** 하나를 만들어 그것으로 정렬하는 것입니다. 중요한 기준을 위쪽 비트에 둡니다.

```cpp
#include <algorithm>
#include <cstdint>
#include <print>
#include <string>
#include <vector>

struct Draw {
    std::string name;
    std::uint16_t material;
    float depth;              // 카메라와의 거리
    bool transparent;
};

// 64비트 정렬 열쇠. 맨 위 비트가 투명 여부라 불투명이 먼저 온다
//   불투명: [0][머티리얼 16비트][깊이 24비트]  -> 머티리얼끼리, 가까운 것부터
//   투명:   [1][거꾸로 뒤집은 깊이 24비트]     -> 맨 나중에, 먼 것부터
std::uint64_t sort_key(const Draw& d)
{
    float t = std::clamp(d.depth / 1000.f, 0.f, 1.f);   // 먼 면 1000
    auto q = static_cast<std::uint64_t>(t * 0xFFFFFF);
    if (!d.transparent)
        return (std::uint64_t(d.material) << 24) | q;
    return (1ull << 63) | (0xFFFFFF - q);
}

int state_changes(const std::vector<Draw>& ds)
{
    int n = 0;
    int last = -1;
    for (const auto& d : ds)
        if (d.material != last) { ++n; last = d.material; }
    return n;
}

int main()
{
    std::vector<Draw> draws = {
        {"바위A", 2, 40, false}, {"유리창", 7, 15, true}, {"나무A", 1, 80, false},
        {"바위B", 2, 10, false}, {"연기", 8, 60, true},   {"나무B", 1, 20, false},
        {"바위C", 2, 90, false}, {"물", 9, 30, true},     {"나무C", 1, 5, false},
    };
    std::println("정렬 전 머티리얼 바꾸기 {}번", state_changes(draws));

    std::ranges::sort(draws, {}, sort_key);
    std::print("정렬 뒤:");
    for (std::size_t i = 0; i < draws.size(); ++i)
        std::print("{}{}({:g})", i == 6 ? "\n       " : " ", draws[i].name,
                   draws[i].depth);
    std::println();
    std::println("정렬 뒤 머티리얼 바꾸기 {}번", state_changes(draws));
}
```

```text
정렬 전 머티리얼 바꾸기 9번
정렬 뒤: 나무C(5) 나무B(20) 나무A(80) 바위B(10) 바위A(40) 바위C(90)
       연기(60) 물(30) 유리창(15)
정렬 뒤 머티리얼 바꾸기 5번
```

- 맨 위 비트가 투명 여부라서 불투명한 것이 모두 먼저 오고, 투명한 것은 맨 뒤에 모였습니다
- 불투명한 것은 머티리얼(나무 1, 바위 2)끼리 모이고, 그 안에서 가까운 것부터입니다
- 투명한 것은 깊이를 뒤집어 넣어서 먼 것(연기 60)부터 가까운 것(유리창 15)으로 갑니다
- 머티리얼 바꾸기가 9번에서 5번으로 줄었습니다. 열쇠는 정수 하나라 정렬이 빠르고, 기수 정렬로 더 빠르게 할 수도 있습니다

열쇠의 비트를 어떻게 나눌지는 엔진마다 다릅니다. 화면 층(배경, 세상, UI)을 맨 위에 두기도 하고, 깊이를 머티리얼보다 위에 두어 "가까운 것부터"를 더 엄격하게 지키기도 합니다. 깊이 24비트는 먼 면까지를 약 1670만 칸으로 나눈 것이라, 정렬 순서를 정하기에는 충분합니다.

<Note>
투명한 물체끼리 서로 꿰뚫거나, 하나의 투명 물체가 크게 겹쳐 있으면 물체 단위 정렬로는 순서를 맞출 수 없습니다. 이럴 때는 순서와 무관하게 섞는 근사 방법(순서 독립 투명도, OIT)을 쓰거나, 디자인에서 그런 상황을 피합니다. 불투명한 것을 그리기 전에 깊이만 먼저 한 번 그리는 깊이 사전 패스(depth prepass)도 덜 그리기를 위해 많이 씁니다.
</Note>

## 정리

- 거리, 시야 절두체, 공간 분할, 가림의 순서로 싼 검사부터 그릴 것을 줄이고, 그 과정에서 LOD도 고른다
- 정렬은 상태 바꾸기를 줄이고, 불투명은 가까운 것부터 그려 덜 그리며, 투명은 먼 것부터 그려 바르게 섞는다
- 그리기마다 중요한 기준을 위쪽 비트에 둔 64비트 열쇠를 만들어 정수 정렬 한 번으로 모든 순서를 맞춘다
