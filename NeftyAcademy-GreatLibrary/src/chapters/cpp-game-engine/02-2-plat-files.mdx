게임은 텍스처, 소리, 레벨, 설정, 세이브 파일을 읽고 씁니다. 그런데 개발 중에는 흩어진 폴더에서, 출시 후에는 하나로 묶은 파일([「묶음 파일」](#/read/cpp-game-engine/res-packaging))에서, 모드를 깔면 그 폴더에서 같은 파일을 찾아야 합니다. 그래서 엔진은 운영체제의 경로를 그대로 쓰지 않고, 그 위에 **가상 파일 시스템**(VFS)을 둡니다.

## 엔진의 경로, 운영체제의 경로

게임 코드는 `data:/config/game.ini`처럼 **엔진 경로**만 씁니다. VFS가 그것을 실제 경로로 바꿉니다. 「C++ STL」의 [「path」](#/read/cpp-stl/fs-path)에서 본 `std::filesystem`으로 만들어 봅니다.

```cpp
#include <filesystem>
#include <fstream>
#include <optional>
#include <print>
#include <sstream>
#include <string>
#include <vector>

namespace fs = std::filesystem;

// 엔진 경로("data:/text/a.txt")를 실제 파일로 찾는 가상 파일 시스템
class Vfs {
public:
    // 나중에 붙인 것이 먼저 찾아진다(모드 폴더가 원본을 덮는다)
    void mount(std::string prefix, fs::path dir)
    {
        mounts_.insert(mounts_.begin(), {std::move(prefix), std::move(dir)});
    }

    std::optional<fs::path> resolve(const std::string& vpath) const
    {
        auto colon = vpath.find(":/");
        if (colon == std::string::npos)
            return std::nullopt;
        std::string prefix = vpath.substr(0, colon);
        fs::path rel = fs::path(vpath.substr(colon + 2)).lexically_normal();
        if (rel.empty() || rel.is_absolute() || *rel.begin() == "..")
            return std::nullopt;        // 바깥으로 나가는 경로 거절
        for (const auto& [p, dir] : mounts_)
            if (p == prefix && fs::exists(dir / rel))
                return dir / rel;
        return std::nullopt;
    }

    std::optional<std::string> read_text(const std::string& vpath) const
    {
        auto real = resolve(vpath);
        if (!real)
            return std::nullopt;
        std::ifstream in(*real, std::ios::binary);
        std::ostringstream ss;
        ss << in.rdbuf();
        return ss.str();
    }

private:
    std::vector<std::pair<std::string, fs::path>> mounts_;
};

// 임시 파일에 다 쓴 뒤 이름을 바꾼다: 도중에 꺼져도 옛 파일이 남는다
bool save_atomic(const fs::path& target, const std::string& data)
{
    fs::path tmp = target;
    tmp += ".tmp";
    {
        std::ofstream out(tmp, std::ios::binary | std::ios::trunc);
        out << data;
        out.flush();
        if (!out)
            return false;
    }
    std::error_code ec;
    fs::rename(tmp, target, ec);        // 같은 디스크 안에서는 한 번에
    return !ec;
}

void write(const fs::path& p, const std::string& s)
{
    fs::create_directories(p.parent_path());
    std::ofstream(p) << s;
}

int main()
{
    fs::path root = fs::temp_directory_path() / "vfs-demo";
    fs::remove_all(root);
    write(root / "base/config/game.ini", "speed=5\n");
    write(root / "base/text/hello.txt", "안녕\n");
    write(root / "mods/fast/config/game.ini", "speed=9\n");

    Vfs vfs;
    vfs.mount("data", root / "base");
    vfs.mount("data", root / "mods/fast");      // 모드가 위에 얹힌다

    for (const char* p : {"data:/config/game.ini", "data:/text/hello.txt",
                          "data:/text/../config/game.ini",
                          "data:/../../etc/passwd", "data:/nope.txt"}) {
        auto t = vfs.read_text(p);
        std::print("{:<32} -> ", p);
        if (t) {
            auto rel = fs::relative(*vfs.resolve(p), root).generic_string();
            std::print("{} : {}", rel, *t);
        } else {
            std::println("없음 또는 거절");
        }
    }

    fs::path save = root / "save/slot1.sav";
    fs::create_directories(save.parent_path());
    std::println("저장 {}", save_atomic(save, "level=3\n") ? "성공" : "실패");
    bool left = fs::exists(save.string() + ".tmp");
    std::println("임시 파일이 남았나: {}", left);
    fs::remove_all(root);
}
```

```text
data:/config/game.ini            -> mods/fast/config/game.ini : speed=9
data:/text/hello.txt             -> base/text/hello.txt : 안녕
data:/text/../config/game.ini    -> mods/fast/config/game.ini : speed=9
data:/../../etc/passwd           -> 없음 또는 거절
data:/nope.txt                   -> 없음 또는 거절
저장 성공
임시 파일이 남았나: false
```

- **겹쳐 붙이기**: `data`에 원본 폴더와 모드 폴더를 둘 다 붙였고, 나중에 붙인 모드가 먼저 찾아집니다. `game.ini`는 모드의 것(speed=9)이, 모드에 없는 `hello.txt`는 원본의 것이 나옵니다. 패치, 모드, 지역화 파일을 같은 방법으로 얹습니다
- **바깥으로 나가지 않게**: `lexically_normal()`로 `text/../config`를 `config`로 정리한 뒤, 그래도 `..`로 시작하면 거절합니다. 모드나 네트워크로 받은 경로가 `../../etc/passwd`처럼 게임 폴더 밖을 가리켜 엉뚱한 파일을 읽거나 덮어쓰는 것을 막습니다. 심볼릭 링크까지 막으려면 `weakly_canonical`로 실제 경로를 구해 붙인 폴더 안인지 한 번 더 확인합니다
- **구분자와 대소문자**: 엔진 경로는 언제나 `/`로 씁니다. 윈도는 `\`도 받지만 리눅스는 받지 않습니다. 또 윈도와 macOS의 기본 파일 시스템은 대소문자를 가리지 않고 리눅스는 가립니다. 윈도에서 `Cat.png`로 불러 잘 되던 것이 리눅스 서버나 콘솔에서 안 되는 일이 흔해서, 많은 엔진이 에셋 경로를 **모두 소문자**로 정하고 굽는 단계에서 검사합니다

## 쓰기: 끊기지 않게 저장하기

세이브 파일을 덮어쓰는 도중에 전원이 나가면, 옛 저장도 새 저장도 아닌 반쪽 파일이 남습니다. 그래서 **임시 파일에 다 쓴 다음 이름을 바꿉니다**. 같은 디스크 안에서 이름 바꾸기는 한 번에 일어나서, 보는 쪽에서는 옛 파일 아니면 새 파일만 보입니다. 위 예제의 `save_atomic`이 그것이고, 끝난 뒤 임시 파일이 남지 않았습니다.

<Note kind="warn">
`flush()`는 프로그램의 버퍼를 운영체제에 넘길 뿐, 디스크에 닿았다는 보장이 아닙니다. 정전에도 살아남아야 하는 저장이라면 이름을 바꾸기 전에 POSIX의 `fsync`나 윈도의 `FlushFileBuffers`로 디스크까지 내려보냅니다. 또 "이미 있는 파일을 덮는 이름 바꾸기"가 한 번에 일어나는지는 운영체제와 파일 시스템마다 보장이 다르니, 출시할 플랫폼에서 확인합니다.
</Note>

## 어디에 쓰나

게임이 설치된 폴더는 쓰기 권한이 없는 경우가 많습니다(윈도의 `Program Files`, 콘솔). 세이브와 설정은 운영체제가 정한 **사용자 데이터 폴더**에 씁니다.

| 운영체제 | 흔한 자리 |
| --- | --- |
| 윈도 | `%APPDATA%\회사\게임` |
| macOS | `~/Library/Application Support/게임` |
| 리눅스 | `$XDG_DATA_HOME/게임` (없으면 `~/.local/share/게임`) |

SDL3의 `SDL_GetPrefPath("회사", "게임")`이 이 자리를 운영체제마다 알맞게 돌려줍니다. VFS에는 이것을 `user:/`로 붙여 두면, 게임 코드는 `user:/save/slot1.sav`처럼 어디서나 같은 경로를 씁니다.

## 정리

- 게임 코드는 엔진 경로만 쓰고, VFS가 마운트 목록을 뒤에서부터 찾아 실제 파일로 바꾸며, 모드와 패치는 위에 겹쳐 붙인다
- 경로는 정리한 뒤 바깥으로 나가는 것을 거절하고, 구분자는 `/`로, 대소문자는 소문자로 통일해 플랫폼 차이를 피한다
- 저장은 임시 파일에 다 쓴 뒤 이름을 바꾸고 필요하면 디스크까지 내려보내며, 사용자 데이터 폴더에 쓴다
