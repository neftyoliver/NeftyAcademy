[「층으로 나눈 구조」](#/read/cpp-game-engine/arch-layers)의 맨 위에는 "이 게임만의 코드"가 있습니다. 엔진을 여러 게임에 다시 쓰려면, 그리고 게임 코드를 고칠 때마다 엔진 전체를 다시 빌드하지 않으려면, 둘 사이에 분명한 **경계**를 그어야 합니다. 이 쪽은 그 경계를 어떻게 긋는지 봅니다.

## 무엇을 어디에

| 엔진 | 게임 |
| --- | --- |
| 창, 입력 장치, 파일, 시간 | "점프 키는 스페이스" 같은 입력 배치 |
| 렌더러, 물리, 소리, 애니메이션 | 캐릭터의 움직임 규칙, 적의 행동 |
| 장면, 엔티티, 자원 관리 | 어떤 장면과 프리팹을 언제 불러오나 |
| 에디터, 프로파일러 | 레벨, 대사, 밸런스 수치(대개 데이터) |

판단 기준은 "**다음 게임에서도 쓸 것인가**"입니다. 슬라임의 체력 회복 규칙은 게임에, "일정 시간마다 무언가를 부르는 타이머"는 엔진에 둡니다. 숫자와 내용은 가능하면 코드가 아니라 데이터(에셋 파일)로 두어서, 프로그래머가 아니어도 고칠 수 있게 합니다.

## 경계를 C로 적는다

엔진과 게임을 따로 빌드해 하나는 실행 파일, 하나는 DLL·`.so`로 만드는 엔진이 많습니다. 그 사이로 C++ 클래스를 그대로 주고받으면, 두 쪽을 다른 컴파일러나 다른 설정으로 빌드했을 때 이름 꾸밈과 객체 배치가 어긋날 수 있습니다(「C++ 고급」의 [「C ABI로 내놓기」](#/read/cpp-advanced/iop-c-abi)). 그래서 경계는 **C 구조체와 함수 포인터의 표**로 적는 것이 안전합니다.

```cpp
#include <cstdint>
#include <cstdio>
#include <print>

// ===== 엔진과 게임이 함께 보는 머리 파일(경계) — C로만 적는다 =====
extern "C" {
constexpr std::uint32_t kEngineApiVersion = 3;

struct EngineApi {                       // 엔진이 게임에게 주는 것
    std::uint32_t version;
    std::uint32_t size;                  // 구조체 크기: 뒤에 칸을 더해도 알아본다
    void (*log)(const char* msg);
    float (*time_seconds)();
    std::uint32_t (*spawn)(const char* prefab, float x, float y);
};

struct GameApi {                         // 게임이 엔진에게 주는 것
    std::uint32_t version;
    void* state;                         // 게임이 가진 상태(엔진은 속을 모른다)
    void (*update)(void* state, float dt);
    void (*shutdown)(void* state);
};
}

// ===== 게임 쪽 (보통은 따로 빌드한 DLL·.so) =====
namespace game {
struct State {
    const EngineApi* engine;
    float timer = 0;
    int spawned = 0;
};

void update(void* p, float dt)
{
    auto* s = static_cast<State*>(p);
    s->timer += dt;
    if (s->timer >= 1.0f) {              // 1초마다 적 하나
        s->timer -= 1.0f;
        auto id = s->engine->spawn("slime", 2.0f * s->spawned, 0);
        ++s->spawned;
        char buf[64];
        std::snprintf(buf, sizeof buf, "슬라임 #%u 생성", id);
        s->engine->log(buf);
    }
}

void shutdown(void* p) { delete static_cast<State*>(p); }

// 엔진이 부르는 유일한 입구
bool game_load(const EngineApi* api, GameApi* out)
{
    if (api->version != kEngineApiVersion || api->size < sizeof(EngineApi))
        return false;                    // 다른 판의 엔진과는 붙지 않는다
    *out = {kEngineApiVersion, new State{api}, update, shutdown};
    return true;
}
}  // namespace game

// ===== 엔진 쪽 =====
namespace engine {
float g_time = 0;
std::uint32_t g_next_id = 100;
void log(const char* m) { std::println("[{:4.1f}s] {}", g_time, m); }
float time_seconds() { return g_time; }
std::uint32_t spawn(const char*, float, float) { return g_next_id++; }
}  // namespace engine

int main()
{
    EngineApi api{kEngineApiVersion, sizeof(EngineApi), engine::log,
                  engine::time_seconds, engine::spawn};
    GameApi g{};
    if (!game::game_load(&api, &g))
        return 1;
    for (int frame = 0; frame < 180; ++frame) {      // 60fps로 3초
        engine::g_time += 1.0f / 60;
        g.update(g.state, 1.0f / 60);
    }
    g.shutdown(g.state);

    EngineApi old = api;
    old.version = 2;
    bool ok = game::game_load(&old, &g);
    std::println("판 2 엔진과 붙이기: {}", ok ? "됨" : "거절");
}
```

```text
[ 1.0s] 슬라임 #100 생성
[ 2.0s] 슬라임 #101 생성
판 2 엔진과 붙이기: 거절
```

- **두 개의 표**: 엔진은 `EngineApi`(로그, 시간, 생성)를 게임에게 주고, 게임은 `GameApi`(갱신, 종료)를 돌려줍니다. 게임이 엔진의 다른 부분을 직접 부를 길이 없으니, 경계를 넘는 것은 표에 적힌 것뿐입니다
- **불투명한 상태**: 게임의 상태는 `void*`로 엔진에게 넘어갑니다. 엔진은 그 속을 모르고 그대로 돌려주기만 합니다. 게임이 상태의 구조를 바꿔도 엔진은 다시 빌드할 필요가 없습니다
- **판 번호와 크기**: 판 2 엔진과는 붙기를 거절했습니다. 표에 칸을 더할 때는 **끝에만** 더하고 판 번호를 올리며, `size`를 보고 "이 엔진은 내가 아는 칸을 다 갖고 있나"를 확인합니다. 경계가 어긋난 채로 붙어 엉뚱한 함수 포인터를 부르는 것보다 시작할 때 거절하는 편이 낫습니다
- **입구는 하나**: 게임 쪽에서 엔진이 찾는 이름은 `game_load` 하나뿐입니다. 실제 DLL에서는 이 함수를 `extern "C"`로 내보내고, 엔진은 [「동적 라이브러리와 핫 리로드」](#/read/cpp-game-engine/plat-hot-reload)에서 보는 방법으로 찾아 부릅니다. 그 쪽의 핫 리로드가 바로 이 경계 덕분에 가능해집니다

## 덤으로 찾은 버그

3초 동안 1초마다 슬라임을 만들었는데 **두 마리**만 나왔습니다. 게임 코드가 `float timer`에 1/60을 180번 더했는데, `float`의 반올림 때문에 3초째의 값이 1.0이 아니라 0.9999992에 머물렀기 때문입니다(NumPy의 `float32`로 같은 계산을 해서 확인했습니다). [「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)에서 "같은 시각이 아니라 같은 걸음 수"를 기준으로 하라고 한 까닭이 이것입니다. 게임 규칙의 타이머는 초를 더하지 말고 정수인 **걸음 수**로 세면 이런 일이 없습니다. 경계를 넘는 시간 값도 `float`보다 `double`이나 정수 틱으로 주는 편이 안전합니다.

<Note>
경계를 C로 적는다고 게임 코드까지 C로 쓸 필요는 없습니다. 표의 함수 안에서는 C++를 마음껏 씁니다. 다만 예외가 경계를 넘어가지 않도록 게임 쪽 함수의 가장 바깥에서 잡고, 메모리는 할당한 쪽에서 해제합니다(위 예제의 `shutdown`이 게임이 `new`한 상태를 게임 쪽에서 `delete`합니다). DLL마다 다른 힙을 쓸 수 있는 윈도에서 특히 중요합니다.
</Note>

## 정리

- 다음 게임에서도 쓸 것은 엔진에, 이 게임만의 규칙은 게임에, 숫자와 내용은 데이터에 둔다
- 따로 빌드하는 엔진과 게임 사이는 C 구조체와 함수 포인터의 표로 주고받고, 게임 상태는 불투명한 포인터로 넘긴다
- 표에는 판 번호와 크기를 두어 어긋난 짝을 시작할 때 거절하고, 예외와 메모리 해제가 경계를 넘지 않게 한다
