요즘 CPU는 코어가 8개, 16개씩 있는데, 게임 루프를 한 스레드에서만 돌리면 나머지는 놉니다. 그렇다고 물리 스레드, 애니메이션 스레드, 소리 스레드처럼 기능마다 스레드를 하나씩 주면, 어떤 프레임엔 물리 스레드만 바쁘고 나머지는 놀게 됩니다. 그래서 대부분의 엔진은 코어 수만큼 **워커 스레드**를 만들어 두고, 모든 일을 작은 **작업**으로 쪼개 공용 **큐**에 넣습니다. 놀고 있는 워커가 큐에서 아무 작업이나 꺼내 실행합니다.

## 작은 작업 시스템

```cpp tsan
#include <atomic>
#include <condition_variable>
#include <deque>
#include <functional>
#include <mutex>
#include <print>
#include <thread>
#include <vector>

class JobSystem {
    std::deque<std::function<void()>> queue;
    std::mutex m;
    std::condition_variable cv;
    std::vector<std::jthread> workers;
    bool stopping = false;

    bool try_run_one() {                       // 큐에서 하나 꺼내 실행
        std::function<void()> job;
        {
            std::lock_guard lk(m);
            if (queue.empty()) return false;
            job = std::move(queue.front());
            queue.pop_front();
        }
        job();
        return true;
    }
public:
    explicit JobSystem(unsigned n) {
        for (unsigned i = 0; i < n; ++i)
            workers.emplace_back([this] {
                for (;;) {
                    std::function<void()> job;
                    {
                        std::unique_lock lk(m);
                        cv.wait(lk, [&] { return stopping || !queue.empty(); });
                        if (stopping && queue.empty()) return;
                        job = std::move(queue.front());
                        queue.pop_front();
                    }
                    job();
                }
            });
    }
    ~JobSystem() {
        { std::lock_guard lk(m); stopping = true; }
        cv.notify_all();
    }
    // 작업을 넣고, 끝나면 counter를 하나 줄인다
    void submit(std::atomic<int>& counter, std::function<void()> f) {
        counter.fetch_add(1, std::memory_order_relaxed);
        {
            std::lock_guard lk(m);
            queue.push_back([&counter, f = std::move(f)] {
                f();
                counter.fetch_sub(1, std::memory_order_release);
            });
        }
        cv.notify_one();
    }
    // 기다리는 동안 놀지 않고 남의 작업을 돕는다
    void wait(std::atomic<int>& counter) {
        while (counter.load(std::memory_order_acquire) > 0)
            if (!try_run_one()) std::this_thread::yield();
    }
    // 범위를 덩어리로 나눠 작업으로 만든다
    void parallel_for(int n, int chunk, const std::function<void(int, int)>& body) {
        std::atomic<int> counter{0};
        for (int b = 0; b < n; b += chunk)
            submit(counter, [&body, b, e = std::min(n, b + chunk)] { body(b, e); });
        wait(counter);
    }
};

int main() {
    JobSystem js(4);
    // 1) 입자 100만 개 위치 갱신
    std::vector<float> pos(1'000'000, 0.f), vel(1'000'000, 2.f);
    js.parallel_for(int(pos.size()), 16384, [&](int b, int e) {
        for (int i = b; i < e; ++i) pos[i] += vel[i] * 0.5f;
    });
    double sum = 0;
    for (float p : pos) sum += p;
    std::println("입자 갱신 합계 {:.0f} (기대 1000000)", sum);

    // 2) 작업 안에서 작업을 또 내고 기다리기: 기다리는 쪽이 도와야 막히지 않는다
    std::atomic<int> outer{0}, leaves{0};
    for (int i = 0; i < 8; ++i)
        js.submit(outer, [&] {
            std::atomic<int> inner{0};
            for (int j = 0; j < 100; ++j)
                js.submit(inner, [&] { leaves.fetch_add(1); });
            js.wait(inner);                    // 워커가 기다리면서 큐를 비운다
        });
    js.wait(outer);
    std::println("중첩 작업 {}개 끝 (기대 800)", leaves.load());
}
```

```text
중첩 작업 800개 끝 (기대 800)
```

이 예제는 스레드 검사기(ThreadSanitizer)와 주소 검사기에서 모두 문제없이 돌았습니다.

## 쪼개기와 기다리기

- **parallel_for**는 100만 개짜리 반복을 16384개씩 62개 작업으로 나눴습니다. 덩어리가 너무 작으면 큐에 넣고 꺼내는 비용이 일보다 커지고, 너무 크면 마지막 몇 덩어리를 기다리느라 다른 워커가 놉니다. 워커 수의 몇 배 정도 개수가 되게 나누는 것이 보통입니다
- **완료 카운터**: 작업을 넣을 때 하나 올리고, 끝날 때 하나 내립니다. 0이 되면 그 묶음이 모두 끝난 것입니다. 끝나는 쪽은 `release`, 확인하는 쪽은 `acquire`로 읽어서, 카운터가 0인 것을 보면 작업들이 쓴 결과(`pos`)도 보장되어 보입니다
- 두 번째 실험은 작업 안에서 다시 작업 100개를 내고 기다립니다. 워커 4개가 모두 바깥 작업을 하면서 안쪽 작업을 **그냥 잠들어 기다린다면**, 안쪽 작업을 실행할 워커가 남지 않아 영원히 멈춥니다. `wait`가 기다리는 동안 큐에서 작업을 꺼내 직접 실행하기 때문에 800개가 모두 끝났습니다

## 큐 하나의 한계

예제는 큐 하나를 잠금 하나로 지킵니다. 워커가 많아지고 작업이 작아지면 모든 워커가 같은 잠금을 두고 다툽니다. 그래서 실제 엔진은 워커마다 자기 큐를 두고, 자기 큐가 비면 남의 큐 반대쪽 끝에서 훔쳐 오는 **작업 훔치기** 방식을 씁니다. 자기 큐는 거의 다툼 없이 쓰고, 훔칠 때만 남과 부딪힙니다.

또 "이 작업은 저 작업이 끝난 뒤에" 같은 순서를 카운터와 `wait`만으로 표현하면, 기다리는 지점마다 워커가 묶입니다. 다음 장 [「의존 그래프」](#/read/cpp-game-engine/job-graph)는 순서 자체를 데이터로 적어 두는 방법이고, 그다음 [「파이버」](#/read/cpp-game-engine/job-fibers)는 기다리는 작업을 통째로 잠시 치워 두는 방법입니다.

<Note>
작업 안에서 잠금을 오래 잡거나, 파일 읽기처럼 오래 막히는 일을 하면 워커 하나가 통째로 묶입니다. 입출력은 [「비동기 로딩」](#/read/cpp-game-engine/res-async)처럼 별도 스레드에 맡기고, 작업은 계산만 하게 두는 것이 원칙입니다. 오디오 스레드처럼 제때 돌아야 하는 스레드도 작업 시스템 밖에 둡니다.
</Note>

## 정리

- 코어 수만큼 워커를 두고, 모든 일을 작은 작업으로 쪼개 큐에서 꺼내 실행하게 한다
- 완료 카운터로 작업 묶음의 끝을 확인하며, 기다리는 쪽이 작업을 도와야 중첩 작업에서 멈추지 않는다
- 큐 하나는 다툼이 생기므로 워커별 큐와 작업 훔치기를 쓰고, 작업 안에서는 오래 막히는 일을 하지 않는다
