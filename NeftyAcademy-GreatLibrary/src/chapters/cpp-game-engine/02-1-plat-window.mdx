## 직접 짜지 말고 감싼다

운영체제마다 창을 직접 만드는 코드는 길고 함정이 많습니다(고해상도 화면의 배율, 전체 화면 전환, 키보드 배치, 게임패드). 그래서 대부분의 엔진은 **SDL**이나 **GLFW** 같은 라이브러리로 운영체제를 감싸고, 그 위에 다시 엔진 자신의 얇은 층을 둡니다. 2025년 1월에 나온 SDL3가 지금의 SDL이며, 소리·게임패드·파일 대화 상자까지 함께 다룹니다.

```cpp nocheck
#include <SDL3/SDL.h>

// SDL3의 키를 엔진의 Key로 바꾼다. 물리적인 자리(scancode)를 쓴다
static bool to_engine_key(SDL_Scancode sc, int* out)
{
    switch (sc) {
    case SDL_SCANCODE_W: *out = 0; return true;
    case SDL_SCANCODE_A: *out = 1; return true;
    case SDL_SCANCODE_S: *out = 2; return true;
    case SDL_SCANCODE_D: *out = 3; return true;
    case SDL_SCANCODE_SPACE: *out = 4; return true;
    case SDL_SCANCODE_ESCAPE: *out = 5; return true;
    default: return false;
    }
}

int main()
{
    if (!SDL_Init(SDL_INIT_VIDEO)) {
        SDL_Log("SDL_Init 실패: %s", SDL_GetError());
        return 1;
    }
    SDL_Window* win = SDL_CreateWindow("엔진", 1280, 720, SDL_WINDOW_RESIZABLE);
    bool running = win != nullptr;
    while (running) {
        SDL_Event e;
        while (SDL_PollEvent(&e)) {
            switch (e.type) {
            case SDL_EVENT_QUIT:
                running = false;
                break;
            case SDL_EVENT_KEY_DOWN:
            case SDL_EVENT_KEY_UP: {
                int k;
                if (to_engine_key(e.key.scancode, &k)) {
                    // input.on_event({Key(k), e.key.down, e.key.repeat});
                }
                break;
            }
            case SDL_EVENT_WINDOW_RESIZED:
                // renderer.resize(e.window.data1, e.window.data2);
                break;
            default:
                break;
            }
        }
        // update(); render();
    }
    SDL_DestroyWindow(win);
    SDL_Quit();
}
```

- 이벤트는 **한 프레임에 몇 개든** 올 수 있으므로 `SDL_PollEvent`가 거짓을 줄 때까지 모두 비웁니다. 비우지 않으면 운영체제가 "응답 없음"으로 봅니다
- 키는 **scancode**(자판 위의 물리적인 자리)로 받습니다. 프랑스식 AZERTY 자판에서는 W 자리에 Z가 찍혀 있어서, 글자(`e.key.key`)로 받으면 WASD 이동이 엉뚱한 자리로 갑니다. 반대로 채팅창처럼 글자가 필요한 곳은 텍스트 입력 이벤트를 따로 씁니다
- 창 크기가 바뀌면 렌더러에 알려 그림 그릴 버퍼를 새로 만듭니다

<Note>
이 검사용 컴퓨터(우분투 24.04)에는 SDL3 패키지가 없어서 위 예제는 실행해 보지 못했습니다. SDL 3.2.24 소스의 머리 파일로 문법 검사(`-fsyntax-only`)만 통과시켰고, 이벤트 이름과 구조체 칸은 그 머리 파일에서 확인했습니다.
</Note>

## 엔진의 입력 층

SDL의 이벤트를 그대로 게임 코드까지 보내면, 게임이 SDL에 묶이고 "이번 프레임에 막 눌렸나"를 곳곳에서 따로 계산하게 됩니다. 엔진은 이벤트를 받아 **프레임 단위의 상태**로 정리해 둡니다.

```cpp
#include <array>
#include <print>
#include <string>
#include <unordered_map>
#include <vector>

// 플랫폼 층이 운영체제 이벤트를 이 모양으로 바꿔 넘긴다
enum class Key { W, A, S, D, Space, Escape, Count };
struct KeyEvent {
    Key key;
    bool down;
    bool repeat;       // 꾹 누르고 있을 때 운영체제가 되풀이해 보내는 것
};

class Input {
public:
    void begin_frame()
    {
        prev_ = curr_;                         // 지난 프레임의 상태를 보관
        went_down_ = {};
    }
    void on_event(const KeyEvent& e)
    {
        if (e.repeat)                          // 되풀이는 상태를 바꾸지 않는다
            return;
        curr_[idx(e.key)] = e.down;
        if (e.down)
            went_down_[idx(e.key)] = true;     // 이번 프레임에 한 번이라도 눌림
    }
    bool held(Key k) const { return curr_[idx(k)]; }
    // 상태만 견주는 방법: 한 프레임 안에 눌렀다 떼면 놓친다
    bool pressed_by_state(Key k) const { return curr_[idx(k)] && !prev_[idx(k)]; }
    bool pressed(Key k) const { return went_down_[idx(k)]; }
    bool released(Key k) const { return !curr_[idx(k)] && prev_[idx(k)]; }

    // 게임은 키가 아니라 "행동"을 묻는다
    void bind(const std::string& action, Key k) { binds_[action].push_back(k); }
    bool action_pressed(const std::string& action) const
    {
        for (Key k : binds_.at(action))
            if (pressed(k)) return true;
        return false;
    }

private:
    static int idx(Key k) { return static_cast<int>(k); }
    std::array<bool, static_cast<int>(Key::Count)> curr_{}, prev_{}, went_down_{};
    std::unordered_map<std::string, std::vector<Key>> binds_;
};

int main()
{
    Input in;
    in.bind("jump", Key::Space);
    in.bind("jump", Key::W);

    // 프레임마다 들어온 이벤트(실제로는 SDL_PollEvent 등에서)
    const std::vector<std::vector<KeyEvent>> frames = {
        {{Key::Space, true, false}},                 // 1: 눌렀다
        {{Key::Space, true, true}},                  // 2: 꾹(되풀이)
        {},                                          // 3: 계속 누르고 있음
        {{Key::Space, false, false}},                // 4: 뗐다
        {{Key::W, true, false}, {Key::W, false, false}},  // 5: 한 프레임 안에 톡
    };
    for (std::size_t f = 0; f < frames.size(); ++f) {
        in.begin_frame();
        for (const auto& e : frames[f])
            in.on_event(e);
        std::println("{}: Space 누름 {:d} 꾹 {:d} 뗌 {:d} | W 상태 비교 {:d} "
                     "| jump {:d}", f + 1, in.pressed(Key::Space),
                     in.held(Key::Space), in.released(Key::Space),
                     in.pressed_by_state(Key::W), in.action_pressed("jump"));
    }
}
```

```text
1: Space 누름 1 꾹 1 뗌 0 | W 상태 비교 0 | jump 1
2: Space 누름 0 꾹 1 뗌 0 | W 상태 비교 0 | jump 0
3: Space 누름 0 꾹 1 뗌 0 | W 상태 비교 0 | jump 0
4: Space 누름 0 꾹 0 뗌 1 | W 상태 비교 0 | jump 0
5: Space 누름 0 꾹 0 뗌 0 | W 상태 비교 0 | jump 1
```

- **누름·꾹·뗌**: 점프처럼 "막 눌렀을 때 한 번"인 행동은 `pressed`, 달리기처럼 "누르고 있는 동안"은 `held`를 씁니다. 2프레임의 되풀이 이벤트는 무시해서, 키를 꾹 누르고 있어도 점프가 계속 일어나지 않습니다
- **한 프레임 안의 톡**: 5프레임에서 W를 눌렀다 떼는 일이 한 프레임 안에 일어났습니다. 프레임 끝의 상태만 지난 프레임과 견주면(`W 상태 비교`) 처음과 끝이 모두 "안 눌림"이라 **놓칩니다**. 30fps처럼 느린 프레임에서 짧게 톡 친 입력이 무시되는 흔한 버그입니다. 그래서 이벤트가 올 때 "이번 프레임에 한 번이라도 눌렸다"를 따로 표시해 두었고, `jump`가 제대로 잡혔습니다
- **행동 배치**: 게임은 `Space`가 아니라 `"jump"`를 묻습니다. 키 바꾸기 설정, 게임패드, 터치를 같은 행동에 묶을 수 있습니다. 실제 엔진에서는 문자열 대신 미리 정한 번호나 해시를 써서 조회 비용을 줄입니다

## 입력은 언제 읽나

[「게임 루프와 고정 시간 간격」](#/read/cpp-game-engine/arch-loop)에서 물리가 한 프레임에 0걸음, 1걸음, 2걸음을 걸 수 있었습니다. "막 눌렀다"를 걸음마다 확인하면, 0걸음인 프레임의 입력은 사라지고 2걸음인 프레임에서는 두 번 점프할 수 있습니다. 흔한 해결은 입력을 프레임마다 모았다가 **다음 고정 걸음에서 한 번만 쓰고 지우는** 것입니다. 네트워크 게임에서는 입력을 걸음 번호와 함께 저장해 보냅니다([「예측과 보정」](#/read/cpp-game-engine/net-prediction)).

## 정리

- 창과 입력은 SDL3·GLFW 같은 라이브러리로 운영체제를 감싸고, 그 위에 엔진의 얇은 입력 층을 둔다
- 이벤트는 매 프레임 모두 비우고, 이동 키는 물리적 자리(scancode)로 받으며, 되풀이 이벤트는 상태를 바꾸지 않는다
- 누름·꾹·뗌을 프레임 단위로 정리하되 한 프레임 안의 톡을 놓치지 않게 이벤트로 표시하고, 게임에는 키 대신 행동을 묻게 한다
