컴파일러가 만든 실행 파일은 기계어만 줄줄이 담은 덩어리가 아닙니다. OS가 그것을 메모리에 어떻게 올리고 어디서부터 실행할지, 어떤 라이브러리가 필요한지를 적은 **정해진 형식**의 파일입니다. 리눅스와 대부분의 유닉스 계열, 라즈베리파이, 안드로이드가 쓰는 형식이 ELF(Executable and Linkable Format)입니다. 이 쪽은 `readelf`, `nm`, `size`로 ELF 파일을 열어 봅니다. 윈도우의 [「PE」](#/read/c-mid/exe-pe)와 맥의 [「Mach-O」](#/read/c-mid/exe-macho)는 다음 쪽들에서 견줍니다.

## 맨 앞 16바이트

[「Makefile」](#/read/c-mid/build-make)에서 만든 `app`의 첫 16바이트를 16진수로 봅니다.

```text nocheck
$ xxd -l 16 app
00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000  .ELF............
```

첫 네 바이트 `7f 45 4c 46`은 `0x7F`와 글자 `E`, `L`, `F`입니다([ASCII](#/read/basics/std-text)). 이 "마법의 수"로 OS와 `file` 명령이 ELF 파일임을 알아봅니다. 다음 `02`는 64비트, `01`은 [리틀 엔디언](#/read/basics/math-integers)입니다. `readelf -h`가 헤더 전체를 풀어 줍니다.

```text nocheck
$ readelf -h app
  Class:                             ELF64
  Data:                              2's complement, little endian
  Type:                              DYN (Position-Independent Executable file)
  Machine:                           Advanced Micro Devices X86-64
  Entry point address:               0x10d0
```

`Machine`이 CPU 종류입니다. [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)로 만든 라즈베리파이용 파일은 여기가 `AArch64`입니다. `Entry point`는 OS가 실행을 시작할 주소인데, 이것은 `main`이 아니라 C 라이브러리의 `_start`입니다. `_start`가 준비를 마치고 `main`을 부릅니다.

## 구역

ELF 파일 안은 쓰임별 **구역**(section)으로 나뉩니다. 전역 변수 몇 개를 둔 프로그램으로 어느 것이 어디에 들어가는지 봅니다.

```c
#include <stdio.h>

int counter = 5;               // 값이 있는 전역 변수
int zeros[1000];               // 0으로 시작하는 전역 배열
const char greeting[] = "hi";  // 바뀌지 않는 값

int main(void)
{
    printf("%s %d %d\n", greeting, counter, zeros[0]);
    return 0;
}
```

```text
hi 5 0
```

`nm`은 파일 안의 심볼과 그것이 든 구역을 글자 하나로 보여 줍니다.

```text nocheck
$ nm v | grep -E " (counter|zeros|greeting|main)$"
0000000000004010 D counter
000000000000200e R greeting
0000000000001060 T main
0000000000004040 B zeros
```

| 구역 | `nm` 글자 | 담는 것 | 메모리에서 |
| --- | --- | --- | --- |
| `.text` | T | 기계어 명령 | 읽기, 실행 |
| `.rodata` | R | `const` 값, 문자열 상수 | 읽기만 |
| `.data` | D | 처음 값이 있는 전역·정적 변수 | 읽기, 쓰기 |
| `.bss` | B | 0으로 시작하는 전역·정적 변수 | 읽기, 쓰기 |

`.bss`에는 재미있는 점이 있습니다. `zeros`는 4,000바이트지만 파일에는 그 자리가 없습니다. 어차피 전부 0이니 "이만큼 0으로 채워 달라"는 크기만 적어 두고, OS가 프로그램을 올릴 때 0으로 채운 메모리를 줍니다.

```text nocheck
$ size v
   text    data     bss     dec     hex filename
   1437     604    4032    6073    17b9 v
```

파일 크기는 16,064바이트입니다. 배열을 `int zeros[1000] = {1};`처럼 0이 아닌 값으로 시작하게 바꾸면 배열이 `.data`로 옮겨 가서(`data` 4,620바이트) 파일이 20,088바이트로 4,024바이트 커집니다. 구역 이름과 크기는 `readelf -S`로 모두 볼 수 있고, 심볼이 무엇인지는 「컴퓨터 프로그래밍 초급」의 [「심볼이란」](#/read/c-basic/symbols)에서 봤습니다.

## 세그먼트: OS가 보는 모습

구역은 링커가 쓰는 단위이고, OS가 메모리에 올릴 때는 권한이 같은 구역들을 묶은 **세그먼트**를 봅니다.

```text nocheck
$ readelf -l -W app | grep -E "LOAD|INTERP"
  INTERP   … R
  LOAD     … R
  LOAD     … R E
  LOAD     … R
  LOAD     … RW
```

`R`은 읽기, `W`는 쓰기, `E`는 실행입니다. 기계어가 든 세그먼트는 읽기와 실행만 되고 쓰기는 안 되며, 변수가 든 세그먼트는 읽고 쓸 수는 있지만 실행은 안 됩니다. 쓸 수 있는 곳과 실행할 수 있는 곳을 나눠 두면, 공격자가 변수에 기계어를 써 넣어도 실행되지 않습니다. 이 방어는 [「메모리를 숨기고 보호하기」](#/read/c-mid/sec-memory)에서 이어집니다.

## 필요한 라이브러리

`printf`는 `app` 안에 없습니다. 실행할 때 C 라이브러리에서 빌려 옵니다.

```text nocheck
$ readelf -d app | grep NEEDED
 0x0000000000000001 (NEEDED)             Shared library: [libc.so.6]
$ nm app | grep " U "
                 U __libc_start_main@GLIBC_2.34
                 U __printf_chk@GLIBC_2.3.4
```

`NEEDED`는 이 프로그램이 필요로 하는 동적 라이브러리, `nm`의 `U`는 파일 안에 정의가 없어 밖에서 찾아야 하는 심볼입니다. `printf`가 `__printf_chk`로 바뀐 것은 `-O2`에서 우분투의 GCC가 켜 두는 안전 검사(`_FORTIFY_SOURCE`) 때문입니다. `INTERP` 세그먼트에는 이 빌려 오기를 맡을 프로그램(동적 링커 `/lib64/ld-linux-x86-64.so.2`)의 경로가 적혀 있습니다. 이 과정은 [「동적 라이브러리」](#/read/c-mid/lib-dynamic)에서 자세히 봅니다.

<Note kind="tip">
목적 파일(`.o`), 정적 라이브러리 속의 파일, 동적 라이브러리(`.so`), 코어 덤프도 모두 ELF입니다. `readelf -h`의 `Type`이 `REL`(목적 파일), `DYN`(PIE 실행 파일이나 공유 라이브러리), `EXEC`(옛 방식의 실행 파일), `CORE`(코어 덤프)로 구분해 줍니다. 처음 보는 바이너리를 만나면 `file`과 `readelf -h`부터 쳐 보세요.
</Note>

## 정리

- ELF는 `7F 45 4C 46`으로 시작하는 리눅스의 실행 파일 형식이고, 헤더에 CPU 종류, 비트 수, 시작 주소가 적혀 있다
- 안은 `.text`(코드), `.rodata`(상수), `.data`(값 있는 변수), `.bss`(0으로 시작하는 변수) 같은 구역으로 나뉘며, `.bss`는 파일에서 자리를 차지하지 않는다
- OS는 권한이 같은 구역을 묶은 세그먼트를 올리고, `NEEDED`에 적힌 동적 라이브러리에서 정의가 없는 심볼을 빌려 온다
