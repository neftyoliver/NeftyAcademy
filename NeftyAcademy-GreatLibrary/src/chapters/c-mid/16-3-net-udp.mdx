**UDP**는 TCP와 같은 층에 있지만 약속이 거의 없습니다. 연결을 맺지 않고, 받았는지 확인하지 않고, 잃어버려도 다시 보내지 않습니다. 대신 보낸 덩어리(**데이터그램**)가 그 모양 그대로 도착하거나, 아예 오지 않습니다. [「TCP」](#/read/c-mid/net-tcp)와 견주며 봅니다.

## TCP와 UDP

| | TCP | UDP |
| --- | --- | --- |
| 연결 | 먼저 인사한다 | 없음, 바로 보낸다 |
| 도착 보장 | 다시 보내서 보장 | 없음 |
| 순서 | 맞춰 준다 | 바뀔 수 있다 |
| 경계 | 없는 바이트 흐름 | 데이터그램 하나가 한 덩어리 |

UDP를 쓰는 곳은 늦게 온 데이터가 쓸모없거나, 짧은 질문 하나에 답 하나면 되는 경우입니다. 이름을 주소로 바꾸는 DNS 질의, 시계를 맞추는 NTP, 영상 통화와 온라인 게임, 센서가 몇 초마다 값을 보내는 경우가 그렇습니다. 요즘 웹의 HTTP/3도 UDP 위의 QUIC이라는 규약에서 재전송과 암호화를 스스로 합니다.

## 덩어리째 오고, 넘치면 잘린다

```c flags=-D_DEFAULT_SOURCE
#include <arpa/inet.h>
#include <netinet/in.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

int main(void)
{
    int rx = socket(AF_INET, SOCK_DGRAM, 0);
    struct sockaddr_in a = {.sin_family = AF_INET,
                            .sin_addr.s_addr = htonl(INADDR_LOOPBACK)};
    socklen_t alen = sizeof a;
    bind(rx, (struct sockaddr *)&a, sizeof a);          // 빈 포트 받기
    getsockname(rx, (struct sockaddr *)&a, &alen);

    int tx = socket(AF_INET, SOCK_DGRAM, 0);            // 연결 없이 바로
    const char *msgs[] = {"temp=23.5", "hum=41", "battery=87%"};
    for (int i = 0; i < 3; i++)
        sendto(tx, msgs[i], strlen(msgs[i]), 0,
               (struct sockaddr *)&a, sizeof a);

    for (int i = 0; i < 3; i++) {
        char buf[8];                                    // 일부러 작게
        struct sockaddr_in from;
        socklen_t flen = sizeof from;
        // MSG_TRUNC: 버퍼가 작아도 원래 길이를 알려 달라(리눅스)
        ssize_t n = recvfrom(rx, buf, sizeof buf, MSG_TRUNC,
                             (struct sockaddr *)&from, &flen);
        size_t got = (size_t)n < sizeof buf ? (size_t)n : sizeof buf;
        printf("%d번: 원래 %zd바이트, 받은 것 \"%.*s\"%s\n", i + 1, n,
               (int)got, buf, (size_t)n > sizeof buf ? " (잘림)" : "");
        printf("  보낸 곳 %s\n", inet_ntoa(from.sin_addr));
    }
    close(tx);
    close(rx);
    return 0;
}
```

```text
1번: 원래 9바이트, 받은 것 "temp=23." (잘림)
  보낸 곳 127.0.0.1
2번: 원래 6바이트, 받은 것 "hum=41"
  보낸 곳 127.0.0.1
3번: 원래 11바이트, 받은 것 "battery=" (잘림)
  보낸 곳 127.0.0.1
```

- 받는 쪽은 `bind`만 하고, 보내는 쪽은 `connect` 없이 `sendto`에 주소를 붙여 바로 보냅니다. `listen`도 `accept`도 없습니다
- 세 번 보낸 것이 **세 번에 나뉘어** 왔습니다. TCP에서는 9바이트가 한꺼번에 왔던 것과 다릅니다. 경계를 직접 만들 필요가 없습니다
- 대신 버퍼가 데이터그램보다 작으면 **남는 부분은 버려집니다**. 다음 `recvfrom`이 나머지를 주지 않고 다음 데이터그램을 줍니다. 리눅스에서는 `MSG_TRUNC`를 주면 원래 길이를 알려 주므로, 잘렸는지 알 수 있습니다. 받을 버퍼는 넉넉하게 잡습니다
- `recvfrom`은 누가 보냈는지도 알려 줍니다. 서버는 이 주소로 `sendto`해서 답합니다. 연결이 없으니 데이터그램마다 보낸 사람이 다를 수 있습니다

<Note>
루프백에서는 잃어버리는 일이 거의 없어서 세 개가 다 왔지만, 실제 네트워크에서는 데이터그램이 사라지거나 순서가 바뀌거나 드물게 두 번 올 수도 있습니다. 받는 쪽 버퍼가 꽉 찼을 때도 커널이 조용히 버립니다. 중요하면 데이터에 일련번호를 넣고, 응답이 없으면 다시 묻는 일을 프로그램이 직접 합니다.
</Note>

## 크기의 한계

데이터그램 하나는 이론상 64KB 가까이 될 수 있지만, [「이더넷 프로토콜」](#/read/c-mid/net-ethernet)의 MTU(보통 1500바이트)보다 크면 IP 층에서 조각으로 나뉘고, 조각 하나만 잃어도 전체가 버려집니다. 그래서 UDP로 보내는 데이터는 대개 수백~1200바이트 정도로 작게 유지합니다. QUIC도 처음에는 약 1200바이트로 시작합니다.

## 한 번에 여럿에게

UDP는 연결이 없어서 **방송**(broadcast, 같은 랜 전체)과 **멀티캐스트**(구독한 무리)에 쓸 수 있습니다. 같은 랜의 프린터나 스마트 기기를 찾는 mDNS(`.local` 이름)가 멀티캐스트 UDP입니다. 방송을 보내려면 소켓에 `SO_BROADCAST` 옵션을 켜야 합니다. TCP로는 할 수 없는 일입니다.

## 정리

- UDP는 연결·확인·재전송 없이 데이터그램을 보내며, 하나하나가 경계가 지켜진 덩어리로 오거나 아예 오지 않는다
- `sendto`·`recvfrom`으로 주고받고, 버퍼가 작으면 남는 부분이 버려지므로 넉넉히 잡고 `MSG_TRUNC`로 잘림을 확인한다
- 늦으면 쓸모없는 데이터, 짧은 질의응답, 방송·멀티캐스트에 쓰고, 신뢰성이 필요하면 일련번호와 재요청을 직접 만든다
