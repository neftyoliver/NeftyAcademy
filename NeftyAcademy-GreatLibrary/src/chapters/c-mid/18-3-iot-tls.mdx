[「HTTP」](#/read/c-mid/http)와 [「MQTT」](#/read/c-mid/iot-mqtt)는 그대로 쓰면 글자가 선 위를 알몸으로 지나갑니다. 같은 Wi-Fi에 있는 누구나 엿보고, 중간에서 바꿔치기할 수 있습니다. **TLS**는 TCP와 응용 사이에 끼어 이것을 막습니다. HTTPS, MQTTS(8883번), 메일의 암호화가 모두 TLS입니다.

## TLS가 지키는 세 가지

| 약속 | 막는 것 | 방법 |
| --- | --- | --- |
| 비밀(기밀성) | 엿보기 | 인사 때 함께 만든 키로 암호화 |
| 무결성 | 중간에서 바꾸기 | 암호화와 함께 붙는 검사값(AEAD) |
| 상대 확인(인증) | 가짜 서버 | 서버 인증서와 CA의 서명 |

세 번째가 가장 자주 무너집니다. 암호화가 아무리 강해도 **가짜 서버와** 암호화해서 이야기하면 소용없기 때문입니다.

## 인증서와 CA 사슬

서버는 인사(handshake) 때 **인증서**를 보냅니다. 인증서에는 "이 공개키의 주인은 `localhost`"라는 내용과, 그것을 보증하는 **CA**(인증 기관)의 서명이 들어 있습니다. 클라이언트는 그 CA를 믿는지(운영체제나 프로그램에 들어 있는 믿는 CA 목록에 있는지), 서명이 맞는지, 기한이 지나지 않았는지, **인증서의 이름이 내가 접속하려던 이름과 같은지**를 봅니다. 실제로는 서버 인증서 → 중간 CA → 뿌리 CA처럼 사슬로 이어집니다.

시험용으로 직접 CA를 하나 만들고, 그 CA로 `localhost` 인증서에 서명했습니다.

```text nocheck
$ openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes \
      -keyout ca.key -out ca.crt -days 30 -subj "/CN=Minerva Test CA"
$ openssl req -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes \
      -keyout srv.key -out srv.csr -subj "/CN=localhost"
$ printf "subjectAltName=DNS:localhost\n" > ext
$ openssl x509 -req -in srv.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
      -out srv.crt -days 30 -extfile ext
$ openssl verify -CAfile ca.crt srv.crt
srv.crt: OK
```

이름은 `subjectAltName`(SAN)에 적습니다. 요즘 클라이언트는 옛 방식의 CN 칸이 아니라 이것을 봅니다.

## OpenSSL로 클라이언트 만들기

```c nocheck
#include <stdio.h>
#include <string.h>
#include <openssl/err.h>
#include <openssl/ssl.h>

int main(int argc, char **argv)
{
    const char *host = argc > 1 ? argv[1] : "localhost";
    const char *ca = argc > 2 ? argv[2] : nullptr;

    SSL_CTX *ctx = SSL_CTX_new(TLS_client_method());
    SSL_CTX_set_min_proto_version(ctx, TLS1_2_VERSION);
    SSL_CTX_set_verify(ctx, SSL_VERIFY_PEER, nullptr);   // 인증서 검사 켜기
    if (ca)
        SSL_CTX_load_verify_locations(ctx, ca, nullptr); // 믿을 CA 파일
    else
        SSL_CTX_set_default_verify_paths(ctx);           // 시스템 CA 목록

    BIO *bio = BIO_new_ssl_connect(ctx);
    SSL *ssl;
    BIO_get_ssl(bio, &ssl);
    BIO_set_conn_hostname(bio, "localhost:8443");
    SSL_set_tlsext_host_name(ssl, host);   // SNI: 어느 이름에 왔는지
    SSL_set1_host(ssl, host);              // 인증서 이름이 맞는지 볼 것

    if (BIO_do_connect(bio) <= 0) {
        printf("연결 실패: %s\n",
               ERR_reason_error_string(ERR_peek_last_error()));
        printf("검사 결과: %s\n",
               X509_verify_cert_error_string(SSL_get_verify_result(ssl)));
        BIO_free_all(bio);
        SSL_CTX_free(ctx);
        return 1;
    }
    printf("규약 %s, 암호 묶음 %s\n", SSL_get_version(ssl),
           SSL_get_cipher_name(ssl));
    X509 *cert = SSL_get1_peer_certificate(ssl);
    char name[256];
    X509_NAME_oneline(X509_get_subject_name(cert), name, sizeof name);
    printf("서버 인증서 %s\n", name);
    X509_free(cert);

    const char *req = "hello\n";
    BIO_write(bio, req, (int)strlen(req));
    char buf[64];
    int n = BIO_read(bio, buf, sizeof buf - 1);
    buf[n > 0 ? n : 0] = '\0';
    printf("암호화된 길로 받은 것: %s", buf);
    BIO_free_all(bio);
    SSL_CTX_free(ctx);
    return 0;
}
```

서버는 `openssl s_server -accept 8443 -cert srv.crt -key srv.key`로 띄우고, 세 가지로 접속해 보았습니다(`-lssl -lcrypto`로 링크, OpenSSL 3.0.13).

```text nocheck
$ ./cl localhost ca.crt        ← 우리 CA를 믿고, 이름도 맞음
규약 TLSv1.3, 암호 묶음 TLS_AES_256_GCM_SHA384
서버 인증서 /CN=localhost
암호화된 길로 받은 것: meow

$ ./cl localhost               ← 시스템 CA 목록만 믿음
연결 실패: certificate verify failed
검사 결과: unable to get local issuer certificate

$ ./cl example.com ca.crt      ← CA는 믿지만 이름이 다름
연결 실패: certificate verify failed
검사 결과: hostname mismatch
```

- 첫째는 성공해서 TLS 1.3으로 암호화된 길이 열렸습니다. 서버가 보낸 "meow"가 그 길로 왔습니다
- 둘째는 시스템에 우리 시험용 CA가 없어서 거부됐습니다. 진짜 서비스라면 공인 CA의 인증서를 쓰므로 시스템 목록으로 통과합니다
- 셋째가 중요합니다. 인증서는 진짜이고 믿는 CA가 서명했지만, **다른 이름**의 인증서라 거부됐습니다. `SSL_set1_host`를 빠뜨리면 이 검사가 일어나지 않아서, 공격자가 자기 도메인용으로 정당하게 받은 인증서로 아무 서버나 흉내 낼 수 있습니다. C로 TLS를 쓸 때 가장 흔한 보안 실수입니다
- 이 프로그램을 ASan으로 돌려 세 경우 모두 새는 메모리가 없게 했습니다. 처음에는 실패한 경로에서 `BIO`와 `SSL_CTX`를 풀지 않아 LeakSanitizer가 알렸습니다

<Note kind="warn">
"일단 되게 하려고" `SSL_VERIFY_NONE`으로 검사를 끄는 코드가 인터넷 예제에 흔합니다. 그러면 암호화는 되지만 상대 확인이 사라져, 중간자 공격 앞에서는 암호화하지 않은 것과 다를 바 없습니다. 시험할 때는 위처럼 시험용 CA를 믿게 하고, 검사는 끄지 않습니다.
</Note>

## 고를 라이브러리와 판

- **OpenSSL**: 리눅스 서버의 표준. 판마다 지원 기간이 정해져 있어서, 이 컴퓨터의 3.0 줄은 2026년 9월 7일에 OpenSSL 프로젝트의 지원이 끝났고(배포판은 자체적으로 계속 고침), 다음 장기 지원 판은 3.5(2030년 4월까지)입니다. 4.0은 2026년 4월에 나왔습니다
- **mbedTLS, wolfSSL**: 메모리가 적은 마이크로컨트롤러용. ESP32 같은 칩의 SDK에 들어 있습니다
- 규약은 **TLS 1.3**(2018년)과 1.2만 씁니다. 1.0과 1.1은 낡아서 막혀 있고, 위 예제도 `SSL_CTX_set_min_proto_version`으로 1.2 미만을 거절합니다

기기에서는 시계도 챙겨야 합니다. 인증서 기한을 확인하려면 현재 시각이 필요한데, 전원을 켠 직후의 작은 기기는 시계가 1970년일 수 있어서 NTP로 시각부터 맞춥니다.

## 정리

- TLS는 비밀, 무결성, 상대 확인을 지키며, 상대 확인은 인증서와 믿는 CA의 서명 사슬로 한다
- 클라이언트는 인증서 검사를 켜고(`SSL_VERIFY_PEER`), 접속하려던 이름과 인증서의 이름이 같은지(`SSL_set1_host`)까지 확인해야 한다
- 시험할 때는 검사를 끄지 말고 시험용 CA를 믿게 하며, 라이브러리의 지원 기간과 TLS 1.2 이상만 쓰는지 챙긴다
