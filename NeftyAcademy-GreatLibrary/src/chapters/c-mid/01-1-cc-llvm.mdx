## LLVM과 Clang

LLVM은 컴파일러를 만드는 부품 모음이고, Clang은 그 위에 얹은 C·C++·Objective-C용 앞단입니다.

| 부분 | 하는 일 |
| --- | --- |
| Clang (앞단) | C 소스를 읽어 문법을 검사하고 LLVM IR로 바꾼다 |
| LLVM (가운데와 뒷단) | IR을 최적화하고, 목표 CPU의 기계어로 바꾼다 |
| lld | LLVM의 링커 |
| lldb, clang-format, clang-tidy | 디버거, 코드 정리기, 정적 분석기 |

가운데에 **LLVM IR**이라는 공통 중간 언어가 있다는 것이 핵심입니다. C든 러스트든 스위프트든 앞단이 IR만 만들면, 최적화와 x86-64·ARM64용 기계어 생성은 LLVM이 한꺼번에 해 줍니다. 러스트 컴파일러와 애플의 스위프트도 LLVM을 씁니다.

## 단계를 하나씩 꺼내기

아래 파일을 단계마다 멈추며 컴파일해 봅니다.

```c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))

static int area(int w, int h)
{
    return w * h;
}

int main(void)
{
    printf("%d %d\n", SQUARE(7), area(3, 4));
    return 0;
}
```

```text
49 12
```

```sh
clang -E sq.c -o sq.i              # 전처리만
clang -S -emit-llvm sq.c -o sq.ll  # LLVM IR까지
clang -S sq.c -o sq.s              # 어셈블리까지
clang -c sq.c -o sq.o              # 목적 파일까지
clang sq.o -o sq                   # 링크
```

| 파일 | 크기(바이트) | 내용 |
| --- | --- | --- |
| `sq.c` | 183 | 소스 |
| `sq.i` | 21,587 | `#include`와 매크로를 펼친 C. 840줄 |
| `sq.ll` | 1,700 | LLVM IR(글) |
| `sq.s` | 1,436 | x86-64 어셈블리(글) |
| `sq.o` | 1,384 | 기계어. 아직 `printf`의 주소를 모른다 |
| `sq` | 16,040 | 실행 파일 |

`sq.i`의 끝을 보면 매크로가 펼쳐져 있습니다.

```c nocheck
int main(void)
{
    printf("%d %d\n", ((7) * (7)), area(3, 4));
    return 0;
}
```

183바이트 소스가 2만 바이트가 된 것은 `stdio.h`가 끌어온 선언들 때문입니다. 헤더가 하는 일은 [「헤더를 포함한 C 파일」](#/read/c-basic/headers)에서 봤습니다.

## LLVM IR 읽어 보기

`area` 함수를 최적화 없이 IR로 바꾸면 이렇습니다(`-fno-discard-value-names`로 변수 이름을 남겼습니다).

```text nocheck
define internal i32 @area(i32 noundef %w, i32 noundef %h) #0 {
entry:
  %w.addr = alloca i32, align 4
  %h.addr = alloca i32, align 4
  store i32 %w, ptr %w.addr, align 4
  store i32 %h, ptr %h.addr, align 4
  %0 = load i32, ptr %w.addr, align 4
  %1 = load i32, ptr %h.addr, align 4
  %mul = mul nsw i32 %0, %1
  ret i32 %mul
}
```

IR은 어셈블리와 비슷하지만 특정 CPU에 묶이지 않습니다. 레지스터 개수에 제한이 없고(`%0`, `%1`…), 타입(`i32`는 32비트 정수)이 붙어 있습니다. `-O0`라서 인자를 굳이 스택(`alloca`)에 저장했다가 다시 읽습니다. `nsw`는 "부호 있는 넘침이 없다고 가정해도 된다"는 표시로, [C에서 부호 있는 정수의 넘침이 정의되지 않은 동작](#/read/basics/math-integers)이라는 규칙이 IR에 그대로 실린 것입니다.

같은 파일을 `-O1`로 바꾸면 `main`이 이렇게 줄어듭니다.

```text nocheck
define dso_local noundef i32 @main() local_unnamed_addr #0 {
entry:
  %call1 = tail call i32 (ptr, ...) @printf(ptr noundef nonnull
                     dereferenceable(1) @.str, i32 noundef 49, i32 noundef 12)
  ret i32 0
}
```

(긴 줄은 접어 옮겼습니다.)

`area` 함수가 사라지고 `49`와 `12`가 상수로 박혔습니다. 컴파일할 때 이미 답을 계산해 둔 것입니다.

## 드라이버가 실제로 부르는 것

`clang` 명령은 사실 **드라이버**입니다. 스스로 컴파일하는 것이 아니라 단계에 맞는 도구를 차례로 부릅니다. `-###`을 붙이면 실행하지 않고 부를 명령만 보여 줍니다.

```sh
clang -### sq.c -o sq
```

출력은 긴 두 줄입니다. 첫 줄은 `clang -cc1 …`(진짜 컴파일러)이고, 둘째 줄은 `/usr/bin/ld …`(링커)입니다. 우분투의 Clang은 링크에 **GNU의 링커** `ld`를 씁니다. LLVM의 링커를 쓰려면 `-fuse-ld=lld`를 붙입니다. 그렇게 만든 실행 파일의 `.comment` 구역에는 `Linker: Ubuntu LLD 18.1.3`이 적힙니다.

## 다른 CPU용으로 컴파일하기

Clang은 **한 벌로 여러 CPU용 코드를 만들 수 있습니다.** 우분투의 `clang -print-targets`는 44가지 목표를 보여 줍니다. 목표는 `--target`에 "CPU-제조사-OS-환경" 꼴의 이름(트리플)으로 줍니다.

```sh
clang --target=aarch64-linux-gnu -c sq.c -o sq-arm.o
file sq-arm.o
```

```text nocheck
sq-arm.o: ELF 64-bit LSB relocatable, ARM aarch64, version 1 (SYSV), not stripped
```

라즈베리파이용 목적 파일이 나왔습니다. GCC는 목표 CPU마다 컴파일러를 따로 깔아야 하는데(`aarch64-linux-gnu-gcc`), Clang은 같은 실행 파일로 됩니다. 다만 **링크**까지 하려면 그 CPU용 C 라이브러리와 헤더가 있어야 합니다. 그 준비는 [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)에서 합니다.

## 경고, 새니타이저, 도구

```c nocheck
int count;
unsigned int size = 10;
int index = -1;
if (index < size)            // -1이 큰 양수로 바뀌어 비교된다
    printf("작다\n");
printf("%d\n", count);       // 값을 넣은 적 없는 변수
```

이 코드를 그냥 컴파일하면 Clang은 아무 말도 하지 않습니다. `-Wall -Wextra`를 붙여야 두 줄 모두 경고합니다(`-Wsign-compare`, `-Wuninitialized`). 경고는 늘 켜 두는 것이 좋습니다.

| 옵션 | 하는 일 |
| --- | --- |
| `-Wall -Wextra` | 흔한 실수를 경고한다. 늘 켠다 |
| `-Werror` | 경고를 오류로 바꿔 빌드를 멈춘다 |
| `-fsanitize=address` | 배열 밖 쓰기, 해제한 메모리 쓰기를 실행 중에 잡는다 |
| `-fsanitize=undefined` | 부호 있는 넘침 같은 정의되지 않은 동작을 잡는다 |

<Note kind="warn">
우분투에서 `clang -fsanitize=address`가 `cannot find …libclang_rt.asan…`이라며 링크에 실패하면, 새니타이저의 실행 부품이 든 `libclang-rt-18-dev` 패키지가 없는 것입니다. `sudo apt install libclang-rt-18-dev`로 깔면 됩니다. 이 책의 검사 기계에서도 처음에는 이 오류가 났습니다.
</Note>

`clang-format`은 코드의 띄어쓰기와 줄바꿈을 정해진 모양으로 고쳐 주고, `clang-tidy`는 컴파일러보다 깊이 코드를 살펴 위험한 습관을 알려 줍니다. 길이를 확인하지 않는 `strcpy(buf, name)`에 `clang-tidy`의 `clang-analyzer-*` 검사를 돌리면 "길이 제한이 없는 복사 함수는 안전하지 않다"는 경고가 나옵니다.

## 정리

- Clang은 C를 LLVM IR로 바꾸는 앞단이고, 최적화와 기계어 생성은 LLVM이 맡으며, `clang` 명령은 이 단계와 링커를 차례로 부르는 드라이버다
- `-E`, `-S -emit-llvm`, `-S`, `-c`로 단계마다 멈출 수 있고, 최적화를 켜면 컴파일할 때 계산할 수 있는 것은 상수가 된다
- `--target`으로 같은 Clang이 다른 CPU용 코드를 만들고, 경고(`-Wall -Wextra`)와 새니타이저, clang-tidy로 실수를 일찍 잡는다
