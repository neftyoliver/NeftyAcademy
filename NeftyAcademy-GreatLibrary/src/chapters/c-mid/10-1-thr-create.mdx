「컴퓨터의 입문」의 [「스레드의 개념」](#/read/basics/threads)에서 스레드가 무엇이고 왜 쓰는지를 봤습니다. 이 장은 C로 스레드 프로그램을 실제로 짭니다. C11부터 표준에 들어온 `threads.h`를 쓰므로 리눅스, 맥(Clang), 윈도우(MSVC 2022 17.8부터)에서 같은 코드가 돕니다. 리눅스와 맥에서 더 오래 쓰여 온 POSIX의 `pthread`와의 짝도 함께 적습니다.

## 만들고 기다리기

스레드 프로그램의 뼈대는 두 함수입니다.

| C11 `threads.h` | POSIX `pthread.h` | 하는 일 |
| --- | --- | --- |
| `thrd_create(&t, 함수, 인자)` | `pthread_create(&t, NULL, 함수, 인자)` | 새 스레드에서 함수를 실행한다 |
| `thrd_join(t, &돌려준값)` | `pthread_join(t, &돌려준값)` | 그 스레드가 끝날 때까지 기다린다 |
| `int 함수(void *)` | `void *함수(void *)` | 스레드가 실행할 함수의 모양 |

스레드 함수는 `void *` 인자 하나만 받습니다. 여러 값을 넘기고 결과도 받으려면 **구조체**를 하나 만들어 그 주소를 넘깁니다. 0부터 999,999까지의 합을 일꾼 넷이 나눠 구해 봅니다.

```c
#include <stdio.h>
#include <threads.h>

typedef struct {
    int id;             // 몇 번째 일꾼인가
    long from, to;      // 맡은 구간 [from, to)
    long long sum;      // 결과를 돌려줄 자리
} Job;

static int worker(void *arg)
{
    Job *job = arg;
    long long s = 0;
    for (long i = job->from; i < job->to; i++)
        s += i;
    job->sum = s;
    return job->id;     // thrd_join이 받는 값
}

int main(void)
{
    enum { N = 4 };
    thrd_t t[N];
    Job jobs[N];
    for (int k = 0; k < N; k++) {
        jobs[k] = (Job){.id = k, .from = k * 250000L, .to = (k + 1) * 250000L};
        if (thrd_create(&t[k], worker, &jobs[k]) != thrd_success) {
            fprintf(stderr, "스레드 %d를 만들지 못했다\n", k);
            return 1;
        }
    }
    long long total = 0;
    for (int k = 0; k < N; k++) {
        int ret;
        thrd_join(t[k], &ret);  // k번 일꾼이 끝날 때까지 기다린다
        printf("일꾼 %d 끝 (돌려준 값 %d): %lld\n", k, ret, jobs[k].sum);
        total += jobs[k].sum;
    }
    printf("0부터 999999까지의 합: %lld\n", total);
    return 0;
}
```

```text
일꾼 0 끝 (돌려준 값 0): 31249875000
일꾼 1 끝 (돌려준 값 1): 93749875000
일꾼 2 끝 (돌려준 값 2): 156249875000
일꾼 3 끝 (돌려준 값 3): 218749875000
0부터 999999까지의 합: 499999500000
```

- 일꾼마다 **자기만의 구조체** `Job`을 가집니다. 각자 자기 구조체의 `sum`에만 쓰므로 [「스레드의 개념」](#/read/basics/threads)에서 본 경쟁 상태가 생기지 않습니다. 같은 변수에 함께 쓰지 않게 일을 나누는 것이 가장 쉬운 안전책입니다
- `jobs[k].sum`은 **`thrd_join`이 돌아온 뒤에만** 읽습니다. 일꾼이 쓰는 중에 읽으면 덜 된 값을 볼 수 있습니다. `thrd_join`은 "그 스레드가 한 일을 이제 다 볼 수 있다"는 약속이기도 합니다
- 일꾼들이 끝나는 순서는 매번 다를 수 있지만, 출력은 `main`이 0번부터 차례로 기다리며 찍으므로 늘 같은 순서입니다
- 리눅스의 glibc 2.34부터는 스레드 함수가 C 라이브러리 안에 들어 있어서 `-pthread` 옵션 없이도 링크됩니다. 옛 시스템과 맞추려면 붙여 두는 것이 안전합니다

## 반복문 변수의 주소를 넘기는 실수

스레드 프로그램에서 가장 흔한 실수 하나를 일부러 해 봅니다.

```c nocheck
static int show(void *arg)
{
    printf("나는 %d번\n", *(int *)arg);    // 받은 주소에서 번호를 읽는다
    return 0;
}

int main(void)
{
    thrd_t t[4];
    for (int k = 0; k < 4; k++)
        thrd_create(&t[k], show, &k);      // k의 주소를 넘긴다
    for (int k = 0; k < 4; k++)
        thrd_join(t[k], NULL);
    return 0;
}
```

세 번 돌린 결과입니다.

```text nocheck
나는 4번 나는 4번 나는 4번 나는 4번
나는 2번 나는 3번 나는 3번 나는 3번
나는 4번 나는 4번 나는 4번 나는 4번
```

0, 1, 2, 3이 나와야 할 것 같은데 엉뚱한 번호가 나오고, 돌릴 때마다 다릅니다. 네 스레드 모두 **같은 변수 `k`의 주소**를 받았기 때문입니다. 스레드가 실제로 그 주소를 읽는 때에는 반복문이 이미 `k`를 바꿨거나, 반복문이 끝나 `k`가 사라진 뒤일 수도 있습니다(사라진 변수를 읽는 것은 정의되지 않은 동작입니다). 앞의 예제처럼 스레드마다 따로 있는 자리(`jobs[k]`)의 주소를 넘겨야 합니다.

<Note kind="warn">
같은 까닭으로, 스레드에 넘긴 구조체가 **스레드보다 먼저 사라지면** 안 됩니다. 함수 안의 지역 변수 주소를 넘기고 그 함수가 먼저 돌아가 버리면, 스레드는 이미 다른 용도로 쓰이는 스택을 읽게 됩니다. 스레드를 만든 함수가 `thrd_join`으로 기다리든지, `malloc`으로 받은 메모리를 넘기고 스레드가 다 쓴 뒤 `free`하게 합니다.
</Note>

## 그 밖의 함수

| 함수 | 하는 일 |
| --- | --- |
| `thrd_current()` | 지금 스레드를 가리키는 값 |
| `thrd_sleep(&시간, NULL)` | 정한 시간만큼 잔다 |
| `thrd_yield()` | 다른 스레드에게 CPU를 양보한다 |
| `thrd_detach(t)` | 기다리지 않겠다고 알린다. 끝나면 저절로 정리된다 |
| `thrd_exit(값)` | 스레드를 그 자리에서 끝낸다 |

`thrd_join`도 `thrd_detach`도 하지 않은 스레드는 끝나도 정리되지 않고 자원을 붙잡고 있습니다. 만든 스레드는 둘 중 하나를 꼭 해 줘야 합니다. 그리고 `main`이 돌아가면 프로세스 전체가 끝나므로, 아직 일하던 스레드도 함께 사라집니다.

<Note kind="tip">
스레드를 몇 개 만들지는 [「코어와 스레드」](#/read/basics/terms-core-thread)에서 본 대로 코어 수가 기준입니다. 계산만 하는 일이라면 코어 수보다 많이 만들어도 빨라지지 않습니다. 리눅스에서는 `sysconf(_SC_NPROCESSORS_ONLN)`(POSIX)으로 쓸 수 있는 코어 수를 알 수 있습니다.
</Note>

## 정리

- `thrd_create`로 스레드를 만들고 `thrd_join`으로 기다리며, 여러 값을 넘기고 결과를 받을 때는 스레드마다 따로 있는 구조체의 주소를 넘긴다
- 스레드가 쓴 결과는 `thrd_join`이 돌아온 뒤에 읽고, 반복문 변수처럼 바뀌거나 사라지는 변수의 주소를 넘기면 안 된다
- 만든 스레드는 반드시 `thrd_join`하거나 `thrd_detach`하고, POSIX의 `pthread_create`/`pthread_join`이 같은 일을 하는 짝이다
