**블루투스 LE**(Low Energy, BLE)는 동전 전지 하나로 몇 달을 버티는 기기를 위해 만든 블루투스입니다. 심박계, 체중계, 스마트 태그, 실내 온도계가 휴대폰과 BLE로 이야기합니다. [「Wi-Fi」](#/read/c-mid/iot-wifi)처럼 IP 네트워크에 붙는 것이 아니라, 가까운 기기끼리 짧게 주고받는 데 맞춰져 있습니다.

## 두 가지 말하는 법

- **광고**(advertising): 기기가 "나 여기 있어"를 31바이트 안팎의 짧은 패킷으로 주기적으로 외칩니다. 듣는 쪽은 연결하지 않고도 이름, 제공하는 서비스, 짧은 데이터(온도 같은)를 받을 수 있습니다. 2.4 GHz 대역 40개 채널 중 광고 전용 세 채널(37·38·39번)을 씁니다
- **연결**(connection): 더 많이 주고받으려면 휴대폰(**central**)이 기기(**peripheral**)에 연결합니다. 연결된 뒤에는 정해진 간격마다 잠깐 깨어 주고받고 나머지 시간은 잡니다. 전기를 아끼는 비결입니다

## 광고 데이터 풀기

광고 데이터는 `[길이][종류][내용]` 묶음이 이어진 단순한 모양입니다. 길이는 종류 바이트까지 센 값입니다.

```c
#include <stdint.h>
#include <stdio.h>

// 광고 데이터(최대 31바이트): [길이][종류][내용]의 되풀이
static const uint8_t adv[] = {
    0x02, 0x01, 0x06,                         // 깃발
    0x05, 0x03, 0x1A, 0x18, 0x0F, 0x18,       // 서비스 0x181A, 0x180F
    0x05, 0x16, 0x1A, 0x18, 0x2E, 0x09,       // 0x181A의 데이터 2350
    0x08, 0x09, 'M', 'i', 'n', 'e', 'r', 'v', 'a',   // 전체 이름
};

static void uuid128(uint16_t u)
{
    // 16비트 UUID는 블루투스 기본 UUID의 한 칸을 바꾼 줄임말
    printf("    = 0000%04x-0000-1000-8000-00805f9b34fb\n", u);
}

int main(void)
{
    printf("광고 데이터 %zu바이트 (최대 31)\n", sizeof adv);
    for (size_t i = 0; i < sizeof adv && adv[i] != 0;) {
        uint8_t len = adv[i], type = adv[i + 1];
        const uint8_t *d = adv + i + 2;
        int n = len - 1;                      // 내용 길이
        switch (type) {
        case 0x01:
            printf("깃발 0x%02x\n", d[0]);
            break;
        case 0x03:
            for (int k = 0; k + 1 < n; k += 2) {
                uint16_t u = (uint16_t)(d[k] | d[k + 1] << 8);
                printf("서비스 0x%04X%s\n", u,
                       u == 0x181A ? " (환경 감지)"
                       : u == 0x180F ? " (배터리)" : "");
                if (k == 0)
                    uuid128(u);
            }
            break;
        case 0x16: {
            uint16_t u = (uint16_t)(d[0] | d[1] << 8);
            int16_t t = (int16_t)(d[2] | d[3] << 8);   // 0.01도 단위
            int a = t < 0 ? -t : t;
            printf("0x%04X의 데이터: 온도 %s%d.%02d도\n", u,
                   t < 0 ? "-" : "", a / 100, a % 100);
            break;
        }
        case 0x09:
            printf("이름 %.*s\n", n, (const char *)d);
            break;
        default:
            printf("모르는 종류 0x%02x\n", type);
        }
        i += (size_t)len + 1;
    }
    return 0;
}
```

```text
광고 데이터 24바이트 (최대 31)
깃발 0x06
서비스 0x181A (환경 감지)
    = 0000181a-0000-1000-8000-00805f9b34fb
서비스 0x180F (배터리)
0x181A의 데이터: 온도 23.50도
이름 Minerva
```

- **깃발** 0x06: "일반 발견 가능"과 "옛 블루투스(BR/EDR)는 지원하지 않음" 두 비트입니다
- **16비트 UUID**: 블루투스 SIG가 정해 둔 표준 서비스는 16비트 번호로 부릅니다. 0x181A는 환경 감지, 0x180F는 배터리입니다. 이것은 기본 UUID `0000xxxx-0000-1000-8000-00805f9b34fb`의 한 칸을 채운 줄임말이라, 128비트로 펼칠 수 있습니다. 직접 만든 서비스는 무작위 128비트 UUID를 씁니다
- **서비스 데이터**: 0x181A 서비스에 딸린 값으로 온도를 실었습니다. 온도 특성(0x2A6E)의 약속대로 부호 있는 16비트, 0.01도 단위라 0x092E = 2350은 23.50도입니다. 음수 온도도 올바로 찍히도록 부호를 따로 처리했습니다
- 모든 두 바이트 값은 **리틀 엔디언**입니다. `1A 18`이 0x181A입니다
- 31바이트는 금방 찹니다(여기서 24바이트). 모자라면 듣는 쪽이 요청할 때 31바이트를 더 주는 **스캔 응답**을 쓰거나, 블루투스 5의 확장 광고를 씁니다

## 연결하면: GATT

연결된 뒤의 데이터는 **GATT**라는 나무 모양으로 정리됩니다.

| 층 | 예 | 하는 일 |
| --- | --- | --- |
| 서비스 | 배터리(0x180F) | 관련된 값들의 묶음 |
| 특성(characteristic) | 배터리 잔량(0x2A19) | 값 하나와 그 성질 |
| 성질 | 읽기, 쓰기, 알림(notify) | 그 값으로 할 수 있는 일 |

휴대폰은 특성을 **읽거나**(read) **쓰고**(write), 값이 바뀔 때마다 기기가 먼저 보내 주도록 **알림을 구독**(notify)합니다. 심박계는 심박 특성에 알림을 켜 두면 1초마다 값을 밀어 줍니다. [「MQTT」](#/read/c-mid/iot-mqtt)의 발행·구독과 닮았지만, 브로커 없이 기기 둘 사이에서 일어납니다.

<Note>
리눅스의 블루투스는 **BlueZ**가 맡습니다. 손으로는 `bluetoothctl`에서 `scan on`으로 광고를 보고, 프로그램에서는 BlueZ가 D-Bus로 내놓는 API를 씁니다. 마이크로컨트롤러에서는 ESP-IDF의 NimBLE이나 Zephyr의 블루투스 스택처럼 제조사·운영체제의 스택을 씁니다. 이 검사용 컴퓨터에는 블루투스 장치가 없어서, 위 광고 데이터는 직접 짜서 풀어 본 것입니다.
</Note>

## 조심할 것

- 광고는 **누구나** 듣습니다. 광고에 개인 정보를 싣지 말고, 기기를 따라다니며 추적하지 못하도록 요즘 기기는 주소를 주기적으로 바꿉니다(무작위 주소)
- 연결 뒤의 데이터는 **페어링**으로 암호화할 수 있습니다. 숫자 비교나 비밀번호 입력 방식이 안전하고, 화면도 버튼도 없는 기기의 "그냥 연결"(Just Works)은 엿듣기는 막아도 중간자 공격은 막지 못합니다
- 블루투스 규격은 지금도 해마다 두 번꼴로 새 판이 나오며 기능이 더해집니다. 새 기능을 쓰기 전에 휴대폰과 칩이 모두 지원하는지 확인합니다

## 정리

- BLE는 광고로 연결 없이 짧은 데이터를 외치고, 더 주고받을 때는 central이 peripheral에 연결해 정해진 간격에만 깨어 전기를 아낀다
- 광고 데이터는 31바이트 안의 `[길이][종류][내용]` 묶음이고, 16비트 UUID는 기본 UUID의 줄임말이며 값은 리틀 엔디언이다
- 연결 뒤에는 GATT의 서비스와 특성을 읽고 쓰고 알림으로 받으며, 광고는 누구나 들으므로 개인 정보와 페어링 방식을 조심한다
