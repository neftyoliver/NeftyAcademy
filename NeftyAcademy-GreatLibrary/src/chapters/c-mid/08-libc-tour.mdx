「컴퓨터 프로그래밍 초급」의 [「먼저 알아 둘 표준 라이브러리」](#/read/c-basic/stdlib-first)에서는 `stdio.h`, `stdlib.h`, `string.h`처럼 날마다 쓰는 헤더 아홉 개를 봤습니다. C23 표준이 정한 헤더는 모두 31개입니다. 이 쪽은 나머지를 포함해 전체를 한 번 훑어서, 필요할 때 "표준에 이런 게 있었지" 하고 떠올릴 수 있게 하는 것이 목표입니다. 어느 OS에서든 쓸 수 있는 것은 여기까지이고, 그 바깥은 [「POSIX와 ISO C」](#/read/basics/std-posix-c)에서 본 POSIX나 OS의 API입니다.

## 31개 헤더 지도

| 쓰임 | 헤더 | 대표 |
| --- | --- | --- |
| 입출력 | `stdio.h` | `printf`, `fopen`, `fgets` |
| 메모리, 변환, 정렬 | `stdlib.h` | `malloc`, `strtol`, `qsort`, `bsearch` |
| 문자열, 메모리 덩어리 | `string.h` | `strlen`, `memcpy`, `memset_explicit` |
| 글자 분류 | `ctype.h`, `wctype.h` | `isdigit`, `iswalpha` |
| 넓은 글자, 유니코드 | `wchar.h`, `uchar.h` | `wprintf`, `char32_t`, `mbrtoc32` |
| 정수의 크기 | `stdint.h`, `inttypes.h`, `limits.h` | `uint64_t`, `PRIu64`, `INT_MAX` |
| 넘침 검사 (C23) | `stdckdint.h` | `ckd_add`, `ckd_mul` |
| 비트 다루기 (C23) | `stdbit.h` | `stdc_count_ones`, `stdc_bit_width` |
| 실수 | `math.h`, `float.h`, `fenv.h`, `tgmath.h`, `complex.h` | `sqrt`, `DBL_EPSILON`, 반올림 방식 |
| 시간 | `time.h` | `time`, `strftime`, `timespec_get` |
| 오류 | `errno.h`, `assert.h` | `errno`, `assert` |
| 기본 타입과 매크로 | `stddef.h`, `stdbool.h`, `stdalign.h`, `stdnoreturn.h`, `iso646.h` | `size_t`, `nullptr_t`, `offsetof` |
| 가변 인자 | `stdarg.h` | `va_list`, `va_arg` |
| 동시성 | `threads.h`, `stdatomic.h` | `thrd_create`, `atomic_int` |
| 프로그램 흐름 | `setjmp.h`, `signal.h` | `longjmp`, `signal` |
| 지역 설정 | `locale.h` | `setlocale` |

`stdbool.h`, `stdalign.h`, `stdnoreturn.h`, `iso646.h`는 C23에서 `bool`, `alignas`, `[[noreturn]]` 같은 것이 언어의 키워드가 되면서 거의 비어 버린 헤더입니다. 옛 코드와 맞추려고 남아 있습니다. 버전별 변화는 [「C23」](#/read/c-basic/ver-c23)에서 봤습니다.

## 잘 모르고 지나치는 것들

아래 프로그램은 표의 몇 줄을 직접 써 봅니다.

```c
#include <inttypes.h>
#include <stdbit.h>
#include <stdckdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

static int cmp_int(const void *a, const void *b)
{
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);
}

int main(void)
{
    // <stdckdint.h>: 넘치면 알려 주는 덧셈 (C23)
    int sum;
    bool over = ckd_add(&sum, 2000000000, 2000000000);
    printf("ckd_add: 넘침=%d\n", over);

    // <stdbit.h>: 비트 세기 (C23)
    unsigned v = 0b1011'0000u;
    printf("켜진 비트 %u개, 아래쪽 0이 %u개\n",
           stdc_count_ones(v), stdc_trailing_zeros(v));

    // <inttypes.h>: 크기가 정해진 정수를 printf로
    uint64_t big = UINT64_MAX;
    printf("uint64_t 최댓값 %" PRIu64 "\n", big);

    // <stdlib.h>: 정렬하고 이진 탐색
    int a[] = {42, 7, 19, 3, 88};
    qsort(a, 5, sizeof a[0], cmp_int);
    int key = 19;
    int *hit = bsearch(&key, a, 5, sizeof a[0], cmp_int);
    printf("정렬 %d %d %d %d %d, 19는 %td번째\n", a[0], a[1], a[2], a[3], a[4],
           hit - a);

    // <time.h>: 날짜를 글로
    struct tm when = {.tm_year = 2026 - 1900, .tm_mon = 10, .tm_mday = 21,
                      .tm_hour = 19};
    char buf[64];
    strftime(buf, sizeof buf, "%Y-%m-%d %H:%M", &when);
    printf("strftime: %s\n", buf);
    return 0;
}
```

```text
ckd_add: 넘침=1
켜진 비트 3개, 아래쪽 0이 4개
uint64_t 최댓값 18446744073709551615
정렬 3 7 19 42 88, 19는 2번째
strftime: 2026-11-21 19:00
```

- **`ckd_add`**: [「정수의 표현과 2의 보수」](#/read/basics/math-integers)에서 부호 있는 정수의 넘침은 정의되지 않은 동작이라고 했습니다. `ckd_add(&결과, a, b)`는 넘치면 `true`를 돌려주고 결과에는 한 바퀴 돈 값을 넣습니다. 크기를 곱해 메모리를 받기 전처럼 넘침을 꼭 확인해야 할 때 씁니다
- **`stdbit.h`**: `0b1011'0000`(C23부터 숫자 사이에 `'`를 넣어 읽기 좋게 쓸 수 있습니다)에서 켜진 비트는 3개, 맨 아래쪽 0은 4개입니다. 직접 반복문으로 세던 일을 CPU의 전용 명령 하나로 바꿔 줍니다
- **`PRIu64`**: `uint64_t`가 OS마다 `unsigned long`이기도 `unsigned long long`이기도 해서 `%lu`로 고정하면 어딘가에서 틀립니다. `PRIu64`는 그 OS에 맞는 서식 글자로 바뀝니다
- **`qsort`와 `bsearch`**: 비교 함수 하나로 정렬과 이진 탐색을 합니다. 비교 함수에서 `return x - y;`라고 쓰면 큰 수끼리 빼다 넘칠 수 있어서 `(x > y) - (x < y)`로 썼습니다. `%td`는 포인터끼리 뺀 값(`ptrdiff_t`)의 서식입니다
- **`strftime`**: 날짜와 시각을 원하는 모양의 글로 바꿉니다. `tm_year`는 1900년부터, `tm_mon`은 0(1월)부터 센다는 옛 약속에 주의해야 합니다

<Note>
`stdckdint.h`와 `stdbit.h`는 C23에 새로 들어와서 컴파일러와 C 라이브러리가 새것이어야 합니다. 이 예제는 GCC 14와 Clang 20, glibc 2.39에서 컴파일됐습니다. 우분투 24.04의 기본 GCC 13은 `-std=c23`을 받지 않으니([「GCC」](#/read/c-mid/cc-gcc)), `gcc-14`를 쓰세요. 반면 같은 C23의 `memset_explicit`은 glibc 2.39에 아직 없었습니다([「메모리를 숨기고 보호하기」](#/read/c-mid/sec-memory)). 표준에 있다고 모든 구현에 바로 있는 것은 아닙니다.
</Note>

## 조심해서 쓸 것들

표준에 있지만 쓸 때 조심해야 하는 것도 있습니다.

| 것 | 조심할 점 |
| --- | --- |
| `setjmp`, `longjmp` | 함수 몇 단계를 건너뛰어 돌아간다. 그 사이의 정리(메모리 해제)를 건너뛰므로 쓸 일이 거의 없다 |
| `signal` | 신호 처리 함수 안에서 할 수 있는 일이 아주 적다. `printf`도 안 된다 |
| `strtok` | 내부에 상태를 숨겨 두어 스레드 안전하지 않고, 원래 문자열을 고친다 |
| `rand` | 품질이 정해져 있지 않다. 보안용 난수로 쓰면 안 된다 |
| `setlocale` | 프로그램 전체의 동작(소수점 글자 등)을 바꾼다 |

이런 것들의 대안은 대개 POSIX나 OS가 줍니다. 예를 들어 보안용 난수는 리눅스의 `getrandom`, 신호를 안전하게 다루는 것은 POSIX의 `sigaction`입니다. 다음 장 [「C 생태계의 네 층」](#/read/c-mid/c-ecosystem)부터 그 바깥 세계를 봅니다.

## 정리

- C23 표준 라이브러리는 헤더 31개이고, 어느 OS에서든 쓸 수 있는 것은 여기까지다
- C23에 새로 들어온 `stdckdint.h`(넘침 검사)와 `stdbit.h`(비트 세기), 그리고 `PRIu64`, `bsearch`, `strftime`처럼 잘 모르고 지나치는 쓸모 있는 것이 많다
- `setjmp`, `signal`, `strtok`, `rand`처럼 표준에 있어도 조심해서 써야 하는 것이 있고, 그 대안은 대개 POSIX나 OS가 준다
