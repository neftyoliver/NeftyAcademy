IoT 기기는 작고, 전기를 아끼고, 네트워크가 자주 끊깁니다. 이런 기기에서 [「HTTP」](#/read/c-mid/http)처럼 매번 요청하고 기다리는 대신 많이 쓰는 것이 **MQTT**입니다. 머리가 2바이트부터 시작할 만큼 가볍고, 기기끼리 서로를 몰라도 이야기할 수 있게 해 줍니다.

## 브로커, 주제, 발행과 구독

MQTT에서 기기들은 서로 직접 잇지 않습니다. 가운데에 **브로커**(Mosquitto 같은 서버)가 있고, 모든 기기는 브로커에만 [「TCP」](#/read/c-mid/net-tcp)로 연결합니다.

- **발행**(publish): 온도 센서가 `home/livingroom/temp`라는 **주제**(topic)로 "23.5"를 보낸다
- **구독**(subscribe): 휴대폰 앱이 `home/+/temp`를 구독해 두면, 브로커가 맞는 메시지를 모두 건네준다
- 주제는 `/`로 나눈 칸입니다. `+`는 한 칸에 아무거나, `#`는 그 아래 전부(맨 끝에만)를 뜻합니다

센서는 누가 듣는지 모르고, 앱은 누가 보내는지 모릅니다. 기기를 더하거나 빼도 다른 쪽을 고칠 필요가 없습니다.

| QoS | 약속 | 대가 |
| --- | --- | --- |
| 0 | 많아야 한 번. 보내고 끝 | 가장 가볍다. 잃어도 모른다 |
| 1 | 적어도 한 번. 확인(PUBACK)이 올 때까지 다시 보냄 | 두 번 받을 수 있다 |
| 2 | 정확히 한 번. 네 번 주고받음 | 가장 무겁다 |

이 밖에 브로커가 주제의 마지막 값을 기억해 새 구독자에게 바로 주는 **retained** 메시지와, 기기가 갑자기 끊기면 브로커가 대신 알리는 **유언**(last will)이 있습니다. 포트는 보통 1883, TLS를 쓰면 8883입니다.

## PUBLISH 패킷을 손으로 짜기

MQTT 3.1.1의 QoS 0 PUBLISH 패킷은 아주 단순합니다.

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

// 남은 길이: 7비트씩 끊고, 뒤에 더 있으면 맨 위 비트를 세운다
static size_t put_varint(uint8_t *out, size_t v)
{
    size_t n = 0;
    do {
        uint8_t b = v % 128;
        v /= 128;
        out[n++] = v ? (uint8_t)(b | 0x80) : b;
    } while (v);
    return n;
}

static size_t put_str(uint8_t *out, const char *s)
{
    size_t len = strlen(s);
    out[0] = (uint8_t)(len >> 8);   // 길이 2바이트(빅 엔디언) + 글자
    out[1] = (uint8_t)len;
    memcpy(out + 2, s, len);
    return len + 2;
}

// QoS 0 PUBLISH 패킷: 머리 0x30, 남은 길이, 주제, 내용
static size_t publish(uint8_t *out, const char *topic, const char *payload)
{
    uint8_t body[512];
    size_t b = put_str(body, topic);
    size_t plen = strlen(payload);
    memcpy(body + b, payload, plen);
    b += plen;
    out[0] = 0x30;
    size_t h = 1 + put_varint(out + 1, b);
    memcpy(out + h, body, b);
    return h + b;
}

static void dump(const uint8_t *p, size_t n)
{
    for (size_t i = 0; i < n; i++)
        printf("%02x%s", p[i], (i + 1) % 16 && i + 1 < n ? " " : "\n");
}

int main(void)
{
    uint8_t pkt[600];
    size_t n = publish(pkt, "home/livingroom/temp", "23.5");
    printf("PUBLISH %zu바이트\n", n);
    dump(pkt, n);

    const size_t lens[] = {127, 128, 300, 16383, 16384};
    for (int i = 0; i < 5; i++) {
        uint8_t v[4];
        size_t k = put_varint(v, lens[i]);
        printf("남은 길이 %5zu ->", lens[i]);
        for (size_t j = 0; j < k; j++)
            printf(" %02x", v[j]);
        printf("\n");
    }
    return 0;
}
```

```text
PUBLISH 28바이트
30 1a 00 14 68 6f 6d 65 2f 6c 69 76 69 6e 67 72
6f 6f 6d 2f 74 65 6d 70 32 33 2e 35
남은 길이   127 -> 7f
남은 길이   128 -> 80 01
남은 길이   300 -> ac 02
남은 길이 16383 -> ff 7f
남은 길이 16384 -> 80 80 01
```

- 첫 바이트 `30`: 위 4비트 3이 PUBLISH, 아래 4비트는 QoS와 retained 같은 깃발입니다(여기서는 모두 0)
- `1a`(26): 그 뒤에 남은 바이트 수. **가변 길이**로 적어서, 127까지는 1바이트, 16383까지는 2바이트면 됩니다. 각 바이트의 아래 7비트가 값이고, 맨 위 비트 1은 "다음 바이트가 더 있다"는 뜻입니다. 작은 메시지가 대부분인 IoT에서 머리를 2바이트로 줄이는 비결입니다
- `00 14` + 글자 20개: 주제. 길이를 두 바이트 빅 엔디언으로 앞에 붙입니다
- 나머지 `32 33 2e 35`: 내용 "23.5". 내용의 길이는 따로 적지 않고 "남은 길이에서 주제를 뺀 나머지"로 압니다. 내용은 그냥 바이트라 글자든 JSON이든 이진 데이터든 됩니다

맞게 짰는지 확인하려고, 연결 응답(CONNACK)만 돌려주는 가짜 서버를 만들고 Mosquitto의 `mosquitto_pub` 도구로 같은 주제와 내용을 보내 받은 바이트를 찍어 보았습니다. CONNECT 패킷 뒤에 온 PUBLISH가 위의 28바이트와 **한 바이트도 다르지 않았고**, 이어서 연결 끊기 패킷 `e0 00`이 왔습니다.

## libmosquitto로 주고받기

실제로는 라이브러리를 씁니다. Eclipse Mosquitto의 C 라이브러리로 구독하고, 구독이 확인되면 발행해서 자기가 보낸 것을 받아 봅니다.

```c nocheck
#include <stdio.h>
#include <string.h>
#include <mosquitto.h>

static void on_connect(struct mosquitto *m, void *obj, int rc)
{
    (void)obj;
    printf("연결됨 (결과 %d)\n", rc);
    // + 는 주제의 한 칸에 아무거나
    mosquitto_subscribe(m, nullptr, "home/+/temp", 1);
}

static void on_subscribe(struct mosquitto *m, void *obj, int mid, int n,
                         const int *granted)
{
    (void)obj; (void)mid; (void)n;
    printf("구독됨 (허락된 QoS %d)\n", granted[0]);
    mosquitto_publish(m, nullptr, "home/livingroom/temp", 4, "23.5", 1, false);
}

static void on_message(struct mosquitto *m, void *obj,
                       const struct mosquitto_message *msg)
{
    (void)obj;
    printf("받음 %s = %.*s (QoS %d)\n", msg->topic, msg->payloadlen,
           (const char *)msg->payload, msg->qos);
    mosquitto_disconnect(m);
}

int main(void)
{
    mosquitto_lib_init();
    struct mosquitto *m = mosquitto_new("minerva-sensor", true, nullptr);
    mosquitto_connect_callback_set(m, on_connect);
    mosquitto_subscribe_callback_set(m, on_subscribe);
    mosquitto_message_callback_set(m, on_message);
    if (mosquitto_connect(m, "localhost", 1883, 60) != MOSQ_ERR_SUCCESS) {
        fprintf(stderr, "브로커에 연결할 수 없음\n");
        return 1;
    }
    mosquitto_loop_forever(m, -1, 1);   // 끊길 때까지 주고받기
    mosquitto_destroy(m);
    mosquitto_lib_cleanup();
    return 0;
}
```

```text nocheck
연결됨 (결과 0)
구독됨 (허락된 QoS 1)
받음 home/livingroom/temp = 23.5 (QoS 1)
```

이 출력은 검사용 컴퓨터에 Mosquitto 2.0.18 브로커를 띄워 놓고 실행한 결과입니다(`-lmosquitto`로 링크). 브로커가 있어야 해서 자동 검사에서는 빼 두었습니다. 모든 일이 **콜백**으로 일어나는 것에 주목하세요. 연결이 되면 구독하고, 구독이 확인되면 발행하고, 메시지가 오면 끊습니다. `mosquitto_loop_forever`가 네트워크를 지켜보다가 일이 생길 때마다 알맞은 콜백을 부릅니다. 끊기면 다시 연결하는 일도 이 고리가 해 줍니다.

<Note kind="warn">
브로커를 인터넷에 열어 둘 때는 반드시 사용자 인증과 [「TLS로 암호화하기」](#/read/c-mid/iot-tls)의 TLS를 켭니다. 인증 없이 열린 MQTT 브로커는 누구나 주제를 엿듣고 기기에 명령을 보낼 수 있습니다. Mosquitto 2.x는 설정 파일 없이 띄우면 같은 컴퓨터(localhost)의 연결만 받도록 바뀌었습니다.
</Note>

## 정리

- MQTT는 모든 기기가 브로커에 연결하고, 주제로 발행하고 구독하여 서로를 모른 채 이야기하며, `+`와 `#`로 여러 주제를 받는다
- PUBLISH 패킷은 종류·깃발 1바이트, 가변 길이, 길이 붙은 주제, 내용으로 되어 있어 머리가 2바이트부터 시작한다
- QoS 0·1·2로 전달 보장의 정도를 고르고, C에서는 libmosquitto의 콜백과 고리로 연결·구독·발행을 다룬다
