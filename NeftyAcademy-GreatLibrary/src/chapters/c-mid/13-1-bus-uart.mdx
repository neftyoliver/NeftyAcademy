**UART**(Universal Asynchronous Receiver-Transmitter)는 선 두 가닥으로 바이트를 한 비트씩 차례로 보내는 가장 오래되고 단순한 직렬 통신입니다. 마이크로컨트롤러와 PC, GPS 모듈, 블루투스 모듈, 그리고 보드의 "디버그 콘솔"이 거의 다 UART로 말합니다. 이 쪽은 신호의 모양을 보고, 리눅스에서 C로 포트를 여는 법을 가상 터미널로 확인합니다. 다음 두 쪽의 [「I2C」](#/read/c-mid/bus-i2c), [「SPI」](#/read/c-mid/bus-spi)와 견주며 읽으면 좋습니다.

## 시계 없이 맞추는 법

UART에는 시계 선이 없습니다(그래서 비동기, asynchronous). 대신 양쪽이 **미리 같은 속도**(baud, 초당 비트 수)를 약속하고, 바이트마다 시작과 끝을 표시합니다.

```c
#include <stdio.h>

// 8N1 틀 하나: 시작 비트 0, 데이터 8비트(낮은 비트부터), 정지 비트 1
static void frame(unsigned char c)
{
    printf("'%c' 0x%02X: 쉼 1 | 시작 0 | 데이터", c, c);
    for (int i = 0; i < 8; i++)
        printf(" %d", (c >> i) & 1);
    printf(" | 정지 1\n");
}

int main(void)
{
    frame('A');
    frame('z');

    const long bauds[] = {9600, 115200, 1000000};
    for (int i = 0; i < 3; i++) {
        double bit_us = 1e6 / (double)bauds[i];
        printf("%7ld baud: 비트 %.2fµs, 바이트(10비트) %.1fµs, "
               "초당 %ld바이트\n",
               bauds[i], bit_us, bit_us * 10, bauds[i] / 10);
    }
    return 0;
}
```

```text
'A' 0x41: 쉼 1 | 시작 0 | 데이터 1 0 0 0 0 0 1 0 | 정지 1
'z' 0x7A: 쉼 1 | 시작 0 | 데이터 0 1 0 1 1 1 1 0 | 정지 1
   9600 baud: 비트 104.17µs, 바이트(10비트) 1041.7µs, 초당 960바이트
 115200 baud: 비트 8.68µs, 바이트(10비트) 86.8µs, 초당 11520바이트
1000000 baud: 비트 1.00µs, 바이트(10비트) 10.0µs, 초당 100000바이트
```

- 쉬는 동안 선은 1(높음)입니다. 0으로 떨어지는 순간이 **시작 비트**이고, 받는 쪽은 여기서 시계를 맞춰 비트 하나 길이마다 선을 읽습니다
- 데이터는 **낮은 비트부터** 나갑니다. `A`(0x41 = 0100 0001)가 `1 0 0 0 0 0 1 0`으로 보이는 까닭입니다
- 마지막 **정지 비트** 1이 다음 시작 비트의 떨어짐을 알아볼 수 있게 해 줍니다. 이 모양을 줄여 **8N1**(데이터 8, 패리티 없음, 정지 1)이라 하고, 지금은 거의 모두 이것을 씁니다
- 그래서 바이트 하나에 10비트가 들고, 115200 baud면 초당 11,520바이트입니다. 양쪽 시계가 몇 % 넘게 어긋나면 뒤쪽 비트를 잘못 읽어 글자가 깨집니다. 글자가 이상하게 깨져 보이면 가장 먼저 속도 설정을 의심합니다

## 선 잇기

| 선 | 잇는 법 |
| --- | --- |
| TX(보내기) | 상대의 RX에 |
| RX(받기) | 상대의 TX에 |
| GND | 반드시 서로 잇는다. 전압은 땅을 기준으로 잰다 |

<Note kind="warn">
보드의 UART는 보통 3.3V 또는 5V의 TTL 수준이고, 옛 PC의 RS-232 포트는 ±수 V~십수 V의 전혀 다른 수준입니다. 라즈베리파이(3.3V)에 5V 장치의 TX나 RS-232를 그대로 이으면 망가질 수 있습니다. PC와 이을 때는 3.3V용 USB-시리얼 변환기를 씁니다.
</Note>

## 리눅스에서 포트 열기: termios

리눅스에서 UART는 파일입니다. USB-시리얼 변환기는 보통 `/dev/ttyUSB0`, 아두이노 같은 USB CDC 장치는 `/dev/ttyACM0`, 라즈베리파이 OS는 GPIO의 UART에 `/dev/serial0`이라는 별칭을 붙여 줍니다. 열어서 `read`·`write`하면 되지만, 그 전에 **termios**로 속도와 틀을 맞춰야 합니다. 터미널 장치는 원래 사람의 타자를 위한 것이라, 그대로 두면 줄 단위로 모으고 특수 문자를 바꾸기 때문입니다.

보드가 없으므로 **가상 터미널**(pseudo-terminal) 한 쌍으로 연습합니다. 한쪽에 쓴 바이트가 다른 쪽에서 읽히는, 터미널 흉내를 내는 커널 장치입니다.

```c flags=-D_DEFAULT_SOURCE,-D_XOPEN_SOURCE=700
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <termios.h>
#include <unistd.h>

// 시리얼 포트를 9600·8N1·가공 없음(raw)으로 맞춘다
static int setup_serial(int fd, speed_t speed)
{
    struct termios t;
    if (tcgetattr(fd, &t) != 0)
        return -1;
    cfmakeraw(&t);                  // 줄 편집·문자 바꾸기를 모두 끈다
    cfsetispeed(&t, speed);
    cfsetospeed(&t, speed);
    t.c_cflag &= ~(tcflag_t)(PARENB | CSTOPB | CSIZE);
    t.c_cflag |= CS8 | CLOCAL | CREAD;   // 8비트, 패리티 없음, 정지 1
    t.c_cc[VMIN] = 0;                    // 읽기: 최대 1초 기다림
    t.c_cc[VTIME] = 10;
    return tcsetattr(fd, TCSANOW, &t);
}

int main(void)
{
    // 가상 터미널 한 쌍: 한쪽은 "보드", 한쪽은 "PC"라고 치자
    int board = posix_openpt(O_RDWR | O_NOCTTY);
    if (board < 0 || grantpt(board) || unlockpt(board))
        return 1;
    int pc = open(ptsname(board), O_RDWR | O_NOCTTY);
    if (pc < 0 || setup_serial(pc, B9600) != 0)
        return 1;
    struct termios bt;
    tcgetattr(board, &bt);
    cfmakeraw(&bt);
    tcsetattr(board, TCSANOW, &bt);

    const char *msg = "temp=23.5\r\n";
    write(board, msg, strlen(msg));          // 보드가 보낸다

    char buf[64];
    ssize_t n = read(pc, buf, sizeof buf - 1);   // PC가 받는다
    buf[n > 0 ? n : 0] = '\0';
    printf("받은 %zd바이트:", n);
    for (ssize_t i = 0; i < n; i++)
        printf(" %02x", (unsigned char)buf[i]);
    printf("\n");

    struct termios now;
    tcgetattr(pc, &now);
    printf("설정된 속도가 9600인가: %d\n", cfgetospeed(&now) == B9600);
    close(pc);
    close(board);
    return 0;
}
```

```text
받은 11바이트: 74 65 6d 70 3d 32 33 2e 35 0d 0a
설정된 속도가 9600인가: 1
```

- `cfmakeraw`가 핵심입니다. 줄 모으기, 메아리, `\r`과 `\n` 바꾸기, Ctrl-C 같은 특수 문자 처리를 모두 꺼서 바이트를 있는 그대로 주고받게 합니다. 받은 바이트의 끝 `0d 0a`(CR LF)가 바뀌지 않고 그대로 왔습니다
- `VMIN`과 `VTIME`은 `read`가 언제 돌아올지 정합니다. `VMIN = 0, VTIME = 10`은 "바이트가 오면 바로, 안 오면 최대 1초(0.1초 단위로 10) 기다리고 돌아온다"입니다. 장치가 응답하지 않을 때 프로그램이 영원히 멈추지 않게 합니다
- 가상 터미널은 진짜 선이 없어서 속도 설정은 저장만 되고 실제로 느려지지는 않습니다. 진짜 포트에서는 같은 코드가 그대로 동작하며, 이 경우 데이터는 9600 baud로 1바이트에 약 1ms씩 걸립니다

<Note>
우분투·데비안에서 `/dev/ttyUSB0`을 열 때 "Permission denied"가 나면, 사용자를 `dialout` 그룹에 넣고 다시 로그인합니다. 빠르게 손으로 확인할 때는 `screen /dev/ttyUSB0 115200`이나 `picocom -b 115200 /dev/ttyUSB0` 같은 터미널 프로그램을 씁니다.
</Note>

## 바이트 너머: 내 규칙 만들기

UART는 바이트만 날라 줄 뿐, 어디가 메시지의 끝인지는 알려 주지 않습니다. 위 예제처럼 줄바꿈으로 끝을 표시하거나, 길이를 앞에 붙이거나, 시작 표시 바이트와 검사값(CRC)을 넣는 식의 **프레이밍** 규칙은 직접 정해야 합니다. 한 번의 `read`가 메시지 하나를 다 준다는 보장도 없으므로, 받은 바이트를 버퍼에 쌓아 두고 끝 표시가 나올 때마다 잘라 쓰는 것이 기본 모양입니다.

## 정리

- UART는 시계 선 없이 약속한 baud로 보내며, 8N1 틀은 시작 0, 낮은 비트부터 8비트, 정지 1로 바이트당 10비트다
- TX는 상대 RX로, GND는 꼭 잇고, 3.3V와 5V와 RS-232의 전압 차이를 조심한다
- 리눅스에서는 포트를 파일로 열고 termios의 `cfmakeraw`, 속도, `VMIN`·`VTIME`을 맞춘 뒤 바이트를 읽고 쓰며, 메시지 경계는 스스로 정한다
