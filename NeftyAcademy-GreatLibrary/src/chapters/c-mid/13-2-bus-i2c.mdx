**I2C**(I²C, Inter-Integrated Circuit, "아이스퀘어시"라고도 읽음)는 선 두 가닥에 장치 여러 개를 매달아 쓰는 버스입니다. 온도·습도 센서, 가속도계, 작은 OLED 화면, 시계 칩, EEPROM이 흔히 I2C로 붙습니다. [「UART」](#/read/c-mid/bus-uart)가 일대일이었다면 I2C는 **한 줄에 여럿**이고, 그래서 주소가 필요합니다.

## 선 두 개, 주소 하나

| 선 | 하는 일 |
| --- | --- |
| SCL(시계) | 컨트롤러가 박자를 낸다. 이 박자에 맞춰 비트를 읽는다 |
| SDA(데이터) | 양쪽이 번갈아 쓰는 데이터 선 |
| 풀업 저항 | 두 선을 약하게 높음으로 당겨 둔다. 장치는 선을 0으로 끌어내리기만 한다 |

장치들은 선을 "끌어내리거나 놓아 주기"만 합니다(오픈 드레인). 그래서 여러 장치가 한 선에 붙어도 서로 부딪쳐 망가지지 않고, 누군가 0을 쓰면 선은 0이 됩니다. 대신 풀업 저항이 없으면 아무것도 동작하지 않습니다. 브레이크아웃 보드나 라즈베리파이에는 대개 이미 달려 있습니다.

각 장치는 보통 **7비트 주소**를 갖습니다. 주소는 칩 제조사가 정하고, 몇 개의 핀으로 아래 비트 한두 개를 바꿀 수 있게 해 둔 칩이 많습니다. 속도는 표준 100kHz, 빠른 모드 400kHz가 흔하고, 더 빠른 모드도 있습니다.

## 한 번의 대화

센서의 레지스터를 읽는 대화를 흉내 내 봅니다. 가짜 센서는 주소 0x48에 있고, 0번 레지스터에 온도를 12비트로 담습니다(TI의 TMP102 같은 흔한 온도 센서와 비슷한 모양).

```c
#include <stdint.h>
#include <stdio.h>

// 가짜 온도 센서: 주소 0x48, 0번 레지스터가 온도
static uint8_t sensor_regs[4] = {0x17, 0x80, 0x00, 0x00};
static uint8_t sensor_ptr;          // 다음에 읽을 레지스터 번호
static int sensor_selected, sensor_reading, sensor_first;

static void start(void) { printf("S "); sensor_selected = 0; }
static void stop(void) { printf("P\n"); }

// 컨트롤러가 한 바이트를 보내고 ACK를 돌려받는다
static int send_byte(uint8_t b, int is_address)
{
    int ack = 0;
    if (is_address) {
        sensor_selected = (b >> 1) == 0x48;
        sensor_reading = b & 1;
        sensor_first = 1;
        ack = sensor_selected;
        printf("[%02X%s] ", b >> 1, (b & 1) ? "+R" : "+W");
    } else {
        if (sensor_selected && sensor_first)  // 쓰기의 첫 바이트는 번호
            sensor_ptr = b & 3;
        sensor_first = 0;
        ack = sensor_selected;
        printf("%02X ", b);
    }
    printf("%s ", ack ? "A" : "N");
    return ack;
}

static uint8_t read_byte(int ack_after)
{
    uint8_t b = sensor_regs[sensor_ptr];
    sensor_ptr = (sensor_ptr + 1) & 3;
    printf("<%02X> %s ", b, ack_after ? "A" : "N");
    return b;
}

static int read_reg16(uint8_t addr, uint8_t reg, uint16_t *out)
{
    start();
    if (!send_byte((uint8_t)(addr << 1 | 0), 1)) {
        stop();
        return -1;                  // 아무도 대답하지 않았다
    }
    send_byte(reg, 0);
    start();                        // 다시 시작(repeated start)
    send_byte((uint8_t)(addr << 1 | 1), 1);
    uint8_t hi = read_byte(1);
    uint8_t lo = read_byte(0);      // 마지막 바이트는 NACK로 끝낸다
    stop();
    *out = (uint16_t)(hi << 8 | lo);
    return 0;
}

int main(void)
{
    uint16_t raw;
    if (read_reg16(0x48, 0x00, &raw) == 0)
        printf("원시값 0x%04X -> %.4f도\n", raw, (raw >> 4) * 0.0625);
    if (read_reg16(0x50, 0x00, &raw) != 0)
        printf("0x50에는 장치가 없다\n");
    return 0;
}
```

```text
S [48+W] A 00 A S [48+R] A <17> A <80> N P
원시값 0x1780 -> 23.5000도
S [50+W] N P
0x50에는 장치가 없다
```

첫 줄을 기호대로 읽으면 이렇습니다.

1. `S` 시작: SCL이 높은 동안 SDA를 떨어뜨려 "지금부터 말한다"고 알린다
2. `[48+W]` 주소 7비트 뒤에 방향 비트 하나(0은 쓰기, 1은 읽기)를 붙인 바이트를 보낸다
3. `A` 그 주소의 장치가 다음 박자에 SDA를 0으로 끌어내려 "들었다"(ACK)고 답한다
4. `00` 읽고 싶은 레지스터 번호를 쓴다
5. `S` 멈추지 않고 **다시 시작**해서, 이번에는 읽기 방향(`[48+R]`)으로 같은 장치를 부른다
6. `<17> A <80> N` 장치가 보내는 바이트를 받으며, 더 받을 때는 ACK, 마지막 바이트에는 NACK로 "그만"이라고 답한다
7. `P` 정지: SCL이 높은 동안 SDA를 올려 버스를 놓아 준다

없는 주소 0x50을 부르면 아무도 SDA를 끌어내리지 않으므로 풀업 때문에 1, 곧 NACK가 읽힙니다. "장치가 응답하지 않는다"는 오류는 이렇게 생깁니다. 받은 0x1780은 앞 12비트가 온도이므로 4비트 밀어 0x178 = 376, 한 칸이 0.0625도라 23.5도입니다.

## 리눅스에서: /dev/i2c-N

리눅스는 I2C 버스마다 `/dev/i2c-N` 장치를 만들어 줍니다(커널의 `i2c-dev`). 위의 "번호 쓰기, 다시 시작, 읽기"를 끊김 없이 한 덩어리로 하려면 `I2C_RDWR` ioctl에 메시지 두 개를 넘깁니다.

```c norun
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <sys/ioctl.h>
#include <unistd.h>
#include <linux/i2c.h>
#include <linux/i2c-dev.h>

// 번호 쓰기 + 다시 시작 + 두 바이트 읽기를 한 번에
static int read_reg16(int fd, uint8_t addr, uint8_t reg, uint16_t *out)
{
    uint8_t buf[2];
    struct i2c_msg msgs[2] = {
        {.addr = addr, .flags = 0, .len = 1, .buf = &reg},
        {.addr = addr, .flags = I2C_M_RD, .len = 2, .buf = buf},
    };
    struct i2c_rdwr_ioctl_data xfer = {.msgs = msgs, .nmsgs = 2};
    if (ioctl(fd, I2C_RDWR, &xfer) < 0)
        return -1;
    *out = (uint16_t)(buf[0] << 8 | buf[1]);
    return 0;
}

int main(void)
{
    int fd = open("/dev/i2c-1", O_RDWR);
    if (fd < 0) {
        perror("/dev/i2c-1");
        return 1;
    }
    uint16_t raw;
    if (read_reg16(fd, 0x48, 0x00, &raw) != 0) {
        perror("I2C_RDWR");
        return 1;
    }
    printf("%.4f도\n", (raw >> 4) * 0.0625);
    close(fd);
    return 0;
}
```

이 검사용 컴퓨터에는 I2C 버스가 없어서 실행하면 `/dev/i2c-1: No such file or directory`만 나옵니다. 경고 없이 컴파일되는 것까지 gcc 14와 clang 18로 확인했습니다. 메시지 하나의 `flags`가 0이면 쓰기, `I2C_M_RD`면 읽기이고, 두 메시지 사이에 커널 드라이버가 다시 시작을 넣어 줍니다.

<Note>
라즈베리파이에서는 `raspi-config`로 I2C를 켜면 GPIO 2번(SDA)과 3번(SCL)이 버스 1, 곧 `/dev/i2c-1`이 됩니다. `i2c-tools` 패키지의 `i2cdetect -y 1`은 버스의 주소들을 차례로 불러 대답하는 장치를 표로 보여 줍니다. 배선을 확인할 때 가장 먼저 해 볼 일입니다. 다만 주소를 불러 보는 것만으로 이상하게 반응하는 장치도 드물게 있어서, 도움말에 그 경고가 적혀 있습니다.
</Note>

## 자주 겪는 문제

- **NACK, 장치가 없음**: 주소가 다르거나(데이터시트의 주소가 8비트로 적혀 있으면 한 비트 오른쪽으로 민 값이 7비트 주소), 선이 바뀌었거나, 전원이나 GND가 빠졌다
- **버스가 멈춤**: 읽던 도중 컨트롤러가 리셋되면 장치가 SDA를 0으로 쥐고 있을 수 있다. 장치 전원을 다시 넣거나, SCL을 몇 번 흔들어 풀어 준다
- **선이 길다**: I2C는 원래 한 기판 안의 칩끼리 쓰려고 만든 것이라, 선이 길어지면 신호가 무뎌져 빠른 속도에서 깨진다

## 정리

- I2C는 SCL과 SDA 두 선에 풀업 저항을 달고 여러 장치를 7비트 주소로 구분하며, 장치는 선을 끌어내리기만 한다
- 레지스터 읽기는 시작, 주소+쓰기, 번호, 다시 시작, 주소+읽기, 바이트들(마지막은 NACK), 정지의 순서이고, 대답이 없으면 NACK다
- 리눅스에서는 `/dev/i2c-N`을 열고 `I2C_RDWR`로 메시지를 묶어 보내며, `i2cdetect`로 배선부터 확인한다
