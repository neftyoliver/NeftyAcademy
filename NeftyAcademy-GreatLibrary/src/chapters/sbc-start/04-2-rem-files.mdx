PC에서 쓴 프로그램은 보드로 가야 하고, 보드가 모은 기록은 PC로 와야 합니다. 그 길에 쓰는 도구가 셋 있고, 셋 다 SSH 위에서 돕니다. [「SSH와 키 인증」](#/read/sbc-start/rem-ssh)에서 키를 등록하고 `~/.ssh/config`에 `sensor`라는 이름을 적어 두었다면 여기의 명령은 암호를 묻지 않습니다.

| 도구 | 하는 일 | 맞는 때 |
| --- | --- | --- |
| `scp` | 파일을 복사한다 | 실행 파일 하나, 설정 파일 하나 |
| `rsync` | 두 폴더를 같게 만든다. 달라진 것만 보낸다 | 프로젝트 폴더, 되풀이하는 배포 |
| `sshfs` | 보드의 폴더를 PC의 폴더로 붙인다 | PC의 편집기로 보드의 파일을 바로 고칠 때 |

## scp

```sh
scp hello sensor:            # PC의 hello 를 보드의 홈 폴더로
scp hello sensor:bin/        # 보드의 bin 폴더로
scp sensor:log.csv .         # 보드의 log.csv 를 PC의 지금 폴더로
scp -r data/ sensor:         # 폴더째로
```

- **콜론이 원격이라는 표시다**: `sensor:` 뒤가 비어 있으면 홈 폴더입니다. 콜론을 빠뜨리면 PC 안에 `sensor`라는 이름의 파일로 복사되고 아무 오류도 나지 않습니다
- **폴더는 만들어 주지 않는다**: 문서는 받는 쪽의 폴더를 미리 만들어 두라고 적습니다
- **빈칸이 든 이름**: `scp "my file.txt" sensor:`처럼 따옴표로 감쌉니다

## 빌드해서 보내고 돌리기

보드에서 돌릴 C 프로그램을 PC에서 만드는 한 바퀴는 세 줄입니다. 첫 줄은 [「교차 컴파일: PC에서 라즈베리파이용으로」](#/read/c-mid/build-cross)에서 깐 컴파일러를 씁니다.

```sh
aarch64-linux-gnu-gcc-14 -std=c23 -O2 hello.c -o hello    # 보드용으로 빌드
scp hello sensor:                                         # 보낸다
ssh sensor ./hello                                        # 보드에서 돌린다
```

보내기 전에 보드용으로 만들어졌는지 확인하려면 `file hello`를 칩니다.

```text
hello: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV), ...
```

- **ARM aarch64**: 64비트 Arm용이라는 뜻입니다. `x86-64`라고 나오면 PC용 컴파일러로 빌드한 것이고, 보드에서 돌지 않습니다
- **거꾸로도 돌지 않는다**: 이 파일을 PC에서 실행하면 `Exec format error`가 납니다
- **세 줄을 한 번에**: 익숙해지면 `Makefile`에 `deploy` 같은 목표를 만들어 묶어 둡니다([「Makefile」](#/read/c-mid/build-make))

## rsync

```sh
rsync -av proj/ sensor:proj/               # PC의 proj 안을 보드의 proj 안으로
rsync -avn --delete proj/ sensor:proj/     # 지울 것까지 미리 보기만 한다
rsync -av --delete proj/ sensor:proj/      # 실제로 맞춘다
rsync -av sensor:data/ data/               # 반대로, 보드의 data 를 PC로
```

둘째 줄처럼 `-n`을 붙이면 무엇을 할지만 알려 줍니다. `main.c`를 고치고, 받는 쪽에만 `stale.o`가 남아 있을 때의 출력은 이렇습니다.

```text
sending incremental file list
deleting stale.o
main.c

sent 94 bytes  received 33 bytes  254.00 bytes/sec
total size is 56  speedup is 0.44 (DRY RUN)
```

- **달라진 것만 보낸다**: 크기와 고친 시각이 같은 파일은 건너뜁니다. 위에서도 고치지 않은 `Makefile`은 목록에 없습니다
- **옵션**: `-a`는 하위 폴더, 권한, 시각을 그대로 옮기고, `-v`는 옮긴 것을 보여 줍니다. `--delete`는 보내는 쪽에 없는 파일을 받는 쪽에서 지웁니다
- **끝의 빗금**: `proj/`는 폴더 안의 것들이고 `proj`는 폴더 자체입니다. 보내는 쪽에 빗금을 빼면 받는 쪽에 `proj/proj`가 생깁니다
- **--delete는 먼저 미리 본다**: 방향을 거꾸로 적으면 원본이 지워집니다. `-n`으로 `deleting`에 무엇이 뜨는지 본 뒤에 실행합니다
- **양쪽에 깔려 있어야 한다**: `rsync`는 PC와 보드 양쪽에 있어야 합니다. Windows의 OpenSSH에는 들어 있지 않으므로 WSL 안에서 쓰거나 `scp`로 대신합니다

## sshfs

```sh
sudo apt install sshfs        # PC(리눅스)에 깐다
mkdir -p ~/sensor
sshfs sensor: ~/sensor        # 보드의 홈 폴더를 ~/sensor 에 붙인다
fusermount3 -u ~/sensor       # 뗀다
```

붙여 둔 동안에는 `~/sensor` 아래의 파일이 PC의 파일처럼 보입니다. 편집기로 열어 저장하면 보드의 파일이 바뀝니다.

- **보드에는 할 일이 없다**: SSH에 딸린 파일 전송 기능(SFTP)으로 돌기 때문에 보드에 따로 깔 것이 없습니다
- **파일 하나하나가 네트워크를 건넌다**: 작은 파일 몇 개를 고치는 데에는 좋지만, 폴더 전체를 훑는 검색이나 빌드는 느립니다. 빌드는 보드에 SSH로 들어가서 하거나, PC에서 해서 결과만 보냅니다
- **끊기면 멈춘다**: 연결이 끊기면 그 폴더를 건드린 프로그램이 멈춘 듯 보입니다. `-o reconnect`를 붙이면 다시 잇고, 한동안 쓰지 않을 때 끊기는 일은 `-o ServerAliveInterval=15`로 줄입니다

## 무엇을 어디에 두나

- **소스는 PC에**: 원본은 PC에 두고 Git으로 관리합니다([「Git 기초」](#/read/basics/git)). 보드에는 빌드한 결과와 설정만 보냅니다
- **보드에서 생긴 것은 가져온다**: 센서 기록처럼 보드에서 만들어지는 파일은 `rsync`로 PC에 모읍니다
- **카드는 언제든 새로 쓸 수 있게**: 보드에만 있는 파일이 없으면 카드가 망가져도 잃는 것이 없습니다([「이미지 통째로 백업하기」](#/read/sbc-start/care-backup))

<Note>
`scp`와 `sshfs`의 명령은 문서와 매뉴얼에서 옮겼고 직접 돌려 보지 못했습니다. 빌드와 `file`의 출력은 PC에서 확인했습니다. `rsync`의 출력은 보드가 아니라 PC 안의 두 폴더 사이에서 `rsync` 3.2.7로 돌려 얻은 것입니다. 원격으로 보낼 때에도 목록의 꼴은 같습니다.
</Note>

## 정리

- 파일 하나는 `scp`, 폴더는 `rsync`, 보드의 파일을 PC에서 바로 고치려면 `sshfs`를 쓴다
- PC에서 보드용으로 빌드하고, 보내고, SSH로 돌리는 세 줄이 개발의 한 바퀴다
- `rsync --delete`는 `-n`으로 먼저 미리 보고, 폴더 끝의 빗금이 뜻을 바꾼다는 것을 기억한다
