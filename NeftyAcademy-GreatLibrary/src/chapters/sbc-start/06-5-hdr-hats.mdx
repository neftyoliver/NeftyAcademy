40핀 헤더에 꽂아 보드 위에 얹는 확장 보드를 HAT이라고 부릅니다. Hardware Attached on Top을 줄인 말입니다. 핀에 선으로 이은 부품과 다른 점은 하나입니다. HAT은 자기가 무엇인지 적어 둔 작은 메모리를 달고 있어서, 꽂고 켜면 설정이 저절로 됩니다.

## 저절로 되는 까닭

- **ID EEPROM**: HAT에는 I2C로 읽는 작은 메모리가 달려 있고, GPIO 0과 1(핀 27과 28)에 이어져 있습니다. 이 두 핀의 이름이 ID_SD와 ID_SC이고, 규격은 여기에 이 메모리 말고는 아무것도 잇지 말라고 정합니다
- **펌웨어가 읽는다**: 켜질 때 펌웨어가 이 핀을 살펴 메모리를 읽고, 거기 적힌 디바이스 트리 오버레이를 얹습니다. `config.txt`에 `dtoverlay` 줄을 적지 않아도 드라이버가 붙는 까닭입니다([「dtoverlay로 기능 켜기」](#/read/sbc-start/cfg-overlays))
- **무엇이 적혀 있나**: 만든 곳의 이름, 제품의 이름, 제품마다 다른 UUID, 그리고 얹을 오버레이입니다

```sh
cat /proc/device-tree/hat/vendor      # 만든 곳
cat /proc/device-tree/hat/product     # 제품의 이름
```

- **확인하는 법**: 펌웨어가 읽은 것을 디바이스 트리의 `hat` 아래에 적어 둡니다. 이 폴더가 없다면 EEPROM이 없는 보드이거나 읽히지 않은 것입니다
- **막는 법**: `config.txt`에서 다른 `dtoverlay`나 `dtparam`보다 앞에 값이 없는 `dtoverlay=` 한 줄을 두면 HAT의 오버레이를 얹지 않습니다. `force_eeprom_read=0`은 메모리를 읽는 일부터 하지 않습니다. 오버레이를 손으로 고쳐 적고 싶을 때 씁니다

## HAT과 HAT+

2014년의 첫 규격이 HAT이고, 2023년 12월에 나온 새 규격이 HAT+입니다. 옛 규격은 폐기 예정이고 새 보드는 HAT+를 따르라고 문서는 적습니다. 옛 HAT도 지금의 보드에서 그대로 돕니다.

| 달라진 것 | 내용 |
| --- | --- |
| 대기 상태 | 5V는 살아 있고 3.3V는 꺼진 상태를 견뎌야 한다. 4와 그 뒤의 보드가 이 상태를 쓴다 |
| EEPROM의 내용 | 단순해졌다. 오버레이의 내용이 아니라 이름만 적는다 |
| 크기 | 덜 까다롭게 정한다 |
| 쌓기 | 함께 얹을 수 있는 종류를 새로 정했다 |

HAT+는 EEPROM의 I2C 주소로 종류를 가립니다.

| 종류 | 주소 | 핀 |
| --- | --- | --- |
| 표준 HAT+, 옛 HAT | 0x50 | GPIO 2부터 27까지를 쓴다 |
| 쌓는 HAT+ | 0x51 | ID 핀만 쓰고 GPIO 2부터 27에는 잇지 않는다 |
| 전원 HAT+ | 0x52(3A쯤), 0x53(5A쯤) | 5V 핀으로 보드에 전원을 넣는다. GPIO는 쓰지 않는다 |

- **종류마다 하나씩, 셋까지**: 표준이나 옛 HAT 하나, 쌓는 것 하나, 전원 하나를 함께 얹을 수 있습니다. 같은 종류 둘은 같은 주소에서 답하므로 펌웨어가 가려 읽지 못합니다
- **전원 HAT+**: 5A쯤을 내는 것(0x53)을 알아보면 펌웨어가 USB 전류 한도를 올립니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **PoE HAT은 예외**: 라즈베리파이의 PoE HAT과 PoE+ HAT에는 EEPROM이 없습니다. 규격은 이 보드들이 다른 HAT+와 함께 될 수도, 안 될 수도 있다고 적습니다

## 함께 얹을 수 있는지 살피기

보드 둘을 겹쳐 얹으려 할 때 볼 것은 둘입니다. EEPROM의 종류가 겹치지 않는지, 그리고 같은 GPIO를 둘이 쓰지 않는지입니다. 아래 예제는 가상의 보드 여섯 개로 그 두 가지를 따집니다.

```c
// 얹으려는 보드들이 함께 올라갈 수 있는지 살핀다: EEPROM의 주소와 핀을 본다
#include <stdio.h>

#define P(n) (1u << (n))                     // 비트 n이 GPIO n이다
enum { I2C = P(2) | P(3), SPI = P(7) | P(8) | P(9) | P(10) | P(11),
       I2S = P(18) | P(19) | P(20) | P(21) };

// EEPROM의 I2C 주소가 보드의 종류다. 0은 EEPROM이 없는 보드
enum { NONE = 0, STANDARD = 0x50, STACKABLE = 0x51, POWER_3A = 0x52,
       POWER_5A = 0x53 };

struct board { const char* name; int eeprom; unsigned pins; };

static void check(const char* title, const struct board* b, int n) {
    int problems = 0;
    printf("%s\n", title);
    for (int i = 0; i < n; ++i) {
        printf("  %s", b[i].name);
        if (b[i].eeprom) printf(" (0x%x)", b[i].eeprom);
        printf("\n");
    }
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            bool both_power = b[i].eeprom >= POWER_3A && b[j].eeprom >= POWER_3A;
            if (b[i].eeprom && (b[i].eeprom == b[j].eeprom || both_power)) {
                printf("  -> 같은 종류가 둘이다: %s, %s\n", b[i].name, b[j].name);
                ++problems;
            }
            // I2C의 두 핀은 주소가 다른 부품끼리 나눠 쓰는 버스라서 겹쳐도 된다
            unsigned clash = b[i].pins & b[j].pins & ~(unsigned)I2C;
            for (int gpio = 2; gpio < 28; ++gpio) {
                if (!(clash & P(gpio))) continue;
                printf("  -> GPIO%d에서 겹친다: %s, %s\n", gpio, b[i].name,
                       b[j].name);
                ++problems;
            }
        }
    }
    if (!problems) printf("  -> 함께 얹을 수 있다\n");
}

int main(void) {
    const struct board sensor = {"센서 보드", STANDARD, I2C};
    const struct board sound = {"소리 보드", STANDARD, I2C | I2S};
    const struct board drive = {"저장 장치 보드", STACKABLE, 0};
    const struct board power = {"전원 보드", POWER_5A, 0};
    const struct board motor = {"모터 보드", NONE, I2C | P(12) | P(13) | P(18)};
    const struct board screen = {"화면 보드", NONE, I2C | SPI | P(24) | P(25)};

    const struct board a[] = {sensor, drive, power};
    const struct board b[] = {sensor, sound};
    const struct board c[] = {sound, motor};
    const struct board d[] = {sensor, screen};
    check("종류가 다른 셋", a, 3);
    check("표준 보드 둘", b, 2);
    check("소리와 모터", c, 2);
    check("센서와 화면", d, 2);
}
```

```text
종류가 다른 셋
  센서 보드 (0x50)
  저장 장치 보드 (0x51)
  전원 보드 (0x53)
  -> 함께 얹을 수 있다
표준 보드 둘
  센서 보드 (0x50)
  소리 보드 (0x50)
  -> 같은 종류가 둘이다: 센서 보드, 소리 보드
소리와 모터
  소리 보드 (0x50)
  모터 보드
  -> GPIO18에서 겹친다: 소리 보드, 모터 보드
센서와 화면
  센서 보드 (0x50)
  화면 보드
  -> 함께 얹을 수 있다
```

- **I2C는 나눠 쓴다**: GPIO 2와 3의 I2C는 주소가 다른 부품끼리 함께 쓰는 버스입니다. 예제가 이 두 핀을 겹침에서 뺀 까닭입니다. 다만 두 보드의 부품이 같은 I2C 주소를 쓰면 그것은 따로 부딪칩니다
- **SPI도 나눠 쓸 수 있다**: 클럭과 데이터 선은 함께 쓰고 칩 선택(CE0, CE1)만 달라야 합니다. 예제는 이것까지 가리지 않고 겹침으로 칩니다
- **EEPROM이 없는 보드**: 종류의 규칙에는 걸리지 않습니다. 대신 저절로 되는 것이 없어서 `config.txt`에 오버레이를 손으로 적어야 하고, 핀이 겹치는지도 스스로 따져야 합니다
- **보드가 쓰는 핀을 아는 법**: 파는 곳의 자료에 핀 표가 있습니다. 없다면 그 보드의 오버레이가 README에서 어떤 핀을 받는지 봅니다([「핀의 대체 기능: I2C, SPI, UART, PWM」](#/read/sbc-start/hdr-functions))

## 얹기 전에 볼 것

- **전원을 뺀다**: 문서는 HAT을 꽂기 전에 반드시 전원에서 떼라고 적습니다. 꽂는 순간 전원 칩이 다시 시작될 수 있습니다
- **한 줄 밀려 꽂지 않는다**: 마흔 개의 핀이 모두 들어갔는지 옆에서 봅니다. 한 줄이나 한 칸 밀리면 5V가 GPIO에 닿습니다([「3.3V 논리와 전류 한계」](#/read/sbc-start/hdr-voltage))
- **높이**: 규격은 받침 기둥을 15mm 이상, 되도록 16mm로 권합니다. 5에 쿨러를 단 채로 얹으려면 핀이 긴 헤더가 있어야 닿습니다
- **가리는 것**: 카메라, 디스플레이, PCIe 케이블의 자리와 팬의 바람길을 HAT이 덮지 않는지 봅니다
- **Zero 크기의 보드**: Zero에 맞춘 작은 보드는 pHAT이나 Bonnet 같은 이름으로 팔립니다. 규격의 이름이 아니라 만든 회사들이 붙인 이름이고, EEPROM이 없는 것도 많습니다
- **다른 회사의 보드에 얹을 때**: 핀 자리가 같다고 적힌 보드라도 HAT의 오버레이와 드라이버가 그 보드의 커널에 있어야 돕니다([「비슷한 급의 다른 보드들」](#/read/sbc-start/brd-others))

## 직접 만든 보드를 HAT으로

EEPROM에 넣을 내용을 만드는 `eepmake`, 읽어서 풀어 주는 `eepdump`, 써 넣는 `eepflash.sh`가 라즈베리파이의 utils 저장소에 있습니다. 내 보드의 오버레이를 쓰는 법은 이 서가의 「임베디드 리눅스 시스템」에서 다룹니다.

<Note>
규칙들은 HAT+ 규격서(2024년 12월 판)와 공식 문서에서 옮겼습니다. 예제의 보드는 가상의 것이고, 실제 제품이 어느 종류인지는 그 제품의 자료에서 확인해야 합니다. 예제는 주소와 핀의 겹침만 봅니다. 보드끼리 모양이 맞는지, 전류가 모자라지 않는지는 보지 않습니다. `/proc/device-tree/hat`의 이름들은 옛 HAT 규격의 안내서에 실린 것입니다.
</Note>

## 정리

- HAT은 GPIO 0과 1에 달린 ID EEPROM으로 자기를 알리고, 펌웨어가 그것을 읽어 오버레이를 얹는다
- HAT+는 표준(0x50), 쌓는 것(0x51), 전원(0x52, 0x53)으로 나뉘고 종류마다 하나씩 셋까지 함께 얹는다
- 얹기 전에 전원을 빼고, 핀이 밀리지 않았는지와 다른 보드와 GPIO가 겹치지 않는지를 본다
