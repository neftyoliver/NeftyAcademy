보드의 설정은 한곳에 모여 있지 않습니다. 부트 파티션의 `config.txt`와 `cmdline.txt`, 부트로더가 든 EEPROM, 리눅스의 여러 설정 파일에 흩어져 있습니다. `raspi-config`는 자주 바꾸는 것들을 메뉴 하나로 모아 놓은 도구입니다. 고를 때마다 알맞은 파일을 대신 고쳐 줍니다. 이 쪽은 메뉴를 다루는 법과, 메뉴 뒤에서 무엇이 바뀌는지를 봅니다.

## 띄우고 움직이기

```sh
sudo raspi-config
```

글자 화면에서 도는 도구라서 SSH로 들어간 터미널에서도 그대로 뜹니다.

| 키 | 하는 일 |
| --- | --- |
| 위아래 화살표 | 항목 사이를 움직인다 |
| Enter | 고른다 |
| Tab, 오른쪽 화살표 | 아래의 Select, Finish 같은 단추로 간다 |
| 글자 | 그 글자로 시작하는 항목으로 건너뛴다. 시간대처럼 긴 목록에서 쓴다 |

다 바꿨으면 Finish로 나옵니다. 다시 켜야 적용되는 것을 바꿨다면 나올 때 다시 시작할지 묻습니다.

## 메뉴의 지도

| 메뉴 | 든 것 | 이 책에서 쓰는 곳 |
| --- | --- | --- |
| System Options | Hostname, Password, Boot, Auto Login | 이름을 바꾸거나 데스크톱과 글자 화면을 바꿀 때 |
| Display Options | Screen Blanking 같은 화면 설정 | 모니터를 붙였을 때 |
| Interface Options | SSH, VNC, SPI, I2C, Serial Port, 1-Wire | 핀과 버스를 켤 때. 가장 자주 온다 |
| Performance Options | Overlay File System, Fan, USB Current | 카드 보호, 팬, USB 전류 |
| Localisation Options | Locale, Timezone, Keyboard, WLAN Country | 시간대와 Wi-Fi의 나라 |
| Advanced Options | Expand Filesystem, Boot Order, Bootloader Version | 부팅 순서와 부트로더 |

- **항목은 보드와 판마다 다르다**: 보드에 없는 기능의 항목은 보이지 않고, 번호도 OS의 판에 따라 바뀝니다. 번호보다 이름으로 찾습니다
- **데스크톱에도 같은 것이 있다**: 데스크톱 판에서는 Preferences의 Control Centre가 같은 설정을 창으로 보여 줍니다

## 켜면 무엇이 바뀌나

메뉴에서 켜는 것은 결국 파일의 한 줄입니다. 어떤 줄인지 알아 두면 메뉴 없이도 고칠 수 있고, 다른 보드에 같은 설정을 옮길 수 있습니다.

| 메뉴의 항목 | 뒤에서 바뀌는 것 |
| --- | --- |
| I2C | `config.txt`에 `dtparam=i2c_arm=on` |
| SPI | `config.txt`에 `dtparam=spi=on` |
| Serial Port | `config.txt`의 `enable_uart`와 `cmdline.txt`의 `console=serial0,115200` |
| Hostname | 리눅스의 `/etc/hostname` |
| Boot Order | 부트로더 EEPROM의 `BOOT_ORDER` |

- **I2C를 켰을 때**: 위의 줄과 함께, 프로그램이 버스를 쓸 수 있게 해 주는 커널 모듈이 켜질 때마다 올라오도록 설정됩니다. 다시 켜면 `/dev/i2c-1`이 생깁니다([「핀의 대체 기능: I2C, SPI, UART, PWM」](#/read/sbc-start/hdr-functions))
- **다시 켜야 하는 까닭**: `config.txt`, `cmdline.txt`, EEPROM은 켜질 때 한 번 읽습니다. 이 파일들을 건드리는 항목은 다시 시작해야 적용됩니다
- **파일들의 문법**: [「config.txt와 cmdline.txt」](#/read/sbc-start/cfg-config-txt), [「dtoverlay로 기능 켜기」](#/read/sbc-start/cfg-overlays), [「부트로더 EEPROM과 부팅 순서」](#/read/sbc-start/cfg-eeprom)에서 차례로 봅니다

## 명령 한 줄로: nonint

메뉴를 거치지 않고 명령 한 줄로 같은 일을 시킬 수 있습니다. `nonint`는 묻지 않고 한다는 뜻입니다.

```sh
sudo raspi-config nonint do_i2c 0            # I2C를 켠다
sudo raspi-config nonint do_spi 0            # SPI를 켠다
sudo raspi-config nonint do_serial_hw 0      # 시리얼 포트의 하드웨어를 켠다
sudo raspi-config nonint do_serial_cons 1    # 시리얼 콘솔은 끈다
```

- **0이 켜기다**: 위의 넷에서는 0이 켜기이고 1이 끄기입니다. 셸에서 0이 성공인 것과 같은 방향이라 처음에는 헷갈립니다. 옛 문서는 0과 1의 뜻이 항목마다 다르다고 경고했으므로, 처음 쓰는 항목은 결과를 확인합니다
- **쓸모**: 보드 여러 대를 같은 설정으로 맞추거나, 카드를 새로 쓴 뒤 설정을 한 번에 되돌릴 때 이 줄들을 스크립트로 모아 둡니다
- **cloud-init도 이 명령을 부른다**: [「모니터 없이 설정하기: Wi-Fi, SSH, 사용자」](#/read/sbc-start/os-headless)에서 본 `rpi` 아래의 `i2c: true` 같은 키는 처음 켜질 때 이 명령으로 바뀝니다
- **항목의 이름 찾기**: `raspi-config`는 `/usr/bin/raspi-config`에 있는 셸 스크립트입니다. `grep -o 'do_[a-z_0-9]*' /usr/bin/raspi-config | sort -u`로 `do_`로 시작하는 이름들을 뽑아 볼 수 있습니다

<Note>
지금의 공식 문서는 메뉴 전체와 `nonint`의 목록을 싣고 있지 않습니다. 이 쪽의 메뉴 이름은 문서 곳곳의 설명에 나오는 것을 모은 것이고, `nonint`의 이름과 0이 켜기라는 것은 cloud-init이 이 명령을 부르는 코드에서 확인했습니다. 직접 실행해 보지는 못했으므로, 내 보드에서 이름이 다르면 스크립트에서 찾은 이름을 따릅니다.
</Note>

## 정리

- `raspi-config`는 여러 파일에 흩어진 설정을 메뉴로 모은 도구이고, 고를 때마다 알맞은 파일을 고쳐 준다
- 핀과 버스는 Interface Options에서 켜고, 켜면 `config.txt`에 한 줄이 들어간다
- `sudo raspi-config nonint`로 같은 일을 명령 한 줄에 할 수 있어 설정을 스크립트로 남길 수 있다
