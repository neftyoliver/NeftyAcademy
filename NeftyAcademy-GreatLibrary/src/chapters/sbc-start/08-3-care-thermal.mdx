보드가 까닭 없이 느려지거나 다시 시작할 때 먼저 의심할 것은 열과 전원입니다. 둘 다 눈에 보이지 않지만, 펌웨어가 켜진 뒤로 있었던 일을 적어 둡니다. 그 기록을 읽는 법과, 일부러 부하를 걸어 내 장치가 버티는지 재 보는 법을 봅니다. 식히는 부품을 고르는 이야기는 [「방열판과 팬」](#/read/sbc-start/prt-cooling)에 있습니다.

## 지금의 상태 보기

```sh
vcgencmd measure_temp          # 칩의 온도
vcgencmd measure_temp pmic     # 전원 칩의 온도. 4와 5에서 된다
vcgencmd get_throttled         # 열과 전압이 남긴 흔적
vcgencmd measure_clock arm     # 코어가 지금 도는 클럭
```

`get_throttled`의 값은 비트마다 뜻이 있는 16진수입니다.

| 비트 | 값 | 서 있으면 |
| --- | --- | --- |
| 0 | 0x1 | 지금 전압이 모자라다 |
| 1 | 0x2 | 지금 Arm 클럭의 상한을 낮췄다 |
| 2 | 0x4 | 지금 스로틀링 중이다 |
| 3 | 0x8 | 지금 소프트 온도 한도에 걸렸다 |
| 16 | 0x10000 | 켠 뒤로 전압이 모자란 적이 있다 |
| 17 | 0x20000 | 켠 뒤로 클럭의 상한을 낮춘 적이 있다 |
| 18 | 0x40000 | 켠 뒤로 스로틀링한 적이 있다 |
| 19 | 0x80000 | 켠 뒤로 소프트 온도 한도에 걸린 적이 있다 |

- **아래 넷은 지금, 위 넷은 지난 일**: 아래쪽 비트는 명령을 친 순간의 상태이고, 16번부터의 비트는 켠 뒤로 한 번이라도 있었으면 서서 다시 켤 때까지 남습니다
- **지난 일을 보는 쪽이 쓸모 있다**: 문제는 내가 보고 있지 않을 때 생깁니다. 며칠 돌린 뒤에 이 값을 보면 그동안 무슨 일이 있었는지 알 수 있습니다

## 값 풀기

여러 비트가 함께 서면 16진수로는 한눈에 읽히지 않습니다. 아래 예제가 값을 문장으로 풀어 줍니다.

```c
// vcgencmd get_throttled가 내놓는 값을 풀어 적는다
#include <stdio.h>

static const char* now[4] = {
    "전압이 모자라다", "Arm 클럭의 상한을 낮췄다", "스로틀링 중이다",
    "소프트 온도 한도에 걸렸다",
};
static const char* since_boot[4] = {
    "전압이 모자란 적이 있다", "Arm 클럭의 상한을 낮춘 적이 있다",
    "스로틀링한 적이 있다", "소프트 온도 한도에 걸린 적이 있다",
};

// "throttled=0x50005" 꼴의 한 줄을 받아 뜻을 적는다
static void decode(const char* line) {
    unsigned v = 0;
    if (sscanf(line, "throttled=%x", &v) != 1) {
        printf("%s\n  읽을 수 없는 줄이다\n", line);
        return;
    }
    printf("%s\n", line);
    if (v == 0) printf("  켠 뒤로 아무 일도 없었다\n");
    for (int bit = 0; bit < 4; ++bit)        // 0~3번 비트: 지금의 상태
        if (v >> bit & 1) printf("  지금 %s\n", now[bit]);
    for (int bit = 0; bit < 4; ++bit)        // 16~19번 비트: 켠 뒤로 있었던 일
        if (v >> (16 + bit) & 1) printf("  켠 뒤로 %s\n", since_boot[bit]);
}

int main(void) {
    const char* samples[] = {
        "throttled=0x0", "throttled=0x50000", "throttled=0x50005",
        "throttled=0xe0000", "throttled=0x4",
    };
    for (size_t i = 0; i < sizeof samples / sizeof samples[0]; ++i)
        decode(samples[i]);
}
```

```text
throttled=0x0
  켠 뒤로 아무 일도 없었다
throttled=0x50000
  켠 뒤로 전압이 모자란 적이 있다
  켠 뒤로 스로틀링한 적이 있다
throttled=0x50005
  지금 전압이 모자라다
  지금 스로틀링 중이다
  켠 뒤로 전압이 모자란 적이 있다
  켠 뒤로 스로틀링한 적이 있다
throttled=0xe0000
  켠 뒤로 Arm 클럭의 상한을 낮춘 적이 있다
  켠 뒤로 스로틀링한 적이 있다
  켠 뒤로 소프트 온도 한도에 걸린 적이 있다
throttled=0x4
  지금 스로틀링 중이다
```

- **0x50000은 자주 보이는 값이다**: 전압이 모자란 적이 있고 스로틀링한 적이 있다는 뜻입니다. 전원이나 케이블을 의심합니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **0x1이 보이면 전원부터**: 전압이 모자란 보드에서는 다른 증상도 믿을 수 없습니다. 열을 따지기 전에 전원을 고칩니다
- **0x4만 보이면 열이다**: 전압의 비트는 깨끗한데 스로틀링의 비트가 서 있다면 식히는 쪽을 봅니다
- **소프트 온도 한도**: 80도보다 낮게 둔 또 하나의 한도입니다. 문서가 이 한도를 설명하는 보드는 60도로 정해 둔 3 Model B+입니다

## 부하를 걸고 지켜보기

```sh
while true; do
    echo "$(date +%T) $(vcgencmd measure_temp) $(vcgencmd get_throttled)"
    sleep 10
done | tee thermal.log
```

- **창을 둘 연다**: SSH 창 하나에서 위 반복을 돌려 두고, 다른 창에서 부하를 겁니다. 10초마다 시각과 온도와 흔적이 한 줄씩 쌓입니다
- **부하 걸기**: `sudo apt install stress`로 깔고 `stress --cpu 4`를 치면 네 코어가 쉬지 않고 돕니다. 내 프로그램이 있다면 그것을 가장 바쁘게 돌리는 편이 더 맞는 시험입니다
- **볼 것은 어디서 멈추는가**: 온도는 오르다가 어느 값에서 멈춥니다. 그 값이 80도 아래면 그 구성으로 충분합니다. 80도를 넘어 0x4가 서기 시작하면 식히는 것을 더하거나 일을 줄입니다
- **쓸 모습 그대로 잰다**: 케이스의 뚜껑을 닫고, 장치가 놓일 자리에서, 15분 넘게 돌립니다. 책상 위에서 맨 보드로 잰 값은 여름날 상자 안의 값과 다릅니다
- **끝난 뒤에도 본다**: 부하를 멈춘 뒤 온도가 내려오는 빠르기도 식히는 힘을 말해 줍니다

## 리눅스 쪽에서 읽는 숫자

```sh
# 온도. 1000분의 1도라서 47200이면 47.2도다
cat /sys/class/thermal/thermal_zone0/temp
# 코어 하나가 지금 도는 클럭(kHz)
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
```

- **파일이라 프로그램에서 읽기 쉽다**: 명령을 띄우지 않고 파일을 열어 숫자를 읽으면 됩니다. 문서는 칩의 온도를 바로 읽는 `vcgencmd` 쪽이 더 정확하다고 적습니다
- **기록에 함께 남긴다**: 센서 값을 적는 프로그램이라면 보드의 온도도 한 칸에 함께 적어 둡니다. 나중에 값이 튀었을 때 보드가 뜨거웠는지부터 볼 수 있습니다
- **클럭이 내려가 있다면**: 한가할 때 클럭이 낮은 것은 전기를 아끼느라 그런 것이고 정상입니다. 바쁜데도 최고값에 못 미친다면 위의 흔적을 봅니다

<Note>
비트의 뜻과 명령은 공식 문서의 vcgencmd 절에서 옮겼습니다. 예제는 본보기로 고른 값을 푸는 것이고, 보드에서 얻은 값이 아닙니다. 어떤 구성에서 온도가 얼마까지 오르는지는 보드와 케이스와 방의 온도에 달려 있어서 직접 재 봐야 압니다. `/sys` 아래의 두 파일은 리눅스 커널이 내주는 것입니다.
</Note>

## 정리

- `vcgencmd get_throttled`의 아래 네 비트는 지금의 상태, 16번부터의 네 비트는 켠 뒤로 있었던 일이다
- 전압의 비트가 보이면 전원부터 고치고, 스로틀링의 비트만 보이면 식히는 쪽을 본다
- 쓸 모습 그대로 부하를 걸어 온도가 어디서 멈추는지를 재 둔다
