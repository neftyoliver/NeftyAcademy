USB 단자는 데이터와 전원을 함께 나릅니다. PC에서는 전원 쪽을 걱정할 일이 드물지만, 보드에서는 USB 장치가 쓰는 전류가 보드와 같은 전원 하나에서 나옵니다. 꽂은 장치가 많아지면 전압이 내려가고, 그것이 까닭 모르게 멈추거나 다시 시작하는 일로 나타납니다.

## 단자의 종류

| 보드 | 단자 | 알아 둘 것 |
| --- | --- | --- |
| 5 | USB 3.0 둘(파랑), USB 2.0 둘(검정) | 3.0 두 단자가 함께 5Gb/s씩 낸다 |
| 4 Model B | USB 3.0 둘, USB 2.0 둘 | 네 단자의 USB 2.0 선이 허브 하나를 나눠 쓴다 |
| Zero 2 W | micro USB 하나(OTG) | 장치를 꽂으려면 OTG 어댑터가 있어야 한다 |

- **파란 단자에는 빠른 장치를**: SSD와 카메라처럼 데이터가 많은 장치는 3.0 단자에, 키보드와 마우스와 동글은 2.0 단자에 꽂습니다
- **4의 나눠 쓰기**: 문서는 4에서 USB 1.1과 2.0 장치들이 2.0 단자 하나의 대역을 함께 나눠 쓴다고 적습니다. 2.0 카메라 여러 대를 한꺼번에 돌리면 여기서 막힙니다
- **Zero 2 W**: USB라고 적힌 쪽이 데이터 단자이고 PWR IN이라고 적힌 쪽은 전원만 받습니다. 모든 통신이 480Mb/s 안에서 이뤄집니다
- **속도 확인**: `lsusb -t`가 장치마다 어느 단자에 어떤 속도로 붙었는지를 나무 모양으로 보여 줍니다. 5Gb/s 장치가 480M으로 보이면 2.0 단자에 꽂혔거나 케이블이 2.0용입니다

## 단자들이 함께 낼 수 있는 전류

| 보드 | USB 단자의 합 | 조건 |
| --- | --- | --- |
| 5 | 1.6A | 5V 5A를 내는 USB-PD 전원일 때 |
| 5 | 600mA | 그보다 작은 전원일 때 |
| 4 Model B | 1.2A | |
| Zero 2 W | 따로 정한 한도가 없다 | 전원과 단자가 버티는 만큼 |

- **5는 전원에 따라 달라진다**: 5A를 약속받지 못하면 USB 쪽을 600mA로 묶습니다. 이때는 USB 저장 장치로 부팅하는 것도 꺼 둡니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **팬도 같은 주머니다**: 5에서는 팬 단자가 이 한도를 USB와 함께 나눠 씁니다
- **지금의 설정 보기**: `vcgencmd get_config usb_max_current_enable`이 1이면 높은 한도, 0이면 낮은 한도입니다
- **손으로 올리기**: `config.txt`의 `usb_max_current_enable=1`은 전원과 말을 맞추지 않고 높은 한도를 켭니다. 전원이 정말로 5A를 낼 때에만 씁니다. 그렇지 않으면 한도만 올라가고 전압이 주저앉습니다

## 전력 예산 짜기

전원이 내는 전류에서 보드가 쓰는 것과 붙인 장치들이 쓰는 것을 빼 봅니다. 따질 것은 둘입니다. USB 장치의 합이 위의 한도 안인지, 그리고 모두 합한 것이 전원의 용량 안인지입니다.

```c
// 전력 예산: 전원이 내는 전류에서 보드와 주변 장치가 쓰는 전류를 빼 본다
#include <stdio.h>
#include <string.h>

struct part { const char* name; int ma; bool usb; };

// 문서의 표에 실린 보드만의 대표 전류(mA)
static int bare(const char* board) {
    if (strcmp(board, "5") == 0) return 800;
    if (strcmp(board, "4") == 0) return 600;
    return 350;                              // Zero 2 W
}

// USB 단자들이 함께 낼 수 있는 전류(mA). 0은 따로 정한 한도가 없다는 뜻
static int usb_cap(const char* board, int supply_ma) {
    if (strcmp(board, "5") == 0) return supply_ma >= 5000 ? 1600 : 600;
    if (strcmp(board, "4") == 0) return 1200;
    return 0;
}

static void plan(const char* board, int supply_ma, const struct part* parts,
                 int n) {
    int usb = 0, all = bare(board);
    for (int i = 0; i < n; ++i) {
        all += parts[i].ma;
        if (parts[i].usb) usb += parts[i].ma;
    }
    int cap = usb_cap(board, supply_ma);
    printf("%s + %dA 전원\n", board, supply_ma / 1000);
    if (cap)
        printf("  USB 장치 %4dmA / 한도 %4dmA  %s\n", usb, cap,
               usb > cap ? "넘는다" : "괜찮다");
    else
        printf("  USB 장치 %4dmA / 한도가 따로 없다\n", usb);
    printf("  모두     %4dmA / 전원 %4dmA  ", all, supply_ma);
    if (all > supply_ma) printf("%dmA 모자란다\n", all - supply_ma);
    else printf("%dmA 남는다\n", supply_ma - all);
}

int main(void) {
    const struct part desk[] = {             // 저장 장치와 카메라를 단 구성
        {"카메라 모듈", 250, false}, {"팬", 60, false}, {"HDMI", 50, false},
        {"USB 3.0 SSD", 900, true},  {"USB 키보드", 100, true},
    };
    const struct part two_drives[] = {
        {"USB 3.0 HDD", 900, true}, {"USB 3.0 SSD", 900, true},
        {"카메라 모듈", 250, false},
    };
    const struct part field[] = {
        {"카메라 모듈", 250, false}, {"USB LTE 모뎀", 500, true},
    };
    plan("5", 5000, desk, 5);
    plan("5", 3000, desk, 5);
    plan("4", 3000, two_drives, 3);
    plan("Zero 2 W", 2000, field, 2);
}
```

```text
5 + 5A 전원
  USB 장치 1000mA / 한도 1600mA  괜찮다
  모두     2160mA / 전원 5000mA  2840mA 남는다
5 + 3A 전원
  USB 장치 1000mA / 한도  600mA  넘는다
  모두     2160mA / 전원 3000mA  840mA 남는다
4 + 3A 전원
  USB 장치 1800mA / 한도 1200mA  넘는다
  모두     2650mA / 전원 3000mA  350mA 남는다
Zero 2 W + 2A 전원
  USB 장치  500mA / 한도가 따로 없다
  모두     1100mA / 전원 2000mA  900mA 남는다
```

- **먼저 걸리는 것은 USB의 한도다**: 5에 3A 전원을 쓴 둘째 구성은 전체로는 840mA가 남지만 USB 쪽이 넘칩니다. 보드가 바쁠 때 쓸 몫을 남겨 두려고 USB를 낮게 묶어 둔 것입니다
- **보드의 전류는 대표값이다**: 800mA, 600mA, 350mA는 문서의 표에 실린 보드만의 대표 전류입니다. 코어 넷이 모두 일하면 이보다 훨씬 더 씁니다. 남는 전류가 넉넉해 보여도 여유를 깎아서 읽습니다
- **장치의 전류는 최대값이다**: USB 2.0 장치는 500mA까지, USB 3.0 장치는 900mA까지 요구할 수 있습니다. 예제는 이 값을 넣었습니다. 실제로는 대개 덜 쓰지만, 디스크가 돌기 시작하는 순간에는 이만큼 당깁니다
- **헤더로 나가는 것도 넣는다**: 5V 핀에서 먹이는 모터 드라이버나 LED 띠도 같은 전원에서 나갑니다([「3.3V 논리와 전류 한계」](#/read/sbc-start/hdr-voltage))

## 장치가 요구하는 전류 보기

```sh
lsusb                                 # 붙은 장치의 목록
lsusb -t                              # 어느 단자에 어떤 속도로 붙었는지
sudo lsusb -v 2>/dev/null | grep -E '^Bus|MaxPower'    # 장치마다 요구하는 최대 전류
```

- **MaxPower**: 장치가 스스로 적어 낸 최대 전류입니다. 잰 값이 아니라 장치의 신고입니다. 예산을 짤 때 이 값을 씁니다
- **스스로 전원을 받는 장치**: 어댑터가 따로 달린 디스크나 허브는 0mA나 작은 값을 적습니다

## 모자랄 때의 증상과 처방

- **증상**: 디스크가 떨어졌다 붙기를 되풀이합니다. 무선 동글이 끊깁니다. 카메라를 켜는 순간 보드가 다시 시작합니다. 커널 로그에 저전압 경고가 남습니다. 문서는 전압이 4.63V 아래로 내려가면 기록된다고 적습니다
- **확인**: `vcgencmd get_throttled`의 값에 0x1이나 0x10000 비트가 서 있으면 전압이 모자랐던 것입니다([「온도와 스로틀링 확인하기」](#/read/sbc-start/care-thermal))
- **전원 달린 허브**: 디스크처럼 많이 쓰는 장치는 어댑터가 따로 있는 허브에 꽂습니다. 장치의 전류가 보드를 거치지 않습니다
- **허브가 보드를 먹이지 않게**: 질이 나쁜 허브는 보드 쪽으로 전류를 거꾸로 흘립니다. 문서는 이것이 보드의 보호 회로를 건너뛴다며 쓰지 말라고 적습니다
- **전원을 키운다**: 5라면 5A를 내는 공식 전원으로 바꾸는 것이 가장 간단합니다

<Note>
한도와 대표 전류는 공식 문서의 표에서 옮겼습니다. 예제는 그 숫자를 더하고 빼는 어림이고, 보드에서 전류를 재 본 것이 아닙니다. 장치 이름에 붙인 900mA와 500mA는 USB 규격이 허락하는 최대값이지 그 제품의 값이 아닙니다. `lsusb`는 리눅스의 일반 명령이며, 이 검사 환경에는 USB 버스가 없어 출력을 싣지 못했습니다.
</Note>

## 정리

- USB 단자들이 함께 낼 수 있는 전류는 5가 1.6A(작은 전원에서는 600mA), 4가 1.2A다
- 예산은 USB 장치의 합과 전체의 합을 따로 따진다. 장치가 요구하는 값은 `lsusb -v`의 MaxPower에 있다
- 모자라면 전원 달린 허브로 장치의 전류를 보드 밖으로 빼거나 전원을 키운다
