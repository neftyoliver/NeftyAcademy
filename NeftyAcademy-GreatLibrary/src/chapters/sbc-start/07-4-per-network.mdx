모니터 없이 쓰는 보드는 네트워크가 유일한 창입니다. 네트워크가 끊기면 보드가 멀쩡히 돌고 있어도 닿을 길이 없습니다. 유선과 무선 가운데 무엇을 쓸지, 붙었는지 어떻게 확인하는지, 안 붙을 때 어디를 볼지를 봅니다.

## 보드마다의 사양

| 보드 | 유선 랜 | Wi-Fi | 블루투스 |
| --- | --- | --- | --- |
| 5 | 기가비트 | 2.4GHz와 5GHz(802.11ac) | 5.0 |
| 4 Model B | 기가비트 | 2.4GHz와 5GHz(802.11ac) | 5.0 |
| Zero 2 W | 없음 | 2.4GHz | 4.2 |

- **둘 다 되면 유선을 쓴다**: 자리가 정해진 장치는 랜선이 가장 덜 끊깁니다. Wi-Fi는 선을 끌 수 없는 자리에 씁니다
- **Zero 2 W는 5GHz가 안 된다**: 공유기가 두 대역에 다른 이름을 쓰고 있다면 2.4GHz 쪽 이름으로 잇습니다
- **무선의 원리**: 대역과 채널, 암호가 키로 바뀌는 과정은 「C 언어 중급」의 [「Wi-Fi」](#/read/c-mid/iot-wifi)에 있습니다

## 유선 랜

```sh
ip -br addr                       # 인터페이스마다의 상태와 주소
cat /sys/class/net/eth0/speed     # 맺은 속도(Mb/s). 1000이면 기가비트다
```

- **꽂으면 된다**: 공유기가 주소를 내주므로 설정할 것이 없습니다. `ip -br addr`의 `eth0` 줄에 `UP`과 주소가 보이면 붙은 것입니다
- **100으로 나올 때**: 케이블이 낡았거나 맞은편 단자가 100Mb/s짜리입니다. 선 여덟 가닥이 모두 살아 있어야 기가비트가 됩니다
- **랜선으로 전원까지**: 5와 4에는 PoE용 4핀 헤더가 있고, PoE+ HAT을 얹으면 랜선 하나로 전원과 데이터를 함께 받습니다. 맞은편의 스위치가 PoE를 내줘야 합니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))
- **Zero 2 W에 유선을**: OTG 어댑터에 USB 랜 어댑터를 꽂습니다

## Wi-Fi 잇기

Raspberry Pi OS의 네트워크는 NetworkManager가 맡고, 명령줄에서는 `nmcli`로 다룹니다. Imager에서 Wi-Fi를 적어 두었다면([「모니터 없이 설정하기: Wi-Fi, SSH, 사용자」](#/read/sbc-start/os-headless)) 이미 이어져 있습니다. 나중에 망을 바꾸거나 더할 때 아래 명령을 씁니다.

```sh
nmcli radio wifi                                   # 무선이 켜져 있는지
nmcli dev wifi list                                # 보이는 망과 신호 세기
sudo nmcli --ask dev wifi connect "workshop"       # 암호를 물어보고 잇는다
nmcli --fields AUTOCONNECT-PRIORITY,NAME connection   # 기억해 둔 망과 우선순위
```

- **이어졌는지**: `nmcli dev wifi list`의 IN-USE 칸에 별표가 붙은 망이 지금 쓰는 망입니다
- **암호가 틀리면**: 문서는 "Secrets were required, but not provided"라는 말이 나오면 암호가 틀린 것이라고 적습니다
- **숨은 망**: 이름을 알리지 않는 망은 끝에 `hidden yes`를 붙입니다
- **여러 망을 기억시키기**: 작업실과 현장의 망을 모두 이어 두면 보드가 보이는 쪽에 알아서 붙습니다. 둘 다 보일 때의 순서는 `sudo nmcli connection modify "workshop" connection.autoconnect-priority 10`처럼 숫자로 정하고, 큰 수가 먼저입니다
- **회사와 학교의 망**: 문서는 이 방법이 기업용 인증을 쓰는 망에서는 되지 않을 수 있다고 적습니다
- **주소를 고정하고 싶을 때**: 문서는 보드 쪽에서 `nmcli`로 주소를 박아 두는 것을 권하지 않습니다. 주소가 바뀌지 않아야 한다면 공유기에서 그 보드에 줄 주소를 예약해 두는 길이 있습니다

## WLAN 나라

- **정하지 않으면 무선이 꺼져 있다**: 쓸 수 있는 채널과 세기가 나라마다 달라서, 5GHz가 되는 보드는 나라를 정하기 전에는 무선을 켜지 않습니다. 문서가 드는 대상은 3 Model B+와 그 뒤의 보드입니다
- **정하는 곳**: Imager에서 고른 나라가 이것까지 정합니다. 나중에는 `sudo raspi-config`의 Localisation Options > WLAN Country입니다
- **망이 하나도 안 보일 때**: `nmcli radio wifi`가 `disabled`라면 `nmcli radio wifi on`으로 켜고, 그래도 안 되면 나라부터 봅니다

## 같은 망인지 따지기

PC에서 보드가 안 보일 때 가장 흔한 까닭은 둘이 다른 망에 있는 것입니다. 주소 뒤의 `/24` 같은 숫자가 프리픽스 길이이고, 그만큼의 앞쪽 비트가 같아야 같은 망입니다. 아래 예제가 그 계산을 합니다.

```c
// 두 주소가 같은 망에 있는지 따진다: 프리픽스 길이만큼의 앞쪽 비트가 같으면 같은 망
#include <stdint.h>
#include <stdio.h>

static uint32_t parse(const char* text) {
    unsigned a = 0, b = 0, c = 0, d = 0;
    sscanf(text, "%u.%u.%u.%u", &a, &b, &c, &d);
    return a << 24 | b << 16 | c << 8 | d;
}

static const char* show(uint32_t v, char out[16]) {
    snprintf(out, 16, "%u.%u.%u.%u", v >> 24, v >> 16 & 255, v >> 8 & 255, v & 255);
    return out;
}

static void check(const char* pc, const char* board, int prefix) {
    uint32_t mask = prefix ? ~UINT32_C(0) << (32 - prefix) : 0;
    uint32_t p = parse(pc), b = parse(board), net = p & mask;
    char t1[16], t2[16], t3[16];
    printf("PC %s/%d, 보드 %s\n", pc, prefix, board);
    printf("  PC의 망 %s, 쓸 수 있는 주소 %s ~ %s (%u개)\n", show(net, t1),
           show(net + 1, t2), show((net | ~mask) - 1, t3), ~mask - 1);
    if ((b & mask) == net)
        printf("  같은 망이다. 이름(.local)으로도 주소로도 닿는다\n");
    else if (b >> 16 == (169u << 8 | 254))
        printf("  보드가 주소를 받지 못해 스스로 붙인 주소다\n");
    else
        printf("  다른 망이다. 공유기를 거쳐야 닿고 이름(.local)은 안 통한다\n");
}

int main(void) {
    check("192.168.0.10", "192.168.0.37", 24);
    check("192.168.0.10", "192.168.1.37", 24);
    check("192.168.0.10", "169.254.12.7", 24);
    check("172.20.10.2", "172.20.10.3", 28);
    check("10.0.3.10", "10.0.7.20", 21);
}
```

```text
PC 192.168.0.10/24, 보드 192.168.0.37
  PC의 망 192.168.0.0, 쓸 수 있는 주소 192.168.0.1 ~ 192.168.0.254 (254개)
  같은 망이다. 이름(.local)으로도 주소로도 닿는다
PC 192.168.0.10/24, 보드 192.168.1.37
  PC의 망 192.168.0.0, 쓸 수 있는 주소 192.168.0.1 ~ 192.168.0.254 (254개)
  다른 망이다. 공유기를 거쳐야 닿고 이름(.local)은 안 통한다
PC 192.168.0.10/24, 보드 169.254.12.7
  PC의 망 192.168.0.0, 쓸 수 있는 주소 192.168.0.1 ~ 192.168.0.254 (254개)
  보드가 주소를 받지 못해 스스로 붙인 주소다
PC 172.20.10.2/28, 보드 172.20.10.3
  PC의 망 172.20.10.0, 쓸 수 있는 주소 172.20.10.1 ~ 172.20.10.14 (14개)
  같은 망이다. 이름(.local)으로도 주소로도 닿는다
PC 10.0.3.10/21, 보드 10.0.7.20
  PC의 망 10.0.0.0, 쓸 수 있는 주소 10.0.0.1 ~ 10.0.7.254 (2046개)
  같은 망이다. 이름(.local)으로도 주소로도 닿는다
```

- **주소는 `ip -br addr`에서**: `192.168.0.37/24`처럼 주소와 프리픽스가 함께 나옵니다. PC와 보드의 것을 나란히 놓고 봅니다
- **이름은 같은 망에서만**: `sensor-01.local`은 같은 망 안에서 서로 묻고 답해 찾는 이름입니다. 공유기 너머로는 건너가지 않습니다
- **169.254로 시작하는 주소**: 주소를 내줄 곳을 찾지 못해 스스로 붙인 것입니다. Raspberry Pi OS에서는 이 기능이 꺼져 있고, `raspi-config`의 Advanced Options > Link-local Fallback으로 켭니다. 켜 두면 공유기 없이 PC와 랜선 하나로 바로 이었을 때에도 서로 닿을 수 있습니다
- **휴대폰 핫스팟**: 넷째 예처럼 주소가 열몇 개뿐인 작은 망을 내주는 것이 있습니다. PC와 보드를 같은 핫스팟에 붙이면 같은 망입니다
- **손님용 Wi-Fi**: 같은 망이어도 기기끼리 말하지 못하게 막아 둔 망이 있습니다. 계산으로는 닿아야 하는데 안 닿는다면 이것을 의심합니다

## 블루투스

- **무엇에 쓰나**: 가까운 센서와 스마트폰을 잇는 일입니다. 전기를 적게 쓰는 블루투스 LE가 IoT에 쓰입니다. 구조는 「C 언어 중급」의 [「블루투스 LE」](#/read/c-mid/iot-ble)에 있고, 이 서가의 「BlueZ」가 프로그램으로 다루는 법을 한 권으로 다룹니다
- **손으로 해 보기**: 데스크톱에서는 블루투스 아이콘의 Add Device로 짝을 짓습니다. 명령줄에서는 `bluetoothctl`을 씁니다
- **4와 Zero 2 W에서는 UART를 하나 쓴다**: 블루투스 칩이 SoC의 UART에 붙어 있습니다. 헤더의 UART 이야기와 얽히는 까닭입니다([「라즈베리파이 5의 RP1」](#/read/sbc-start/hdr-rp1))

## 무선이 약할 때

- **금속이 가린다**: 보드의 안테나는 기판 위에 있습니다. 금속 케이스나 금속 상자 안에 넣으면 신호가 크게 줄어듭니다
- **절전 설정은 건드리지 않는다**: `raspi-config`에 WLAN Power Save가 있지만, 문서는 라즈베리파이의 기술자가 시키지 않았다면 바꾸지 말라고 적습니다
- **신호 세기 보기**: `nmcli dev wifi list`의 SIGNAL 칸이 0에서 100 사이의 세기입니다. 장치를 둘 자리에서 미리 재 봅니다

<Note>
사양과 명령은 공식 문서에서 옮겼습니다. 검사 환경에는 무선 장치도 NetworkManager도 없어서 `nmcli`를 돌려 보지 못했습니다. 망의 이름 `workshop`은 본보기입니다. 예제의 주소 계산은 IPv4의 규칙 그대로이고, 판정의 문장은 흔한 경우를 적은 것입니다. 공유기가 막아 둔 경우는 계산으로 알 수 없습니다.
</Note>

## 정리

- 5와 4는 기가비트 유선과 두 대역의 Wi-Fi가 있고, Zero 2 W는 2.4GHz Wi-Fi뿐이다
- Wi-Fi는 `nmcli dev wifi list`로 보고 `sudo nmcli --ask dev wifi connect`로 잇는다. 무선이 꺼져 있으면 WLAN 나라를 본다
- 보드가 안 보이면 PC와 보드의 주소와 프리픽스를 놓고 같은 망인지부터 따진다
