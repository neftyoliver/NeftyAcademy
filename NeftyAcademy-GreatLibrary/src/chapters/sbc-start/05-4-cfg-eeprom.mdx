전원을 넣으면 가장 먼저 도는 프로그램이 부트로더입니다. 4와 5에서는 이것이 SD카드가 아니라 보드에 붙은 작은 메모리(EEPROM)에 들어 있습니다. 그래서 카드가 없어도 화면에 진단을 띄울 수 있고, USB나 NVMe나 네트워크에서 부팅할 수 있으며, 어디를 먼저 찾을지를 설정으로 정할 수 있습니다. 이 설정은 카드가 아니라 보드에 남습니다.

## 어느 보드의 이야기인가

- **EEPROM에 부트로더가 든 보드**: 4 Model B와 그 뒤의 보드, 400과 그 뒤의 키보드형, CM4와 그 뒤의 컴퓨트 모듈입니다
- **그 밖의 보드**: Zero 2 W나 3 Model B+ 같은 보드는 부트 파티션의 `bootcode.bin`이 그 일을 합니다. 이 쪽의 명령은 그 보드들의 것이 아닙니다
- **켜지는 순서**: 칩 안의 ROM이 EEPROM의 부트로더를 올립니다. 부트로더는 메모리를 깨우고 자기 설정을 읽은 뒤, 설정에 적힌 순서대로 부팅할 곳을 찾습니다. [「config.txt와 cmdline.txt」](#/read/sbc-start/cfg-config-txt)는 그렇게 찾은 곳에서 읽힙니다

## 판 확인하고 올리기

```sh
sudo rpi-eeprom-update          # 지금 판과 새 판을 견준다
sudo rpi-eeprom-update -a       # 새 판을 올리도록 걸어 둔다. 다시 켤 때 올라간다
sudo rpi-eeprom-update -r       # 걸어 둔 것을 취소한다
vcgencmd bootloader_version     # 지금 도는 부트로더의 판
```

문서에 실린 첫 명령의 출력은 이런 꼴입니다. 4에서 받은 것이라 경로에 4의 칩 번호인 2711이 들어 있습니다.

```text
BOOTLOADER: update available
   CURRENT: Thu 18 Jan 13:59:23 UTC 2024 (1705586363)
    LATEST: Mon 22 Jan 10:41:21 UTC 2024 (1705920081)
   RELEASE: latest (/lib/firmware/raspberrypi/bootloader-2711/latest)
```

- **CURRENT와 LATEST**: 보드에 든 것과 새것의 날짜입니다. 다른 글이 부트로더가 어느 날짜 뒤의 것이어야 한다고 할 때 견줄 것이 CURRENT입니다. NVMe 부팅([「microSD와 NVMe」](#/read/sbc-start/prt-storage))과 우분투([「Raspberry Pi OS, 우분투, 그 밖의 배포판」](#/read/sbc-start/os-choices))가 그런 조건을 답니다
- **RELEASE**: 받는 채널입니다. `default`는 공장에서 나올 때의 것이고, `latest`에서 시험을 거친 것이 때때로 넘어옵니다. `latest`는 더 자주 바뀝니다. `raspi-config`의 Advanced Options > Bootloader Version에서 바꾸고, 파일로는 `/etc/default/rpi-eeprom-update`의 `FIRMWARE_RELEASE_STATUS`입니다
- **가만히 둬도 올라간다**: 켜질 때 도는 `rpi-eeprom-update` 서비스가 새 판이 있으면 올리고 지금의 설정도 옮겨 줍니다. 새 판의 파일은 패키지 갱신에 실려 오므로 `sudo apt full-upgrade`가 먼저입니다([「첫 부팅과 갱신」](#/read/sbc-start/os-first-boot))
- **멈춰 두기**: 여러 대를 같은 판에 묶어 두려면 `sudo systemctl mask rpi-eeprom-update`로 그 서비스를 막거나, 아래의 설정에 `FREEZE_VERSION=1`을 적습니다

## 설정 보기와 고치기

```sh
rpi-eeprom-config                  # 지금 설정을 보여 준다
sudo rpi-eeprom-config --edit      # 편집기로 고친다. 저장하고 다시 켜면 적용된다
```

```text
[all]
BOOT_UART=1
POWER_OFF_ON_HALT=0
BOOT_ORDER=0xf461
```

- **문법은 config.txt와 같다**: 한 줄에 `이름=값` 하나이고, 대괄호 필터도 EDID 필터만 빼고 그대로 씁니다
- **보드에 남는다**: 카드를 바꿔 꽂아도, OS를 새로 깔아도 이 설정은 그대로입니다. 남이 쓰던 보드를 받았다면 한번 확인합니다
- **파일로 넣기**: `sudo rpi-eeprom-config --apply boot.conf`는 파일에 적어 둔 설정을 통째로 넣습니다. 여러 대를 같게 맞출 때 씁니다

## BOOT_ORDER 읽는 법

`BOOT_ORDER`는 16진수 하나이고, 자리 하나가 부팅할 곳 하나입니다. 읽는 방향이 글과 반대여서, 오른쪽 자리부터 차례로 시도합니다. 아래 예제가 몇 가지 값을 풀어 적습니다.

```c
// BOOT_ORDER 풀기: 16진수의 오른쪽 자리부터 읽어 부팅을 시도하는 순서를 적는다
#include <stdio.h>

static const char* mode_name(unsigned digit) {
    switch (digit) {
    case 0x1: return "SD카드";
    case 0x2: return "네트워크";
    case 0x3: return "RPIBOOT";
    case 0x4: return "USB 저장 장치";
    case 0x5: return "BCM-USB-MSD";
    case 0x6: return "NVMe";
    case 0x7: return "HTTP";
    case 0xe: return "멈춤";
    case 0xf: return "처음부터 다시";
    default:  return "?";
    }
}

int main(void) {
    const unsigned orders[] = {0xf41, 0xf461, 0xf416, 0xf21, 0xe1};
    for (size_t i = 0; i < sizeof orders / sizeof orders[0]; ++i) {
        printf("0x%-5x", orders[i]);
        for (unsigned v = orders[i]; v; v >>= 4)     // 오른쪽 자리부터 하나씩
            printf("%s%s", v == orders[i] ? " " : " → ", mode_name(v & 0xf));
        printf("\n");
    }
}
```

```text
0xf41   SD카드 → USB 저장 장치 → 처음부터 다시
0xf461  SD카드 → NVMe → USB 저장 장치 → 처음부터 다시
0xf416  NVMe → SD카드 → USB 저장 장치 → 처음부터 다시
0xf21   SD카드 → 네트워크 → 처음부터 다시
0xe1    SD카드 → 멈춤
```

| 자리 | 뜻 |
| --- | --- |
| `1` | SD카드 |
| `2` | 네트워크 |
| `4` | USB 저장 장치 |
| `6` | NVMe |
| `7` | HTTP로 이미지를 받아 부팅 |
| `e` | 멈춘다 |
| `f` | 처음으로 돌아가 다시 돈다 |

- **기본값은 `0xf41`**: 값이 비어 있을 때 쓰입니다. SD카드, USB 저장 장치를 차례로 보고 처음으로 돌아갑니다
- **왼쪽 끝은 `f`나 `e`**: 맨 마지막에 읽히는 자리입니다. `f`면 부팅할 곳이 생길 때까지 계속 돌므로, 켜 둔 채 카드를 꽂아도 다음 바퀴에서 부팅이 됩니다. `e`면 한 바퀴 돌고 멈춥니다
- **5에 NVMe를 달았다면**: 문서의 예에 나오는 `0xf461`은 SD카드를 먼저 봅니다. 카드를 꽂으면 카드로, 빼면 NVMe로 켜지므로 카드를 응급용으로 쓸 수 있습니다. NVMe를 먼저 보게 하려면 `0xf416`입니다
- **raspi-config로도**: Advanced Options > Boot Order에서 고르면 이 값을 대신 적어 줍니다([「raspi-config」](#/read/sbc-start/cfg-raspi-config))
- **표에 없는 자리**: 예제의 `3`과 `5`는 드물게 쓰는 방식이라 뺐습니다. 문서의 표에 모두 있습니다

## 자주 만나는 설정

| 이름 | 기본값 | 하는 일 |
| --- | --- | --- |
| `BOOT_UART` | 0 | 1이면 부트로더가 하는 일을 UART로 찍는다 |
| `POWER_OFF_ON_HALT` | 0 | 1이면 끈 뒤에 전원 칩의 출력까지 내린다 |
| `WAIT_FOR_POWER_BUTTON` | 0 | 5에서, 전원이 들어와도 버튼을 눌러야 켜진다 |
| `PSU_MAX_CURRENT` | 비어 있음 | 5에서, 전원과의 협상을 건너뛰고 용량을 정한다 |
| `PCIE_PROBE` | 0 | 5에서, HAT+ 규격이 아닌 NVMe 보드를 찾게 한다 |
| `FREEZE_VERSION` | 0 | 1이면 부트로더를 저절로 올리지 않는다 |

- **`BOOT_UART=1`**: 화면은 까맣고 LED만 깜박일 때 씁니다. [「시리얼 콘솔」](#/read/sbc-start/rem-serial)의 선을 이어 두면 부트로더가 어디까지 갔는지가 115200bps로 찍힙니다
- **`POWER_OFF_ON_HALT=1`**: 문서는 5가 꺼진 뒤에도 1W에서 1.4W쯤을 쓰고, 이 값을 1로 두면 0.01W쯤으로 내려간다고 적습니다. 다시 켤 때에는 전원 버튼을 누릅니다. 전지로 돌리는 장치에서 뜻이 있습니다
- **4의 `WAKE_ON_GPIO`**: 4에서는 이 값이 1이면 끈 뒤에 낮은 전력으로 기다리다가 GPIO 3을 GND에 이을 때 다시 켜집니다. `POWER_OFF_ON_HALT=1`은 이 값이 0일 때에만 전원을 내립니다
- **`WAIT_FOR_POWER_BUTTON=1`**: `POWER_OFF_ON_HALT`도 1이어야 합니다. 정전 뒤에 저절로 켜지면 안 되는 장치에 씁니다
- **`PSU_MAX_CURRENT`**: 3000이나 5000을 적습니다. 전원이 실제로 낼 수 있는 값만 적습니다([「전원: 5V 5A와 USB-PD」](#/read/sbc-start/prt-power))

## 망가졌을 때 되살리기

올리는 도중에 전원이 나갔거나 설정을 잘못 적어 켜지지 않게 되어도, 부트로더를 다시 써 넣을 수 있습니다.

- **카드를 만든다**: 다른 컴퓨터의 Imager에서 OS를 고르는 단계의 맨 아래에 있는 Misc utility images > Bootloader > SD Card Boot를 고릅니다. 카드는 지워지므로 비어도 되는 것을 씁니다
- **꽂고 켠다**: 초록 LED가 고르게 깜박이고 HDMI 화면이 초록색으로 차면 끝난 것입니다. 전원을 빼고 카드를 뺍니다
- **빨간 화면**: 실패입니다. LED가 깜박이는 무늬가 까닭을 알려 줍니다([「부팅이 안 될 때: LED 신호와 진단」](#/read/sbc-start/care-troubleshoot))
- **진단 화면**: 4와 그 뒤의 보드는 부팅할 곳을 찾지 못하면 HDMI에 진단 화면을 띄웁니다. 부팅 매체를 빼고 켜면 일부러 볼 수 있습니다. 모델과 메모리, 부트로더의 판과 날짜, 부팅 순서, SD카드가 보이는지, 네트워크의 상태가 나오므로 리눅스 없이도 설정이 뜻대로 들어갔는지 확인할 수 있습니다

<Note>
예제는 숫자를 풀어 적기만 합니다. 실제 부트로더에는 방식마다 기다리는 시간과 다시 시도하는 횟수의 설정이 따로 있습니다. 명령과 출력은 문서에서 옮겼고 보드에서 돌려 보지 못했습니다. 잘못 적으면 켜지지 않을 수 있는 곳이므로, 고치기 전에 `rpi-eeprom-config`의 출력을 파일로 남기고 되살리는 카드를 만들 수 있는 상태에서 손댑니다.
</Note>

## 정리

- 4와 5의 부트로더는 보드의 EEPROM에 들어 있고, `sudo rpi-eeprom-update`로 판을 보고 올린다
- `BOOT_ORDER`는 오른쪽 자리부터 읽는 16진수다. `rpi-eeprom-config`로 보고 `--edit`로 고친다
- 켜지지 않게 되면 Imager의 Bootloader 이미지를 쓴 카드로 되살린다
