벌칸 말고도 GPU를 부리는 API는 여럿입니다. OpenGL과 Direct3D 11은 드라이버가 많은 일을 대신하는 앞 세대이고, Direct3D 12와 Metal은 벌칸과 같은 시기에 나온 명시적 API입니다. 이름은 달라도 개념이 거의 그대로 대응하므로, 벌칸을 익히면 나머지도 빨리 읽힙니다.

## 상태 기계에서 커맨드 버퍼로

OpenGL은 커다란 상태 기계입니다. 텍스처와 셰이더를 "지금 쓸 것"으로 묶어 두고 그리기를 부르면, 드라이버가 그 순간의 상태를 보고 검사하고, 필요하면 셰이더를 그 조합에 맞게 다시 컴파일하고, 앞선 작업과의 순서를 맞추고, 메모리를 옮깁니다. 이 일이 그리기 호출 안에서 몰래 일어나서 가끔 프레임이 튀고, 문맥이 한 스레드에 묶여 있어 여러 코어로 나누기 어렵습니다. 벌칸, Direct3D 12, Metal은 그리기 명령을 커맨드 버퍼에 미리 기록해 큐에 넣고, 상태 조합은 파이프라인 객체로 미리 만들어 두며, 메모리와 동기화는 프로그램이 정합니다. OpenGL은 4.6(2017년)이 마지막 판입니다.

## 같은 셰이더, 세 언어

셰이딩 언어도 API마다 다릅니다. 벌칸은 GLSL 같은 언어를 SPIR-V라는 중간 표현으로 컴파일해 받고, Direct3D는 HLSL을, Metal은 MSL을 씁니다. 아래 프로그램은 GLSL 프래그먼트 셰이더를 shaderc로 SPIR-V로 컴파일한 뒤, SPIRV-Cross로 HLSL과 MSL로 옮겨 자원 연결이 드러나는 줄만 보여 줍니다.

```cpp pkg=shaderc,spirv-cross-c-shared
#include <shaderc/shaderc.hpp>
#include <spirv_cross/spirv_cross_c.h>
#include <cstdio>
#include <sstream>
#include <string>
#include <vector>

const char* kFrag = R"(#version 450
layout(set = 0, binding = 0) uniform Params { vec4 tint; } params;
layout(set = 0, binding = 1) uniform sampler2D albedo;
layout(location = 0) in vec2 uv;
layout(location = 0) out vec4 color;
void main() { color = texture(albedo, uv) * params.tint; }
)";

// SPIR-V를 다른 셰이딩 언어로 옮기고, 자원 연결이 드러나는 줄만 찍는다
void translate(const std::vector<uint32_t>& spirv, spvc_backend backend,
               const char* name, const char* mark) {
    spvc_context ctx;
    spvc_context_create(&ctx);
    spvc_parsed_ir ir;
    spvc_context_parse_spirv(ctx, spirv.data(), spirv.size(), &ir);
    spvc_compiler comp;
    spvc_context_create_compiler(ctx, backend, ir, SPVC_CAPTURE_MODE_TAKE_OWNERSHIP,
                                 &comp);
    spvc_compiler_options opts;
    spvc_compiler_create_compiler_options(comp, &opts);
    if (backend == SPVC_BACKEND_HLSL)              // 셰이더 모델 6.0
        spvc_compiler_options_set_uint(opts, SPVC_COMPILER_OPTION_HLSL_SHADER_MODEL,
                                       60);
    spvc_compiler_install_compiler_options(comp, opts);
    const char* src = nullptr;
    spvc_compiler_compile(comp, &src);
    std::printf("%s\n", name);
    std::istringstream in(src);
    for (std::string line; std::getline(in, line);) {
        if (line.find(mark) == std::string::npos) continue;
        line.erase(0, line.find_first_not_of(' '));
        for (size_t at; line.size() > 76 && (at = line.find(", ")) != line.npos;) {
            std::printf("  %s,\n", line.substr(0, at).c_str());  // 인자마다 끊는다
            line = "      " + line.substr(at + 2);
        }
        std::printf("  %s\n", line.c_str());
    }
    spvc_context_destroy(ctx);
}

int main() {
    shaderc::Compiler compiler;
    auto r = compiler.CompileGlslToSpv(kFrag, shaderc_fragment_shader, "tint.frag");
    if (r.GetCompilationStatus() != shaderc_compilation_status_success) {
        std::printf("%s", r.GetErrorMessage().c_str());
        return 1;
    }
    std::vector<uint32_t> spirv(r.cbegin(), r.cend());
    std::printf("GLSL → SPIR-V %zu워드\n", spirv.size());
    translate(spirv, SPVC_BACKEND_HLSL, "HLSL (Direct3D)", "register(");
    translate(spirv, SPVC_BACKEND_MSL, "MSL (Metal)", "[[");
}
```

```text
GLSL → SPIR-V 221워드
HLSL (Direct3D)
  cbuffer Params : register(b0, space0)
  Texture2D<float4> albedo : register(t1, space0);
  SamplerState _albedo_sampler : register(s1, space0);
MSL (Metal)
  float4 color [[color(0)]];
  float2 uv [[user(locn0)]];
  fragment main0_out main0(main0_in in [[stage_in]],
        constant Params& params [[buffer(0)]],
        texture2d<float> albedo [[texture(0)]],
        sampler albedoSmplr [[sampler(0)]])
```

- **set과 binding**: 벌칸의 자원은 (세트, 바인딩) 두 번호로 찾습니다. HLSL에서는 세트가 `space`, 바인딩이 레지스터 번호가 되었고, 레지스터 종류(`b` 상수 버퍼, `t` 텍스처, `s` 샘플러)가 앞에 붙습니다. MSL은 종류별로 0부터 다시 셉니다
- **합친 이미지 샘플러**: GLSL의 `sampler2D` 하나가 HLSL과 MSL에서는 텍스처와 샘플러 두 객체로 갈라졌습니다. 벌칸은 둘을 합친 형태와 따로 둔 형태를 모두 지원합니다
- **입출력**: `location`으로 이은 셰이더 단계 사이의 값은 MSL에서 `[[user(locn0)]]`, 출력 색은 `[[color(0)]]`이 되었습니다. 맥에서 벌칸을 Metal 위로 돌리는 MoltenVK가 바로 이 번역을 실행 중에 합니다([「MoltenVK」](#/read/cpp-vulkan/port-moltenvk))

## 개념 대응표

| 벌칸 | Direct3D 12 | Metal |
| --- | --- | --- |
| `VkDevice` | `ID3D12Device` | `MTLDevice` |
| `VkQueue` | `ID3D12CommandQueue` | `MTLCommandQueue` |
| `VkCommandBuffer` | `ID3D12GraphicsCommandList` | `MTLCommandBuffer`와 인코더 |
| `VkPipeline` | 파이프라인 상태 객체(PSO) | `MTLRenderPipelineState` |
| `VkPipelineLayout` | 루트 시그니처 | 없음(인자 번호로 정함) |
| 디스크립터 세트 | 디스크립터 힙의 테이블 | 인자 버퍼 |
| `VkFence`, `VkSemaphore` | `ID3D12Fence` | `MTLSharedEvent`, `MTLFence` |
| `VkSwapchainKHR` | `IDXGISwapChain` | `CAMetalLayer` |
| SPIR-V | DXIL | Metal 라이브러리 |

가장 많이 다른 곳은 자원 묶기입니다. Direct3D 12는 루트 시그니처에 상수와 테이블을 직접 넣을 수 있고, Metal은 인덱스로 자원을 꽂는 단순한 방식에 더해 인자 버퍼를 둡니다. 동기화는 벌칸과 Direct3D 12가 배리어를 프로그램이 넣는 쪽이고, 예전 Metal은 자원 사이의 위험을 기본으로 추적해 주었지만 2025년의 Metal 4는 모든 자원을 추적하지 않고 배리어를 직접 넣게 바뀌었습니다. 여러 API를 감싸는 엔진은 이 차이를 얇은 층으로 덮습니다([「그래픽 API 감싸기」](#/read/cpp-game-engine/rend-abstraction)).

## 서로 위에 얹기

API는 다른 API 위에서 돌기도 합니다. MoltenVK는 벌칸을 Metal 위에, DXVK와 VKD3D-Proton은 Direct3D 9~12를 벌칸 위에 구현해 리눅스와 스팀 덱에서 윈도우 게임을 돌리고, Mesa의 Zink는 OpenGL을 벌칸 위에 구현합니다. 브라우저의 WebGPU도 운영체제에 따라 Direct3D 12, Metal, 벌칸 위에서 돌면서, 그 위에 더 안전하고 단순한 명시적 API를 줍니다.

<Note>
마이크로소프트는 2024년 9월에, 셰이더 모델 7부터 Direct3D 12가 SPIR-V로 컴파일한 셰이더를 받고 DXIL을 SPIR-V로 바꿔 가겠다고 발표했습니다. HLSL을 SPIR-V로 컴파일하는 DXC의 벌칸 백엔드는 이미 널리 쓰여서, HLSL로 쓴 셰이더를 벌칸에서 돌리는 일도 흔합니다([「HLSL과 Slang에서 오기」](#/read/cpp-vulkan/spv-languages)).
</Note>

## 정리

- OpenGL은 드라이버가 그리기 순간에 상태를 검사·컴파일·동기화하는 상태 기계이고, 벌칸·Direct3D 12·Metal은 커맨드 버퍼, 파이프라인 객체, 명시적 메모리와 동기화를 쓴다
- 셰이더는 SPIR-V(벌칸), DXIL(Direct3D), Metal 라이브러리로 나뉘며 SPIRV-Cross 같은 도구가 서로 옮기고, set·binding은 레지스터와 space, 인자 번호로 바뀐다
- 큐, 커맨드 버퍼, 파이프라인, 펜스는 세 API에서 거의 그대로 대응하고, 가장 다른 곳은 자원 묶기와 동기화의 책임이다
