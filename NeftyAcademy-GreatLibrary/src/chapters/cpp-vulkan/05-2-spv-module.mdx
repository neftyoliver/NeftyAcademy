SPIR-V 모듈은 32비트 낱말의 배열입니다. 앞의 다섯 낱말이 머리말이고, 그 뒤로 명령이 이어집니다. 명령의 첫 낱말은 위 16비트가 이 명령의 낱말 수, 아래 16비트가 명령 번호(opcode)이고, 나머지 낱말이 피연산자입니다. 그래서 드라이버는 낱말 수만큼 건너뛰며 모듈 전체를 훑을 수 있습니다. 아래 프로그램은 콜라츠 한 걸음을 하는 컴퓨트 셰이더를 번역·최적화한 뒤, 머리말을 직접 읽고 명령마다 어느 칸에 속하는지 붙여 찍습니다.

```cpp vk pkg=SPIRV-Tools with=vkx_instance.hpp,vkx_device.hpp,vkx_pipeline.hpp
#include <sstream>
#include <spirv-tools/libspirv.hpp>
#include <spirv-tools/optimizer.hpp>
#include "vkx_pipeline.hpp"

const char* CS = R"(#version 450
layout(local_size_x = 64) in;
layout(binding = 0) buffer Data { uint v[]; };
void main() {                      // 콜라츠 한 걸음
    uint i = gl_GlobalInvocationID.x;
    if (v[i] % 2u == 1u) v[i] = v[i] * 3u + 1u;
    else v[i] /= 2u;
})";

// 명령 번호로 모듈의 어느 칸에 속하는지 가른다(SPIR-V가 정한 순서)
const char* section(uint32_t op) {
    if (op == 17) return "능력  ";                  // OpCapability
    if (op == 10 || op == 11) return "확장  ";      // OpExtension, OpExtInstImport
    if (op == 14) return "메모리";                  // OpMemoryModel
    if (op == 15) return "진입점";                  // OpEntryPoint
    if (op == 16) return "실행  ";                  // OpExecutionMode
    if (op >= 3 && op <= 8) return "디버그";        // OpSource, OpName, ...
    if (op == 71 || op == 72) return "장식  ";      // OpDecorate, OpMemberDecorate
    return nullptr;                                 // 그 밖은 선언이나 함수
}

int main() {
    std::vector<uint32_t> m = vkx::compile(CS, shaderc_compute_shader), opt;
    spvtools::Optimizer optimizer(SPV_ENV_VULKAN_1_3);
    optimizer.RegisterPerformancePasses();
    optimizer.Run(m.data(), m.size(), &opt);
    m = opt;
    std::printf("머리말: 마법수 %08X, 버전 %u.%u, 생성기 %u판 %u, 번호 상한 %u\n",
                m[0], m[1] >> 16 & 0xFF, m[1] >> 8 & 0xFF, m[2] >> 16,
                m[2] & 0xFFFF, m[3]);

    spvtools::SpirvTools tools(SPV_ENV_VULKAN_1_3);
    std::string text;
    tools.Disassemble(m, &text, SPV_BINARY_TO_TEXT_OPTION_FRIENDLY_NAMES |
                                    SPV_BINARY_TO_TEXT_OPTION_NO_HEADER);
    std::istringstream lines(text);   // 줄 하나가 명령 하나다
    std::string line;
    bool in_function = false;
    for (size_t at = 5; at < m.size() && std::getline(lines, line);
         at += m[at] >> 16) {
        uint32_t op = m[at] & 0xFFFF;
        in_function = in_function || op == 54;   // OpFunction부터는 함수
        const char* s = section(op);
        std::printf("[%s] %s\n", in_function ? "함수  " : s ? s : "선언  ",
                    line.c_str());
    }
}
```

- **머리말**: 마법수 `07230203`, 버전(1.6은 `0x00010600`), 생성기(위 16비트가 도구 번호로 13은 shaderc, 아래가 그 도구의 판), 모든 결과 번호가 그보다 작다는 상한, 예약된 0입니다. 벌칸 1.3은 SPIR-V 1.0부터 1.6까지를 받습니다
- **정해진 칸의 순서**: 능력(`OpCapability`) → 확장과 확장 명령 집합 → 메모리 모델 → 진입점 → 실행 모드 → 디버그 정보 → 장식 → 타입·상수·전역 변수 → 함수 순서를 지켜야 합니다. 드라이버는 함수를 읽기 전에 필요한 능력과 모든 타입을 이미 압니다
- **SSA 번호**: `%15 = OpLoad %uint %14`처럼 결과마다 번호를 한 번만 붙이고, 타입(`%uint`)과 상수(`%uint_3`)도 번호로 가리킵니다. `%main`, `%uint` 같은 이름은 디버그 정보(`OpName`)에서 디스어셈블러가 빌려 온 것일 뿐입니다
- **장식**: `layout(binding = 0)`, std430의 `Offset`과 `ArrayStride`, `gl_GlobalInvocationID` 같은 내장 변수가 모두 `OpDecorate`로 적힙니다. [「인터페이스 블록과 레이아웃」](#/read/cpp-vulkan/glsl-interface)의 오프셋이 드라이버에 가는 길이 이것입니다
- **포인터와 저장 공간**: 변수는 `Input`, `StorageBuffer`, `Function`, `Workgroup` 같은 저장 공간이 붙은 포인터이고, `OpAccessChain`으로 원소의 포인터를 얻어 `OpLoad`·`OpStore`합니다

## 구조적 제어 흐름

함수 본문은 이름표(`OpLabel`)로 시작하는 블록들이고, 블록은 분기 명령으로 끝납니다. 셰이더용 SPIR-V는 `if`와 반복문의 모양을 남겨야 해서, 갈라지기 직전에 `OpSelectionMerge %32`로 두 갈래가 다시 만나는 블록을 먼저 밝힙니다(반복문은 `OpLoopMerge`). GPU는 서브그룹의 실행들이 갈라졌다가 어디서 다시 합쳐지는지 알아야 하므로, 이 정보가 있으면 드라이버가 흐름을 다시 분석하지 않아도 됩니다.

<Note>
디버그 정보(`OpSource`, `OpName`)는 동작에 영향을 주지 않으므로 `spirv-opt --strip-debug`로 지워 크기를 줄일 수 있습니다. 반대로 셰이더를 디버거에서 원문 줄 단위로 따라가려면 glslc의 `-g`로 원문(`OpSource`)과 줄 정보(`OpLine`)를 남기고, 더 자세한 NonSemantic.Shader.DebugInfo.100은 glslangValidator의 `-gV`로 남깁니다([「glslang과 shaderc」](#/read/cpp-vulkan/spv-compile)).
</Note>

## 정리

- SPIR-V 모듈은 32비트 낱말 배열로, 머리말 다섯 낱말 뒤에 "낱말 수 | 명령 번호"로 시작하는 명령이 이어진다
- 능력 → 확장 → 메모리 모델 → 진입점 → 실행 모드 → 디버그 → 장식 → 선언 → 함수의 순서가 정해져 있고, 결과·타입·상수는 SSA 번호로 가리킨다
- 레이아웃과 바인딩은 장식으로, 제어 흐름은 합류 블록을 밝힌 구조적 분기로 드라이버에 전해진다
