GPU는 삼각형을 픽셀로 바꾸는 일을 아주 빠르게 하도록 만든 프로세서입니다. 벌칸의 객체와 함수 대부분이 이 과정의 어느 단계를 설정하거나 그 사이를 맞추는 일이므로, 벌칸 코드를 쓰기 전에 그 단계들을 먼저 봅니다. 아래 프로그램은 GPU가 하는 일을 CPU에서 아주 작게 흉내 내어, 삼각형 하나를 40×20 글자 화면에 그립니다.

## 삼각형이 픽셀이 되기까지

```cpp
#include <cstdio>
#include <string>

struct V2 { float x, y; };

// 정점 셰이더 흉내: 정규화 장치 좌표(-1~1)를 W×H 화면의 픽셀 좌표로.
// 벌칸처럼 y는 아래로 갈수록 커진다
V2 to_screen(V2 ndc, int w, int h) {
    return {(ndc.x + 1) * 0.5f * w, (ndc.y + 1) * 0.5f * h};
}

// 변 함수: p가 a→b의 어느 쪽에 있는지. 세 변 모두 같은 쪽이면 삼각형 안
float edge(V2 a, V2 b, V2 p) {
    return (b.x - a.x) * (p.y - a.y) - (b.y - a.y) * (p.x - a.x);
}

int main() {
    const int W = 40, H = 20;
    struct { V2 ndc; float shade; } tri[3] = {   // 정점마다 위치와 밝기
        {{0.0f, -0.9f}, 0.0f}, {{0.9f, 0.8f}, 1.0f}, {{-0.9f, 0.8f}, 0.5f}};
    V2 s[3];
    for (int i = 0; i < 3; ++i) s[i] = to_screen(tri[i].ndc, W, H);
    const float area = edge(s[0], s[1], s[2]);
    const char* ramp = ".:-=+*#%@";
    int fragments = 0;
    for (int y = 0; y < H; ++y) {
        std::string row;
        for (int x = 0; x < W; ++x) {
            V2 p{x + 0.5f, y + 0.5f};             // 픽셀의 가운데에서 잰다
            float w0 = edge(s[1], s[2], p) / area;
            float w1 = edge(s[2], s[0], p) / area;
            float w2 = edge(s[0], s[1], p) / area;
            if (w0 < 0 || w1 < 0 || w2 < 0) {      // 래스터화: 덮지 않은 픽셀
                row += ' ';
                continue;
            }
            ++fragments;                           // 프래그먼트 셰이더 한 번
            float shade = w0 * tri[0].shade + w1 * tri[1].shade + w2 * tri[2].shade;
            row += ramp[int(shade * 8.999f)];
        }
        std::printf("|%s|\n", row.c_str());
    }
    std::printf("정점 3개 → 프래그먼트 %d개\n", fragments);
}
```

```text
|                                        |
|                   ..                   |
|                  ....                  |
|                 ...:::                 |
|                .:::::::                |
|               :::::::---               |
|              :::::-------              |
|             ::--------====             |
|            --------========            |
|           ------========++++           |
|          ----========++++++++          |
|         --========++++++++****         |
|        =======++++++++********#        |
|       =====++++++++********#####       |
|      ===++++++++********########%      |

|    +++++++********########%%%%%%%%@    |
|   +++++********########%%%%%%%%@@@@@   |
|                                        |
|                                        |
정점 3개 → 프래그먼트 306개
```

- **정점 셰이더**: 정점마다 한 번씩 돌아 위치를 바꿉니다. 여기서는 -1~1의 좌표를 픽셀 좌표로 옮기기만 했지만, 실제로는 모델·뷰·투영 행렬을 곱해 클립 좌표를 내고, 원근 나눗셈과 뷰포트 변환은 고정 기능이 맡습니다. 벌칸의 정규화 좌표는 y가 아래로 커지고 깊이는 0~1입니다([「좌표계의 약속」](#/read/cpp-game-engine/math-conventions))
- **래스터화**: 삼각형이 어느 픽셀을 덮는지 고르는 고정 기능 단계입니다. 픽셀 가운데가 세 변 모두의 안쪽에 있으면 덮인 것으로 봅니다. 두 삼각형이 함께 쓰는 변 위에 놓인 픽셀은 정확히 한쪽만 그리도록 규칙이 정해져 있어서, 맞붙은 삼각형 사이에 틈이나 겹침이 생기지 않습니다
- **보간**: 덮인 픽셀마다 세 정점의 값(여기서는 밝기)을 무게중심 좌표 `w0`, `w1`, `w2`로 섞어 넘깁니다. 실제 GPU는 깊이에 따라 원근을 고려해 보간합니다
- **프래그먼트 셰이더**: 덮인 픽셀마다 한 번씩 돌아 색을 정합니다. 정점은 3개였지만 프래그먼트 셰이더는 306번 돌았습니다. 화면이 커질수록 일의 대부분은 이쪽에 몰립니다

## 파이프라인의 단계

벌칸의 그래픽 파이프라인은 정점 입력, 정점 셰이더, (있으면) 테셀레이션과 지오메트리 셰이더, 기본 도형 조립과 클리핑, 래스터화, 프래그먼트 셰이더, 그리고 깊이·스텐실 검사와 블렌딩을 거쳐 첨부물(attachment)이라 부르는 이미지에 쓰는 순서로 이루어집니다. 셰이더 단계는 GLSL로 쓴 프로그램이 돌고, 나머지는 구조체 몇 개로 켜고 끄는 고정 기능입니다. 벌칸은 이 설정 전부를 **파이프라인 객체** 하나로 미리 묶어 두게 해서, 그리는 도중에 드라이버가 셰이더를 다시 컴파일하는 일을 줄입니다. 래스터화가 없는 **컴퓨트 파이프라인**은 셰이더 하나를 정해진 수의 작업 그룹으로 나눠 돌릴 뿐이라, 그래픽과 상관없는 계산(GPGPU)에도 씁니다.

## GPU가 빠른 까닭

위 프로그램에서 픽셀 하나의 계산은 다른 픽셀과 아무 관계가 없습니다. GPU는 이런 일에 맞춰, 복잡한 코어 몇 개 대신 단순한 계산 단위를 수천 개 둡니다. 레인 32개나 64개가 한 묶음(NVIDIA의 워프, AMD의 웨이브프런트, 벌칸에서는 서브그룹)이 되어 같은 명령을 서로 다른 데이터에 함께 실행하고, 한 묶음이 메모리를 기다리는 동안 다른 묶음으로 바꿔 돌려 기다림을 감춥니다. 그래서 묶음 안의 레인들이 `if`에서 서로 다른 쪽으로 갈라지면 양쪽을 차례로 실행하느라 느려지고, 한 번에 돌릴 일이 적으면 계산 단위가 놉니다.

## 즉시 렌더링과 타일 렌더링

데스크톱 GPU는 삼각형을 받는 대로 래스터화해 화면 크기의 이미지에 바로 씁니다. 대부분의 모바일 GPU는 먼저 모든 삼각형을 작은 타일별로 나눠 두고, 타일 하나씩 칩 안의 빠른 메모리에서 끝까지 그린 뒤 결과만 바깥 메모리에 씁니다(타일 기반 렌더링). 이런 GPU에서는 바깥 메모리를 읽고 쓰는 일이 비싸므로, 벌칸은 그리기를 시작할 때 이전 내용을 불러올지(load), 끝날 때 결과를 남길지(store)를 직접 말하게 합니다([「렌더 패스와 동적 렌더링」](#/read/cpp-vulkan/tri-renderpass)). 데스크톱에서는 별 차이가 없어 보이는 설정이 모바일에서는 성능을 크게 가릅니다.

<Note>
정점 입력에서 지오메트리 셰이더까지의 앞부분을 통째로 바꾸는 **메시 셰이더**도 있습니다(`VK_EXT_mesh_shader`). 컴퓨트 셰이더처럼 작업 그룹으로 돌면서 정점과 삼각형을 직접 만들어 내므로, 보이지 않는 덩어리를 GPU에서 미리 버리는 식의 처리를 할 수 있습니다. 모든 장치가 지원하지는 않으므로 기능을 확인하고 씁니다([「장치 기능에 따라 가르기」](#/read/cpp-vulkan/port-features)).
</Note>

## 정리

- 그래픽 파이프라인은 정점 셰이더, 래스터화, 프래그먼트 셰이더, 깊이 검사와 블렌딩을 거쳐 첨부물 이미지에 쓰고, 셰이더가 아닌 단계는 고정 기능이다
- 래스터화는 픽셀 가운데가 삼각형 안인지 보고, 정점의 값을 무게중심 좌표로 보간해 프래그먼트 셰이더에 넘긴다
- GPU는 같은 명령을 여러 레인이 함께 실행하고 묶음을 바꿔 가며 메모리 기다림을 감추며, 모바일의 타일 렌더링 때문에 벌칸은 첨부물의 load·store를 직접 정하게 한다
