C17은 새 기능이 **하나도 없는** 버전입니다. C11 문서의 모호한 문장과 오류를 고친 판입니다. 짧은 챕터지만, 버전을 고를 때 기준점이 되므로 알아 둡니다.

## 무엇이 바뀌었나

- C11에 대해 쌓인 결함 보고서의 답을 본문에 반영했다
- 새 문법, 새 헤더, 새 함수는 없다
- `__STDC_VERSION__`의 값만 `201112L`에서 `201710L`로 바뀌었다

문서가 2017년에 마무리되고 2018년에 출판되어서 C17과 C18이라는 두 이름이 섞여 쓰입니다. 같은 것입니다.

## 버전 확인하기

```c std=c17
#include <stdio.h>

int main(void)
{
    printf("%ld\n", __STDC_VERSION__);
    return 0;
}
```

| 옵션 | 찍히는 값 |
| --- | --- |
| `-std=c99` | `199901` |
| `-std=c11` | `201112` |
| `-std=c17` | `201710` |
| `-std=c23` | `202311` |

이 매크로로 버전에 따라 다른 코드를 넣을 수 있습니다.

```c nocheck
#if __STDC_VERSION__ >= 202311L
    // C23: bool, nullptr 가 키워드다
#else
    #include <stdbool.h>
    #define nullptr NULL
#endif
```

## 왜 중요한가

| 이유 | 설명 |
| --- | --- |
| 오랫동안 기본값이었다 | 옵션을 안 주면 `gnu17`(C17 + 확장)로 컴파일하는 컴파일러가 많다. GCC는 15부터 `gnu23`이 기본이다 |
| 안정된 기준선 | "C17로 컴파일된다"는 것은 지금 쓰이는 거의 모든 컴파일러에서 된다는 뜻이다 |
| C23으로 가는 출발점 | C23의 새 기능을 못 쓰는 환경에서는 C17로 맞춘다 |

## -std=c17과 -std=gnu17

| 옵션 | 뜻 |
| --- | --- |
| `-std=c17` | 표준 C17만. 표준에 없는 확장 일부가 꺼진다 |
| `-std=gnu17` | C17에 GNU 확장을 더한 것 |

GNU 확장에는 `typeof`(C23에서 표준이 됨), 문장 식 `({ … })`, `__attribute__` 같은 것이 있습니다. 리눅스 커널은 이런 확장을 많이 씁니다. 다른 컴파일러에서도 돌아야 하는 코드라면 `-std=c17 -pedantic`으로 표준 밖의 문법을 경고받는 편이 좋습니다.

<Note>
윈도우의 Visual Studio 컴파일러(MSVC)는 `/std:c17` 옵션으로 C17을 지원합니다. 다만 가변 길이 배열은 지원하지 않습니다(C11부터 선택 기능이므로 표준을 어기는 것은 아닙니다).
</Note>

## 정리

- C17은 C11의 오류 수정판이고 새 기능이 없다
- 오랫동안 컴파일러의 기본값이었고, 어디서나 통하는 기준선이다
- `__STDC_VERSION__`으로 버전을 알아낼 수 있다
