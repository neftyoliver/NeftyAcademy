C 컴파일러는 파일을 위에서 아래로 **한 번만** 읽습니다. 그래서 무엇이든 쓰기 전에 그 이름이 무엇인지 먼저 알려 줘야 합니다. 몸통보다 먼저 이름만 알려 주는 것이 전방 선언입니다.

## 함수의 전방 선언

```c
#include <stdio.h>

int square(int x);          // 선언(원형): 이름, 인자, 반환 타입만

int main(void)
{
    printf("%d\n", square(7));      // 49
    return 0;
}

int square(int x)           // 정의: 몸통
{
    return x * x;
}
```

선언이 없으면 `main`에서 `square`를 만났을 때 컴파일러는 그것이 무엇인지 모릅니다. 선언만 있으면 "`int` 하나를 받아 `int`를 돌려준다"는 것을 알고 호출 코드를 만들 수 있습니다. 몸통은 같은 파일 아래쪽에 있어도 되고 다른 파일에 있어도 됩니다.

헤더 파일은 이 전방 선언을 모아 둔 것입니다.

<Note>
아주 옛날 C는 선언 없이 함수를 부르면 "`int`를 돌려주는 함수겠지" 하고 넘어갔습니다. 이 규칙은 C99에서 없어졌고, 지금은 오류입니다.
</Note>

## 서로를 부르는 함수

```c
#include <stdio.h>

bool is_odd(unsigned n);    // 이 선언이 없으면 is_even 을 컴파일할 수 없다

bool is_even(unsigned n)
{
    return n == 0 ? true : is_odd(n - 1);
}

bool is_odd(unsigned n)
{
    return n == 0 ? false : is_even(n - 1);
}

int main(void)
{
    printf("%d %d\n", is_even(10), is_odd(10));     // 1 0
    return 0;
}
```

두 함수가 서로를 부르면 어느 쪽을 먼저 써도 다른 쪽이 아직 안 나왔습니다. 전방 선언이 꼭 필요한 경우입니다.

## 빈 괄호

| 선언 | C17까지 | C23 |
| --- | --- | --- |
| `int f(void);` | 인자가 없다 | 인자가 없다 |
| `int f();` | 인자를 **알려 주지 않는다** (무엇을 넘겨도 통과) | 인자가 없다 |

옛 C에서 `f()`는 "인자 검사를 하지 말라"는 뜻이었습니다. C23에서 `f(void)`와 같아졌지만, 옛 컴파일러에서도 같은 뜻이 되도록 `(void)`라고 적는 습관이 안전합니다.

## 구조체의 전방 선언

```c
struct node;                // "node라는 구조체가 있다"까지만

struct list {
    struct node *head;      // 포인터는 만들 수 있다
    size_t count;
};

struct node {               // 이제 내용을 정한다
    int value;
    struct node *next;      // 자기 자신을 가리키는 포인터
};
```

이름만 알려진 구조체를 <strong>불완전한 타입</strong>이라고 합니다. 크기를 모르므로 변수를 만들거나 멤버에 접근할 수는 없지만, **포인터는 만들 수 있습니다**. 포인터의 크기는 무엇을 가리키든 같기 때문입니다.

## 내용을 숨기는 타입

이 성질을 이용해 헤더에는 이름만 내놓고 내용은 `.c` 파일에 감출 수 있습니다.

```c nocheck
// sensor.h
struct sensor;                              // 내용은 비공개

struct sensor *sensor_open(const char *port);
int sensor_read(struct sensor *s);
void sensor_close(struct sensor *s);
```

```c nocheck
// sensor.c
#include "sensor.h"

struct sensor {                             // 여기서만 내용을 안다
    int fd;
    int last_value;
};
```

라이브러리를 쓰는 쪽은 `struct sensor *`를 받아서 함수에 넘기기만 하고 안을 들여다볼 수 없습니다. 그래서 라이브러리가 구조체의 내용을 바꿔도 쓰는 쪽을 다시 컴파일할 필요가 없습니다. 표준 라이브러리의 `FILE *`이 바로 이 방식입니다.

## 변수의 선언

```c nocheck
extern int counter;     // 선언: 다른 곳에 있다
int counter = 0;        // 정의: 여기에 만든다
```

전역 변수를 여러 파일에서 쓰려면 헤더에 `extern` 선언을 두고, `.c` 파일 한 곳에만 정의를 둡니다.

## 정리

- 이름은 쓰기 전에 선언되어 있어야 한다
- 함수는 원형으로, 구조체는 `struct 이름;`으로 미리 알린다
- 불완전한 타입은 포인터로만 다룰 수 있고, 이것으로 내용을 숨긴다
