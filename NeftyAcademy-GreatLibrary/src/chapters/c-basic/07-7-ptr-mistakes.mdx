포인터 실수는 컴파일은 되는데 실행 중에 죽거나, 더 나쁘게는 죽지도 않고 엉뚱한 값을 냅니다. 자주 나오는 것들을 모았습니다.

## 초기화하지 않은 포인터

```c nocheck
int *p;
*p = 5;         // p에는 쓰레기 주소가 들어 있다
```

고치는 법: 선언할 때 주소나 `nullptr`을 넣습니다.

## 널 포인터 따라가기

```c nocheck
int *v = malloc(100 * sizeof *v);
v[0] = 1;       // malloc이 실패했다면 v는 널
```

고치는 법: 널을 돌려줄 수 있는 함수(`malloc`, `fopen`, `strchr` 등)의 결과는 쓰기 전에 확인합니다.

## 사라진 변수의 주소 돌려주기

```c nocheck
int *make(void)
{
    int n = 42;
    return &n;      // 함수가 끝나면 n의 자리는 남의 것이 된다
}
```

지역 변수는 함수가 끝나면 사라집니다. 그 주소를 들고 나가면 <strong>죽은 포인터</strong>(dangling pointer)가 됩니다. 고치는 법: 값을 그대로 돌려주거나, 부른 쪽이 준비한 자리의 주소를 인자로 받거나, `malloc`으로 만든 메모리를 돌려줍니다.

## 해제한 뒤에 쓰기, 두 번 해제하기

```c nocheck
free(p);
p[0] = 1;       // 이미 돌려준 메모리
free(p);        // 두 번째 해제
```

고치는 법: `free(p);` 다음 줄에 `p = nullptr;`을 적어 둡니다. 널을 `free`하는 것은 아무 일도 하지 않아 안전하고, 널을 따라가면 바로 죽어서 찾기 쉽습니다.

## 배열 밖으로 나가기

```c nocheck
int a[4];
for (int i = 0; i <= 4; i++)    // i < 4 여야 한다
    a[i] = 0;
```

C는 배열의 범위를 확인하지 않습니다. `a[4]`는 배열 바로 뒤에 있는 다른 변수의 자리일 수 있습니다. `<=`와 `<`를 헷갈리는 "하나 차이 오류"가 가장 흔합니다.

## sizeof로 길이를 구하려다

```c nocheck
void clear(int v[])
{
    for (size_t i = 0; i < sizeof v / sizeof v[0]; i++)   // sizeof v 는 8
        v[i] = 0;
}
```

함수 인자로 받은 배열은 포인터입니다. 고치는 법: 길이를 인자로 따로 받습니다.

## 글자열을 == 로 비교하기

```c nocheck
if (name == "on")           // 주소를 비교한다. 거의 언제나 거짓
if (strcmp(name, "on") == 0)    // 내용을 비교한다
```

마찬가지로 `char *a = b;`는 글자열을 복사하지 않고 같은 글자열을 가리키게 할 뿐입니다. 복사하려면 `strcpy`나 `memcpy`를 씁니다.

## & 를 빠뜨리거나 더 붙이기

```c nocheck
int n;
scanf("%d", n);     // &n 이어야 한다

char s[32];
scanf("%31s", &s);  // s 여야 한다 (배열 이름이 이미 주소)
```

## 도구에게 맡기기

눈으로 찾기 어려운 실수를 도구가 잡아 줍니다.

```sh
clang -std=c23 -Wall -Wextra -g -fsanitize=address,undefined bug.c -o bug
./bug
```

`-fsanitize=address`(ASan)는 실행 중에 배열 밖 접근, 해제한 메모리 사용, 두 번 해제를 잡아 **어느 줄에서** 일어났는지 알려 줍니다. `undefined`(UBSan)는 정수 넘침 같은 정의되지 않은 동작을 잡습니다. 프로그램이 느려지므로 개발하는 동안에만 켭니다.

<Note kind="tip">
포인터 버그는 "틀린 곳"과 "죽는 곳"이 다른 경우가 많습니다. 한참 뒤 엉뚱한 줄에서 죽기 때문입니다. 원인 모를 죽음을 만나면 먼저 ASan을 켜고 다시 실행해 보세요.
</Note>

## 점검표

- 포인터를 만들 때 초기화했는가
- 따라가기 전에 널을 확인했는가
- 이 포인터가 가리키는 것이 아직 살아 있는가
- 인덱스가 0 이상, 길이 미만인가
- `malloc`마다 짝이 되는 `free`가 한 번씩 있는가
