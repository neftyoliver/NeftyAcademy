`.c` 파일은 하나씩 따로 컴파일됩니다. 그런데 `main.c`에서 부른 `add`는 `add.c`에 있습니다. 따로 만든 조각들이 서로를 찾는 방법이 <strong>심볼</strong>입니다.

## 오브젝트 파일 들여다보기

```sh
clang -std=c23 -c hello.c -o hello.o
nm hello.o
```

```text
0000000000000000 T main
                 U puts
```

`nm`은 오브젝트 파일 안의 심볼 목록을 보여 줍니다. 심볼은 **이름이 붙은 자리**입니다. 함수와 전역 변수가 심볼이 됩니다.

| 글자 | 뜻 |
| --- | --- |
| `T` | 이 파일 안에 몸통이 있는 함수 |
| `U` | 이름만 쓰고 몸통은 없는 것 (undefined). 다른 곳에서 찾아야 한다 |
| `D`, `B` | 전역 변수. 초깃값이 있으면 `D`, 없거나 0이면 `B` |
| 소문자(`t`, `d`) | 이 파일 안에서만 보이는 것 |

`hello.o`는 `main`을 가지고 있고(`T`), `puts`는 가지고 있지 않습니다(`U`). 컴파일러는 `puts`를 부르는 자리를 빈칸으로 두고 "여기에 `puts`의 주소를 채워 달라"는 메모만 남깁니다.

## 링커가 하는 일

링커는 모든 `.o`와 라이브러리의 심볼 표를 모아서, `U`인 이름마다 같은 이름의 `T`를 찾아 빈칸에 주소를 채웁니다. 그래서 링크 오류는 두 가지뿐입니다.

짝을 못 찾으면:

```text
main.c:(.text+0x1a): undefined reference to `add'
```

`add.c`를 명령에 빠뜨렸거나, 이름에 오타가 있거나, 라이브러리를 안 붙였을 때 납니다.

같은 이름이 둘이면:

```text
dup.c:(.text+0x0): multiple definition of `add'; add.c:(.text+0x0): first defined here
```

<Note kind="tip">
두 오류 모두 <strong>컴파일은 이미 끝난 뒤</strong>에 납니다. 문법을 들여다볼 게 아니라 "어느 파일이 빠졌나, 어디에 두 번 있나"를 찾으면 됩니다.
</Note>

## static: 밖에서 안 보이게

```c
static int helper(int x) { return x * 2; }   // 이 파일 안에서만
int counter = 0;                             // 다른 파일에서도 보임
static int hidden = 5;                       // 이 파일 안에서만
extern int other;                            // 다른 파일에 있다는 선언
int twice(int x) { return helper(x) + hidden + other; }
```

```text
0000000000000000 B counter
0000000000000030 t helper
0000000000000000 d hidden
                 U other
0000000000000000 T twice
```

`static`을 붙인 함수와 전역 변수는 소문자로 나옵니다. 링커가 다른 파일과 이어 주지 않으므로, 여러 파일에 같은 이름의 `static` 함수가 있어도 부딪히지 않습니다. 파일 안에서만 쓰는 도우미 함수에는 `static`을 붙이는 습관을 들이세요.

`extern`은 반대로 "이 변수는 다른 파일에 정의되어 있다"는 선언입니다. 헤더에 전역 변수를 알릴 때 씁니다.

## C의 심볼 이름은 그대로

C에서는 함수 이름이 그대로 심볼 이름이 됩니다. `add`는 `add`입니다. 이 단순함 때문에 다른 언어들이 C 함수를 쉽게 부를 수 있고, C가 여러 언어 사이의 공용어가 되었습니다.

C++은 같은 이름의 함수를 인자 타입에 따라 여럿 만들 수 있어서 심볼 이름을 `_Z3addii`처럼 바꿉니다(맹글링). C++에서 C 함수를 쓸 때 `extern "C"`를 붙이는 이유가 이것입니다.

## 이름이 맞는다고 다 맞는 것은 아니다

링커는 <strong>이름만</strong> 봅니다. 인자가 몇 개인지, 타입이 무엇인지는 확인하지 않습니다. 선언과 정의가 어긋나도 링크는 되고, 실행할 때 엉뚱하게 동작합니다. 그래서 선언을 헤더 한 곳에 두고 양쪽이 같은 헤더를 포함합니다. 인자를 실제로 어떻게 주고받는지는 [「ABI」](#/read/c-basic/abi) 챕터에서 봅니다.

## 정리

- 심볼은 함수와 전역 변수에 붙은 이름표다
- 링커는 `U`와 `T`를 이름으로 짝지어 준다
- `static`은 심볼을 파일 안에 가둔다
