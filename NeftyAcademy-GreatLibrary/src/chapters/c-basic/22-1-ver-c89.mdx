C는 1972년쯤 벨 연구소에서 유닉스를 만들려고 태어났고, 1989년에 처음으로 표준이 되었습니다. 그 뒤 대략 10년에 한 번씩 고쳐졌습니다. 이 묶음에서는 버전마다 무엇이 들어왔는지 봅니다. 옛 코드나 임베디드 컴파일러를 만나면 "이 문법이 왜 안 되지?"의 답이 여기 있습니다.

## 버전 한눈에

| 이름 | 해 | 한마디 | 컴파일러 옵션 |
| --- | --- | --- | --- |
| K&R C | 1978 | 표준 이전. 책 『The C Programming Language』가 기준이었다 | |
| C89 (= C90, ANSI C) | 1989 | 첫 표준 | `-std=c89` |
| C99 | 1999 | 가장 큰 변화. 지금 쓰는 C의 모양이 여기서 나왔다 | `-std=c99` |
| C11 | 2011 | 스레드, 원자적 연산, 정적 검사 | `-std=c11` |
| C17 (= C18) | 2018 | 오류 수정만 | `-std=c17` |
| C23 | 2024 | `bool`, `nullptr`, `constexpr` 등 편의 기능 | `-std=c23` |

ANSI(미국)가 1989년에 정하고 ISO(국제)가 1990년에 받아들여서 C89와 C90은 같은 것입니다. 옵션을 주지 않으면 컴파일러가 정한 기본 버전에 확장을 더한 것으로 컴파일됩니다. 오랫동안 `gnu17`이었고, GCC는 15부터 `gnu23`으로 바뀌었습니다. 기본값에 기대지 말고 `-std=`를 늘 적는 편이 좋습니다.

## C89가 정한 것

K&R C에서 표준이 되며 들어온 것들입니다.

- **함수 원형**: `int add(int a, int b);`처럼 인자의 타입을 선언에 적는다. 그 전에는 컴파일러가 인자를 검사하지 못했다
- `void`, `const`, `volatile`, `enum`, `signed`
- `void *`: 타입 없는 포인터
- 표준 라이브러리: `<stdio.h>`, `<stdlib.h>`, `<string.h>`, `<math.h>` 등 15개 헤더
- 구조체를 통째로 대입하고, 함수에 넘기고, 돌려받기

## C89의 모양

```c std=c89
#include <stdio.h>

int main(void)
{
    int i;                  /* 변수는 블록 맨 앞에서만 선언한다 */
    int sum = 0;

    for (i = 0; i < 5; i++) {
        sum += i;
    }
    printf("%d\n", sum);    /* 주석은 이것 하나뿐이다 */
    return 0;               /* main 에서도 return 을 꼭 적는다 */
}
```

## C89에 없는 것

지금은 당연하게 쓰지만 C89에서는 안 되는 것들입니다.

| 없는 것 | C89에서 쓰던 방법 |
| --- | --- |
| `//` 주석 | `/* … */` |
| 블록 중간에서 변수 선언, `for (int i = 0; …)` | 블록 맨 앞에서 선언 |
| `bool` | `int`와 0, 1 |
| `long long`, `<stdint.h>` | `long`, 직접 만든 `typedef` |
| `.x = 1` 지정 초기화 | 순서대로 적기 |
| `inline` | 매크로 |
| `snprintf` | `sprintf`와 조심하기 |
| 가변 인자 매크로 | 없음 |

그리고 지금은 없어진 느슨한 규칙이 있었습니다.

```c nocheck
main()              /* 반환 타입을 안 적으면 int */
{
    foo(1, 2);      /* 선언 없이 불러도 된다. int 를 돌려준다고 친다 */
}
```

타입을 생략하면 `int`로 치는 것(암시적 `int`)과 선언 없이 함수를 부르는 것은 많은 버그의 원인이었고 C99에서 없어졌습니다.

## 지금 C89를 만나는 곳

- 오래된 코드와 책의 예제
- 일부 마이크로컨트롤러용 컴파일러 (C99를 다 지원하지 않는 것이 남아 있다)
- 어디서나 컴파일되어야 하는 라이브러리 (SQLite, zlib, Lua 등은 아주 보수적인 C로 쓴다)

<Note>
새 코드를 C89로 쓸 이유는 거의 없습니다. 다만 "변수를 맨 위에 모아 선언한 코드"를 보면 C89 시절의 습관이라는 것을 알아 두면 됩니다.
</Note>

## 정리

- C89는 첫 표준이고, 함수 원형과 표준 라이브러리를 정했다
- `//` 주석, 중간 선언, `bool`, `long long`이 없다
- 암시적 `int`와 선언 없는 호출이 허용되던 시절이다
