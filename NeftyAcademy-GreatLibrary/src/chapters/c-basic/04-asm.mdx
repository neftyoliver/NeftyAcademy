같은 C 코드라도 CPU가 다르면 완전히 다른 명령어가 됩니다. 함수 하나를 여러 CPU용으로 컴파일해서 눈으로 확인합니다.

## 어셈블리 뽑기

```c
int add(int a, int b)
{
    return a + b;
}
```

```sh
clang -O1 -S add.c -o -
```

`-S`는 어셈블리까지만 만들고 멈추게 하고, `-o -`는 파일 대신 화면에 내보냅니다. `.`으로 시작하는 줄은 어셈블러에게 주는 지시라서 지금은 건너뛰어도 됩니다.

## 네 가지 CPU

Clang은 `--target` 옵션으로 다른 CPU용 코드를 만들 수 있습니다.

x86-64 (PC, 대부분의 노트북):

```asm
add:
    leal    (%rdi,%rsi), %eax
    retq
```

ARM64 (`--target=aarch64-linux-gnu`, 라즈베리파이 3 이후, 스마트폰):

```asm
add:
    add     w0, w1, w0
    ret
```

ARM 32비트 (`--target=armv7-linux-gnueabihf`, 옛 라즈베리파이):

```asm
add:
    add     r0, r1, r0
    bx      lr
```

RISC-V 64 (`--target=riscv64-linux-gnu`):

```asm
add:
    addw    a0, a0, a1
    ret
```

## 무엇이 다른가

| | x86-64 | ARM64 | RISC-V |
| --- | --- | --- | --- |
| 첫째·둘째 인자가 들어 있는 곳 | `edi`, `esi` | `w0`, `w1` | `a0`, `a1` |
| 결과를 두는 곳 | `eax` | `w0` | `a0` |
| 돌아가기 | `ret` | `ret` | `ret` |
| 명령어 길이 | 1~15바이트로 제각각 | 4바이트 고정 | 4바이트(짧은 형식은 2) |

이 칸들을 <strong>레지스터</strong>라고 합니다. CPU 안에 있는 아주 빠른 변수이고, 이름과 개수가 CPU마다 다릅니다. x86-64에서 `leal (%rdi,%rsi), %eax`는 원래 주소를 계산하는 명령인데, 두 값을 더해 다른 레지스터에 넣는 일을 한 번에 할 수 있어서 덧셈에 쓰였습니다.

<Note>
인자를 어느 레지스터에 담을지는 CPU가 아니라 <strong>ABI</strong>라는 약속이 정합니다. 같은 x86-64라도 윈도우에서는 첫 인자가 `ecx`에 들어갑니다. 「ABI」 챕터에서 다룹니다.
</Note>

## 최적화를 끄면

```sh
clang -O0 -S add.c -o -
```

```asm
add:
    pushq   %rbp
    movq    %rsp, %rbp
    movl    %edi, -4(%rbp)
    movl    %esi, -8(%rbp)
    movl    -4(%rbp), %eax
    addl    -8(%rbp), %eax
    popq    %rbp
    retq
```

`-O0`에서는 C 코드를 글자 그대로 옮깁니다. 인자를 스택(메모리)에 저장했다가 다시 꺼내서 더합니다. 느리지만 C의 줄과 어셈블리가 하나씩 대응해서 디버거로 따라가기 좋습니다. 공부할 때 `-O0 -g`를 쓰는 이유입니다.

## 두 가지 표기법

x86 어셈블리는 적는 법이 둘입니다.

| | AT&T (리눅스 기본) | Intel (윈도우, 인텔 문서) |
| --- | --- | --- |
| 순서 | `movl %esi, %eax` (원본, 목적지) | `mov eax, esi` (목적지, 원본) |
| 레지스터 | `%eax` | `eax` |
| 숫자 | `$5` | `5` |

Intel 식으로 보려면 `-masm=intel`을 붙입니다. 어느 쪽이든 만들어지는 기계어는 같습니다.

## 그래서

- C가 "이식성 있는 어셈블리"라고 불리는 이유: 같은 소스를 CPU마다 다시 컴파일하면 된다
- 반대로 **실행 파일은 이식되지 않는다**. PC에서 만든 실행 파일은 라즈베리파이에서 돌지 않는다
- PC에서 라즈베리파이용으로 컴파일하는 것을 교차 컴파일이라 하고, 중급에서 다룬다
