타입은 "이 칸들을 몇 바이트로, 어떤 뜻으로 읽을 것인가"를 정합니다. 먼저 정수입니다.

## 기본 정수 타입

| 타입 | 리눅스 64비트에서의 크기 | 표준이 보장하는 것 |
| --- | --- | --- |
| `char` | 1바이트 | 정확히 1바이트 |
| `short` | 2 | 16비트 이상 |
| `int` | 4 | 16비트 이상 |
| `long` | 8 (윈도우는 4) | 32비트 이상 |
| `long long` | 8 | 64비트 이상 |

표준은 최소 크기만 정합니다. 그래서 같은 코드가 플랫폼마다 다르게 동작할 수 있습니다. 실제 크기는 `sizeof`로, 범위는 `<limits.h>`의 `INT_MAX` 같은 상수로 확인합니다.

## 부호 있는 것과 없는 것

| 타입 (32비트) | 범위 |
| --- | --- |
| `int` (= `signed int`) | −2,147,483,648 ~ 2,147,483,647 |
| `unsigned int` | 0 ~ 4,294,967,295 |

같은 32비트를 음수까지 쓰느냐, 0 이상만 쓰느냐의 차이입니다. 음수는 2의 보수로 표현합니다. 비트 하나하나를 다루거나 하드웨어 레지스터를 읽을 때는 `unsigned`를 씁니다.

<Note>
`char`가 부호가 있는지 없는지는 플랫폼마다 다릅니다(x86에서는 있고, ARM 리눅스에서는 없습니다). 글자가 아닌 작은 숫자나 바이트를 담을 때는 `signed char`, `unsigned char`, 또는 아래의 `int8_t`, `uint8_t`를 쓰세요.
</Note>

## 크기가 정해진 타입

```c
#include <stdint.h>

int8_t   a;     // 정확히 8비트, 부호 있음
uint8_t  b;     // 정확히 8비트, 부호 없음 (바이트)
int16_t  c;
uint32_t d;
int64_t  e;
```

파일 형식, 통신 프로토콜, 하드웨어 레지스터처럼 **비트 수가 정해진 곳**에서는 반드시 이 타입들을 씁니다. `long`이 플랫폼마다 달라서 생기는 문제가 없어집니다.

그 밖에 자주 보는 타입입니다.

| 타입 | 쓰임 |
| --- | --- |
| `size_t` | 크기와 개수, 배열 인덱스. `sizeof`와 `strlen`의 결과. 부호 없음 |
| `ptrdiff_t` | 두 포인터의 차 |
| `intptr_t`, `uintptr_t` | 포인터를 담을 수 있는 정수 |
| `bool` | 참과 거짓. C23부터 키워드(그 전에는 `<stdbool.h>`) |

## 넘치면

```c
#include <limits.h>
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    uint8_t u = 255;
    u = u + 1;
    printf("%d\n", u);              // 0: 부호 없는 정수는 한 바퀴 돈다

    unsigned int z = 0;
    printf("%u\n", z - 1);          // 4294967295

    printf("%d\n", INT_MAX);        // 2147483647
    return 0;
}
```

| | 범위를 넘으면 |
| --- | --- |
| 부호 없는 정수 | 표준이 정한 대로 한 바퀴 돈다 (2ⁿ으로 나눈 나머지) |
| 부호 있는 정수 | <strong>정의되지 않은 동작</strong>. 무슨 일이 일어날지 표준이 정하지 않는다 |

`INT_MAX + 1`이 음수가 될 거라고 기대하면 안 됩니다. 컴파일러는 "넘침은 일어나지 않는다"고 가정하고 최적화합니다. 자세한 것은 「UB란 무엇인가」에서 봅니다.

## 숫자 적는 법

```c
int dec = 255;
int hex = 0xff;             // 16진수
int oct = 0377;             // 8진수: 0으로 시작하면 8진수다
int bin = 0b1111'1111;      // 2진수와 자릿수 구분 기호 (둘 다 C23)

unsigned int u = 255u;
long l = 255L;
long long big = 5'000'000'000LL;
```

접미사 없이 적은 숫자는 `int`입니다. `int`에 안 들어가는 큰 수를 계산할 때는 접미사를 붙여 처음부터 큰 타입으로 만듭니다.

<Note kind="warn">
`010`은 10이 아니라 8입니다. 자릿수를 맞추려고 앞에 0을 붙이면 8진수가 됩니다.
</Note>

## printf 서식

| 타입 | 서식 |
| --- | --- |
| `int`, `unsigned` | `%d`, `%u` |
| `long`, `unsigned long` | `%ld`, `%lu` |
| `long long` | `%lld` |
| `size_t` | `%zu` |
| `int32_t`, `uint64_t` 등 | `<inttypes.h>`의 `PRId32`, `PRIu64` |

```c
#include <inttypes.h>
#include <stdio.h>

int main(void)
{
    uint64_t n = 1234567890123ULL;
    printf("%" PRIu64 "\n", n);
    return 0;
}
```

## 정리

- 기본 타입의 크기는 플랫폼마다 다르다. 크기가 중요하면 `<stdint.h>`
- 크기와 인덱스에는 `size_t`
- 부호 없는 정수는 한 바퀴 돌고, 부호 있는 정수의 넘침은 정의되지 않았다
