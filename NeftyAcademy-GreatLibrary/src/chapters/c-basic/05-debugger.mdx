디버거는 프로그램을 원하는 곳에서 멈추고, 한 줄씩 실행하면서 변수와 레지스터를 들여다보는 도구입니다. 첫 프로그램을 디버거로 열어 CPU가 정말 한 걸음씩 가는지 봅니다.

## 준비

```sh
clang -std=c23 -g -O0 hello.c -o hello
gdb ./hello
```

`-g`가 있어야 디버거가 "이 기계어는 `hello.c`의 몇 번째 줄"인지 압니다. 여기서는 GDB로 보여 주고, LLVM의 LLDB 명령은 아래 표에 함께 적습니다. 윈도우에서는 x64dbg나 Visual Studio의 디버거로 같은 일을 할 수 있습니다.

## 멈추고, 보고, 한 줄 가기

```text
(gdb) break main
Breakpoint 1 at 0x114f: file hello.c, line 5.
(gdb) run
Breakpoint 1, main () at hello.c:5
5	    puts("hello, world");
```

<strong>중단점</strong>(breakpoint)을 `main`에 걸고 실행하면 5번째 줄을 실행하기 직전에 멈춥니다. 지금 CPU가 어디 있는지 기계어로 봅니다.

```text
(gdb) set disassembly-flavor intel
(gdb) disassemble
   0x0000555555555140 <+0>:   push   rbp
   0x0000555555555141 <+1>:   mov    rbp,rsp
   0x0000555555555144 <+4>:   sub    rsp,0x10
   0x0000555555555148 <+8>:   mov    DWORD PTR [rbp-0x4],0x0
=> 0x000055555555514f <+15>:  lea    rdi,[rip+0xeae]        # 0x555555556004
   0x0000555555555156 <+22>:  call   0x555555555030 <puts@plt>
   0x000055555555515b <+27>:  xor    eax,eax
   0x000055555555515d <+29>:  add    rsp,0x10
   0x0000555555555161 <+33>:  pop    rbp
   0x0000555555555162 <+34>:  ret
```

`=>`가 다음에 실행할 명령입니다. `main`은 이 열 줄이 전부입니다.

| 명령 | 하는 일 |
| --- | --- |
| `push rbp` ~ `sub rsp,0x10` | 이 함수가 쓸 스택 공간 마련 |
| `lea rdi,[rip+0xeae]` | 글자열 `"hello, world"`의 주소를 `rdi`에 넣기 (첫째 인자) |
| `call puts@plt` | `puts` 부르기 |
| `xor eax,eax` | `eax`를 0으로. `return 0`의 0 |
| `add rsp` ~ `ret` | 스택을 돌려놓고 부른 곳으로 돌아가기 |

글자열이 정말 그 주소에 있는지, 프로그램 카운터(`rip`)가 어디인지 확인합니다.

```text
(gdb) x/s 0x555555556004
0x555555556004:	"hello, world"
(gdb) info registers rip
rip            0x55555555514f      0x55555555514f <main+15>
(gdb) next
hello, world
6	    return 0;
(gdb) info registers rip
rip            0x55555555515b      0x55555555515b <main+27>
```

`next`로 한 줄을 실행하자 글자가 찍혔고, `rip`은 `main+15`에서 `main+27`로 옮겨 갔습니다. [「우리 프로그램이 작동하는 방식」](#/read/basics/code-runs)에서 본 프로그램 카운터가 이것입니다.

## 함수 안으로 들어가기

```c
#include <stdio.h>

int add(int a, int b)
{
    int sum = a + b;
    return sum;
}

int main(void)
{
    int x = add(3, 4);
    printf("%d\n", x);
    return 0;
}
```

```text
(gdb) break add
(gdb) run
Breakpoint 1, add (a=3, b=4) at sum.c:5
5	    int sum = a + b;
(gdb) backtrace
#0  add (a=3, b=4) at sum.c:5
#1  0x000055555555517e in main () at sum.c:11
(gdb) next
6	    return sum;
(gdb) print sum
$1 = 7
(gdb) print &sum
$2 = (int *) 0x7fffffff60f4
(gdb) finish
Value returned is $3 = 7
```

`backtrace`는 "누가 누구를 불렀나"를 보여 줍니다. 지금 `add` 안에 있고, `add`는 `main`의 11번째 줄에서 불렸습니다. `print &sum`은 변수 `sum`이 놓인 메모리 주소입니다. 이 [주소라는 값](#/read/c-basic/ptr-what)이 포인터 챕터의 주제입니다.

## 명령 모음

<Cmd means="중단점 걸기">break 함수 / break 파일:줄</Cmd>
<Cmd means="실행 / 다음 중단점까지 계속">run / continue</Cmd>
<Cmd means="한 줄 가기 (함수는 건너뜀 / 함수 안으로)">next / step</Cmd>
<Cmd means="기계어 명령 하나씩">nexti / stepi</Cmd>
<Cmd means="지금 함수를 끝까지 실행하고 돌아가기">finish</Cmd>
<Cmd means="값 보기">print 식</Cmd>
<Cmd means="메모리 보기 (글자열 / 16진수 4칸)">x/s 주소, x/4x 주소</Cmd>
<Cmd means="호출 순서">backtrace</Cmd>
<Cmd means="레지스터 / 기계어">info registers, disassemble</Cmd>

LLDB는 `break main` 대신 `b main`, `info registers` 대신 `register read`, `x/s` 대신 `memory read`를 쓰고, `run`·`next`·`step`·`finish`·`print`·`bt`는 같습니다.

<Note>
주소 숫자는 실행할 때마다, 컴퓨터마다 다릅니다. 운영체제가 보안을 위해 프로그램을 메모리의 아무 곳에나 올리기 때문입니다(ASLR). GDB는 비교하기 쉽도록 이 기능을 꺼 둔 채 실행합니다.
</Note>

## 정리

- `-g -O0`으로 컴파일하고 `break`, `run`, `next`, `print`로 따라간다
- 프로그램 카운터(`rip`)가 명령을 하나씩 지나가는 것을 직접 볼 수 있다
- 프로그램이 이상할 때 `printf`를 여기저기 넣기 전에 디버거를 먼저 연다
