`#include <stdio.h>`는 C 파일에서 가장 먼저 보는 줄입니다. 이 줄이 실제로 무엇을 하는지, 그리고 우리 헤더는 어떻게 만드는지 봅니다.

## #include는 붙여넣기

`#include`는 컴파일하기 전에 <strong>그 파일의 내용을 그 자리에 통째로 끼워 넣으라</strong>는 지시입니다. 전처리 결과를 보면 확인할 수 있습니다.

```sh
clang -E hello.c | wc -l
```

일곱 줄짜리 `hello.c`가 800줄 넘게 불어납니다(숫자는 시스템마다 다릅니다). 그 안에서 `puts`를 찾으면 이런 줄이 나옵니다.

```c
extern int puts (const char *__s);
```

이것이 `puts`의 <strong>선언</strong>입니다. "`puts`라는 함수가 있고, 글자열 하나를 받아 `int`를 돌려준다"는 약속만 있고 몸통은 없습니다. 몸통은 이미 컴파일되어 C 라이브러리 파일(`libc.so`) 안에 들어 있습니다.

## 선언과 정의

| | 뜻 | 예 |
| --- | --- | --- |
| 선언 | 이름과 모양을 알려 준다. 여러 번 해도 된다 | `int add(int a, int b);` |
| 정의 | 실제 내용을 만든다. 프로그램 전체에서 한 번만 | `int add(int a, int b) { return a + b; }` |

컴파일러는 파일을 위에서 아래로 한 번 읽습니다. 그래서 함수를 부르는 줄보다 **앞에** 그 함수의 선언이 있어야 합니다. 헤더는 그 선언들을 모아 둔 파일입니다.

## 내 헤더 만들기

파일 세 개로 나눠 봅니다.

```c
// add.h
#ifndef ADD_H
#define ADD_H

int add(int a, int b);

#endif
```

```c
// add.c
#include "add.h"

int add(int a, int b)
{
    return a + b;
}
```

```c
// main.c
#include <stdio.h>
#include "add.h"

int main(void)
{
    printf("%d\n", add(3, 4));
    return 0;
}
```

```sh
clang -std=c23 -Wall -Wextra main.c add.c -o app
./app
```

`.c` 파일은 각각 따로 컴파일되고 마지막에 링커가 잇습니다. `main.c`는 `add`의 몸통을 본 적이 없지만 `add.h`의 선언만으로 컴파일됩니다.

## 꺾쇠와 따옴표

| 쓰는 법 | 찾는 곳 |
| --- | --- |
| `#include <stdio.h>` | 시스템 헤더 폴더(`/usr/include` 등) |
| `#include "add.h"` | 지금 파일이 있는 폴더부터, 없으면 시스템 폴더 |

다른 폴더에 있는 헤더는 `-I 폴더` 옵션으로 찾는 곳을 더합니다.

## 인클루드 가드

`add.h`의 `#ifndef ADD_H … #endif`는 같은 헤더가 한 파일에 두 번 끼워져도 내용이 한 번만 들어가게 합니다. 헤더가 다른 헤더를 포함하다 보면 겹치는 일이 흔해서 모든 헤더에 붙입니다. 대부분의 컴파일러는 한 줄짜리 `#pragma once`도 받아 주지만 표준은 아닙니다.

## 헤더에 넣는 것과 넣지 않는 것

| 넣는다 | 넣지 않는다 |
| --- | --- |
| 함수 선언 | 함수의 몸통 |
| `struct`·`typedef` 같은 타입 | 변수의 정의(`int count = 0;`) |
| 매크로, 상수 | 그 파일 안에서만 쓰는 것 |

<Note kind="warn">
헤더에 함수 몸통이나 변수 정의를 넣으면, 그 헤더를 포함한 `.c` 파일마다 같은 것이 하나씩 만들어져 링크할 때 "multiple definition" 오류가 납니다.
</Note>

## 정리

- `#include`는 파일 내용을 그 자리에 끼워 넣는다
- 헤더에는 선언을, `.c`에는 정의를 둔다
- 인클루드 가드로 두 번 들어가는 것을 막는다
