자주 마주치는 정의되지 않은 동작을 종류별로 모았습니다. 각각 무엇이 문제이고 어떻게 쓰면 되는지 봅니다.

## 정수

| UB | 예 | 고치는 법 |
| --- | --- | --- |
| 부호 있는 정수의 넘침 | `INT_MAX + 1`, `-INT_MIN`, `abs(INT_MIN)` | 계산 전에 범위를 확인한다. 넘쳐도 되는 계산은 `unsigned`로 |
| 0으로 나누기 | `x / 0`, `x % 0` | 나누기 전에 확인한다 |
| `INT_MIN / -1` | 결과가 `int`에 안 들어간다 | 이 경우만 따로 처리한다 |
| 너무 많이 밀기 | `1 << 32` (32비트 `int`), `x << -1` | 미는 양은 0 이상, 비트 수 미만 |
| 음수를 왼쪽으로 밀기 | `-1 << 3` | 비트 연산은 `unsigned`로 |

넘침을 안전하게 확인하는 법입니다.

```c
#include <limits.h>
#include <stdckdint.h>      // C23
#include <stdio.h>

bool add_checked(int a, int b, int *out)
{
    if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b))
        return false;       // 더하기 전에 확인한다
    *out = a + b;
    return true;
}

int main(void)
{
    int r;
    printf("%d\n", add_checked(INT_MAX, 1, &r));    // 0 (실패)
    printf("%d\n", ckd_add(&r, INT_MAX, 1));        // 1 (넘쳤다): C23의 표준 도구
    return 0;
}
```

## 메모리

| UB | 예 |
| --- | --- |
| 배열 밖 읽기와 쓰기 | `int a[4]; a[4] = 0;` |
| 널 포인터 따라가기 | `int *p = nullptr; *p = 1;` |
| 해제한 메모리 쓰기 | `free(p); p[0] = 1;` |
| 두 번 해제하기 | `free(p); free(p);` |
| 사라진 지역 변수의 주소 쓰기 | `return &local;` 한 뒤 따라가기 |
| 초기화하지 않은 변수 읽기 | `int x; if (x > 0) …` |
| 글자열 상수 고치기 | `char *s = "hi"; s[0] = 'H';` |
| `const`로 만든 것을 형 변환해서 고치기 | `*(int *)&const_var = 1;` |
| 겹치는 구간에 `memcpy` | `memcpy(a + 1, a, n);` → `memmove`를 쓴다 |

배열의 **끝 바로 다음** 주소를 만드는 것까지는 괜찮습니다(`a + 4`). 반복문의 끝 표시로 쓰기 때문입니다. 따라가는 것은 안 되고, 그보다 더 먼 주소는 만드는 것만으로 UB입니다.

## 한 식에서 두 번 바꾸기

```c nocheck
i = i++ + 1;        // UB
a[i] = i++;         // UB
f(i++, i++);        // UB
```

한 식 안에서 같은 변수를 두 번 바꾸거나, 바꾸면서 다른 곳에서 읽으면 UB입니다. 어느 쪽이 먼저 일어날지 표준이 정하지 않기 때문입니다. `++`와 `--`는 **혼자 한 줄에** 쓰면 문제가 없습니다.

## 타입을 속여 읽기

```c nocheck
float f = 1.0f;
int *p = (int *)&f;
int bits = *p;          // UB: float 를 int 포인터로 읽었다
```

어떤 타입으로 만든 것을 **관계없는 타입의 포인터**로 읽으면 UB입니다(엄격한 별칭 규칙). 컴파일러는 "`int *`와 `float *`는 같은 곳을 가리킬 리 없다"고 가정하고 최적화합니다. 비트를 그대로 옮겨 보고 싶으면 `memcpy`를 씁니다.

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    float f = 1.0f;
    uint32_t bits;
    memcpy(&bits, &f, sizeof bits);     // 바이트를 그대로 복사한다
    printf("0x%08x\n", bits);           // 0x3f800000
    return 0;
}
```

예외가 있습니다. 어떤 것이든 `unsigned char *`(또는 `char *`)로 바이트 단위로 읽는 것은 허용됩니다. `union`을 통해 읽는 것도 C에서는 됩니다.

또 하나, 정렬이 맞지 않는 주소를 따라가는 것도 UB입니다. 바이트 버퍼의 홀수 번째 주소를 `uint32_t *`로 바꿔 읽는 경우입니다. x86에서는 우연히 되지만 다른 CPU에서는 죽을 수 있습니다. 이것도 `memcpy`로 해결합니다.

## 함수

| UB | 예 |
| --- | --- |
| 값을 돌려줘야 하는 함수가 `return` 없이 끝났는데 그 값을 쓴다 | `int f(void) { if (x) return 1; }` |
| `printf` 서식과 인자가 안 맞는다 | `printf("%d", 3.14);`, `printf("%s", 42);` |
| 선언과 다른 모양으로 함수를 부른다 | 함수 포인터를 다른 타입으로 바꿔 호출 |
| 표준 함수에 약속에 어긋나는 인자를 준다 | `strlen(nullptr)`, `isdigit(-5)` |

## 동시에 접근하기

두 스레드가 같은 변수를 동시에 건드리고 그중 하나라도 쓰기이면 UB입니다(데이터 경쟁). 뮤텍스나 원자적 타입으로 막습니다. 중급의 스레드 챕터에서 다룹니다.

## UB가 아닌 것

헷갈리기 쉬운 것들입니다.

| 동작 | 결과 |
| --- | --- |
| 부호 없는 정수의 넘침 | 정의되어 있다. 한 바퀴 돈다 |
| 큰 값을 작은 부호 있는 타입에 대입 | 구현이 정한다 (흔히 위쪽 비트를 버린다) |
| 음수를 오른쪽으로 밀기 | 구현이 정한다 (흔히 부호를 채우며 민다) |
| `free(nullptr)` | 아무 일도 하지 않는다 |
| `malloc(0)` | 널이거나 쓸 수 없는 주소. 구현이 정한다 |
| 함수 인자를 계산하는 순서 | 명시되지 않았다. 순서에 기대지 않으면 된다 |

<Note kind="tip">
C의 UB와 안전한 쓰기에 대해 더 깊이 읽고 싶다면 옌스 구스테트의 『Modern C』가 좋은 길잡이입니다. 이 책의 지침도 그 책의 방향을 따릅니다.
</Note>

## 습관으로 만들 것

- 변수는 선언할 때 초기화한다
- 인덱스와 크기는 `size_t`로 쓰고, 쓰기 전에 범위를 확인한다
- 포인터는 따라가기 전에 널을 확인하고, `free`한 뒤에는 널을 넣는다
- 비트 연산은 `unsigned`로, 비트 수가 중요하면 `uint32_t`로
- 타입을 바꿔 읽을 때는 `memcpy`
- 경고를 모두 켜고, 개발 중에는 ASan과 UBSan을 켠다
