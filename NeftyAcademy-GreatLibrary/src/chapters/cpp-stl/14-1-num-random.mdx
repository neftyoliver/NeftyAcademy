`<random>`은 난수를 두 조각으로 나눕니다. **엔진**이 무작위 비트를 만들고, **분포**가 그 비트를 원하는 범위와 모양의 수로 바꿉니다. `rand() % 6`으로 하던 일을 두 줄로 쓰게 되지만, 그 대가로 치우침이 없고 다시 돌릴 수 있는 난수를 얻습니다.

## 엔진과 분포

```cpp
#include <print>
#include <random>

int main()
{
    std::mt19937 engine(42);                        // 씨앗 42 로 시작하는 엔진
    // 1 부터 6 까지. 양 끝을 포함한다
    std::uniform_int_distribution<int> dice(1, 6);

    for (int i = 0; i < 10; ++i)
        std::print("{}{}", i ? " " : "", dice(engine));
    std::println("");

    std::mt19937 again(42);                         // 같은 씨앗이면 같은 수열
    for (int i = 0; i < 10; ++i)
        std::print("{}{}", i ? " " : "", dice(again));
    std::println("");
}
```

```text
3 5 6 2 5 5 4 4 1 3
3 5 6 2 5 5 4 4 1 3
```

엔진은 진짜 무작위가 아니라 **씨앗에서 계산되는 수열**입니다. 같은 씨앗은 같은 수열을 냅니다. 흠이 아니라 쓸모입니다. 시험과 시뮬레이션은 다시 돌려도 같아야 하고, 버그가 난 판의 씨앗을 적어 두면 그대로 되풀이할 수 있습니다.

`std::mt19937`(메르센 트위스터)이 흔히 쓰는 엔진입니다. 주기가 길고 빠르며, 게임과 시뮬레이션과 시험 자료에 충분합니다.

## %로 줄이면 치우친다

엔진이 낸 수를 `%`로 줄이면 작은 값이 더 자주 나옵니다. 0부터 7까지 여덟 값이 고르게 나오는 원천을 `% 3`으로 줄이면, 0과 1은 세 가지 값(0·3·6, 1·4·7)에서, 2는 두 가지 값(2·5)에서 나옵니다.

```cpp
#include <array>
#include <cstddef>
#include <print>
#include <random>

int main()
{
    std::mt19937 engine(1);
    std::uniform_int_distribution<int> eight(0, 7);
    std::uniform_int_distribution<int> three(0, 2);
    std::array<int, 3> by_modulo{};
    std::array<int, 3> by_distribution{};

    for (int i = 0; i < 800'000; ++i) {
        ++by_modulo[static_cast<std::size_t>(eight(engine) % 3)];
        ++by_distribution[static_cast<std::size_t>(three(engine))];
    }
    std::println("% 3  {} {} {}", by_modulo[0], by_modulo[1], by_modulo[2]);
    std::println("분포 {} {} {}", by_distribution[0], by_distribution[1],
                 by_distribution[2]);
}
```

```text
% 3  299735 299902 200363
분포 266203 266416 267381
```

여기서는 차이를 키우려고 원천을 8가지로 줄였습니다. 원천이 32비트이고 범위가 작으면 치우침은 눈에 띄지 않을 만큼 작지만, 범위가 커질수록 다시 커집니다. 분포는 남는 값을 버리고 다시 뽑아서 치우침을 없앱니다. C의 `rand()`는 여기에 문제가 더 있습니다.

| `rand()`의 문제 | 내용 |
| --- | --- |
| 범위가 좁을 수 있다 | `RAND_MAX`가 32767인 구현이 있다. 그보다 큰 범위는 아예 만들지 못한다 |
| 상태가 전역 하나다 | 어느 코드가 `rand()`를 부르든 수열이 섞인다. 다시 돌려도 같지 않다 |
| 품질과 속도를 알 수 없다 | 구현마다 알고리즘이 다르다 |

## 씨앗

| 씨앗 | 쓰는 곳 |
| --- | --- |
| 정해진 수 (`std::mt19937 engine(42);`) | 시험, 버그 되풀이, 같은 결과가 나와야 하는 시뮬레이션 |
| `std::random_device{}()` | 돌릴 때마다 달라야 하는 실제 실행 |

`std::random_device`는 운영체제가 모은 예측할 수 없는 수를 줍니다. 느려서(아래 표) 난수의 원천으로 쓰지 않고 **씨앗으로만** 씁니다. 가장 흔한 실수는 엔진을 쓸 때마다 새로 만드는 것입니다. 함수 안에 `std::mt19937 engine(std::random_device{}());`를 두면 부를 때마다 5KB를 초기화하고 운영체제를 부릅니다. 엔진은 한 번 만들어 계속 씁니다.

```cpp
#include <print>
#include <random>

// 스레드마다 하나씩, 처음 쓸 때 한 번만 씨앗을 준다
std::mt19937& engine()
{
    thread_local std::mt19937 instance{std::random_device{}()};
    return instance;
}

int roll(int sides)
{
    std::uniform_int_distribution<int> distribution(1, sides);
    return distribution(engine());
}

int main()
{
    bool in_range = true;
    for (int i = 0; i < 1000; ++i) {
        const int value = roll(6);
        in_range = in_range && value >= 1 && value <= 6;
    }
    std::println("모두 1..6 안에 있다 {}", in_range);
}
```

```text
모두 1..6 안에 있다 true
```

엔진은 스레드에 안전하지 않으므로 [`thread_local`](#/read/cpp-syntax/life-storage)로 스레드마다 하나씩 둡니다. 분포 객체는 가벼워서 쓸 때 만들어도 됩니다. 시험할 수 있게 하려면 전역 엔진에 기대지 말고 **엔진을 인자로 받는** 함수로 만듭니다. 시험에서는 씨앗이 정해진 엔진을 넘깁니다.

## 분포 고르기

| 분포 | 내는 것 | 쓰는 곳 |
| --- | --- | --- |
| `uniform_int_distribution<int>(a, b)` | `a` 이상 `b` **이하**의 정수 | 주사위, 인덱스 |
| `uniform_real_distribution<double>(a, b)` | `a` 이상 `b` **미만**의 실수 | 확률, 좌표 |
| `bernoulli_distribution(p)` | 확률 `p`로 `true` | 실패 주입, 동전 |
| `normal_distribution<double>(평균, 표준편차)` | 종 모양 | 센서 잡음 흉내 |
| `discrete_distribution<int>({무게...})` | 무게에 비례해 0, 1, 2, … | 등급별 뽑기 |
| `exponential_distribution<double>(비율)` | 사건 사이의 간격 | 도착 시간 흉내 |

```cpp
#include <array>
#include <cstddef>
#include <print>
#include <random>

int main()
{
    std::mt19937 engine(2026);

    std::normal_distribution<double> noise(20.0, 0.5);
    const double a = noise(engine);
    const double b = noise(engine);
    std::println("normal     {:.2f} {:.2f}", a, b);

    std::bernoulli_distribution fails(0.3);
    int failures = 0;
    for (int i = 0; i < 100'000; ++i)
        failures += fails(engine);
    std::println("bernoulli  10만 번에 {}번", failures);

    std::discrete_distribution<int> loot({70, 25, 5});
    std::array<int, 3> drops{};
    for (int i = 0; i < 100'000; ++i)
        ++drops[static_cast<std::size_t>(loot(engine))];
    std::println("discrete   {} {} {}", drops[0], drops[1], drops[2]);
}
```

```text
normal     20.02 19.91
bernoulli  10만 번에 30075번
discrete   70105 24890 5005
```

`noise(engine)`을 `println`의 인자 자리에 두 번 쓰지 않고 변수에 받은 것은 까닭이 있습니다. 함수 인자가 계산되는 순서는 정해져 있지 않아서, 한 줄에 두 번 쓰면 GCC 14에서는 오른쪽 것이 먼저 뽑힙니다. 순서가 뜻이 있는 호출은 한 줄에 하나씩 씁니다.

## 섞기와 뽑기

```cpp
#include <algorithm>
#include <iterator>
#include <print>
#include <random>
#include <string>
#include <vector>

int main()
{
    std::mt19937 engine(7);
    std::vector<std::string> deck{"A", "B", "C", "D", "E", "F", "G", "H"};

    std::ranges::shuffle(deck, engine);
    for (const auto& card : deck)
        std::print("{}", card);
    std::println("");

    // 겹치지 않게 셋을 뽑는다. 원래 순서를 지킨다
    std::vector<std::string> hand;
    std::ranges::sample(deck, std::back_inserter(hand), 3, engine);
    for (const auto& card : hand)
        std::print("{}", card);
    std::println("");
}
```

```text
CHGEBFDA
BDA
```

"겹치지 않게 `n`개"가 필요할 때 난수를 뽑아 겹치는지 확인하는 루프를 짜지 않습니다. `shuffle`한 뒤 앞의 `n`개를 쓰거나 `sample`을 씁니다. C++17에서 사라진 [`std::random_shuffle`](#/read/cpp-syntax/leg-98)은 `rand()`를 썼습니다.

## 재현성, 크기, 속도

같은 씨앗의 **엔진**은 어느 컴파일러에서나 같은 수열을 냅니다. 표준이 알고리즘을 정해 두었습니다. **분포**는 그렇지 않습니다. 이 페이지의 첫 예제를 Clang의 libc++로 돌리면 `4 5 3 5 5 2 3 3 3 5`가 나옵니다. 다른 플랫폼과 같은 결과를 내야 하는 코드(리플레이, 멀티플레이 동기화, 기대 출력을 박아 둔 시험)는 표준 분포를 쓰지 않고 엔진의 출력을 직접 범위로 바꿉니다.

| 원천 | 크기 | 1억 번 뽑는 시간 |
| --- | --- | --- |
| `std::mt19937` | 5,000바이트 | 209 ms |
| `std::mt19937_64` | 2,504바이트 | 205 ms |
| `std::minstd_rand` | 8바이트 | 373 ms |
| `std::mt19937` + `uniform_int_distribution` | | 340 ms |
| `std::rand()` | | 1,322 ms |
| `std::random_device` | 5,000바이트 | 116,300 ms |

x86-64 서버, GCC 14 `-O2`에서 잰 값이고, 마지막 줄은 100만 번을 재어 100배 한 것입니다. `random_device`는 한 번에 1.2마이크로초가 듭니다. `mt19937`이 5KB나 되는 것은 624칸짜리 상태를 가지기 때문이고, x86-64의 libstdc++에서는 한 칸이 8바이트라서 `mt19937_64`보다 오히려 큽니다. RAM이 수 KB인 마이크로컨트롤러에서는 이 크기 때문에 다른 엔진을 고릅니다.

<Note kind="warn">
이 엔진들은 **보안용이 아닙니다.** 출력을 얼마간 보면 다음 값을 계산할 수 있습니다. 암호 키, 세션 토큰, 비밀번호 재설정 링크는 `mt19937`로 만들지 않고 운영체제의 암호용 난수(리눅스의 `getrandom`)나 암호 라이브러리로 만듭니다. `std::random_device`도 표준이 품질을 보장하지 않습니다.
</Note>

## 정리

- 엔진이 비트를 만들고 분포가 범위와 모양을 정한다. `%`로 범위를 줄이면 치우치므로 `uniform_int_distribution`을 쓴다
- 엔진은 한 번 만들어 계속 쓴다. 시험에는 정해진 씨앗을, 실제 실행에는 `random_device`로 얻은 씨앗을 준다
- 엔진의 수열은 어디서나 같지만 분포의 결과는 구현마다 다르다. 보안이 걸린 값에는 쓰지 않는다
