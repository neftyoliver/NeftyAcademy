`<<`와 `>>`는 값을 **글자로** 바꿉니다. 센서 로그, 이미지, 펌웨어처럼 바이트 그대로 주고받아야 하는 자료에는 `read`와 `write`를 씁니다.

## read와 write

| 함수 | 하는 일 |
| --- | --- |
| `out.write(p, n)` | `p`부터 `n`바이트를 그대로 쓴다 |
| `in.read(p, n)` | `n`바이트를 읽어 `p`에 넣는다. 모자라면 `failbit`와 `eofbit`가 켜진다 |
| `in.gcount()` | 방금의 `read`가 실제로 읽은 바이트 수 |
| `in.seekg(pos)`, `out.seekp(pos)` | 읽는 자리, 쓰는 자리를 옮긴다 |
| `in.tellg()`, `out.tellp()` | 지금 자리 |

`p`의 타입은 `char*`입니다. 다른 타입의 메모리를 넘길 때는 `reinterpret_cast<char*>`가 필요하고, `char`로 들여다보는 것은 [별칭 규칙의 예외](#/read/cpp-syntax/ubc-aliasing)라서 허용됩니다.

파일은 <strong>`std::ios::binary`</strong>로 엽니다. 윈도우의 텍스트 방식은 쓸 때 `\n`을 `\r\n`으로 바꾸고, 읽을 때 되돌리며, 값이 `0x1A`인 바이트를 파일의 끝으로 여깁니다. 이진 자료 속의 `0x0A`가 두 바이트로 늘어나 파일이 깨집니다. 리눅스에서는 두 방식이 같지만, 붙여 두면 어디서 컴파일해도 같은 결과가 나옵니다.

## 구조체를 통째로 쓰면

가장 쉬운 방법은 구조체의 메모리를 그대로 쓰는 것입니다. 무엇이 파일에 들어가는지 봅니다.

```cpp
#include <bit>
#include <cstddef>
#include <cstdint>
#include <cstring>
#include <print>
#include <span>
#include <string>
#include <type_traits>

struct Record {
    std::uint8_t channel;
    std::int32_t centi_celsius;     // 섭씨 × 100
    std::uint16_t flags;
};

void hex_dump(std::span<const std::byte> bytes)
{
    for (std::size_t i = 0; i < bytes.size(); ++i)
        std::print("{}{:02x}", i ? " " : "", std::to_integer<int>(bytes[i]));
    std::println("");
}

int main()
{
    std::println("sizeof {} / 멤버의 합 {}", sizeof(Record), 1 + 4 + 2);

    // 쓰레기 값이 있던 메모리를 흉내 낸다
    Record r;
    std::memset(&r, 0xAA, sizeof r);
    r.channel = 3;
    r.centi_celsius = -1250;
    r.flags = 0x8001;
    hex_dump(std::as_bytes(std::span(&r, 1)));

    const bool little = std::endian::native == std::endian::little;
    std::println("작은 쪽부터 놓는 기계인가 {}", little);
    std::println("그대로 복사해도 되는 타입인가 {} {}",
                 std::is_trivially_copyable_v<Record>,
                 std::is_trivially_copyable_v<std::string>);
}
```

```text
sizeof 12 / 멤버의 합 7
03 aa aa aa 1e fb ff ff 01 80 aa aa
작은 쪽부터 놓는 기계인가 true
그대로 복사해도 되는 타입인가 true false
```

`out.write(reinterpret_cast<const char*>(&r), sizeof r)`로 쓰면 이 12바이트가 파일에 들어갑니다. 문제가 넷입니다.

| 문제 | 위에서 보이는 것 |
| --- | --- |
| [채움 바이트](#/read/cpp-syntax/life-alignment) | `aa` 다섯 개. 7바이트면 될 것이 12바이트가 되고, 메모리에 있던 쓰레기 값이 파일로 나간다 |
| 바이트 순서 | `-1250`이 `1e fb ff ff`. 큰 쪽부터 놓는 기계는 `ff ff fb 1e`로 읽는다 |
| 배치는 컴파일러의 몫 | 다른 컴파일러, 다른 옵션, 다른 CPU에서 채움이 달라질 수 있다 |
| 포인터를 품은 타입 | `std::string`을 이렇게 쓰면 글자가 아니라 **주소**가 파일에 들어간다 |

같은 기계의 같은 프로그램이 곧바로 다시 읽는 캐시 정도에는 써도 됩니다. 그때도 `static_assert(std::is_trivially_copyable_v<Record>);`를 붙여 두면, 누가 `std::string` 멤버를 넣는 순간 컴파일이 멈춥니다. 다른 기기나 다른 버전의 프로그램이 읽을 파일이라면 형식을 직접 정합니다.

## 한 필드씩, 순서를 정해서

파일 형식을 "어느 바이트에 무엇이, 어떤 순서로"까지 정하고, 그대로 쓰고 읽는 함수를 둡니다.

```cpp
#include <cstddef>
#include <cstdint>
#include <filesystem>
#include <fstream>
#include <print>
#include <string_view>
#include <type_traits>
#include <vector>

struct Record {
    std::uint8_t channel;
    std::int32_t centi_celsius;
    std::uint16_t flags;
};

// 정수를 작은 쪽 바이트부터(리틀 엔디언) 쓴다
template <typename T>
void put_le(std::ostream& out, T value)
{
    const auto bits = static_cast<std::make_unsigned_t<T>>(value);
    char bytes[sizeof(T)];
    for (std::size_t i = 0; i < sizeof(T); ++i)
        bytes[i] = static_cast<char>((bits >> (8 * i)) & 0xff);
    out.write(bytes, sizeof bytes);
}

template <typename T>
bool get_le(std::istream& in, T& value)
{
    using U = std::make_unsigned_t<T>;
    unsigned char bytes[sizeof(T)];
    if (!in.read(reinterpret_cast<char*>(bytes), sizeof bytes))
        return false;
    U bits = 0;
    for (std::size_t i = 0; i < sizeof(T); ++i)
        bits |= static_cast<U>(static_cast<U>(bytes[i]) << (8 * i));
    value = static_cast<T>(bits);
    return true;
}

int main()
{
    const auto path = std::filesystem::temp_directory_path() / "na-records.bin";
    const std::vector<Record> records{{1, 2150, 0}, {2, -1250, 0x8001}, {3, 0, 1}};
    {
        std::ofstream out(path, std::ios::binary);
        out.write("NALG", 4);                       // 무슨 파일인지 알리는 4바이트
        put_le<std::uint16_t>(out, 1);              // 형식 버전
        put_le(out, static_cast<std::uint32_t>(records.size()));
        for (const Record& r : records) {
            put_le(out, r.channel);
            put_le(out, r.centi_celsius);
            put_le(out, r.flags);
        }
    }
    std::println("파일 크기 {}", std::filesystem::file_size(path));

    std::ifstream in(path, std::ios::binary);
    char magic[4] = {};
    std::uint16_t version = 0;
    std::uint32_t count = 0;
    in.read(magic, 4);
    get_le(in, version);
    get_le(in, count);
    std::println("{} v{} 레코드 {}개", std::string_view(magic, 4), version, count);

    // 둘째 레코드로 바로 간다: 머리 10바이트 + 레코드 7바이트 × 1
    in.seekg(10 + 7 * 1);
    Record r{};
    get_le(in, r.channel);
    get_le(in, r.centi_celsius);
    get_le(in, r.flags);
    const auto here = static_cast<long>(in.tellg());
    std::println("채널 {} 값 {} 깃발 {:#x}, 지금 자리 {}", r.channel,
                 r.centi_celsius, r.flags, here);

    // 끝에서 3바이트 앞으로 가서 4바이트를 읽으려 한다
    in.seekg(-3, std::ios::end);
    std::uint32_t too_much = 0;
    const bool ok = get_le(in, too_much);
    std::println("읽혔나 {}, 실제로 읽은 바이트 {}", ok, in.gcount());
    std::filesystem::remove(path);
}
```

```text
파일 크기 31
NALG v1 레코드 3개
채널 2 값 -1250 깃발 0x8001, 지금 자리 24
읽혔나 false, 실제로 읽은 바이트 3
```

파일은 머리 10바이트(4 + 2 + 4)와 레코드 7바이트 셋으로 정확히 31바이트입니다. 채움이 없고, 어떤 CPU에서 읽어도 같은 값이 나옵니다. 시프트로 바이트를 꺼내고 모으므로 기계의 바이트 순서와 상관이 없습니다.

형식을 정할 때 넣어 두면 좋은 것이 예제에 다 있습니다.

- **매직 넘버**: 맨 앞의 정해진 몇 바이트. 엉뚱한 파일을 읽으려 할 때 바로 압니다
- **버전**: 형식을 바꿀 날이 옵니다. 읽는 쪽이 모르는 버전이면 거절합니다
- **고정 폭 타입**: `int`, `long`이 아니라 [`std::int32_t`](#/read/cpp-syntax/types-builtin) 같은 것으로 크기를 못 박습니다
- **개수나 길이를 먼저**: 뒤에 올 것이 몇 개인지 알아야 읽는 쪽이 메모리를 준비합니다. 파일에서 읽은 개수는 **믿기 전에 상한을 확인**합니다. 깨진 파일의 `count`가 40억이면 그대로 `reserve`하다 죽습니다

## 자리 옮기기와 짧은 읽기

레코드의 크기가 일정하면 `seekg`로 `i`번째 레코드에 바로 갈 수 있습니다. 텍스트 파일에서는 줄의 길이가 제각각이라 할 수 없는 일입니다. `seekg(offset, 기준)`의 기준은 `std::ios::beg`(처음), `std::ios::cur`(지금), `std::ios::end`(끝)입니다.

마지막 줄이 보여 주는 것은 **짧은 읽기**입니다. 4바이트를 달라고 했는데 3바이트밖에 없으면 `read`는 있는 만큼 채우고 실패 상태가 됩니다. 반환된 스트림을 `if`로 확인하지 않으면 반쯤 채워진 값을 그대로 쓰게 됩니다. 이진 파일을 읽는 코드에서 `read`의 결과를 버리는 줄이 있으면 버그입니다.

<Note>
바이트 순서를 뒤집는 일은 C++23의 `std::byteswap`으로도 합니다(`std::byteswap(std::uint16_t{0x1234})`는 `0x3412`). `std::endian::native`와 견주어 필요할 때만 뒤집는 방식입니다. 위의 시프트 루프도 느리지는 않습니다. x86-64에서 `-O2`로 확인하면 쓰는 쪽은 GCC 14와 Clang 20이 모두 명령 하나로 줄이고, 읽는 쪽은 Clang만 그렇게 합니다. 네트워크 규약은 대개 큰 쪽부터(빅 엔디언) 보냅니다.
</Note>

## 정리

- 이진 자료는 `std::ios::binary`로 열고 `read`와 `write`로 다룬다. `read`가 모자라게 읽으면 실패 상태가 되므로 결과를 늘 확인한다
- 구조체를 통째로 쓰면 채움 바이트, 바이트 순서, 컴파일러마다 다른 배치가 파일에 들어간다. 포인터를 품은 타입은 아예 안 된다
- 남이 읽을 파일은 매직 넘버, 버전, 고정 폭 타입, 정해진 바이트 순서로 한 필드씩 쓴다
