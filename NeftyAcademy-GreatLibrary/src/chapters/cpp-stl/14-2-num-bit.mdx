켜진 비트를 세거나 가장 낮은 켜진 비트를 찾는 일은 예전에는 루프로 짜거나 `__builtin_popcount` 같은 컴파일러 전용 함수로 했습니다. C++20의 `<bit>`가 이것들을 표준 함수로 내놓았습니다. [`bitset`](#/read/cpp-stl/voc-bitset)과 달리 보통의 부호 없는 정수에 바로 씁니다.

## 세기와 찾기

| 함수 | 주는 것 |
| --- | --- |
| `std::popcount(x)` | 켜진 비트의 수 |
| `std::countr_zero(x)` | 낮은 쪽 끝에서 이어지는 0의 수. 곧 **가장 낮은 켜진 비트의 번호** |
| `std::countl_zero(x)` | 높은 쪽 끝에서 이어지는 0의 수 |
| `std::countr_one(x)`, `std::countl_one(x)` | 같은 것을 1로 센다 |
| `std::bit_width(x)` | `x`를 적는 데 필요한 비트 수. 0이면 0 |

```cpp
#include <bit>
#include <cstdint>
#include <print>

int main()
{
    const std::uint8_t flags = 0b0010'1100;
    std::println("popcount    {}", std::popcount(flags));
    std::println("countr_zero {}", std::countr_zero(flags));
    std::println("countl_zero {}", std::countl_zero(flags));
    std::println("bit_width   {}", std::bit_width(flags));

    // 0 을 넣어도 정의되어 있다: 그 타입의 비트 수
    std::println("{} {}", std::countr_zero(std::uint32_t{0}),
                 std::countl_zero(std::uint8_t{0}));
}
```

```text
popcount    3
countr_zero 2
countl_zero 2
bit_width   6
32 8
```

알아 둘 것이 둘입니다.

- **부호 없는 정수만 받습니다.** `std::popcount(-1)`이나 `int` 변수를 넣으면 컴파일 오류입니다. 부호 있는 수의 비트를 세는 것이 무슨 뜻인지 애매하기 때문이고, 필요하면 `static_cast<unsigned>`로 뜻을 밝힙니다
- **결과가 타입의 폭에 달려 있습니다.** `countl_zero`는 같은 값 `0x2C`라도 `uint8_t`이면 2, `uint32_t`이면 26입니다. 0을 넣었을 때 `__builtin_ctz`는 정의되지 않은 동작이지만 이 함수들은 타입의 비트 수를 줍니다

## 켜진 비트만 차례로

인터럽트 대기 표시, 눌린 버튼, 준비된 채널처럼 "켜진 비트마다 무언가 한다"는 코드는 `countr_zero`로 씁니다.

```cpp
#include <bit>
#include <cstdint>
#include <print>

int main()
{
    const char* names[] = {"timer", "uart-rx", "uart-tx", "gpio",
                           "adc",   "i2c",     "spi",     "watchdog"};

    std::uint32_t pending = 0b1010'0100;
    while (pending != 0) {
        const int bit = std::countr_zero(pending);
        std::println("처리: {} ({}번)", names[bit], bit);
        pending &= pending - 1;     // 가장 낮은 켜진 비트를 끈다
    }
}
```

```text
처리: uart-tx (2번)
처리: i2c (5번)
처리: watchdog (7번)
```

0번부터 31번까지 하나씩 `if (pending & (1u << i))`로 묻는 루프는 32번 돕니다. 이 루프는 **켜진 수만큼만** 돕니다. `x & (x - 1)`은 가장 낮은 켜진 비트 하나를 끄는 오래된 요령입니다. 높은 쪽이 급한 일이면 `countl_zero`로 같은 일을 합니다.

## 2의 거듭제곱

| 함수 | 주는 것 |
| --- | --- |
| `std::has_single_bit(x)` | 비트가 꼭 하나 켜져 있는가. 곧 2의 거듭제곱인가 |
| `std::bit_ceil(x)` | `x` 이상인 가장 작은 2의 거듭제곱 |
| `std::bit_floor(x)` | `x` 이하인 가장 큰 2의 거듭제곱. 0이면 0 |

```cpp
#include <bit>
#include <cstddef>
#include <print>

// 용량을 2의 거듭제곱으로 올려 잡으면 나머지 연산이 & 하나가 된다
struct Ring {
    std::size_t capacity;

    explicit Ring(std::size_t wanted) : capacity(std::bit_ceil(wanted)) {}
    std::size_t wrap(std::size_t index) const { return index & (capacity - 1); }
};

// alignment 는 2의 거듭제곱이어야 한다
constexpr std::size_t align_up(std::size_t n, std::size_t alignment)
{
    return (n + alignment - 1) & ~(alignment - 1);
}

int main()
{
    for (const unsigned n : {0u, 1u, 5u, 64u, 100u}) {
        std::println("{:3}: 하나만 켜짐 {:5} / ceil {:3} / floor {}", n,
                     std::has_single_bit(n), std::bit_ceil(n), std::bit_floor(n));
    }

    const Ring ring(100);
    std::println("{} {} {}", ring.capacity, ring.wrap(127), ring.wrap(130));
    std::println("{} {} {}", align_up(13, 8), align_up(16, 8),
                 align_up(4097, 4096));
}
```

```text
  0: 하나만 켜짐 false / ceil   1 / floor 0
  1: 하나만 켜짐 true  / ceil   1 / floor 1
  5: 하나만 켜짐 false / ceil   8 / floor 4
 64: 하나만 켜짐 true  / ceil  64 / floor 64
100: 하나만 켜짐 false / ceil 128 / floor 64
128 127 2
16 16 8192
```

[링 버퍼](#/read/cpp-syntax/tpl-nontype)의 `index % capacity`는 나눗셈입니다. 용량이 2의 거듭제곱이면 `index & (capacity - 1)`로 같은 답을 얻습니다. 나눗셈 명령이 없거나 느린 작은 CPU에서 차이가 납니다. `align_up`도 같은 요령으로, [정렬](#/read/cpp-syntax/life-alignment)에 맞춰 크기를 올림합니다. 인자가 2의 거듭제곱이 아니면 틀린 답이 나오므로 `has_single_bit`로 확인해 둘 만합니다.

`bit_ceil`은 답이 그 타입에 담기지 않으면 정의되지 않은 동작입니다. `std::uint8_t{200}`에는 쓸 수 없습니다.

## 돌리기

```cpp
#include <bit>
#include <cstdint>
#include <print>

int main()
{
    const std::uint8_t pattern = 0b1001'0001;
    std::println("{:08b} rotl {:08b} rotr {:08b}", pattern,
                 std::rotl(pattern, 1), std::rotr(pattern, 1));
    // 밀기는 넘친 비트를 버린다
    const auto shifted = static_cast<std::uint8_t>(pattern << 1);
    std::println("{:08b} <<   {:08b}", pattern, shifted);
}
```

```text
10010001 rotl 00100011 rotr 11001000
10010001 <<   00100010
```

`rotl`과 `rotr`은 넘친 비트를 반대쪽 끝으로 되돌립니다. 해시 함수, 체크섬, 암호 알고리즘이 쓰는 연산이고, 32비트 값을 `(x << n) | (x >> (32 - n))`으로 손수 돌리면 `n`이 0일 때 32칸을 밀게 되어 정의되지 않은 동작입니다. 바이트 순서를 뒤집는 `std::byteswap`과 `std::endian`은 [「이진 입출력」](#/read/cpp-stl/io-binary)에서, 비트 그대로 다른 타입으로 읽는 `std::bit_cast`는 [「reinterpret_cast와 std::bit_cast」](#/read/cpp-syntax/cast-reinterpret)에서 봤습니다.

## 명령 하나가 되는가

이 함수들의 값어치는 CPU의 전용 명령으로 바뀐다는 데 있습니다. GCC 14 `-O2`가 만든 어셈블리를 확인했습니다.

| 함수 | x86-64 (기본 설정) | x86-64 (`-march=x86-64-v3`) | AArch64 |
| --- | --- | --- | --- |
| `std::popcount` | `__popcountdi2` 함수 호출 | `popcnt` 하나 | `cnt`, `addv` |
| `std::countr_zero` | `bsf` 하나 | `tzcnt` 하나 | `rbit`, `clz` |

x86-64의 기본 설정에서 `popcount`가 **함수 호출**이 되는 것이 눈에 띕니다. 2003년의 첫 x86-64 CPU에는 `popcnt` 명령이 없었고, 컴파일러는 따로 말해 주지 않으면 그 CPU에서도 도는 코드를 만듭니다. `-mpopcnt`나 `-march=native`를 주면 명령 하나가 됩니다. 라즈베리 파이 3부터 5까지가 쓰는 AArch64에서는 옵션 없이도 명령 두세 개로 끝납니다. 빠르다고 믿기 전에 `-S`로 한 번 확인하는 버릇이 이런 데서 값을 합니다.

## 넘침을 피하는 산술

`<numeric>`에 비트 조작과 자주 함께 쓰이는 함수가 있습니다.

```cpp std26
#include <cstdint>
#include <numeric>
#include <print>

int main()
{
    // (a + b) / 2 는 a + b 가 넘칠 수 있다. midpoint 는 넘치지 않는다
    std::println("{}", std::midpoint(2'000'000'000, 2'100'000'000));
    std::println("{} {}", std::midpoint(1, 4), std::midpoint(4, 1));
    std::println("{} {}", std::gcd(12, 18), std::lcm(4, 6));

    // C++26: 넘치면 감기지 않고 끝에서 멈춘다
    std::println("{} {}", std::add_sat<std::uint8_t>(200, 100),
                 std::sub_sat<std::uint8_t>(10, 20));
    std::println("{}", std::saturate_cast<std::uint8_t>(300));
}
```

```text
2050000000
2 3
6 12
255 0
255
```

이진 탐색의 가운데를 `(low + high) / 2`로 구하면 두 수의 합이 `int`의 범위를 넘을 때 [정의되지 않은 동작](#/read/c-basic/ub-what)입니다. `std::midpoint`는 그 걱정이 없고, 딱 가운데가 없을 때는 첫 인자 쪽으로 기웁니다. [포화 산술](#/read/cpp-syntax/ver-26)(`add_sat`, `sub_sat`, `saturate_cast`)은 GCC 14에서 `-std=c++26`으로 켜야 합니다. 밝기나 볼륨처럼 "넘으면 끝값"이 맞는 양에 씁니다. `uint8_t`에 200 + 100을 그냥 더하면 44가 됩니다.

<Note>
`<bit>`의 함수는 모두 `constexpr`이라 [컴파일할 때](#/read/cpp-syntax/ct-constexpr) 계산할 수 있습니다. 표의 크기나 마스크를 `std::bit_ceil`로 정하고 `static_assert(std::has_single_bit(N))`으로 지키는 식으로 씁니다.
</Note>

## 정리

- `<bit>`의 함수는 부호 없는 정수에 쓴다. `popcount`로 세고, `countr_zero`로 가장 낮은 켜진 비트를 찾고, `x &= x - 1`로 끄면서 켜진 것만 돈다
- 2의 거듭제곱은 `has_single_bit`, `bit_ceil`, `bit_floor`로 다룬다. 용량을 2의 거듭제곱으로 잡으면 나머지 연산이 `&` 하나가 된다
- 이 함수들은 CPU 명령으로 바뀌지만 대상과 옵션에 따라 다르다. x86-64의 기본 설정에서 `popcount`는 함수 호출이고, AArch64에서는 명령 둘이다
