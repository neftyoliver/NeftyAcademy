[「예외 없이 오류 알리기: optional과 expected」](#/read/cpp-syntax/exc-without)에서 `std::optional<T>`를 "없을 수 있는 값"으로 쓰고, `transform`과 `and_then`으로 이어 붙였습니다. 여기서는 속이 어떻게 생겼는지와, 반환값 말고 쓰이는 자리를 봅니다.

## 값을 안에 품는다

`std::optional<T>`는 포인터가 아닙니다. `T`가 들어갈 자리와 "지금 값이 있는가"라는 표시 하나를 **자기 안에** 가집니다. 힙을 쓰지 않습니다.

```cpp
#include <optional>
#include <print>
#include <string>

int main()
{
    std::println("optional<char>   {}", sizeof(std::optional<char>));
    std::println("optional<int>    {}", sizeof(std::optional<int>));
    std::println("optional<double> {}", sizeof(std::optional<double>));
    std::println("optional<string> {}", sizeof(std::optional<std::string>));
    std::println("string           {}", sizeof(std::string));

    // 비어 있다. string 은 아직 만들어지지 않았다
    std::optional<std::string> name;
    std::println("{}", name.has_value());
    name.emplace(3, 'x');                   // 그 자리에서 string(3, 'x') 를 만든다
    std::println("{} {}", name.has_value(), *name);
    name.reset();                           // 든 값을 없앤다. 소멸자가 불린다
    name = "led";
    name = std::nullopt;                    // reset() 과 같다
    std::println("{}", name.has_value());
}
```

```text
optional<char>   2
optional<int>    8
optional<double> 16
optional<string> 40
string           32
false
true xxx
false
```

표시 하나에 [정렬 때문에 채움 바이트](#/read/cpp-syntax/life-alignment)가 붙어, `double` 하나가 16바이트가 됩니다. `optional<double>` 100만 개의 배열은 8MB가 아니라 16MB입니다. 메모리가 빠듯한 곳에서 "없음"을 수없이 담아야 하면, 쓰지 않는 값 하나(NaN, -1)를 없음으로 삼는 옛 방식이 여전히 쓸모 있습니다.

비어 있는 동안에는 `T`가 **만들어지지 않습니다.** 자리만 있습니다. 이 성질이 아래의 "나중에 만드는 멤버"에 쓰입니다.

## 꺼내는 세 가지 방법

| 방법 | 비어 있을 때 |
| --- | --- |
| `*opt`, `opt->멤버` | 정의되지 않은 동작. 검사하지 않는다 |
| `opt.value()` | `std::bad_optional_access` 예외 |
| `opt.value_or(기본값)` | 기본값 |

`*opt`는 포인터처럼 생겼고 포인터처럼 위험합니다. `if (opt)`로 확인한 블록 안에서만 씁니다. `-D_GLIBCXX_ASSERTIONS`로 빌드하면 빈 `optional`에 `*`를 쓰는 순간 멈춥니다([「디버그 모드와 경화 모드」](#/read/cpp-stl/impl-debug)).

## optional&lt;bool&gt;의 함정

`if (opt)`는 **값이 있는가**를 묻습니다. 든 값이 무엇인지가 아닙니다.

```cpp
#include <optional>
#include <print>

std::optional<bool> read_switch(int pin)
{
    if (pin < 0)
        return std::nullopt;        // 읽지 못했다
    return pin % 2 == 1;            // 홀수 핀은 켜져 있다고 하자
}

int main()
{
    const auto off = read_switch(4);        // 값이 있고, 그 값이 false
    if (off)
        std::println("if (off) 는 참이다. 값은 {}", *off);

    for (int pin : {3, 4, -1}) {
        const auto state = read_switch(pin);
        if (!state)
            std::println("{:2}: 읽지 못함", pin);
        else if (*state)
            std::println("{:2}: 켜짐", pin);
        else
            std::println("{:2}: 꺼짐", pin);
    }
    // 값과 직접 견줄 수 있다
    std::println("{} {}", off == false, off == std::nullopt);
}
```

```text
if (off) 는 참이다. 값은 false
 3: 켜짐
 4: 꺼짐
-1: 읽지 못함
true false
```

스위치가 꺼져 있는데 `if (off)`가 참입니다. `optional<bool>`, `optional<int>`(0), 포인터를 담은 `optional`에서 같은 일이 생깁니다. 세 가지 상태를 가르는 코드는 위처럼 "있는가"를 먼저 묻고 그다음에 값을 봅니다. `opt == false`처럼 값과 직접 견주면 "값이 있고 그것이 `false`인가"가 되어 뜻이 분명합니다.

## 나중에 만드는 멤버

기본 생성자가 없는 타입을 멤버로 두되, 만드는 때를 뒤로 미루고 싶을 때가 있습니다. 포트 번호를 설정에서 읽은 뒤에야 열 수 있는 장치가 그렇습니다. `std::unique_ptr`로 하면 힙이 들고, `optional`로 하면 객체 안의 자리에 만듭니다.

```cpp
#include <optional>
#include <print>
#include <string>
#include <utility>

class Serial {
public:
    Serial(std::string port, int baud) : port_(std::move(port)), baud_(baud)
    {
        std::println("  {} 을 {} 로 연다", port_, baud_);
    }
    ~Serial() { std::println("  {} 을 닫는다", port_); }
    void write(const std::string& text) { std::println("  {} <- {}", port_, text); }

private:
    std::string port_;
    int baud_;
};

class Logger {
public:
    void open(std::string port, int baud)
    {
        serial_.emplace(std::move(port), baud);     // 이때 Serial 이 만들어진다
    }
    void close() { serial_.reset(); }
    void log(const std::string& text)
    {
        if (serial_)
            serial_->write(text);
        else
            std::println("  (열리지 않음) {}", text);
    }

private:
    // 처음에는 비어 있다. Serial 은 만들어지지 않는다
    std::optional<Serial> serial_;
};

int main()
{
    Logger logger;
    logger.log("boot");
    logger.open("/dev/ttyAMA0", 115200);
    logger.log("ready");
    logger.close();
    std::println("끝");
}
```

```text
  (열리지 않음) boot
  /dev/ttyAMA0 을 115200 로 연다
  /dev/ttyAMA0 <- ready
  /dev/ttyAMA0 을 닫는다
끝
```

`emplace`가 생성자를, `reset`이 소멸자를 부릅니다. [placement new](#/read/cpp-syntax/life-new)로 손수 하던 일을 타입이 대신해 줍니다. 힙이 없는 마이크로컨트롤러 코드에서 "초기화 순서를 내가 정하는 전역 객체"를 만드는 데에도 같은 방법을 씁니다.

## 참조는 담을 수 없다

`std::optional<T&>`는 C++23까지 없습니다. C++26에 들어왔지만 GCC 14에서는 쓸 수 없습니다. "있을 수도 없을 수도 있는, 남의 객체"는 이렇게 나타냅니다.

| 방법 | 꼴 |
| --- | --- |
| 포인터 | `Device* find(int id);` 없으면 `nullptr` |
| 참조를 감싼 것 | `std::optional<std::reference_wrapper<Device>>` |

대개 포인터로 충분합니다. "없을 수 있는, 소유하지 않는 것"이 바로 [포인터의 뜻](#/read/cpp-syntax/ref-vs-pointer)이기 때문입니다. 둘째는 [「reference_wrapper」](#/read/cpp-stl/voc-refwrap)에서 봅니다.

<Note>
함수의 인자를 `std::optional<T>`로 받는 것은 대개 좋은 선택이 아닙니다. 부르는 쪽에서 `T`가 `optional` 안으로 복사되고, "주지 않음"은 오버로드나 기본 인자로 더 잘 나타낼 수 있습니다. `optional`은 **반환값과 멤버**에 씁니다.
</Note>

## 정리

- `optional<T>`는 `T`의 자리와 표시 하나를 자기 안에 둔다. 힙을 쓰지 않고, 비어 있는 동안 `T`는 만들어지지 않는다
- `*opt`는 검사하지 않는다. `if (opt)`는 값이 아니라 "있는가"를 묻는다
- 만드는 때를 미루는 멤버에 `emplace`와 `reset`으로 쓴다. 참조는 담지 못하므로 포인터를 쓴다
