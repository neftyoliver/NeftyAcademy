화면 출력은 [`std::println`](#/read/cpp-syntax/from-c-hello)으로 하면 됩니다. 그런데도 스트림을 알아야 하는 까닭이 둘 있습니다. 파일과 문자열을 읽는 표준 도구가 아직 스트림이고, 지금 있는 C++ 코드의 대부분이 `std::cout`과 `>>`로 쓰여 있습니다. 이 챕터는 스트림을 읽고 고칠 수 있을 만큼 다룹니다.

## 두 층

스트림은 두 층으로 되어 있습니다.

| 층 | 타입 | 하는 일 |
| --- | --- | --- |
| 스트림 | `std::istream`, `std::ostream` | 값과 글자를 서로 바꾼다. 서식과 오류 상태를 가진다 |
| 스트림 버퍼 | `std::streambuf` | 글자를 모아 두었다가 실제 장치(화면, 파일, 문자열)와 주고받는다 |

`std::ofstream`, `std::ostringstream`, `std::cout`은 모두 `std::ostream`이고, 다른 것은 뒤에 붙은 버퍼뿐입니다. 그래서 `std::ostream&`를 받는 함수 하나로 어디에든 쓸 수 있습니다.

```cpp
#include <iostream>
#include <print>
#include <sstream>
#include <string>

void report(std::ostream& out, const std::string& name, double value)
{
    out << name << " = " << value << '\n';
}

int main()
{
    report(std::cout, "temp", 21.5);        // 화면으로

    std::ostringstream memory;
    report(memory, "humid", 40);            // 문자열로
    std::print("문자열에 모인 것: {}", memory.str());

    // cout 의 버퍼를 잠깐 바꿔 끼운다
    std::ostringstream captured;
    std::streambuf* original = std::cout.rdbuf(captured.rdbuf());
    report(std::cout, "press", 1013.2);
    std::cout.rdbuf(original);              // 반드시 되돌린다
    std::print("가로챈 것: {}", captured.str());
}
```

```text
temp = 21.5
문자열에 모인 것: humid = 40
가로챈 것: press = 1013.2
```

`rdbuf`로 버퍼를 바꿔 끼우는 것은 `std::cout`에 직접 찍는 옛 코드를 시험할 때 쓰는 방법입니다. 새 함수는 처음부터 `std::ostream&`를 인자로 받게 만들면 그럴 필요가 없습니다.

## 상태 비트

스트림은 마지막 동작이 어떻게 됐는지를 비트 셋으로 기억합니다.

| 비트 | 뜻 | 보는 함수 |
| --- | --- | --- |
| `eofbit` | 입력의 끝에 닿았다 | `eof()` |
| `failbit` | 읽거나 쓰려던 것이 되지 않았다 (숫자 자리에 글자가 있다) | `fail()` |
| `badbit` | 장치가 고장 났다 (디스크 오류) | `bad()` |

셋 다 꺼져 있으면 `good()`입니다. `if (in)`과 `while (in >> x)`가 보는 것은 <strong>`!fail()`</strong>입니다. `fail()`은 `failbit`나 `badbit`가 켜져 있으면 참입니다.

```cpp
#include <print>
#include <sstream>
#include <string>

void show(const char* label, int value, const std::istream& in)
{
    std::println("{:10} {:3} good={:5} eof={:5} fail={}", label, value,
                 in.good(), in.eof(), in.fail());
}

int main()
{
    std::istringstream in("12 abc 7");
    int x = -1;
    in >> x;
    show("12 읽기", x, in);
    in >> x;
    show("abc 읽기", x, in);
    x = -1;
    in >> x;                // 실패 상태에서는 아무 일도 하지 않는다
    show("그 뒤", x, in);

    in.clear();             // 상태를 지운다
    std::string junk;
    in >> junk;             // 걸린 낱말을 문자열로 읽어 치운다
    in >> x;
    show("7 읽기", x, in);
    in >> x;
    show("끝에서", x, in);
}
```

```text
12 읽기     12 good=true  eof=false fail=false
abc 읽기     0 good=false eof=false fail=true
그 뒤       -1 good=false eof=false fail=true
7 읽기       7 good=false eof=true  fail=false
끝에서       7 good=false eof=true  fail=true
```

읽을 것이 세 가지 있습니다.

- **실패하면 0이 들어간다.** `abc`를 `int`로 읽지 못하면 변수에 0을 쓰고 `failbit`를 켭니다. 범위를 넘는 숫자(`99999999999`)는 최댓값을 쓰고 역시 `failbit`를 켭니다. 값만 보고는 성공인지 알 수 없습니다
- **한 번 실패하면 멈춘다.** `failbit`가 켜진 스트림은 `clear()`를 부를 때까지 모든 읽기를 건너뜁니다. 변수는 그대로입니다
- **`eof()`는 실패가 아니다.** 마지막 `7`은 제대로 읽혔는데 `eof`가 켜졌습니다. 숫자가 끝났는지 보려고 한 글자를 더 보다가 끝에 닿았기 때문입니다. `good()`으로 성공을 판단하면 마지막 값을 버리게 됩니다

## 읽는 루프

그래서 루프의 조건은 **읽기 자체**여야 합니다.

```cpp
#include <limits>
#include <print>
#include <sstream>

int main()
{
    // 틀린 루프: 끝인지 먼저 묻고 읽는다
    std::istringstream first("1 2 3\n");
    int x = 0;
    while (!first.eof()) {
        first >> x;
        std::print("[{}]", x);
    }
    std::println("");

    // 옳은 루프: 읽고, 읽혔는지 묻는다
    std::istringstream second("1 2 3\n");
    while (second >> x)
        std::print("[{}]", x);
    std::println("");

    // 틀린 줄을 건너뛰며 읽기
    std::istringstream lines("21.5\nerror\n19\n");
    double value = 0;
    while (true) {
        if (lines >> value) {
            std::println("값 {}", value);
        } else if (lines.eof()) {
            break;
        } else {
            lines.clear();
            lines.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            std::println("한 줄 건너뜀");
        }
    }
}
```

```text
[1][2][3][3]
[1][2][3]
값 21.5
한 줄 건너뜀
값 19
```

첫 루프는 `3`을 두 번 처리했습니다. `3`을 읽은 뒤에도 줄바꿈이 남아 있어 `eof`가 아니고, 한 번 더 돌아 읽기에 실패한 다음에야 끝을 압니다. 그 사이 `x`는 앞의 값 그대로입니다.

셋째 루프의 `clear()`와 `ignore()`가 실패에서 벗어나는 짝입니다. 상태를 지우고, 걸린 글자를 줄 끝까지 버립니다. 손이 많이 가므로, 형식이 정해진 입력은 [`std::getline`으로 한 줄을 읽고](#/read/cpp-stl/io-file) 그 줄을 [`from_chars`](#/read/cpp-stl/str-convert)로 푸는 쪽이 낫습니다. 실패가 그 줄 안에서 끝납니다.

<Note>
상태를 `if`로 보는 대신 예외로 받을 수도 있습니다. `in.exceptions(std::ios::failbit | std::ios::badbit);`를 해 두면 그 비트가 켜지는 순간 `std::ios_base::failure`가 던져집니다. 다만 "파일 끝에서 읽기 실패"처럼 늘 생기는 일까지 예외가 되므로 `badbit`만 켜 두는 경우가 많습니다.
</Note>

## 표준 스트림 넷

| 스트림 | 가는 곳 | 내보내는 때 |
| --- | --- | --- |
| `std::cin` | 표준 입력 | 읽기 전에 `std::cout`을 먼저 비운다 |
| `std::cout` | 표준 출력 | 모아 두었다가 내보낸다 |
| `std::cerr` | 표준 오류 | `<<` 한 번마다 바로 내보낸다 |
| `std::clog` | 표준 오류 | 모아 두었다가 내보낸다 |

```cpp
#include <iostream>
#include <print>

int main()
{
    std::println("cin 이 cout 에 묶여 있다 {}", std::cin.tie() == &std::cout);
    std::println("cerr 가 cout 에 묶여 있다 {}", std::cerr.tie() == &std::cout);
    const auto unit = std::ios::unitbuf;
    std::println("cerr unitbuf {}", (std::cerr.flags() & unit) != 0);
    std::println("clog unitbuf {}", (std::clog.flags() & unit) != 0);
}
```

```text
cin 이 cout 에 묶여 있다 true
cerr 가 cout 에 묶여 있다 true
cerr unitbuf true
clog unitbuf false
```

**묶여 있다**(tie)는 것은 "이 스트림을 쓰기 전에 저 스트림을 비운다"는 뜻입니다. 그래서 `std::cout << "이름: "; std::cin >> name;`에서 줄바꿈이 없어도 물음이 먼저 화면에 나옵니다. `std::cerr`는 프로그램이 죽기 직전의 말이 버퍼에 남은 채 사라지지 않도록 바로 내보냅니다. 오류와 진단은 `std::cerr`로, 결과는 `std::cout`으로 보내면 `prog > result.txt`처럼 결과만 파일로 돌릴 때 오류가 화면에 남습니다.

`std::endl`은 `'\n'`을 쓰고 **버퍼를 비우기까지** 합니다. 줄마다 비우면 줄마다 운영체제를 부르게 됩니다. 줄바꿈은 `'\n'`으로 쓰고, 꼭 지금 보여야 하는 곳에서만 `std::flush`나 `std::endl`을 씁니다. 그 차이가 몇 배인지는 [「느린 이유와 대안」](#/read/cpp-stl/io-speed)에서 잽니다.

## 정리

- 스트림은 서식과 상태를 맡고, 스트림 버퍼가 장치를 맡는다. `std::ostream&`를 받는 함수는 화면, 파일, 문자열에 모두 쓸 수 있다
- 읽기가 실패하면 `failbit`가 켜지고 `clear()`를 부를 때까지 모든 읽기가 건너뛰어진다. 루프의 조건은 `while (in >> x)`처럼 읽기 자체로 쓴다
- `cin`은 `cout`에 묶여 있고 `cerr`는 바로 내보낸다. `std::endl`은 줄바꿈에 비우기까지 한다
