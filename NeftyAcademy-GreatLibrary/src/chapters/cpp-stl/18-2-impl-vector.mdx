[「vector」](#/read/cpp-stl/seq-vector)에서 쓰는 법을, [「복잡도 보장 읽는 법」](#/read/cpp-stl/ov-complexity)에서 `push_back`이 "평균적으로" 빠르다는 것을 봤습니다. 여기서는 속을 열어, 그 평균이 어디서 나오고 무엇을 치르는지 봅니다. 수치는 GCC 14의 libstdc++ 것입니다.

## 포인터 셋

`std::vector<T>`의 속은 포인터 셋입니다.

| 포인터 | 가리키는 곳 |
| --- | --- |
| 시작 | 힙에 잡은 블록의 처음 |
| 끝 | 마지막 원소의 다음 칸. `size()`는 끝 − 시작 |
| 용량의 끝 | 블록의 끝. `capacity()`는 용량의 끝 − 시작 |

그래서 `sizeof(std::vector<int>)`가 24입니다. 끝과 용량의 끝 사이가 [객체 없이 비어 있는 메모리](#/read/cpp-stl/mem-uninit)이고, `push_back`은 그 자리에 원소를 만들고 끝을 한 칸 밉니다. 빈 칸이 없으면 **더 큰 블록을 새로 잡아 통째로 옮깁니다.**

```cpp
#include <cstddef>
#include <print>
#include <vector>

// 옮겨질 때마다 센다
struct Counted {
    static inline long moves = 0;
    int value = 0;

    explicit Counted(int v) : value(v) {}
    Counted(Counted&& other) noexcept : value(other.value) { ++moves; }
    Counted& operator=(Counted&&) noexcept = default;
};

int main()
{
    std::vector<int> v;
    std::println("빈 벡터: 용량 {}, 블록 없음 {}", v.capacity(),
                 v.data() == nullptr);

    std::size_t capacity = 0;
    for (int i = 0; i < 100; ++i) {
        v.push_back(i);
        if (v.capacity() != capacity) {
            capacity = v.capacity();
            std::print("[{}]", capacity);
        }
    }
    std::println("");

    std::vector<Counted> counted;
    int grows = 0;
    capacity = 0;
    for (int i = 0; i < 1'000'000; ++i) {
        counted.emplace_back(i);
        if (counted.capacity() != capacity) {
            capacity = counted.capacity();
            ++grows;
        }
    }
    std::println("100만 개: 재할당 {}번, 옮긴 횟수 {}, 용량 {}", grows,
                 Counted::moves, capacity);
}
```

```text
빈 벡터: 용량 0, 블록 없음 true
[1][2][4][8][16][32][64][128]
100만 개: 재할당 21번, 옮긴 횟수 1048575, 용량 1048576
```

빈 벡터는 힙을 쓰지 않습니다. 첫 `push_back`에서 한 칸을 잡고, 그 뒤로는 찰 때마다 **두 배**로 늘립니다.

## 배로 자라는 까닭

100만 개를 넣는 동안 재할당은 21번뿐이고, 옮긴 횟수는 모두 합쳐 1,048,575번입니다. 원소 하나에 **한 번꼴**입니다. 한 칸씩 늘렸다면 옮긴 횟수는 1 + 2 + … + 999,999, 약 5천억 번이었을 것입니다.

배로 늘리면 직전까지의 옮김을 다 합쳐도 지금 크기를 넘지 않습니다(1 + 2 + 4 + … + n/2 < n). 이것이 `push_back`이 "분할 상환 O(1)"이라는 말의 뜻입니다. 평균은 일정하고, **가끔 한 번이 아주 비쌉니다.**

비율은 표준이 정하지 않았습니다. libstdc++와 libc++는 2배, MSVC는 1.5배입니다. 2배는 재할당 횟수가 적고, 1.5배는 남는 칸이 적고 예전에 쓰던 블록들을 합쳐 다시 쓸 여지가 있습니다. 어느 쪽이 낫다는 결론은 없습니다.

`insert`나 `resize`로 한꺼번에 여러 개가 늘 때는 "지금 크기 + 지금 크기와 늘어날 개수 가운데 큰 쪽"으로 잡습니다. 아래 예제의 뒤쪽에서 확인합니다.

## 치르는 값

| 값 | 내용 |
| --- | --- |
| 남는 칸 | 용량은 크기의 최대 두 배다. 위에서는 48,576칸(4.6%)이 남았고, 운이 나쁘면 절반이 남는다 |
| 자라는 순간의 메모리 | 옛 블록과 새 블록이 **함께** 있어야 한다. `int` 100만 개(4MB)를 넣는 동안 가장 많이 쓴 순간은 6.3MB였다 |
| 한 번의 지연 | 재할당 한 번이 그때까지의 원소를 모두 옮긴다 |
| [무효화](#/read/cpp-stl/seq-invalidation) | 재할당하면 모든 포인터, 참조, 반복자가 죽는다 |

둘째 줄은 메모리가 작은 기기에서 중요합니다. 벡터가 메모리의 3분의 1을 넘으면 **다음 재할당은 실패합니다.** 512MB 보드에서 200MB짜리 벡터에 원소 하나를 더 넣으려면 400MB짜리 새 블록이 필요하고, 그 순간 600MB가 있어야 합니다. 크기를 알면 `reserve`로 한 번에 잡고, 모르면 [`deque`](#/read/cpp-stl/seq-deque)처럼 블록을 이어 붙이는 구조를 씁니다.

시간도 재어 봤습니다(x86-64, GCC 14 `-O2`).

| 넣은 것 | 그냥 `push_back` | `reserve` 뒤 `push_back` |
| --- | --- | --- |
| `int` 1,000만 개 | 28 ms | 6 ms |
| 31글자 `std::string` 100만 개 | 46 ms | 42 ms |

`int`는 다섯 배 가까이 차이 납니다. 문자열은 거의 같습니다. 문자열마다 드는 힙 할당이 시간의 대부분이라, 벡터가 옮기는 값(포인터 몇 개 복사)은 묻힙니다. `reserve`의 이득도 원소가 무엇이냐에 따라 다릅니다.

## 용량을 다루는 함수들

```cpp
#include <print>
#include <vector>

int main()
{
    std::vector<int> v;
    v.reserve(100);
    std::println("reserve(100)      크기 {:3} 용량 {}", v.size(), v.capacity());
    v.resize(10);
    std::println("resize(10)        크기 {:3} 용량 {}", v.size(), v.capacity());
    v.reserve(50);                  // 지금보다 작으면 아무 일도 하지 않는다
    std::println("reserve(50)       크기 {:3} 용량 {}", v.size(), v.capacity());
    v.insert(v.end(), 100, 7);      // 10 + max(10, 100)
    std::println("100개 insert      크기 {:3} 용량 {}", v.size(), v.capacity());
    v.push_back(1);                 // 110 + max(110, 1)
    std::println("push_back         크기 {:3} 용량 {}", v.size(), v.capacity());

    const std::vector<int> copy = v;    // 복사본은 딱 맞게 잡는다
    std::println("복사본            크기 {:3} 용량 {}", copy.size(),
                 copy.capacity());

    v.clear();                      // 원소만 없앤다
    std::println("clear             크기 {:3} 용량 {}", v.size(), v.capacity());
    v.shrink_to_fit();              // 남는 칸을 돌려 달라고 "부탁" 한다
    std::println("shrink_to_fit     크기 {:3} 용량 {}", v.size(), v.capacity());
}
```

```text
reserve(100)      크기   0 용량 100
resize(10)        크기  10 용량 100
reserve(50)       크기  10 용량 100
100개 insert      크기 110 용량 110
push_back         크기 111 용량 220
복사본            크기 111 용량 111
clear             크기   0 용량 220
shrink_to_fit     크기   0 용량 0
```

| 함수 | 크기 | 용량 |
| --- | --- | --- |
| `reserve(n)` | 그대로 | `n` 이상으로. 줄이지는 않는다 |
| `resize(n)` | `n`으로 (원소를 만들거나 없앤다) | 모자라면 늘린다 |
| `clear()` | 0 | **그대로** |
| `shrink_to_fit()` | 그대로 | 크기에 맞춰 달라는 부탁. 들어줄 의무는 없다 |

- **`reserve`와 `resize`를 헷갈리지 않습니다.** `reserve(100)` 뒤에 `v[5] = 1;`은 없는 원소에 쓰는 것이고 `size()`는 여전히 0입니다. 자리를 만들어 놓고 번호로 채우려면 `resize`입니다
- **`clear()`는 메모리를 돌려주지 않습니다.** 주기마다 채우고 비우는 버퍼에는 좋은 성질입니다. 둘째 주기부터는 할당이 없습니다. 한 번 크게 썼던 벡터가 메모리를 쥐고 있는 것이 문제라면 `shrink_to_fit()`을 부르거나 `v = {}` 뒤에 `shrink_to_fit()`을 붙입니다
- **`reserve`를 루프 안에서 조금씩 부르지 않습니다.** `v.reserve(v.size() + 1)`을 매번 부르면 구현에 따라 딱 그만큼만 잡아서 배로 자라는 성질이 사라지고, 넣을 때마다 통째로 옮기게 됩니다

## 옮기는 방법

재할당할 때 원소를 새 블록으로 옮기는 방법은 원소 타입이 정합니다.

| 원소 타입 | 옮기는 방법 |
| --- | --- |
| `int`, 포인터, 단순한 구조체 | 메모리를 통째로 복사한다 |
| 이동 생성자가 `noexcept`인 타입 | 하나씩 이동한다 |
| 이동 생성자가 예외를 던질 수 있는 타입 | 하나씩 **복사**한다 |

셋째 줄이 [`noexcept`를 붙여야 하는 까닭](#/read/cpp-syntax/exc-noexcept)입니다. 옮기다 실패하면 원래대로 되돌릴 수 없으므로, 벡터는 안전한 복사를 고릅니다. 직접 만든 이동 생성자에 `noexcept`가 빠져 있으면 그 타입을 담은 벡터는 자랄 때마다 전부 복사합니다.

<Note>
`realloc`처럼 "그 자리에서 늘리기"는 하지 않습니다. 뒤에 빈 메모리가 있어도 새 블록을 잡습니다. C++의 할당자 인터페이스에 그런 요청이 없고, 객체는 바이트를 옮기는 것만으로 옮겨지지 않을 수 있기 때문입니다([자기 안을 가리키는 `string`](#/read/cpp-stl/impl-sso)이 그렇습니다). 용량이 타입에 정해져 있고 절대 재할당하지 않는 벡터가 필요하면 [고정 용량 벡터](#/read/cpp-stl/mem-uninit)를 씁니다.
</Note>

## 정리

- `vector`는 시작, 끝, 용량의 끝을 가리키는 포인터 셋이다. 빈 칸이 없으면 두 배짜리 블록을 새로 잡아 통째로 옮긴다
- 배로 늘리므로 옮기는 횟수는 원소 하나에 한 번꼴이다. 그 대신 칸이 남고, 자라는 순간에는 옛 블록과 새 블록이 함께 있어야 한다
- 크기를 알면 `reserve`로 미리 잡는다. `clear()`는 용량을 그대로 두고, `shrink_to_fit()`은 부탁일 뿐이다
