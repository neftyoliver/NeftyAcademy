`std::map`은 **열쇠**(key)로 값을 찾는 컨테이너이고, `std::set`은 열쇠만 있는 `map`입니다. 둘 다 원소를 열쇠 순서로 정렬해 둔 트리여서, 찾기와 넣기와 지우기가 [O(log n)](#/read/cpp-stl/ov-complexity)이고 차례로 돌면 정렬된 순서로 나옵니다.

## 넣는 다섯 가지 방법

넣는 방법이 여럿이고, **이미 있는 열쇠일 때** 하는 일이 서로 다릅니다.

```cpp
#include <map>
#include <print>
#include <string>

int main()
{
    std::map<std::string, int> pins;

    pins["led"] = 17;                           // 없으면 만들고, 있으면 덮어쓴다
    auto [it1, inserted1] = pins.insert({"led", 99});   // 있으면 건드리지 않는다
    std::println("insert: 넣었나 {}, 지금 값 {}", inserted1, it1->second);

    auto [it2, inserted2] = pins.insert_or_assign("led", 27);   // 있으면 덮어쓴다
    std::println("insert_or_assign: 넣었나 {}, 지금 값 {}", inserted2, it2->second);

    auto [it3, inserted3] = pins.try_emplace("button", 22);     // 없을 때만 만든다
    std::println("try_emplace: 넣었나 {}, 지금 값 {}", inserted3, it3->second);

    std::println("at: {}", pins.at("button"));      // 없으면 예외
    std::println("contains: {} {}", pins.contains("led"), pins.contains("fan"));

    if (pins["fan"] == 0)                       // 읽으려던 것인데 "fan" 이 생겼다
        std::println("size {}", pins.size());

    for (const auto& [name, pin] : pins)        // 열쇠 순서로 나온다
        std::print("{}={} ", name, pin);
    std::println("");
}
```

```text
insert: 넣었나 false, 지금 값 17
insert_or_assign: 넣었나 false, 지금 값 27
try_emplace: 넣었나 true, 지금 값 22
at: 22
contains: true false
size 3
button=22 fan=0 led=27
```

| 방법 | 열쇠가 이미 있으면 | 돌려주는 것 |
| --- | --- | --- |
| `m[k] = v` | 덮어쓴다 | 값의 참조 |
| `m.insert({k, v})` | 그대로 둔다 | 반복자와 `bool` |
| `m.insert_or_assign(k, v)` | 덮어쓴다 | 반복자와 `bool` |
| `m.try_emplace(k, 인자…)` | 그대로 둔다. 인자도 건드리지 않는다 | 반복자와 `bool` |
| `m.emplace(인자…)` | 그대로 둔다. 노드를 만들었다가 버릴 수 있다 | 반복자와 `bool` |

<Note kind="warn">
`m[k]`는 **읽기만 해도** 없는 열쇠를 만듭니다. 값은 0이나 빈 문자열로 초기화됩니다. 있는지 확인하려던 `if (m[k] == 0)`이 `map`을 키우고, `const` `map`에서는 `[]`가 아예 컴파일되지 않습니다. 읽을 때는 `find`, `contains`, `at`을 씁니다.
</Note>

`[]`가 편한 자리도 있습니다. `++counts[word];`는 "없으면 0으로 만들고 1을 더한다"가 되어 세는 코드가 한 줄입니다.

## 찾기와 범위

`find`는 반복자를 돌려주고, 없으면 `end()`입니다. 정렬되어 있으므로 "이 열쇠와 **가까운** 것"도 O(log n)으로 찾습니다.

| 멤버 | 돌려주는 것 |
| --- | --- |
| `m.find(k)` | 열쇠가 `k`인 원소. 없으면 `end()` |
| `m.lower_bound(k)` | 열쇠가 `k` **이상인** 첫 원소 |
| `m.upper_bound(k)` | 열쇠가 `k`**보다 큰** 첫 원소 |

보정표가 대표적인 쓰임입니다. 재어 둔 점 몇 개 사이를 직선으로 이어 값을 구합니다.

```cpp
#include <iterator>
#include <map>
#include <print>

// 센서의 원시 값 -> 실제 온도. 재어 둔 점들
const std::map<double, double> calibration = {
    {100, 0.0},
    {400, 25.0},
    {900, 60.0},
};

double to_celsius(double raw)
{
    const auto above = calibration.lower_bound(raw);    // raw 이상인 첫 점
    if (above == calibration.begin())
        return above->second;                           // 표의 아래쪽 밖
    if (above == calibration.end())
        return calibration.rbegin()->second;            // 표의 위쪽 밖
    const auto below = std::prev(above);
    const double ratio = (raw - below->first) / (above->first - below->first);
    return below->second + ratio * (above->second - below->second);
}

int main()
{
    for (double raw : {50.0, 100.0, 250.0, 650.0, 2000.0})
        std::println("{:6} -> {:5.1f}", raw, to_celsius(raw));
}
```

```text
    50 ->   0.0
   100 ->   0.0
   250 ->  12.5
   650 ->  42.5
  2000 ->  60.0
```

<Note>
`std::lower_bound(m.begin(), m.end(), k)`가 아니라 **멤버** `m.lower_bound(k)`를 씁니다. 비교 횟수는 같지만, 바깥의 알고리즘은 트리의 구조를 몰라서 [한 칸씩 걸어야](#/read/cpp-stl/ov-complexity) 합니다. `std::find(m.begin(), m.end(), …)`도 같습니다.
</Note>

## set

`std::set<T>`는 값이 곧 열쇠입니다. "겹치지 않게, 정렬해서" 들고 있을 때 씁니다.

```cpp
#include <print>
#include <set>

int main()
{
    std::set<int> seen;
    for (int id : {42, 7, 42, 19, 7}) {
        const bool is_new = seen.insert(id).second;
        std::println("{:2}: {}", id, is_new ? "처음 봄" : "이미 봄");
    }
    for (int id : seen)
        std::print("{} ", id);
    std::println("(가장 작은 것 {}, 가장 큰 것 {})", *seen.begin(), *seen.rbegin());
}
```

```text
42: 처음 봄
 7: 처음 봄
42: 이미 봄
19: 처음 봄
 7: 이미 봄
7 19 42 (가장 작은 것 7, 가장 큰 것 42)
```

## 열쇠는 고칠 수 없다

원소의 타입은 `std::pair<const Key, Value>`입니다. 열쇠가 `const`인 것은 열쇠를 고치면 정렬이 깨지기 때문입니다. `set`의 원소도 같은 까닭으로 고칠 수 없습니다. 열쇠를 바꾸려면 지우고 다시 넣거나, 할당 없이 하려면 [노드 핸들](#/read/cpp-stl/assoc-node)을 씁니다.

## 무효화 규칙과 값

| 연산 | 반복자, 포인터, 참조 |
| --- | --- |
| 넣기 | 아무것도 죽지 않는다 |
| 지우기 | 지운 원소의 것만 죽는다 |

[`list`](#/read/cpp-stl/seq-list)와 같은 규칙입니다. 원소마다 노드가 따로 있기 때문이고, 그래서 값도 같습니다. `int` 둘짜리 원소 하나에 [노드 40바이트](#/read/cpp-stl/ov-allocator)가 들고, 찾을 때마다 흩어진 노드를 따라갑니다. 열쇠가 100만 개인 `map<int, int>`에서 찾기 한 번이 x86-64 서버에서 1.4마이크로초쯤 걸렸고, 같은 내용을 정렬된 `vector`에 담아 이진 탐색하면 0.2마이크로초였습니다.

| 상황 | 고르는 것 |
| --- | --- |
| 순서대로 돌거나 범위로 찾는다. 넣고 지우는 일이 잦다 | `map`, `set` |
| 순서가 필요 없고 찾기가 빨라야 한다 | [`unordered_map`](#/read/cpp-stl/assoc-unordered) |
| 한 번 만들고 찾기만 한다. 메모리가 빠듯하다 | [정렬된 `vector`, `flat_map`](#/read/cpp-stl/assoc-flat) |

## 정리

- `map`과 `set`은 열쇠로 정렬된 트리다. 찾기, 넣기, 지우기가 O(log n)이고 순서대로 돈다
- `[]`는 없는 열쇠를 만든다. 읽을 때는 `find`, `contains`, `at`. 넣을 때는 있을 때의 동작을 보고 고른다
- 넣어도 가리키던 것이 죽지 않는다. 그 값으로 원소마다 할당과 느린 순회를 치른다
