export const summary = 'numbers의 상수, 실수가 어림이라는 것과 견주는 법, 반올림 함수들, NaN, float와 double이 섞일 때';

`<numbers>`(C++20)가 수학 상수를, `<cmath>`가 함수를 줍니다. 함수의 목록보다, 실수를 다룰 때 틀리기 쉬운 곳을 중심으로 봅니다.

## 상수

```cpp
#include <numbers>
#include <print>

int main()
{
    std::println("{} {}", std::numbers::pi, std::numbers::e);
    std::println("{} {}", std::numbers::sqrt2, std::numbers::phi);
    // 다른 타입의 정밀도로
    std::println("{} {}", std::numbers::pi_v<float>,
                 std::numbers::pi_v<long double>);
    const double degrees = 135.0;
    std::println("{}", degrees * std::numbers::pi / 180.0);
}
```

```text
3.141592653589793 2.718281828459045
1.4142135623730951 1.618033988749895
3.1415927 3.1415926535897932385
2.356194490192345
```

`pi`, `e`, `sqrt2`, `sqrt3`, `ln2`, `ln10`, `log2e`, `log10e`, `inv_pi`, `inv_sqrtpi`, `phi`, `egamma`가 있습니다. 이름 뒤에 `_v<T>`를 붙이면 그 타입의 값입니다. `M_PI`는 표준이 아닙니다. POSIX가 `<math.h>`에 덧붙인 것이라 리눅스에서는 되고, MSVC에서는 `_USE_MATH_DEFINES`를 정의해야 나옵니다. `3.14`를 손으로 적은 코드는 유효 숫자 세 자리짜리 원주율을 쓰는 것입니다.

## 실수는 어림이다

`double`은 10진수로 약 15~17자리, `float`는 6~9자리만큼의 정밀도를 가집니다. 0.1 같은 수는 2진수로 끝나지 않으므로 가장 가까운 값이 대신 들어갑니다.

```cpp
#include <algorithm>
#include <cmath>
#include <print>

// 큰 수는 비율로, 0 근처는 절대 오차로 견준다
bool nearly_equal(double a, double b, double relative = 1e-9,
                  double absolute = 1e-12)
{
    const double diff = std::abs(a - b);
    const double scale = std::max(std::abs(a), std::abs(b));
    return diff <= absolute || diff <= relative * scale;
}

int main()
{
    std::println("{} / {:.17f}", 0.1 + 0.2 == 0.3, 0.1 + 0.2);
    std::println("{}", nearly_equal(0.1 + 0.2, 0.3));

    // float 는 16,777,216 (2 의 24 제곱) 부터 1 을 더해도 그대로다
    const float big = 16'777'216.0f;
    std::println("{} {}", big + 1.0f == big, big + 2.0f == big);

    // 1ms 를 천만 번 더하면 10,000 초가 되어야 한다
    float clock_f = 0.0f;
    double clock_d = 0.0;
    for (int i = 0; i < 10'000'000; ++i) {
        clock_f += 0.001f;
        clock_d += 0.001;
    }
    std::println("{} / {}", clock_f, clock_d);
}
```

```text
false / 0.30000000000000004
true
true false
9780.204 / 10000.000001578517
```

마지막 줄을 봅니다. `float`에 1밀리초를 천만 번 더한 시계는 **220초나 모자랍니다.** 합이 커질수록 더해지는 0.001이 `float`의 정밀도 아래로 깎여 나가기 때문입니다. 시간, 거리, 금액처럼 **작은 값을 오래 쌓는** 양은 실수로 누적하지 않습니다. 눈금 수를 정수로 세고(`std::chrono`가 [그렇게 합니다](#/read/cpp-stl/chr-duration)), 실수가 필요한 순간에만 바꿉니다.

| 하려는 일 | 방법 |
| --- | --- |
| 두 실수가 같은가 | `==`를 쓰지 않는다. 허용 오차를 정해 견준다 |
| 작은 값을 오래 쌓는다 | 정수로 센다 |
| 돈 | 가장 작은 단위(원, 센트)의 정수로 |
| 루프를 0.1씩 돈다 | 정수로 돌고 `i * 0.1`로 계산한다 |

허용 오차에 `std::numeric_limits<double>::epsilon()`을 그대로 쓰는 코드가 많지만 맞지 않습니다. 그 값(2.2×10⁻¹⁶)은 **1.0 근처에서** 이웃한 두 `double`의 간격일 뿐이고, 수가 커지면 간격도 커집니다. 오차는 다루는 양의 크기와 필요한 정밀도를 보고 정합니다.

## 반올림

| 함수 | 2.5 | −2.5 | 규칙 |
| --- | --- | --- | --- |
| `std::round` | 3 | −3 | 가까운 정수로. 한가운데면 0에서 먼 쪽 |
| `std::nearbyint`, `std::rint` | 2 | −2 | 가까운 정수로. 한가운데면 짝수 쪽(기본 설정에서) |
| `std::floor` | 2 | −3 | 작은 쪽으로 |
| `std::ceil` | 3 | −2 | 큰 쪽으로 |
| `std::trunc` | 2 | −2 | 0 쪽으로. `static_cast<int>`와 같은 방향 |

```cpp
#include <cmath>
#include <print>

int main()
{
    std::println("{} {} {}", std::round(2.5), std::round(-2.5), std::lround(2.5));
    std::println("{} {} {}", std::nearbyint(2.5), std::nearbyint(3.5),
                 std::nearbyint(-2.5));
    std::println("{} {} {}", std::floor(-2.5), std::ceil(-2.5), std::trunc(-2.5));
    // 음수의 나머지
    std::println("{} {}", std::fmod(-7.5, 2.0), std::remainder(7.5, 2.0));
}
```

```text
3 -3 3
2 4 -2
-3 -2 -2
-1.5 -0.5
```

이 함수들은 **실수를 돌려줍니다.** 정수가 필요하면 `std::lround`를 쓰거나 결과를 변환합니다. 이때 값이 정수 타입의 범위를 벗어나면 [정의되지 않은 동작](#/read/c-basic/ub-what)입니다. 센서에서 온 실수를 `std::uint8_t`로 바꾸기 전에는 `std::clamp(value, 0.0, 255.0)`으로 범위에 가둡니다.

## NaN과 무한대

0을 0으로 나누거나 음수의 제곱근을 구하면 **NaN**(수가 아님)이 나옵니다. NaN은 한 번 생기면 그 뒤의 모든 계산을 NaN으로 물들이고, 견주는 방식이 보통의 수와 다릅니다.

```cpp
#include <algorithm>
#include <cmath>
#include <limits>
#include <print>

int main()
{
    const double nan = std::numeric_limits<double>::quiet_NaN();
    std::println("{} {} {}", nan == nan, nan < 1.0, nan > 1.0);
    std::println("{} {}", std::isnan(nan), std::isfinite(nan));

    // std::max 는 인자의 순서에 따라 답이 달라진다
    const double a = std::max(1.0, nan);
    const double b = std::max(nan, 1.0);
    std::println("{} {} {}", a, std::isnan(b), std::fmax(nan, 1.0));

    std::println("{} {}", 1.0 / 0.0, std::isinf(-1.0 / 0.0));
}
```

```text
false false false
true false
1 true 1
inf true
```

NaN과의 비교는 **모두 거짓**입니다. 자기 자신과 같지도 않습니다. 그래서 `if (value < limit)`으로 범위를 검사하는 코드는 NaN을 "범위 밖"으로 처리하고, `if (!(value >= limit))`으로 쓴 코드는 통과시킵니다. `std::max`와 `std::min`은 `<` 하나로 구현되어 있어 NaN이 어느 자리에 오느냐에 따라 결과가 달라집니다. 센서 값이나 파일에서 읽은 실수는 받는 자리에서 `std::isfinite`로 걸러 내고, 그 안쪽 코드는 NaN이 없다고 믿게 합니다.

<Note kind="warn">
`-ffast-math`는 "NaN과 무한대는 없다"고 컴파일러에게 약속하는 옵션입니다. 이 옵션을 켜고 GCC 14 `-O2`로 빌드하면 NaN에 대한 `std::isnan(value)`가 **거짓**이 됩니다(확인한 것). 검사 자체가 지워집니다. 속도 때문에 이 옵션을 쓰는 코드에서는 NaN 검사를 믿을 수 없습니다.
</Note>

## float와 double이 섞일 때

```cpp
#include <cmath>
#include <print>

int main()
{
    const float x = 0.1f;
    // 2.0 은 double 이다. x 가 double 로 올라가 계산된다
    std::println("{} {}", sizeof(x * 2.0), sizeof(x * 2.0f));
    // std::sin 은 인자의 타입을 따른다. 정수를 넣으면 double
    std::println("{} {}", sizeof(std::sin(x)), sizeof(std::sin(1)));
    std::println("{} {}", sizeof(float), sizeof(double));
}
```

```text
8 4
4 8
4 8
```

`f`가 붙지 않은 실수 리터럴은 `double`입니다. `float` 변수에 `2.0`을 곱하면 계산 전체가 `double`로 이뤄집니다. 라즈베리 파이의 CPU는 두 타입 모두 하드웨어로 계산하므로 속도 차이가 작지만, 단정밀도 FPU만 가진 마이크로컨트롤러(Cortex-M4F 등)에서는 `f` 하나가 빠진 탓에 `double` 연산이 소프트웨어 루틴으로 돌아 훨씬 느려지고 코드도 커집니다. `float`로 쓰기로 한 코드에서는 리터럴에 `f`를 붙이고, GCC의 `-Wdouble-promotion`으로 새는 곳을 찾습니다.

폭을 못 박은 타입도 있습니다. C++23의 `<stdfloat>`에 `std::float32_t`, `std::float64_t`, `std::float16_t`가 있고 GCC 13부터 됩니다(Clang 20의 libc++에는 아직 없습니다).

## 그 밖의 함수

| 함수 | 하는 일 |
| --- | --- |
| `std::hypot(x, y)`, `std::hypot(x, y, z)` | √(x²+y²). 중간에 넘치지 않게 계산한다 |
| `std::lerp(a, b, t)` | `a`와 `b` 사이를 `t`로 보간한다. `t`가 0~1 밖이면 바깥으로 이어진다 |
| `std::fma(x, y, z)` | `x*y+z`를 반올림 한 번으로 |
| `std::atan2(y, x)` | 사분면을 가린 각도. `atan(y/x)`와 달리 `x`가 0이어도 된다 |
| `std::clamp(v, lo, hi)` | `<algorithm>`에 있다. 범위에 가둔다 |

```cpp
#include <algorithm>
#include <cmath>
#include <numbers>
#include <print>

int main()
{
    std::println("{} {}", std::hypot(3.0, 4.0), std::hypot(1.0, 2.0, 2.0));
    std::println("{} {}", std::lerp(10.0, 20.0, 0.25), std::lerp(10.0, 20.0, 1.5));
    std::println("{}", std::atan2(1.0, -1.0) * 180.0 / std::numbers::pi);
    std::println("{} {}", std::clamp(150, 0, 100), std::clamp(-5.0, 0.0, 1.0));
}
```

```text
5 3
12.5 25
135
100 0
```

C++17은 베셀 함수, 리만 제타 함수, 타원 적분 같은 **특수 함수**도 `<cmath>`에 넣었습니다(`std::cyl_bessel_j`, `std::riemann_zeta`, `std::comp_ellint_1` 등). libstdc++와 MSVC에는 있고 libc++에는 없습니다. 필터 설계나 물리 계산에서 필요해지면 찾아 쓰면 됩니다.

## 정리

- 상수는 `std::numbers`에서 가져온다. 실수는 어림이므로 `==`로 견주지 않고, 작은 값을 오래 쌓는 양은 정수로 센다
- NaN과의 비교는 모두 거짓이다. 바깥에서 들어오는 실수는 `std::isfinite`로 거르고, `-ffast-math`에서는 그 검사가 사라진다
- `f`가 없는 리터럴은 `double`이다. `float`와 섞으면 계산이 `double`로 올라간다
