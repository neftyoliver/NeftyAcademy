오류가 났을 때 가장 먼저 알고 싶은 것은 **어디서**입니다. C에서는 `__FILE__`과 `__LINE__` 매크로로 했습니다. C++20의 `std::source_location`이 그것을 보통의 값으로 만들었고, C++23의 `std::stacktrace`는 거기까지 온 호출 경로를 통째로 줍니다.

## source_location

```cpp
#include <print>
#include <source_location>
#include <string_view>

void log(std::string_view message,
         const std::source_location& where = std::source_location::current())
{
    std::println("[{}줄 {}] {}", where.line(), where.function_name(), message);
}

struct Motor {
    void start(int rpm)
    {
        log("시작");
        if (rpm > 3000)
            log("회전수가 너무 높다");
    }
};

template <typename T>
T twice(T value)
{
    log("템플릿 안");
    return value + value;
}

int main()
{
    log("main 에서");
    Motor motor;
    motor.start(5000);
    twice(21);
}
```

```text
[29줄 int main()] main 에서
[14줄 void Motor::start(int)] 시작
[16줄 void Motor::start(int)] 회전수가 너무 높다
[23줄 T twice(T) [with T = int]] 템플릿 안
```

요령은 **기본 인자**입니다. `std::source_location::current()`는 자기가 적힌 자리의 정보를 돌려주는데, 기본 인자로 쓰이면 함수를 **부른 자리**에서 계산됩니다. 그래서 `log`를 부른 줄이 찍힙니다. 함수 본문 안에서 `current()`를 부르면 `log` 자신의 위치가 나옵니다.

| 멤버 | 주는 것 |
| --- | --- |
| `file_name()` | 소스 파일의 경로. 컴파일러에 넘긴 그대로 |
| `line()`, `column()` | 줄과 칸 |
| `function_name()` | 함수의 이름. 꼴은 컴파일러마다 다르다 |

객체는 포인터 하나 크기(GCC 14에서 8바이트)이고, 내용은 컴파일할 때 정해져 실행 중의 비용이 거의 없습니다. 다만 파일 경로와 함수 이름이 **글자 그대로 실행 파일에 들어갑니다.** 배포하는 바이너리에 소스 경로가 보이는 것이 싫으면 `-ffile-prefix-map`으로 줄입니다.

## 서식 인자와 함께 받기

`log("포트 {}", port)`처럼 인자를 여럿 받는 함수에는 기본 인자를 맨 뒤에 둘 수 없습니다. 서식 문자열을 받는 자리에 위치를 함께 붙잡는 작은 타입을 둡니다.

```cpp
#include <concepts>
#include <format>
#include <print>
#include <source_location>
#include <string_view>
#include <type_traits>
#include <utility>

// 서식 문자열과 "어디서 불렀는가" 를 함께 받는다
template <typename... Args>
struct FormatAt {
    std::format_string<Args...> format;
    std::source_location where;

    template <typename S>
        requires std::convertible_to<const S&, std::string_view>
    consteval FormatAt(const S& text,
                       std::source_location loc = std::source_location::current())
        : format(text), where(loc)
    {
    }
};

template <typename... Args>
void log(FormatAt<std::type_identity_t<Args>...> message, Args&&... args)
{
    std::println("[{}줄] {}", message.where.line(),
                 std::format(message.format, std::forward<Args>(args)...));
}

void connect(int port)
{
    log("포트 {} 에 붙는다", port);
    log("재시도 {}/{}", 1, 3);
}

int main()
{
    log("시작");
    connect(8080);
    // log("{} {}", 1);     // 컴파일 오류: 인자가 모자란다
}
```

```text
[39줄] 시작
[33줄] 포트 8080 에 붙는다
[34줄] 재시도 1/3
```

문자열 리터럴이 `FormatAt`으로 바뀌는 순간, 곧 부른 자리에서 위치가 붙잡힙니다. `std::format_string`을 품고 있으므로 [서식 검사](#/read/cpp-stl/str-format)도 컴파일할 때 그대로 됩니다. `std::type_identity_t`는 "이 자리에서는 `Args`를 추론하지 말라"는 표시입니다. 로그 라이브러리들이 안에서 쓰는 방식이고, 한 번 만들어 두면 `printf`식 매크로 로그를 대신합니다.

매크로가 아직 필요한 곳이 하나 남아 있습니다. `CHECK(x > 0)`이 실패했을 때 **`"x > 0"`이라는 글자**를 찍는 것은 함수로는 할 수 없습니다. 조건식을 글자로 바꾸는 일은 전처리기만 합니다.

## stacktrace

`std::stacktrace::current()`는 지금 실행 중인 함수에서 `main`까지 거슬러 올라가는 호출 경로를 붙잡습니다.

```cpp flags=-lstdc++exp
#include <print>
#include <stacktrace>
#include <stdexcept>
#include <string>

// 던져진 자리의 호출 경로를 함께 싣는 예외
class TracedError : public std::runtime_error {
public:
    explicit TracedError(const std::string& what)
        : std::runtime_error(what), trace_(std::stacktrace::current(1))
    {
    }
    const std::stacktrace& trace() const noexcept { return trace_; }

private:
    std::stacktrace trace_;
};

void read_register(int address)
{
    if (address > 0x7f)
        throw TracedError("주소가 범위를 벗어났다");
}

void init_sensor()
{
    read_register(0x90);
}

int main()
{
    try {
        init_sensor();
    } catch (const TracedError& e) {
        std::println("{}", e.what());
        for (const std::stacktrace_entry& frame : e.trace())
            std::println("  {} ({}줄)", frame.description(), frame.source_line());
    }
}
```

```text nocheck
주소가 범위를 벗어났다
  read_register(int) (22줄)
  init_sensor() (27줄)
  main (33줄)
  __libc_start_call_main (58줄)
  __libc_start_main_impl (360줄)
  _start (0줄)
```

`catch`한 자리에서는 예외가 **어디서 던져졌는지** 알 수 없습니다. 스택이 이미 풀렸기 때문입니다. 위처럼 생성자에서 붙잡아 두면 "누가 `read_register`를 그 값으로 불렀는가"까지 남습니다. `current(1)`의 1은 맨 위의 한 칸(생성자 자신)을 건너뛰라는 뜻입니다. `main` 아래의 줄들은 `main`을 부르는 C 라이브러리의 시작 코드입니다. 통째로 찍을 때는 `std::println("{}", trace)`나 `std::to_string(trace)`를 씁니다.

GCC 14에서 쓰려면 알아 둘 것이 있습니다.

| 조건 | 내용 |
| --- | --- |
| 링크 옵션 | `-lstdc++exp`를 붙인다 (GCC 12, 13에서는 `-lstdc++_libbacktrace`) |
| `-g` | 디버그 정보가 있어야 파일과 줄이 나온다. 없으면 함수 이름만, 그것도 없으면 주소만 나온다 |
| 최적화 | 인라인된 함수는 경로에서 사라질 수 있다. `-O1`로 빌드하니 위의 `read_register` 줄이 없어졌다 |
| 구현 | Clang 20의 libc++에는 `<stacktrace>`가 없다 |

## 비용

| 일 | 걸린 시간 |
| --- | --- |
| 경로 붙잡기 (5칸) | 0.7 µs |
| 처음으로 글로 바꾸기 | 77,000 µs |
| 그 뒤에 글로 바꾸기 | 4 µs |

x86-64 서버, GCC 14 `-O2 -g`에서 잰 값입니다. 붙잡는 것은 주소 몇 개를 적는 일이라 쌉니다. 비싼 것은 주소를 **이름과 줄 번호로 바꾸는 일**입니다. 처음 할 때 실행 파일의 디버그 정보를 읽어 들이느라 77ms가 걸렸습니다. 그래서 쓰는 방식이 정해집니다.

- 붙잡는 것은 예외를 만드는 자리나 "있을 수 없는 상태"를 발견한 자리처럼 **드문 곳**에서만 한다. 자주 도는 루프의 예외에 실으면 [예외의 비용](#/read/cpp-syntax/exc-unwind)에 이 값이 더해진다
- 글로 바꾸는 것은 **로그에 쓸 때로 미룬다.** `stacktrace` 객체는 주소의 목록일 뿐이라 들고 다니기는 싸다
- 시간을 지켜야 하는 스레드에서 처음 글로 바꾸는 일이 생기지 않게 한다

<Note>
프로그램이 죽을 때 경로를 남기려면 `std::set_terminate`에 건 함수 안에서 `std::stacktrace::current()`를 찍습니다. 받지 않은 예외로 끝날 때 어디서 끝났는지가 로그에 남습니다. 세그먼테이션 오류 같은 시그널 안에서는 이 방법이 안전하지 않습니다. 그쪽은 코어 덤프와 디버거, [새니타이저](#/read/cpp-syntax/ubc-tools)가 맡습니다.
</Note>

## 정리

- `std::source_location::current()`를 기본 인자로 두면 함수를 부른 자리가 들어온다. `__FILE__`, `__LINE__` 매크로 없이 로그와 검사 함수를 만든다
- `std::stacktrace`는 호출 경로를 붙잡는다. 예외의 생성자에서 붙잡아 두면 던져진 자리가 남는다. GCC 14에서는 `-lstdc++exp`와 `-g`가 필요하다
- 붙잡기는 싸고 글로 바꾸기는 비싸다. 드문 곳에서 붙잡고, 글로 바꾸는 것은 로그에 쓸 때로 미룬다
