`<filesystem>`(C++17)의 중심은 `std::filesystem::path`입니다. 경로를 `std::string`으로 다루면 "끝에 `/`가 있나", "확장자가 어디부터인가"를 매번 손으로 따져야 합니다. `path`는 그 규칙을 알고 있습니다. 이름이 길어서 다들 이렇게 줄여 씁니다.

```cpp nocheck
namespace fs = std::filesystem;
```

## 쪼개기

```cpp
#include <filesystem>
#include <print>

namespace fs = std::filesystem;

int main()
{
    const fs::path p = "/home/pi/logs/2026-11/temp.csv.gz";
    std::println("root_path     {}", p.root_path().string());
    std::println("parent_path   {}", p.parent_path().string());
    std::println("filename      {}", p.filename().string());
    std::println("stem          {}", p.stem().string());
    std::println("extension     {}", p.extension().string());
    for (const auto& part : p)
        std::print("[{}]", part.string());
    std::println("");

    // 헷갈리는 경우들
    std::println("[{}] [{}]", fs::path(".bashrc").stem().string(),
                 fs::path(".bashrc").extension().string());
    std::println("[{}] [{}]", fs::path("/data/logs/").filename().string(),
                 fs::path("/data/logs/").parent_path().string());
}
```

```text
root_path     /
parent_path   /home/pi/logs/2026-11
filename      temp.csv.gz
stem          temp.csv
extension     .gz
[/][home][pi][logs][2026-11][temp.csv.gz]
[.bashrc] []
[] [/data/logs]
```

- **확장자는 마지막 점부터**입니다. `temp.csv.gz`의 확장자는 `.gz`이고 점을 포함합니다
- 점으로 시작하는 이름(`.bashrc`)은 통째로 이름이고 확장자가 없습니다
- `/`로 끝나는 경로는 **파일 이름이 빈** 경로입니다. `"/data/logs/"`의 `parent_path()`는 `/data`가 아니라 `/data/logs`입니다. 디렉터리 경로를 받을 때 끝의 `/`가 있고 없고에 따라 결과가 달라지는 곳입니다

`path`를 `std::println`에 바로 넣는 서식은 C++26에 들어왔고 GCC 14에는 없습니다. 이 책에서는 `.string()`으로 바꿔 찍습니다.

## 잇기

`/` 연산자가 구분자를 알아서 넣습니다. `+=`는 글자를 그대로 붙입니다.

```cpp
#include <filesystem>
#include <print>

namespace fs = std::filesystem;

int main()
{
    const fs::path base = "/data";
    std::println("{}", (base / "logs" / "a.txt").string());

    fs::path with_plus = "/data/log";
    with_plus += ".txt";                // 글자를 붙인다
    fs::path with_slash = "/data/log";
    with_slash /= ".txt";               // 한 단계 아래로 들어간다
    std::println("{} {}", with_plus.string(), with_slash.string());

    // 오른쪽이 절대 경로이면 왼쪽은 버려진다
    std::println("{}", (base / "/etc/passwd").string());

    const fs::path report = "/data/report.txt";
    std::println("{}", fs::path(report).replace_extension(".bak").string());
    std::println("{}", fs::path(report).replace_filename("other.md").string());
}
```

```text
/data/logs/a.txt
/data/log.txt /data/log/.txt
/etc/passwd
/data/report.bak
/data/other.md
```

셋째 줄이 중요합니다. **`/`의 오른쪽이 절대 경로이면 결과는 오른쪽 그대로**입니다. `base / 사용자가_준_이름`이 `base` 아래에 있으리라고 믿으면 안 됩니다. 아래에서 다시 봅니다.

## 글자만 보는 함수, 디스크를 보는 함수

`path`의 멤버 함수는 모두 **글자만** 다룹니다. 그 경로에 파일이 있는지는 모릅니다. 실제 파일 시스템을 들여다보는 것은 `fs::` 아래의 자유 함수입니다.

| 함수 | 하는 일 | 디스크를 보나 |
| --- | --- | --- |
| `p.lexically_normal()` | `.`, `..`, 겹친 `/`를 정리한다 | 아니다 |
| `p.lexically_relative(base)` | `base`에서 `p`로 가는 상대 경로 | 아니다 |
| `fs::absolute(p)` | 현재 디렉터리를 앞에 붙인다 | 현재 디렉터리만 |
| `fs::canonical(p)` | 심볼릭 링크까지 풀어 실제 경로를 준다. 없으면 오류 | 본다 |
| `fs::weakly_canonical(p)` | 있는 데까지만 풀고 나머지는 글자로 정리한다 | 본다 |
| `fs::equivalent(a, b)` | 두 경로가 같은 파일인가 | 본다 |

```cpp
#include <filesystem>
#include <print>

namespace fs = std::filesystem;

int main()
{
    std::println("{}", fs::path("a/./b/../c//d").lexically_normal().string());

    const fs::path file = "/data/logs/a.txt";
    std::println("{}", file.lexically_relative("/data").string());
    std::println("{}", file.lexically_relative("/data/img/x").string());

    // == 는 글자를 견준다. 조각 단위로 견주므로 겹친 / 는 같게 본다
    std::println("{} {}", fs::path("a/b") == fs::path("a//b"),
                 fs::path("a/b") == fs::path("a/./b"));
}
```

```text
a/c/d
logs/a.txt
../../logs/a.txt
true false
```

`a/b`와 `a/./b`는 같은 파일을 가리키지만 `==`는 거짓입니다. 같은 파일인지 알려면 `lexically_normal()`로 정리해 견주거나, 실제로 있는 파일이면 `fs::equivalent`를 씁니다. `..`을 글자로만 지우는 것은 심볼릭 링크가 끼면 실제와 달라질 수 있습니다. 링크까지 풀어야 하면 `fs::canonical`입니다.

## 사용자 입력을 경로에 붙일 때

웹 요청이나 설정 파일에서 받은 이름을 디렉터리에 이어 붙이는 코드는, 그 결과가 **정말 그 디렉터리 아래인지** 확인해야 합니다. `../../etc/passwd`나 절대 경로가 들어오면 바깥의 파일이 읽힙니다.

```cpp
#include <algorithm>
#include <filesystem>
#include <optional>
#include <print>
#include <string_view>

namespace fs = std::filesystem;

// base 아래의 경로만 돌려준다. 벗어나면 빈 값
std::optional<fs::path> join_inside(const fs::path& base, std::string_view user)
{
    const fs::path joined = (base / user).lexically_normal();
    // base 의 조각이 모두 joined 의 앞부분과 같아야 한다
    const auto [in_base, in_joined] = std::ranges::mismatch(base, joined);
    if (in_base != base.end())
        return std::nullopt;
    return joined;
}

int main()
{
    const fs::path base = "/srv/data";
    const std::string_view inputs[] = {
        "logs/a.txt",
        "./logs/../img/b.png",
        "../etc/passwd",
        "/etc/passwd",
        "logs/../../x",
    };
    for (const std::string_view user : inputs) {
        if (const auto p = join_inside(base, user))
            std::println("{:20} -> {}", user, p->string());
        else
            std::println("{:20} -> 거절", user);
    }
}
```

```text
logs/a.txt           -> /srv/data/logs/a.txt
./logs/../img/b.png  -> /srv/data/img/b.png
../etc/passwd        -> 거절
/etc/passwd          -> 거절
logs/../../x         -> 거절
```

`path`는 조각의 [레인지](#/read/cpp-stl/rng-algorithms)이므로 알고리즘에 그대로 넣을 수 있습니다. 글자를 `starts_with`로 견주면 `/srv/data-secret`이 `/srv/data`로 시작한다고 통과시키는 실수를 하게 됩니다. 조각으로 견주면 그렇지 않습니다.

<Note kind="warn">
이 검사는 글자만 봅니다. `base` 안에 바깥을 가리키는 심볼릭 링크가 있으면 통과합니다. 남이 파일을 만들 수 있는 디렉터리라면 `fs::weakly_canonical`로 양쪽을 푼 다음 같은 검사를 합니다.
</Note>

## 문자열과 오가기

| 멤버 | 주는 것 |
| --- | --- |
| `p.string()` | `std::string` |
| `p.native()`, `p.c_str()` | 운영체제의 형식 그대로. 리눅스는 `char`, 윈도우는 `wchar_t` |
| `p.u8string()` | UTF-8. C++20부터 `std::u8string` |
| `p.generic_string()` | 구분자를 `/`로 통일한 것 |

리눅스에서는 경로가 바이트열 그대로라서 `string()`으로 충분합니다. 윈도우에서는 경로가 UTF-16이고 `string()`은 시스템의 [코드 페이지](#/read/cpp-stl/str-unicode)로 바꾸므로, 한글 이름이 깨질 수 있습니다. 두 곳에서 다 도는 코드는 경로를 `std::string`으로 바꿨다 되돌리지 않고 **`path` 그대로** 들고 다닙니다. [`std::ifstream`](#/read/cpp-stl/io-file)도 `path`를 바로 받습니다.

## 정리

- `path`는 경로를 조각으로 안다. `filename`, `stem`, `extension`, `parent_path`로 쪼개고 `/`로 잇는다
- `/`의 오른쪽이 절대 경로이면 왼쪽이 버려진다. 받은 이름을 붙일 때는 정리한 뒤 조각 단위로 범위를 확인한다
- 멤버 함수는 글자만 보고, `fs::canonical`과 `fs::equivalent` 같은 자유 함수가 디스크를 본다
