[`system_clock`의 시각](#/read/cpp-stl/chr-clocks)은 1970년부터 흐른 시간일 뿐, 그것이 몇 월 며칠인지는 따로 계산해야 합니다. C++20의 `<chrono>`에 그 계산이 들어 있습니다. 윤년, 달마다 다른 날수, 요일, 시간대를 직접 짤 까닭이 없습니다.

## 날짜 타입

날짜를 나타내는 길이 둘 있고, 서로 바꿀 수 있습니다.

| 타입 | 속 | 잘하는 일 |
| --- | --- | --- |
| `year_month_day` | 연, 월, 일 세 칸 | 사람이 읽는 꼴, 달과 해 더하기 |
| `sys_days` | 1970-01-01부터의 날수 | 날 더하기, 날짜끼리 빼기, 요일 |

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;

int main()
{
    // 연/월/일, 일/월/연, 월/일/연 순서로 쓸 수 있다.
    // 첫 조각의 타입이 순서를 정한다
    const year_month_day date = 2026y / November / 20;
    std::println("{} {}", date, date == 20d / 11 / 2026);

    const sys_days as_days = date;          // 날수로 바꾼다
    std::println("1970년부터 {}일째", as_days.time_since_epoch().count());
    std::println("요일 {}", weekday{as_days});

    // 날을 더하고 빼는 것은 날수 쪽에서 한다
    std::println("45일 뒤 {}", year_month_day{as_days + days{45}});
    std::println("새해까지 {}", sys_days{2027y / January / 1} - as_days);

    std::println("윤년인가 {} {}", year{2024}.is_leap(), year{2026}.is_leap());
}
```

```text
2026-11-20 true
1970년부터 20777일째
요일 Fri
45일 뒤 2027-01-04
새해까지 42d
윤년인가 true false
```

`2026y / November / 20`은 나눗셈이 아니라 날짜를 조립하는 연산자입니다. `year`, `month`, `day`가 서로 다른 타입이라서, `2026y / 20 / 11`처럼 월과 일을 바꿔 쓰면 20월이라는 없는 달이 됩니다. 컴파일은 되지만 아래의 `ok()`가 잡아냅니다.

`sys_days`는 `time_point<system_clock, days>`의 다른 이름입니다. 보통의 [시각](#/read/cpp-stl/chr-duration)과 같은 종류라서, 시간을 더하면 그대로 시각이 됩니다.

## 없는 날짜

`year_month_day`는 세 칸을 그대로 담을 뿐 검사하지 않습니다. 2월 30일도 담깁니다.

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;

int main()
{
    const year_month_day bad = 2026y / February / 30;
    std::println("{} / ok={}", bad, bad.ok());
    // 날수로 바꾸면 넘친 만큼 다음 달로 간다
    std::println("{}", year_month_day{sys_days{bad}});

    // 달을 더하는 것은 달 칸만 바꾼다
    const year_month_day jan31 = 2026y / January / 31;
    const year_month_day plus_month = jan31 + months{1};
    std::println("{}/{} ok={}", unsigned{plus_month.month()},
                 unsigned{plus_month.day()}, plus_month.ok());

    // "그 달의 마지막 날" 은 last 로 쓴다
    const year_month_day_last end_of_feb = 2026y / February / last;
    std::println("{}", year_month_day{end_of_feb});

    // 넘치면 마지막 날로 당기는 더하기
    const auto ym = jan31.year() / jan31.month() + months{1};
    const year_month_day clamped =
        plus_month.ok() ? plus_month : year_month_day{ym / last};
    std::println("{}", clamped);
}
```

```text
2026-02-30 is not a valid date / ok=false
2026-03-02
2/31 ok=false
2026-02-28
2026-02-28
```

"1월 31일의 한 달 뒤"에는 정답이 없습니다. 2월 28일일 수도, 3월 3일일 수도 있습니다. 그래서 라이브러리는 달 칸만 올려 `2월 31일`이라는 없는 날짜를 주고, 어떻게 할지를 쓰는 사람에게 맡깁니다. **달이나 해를 더한 뒤에는 `ok()`를 봅니다.** 구독 갱신일처럼 "말일로 당긴다"가 규칙이면 위의 마지막 꼴을 씁니다.

달을 더할 때 `year_month_day`에 더하는 것과 시각에 [`months{1}`](#/read/cpp-stl/chr-duration)을 더하는 것은 전혀 다릅니다. 앞의 것은 달력의 달이고, 뒤의 것은 30.44일이라는 평균 길이입니다.

## 몇째 요일, 그리고 시각 쪼개기

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;
using namespace std::chrono_literals;

int main()
{
    // 11월의 넷째 목요일, 마지막 금요일
    std::println("{}", year_month_day{sys_days{2026y / November / Thursday[4]}});
    std::println("{}", year_month_day{sys_days{2026y / November / Friday[last]}});

    // 다음 월요일까지 며칠
    const weekday today{sys_days{2026y / November / 20}};
    std::println("{} -> 월요일까지 {}", today, Monday - today);

    // 시각을 날짜와 하루 안의 시각으로 쪼갠다
    const sys_time<milliseconds> moment =
        sys_days{2026y / November / 20} + 13h + 5min + 9s + 250ms;
    const sys_days day = floor<days>(moment);
    const year_month_day ymd{day};
    const hh_mm_ss time_of_day{moment - day};
    std::println("{}년 {}월 {}일 {}시 {}분 {}초 {}", int{ymd.year()},
                 unsigned{ymd.month()}, unsigned{ymd.day()},
                 time_of_day.hours().count(), time_of_day.minutes().count(),
                 time_of_day.seconds().count(), time_of_day.subseconds());
}
```

```text
2026-11-26
2026-11-27
Fri -> 월요일까지 3d
2026년 11월 20일 13시 5분 9초 250ms
```

요일끼리의 뺄셈은 7로 나눈 나머지로 계산되어 늘 0부터 6 사이입니다. 시각을 쪼개는 방법은 정해져 있습니다. `floor<days>`로 날짜 부분을 떼고, 나머지를 `hh_mm_ss`에 넣습니다. 로그의 시각을 찍는 데는 이럴 필요 없이 [서식](#/read/cpp-stl/chr-format)을 쓰면 되고, 이 방법은 시와 분을 수로 꺼내 계산해야 할 때 씁니다.

## 시간대

지금까지의 날짜와 시각은 모두 UTC입니다. 사람이 보는 시각으로 바꾸는 것이 `zoned_time`입니다.

```cpp
#include <chrono>
#include <print>

using namespace std::chrono;
using namespace std::chrono_literals;

int main()
{
    const sys_seconds moment = sys_days{2026y / November / 20} + 13h + 5min;

    const zoned_time seoul{"Asia/Seoul", moment};
    const zoned_time new_york{"America/New_York", moment};
    std::println("{:%F %R %Z (%z)}", seoul);
    std::println("{:%F %R %Z (%z)}", new_york);

    // 그 지역의 벽시계 시각으로 만들 때
    const local_seconds wall = local_days{2026y / November / 21} + 9h;
    const zoned_time meeting{"Asia/Seoul", wall};
    std::println("서울 9시는 UTC {:%F %R}", meeting.get_sys_time());

    // 서머타임이 시작되는 밤에는 없는 시각이 있다
    try {
        const local_seconds gap = local_days{2026y / March / 29} + 2h + 30min;
        const zoned_time berlin{"Europe/Berlin", gap};
        std::println("{:%F %R %Z}", berlin);
    } catch (const nonexistent_local_time&) {
        std::println("베를린의 3월 29일 02:30 은 없는 시각이다");
    }

    // 끝나는 밤에는 같은 시각이 두 번 온다. 어느 쪽인지 골라 준다
    const local_seconds twice = local_days{2026y / October / 25} + 2h + 30min;
    const zoned_time first{"Europe/Berlin", twice, choose::earliest};
    const zoned_time second{"Europe/Berlin", twice, choose::latest};
    std::println("{:%R %Z} = UTC {:%R}", first, first.get_sys_time());
    std::println("{:%R %Z} = UTC {:%R}", second, second.get_sys_time());
}
```

```text
2026-11-20 22:05 KST (+0900)
2026-11-20 08:05 EST (-0500)
서울 9시는 UTC 2026-11-21 00:00
베를린의 3월 29일 02:30 은 없는 시각이다
02:30 CEST = UTC 00:30
02:30 CET = UTC 01:30
```

| 타입 | 뜻 |
| --- | --- |
| `sys_time<D>` | UTC의 한 순간. 어디서나 같은 순간을 가리킨다 |
| `local_time<D>` | 어느 곳인지 정해지지 않은 벽시계 시각. 시간대와 만나야 순간이 된다 |
| `zoned_time` | 시간대 하나와 순간 하나의 짝 |

서머타임이 있는 지역에서는 벽시계 시각이 한 해에 한 번 **건너뛰고** 한 번 **겹칩니다.** `choose`를 주지 않으면 그런 시각에서 예외(`nonexistent_local_time`, `ambiguous_local_time`)가 납니다. 한국에는 지금 서머타임이 없지만, 다른 나라의 사용자나 서버를 다루는 코드는 이 둘을 만납니다.

여기서 나오는 규칙이 하나 있습니다. **저장하고 계산하는 것은 UTC(`sys_time`)로 하고, 지역 시각은 보여 줄 때만 만든다.** 로그의 시각, 파일에 적는 시각, 기기끼리 주고받는 시각이 모두 그렇습니다. 지역 시각으로 저장한 "02:30"은 위에서 보듯 어느 순간인지 알 수 없을 때가 있습니다.

<Note kind="warn">
시간대는 **시간대 자료**가 있어야 동작합니다. 리눅스에서는 `tzdata` 패키지(`/usr/share/zoneinfo`)를 읽고, 자료가 없는 작은 이미지에서는 `zoned_time`을 만드는 순간 예외가 납니다. 나라가 규칙을 바꾸면 이 자료를 갱신해야 맞는 답이 나옵니다. `std::chrono::current_zone()`은 실행하는 기계의 설정을 따르므로 이 책의 예제에서는 쓰지 않았습니다. GCC는 13부터 시간대를 지원하고, Clang 20의 libc++에서는 `-fexperimental-library`를 줘야 합니다.
</Note>

## 정리

- 날짜는 `year_month_day`(세 칸)와 `sys_days`(날수) 둘로 다룬다. 날 계산은 날수로, 달과 해 계산은 세 칸으로 하고 서로 바꾼다
- `year_month_day`는 없는 날짜도 담는다. 달이나 해를 더한 뒤에는 `ok()`를 보고, 말일은 `last`로 쓴다
- 순간은 UTC로 저장하고 `zoned_time`은 보여 줄 때 만든다. 서머타임이 있는 곳에는 없는 시각과 두 번 오는 시각이 있다
