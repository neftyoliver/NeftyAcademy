[「할당자가 끼어드는 자리」](#/read/cpp-stl/ov-allocator)에서 컨테이너가 메모리를 할당자에게서 받는다는 것과, 그 출처를 바꾸는 길 셋을 봤습니다. 그 가운데 `std::pmr`(`<memory_resource>`)을 실제로 써 봅니다. 자원의 종류는 [「new, delete, placement new」](#/read/cpp-syntax/life-new)에서 한 번 만났습니다.

## 스택 위의 4KB에서

요청 하나를 처리하는 동안 쓰는 임시 컨테이너를 전부 스택의 버퍼에서 할당받게 합니다.

```cpp
#include <algorithm>
#include <array>
#include <cstddef>
#include <cstdio>
#include <cstdlib>
#include <memory_resource>
#include <new>
#include <print>
#include <string>
#include <string_view>
#include <vector>

static int allocations = 0;
void* operator new(std::size_t n)
{
    ++allocations;
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

// 경로를 '/' 로 나눠 조각 수를 돌려준다
std::size_t handle(std::string_view request)
{
    std::array<std::byte, 4096> buffer;
    std::pmr::monotonic_buffer_resource arena(
        buffer.data(), buffer.size(), std::pmr::null_memory_resource());

    std::pmr::vector<std::pmr::string> parts(&arena);
    std::size_t start = 0;
    while (start < request.size()) {
        const auto slash = request.find('/', start);
        const std::size_t end = std::min(slash, request.size());
        if (end > start)
            parts.emplace_back(request.substr(start, end - start));
        start = end + 1;
    }

    std::pmr::string reply("parts:", &arena);
    for (const auto& part : parts) {
        reply += ' ';
        reply += part;
    }
    // GCC 14 의 println 은 긴 줄에서 힙을 쓴다. 세는 데 섞이지 않게 puts 로 찍는다
    std::puts(reply.c_str());
    return parts.size();
}

int main()
{
    allocations = 0;
    const std::string_view path =
        "/sensors/kitchen-window-north/temperature-celsius/latest";
    const auto n = handle(path);
    std::println("조각 {}개, 힙 할당 {}번", n, allocations);
}
```

```text
parts: sensors kitchen-window-north temperature-celsius latest
조각 4개, 힙 할당 0번
```

`std::vector<std::string>`으로 썼다면 벡터가 자랄 때마다, [15자](#/read/cpp-stl/str-string)를 넘는 문자열마다 `malloc`이 불렸을 코드입니다. 여기서는 한 번도 불리지 않았고, 함수가 끝나면 4KB가 스택과 함께 사라집니다.

읽는 법은 세 가지입니다.

- **자원**(`memory_resource`)이 메모리를 내준다. `monotonic_buffer_resource`는 받은 버퍼를 앞에서부터 잘라 준다
- **컨테이너**는 생성자의 마지막 인자로 자원의 주소를 받는다. `std::pmr::vector<T>`는 `std::vector<T, std::pmr::polymorphic_allocator<T>>`의 다른 이름이다
- 버퍼가 바닥나면 **위쪽 자원**(upstream)에 요청한다. `null_memory_resource()`를 위쪽으로 두면 `std::bad_alloc`이 나고, 생략하면 조용히 힙으로 간다

## 자원을 쌓아 쓴다

| 자원 | 내주는 법 | 돌려받으면 |
| --- | --- | --- |
| `monotonic_buffer_resource` | 앞에서부터 잘라 준다 | 아무 일도 안 한다 |
| `unsynchronized_pool_resource` | 크기별 풀에서 한 칸 | 풀에 넣어 다시 쓴다 |
| `synchronized_pool_resource` | 위와 같고 스레드에 안전하다 | 위와 같다 |
| `new_delete_resource()` | `operator new` | `operator delete` |
| `null_memory_resource()` | 늘 `bad_alloc` | 아무 일도 안 한다 |

자원은 위쪽 자원을 하나씩 가지므로 겹쳐 쌓을 수 있습니다. 직접 만들 때는 가상 함수 셋을 채웁니다. 요청을 세어 위로 넘기는 자원을 만들어, 단조 자원에 바로 붙였을 때와 사이에 풀을 끼웠을 때를 견줍니다.

```cpp
#include <array>
#include <cstddef>
#include <list>
#include <memory_resource>
#include <new>
#include <print>

class Counting : public std::pmr::memory_resource {
public:
    explicit Counting(std::pmr::memory_resource* up) : up_(up) {}

    int count = 0;
    std::size_t bytes = 0;

private:
    void* do_allocate(std::size_t n, std::size_t align) override
    {
        ++count;
        bytes += n;
        return up_->allocate(n, align);
    }
    void do_deallocate(void* p, std::size_t n, std::size_t align) override
    {
        up_->deallocate(p, n, align);
    }
    bool do_is_equal(const std::pmr::memory_resource& other) const
        noexcept override
    {
        return this == &other;
    }

    std::pmr::memory_resource* up_;
};

int main()
{
    std::array<std::byte, 8192> buffer;

    // 넣고 빼기를 5000번 되풀이하는 대기열
    {
        std::pmr::monotonic_buffer_resource arena(
            buffer.data(), buffer.size(), std::pmr::null_memory_resource());
        Counting counted(&arena);
        std::pmr::list<int> queue(&counted);
        try {
            for (int i = 0; i < 5000; ++i) {
                queue.push_back(i);
                queue.pop_front();
            }
        } catch (const std::bad_alloc&) {
            std::println("단조: {}번째 요청에서 바닥났다", counted.count);
        }
    }
    {
        std::pmr::monotonic_buffer_resource arena(
            buffer.data(), buffer.size(), std::pmr::null_memory_resource());
        Counting counted(&arena);
        std::pmr::unsynchronized_pool_resource pool(&counted);
        std::pmr::list<int> queue(&pool);
        for (int i = 0; i < 5000; ++i) {
            queue.push_back(i);
            queue.pop_front();
        }
        std::println("풀: 위쪽에 {}번 {}바이트", counted.count, counted.bytes);
    }
}
```

```text
단조: 342번째 요청에서 바닥났다
풀: 위쪽에 3번 1712바이트
```

대기열에 든 것은 늘 하나뿐인데도 단조 자원은 8KB를 다 썼습니다. 24바이트짜리 노드 341개를 내주고 하나도 다시 쓰지 않았기 때문입니다. 풀을 끼우면 돌려받은 칸을 다시 내주므로 위쪽에는 처음 몇 번만 요청합니다.

| 쓰임 | 맞는 자원 |
| --- | --- |
| 만들기만 하고 통째로 버린다 (요청 하나, 한 주기) | 단조 |
| 넣고 빼기를 오래 되풀이한다 | 풀 (위쪽에 단조나 힙) |

100만 개짜리 `list<int>`를 만들고 버리는 데 기본 할당자는 28ms, 단조 자원은 14ms, 풀 자원은 22ms가 걸렸습니다(x86-64, GCC 14 `-O2`). 빨라지는 것보다 **힙을 건드리지 않고 시간이 일정하다**는 쪽이 `pmr`을 쓰는 까닭입니다.

## 자원은 안쪽으로 전해진다

첫 예제에서 `parts`에만 자원을 줬는데 그 안의 문자열도 같은 버퍼를 썼습니다. `pmr` 컨테이너는 원소를 만들 때 **원소가 할당자를 받는 타입이면 자기 자원을 건네줍니다.** 원소가 보통의 `std::string`이면 건네줄 길이 없습니다.

```cpp
#include <array>
#include <cstddef>
#include <cstdio>
#include <cstdlib>
#include <format>
#include <iterator>
#include <memory_resource>
#include <new>
#include <string>
#include <vector>

static int allocations = 0;
void* operator new(std::size_t n)
{
    ++allocations;
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

int main()
{
    std::array<std::byte, 16384> buffer;
    {
        std::pmr::monotonic_buffer_resource arena(
            buffer.data(), buffer.size(), std::pmr::null_memory_resource());
        allocations = 0;
        std::pmr::vector<std::pmr::string> names(&arena);
        for (int i = 0; i < 100; ++i) {
            // 빈 pmr::string 을 넣고, 그 뒤에 바로 서식을 써 넣는다
            auto out = std::back_inserter(names.emplace_back());
            std::format_to(out, "sensor-reading-number-{}", i);
        }
        std::printf("pmr::string 을 담으면 힙 할당 %d번\n", allocations);
    }
    {
        std::pmr::monotonic_buffer_resource arena(
            buffer.data(), buffer.size(), std::pmr::null_memory_resource());
        allocations = 0;
        std::pmr::vector<std::string> names(&arena);
        for (int i = 0; i < 100; ++i)
            names.push_back(std::format("sensor-reading-number-{}", i));
        std::printf("std::string 을 담으면 힙 할당 %d번\n", allocations);
    }
    std::printf("%zu %zu\n", sizeof(std::vector<int>),
                sizeof(std::pmr::vector<int>));
    std::printf("%zu %zu\n", sizeof(std::string), sizeof(std::pmr::string));
}
```

```text
pmr::string 을 담으면 힙 할당 0번
std::string 을 담으면 힙 할당 100번
24 32
32 40
```

`std::format`은 `std::string`을 돌려주므로 힙을 씁니다. `pmr` 문자열에 서식을 쓰려면 위처럼 [`std::format_to`](#/read/cpp-stl/str-format)로 바로 써 넣습니다. `pmr` 컨테이너는 자원의 주소를 들고 다니므로 8바이트씩 큽니다.

`std::pmr::string`과 `std::string`은 **다른 타입**입니다. `const std::string&`를 받는 함수에 넘길 수 없고, `std::string s = name;`도 안 됩니다(`std::string s(name);`으로 복사는 됩니다). 함수가 [`std::string_view`](#/read/cpp-stl/str-view)로 받게 해 두면 둘 다 받을 수 있습니다.

## 흔한 실수

| 실수 | 일어나는 일 |
| --- | --- |
| 컨테이너가 자원보다 오래 산다 | 컨테이너가 사라진 버퍼를 가리킨다 |
| 지역 버퍼를 쓰는 `pmr` 컨테이너를 반환한다 | 위와 같다. 컴파일러는 경고하지 않는다 |
| 위쪽 자원을 생략한다 | 버퍼가 바닥나면 조용히 힙을 쓴다 |
| 자원이 다른 컨테이너로 이동 대입한다 | 통째로 옮기지 못하고 원소를 하나씩 옮긴다 |

```cpp nocheck
std::pmr::vector<int> make_table()
{
    std::array<std::byte, 1024> buffer;
    std::pmr::monotonic_buffer_resource arena(buffer.data(), buffer.size());
    std::pmr::vector<int> table(&arena);
    table.push_back(1);
    return table;       // table 의 메모리는 buffer 안에 있다. 반환하면 댕글링
}
```

선언 순서가 곧 안전장치입니다. **버퍼, 자원, 컨테이너** 순서로 선언하면 사라질 때는 거꾸로 컨테이너, 자원, 버퍼 순서입니다. 결과를 함수 밖으로 내보내야 하면 자원을 부른 쪽에서 만들어 인자로 넘기거나, 마지막에 보통의 `std::vector`로 복사해 돌려줍니다.

<Note>
단조 자원을 주기마다 다시 쓰려면 `arena.release()`를 부릅니다. 내준 것을 모두 잊고 버퍼의 처음으로 돌아가므로, 그 자원을 쓰던 컨테이너가 모두 사라진 뒤에 부릅니다. 템플릿 인자로 주는 옛 방식의 할당자를 만드는 법은 [「할당자 만들기」](#/read/cpp-advanced/mm-allocator)에서, 자원을 설계하는 법은 [「pmr 메모리 자원」](#/read/cpp-advanced/mm-pmr)에서, 힙이 아예 없는 기기에서 쓰는 법은 [「pmr로 버퍼 지정하기」](#/read/cpp-embedded/nh-pmr)에서 다룹니다.
</Note>

## 정리

- `std::pmr` 컨테이너는 생성자에서 자원의 주소를 받는다. 단조 자원에 스택 버퍼를 주고 위쪽을 `null_memory_resource()`로 막으면 힙을 쓰지 않는 구간이 된다
- 단조 자원은 돌려받은 메모리를 다시 쓰지 않는다. 넣고 빼기를 되풀이하는 곳에는 풀 자원을 사이에 끼운다
- 자원은 `pmr` 원소에게만 전해진다. 속까지 `std::pmr::string`으로 맞추고, 컨테이너가 자원과 버퍼보다 먼저 사라지게 선언한다
