[「string과 string_view」](#/read/cpp-syntax/ft-string)에서 `std::string("한글").size()`가 6이라는 것을 보았습니다. `std::string`은 글자가 아니라 **바이트**의 열입니다. 한글을 다루는 프로그램이라면 그 사이를 직접 메워야 합니다.

## 세 가지 길이

| 단위 | 뜻 | `"한글"`에서 |
| --- | --- | --- |
| 코드 유닛 | 인코딩의 한 칸. UTF-8에서는 바이트 | 6 |
| 코드 포인트 | 유니코드가 번호를 붙인 것 하나. 한은 U+D55C | 2 |
| 글자 | 사람이 한 글자로 보는 것 | 2 |

`size()`, `[]`, `substr`은 모두 첫째 단위로 일합니다. 둘째와 셋째가 갈리는 경우도 있습니다. 아래에서 봅니다.

## UTF-8의 모양

| 코드 포인트 | 바이트 수 | 첫 바이트 |
| --- | --- | --- |
| U+0000 - U+007F (ASCII) | 1 | `0xxxxxxx` |
| U+0080 - U+07FF | 2 | `110xxxxx` |
| U+0800 - U+FFFF (한글, 한자) | 3 | `1110xxxx` |
| U+10000 - U+10FFFF (이모지) | 4 | `11110xxx` |

둘째 바이트부터는 모두 `10xxxxxx` 꼴입니다. 이 설계에서 두 가지를 얻습니다.

- **ASCII 글자의 바이트는 다른 글자 안에 나오지 않습니다.** 그래서 `find('=')`나 쉼표로 토막 내기는 한글이 섞인 글에서도 그대로 옳습니다. [앞에서 만든 `split`](#/read/cpp-stl/str-view)을 고칠 필요가 없습니다.
- 아무 바이트나 보고 "글자의 첫 바이트인가"를 알 수 있습니다. `10`으로 시작하지 않으면 첫 바이트입니다.

## 글자 단위로 세고 자르기

둘째 성질만으로 코드 포인트를 세고, 글자 중간을 자르지 않게 할 수 있습니다.

```cpp
#include <algorithm>
#include <print>
#include <string>
#include <string_view>

// 코드 포인트의 첫 바이트인가 (10xxxxxx 가 아닌가)
bool is_lead(char c) { return (static_cast<unsigned char>(c) & 0xC0) != 0x80; }

std::size_t count_code_points(std::string_view s)
{
    return static_cast<std::size_t>(std::ranges::count_if(s, is_lead));
}

// 앞에서 코드 포인트 n개만 남긴다
std::string_view take_code_points(std::string_view s, std::size_t n)
{
    std::size_t i = 0;
    for (; i < s.size(); ++i)
        if (is_lead(s[i]) && n-- == 0)
            break;
    return s.substr(0, i);
}

int main()
{
    std::string s = "라즈베리파이 5";
    std::println("{}바이트, 코드 포인트 {}개", s.size(), count_code_points(s));

    std::print("substr(0, 4)의 바이트:");
    for (unsigned char byte : s.substr(0, 4))
        std::print(" {:02X}", byte);
    std::println("");
    std::println("[{}]", take_code_points(s, 4));
}
```

```text
20바이트, 코드 포인트 8개
substr(0, 4)의 바이트: EB 9D BC EC
[라즈베리]
```

`substr(0, 4)`는 "라"의 세 바이트와 "즈"의 첫 바이트 하나를 잘라 왔습니다. 마지막 `EC`는 짝을 잃은 바이트이고, 화면에는 깨진 글자로 나옵니다. 16글자짜리 LCD에 이름을 맞춰 자르는 코드가 흔히 이렇게 틀립니다.

## 코드 포인트 꺼내기

번호 자체가 필요하면 비트를 모읍니다. 첫 바이트에서 길이를 알아내고, 이어지는 바이트마다 아래 6비트를 붙입니다.

```cpp
#include <cstdint>
#include <print>
#include <string>
#include <string_view>

// 맨 앞의 코드 포인트 하나를 읽고, 읽은 만큼 text 를 줄인다. 잘못된 바이트는 U+FFFD
char32_t next_code_point(std::string_view& text)
{
    const auto byte = [&](std::size_t i) {
        return static_cast<unsigned char>(text[i]);
    };
    const unsigned char lead = byte(0);
    const std::size_t length = lead < 0x80          ? 1
                               : (lead >> 5) == 0b110   ? 2
                               : (lead >> 4) == 0b1110  ? 3
                               : (lead >> 3) == 0b11110 ? 4
                                                        : 0;
    if (length == 0 || text.size() < length) {
        text.remove_prefix(1);
        return U'�';
    }
    char32_t code = length == 1 ? lead : lead & (0xFF >> (length + 1));
    for (std::size_t i = 1; i < length; ++i) {
        if ((byte(i) & 0xC0) != 0x80) {
            text.remove_prefix(1);
            return U'�';
        }
        code = (code << 6) | (byte(i) & 0x3F);
    }
    text.remove_prefix(length);
    return code;
}

int main()
{
    std::string_view rest = "온도 23℃";
    while (!rest.empty()) {
        const std::size_t before = rest.size();
        const auto code = static_cast<std::uint32_t>(next_code_point(rest));
        std::print("U+{:04X}({}) ", code, before - rest.size());
    }
    std::println("");
}
```

```text
U+C628(3) U+B3C4(3) U+0020(1) U+0032(1) U+0033(1) U+2103(3)
```

바깥에서 들어온 글은 올바른 UTF-8이 아닐 수 있습니다. 위 함수는 그럴 때 한 바이트를 버리고 U+FFFD(대체 문자)를 돌려주어 멈추지 않고 나아갑니다. 보안이 걸린 자리라면 더 엄격해야 하고(같은 글자를 필요보다 길게 적은 꼴 거르기 등), 그때는 검증된 라이브러리를 씁니다.

## 한글 풀기

완성된 한글 11,172자는 U+AC00부터 초성 19, 중성 21, 종성 28(없음 포함)의 순서로 놓여 있습니다. 그래서 나눗셈으로 풀립니다.

```cpp
#include <print>
#include <string>

int main()
{
    const char* initials[] = {"ㄱ", "ㄲ", "ㄴ", "ㄷ", "ㄸ", "ㄹ", "ㅁ",
                              "ㅂ", "ㅃ", "ㅅ", "ㅆ", "ㅇ", "ㅈ", "ㅉ",
                              "ㅊ", "ㅋ", "ㅌ", "ㅍ", "ㅎ"};
    std::u32string word = U"라즈베리";       // char32_t: 한 칸이 코드 포인트 하나
    for (char32_t c : word)
        if (c >= 0xAC00 && c <= 0xD7A3)
            std::print("{}", initials[(c - 0xAC00) / (21 * 28)]);
    std::println("");

    std::string composed = "가";             // 가: 코드 포인트 하나
    std::string decomposed = "가";     // ᄀ + ᅡ: 코드 포인트 둘
    std::println("{} {}", composed, decomposed);
    std::println("{}바이트 {}바이트, 같은가 {}", composed.size(), decomposed.size(),
                 composed == decomposed);
}
```

```text
ㄹㅈㅂㄹ
가 가
3바이트 6바이트, 같은가 false
```

둘째와 셋째 줄이 코드 포인트와 글자가 갈리는 경우입니다. 화면에는 둘 다 "가"로 보이지만 한쪽은 한 덩어리(NFC)이고 한쪽은 자모를 늘어놓은 것(NFD)입니다. `==`는 바이트를 견주므로 다르다고 합니다. 맥에서 만든 파일 이름의 한글이 다른 운영체제에서 자모로 풀려 보이는 것이 이 때문입니다. 두 꼴을 맞추는 일(정규화)은 표준 라이브러리에 없고 ICU 같은 라이브러리의 몫입니다.

## 문자 타입들

| 타입 | 담는 것 | 리터럴 |
| --- | --- | --- |
| `char` | 바이트. 요즘은 대개 UTF-8 | `"한글"` |
| `char8_t` (C++20) | UTF-8 코드 유닛 | `u8"한글"` |
| `char16_t` | UTF-16 코드 유닛 | `u"한글"` |
| `char32_t` | 코드 포인트 | `U"한글"` |
| `wchar_t` | 윈도우에서 16비트, 리눅스에서 32비트 | `L"한글"` |

권하는 길은 단순합니다. **프로그램 안에서는 `std::string`에 UTF-8로 들고, 다른 인코딩은 경계에서만 바꿉니다.** 윈도우 API의 `W` 함수를 부를 때 UTF-16으로, 돌려받으면 다시 UTF-8로 바꾸는 식입니다.

- `std::u8string`은 타입으로 "이것은 UTF-8"임을 말해 주지만, `std::format`과 `std::print`가 받지 않아 쓰기 번거롭습니다.
- `wchar_t`는 크기가 플랫폼마다 달라서 파일이나 통신에 쓰면 안 됩니다.
- 인코딩을 바꿔 주던 `<codecvt>`는 C++17에서 권하지 않는 것이 되었고 C++26에서 빠졌습니다. 표준에는 지금 대신할 것이 없어서, 위처럼 직접 풀거나 운영체제의 함수나 ICU를 씁니다.

<Note>
소스 파일의 인코딩도 맞아야 합니다. GCC와 Clang은 소스와 실행 파일 속 문자열을 모두 UTF-8로 봅니다. MSVC는 옵션이 없으면 시스템 코드 페이지(한국어 윈도우는 CP949)로 보므로, 프로젝트에 `/utf-8`을 줍니다. 그러지 않으면 문자열 상수가 CP949로 들어가 `"한글"`이 4바이트가 되거나, 소스를 잘못 읽었다는 경고 C4819를 만납니다.
</Note>

## 정리

- `std::string`의 길이와 첨자는 바이트 단위다. 코드 포인트는 첫 바이트(`10`으로 시작하지 않는 바이트)를 세어 구한다
- ASCII 구분자로 찾고 자르는 코드는 UTF-8에서도 옳다. 길이로 자르는 코드가 글자를 깬다
- 안에서는 UTF-8 `std::string`, 다른 인코딩은 경계에서만. 정규화와 자소 묶음은 ICU의 일이다
