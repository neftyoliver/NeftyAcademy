C++17부터 표준 알고리즘 대부분은 **첫 인자로 실행 정책**을 받습니다. `std::sort(v.begin(), v.end())`를 `std::sort(std::execution::par, v.begin(), v.end())`로 바꾸면 여러 코어로 나눠 정렬해 달라는 뜻이 됩니다. 스레드를 직접 만들지 않고 코어를 쓰는 가장 짧은 길입니다.

## 네 가지 정책

`<execution>` 헤더에 있습니다.

| 정책 | 뜻 |
| --- | --- |
| `std::execution::seq` | 한 스레드에서 차례로. 정책을 주지 않은 것과 거의 같다 |
| `std::execution::par` | 여러 스레드로 나눠서 |
| `std::execution::par_unseq` | 여러 스레드로, 스레드 안에서도 SIMD 명령으로 묶어서 |
| `std::execution::unseq` (C++20) | 한 스레드에서 SIMD 명령으로 묶어서 |

정책은 **허락**이지 명령이 아닙니다. 라이브러리는 범위가 작거나 코어가 하나면 그냥 차례로 돌려도 됩니다.

## 써 보기

```cpp nosan flags=-ltbb
#include <algorithm>
#include <chrono>
#include <execution>
#include <numeric>
#include <print>
#include <random>
#include <thread>
#include <vector>

int main()
{
    using clock = std::chrono::steady_clock;
    const auto ms = [](clock::duration d) {
        return std::chrono::duration_cast<std::chrono::milliseconds>(d).count();
    };

    std::mt19937 rng(1);
    std::vector<double> base(5'000'000);
    for (double& x : base)
        x = static_cast<double>(rng());
    std::println("코어 {}개", std::thread::hardware_concurrency());

    auto a = base;
    const auto t0 = clock::now();
    std::sort(a.begin(), a.end());
    const auto t1 = clock::now();

    auto b = base;
    const auto t2 = clock::now();
    // 바뀐 것은 첫 인자뿐이다
    std::sort(std::execution::par, b.begin(), b.end());
    const auto t3 = clock::now();
    std::println("정렬: 차례로 {}ms, 병렬 {}ms", ms(t1 - t0), ms(t3 - t2));
    std::println("결과가 같은가 {}", a == b);

    const auto par = std::execution::par;
    const double sum1 = std::accumulate(base.begin(), base.end(), 0.0);
    const double sum2 = std::reduce(par, base.begin(), base.end(), 0.0);
    std::println("합: {:.0f} / {:.0f}", sum1, sum2);
}
```

```text nocheck
코어 2개
정렬: 차례로 360ms, 병렬 251ms
결과가 같은가 true
합: 10738368417072082 / 10738368417072668
```

2코어 x86-64 서버, GCC 14 `-O2`의 결과입니다. 정렬이 1.4배 빨라졌습니다. 코어가 넷인 라즈베리파이 5나 4에서는 비율이 다를 것이고, 직접 재 봐야 합니다.

마지막 줄이 눈여겨볼 곳입니다. **합의 끝자리가 다릅니다.** `std::reduce`는 범위를 토막 내어 따로 더한 뒤 합치므로 더하는 순서가 `accumulate`와 다르고, 실수의 덧셈은 순서에 따라 반올림이 달라집니다. 틀린 것이 아니라 병렬의 성질입니다. 결과가 비트까지 같아야 하는 계산(검증용 체크섬, 재현되어야 하는 시뮬레이션)에는 쓰지 않습니다.

<Note kind="warn">
GCC의 병렬 알고리즘은 인텔 TBB 라이브러리 위에 만들어져 있습니다. 라즈베리파이 OS와 우분투에서는 `sudo apt install libtbb-dev`로 깔고, 링크할 때 `-ltbb`를 붙입니다. CMake에서는 `find_package(TBB REQUIRED)`와 `target_link_libraries(app PRIVATE TBB::tbb)`입니다. TBB 헤더가 있는데 `-ltbb`를 빼먹으면 `undefined reference to tbb::…` 링크 오류가 길게 나옵니다. TBB가 아예 없으면 오류 없이 컴파일되고 **차례로** 돕니다. 빨라지지 않았다면 이것부터 확인합니다.
</Note>

## 지켜야 할 규칙

병렬 정책을 주는 순간, 내가 넘긴 함수는 여러 스레드에서 동시에 불립니다. 라이브러리는 그 함수 안을 지켜 주지 않습니다.

```cpp nosan flags=-ltbb
#include <algorithm>
#include <atomic>
#include <execution>
#include <print>
#include <vector>

int main()
{
    std::vector<int> values(100'000);
    for (std::size_t i = 0; i < values.size(); ++i)
        values[i] = static_cast<int>(i % 20);

    // 틀린 코드: 여러 스레드가 같은 int 를 고친다 (데이터 경쟁)
    //   int hits = 0;
    //   std::for_each(std::execution::par, values.begin(), values.end(),
    //                 [&](int v) { if (v == 7) ++hits; });

    // 고치는 법 1: 함께 쓰는 변수를 atomic 으로
    std::atomic<int> hits = 0;
    std::for_each(std::execution::par, values.begin(), values.end(), [&](int v) {
        if (v == 7)
            ++hits;
    });

    // 고치는 법 2: 함께 쓰는 변수를 없앤다. 결과를 돌려주는 알고리즘을 쓴다
    const auto par = std::execution::par;
    const auto counted = std::count(par, values.begin(), values.end(), 7);

    std::println("{} {}", hits.load(), counted);
}
```

```text
5000 5000
```

| 규칙 | 어기면 |
| --- | --- |
| 넘긴 함수가 같은 변수를 보호 없이 고치지 않는다 | 데이터 경쟁. 가끔 틀린 값이 나온다 |
| 넘긴 함수가 예외를 던지지 않는다 | `std::terminate`. 잡을 수 없다 |
| `par_unseq`와 `unseq`에서는 잠금도 쓰지 않는다 | 교착이나 정의되지 않은 동작 |
| 임의 접근 반복자를 넘긴다 | `list`에는 병렬의 이득이 거의 없다 |

둘째 고치는 법이 더 낫습니다. "모아서 하나의 값을 낸다"는 일은 `for_each`에 바깥 변수를 엮지 말고 `count`, `reduce`, `transform_reduce`로 씁니다. 그러면 지킬 것이 없어집니다.

## 언제 이득인가

병렬에는 밑천이 듭니다. 일을 나누고, 스레드를 깨우고, 결과를 모읍니다.

| 잰 것 | 차례로 | 병렬 |
| --- | --- | --- |
| `double` 500만 개 정렬 | 360ms | 251ms |
| `double` 500만 개의 합 | 5ms | 2ms |
| 원소 100개의 합을 10만 번 | 1ms | 216ms |

셋째 줄에서 병렬이 200배 넘게 느립니다. 범위가 작으면 밑천이 일보다 큽니다. 기준은 이렇습니다.

- 원소가 수만 개 이상이고 원소 하나에 드는 일이 가볍지 않을 때 써 본다
- 메모리를 읽고 쓰는 것이 전부인 일(단순한 복사, 합)은 코어보다 메모리 속도가 먼저 막힌다
- 이미 여러 스레드가 도는 프로그램 안에서는 코어를 서로 뺏는다
- 작은 보드에서는 코어를 모두 쓰면 열이 올라 클럭이 내려갈 수 있다

그리고 언제나 **재 보고** 정합니다. 직접 스레드를 다루는 방법은 [「thread와 jthread」](#/read/cpp-stl/conc-thread)에서 시작합니다.

<Note>
`std::ranges::` 알고리즘은 C++23까지 실행 정책을 받지 않습니다. 병렬로 돌리려면 반복자 한 쌍을 받는 옛 꼴을 씁니다. Clang의 libc++는 이 기능의 구현이 아직 일부뿐이고, MSVC는 따로 깔 것 없이 됩니다.
</Note>

## 정리

- 알고리즘의 첫 인자로 `std::execution::par`를 주면 여러 코어로 나눠 돈다. GCC에서는 TBB를 깔고 `-ltbb`로 링크한다
- 넘긴 함수는 동시에 불린다. 함께 쓰는 변수를 없애거나 `atomic`으로 지키고, 예외를 던지지 않는다
- 작은 범위에서는 훨씬 느리다. 실수의 합은 끝자리가 달라진다. 재 보고 쓴다
