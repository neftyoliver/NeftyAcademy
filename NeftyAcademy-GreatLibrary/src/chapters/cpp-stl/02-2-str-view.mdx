[「string과 string_view」](#/read/cpp-syntax/ft-string)에서 "읽기만 하는 인자는 `std::string_view`로 받는다"까지 보았습니다. 이 타입은 싸고 편한 만큼 죽은 메모리를 가리키기도 쉽습니다. 무엇을 할 수 있고 어디서 다치는지 봅니다.

## 포인터 하나와 길이 하나

```cpp
#include <print>
#include <string>
#include <string_view>

using namespace std::string_view_literals;

// 컴파일할 때 만들어져 읽기 전용 메모리에 놓인다. 실행 중에 하는 일이 없다
constexpr std::string_view level_names[] = {"DEBUG", "INFO", "WARN", "ERROR"};
static_assert(level_names[2].size() == 4);

int main()
{
    std::println("sizeof(string_view) = {}", sizeof(std::string_view));

    std::string owner = "raspberry";
    const char* c_string = "pi";
    std::string_view a = owner;                 // std::string 에서
    std::string_view b = c_string;              // C 문자열에서 (길이를 센다)
    std::string_view c = "zero 2 w";            // 문자열 상수에서
    std::string_view d(owner.data() + 4, 5);    // 포인터와 길이로
    auto e = "a\0b"sv;                          // sv: 길이를 컴파일러가 안다
    std::println("{} / {} / {} / {} / {}", a, b, c, d, e.size());
    std::println("{}", level_names[2]);
}
```

```text
sizeof(string_view) = 16
raspberry / pi / zero 2 w / berry / 3
WARN
```

`std::string_view`는 16바이트짜리 값입니다(64비트). 복사가 포인터 두 개를 복사하는 값이므로, 인자로는 참조가 아니라 **값으로** 받습니다. 가리키는 글자를 고칠 수 없고, 소유하지도 않습니다.

`constexpr` 배열은 마이크로컨트롤러에서 특히 쓸모가 있습니다. `std::string`의 배열과 달리 시작할 때 생성자가 돌지 않고, 램이 아니라 플래시에 놓입니다.

## 복사 없이 자르기

`substr`, `remove_prefix`, `remove_suffix`는 포인터와 길이만 바꿉니다. 그래서 한 줄을 토막 내는 일을 할당 없이 할 수 있습니다.

```cpp
#include <print>
#include <string_view>
#include <vector>

std::vector<std::string_view> split(std::string_view text, char delimiter)
{
    std::vector<std::string_view> parts;
    while (true) {
        const auto pos = text.find(delimiter);
        parts.push_back(text.substr(0, pos));   // npos 이면 "끝까지"가 된다
        if (pos == std::string_view::npos)
            break;
        text.remove_prefix(pos + 1);            // 구분자까지 앞을 떼어 낸다
    }
    return parts;
}

int main()
{
    std::string_view line = "temp=23.5,humid=41,press=1013";
    for (std::string_view field : split(line, ',')) {
        const auto eq = field.find('=');
        std::string_view key = field.substr(0, eq);
        std::string_view value = field.substr(eq + 1);
        std::println("{:5} -> {}", key, value);
    }
}
```

```text
temp  -> 23.5
humid -> 41
press -> 1013
```

`parts` 안의 뷰는 모두 `line`이 가리키는 원래 글자를 가리킵니다. 글자는 한 번도 복사되지 않았습니다. `std::string`의 `substr`로 같은 일을 하면 토막마다 새 문자열이 생깁니다. 같은 일을 하는 `std::views::split`은 [「뷰」](#/read/cpp-stl/rng-views)에서 봅니다.

## `\0`으로 끝나지 않는다

뷰는 "여기부터 몇 글자"일 뿐이어서, 그 뒤에 `\0`이 있다는 보장이 없습니다. C 함수에 `data()`를 그대로 넘기면 뷰의 끝을 지나서 읽습니다.

```cpp
#include <cstdio>
#include <print>
#include <string>
#include <string_view>

int main()
{
    std::string_view line = "GPIO17=HIGH";
    std::string_view key = line.substr(0, 6);

    std::println("{}", key);                    // 길이를 아는 쪽
    std::printf("%s\n", key.data());            // 모르는 쪽: \0 까지 간다

    // 고치는 법 1: 길이를 알려 준다
    std::printf("%.*s\n", static_cast<int>(key.size()), key.data());
    // 고치는 법 2: 복사해서 \0 을 붙인다
    std::printf("%s\n", std::string(key).c_str());
}
```

```text
GPIO17
GPIO17=HIGH
GPIO17
GPIO17
```

둘째 줄이 틀렸습니다. 이 예제는 뒤에 문자열 상수의 나머지가 있어서 그것이 찍혔지만, 버퍼의 일부를 가리키는 뷰였다면 버퍼 밖을 읽습니다. `fopen`, `open`, `std::stoi`처럼 `\0`으로 끝나는 문자열을 받는 함수에 넘길 것이라면 인자를 `const std::string&`로 받는 편이 맞습니다.

## 뷰가 죽는 길

뷰는 주인이 살아 있고 **옮겨지지 않는 동안만** 쓸 수 있습니다.

| 코드 | 죽는 까닭 |
| --- | --- |
| `std::string_view v = make_name();` | 돌려받은 임시 `std::string`이 그 줄 끝에서 사라진다 |
| `std::string_view v = a + b;` | `a + b`도 임시 객체다 |
| `std::string_view v = s; s += more;` | `s`가 더 큰 메모리로 옮겨 간다 |
| 뷰를 구조체 멤버로 들고 있기 | 주인이 구조체보다 먼저 사라진다 |
| 함수가 지역 `std::string`의 뷰를 돌려주기 | 함수가 끝나면 주인이 사라진다 |

셋째를 실제로 돌려 봅니다.

```cpp nocheck
std::string s = "a string long enough to live on the heap";
std::string_view v = s;
s += " and now it has to move to a bigger block";
std::println("{}", v);
```

```text
==5583==ERROR: AddressSanitizer: heap-use-after-free on address 0x504000000010 ...
READ of size 40 at 0x504000000010 thread T0
```

`-fsanitize=address`를 켠 결과입니다. 끄고 돌리면 깨진 글자 몇 개와 옛 문장의 뒷부분이 찍히고 정상 종료합니다. 조용히 틀리는 쪽입니다.

<Note>
앞의 두 줄(임시 객체에서 뷰 만들기)은 Clang이 기본으로 경고합니다. `warning: object backing the pointer will be destroyed at the end of the full-expression [-Wdangling-gsl]`. GCC 14는 `-Wall -Wextra`에서도 말이 없습니다. 두 컴파일러로 번갈아 빌드하는 것이 값싼 검사가 됩니다.
</Note>

## 쓰는 자리

| 자리 | 권하는 타입 | 까닭 |
| --- | --- | --- |
| 읽기만 하는 인자 | `std::string_view` | 무엇이든 복사 없이 받는다 |
| 받아서 보관하는 인자 | `std::string`으로 받아 `std::move` | 어차피 사본이 필요하다 |
| C 함수로 넘길 인자 | `const std::string&` | `\0`이 필요하다 |
| 반환값 | `std::string` | 받는 쪽이 수명을 따질 일이 없다 |
| 멤버 변수 | `std::string` | 주인과 수명이 묶인다 |

반환값과 멤버에 뷰를 쓰는 것은 가리키는 것이 문자열 상수이거나, 주인이 더 오래 산다는 것을 구조로 보일 수 있을 때뿐입니다.

`std::string`과 섞어 쓸 때 걸리는 곳이 둘 있습니다.

```cpp nocheck
std::string_view name = "pi";
std::string a = name;       // 오류: 뷰에서 string 으로는 저절로 바뀌지 않는다
std::string b(name);        // 된다. 할당이 일어나는 일이라 드러내어 적게 했다

std::string greeting = "hello ";
std::string c = greeting + name;    // GCC 14 에서 오류: 이런 + 가 없다
greeting += name;                   // 된다
```

`string + string_view`는 C++26에 들어갔고, Clang 20의 libc++에서는 됩니다. 그 전에는 `+=`나 `append`, 또는 [`std::format`](#/read/cpp-stl/str-format)을 씁니다.

## 정리

- `std::string_view`는 포인터와 길이다. 값으로 넘기고, 자르는 일은 복사 없이 한다
- `\0`으로 끝난다는 보장이 없다. C 함수에 `data()`를 그대로 넘기지 않는다
- 주인이 사라지거나 옮겨지면 뷰는 죽는다. 인자에는 쓰고, 반환값과 멤버에는 `std::string`을 쓴다
