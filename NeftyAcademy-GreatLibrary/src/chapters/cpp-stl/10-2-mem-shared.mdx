[`unique_ptr`](#/read/cpp-stl/mem-unique)는 주인이 하나입니다. `std::shared_ptr`는 주인이 여럿이고, **마지막 주인이 사라질 때** 객체를 지웁니다. 누가 마지막일지 코드를 쓸 때 알 수 없는 경우를 위한 도구입니다.

## 주인을 센다

```cpp
#include <memory>
#include <print>
#include <utility>
#include <vector>

struct Frame {
    int id;

    explicit Frame(int i) : id(i) { std::println("  Frame {} 생성", id); }
    ~Frame() { std::println("  Frame {} 소멸", id); }
};

int main()
{
    auto a = std::make_shared<Frame>(1);
    std::println("a 만 있다: {}", a.use_count());
    {
        auto b = a;                     // 복사하면 주인이 하나 는다
        std::vector<std::shared_ptr<Frame>> queue{a, b};
        std::println("b 와 queue: {}", a.use_count());

        auto c = std::move(b);          // 이동은 수를 바꾸지 않는다
        std::println("이동 뒤: {}, b 는 {}", a.use_count(), b ? "있음" : "비었음");
    }
    std::println("블록 끝: {}", a.use_count());
    a.reset();
    std::println("main 끝");
}
```

```text
  Frame 1 생성
a 만 있다: 1
b 와 queue: 4
이동 뒤: 4, b 는 비었음
블록 끝: 1
  Frame 1 소멸
main 끝
```

복사할 때마다 수가 오르고, 사라질 때마다 내려가고, 0이 되는 순간 객체가 지워집니다. `use_count()`는 배우거나 디버깅할 때 보는 값입니다. 다른 스레드가 그 사이에 바꿀 수 있으므로 프로그램의 판단에 쓰지는 않습니다.

## 제어 블록

그 수는 `shared_ptr` 안에 있지 않습니다. 여러 `shared_ptr`가 함께 봐야 하므로 힙의 **제어 블록**(control block)에 따로 있습니다.

| 있는 곳 | 든 것 |
| --- | --- |
| `shared_ptr` 자신 | 객체를 가리키는 포인터, 제어 블록을 가리키는 포인터 |
| 제어 블록 (힙) | 주인 수, 지켜보는 수, 지우는 방법 |
| 객체 (힙) | `T` |

```cpp
#include <cstdio>
#include <memory>
#include <print>

int main()
{
    std::println("{} {}", sizeof(std::shared_ptr<int>), sizeof(std::weak_ptr<int>));

    // 삭제자는 타입에 나타나지 않는다. 제어 블록에 들어간다
    std::shared_ptr<std::FILE> f(std::tmpfile(), [](std::FILE* p) {
        std::println("닫는다");
        if (p)
            std::fclose(p);
    });
    std::shared_ptr<std::FILE> empty(nullptr, [](std::FILE* p) {
        std::println("빈 것에도 삭제자가 불린다: {}", p == nullptr);
    });
    std::println("{} {}", f.use_count(), empty.use_count());
}
```

```text
16 16
1 1
빈 것에도 삭제자가 불린다: true
닫는다
```

포인터 두 개라서 16바이트입니다. "지우는 방법"이 제어 블록에 있으므로 삭제자가 달라도 타입은 같은 `shared_ptr<FILE>`입니다. `unique_ptr`와 다른 점이 하나 더 보입니다. 포인터가 `nullptr`이어도 **삭제자가 불립니다.** `fopen`이 실패한 결과를 `fclose`와 함께 넘기면 `fclose(nullptr)`이 되므로, 삭제자 안에서 확인하거나 실패했을 때는 아예 만들지 않습니다.

제어 블록은 맨 포인터에서 `shared_ptr`를 **만들 때** 생깁니다. 그래서 같은 맨 포인터로 두 번 만들면 안 됩니다.

```cpp nocheck
Frame* raw = new Frame(1);
std::shared_ptr<Frame> a(raw);
std::shared_ptr<Frame> b(raw);      // 제어 블록이 둘. 각자 1 을 세다가 두 번 지운다

std::shared_ptr<Frame> c = a;       // 옳다. a 의 제어 블록을 함께 쓴다
```

멤버 함수 안에서 `std::shared_ptr<Frame>(this)`라고 쓰는 것이 같은 실수의 흔한 모습입니다. 자기 자신의 `shared_ptr`가 필요한 클래스는 [`enable_shared_from_this`](#/read/cpp-advanced/sp-from-this)를 씁니다.

## 순환 참조

두 객체가 서로를 `shared_ptr`로 붙들면 수가 0이 되지 않습니다.

```cpp nosan
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Node {
    std::string name;
    std::shared_ptr<Node> child;
    std::shared_ptr<Node> parent;       // 문제의 줄

    explicit Node(std::string n) : name(std::move(n)) {}
    ~Node() { std::println("  {} 소멸", name); }
};

int main()
{
    {
        auto root = std::make_shared<Node>("root");
        auto leaf = std::make_shared<Node>("leaf");
        root->child = leaf;
        leaf->parent = root;
        std::println("root {} leaf {}", root.use_count(), leaf.use_count());
    }
    std::println("블록 끝");
}
```

```text
root 2 leaf 2
블록 끝
```

소멸자가 한 번도 불리지 않았습니다. 블록을 나가며 `root`와 `leaf` 변수가 사라져도 수는 2에서 1이 될 뿐이고, 남은 1은 서로가 쥐고 있습니다. 바깥에서는 닿을 길이 없는 누수입니다. `-fsanitize=address`로 빌드하면 프로그램이 끝날 때 이 누수를 알려 줍니다.

고치는 법은 방향을 정하는 것입니다. **가진다**는 쪽만 `shared_ptr`로, 거슬러 올라가는 쪽은 `std::weak_ptr`로 둡니다.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Node {
    std::string name;
    std::shared_ptr<Node> child;
    std::weak_ptr<Node> parent;         // 지켜보기만 한다

    explicit Node(std::string n) : name(std::move(n)) {}
    ~Node() { std::println("  {} 소멸", name); }
};

int main()
{
    std::shared_ptr<Node> kept;
    {
        auto root = std::make_shared<Node>("root");
        auto leaf = std::make_shared<Node>("leaf");
        root->child = leaf;
        leaf->parent = root;
        std::println("root {} leaf {}", root.use_count(), leaf.use_count());

        // 살아 있으면 잠깐 주인이 되어 쓴다
        if (auto up = leaf->parent.lock())
            std::println("leaf 의 부모는 {}", up->name);
        kept = leaf;
    }
    const bool gone = kept->parent.expired();
    std::println("블록 끝. 부모는 {}", gone ? "사라졌다" : "있다");
    if (auto up = kept->parent.lock())
        std::println("{}", up->name);
    else
        std::println("lock 은 빈 shared_ptr 를 준다");
}
```

```text
root 1 leaf 2
leaf 의 부모는 root
  root 소멸
블록 끝. 부모는 사라졌다
lock 은 빈 shared_ptr 를 준다
  leaf 소멸
```

## weak_ptr

`weak_ptr`는 주인 수를 올리지 않습니다. 객체가 지워지는 것을 막지 못하고, 그 대신 **지워졌는지 알 수 있습니다.** 맨 포인터는 그것을 알 길이 없습니다.

| 멤버 | 하는 일 |
| --- | --- |
| `w.lock()` | 살아 있으면 `shared_ptr`를, 아니면 빈 `shared_ptr`를 준다 |
| `w.expired()` | 이미 지워졌는가 |
| `w.reset()` | 지켜보기를 그만둔다 |

`weak_ptr`에는 `*`와 `->`가 없습니다. 쓰려면 반드시 `lock()`으로 `shared_ptr`를 받아야 하고, 그것을 쥐고 있는 동안에는 객체가 사라지지 않습니다. `expired()`로 확인한 다음 `lock()`을 하면 그 사이에 다른 스레드가 지울 수 있으므로, **`lock()` 하나로 확인과 붙들기를 함께** 합니다.

순환 끊기 말고 흔한 쓰임이 캐시입니다. 쓰는 사람이 있는 동안만 살아 있고, 아무도 쓰지 않으면 저절로 비워집니다.

```cpp
#include <map>
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Font {
    std::string name;

    explicit Font(std::string n) : name(std::move(n))
    {
        std::println("  {} 불러옴", name);
    }
    ~Font() { std::println("  {} 버림", name); }
};

class FontCache {
public:
    std::shared_ptr<Font> get(const std::string& name)
    {
        // 아직 살아 있으면 그것을 준다
        if (auto found = cache_[name].lock())
            return found;
        auto fresh = std::make_shared<Font>(name);
        cache_[name] = fresh;
        return fresh;
    }

private:
    std::map<std::string, std::weak_ptr<Font>> cache_;
};

int main()
{
    FontCache cache;
    {
        auto title = cache.get("nanum");
        auto body = cache.get("nanum");     // 같은 객체를 받는다
        std::println("같은가 {} 주인 {}", title == body, title.use_count());
    }
    std::println("둘 다 놓았다");
    auto again = cache.get("nanum");        // 다시 불러온다
    std::println("주인 {}", again.use_count());
}
```

```text
  nanum 불러옴
같은가 true 주인 2
  nanum 버림
둘 다 놓았다
  nanum 불러옴
주인 1
  nanum 버림
```

콜백이 "부를 때 그 객체가 아직 있는가"를 확인하는 데에도 같은 방법을 씁니다([「캡처의 종류와 수명」](#/read/cpp-syntax/lam-capture)).

## 비용

| 일 | 드는 것 |
| --- | --- |
| 만들기 | 제어 블록 할당. [`make_shared`](#/read/cpp-stl/mem-make)를 쓰면 객체와 한 번에 한다 |
| 복사, 소멸 | 주인 수를 원자적으로 올리고 내린다 |
| 이동 | 포인터 두 개를 옮긴다. 수는 건드리지 않는다 |
| `*p`, `p->` | 맨 포인터와 같다 |

복사가 비쌉니다. 여러 스레드가 같은 객체의 `shared_ptr`를 자주 복사하면 그 수가 든 [캐시 줄](#/read/cpp-syntax/life-alignment)을 코어끼리 주고받느라 느려집니다. 그래서 객체를 쓰기만 하는 함수는 `shared_ptr`를 받지 않고 `const T&`로 받습니다. `shared_ptr`를 값으로 받는 것은 "나도 주인이 되겠다"는 함수뿐입니다. 고르는 기준은 [「함수에 넘기고 돌려주는 법」](#/read/cpp-advanced/sp-passing)에서 자세히 봅니다.

<Note kind="warn">
스레드에 안전한 것은 **주인 수**뿐입니다. 서로 다른 스레드가 각자의 `shared_ptr` 복사본을 만들고 버리는 것은 괜찮습니다. 그러나 가리키는 객체의 내용은 보호되지 않고, **같은 `shared_ptr` 변수 하나**를 한 스레드가 바꾸는 동안 다른 스레드가 읽는 것도 경합입니다. 앞의 것은 [뮤텍스](#/read/cpp-stl/conc-mutex)로, 뒤의 것은 `std::atomic<std::shared_ptr<T>>`(C++20)로 막습니다.
</Note>

`shared_ptr`는 "누가 지울지 정하기 귀찮을 때" 쓰는 것이 아닙니다. 주인이 하나로 정해지는 구조라면 `unique_ptr`와 참조가 더 싸고, 수명이 코드에 드러납니다. 주인이 정말 여럿인 경우는 여러 스레드나 콜백이 같은 객체를 쓰는데 누가 마지막일지 모를 때, 캐시가 내준 객체, 여러 곳에서 가리키는 그래프의 노드 정도입니다.

## 정리

- `shared_ptr`는 포인터 둘(객체, 제어 블록)이고, 제어 블록의 주인 수가 0이 될 때 객체가 지워진다. 같은 맨 포인터로 두 번 만들지 않는다
- 서로를 `shared_ptr`로 붙들면 영영 지워지지 않는다. 거슬러 올라가는 쪽은 `weak_ptr`로 두고 `lock()`으로 확인하며 쓴다
- 복사는 원자 연산이라 싸지 않고, 안전한 것은 주인 수뿐이다. 쓰기만 하는 함수는 참조로 받는다
