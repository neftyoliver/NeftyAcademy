수를 다루는 타입 둘을 봅니다. `std::complex`는 실행 중에 계산하는 복소수이고, `std::ratio`는 컴파일할 때만 존재하는 분수입니다. 닮은 데는 없지만 둘 다 "단위와 신호를 다루는 코드"에서 만납니다.

## complex

```cpp
#include <complex>
#include <numbers>
#include <print>

using namespace std::complex_literals;      // 1.0i 를 쓰기 위해

int main()
{
    const std::complex<double> z{3.0, 4.0};         // 3 + 4i
    std::println("{} {}", z.real(), z.imag());
    std::println("크기 {} 각도 {:.4f} 크기의 제곱 {}", std::abs(z), std::arg(z),
                 std::norm(z));

    const auto product = z * (1.0 + 2.0i);
    std::println("({}, {})", product.real(), product.imag());

    const auto mirrored = std::conj(z);             // 켤레: 허수부의 부호를 바꾼다
    std::println("({}, {})", mirrored.real(), mirrored.imag());

    // 극형식: 크기 2, 각도 90도
    const auto up = std::polar(2.0, std::numbers::pi / 2);
    std::println("({:.3f}, {:.3f})", up.real(), up.imag());

    // 음수의 제곱근도 된다
    const auto root = std::sqrt(std::complex<double>{-4.0, 0.0});
    std::println("({}, {})", root.real(), root.imag());
    std::println("{} {}", sizeof(std::complex<float>),
                 sizeof(std::complex<double>));
}
```

```text
3 4
크기 5 각도 0.9273 크기의 제곱 25
(-5, 10)
(3, -4)
(0.000, 2.000)
(0, 2)
8 16
```

`std::complex<double>`은 `double` 둘이 전부입니다. 메모리에 실수부, 허수부 순서로 놓인다는 것을 표준이 보장하므로, 복소수 배열을 `double` 배열로 받는 C 라이브러리(FFT 라이브러리 등)에 그대로 넘길 수 있습니다. `std::abs`는 제곱근을 구하므로, 크기를 **견주기만** 할 때는 `std::norm`(제곱근 없이 제곱의 합)이 쌉니다.

GCC 14에는 `complex`를 `std::println`에 바로 넣는 서식이 없습니다. 위처럼 `real()`과 `imag()`를 따로 찍거나, `std::cout << z`를 씁니다(`(3,4)`로 찍힙니다).

## 어디에 쓰나

복소수를 곱하면 **크기는 곱해지고 각도는 더해집니다.** 이 성질 하나로 회전과 교류 회로와 주파수 분석이 같은 연산이 됩니다.

```cpp
#include <complex>
#include <cstddef>
#include <numbers>
#include <print>
#include <vector>

using namespace std::complex_literals;
using std::numbers::pi;

int main()
{
    // 1. 회전: 점 (1, 0) 을 45도 돌린다
    const std::complex<double> point{1.0, 0.0};
    const auto turned = point * std::polar(1.0, pi / 4);
    std::println("({:.4f}, {:.4f})", turned.real(), turned.imag());

    // 2. RC 저역 통과 필터: 1kΩ, 1µF, 159.155Hz 에서의 응답
    const double r = 1000.0;
    const double c = 1e-6;
    const double omega = 2 * pi * 159.155;
    const std::complex<double> zc = 1.0 / (1.0i * omega * c);   // 축전기의 임피던스
    const auto h = zc / (r + zc);                               // 전압 나눔
    std::println("크기 {:.3f} 위상 {:.1f}도", std::abs(h), std::arg(h) * 180 / pi);

    // 3. 이산 푸리에 변환: 8개 표본에 든 주파수 성분의 크기
    std::vector<double> samples(8);
    for (std::size_t n = 0; n < samples.size(); ++n)
        samples[n] = std::cos(2 * pi * static_cast<double>(n) / 8.0);
    for (int k = 0; k < 4; ++k) {
        std::complex<double> sum{};
        for (std::size_t n = 0; n < samples.size(); ++n) {
            const double angle = -2 * pi * k * static_cast<double>(n) / 8.0;
            sum += samples[n] * std::polar(1.0, angle);
        }
        std::println("k={} 크기 {:.3f}", k, std::abs(sum));
    }
}
```

```text
(0.7071, 0.7071)
크기 0.707 위상 -45.0도
k=0 크기 0.000
k=1 크기 4.000
k=2 크기 0.000
k=3 크기 0.000
```

- **회전**: 2차원 좌표를 복소수 하나로 보고 `polar(1, 각도)`를 곱하면 회전입니다. 사인과 코사인으로 2×2 행렬을 쓰는 것과 같은 계산입니다
- **필터**: 저항 1kΩ과 축전기 1µF의 차단 주파수는 1/(2πRC) ≈ 159Hz입니다. 그 주파수에서 출력이 0.707배(−3dB)로 줄고 45도 늦어진다는 교과서의 값이 임피던스를 복소수로 넣고 나눗셈 한 번을 하면 나옵니다
- **DFT**: 한 주기짜리 코사인 표본 8개를 넣었더니 `k=1`에만 값이 나왔습니다. 이 이중 루프가 푸리에 변환의 정의이고, 표본이 많을 때는 같은 답을 빨리 내는 FFT 라이브러리를 씁니다

<Note>
`std::complex<float>`와 `std::complex<double>`은 서로 저절로 바뀌지 않는 방향이 있고(`double`에서 `float`로는 적어야 합니다), 정수 복소수 `std::complex<int>`는 표준이 동작을 정하지 않았습니다. 실수 타입으로만 씁니다.
</Note>

## ratio

`std::ratio<N, D>`는 **타입에 들어 있는 분수**입니다. 객체를 만들지 않고, 값은 `::num`과 `::den`이라는 컴파일 시간 상수로 꺼냅니다.

```cpp
#include <chrono>
#include <cstdint>
#include <print>
#include <ratio>

int main()
{
    // 저절로 약분된다
    using three_quarters = std::ratio<6, 8>;
    std::println("{}/{}", three_quarters::num, three_quarters::den);

    // 타입끼리 계산한다. 결과도 타입이다
    using sum = std::ratio_add<std::ratio<1, 3>, std::ratio<1, 6>>;
    std::println("{}/{}", sum::num, sum::den);
    std::println("{}", std::ratio_less<std::ratio<1, 3>, std::ratio<1, 2>>::value);

    // SI 접두어가 이름으로 있다
    std::println("{}/{} {}/{}", std::milli::num, std::milli::den, std::kilo::num,
                 std::kilo::den);

    // 115200 보드의 비트 하나를 눈금으로 하는 기간
    using bit_time = std::chrono::duration<std::int64_t, std::ratio<1, 115200>>;
    const bit_time one_byte{10};        // 시작 1 + 자료 8 + 정지 1
    using std::chrono::microseconds;
    std::println("{}", std::chrono::duration_cast<microseconds>(one_byte));
    std::println("{}", bit_time{115200} == std::chrono::seconds{1});
}
```

```text
3/4
1/2
true
1/1000 1000/1
86us
true
```

`ratio` 혼자 쓰이는 일은 드뭅니다. 쓰임새는 [`std::chrono::duration`](#/read/cpp-stl/chr-duration)의 둘째 인자처럼 <strong>"이 수의 1은 기준 단위의 몇 분의 몇인가"</strong>를 타입에 적는 것입니다. `milliseconds`가 `duration<int64_t, std::milli>`이고, 단위가 다른 두 기간을 더할 때 컴파일러가 두 `ratio`의 공통 단위를 계산합니다. 실행 시간에는 정수 곱셈 하나만 남습니다.

같은 방법으로 길이, 전압, 각도 같은 내 단위 타입을 만들 수 있습니다. `Quantity<Rep, Ratio, Tag>` 꼴의 템플릿에 덧셈과 변환을 [연산자로](#/read/cpp-syntax/op-arith) 주면, 밀리볼트와 볼트를 섞어 더하는 실수를 컴파일러가 잡습니다. 표준에 단위 라이브러리를 넣자는 제안은 있지만 아직 들어오지 않았고, 지금은 직접 만들거나 mp-units 같은 라이브러리를 씁니다.

`ratio`의 분자와 분모는 `std::intmax_t`입니다. 계산하다 넘치면 실행 중에 틀리는 것이 아니라 **컴파일 오류**가 납니다.

## 정리

- `std::complex`는 실수 둘이고, 곱하면 크기가 곱해지고 각도가 더해진다. 회전, 교류 회로의 임피던스, 푸리에 변환이 이 곱셈으로 쓰인다
- 크기만 견줄 때는 제곱근이 없는 `std::norm`을 쓴다. GCC 14에는 `complex`의 `std::format` 서식이 없다
- `std::ratio`는 타입에 든 분수다. `duration`처럼 단위를 타입으로 나타내는 데 쓰이고, 계산은 모두 컴파일할 때 끝난다
