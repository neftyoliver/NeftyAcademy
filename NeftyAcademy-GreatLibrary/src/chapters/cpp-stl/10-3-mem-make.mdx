스마트 포인터는 `new`로 얻은 포인터를 받아서도 만들 수 있지만, 지금까지의 예제는 모두 `std::make_unique`와 `std::make_shared`를 썼습니다. 그 까닭과, 두 함수가 안에서 하는 일을 봅니다.

## new를 쓰지 않는 까닭

| `std::unique_ptr<Sensor> p(new Sensor(4));` | `auto p = std::make_unique<Sensor>(4);` |
| --- | --- |
| 타입을 두 번 적는다 | 한 번 적는다 |
| 맨 포인터가 잠깐 존재한다 | 처음부터 주인이 있다 |
| `new`를 찾으면 살펴볼 곳이 나온다 | 코드에 `new`와 `delete`가 없다 |

둘째 줄이 핵심입니다. `new`가 돌려준 맨 포인터가 주인에게 건네지기 전에 무슨 일이 생기면 그 객체는 샙니다. C++14까지는 `f(std::unique_ptr<A>(new A), std::unique_ptr<B>(new B))`에서 `new A`, `new B`, 두 생성자가 뒤섞인 순서로 실행될 수 있었고, `new B`가 예외를 던지면 `A`가 샜습니다. C++17이 인자 하나의 계산을 끝낸 뒤에 다음 인자로 가도록 고쳤지만, [같은 포인터로 주인을 둘 만드는 실수](#/read/cpp-stl/mem-unique)는 여전히 `new`를 직접 쓸 때만 생깁니다.

인자는 생성자로 그대로 [전달](#/read/cpp-advanced/mv-forwarding)됩니다. 이때 **괄호**로 초기화한다는 점을 기억해 둡니다.

```cpp
#include <initializer_list>
#include <memory>
#include <print>
#include <string>
#include <vector>

struct Point {
    int x;
    int y;
};

int main()
{
    // vector<int>(3, 7) 과 같다. 7 이 세 개
    auto v = std::make_unique<std::vector<int>>(3, 7);
    std::println("{} {}", v->size(), v->front());

    // 원소 3 과 7 을 원하면 목록임을 밝힌다
    auto w = std::make_unique<std::vector<int>>(std::initializer_list<int>{3, 7});
    std::println("{} {}", w->size(), w->front());

    // 생성자가 없는 구조체도 C++20 부터 된다
    auto p = std::make_unique<Point>(3, 4);
    std::println("{} {}", p->x, p->y);

    auto s = std::make_shared<std::string>(3, 'x');
    std::println("{}", *s);
}
```

```text
3 7
2 3
3 4
xxx
```

`make_` 함수를 쓸 수 없는 경우가 둘 있습니다. [삭제자](#/read/cpp-stl/mem-unique)를 줄 때는 생성자에 포인터와 함께 넘겨야 하고, 생성자가 `private`인 클래스는 `make_unique`가 그 생성자를 부를 수 없습니다. 뒤의 경우에는 클래스 안의 정적 함수에서 `std::unique_ptr<T>(new T(...))`로 만들어 돌려줍니다.

## make_shared: 할당 한 번

[`shared_ptr`](#/read/cpp-stl/mem-shared)에는 객체 말고 제어 블록이 필요합니다. `shared_ptr<T>(new T)`는 둘을 따로 할당하고, `make_shared<T>()`는 **한 덩어리**로 할당합니다. [전역 `operator new`를 바꿔](#/read/cpp-stl/str-string) 세어 봅니다.

```cpp
#include <cstdlib>
#include <memory>
#include <new>
#include <print>

static int allocations = 0;
static std::size_t bytes = 0;
void* operator new(std::size_t n)
{
    ++allocations;
    bytes += n;
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

struct Image {
    char pixels[1000];
};

template <typename F>
void measure(const char* label, F make)
{
    allocations = 0;
    bytes = 0;
    {
        auto p = make();
    }
    std::println("{:22} 할당 {}번 {}바이트", label, allocations, bytes);
}

int main()
{
    measure("make_unique", [] { return std::make_unique<Image>(); });
    measure("make_shared", [] { return std::make_shared<Image>(); });
    measure("shared_ptr(new Image)", [] {
        return std::shared_ptr<Image>(new Image);
    });
}
```

```text
make_unique            할당 1번 1000바이트
make_shared            할당 1번 1016바이트
shared_ptr(new Image)  할당 2번 1024바이트
```

GCC 14에서 제어 블록은 `make_shared`일 때 16바이트, 따로 만들 때 24바이트입니다. 바이트보다 **횟수**가 중요합니다. `malloc` 한 번이 줄고, 객체와 주인 수가 메모리에서 붙어 있어 캐시에도 좋습니다. 작은 객체를 많이 만들수록 차이가 큽니다.

## 한 덩어리의 뒷면

한 덩어리라서 생기는 일이 하나 있습니다. 제어 블록은 [`weak_ptr`](#/read/cpp-stl/mem-shared)가 하나라도 남아 있으면 살아 있어야 합니다. 객체와 제어 블록이 한 덩어리이면, 주인이 모두 사라져 소멸자가 불린 뒤에도 **메모리는 돌려주지 못합니다.**

```cpp
#include <cstdio>
#include <cstdlib>
#include <memory>
#include <new>

void* operator new(std::size_t n)
{
    if (void* p = std::malloc(n))
        return p;
    throw std::bad_alloc{};
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t n) noexcept
{
    // 큰 덩어리가 돌아올 때만 알린다
    if (n >= 1000)
        std::printf("  %zu바이트 반환\n", n);
    std::free(p);
}

struct Image {
    char pixels[1000];

    ~Image() { std::puts("  ~Image"); }
};

int main()
{
    std::puts("make_shared");
    std::weak_ptr<Image> watcher;
    {
        auto owner = std::make_shared<Image>();
        watcher = owner;
    }
    std::puts("주인이 사라졌다");
    watcher.reset();
    std::puts("지켜보던 것도 사라졌다");

    std::puts("shared_ptr(new Image)");
    {
        std::shared_ptr<Image> owner(new Image);
        watcher = owner;
    }
    std::puts("주인이 사라졌다");
    watcher.reset();
    std::puts("지켜보던 것도 사라졌다");
}
```

```text
make_shared
  ~Image
주인이 사라졌다
  1016바이트 반환
지켜보던 것도 사라졌다
shared_ptr(new Image)
  ~Image
  1000바이트 반환
주인이 사라졌다
지켜보던 것도 사라졌다
```

소멸자는 두 경우 모두 주인이 사라질 때 불립니다. 다른 것은 메모리입니다. `make_shared` 쪽은 `watcher`까지 사라진 뒤에야 1016바이트가 돌아옵니다. 객체가 수 MB짜리 버퍼를 **멤버 배열로** 품고 있고 `weak_ptr`가 캐시에 오래 남는 구조라면, 이 경우에 한해 `shared_ptr<T>(new T)`가 낫습니다. 버퍼를 `std::vector` 멤버로 가진 객체는 상관없습니다. 소멸자가 벡터의 메모리를 돌려주고, 남는 것은 껍데기 수십 바이트입니다.

## 배열과 for_overwrite

`make_unique<T[]>(n)`은 원소를 **값 초기화**합니다. `int`나 `char`라면 0으로 채웁니다. 곧바로 다른 내용으로 덮어쓸 버퍼라면 그 채우기는 버리는 일입니다. C++20의 `std::make_unique_for_overwrite`는 채우지 않습니다.

```cpp
#include <chrono>
#include <cstddef>
#include <cstring>
#include <memory>
#include <print>

int main()
{
    using clock = std::chrono::steady_clock;
    using ms = std::chrono::duration<double, std::milli>;
    const std::size_t size = 64 * 1024;     // 받는 버퍼 64KB
    const int rounds = 100'000;
    long sum = 0;

    const auto t0 = clock::now();
    for (int i = 0; i < rounds; ++i) {
        auto buffer = std::make_unique<char[]>(size);
        // 실제로 쓰는 것은 10 바이트
        std::memcpy(buffer.get(), "temp=21.5", 10);
        sum += buffer[5];
    }
    const auto t1 = clock::now();
    for (int i = 0; i < rounds; ++i) {
        auto buffer = std::make_unique_for_overwrite<char[]>(size);
        std::memcpy(buffer.get(), "temp=21.5", 10);
        sum += buffer[5];
    }
    const auto t2 = clock::now();

    std::println("make_unique               {:6.1f} ms", ms(t1 - t0).count());
    std::println("make_unique_for_overwrite {:6.1f} ms", ms(t2 - t1).count());
    std::println("{}", sum);
}
```

```text nocheck
make_unique               113.9 ms
make_unique_for_overwrite   2.6 ms
10000000
```

x86-64 서버에서 GCC 14 `-O2`로 잰 값입니다. 메시지를 받을 때마다 64KB 버퍼를 새로 잡는 코드라면 시간의 대부분이 0을 채우는 데 들어갑니다.

<Note kind="warn">
`for_overwrite`로 얻은 메모리의 내용은 정해져 있지 않습니다. 쓰기 전에 읽으면 [정의되지 않은 동작](#/read/c-basic/ub-what)입니다. 받은 바이트 수만큼만 읽는 코드에서만 씁니다. 그리고 수십 MB짜리를 **한 번** 잡아 전부 채우는 경우에는 이득이 거의 없습니다. 같은 기계에서 64MB를 잡아 전부 채우는 데 두 방법 모두 28ms쯤 걸렸습니다. 그 시간은 운영체제가 페이지를 처음 내줄 때 드는 것이고, 어느 쪽이든 처음 쓰는 순간에 치릅니다.
</Note>

같은 이름의 `std::make_shared_for_overwrite`가 있고, `std::make_shared<int[]>(n)`처럼 `shared_ptr`로 배열을 만드는 것도 C++20부터 됩니다.

## 고르는 표

| 상황 | 쓰는 것 |
| --- | --- |
| 객체 하나, 주인 하나 | `std::make_unique<T>(인자...)` |
| 객체 하나, 주인 여럿 | `std::make_shared<T>(인자...)` |
| 길이가 실행 중에 정해지는 버퍼 | `std::vector<T>`. 포인터 하나 크기여야 하면 `make_unique<T[]>(n)` |
| 곧 덮어쓸 버퍼 | `std::make_unique_for_overwrite<T[]>(n)` |
| 삭제자가 필요하다, 생성자가 `private`이다 | 생성자에 `new`의 결과를 넘긴다 |
| 큰 멤버 배열 + 오래 남는 `weak_ptr` | `std::shared_ptr<T>(new T)` |

## 정리

- `make_unique`와 `make_shared`를 쓰면 맨 포인터가 한순간도 주인 없이 있지 않는다. 인자는 괄호 초기화로 생성자에 전달된다
- `make_shared`는 객체와 제어 블록을 한 번에 할당한다. 그 대신 `weak_ptr`가 남아 있는 동안에는 객체의 메모리도 돌려주지 못한다
- `make_unique<T[]>(n)`은 0으로 채우고 `for_overwrite`는 채우지 않는다. 잦은 버퍼 할당에서 차이가 크다
