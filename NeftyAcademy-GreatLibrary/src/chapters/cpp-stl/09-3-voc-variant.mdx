`std::variant<A, B, C>`는 "A이거나 B이거나 C인 값 하나"입니다. [「C++17」](#/read/cpp-syntax/ver-17)에서 가상 함수 없이 종류에 따라 다르게 동작하는 예를 보았습니다. C의 `union`과 꼬리표를 손으로 맞추던 일을 타입이 대신하고, **꼬리표와 내용이 어긋날 수 없게** 해 줍니다.

## 담고 묻기

```cpp
#include <print>
#include <string>
#include <variant>

int main()
{
    std::variant<int, double, std::string> value = 42;
    std::println("index {}", value.index());
    std::println("int 인가 {}", std::holds_alternative<int>(value));

    // 이제 string 이 들었다. int 는 사라졌다
    value = "hello";
    std::println("index {}", value.index());

    // 맞으면 포인터, 아니면 nullptr
    if (const auto* text = std::get_if<std::string>(&value))
        std::println("string: {}", *text);

    try {
        // 든 것과 다른 타입을 청하면 예외
        std::println("{}", std::get<int>(value));
    } catch (const std::bad_variant_access&) {
        std::println("int 가 들어 있지 않다");
    }

    using Small = std::variant<int, double>;
    using Large = std::variant<char, std::string>;
    std::println("variant<int, double> {}바이트", sizeof(Small));
    std::println("variant<char, string> {}바이트", sizeof(Large));
}
```

```text
index 0
int 인가 true
index 2
string: hello
int 가 들어 있지 않다
variant<int, double> 16바이트
variant<char, string> 40바이트
```

| 하는 일 | 적는 법 | 틀렸을 때 |
| --- | --- | --- |
| 몇째가 들었나 | `v.index()` | |
| 이 타입이 들었나 | `std::holds_alternative<T>(v)` | |
| 꺼내기 | `std::get<T>(v)` | `std::bad_variant_access` 예외 |
| 있으면 꺼내기 | `std::get_if<T>(&v)` | `nullptr` |

크기는 **가장 큰 후보**에 "몇째인가"를 적는 자리가 더해진 것입니다. [`optional`](#/read/cpp-stl/voc-optional)처럼 값을 자기 안에 품고 힙을 쓰지 않습니다.

기본 생성자는 **첫째 후보**를 만듭니다. 첫째 후보에 기본 생성자가 없거나 "아직 아무것도 아님"을 나타내고 싶으면, 맨 앞에 빈 타입 `std::monostate`를 둡니다.

## visit: 든 것에 따라 다르게

`std::get_if`를 줄줄이 쓰는 대신, 후보마다 할 일을 적어 `std::visit`에 넘깁니다. 람다 여럿을 하나로 묶는 작은 도구 `overloaded`와 함께 쓰는 것이 관용구입니다.

```cpp
#include <print>
#include <string>
#include <variant>
#include <vector>

// 람다 여럿을 물려받아, 호출 연산자가 여럿인 객체 하나로 만든다
template <typename... Fs>
struct overloaded : Fs... {
    using Fs::operator()...;
};

struct SetPin {
    int pin;
    bool high;
};
struct Sleep {
    int ms;
};
struct Print {
    std::string text;
};
using Command = std::variant<SetPin, Sleep, Print>;

void run(const Command& command)
{
    const overloaded handlers{
        [](const SetPin& c) { std::println("GPIO{} <- {}", c.pin, c.high); },
        [](const Sleep& c) { std::println("{}ms 쉰다", c.ms); },
        [](const Print& c) { std::println("출력: {}", c.text); },
    };
    std::visit(handlers, command);
}

int main()
{
    const std::vector<Command> script = {
        SetPin{17, true}, Sleep{500}, Print{"done"}, SetPin{17, false},
    };
    for (const auto& command : script)
        run(command);
}
```

```text
GPIO17 <- true
500ms 쉰다
출력: done
GPIO17 <- false
```

`overloaded`는 [가변 인자 템플릿](#/read/cpp-syntax/tpl-variadic) 세 줄입니다. 표준에 아직 없어서 프로젝트마다 한 벌씩 둡니다.

`std::visit`의 값어치는 **빠뜨릴 수 없다**는 데 있습니다. `Command`에 `Beep`을 더하고 `run`을 고치지 않으면, 실행 중에 조용히 지나가는 것이 아니라 컴파일이 멈춥니다. `switch`의 `default:`나 `if`의 사슬은 새 종류를 조용히 삼킵니다. 종류가 늘 때마다 고칠 곳을 컴파일러가 모두 짚어 주는 것, 그것이 `variant`를 쓰는 가장 큰 이유입니다.

## 상태 기계

"지금 어느 상태이고, 상태마다 다른 자료를 든다"는 구조가 `variant`에 그대로 맞습니다.

```cpp
#include <format>
#include <print>
#include <string>
#include <variant>

template <typename... Fs>
struct overloaded : Fs... {
    using Fs::operator()...;
};

struct Disconnected {};
struct Connecting {
    int attempt;            // 연결하는 동안에만 뜻이 있는 자료
};
struct Connected {
    std::string session;    // 연결된 뒤에만 있는 자료
};
using State = std::variant<Disconnected, Connecting, Connected>;

// 타이머가 울릴 때마다: 지금 상태를 받아 다음 상태를 돌려준다
State on_tick(const State& state, bool server_answered)
{
    const overloaded next{
        [](const Disconnected&) -> State { return Connecting{1}; },
        [&](const Connecting& c) -> State {
            if (server_answered)
                return Connected{"s-1024"};
            if (c.attempt >= 3)
                return Disconnected{};      // 세 번 해 보고 포기
            return Connecting{c.attempt + 1};
        },
        [](const Connected& c) -> State { return c; },
    };
    return std::visit(next, state);
}

std::string describe(const State& state)
{
    const overloaded text{
        [](const Disconnected&) { return std::string("끊김"); },
        [](const Connecting& c) { return std::format("연결 중({}번)", c.attempt); },
        [](const Connected& c) { return "연결됨 " + c.session; },
    };
    return std::visit(text, state);
}

int main()
{
    State state = Disconnected{};
    for (bool answered : {false, false, false, false, false, true, false}) {
        state = on_tick(state, answered);
        std::println("{}", describe(state));
    }
}
```

```text
연결 중(1번)
연결 중(2번)
연결 중(3번)
끊김
연결 중(1번)
연결됨 s-1024
연결됨 s-1024
```

`enum`과 멤버 변수 여럿으로 쓰면 "연결되지 않았는데 `session`을 읽는" 코드를 막을 수 없습니다. 여기서는 `session`이 `Connected` 안에만 있으므로, 연결된 상태를 다루는 람다 안에서만 손이 닿습니다. **있을 수 없는 조합을 타입으로 없앤** 것입니다.

## 값과 주의할 것

| | `variant` | 가상 함수 |
| --- | --- | --- |
| 종류의 집합 | 닫혀 있다. 타입에 적은 것이 전부 | 열려 있다. 누구나 자식을 더한다 |
| 저장 | 값으로. 힙 없음 | 대개 힙에 따로 |
| 새 **종류**를 더하면 | `visit`하는 곳을 모두 고친다 (컴파일러가 짚어 준다) | 클래스 하나를 더한다 |
| 새 **동작**을 더하면 | 함수 하나를 더한다 | 모든 자식을 고친다 |

종류가 정해져 있고 동작이 늘어나는 쪽이면 `variant`, 동작이 정해져 있고 종류가 늘어나는 쪽이면 가상 함수입니다. 메시지의 종류, 상태, 설정 값의 타입, 구문 트리의 노드는 대개 앞쪽입니다.

<Note kind="warn">
후보 가운데 하나만 유난히 크면 `variant` 전체가 그 크기가 됩니다. 4KB짜리 버퍼를 든 후보 하나 때문에 모든 메시지가 4KB가 됩니다. 큰 후보는 `std::unique_ptr`로 감싸 넣습니다. 그리고 `variant`의 `vector`를 메시지 큐로 쓰는 작은 기기에서는 `sizeof`를 한 번 찍어 봅니다.
</Note>

## 정리

- `variant`는 후보 가운데 하나를 자기 안에 품고, 무엇이 들었는지를 함께 안다. 틀린 타입으로 꺼내면 예외다
- `std::visit`과 `overloaded`로 후보마다 할 일을 적는다. 후보를 빠뜨리면 컴파일되지 않는다
- 상태마다 다른 자료는 후보 구조체 안에 둔다. 있을 수 없는 조합이 타입에서 사라진다
