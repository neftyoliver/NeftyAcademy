프로그램을 만든다는 건 결국 **CPU가 한 줄씩 따라 할 수 있는 명령의 목록**을 만드는 일입니다. 이 챕터는 그 목록이 어디서 오는지, CPU가 그걸 어떻게 따라가는지를 봅니다.

## 소스에서 실행 파일까지

C 소스 `hello.c`가 실행 파일 `hello`가 되기까지는 네 단계를 거칩니다. 평소에는 `gcc hello.c -o hello` 한 줄이 넷을 한꺼번에 하지만, 옵션으로 단계마다 멈춰 볼 수 있습니다.

<Figure caption="네모를 누르면 그 단계의 명령과 결과가 나옵니다">
  <Pipeline />
</Figure>

| 단계 | 하는 일 | 결과 |
| --- | --- | --- |
| 전처리 | `#include` 파일 내용을 끼워 넣고, `#define`을 바꿔 넣고, `#if`로 고른다 | `.i` (여전히 C) |
| 컴파일 | C를 그 CPU의 어셈블리로 옮긴다. 문법 오류는 여기서 난다 | `.s` |
| 어셈블 | 어셈블리를 기계어로. 남의 함수 자리는 빈칸(심볼)으로 둔다 | `.o` |
| 링크 | `.o`들과 라이브러리를 이어 빈칸을 채운다. "undefined reference"는 여기서 난다 | 실행 파일 |

<Note kind="tip">
오류 메시지가 **어느 단계에서** 났는지 먼저 보면 원인 찾기가 반으로 줄어듭니다. 문법 오류는 컴파일, "undefined reference"는 링크입니다.
</Note>

## 실행 파일이 메모리에 올라가면

실행 파일을 실행하면 운영체제의 <Term tip="실행 파일을 읽어 메모리에 펼치고 시작 주소로 뛰게 하는 부분">로더</Term>가 파일을 메모리에 펼치고, 필요한 공유 라이브러리(`libc.so` 등)를 붙인 뒤, 시작 지점으로 CPU를 보냅니다. 그다음부터는 CPU 혼자 갑니다.

## CPU는 한 걸음씩 간다

CPU 안에는 <strong>프로그램 카운터(PC)</strong>라는 칸이 있어서 "다음에 실행할 명령이 몇 번째인지"를 들고 있습니다. CPU가 하는 일은 이것뿐입니다.

1. PC가 가리키는 명령을 읽는다 (fetch)
2. 무슨 명령인지 푼다 (decode)
3. 실행하고, PC를 다음 칸으로 옮긴다 (execute)

반복문과 `if`는 **PC를 다음 칸이 아닌 다른 번호로 바꾸는 명령**(점프)으로 만들어집니다. 아래는 3 + 2 + 1을 구하는 작은 프로그램입니다. 한 걸음씩 눌러 보세요.

<Figure caption="jnz는 'r1이 0이 아니면(not zero) 점프'. 이 한 줄이 반복문을 만듭니다">
  <PcStepper />

C로 쓰면 이렇게 생긴 코드입니다.

```c
int sum = 0;
for (int n = 3; n != 0; n--)
    sum += n;
```

## 정리

- 소스는 전처리 → 컴파일 → 어셈블 → 링크를 거쳐 실행 파일이 된다
- 실행 파일 안에는 CPU 명령이 줄지어 있고, CPU는 PC를 따라 하나씩 실행한다
- 반복과 분기는 PC를 바꾸는 점프로 만들어진다
