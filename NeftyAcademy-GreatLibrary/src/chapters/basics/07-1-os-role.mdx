[「마이크로컨트롤러와 라즈베리파이」](#/read/basics/modern-mcu-sbc)에서 마이크로컨트롤러에는 OS가 없고 내 프로그램 하나가 칩 전체를 차지한다고 했습니다. PC와 스마트폰에서는 프로그램 수십 개가 한 컴퓨터를 함께 씁니다. 그 사이에서 교통정리를 하는 것이 OS(운영체제)입니다. 이 쪽은 OS가 맡는 일을 셋으로 나눠 보고, 프로그램이 OS에 부탁하는 순간을 직접 엿봅니다.

## 세 가지 일

| 일 | 뜻 | 예 |
| --- | --- | --- |
| 감추기 | 하드웨어의 복잡함을 쉬운 개념 뒤로 감춘다 | 디스크의 블록 대신 "파일", CPU와 램 대신 "프로세스" |
| 나누기 | 한정된 자원을 여러 프로그램에 공평하게 나눈다 | CPU 시간, 램, 화면, 네트워크 |
| 지키기 | 프로그램끼리, 사용자끼리 서로 침범하지 못하게 한다 | 남의 메모리 읽기 금지, 남의 파일 권한 |

**감추기.** 프로그램은 "note.txt라는 파일에 '안녕'을 써 줘"라고만 합니다. 그 파일이 SSD의 몇 번 블록에 있는지, SSD 컨트롤러에 어떤 명령을 보내야 하는지, 디스크가 SATA인지 NVMe인지는 OS가 알아서 합니다. [「버스와 입출력」](#/read/basics/arch-bus-io)에서 본 주소, 인터럽트, DMA를 프로그램이 직접 다룰 일이 없습니다.

**나누기.** CPU가 둘인데 프로그램이 백 개면 OS가 아주 짧게 번갈아 맡깁니다. 램은 프로그램마다 따로 떼어 줍니다. 이 두 가지는 [「프로세스와 메모리 관리」](#/read/basics/os-process-memory)에서 자세히 봅니다.

**지키기.** 브라우저가 망가져도 메모장의 글은 멀쩡해야 하고, 다른 사용자의 파일은 함부로 읽을 수 없어야 합니다. [「리눅스 명령어와 POSIX」](#/read/basics/commands)에서 본 파일 권한이 여기에 속합니다.

## 커널 모드와 사용자 모드

지키기가 가능한 것은 CPU에 **모드**가 있기 때문입니다. CPU는 두 가지 모드 가운데 하나로 실행됩니다.

| | 커널 모드 | 사용자 모드 |
| --- | --- | --- |
| 누가 | OS의 커널 | 보통의 프로그램 |
| 할 수 있는 일 | 모든 명령, 모든 메모리, 장치 직접 다루기 | 계산과 자기 메모리 읽고 쓰기만 |
| 금지된 일을 하면 | | CPU가 멈추고 커널에 알린다. 보통 그 프로그램이 끝난다 |

보통의 프로그램은 사용자 모드라서 장치를 직접 만지거나 남의 메모리를 볼 수 없습니다. 시도하면 CPU가 그 순간 커널을 불러내고, 커널은 그 프로그램을 끝냅니다. C 프로그램이 잘못된 포인터를 썼을 때 보는 `Segmentation fault`가 이것입니다. [「커널의 종류」](#/read/basics/kernels)의 그림에서 커널 공간과 사용자 공간을 나눈 선이 이 모드의 경계입니다.

## 시스템 콜

그러면 사용자 모드의 프로그램은 파일을 어떻게 쓸까요? 커널에 **부탁**합니다. 정해진 번호의 부탁을 레지스터에 적고, 특별한 명령(x86-64의 `syscall`, ARM64의 `svc`)을 실행하면 CPU가 커널 모드로 바뀌어 커널의 코드가 그 부탁을 처리하고, 결과를 돌려주며 다시 사용자 모드로 돌아옵니다. 이것이 **시스템 콜**입니다.

C의 `fopen`, `fputs`, `printf`는 C 라이브러리(glibc)의 함수이고, 그 안에서 결국 시스템 콜을 부릅니다. 아래 프로그램으로 확인해 봅니다.

```c
#include <stdio.h>

int main(void)
{
    FILE *f = fopen("note.txt", "w");
    if (f == NULL)
        return 1;
    fputs("안녕\n", f);
    fclose(f);
    printf("다 썼다\n");
    return 0;
}
```

```text
다 썼다
```

리눅스의 `strace`는 프로그램이 부르는 시스템 콜을 하나하나 보여 주는 도구입니다. 파일과 관계있는 것만 골라 보면 이렇습니다.

```text nocheck
$ strace -e trace=openat,write,close ./h
openat(AT_FDCWD, "note.txt", O_WRONLY|O_CREAT|O_TRUNC, 0666) = 3
write(3, "\354\225\210\353\205\225\n", 7) = 7
close(3)                                = 0
write(1, "\353\213\244 \354\215\274\353\213\244\n", 11) = 11
+++ exited with 0 +++
```

- `fopen`은 `openat` 시스템 콜이 됐습니다. 커널은 파일을 열고 **3**이라는 번호(파일 기술자)를 돌려줍니다. 앞으로 이 파일은 번호 3으로 부릅니다
- `fputs`는 `write(3, …, 7)`이 됐습니다. "안녕\n"은 [UTF-8](#/read/basics/std-text)로 7바이트입니다(한글 두 글자 6바이트 + 줄바꿈 1바이트)
- `printf`는 `write(1, …)`이 됐습니다. 1번은 처음부터 열려 있는 표준 출력, 곧 화면입니다

<Note>
`strace -c`로 전체를 세어 보면 이 작은 프로그램이 시스템 콜을 38번 부릅니다. 대부분은 `main`보다 먼저 일어나는 일입니다. 프로그램 파일을 메모리에 올리고(`execve`, `mmap`), C 라이브러리를 불러오는 준비입니다. [「우리 프로그램이 작동하는 방식」](#/read/basics/code-runs)에서 본 실행 과정이 이 준비입니다.
</Note>

<Note kind="tip">
시스템 콜은 일반 함수 호출보다 훨씬 비쌉니다. CPU 모드를 바꾸고 커널이 확인 작업을 하기 때문입니다. 그래서 C 라이브러리는 `fputs`를 부를 때마다 바로 `write`를 하지 않고, 내용을 모아 두었다가 한꺼번에 씁니다(버퍼링). 위에서 `fputs`가 `fclose` 때 한 번의 `write`가 된 것도 이 때문입니다.
</Note>

## 정리

- OS는 하드웨어를 파일과 프로세스 같은 개념 뒤로 감추고, CPU와 램을 프로그램들에 나누고, 프로그램끼리 침범하지 못하게 지킨다
- CPU의 커널 모드와 사용자 모드가 지키기의 바탕이고, 사용자 모드의 프로그램이 금지된 일을 하면 커널이 그 프로그램을 끝낸다
- 프로그램은 시스템 콜로 커널에 부탁하며, `strace`로 보면 `fopen`, `fputs`, `printf`가 `openat`, `write` 같은 시스템 콜이 된다
