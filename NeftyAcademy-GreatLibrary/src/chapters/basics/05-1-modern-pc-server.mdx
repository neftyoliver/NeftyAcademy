지금 쓰는 데스크톱과 노트북, 그리고 웹사이트와 앱을 돌리는 데이터센터의 서버는 대부분 같은 x86-64 CPU 집안입니다([「8086에서 x86-64까지」](#/read/basics/history-x86)). 같은 설계로 만들었는데도 생김새와 쓰는 법은 꽤 다릅니다. 이 쪽은 그 차이를 보고, 서버를 잘게 나눠 쓰는 가상 기계와 클라우드를 봅니다.

## PC의 부품

데스크톱 PC를 열면 이런 부품이 보입니다. 각각 앞 장에서 본 것들입니다.

| 부품 | 하는 일 | 앞에서 본 곳 |
| --- | --- | --- |
| CPU | 명령을 실행한다 | [「CPU와 레지스터」](#/read/basics/arch-cpu) |
| 램 | 실행 중인 프로그램과 자료를 담는다 | [「메모리와 저장 장치의 계층」](#/read/basics/arch-memory) |
| SSD, HDD | 전원을 꺼도 남는 파일 | 같은 쪽 |
| 메인보드 | 부품을 버스로 잇는 기판 | [「버스와 입출력」](#/read/basics/arch-bus-io) |
| 그래픽 카드(GPU) | 화면을 그리고, 같은 계산을 대량으로 나란히 한다 | |
| 전원 공급 장치 | 콘센트의 교류를 부품이 쓰는 직류로 바꾼다 | |

노트북은 같은 부품을 작게, 전기를 덜 쓰게 만들어 한 판에 붙인 것입니다. 그래서 램이나 CPU를 나중에 바꿀 수 없는 경우가 많습니다. 데스크톱은 [「하드웨어 규격들」](#/read/basics/std-hardware)의 ATX 같은 규격 덕분에 부품을 하나씩 골라 바꿀 수 있습니다.

## 서버는 무엇이 다른가

서버는 다른 컴퓨터의 요청에 답하는 일을 하는 컴퓨터입니다. 웹페이지를 보내 주고, 게임의 접속을 받고, 파일을 지켜 줍니다. 하는 일이 다르니 고르는 기준이 다릅니다.

| | PC | 서버 |
| --- | --- | --- |
| 쉬는 시간 | 끄고 켠다 | 몇 년씩 켜 둔다 |
| CPU | 코어 수 개~20여 개, 한 코어가 빠른 것 | 코어 수십~백수십 개, CPU를 두 개 꽂기도 한다 |
| 램 | 수~수십 GB | 수백 GB~수 TB. 오류를 고치는 ECC 램 |
| 화면, 키보드 | 붙어 있다 | 없다. 네트워크로 원격 접속한다 |
| 생김새 | 책상 위 상자 | 랙(선반)에 끼우는 납작한 상자 |
| OS | 윈도우, macOS가 많다 | 리눅스가 대부분 |

몇 가지는 설명이 필요합니다.

- **ECC 램.** 램의 비트는 아주 드물게 우주선(cosmic ray)이나 전기 잡음 때문에 저절로 뒤집힙니다. 집 PC에서는 몇 년에 한 번 이상한 일이 생기는 정도지만, 램이 수 TB이고 몇 년씩 켜 두는 서버에서는 흔한 일이 됩니다. ECC 램은 여분의 비트를 더 저장해 두고, 비트 하나가 뒤집히면 스스로 고칩니다
- **원격 관리.** 서버에는 본체와 별도로 도는 작은 관리용 컴퓨터(BMC)가 들어 있어서, OS가 멈춰도 네트워크로 전원을 껐다 켜고 화면을 볼 수 있습니다
- **리눅스.** 공짜이고, 화면 없이 명령만으로 모든 것을 다룰 수 있고, 몇 년씩 재부팅 없이 돌리기 좋아서 서버 OS의 대부분을 차지합니다. [「OS가 맡는 일」](#/read/basics/os-role)과 [「커널의 종류」](#/read/basics/kernels)에서 이어집니다

<Note>
PC와 서버의 경계는 부품이 아니라 쓰임입니다. 집에 있는 낡은 노트북에 리눅스를 깔고 마인크래프트 서버를 돌리면 그 노트북이 서버입니다. 라즈베리파이도 작은 웹 서버나 파일 서버로 자주 씁니다.
</Note>

## 가상 기계

서버 한 대의 CPU 코어가 100개이고 램이 1TB라도, 웹사이트 하나는 그중 일부만 씁니다. 그래서 **한 대의 실제 컴퓨터를 여러 대의 가짜 컴퓨터로 나눠** 씁니다. 이 가짜 컴퓨터를 가상 기계(VM)라고 하고, 나눠 주는 프로그램을 하이퍼바이저라고 합니다.

가상 기계 안의 OS는 자기가 진짜 컴퓨터에서 도는 줄 압니다. CPU 코어 두 개, 램 8GB, 디스크 하나를 가진 컴퓨터처럼 보이지만, 실제로는 하이퍼바이저가 큰 서버의 자원을 잘라 보여 주는 것입니다. 지금의 x86-64와 ARM64 CPU에는 이 일을 빠르게 하는 회로가 들어 있어서, 가상 기계 안의 프로그램도 거의 제 속도로 돕니다.

이 책의 예제를 검사하는 기계가 바로 이런 가상 기계입니다. [「버스와 입출력」](#/read/basics/arch-bus-io)에서 `lspci`가 실제 부품 대신 `Virtio` 장치를 보여 준 것이 그 흔적입니다. 디스크와 네트워크 카드가 하이퍼바이저가 흉내 내는 가상 장치입니다.

```sh
nproc       # 이 기계가 쓸 수 있는 CPU 코어 수
free -g     # 램 크기(GB 단위)
```

```text
2
               total        used        free      shared  buff/cache   available
Mem:               7           0           6           0           0           7
```

코어 두 개와 램 약 7GiB입니다. [「메모리와 저장 장치의 계층」](#/read/basics/arch-memory)에서 `lscpu`가 L3 캐시를 504MiB라고 했던 것도, 이 가상 기계가 받은 진짜 칩의 일부가 아니라 하이퍼바이저가 알려 준 값이었습니다.

## 클라우드

가상 기계를 시간 단위로 빌려주는 사업이 클라우드입니다. 아마존(AWS), 마이크로소프트(Azure), 구글(Google Cloud) 같은 회사가 전 세계에 데이터센터를 짓고 서버 수백만 대를 들여놓은 뒤, 몇 분 만에 원하는 크기의 가상 기계를 빌려줍니다. 필요 없어지면 지우고, 쓴 만큼만 돈을 냅니다.

"클라우드에 저장했다"는 말은 결국 **남의 데이터센터에 있는 서버의 디스크에 저장했다**는 뜻입니다. 구름 속에 있는 것이 아니라, 어딘가의 건물 안 랙에 꽂힌 SSD에 있습니다.

<Note kind="tip">
가상 기계는 내 PC에서도 돌릴 수 있습니다. 윈도우에서 리눅스를 써 보고 싶다면 VirtualBox 같은 프로그램으로 가상 기계를 만들어 [「루분투 설치」](#/read/basics/lubuntu)를 연습해 볼 수 있고, 망가져도 지우고 다시 만들면 됩니다. 윈도우의 WSL도 가벼운 가상 기계 위에서 리눅스를 돌립니다.
</Note>

## 정리

- PC와 서버는 같은 CPU 집안으로 만들지만, 서버는 오래 켜 두고 원격으로 다루기 위해 코어와 램이 많고 ECC 램과 관리용 칩을 쓴다
- 하이퍼바이저는 실제 컴퓨터 한 대를 여러 가상 기계로 나누고, 가상 기계 안의 OS는 진짜 컴퓨터에서 도는 줄 안다
- 클라우드는 데이터센터의 가상 기계를 시간 단위로 빌려주는 사업이고, 이 책의 예제도 그런 가상 기계에서 검사했다
