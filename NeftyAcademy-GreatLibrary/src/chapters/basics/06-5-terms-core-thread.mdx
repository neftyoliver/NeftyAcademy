CPU 광고에는 "8코어 16스레드" 같은 말이 붙습니다. [「진공관에서 트랜지스터, 집적회로로」](#/read/basics/history-transistor)에서 2000년대 중반에 클럭이 벽에 부딪힌 뒤로 CPU가 코어 수를 늘리는 쪽으로 방향을 바꿨다고 했습니다. 이 쪽은 코어와 스레드가 무엇을 세는 숫자인지, 그리고 코어를 늘리면 정말 빨라지는지를 봅니다.

## 코어

코어는 **명령을 실행하는 CPU 한 벌**입니다. [「CPU와 레지스터」](#/read/basics/arch-cpu)에서 본 연산 장치, 제어 장치, 레지스터를 모두 갖춘 덩어리입니다. 4코어 CPU는 칩 하나에 이것이 네 벌 들어 있어서, 서로 다른 명령 흐름 네 개를 **정말로 동시에** 실행합니다. L1, L2 캐시는 보통 코어마다 따로, L3 캐시는 여러 코어가 함께 씁니다.

## 하드웨어 스레드

코어 하나는 명령을 실행하다가 램에서 값이 오기를 기다리느라 노는 시간이 꽤 됩니다([「메모리와 저장 장치의 계층」](#/read/basics/arch-memory)). 그 빈틈을 쓰려고 **코어 하나가 명령 흐름 두 개를 번갈아 받도록** 만든 것이 하드웨어 스레드입니다. 인텔은 하이퍼스레딩, AMD는 SMT라고 부릅니다.

코어 하나에 레지스터와 프로그램 카운터를 두 벌 두고, 연산 장치는 함께 씁니다. 한쪽 흐름이 기다리는 동안 다른 쪽 흐름의 명령을 실행합니다. OS에게는 코어 하나가 CPU 두 개처럼 보입니다.

| 광고 문구 | 실제 코어 | OS가 보는 CPU 수 |
| --- | --- | --- |
| 4코어 4스레드 | 4 | 4 |
| 8코어 16스레드 | 8 | 16 |
| 6P + 8E코어 20스레드 | 14 (큰 코어 6, 작은 코어 8) | 20 |

마지막 줄은 [「스마트폰과 ARM」](#/read/basics/modern-arm-mobile)에서 본 큰 코어와 작은 코어를 섞은 칩입니다. 큰 코어만 하드웨어 스레드를 두 개씩 가져서 6 × 2 + 8 = 20입니다. 하드웨어 스레드 두 개는 연산 장치를 나눠 쓰므로 코어 두 개만큼 빠르지는 않습니다. 하는 일에 따라 다르지만 보통 수십 % 더 빨라지는 정도입니다.

리눅스에서는 `lscpu`로 셀 수 있습니다. 이 책의 검사 기계는 이렇습니다.

```text nocheck
CPU(s):                                  2
Thread(s) per core:                      1
Core(s) per socket:                      2
Socket(s):                               1
```

코어 2개에 코어당 스레드 1개, CPU 소켓 1개라 OS가 보는 CPU는 2개입니다. 가상 기계라서 하이퍼바이저가 나눠 준 몫입니다([「PC와 서버」](#/read/basics/modern-pc-server)).

## 소프트웨어 스레드

"스레드"라는 말은 프로그래밍에서 다른 뜻으로도 씁니다. 프로그램 안에서 동시에 진행되는 **명령 흐름 하나**를 스레드라고 부르고, 프로그램은 스레드를 몇 개든 만들 수 있습니다. 브라우저 하나가 스레드를 수십 개 씁니다.

OS는 이 소프트웨어 스레드들을 하드웨어 스레드(OS가 보는 CPU)에 번갈아 올려 실행합니다. CPU가 2개인데 스레드가 100개면, 아주 짧은 시간씩 돌아가며 맡깁니다. 사람에게는 모두 동시에 도는 것처럼 보입니다. 이 번갈아 맡기기는 [「프로세스와 메모리 관리」](#/read/basics/os-process-memory)에서, 스레드를 쓰는 법은 [「스레드의 개념」](#/read/basics/threads)에서 봅니다.

## 늘린 만큼 빨라질까

1부터 4억까지 1/i를 더하는 일을 스레드 1개, 2개, 4개로 나눠 맡겨 봅니다. C11부터 표준에 든 `threads.h`를 썼습니다.

```c
#include <stdio.h>
#include <threads.h>
#include <time.h>

enum { WORK = 400000000 };

typedef struct {
    long from, to;
    double sum;
} Part;

// 맡은 구간의 1/i를 더한다
static int work(void *arg)
{
    Part *p = arg;
    double s = 0.0;
    for (long i = p->from; i < p->to; i++)
        s += 1.0 / (double)i;
    p->sum = s;
    return 0;
}

static double run(int n)
{
    thrd_t t[8];
    Part part[8];
    struct timespec a, b;
    timespec_get(&a, TIME_UTC);
    for (int k = 0; k < n; k++) {
        part[k].from = 1 + (long)WORK / n * k;
        part[k].to = 1 + (long)WORK / n * (k + 1);
        thrd_create(&t[k], work, &part[k]);
    }
    double total = 0.0;
    for (int k = 0; k < n; k++) {
        thrd_join(t[k], NULL);
        total += part[k].sum;
    }
    timespec_get(&b, TIME_UTC);
    printf("스레드 %d개: 합 %.6f, %.2f초\n", n, total,
           (double)(b.tv_sec - a.tv_sec) + (double)(b.tv_nsec - a.tv_nsec) / 1e9);
    return total;
}

int main(void)
{
    run(1);
    run(2);
    run(4);
    return 0;
}
```

`gcc -O2`로 컴파일해 코어가 2개인 검사 기계에서 돌린 결과입니다.

```text nocheck
스레드 1개: 합 20.384191, 0.43초
스레드 2개: 합 20.384191, 0.23초
스레드 4개: 합 20.384191, 0.23초
```

스레드 2개는 거의 두 배 빨라졌습니다. 코어가 둘이니 둘이 정말로 동시에 일했습니다. 4개로 늘려도 더 빨라지지 않습니다. 코어는 여전히 둘뿐이라, OS가 스레드 넷을 코어 둘에 번갈아 올렸을 뿐입니다. **코어 수보다 스레드를 많이 만들어도 계산은 빨라지지 않습니다.**

<Note kind="warn">
이 예제는 일을 겹치지 않게 나눌 수 있어서 쉽게 빨라졌습니다. 여러 스레드가 같은 변수를 함께 고치면 결과가 망가지거나(경쟁 상태), 서로 기다리느라 오히려 느려집니다. 일의 일부가 꼭 차례로 해야 하는 것이라면, 코어를 아무리 늘려도 그 부분이 걸리는 시간 아래로는 줄지 않습니다. 이 한계를 암달의 법칙이라고 부릅니다.
</Note>

## 정리

- 코어는 명령을 실행하는 CPU 한 벌이고, 하드웨어 스레드는 코어 하나가 명령 흐름 두 개를 번갈아 받아 OS에 CPU 두 개처럼 보이게 하는 것이다
- "8코어 16스레드"는 실제 코어 8개에 코어마다 하드웨어 스레드 2개라는 뜻이고, 하드웨어 스레드는 코어만큼 빨라지지는 않는다
- 프로그램의 스레드는 OS가 CPU에 번갈아 올리므로, 코어 수보다 많이 만들어도 계산은 빨라지지 않는다
