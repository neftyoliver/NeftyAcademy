[「마이크로프로세서의 등장」](#/read/basics/history-microprocessor)에서 ARM이 1985년 영국의 한 컴퓨터 회사에서 시작했다고 했습니다. 지금은 거의 모든 스마트폰과 태블릿, 라즈베리파이, 애플의 맥, 그리고 많은 서버가 ARM 설계의 CPU를 씁니다. 이 쪽은 ARM이 어떻게 이렇게 퍼졌는지와, 개발자가 알아야 할 차이를 봅니다.

## 설계를 빌려주는 회사

인텔과 AMD는 CPU를 설계하고 직접 만들거나 주문해서 **칩을 팝니다.** ARM은 칩을 팔지 않고 **설계를 빌려주고** 사용료를 받습니다.

| 빌려주는 것 | 받는 회사가 하는 일 | 예 |
| --- | --- | --- |
| 완성된 코어 설계(Cortex 시리즈) | 그대로 가져다 자기 칩에 넣는다 | 라즈베리파이의 브로드컴 칩, 많은 안드로이드 폰 |
| 명령어 집합 규칙만 | 그 규칙을 따르는 코어를 직접 설계한다 | 애플 M 시리즈, 퀄컴의 일부 칩 |

그래서 수백 개 회사가 각자 필요에 맞춘 ARM 칩을 만듭니다. 전기를 아주 적게 쓰는 센서용 칩부터 코어가 백 개 넘는 서버용 칩까지 모두 같은 ARM 명령어 집합을 씁니다. 명령어 집합이 무엇인지는 [「CPU와 레지스터」](#/read/basics/arch-cpu)에서 봤습니다.

## SoC: 칩 하나에 담은 컴퓨터

PC는 CPU, 그래픽 카드, 램, 네트워크 카드가 따로따로 부품입니다. 스마트폰에는 그럴 자리가 없어서 이것들을 **칩 하나에 모아** 넣습니다. 이것을 SoC(System on a Chip)라고 합니다.

| SoC 안에 흔히 든 것 | 하는 일 |
| --- | --- |
| CPU 코어 여러 개 | 프로그램 실행 |
| GPU | 화면 그리기, 게임 |
| NPU | 인공지능 계산 |
| 영상 처리기 | 카메라 사진 다듬기, 동영상 압축 |
| 모뎀 | 휴대전화망 연결 |
| 메모리 컨트롤러 | 바로 옆에 붙인 LPDDR 램과 연결 |

부품 사이의 거리가 짧아서 빠르고 전기를 덜 씁니다. 대신 나중에 부품 하나만 바꿀 수는 없습니다. 라즈베리파이 5의 BCM2712, 애플의 M 시리즈, 퀄컴의 스냅드래곤이 모두 SoC입니다. [「마이크로프로세서의 등장」](#/read/basics/history-microprocessor)의 마이크로컨트롤러도 칩 하나에 다 넣은 것이지만, SoC는 리눅스나 안드로이드 같은 큰 OS를 돌릴 만큼 크고 빠르다는 점이 다릅니다.

## 큰 코어와 작은 코어

전화기는 배터리로 하루를 버텨야 합니다. 그래서 2011년 무렵부터 ARM 칩에는 **빠르지만 전기를 많이 먹는 큰 코어**와 **느리지만 아끼는 작은 코어**를 함께 넣는 방식이 퍼졌습니다. 메시지를 확인하는 정도는 작은 코어가, 게임은 큰 코어가 맡습니다. 어떤 일을 어느 코어에 줄지는 OS가 정합니다.

이 방식은 PC로도 넘어왔습니다. 애플 M 시리즈에는 성능 코어와 효율 코어가 있고, 인텔도 2021년의 12세대 코어부터 P코어와 E코어를 섞어 넣습니다. 코어와 스레드에 대해서는 [「코어와 스레드」](#/read/basics/terms-core-thread)에서 이어집니다.

<Note>
2020년에 애플이 맥의 CPU를 인텔에서 자체 ARM 칩(M1)으로 바꾸면서 "ARM은 전화기용"이라는 생각이 깨졌습니다. 서버에서도 아마존(Graviton) 같은 클라우드 회사들이 자체 ARM 칩을 만들어 빌려줍니다. 같은 일을 전기를 덜 쓰며 하면 데이터센터의 전기 요금이 줄기 때문입니다.
</Note>

## x86용 프로그램은 ARM에서 돌지 않는다

명령어 집합이 다르면 기계어가 다르므로, 컴파일된 프로그램은 그 CPU에서만 돕니다. 같은 C 소스를 PC용과 ARM64용으로 각각 컴파일해 봅니다.

```c
#include <stdio.h>

int main(void)
{
    printf("안녕, %zu비트 세상\n", sizeof(void *) * 8);
    return 0;
}
```

```text
안녕, 64비트 세상
```

검사 기계(x86-64)에서 `gcc`로, 그리고 ARM64용 교차 컴파일러 `aarch64-linux-gnu-gcc`로 컴파일한 뒤 `file` 명령으로 두 실행 파일을 살펴본 결과입니다(길어서 일부를 줄였습니다).

```text nocheck
hello-x86: ELF 64-bit LSB pie executable, x86-64, ... dynamically linked
hello-arm: ELF 64-bit LSB pie executable, ARM aarch64, ... dynamically linked
```

PC용 파일은 그대로 실행되지만, ARM용 파일을 PC에서 실행하면 OS가 거부합니다.

```text nocheck
$ ./hello-arm
bash: ./hello-arm: cannot execute binary file: Exec format error
```

"실행 파일 형식이 맞지 않는다"는 뜻입니다. ARM용 파일을 PC에서 돌리려면 ARM CPU를 소프트웨어로 흉내 내는 QEMU 같은 에뮬레이터가 필요하고, 그렇게 돌리면 위와 같은 `안녕, 64비트 세상`이 나옵니다. 이 책이 라즈베리파이용 코드를 검사할 때 쓰는 방법입니다. 다른 CPU용으로 컴파일하는 교차 컴파일은 소형 기기 서가의 「교차 컴파일과 배포」에서 자세히 다룹니다.

<Note kind="tip">
파이썬이나 자바스크립트로 쓴 프로그램은 CPU마다 따로 컴파일할 필요가 없습니다. 각 CPU용으로 컴파일된 파이썬, 자바스크립트 실행기가 소스를 읽어 실행하기 때문입니다. 애플의 로제타 2나 윈도우의 ARM용 에뮬레이션처럼 x86 기계어를 실행 시점에 ARM 기계어로 바꿔 주는 프로그램도 있지만, 원래 ARM용으로 컴파일한 것보다는 느립니다.
</Note>

## 정리

- ARM은 칩 대신 설계를 빌려주는 회사이고, 그래서 수많은 회사가 각자 맞춘 ARM 칩을 만들어 전화기부터 서버까지 쓴다
- 스마트폰의 칩은 CPU, GPU, NPU, 모뎀을 한데 모은 SoC이고, 큰 코어와 작은 코어를 섞어 배터리를 아낀다
- 명령어 집합이 달라 x86-64용 실행 파일은 ARM에서 돌지 않으므로, 다시 컴파일하거나 에뮬레이터를 써야 한다
