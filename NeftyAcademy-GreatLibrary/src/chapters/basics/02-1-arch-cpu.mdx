## CPU 안의 세 부분

| 부분 | 하는 일 | 비유 |
| --- | --- | --- |
| 연산 장치(ALU) | 덧셈, 뺄셈, 비교, 비트 연산 | 계산기 |
| 제어 장치 | 메모리에서 명령을 꺼내 읽고, 무엇을 할지 다른 부분에 알린다 | 악보를 읽는 지휘자 |
| 레지스터 | 지금 계산하는 수를 담는 아주 빠른 칸 몇십 개 | 계산하면서 손에 쥔 메모지 |

CPU는 메모리에 있는 수를 바로 더하지 않는 경우가 많습니다. 먼저 수를 레지스터로 가져오고, 레지스터끼리 계산하고, 결과를 다시 메모리에 씁니다. 메모리는 CPU에서 멀고 느리기 때문입니다. 얼마나 느린지는 다음 쪽 [「메모리와 저장 장치의 계층」](#/read/basics/arch-memory)에서 숫자로 봅니다.

## 레지스터

레지스터는 CPU 칩 안에 있는 기억 칸입니다. 칸 하나의 크기가 그 CPU의 비트 수입니다. 64비트 CPU의 레지스터는 한 칸에 64비트(8바이트)를 담습니다. 개수는 아주 적습니다.

| | x86-64 (PC) | ARM64 (라즈베리파이, 스마트폰) |
| --- | --- | --- |
| 범용 레지스터 | 16개: `rax`, `rbx`, `rcx`, `rdx`, `rsi`, `rdi`, `rbp`, `rsp`, `r8`~`r15` | 31개: `x0`~`x30` |
| 같은 칸의 아래 32비트 | `eax`, `edi` 처럼 `e`로 시작 | `w0`~`w30` |
| 다음 명령의 위치 | `rip` | `pc` |
| 스택의 꼭대기 | `rsp` | `sp` |
| 계산 결과의 표시(0인가, 넘쳤는가) | `rflags` | `nzcv` |

범용 레지스터는 아무 수나 담을 수 있는 칸이고, 나머지는 쓰임이 정해진 칸입니다. 이 밖에 실수와 여러 수를 한꺼번에 계산하는 데 쓰는 넓은 레지스터(x86-64는 128~512비트, ARM64는 128비트)가 따로 있습니다.

x86-64의 이름이 제각각인 것은 [「8086에서 x86-64까지」](#/read/basics/history-x86)의 역사 때문입니다. 8086의 16비트 칸 `ax`가 386에서 32비트 `eax`로, 다시 64비트 `rax`로 넓어졌고 옛 이름도 그대로 남았습니다. 새로 더한 여덟 칸에는 `r8`~`r15`라는 번호 이름을 붙였습니다. ARM64는 처음부터 64비트로 설계해서 번호만 붙였습니다.

## 실제로 쓰이는 모습

C 함수 하나를 컴파일러가 CPU 명령으로 바꾼 결과를 보겠습니다. 수 세 개를 받아 더하는 함수입니다.

```c
int add3(int a, int b, int c)
{
    return a + b + c;
}
```

GCC 14로 x86-64와 ARM64용으로 각각 컴파일하고(`-O1 -S`), 설명에 필요 없는 줄을 지운 결과입니다.

```text
x86-64                      ARM64
add3:                       add3:
    endbr64                     add  w0, w0, w1
    add  edi, esi               add  w0, w0, w2
    lea  eax, [rdi+rdx]         ret
    ret
```

- **인자는 레지스터로 들어온다.** x86-64 리눅스에서는 첫째, 둘째, 셋째 인자가 `edi`, `esi`, `edx`에, ARM64에서는 `w0`, `w1`, `w2`에 들어 있습니다. 이 약속을 호출 규약이라고 부릅니다
- **결과도 레지스터로 돌려준다.** x86-64는 `eax`, ARM64는 `w0`에 담아 두고 `ret`으로 돌아갑니다
- **`int`가 32비트라서** 64비트 칸의 아래 절반인 `e…`, `w…` 이름을 씁니다
- x86-64의 `lea`는 원래 주소를 계산하는 명령인데, 덧셈 두 개를 한 번에 하는 데 빌려 썼습니다. 첫 줄의 `endbr64`는 계산과 관계없는 보안 표시입니다

메모리에는 한 번도 가지 않았습니다. 수 세 개가 처음부터 끝까지 레지스터 안에서 계산됐습니다. 컴파일러는 이렇게 자주 쓰는 값을 될 수 있는 한 레지스터에 두려고 애씁니다. 두 아키텍처의 명령을 더 자세히 견주는 것은 [「어셈블리로 보는 아키텍처의 차이」](#/read/c-basic/asm)에서 합니다.

## 클럭

CPU 안의 모든 부분은 **클럭**이라는 일정한 박자에 맞춰 움직입니다. 박자 한 번마다 회로가 한 단계씩 나아갑니다. 3GHz CPU는 1초에 30억 번 박자를 칩니다. 한 박자는 약 0.33나노초이고, 빛도 그 사이에 10cm밖에 가지 못합니다.

박자 한 번에 명령 하나를 한다고 생각하기 쉽지만 실제로는 다릅니다. 지금의 CPU는 명령 여러 개를 겹쳐서 진행하고, 서로 상관없는 명령은 한 박자에 서너 개씩 끝내기도 합니다. 그래서 클럭이 같아도 설계에 따라 빠르기가 크게 다릅니다. 클럭 수치만으로 서로 다른 CPU를 견줄 수 없는 까닭입니다.

<Note>
이 책의 예제를 검사한 기계의 CPU는 리눅스에서 `Intel(R) Xeon(R) Processor @ 2.30GHz`로 보입니다. 데이터센터에서 빌린 서버의 일부(코어 2개)라서 정확한 제품명이 가려져 있습니다. 내 컴퓨터의 CPU는 터미널에서 `lscpu`로 볼 수 있습니다.
</Note>

## 명령어 집합

CPU가 알아듣는 명령의 목록과 그 규칙을 **명령어 집합 구조**(ISA)라고 합니다. x86-64와 ARM64는 서로 다른 ISA입니다. 같은 `add`라는 이름이어도 기계어로는 전혀 다른 비트 무늬가 되고, 레지스터 이름과 개수도 다릅니다. 그래서 PC용으로 컴파일한 프로그램은 라즈베리파이에서 돌지 않고, 소스를 그 CPU에 맞게 다시 컴파일해야 합니다.

| | x86-64 | ARM64 |
| --- | --- | --- |
| 명령 하나의 길이 | 1~15바이트로 제각각 | 언제나 4바이트 |
| 메모리를 직접 계산에 쓰기 | 된다(`add eax, [rbx]`) | 안 된다. 먼저 레지스터로 읽어 온다 |
| 설계의 뿌리 | 1978년의 8086과 호환 | 2011년에 64비트로 새로 정리 |

<Note kind="tip">
명령 하나가 많은 일을 하는 x86 같은 설계를 CISC, 명령은 단순하게 두고 개수로 해결하는 ARM 같은 설계를 RISC라고 부릅니다. 다만 지금의 x86 CPU는 안에서 명령을 잘게 쪼개 RISC처럼 실행하므로, 이 구분은 예전만큼 뚜렷하지 않습니다.
</Note>

## 정리

- CPU는 계산하는 연산 장치, 명령을 읽고 지시하는 제어 장치, 그리고 지금 쓰는 수를 담는 레지스터로 이루어진다
- 레지스터는 x86-64에 16개, ARM64에 31개뿐인 아주 빠른 칸이고, 컴파일러는 인자와 결과를 될 수 있는 한 여기에 둔다
- CPU는 클럭의 박자에 맞춰 움직이고, 알아듣는 명령의 목록(ISA)이 달라서 x86-64용 프로그램은 ARM64에서 돌지 않는다
