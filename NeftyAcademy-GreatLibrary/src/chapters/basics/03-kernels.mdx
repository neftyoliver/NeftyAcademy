**커널**은 하드웨어를 직접 만지는 OS의 심장입니다. 메모리를 나눠 주고, 프로세스를 번갈아 돌리고, 디스크·네트워크 같은 장치를 맡습니다. 우리가 짜는 프로그램은 커널에 **시스템 콜**로 부탁만 할 수 있습니다.

## 구조에 따른 종류

| 종류 | 생각 | 예 |
| --- | --- | --- |
| 모놀리식 | 드라이버·파일 시스템까지 전부 커널 안에. 빠르지만 커널이 큼 | Linux, FreeBSD |
| 마이크로커널 | 커널은 최소만, 드라이버 등은 바깥 프로세스로. 튼튼하지만 오가는 비용 | seL4, QNX, MINIX 3 |
| 하이브리드 | 마이크로커널 생각에서 출발했지만 성능 때문에 많은 걸 안에 둠 | Windows NT, macOS의 XNU |

<Note>
리눅스는 모놀리식이지만 **모듈**을 실행 중에 넣고 뺄 수 있습니다. `lsmod`로 지금 들어 있는 모듈을 볼 수 있습니다.
</Note>

## 배포판 = 커널 + 나머지

"리눅스"는 원래 커널 이름입니다. 우리가 까는 우분투·데비안·페도라는 **배포판**으로, 리눅스 커널에 C 라이브러리, 셸, 패키지 매니저, 데스크톱 등을 묶은 것입니다. 그래서 같은 커널을 쓰더라도 배포판마다 패키지 매니저와 설정 방식이 다릅니다.

## 같은 리눅스 커널 안의 종류

| 이름 | 뜻 |
| --- | --- |
| generic | 우분투 기본 커널 |
| lowlatency | 반응 시간을 줄인 설정. 음악 작업 등 |
| HWE | 우분투 LTS에서 더 새 하드웨어를 위해 올려 주는 새 커널 줄기 |
| 라즈베리파이 커널 | 라즈베리파이 하드웨어용 설정과 드라이버가 들어간 커널 |

```sh
uname -r      # 지금 돌아가는 커널 버전
uname -a      # 더 자세히 (아키텍처 포함)
```
