[「OS가 맡는 일」](#/read/basics/os-role)에서 OS가 CPU와 램을 프로그램들에 나눠 준다고 했습니다. 이 쪽은 그 나누기를 봅니다. 나눠 받는 단위가 **프로세스**이고, CPU는 **스케줄러**가, 램은 **가상 메모리**가 나눕니다.

## 프로세스

디스크에 있는 실행 파일은 그냥 파일입니다. 그것을 실행하면 OS가 램에 올리고, 번호를 붙이고, 실행 상태를 관리하기 시작합니다. 이렇게 **실행 중인 프로그램 하나**를 프로세스라고 합니다. 같은 프로그램을 두 번 실행하면 프로세스가 둘 생깁니다.

OS는 프로세스마다 이런 것을 기억합니다.

| 항목 | 내용 |
| --- | --- |
| PID | 프로세스 번호 |
| 메모리 | 코드, 변수, 힙, 스택이 놓인 곳 |
| 레지스터 | 멈췄을 때의 레지스터 값과 프로그램 카운터 |
| 열린 파일 | 파일 기술자 0, 1, 2, 3… 이 가리키는 것 |
| 주인과 권한 | 누가 실행했는지, 무엇을 할 수 있는지 |

리눅스에서는 `ps`로 프로세스 목록을, `top`이나 `htop`으로 실시간 사용량을 봅니다. 모든 프로세스는 다른 프로세스가 만든 것이라 부모가 있고, 거슬러 올라가면 부팅할 때 커널이 처음 만든 1번 프로세스에 닿습니다.

## CPU 나누기: 스케줄러

CPU가 2개인데 실행할 스레드가 100개라면, OS의 **스케줄러**가 아주 짧은 시간(수 밀리초)씩 돌아가며 CPU를 맡깁니다. 정해진 시간이 지나면 타이머 [인터럽트](#/read/basics/arch-bus-io)가 와서 커널이 끼어들고, 지금 스레드의 레지스터를 저장한 뒤 다음 스레드의 레지스터를 불러와 이어서 실행합니다. 이 바꿔 끼우기를 **문맥 교환**이라고 합니다.

사람에게는 1초에 수백 번 바뀌는 것이 모두 동시에 도는 것처럼 보입니다. 스케줄러는 공평함과 반응성을 함께 챙깁니다.

- **기다리는 스레드는 CPU를 받지 않는다.** 키 입력이나 디스크 읽기를 기다리는 스레드는 잠재워 두고, 일이 생기면 깨운다. 그래서 프로그램을 많이 띄워 놔도 대부분은 CPU를 쓰지 않는다
- **화면 앞의 일을 먼저.** 사용자가 보고 있는 창, 소리를 내는 프로그램은 빨리 반응하도록 앞세운다
- **우선순위를 바꿀 수 있다.** 리눅스의 `nice` 명령으로 오래 걸리는 작업을 뒤로 미룰 수 있다

[「코어와 스레드」](#/read/basics/terms-core-thread)에서 스레드를 코어 수보다 많이 만들어도 빨라지지 않았던 것이 이 번갈아 맡기기 때문이었습니다. 리눅스는 범용 OS라 어떤 스레드가 정확히 몇 마이크로초 안에 CPU를 받는다고 약속하지 않습니다. [「마이크로컨트롤러와 라즈베리파이」](#/read/basics/modern-mcu-sbc)에서 정확한 박자가 필요한 일을 마이크로컨트롤러에 맡긴 까닭입니다.

## 램 나누기: 가상 메모리

프로세스는 모두 자기만의 메모리를 가진 것처럼 봅니다. 주소 0부터 아주 큰 주소까지가 통째로 자기 것처럼 보이고, 다른 프로세스의 메모리는 보이지도 않습니다. 이것이 **가상 메모리**입니다.

실제로는 프로그램이 쓰는 주소(가상 주소)와 램의 진짜 위치(물리 주소)가 다릅니다. OS는 프로세스마다 **페이지 표**라는 대응표를 만들어, 가상 주소 4KiB 덩어리(페이지)가 램의 어느 칸에 있는지 적어 둡니다. CPU 안의 회로(MMU)가 명령을 실행할 때마다 이 표를 보고 주소를 바꿉니다.

아래 프로그램은 `fork`로 자기 자신을 통째로 복제합니다. 복제된 쪽(자식)이 변수 `x`를 바꾸고, 두 프로세스가 각자 `x`의 값과 주소를 찍습니다. `fork`는 POSIX 함수라 `_POSIX_C_SOURCE`를 정의해 컴파일했습니다([「POSIX와 ISO C」](#/read/basics/std-posix-c)).

```c flags=-D_POSIX_C_SOURCE=200809L
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
    int x = 100;
    pid_t pid = fork();                 // 이 프로세스를 통째로 복제한다
    if (pid == 0) {                     // 복제된 쪽(자식)
        x = 999;
        printf("자식 PID %d: x = %d, 주소 %p\n", (int)getpid(), x, (void *)&x);
        return 0;
    }
    waitpid(pid, NULL, 0);              // 자식이 끝나기를 기다린다
    printf("부모 PID %d: x = %d, 주소 %p\n", (int)getpid(), x, (void *)&x);
    return 0;
}
```

```text nocheck
자식 PID 7972: x = 999, 주소 0x7ffefb3941e0
부모 PID 7971: x = 100, 주소 0x7ffefb3941e0
```

**같은 주소에 다른 값**이 들어 있습니다. 두 프로세스가 보는 `0x7ffefb3941e0`은 가상 주소이고, 각자의 페이지 표가 그것을 램의 서로 다른 칸으로 바꿉니다. 그래서 자식이 `x`를 고쳐도 부모의 `x`는 그대로입니다. 프로세스끼리 서로의 메모리를 망가뜨릴 수 없는 까닭이 이것입니다. 실행할 때마다 주소가 바뀌는 것은 해킹을 어렵게 하려고 OS가 일부러 주소를 흩어 놓기 때문입니다([「메모리를 숨기고 보호하기」](#/read/c-mid/sec-memory)).

가상 메모리 덕분에 생기는 일이 몇 가지 더 있습니다.

- **필요할 때만 램을 준다.** 프로그램이 큰 메모리를 달라고 해도, OS는 실제로 그 페이지를 처음 쓸 때 램 칸을 붙인다
- **같은 것은 함께 쓴다.** 여러 프로세스가 쓰는 C 라이브러리의 코드는 램에 한 벌만 올리고 각자의 페이지 표가 그곳을 가리킨다. 위의 `fork`도 처음에는 복사하지 않고 함께 쓰다가, 한쪽이 고치는 순간 그 페이지만 복사한다
- **램보다 많이 쓴다.** 오래 안 쓴 페이지를 디스크의 스왑으로 내려놓을 수 있다([「램과 저장 공간」](#/read/basics/terms-ram-storage))

<Note kind="warn">
램과 스왑이 모두 바닥나면 리눅스는 OOM 킬러(Out Of Memory killer)를 깨워, 메모리를 많이 쓰는 프로세스를 골라 강제로 끝냅니다. 프로그램이 오류 메시지도 없이 사라졌다면 `sudo dmesg`에서 `Out of memory: Killed process`라는 줄이 있는지 찾아보세요. 램이 작은 라즈베리파이에서 큰 프로그램을 컴파일할 때 자주 만납니다.
</Note>

## 정리

- 프로세스는 실행 중인 프로그램 하나이고, OS는 프로세스마다 번호, 메모리, 레지스터, 열린 파일, 권한을 기억한다
- 스케줄러는 타이머 인터럽트로 끼어들어 문맥 교환을 하며 CPU를 아주 짧게 번갈아 나눠 주고, 기다리는 스레드는 재워 둔다
- 가상 메모리는 프로세스마다 페이지 표로 주소를 따로 바꿔 주므로, 같은 주소라도 프로세스마다 다른 램 칸을 가리킨다
