[「CPU와 레지스터」](#/read/basics/arch-cpu)에서 레지스터는 몇십 개뿐이라고 했습니다. 프로그램이 쓰는 나머지 수는 모두 그보다 멀고 느린 곳에 있습니다. 이 쪽은 그 "멀고 느린 정도"를 층으로 나눠 보고, 프로그램으로 직접 잽니다.

## 계층

기억 장치에는 세 가지를 한꺼번에 가질 수 없다는 사정이 있습니다. **빠르고, 크고, 싼 것.** 빠른 것은 작고 비싸며, 큰 것은 느립니다. 그래서 컴퓨터는 여러 층을 쌓아 둡니다.

| 층 | 크기(흔한 값) | 한 번 읽는 시간(대략) | 전원을 끄면 |
| --- | --- | --- | --- |
| 레지스터 | 수백 바이트 | 박자 1번 미만 | 사라진다 |
| L1 캐시 | 코어마다 수십 KB | 1ns | 사라진다 |
| L2 캐시 | 코어마다 수 MB | 수 ns | 사라진다 |
| L3 캐시 | 칩 전체에 수십 MB | 십여 ns | 사라진다 |
| 램 | 수~수십 GB | 100ns 안팎 | 사라진다 |
| SSD | 수백 GB~수 TB | 수십~수백 µs | 남는다 |
| HDD | 수 TB | 수 ms | 남는다 |

위로 갈수록 CPU에 가깝습니다. 레지스터에서 HDD까지 빠르기는 천만 배쯤 차이 납니다. 1ns를 1초로 늘리면 램은 2분쯤, SSD는 하루쯤, HDD는 몇 달쯤입니다.

## 캐시

캐시는 램의 내용 가운데 **최근에 쓴 부분의 사본**을 CPU 가까이 둔 것입니다. CPU가 램의 어느 주소를 읽으면, 그 주소를 둘러싼 64바이트를 한 묶음(캐시 줄)으로 가져와 캐시에 남겨 둡니다. 다음에 같은 곳이나 바로 옆을 읽으면 램까지 가지 않고 캐시에서 꺼냅니다.

이것이 통하는 까닭은 프로그램의 버릇 때문입니다.

- **방금 쓴 것을 곧 또 쓴다.** 반복문의 변수, 자주 부르는 함수
- **방금 쓴 것의 옆을 곧 쓴다.** 배열을 처음부터 끝까지 훑는 일

캐시는 프로그래머가 따로 다루지 않아도 CPU가 알아서 채우고 비웁니다. 다만 프로그램이 이 버릇을 따르는지에 따라 빠르기가 몇 배씩 달라집니다.

## 직접 재 보기

아래 프로그램은 정해진 크기의 배열 안에서 칸을 무작위 순서로 하나씩 따라갑니다. 다음 칸의 위치를 지금 칸에서 읽어야 알 수 있으므로, CPU는 미리 읽어 두는 꾀를 쓸 수 없습니다. 배열이 캐시에 들어가는 크기면 빠르고, 넘치면 램까지 다녀와야 합니다.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

// 크기가 bytes인 고리를 만들고 한 칸씩 따라가며 한 번에 걸리는 시간을 잰다
static double chase(size_t bytes)
{
    size_t n = bytes / sizeof(size_t);
    size_t *next = malloc(n * sizeof(size_t));
    size_t *order = malloc(n * sizeof(size_t));
    for (size_t i = 0; i < n; i++) order[i] = i;
    for (size_t i = n - 1; i > 0; i--) {          // 순서를 뒤섞는다
        size_t j = (size_t)rand() % (i + 1);
        size_t t = order[i]; order[i] = order[j]; order[j] = t;
    }
    for (size_t i = 0; i < n; i++) next[order[i]] = order[(i + 1) % n];

    const long steps = 20000000;
    size_t p = 0;
    struct timespec a, b;
    timespec_get(&a, TIME_UTC);
    for (long s = 0; s < steps; s++) p = next[p];
    timespec_get(&b, TIME_UTC);
    double ns = (b.tv_sec - a.tv_sec) * 1e9 + (b.tv_nsec - a.tv_nsec);
    if (p == (size_t)-1) puts("");                 // p를 쓰게 해서 지워지지 않게
    free(next);
    free(order);
    return ns / steps;
}

int main(void)
{
    size_t sizes[] = {16 << 10, 256 << 10, 4 << 20, 64 << 20, 512 << 20};
    for (int i = 0; i < 5; i++)
        printf("%7zu KiB  %6.1f ns\n", sizes[i] >> 10, chase(sizes[i]));
    return 0;
}
```

`gcc -O2`로 컴파일해 이 책의 검사 기계에서 돌린 결과입니다. 기계마다, 돌릴 때마다 숫자는 달라집니다.

```text nocheck
     16 KiB     1.3 ns
    256 KiB     4.2 ns
   4096 KiB    26.7 ns
  65536 KiB   139.4 ns
 524288 KiB   195.7 ns
```

이 기계의 캐시는 `lscpu`로 보면 코어마다 L1 48KiB, L2 2MiB입니다. 16KiB는 L1에 다 들어가서 1.3ns, 256KiB는 L2에 들어가서 4ns 남짓입니다. 4MiB부터는 L2를 넘쳐서 크게 느려지고, 64MiB를 넘으면 한 번에 100ns가 넘습니다. 16KiB와 512MiB 사이가 150배입니다. 같은 일을 하는 같은 코드인데 **데이터의 크기만으로** 이만큼 차이가 납니다.

<Note>
4MiB 줄은 세 번 돌렸을 때 27ns, 41ns, 59ns로 크게 흔들렸습니다. 검사 기계는 다른 손님과 칩을 나눠 쓰는 클라우드 서버라서, 큰 캐시와 램 쪽 수치일수록 이웃의 사정에 따라 달라집니다. `lscpu`가 L3를 504MiB로 보고하는 것도 실제 칩의 값이라기보다 가상 기계가 알려 주는 값이라, 64MiB가 L3에 들어간다고 보기는 어렵습니다.
</Note>

## 램

램은 전원이 들어와 있는 동안만 내용을 기억합니다. 프로그램을 실행하면 OS가 디스크에서 프로그램을 램으로 읽어 올리고, CPU는 램에 있는 명령과 자료만 다룹니다. 디스크에 있는 파일을 CPU가 바로 계산할 수는 없습니다. 이것이 프로그램을 "연다", "불러온다"고 할 때 실제로 일어나는 일입니다.

PC의 램은 대부분 DDR이라는 규격의 막대를 메인보드에 꽂은 것이고, 노트북과 스마트폰, 라즈베리파이는 칩을 기판에 바로 붙인 LPDDR을 많이 씁니다. 램과 저장 공간을 헷갈리기 쉬운 이야기는 [「램과 저장 공간」](#/read/basics/terms-ram-storage)에서 따로 다룹니다.

## 저장 장치

전원을 꺼도 남아야 하는 것은 저장 장치에 둡니다.

| | SSD | HDD |
| --- | --- | --- |
| 기억하는 방법 | 플래시 메모리 칩의 전하 | 돌아가는 자기 원판 |
| 움직이는 부품 | 없다 | 원판과 바늘 |
| 무작위로 읽을 때 | 빠르다 | 바늘이 옮겨 가느라 아주 느리다 |
| 같은 값에 담는 양 | 적다 | 많다 |

HDD에서 무작위 읽기가 느린 것은 원판이 돌아 원하는 자리가 바늘 밑에 올 때까지 기다려야 하기 때문입니다. 7,200RPM 원판은 한 바퀴에 8.3ms가 걸립니다. 라즈베리파이가 쓰는 SD 카드와 USB 메모리도 플래시 메모리지만, SSD보다 훨씬 느리고 쓰기를 많이 하면 빨리 닳습니다.

<Note kind="tip">
"컴퓨터가 느리다"는 말은 대부분 계층의 아래층을 기다린다는 뜻입니다. 램이 모자라 OS가 램의 내용을 디스크로 내렸다가 다시 올리기 시작하면(스와핑) 접근 한 번이 나노초에서 마이크로초나 밀리초로 바뀝니다. 이 일은 [「프로세스와 메모리 관리」](#/read/basics/os-process-memory)에서 이어집니다.
</Note>

## 정리

- 기억 장치는 빠르고 작은 것부터 크고 느린 것까지 레지스터, 캐시, 램, SSD, HDD의 층으로 쌓여 있다
- 캐시는 최근에 쓴 램 내용의 사본이고, 같은 곳과 옆자리를 다시 쓰는 프로그램의 버릇 덕분에 통한다
- 데이터가 캐시를 넘치는 순간 같은 코드도 수십~백 배 느려지며, 램은 전원이 꺼지면 지워지고 저장 장치는 남는다
