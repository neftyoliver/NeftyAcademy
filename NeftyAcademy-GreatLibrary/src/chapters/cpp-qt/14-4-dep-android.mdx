Qt 앱은 코드를 거의 그대로 두고 안드로이드 휴대폰과 태블릿에서도 돌릴 수 있습니다. 다만 겉모습이 같을 뿐 사는 환경은 많이 다릅니다. 앱은 C++ **공유 라이브러리**로 빌드되고, Qt가 넣어 주는 자바 쪽 코드(액티비티)가 그것을 불러 실행합니다. 그리고 운영 체제가 앱을 언제든 멈추거나 없앨 수 있습니다.

## 준비물과 빌드

- **도구**: JDK, 안드로이드 SDK, 안드로이드 NDK가 필요하고, Qt는 대상 ABI(arm64-v8a, armeabi-v7a, x86_64, x86)마다 안드로이드용 빌드가 따로 있어야 합니다. 쓸 수 있는 SDK·NDK 판의 조합은 Qt 판마다 다르므로 그 판의 문서에 있는 표를 따릅니다. Qt Creator는 이 도구들을 내려받고 키트를 맞추는 일을 대신해 줍니다
- **빌드**: 안드로이드용 Qt로 구성하면 `qt_add_executable`이 실행 파일 대신 공유 라이브러리를 만들고, `androiddeployqt`가 Qt 라이브러리와 플러그인, 자바 코드를 모아 Gradle로 패키지를 만듭니다
- **패키지**: 휴대폰에 바로 설치해 시험할 때는 **APK**, Google Play에 올릴 때는 **AAB**를 씁니다. AAB에는 모든 ABI가 들어가고, Play가 기기마다 필요한 부분만 골라 APK를 만들어 내려보냅니다. 여러 ABI를 한 번에 빌드하는 설정으로는 `QT_ANDROID_ABIS`가 있습니다(Qt 6.3에서 들어온 기술 미리보기)

앱 이름, 아이콘, 화면 방향, 권한 같은 것은 `AndroidManifest.xml`에 적습니다. Qt가 쓰는 기본 틀을 프로젝트의 `android` 폴더에 복사해 고치고, 그 위치를 알려 주면 됩니다.

```cmake
qt_add_executable(reader main.cpp)
set_target_properties(reader PROPERTIES
    QT_ANDROID_PACKAGE_SOURCE_DIR ${CMAKE_CURRENT_SOURCE_DIR}/android)
```

이 폴더의 `src/`에 자바나 코틀린 코드를, `res/`에 아이콘 같은 리소스를 둡니다.

## 앱의 일생

데스크톱 앱은 사용자가 닫을 때까지 살아 있지만, 휴대폰 앱은 그렇지 않습니다. 홈 화면으로 나가면 앱은 멈추고, 메모리가 모자라면 운영 체제가 **경고 없이** 앱을 없앱니다. 사용자가 다시 앱을 열었을 때 처음 화면으로 돌아가 있으면 안 되므로, 앱은 멈추기 직전에 상태를 저장해야 합니다. Qt는 이 순간을 `applicationStateChanged` 신호로 알려 줍니다. 안드로이드 액티비티의 `onResume`, `onPause`, `onStop`이 각각 `ApplicationActive`, `ApplicationInactive`, `ApplicationSuspended`가 됩니다.

안드로이드 기기 없이 이 흐름을 확인하려고, 플랫폼 플러그인이 상태를 바꾸는 일을 Qt 내부 API로 흉내 냈습니다. 읽던 쪽을 기억하는 책 읽기 앱입니다.

```cpp qt=Gui flags=-I/usr/include/x86_64-linux-gnu/qt6/QtGui/6.4.2,-I/usr/include/x86_64-linux-gnu/qt6/QtGui/6.4.2/QtGui,-I/usr/include/x86_64-linux-gnu/qt6/QtCore/6.4.2,-I/usr/include/x86_64-linux-gnu/qt6/QtCore/6.4.2/QtCore
// 안드로이드가 앱을 뒤로 보냈다가 없애는 상황을 데스크톱에서 흉내 낸다
#include <QGuiApplication>
#include <QMetaEnum>
#include <QSettings>
#include <QTemporaryDir>
#include <qpa/qwindowsysteminterface.h>   // 흉내 내기용 Qt 내부 API
#include <cstdio>

// 안드로이드 플랫폼 플러그인이 액티비티의 상태가 바뀔 때 하는 일
static void platformSays(Qt::ApplicationState s) {
    QWindowSystemInterface::handleApplicationStateChanged(s);
    QWindowSystemInterface::flushWindowSystemEvents();
}

int main(int argc, char* argv[]) {
    QGuiApplication app(argc, argv);
    QTemporaryDir dir;
    const QString ini = dir.filePath("reader.ini");
    auto lastPage = [&] {
        return QSettings(ini, QSettings::IniFormat).value("page", 1).toInt();
    };

    int page = lastPage();
    std::printf("시작: %d쪽부터\n", page);
    QObject::connect(&app, &QGuiApplication::applicationStateChanged,
                     [&](Qt::ApplicationState s) {
        const auto e = QMetaEnum::fromType<Qt::ApplicationState>();
        std::printf("상태: %s\n", e.valueToKey(s));
        if (s == Qt::ApplicationSuspended) {    // 이제 언제 없어져도 이상하지 않다
            QSettings settings(ini, QSettings::IniFormat);
            settings.setValue("page", page);
            settings.sync();
            std::printf("  %d쪽을 저장\n", page);
        }
    });

    platformSays(Qt::ApplicationActive);
    page = 42;
    std::printf("42쪽까지 읽음\n");
    platformSays(Qt::ApplicationInactive);    // 전화가 와서 가려짐
    platformSays(Qt::ApplicationSuspended);   // 홈 화면으로 나감
    page = 0;                                 // 운영 체제가 앱을 없앴다고 치고
    std::printf("다시 시작: %d쪽부터\n", lastPage());
}
```

```text
시작: 1쪽부터
상태: ApplicationActive
42쪽까지 읽음
상태: ApplicationInactive
상태: ApplicationSuspended
  42쪽을 저장
다시 시작: 42쪽부터
```

- `ApplicationInactive`는 앱이 보이지만 앞에 있지 않은 상태입니다. 전화나 알림 창이 앱을 가릴 때 오며, 무거운 계산을 줄이기 좋은 때입니다
- `ApplicationSuspended`가 오면 지금 저장해야 합니다. 이 뒤로는 코드가 다시 실행된다는 보장이 없습니다
- 저장에는 [「파일과 설정」](#/read/cpp-qt/core-files)에서 본 `QSettings`나 `QStandardPaths`의 앱 데이터 폴더를 씁니다. 안드로이드에서는 앱만 쓸 수 있는 전용 폴더로 연결됩니다
- `qpa/qwindowsysteminterface.h`는 플랫폼 플러그인을 만들 때 쓰는 내부 API로, 여기서는 흉내 내기에만 썼습니다. 실제 앱은 신호를 받기만 하면 됩니다

## 자바 세계와 이야기하기

Qt에 없는 안드로이드 기능은 JNI로 자바 API를 직접 부릅니다. Qt 6.1부터 QtCore에 들어온 `QJniObject`가 JNI의 번거로운 부분을 감싸 줍니다. 안드로이드에서만 빌드되는 코드이므로 `Q_OS_ANDROID`로 막아 둡니다.

```cpp nocheck
#ifdef Q_OS_ANDROID
#include <QCoreApplication>
#include <QJniObject>

void printDevice() {
    const int sdk = QNativeInterface::QAndroidApplication::sdkVersion();
    const QJniObject model =    // 자바의 android.os.Build.MODEL
        QJniObject::getStaticObjectField<jstring>("android/os/Build", "MODEL");
    qInfo() << "API 수준" << sdk << "모델" << model.toString();
}
#endif
```

자바 클래스 이름은 점 대신 빗금으로 씁니다. 자바 쪽에서 C++ 함수를 부르게 하려면 C++ 함수를 JNI 네이티브 메서드로 등록하는데, `QJniEnvironment::registerNativeMethods`가 이 일을 돕습니다.

## 권한 요청

카메라, 위치, 마이크 같은 권한은 설치할 때가 아니라 쓰는 순간에 사용자에게 물어야 합니다. Qt 6.5부터는 이를 플랫폼에 상관없이 `QPermission`으로 처리합니다(이 책의 환경인 Qt 6.4에는 없습니다).

```cpp nocheck
#include <QGuiApplication>
#include <QPermissions>

void startCamera();   // 앱의 함수라고 치자

void askCamera() {
    qApp->requestPermission(QCameraPermission{}, [](const QPermission& p) {
        if (p.status() == Qt::PermissionStatus::Granted)
            startCamera();
        else
            qWarning("카메라 권한이 없어 사진 기능을 끕니다");
    });
}
```

요청하기 전에 `qApp->checkPermission(...)`으로 이미 허락받았는지 확인할 수 있고, 안드로이드에서는 매니페스트에도 그 권한이 선언되어 있어야 합니다. 사용자가 거절해도 앱이 멈추지 않고 그 기능만 끄는 것이 좋습니다.

<Note>
휴대폰은 화면 밀도가 기기마다 크게 다르고, 마우스 대신 손가락으로 조작합니다. [「고해상도 화면」](#/read/cpp-qt/paint-hidpi)에서 본 장치 독립 크기로 그리고, 위젯보다는 터치에 맞춰 만들어진 Qt Quick과 [「Qt Quick Controls」](#/read/cpp-qt/qml-controls)로 화면을 만드는 편이 자연스럽습니다. 뒤로 가기 버튼은 Qt Quick에서 `Keys.onBackPressed`나 `Qt.Key_Back` 키 이벤트로 받습니다.
</Note>

## 정리

- 안드로이드용 Qt 앱은 공유 라이브러리로 빌드되어 androiddeployqt와 Gradle로 APK(시험용)나 AAB(Play 배포용)가 된다
- 운영 체제가 앱을 경고 없이 없앨 수 있으므로 applicationStateChanged에서 ApplicationSuspended를 받으면 상태를 저장한다
- Qt에 없는 기능은 QJniObject로 자바 API를 부르고, 실행 중 권한은 Qt 6.5부터 QPermission으로 요청한다
