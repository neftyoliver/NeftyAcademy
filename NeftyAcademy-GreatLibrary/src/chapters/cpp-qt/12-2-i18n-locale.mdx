[「tr과 번역 파일」](#/read/cpp-qt/i18n-tr)은 글을 번역하지만, 국제화의 절반은 번역이 아닙니다. 같은 날짜, 같은 금액이라도 나라마다 쓰는 모양이 다르고, 주의 첫날과 글을 쓰는 방향과 사전의 순서도 다릅니다. `QLocale`은 이 관례들을 유니코드 CLDR 데이터에 따라 알려 줍니다.

## 네 나라의 같은 값

```cpp qt
#include <QCollator>
#include <QCoreApplication>
#include <QDate>
#include <QLocale>
#include <algorithm>
#include <cstdio>

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    QDate d(2026, 11, 22);
    double amount = 1234567.5;
    for (QLocale loc : {QLocale(QLocale::Korean, QLocale::SouthKorea),
                        QLocale(QLocale::English, QLocale::UnitedStates),
                        QLocale(QLocale::German, QLocale::Germany),
                        QLocale(QLocale::Arabic, QLocale::Egypt)}) {
        std::printf("[%s] %s\n", qPrintable(loc.name()),
                    qPrintable(loc.toString(d, QLocale::LongFormat)));
        std::printf("  %s | %s | 첫 요일 %s | %s\n",
                    qPrintable(loc.toString(amount, 'f', 1)),
                    qPrintable(loc.toCurrencyString(amount)),
                    qPrintable(loc.dayName(loc.firstDayOfWeek(),
                                           QLocale::ShortFormat)),
                    loc.textDirection() == Qt::RightToLeft ? "RTL" : "LTR");
    }

    // 사용자가 입력한 숫자는 그 사람의 로캘로 읽는다
    bool ok1 = false, ok2 = false;
    double v1 = QLocale(QLocale::German).toDouble("1.234,5", &ok1);
    double v2 = QLocale::c().toDouble("1.234,5", &ok2);
    std::printf("'1.234,5'를 독일 로캘로 %.1f(%s), C 로캘로 %.1f(%s)\n",
                v1, ok1 ? "성공" : "실패", v2, ok2 ? "성공" : "실패");

    // 정렬: 언어마다 사전 순서가 다르다
    QStringList words{"Zebra", "Äpfel", "apple", "Bär", "Österreich"};
    QCollator de(QLocale(QLocale::German));
    QStringList byCode = words, byGerman = words;
    std::sort(byCode.begin(), byCode.end());
    std::sort(byGerman.begin(), byGerman.end(), de);
    std::printf("코드 순서: %s\n", qPrintable(byCode.join(" ")));
    std::printf("독일어 순서: %s\n", qPrintable(byGerman.join(" ")));
}
```

## 형식

- **날짜**: 한국은 "2026년 11월 22일 일요일", 미국은 요일과 월 이름이 앞에, 독일은 "22. November"입니다. `LongFormat`, `ShortFormat`, `NarrowFormat` 중에서 고르면 각 나라의 관례대로 나옵니다. 형식 문자열("yyyy-MM-dd")을 직접 주면 관례를 무시하게 되므로, 파일 이름이나 기록용이 아니라면 쓰지 않습니다
- **숫자**: 천 단위 구분자와 소수점이 나라마다 다릅니다. 독일은 "1.234.567,5", 이집트 아랍어는 아라비아-인도 숫자까지 다릅니다
- **통화**: `toCurrencyString`은 기호의 위치와 소수 자릿수까지 맞춥니다. 원화는 보조 단위를 쓰지 않아 반올림된 "₩1,234,568"이 되었습니다
- **첫 요일**: 한국과 미국은 일요일, 독일은 월요일, 이집트는 토요일입니다. 달력 위젯을 직접 그릴 때 맞춰야 합니다

## 입력 읽기

사용자가 쓴 숫자는 **그 사용자의 로캘로** 읽어야 합니다. 독일 사용자가 "1.234,5"라고 쓰면 독일 로캘로는 1234.5지만, C 로캘(또는 `std::stod`)로 읽으면 실패하거나 엉뚱한 수가 됩니다. 반대로 파일 형식, 설정, 네트워크 프로토콜에 쓰는 숫자는 사용자 로캘과 상관없이 언제나 `QLocale::c()`로 쓰고 읽어야, 독일에서 저장한 파일을 한국에서 열 수 있습니다.

## 글 방향과 정렬

- 아랍어와 히브리어는 **오른쪽에서 왼쪽**(RTL)으로 씁니다. Qt 위젯과 Qt Quick은 앱의 레이아웃 방향을 RTL로 바꾸면 레이아웃, 메뉴, 스크롤 막대를 거울처럼 뒤집습니다(`QGuiApplication::setLayoutDirection`). 그래서 레이아웃을 "왼쪽, 오른쪽"이 아니라 "시작, 끝"으로 생각해 두면 좋습니다
- **정렬**: 문자열을 코드 값으로 정렬하면 대문자가 소문자보다, "Ä"가 "Z"보다 뒤에 갑니다. `QCollator`에 로캘을 주면 그 언어의 사전 순서로 비교합니다. 독일어 순서에서는 Ä가 A와 함께, Ö가 O와 함께 섰습니다. 한글은 유니코드 순서가 가나다순이라 큰 문제가 없지만, 영문과 섞이거나 숫자를 자연스러운 순서("2"가 "10"보다 앞)로 정렬하려면 `setNumericMode(true)`를 켠 `QCollator`가 필요합니다

<Note>
`QLocale::system()`은 운영체제에서 사용자가 고른 지역 설정을 돌려주고, 아무것도 지정하지 않은 `QLocale()`는 `QLocale::setDefault()`로 정한 기본값(처음에는 시스템 로캘)입니다. 앱에서 언어를 따로 고르게 한다면, 번역 파일을 불러오는 것과 함께 `setDefault`도 바꿔 형식이 언어와 맞게 합니다.
</Note>

## 정리

- QLocale은 날짜, 숫자, 통화, 첫 요일, 글 방향 같은 나라별 관례를 CLDR 데이터로 알려 준다
- 사용자 입력은 사용자의 로캘로 읽고, 파일과 프로토콜의 숫자는 언제나 C 로캘로 쓰고 읽는다
- RTL 언어를 위해 레이아웃을 시작과 끝으로 생각하고, 사람에게 보이는 정렬은 QCollator로 한다
