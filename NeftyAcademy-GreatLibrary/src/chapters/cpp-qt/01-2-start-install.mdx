Qt를 설치하는 길은 여럿입니다. 무엇을 고르든 결과는 같습니다. 머리 파일, 라이브러리, 플러그인, 그리고 `moc` 같은 빌드 도구가 어딘가에 놓이고, 빌드 시스템이 그 위치를 알면 됩니다. 이 장은 설치 방법들을 견주고, 설치된 Qt가 어떻게 생겼는지 직접 들여다봅니다.

## 설치 방법

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| Qt 온라인 설치 프로그램 | 원하는 판과 모듈, 안드로이드 등 여러 대상, Qt Creator를 한꺼번에 | Qt 계정이 필요하고 용량이 큼 |
| 리눅스 배포판 패키지 | 명령 하나, 시스템과 잘 맞음 | 배포판이 정한 판에 묶임 |
| Homebrew, vcpkg, Conan | 빌드 스크립트에 판을 적어 재현 가능 | 처음 빌드가 오래 걸릴 수 있음 |
| 소스에서 빌드 | 원하는 설정(정적, 임베디드) 가능 | 몇 시간 걸리고 의존 라이브러리가 많음 |

이 책의 예제 환경은 Ubuntu 24.04의 배포판 패키지입니다.

```text nocheck
$ sudo apt install qt6-base-dev qt6-declarative-dev qt6-tools-dev
```

macOS에서는 `brew install qt`, Windows에서는 공식 설치 프로그램이나 `vcpkg install qtbase`가 흔한 선택입니다. 여러 Qt 판을 오가며 테스트해야 하거나 안드로이드, iOS용 빌드가 필요하다면 공식 설치 프로그램이 가장 편합니다.

## 설치된 Qt 들여다보기

```cpp qt
#include <QCoreApplication>
#include <QLibraryInfo>
#include <cstdio>

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    struct { const char* what; QLibraryInfo::LibraryPath p; } rows[] = {
        {"머리 파일", QLibraryInfo::HeadersPath},
        {"라이브러리", QLibraryInfo::LibrariesPath},
        {"도구(designer, lupdate…)", QLibraryInfo::BinariesPath},
        {"내부 도구(moc, rcc, uic)", QLibraryInfo::LibraryExecutablesPath},
        {"QML 모듈", QLibraryInfo::QmlImportsPath},
    };
    for (auto& r : rows)
        std::printf("%s\n  %s\n", r.what, qPrintable(QLibraryInfo::path(r.p)));
}
```

```text
머리 파일
  /usr/include/x86_64-linux-gnu/qt6
라이브러리
  /usr/lib/x86_64-linux-gnu
도구(designer, lupdate…)
  /usr/lib/qt6/bin
내부 도구(moc, rcc, uic)
  /usr/lib/qt6/libexec
QML 모듈
  /usr/lib/x86_64-linux-gnu/qt6/qml
```

`QLibraryInfo`는 지금 링크된 Qt가 자기 파일들을 어디에 두었는지 알려 줍니다. 공식 설치 프로그램으로 설치했다면 이 경로들이 모두 `~/Qt/6.12.0/gcc_64/` 같은 한 폴더 아래에 모여 있습니다. 명령줄에서는 `qtpaths --query`로 같은 정보를 볼 수 있습니다.

- **내부 도구**: `moc`(메타 객체 컴파일러), `rcc`(자원 컴파일러), `uic`(UI 파일 변환기)는 빌드 시스템이 부르는 도구라서 직접 실행할 일이 드뭅니다. 다음 장들에서 하나씩 무엇을 하는지 봅니다
- **사용자 도구**: Qt Designer(위젯 화면 편집기), Qt Linguist와 `lupdate`·`lrelease`(번역), `qmllint`·`qmlformat`(QML 검사와 정리) 같은 것들입니다

## Qt Creator

Qt Creator는 Qt 회사가 만드는 IDE로, CMake 프로젝트를 열면 Qt 판 선택(키트), 빌드, 디버거, 위젯 디자이너, QML 편집과 미리 보기, QML 프로파일러가 한곳에 묶여 나옵니다. Qt를 처음 배운다면 가장 덜 헤매는 길입니다. 하지만 Qt 프로젝트는 그냥 CMake 프로젝트이므로 Visual Studio(Qt VS Tools 확장), VS Code(CMake 확장), CLion에서도 그대로 열립니다. 이 책은 어느 편집기에도 기대지 않고 [「CMake로 프로젝트 만들기」](#/read/cpp-qt/start-cmake)의 명령줄 빌드를 기준으로 설명합니다.

<Note>
Windows에서는 Qt를 빌드한 컴파일러와 앱을 빌드하는 컴파일러가 맞아야 합니다. MSVC 2022용으로 빌드된 Qt에 MinGW로 링크하면 실패합니다. 공식 설치 프로그램은 "MSVC 2022 64-bit", "MinGW 64-bit"처럼 컴파일러별로 따로 받게 되어 있으니, 쓰는 컴파일러와 같은 것을 고르세요.
</Note>

## 정리

- Qt는 공식 설치 프로그램, 배포판 패키지, 패키지 관리자, 소스 빌드로 설치하며, 여러 판과 대상이 필요하면 공식 설치 프로그램이 편하다
- 설치된 Qt는 머리 파일, 라이브러리, 플러그인, QML 모듈과 moc·rcc·uic 같은 빌드 도구로 이루어지고, QLibraryInfo나 qtpaths로 위치를 볼 수 있다
- Qt Creator가 가장 편한 출발점이지만 Qt 프로젝트는 CMake 프로젝트라서 어느 편집기에서든 열린다
