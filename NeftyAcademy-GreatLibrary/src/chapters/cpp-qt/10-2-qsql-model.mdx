[「연결과 쿼리」](#/read/cpp-qt/qsql-connect)에서는 결과를 한 줄씩 꺼내 출력했습니다. 화면에 표로 보여 주고 편집까지 하려면, 데이터베이스를 [「모델 인터페이스」](#/read/cpp-qt/mv-model)의 모델로 감싸 뷰에 꽂으면 됩니다. Qt SQL은 이를 위한 모델 세 가지를 제공합니다. `QTableView`에 그대로 넣으면 머리글, 정렬, 편집이 다 따라옵니다.

## 세 가지 모델

```cpp qt=Sql
#include <QCoreApplication>
#include <QSqlDatabase>
#include <QSqlQuery>
#include <QSqlQueryModel>
#include <QSqlRelationalTableModel>
#include <QSqlTableModel>
#include <cstdio>

void dump(const char* title, QAbstractItemModel* m) {
    std::printf("%s:", title);
    for (int r = 0; r < m->rowCount(); ++r) {
        QStringList cells;
        for (int c = 0; c < m->columnCount(); ++c)
            cells << m->index(r, c).data().toString();
        std::printf(" [%s]", qPrintable(cells.join(" ")));
    }
    std::printf("\n");
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE");
    db.setDatabaseName(":memory:");
    db.open();
    QSqlQuery q;
    q.exec("CREATE TABLE shelves(id INTEGER PRIMARY KEY, name TEXT)");
    q.exec("INSERT INTO shelves VALUES (1, 'C++'), (2, '파이썬')");
    q.exec("CREATE TABLE books("
           "id INTEGER PRIMARY KEY, title TEXT, pages INT, shelf INT)");
    q.exec("INSERT INTO books(title, pages, shelf) VALUES "
           "('Qt', 59, 1), ('STL', 40, 1), ('넘파이', 18, 2)");

    // 1) 읽기 전용: SELECT 결과를 그대로 모델로
    QSqlQueryModel query;
    query.setQuery(
        "SELECT title, pages FROM books WHERE pages > 30 ORDER BY title");
    dump("쿼리 모델", &query);

    // 2) 표 하나를 편집하는 모델: 바꾼 것을 모았다가 한 번에 저장
    QSqlTableModel table;
    table.setTable("books");
    table.setEditStrategy(QSqlTableModel::OnManualSubmit);
    table.setSort(1, Qt::AscendingOrder);        // title 순
    table.select();
    // Qt의 쪽수 59 -> 60(아직 화면에만)
    table.setData(table.index(0, 2), 60);
    int row = table.rowCount();
    table.insertRow(row);
    table.setData(table.index(row, 1), "QML");
    table.setData(table.index(row, 2), 12);
    table.setData(table.index(row, 3), 1);
    q.exec("SELECT pages FROM books WHERE title='Qt'");
    q.next();
    std::printf("저장 전 데이터베이스의 Qt 쪽수: %d\n", q.value(0).toInt());
    // 여기서 UPDATE와 INSERT가 실행된다
    table.submitAll();
    q.exec("SELECT pages FROM books WHERE title='Qt'");
    q.next();
    std::printf("submitAll 뒤: %d, 책 수 %d\n",
                q.value(0).toInt(), table.rowCount());

    // 3) 외래 키를 이름으로 보여 주는 관계 모델
    QSqlRelationalTableModel rel;
    rel.setTable("books");
    rel.setRelation(3, QSqlRelation("shelves", "id", "name"));  // shelf -> 이름
    rel.setSort(1, Qt::AscendingOrder);
    rel.select();
    dump("관계 모델", &rel);
}
```

```text
쿼리 모델: [Qt 59] [STL 40]
저장 전 데이터베이스의 Qt 쪽수: 59
submitAll 뒤: 60, 책 수 4
관계 모델: [4 QML 12 C++] [1 Qt 60 C++] [2 STL 40 C++] [3 넘파이 18 파이썬]
```

## QSqlQueryModel: 읽기 전용

아무 SELECT 문이나 모델로 만듭니다. 조인, 집계, 계산 열이 섞인 보고서 화면에 적합합니다. 행이 많으면 필요한 만큼만 가져오다가(`fetchMore`) 스크롤에 맞춰 더 가져오므로, [「리스트, 테이블, 트리」](#/read/cpp-qt/mv-views)에서 본 "보이는 것만" 원칙이 데이터베이스까지 이어집니다.

## QSqlTableModel: 표 하나를 편집

- `setTable("books")`과 `select()`로 표 전체를 읽고, `setSort`로 정렬하고, `setFilter("pages > 30")`처럼 WHERE 조건을 줍니다
- 칸을 고치면(`setData`) 모델이 UPDATE 문을, 행을 넣으면 INSERT 문을 만들어 실행합니다. SQL을 직접 쓰지 않아도 됩니다
- **편집 전략**이 언제 저장할지를 정합니다. `OnFieldChange`는 칸을 바꿀 때마다, `OnRowChange`는 다른 행으로 옮길 때, `OnManualSubmit`은 `submitAll()`을 부를 때 저장합니다. 예제는 수동 저장이라, 쪽수를 60으로 바꾸고 QML 책을 넣은 뒤에도 데이터베이스에는 59가 그대로였고, `submitAll()` 뒤에야 60이 되었습니다. "저장"과 "취소"(`revertAll()`) 단추가 있는 편집 화면에 맞습니다. `submitAll`을 거래로 감싸면 여러 줄 변경이 한꺼번에 반영되거나 한꺼번에 취소됩니다

## QSqlRelationalTableModel: 외래 키를 이름으로

`books.shelf`에는 1, 2 같은 책장 번호가 들어 있습니다. `setRelation(3, QSqlRelation("shelves", "id", "name"))`으로 "3열은 shelves 표의 id를 가리키고, 보여 줄 때는 name을 써라"고 알려 주자, 모델이 조인을 만들어 "C++", "파이썬"으로 보여 주었습니다. 뷰에 `QSqlRelationalDelegate`를 붙이면 그 칸을 편집할 때 책장 이름 콤보 상자가 뜹니다.

<Note>
모델은 편리하지만 무엇을 실행하는지 숨깁니다. 표가 크거나 조건이 복잡해지면 생성된 SQL이 비효율적일 수 있고, 여러 사람이 동시에 쓰는 서버 데이터베이스에서는 "읽은 뒤 남이 바꾼" 충돌을 직접 다뤄야 합니다. 그럴 때는 읽기에는 `QSqlQueryModel`이나 직접 만든 모델을, 쓰기에는 명시적인 `QSqlQuery`와 거래를 쓰는 편이 예측 가능합니다.
</Note>

## 정리

- QSqlQueryModel은 아무 SELECT 결과를 읽기 전용 모델로, QSqlTableModel은 표 하나를 편집 가능한 모델로 만든다
- 편집 전략으로 저장 시점을 정하며, 수동 저장은 submitAll과 revertAll로 저장과 취소를 한다
- QSqlRelationalTableModel은 외래 키를 연결된 표의 이름으로 보여 주고 편집하게 한다
