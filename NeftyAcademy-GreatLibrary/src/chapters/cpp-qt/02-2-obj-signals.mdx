버튼은 눌렸다는 사실만 알리고, 누가 그것을 듣는지는 모릅니다. 듣는 쪽도 버튼의 내부를 모릅니다. 둘을 잇는 것은 바깥의 `connect` 한 줄입니다. 이 **시그널과 슬롯**은 관찰자 패턴을 언어처럼 쓰게 해 주는 Qt의 핵심입니다. 보내는 쪽과 받는 쪽이 서로의 머리 파일을 포함하지 않아도 되므로, 큰 앱을 조각으로 나누기 쉬워집니다.

## 센서 하나, 화면 둘

```cpp qt
#include <QCoreApplication>
#include <QObject>
#include <QTimer>
#include <cstdio>

class Sensor : public QObject {
    Q_OBJECT
public:
    void measure(int v) { emit reading(v); }
signals:
    void reading(int value);
    void alarm(const QString& why);
};

class Display : public QObject {
    Q_OBJECT
public:
    explicit Display(const char* n) : name(n) {}
public slots:
    void show(int v) { std::printf("  [%s] %d\n", name, v); }
private:
    const char* name;
};

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    Sensor s;
    Display a("화면A");
    auto* b = new Display("화면B");

    // 1) 멤버 함수 포인터: 컴파일 시간에 시그니처를 검사한다
    QObject::connect(&s, &Sensor::reading, &a, &Display::show);
    QObject::connect(&s, &Sensor::reading, b, &Display::show);
    // 2) 람다 + 문맥 객체: 문맥(&a)이 사라지면 연결도 사라진다
    auto conn = QObject::connect(&s, &Sensor::reading, &a, [](int v) {
        if (v > 30) std::printf("  [람다] 너무 높음 %d\n", v);
    });
    // 3) 시그널을 시그널에 잇기
    QObject::connect(&s, &Sensor::reading, &s, [&s](int v) {
        if (v > 40) emit s.alarm(QString("값 %1").arg(v));
    });
    QObject::connect(&s, &Sensor::alarm, [](const QString& w) {
        std::printf("  [경보] %s\n", qPrintable(w));
    });

    std::printf("측정 25\n"); s.measure(25);
    std::printf("측정 45\n"); s.measure(45);

    delete b;                                      // 받는 쪽이 사라지면
    QObject::disconnect(conn);                     // 연결 하나만 끊기
    std::printf("화면B 삭제, 람다 연결 끊음, 측정 35\n"); s.measure(35);

    // 4) 같은 연결을 두 번 하면 두 번 불린다(UniqueConnection으로 막는다)
    QObject::connect(&s, &Sensor::reading, &a, &Display::show,
                     Qt::UniqueConnection);
    std::printf("중복 연결 시도 뒤 측정 10\n"); s.measure(10);
}
#include "main.moc"
```

  [화면A] 35

  [화면A] 10

## 잇는 방법

- **멤버 함수 포인터** `connect(&s, &Sensor::reading, &a, &Display::show)`: Qt 5부터의 기본 문법입니다. 시그널과 슬롯의 인자 타입이 맞지 않으면 **컴파일 오류**가 납니다. 슬롯은 시그널보다 인자가 적어도 됩니다(뒤의 것을 버림)
- **람다**: 짧은 반응은 슬롯 함수를 따로 만들지 않고 람다로 씁니다. 이때 세 번째 인자로 **문맥 객체**(`&a`)를 주는 습관이 중요합니다. 람다가 그 객체를 쓰는 경우, 문맥 객체가 소멸하면 연결도 함께 끊어져서 죽은 객체를 건드리지 않습니다
- **시그널에서 시그널로**: 슬롯 자리에 다른 시그널을 두거나, 예제처럼 조건에 따라 다른 시그널을 내보내 사건을 한 단계 위로 올려 보낼 수 있습니다
- **옛 문자열 문법** `connect(&s, SIGNAL(reading(int)), &a, SLOT(show(int)))`도 아직 동작하지만, 오타가 실행 중 경고로만 나타나므로 새 코드에서는 쓰지 않습니다

## 끊기

- 받는 쪽 `화면B`를 `delete`하자 그 연결은 **저절로** 사라졌습니다. 소멸하는 QObject는 자기에게 들어온 연결을 모두 정리합니다. 그래서 대부분의 경우 `disconnect`를 직접 부를 일이 없습니다
- 특정 연결만 끊고 싶으면 `connect`가 돌려준 `QMetaObject::Connection`을 보관했다가 `disconnect(conn)`합니다
- 같은 `connect`를 두 번 하면 슬롯도 두 번 불립니다. 초기화 코드가 여러 번 도는 구조라면 `Qt::UniqueConnection`을 주어 이미 같은 연결이 있으면 무시하게 합니다. 마지막 측정에서 화면A가 한 번만 찍힌 이유입니다

<Note>
여기서 슬롯은 모두 `emit` 순간에 **바로**, 같은 스레드에서 불렸습니다(직접 연결). 보내는 객체와 받는 객체가 서로 다른 스레드에 살면 Qt는 자동으로 큐 연결로 바꿔, 받는 쪽 스레드의 이벤트 루프에서 나중에 부릅니다. 이 차이는 [「스레드를 건너는 시그널」](#/read/cpp-qt/qthr-signals)에서 다룹니다. 이름이 같은 시그널이 여러 개로 오버로드되어 있으면(`QSpinBox::valueChanged` 같은 옛 API) `qOverload<int>(&QSpinBox::valueChanged)`처럼 어느 것인지 골라 줘야 합니다.
</Note>

## 정리

- 시그널은 사건을 알리기만 하고 받는 쪽을 모르며, connect가 바깥에서 둘을 잇는다
- 멤버 함수 포인터 문법은 타입을 컴파일 시간에 검사하고, 람다에는 문맥 객체를 주어 수명에 맞게 끊기게 한다
- 받는 객체가 소멸하면 연결은 저절로 끊기고, 특정 연결은 Connection으로 끊으며, 중복은 UniqueConnection으로 막는다
