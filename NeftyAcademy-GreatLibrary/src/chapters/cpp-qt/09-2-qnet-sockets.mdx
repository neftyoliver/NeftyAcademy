HTTP 위의 API가 아니라 장치나 게임 서버와 직접 이야기해야 할 때는 소켓을 씁니다. Qt의 소켓도 [「HTTP 요청」](#/read/cpp-qt/qnet-http)처럼 막히지 않습니다. 연결되면 `connected`, 데이터가 오면 `readyRead` 시그널이 오고, 우리는 그때 와 있는 만큼 읽습니다. 이 "와 있는 만큼"이 TCP 소켓 프로그래밍의 핵심 문제입니다.

## 대문자로 돌려주는 서버, 그리고 UDP

```cpp qt=Network
#include <QCoreApplication>
#include <QDataStream>
#include <QNetworkDatagram>
#include <QTcpServer>
#include <QTcpSocket>
#include <QUdpSocket>
#include <cstdio>

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);

    // ---- TCP: 바이트의 흐름. 메시지 경계는 우리가 정해야 한다 ----
    QTcpServer server;
    server.listen(QHostAddress::LocalHost, 0);
    QObject::connect(&server, &QTcpServer::newConnection, [&] {
        QTcpSocket* peer = server.nextPendingConnection();
        auto* in = new QDataStream(peer);
        QObject::connect(peer, &QTcpSocket::readyRead, peer, [peer, in] {
            for (;;) {                           // 와 있는 만큼 메시지를 꺼낸다
                in->startTransaction();          // 읽다가 모자라면 되돌린다
                QString msg;
                *in >> msg;                      // 길이 + 내용으로 저장된 문자열
                // 덜 왔으면 다음 readyRead에
                if (!in->commitTransaction()) return;
                QByteArray reply;
                QDataStream out(&reply, QIODevice::WriteOnly);
                out << msg.toUpper();
                peer->write(reply);
            }
        });
        QObject::connect(peer, &QTcpSocket::disconnected, peer, [peer, in] {
            delete in;
            peer->deleteLater();
        });
    });

    QTcpSocket client;
    QDataStream cin(&client);
    QStringList got;
    QObject::connect(&client, &QTcpSocket::connected, [&] {
        QByteArray batch;                        // 세 메시지를 한 번에 써 보낸다
        QDataStream out(&batch, QIODevice::WriteOnly);
        out << QString("hello") << QString("qt") << QString("sockets");
        // 일부러 잘라서 두 번에 나눠 보낸다
        client.write(batch.left(7));
        client.flush();
        client.write(batch.mid(7));
    });
    QObject::connect(&client, &QTcpSocket::readyRead, [&] {
        for (;;) {
            cin.startTransaction();
            QString msg;
            cin >> msg;
            if (!cin.commitTransaction()) return;
            got << msg;
            if (got.size() == 3) {
                std::printf("TCP 답: %s\n", qPrintable(got.join(" ")));
                client.disconnectFromHost();
            }
        }
    });
    QObject::connect(&client, &QTcpSocket::disconnected, &app, [&] {
        // ---- UDP: 데이터그램 하나가 그대로 한 덩어리, 도착은 보장 안 됨 ----
        auto* rx = new QUdpSocket(&app);
        rx->bind(QHostAddress::LocalHost, 0);
        QObject::connect(rx, &QUdpSocket::readyRead, [rx, &app] {
            while (rx->hasPendingDatagrams()) {
                QNetworkDatagram d = rx->receiveDatagram();
                std::printf("UDP 받음: '%s' (%lld바이트)\n", d.data().constData(),
                            (long long)d.data().size());
                if (d.data() == "끝") app.quit();
            }
        });
        QUdpSocket tx;
        for (const char* m : {"위치 3,4", "위치 5,4", "끝"})
            tx.writeDatagram(QByteArray(m), QHostAddress::LocalHost,
                             rx->localPort());
    });
    client.connectToHost(QHostAddress::LocalHost, server.serverPort());
    return app.exec();
}
```

```text
TCP 답: HELLO QT SOCKETS
UDP 받음: '위치 3,4' (10바이트)
UDP 받음: '위치 5,4' (10바이트)
UDP 받음: '끝' (3바이트)
```

## TCP는 흐름이다

TCP는 바이트가 순서대로, 빠짐없이 도착하는 것을 보장하지만 **메시지의 경계는 지키지 않습니다**. 세 번 `write`한 것이 한 번의 `readyRead`로 올 수도 있고, 한 번 쓴 것이 두 번에 나뉘어 올 수도 있습니다. 예제는 일부러 세 메시지를 묶은 바이트를 7바이트에서 잘라 두 번에 보냈습니다.

그래서 메시지마다 **길이**를 앞에 붙이는 등의 경계 규칙이 필요합니다. `QDataStream`에 `QString`을 쓰면 길이와 내용이 함께 저장되므로, 읽는 쪽은 길이만큼 다 왔는지 알 수 있습니다.

- `startTransaction()`으로 읽기를 시작하고, `>>`로 메시지 하나를 읽은 뒤, `commitTransaction()`이 거짓이면 **아직 덜 온 것**이라 읽은 위치를 되돌립니다. 다음 `readyRead`에서 처음부터 다시 시도합니다
- 한 번의 `readyRead`에 여러 메시지가 와 있을 수 있으므로 반복문으로 다 꺼냅니다

잘려서 온 데이터를 서버가 제대로 모아 "HELLO QT SOCKETS"를 돌려주었습니다. 직접 정한 이진 형식이나 줄 단위 글 형식(`canReadLine()`과 `readLine()`)에도 같은 원칙이 적용됩니다.

## 서버와 연결 정리

- `QTcpServer::listen(주소, 0)`은 비어 있는 포트를 아무거나 골라 기다립니다. 실제 서버는 정해진 포트를 씁니다
- 새 연결은 `newConnection`에서 `nextPendingConnection()`으로 꺼냅니다. 연결마다 소켓 객체가 하나씩 생기고, 끊기면(`disconnected`) `deleteLater`로 정리합니다
- 연결마다 상태(받다 만 데이터, 로그인 정보)가 필요하면 연결 하나를 맡는 작은 QObject 클래스를 만들어 소켓과 함께 관리하는 것이 깔끔합니다

## UDP는 소포다

`QUdpSocket`은 **데이터그램** 단위로 주고받습니다. 한 번 보낸 것은 한 덩어리로 도착하므로 경계 문제는 없지만, 대신 **도착도 순서도 보장되지 않습니다**. 이 예제는 같은 기계 안이라 셋이 다 순서대로 왔지만, 실제 네트워크에서는 사라지거나 뒤바뀔 수 있습니다. 게임의 위치 정보처럼 늦게 온 옛 값은 버려도 되는 데이터, 장치 찾기 같은 방송(broadcast)에 씁니다. 받는 쪽은 `bind`로 포트를 열고, `readyRead`마다 `hasPendingDatagrams()`가 참인 동안 `receiveDatagram()`으로 꺼냅니다.

<Note>
`QDataStream`의 형식은 Qt 판에 따라 바뀔 수 있으므로, Qt가 아닌 프로그램이나 다른 Qt 판과 주고받는다면 `setVersion(QDataStream::Qt_6_0)`처럼 판을 고정하거나 JSON, CBOR, 직접 정한 형식을 쓰세요. 암호화가 필요하면 `QSslSocket`이 같은 인터페이스로 TLS를 제공합니다.
</Note>

## 정리

- Qt 소켓은 막히지 않으며 connected와 readyRead 시그널이 올 때 와 있는 만큼 읽는다
- TCP는 경계 없는 바이트 흐름이므로 길이를 붙이는 등 메시지 경계를 정하고, QDataStream의 거래 읽기로 덜 온 메시지를 기다린다
- UDP는 데이터그램 단위라 경계는 지켜지지만 도착과 순서가 보장되지 않아, 잃어도 되는 데이터와 방송에 쓴다
