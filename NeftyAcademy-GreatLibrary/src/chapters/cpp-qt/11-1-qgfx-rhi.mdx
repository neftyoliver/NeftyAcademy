Qt 6의 Qt Quick은 OpenGL에 묶여 있던 Qt 5와 달리, 플랫폼에 맞는 그래픽 API를 골라 씁니다. Windows에서는 Direct3D, macOS와 iOS에서는 Metal, 리눅스와 안드로이드에서는 Vulkan이나 OpenGL입니다. 이것을 가능하게 하는 것이 **RHI**(Rendering Hardware Interface)입니다. [「그래픽 API 감싸기」](#/read/cpp-game-engine/rend-abstraction)에서 게임 엔진이 하는 일을 Qt가 직접 한 것입니다.

## 오프스크린 프레임 하나

RHI로 64×64 텍스처를 하늘색으로 지우고, 그 결과를 CPU로 읽어 왔습니다.

```cpp qt=Gui xvfb flags=-I/usr/include/x86_64-linux-gnu/qt6/QtGui/6.4.2,-I/usr/include/x86_64-linux-gnu/qt6/QtGui/6.4.2/QtGui,-I/usr/include/x86_64-linux-gnu/qt6/QtCore/6.4.2,-I/usr/include/x86_64-linux-gnu/qt6/QtCore/6.4.2/QtCore
#include <QGuiApplication>
#include <QVulkanInstance>
#include <QtGui/private/qrhi_p.h>          // Qt 6.6부터는 <rhi/qrhi.h>
#include <QtGui/private/qrhivulkan_p.h>
#include <cstdio>
#include <memory>

int main(int argc, char** argv) {
    QGuiApplication app(argc, argv);

    // 1) 백엔드 고르기: 여기서는 Vulkan(이 환경은 Mesa의 소프트웨어 구현)
    QVulkanInstance vk;
    vk.setApiVersion(QVersionNumber(1, 1));
    vk.setExtensions(QRhiVulkanInitParams::preferredInstanceExtensions());
    if (!vk.create()) { std::printf("Vulkan 인스턴스 실패\n"); return 1; }
    QRhiVulkanInitParams params;
    params.inst = &vk;
    std::unique_ptr<QRhi> rhi(QRhi::create(QRhi::Vulkan, &params));
    if (!rhi) { std::printf("QRhi 만들기 실패\n"); return 1; }
    std::printf("백엔드 %s\n", rhi->backendName());

    // 2) 자원: 64x64 텍스처를 그리기 대상으로
    auto flags = QRhiTexture::RenderTarget | QRhiTexture::UsedAsTransferSource;
    std::unique_ptr<QRhiTexture> tex(
        rhi->newTexture(QRhiTexture::RGBA8, QSize(64, 64), 1, flags));
    tex->create();
    std::unique_ptr<QRhiTextureRenderTarget> rt(
        rhi->newTextureRenderTarget({tex.get()}));
    std::unique_ptr<QRhiRenderPassDescriptor> rp(
        rt->newCompatibleRenderPassDescriptor());
    rt->setRenderPassDescriptor(rp.get());
    rt->create();

    // 3) 한 프레임: 명령을 기록하고 제출한다
    QRhiCommandBuffer* cb = nullptr;
    rhi->beginOffscreenFrame(&cb);
    QRhiReadbackResult result;
    QRhiResourceUpdateBatch* u = rhi->nextResourceUpdateBatch();
    // 패스가 끝난 뒤 CPU로 읽어 온다
    u->readBackTexture({tex.get()}, &result);
    cb->beginPass(rt.get(), QColor::fromRgbF(0.2f, 0.6f, 1.0f), {1.0f, 0});
    // (실제로는 여기서 파이프라인을 설정하고 draw 호출을 기록한다)
    cb->endPass(u);
    rhi->endOffscreenFrame();                          // 제출하고 GPU가 끝날 때까지

    const uchar* px = reinterpret_cast<const uchar*>(result.data.constData());
    std::printf("읽어 온 %dx%d, 첫 화소 RGBA = %d %d %d %d\n",
                result.pixelSize.width(), result.pixelSize.height(),
                px[0], px[1], px[2], px[3]);
}
```

```text
백엔드 Vulkan
읽어 온 64x64, 첫 화소 RGBA = 51 153 255 255
```

이 예제는 GPU 없는 환경에서 Mesa의 소프트웨어 Vulkan 구현(lavapipe)과 가상 X 서버(Xvfb)로 실행했습니다. 화면 없는 `offscreen` 플랫폼 플러그인은 Vulkan을 지원하지 않아서 이 예제만 xcb 플랫폼을 썼습니다. 지운 색 (0.2, 0.6, 1.0)이 8비트로 (51, 153, 255)가 되어 돌아왔습니다.

## 그래픽 API의 공통분모

RHI의 객체들은 현대 그래픽 API의 공통 개념을 그대로 따릅니다.

- **QRhi**: 장치 하나. `QRhi::create(QRhi::Vulkan, &params)`처럼 백엔드를 골라 만듭니다. 같은 코드에 `QRhi::Metal`, `QRhi::D3D11`, `QRhi::OpenGLES2`를 넣으면 다른 API로 돕니다. 시험용으로 아무것도 그리지 않는 `QRhi::Null`도 있습니다
- **자원**: `QRhiBuffer`(정점, 인덱스, 유니폼), `QRhiTexture`, `QRhiSampler`, `QRhiTextureRenderTarget`
- **파이프라인**: `QRhiGraphicsPipeline`에 셰이더, 정점 형식, 블렌딩, 깊이 검사 같은 상태를 미리 묶어 둡니다. `QRhiShaderResourceBindings`가 셰이더에 버퍼와 텍스처를 연결합니다
- **명령**: `beginOffscreenFrame`(창이 있으면 `beginFrame`)으로 `QRhiCommandBuffer`를 받아, 패스를 열고 그리기 명령을 기록하고 제출합니다. 자원 갱신과 읽어 오기는 `QRhiResourceUpdateBatch`에 모아 패스에 넘깁니다

## 셰이더는 한 번 쓰고 여러 형식으로

API마다 셰이더 언어가 다릅니다(SPIR-V, HLSL, MSL, GLSL). RHI는 셰이더를 Vulkan식 GLSL로 한 번 쓰고, **qsb** 도구로 모든 형식을 담은 `.qsb` 파일을 만들게 합니다.

```text nocheck
$ qsb --glsl "100 es,120,150" --hlsl 50 --msl 12 -o color.frag.qsb color.frag
$ qsb -d color.frag.qsb
Stage: Fragment
QSB_VERSION: 6
Has 6 shaders: (unordered list)
  Shader 0: GLSL 100 es [Standard]
  Shader 1: MSL 12 [Standard]
  Shader 2: HLSL 50 [Standard]
  Shader 3: SPIR-V 100 [Standard]
  Shader 4: GLSL 150 [Standard]
  Shader 5: GLSL 120 [Standard]
```

`.qsb`에는 입력·출력·유니폼 같은 **반사 정보**도 들어 있어서 RHI가 바인딩을 맞춥니다. CMake에서는 `qt_add_shaders()`로 빌드할 때 자동으로 만들고 자원에 넣습니다. Qt Quick의 `ShaderEffect`에 쓰는 셰이더도 같은 방식입니다.

<Note>
RHI는 Qt 6.6부터 공개 API(`#include <rhi/qrhi.h>`, `Qt6::GuiPrivate`)가 되었지만, Qt 문서는 이 클래스들에 **소스·이진 호환성 보장이 없다**고 밝힙니다. 빌드한 Qt 판에서만 동작이 보장되고, 부 판이 바뀔 때 고쳐야 할 수 있습니다. 이 예제는 6.4라서 더 이전의 비공개 머리 파일 `QtGui/private/qrhi_p.h`를 썼습니다. 대부분의 앱은 RHI를 직접 쓰지 않고, [「Qt Quick 3D」](#/read/cpp-qt/qgfx-quick3d)나 Qt Quick을 통해 간접적으로 씁니다. Qt Quick이 어느 API를 쓰는지는 `QSG_INFO=1` 환경 변수로 실행하면 로그에 나옵니다.
</Note>

## 정리

- RHI는 Vulkan, Metal, Direct3D, OpenGL을 하나의 API로 감싸 Qt Quick이 플랫폼에 맞는 그래픽 API를 쓰게 한다
- QRhi 장치, 버퍼·텍스처 자원, 파이프라인, 명령 버퍼라는 현대 그래픽 API의 공통 개념으로 이루어진다
- 셰이더는 Vulkan식 GLSL로 한 번 쓰고 qsb로 모든 형식과 반사 정보를 담은 .qsb를 만들며, RHI 직접 사용은 호환성 보장이 약하다
