검색 칸에 글을 치면 목록이 좁혀지고, 머리글을 누르면 정렬되는 화면을 만들고 싶을 때, 모델의 데이터를 직접 정렬하거나 지우면 안 됩니다. 원본 순서가 필요한 다른 화면이 있을 수 있고, 걸러낸 항목도 데이터로는 남아 있어야 하기 때문입니다. **프록시 모델**은 원본 모델과 뷰 사이에 끼어, 원본은 그대로 둔 채 **보는 방식만** 바꿉니다. 뷰에게는 프록시가 보통의 모델처럼 보입니다.

## 과일 재고

```cpp qt=Gui
#include <QCoreApplication>
#include <QRegularExpression>
#include <QSortFilterProxyModel>
#include <QStandardItemModel>
#include <cstdio>

// 이름 걸러내기에 더해 "재고 있는 것만" 조건을 덧붙인 프록시
class StockFilter : public QSortFilterProxyModel {
public:
    bool onlyInStock = false;
    void setOnlyInStock(bool on) {
        onlyInStock = on;
        invalidateFilter();                     // 조건이 바뀌었으니 다시 걸러라
    }
protected:
    bool filterAcceptsRow(int row, const QModelIndex& parent) const override {
        if (onlyInStock) {
            int qty = sourceModel()->index(row, 1, parent).data().toInt();
            if (qty == 0) return false;
        }
        return QSortFilterProxyModel::filterAcceptsRow(row, parent);  // 글자 조건
    }
};

void dump(const char* title, QAbstractItemModel* m) {
    std::printf("%s:", title);
    for (int r = 0; r < m->rowCount(); ++r)
        std::printf(" %s(%s)", qPrintable(m->index(r, 0).data().toString()),
                    qPrintable(m->index(r, 1).data().toString()));
    std::printf("\n");
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    QStandardItemModel src;
    for (auto [name, qty] : {std::pair{"바나나", 4}, {"사과", 0}, {"블루베리", 12},
                             {"배", 2}, {"복숭아", 0}}) {
        auto* q = new QStandardItem;
        q->setData(qty, Qt::DisplayRole);       // 숫자로 넣어야 숫자로 정렬된다
        src.appendRow({new QStandardItem(name), q});
    }

    StockFilter proxy;
    proxy.setSourceModel(&src);                 // 원본은 그대로, 보는 방식만 바꾼다
    dump("원본", &src);

    proxy.sort(0);                              // 이름순
    dump("이름순", &proxy);
    proxy.sort(1, Qt::DescendingOrder);         // 수량 많은 순
    dump("수량 많은 순", &proxy);

    proxy.setFilterRegularExpression(QRegularExpression("^(바|블)"));
    proxy.setFilterKeyColumn(0);
    dump("'바'나 '블'로 시작", &proxy);
    proxy.setFilterRegularExpression(QString());   // 글자 조건 해제
    proxy.setOnlyInStock(true);
    dump("재고 있는 것만", &proxy);

    // 원본이 바뀌면 프록시가 알아서 다시 정렬·걸러낸다
    src.setData(src.index(1, 1), 30);           // 사과 재고 30
    dump("사과가 입고된 뒤", &proxy);

    // 프록시의 행 번호는 원본과 다르다: 원본에서 고칠 때는 꼭 변환한다
    QModelIndex top = proxy.index(0, 0);
    QModelIndex inSource = proxy.mapToSource(top);
    std::printf("프록시 0행 = 원본 %d행 (%s)\n", inSource.row(),
                qPrintable(inSource.data().toString()));
}
```

이름순: 바나나(4) 배(2) 복숭아(0) 블루베리(12) 사과(0)

사과가 입고된 뒤: 사과(30) 블루베리(12) 바나나(4) 배(2)

## 정렬

`sort(열, 순서)`로 정렬합니다. 뷰에서는 `setSortingEnabled(true)`만 하면 머리글을 누를 때 프록시가 정렬됩니다. 수량을 `setData(4, Qt::DisplayRole)`처럼 **숫자**로 넣었기 때문에 12가 4보다 크게 정렬되었습니다. 글로 넣었다면 "12"가 "4"보다 앞에 오는 사전순이 됩니다. 한글은 유니코드 순서가 가나다순과 같아서 기본 정렬로도 바나나, 배, 복숭아, 블루베리, 사과 순이 되었습니다. 다른 언어의 사전순이 필요하면 `setSortLocaleAware(true)`를 켭니다. 더 복잡한 정렬은 `lessThan`을 재정의합니다.

## 걸러내기

- **정규식**: `setFilterRegularExpression`과 `setFilterKeyColumn`으로 0열이 `^(바|블)`에 맞는 행만 남겼습니다. 검색 칸의 `textChanged`를 여기에 이으면 입력하는 대로 좁혀집니다. 대소문자 구분은 `setFilterCaseSensitivity`로 정합니다
- **사용자 조건**: `filterAcceptsRow`를 재정의해 "재고가 0이면 숨김"을 더했습니다. 조건을 바꾼 뒤에는 `invalidateFilter()`로 다시 걸러 달라고 알려야 합니다. 부모 클래스의 `filterAcceptsRow`를 마지막에 불러 글자 조건과 함께 쓰는 것이 요령입니다

## 원본을 따라간다

사과의 재고를 원본에서 30으로 바꾸자, 숨겨져 있던 사과가 나타나 수량 많은 순 맨 앞에 섰습니다. 프록시는 원본의 `dataChanged`, `rowsInserted` 같은 알림을 듣고 정렬과 걸러내기를 다시 합니다(`dynamicSortFilter`가 기본으로 켜져 있음).

## 행 번호는 다르다

프록시의 0행은 원본의 1행입니다. 뷰에서 사용자가 고른 인덱스는 **프록시의** 인덱스이므로, 원본 데이터를 고치거나 원본 모델의 함수에 넘길 때는 반드시 `mapToSource`로 바꿔야 합니다. 반대 방향은 `mapFromSource`입니다. 이것을 잊으면 정렬하지 않았을 때는 우연히 맞다가, 정렬하는 순간 엉뚱한 행을 지우는 버그가 됩니다.

<Note>
프록시는 겹쳐 쌓을 수 있습니다. 걸러내는 프록시 위에 정렬하는 프록시를 얹는 식입니다. 다만 프록시는 원본의 모든 행에 대한 대응표를 메모리에 갖고 있으므로, 백만 행 모델에 정렬 프록시를 얹으면 [「리스트, 테이블, 트리」](#/read/cpp-qt/mv-views)에서 본 "보이는 행만 묻기"의 장점이 사라집니다. 그런 경우는 데이터베이스 질의의 `ORDER BY`와 `WHERE`로 원본에서 정렬하고 걸러내는 편이 낫습니다.
</Note>

## 정리

- 프록시 모델은 원본과 뷰 사이에 끼어 원본을 바꾸지 않고 정렬과 걸러내기를 한다
- 정렬은 값의 타입대로 되므로 숫자는 숫자로 넣고, 걸러내기는 정규식이나 filterAcceptsRow 재정의로 하며 조건이 바뀌면 다시 걸러 달라고 알린다
- 프록시는 원본의 변화를 따라가며, 프록시와 원본의 인덱스는 mapToSource와 mapFromSource로 바꿔 써야 한다
