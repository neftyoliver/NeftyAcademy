플러그인은 본체의 코드를 고치지 않고 기능을 더합니다. 그러려면 본체가 더할 수 있는 자리를 미리 정해 이름을 붙여 두어야 합니다. 이 자리가 **확장 지점**이고, 플러그인이 거기에 넣는 것이 **기여**입니다. 명령([「실제 프로그램들의 구조」](#/read/cpp-complex-app/ana-cases)), 메뉴 항목, 파일 형식, 도구, 패널이 흔한 확장 지점입니다. 본체가 플러그인의 코드를 돌리기 전에 알아야 할 것과, 플러그인이 겹치거나 실패하거나 꺼질 때의 일을 봅니다.

```cpp
// 확장 지점: 선언만 읽어 표를 만들고, 처음 쓰일 때 플러그인을 깨운다
#include <algorithm>
#include <deque>
#include <functional>
#include <map>
#include <print>
#include <set>
#include <stdexcept>
#include <string>
#include <vector>

struct Host;
using Handler = std::function<std::string()>;
struct Manifest {                            // 코드를 올리지 않고 읽을 수 있는 선언
    std::string id;
    int needs_api;                           // 본체가 이 판 이상이어야 한다
    std::vector<std::string> offers;         // "cmd:filter.blur", "open:png" 따위
    int priority = 0;                        // 같은 것을 여럿이 내놓았을 때
    std::function<void(Host&)> activate;     // 실제 코드. 처음 쓰일 때에만 부른다
};

struct Host {
    static constexpr int kApi = 2;
    std::deque<Manifest> plugins;
    std::map<std::string, std::vector<Manifest*>> table;     // 기여 -> 내놓은 쪽들
    std::map<std::string, Handler> handlers;
    std::set<std::string> awake, off;
    Manifest* waking = nullptr;

    void add(Manifest m) {                   // 선언만 본다. 코드는 부르지 않는다
        if (m.needs_api > kApi)
            return std::println("  {}: API {}이 필요한데 본체는 {} -> 건너뜀", m.id,
                                m.needs_api, kApi);
        Manifest* p = &plugins.emplace_back(std::move(m));
        for (const std::string& what : p->offers) {
            auto& list = table[what];
            list.push_back(p);
            std::ranges::stable_sort(list, std::greater{}, &Manifest::priority);
            if (list.size() > 1)
                std::println("  {}: 여럿이 내놓음 -> 먼저 {}", what, list[0]->id);
        }
    }
    void handle(const std::string& what, Handler fn) {       // 깨우는 중에 부른다
        handlers[waking->id + " " + what] = std::move(fn);
    }
    std::string use(const std::string& what) {
        std::string log;
        for (Manifest* p : table[what]) {    // 우선순위대로. 꺼진 것은 건너뛴다
            if (off.contains(p->id)) continue;
            if (awake.insert(p->id).second) {
                log += "깨움(" + p->id + ") -> ";
                try {
                    waking = p, p->activate(*this);
                } catch (const std::exception& e) {
                    log += std::format("실패({}) -> ", e.what());
                    log += disable(p->id) + " -> ";
                    continue;
                }
            }
            if (auto h = handlers.find(p->id + " " + what); h != handlers.end())
                return log + h->second();
        }
        return log + "없음";
    }
    std::string disable(const std::string& id) {     // 내놓은 것이 표에서 빠진다
        off.insert(id), awake.erase(id);
        return "끔(" + id + ")";
    }
    void status() {
        int usable = 0;
        auto on = [&](const Manifest* p) { return !off.contains(p->id); };
        for (auto& [what, list] : table) usable += std::ranges::any_of(list, on);
        std::println("쓸 수 있는 기여 {}개, 깨어 있는 플러그인 {}개", usable,
                     awake.size());
    }
};

int main() {
    Host host;
    std::println("선언을 읽는다");
    host.add({"basic-formats", 1, {"open:png", "open:jpg"}, 0, [](Host& h) {
        h.handle("open:png", [] { return "PNG를 읽었다"; });
        h.handle("open:jpg", [] { return "JPEG를 읽었다"; });
    }});
    host.add({"filters", 2, {"cmd:filter.blur", "cmd:filter.sharpen"}, 0,
              [](Host& h) {
        h.handle("cmd:filter.blur", [] { return "흐리게 했다"; });
        h.handle("cmd:filter.sharpen", [] { return "선명하게 했다"; });
    }});
    host.add({"png-fast", 2, {"open:png"}, 10, [](Host& h) {
        h.handle("open:png", [] { return "PNG를 빨리 읽었다"; });
    }});
    host.add({"broken", 1, {"cmd:broken"}, 0, [](Host&) {
        throw std::runtime_error("설정 파일이 없다");
    }});
    host.add({"future", 3, {"cmd:future"}, 0, [](Host&) {}});
    host.status();

    for (const char* what : {"cmd:filter.blur", "cmd:filter.sharpen", "open:png",
                             "cmd:broken", "cmd:broken"})
        std::println("{} -> {}", what, host.use(what));
    std::println("{}", host.disable("png-fast"));
    std::println("open:png -> {}", host.use("open:png"));
    host.status();
}
```

```text
선언을 읽는다
  open:png: 여럿이 내놓음 -> 먼저 png-fast
  future: API 3이 필요한데 본체는 2 -> 건너뜀
쓸 수 있는 기여 5개, 깨어 있는 플러그인 0개
cmd:filter.blur -> 깨움(filters) -> 흐리게 했다
cmd:filter.sharpen -> 선명하게 했다
open:png -> 깨움(png-fast) -> PNG를 빨리 읽었다
cmd:broken -> 깨움(broken) -> 실패(설정 파일이 없다) -> 끔(broken) -> 없음
cmd:broken -> 없음
끔(png-fast)
open:png -> 깨움(basic-formats) -> PNG를 읽었다
쓸 수 있는 기여 4개, 깨어 있는 플러그인 2개
```

- **선언과 코드를 나눈다**: `Manifest`의 id, 필요한 API 판, 내놓는 것, 우선순위는 코드를 올리지 않고 읽을 수 있는 데이터입니다. 선언 다섯 개를 읽은 뒤에 쓸 수 있는 기여는 5개인데 깨어 있는 플러그인은 0개입니다. 메뉴와 파일 형식의 목록은 이 표만으로 만듭니다
- **처음 쓰일 때 깨운다**: 흐리게를 처음 부를 때 `filters`를 깨웠고, 선명하게를 부를 때는 다시 깨우지 않았습니다. 플러그인을 많이 설치해도 시작 시간은 선언을 읽는 만큼만 늘어납니다([「프로세스와 모듈」](#/read/cpp-complex-app/ana-modules)). 대신 처음 부른 쪽이 깨우는 시간을 기다립니다
- **API 판은 올리기 전에 본다**: `future`는 API 3이 필요한데 본체는 2라서 선언 단계에서 걸렀습니다. 새 API로 빌드한 코드는 옛 본체에 없는 함수를 부를 수 있으므로 코드를 올리기 전에 거릅니다
- **겹치면 차례가 있다**: PNG 열기를 둘이 내놓았고 우선순위가 높은 `png-fast`가 맡았습니다. `png-fast`를 끄자 `basic-formats`가 그때 깨어나 이어받았습니다
- **실패는 그 플러그인에서 멈춘다**: `broken`은 깨우는 중에 예외를 던졌습니다. 본체는 그 플러그인만 끄고 계속 돌며, 두 번째 호출에서는 다시 깨우려 하지 않습니다. 여기서는 한 프로그램 안이라 예외를 잡았지만, 따로 빌드한 모듈의 예외는 경계를 넘기지 않습니다([「ABI가 안정된 인터페이스」](#/read/cpp-complex-app/plg-abi))
- **끄면 기여가 함께 빠진다**: 기여마다 누가 내놓았는지 적어 두었으므로, 플러그인을 끄면 그 기여를 모두 건너뛸 수 있습니다. 마지막에 쓸 수 있는 기여는 4개입니다. 플러그인이 본체의 메뉴 객체를 직접 고쳤다면 끌 때 무엇을 되돌릴지 알 수 없습니다

## 실제 프로그램의 선언

- **VS Code**: 확장의 `package.json`에 있는 `contributes`가 선언이고, 명령, 메뉴, 단축키, 언어 같은 지점이 정해져 있습니다. 언제 깨울지는 `activationEvents`에 `onLanguage`, `onView` 같은 사건으로 적습니다. 1.74부터는 선언한 명령이 불리면 따로 적지 않아도 깨웁니다. 시작할 때마다 깨우는 `*`는 다른 사건으로 안 될 때에만 쓰라고 합니다
- **자리와 조건도 선언이다**: VS Code의 메뉴 항목은 놓일 묶음을 적고, 묶음 이름 뒤에 `@1`처럼 숫자를 붙여 그 안의 차례를 정합니다. 보일 조건은 `when`에, 명령이 켜질 조건은 `enablement`에 식으로 적습니다. 식은 본체가 계산하므로 메뉴를 그리려고 확장을 깨우지 않아도 됩니다([「메뉴, 도구 모음, 리본」](#/read/cpp-complex-app/win-ribbon))
- **GIMP**: 선언이 플러그인의 코드 안에 있어서, 본체는 플러그인을 query, init, run 세 가지로 부릅니다. query는 설치한 뒤에 한 번 불려 `query_procedures`로 프로시저의 이름을 알리고, 본체는 그 정보를 `pluginrc` 파일에 적어 둡니다. run은 프로시저가 불릴 때마다 일어납니다
- **Blender**: 애드온의 `bl_info` 사전에 필요한 가장 낮은 Blender 판을 적고, 그보다 옛 판에서는 애드온이 목록에 나오지 않습니다. `register`는 애드온을 켤 때에만 돌고, `unregister`는 끌 때 불려 `register`가 차려 둔 것을 치웁니다
- **Qt**: 플러그인 파일 안의 JSON 메타데이터를 `QPluginLoader`가 코드를 올리지 않고 읽습니다([「플러그인」](#/read/cpp-qt/qarch-plugins))

## 확장 지점을 둘 때 정할 것

- **여럿이 내놓으면**: 지점마다 답이 다릅니다. 메뉴 항목과 패널은 모두 보이고 차례만 정하면 됩니다. 파일 형식은 하나가 맡되 사용자가 고를 수 있어야 합니다. 명령 id는 겹치면 안 되므로 나중 것을 받지 않고 알립니다
- **본체의 기능도 같은 지점으로**: 본체의 필터와 파일 형식을 플러그인과 같은 길로 등록합니다. 본체만 쓰는 뒷길이 있으면 지점이 모자란 것을 늦게 압니다. GIMP의 PDB에는 내부 프로시저와 플러그인의 프로시저가 함께 있습니다
- **지점은 좁게 연다**: 플러그인이 기대는 것은 모두 공개된 약속이 되어 바꾸기 어렵습니다. 메인 윈도우 객체를 통째로 넘기면 그 안의 모든 것이 약속이 되므로, 명령을 더하는 자리, 패널을 더하는 자리처럼 하나씩 엽니다
- **실행 중에 끄기**: 그 플러그인의 명령이 실행 취소 스택에 남아 있을 수 있습니다. 기여는 바로 빼더라도 코드는 프로그램이 끝날 때까지 내리지 않는 편이 안전합니다
- **플러그인이 없어진 문서**: 지운 플러그인의 패널은 배치에서 빼면 되지만([「작업 공간 저장」](#/read/cpp-complex-app/win-workspace)), 문서에 든 그 플러그인의 데이터는 버리면 안 됩니다. 모르는 채로 간직했다가 저장할 때 그대로 다시 씁니다([「버전과 호환」](#/read/cpp-complex-app/file-versions))

<Note>
시험에는 깨울 때 실패하는 플러그인, 판이 맞지 않는 플러그인, 같은 것을 내놓는 플러그인 둘을 넣어 둡니다. 플러그인을 모두 끈 채로 본체가 뜨는지도 확인합니다. 문제가 생겼을 때 플러그인 탓인지를 가리려면 그렇게 띄울 수 있어야 합니다.
</Note>

## 정리

- 확장 지점은 기여가 들어갈 이름 붙은 자리다. 기여는 코드를 올리지 않고 읽는 선언으로 받아 표를 만들고, 코드는 처음 쓰일 때 깨운다
- 선언을 읽을 때 API 판을 확인하고, 겹치는 기여의 차례를 정하고, 깨우다 실패한 플러그인은 그것만 끈다
- 기여를 플러그인별로 적어 두어야 끌 때 함께 뺄 수 있다. 지점은 공개된 약속이므로 좁게 열고, 본체의 기능도 같은 지점으로 넣는다
