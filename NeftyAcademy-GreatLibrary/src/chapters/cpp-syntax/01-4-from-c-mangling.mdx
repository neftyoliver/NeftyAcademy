C++에서는 이름이 같은 함수를 인자만 달리해서 여러 개 만들 수 있습니다. 그런데 링커는 [「심볼이란」](#/read/c-basic/symbols)에서 본 대로 이름 하나에 주소 하나만 압니다. 이 틈을 메우는 것이 이름 맹글링입니다.

## 심볼 이름에 타입을 새긴다

```cpp
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
```

```sh
g++ -std=c++23 -c add.cpp -o add.o
nm add.o
```

```text
0000000000000018 T _Z3adddd
0000000000000000 T _Z3addii
```

컴파일러가 함수 이름에 인자 타입을 붙여 서로 다른 심볼로 만들었습니다. `_Z3addii`는 "이름이 3글자 `add`, 인자가 `int`, `int`"라는 뜻입니다. 사람이 읽을 때는 풀어서 봅니다.

```sh
nm -C add.o            # 또는 nm add.o | c++filt
```

```text
0000000000000018 T add(double, double)
0000000000000000 T add(int, int)
```

네임스페이스, 클래스 이름, 템플릿 인자도 모두 심볼 이름에 들어갑니다. 맹글링 규칙은 표준이 아니라 ABI가 정합니다. 리눅스와 맥은 Itanium C++ ABI를, MSVC는 자기 규칙을 씁니다. 그래서 GCC로 만든 C++ 라이브러리를 MSVC로 링크할 수 없습니다.

## C 함수를 부를 때

C 컴파일러는 `add`를 그냥 `add`라는 심볼로 만듭니다. C++ 쪽에서 `int add(int, int);`라고 선언하고 부르면 링커는 `_Z3addii`를 찾다가 실패합니다.

```text
undefined reference to `add(int, int)'
```

"이 함수는 C의 방식으로 이름 붙여졌다"고 알려 주는 것이 `extern "C"`입니다.

```cpp nocheck
extern "C" int add(int a, int b);       // 하나만

extern "C" {                            // 여러 개
#include "sensor.h"
}
```

## 양쪽에서 쓰는 헤더

C에서도 C++에서도 포함할 헤더는 이렇게 씁니다. C 라이브러리의 헤더를 열어 보면 거의 다 이 모양입니다.

```c
/* sensor.h */
#ifndef SENSOR_H
#define SENSOR_H

#ifdef __cplusplus
extern "C" {
#endif

int sensor_open(const char *path);
int sensor_read(int fd, double *celsius);
void sensor_close(int fd);

#ifdef __cplusplus
}
#endif

#endif
```

`__cplusplus`는 C++ 컴파일러에서만 정의됩니다. C 컴파일러는 `extern "C"`를 모르므로 가려 주는 것입니다.

## 거꾸로: C++ 함수를 C에 내놓기

```cpp
#include <string>
#include <vector>

static std::vector<std::string> names = {"led", "button"};

extern "C" const char *device_name(int index)
{
    if (index < 0 || index >= static_cast<int>(names.size()))
        return nullptr;
    return names[static_cast<std::size_t>(index)].c_str();
}
```

함수의 **안**에서는 C++을 마음껏 써도 됩니다. `extern "C"`가 바꾸는 것은 바깥에 보이는 이름과 호출 규약뿐입니다. 대신 경계에는 제약이 있습니다.

| 할 수 없는 것 | 이유 |
| --- | --- |
| 오버로딩 | 이름에 타입이 안 들어가므로 구분할 수 없다 |
| 인자나 반환에 `std::string`, 참조, 클래스 | C가 모르는 타입이다 |
| 예외가 경계를 넘어가게 두기 | C 코드는 예외를 풀 줄 모른다. 안에서 잡아 오류 코드로 바꾼다 |

파이썬, Rust, C# 같은 다른 언어에서 C++ 라이브러리를 쓸 때도 이 방법을 씁니다. 언어들이 서로 약속한 공통어가 C ABI이기 때문입니다.

<Note kind="tip">
링크 오류에 `_Z`로 시작하는 이름이 보이면 C++ 심볼을 찾고 있다는 뜻입니다. C 라이브러리 함수인데 그렇게 나온다면 헤더에 `extern "C"`가 빠진 것입니다.
</Note>

## 정리

- 오버로딩을 위해 컴파일러가 심볼 이름에 인자 타입을 새긴다. `nm -C`로 풀어 본다
- C 함수는 `extern "C"`로 선언해야 링크된다. 헤더에는 `#ifdef __cplusplus`로 감싼다
- `extern "C"`는 경계의 이름만 바꾼다. 경계에는 C가 아는 타입만 둔다
