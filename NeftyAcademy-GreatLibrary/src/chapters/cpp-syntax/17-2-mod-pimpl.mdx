헤더의 `#include`는 그 헤더를 쓰는 모든 파일로 번집니다. 줄이는 방법이 둘 있습니다. **전방 선언**은 포함 자체를 없애고, **pimpl**은 클래스의 속을 헤더에서 통째로 빼냅니다.

## 전방 선언

`class Sensor;`는 "`Sensor`라는 클래스가 있다"만 알립니다. 크기도 멤버도 모르는 이 상태를 **불완전한 타입**이라고 합니다.

| 불완전한 타입으로 되는 것 | 완전해야 하는 것 |
| --- | --- |
| 포인터와 참조를 선언한다 (`Sensor*`, `Sensor&`) | 값으로 멤버나 지역 변수를 둔다 |
| 함수의 선언에서 인자·반환 타입으로 쓴다 | 멤버를 부른다 (`s.read()`) |
| `std::unique_ptr<Sensor>`, `std::vector<Sensor>` 멤버를 **선언**한다 | `sizeof`, 상속, `delete` |

```cpp nocheck
// logger.h
#pragma once

class Sensor;                   // #include "sensor.h" 대신

class Logger {
public:
    void attach(Sensor& sensor);        // 참조만 쓰므로 선언으로 충분하다

private:
    Sensor* sensor_ = nullptr;
};
```

`logger.h`를 포함하는 파일들은 이제 `sensor.h`가 바뀌어도 다시 컴파일되지 않습니다. 실제로 `Sensor`의 멤버를 부르는 `logger.cpp`만 `sensor.h`를 포함합니다. 두 헤더가 서로를 포함해야 하는 순환도 이렇게 끊습니다.

| 전방 선언할 수 있는 것 | 꼴 |
| --- | --- |
| 클래스, 구조체 | `class Sensor;` `struct Config;` |
| 바탕 타입을 적은 열거형 | `enum class Mode : std::uint8_t;` |
| 클래스 템플릿 | `template <typename T> class Buffer;` |

`std::string` 같은 표준 라이브러리의 타입은 직접 전방 선언하면 안 됩니다. 별칭과 기본 인자가 얽혀 있고, `std` 안에 선언을 넣는 것 자체가 허용되지 않습니다. 스트림만은 표준이 `<iosfwd>`를 따로 줍니다.

## pimpl

[`private` 멤버도 헤더에 보입니다](#/read/cpp-syntax/class-members). 멤버의 타입이 필요로 하는 헤더도 함께 따라옵니다. pimpl(pointer to implementation)은 `private` 멤버를 **별도의 구조체로 옮기고 포인터 하나만** 남기는 관용구입니다.

```cpp nocheck
// gpio_line.h
#pragma once
#include <memory>

class GpioLine {
public:
    explicit GpioLine(int pin);
    ~GpioLine();                            // 정의는 .cpp에
    GpioLine(GpioLine&&) noexcept;
    GpioLine& operator=(GpioLine&&) noexcept;

    void set(bool high);
    bool get() const;

private:
    struct Impl;                            // 전방 선언만. 내용은 헤더에 없다
    std::unique_ptr<Impl> impl_;
};
```

```cpp nocheck
// gpio_line.cpp
#include "gpio_line.h"

#include <print>            // 구현에만 필요한 헤더. 쓰는 쪽으로 새지 않는다

struct GpioLine::Impl {
    int pin;
    bool level = false;
    int writes = 0;
};

GpioLine::GpioLine(int pin) : impl_(std::make_unique<Impl>(pin)) {}
GpioLine::~GpioLine() = default;
GpioLine::GpioLine(GpioLine&&) noexcept = default;
GpioLine& GpioLine::operator=(GpioLine&&) noexcept = default;

void GpioLine::set(bool high)
{
    impl_->level = high;
    ++impl_->writes;
    std::println("pin {} <- {} ({}번째)", impl_->pin, high ? "H" : "L",
                 impl_->writes);
}

bool GpioLine::get() const { return impl_->level; }
```

```cpp nocheck
// main.cpp
#include "gpio_line.h"

#include <print>
#include <utility>

int main()
{
    GpioLine led(17);
    led.set(true);

    GpioLine moved = std::move(led);
    moved.set(false);
    std::println("{} {}", moved.get(), sizeof(GpioLine));
}
```

```text
pin 17 <- H (1번째)
pin 17 <- L (2번째)
false 8
```

`GpioLine`의 크기는 포인터 하나, 8바이트입니다. `Impl`에 멤버를 더하거나 `<gpiod.h>` 같은 헤더를 `gpio_line.cpp`에 포함해도 `gpio_line.h`는 한 글자도 바뀌지 않고, 그것을 쓰는 파일들은 다시 컴파일되지 않습니다.

## 소멸자의 자리

헤더에서 `~GpioLine();`을 지우면 이런 오류가 납니다.

```text
error: invalid application of 'sizeof' to incomplete type 'GpioLine::Impl'
```

컴파일러가 만들어 주는 소멸자는 **헤더를 포함한 곳마다** 만들어집니다. 그 소멸자는 `unique_ptr<Impl>`을 지워야 하는데, 그 자리에서 `Impl`은 불완전한 타입입니다. 그래서 소멸자를 헤더에서 **선언만** 하고, `Impl`의 정의가 보이는 `.cpp`에서 `= default`로 정의합니다. 이동 생성자와 이동 대입도 같은 까닭으로 같은 자리에 둡니다.

[소멸자를 선언했으므로](#/read/cpp-syntax/sm-rules) 이동 연산은 저절로 생기지 않습니다. 위처럼 직접 선언해야 합니다. 복사가 필요하면 `Impl`을 복사하는 복사 생성자를 직접 씁니다.

## 값과 대가

| 얻는 것 | 치르는 것 |
| --- | --- |
| 구현의 헤더가 쓰는 쪽으로 번지지 않는다 | 객체마다 힙 할당 한 번 |
| 구현을 바꿔도 쓰는 쪽은 다시 컴파일하지 않는다 | 멤버 접근마다 포인터를 한 번 거친다 |
| 클래스의 크기와 배치가 고정된다. 라이브러리를 바꿔 끼워도 프로그램이 깨지지 않는다 | 함수가 인라인되지 않는다. 특수 멤버를 손으로 적어야 한다 |

모든 클래스에 쓸 것은 아닙니다. **라이브러리의 바깥 얼굴**이 되는 클래스, 무거운 헤더나 플랫폼 전용 헤더를 품은 클래스에 씁니다. 안쪽 루프에서 수없이 만들어지는 작은 값 타입에는 맞지 않습니다.

같은 목적의 다른 방법이 [추상 클래스와 생성 함수](#/read/cpp-syntax/inh-abstract)입니다. 헤더에는 인터페이스와 `std::unique_ptr<Gpio> make_gpio(int pin);`만 두고, 구현 클래스는 `.cpp`에 숨깁니다. 구현이 여럿일 수 있으면 그쪽이, 하나뿐이면 pimpl이 맞습니다.

<Note kind="warn">
`const` 멤버 함수 안에서도 `impl_->level = true;`는 컴파일됩니다. `const`인 것은 포인터이지 그것이 가리키는 `Impl`이 아니기 때문입니다. pimpl 클래스에서는 `const` 함수가 상태를 바꾸지 않도록 스스로 지켜야 합니다.
</Note>

## 정리

- 포인터나 참조로만 쓰는 타입은 `#include` 대신 `class 이름;`으로 선언한다
- pimpl은 `private` 멤버를 `.cpp`의 `Impl`로 옮기고 `std::unique_ptr<Impl>` 하나만 남긴다
- pimpl 클래스의 소멸자와 이동 연산은 헤더에서 선언하고 `.cpp`에서 `= default`로 정의한다
