구조체의 크기는 멤버 크기의 합이 아닙니다. 타입마다 "몇의 배수인 주소에 놓여야 하는가"가 있고, 컴파일러는 그것을 맞추려고 멤버 사이에 빈 바이트를 끼웁니다.

## 재 보기

```cpp
#include <cstddef>
#include <cstdint>
#include <print>

struct Loose {          // 선언한 순서대로 놓인다
    std::uint8_t flag;
    std::uint64_t stamp;
    std::uint8_t kind;
    std::uint32_t value;
};

struct Tight {          // 큰 것부터 적었다
    std::uint64_t stamp;
    std::uint32_t value;
    std::uint8_t flag;
    std::uint8_t kind;
};

struct alignas(64) CacheLine {
    int counter;
};

struct Empty {};

struct WithEmpty {
    [[no_unique_address]] Empty tag;
    int value;
};

int main()
{
    std::println("{} {}", sizeof(Loose), alignof(Loose));
    std::println("{} {} {}", offsetof(Loose, stamp), offsetof(Loose, kind),
                 offsetof(Loose, value));
    std::println("{} {}", sizeof(Tight), alignof(Tight));
    std::println("{} {}", sizeof(CacheLine), alignof(CacheLine));
    std::println("{} {}", sizeof(Empty), sizeof(WithEmpty));
    std::println("{}", alignof(std::max_align_t));
}
```

```text
24 8
8 16 20
16 8
64 64
1 4
16
```

64비트 리눅스(x86-64, 64비트 라즈베리 파이 OS)에서의 결과입니다. 32비트 ARM에서는 마지막 줄이 8입니다.

## 정렬

`alignof(T)`는 `T` 객체가 놓일 주소가 **몇의 배수여야 하는지**입니다.

| 타입 | `sizeof` | `alignof` |
| --- | --- | --- |
| `char`, `std::uint8_t` | 1 | 1 |
| `std::uint16_t` | 2 | 2 |
| `int`, `float`, `std::uint32_t` | 4 | 4 |
| `double`, `std::uint64_t`, 포인터 (64비트) | 8 | 8 |
| 구조체 | 아래 참조 | 멤버 가운데 가장 큰 정렬 |

CPU는 정렬된 주소에서 읽고 쓸 때 가장 빠르고, 어긋난 접근을 아예 못 하는 명령도 있습니다. 그래서 컴파일러는 모든 객체를 정렬에 맞춰 놓습니다.

## 채움

`Loose`의 14바이트짜리 멤버들이 24바이트를 차지합니다.

| 오프셋 | 내용 |
| --- | --- |
| 0 | `flag` (1) |
| 1 ~ 7 | **채움 7바이트.** `stamp`가 8의 배수에 놓여야 한다 |
| 8 | `stamp` (8) |
| 16 | `kind` (1) |
| 17 ~ 19 | 채움 3바이트. `value`가 4의 배수에 놓여야 한다 |
| 20 | `value` (4) |
| 24 | 끝. 전체 크기가 정렬(8)의 배수여야 한다 |

마지막 조건은 배열 때문입니다. `Loose` 여럿을 이어 놓았을 때 다음 원소도 정렬이 맞아야 합니다.

컴파일러는 멤버의 **순서를 바꾸지 않습니다.** 줄이는 것은 쓰는 사람의 일입니다. `Tight`처럼 **큰 것부터** 적으면 채움이 끝에만 남아 16바이트가 됩니다. 원소가 백만 개인 배열이라면 8MB 차이입니다. 캐시에 들어가는 원소 수도 그만큼 달라집니다.

`-Wpadded`가 채움이 들어간 자리를 모두 알려 줍니다. 평소에는 시끄러우니 구조체를 다듬을 때만 켭니다.

## alignas

`alignas(N)`으로 정렬을 **키울** 수 있습니다. 줄일 수는 없습니다.

| 쓰임 | 예 |
| --- | --- |
| 캐시 줄 단위로 떼어 놓기 | 서로 다른 스레드가 고치는 두 카운터가 같은 캐시 줄(보통 64바이트)에 있으면 서로를 느리게 한다. `alignas(64)`로 떼어 놓는다 |
| SIMD | NEON, SSE 레지스터에 올릴 배열은 16바이트 정렬 |
| DMA, 하드웨어 버퍼 | 드라이버가 특정 정렬을 요구한다 |
| 날것의 저장소 | `alignas(T) std::byte storage[sizeof(T)];` [placement new](#/read/cpp-syntax/life-new)의 자리 |

## 빈 타입

멤버가 없는 클래스도 `sizeof`는 1입니다. 서로 다른 객체는 주소가 달라야 하기 때문입니다. 그런데 빈 타입을 **멤버로** 두면 그 1바이트와 채움이 구조체를 키웁니다.

C++20의 `[[no_unique_address]]`를 붙이면 빈 멤버가 자리를 차지하지 않습니다. 위에서 `WithEmpty`가 8이 아니라 4인 까닭입니다. 상태 없는 비교 객체, [할당자](#/read/cpp-syntax/life-new), 캡처 없는 [람다](#/read/cpp-syntax/lam-closure)를 멤버로 품을 때 씁니다. `std::unique_ptr`이 지우는 함수 객체를 품고도 포인터 하나 크기인 것이 같은 원리(빈 부모 최적화)입니다.

## 묶음 구조체

통신 프로토콜의 헤더처럼 **채움이 없어야** 하는 배치는 컴파일러 확장으로 만듭니다.

```cpp nocheck
struct [[gnu::packed]] Frame {
    std::uint8_t kind;
    std::uint32_t length;       // 오프셋 1. 정렬이 맞지 않는다
};
static_assert(sizeof(Frame) == 5);
```

위험이 있습니다.

| 위험 | 내용 |
| --- | --- |
| 느리다 | 컴파일러가 어긋난 멤버를 바이트 단위로 읽는 코드를 만든다 |
| 참조와 포인터 | `std::uint32_t& r = frame.length;`는 어긋난 주소를 가리킨다. 그것을 받는 함수는 정렬되어 있다고 믿는다. GCC는 `-Waddress-of-packed-member`로 경고한다 |
| 이식성 | 표준 문법이 아니다. 바이트 순서 문제는 그대로 남는다 |

더 안전한 길은 **묶지 않은 구조체**를 프로그램 안에서 쓰고, 보내고 받는 경계에서만 멤버 하나하나를 [`memcpy`](#/read/cpp-syntax/cast-reinterpret)로 바이트 열에 옮기는 것입니다. 묶음 구조체를 쓴다면 [`static_assert`](#/read/cpp-syntax/ct-assert)로 크기와 오프셋을 적어 두고, 멤버의 참조를 만들지 않습니다.

<Note>
비트 필드(`unsigned ready : 1;`)의 배치는 표준이 정하지 않습니다. 비트가 낮은 쪽부터 채워지는지, 바이트 경계를 넘는지가 컴파일러와 CPU마다 다릅니다. 메모리를 아끼는 데는 좋지만, 하드웨어 레지스터나 통신 형식에 그대로 겹쳐 쓰는 용도로는 믿을 수 없습니다. 그런 자리에는 정수와 시프트, 마스크를 씁니다.
</Note>

## 정리

- 타입마다 정렬이 있고, 컴파일러는 그것을 맞추려 멤버 사이와 끝에 채움을 넣는다
- 멤버를 큰 것부터 적으면 채움이 줄어든다. 순서는 컴파일러가 바꿔 주지 않는다
- `alignas`로 정렬을 키우고, `[[no_unique_address]]`로 빈 멤버의 자리를 없앤다
