export const summary = '인자의 타입이 사는 네임스페이스에서도 함수를 찾는다';

`std::cout << x`에서 `<<`는 `std` 안에 정의된 함수인데, `std::operator<<(std::cout, x)`라고 쓰지 않아도 찾아집니다. 접두어 없이 부른 함수를 **인자의 타입이 속한 네임스페이스에서도 찾는** 규칙 덕분입니다. 인자 의존 이름 찾기, 줄여서 ADL(Argument-Dependent Lookup)입니다.

## 접두어 없이 찾아진다

```cpp
#include <format>
#include <print>
#include <string>

namespace geo {

struct point {
    int x, y;
};

std::string to_text(const point& p) { return std::format("({}, {})", p.x, p.y); }
point operator+(const point& a, const point& b) { return {a.x + b.x, a.y + b.y}; }

}   // namespace geo

int main()
{
    geo::point a{1, 2}, b{10, 20};
    std::println("{}", to_text(a));         // geo:: 를 적지 않았는데 찾는다
    std::println("{}", to_text(a + b));     // operator+ 도 ADL로 찾는다
}
```

```text
(1, 2)
(11, 22)
```

`main`에서 `to_text`는 보이지 않는 이름입니다. 하지만 인자 `a`의 타입이 `geo::point`이므로 컴파일러가 `geo` 안도 뒤져서 `geo::to_text`를 찾습니다. `a + b`도 마찬가지입니다. ADL이 없다면 `geo::operator+(a, b)`라고 써야 했을 것입니다.

## 규칙

- 접두어 없이 **함수를 부를 때**만 일어난다. `geo::to_text(a)`처럼 접두어가 있으면 그곳만 본다
- 인자마다, 그 타입이 정의된 네임스페이스를 찾아볼 곳에 더한다
- 타입이 템플릿이면 템플릿 인자의 네임스페이스도, 클래스면 부모 클래스의 네임스페이스도 본다
- `int`, `double` 같은 기본 타입은 네임스페이스가 없으므로 더해지는 곳이 없다
- 보통의 방법으로 찾은 것과 ADL로 찾은 것을 모두 모아 놓고 [오버로드를 고른다](#/read/cpp-syntax/fn-overload)

## 여기서 나오는 설계 원칙

**타입과 그 타입을 다루는 함수는 같은 네임스페이스에 둔다.** 연산자가 특히 그렇습니다. `geo::point`의 `operator+`, `operator==`, `to_text`를 `geo` 안에 두면 쓰는 쪽은 아무것도 꺼내 오지 않아도 됩니다. 전역에 두면 다른 네임스페이스 안에서 가려져 찾지 못하는 일이 생깁니다.

클래스의 "인터페이스"는 멤버 함수만이 아닙니다. 같은 네임스페이스에 있고 그 타입을 인자로 받는 함수들도 인터페이스의 일부입니다.

## 놀라는 경우

```cpp
#include <print>
#include <vector>

namespace tools {
template <typename It>
int distance(It, It) { return -1; }     // 내가 만든 distance
}

int main()
{
    using namespace tools;
    std::vector<int> v = {1, 2, 3};
    std::println("{}", tools::distance(v.begin(), v.end()));
    // distance(v.begin(), v.end());    // 오류: std::distance 와 모호하다
}
```

```text
-1
```

`v.begin()`의 타입은 `std` 안에 있으므로, 접두어 없는 `distance(...)`는 `std::distance`도 후보에 올립니다. `using namespace std;`를 쓰지 않았는데도 그렇습니다. 표준 타입을 인자로 넘길 때는 내 함수에 접두어를 붙여 부르면 이런 일이 없습니다.

## swap과 맞춤 지점

ADL을 일부러 이용하는 오래된 관용구가 있습니다.

```cpp nocheck
using std::swap;    // 기본으로 std::swap 을 후보에 올리고
swap(a, b);         // a의 타입에 전용 swap 이 있으면 ADL이 그것을 찾는다
```

"타입이 직접 제공한 것이 있으면 그것을, 없으면 표준의 것을"이라는 뜻입니다. `std::swap(a, b)`라고 쓰면 전용 `swap`을 지나칩니다. C++20의 `std::ranges::swap(a, b)`는 이 두 줄을 대신해 줍니다. `begin`, `end`, `size`도 같은 방식으로 `std::ranges::begin` 등이 있습니다.

<Note>
괄호로 감싼 `(to_text)(a)`는 ADL을 끕니다. 함수 이름과 같은 이름의 변수나 람다가 보통의 방법으로 먼저 찾아진 경우에도 ADL은 일어나지 않습니다. 표준 라이브러리의 `std::ranges` 알고리즘이 함수가 아니라 객체로 만들어진 까닭이 이것입니다.
</Note>

## 정리

- 접두어 없는 함수 호출은 인자 타입의 네임스페이스에서도 찾는다
- 그래서 타입과 그 연산자·도우미 함수를 같은 네임스페이스에 둔다
- 표준 타입을 넘길 때는 `std`의 함수가 후보에 끼어들 수 있다
