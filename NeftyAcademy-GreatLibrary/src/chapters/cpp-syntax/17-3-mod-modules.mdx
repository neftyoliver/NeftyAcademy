C++20의 모듈은 [헤더가 가진 문제](#/read/cpp-syntax/mod-headers)의 답으로 나왔습니다. 글자를 복사해 넣는 대신, 한 번 컴파일해 둔 결과를 **가져다 씁니다.**

## 모듈 만들기

```cpp nocheck
// src/gpio.cppm
module;                         // 전역 모듈 조각: 옛 헤더는 여기서 #include 한다
#include <print>
#include <string>

export module gpio;             // 이 파일이 gpio 모듈의 인터페이스다

export namespace gpio {

class Line {
public:
    explicit Line(int pin) : pin_(pin) {}
    void set(bool high);
    int pin() const { return pin_; }

private:
    int pin_;
};

std::string describe(const Line& line);

}  // namespace gpio

std::string prefix() { return "GPIO"; }     // export가 없다. 밖에서는 보이지 않는다

void gpio::Line::set(bool high)
{
    std::println("{}{} <- {}", prefix(), pin_, high ? "H" : "L");
}

std::string gpio::describe(const Line& line)
{
    return prefix() + std::to_string(line.pin());
}
```

```cpp nocheck
// src/main.cpp
#include <print>

import gpio;

int main()
{
    gpio::Line led(17);
    led.set(true);
    std::println("{}", gpio::describe(led));
    // prefix();        // 오류: export되지 않은 이름
}
```

```text
GPIO17 <- H
GPIO17
```

| 문법 | 뜻 |
| --- | --- |
| `export module gpio;` | 이 파일은 `gpio` 모듈의 인터페이스 |
| `export` | 모듈 밖에서 보이게 한다. 선언 하나에도, `namespace`나 `{ }` 블록 통째에도 붙는다 |
| `import gpio;` | 그 모듈이 `export`한 것을 쓴다 |
| `module;` … `export module` 사이 | 전역 모듈 조각. `#include`는 여기에 둔다 |
| `module gpio;` (`export` 없이) | 구현 파일. 인터페이스와 정의를 파일 둘로 나눌 때 |

헤더와 `.cpp`를 나누지 않아도 됩니다. 위처럼 한 파일에 선언과 정의를 함께 두어도, 쓰는 쪽에는 `export`한 것만 보입니다. 파일 확장자는 정해져 있지 않습니다. `.cppm`(Clang), `.ixx`(MSVC), `.cc` 등이 쓰입니다.

## 헤더와 다른 점

| | `#include` | `import` |
| --- | --- | --- |
| 하는 일 | 글자를 복사해 넣는다 | 컴파일해 둔 결과(BMI)를 읽는다 |
| 비용 | 포함한 파일마다 다시 컴파일 | 모듈은 한 번만 컴파일 |
| 매크로 | 들어오고 나간다. 포함 순서에 따라 뜻이 달라진다 | **넘나들지 않는다.** `import` 순서는 상관없다 |
| 밖에 보이는 것 | 헤더에 쓴 전부 | `export`한 것만 |
| 구현의 도우미 | `detail` 네임스페이스에 숨기는 시늉 | 정말로 안 보인다 |
| [ODR 충돌](#/read/cpp-syntax/mod-headers) | 번역 단위마다 정의가 복사된다 | 정의가 모듈 하나에 속한다 |

BMI(binary module interface)는 컴파일러가 모듈을 읽어 만든 중간 파일입니다. GCC는 `.gcm`, Clang은 `.pcm`, MSVC는 `.ifc`이고, 서로 호환되지 않으며 같은 컴파일러라도 버전과 옵션이 다르면 다시 만들어야 합니다. 그래서 라이브러리는 BMI가 아니라 **모듈의 소스**를 배포합니다.

## 빌드 순서가 생긴다

헤더 방식에서는 `.cpp`들을 아무 순서로, 동시에 컴파일해도 됐습니다. 모듈에서는 `import gpio;`를 컴파일하기 전에 `gpio`의 BMI가 **먼저 있어야** 합니다. 빌드 도구가 소스를 미리 훑어 누가 누구를 `import`하는지 알아내고 순서를 정해야 합니다.

손으로 하기는 번거롭고, [CMake](#/read/cpp-syntax/mod-cmake)가 대신 합니다.

```cmake
add_library(gpio)
target_sources(gpio
    PUBLIC
        FILE_SET CXX_MODULES FILES src/gpio.cppm)

add_executable(blink src/main.cpp)
target_link_libraries(blink PRIVATE gpio)
```

위 예제는 CMake 3.28, Ninja 1.11과 함께 GCC 14, Clang 19 양쪽에서 빌드해 확인했습니다. (Clang은 `clang-scan-deps`가 필요합니다. 우분투에서는 `clang-tools-19` 패키지에 있습니다.)

## import std

C++23은 표준 라이브러리 전체를 모듈 하나로 줍니다.

```cpp nocheck
import std;

int main()
{
    std::vector<int> pins{17, 27, 22};
    std::println("{} pins, first {}", pins.size(), pins.front());
}
```

`#include`를 하나도 쓰지 않습니다. `std` 모듈은 한 번만 컴파일되므로 빠릅니다. Clang 19와 libc++로 재 보니, `std` 모듈을 만드는 데 2초가 한 번 들고, 그 뒤 위 파일의 컴파일은 `#include <print>`와 `<vector>`를 쓴 판의 0.99초에서 0.39초로 줄었습니다(x86-64 PC에서 잰 값. 라즈베리 파이에서는 절댓값이 더 큽니다).

`import std;`는 매크로를 주지 않습니다. `assert`, `errno`, `INT_MAX` 같은 것은 여전히 `#include <cassert>` 등으로 얻습니다. C의 전역 이름(`::printf`)까지 원하면 `import std.compat;`을 씁니다.

## 2026년 11월의 상황

| | 이름 있는 모듈 | `import std` |
| --- | --- | --- |
| GCC | 14부터 CMake가 지원. 옵션(GCC 14는 `-fmodules-ts`, GCC 16은 `-fmodules`)이 필요하고, GCC 16에서도 **실험적**이라고 적혀 있다. CMake가 옵션을 대신 붙인다 | 15부터 |
| Clang | 16부터 | 18.1.2부터 (libc++ 또는 libstdc++) |
| MSVC | Visual Studio 2022 17.4부터 | 17.6부터 |
| CMake | 3.28부터 정식 (Ninja 1.11 이상, 또는 Visual Studio 생성기) | 4.5부터 정식. 3.30에서 4.4까지는 실험 기능 |

- 헤더 유닛(`import <vector>;`)은 CMake가 아직 지원하지 않는다
- 우분투 26.04 이전 판은 `import std`에 필요한 libstdc++의 메타데이터 파일이 깨져 있다고 CMake 문서가 적고 있다
- 이 책의 기준인 GCC 14(라즈베리 파이 OS)에서는 이름 있는 모듈은 되고 `import std`는 안 된다

그래서 이 책의 예제는 `#include`를 씁니다.

## 지금 쓸 것인가

| 상황 | 권하는 것 |
| --- | --- |
| 여러 컴파일러, 오래된 배포판에서 빌드해야 한다 | 헤더 |
| 남이 쓸 라이브러리를 낸다 | 헤더 (필요하면 모듈 인터페이스를 **덧붙여** 준다) |
| 새로 시작하는, 컴파일러를 정할 수 있는 프로젝트 | 써 볼 만하다. Clang이나 MSVC라면 더 |
| 표준 라이브러리만 빨리 가져오고 싶다 | 컴파일러와 CMake가 받쳐 주면 `import std;`부터 |

헤더와 모듈은 섞어 쓸 수 있습니다. 모듈 안에서 옛 헤더를 `#include`할 수 있고(전역 모듈 조각), 헤더를 쓰는 코드가 모듈을 `import`할 수 있습니다. 한꺼번에 옮길 필요가 없습니다.

<Note>
큰 모듈은 **분할**(partition)로 파일을 나눕니다. `export module gpio:line;`이 `gpio` 모듈의 `line` 분할이고, 주 인터페이스에서 `export import :line;`으로 다시 내보냅니다. 바깥에서는 여전히 `import gpio;` 하나로 보입니다.
</Note>

## 정리

- `export module 이름;`으로 만들고 `import 이름;`으로 쓴다. `export`한 것만 보이고 매크로는 넘나들지 않는다
- 모듈은 한 번만 컴파일되지만 빌드 순서가 생긴다. CMake 3.28 이상이 맡아 준다
- 지원은 컴파일러마다 다르다. GCC 14 기준으로는 이름 있는 모듈까지, `import std`는 GCC 15와 CMake 4.5부터
