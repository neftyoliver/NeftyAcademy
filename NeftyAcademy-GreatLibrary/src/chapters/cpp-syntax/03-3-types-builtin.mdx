기본 타입은 C에서 온 그대로입니다([「정수형」](#/read/c-basic/types-integers)). 여기서는 C++에서 더해졌거나 고쳐진 것만 봅니다.

## nullptr

C의 `NULL`은 정수 `0`이었습니다. 오버로딩이 있는 C++에서는 이것이 문제를 일으킵니다.

```cpp
#include <cstdint>
#include <limits>
#include <print>
#include <utility>

void f(int) { std::println("f(int)"); }
void f(const char*) { std::println("f(const char*)"); }

int main()
{
    f(0);
    f(nullptr);                             // 포인터 쪽이 불린다

    std::int32_t big = 2'000'000'000;       // 작은따옴표로 자리를 끊어 적는다
    std::uint8_t mask = 0b1111'0000;        // 2진수 표기
    std::println("{} {}", big, mask);
    std::println("{}", std::numeric_limits<std::int32_t>::max());

    int neg = -1;
    unsigned int one = 1;
    std::println("{} {}", neg < one, std::cmp_less(neg, one));
}
```

```text
f(int)
f(const char*)
2000000000 240
2147483647
false true
```

`nullptr`은 정수가 아니라 "널 포인터"만을 뜻하는 값입니다. 어떤 포인터 타입으로도 바뀌지만 `int`로는 바뀌지 않습니다. C++에서 `NULL`과 `0`을 포인터 자리에 쓸 이유는 없습니다.

## bool

`bool`, `true`, `false`는 처음부터 키워드입니다. 정수로 바뀌면 1과 0이고, 정수와 포인터는 조건식에서 "0이 아니면 참"으로 바뀝니다.

```cpp nocheck
bool ok = (count > 0);
if (ptr) { … }              // ptr != nullptr 과 같다
int n = ok + ok;            // 2. 되기는 하지만 쓰지 않는다
```

## 정수

크기 규칙은 C와 같습니다. `int`가 몇 비트인지는 플랫폼이 정하므로, 폭이 중요하면 `<cstdint>`의 `std::int32_t`, `std::uint8_t`를 씁니다. 레지스터와 통신 패킷을 다루는 코드에서는 늘 이쪽입니다.

| 도구 | 하는 일 |
| --- | --- |
| `1'000'000`, `0xff'ff` | 자리 구분. 값에는 영향이 없다 |
| `0b1010` | 2진수 리터럴 |
| `std::numeric_limits<T>::max()` | 타입의 최댓값. `INT_MAX` 대신 |
| `std::cmp_less(a, b)` (C++20) | 부호가 다른 정수를 수학적으로 옳게 비교 |
| `std::in_range<T>(v)` (C++20) | `v`가 `T`에 들어가는가 |
| `std::size_t` | 크기와 번호. 부호가 없다 |
| `std::ssize(v)` (C++20) | 부호 있는 크기 |
| `std::byte` | 숫자가 아닌 "바이트 하나". 비트 연산만 된다 |

위 예제의 `neg < one`이 `false`인 것은 C와 같은 이유입니다. `-1`이 부호 없는 수로 바뀌어 아주 큰 수가 됩니다([「형 변환」](#/read/c-basic/types-conversion)). 컴파일러가 `-Wsign-compare`로 경고해 줍니다. `std::cmp_less`는 이 함정 없이 비교합니다.

부호 있는 정수의 넘침은 C++에서도 정의되지 않은 동작입니다.

## 문자 타입

| 타입 | 크기 | 쓰임 |
| --- | --- | --- |
| `char` | 1바이트 | 보통의 글자와 바이트. 부호 여부는 플랫폼마다 다르다 |
| `char8_t` (C++20) | 1바이트 | UTF-8의 한 단위임을 타입으로 나타낸다. `u8"…"`의 타입 |
| `char16_t` | 2바이트 | UTF-16. `u"…"` |
| `char32_t` | 4바이트 | 유니코드 코드 포인트 하나. `U"…"` |
| `wchar_t` | 윈도우 2, 리눅스 4바이트 | 윈도우 API. 이식성이 없다 |

실제 코드에서는 `char`와 `std::string`에 UTF-8을 담는 것이 표준처럼 됐습니다. `char8_t`는 타입이 달라서 기존 함수들과 잘 섞이지 않으므로 아직 드물게 씁니다.

`'a'`의 타입이 `char`라는 것은 오버로딩에서 드러납니다. `std::println("{}", 'a')`는 `a`를 찍고, `std::println("{}", 'a' + 1)`은 `int`가 되어 `98`을 찍습니다.

## 실수

`float`, `double`, `long double`은 C와 같습니다. C++23에는 폭이 정해진 `<stdfloat>`의 `std::float32_t`, `std::float64_t`, 그리고 반정밀도 `std::float16_t`와 `std::bfloat16_t`가 더해졌습니다. 지원 여부는 컴파일러와 CPU에 따라 다릅니다.

<Note>
리터럴에도 타입이 있습니다. `42`는 `int`, `42u`는 `unsigned`, `42L`은 `long`, `42uz`는 `std::size_t`(C++23), `4.2`는 `double`, `4.2f`는 `float`입니다. `auto`와 함께 쓰면 접미어가 곧 변수의 타입이 됩니다.
</Note>

## 정리

- 널 포인터는 `nullptr`. `NULL`과 `0`은 쓰지 않는다
- 폭이 중요하면 `std::int32_t` 같은 고정 폭 타입, 부호가 섞인 비교는 `std::cmp_less`
- 글자는 `char`와 UTF-8이 기본
