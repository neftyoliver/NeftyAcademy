컨테이너의 원소를 가리키는 반복자, 포인터, 참조는 **컨테이너가 바뀌면 무효가 될 수 있습니다.** 무효가 된 것을 쓰면 [죽은 객체를 쓰는 것](#/read/cpp-syntax/ubc-lifetime)과 같습니다. [`vector`의 재할당](#/read/cpp-syntax/ft-vector)에서 잠깐 본 것을 여기서 정리합니다.

## 옳은 꼴

```cpp
#include <cstddef>
#include <cstdint>
#include <iterator>
#include <list>
#include <print>
#include <vector>

int main()
{
    std::vector<int> v{1, 2, 3, 4};
    auto before = reinterpret_cast<std::uintptr_t>(v.data());
    v.push_back(5);                         // 자리가 없어 새 메모리로 옮겨 간다
    auto after = reinterpret_cast<std::uintptr_t>(v.data());
    std::println("옮겨 갔나: {}", before != after);

    // 지우면서 돌기: erase가 돌려주는 반복자를 받는다
    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0)
            it = v.erase(it);
        else
            ++it;
    }

    // 같은 일을 한 줄로 (C++20)
    std::erase_if(v, [](int x) { return x > 3; });

    // 돌면서 넣기: 반복자 대신 인덱스로, 처음 크기만큼만
    for (std::size_t i = 0, n = v.size(); i < n; ++i)
        v.push_back(v[i] * 10);

    std::println("{} {} {} {}", v[0], v[1], v[2], v[3]);

    std::list<int> stable{1, 2, 3};
    int& second = *std::next(stable.begin());
    stable.push_back(4);
    stable.pop_front();
    std::println("{}", second);     // list는 다른 원소를 건드려도 참조가 산다
}
```

```text
옮겨 갔나: true
1 3 10 30
2
```

## 틀린 꼴

위와 같은 일을 하려던 흔한 실수 셋입니다.

```cpp nocheck
std::vector<int> v{1, 2, 3, 4};

int& first = v[0];              // 1. 참조를 들고
v.push_back(5);                 //    재할당
std::println("{}", first);      //    옛 메모리를 읽는다

for (int x : v)                 // 2. 범위 for로 도는 중에
    if (x == 2)
        v.push_back(20);        //    넣는다. 숨은 반복자가 죽는다

for (auto it = v.begin(); it != v.end(); ++it)
    if (*it % 2 == 0)
        v.erase(it);            // 3. 지운 뒤의 it를 ++ 한다
```

직접 돌려 본 결과입니다(GCC 14).

| | 그냥 빌드 | AddressSanitizer | `-D_GLIBCXX_DEBUG` |
| --- | --- | --- | --- |
| 1 | 쓰레기 값을 찍고 정상 종료 | `heap-use-after-free` | 못 잡는다 |
| 2 | 아무 일 없이 정상 종료 | `heap-use-after-free` | `attempt to increment a singular iterator` |
| 3 | 아무 일 없이 정상 종료 | `heap-buffer-overflow` | `attempt to increment a singular iterator` |

셋 다 그냥 빌드에서는 **멀쩡히 끝납니다.** 2와 3은 출력조차 틀리지 않을 수 있습니다.

## 컨테이너별 규칙

| 컨테이너 | 넣을 때 | 지울 때 |
| --- | --- | --- |
| `vector`, `string` | 재할당되면 **전부** 무효. 아니면 넣은 자리 뒤쪽만 | 지운 자리와 그 뒤쪽 |
| `deque` | 반복자는 전부 무효. 양 끝에 넣는 것은 원소의 참조·포인터를 살린다 | 양 끝을 지우면 그 원소만. 가운데를 지우면 전부 |
| `list`, `forward_list` | 아무것도 무효가 되지 않는다 | 지운 원소만 |
| `map`, `set` 계열 | 아무것도 무효가 되지 않는다 | 지운 원소만 |
| `unordered_map`, `unordered_set` | 다시 해싱되면 **반복자**는 전부 무효. 원소의 참조·포인터는 산다 | 지운 원소만 |
| `array`, `span` | 크기가 바뀌지 않는다 | |

노드 기반 컨테이너(`list`, `map`, `set`, `unordered_*`)는 원소가 각자 힙에 따로 살아서 **주소가 안정적**입니다. 그 대가로 캐시 효율이 나쁩니다. `vector`는 그 반대입니다.

`std::string`에는 함정이 하나 더 있습니다. 짧은 문자열은 객체 **안에** 글자를 두므로(SSO), 문자열을 **옮기면** `c_str()`과 `data()`로 얻어 둔 포인터가 무효가 됩니다. `vector`는 옮겨도 원소의 주소가 그대로입니다.

## vector에서 살아남기

| 방법 | 내용 |
| --- | --- |
| 미리 `reserve` | `capacity()`를 넘지 않는 동안은 재할당이 없다. 넣을 개수를 알면 가장 간단하다 |
| 참조 대신 **인덱스** | `v[i]`는 재할당 뒤에도 옳은 원소를 가리킨다. 지우기에는 약하다 |
| 필요한 값을 **복사해** 둔다 | `int first = v[0];` |
| 고치는 일과 읽는 일을 나눈다 | 넣을 것을 다른 벡터에 모았다가 루프 뒤에 한꺼번에 붙인다 |
| 주소가 꼭 안정적이어야 하면 | `std::vector<std::unique_ptr<T>>`, `std::deque`(끝에만 넣을 때), `std::list` |

객체들이 서로를 포인터로 가리키는 구조(그래프, 관찰자 목록)를 `std::vector<T>`에 값으로 담으면 반드시 이 문제를 만납니다.

## 돌면서 지우기

| 방법 | 꼴 |
| --- | --- |
| C++20 | `std::erase_if(v, 조건);` `std::erase(v, 값);` 모든 표준 컨테이너에 있다 |
| C++20 이전의 `vector` | `v.erase(std::remove_if(v.begin(), v.end(), 조건), v.end());` |
| 손으로 | `it = v.erase(it);` 지웠으면 `++it`를 하지 않는다 |
| `map`, `set` | `it = m.erase(it);` 같다 |

`vector`에서 하나씩 `erase`하면 지울 때마다 뒤의 원소를 모두 당깁니다. 여러 개를 지울 때는 `erase_if`가 한 번의 훑기로 끝내므로 훨씬 빠릅니다.

## 자기 자신의 원소를 넣기

`v.push_back(v[0]);`은 **괜찮습니다.** 표준이 이 경우에도 옳게 동작하도록 요구하고, 구현은 재할당하기 전에 값을 먼저 챙깁니다. `v.insert(v.begin(), v.back());`도 같습니다. 반면 자기 자신의 **범위**를 넘기는 `v.insert(v.end(), v.begin(), v.end());`는 정의되지 않은 동작입니다. 넣는 도중에 그 반복자들이 무효가 되기 때문입니다. 복사본을 먼저 만들어 그것을 넣습니다.

<Note>
`-D_GLIBCXX_DEBUG`는 libstdc++의 디버그 모드입니다. 반복자가 자기 컨테이너를 기억하고 있다가 무효가 된 뒤의 사용을 알려 줍니다. 컨테이너의 크기와 배치가 바뀌므로, **프로그램 전체**(링크하는 라이브러리까지)를 같은 옵션으로 빌드해야 합니다. 일부만 켜면 그것이 [ODR 위반](#/read/cpp-syntax/mod-headers)이 됩니다. 가벼운 대안은 [`-D_GLIBCXX_ASSERTIONS`](#/read/cpp-syntax/ubc-tools)입니다.
</Note>

## 정리

- `vector`와 `string`은 재할당되면 원소를 가리키던 모든 것이 죽는다. 노드 기반 컨테이너는 지운 원소만 죽는다
- 도는 중에 넣거나 지우지 않는다. 지울 때는 `std::erase_if`, 손으로는 `it = v.erase(it)`
- 그냥 빌드에서는 티가 나지 않는다. AddressSanitizer가 잡는다
