C++은 C보다 헤더에 코드를 훨씬 많이 둡니다. 템플릿과 작은 함수가 통째로 헤더에 들어갑니다. 그러려면 "정의는 프로그램 전체에 하나"라는 링커의 규칙과 부딪히지 않아야 합니다.

## 하나의 정의 규칙

**선언**은 몇 번을 해도 되지만 **정의**는 한 번만 있어야 합니다. 이것을 ODR(One Definition Rule)이라고 부릅니다. C에서 헤더에 함수 본문을 적으면 안 됐던 이유와 같습니다([「심볼이란」](#/read/c-basic/symbols)).

```cpp nocheck
// util.h
#pragma once
int twice(int x) { return x * 2; }      // 정의가 헤더에 있다
```

이 헤더를 `a.cpp`와 `main.cpp`가 포함하면 두 목적 파일에 `twice`가 하나씩 생기고, 링커가 거부합니다.

```text
main.cpp:(.text+0x0): multiple definition of `twice(int)';
a.o:a.cpp:(.text+0x0): first defined here
```

## inline

```cpp nocheck
// util.h
#pragma once
inline int twice(int x) { return x * 2; }
```

`inline`을 붙이면 링크가 됩니다. `inline`의 뜻은 <strong>"이 정의는 여러 번역 단위에 똑같이 나타나도 되고, 링커가 하나만 남긴다"</strong>입니다. `nm`으로 보면 심볼의 종류가 `T`에서 `W`(약한 심볼)로 바뀌어 있습니다.

이름 때문에 "호출을 본문으로 바꿔 넣어 빠르게 한다"로 알려져 있지만, 요즘 컴파일러는 그 판단을 `inline`과 상관없이 스스로 합니다. 지금의 `inline`은 링커에게 하는 말입니다.

## 적지 않아도 inline인 것

| 대상 | 헤더에 정의해도 되는 이유 |
| --- | --- |
| 클래스 정의 안에 본문을 적은 멤버 함수 | 저절로 `inline` |
| 템플릿 | 쓰는 곳마다 만들어지고 링커가 합친다 |
| `constexpr`, `consteval` 함수 | 저절로 `inline` |
| 클래스, 구조체, `enum`의 정의 | 번역 단위마다 하나씩 있어도 된다 (내용이 같아야 한다) |

## inline 변수

C++17부터 변수에도 `inline`을 붙일 수 있습니다. 헤더에 전역 상수와 `static` 멤버를 정의할 때 씁니다.

```cpp
#include <print>
#include <string_view>

inline constexpr int max_pins = 40;                 // 헤더에 둬도 프로그램에 하나
inline constexpr std::string_view board = "pi5";

struct limits {
    static inline int open_count = 0;       // 클래스 밖에 따로 정의하지 않아도 된다
};

int main()
{
    ++limits::open_count;
    std::println("{} {} {}", max_pins, board, limits::open_count);
}
```

```text
40 pi5 1
```

## 헤더에 두는 것과 두지 않는 것

| 헤더에 둔다 | `.cpp`에 둔다 |
| --- | --- |
| 선언: `int counter();` | 보통 함수의 정의 |
| `inline` 함수, 템플릿, `constexpr` 함수 | `inline`이 아닌 전역 변수의 정의 |
| 클래스 정의, `enum`, `using` 별칭 | 이름 없는 네임스페이스 안의 도우미 |
| `inline` 변수, `constexpr` 상수 | |

헤더에서 `static int twice(int)`로 써도 링크는 됩니다. 하지만 뜻이 다릅니다. `static`은 포함한 파일마다 **따로따로** 하나씩 만들고, `inline`은 프로그램 전체에 **하나**입니다. 함수 안에 `static` 지역 변수가 있다면 결과가 달라집니다.

## 정의가 서로 다르면

`inline` 함수와 클래스는 여러 번역 단위에 나타나도 되지만, **모두 똑같아야** 합니다. 다르면 정의되지 않은 동작이고, 컴파일러도 링커도 알려 주지 않습니다.

```cpp nocheck
// a.cpp                                 // b.cpp
struct packet { int id; };               struct packet { int id; int size; };
inline int size_of() { return 4; }       inline int size_of() { return 8; }
```

링커는 둘 중 아무거나 하나를 남깁니다. 같은 이름의 구조체를 서로 다른 `.cpp`에서 따로 정의하거나, 파일마다 `#define`이 달라서 같은 헤더가 다르게 펼쳐질 때 생깁니다. 파일 안에서만 쓰는 타입과 함수는 [이름 없는 네임스페이스](#/read/cpp-syntax/ns-basic)에 넣으면 이 사고가 나지 않습니다.

<Note kind="tip">
작은 함수를 헤더에 `inline`으로 두면 컴파일러가 호출하는 쪽에서 본문을 볼 수 있어 실제로 끼워 넣기 쉬워집니다. 하지만 헤더를 고칠 때마다 그것을 포함한 파일이 전부 다시 컴파일됩니다. 자주 바뀌는 함수는 `.cpp`에 둡니다.
</Note>

## 정리

- 정의는 프로그램에 하나(ODR). 헤더에 정의를 두려면 `inline`이어야 한다
- `inline`은 "여러 곳에 똑같이 나타나도 된다"는 뜻. 클래스 안의 함수, 템플릿, `constexpr`은 저절로 그렇다
- 헤더의 상수는 `inline constexpr`로
