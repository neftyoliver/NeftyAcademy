템플릿은 모든 타입에 같은 본문을 씁니다. 특수화는 "이 타입일 때는 이 정의를 쓴다"는 예외를 두는 문법입니다.

## 완전 특수화와 부분 특수화

```cpp
#include <cstddef>
#include <print>

template <typename T>
struct Describe {                       // 기본 템플릿
    static const char* text() { return "어떤 타입"; }
};

template <>
struct Describe<int> {                  // 완전 특수화: 정확히 int일 때
    static const char* text() { return "정수"; }
};

template <typename T>
struct Describe<T*> {                   // 부분 특수화: 모든 포인터 타입
    static const char* text() { return "포인터"; }
};

template <typename T, std::size_t N>
struct Describe<T[N]> {                 // 부분 특수화: 모든 배열 타입
    static const char* text() { return "배열"; }
};

int main()
{
    std::println("{}", Describe<double>::text());
    std::println("{}", Describe<int>::text());
    std::println("{}", Describe<char*>::text());
    std::println("{}", Describe<int[4]>::text());
}
```

```text
어떤 타입
정수
포인터
배열
```

| 종류 | 꼴 | 뜻 |
| --- | --- | --- |
| 기본 템플릿 | `template <typename T> struct X` | 달리 맞는 것이 없을 때 |
| 완전 특수화 | `template <> struct X<int>` | 인자가 **모두** 정해진 한 가지 경우 |
| 부분 특수화 | `template <typename T> struct X<T*>` | 인자가 어떤 **무늬**에 맞는 모든 경우 |

컴파일러는 맞는 것 가운데 **가장 구체적인 것**을 고릅니다. `Describe<char*>`에는 기본 템플릿과 `T*` 특수화가 모두 맞지만 `T*`가 더 구체적입니다.

특수화는 기본 템플릿과 **아무것도 공유하지 않는** 별개의 클래스입니다. 멤버를 물려받지 않으므로 필요한 것을 모두 다시 써야 합니다.

## 표준 라이브러리에 끼워 넣기

특수화를 가장 자주 쓰는 곳은 내 템플릿이 아니라 **표준 라이브러리의 템플릿**입니다. 표준 라이브러리는 "타입마다 달라지는 부분"을 클래스 템플릿으로 떼어 두고, 사용자가 자기 타입에 대해 특수화하게 해 두었습니다.

```cpp
#include <cstddef>
#include <functional>
#include <print>
#include <unordered_map>

struct Pin {
    int chip;
    int line;
    bool operator==(const Pin&) const = default;
};

template <>
struct std::hash<Pin> {                 // Pin을 해시하는 법을 알려 준다
    std::size_t operator()(const Pin& p) const noexcept
    {
        return std::hash<int>{}(p.chip * 64 + p.line);
    }
};

int main()
{
    std::unordered_map<Pin, const char*> names;
    names[{0, 17}] = "LED";
    names[{0, 27}] = "BUTTON";
    std::println("{}", names[{0, 17}]);
}
```

```text
LED
```

`std::unordered_map<Key, Value>`는 안에서 `std::hash<Key>`를 씁니다. `Pin`에 대한 `std::hash`가 없으면 컴파일되지 않고, 위처럼 특수화를 두면 됩니다.

| 템플릿 | 특수화하면 |
| --- | --- |
| `std::hash<T>` | `unordered_map`, `unordered_set`의 키로 쓸 수 있다 |
| [`std::formatter<T>`](#/read/cpp-syntax/op-stream) | `std::println("{}", 값)`으로 찍을 수 있다 |
| `std::tuple_size<T>`, `std::tuple_element<I, T>` | [구조적 바인딩](#/read/cpp-syntax/types-binding)으로 풀 수 있다 |

`std` 네임스페이스에 무언가를 넣는 것은 원래 금지이지만, **내 타입에 대한 특수화**는 표준이 허락한 예외입니다.

## 함수 템플릿은 오버로딩으로

함수 템플릿은 부분 특수화가 **없습니다.** 완전 특수화는 되지만 오버로드를 고르는 과정에 끼지 못해 뜻밖의 것이 뽑히곤 합니다. 함수는 특수화하지 말고 오버로드합니다.

```cpp nocheck
template <typename T> void show(T value);       // (1)
template <typename T> void show(T* pointer);    // (2) 포인터용 오버로드
void show(const char* text);                    // (3) 보통 함수

show(42);           // (1)
show(&x);           // (2): 더 구체적인 템플릿이 이긴다
show("text");       // (3): 똑같이 맞으면 보통 함수가 이긴다
```

## 타입에서 타입을 뽑아내기

부분 특수화는 무늬 맞추기입니다. 맞춘 조각을 멤버로 내놓으면 "타입을 받아 타입을 돌려주는 함수"가 됩니다.

```cpp nocheck
template <typename T> struct remove_pointer     { using type = T; };
template <typename T> struct remove_pointer<T*> { using type = T; };

remove_pointer<int*>::type x;       // int
remove_pointer<int>::type y;        // int
```

`<type_traits>`의 `std::remove_pointer`, `std::remove_const`, `std::is_pointer`가 실제로 이렇게 만들어져 있습니다. [「static_assert와 타입 특성」](#/read/cpp-syntax/ct-assert)에서 씁니다.

<Note kind="warn">
`std::vector<bool>`은 표준이 정해 둔 특수화입니다. `bool`을 1비트씩 채워 넣어서 `v[0]`이 `bool&`가 아니라 대리 객체를 돌려주고, `&v[0]`으로 `bool*`를 얻을 수 없습니다. "특수화가 기본 템플릿과 다른 인터페이스를 가지면 쓰는 쪽이 놀란다"는 것을 보여 주는 사례로 자주 꼽힙니다. 바이트 단위의 `bool` 배열이 필요하면 `std::vector<char>`나 `std::vector<std::uint8_t>`를 씁니다.
</Note>

## 정리

- 완전 특수화는 한 타입, 부분 특수화는 무늬에 맞는 모든 타입. 가장 구체적인 것이 뽑힌다
- `std::hash`, `std::formatter`를 내 타입에 대해 특수화해서 표준 라이브러리에 끼워 넣는다
- 함수 템플릿은 특수화하지 말고 오버로드한다
