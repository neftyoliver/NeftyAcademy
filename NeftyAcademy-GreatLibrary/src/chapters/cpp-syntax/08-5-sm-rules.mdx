export const summary = '특수 멤버 함수 다섯, 컴파일러가 만들어 주는 조건, = default와 = delete';

소멸자, 복사 생성자, 복사 대입 연산자, 이동 생성자, 이동 대입 연산자. 이 다섯을 **특수 멤버 함수**라고 부릅니다. 적지 않으면 컴파일러가 만들어 주지만, 하나를 적으면 다른 것이 사라지는 규칙이 얽혀 있습니다. 숫자 셋으로 정리합니다.

## 0의 규칙

**다섯 가운데 아무것도 적지 않는다.** 멤버를 스스로 복사되고, 옮겨지고, 정리되는 타입으로만 구성하면 컴파일러가 만든 것이 전부 옳습니다.

```cpp
#include <memory>
#include <print>
#include <string>
#include <type_traits>
#include <vector>

struct Reading {                // 0의 규칙: 아무것도 적지 않는다
    std::string sensor;
    std::vector<double> samples;
};

struct Handle {                 // 이동만 되는 타입
    Handle() = default;
    Handle(const Handle&) = delete;
    Handle& operator=(const Handle&) = delete;
    Handle(Handle&&) noexcept = default;
    Handle& operator=(Handle&&) noexcept = default;

    std::unique_ptr<int> resource;
};

struct Legacy {                 // 소멸자만 적었다
    ~Legacy() {}
    std::string name;
};

void row(const char* name, bool copy, bool move, bool nothrow_move)
{
    std::println("{:8} 복사 {:5} 이동 {:5} 예외 없는 이동 {}",
                 name, copy, move, nothrow_move);
}

int main()
{
    row("Reading", std::is_copy_constructible_v<Reading>,
        std::is_move_constructible_v<Reading>,
        std::is_nothrow_move_constructible_v<Reading>);
    row("Handle", std::is_copy_constructible_v<Handle>,
        std::is_move_constructible_v<Handle>,
        std::is_nothrow_move_constructible_v<Handle>);
    row("Legacy", std::is_copy_constructible_v<Legacy>,
        std::is_move_constructible_v<Legacy>,
        std::is_nothrow_move_constructible_v<Legacy>);
}
```

```text
Reading  복사 true  이동 true  예외 없는 이동 true
Handle   복사 false 이동 true  예외 없는 이동 true
Legacy   복사 true  이동 true  예외 없는 이동 false
```

`Reading`은 아무것도 적지 않았는데 복사도 이동도 되고 이동은 `noexcept`입니다. 가장 좋은 상태입니다.

## 하나를 적으면 다른 것이 사라진다

`Legacy`를 보세요. 빈 소멸자 하나를 적었을 뿐인데 "예외 없는 이동"이 `false`가 됐습니다. 이동 생성자가 **만들어지지 않아서**, 옮기려 하면 복사 생성자가 대신 불리기 때문입니다.

| 직접 적은 것 | 복사 생성·대입 | 이동 생성·대입 |
| --- | --- | --- |
| 아무것도 없음 | 만들어 준다 | 만들어 준다 |
| 소멸자 | 만들어 준다 (표준은 이 동작을 없앨 예정으로 표시해 두었다) | **만들지 않는다** → 복사로 대신한다 |
| 복사 생성자나 복사 대입 | 적은 것만 있다 | **만들지 않는다** |
| 이동 생성자나 이동 대입 | **지워진다** | 적은 것만 있다 |

논리는 이렇습니다. 소멸자나 복사를 직접 적었다는 것은 "이 클래스는 자원을 특별하게 다룬다"는 뜻이므로, 컴파일러가 멤버별 이동을 함부로 만들지 않습니다. 이동을 직접 적었다면 멤버별 복사도 옳지 않을 테니 지웁니다.

## 5의 규칙

**다섯 가운데 하나를 적어야 한다면 다섯을 모두 정한다.** 직접 쓰든, `= default`로 달라고 하든, `= delete`로 막든 하나하나 뜻을 밝힙니다. C++11 전에는 이동이 없어서 "3의 규칙"(소멸자, 복사 생성자, 복사 대입)이라고 불렀습니다.

`Handle`이 그 예입니다. 복사 둘은 지우고 이동 둘은 `= default`로 돌려받았습니다.

| 표기 | 뜻 |
| --- | --- |
| `= default` | 컴파일러가 만드는 것을 그대로 쓰겠다 |
| `= delete` | 이 연산은 없다. 쓰면 컴파일 오류 |

## 어느 타입이 어느 쪽인가

| 타입의 성격 | 규칙 | 예 |
| --- | --- | --- |
| 값의 묶음, 다른 클래스를 조합한 것 | 0 | 대부분의 클래스 |
| 날 자원 하나를 쥔 작은 래퍼 | 5 | 파일 기술자, C 라이브러리의 핸들 |
| 복사가 말이 안 되는 것 | 복사 `delete`, 이동 `default` | 연결, 잠금, 장치 |
| 옮기는 것도 말이 안 되는 것 | 넷 다 `delete` | 자기 주소를 남에게 알려 준 객체 |

5의 규칙을 따르는 클래스는 프로그램에 몇 개뿐이어야 합니다. 그것들을 멤버로 쓰는 나머지 클래스는 모두 0의 규칙입니다. 표준 라이브러리의 `std::unique_ptr`와 `std::vector`가 이미 메모리에 대해 그 일을 해 두었습니다.

## 상속의 바탕이 되는 클래스

가상 소멸자를 적어야 하는 클래스는 소멸자를 적는 순간 이동이 사라집니다. 필요하면 다섯을 `= default`로 되살립니다. 다만 그런 클래스는 대개 복사하지 않는 것이 옳습니다([「가상 소멸자」](#/read/cpp-syntax/inh-dtor), [「객체 잘림」](#/read/cpp-syntax/inh-slicing)).

<Note kind="tip">
클래스를 쓰다가 소멸자를 적고 싶어지면 멈추고 물어보세요. "이 일을 대신해 줄 멤버 타입이 없는가?" `delete`는 [`unique_ptr`](#/read/cpp-syntax/ft-ownership)가, `fclose`는 삭제자를 바꿔 단 `unique_ptr`나 작은 래퍼 클래스가 맡을 수 있습니다.
</Note>

## 정리

- 0의 규칙: 스스로 관리되는 멤버로만 구성하고 다섯을 적지 않는다. 기본으로 삼는다
- 소멸자나 복사를 적으면 이동이 사라지고 복사로 대신된다
- 5의 규칙: 하나를 적었다면 다섯 모두를 직접 쓰거나 `= default`, `= delete`로 정한다
