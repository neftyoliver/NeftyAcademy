프로그램이 실행될 때마다 같은 값을 계산한다면 그 계산은 **컴파일할 때 한 번** 해 두면 됩니다. `constexpr`은 "이것은 컴파일할 때 계산될 수 있다"는 표시입니다.

## 컴파일할 때 만든 표

```cpp
#include <array>
#include <cstddef>
#include <cstdint>
#include <print>
#include <string_view>

constexpr std::uint8_t crc8_byte(std::uint8_t value)
{
    for (int bit = 0; bit < 8; ++bit) {
        bool top = value & 0x80;
        value = static_cast<std::uint8_t>(value << 1);
        if (top)
            value ^= 0x07;
    }
    return value;
}

constexpr std::array<std::uint8_t, 256> make_table()
{
    std::array<std::uint8_t, 256> table{};
    for (std::size_t i = 0; i < table.size(); ++i)
        table[i] = crc8_byte(static_cast<std::uint8_t>(i));
    return table;
}

constexpr auto crc_table = make_table();        // 256칸이 컴파일할 때 채워진다

constexpr std::uint8_t crc8(std::string_view text)
{
    std::uint8_t crc = 0;
    for (char c : text)
        crc = crc_table[crc ^ static_cast<std::uint8_t>(c)];
    return crc;
}

static_assert(crc8("123456789") == 0xF4);       // 컴파일할 때 검사된다

int main()
{
    std::println("{:#04x} {:#04x}", crc_table[1], crc_table[255]);
    std::println("{:#04x}", crc8("123456789"));

    constexpr int size = 4 * 8;
    std::array<int, size> buffer{};             // 상수가 필요한 자리에 쓴다
    std::println("{}", buffer.size());
}
```

```text
0x07 0xf3
0xf4
32
```

`crc_table`은 실행 파일의 읽기 전용 구역(`.rodata`)에 **이미 계산된 256바이트**로 들어갑니다. 프로그램이 시작할 때 표를 만드는 코드는 없습니다. 마이크로컨트롤러에서는 이 표가 RAM이 아니라 플래시에 놓입니다. C에서는 이런 표를 스크립트로 만들어 소스에 붙여 넣었습니다.

## constexpr 변수

`constexpr` 변수는 `const`이면서, 초기값이 **컴파일할 때 정해져야** 합니다.

| | 초기값 | 상수가 필요한 자리(배열 크기, 템플릿 인자, `case`)에 |
| --- | --- | --- |
| `const int n = read_config();` | 실행 중에 정해져도 된다 | 쓸 수 없다 |
| `const int n = 32;` | 우연히 상수 | 쓸 수 있다 (정수일 때만의 옛 규칙) |
| `constexpr int n = 32;` | 반드시 상수. 아니면 컴파일 오류 | 쓸 수 있다 |

"이 값은 컴파일할 때의 상수다"가 뜻이라면 `constexpr`을 씁니다. C의 `#define SIZE 32`를 대신합니다. 타입이 있고, 네임스페이스를 따르고, 디버거에 이름이 보입니다.

## constexpr 함수

`constexpr` 함수는 **두 가지로** 쓰입니다.

| 부르는 곳 | 일어나는 일 |
| --- | --- |
| 상수가 필요한 자리, 인자가 모두 상수 | 컴파일러가 직접 계산한다. 결과만 실행 파일에 남는다 |
| 그 밖 (인자가 실행 중에 정해진다) | 보통 함수처럼 실행 중에 불린다 |

위의 `crc8`이 그렇습니다. `static_assert` 안에서는 컴파일할 때, `main` 안의 `println`에서는 (최적화가 없으면) 실행 중에 계산됩니다. **같은 함수를 한 번만 쓰고** 양쪽에서 씁니다.

컴파일할 때의 계산을 **보장**하려면 결과를 `constexpr` 변수에 받습니다. `constexpr auto c = crc8("abc");`

## 쓸 수 있는 것

`constexpr` 함수 안에서 할 수 있는 일은 표준이 나올 때마다 늘었습니다.

| 표준 | 할 수 있게 된 것 |
| --- | --- |
| C++11 | `return` 한 줄 |
| C++14 | 지역 변수, `if`, 반복문 |
| C++17 | 람다, [`if constexpr`](#/read/cpp-syntax/ct-if) |
| C++20 | `new`와 `delete`, `std::vector`와 `std::string`(계산이 끝나기 전에 모두 해제되어야 한다), 가상 함수, `try` |
| C++23 | 제약이 더 풀렸다. `constexpr`을 붙이는 것 자체는 거의 늘 된다 |

여전히 안 되는 것은 컴파일러가 흉내 낼 수 없는 일입니다. 파일 읽기, `reinterpret_cast`, 정의되지 않은 동작이 그렇습니다.

## 정의되지 않은 동작이 오류가 된다

컴파일할 때의 계산에서는 정의되지 않은 동작이 **컴파일 오류**입니다.

```cpp nocheck
constexpr int scale(int value) { return value * 1000; }

constexpr int ok = scale(1'000'000);        // 1,000,000,000: 된다
constexpr int bad = scale(3'000'000);       // 오류: overflow in constant expression
```

실행 중이었다면 조용히 틀린 값이 나왔을 넘침입니다. 범위를 벗어난 배열 접근, 널 포인터 읽기도 마찬가지로 잡힙니다. 중요한 계산 함수를 `constexpr`로 만들고 `static_assert`로 몇 가지 입력을 확인해 두면, **컴파일러가 단위 시험을 돌려 주는** 셈이 됩니다.

## 헤더에 둔다

`constexpr` 함수는 암묵적으로 [`inline`](#/read/cpp-syntax/fn-inline)입니다. 컴파일러가 계산하려면 본문이 보여야 하므로 헤더에 정의합니다. 헤더에 두는 `constexpr` 변수는 `inline constexpr`로 적어 프로그램 전체에 하나만 있게 합니다.

<Note>
컴파일할 때의 계산은 컴파일 시간을 씁니다. 256칸짜리 표는 눈에 띄지 않지만, 수백만 번 도는 반복은 컴파일을 느리게 하고 컴파일러의 한도(`-fconstexpr-ops-limit`)에 걸립니다. 큰 표는 여전히 스크립트로 만드는 편이 낫습니다. C++26의 `#embed`가 그런 데이터를 넣는 길을 열어 줍니다([「C++26」](#/read/cpp-syntax/ver-26)).
</Note>

## 정리

- `constexpr` 변수는 컴파일할 때 값이 정해지는 상수. `#define` 상수를 대신한다
- `constexpr` 함수는 컴파일할 때도, 실행 중에도 불린다. 표를 미리 만들어 읽기 전용 메모리에 둘 수 있다
- 컴파일할 때의 계산에서는 넘침 같은 정의되지 않은 동작이 컴파일 오류로 드러난다
