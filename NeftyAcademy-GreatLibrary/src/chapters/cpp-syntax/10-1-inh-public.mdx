상속은 "B는 A의 한 종류다"를 타입으로 적는 방법입니다. `Led`가 `Device`를 상속하면 `Device`가 필요한 자리 어디에나 `Led`를 넘길 수 있습니다.

## 물려받기

```cpp
#include <print>
#include <string>
#include <utility>

class Device {
public:
    explicit Device(std::string name) : name_(std::move(name))
    {
        std::println("Device 생성");
    }
    ~Device() { std::println("Device 소멸"); }
    const std::string& name() const { return name_; }

protected:
    void log(const std::string& text) const
    {
        std::println("[{}] {}", name_, text);
    }

private:
    std::string name_;
};

class Led : public Device {             // Led는 Device의 한 종류다
public:
    Led(std::string name, int pin) : Device(std::move(name)), pin_(pin)
    {
        std::println("Led 생성 (pin {})", pin_);
    }
    ~Led() { std::println("Led 소멸"); }
    void on() { log("켜짐"); }            // protected 멤버는 자식이 쓸 수 있다

private:
    int pin_;
};

void describe(const Device& d) { std::println("이름: {}", d.name()); }

int main()
{
    Led led("status", 17);
    led.on();
    describe(led);              // Led를 Device&로 받는다
}
```

```text
Device 생성
Led 생성 (pin 17)
[status] 켜짐
이름: status
Led 소멸
Device 소멸
```

`Device`를 **부모 클래스**(기반 클래스), `Led`를 **자식 클래스**(파생 클래스)라고 합니다.

- `Led` 객체 안에는 `Device` 부분이 통째로 들어 있다. 부모의 멤버가 앞에, 자식의 멤버가 뒤에 놓인다
- 부모의 `public` 함수는 자식에서도 `public`이다 (`led.name()`)
- 부모의 `private` 멤버는 자식 안에 있지만 자식이 직접 만질 수는 없다
- 자식의 포인터와 참조는 부모의 포인터와 참조로 저절로 바뀐다 (`describe(led)`)

C에서 구조체의 첫 멤버로 다른 구조체를 넣고 포인터를 형 변환해 쓰던 기법과 메모리 배치가 같습니다. 그 관례를 언어가 맡아 준 것입니다.

## 생성과 소멸의 순서

자식의 생성자는 초기화 리스트의 맨 앞에서 **부모의 생성자를 부릅니다**(`Device(std::move(name))`). 적지 않으면 부모의 기본 생성자가 불리고, 그것이 없으면 오류입니다.

| 만들어질 때 | 사라질 때 |
| --- | --- |
| 1. 부모의 생성자 | 1. 자식의 소멸자 본문 |
| 2. 자식의 멤버들 | 2. 자식의 멤버들 |
| 3. 자식의 생성자 본문 | 3. 부모의 소멸자 |

집을 짓는 순서와 허무는 순서입니다. 자식은 부모가 다 지어진 뒤에야 일을 시작하고, 부모보다 먼저 치워집니다.

## 접근 지정 다시 보기

| 멤버의 지정 | 클래스 안 | 자식 클래스 안 | 바깥 |
| --- | --- | --- | --- |
| `public` | 쓴다 | 쓴다 | 쓴다 |
| `protected` | 쓴다 | 쓴다 | 못 쓴다 |
| `private` | 쓴다 | 못 쓴다 | 못 쓴다 |

`class Led : public Device`의 `public`은 "부모의 `public`을 그대로 `public`으로 물려받는다"는 뜻입니다. `class`는 적지 않으면 `private` 상속이 되어 `describe(led)`가 컴파일되지 않습니다. **늘 `public`을 적습니다.** `private` 상속은 거의 쓰지 않습니다.

`protected` 데이터 멤버는 피하는 편이 좋습니다. 자식이 부모의 데이터를 직접 고치면 부모가 지키던 약속이 깨집니다. 위처럼 `protected` 함수를 내주는 정도로 씁니다.

## 상속할까, 멤버로 가질까

| 관계 | 적는 법 | 예 |
| --- | --- | --- |
| A는 B의 한 종류다 (is-a) | `class A : public B` | `Led`는 `Device`다 |
| A는 B를 가지고 있다 (has-a) | `B` 타입의 멤버 | `Robot`은 `Motor`를 가진다 |

상속은 강한 묶음입니다. 부모가 바뀌면 자식이 모두 영향을 받고, 부모가 약속한 모든 것을 자식도 지켜야 합니다. "부모가 쓰이는 모든 자리에 자식을 대신 넣어도 프로그램이 옳게 도는가"가 기준입니다. **코드를 다시 쓰고 싶을 뿐이라면 멤버로 가지는 쪽**이 맞습니다.

## 이름 가리기

```cpp nocheck
struct Base {
    void set(int v);
    void set(double v);
};
struct Derived : Base {
    using Base::set;        // 없으면 아래 set 하나가 부모의 set 둘을 가린다
    void set(const char* v);
};
```

자식에 같은 이름의 함수가 있으면 부모의 그 이름은 **인자가 달라도 전부** 가려집니다. [이름을 안쪽에서 바깥쪽으로 찾다가 처음 찾은 곳에서 멈추기](#/read/cpp-syntax/ns-basic) 때문입니다. `using Base::set;`으로 부모의 것을 함께 보이게 합니다.

<Note>
`struct`는 적지 않으면 `public` 상속입니다. 그래서 `struct Derived : Base`는 `public`을 생략할 수 있습니다. 이 책의 짧은 예제에서는 그렇게 쓰기도 합니다.
</Note>

## 정리

- `class 자식 : public 부모`. 자식 객체는 부모 부분을 품고, 부모가 필요한 자리에 쓰일 수 있다
- 생성은 부모부터, 소멸은 자식부터
- "한 종류다"일 때만 상속. 코드를 빌려 쓰려는 것이면 멤버로 가진다
