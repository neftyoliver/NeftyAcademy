export const summary = '예외가 지나가는 길의 소멸자가 불린다, 정리 코드를 소멸자에 두기, 비용';

예외가 던져지면 `throw`에서 `catch`까지 함수 여러 개를 건너뜁니다. 건너뛴 함수들의 지역 객체는 버려지지 않고 **소멸자가 차례로 불립니다.** 이것을 스택 풀기(stack unwinding)라고 합니다.

## 풀리는 순서

```cpp
#include <print>
#include <stdexcept>

struct Trace {
    const char* name;
    explicit Trace(const char* n) : name(n) { std::println("+ {}", name); }
    ~Trace() { std::println("- {}", name); }
};

void inner()
{
    Trace t("inner");
    throw std::runtime_error("고장");
}

void outer()
{
    Trace t("outer");
    inner();
    std::println("여기는 실행되지 않는다");
}

int main()
{
    try {
        Trace t("try 블록");
        outer();
    } catch (const std::exception& e) {
        std::println("잡음: {}", e.what());
    }
}
```

```text
+ try 블록
+ outer
+ inner
- inner
- outer
- try 블록
잡음: 고장
```

만들어진 순서의 **거꾸로**, `catch`에 들어가기 **전에** 모두 치워졌습니다. 함수가 `return`으로 끝날 때와 똑같은 정리가 일어납니다.

## 정리 코드는 소멸자에

C 방식의 코드는 예외 앞에서 샙니다.

```cpp nocheck
void save(const Data& data)
{
    FILE* f = std::fopen("out.bin", "wb");
    write_all(f, data);         // 여기서 예외가 나면
    std::fclose(f);             // 이 줄은 실행되지 않는다. 파일이 열린 채 남는다
}
```

`try`/`catch`로 감싸 `fclose`를 두 번 적는 것은 답이 아닙니다. 자원을 **객체가 쥐게** 하면 됩니다. [소멸자](#/read/cpp-syntax/class-dtor)는 어떤 길로 함수를 떠나든 불립니다.

| 자원 | 쥐는 객체 |
| --- | --- |
| 힙 메모리 | `std::unique_ptr`, `std::vector`, `std::string` |
| 파일 | `std::ofstream`, 또는 `std::unique_ptr<FILE, 닫는 함수>` |
| 뮤텍스 잠금 | `std::lock_guard`, `std::scoped_lock` |
| 파일 디스크립터, GPIO 줄, 소켓 | 직접 만든 작은 클래스 |

이 원칙이 RAII이고, C++에 `finally`가 없는 까닭입니다. 정리할 것을 모두 객체가 쥐고 있으면 예외가 어디서 나든 새는 것이 없습니다. `try`/`catch`는 오류를 **처리**할 곳에만 쓰고, **정리**에는 쓰지 않습니다.

## 생성자가 던지면

생성자가 도중에 예외를 던지면 그 객체는 "만들어진 적이 없는 것"이 됩니다. **그 객체의 소멸자는 불리지 않습니다.** 대신 이미 만들어진 멤버와 부모는 거꾸로 순서로 치워집니다.

```cpp
#include <print>
#include <stdexcept>

struct Part {
    const char* name;
    explicit Part(const char* n) : name(n) { std::println("+ {}", name); }
    ~Part() { std::println("- {}", name); }
};

struct Machine {
    Part a{"a"};
    Part b{"b"};
    Machine() { throw std::runtime_error("생성 실패"); }
    ~Machine() { std::println("~Machine"); }
};

int main()
{
    try {
        Machine m;
    } catch (const std::exception& e) {
        std::println("{}", e.what());
    }
}
```

```text
+ a
+ b
- b
- a
생성 실패
```

`~Machine`이 찍히지 않았습니다. 그래서 생성자 본문에서 `new`로 얻은 맨 포인터는 샙니다. 멤버를 `std::unique_ptr`로 두면 멤버의 소멸자가 치워 줍니다. "자원 하나에 객체 하나"를 지키면 이 경우도 저절로 맞습니다.

## 소멸자는 던지지 않는다

스택을 푸는 중에 불린 소멸자가 **또** 예외를 던지면 예외가 둘이 되고, 프로그램은 `std::terminate`로 끝납니다. 그래서 소멸자는 암묵적으로 [`noexcept`](#/read/cpp-syntax/exc-noexcept)입니다. 소멸자 안에서 실패할 수 있는 일(파일 닫기 등)은 오류를 삼키거나 로그만 남깁니다. 실패를 알아야 한다면 `close()` 같은 멤버 함수를 따로 두어 소멸 전에 부르게 합니다.

## 비용

GCC와 Clang은 "표를 보고 푸는" 방식을 씁니다.

| 때 | 비용 |
| --- | --- |
| 예외가 나지 않을 때 | 실행 시간은 거의 0. `try`에 들어가는 데 명령이 들지 않는다 |
| 실행 파일 | 함수마다 "여기서 예외가 나면 무엇을 치울지"의 표가 붙어 커진다. `size -A 파일`의 `.eh_frame`, `.gcc_except_table` 줄이 그것이다 |
| 예외가 날 때 | 느리다. 예외 객체를 힙에 만들고, 표를 뒤져 가며 함수를 하나씩 푼다. 보통의 `return`과는 자릿수가 다르다 |

그래서 예외는 **드문 일**에만 씁니다. 루프 안에서 흐름을 바꾸는 용도로 쓰면 안 됩니다. 걸리는 시간을 미리 알 수 없다는 점 때문에 실시간 제어 루프에서는 피하고, 플래시가 작은 마이크로컨트롤러는 `-fno-exceptions`로 꺼 버립니다. 라즈베리 파이 급의 리눅스 프로그램에서는 켜 두는 것이 보통입니다.

<Note kind="warn">
`-fno-exceptions`로 컴파일하면 `throw`와 `try`가 컴파일 오류가 됩니다. 표준 라이브러리가 던지려는 순간(`v.at(10)`, 메모리 부족)에는 프로그램이 그대로 끝납니다. 예외를 끈 코드는 [`std::expected`](#/read/cpp-syntax/exc-without)나 반환 코드로 오류를 알립니다.
</Note>

## 정리

- 예외가 지나가는 길의 지역 객체는 만들어진 거꾸로 순서로 소멸자가 불린다
- 정리할 것은 모두 객체가 쥐게 한다(RAII). 그러면 `try`/`catch` 없이도 새지 않는다
- 소멸자는 던지지 않는다. 예외는 안 날 때는 싸고 날 때는 비싸다
