복사는 원본을 그대로 둡니다. 그런데 원본이 **어차피 곧 사라질 값**이라면, 통째로 복사한 다음 원본을 버리는 것은 낭비입니다. C++11은 "이 값은 곧 사라진다"를 타입으로 알아볼 수 있게 했습니다. 우측값 참조 `T&&`입니다.

## 좌측값과 우측값

| | 좌측값 (lvalue) | 우측값 (rvalue) |
| --- | --- | --- |
| 대략 | 이름이 있고, 그 문장 뒤에도 남는다 | 이름이 없고, 그 문장이 끝나면 사라진다 |
| 예 | 변수 `name`, `v[0]`, `*p`, 멤버 `d.pin` | `make()`가 돌려준 값, `a + b`, `std::string("x")`, `42` |
| 주소 | `&name`이 된다 | `&make()`는 안 된다 |

이름의 유래는 대입문의 왼쪽과 오른쪽이지만, 지금은 "자리가 있는 것"과 "값일 뿐인 것" 정도로 읽습니다.

## T&&는 우측값에만 묶인다

```cpp
#include <print>
#include <string>
#include <utility>

void take(const std::string& s) { std::println("좌측값: {}", s); }
void take(std::string&& s) { std::println("우측값: {}", s); }

std::string make() { return "임시"; }

int main()
{
    std::string name = "이름";
    take(name);                 // 이름이 있다 → 좌측값
    take(make());               // 함수가 돌려준 임시 객체 → 우측값
    take(name + "!");           // 계산 결과 → 우측값
    take(std::move(name));      // "이제 안 쓴다"고 표시 → 우측값으로 다룬다

    std::string&& r = make();   // 우측값 참조에 이름을 붙이면
    take(r);                    // 그 이름 자체는 좌측값이다
}
```

```text
좌측값: 이름
우측값: 임시
우측값: 이름!
우측값: 이름
좌측값: 임시
```

두 `take`는 [오버로드](#/read/cpp-syntax/fn-overload)입니다. 컴파일러는 인자가 좌측값인지 우측값인지 보고 고릅니다. 함수 쪽에서 보면 **`T&&` 판이 불렸다는 사실 자체가 "이 인자는 곧 사라지니 속을 가져가도 된다"는 신호**입니다.

| 인자 타입 | 좌측값을 받나 | 우측값을 받나 |
| --- | --- | --- |
| `T&` | 받는다 | 안 받는다 |
| `const T&` | 받는다 | 받는다 |
| `T&&` | 안 받는다 | 받는다 |

`const T&` 판만 있으면 둘 다 그것이 받습니다(지금까지 그렇게 써 왔습니다). `T&&` 판을 더하면 우측값은 그쪽으로 갑니다.

## std::move는 옮기지 않는다

`std::move(name)`은 아무것도 옮기지 않습니다. `name`을 **우측값으로 취급하라는 형 변환**일 뿐입니다. 위 예제에서 `take(std::move(name))` 뒤에도 `name`은 멀쩡합니다. `take`가 속을 가져가지 않았기 때문입니다.

실제로 옮기는 일은 `T&&`를 받는 함수가 합니다. 그 대표가 다음 챕터의 이동 생성자입니다. `std::move`는 "나는 이 변수를 더 안 쓸 테니 가져가도 좋다"는 **허락**입니다.

## 이름이 붙으면 좌측값

예제의 마지막 두 줄이 헷갈리는 곳입니다. `r`의 **타입**은 `std::string&&`이지만, `r`이라는 **식**은 이름이 있으므로 좌측값입니다. 그래서 `take(r)`은 좌측값 판을 부릅니다.

이 규칙은 일부러 그런 것입니다. 이름이 있는 것은 뒤에서 또 쓸 수 있으므로, 조용히 속을 가져가면 안 됩니다. `T&&`로 받은 인자를 다시 우측값으로 넘기려면 한 번 더 `std::move`를 씁니다.

```cpp nocheck
void store(std::string&& s)
{
    items.push_back(std::move(s));      // s는 이름이 있으므로 다시 표시해 줘야 한다
}
```

## 값 범주

표준은 좌측값과 우측값을 더 잘게 나눕니다. 오류 메시지와 문서에 나오므로 이름만 알아 둡니다.

| 이름 | 뜻 | 예 |
| --- | --- | --- |
| lvalue | 자리가 있고, 가져가면 안 된다 | `name` |
| xvalue | 자리가 있지만, 가져가도 된다 | `std::move(name)` |
| prvalue | 자리 없이 값일 뿐이다 | `make()`, `42`, `a + b` |

xvalue와 prvalue를 합쳐 rvalue라고 부릅니다.

<Note>
템플릿에서 `T&&`는 뜻이 다릅니다. `template <typename T> void f(T&& x)`의 `T&&`는 좌측값과 우측값을 모두 받는 "전달 참조"입니다. `auto&&`도 그렇습니다. 타입이 추론되는 자리의 `&&`만 그렇고, `std::string&&`처럼 타입이 정해져 있으면 언제나 우측값 참조입니다. 고급 책의 완벽 전달에서 다룹니다.
</Note>

## 정리

- 우측값은 곧 사라질 값. `T&&`는 우측값에만 묶인다
- `std::move`는 형 변환이다. "가져가도 좋다"는 표시일 뿐 옮기지 않는다
- 이름이 붙은 것은 타입이 `T&&`여도 좌측값이다
