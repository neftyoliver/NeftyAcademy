## 주소 공간과 구독

OPC UA 서버의 데이터는 **노드**와 노드를 잇는 **참조**로 된 그래프, 곧 주소 공간에 있습니다. 노드는 객체, 변수, 메서드 같은 종류(노드 클래스)를 가지고, `ns=2;s=Line1.Oven.Temperature`처럼 이름 공간 번호와 식별자로 된 NodeId로 찾습니다. 클라이언트는 Browse로 이 그래프를 따라가며 무엇이 있는지 알아낸 뒤, 필요한 변수를 읽거나 **구독**합니다. 작은 주소 공간과 구독 하나를 흉내 냈습니다.

```cpp
// OPC UA의 두 기둥을 흉내 낸다: 노드와 참조로 된 주소 공간, 그리고 구독
#include <cmath>
#include <cstdio>
#include <string>
#include <vector>

struct Node {
    std::string nodeId, browseName;
    const char* nodeClass;               // 객체, 변수, 메서드
    std::string value;                   // 변수일 때만
    std::vector<int> components;         // HasComponent 참조로 이어진 자식
};

std::vector<Node> space = {
    {"ns=0;i=85", "Objects", "객체", "", {1}},
    {"ns=2;s=Line1", "Line1", "객체", "", {2}},
    {"ns=2;s=Line1.Oven", "Oven", "객체", "", {3, 4, 5}},
    {"ns=2;s=Line1.Oven.Temperature", "Temperature", "변수",
     "180.0 (Double, °C)", {}},
    {"ns=2;s=Line1.Oven.Setpoint", "Setpoint", "변수",
     "185.0 (Double, °C)", {}},
    {"ns=2;s=Line1.Oven.Start", "Start", "메서드", "", {}},
};

void browse(int i, int depth) {          // Browse 서비스로 따라가는 것과 같다
    const Node& n = space[i];
    std::printf("%*s%s [%s] %s%s%s\n", depth * 2, "", n.browseName.c_str(),
                n.nodeClass, n.nodeId.c_str(), n.value.empty() ? "" : " = ",
                n.value.c_str());
    for (int c : n.components) browse(c, depth + 1);
}

struct Sample { double value; bool good; };

int main() {
    browse(0, 0);

    // 서버가 100ms마다 재는 온도. 1300ms에 센서가 잠깐 고장 난다
    const std::vector<Sample> samples = {
        {180.0, 1}, {180.1, 1}, {180.2, 1}, {180.3, 1}, {180.8, 1}, {181.4, 1},
        {181.5, 1}, {181.5, 1}, {181.6, 1}, {182.3, 1}, {182.2, 1}, {182.4, 1},
        {182.5, 1}, {0.0, 0},   {183.0, 1}, {183.1, 1}, {183.2, 1}, {183.9, 1},
        {184.0, 1}, {184.6, 1}};
    // 절대 데드밴드: 0.5보다 크게 바뀌어야 알린다
    const double deadband = 0.5;
    std::printf("\n구독: 샘플링 100ms, 게시 500ms, 데드밴드 %.1f\n", deadband);

    std::vector<std::string> queue;      // 다음 게시까지 쌓이는 알림
    double last = NAN;
    bool lastGood = true;
    for (int i = 0; i < int(samples.size()); ++i) {
        const int t = i * 100;
        const Sample& s = samples[i];
        const bool changed = std::isnan(last) || s.good != lastGood ||
                             (s.good && std::fabs(s.value - last) > deadband);
        if (changed) {
            char buf[48];
            if (s.good) std::snprintf(buf, sizeof buf, "%.1f(%dms)", s.value, t);
            else std::snprintf(buf, sizeof buf, "Bad(%dms)", t);
            queue.push_back(buf);
            if (s.good) last = s.value;
            lastGood = s.good;
        }
        // 게시 주기: 쌓인 알림을 한 메시지로 보낸다
        if ((t + 100) % 500 == 0) {
            std::printf("%4dms 게시, 알림 %zu개:", t + 100, queue.size());
            for (const auto& q : queue) std::printf(" %s", q.c_str());
            std::printf("\n");
            queue.clear();
        }
    }
}
```

- **스스로 설명하는 데이터**: 클라이언트는 설명서 없이도 Browse만으로 오븐 아래에 온도, 설정값, 시작 메서드가 있다는 것과 값의 타입, 단위를 알 수 있습니다. `ns=0`의 노드(Objects 폴더 `i=85` 등)는 표준이 정해 두었고, 장비의 노드는 다른 이름 공간에 있습니다
- **구독은 서버가 거른다**: 클라이언트가 2초 동안 온도를 100ms마다 물어 왔다면 요청과 응답이 20번씩 오갔을 것입니다. 구독에서는 서버가 100ms마다 값을 재되(샘플링), 0.5보다 크게 바뀐 것만 골라(데드밴드) 쌓아 두었다가 500ms마다 한 메시지로 보냅니다(게시). 20번의 샘플이 알림 8개, 메시지 4개가 되었습니다
- **값에는 상태와 시각이 붙는다**: OPC UA의 값은 늘 상태 코드(Good, Uncertain, Bad)와 시각을 함께 가집니다. 1300ms의 센서 고장은 값이 아니라 Bad 상태로 전달되었고, 데드밴드와 상관없이 바로 알림이 되었습니다. 받는 쪽은 Bad인 값을 계산에 쓰지 않습니다

## open62541로 읽기

C로 쓰인 오픈 소스 구현 open62541(MPL 2.0)이 가장 널리 쓰이며, C++에서는 그대로 부르거나 open62541pp 같은 감싸개를 씁니다. 서버의 변수 하나를 읽는 클라이언트는 이렇습니다. 이 책의 검사 환경에는 open62541 패키지가 없어 이 코드는 문서와 대조만 했습니다.

```cpp nocheck
// open62541로 OPC UA 서버의 변수 하나를 읽는다(C API를 C++에서 부름)
#include <open62541/client_config_default.h>
#include <open62541/client_highlevel.h>
#include <cstdio>

int main() {
    UA_Client* client = UA_Client_new();
    UA_ClientConfig_setDefault(UA_Client_getConfig(client));
    const char* url = "opc.tcp://192.168.0.10:4840";
    if (UA_Client_connect(client, url) != UA_STATUSCODE_GOOD) {
        UA_Client_delete(client);
        return 1;
    }
    UA_Variant value;
    UA_Variant_init(&value);
    char id[] = "Line1.Oven.Temperature";
    const UA_StatusCode rc =
        UA_Client_readValueAttribute(client, UA_NODEID_STRING(2, id), &value);
    if (rc == UA_STATUSCODE_GOOD &&
        UA_Variant_hasScalarType(&value, &UA_TYPES[UA_TYPES_DOUBLE]))
        std::printf("온도 %.1f\n", *static_cast<UA_Double*>(value.data));
    else
        std::printf("읽기 실패: %s\n", UA_StatusCode_name(rc));
    UA_Variant_clear(&value);
    UA_Client_delete(client);                    // 안에서 연결도 끊는다
}
```

- 4840은 OPC UA의 기본 포트이고, 주소는 `opc.tcp://`로 시작합니다
- `UA_Variant`는 어떤 타입의 값이든 담는 상자이므로, 꺼내기 전에 타입을 확인합니다
- 실제 프로그램은 같은 클라이언트로 구독을 만들고(`UA_Client_Subscriptions_create`, `UA_Client_MonitoredItems_createDataChange`), `UA_Client_run_iterate`를 주기적으로 불러 알림을 받습니다

<Note>
OPC UA는 처음부터 보안을 품고 설계되었습니다. 응용 프로그램마다 X.509 인증서를 가지고, 연결할 때 보안 정책과 모드(없음, 서명, 서명과 암호화)를 고르며, 사용자 인증도 따로 합니다. 시험할 때 편하다고 보안 없음으로 둔 설정이 현장에 그대로 남는 일이 흔하므로 주의합니다. 같은 정보 모델을 브로커나 UDP로 뿌리는 PubSub 방식도 있으며, 업계마다 장비 모델을 표준화한 동반 사양(예: 기계, 사출기, 로봇용)이 계속 나오고 있습니다.
</Note>

## 정리

- OPC UA는 장비의 데이터를 노드와 참조로 된 주소 공간에 이름, 타입, 단위와 함께 내놓으며, 노드는 NodeId로 찾고 Browse로 따라간다
- 구독에서는 서버가 샘플링하고 데드밴드로 걸러 게시 주기마다 묶어 보내므로, 같은 정보를 훨씬 적은 메시지로 받는다
- 값에는 상태 코드와 시각이 붙고, 연결은 인증서와 보안 정책으로 지키며, C++에서는 open62541 같은 구현을 쓴다
