HMI는 작업자가 기계를 보고 다루는 창입니다. 오래전 HMI는 장비를 사진처럼 그리고 파이프에 물이 흐르는 애니메이션을 넣는 것이 유행이었지만, 그런 화면에서는 정작 이상이 생겼을 때 눈에 띄지 않는다는 것이 사고 조사들에서 드러났습니다. 지금의 기준은 ISA-101 표준과 "고성능 HMI"라고 부르는 원칙들입니다.

## 고성능 HMI의 원칙

- **회색 바탕, 색은 이상에만**: 정상인 것은 회색과 검정으로 차분하게 그리고, 빨강·노랑 같은 강한 색은 알람과 이상에만 씁니다. 화면 전체가 알록달록하면 진짜 빨강이 묻힙니다
- **숫자보다 맥락**: "182.4°C"만 보여 주기보다, 정상 범위를 표시한 막대나 최근 추세를 함께 보여 주면 값이 괜찮은지 한눈에 압니다
- **화면의 계층**: 공장 전체의 개요(1단계), 한 구역(2단계), 한 장치의 상세(3단계), 진단(4단계)으로 나누고, 어디서든 같은 방식으로 오르내리게 합니다
- **조작은 확인을 거쳐**: 장비를 움직이는 버튼은 크고 떨어져 있어야 하며, 되돌릴 수 없는 조작은 확인을 한 번 더 받습니다

## 사람의 속도로 갱신하기

통신은 10ms마다 새 값을 가져오지만, 사람의 눈은 1초에 몇 번 이상 바뀌는 숫자를 읽지 못합니다. 그래서 화면은 대개 1초에 2~4번 갱신하고, 표시하는 자릿수에서 글자가 바뀐 칸만 다시 씁니다. 세 태그를 Qt 위젯에 묶어 3초 동안 흉내 냈습니다.

```cpp qt=Widgets
// HMI 화면 갱신: 태그는 100Hz로 바뀌어도 화면은 4Hz로, 글자가 바뀔 때만 다시 쓴다
#include <QApplication>
#include <QFormLayout>
#include <QLabel>
#include <QWidget>
#include <cstdio>
#include <map>
#include <string>

struct Tag { double value = 0; int decimals; const char* unit; };

class Screen {                                   // 태그 하나에 표시 칸 하나
    std::map<std::string, QLabel*> labels;
public:
    int textChanges = 0;
    QWidget window;
    QFormLayout* form = new QFormLayout(&window);
    void bind(const std::string& name) {
        auto* l = new QLabel;
        form->addRow(QString::fromStdString(name), l);
        labels[name] = l;
    }
    void refresh(const std::map<std::string, Tag>& tags) {   // 사람이 볼 만큼만
        for (auto& [name, label] : labels) {
            const Tag& t = tags.at(name);
            const QString text =
                QString::number(t.value, 'f', t.decimals) + " " + t.unit;
            // 표시 자릿수에서 같으면 건드리지 않는다
            if (text != label->text()) {
                label->setText(text);
                ++textChanges;
            }
        }
    }
};

int main(int argc, char* argv[]) {
    QApplication app(argc, argv);
    std::map<std::string, Tag> tags = {{"온도", {180.0, 1, "°C"}},
                                       {"압력", {2.50, 2, "bar"}},
                                       {"속도", {1200, 0, "rpm"}}};
    Screen screen;
    for (const auto& [name, tag] : tags) screen.bind(name);

    unsigned rng = 1;                            // 측정 잡음
    auto noise = [&] {                           // -2~2
        rng = rng * 1103515245u + 12345u;
        return int(rng >> 16) % 5 - 2;
    };
    int tagUpdates = 0, refreshes = 0;
    // 3초: 통신은 10ms마다 값을 가져온다
    for (int ms = 0; ms < 3000; ms += 10) {
        // 천천히 오른다
        tags["온도"].value = 180.0 + ms / 1000.0 + noise() * 0.01;
        tags["압력"].value = 2.50 + noise() * 0.001;                // 잡음만 있다
        tags["속도"].value = 1200 + noise() * 0.2;
        tagUpdates += 3;
        if (ms % 250 == 0) {                     // 화면은 4Hz
            screen.refresh(tags);
            ++refreshes;
        }
    }
    std::printf("태그 갱신 %d번, 화면 갱신 %d번, 실제로 바뀐 글자 %d번\n",
                tagUpdates, refreshes, screen.textChanges);
}
```

```text
태그 갱신 900번, 화면 갱신 12번, 실제로 바뀐 글자 14번
```

- 태그 값은 900번 바뀌었지만 화면 갱신은 12번이고, 실제로 글자를 바꾼 것은 14번(처음 세 칸 + 천천히 오르는 온도 11번)뿐입니다. 압력과 속도의 잡음은 표시 자릿수 아래라 화면이 떨리지 않았습니다
- 숫자가 쉼 없이 깜박이면 작업자는 그 칸을 보지 않게 됩니다. 표시 자릿수는 측정의 정밀도와 작업자에게 필요한 정밀도 중 작은 쪽으로 정합니다
- 화면은 통신 스레드가 채워 둔 태그 저장소를 읽기만 합니다([「폴링 설계」](#/read/cpp-industrial/plc-polling)). 장비 하나의 통신이 끊겨도 화면이 얼지 않고, 그 칸만 품질 Bad로 표시합니다

<Note>
산업용 HMI는 대부분 전용 HMI 소프트웨어나 PLC 제조사의 패널로 만들지만, 특수한 장비의 HMI는 C++과 Qt로 직접 만드는 일이 많습니다. Qt Quick의 속성 바인딩은 태그 값이 바뀔 때 화면을 자동으로 갱신하므로 편하지만, 100Hz로 바뀌는 태그를 그대로 묶으면 화면도 100Hz로 다시 그립니다. 태그와 화면 사이에 위처럼 갱신을 모아 주는 층을 두는 것이 좋습니다.
</Note>

## 정리

- 고성능 HMI는 회색 바탕에 이상에만 강한 색을 쓰고, 값에 정상 범위와 추세의 맥락을 붙이며, 화면을 개요부터 진단까지 계층으로 나눈다
- 화면은 사람이 읽을 수 있는 속도(초당 2~4번)로 갱신하고, 표시 자릿수에서 바뀐 칸만 다시 쓴다
- 화면은 통신이 채운 태그 저장소를 읽기만 하여, 통신이 멈춰도 화면이 얼지 않게 한다
