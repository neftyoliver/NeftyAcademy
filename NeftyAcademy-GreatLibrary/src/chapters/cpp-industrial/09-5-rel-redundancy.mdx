## 자리 넘김과 증인, 센서 판정

주 제어기 A와 대기 제어기 B를 두고, A는 매초 상태를 B에 보내며 증인에게 3초짜리 "주 역할 임대"를 갱신합니다. 4초에 A와 B 사이의 선만 끊기고(A는 살아 있음), 8초에 A가 정말로 죽습니다. 마지막으로 같은 값을 재는 센서 셋으로 둘 이상이 맞는 값을 골랐습니다.

```cpp
// 이중화: 주·대기 제어기의 자리 넘김과 둘로 갈라짐 막기, 센서 셋 중 둘(2oo3) 판정
#include <algorithm>
#include <array>
#include <cmath>
#include <cstdio>

struct Controller {
    const char* name;
    bool primary;
    // state: 동기화되는 공정 상태(예: 레시피 단계)
    int lastHeartbeat = 0, state = 0;
};

// 증인(arbiter): 주 역할의 임대를 한 번에 한 쪽에만 준다. 임대는 3초짜리
struct Witness {
    const char* holder = "A";
    int leaseUntil = 3;
    bool request(const char* who, int now, bool reachable) {
        if (!reachable) return false;            // 증인과도 끊긴 쪽은 받을 수 없다
        // 아직 다른 쪽의 임대
        if (now < leaseUntil && holder != who) return false;
        holder = who;
        leaseUntil = now + 3;
        return true;
    }
};

double vote2oo3(std::array<double, 3> v, double tol, int& outlier) {
    std::array<double, 3> s = v;
    std::sort(s.begin(), s.end());
    // 가운데 값은 하나가 미쳐도 멀쩡하다
    const double median = s[1];
    outlier = -1;
    for (int i = 0; i < 3; ++i)
        if (std::fabs(v[i] - median) > tol) outlier = i;
    return median;
}

int main() {
    Controller a{"A", true}, b{"B", false};
    Witness w;
    for (int t = 1; t <= 14; ++t) {              // 1초마다
        const bool aAlive = t < 8;               // A는 8초에 정말로 죽는다
        const bool linkAB = t < 4;               // A-B 사이 선은 4초에 끊긴다
        if (aAlive && a.primary) {
            ++a.state;                           // A가 일하고
            w.request("A", t, true);             // 증인에게 임대를 갱신하고
            // 선이 살아 있으면 상태를 B에 보낸다
            if (linkAB) {
                b.state = a.state;
                b.lastHeartbeat = t;
            }
        }
        if (!b.primary && t - b.lastHeartbeat >= 2) {   // 2초 동안 A의 소식이 없다
            if (w.request("B", t, true)) {
                b.primary = true;
                std::printf("%2d초: B가 주 역할을 넘겨받음"
                            "(마지막으로 받은 상태 %d)\n",
                            t, b.state);
            } else {
                std::printf("%2d초: B는 A의 소식이 없지만 증인이 거절함\n", t);
            }
        }
        if (b.primary) ++b.state;
    }
    std::printf("끝: 주=%s\n", b.primary ? "B" : "A");

    int bad;
    const double v1 = vote2oo3({101.2, 100.9, 101.1}, 1.0, bad);
    std::printf("센서 101.2, 100.9, 101.1 → %.1f, 이상한 센서 %d\n", v1, bad);
    const double v2 = vote2oo3({101.2, 12.5, 101.1}, 1.0, bad);
    std::printf("센서 101.2, 12.5, 101.1 → %.1f, 이상한 센서 %d(%s)\n", v2, bad,
                bad == 1 ? "두 번째" : "?");
}
```

```text
 8초: B는 A의 소식이 없지만 증인이 거절함
 9초: B는 A의 소식이 없지만 증인이 거절함
10초: B가 주 역할을 넘겨받음(마지막으로 받은 상태 3)
끝: 주=B
센서 101.2, 100.9, 101.1 → 101.1, 이상한 센서 -1
센서 101.2, 12.5, 101.1 → 101.1, 이상한 센서 1(두 번째)
```

- **소식이 없다고 죽은 것은 아니다**: 4초에 A-B 선이 끊기자 B는 A의 소식을 받지 못했습니다. 이때 B가 바로 주 역할을 가져갔다면 살아 있는 A와 함께 두 제어기가 같은 밸브에 다른 명령을 냈을 것입니다. B가 다른 경로의 **증인**에게 물었고, A가 임대를 계속 갱신하고 있었으므로 거절되었습니다
- **임대가 끝나야 넘긴다**: A가 8초에 죽자 마지막 갱신(7초)의 임대가 10초에 끝났고, 그제야 B가 넘겨받았습니다. 넘김에 걸리는 시간은 임대 길이로 정해지므로, 공정이 견딜 수 있는 시간보다 짧게 잡습니다
- **상태는 낡았을 수 있다**: B가 마지막으로 받은 상태는 3인데, A는 7까지 진행했습니다. 선이 끊긴 동안 동기화가 멈췄기 때문입니다. 넘겨받은 쪽은 저장된 상태를 그대로 믿지 말고 현장의 실제 값을 다시 읽어 맞춘 뒤 이어 갑니다([「오류에서 돌아오기」](#/read/cpp-industrial/rel-recovery))
- **셋 중 둘(2oo3)**: 같은 온도를 센서 셋으로 재고 가운데 값을 씁니다. 하나가 12.5처럼 엉뚱한 값을 내도 결과는 흔들리지 않고, 그 센서를 고장으로 알릴 수 있습니다. 둘로는 어느 쪽이 틀렸는지 알 수 없다는 것이 셋을 쓰는 까닭입니다

<Note>
네트워크도 이중화합니다. PRP와 HSR(IEC 62439-3)은 모든 프레임을 두 경로로 동시에 보내고 받는 쪽이 먼저 온 것을 쓰므로, 한쪽이 끊겨도 전환 시간이 0입니다. 고리 모양 네트워크의 MRP(IEC 62439-2)는 끊긴 곳을 돌아가는 경로로 바꿉니다. 전원은 이중 전원 공급 장치와 무정전 전원(UPS)으로 지킵니다. 이중화는 비싸므로, 어느 고장에 얼마나 견뎌야 하는지를 먼저 정하고 필요한 곳에만 씁니다.
</Note>

## 정리

- 주·대기 제어기는 주가 대기에 상태를 보내며, 대기는 소식이 끊기면 넘겨받되 넘겨받은 뒤 현장의 실제 값으로 상태를 맞춘다
- 소식이 끊긴 것과 죽은 것은 다르므로, 증인과 시간 제한이 있는 임대로 한 번에 한 쪽만 주 역할을 하게 해 둘로 갈라짐을 막는다
- 같은 값을 재는 센서 셋 중 가운데 값을 쓰는 2oo3 판정은 하나의 고장을 견디고 고장 난 센서를 찾아낸다
