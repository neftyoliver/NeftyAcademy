## 표준과 등급

기능 안전의 바탕은 IEC 61508이고, 분야마다 이것을 다듬은 표준이 있습니다. 위험이 클수록 높은 등급을 요구하고, 등급이 높을수록 설계, 시험, 문서의 요구가 엄격해집니다.

| 표준 | 대상 | 등급 |
| --- | --- | --- |
| IEC 61508 | 전기·전자·프로그래머블 안전 시스템 전반 | SIL 1~4 |
| ISO 13849-1 | 기계 제어 시스템의 안전 관련 부분 | PL a~e |
| IEC 62061 | 기계의 전기 제어 시스템 | SIL 1~3 |
| IEC 61511 | 공정 산업(화학, 정유) | SIL 1~4 |
| ISO 26262 | 자동차 | ASIL A~D |
| IEC 62304 | 의료 기기 소프트웨어 | 클래스 A~C |

순서는 이렇습니다. 먼저 기계가 사람을 어떻게 다치게 할 수 있는지 **위험성 평가**를 합니다. 위험은 설계로 없애고, 덮개나 울타리로 막고, 그래도 남는 위험을 **안전 기능**으로 줄입니다. 안전 기능은 "보호문이 열리면 0.5초 안에 모터의 토크를 끊는다"처럼 무엇을 감지해 어떤 안전 상태로 언제까지 가는지가 분명한 기능입니다. 등급은 이 안전 기능 하나하나에 매겨집니다.

## 안전 기능의 모양

비상 정지 버튼을 두 접점(채널)으로 읽어 기계의 운전을 허가하는 감시 논리를 흉내 냈습니다. 안전 장치들이 공통으로 쓰는 원칙이 여기에 다 들어 있습니다.

```cpp
// 비상 정지 버튼을 두 채널로 읽는 감시 논리 (개념 설명용 흉내)
#include <cstdio>

enum class State { Stopped, Running, Fault };
const char* name(State s) {
    switch (s) {
    case State::Stopped: return "정지";
    case State::Running: return "운전 허가";
    case State::Fault:   return "고장(수리 필요)";
    }
    return "?";
}

class EStopMonitor {
    static constexpr int kDiscrepancyMs = 50;   // 두 채널이 달라도 되는 시간
    State state = State::Stopped;               // 켜자마자 돌지 않는다
    int disagreeMs = 0;
    bool lastReset = false, provedBoth = false;
public:
    // a, b: 버튼의 두 접점. 닫힘(true)이 "누르지 않음"이다.
    // 전선이 끊기면 열림(false)이 되어 정지 쪽으로 간다.
    State update(bool a, bool b, bool reset, int dtMs) {
        const bool resetPressed = reset && !lastReset;
        lastReset = reset;
        disagreeMs = (a != b) ? disagreeMs + dtMs : 0;

        // 두 채널이 함께 열리는 것을 봐야 풀린다
        if (state == State::Fault) {
            if (!a && !b) provedBoth = true;
            if (provedBoth && a && b && resetPressed) state = State::Stopped;
            return state;
        }
        if (disagreeMs > kDiscrepancyMs) {      // 한쪽이 고장 났다
            state = State::Fault;
            provedBoth = false;
        } else if (!a || !b) {                  // 어느 한 채널만 열려도 멈춘다
            state = State::Stopped;
        } else if (state == State::Stopped && resetPressed) {
            state = State::Running;             // 사람이 재시작을 눌러야 돈다
        }
        return state;
    }
};

int main() {
    EStopMonitor mon;
    State last = State::Stopped;
    bool bStuck = false;                        // 채널 B 접점이 붙어 버림
    std::printf("   0ms 정지 (전원을 켬)\n");
    for (int t = 0; t <= 4000; t += 10) {
        if (t == 1500) {
            bStuck = true;
            std::printf("%4dms (채널 B 접점이 붙음)\n", t);
        }
        if (t == 3000) {
            bStuck = false;
            std::printf("%4dms (B를 고침)\n", t);
        }
        const bool pressed = (t >= 500 && t < 800) || (t >= 2000 && t < 2500) ||
                             (t >= 3200 && t < 3300);
        const bool reset = t == 100 || t == 900 || t == 2700 || t == 3400 ||
                           t == 3500;
        const bool a = !pressed;
        const bool b = bStuck ? true : !pressed;
        const State s = mon.update(a, b, reset, 10);
        if (t == 500 || t == 2000 || t == 3200)
            std::printf("%4dms 비상 정지 버튼을 누름\n", t);
        if (t == 800 || t == 2500 || t == 3300)
            std::printf("%4dms 비상 정지 버튼을 놓음\n", t);
        if (reset) std::printf("%4dms 재시작 버튼\n", t);
        if (s != last) std::printf("%4dms → %s\n", t, name(s));
        last = s;
    }
}
```

```text
   0ms 정지 (전원을 켬)
 100ms 재시작 버튼
 100ms → 운전 허가
 500ms 비상 정지 버튼을 누름
 500ms → 정지
 800ms 비상 정지 버튼을 놓음
 900ms 재시작 버튼
 900ms → 운전 허가
1500ms (채널 B 접점이 붙음)
2000ms 비상 정지 버튼을 누름
2000ms → 정지
2050ms → 고장(수리 필요)
2500ms 비상 정지 버튼을 놓음
2700ms 재시작 버튼
3000ms (B를 고침)
3200ms 비상 정지 버튼을 누름
3300ms 비상 정지 버튼을 놓음

3500ms → 운전 허가
```

- **끊기면 멈춘다**: 접점이 닫혀 있어야 "괜찮다"는 뜻입니다. 전선이 끊기거나 커넥터가 빠지면 버튼을 누른 것과 같아집니다. 고장이 위험한 쪽이 아니라 안전한 쪽으로 가게 하는 이 원칙을 페일 세이프라고 합니다
- **한 채널만으로도 멈춘다**: 두 채널 중 하나만 열려도 정지합니다. 한쪽이 고장 나도 다른 쪽이 안전 기능을 해냅니다
- **숨은 고장을 찾는다**: B 접점이 붙은 뒤에도 겉으로는 아무 일이 없다가, 버튼을 누른 순간 두 채널이 달라졌고 50ms 뒤 고장으로 잠겼습니다. 이대로 두면 다음에 A까지 고장 났을 때 버튼이 아무 일도 하지 못합니다
- **사람이 다시 시작한다**: 버튼을 놓아도 저절로 돌지 않고 재시작 버튼이 필요합니다. 고장 상태에서는 재시작도 듣지 않으며(2700ms), 두 채널이 함께 열리는 것을 확인한 뒤에야 풀립니다

## 인증과 법

기계를 파는 나라의 법이 이 표준들을 끌어옵니다. 유럽에서는 기계 지침(2006/42/EC)을 대신하는 기계 규정(EU 2023/1230)이 2027년 1월 20일부터 적용되며, 이 규정은 소프트웨어로 된 안전 기능과 외부 공격에 대한 보호도 다룹니다. 제조사는 표준에 맞게 설계했다는 기술 문서를 갖추고, 높은 등급의 안전 장치는 인증 기관의 평가를 받습니다. 그래서 안전 관련 소프트웨어는 코드뿐 아니라 요구 사항, 설계, 시험 기록이 함께 산출물이 됩니다([「검증 문서」](#/read/cpp-industrial/safe-docs)).

<Note>
위 코드는 원리를 보이기 위한 흉내이며 실제 안전 기능으로 쓰면 안 됩니다. 실제 비상 정지와 보호문 감시는 인증받은 안전 릴레이, 안전 PLC, 드라이브의 안전 토크 차단(STO) 기능이 맡습니다. 보통의 PC에서 도는 C++ 프로그램은 대개 안전과 무관한 "표준" 부분이며, 그 프로그램이 멈추거나 잘못 동작해도 안전 기능은 따로 살아 있어야 합니다. C++로 안전 관련 소프트웨어 자체를 만드는 경우에는 [「IEC 61508」](#/read/cpp-industrial/safe-iec61508)의 개발 절차와 [「MISRA C++」](#/read/cpp-industrial/safe-misra) 같은 코딩 규칙을 따릅니다.

## 정리

- 기능 안전은 IEC 61508을 바탕으로 분야별 표준이 있으며, 위험성 평가로 필요한 안전 기능과 그 등급(SIL, PL, ASIL)을 정한다
- 안전 기능은 끊기면 멈추고, 한 채널만으로도 멈추며, 채널 사이의 불일치로 숨은 고장을 찾고, 사람이 다시 시작하게 짠다
- 실제 안전 기능은 인증된 안전 장치가 맡고, 법과 인증은 코드뿐 아니라 요구 사항, 설계, 시험 문서를 함께 요구한다
