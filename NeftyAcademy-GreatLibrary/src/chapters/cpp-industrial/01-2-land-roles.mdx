[「자동화 피라미드」](#/read/cpp-industrial/land-pyramid)의 수준 2와 3에는 이름이 넷 있습니다. 현장 사람들은 이 이름으로 시스템을 나누고, 어디에 무엇을 맡길지도 이 경계로 정합니다.

- **PLC**(프로그래머블 로직 컨트롤러): 장비를 직접 제어하는 산업용 컴퓨터입니다. 입력(센서, 버튼)을 읽고 프로그램을 한 바퀴 돌린 뒤 출력(모터, 밸브)을 쓰는 일을 몇 밀리초마다 끝없이 되풀이합니다. 정유 시설처럼 연속 공정이 큰 곳에서는 비슷한 일을 DCS(분산 제어 시스템)가 맡습니다
- **HMI**(사람과 기계의 접점): 장비 옆의 조작 패널입니다. 버튼을 누르면 PLC에 명령을 쓰고, PLC의 상태를 읽어 화면에 보여 줍니다
- **SCADA**(감시 제어와 데이터 수집): 여러 PLC, 때로는 멀리 흩어진 현장(배관, 상수도, 송전망)을 한곳에서 감시합니다. 값을 주기적으로 읽어 이력으로 남기고 알람을 냅니다. 빠른 제어는 하지 않습니다
- **MES**(생산 실행 시스템): 작업 지시를 내리고, 무엇을 언제 몇 개 만들었는지, 어떤 재료가 들어갔는지 기록하며, OEE 같은 지표를 계산합니다

## 함께 돌려 보기

네 역할이 병 20개를 만드는 작업 하나를 처리하는 과정을 흉내 냈습니다. 중간에 컨베이어에 병이 걸립니다.

```cpp
// MES, SCADA, HMI, PLC가 한 라인을 함께 돌리는 모습을 한 프로그램 안에서 흉내 낸다
#include <cstdio>
#include <string>
#include <vector>

// PLC의 메모리. 다른 역할은 이것으로만 PLC와 말한다
struct Tags {
    bool startCmd = false;        // HMI가 쓰는 명령(PLC가 한 번 읽고 지운다)
    bool stopCmd = false;
    int target = 0;               // MES가 내려보낸 목표 수량
    bool running = false;         // 여기부터는 PLC가 쓰고 다른 역할이 읽는다
    bool jam = false;
    bool done = false;
    int count = 0;
};

double now = 0;                   // 흉내 낸 시각(초)
void log(const char* who, const std::string& what) {
    std::printf("%5.1f초 %-5s %s\n", now, who, what.c_str());
}

class Plc {                       // 스캔마다: 입력 읽기 → 논리 → 출력 쓰기
    bool lastEye = false, lastRunning = false;
public:
    void scan(Tags& t, bool eye, bool jamSwitch) {
        t.jam = jamSwitch;
        // 자기 유지 회로: (시작 명령 또는 이미 운전 중) 그리고 멈출 까닭이 없음
        t.running = (t.startCmd || t.running) && !t.stopCmd && !t.jam && !t.done;
        if (t.running && eye && !lastEye) ++t.count;      // 광센서의 상승 에지
        lastEye = eye;
        t.done = t.target > 0 && t.count >= t.target;
        if (t.done) t.running = false;
        t.startCmd = t.stopCmd = false;
        if (t.running != lastRunning)
            log("PLC", t.running ? "컨베이어 켬" : "컨베이어 끔");
        lastRunning = t.running;
    }
};

class Scada {                     // 1초마다 PLC를 읽어 이력을 남기고 알람을 낸다
    bool lastJam = false;
public:
    std::vector<std::string> history;
    void poll(const Tags& t) {
        history.push_back(std::to_string(t.count));
        if (t.jam && !lastJam) log("SCADA", "알람: 컨베이어 걸림 (" +
                                   std::to_string(t.count) + "개째)");
        lastJam = t.jam;
    }
};

int main() {
    Tags tags;
    Plc plc;
    Scada scada;
    int beltMs = 0;               // 장비: 컨베이어가 움직인 거리(시간으로 셈)
    bool orderOpen = true;

    log("MES", "작업 지시 WO-1024: 병 20개");
    tags.target = 20;             // 실제로는 SCADA나 게이트웨이를 거쳐 내려간다

    for (int ms = 0; ms <= 40000; ms += 10) {             // PLC 스캔 10ms
        now = ms / 1000.0;
        // 작업자가 HMI 버튼을 누른다
        if (ms == 500 || ms == 12000) {
            log("HMI", "시작 버튼");
            tags.startCmd = true;
        }
        // 7초에 병이 걸리고 11초에 치움
        const bool jamSwitch = ms >= 7000 && ms < 11000;
        // 1초마다 병이 센서를 가린다
        const bool eye = beltMs % 1000 < 200;
        plc.scan(tags, eye, jamSwitch);
        if (tags.running) beltMs += 10;
        if (ms % 1000 == 0) scada.poll(tags);
        if (orderOpen && tags.done) {
            log("MES", "WO-1024 완료: " + std::to_string(tags.count) + "개");
            orderOpen = false;
        }
    }
    std::printf("SCADA 이력 %zu건, 마지막 값 %s\n", scada.history.size(),
                scada.history.back().c_str());
}
```

```text
  0.0초 MES   작업 지시 WO-1024: 병 20개
  0.5초 HMI   시작 버튼
  0.5초 PLC   컨베이어 켬
  7.0초 PLC   컨베이어 끔
  7.0초 SCADA 알람: 컨베이어 걸림 (6개째)
 12.0초 HMI   시작 버튼
 12.0초 PLC   컨베이어 켬
 25.5초 PLC   컨베이어 끔
 25.5초 MES   WO-1024 완료: 20개
SCADA 이력 41건, 마지막 값 20
```

- **경계는 태그**: 다른 역할은 PLC의 메모리(`Tags`)를 읽고 쓰는 것으로만 PLC와 말합니다. 실제로는 이 읽고 쓰기가 다음 장의 필드버스와 프로토콜로 오갑니다([「태그 읽고 쓰기」](#/read/cpp-industrial/plc-tags))
- **명령은 한 번만**: HMI가 쓴 시작 명령은 PLC가 한 번 읽고 지웁니다. 지우지 않으면 걸림을 치운 순간 아무도 누르지 않았는데 컨베이어가 다시 돌기 시작합니다
- **멈추는 판단은 PLC가**: 걸림을 감지해 컨베이어를 끈 것은 PLC이고, SCADA는 그 사실을 알렸을 뿐입니다. SCADA나 MES의 컴퓨터가 꺼져도 PLC는 혼자서 장비를 안전하게 다룰 수 있어야 합니다
- **MES는 시작과 끝을 본다**: MES가 아는 것은 작업 지시와 완료뿐입니다. 0.01초마다의 일은 몰라도 됩니다

## 자기 유지 회로

PLC 코드의 핵심 줄은 `running = (start || running) && !stop && !jam && !done` 입니다. 시작 버튼은 잠깐 눌렸다 떨어지지만, 출력 `running`이 자기 자신을 다시 입력으로 받아 켜진 상태를 유지합니다. PLC 프로그래머는 같은 논리를 래더 다이어그램으로 이렇게 그립니다.

```text nocheck
|   START      STOP      JAM      RUN
|----| |----+---|/|------|/|------( )----|
|    RUN    |
|----| |----+
```

`| |`는 "켜져 있으면 통한다", `|/|`는 "꺼져 있으면 통한다", `( )`는 출력입니다. 전기 회로의 릴레이를 본뜬 표기라서 전기 기술자가 읽기 쉽습니다.

PLC 언어는 IEC 61131-3 표준이 정합니다. 래더 다이어그램(LD), 기능 블록 다이어그램(FBD), 파스칼을 닮은 구조화 텍스트(ST)가 있고, 순서 동작을 단계와 전이로 나누는 SFC가 이들을 엮습니다. 어셈블리를 닮은 명령 목록(IL)은 2013년 판에서 권장되지 않게 되었고 2025년 5월의 4판에서 빠졌습니다.

<Note>
C++는 이 그림의 여러 곳에 들어갑니다. PC에서 PLC처럼 도는 소프트 PLC의 실행 환경, HMI와 SCADA 프로그램, 장비와 상위 시스템을 잇는 게이트웨이, 그리고 PLC 대신 C++ 프로그램이 직접 장비를 제어하는 전용 기계(비전 검사기, 로봇 컨트롤러)가 그렇습니다. 어느 경우든 위에서 본 역할의 경계, 특히 "제어는 아래에서 스스로 계속된다"는 원칙을 그대로 지켜야 합니다.

## 정리

- PLC는 장비를 직접 제어하고, HMI는 현장의 조작 패널, SCADA는 여러 장비의 감시와 이력, MES는 작업 지시와 생산 기록을 맡는다
- 역할들은 PLC의 태그를 읽고 쓰는 것으로 말하며, 명령 비트는 한 번 읽고 지우고, 멈추는 판단은 PLC가 스스로 한다
- 자기 유지 회로는 순간 신호를 유지된 상태로 바꾸는 PLC의 기본 논리이며, PLC 언어는 IEC 61131-3이 정한다
