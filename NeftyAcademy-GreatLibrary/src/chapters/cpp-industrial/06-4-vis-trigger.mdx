비전 검사의 성패는 코드보다 조명에서 먼저 갈립니다. 흠집이 화면에 보이지 않으면 어떤 알고리즘도 찾지 못하고, 반대로 조명이 좋으면 단순한 이진화로도 충분합니다. 그리고 움직이는 라인에서는 "언제 찍는가"와 "그 결과를 어느 부품에 붙이는가"가 정확해야 합니다.

## 조명 고르기

| 조명 | 원리 | 잘 보이는 것 |
| --- | --- | --- |
| 백라이트 | 부품 뒤에서 비춰 그림자를 찍는다 | 윤곽, 치수, 구멍 |
| 돔(확산) | 사방에서 고르게 비춘다 | 반짝이는 표면의 글자와 무늬 |
| 동축 | 렌즈와 같은 축으로 비춘다 | 평평한 금속 면의 흠 |
| 저각(암시야) | 거의 옆에서 비춘다 | 흠집, 찍힘, 돋을새김 |
| 바·링 | 한쪽 또는 둘레에서 비춘다 | 일반 외관 |

색도 도구입니다. 빨간 조명 아래에서는 빨간 표시가 밝아지고 파란 표시가 어두워지므로, 흑백 카메라로도 원하는 색만 도드라지게 할 수 있습니다. 바깥의 빛(창문, 천장 조명)이 결과를 흔들지 않게 덮개를 씌우는 것도 기본입니다.

## 번짐과 결과 따라가기

움직이는 컨베이어에서 노출 시간에 따른 번짐을 계산하고, 검사 결과를 엔코더로 따라가 300mm 뒤의 밀어내기 장치에서 불량을 밀어내는 과정을 흉내 냈습니다. 부품 3은 처리가 늦어(700ms) 밀어내기 앞에 올 때까지 결과가 없습니다.

```cpp
// 움직이는 컨베이어: 노출과 번짐, 그리고 엔코더로 검사 결과를 따라가 불량 밀어내기
#include <cstdio>
#include <deque>

struct Part {
    int id;
    long triggerCount;                           // 찍은 순간의 엔코더 값
    int triggerMs;
    bool resultReady = false, ng = false;
};

int main() {
    const double speed = 500;                    // 컨베이어 500mm/s
    const double mmPerPx = 0.1;                  // 화소 하나가 부품 위에서 0.1mm
    for (double exposureUs : {1000.0, 200.0, 50.0})
        std::printf("노출 %4.0fµs → 번짐 %.2f화소\n", exposureUs,
                    speed * exposureUs * 1e-6 / mmPerPx);

    // 엔코더 10카운트/mm. 광센서 자리에서 찍고, 300mm 뒤의 밀어내기에서 처리한다
    const long countsPerMm = 10, gateAt = 300 * countsPerMm;
    // 부품별 처리 시간
    const int latencyMs[] = {120, 150, 90, 700, 130, 110, 140};
    const bool ngTruth[] = {false, true, false, false, false, true, false};
    std::deque<Part> tracking;                   // 광센서와 밀어내기 사이의 부품들
    int nextId = 0;
    const long countsPerMs = long(speed * countsPerMm / 1000);   // 1ms에 5카운트
    for (int ms = 0; ms <= 2200; ++ms) {
        const long count = ms * countsPerMs;     // 엔코더 값
        if (ms % 240 == 0 && nextId < 7) {       // 120mm 간격으로 부품이 지나간다
            tracking.push_back({nextId, count, ms});
            ++nextId;
        }
        for (Part& p : tracking)                 // 비전 결과가 도착(늦을 수도 있다)
            if (!p.resultReady && ms - p.triggerMs >= latencyMs[p.id]) {
                p.resultReady = true;
                p.ng = ngTruth[p.id];
            }
        if (!tracking.empty() && count - tracking.front().triggerCount >= gateAt) {
            const Part p = tracking.front();     // 맨 앞 부품이 밀어내기 앞에 왔다
            tracking.pop_front();
            const char* action = !p.resultReady ? "결과 없음 → 밀어냄(안전 쪽)"
                               : p.ng           ? "불량 → 밀어냄" : "양품 → 통과";
            std::printf("%5dms 부품 %d: %s\n", ms, p.id, action);
        }
    }
}
```

```text
노출 1000µs → 번짐 5.00화소
노출  200µs → 번짐 1.00화소
노출   50µs → 번짐 0.25화소
  600ms 부품 0: 양품 → 통과
  840ms 부품 1: 불량 → 밀어냄
 1080ms 부품 2: 양품 → 통과
 1320ms 부품 3: 결과 없음 → 밀어냄(안전 쪽)
 1560ms 부품 4: 양품 → 통과
 1800ms 부품 5: 불량 → 밀어냄
 2040ms 부품 6: 양품 → 통과
```

- **노출과 번짐**: 500mm/s로 지나가는 부품을 1ms 동안 노출하면 0.5mm, 곧 5화소나 번집니다. 0.1mm를 재는 검사에는 쓸 수 없습니다. 노출을 50µs로 줄이면 0.25화소가 되는데, 그만큼 빛이 모자라므로 아주 밝은 조명을 그 순간에만 켜는 **스트로브**를 씁니다
- **하드웨어 트리거**: 부품이 정해진 자리에 왔을 때 광센서나 엔코더의 신호가 카메라의 트리거 입력에 직접 들어가 노출을 시작합니다. PC가 신호를 받아 소프트웨어로 찍으라고 하면 운영 체제의 지연만큼 부품이 이미 지나가 있습니다
- **시간이 아니라 엔코더로**: 컨베이어는 멈추기도 하고 속도가 바뀌기도 하므로, 부품이 밀어내기에 닿는 때를 시간으로 계산하면 틀립니다. 찍은 순간의 엔코더 값을 부품과 함께 기록하고, 엔코더가 300mm만큼 더 가면 그 부품이 밀어내기 앞에 왔다고 봅니다
- **결과가 없으면 안전 쪽으로**: 부품 3은 결과가 오기 전에 밀어내기 앞에 왔습니다. 모르면 통과시키는 것이 아니라 밀어내는 것이 맞습니다. 이런 일이 잦으면 처리 시간이나 밀어내기의 거리를 다시 설계해야 한다는 신호입니다

<Note>
결과를 부품에 붙이는 일은 순서가 생명입니다. 처리를 여러 스레드로 나누면 결과가 찍은 순서와 다르게 도착할 수 있으므로, 프레임 번호나 트리거 번호로 맞춰 줄을 세웁니다. 카메라가 트리거를 놓쳐 한 장을 덜 찍으면 그 뒤의 모든 결과가 한 칸씩 밀리므로, 트리거 수와 받은 프레임 수를 늘 비교하는 감시도 둡니다.
</Note>

## 정리

- 조명은 보려는 특징에 맞춰 고르며(윤곽은 백라이트, 흠집은 저각), 색과 덮개도 대비를 만드는 도구다
- 움직이는 부품은 노출이 길면 번지므로 짧은 노출과 스트로브를 쓰고, 찍는 순간은 하드웨어 트리거로 정한다
- 검사 결과는 시간이 아니라 엔코더 값으로 부품을 따라가 처리하고, 결과가 없거나 순서가 어긋나면 안전한 쪽으로 처리한다
