PLC와 말하는 프로그램이 커지면 `modbus_read_registers(ctx, 37, ...)` 같은 줄이 코드 곳곳에 흩어지기 쉽습니다. 37번이 무엇인지, 몇 배를 해야 실제 값인지, 써도 되는지는 그 줄을 쓴 사람만 압니다. 현장 소프트웨어는 이것을 **태그**로 정리합니다. 태그는 "Oven.Temperature" 같은 이름에 주소, 형식, 환산, 단위, 권한을 묶은 것이고, 나머지 코드는 이름으로만 값을 다룹니다. HMI와 SCADA가 모두 이 구조이며, 직접 만드는 프로그램도 같은 층을 두는 것이 좋습니다.

## 태그 계층 만들기

[「Modbus RTU와 TCP」](#/read/cpp-industrial/fb-modbus)의 libmodbus 서버를 PLC 역할로 두고, 통신 한 번마다 PLC 프로그램이 한 번 돈다고 했습니다. 그 위에 태그 계층을 얹었습니다.

```cpp flags=-I/usr/include/modbus,-lmodbus
// 태그 계층: 이름·주소·형식·환산·권한을 한곳에 정의하고, 명령은 핸드셰이크로 보낸다
#include <modbus.h>
#include <atomic>
#include <cstdio>
#include <map>
#include <string>
#include <thread>

enum class Quality { Good, Bad };
struct TagDef {
    int reg;                          // 보유 레지스터 번호
    double rawMax, engMax;            // 0~rawMax ↔ 0~engMax로 선형 환산
    const char* unit;
    bool writable;
};
struct TagValue { double value; Quality quality; };

const std::map<std::string, TagDef> tags = {
    {"Oven.Temperature", {0, 27648, 200.0, "°C", false}},   // 아날로그 입력
    {"Oven.Setpoint",    {10, 1000, 100.0, "°C", true}},     // 0.1도 단위 정수
};

class TagClient {
    modbus_t* ctx;
public:
    explicit TagClient(modbus_t* c) : ctx(c) {}
    TagValue read(const std::string& name) {
        const TagDef& t = tags.at(name);
        uint16_t raw;
        if (modbus_read_registers(ctx, t.reg, 1, &raw) != 1)
            return {0, Quality::Bad};                      // 통신 실패
        // 32767: 범위 넘침(단선 등)
        if (raw > t.rawMax) return {0, Quality::Bad};
        return {raw * t.engMax / t.rawMax, Quality::Good};
    }
    bool write(const std::string& name, double value) {
        const TagDef& t = tags.at(name);
        // 권한은 태그 정의가 정한다
        if (!t.writable) return false;
        const uint16_t raw = uint16_t(value * t.rawMax / t.engMax + 0.5);
        uint16_t back = 0;
        return modbus_write_register(ctx, t.reg, raw) == 1 &&
               modbus_read_registers(ctx, t.reg, 1, &back) == 1 && back == raw;
    }
    // 명령 핸드셰이크: 명령과 요청을 쓰고 → PLC가 확인을 올리면 → 요청을 내린다
    bool command(uint16_t code) {
        const uint16_t req[2] = {code, 1};
        modbus_write_registers(ctx, 20, 2, req);           // 20: 명령, 21: 요청
        uint16_t ack = 0, result = 0;
        for (int i = 0; i < 10 && ack != code; ++i)        // 정해진 횟수만 기다린다
            modbus_read_registers(ctx, 22, 1, &ack);
        const bool acked = ack == code;
        modbus_read_registers(ctx, 23, 1, &result);
        modbus_write_register(ctx, 21, 0);                 // 요청 내림
        for (int i = 0; i < 10 && ack != 0; ++i)
            modbus_read_registers(ctx, 22, 1, &ack);
        std::printf("  명령 %u: 확인 %s, 결과 %u, 확인 내려감 %s\n", code,
                    acked ? "받음" : "없음", result, ack == 0 ? "예" : "아니요");
        return acked && ack == 0 && result == 0;
    }
};

std::atomic<uint16_t> sensorRaw{15000};

// PLC 프로그램: 통신이 한 번 처리될 때마다 돈다
void plcScan(modbus_mapping_t* m) {
    uint16_t* r = m->tab_registers;
    r[0] = sensorRaw;
    if (r[21] == 1 && r[22] == 0) {   // 새 요청: 실행하고 확인을 올린다
        r[23] = (r[20] == 1 || r[20] == 2) ? 0 : 1;        // 알 수 없는 명령은 1
        if (r[20] == 1) r[1] |= 1;                         // 운전
        if (r[20] == 2) r[1] &= ~1;                        // 정지
        r[22] = r[20];
    } else if (r[21] == 0) {
        r[22] = 0;                    // 요청이 내려가면 확인도 내린다
    }
}

int main() {
    modbus_mapping_t* map = modbus_mapping_new(0, 0, 32, 0);
    modbus_t* server = modbus_new_tcp("127.0.0.1", 1503);
    int fd = modbus_tcp_listen(server, 1);
    std::thread plc([&] {
        modbus_tcp_accept(server, &fd);
        uint8_t q[MODBUS_TCP_MAX_ADU_LENGTH];
        for (int n; (n = modbus_receive(server, q)) > 0;) {
            plcScan(map);
            modbus_reply(server, q, n, map);
        }
    });
    modbus_t* ctx = modbus_new_tcp("127.0.0.1", 1503);
    modbus_connect(ctx);
    TagClient tc(ctx);

    auto show = [&](const char* name) {
        const TagValue v = tc.read(name);
        if (v.quality == Quality::Good)
            std::printf("  %s = %.1f %s\n", name, v.value, tags.at(name).unit);
        else
            std::printf("  %s = (Bad)\n", name);
    };
    std::printf("읽기\n");
    show("Oven.Temperature");
    std::printf("쓰기\n");
    const bool ok = tc.write("Oven.Setpoint", 65.0);
    std::printf("  설정 65.0도: %s\n", ok ? "확인됨" : "실패");
    show("Oven.Setpoint");
    const bool wrote = tc.write("Oven.Temperature", 10);
    std::printf("  온도에 쓰기: %s\n", wrote ? "됨" : "거부");
    std::printf("명령\n");
    tc.command(1);
    tc.command(7);
    std::printf("센서 단선\n");
    sensorRaw = 32767;
    show("Oven.Temperature");

    modbus_close(ctx);
    modbus_free(ctx);
    plc.join();
    modbus_close(server);
    modbus_free(server);
    modbus_mapping_free(map);
}
```

```text
읽기
  Oven.Temperature = 108.5 °C
쓰기
  설정 65.0도: 확인됨
  Oven.Setpoint = 65.0 °C
  온도에 쓰기: 거부
명령
  명령 1: 확인 받음, 결과 0, 확인 내려감 예
  명령 7: 확인 받음, 결과 1, 확인 내려감 예
센서 단선
  Oven.Temperature = (Bad)
```

- **정의는 한곳에**: 주소, 환산 범위, 단위, 쓰기 권한이 `tags` 표에만 있습니다. 실제로는 이 표를 설정 파일(CSV나 JSON)에서 읽어, 레지스터 맵이 바뀌어도 코드를 고치지 않게 합니다
- **환산**: 지멘스의 아날로그 입력은 측정 범위 전체를 0~27648로 나타냅니다. 15000은 0~200도 범위에서 108.5도입니다. 정수로 주고받는 설정값은 0.1도 단위로 환산했습니다
- **품질**: 통신이 실패하거나 원시 값이 범위를 넘으면 숫자 대신 Bad를 돌려줍니다. 센서 선이 끊긴 아날로그 입력은 32767(넘침)을 보이는데, 이것을 그대로 환산하면 237도라는 그럴듯한 거짓말이 됩니다. [「OPC UA」](#/read/cpp-industrial/fb-opcua)처럼 값과 품질을 늘 함께 다룹니다
- **쓰기는 조심스럽게**: 읽기 전용 태그는 태그 계층이 거부하고, 쓴 값은 다시 읽어 같은지 확인합니다. 어떤 태그를 누가 쓸 수 있는지는 [「사용자와 권한」](#/read/cpp-industrial/hmi-users)과도 이어집니다

## 명령은 핸드셰이크로

"시작" 같은 명령을 비트 하나로 보내면 문제가 생깁니다. PLC가 그 비트를 읽기 전에 PC가 지울 수도 있고, PLC가 실행했는지 PC는 알 수 없습니다. 그래서 요청과 확인을 주고받는 핸드셰이크를 씁니다.

1. PC가 명령 번호를 쓰고 요청 비트를 올린다
2. PLC가 요청을 보고 실행한 뒤, 결과를 쓰고 확인(명령 번호)을 올린다
3. PC가 확인과 결과를 읽고 요청을 내린다
4. PLC가 요청이 내려간 것을 보고 확인을 내린다

네 단계 모두 상대가 올리거나 내린 것을 **본 뒤에** 움직이므로, 어느 쪽의 주기가 얼마든 명령을 놓치거나 두 번 실행하지 않습니다. 알 수 없는 명령 7은 PLC가 결과 1로 거절했고, PC는 그것을 알 수 있었습니다. 기다리는 횟수에 한도를 둔 것도 중요합니다. PLC가 멈춰 있으면 영원히 기다리지 않고 실패로 끝내야 합니다.

<Note>
값을 쓸 때는 그 값의 "주인"이 누구인지 정해 둡니다. 설정값처럼 PC가 주인인 태그만 PC가 쓰고, PLC가 계산하는 값은 읽기만 합니다. 같은 레지스터를 HMI와 PC 프로그램이 서로 쓰면 마지막에 쓴 쪽이 이기고, 어느 쪽도 그 사실을 모릅니다.
</Note>

## 정리

- 주소, 형식, 환산, 단위, 권한을 태그 정의 한곳에 모으고, 나머지 코드는 태그 이름으로만 값을 다룬다
- 읽은 값은 품질과 함께 다루어 통신 실패나 범위 넘침을 숫자로 속이지 않고, 쓴 값은 다시 읽어 확인한다
- 명령은 요청과 확인을 주고받는 네 단계 핸드셰이크로 보내고, 기다림에는 한도를 둔다
