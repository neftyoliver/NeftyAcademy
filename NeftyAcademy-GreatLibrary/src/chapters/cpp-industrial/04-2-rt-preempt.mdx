[「지연과 지터」](#/read/cpp-industrial/rt-jitter)에서 실시간 우선순위를 주어도 가끔 수백 마이크로초씩 늦는 것을 보았습니다. 보통 커널에는 선점할 수 없는 구간(스핀락을 쥔 코드, 인터럽트 처리)이 곳곳에 있어서, 가장 높은 우선순위의 스레드도 그 구간이 끝나기를 기다려야 하기 때문입니다. **PREEMPT_RT**는 이 구간을 거의 없애 리눅스를 경성 실시간에 쓸 수 있게 만드는 커널 설정입니다. 2005년부터 커널 바깥의 패치로 다듬어 오다가 2024년 9월 본선에 합쳐졌고, Linux 6.12부터 x86, ARM64, RISC-V에서 `CONFIG_PREEMPT_RT`로 켤 수 있습니다.

## 무엇이 바뀌나

- **잠금이 잠들 수 있게 된다**: 커널 안의 스핀락 대부분이 우선순위 상속을 하는 잠자는 잠금으로 바뀝니다. 잠금을 쥔 코드도 더 높은 스레드에게 CPU를 내줄 수 있습니다
- **인터럽트가 스레드가 된다**: 장치 인터럽트 처리가 우선순위를 가진 커널 스레드에서 돌므로, 제어 스레드를 네트워크나 디스크 인터럽트보다 높게 둘 수 있습니다
- **처리량은 조금 줄어든다**: 선점 지점이 많아진 만큼 전체 처리량은 보통 커널보다 약간 낮습니다. 실시간 커널은 빠르게가 아니라 **늦지 않게** 만드는 것입니다

실행 중인 커널이 실시간인지는 `uname -v`에 `PREEMPT_RT`가 보이는지로 알 수 있습니다. 이 책의 검사 환경은 `PREEMPT_DYNAMIC`, 곧 보통 커널입니다.

## 스케줄링 정책

| 정책 | 동작 | 쓰임 |
| --- | --- | --- |
| SCHED_OTHER | 공정하게 나눠 쓴다 | 보통 프로그램 |
| SCHED_FIFO | 우선순위(1~99)가 높은 스레드가 스스로 쉴 때까지 계속 돈다 | 제어 루프 |
| SCHED_RR | FIFO와 같되, 같은 우선순위끼리 시간을 나눈다 | 드묾 |
| SCHED_DEADLINE | 주기와 마감, 실행 시간을 선언하면 마감이 급한 것부터 돌린다 | 주기가 분명한 작업 |

## 우선순위 역전

실시간 우선순위를 쓰면 새로운 함정이 생깁니다. 높은 스레드가 낮은 스레드가 쥔 잠금을 기다리는 동안, 잠금과 상관없는 중간 스레드가 낮은 스레드를 밀어내면 높은 스레드는 중간 스레드가 끝날 때까지 기다리게 됩니다. 이것을 **우선순위 역전**이라고 합니다. 1997년 화성 탐사선 패스파인더가 되풀이해 재시작한 원인으로 유명합니다. 세 스레드를 한 CPU에 묶어 재현했습니다.

```cpp norun
// 우선순위 역전: 높은 스레드가 낮은 스레드의 잠금을 기다릴 때 중간이 끼어든다
#include <pthread.h>
#include <sched.h>
#include <atomic>
#include <cstdio>
#include <ctime>

pthread_mutex_t m;
std::atomic<bool> lowHasLock{false};
double highWaitedMs = 0;

double nowMs(clockid_t c = CLOCK_MONOTONIC) {
    timespec t;
    clock_gettime(c, &t);
    return t.tv_sec * 1e3 + t.tv_nsec / 1e6;
}
// 이 스레드의 CPU 시간으로 ms만큼 일한다
void burnCpu(double ms) {
    const double end = nowMs(CLOCK_THREAD_CPUTIME_ID) + ms;
    while (nowMs(CLOCK_THREAD_CPUTIME_ID) < end) {}
}
void sleepMs(int ms) {
    timespec t{0, ms * 1'000'000L};
    nanosleep(&t, nullptr);
}

pthread_t start(void* (*fn)(void*), int prio) {   // CPU 0에 묶인 SCHED_FIFO 스레드
    pthread_attr_t a;
    pthread_attr_init(&a);
    pthread_attr_setinheritsched(&a, PTHREAD_EXPLICIT_SCHED);
    pthread_attr_setschedpolicy(&a, SCHED_FIFO);
    sched_param p{};
    p.sched_priority = prio;
    pthread_attr_setschedparam(&a, &p);
    cpu_set_t cpus;
    CPU_ZERO(&cpus);
    CPU_SET(0, &cpus);
    pthread_attr_setaffinity_np(&a, sizeof cpus, &cpus);
    pthread_t t;
    pthread_create(&t, &a, fn, nullptr);
    pthread_attr_destroy(&a);
    return t;
}

// 우선순위 10: 잠금을 쥐고 50ms 일한다
void* low(void*) {
    pthread_mutex_lock(&m);
    lowHasLock = true;
    burnCpu(50);
    pthread_mutex_unlock(&m);
    return nullptr;
}
void* high(void*) {                              // 우선순위 30: 잠금이 필요하다
    const double t0 = nowMs();
    pthread_mutex_lock(&m);
    highWaitedMs = nowMs() - t0;
    pthread_mutex_unlock(&m);
    return nullptr;
}
// 우선순위 20: 잠금과 상관없이 300ms 일한다
void* medium(void*) {
    burnCpu(300);
    return nullptr;
}

void run(const char* name, int protocol) {
    pthread_mutexattr_t ma;
    pthread_mutexattr_init(&ma);
    pthread_mutexattr_setprotocol(&ma, protocol);
    pthread_mutex_init(&m, &ma);
    lowHasLock = false;

    pthread_t l = start(low, 10);
    while (!lowHasLock) sleepMs(1);
    pthread_t h = start(high, 30);
    sleepMs(5);                                  // high가 잠금에서 막힐 때까지
    pthread_t md = start(medium, 20);
    pthread_join(h, nullptr);
    pthread_join(md, nullptr);
    pthread_join(l, nullptr);
    std::printf("%s: 높은 스레드가 기다린 시간 %.0fms\n", name, highWaitedMs);
    pthread_mutex_destroy(&m);
}

int main() {
    sched_param p{};
    p.sched_priority = 40;                       // 지휘하는 main은 가장 높게
    sched_setscheduler(0, SCHED_FIFO, &p);
    cpu_set_t cpus;
    CPU_ZERO(&cpus);
    CPU_SET(0, &cpus);
    sched_setaffinity(0, sizeof cpus, &cpus);
    run("보통 잠금", PTHREAD_PRIO_NONE);
    run("우선순위 상속 잠금", PTHREAD_PRIO_INHERIT);
}
```

```text nocheck
보통 잠금: 높은 스레드가 기다린 시간 352ms
우선순위 상속 잠금: 높은 스레드가 기다린 시간 49ms
```

보통 잠금에서는 높은 스레드(30)가 중간 스레드(20)의 300ms와 낮은 스레드(10)의 남은 일 50ms를 모두 기다렸습니다. `PTHREAD_PRIO_INHERIT` 잠금에서는 높은 스레드가 기다리기 시작하는 순간 낮은 스레드가 30으로 올라가 중간 스레드에게 밀리지 않고 일을 끝냈으므로, 높은 스레드는 50ms만 기다렸습니다. `std::mutex`는 이 속성을 줄 방법이 없으므로, 실시간 스레드와 나눠 쓰는 잠금은 `pthread_mutex_t`를 직접 감싸 씁니다. 더 좋은 것은 실시간 스레드가 잠금을 아예 기다리지 않게 설계하는 것입니다([「주기 작업」](#/read/cpp-industrial/rt-cyclic)).

<Note>
실시간 우선순위를 쓰려면 관리자 권한이나 `CAP_SYS_NICE`, 또는 `/etc/security/limits.conf`의 `rtprio` 허용이 필요합니다. 우선순위 99는 커널의 감시 스레드들이 쓰므로 제어 루프에는 80 정도를 줍니다. 그리고 리눅스는 기본으로 실시간 스레드들이 1초에 0.95초까지만 CPU를 쓰게 막습니다(`/proc/sys/kernel/sched_rt_runtime_us`). 실시간 스레드가 무한 루프에 빠져도 시스템 전체가 얼어붙지 않게 하는 안전장치이므로, 실시간 스레드는 반드시 매 주기 잠들어야 합니다.
</Note>

## 정리

- PREEMPT_RT는 커널의 잠금과 인터럽트 처리를 선점할 수 있게 만들어 최악의 지연을 줄이며, Linux 6.12부터 본선 커널의 설정으로 켤 수 있다
- 제어 루프는 SCHED_FIFO 같은 실시간 정책과 우선순위로 돌리며, 주기와 마감이 분명하면 SCHED_DEADLINE도 쓸 수 있다
- 높은 스레드가 낮은 스레드의 잠금을 기다리는 곳에서는 우선순위 역전이 생기므로 우선순위 상속 잠금을 쓰거나, 실시간 스레드가 잠금을 기다리지 않게 설계한다
