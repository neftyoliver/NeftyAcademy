산업용 로봇은 팔만 오지 않습니다. 경로를 계획하고 관절 서보를 돌리고 안전 기능을 맡는 **로봇 제어기**와, 사람이 위치를 가르치는 티치 펜던트가 함께 옵니다. 로봇 프로그램은 회사마다 다른 언어(FANUC의 TP와 KAREL, ABB의 RAPID, KUKA의 KRL, 야스카와의 INFORM, UR의 URScript)로 쓰고 제어기가 실행합니다. PC의 C++ 프로그램은 이 제어기를 대신하지 않고, 제어기와 이어져 일을 시키거나 보정합니다.

## 세 가지 잇는 방법

| 방법 | 주고받는 것 | 주로 쓰는 곳 |
| --- | --- | --- |
| 신호와 레지스터 | 프로그램 번호, 시작·완료 비트, 숫자 레지스터 | 대부분의 생산 셀 |
| 명령 인터페이스 | 상태 읽기, 변수 쓰기, 프로그램 실행, 목표 자세 | 셀 컴퓨터, 작업 지시 |
| 실시간 외부 제어 | 몇 ms마다 관절 목표나 보정값 | 비전 추적, 힘 제어, 연구 |

가장 흔한 것은 **신호와 레지스터**입니다. PLC가 [「PROFINET과 EtherNet/IP」](#/read/cpp-industrial/fb-ethernet) 같은 필드버스로 프로그램 번호와 시작 신호를 주면, 로봇은 실행 중, 완료, 고장을 신호로 돌려줍니다. [「PLC, HMI, SCADA, MES」](#/read/cpp-industrial/land-roles)에서 본 대로 시작 신호는 로봇이 받았음을 알린 뒤에 내리고, 비전이 잰 부품 위치 같은 숫자는 로봇의 레지스터로 넘깁니다. 로봇이 경로를 다 스스로 정하므로 단단하고, 셀 전체를 PLC가 지휘합니다.

**명령 인터페이스**는 이더넷으로 상태를 읽고 변수를 쓰고 프로그램을 시작하는 API입니다(ABB의 Robot Web Services, KUKA의 EthernetKRL 등). 수십 ms 단위로 오가므로 셀 컴퓨터가 작업을 바꾸거나 상태를 모으는 데 알맞습니다. **실시간 외부 제어**는 PC가 제어기의 주기마다 목표를 흘려보내는 방식입니다. ABB의 EGM은 4ms마다(실제 움직임까지 10~20ms 지연), KUKA의 RSI는 4ms나 12ms마다 값을 주고받고, FANUC은 DPM이 비슷한 일을 합니다. 용접선을 따라가거나 움직이는 물체를 쫓을 때처럼 센서가 경로를 바로잡아야 할 때 씁니다.

## 흘려보낼 때의 감시

실시간 외부 제어에서 PC는 언제든 늦거나, 멈추거나, 이상한 값을 보낼 수 있습니다. 그래서 로봇 제어기는 PC를 믿지 않고 들어오는 목표를 스스로 감시합니다. 아래는 4ms 주기 제어기의 감시를 흉내 낸 것입니다. PC는 1초 동안 관절을 0도에서 30도로 옮기는 경로를 보내는데, 중간에 한 번 튄 값을 보내고, 12ms 늦고, 160ms 멈춥니다.

```cpp
#include <cmath>
#include <cstdio>
#include <numbers>
#include <optional>

constexpr double kDt = 0.004;           // 로봇 제어기 주기 4ms
constexpr double kStep = 90.0 * kDt;    // 관절 최대 90도/s, 한 주기에 0.36도
constexpr int kMaxMissing = 5;          // 목표가 5주기(20ms) 없으면 보호 정지

// 로봇 제어기 쪽: PC를 믿지 않고 스스로 감시한다
class Robot {
public:
    void cycle(int k, std::optional<double> target) {
        double t = k * kDt;
        if (stopped_) { if (target) ++ignored_; return; }
        if (!target) {
            if (++missing_ == kMaxMissing) {
                stopped_ = true;
                std::printf("%.3fs 목표가 %d주기 끊김: 보호 정지 (관절 %.2f도)\n",
                            t, missing_, q_);
            }
            return;                     // 마지막 목표에 머문다
        }
        if (missing_ > 0)
            std::printf("%.3fs 목표 %d주기 늦음: 기다렸다가 이어 감\n", t,
                        missing_);
        missing_ = 0;
        double step = *target - q_;
        if (std::abs(step) > kStep) {
            std::printf("%.3fs %.2f도 걸음 요청: 한 주기 한계 %.2f도로 줄임\n",
                        t, step, kStep);
            step = std::copysign(kStep, step);
        }
        q_ += step;
    }
    void report() const {
        std::printf("멈춘 뒤 들어온 목표 %d개는 무시함, 다시 시작은 현장 확인 뒤\n",
                    ignored_);
    }

private:
    double q_ = 0;
    int missing_ = 0, ignored_ = 0;
    bool stopped_ = false;
};

double plan(double t) {                 // PC가 계획한 경로: 1초 동안 0도에서 30도로
    return t >= 1 ? 30 : 15 * (1 - std::cos(std::numbers::pi * t));
}

int main() {
    Robot robot;
    for (int k = 0; k <= 300; ++k) {    // 1.2초 동안 4ms마다
        double t = k * kDt;
        std::optional<double> target = plan(t);
        if (k == 100) *target += 10;                 // 비전이 한 번 튄 값을 보냄
        if (k >= 150 && k < 153) target.reset();     // PC가 12ms 늦음
        if (k >= 200 && k < 240) target.reset();     // PC가 160ms 멈춤
        robot.cycle(k, target);
    }
    robot.report();
}
```

```text
0.400s 10.18도 걸음 요청: 한 주기 한계 0.36도로 줄임
0.612s 목표 3주기 늦음: 기다렸다가 이어 감
0.612s 0.71도 걸음 요청: 한 주기 한계 0.36도로 줄임
0.616s 0.53도 걸음 요청: 한 주기 한계 0.36도로 줄임
0.816s 목표가 5주기 끊김: 보호 정지 (관절 27.02도)
멈춘 뒤 들어온 목표 61개는 무시함, 다시 시작은 현장 확인 뒤
```

- **큰 걸음은 줄인다**: 비전이 한 번 튀어 10도 떨어진 목표를 보냈지만, 로봇은 한 주기에 갈 수 있는 0.36도(90도/s)까지만 움직였습니다. 실제 제어기는 속도와 함께 가속도와 위치 한계도 보고, 한계를 넘는 요청이 이어지면 멈춥니다
- **늦으면 뒤처진다**: PC가 12ms 늦는 동안 로봇은 마지막 목표에 머물렀고, 그 사이 경로는 앞서 나가 0.71도를 따라잡아야 했습니다. 따라잡는 걸음이 한계에 걸려 경로가 어긋났습니다. 실제 제어기는 목표를 거르거나 앞으로 늘여 흔들림을 줄이지만, 근본 대책은 PC 쪽 루프를 [「주기 작업」](#/read/cpp-industrial/rt-cyclic)처럼 늦지 않게 돌리는 것입니다
- **끊기면 멈춘다**: 20ms 동안 목표가 없자 보호 정지했고, 그 뒤 PC가 다시 보낸 목표 61개는 무시했습니다. 멈춘 로봇이 PC의 목표만 보고 저절로 다시 움직이면 안 되므로, 다시 시작은 [「오류에서 돌아오기」](#/read/cpp-industrial/rel-recovery)처럼 현장 확인을 거칩니다

## ros2_control

[「ROS 2」](#/read/cpp-industrial/rob-ros2)에서는 ros2_control이 이 연결을 맡습니다. 로봇마다 하드웨어 인터페이스 하나를 만들어 `read`에서 관절 상태를 읽고 `write`에서 목표를 보내게 하면, 컨트롤러 관리자가 실시간 루프에서 읽기, 컨트롤러 계산, 쓰기를 반복합니다. 그 위에서 joint_trajectory_controller 같은 컨트롤러가 MoveIt 2가 [「기구학」](#/read/cpp-industrial/rob-kinematics)으로 계획한 궤적을 따라갑니다. Universal Robots처럼 공식 ROS 2 드라이버를 내놓은 회사도 있고, 사용자 모임이 만든 드라이버도 많습니다. 어느 쪽이든 하드웨어 인터페이스 밑에서는 위의 세 방법 중 하나로 제어기와 말합니다.

<Note>
로봇의 안전 한계는 PC가 아니라 로봇 제어기 안의 안전 제어기가 지킵니다. 안전 속도, 작업 영역 제한, 정지 기능은 외부 제어로 넘어설 수 없게 만들어져 있고, 셀 전체의 안전은 [「안전과 인증」](#/read/cpp-industrial/land-safety)의 위험성 평가로 정합니다. 산업용 로봇의 안전 표준 ISO 10218은 2025년에 개정되면서 협동 로봇의 요구(예전의 ISO/TS 15066)를 본문에 합치고 사이버 보안 요구도 더했습니다.
</Note>

## 정리

- 산업용 로봇은 자기 제어기가 경로와 서보와 안전을 맡고, PC와 PLC는 신호와 레지스터, 명령 인터페이스, 실시간 외부 제어 중 하나로 제어기와 잇는다
- 실시간 외부 제어에서 로봇 제어기는 큰 걸음을 줄이고 목표가 끊기면 보호 정지하므로, PC 쪽 루프는 늦지 않게 돌리고 다시 시작은 현장 확인을 거친다
- ROS 2에서는 ros2_control의 하드웨어 인터페이스가 read와 write로 로봇과 이어지며, 안전 한계는 언제나 로봇의 안전 제어기가 지킨다
