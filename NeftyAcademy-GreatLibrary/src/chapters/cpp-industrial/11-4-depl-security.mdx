공장의 보안은 사무실의 보안과 우선순위가 다릅니다. 사무실에서는 정보가 새는 것이 가장 큰 걱정이지만, 공장에서는 라인이 멈추거나 위조된 명령으로 기계가 움직이는 것이 더 큰 걱정입니다. 장비는 10년 넘게 쓰이고, [「Modbus RTU와 TCP」](#/read/cpp-industrial/fb-modbus)처럼 인증이 없는 프로토콜이 아직 많으며, 패치 하나에도 라인을 세워야 합니다([「업데이트」](#/read/cpp-industrial/depl-update)). 그래서 한 겹에 기대지 않고 망, 장비, 사람의 절차를 겹겹이 지킵니다.

## 퍼듀 모델

퍼듀 모델은 [「자동화 피라미드」](#/read/cpp-industrial/land-pyramid)와 비슷하게 공장을 수준으로 나누지만, PLC 같은 제어기를 1수준, HMI와 SCADA를 2수준, 히스토리언과 MES를 3수준, 업무망을 4수준에 두고, 3수준과 4수준 사이에 **DMZ**(3.5수준)를 둡니다. 핵심 규칙은 업무망과 제어 쪽이 직접 말하지 않는다는 것입니다. 데이터는 DMZ에 둔 복제본이나 게이트웨이를 거쳐 위로 나가고, 원격 접속은 DMZ의 점프 호스트를 거쳐 들어옵니다([「원격 유지보수」](#/read/cpp-industrial/depl-remote)). 업무망이 랜섬웨어에 걸려도 제어망까지 번지지 않게 하려는 것입니다.

## 구역과 길

산업 자동화 보안 표준인 **IEC 62443**은 이 생각을 **구역**(zone)과 **길**(conduit)로 정리합니다. 보안 요구가 같은 자산을 한 구역으로 묶고, 구역 사이에는 허락한 통신만 지나는 길을 둡니다. 구역마다 막아야 할 공격자의 수준을 보안 수준(SL 1~4)으로 정하는데, SL 1은 실수나 우연, SL 2는 단순한 수단의 의도적 공격, SL 3과 4는 산업 시스템을 아는 공격자의 정교한 공격을 막는 수준입니다. 이름이 비슷하지만 [「IEC 61508」](#/read/cpp-industrial/safe-iec61508)의 SIL과는 다른 척도입니다. 표준은 역할별로 나뉘어, 공장 주인(2-1), 위험 평가와 구역 설계(3-2), 시스템 요구(3-3), 장비 회사의 개발 과정(4-1)과 부품 요구(4-2)를 따로 다룹니다.

아래는 구역과 길을 표로 적고, 관찰한 연결을 그 표에 비춰 보는 프로그램입니다. 산업용 방화벽처럼 Modbus는 기능 코드까지 봅니다.

```cpp
#include <cstdio>
#include <map>
#include <set>
#include <string>
#include <vector>

enum Zone { Cloud, Enterprise, DMZ, Operations, Supervisory, Control };
const char* zone_name[] = {"클라우드", "업무망(4)", "DMZ(3.5)",
                           "운영(3)",  "감시(2)",   "제어(1)"};

const std::map<std::string, Zone> assets = {
    {"클라우드 브로커", Cloud},  {"사무실 PC", Enterprise},
    {"점프 호스트", DMZ},        {"에지 게이트웨이", DMZ},
    {"히스토리언", Operations},  {"OPC UA 서버", Supervisory},
    {"HMI", Supervisory},        {"PLC", Control},
};

struct Conduit {            // 구역 사이에 허락한 길, 연결은 from 쪽에서만 연다
    Zone from, to;
    std::string proto;
    int port;
    std::set<int> fcodes;   // 허락한 Modbus 기능 코드 (비어 있으면 보지 않음)
};
const std::vector<Conduit> conduits = {
    {Supervisory, Control, "modbus", 502, {3, 16}},   // 레지스터 읽기, 여러 개 쓰기
    {Operations, Supervisory, "opcua", 4840, {}},
    {Operations, DMZ, "mqtts", 8883, {}},
    {DMZ, Cloud, "mqtts", 8883, {}},
    {DMZ, Supervisory, "rdp", 3389, {}},              // 원격 유지보수용
    {Enterprise, DMZ, "https", 443, {}},
};

struct Flow { std::string src, dst, proto; int port; int fcode = 0; };

void check(const Flow& f) {
    Zone a = assets.at(f.src), b = assets.at(f.dst);
    std::string why;
    bool ok = a == b;                                  // 같은 구역 안
    for (const Conduit& c : conduits) {
        if (ok) break;
        bool same_path = c.proto == f.proto && c.port == f.port;
        if (c.from == b && c.to == a && same_path) why = "연결은 반대쪽에서만 연다";
        if (c.from != a || c.to != b) continue;
        if (!same_path) {
            why = "이 길은 " + c.proto + ":" + std::to_string(c.port) + "만";
            continue;
        }
        if (!c.fcodes.empty() && !c.fcodes.count(f.fcode)) {
            why = "막힌 기능 코드 " + std::to_string(f.fcode);
            continue;
        }
        ok = true;
    }
    if (!ok && why.empty())
        why = std::string(zone_name[a]) + "에서 " + zone_name[b] +
              "로 가는 길 없음";
    std::printf("%s %s -> %s %s:%d", ok ? "허락" : "거부", f.src.c_str(),
                f.dst.c_str(), f.proto.c_str(), f.port);
    if (f.fcode) std::printf(" FC%d", f.fcode);
    if (!ok) std::printf("  (%s)", why.c_str());
    std::printf("\n");
}

int main() {
    const std::vector<Flow> flows = {
        {"HMI", "PLC", "modbus", 502, 3},
        {"HMI", "PLC", "modbus", 502, 5},
        {"히스토리언", "OPC UA 서버", "opcua", 4840},
        {"히스토리언", "PLC", "modbus", 502, 3},
        {"사무실 PC", "HMI", "rdp", 3389},
        {"사무실 PC", "점프 호스트", "https", 443},
        {"점프 호스트", "HMI", "rdp", 3389},
        {"에지 게이트웨이", "클라우드 브로커", "mqtt", 1883},
        {"클라우드 브로커", "에지 게이트웨이", "mqtts", 8883},
    };
    for (const Flow& f : flows) check(f);
}
```

```text
허락 HMI -> PLC modbus:502 FC3
거부 HMI -> PLC modbus:502 FC5  (막힌 기능 코드 5)
허락 히스토리언 -> OPC UA 서버 opcua:4840
거부 히스토리언 -> PLC modbus:502 FC3  (운영(3)에서 제어(1)로 가는 길 없음)
거부 사무실 PC -> HMI rdp:3389  (업무망(4)에서 감시(2)로 가는 길 없음)
허락 사무실 PC -> 점프 호스트 https:443
허락 점프 호스트 -> HMI rdp:3389
거부 에지 게이트웨이 -> 클라우드 브로커 mqtt:1883  (이 길은 mqtts:8883만)
거부 클라우드 브로커 -> 에지 게이트웨이 mqtts:8883  (연결은 반대쪽에서만 연다)
```

- **적어 둔 길만**: 구역 사이에는 표에 적은 길만 열고 나머지는 모두 막습니다. 업무망에서 HMI로 바로 가는 원격 데스크톱은 길이 없어 막혔고, 같은 일은 DMZ의 점프 호스트를 거쳐야 됩니다
- **수준을 건너뛰지 않는다**: 히스토리언(3)은 PLC(1)를 바로 읽지 못하고 감시 수준의 OPC UA 서버에서 읽습니다. 3수준이 뚫려도 PLC까지 한 번에 닿지 않게 하려는 것입니다
- **방향과 암호화**: 데이터는 안에서 바깥으로 밀어 냅니다. 클라우드가 먼저 여는 연결은 막고, 평문 MQTT(1883)도 막아 TLS(8883)만 씁니다([「MQTT와 Sparkplug」](#/read/cpp-industrial/data-mqtt))
- **기능 코드까지**: 인증이 없는 Modbus는 포트가 열려 있으면 누구나 코일을 씁니다. 그래서 이 길에서는 레지스터 읽기(3)와 여러 레지스터 쓰기(16)만 통과시키고, 코일 하나 쓰기(5)는 막았습니다

## 장비 회사가 할 일

공장 주인이 망을 나누어도 장비가 허술하면 구역 안에서 뚫립니다. 장비를 만드는 쪽은 처음부터 안전한 기본값으로 내보냅니다. 모든 장비에 같은 기본 암호를 두지 않고 장비마다 다르게 하거나 처음 켤 때 바꾸게 하며, 쓰지 않는 서비스와 포트는 닫습니다. 업데이트는 서명하고 보안 부팅으로 켜지는 코드를 확인하며([「업데이트」](#/read/cpp-industrial/depl-update)), 통신은 인증서로 상대를 확인하고([「OPC UA」](#/read/cpp-industrial/fb-opcua)의 서명과 암호화 모드), 프로그램은 필요한 권한만 가지고 돌고([「산업용 PC」](#/read/cpp-industrial/depl-ipc)), 누가 무엇을 했는지 남깁니다. 제품에 든 라이브러리 목록(SBOM)을 관리해, 어떤 라이브러리에 취약점이 나오면 어느 제품이 영향을 받는지 바로 찾고 고친 판을 내놓습니다.

<Note>
법도 이 방향으로 움직입니다. EU의 사이버 복원력법(CRA)에 따라 EU 시장에 디지털 요소가 있는 제품을 파는 제조사는 2026년 9월 11일부터 실제로 악용된 취약점과 심각한 보안 사고를 보고해야 하고, 2027년 12월 11일부터는 설계 단계의 보안, 취약점 처리, 지원 기간 동안의 보안 업데이트 같은 주요 의무를 지켜야 합니다. 산업용 장비의 개발 과정과 기능 요구는 IEC 62443-4-1과 4-2가 구체적으로 정합니다.
</Note>

## 정리

- 공장 보안은 가용성과 안전이 먼저이며, 퍼듀 모델처럼 수준을 나누고 업무망과 제어 쪽 사이에 DMZ를 두어 직접 말하지 않게 한다
- IEC 62443은 자산을 구역으로 묶고 구역 사이에 허락한 길만 두며, 길은 방향과 프로토콜, Modbus라면 기능 코드까지 정하고 나머지는 막는다
- 장비 회사는 장비마다 다른 암호, 닫힌 포트, 서명된 업데이트, 인증서 통신, 최소 권한, SBOM으로 안전한 기본값을 갖추고, CRA 같은 법의 보고와 업데이트 의무를 지킨다
