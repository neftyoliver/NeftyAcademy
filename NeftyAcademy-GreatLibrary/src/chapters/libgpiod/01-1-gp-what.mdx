GPIO 핀은 프로그램이 전압을 올리고 내리거나 읽는 선입니다. 리눅스에서는 프로그램이 핀을 직접 만지지 않습니다. 핀은 커널의 것이고, 프로그램은 커널에 그 핀을 달라고 해서 받은 동안에만 씁니다. 이 책은 그 일을 libgpiod 2로 합니다. 이 쪽은 달라고 하고, 쓰고, 돌려주는 한 바퀴를 먼저 돌려 보고, 책 전체에서 쓸 낱말을 정합니다. LED를 잇는 법은 「라즈베리파이 시작하기」의 [「첫 프로젝트: LED 하나 켜기까지」](#/read/sbc-start/first-project)에서 봤습니다.

## 세 낱말

| 낱말 | 무엇인가 | 어떻게 가리키나 |
| --- | --- | --- |
| 칩 | 핀 여러 개를 맡은 제어기 하나 | `/dev/gpiochip0` 같은 장치 파일 |
| 줄 | 칩이 맡은 신호 하나. 핀 하나에 해당한다 | 칩 안에서 0부터 매긴 번호(오프셋) |
| 요청 | 줄을 쥐고 있다는 표. 줄 하나나 여럿을 묶는다 | 요청할 때 돌려받는 객체 |

- **칩**: 라즈베리파이 4에서 40핀 헤더를 맡은 칩은 `/dev/gpiochip0`이고 줄이 58개입니다. 헤더로 나온 것은 그 가운데 0번부터 27번입니다
- **줄**: 헤더의 칩에서는 오프셋이 GPIO 번호와 같습니다. GPIO 17은 17번 줄입니다([「핀 번호: 헤더, BCM, 줄 오프셋」](#/read/libgpiod/gp-numbering))
- **요청**: 값을 쓰고 읽는 함수는 모두 요청을 받습니다. 요청이 없으면 줄의 값을 볼 수도 바꿀 수도 없습니다

## 한 바퀴

아래 프로그램은 GPIO 17을 쥐기 전과 쥔 동안과 놓은 뒤에 그 줄이 누구의 것인지 묻고, 쥔 동안에 LED를 두 번 깜박입니다. 쥔 채로 같은 줄을 한 번 더 달라고도 해 봅니다.

```c gpiosim
// 줄 하나를 쥐었다 놓는다: 쥐기 전, 쥔 동안, 놓은 뒤에 그 줄이 누구의 것인가
#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <gpiod.h>
#include <stdio.h>
#include <string.h>
#include <time.h>

enum { LED = 17 };                           // GPIO 17, 헤더의 핀 11

// 그 줄을 지금 누가 쥐고 있는지 적는다
static void who_holds(struct gpiod_chip* chip, const char* when) {
    struct gpiod_line_info* info = gpiod_chip_get_line_info(chip, LED);
    if (!info) {
        perror("줄 정보");
        return;
    }
    const char* consumer = gpiod_line_info_get_consumer(info);
    if (!gpiod_line_info_is_used(info))
        printf("%s: 아무도 쥐고 있지 않다\n", when);
    else
        printf("%s: %s\n", when, consumer ? consumer : "이름 없는 누군가");
    gpiod_line_info_free(info);
}

// GPIO 17을 출력으로 달라고 한다. 받지 못하면 nullptr
static struct gpiod_line_request* hold(struct gpiod_chip* chip, const char* name) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_OUTPUT);
    struct gpiod_line_config* config = gpiod_line_config_new();
    unsigned int offset = LED;
    gpiod_line_config_add_line_settings(config, &offset, 1, settings);
    struct gpiod_request_config* who = gpiod_request_config_new();
    gpiod_request_config_set_consumer(who, name);

    struct gpiod_line_request* request =
        gpiod_chip_request_lines(chip, who, config);

    gpiod_request_config_free(who);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    who_holds(chip, "쥐기 전");

    struct gpiod_line_request* mine = hold(chip, "first-hold");
    if (!mine) {
        perror("요청");
        return 1;
    }
    who_holds(chip, "쥔 동안");

    const struct timespec half_second = {.tv_nsec = 500'000'000};
    for (int i = 0; i < 2; ++i) {
        gpiod_line_request_set_value(mine, LED, GPIOD_LINE_VALUE_ACTIVE);
        nanosleep(&half_second, nullptr);
        gpiod_line_request_set_value(mine, LED, GPIOD_LINE_VALUE_INACTIVE);
        nanosleep(&half_second, nullptr);
    }

    if (!hold(chip, "second-hold"))          // 같은 줄을 한 번 더 달라고 해 본다
        printf("둘째 요청: %s\n", strerror(errno));

    gpiod_line_request_release(mine);
    who_holds(chip, "놓은 뒤");
    gpiod_chip_close(chip);
}
```

```text
쥐기 전: 아무도 쥐고 있지 않다
쥔 동안: first-hold
핀|   0.000s  GPIO 17 → HIGH
핀|   0.500s  GPIO 17 → LOW
핀|   1.000s  GPIO 17 → HIGH
핀|   1.500s  GPIO 17 → LOW
둘째 요청: Device or resource busy
놓은 뒤: 아무도 쥐고 있지 않다
```

- **`핀|`으로 시작하는 줄**: 프로그램이 찍은 것이 아닙니다. 예제를 돌린 흉내 칩이 핀의 전압이 바뀐 때를 적은 것입니다. 보드에서는 이 자리에 LED가 켜지고 꺼집니다
- **쥐기 전**: 줄은 누구의 것도 아닙니다. 정보는 요청 없이도 읽을 수 있습니다
- **쥔 동안**: 줄에 내가 붙인 이름이 보입니다. 다른 프로그램이 `gpioinfo`로 봐도 같은 이름이 보입니다
- **둘째 요청**: 이미 쥔 줄을 또 달라고 하면 `EBUSY`로 거절됩니다. 같은 프로그램이 해도 마찬가지입니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))
- **놓은 뒤**: 줄은 다시 누구의 것도 아닙니다. 커널 문서는 놓은 줄의 상태를 더는 보장하지 않으며 기본 상태로 돌아갈 수 있다고 적습니다([「놓아주기」](#/read/libgpiod/rq-release))

`hold` 안에서 객체 셋을 만들었다 버리는 까닭은 [「설정 객체 셋: line_settings, line_config, request_config」](#/read/libgpiod/rq-objects)에서 봅니다. 지금은 줄의 성질을 적고, 어느 줄인지 적고, 내 이름을 적어서 한 번에 낸다는 것만 봅니다.

## 커널이 사이에 서는 까닭

- **한 줄에는 임자가 하나다**: 두 프로그램이 같은 핀을 하나는 올리고 하나는 내리면 결과를 알 수 없습니다. 요청은 그 일을 처음부터 막습니다
- **프로그램이 죽어도 놓인다**: 요청은 커널이 내준 파일에 매여 있습니다. 프로그램이 끝나면 파일이 닫히고 줄도 함께 놓입니다. 놓는 것을 잊은 프로그램이 핀을 영영 붙들지 못합니다
- **누가 쓸 수 있는지를 정한다**: 칩은 장치 파일이라서 파일의 권한이 곧 핀의 권한입니다([「권한: gpio 그룹과 udev」](#/read/libgpiod/st-permission))
- **보드가 달라도 같은 코드**: 프로그램은 칩과 오프셋만 압니다. 그 뒤에서 어떤 회로의 어떤 레지스터를 만지는지는 커널의 드라이버가 압니다

## 어디에 쓰고 어디에 쓰지 않나

커널 문서는 사용자 공간에서 GPIO를 만지는 길이 누구를 위한 것인지를 따로 적어 둡니다.

- **맞는 자리**: 시제품, 공장의 설비, 메이커의 작품, 실험 장비처럼 하나씩 만들어 쓰고 다루는 사람이 그 장치를 잘 아는 물건입니다. 이 서가가 다루는 장치가 여기에 듭니다
- **맞지 않는 자리**: 똑같이 여러 대를 찍어 파는 제품입니다. 문서는 그런 물건이라면 커널 드라이버로 다시 쓰라고 적습니다
- **이미 드라이버가 있는 일**: LED, 키로 쓰는 단추, I2C와 SPI, PWM, 1-Wire는 커널에 드라이버가 있습니다. 핀을 프로그램으로 흔들어 흉내 내기 전에 그것부터 찾습니다([「커널 드라이버에 맡길 것들」](#/read/libgpiod/tm-kernel))

<Note>
이 책의 libgpiod 예제는 보드가 아니라 이 책을 쓰며 만든 흉내 칩에서 돌렸습니다. 흉내 칩은 libgpiod 2와 같은 이름의 함수를 내주고 4 Model B의 칩처럼 대답하는 프로그램입니다. 시간도 가짜여서 `nanosleep`은 기다리지 않고 가상의 시계만 돌립니다. 그래서 출력의 시각이 딱 떨어집니다. 줄을 쥐는 규칙과 오류 코드는 커널 문서와 libgpiod의 문서에 적힌 대로 흉내 냈고, 문서에 없는 부분은 쪽마다 밝힙니다. 같은 소스가 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 경고 없이 컴파일되는 것까지는 확인했고, 진짜 보드에서 돌려 보지는 못했습니다.
</Note>

## 정리

- 칩은 핀들을 맡은 제어기, 줄은 그 안의 신호 하나, 요청은 줄을 쥐고 있다는 표다
- 줄은 요청한 프로그램만 쓰고, 이미 쥔 줄을 또 달라고 하면 `EBUSY`이며, 프로그램이 끝나면 저절로 놓인다
- 사용자 공간의 GPIO는 하나씩 만들어 쓰는 장치를 위한 길이고, 커널에 드라이버가 있는 일은 드라이버에 맡긴다
