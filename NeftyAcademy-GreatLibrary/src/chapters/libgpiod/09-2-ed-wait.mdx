에지 감지를 켠 요청에서 이벤트를 받는 일은 두 함수가 나눠 맡습니다. 하나는 이벤트가 생길 때까지 프로그램을 재우고, 하나는 생긴 이벤트를 꺼내 옵니다. 앞 쪽의 예제가 이미 둘을 썼고, 여기서는 그 규칙을 봅니다.

## 기다리는 함수

`gpiod_line_request_wait_edge_events(request, timeout_ns)`는 요청에 든 줄 가운데 어디서든 이벤트가 생길 때까지 기다립니다. 둘째 인수는 기다릴 시간이고 단위는 나노초입니다.

| `timeout_ns` | 하는 일 |
| --- | --- |
| 음수 | 이벤트가 올 때까지 끝없이 기다린다 |
| 0 | 기다리지 않고, 지금 있는지만 알려 준다 |
| 양수 | 많아야 그만큼 기다린다 |

- **돌려주는 값은 셋이다**: 읽을 이벤트가 있으면 1, 시간이 다 됐으면 0, 오류면 -1입니다
- **꺼내지는 않는다**: 있는지를 알려 줄 뿐입니다. 읽지 않고 다시 부르면 곧바로 1이 또 돌아옵니다
- **자는 동안에는 CPU를 쓰지 않는다**: 프로그램은 커널 안에서 잠들고, 인터럽트가 이벤트를 만들었을 때 깨어납니다
- **1초는 `1'000'000'000`이다**: 형은 `int64_t`입니다. 밀리초로 적는 `poll`과 단위가 다릅니다([「poll, epoll과 함께 쓰기」](#/read/libgpiod/ed-poll))

## 읽는 함수와 이벤트 버퍼

- **`gpiod_edge_event_buffer_new`**: 이벤트를 받아 둘 buffer를 만듭니다. 인수는 담을 수 있는 개수이고, 다 쓰면 `gpiod_edge_event_buffer_free`로 치웁니다([「이벤트 버퍼」](#/read/libgpiod/ed-buffer))
- **`gpiod_line_request_read_edge_events`**: 커널에 쌓인 이벤트를 많아야 셋째 인수의 개수만큼 buffer로 옮기고, 옮긴 개수를 돌려줍니다. 실패하면 -1입니다
- **없으면 막힌다**: 쌓인 이벤트가 하나도 없을 때 부르면 올 때까지 돌아오지 않습니다. 그래서 기다리는 함수로 있음을 확인한 뒤에 부릅니다
- **덮어쓴다**: buffer에 있던 것은 지워지고 이번에 읽은 것만 남습니다. 이어 붙지 않습니다
- **`gpiod_edge_event_buffer_get_event`**: buffer의 몇 번째 이벤트를 가리키는 포인터를 줍니다. 읽은 개수를 넘는 번호에는 NULL입니다
- **이벤트는 buffer의 것이다**: 받은 포인터를 free하지 않고, 다음에 읽은 뒤에는 쓰지 않습니다. 더 오래 들고 있으려면 `gpiod_edge_event_copy`로 베끼고, 베낀 것은 `gpiod_edge_event_free`로 치웁니다

이벤트 하나에서 꺼낼 수 있는 것은 다섯입니다. 함수 이름은 모두 `gpiod_edge_event_get_`으로 시작합니다.

| 이름의 끝 | 꺼내는 것 |
| --- | --- |
| `event_type` | 올라가는 에지인지 내려가는 에지인지 |
| `line_offset` | 어느 줄에서 났는지 |
| `timestamp_ns` | 커널이 찍은 시각 |
| `global_seqno` | 이 요청에서 몇 번째 이벤트인지 |
| `line_seqno` | 그 줄에서 몇 번째 이벤트인지 |

## 단추를 기다려서 읽기

아래 예제는 [「단추 읽기」](#/read/libgpiod/in-button)의 단추를 이번에는 훑지 않고 기다려서 읽습니다. 단추는 그때처럼 0.15초 동안 한 번, 1.4초 동안 한 번 눌리고, 4.5초에 Ctrl+C가 옵니다.

```c gpiosim=tap
// 단추의 에지를 기다렸다가 누른 횟수와 길이를 적고, Ctrl+C에 합계를 내고 끝난다
#include <errno.h>
#include <gpiod.h>
#include <inttypes.h>
#include <signal.h>
#include <stdio.h>

enum {
    BUTTON = 27,                             // GPIO 27, 핀 13. 건너편은 GND
    ROOM = 8,                                // 한 번에 읽어 올 이벤트의 수
};

static volatile sig_atomic_t stop;
static void on_signal(int) { stop = 1; }

// 풀업을 켠 액티브 로 입력에 두 방향의 에지 감지를 켠다
static struct gpiod_line_request* request_button(struct gpiod_chip* chip,
                                                 unsigned int offset,
                                                 const char* consumer) {
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    struct gpiod_line_request* request = nullptr;
    if (settings && config && request_config) {
        gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_INPUT);
        gpiod_line_settings_set_bias(settings, GPIOD_LINE_BIAS_PULL_UP);
        gpiod_line_settings_set_active_low(settings, true);
        gpiod_line_settings_set_edge_detection(settings, GPIOD_LINE_EDGE_BOTH);
        gpiod_line_settings_set_debounce_period_us(settings, 10'000);  // 떨림 거름
        gpiod_line_config_add_line_settings(config, &offset, 1, settings);
        gpiod_request_config_set_consumer(request_config, consumer);
        request = gpiod_chip_request_lines(chip, request_config, config);
    }
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_line_request* button = request_button(chip, BUTTON, "button");
    gpiod_chip_close(chip);
    struct gpiod_edge_event_buffer* buffer = gpiod_edge_event_buffer_new(ROOM);
    if (!button || !buffer) {
        perror("요청");
        return 1;
    }
    signal(SIGINT, on_signal);
    signal(SIGTERM, on_signal);

    int presses = 0;
    uint64_t pressed_at = 0;                 // 누른 순간의 타임스탬프. 0이면 모른다
    while (!stop) {
        // 이벤트가 올 때까지 잔다. 신호가 와도 깬다
        int ready = gpiod_line_request_wait_edge_events(button, -1);
        if (ready < 0) {
            if (errno == EINTR) continue;    // 신호였다. 깃발을 보러 간다
            perror("기다리기");
            break;
        }
        int count = gpiod_line_request_read_edge_events(button, buffer, ROOM);
        if (count < 0) {
            perror("읽기");
            break;
        }
        for (int i = 0; i < count; ++i) {
            struct gpiod_edge_event* event =
                gpiod_edge_event_buffer_get_event(buffer, (unsigned long)i);
            uint64_t at = gpiod_edge_event_get_timestamp_ns(event);
            if (gpiod_edge_event_get_event_type(event) ==
                GPIOD_EDGE_EVENT_RISING_EDGE) {
                pressed_at = at;             // 눌렸다
                ++presses;
            } else if (pressed_at != 0) {    // 떼었다
                printf("%d번째 누름: %" PRIu64 "ms\n", presses,
                       (at - pressed_at) / 1'000'000);
            }
        }
    }
    printf("모두 %d번 눌렀다\n", presses);
    gpiod_edge_event_buffer_free(buffer);
    gpiod_line_request_release(button);
}
```

```text
1번째 누름: 150ms
2번째 누름: 1400ms
모두 2번 눌렀다
```

- **다섯 번만 깼다**: 훑어 읽던 프로그램은 4초 동안 800번 넘게 깼습니다. 이 프로그램은 누르고 뗀 네 번과 신호 한 번에만 깼습니다
- **길이는 타임스탬프의 차이다**: 뗀 시각에서 누른 시각을 뺐습니다. 둘 다 커널이 찍은 것이라, 프로그램이 늦게 깨어 읽어도 길이는 달라지지 않습니다([「타임스탬프와 시계 고르기」](#/read/libgpiod/ed-timestamp))
- **떨림은 커널이 걸렀다**: 요청에 적은 `gpiod_line_settings_set_debounce_period_us`가 그 일을 합니다. 접점이 떨린 것도, 길게 누르던 도중에 잠깐 뜬 것도 이벤트가 되지 않았습니다([「디바운스」](#/read/libgpiod/ed-debounce))
- **돌려받은 개수만큼 돈다**: 프로그램이 다른 일을 하는 사이에 이벤트가 여럿 쌓일 수 있습니다. 하나만 왔으리라고 치지 않습니다
- **첫 이벤트가 뗌일 수도 있다**: 단추를 누른 채로 프로그램을 켜면 뗄 때의 이벤트가 먼저 옵니다. `pressed_at`이 0인 동안의 뗌은 길이를 셈하지 않고 넘깁니다

## 신호가 왔을 때

- **기다리던 함수는 -1로 돌아온다**: 신호 처리기가 돌고 나면 기다리는 함수는 -1을 돌려주고 `errno`는 `EINTR`입니다. 오류로 치지 않고 깃발을 보러 갑니다([「놓아주기」](#/read/libgpiod/rq-release))
- **읽는 함수에서 막혀 있었다면 다르다**: 처리기를 어떻게 걸었느냐에 따라, 막혀 있던 읽기가 `EINTR`로 돌아오기도 하고 신호를 받고도 다시 기다리기도 합니다. 뒤쪽이면 Ctrl+C를 눌러도 다음 이벤트가 올 때까지 끝나지 않습니다
- **`signal`은 컴파일 옵션을 탄다**: glibc의 `signal`은 `-std=c23`에서는 돌아오게 하는 쪽으로, `-std=gnu23`이나 옵션이 없을 때에는 다시 기다리게 하는 쪽으로 처리기를 겁니다
- **그래서 짝으로 쓴다**: 기다리는 일은 어느 쪽이든 신호에 깨는 기다리는 함수에 맡기고, 읽는 함수는 있음을 확인한 뒤에만 부릅니다. 그러면 처리기를 건 방식을 따질 일이 없습니다

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, 단추와 Ctrl+C는 대본으로 넣었습니다. `signal`이 처리기를 거는 두 방식과, 막힌 읽기가 그에 따라 돌아오거나 다시 기다리는 것은 이 책을 쓴 환경(glibc 2.39, GCC 14)에서 파이프로 확인했습니다. GPIO 요청의 읽기도 같으리라는 것은 커널 소스에서 읽은 것이고 보드에서 본 것은 아닙니다. 기다리는 함수가 언제나 `EINTR`로 돌아온다는 것은 signal(7)에 적혀 있습니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했습니다.
</Note>

## 정리

- 기다리는 함수는 이벤트가 있으면 1, 시간이 다 되면 0, 오류나 신호에는 -1을 돌려준다
- 읽는 함수는 쌓인 이벤트를 buffer로 옮기고 개수를 돌려준다. 없을 때 부르면 막힌다
- 기다리기와 읽기를 짝으로 쓰고, -1에 `EINTR`이면 끝내라는 깃발을 본다
