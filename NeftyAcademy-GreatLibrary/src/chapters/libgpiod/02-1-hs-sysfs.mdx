오래된 글은 GPIO를 `/sys/class/gpio` 아래의 파일에 숫자를 써 넣어 다룹니다. 이것이 sysfs 방식입니다. 셸에서 `echo` 한 줄로 핀이 움직여서 널리 퍼졌지만, 커널 문서는 이제 이 방식을 낡은 것으로 적고 앞으로 없앤다고 밝힙니다. 새 프로그램을 이 방식으로 쓸 일은 없습니다. 다만 옛 글과 옛 스크립트를 읽고 옮기려면 어떻게 생겼는지, 왜 밀려났는지는 알아야 합니다.

## 어떻게 생겼나

```sh
cd /sys/class/gpio
echo 17 > export                 # gpio17 폴더가 생긴다
echo out > gpio17/direction      # 출력으로 바꾼다
echo 1 > gpio17/value            # HIGH
cat gpio17/value                 # 지금 값을 읽는다
echo 17 > unexport               # 돌려준다
```

| 파일 | 하는 일 |
| --- | --- |
| `export`, `unexport` | 번호를 써 넣으면 그 줄의 폴더가 생기고 없어진다 |
| `gpioN/direction` | `in`이나 `out`. `low`나 `high`를 쓰면 출력으로 바꾸면서 처음 값까지 정한다 |
| `gpioN/value` | 0이나 1을 읽고 쓴다 |
| `gpioN/edge` | `none`, `rising`, `falling`, `both`. 어느 변화에 `poll`을 깨울지 고른다 |
| `gpioN/active_low` | 1을 쓰면 `value`의 뜻을 뒤집는다 |
| `gpiochipN/base`, `ngpio` | 그 칩이 맡은 번호가 `base`부터 몇 개인지 |

- **좋았던 점**: 파일을 읽고 쓸 수 있으면 어떤 언어로든 되고, 프로그램을 짜지 않고 셸에서 바로 해 볼 수 있었습니다
- **위의 명령은 따라 하지 않는다**: 생김새를 보이려고 커널 문서의 설명대로 적은 것입니다. 지금의 보드에서는 번호부터 맞지 않을 수 있습니다

## 번호가 흔들린다

sysfs는 줄을 칩과 오프셋이 아니라 시스템 전체에서 하나뿐인 번호로 가리킵니다. 그 번호는 칩마다 받는 `base`에 오프셋을 더한 값입니다. 커널 문서는 이 번호가 늘 그대로이지는 않다고 적습니다.

```c
// sysfs의 번호는 칩의 base에 오프셋을 더한 값이다. base가 바뀌면 파일 이름도 바뀐다
#include <stdio.h>

enum { LED = 17, BUTTON = 27 };              // 헤더를 맡은 칩 안의 오프셋

int main(void) {
    // 같은 보드라도 커널에 따라 칩이 받는 base가 다르다
    const int bases[] = {0, 454, 512};
    for (size_t i = 0; i < sizeof bases / sizeof bases[0]; ++i) {
        int base = bases[i];
        printf("칩의 base가 %d일 때\n", base);
        printf("  echo %d > /sys/class/gpio/export\n", base + LED);
        printf("  LED는 gpio%d/value, 단추는 gpio%d/value\n", base + LED,
               base + BUTTON);
    }
    printf("문자 장치에서는 칩 안의 번호 %d과 %d을 그대로 적는다\n", LED, BUTTON);
}
```

```text
칩의 base가 0일 때
  echo 17 > /sys/class/gpio/export
  LED는 gpio17/value, 단추는 gpio27/value
칩의 base가 454일 때
  echo 471 > /sys/class/gpio/export
  LED는 gpio471/value, 단추는 gpio481/value
칩의 base가 512일 때
  echo 529 > /sys/class/gpio/export
  LED는 gpio529/value, 단추는 gpio539/value
문자 장치에서는 칩 안의 번호 17과 27을 그대로 적는다
```

- **`base`는 커널이 정한다**: 같은 보드여도 커널이 바뀌면 달라질 수 있습니다. 커널 6.2에서 칩의 `base`를 매기는 방식이 바뀌어, 6.6으로 올린 보드에서 번호가 512부터 시작하게 되었다는 보고가 있습니다
- **454의 예**: 라즈베리파이에서 `/sys/class/gpio`에 `gpiochip454`와 `gpiochip446`이 보였다는 보고에서 가져온 값입니다. 512에서 두 칩의 줄 수인 58과 8을 차례로 뺀 숫자입니다
- **옛 글의 `echo 17`**: `base`가 0이던 환경에서 쓴 글입니다. 다른 환경에서 그대로 치면 엉뚱한 줄이거나 없는 줄입니다
- **문자 장치는 이 번호를 쓰지 않는다**: 칩을 장치 파일로 열고 그 안의 오프셋을 적습니다. 오프셋은 칩의 회로가 정하므로 커널이 바뀌어도 그대로입니다

## 임자가 없다

- **내보낸 줄은 남는다**: `export`한 줄은 `unexport`할 때까지 그대로입니다. 스크립트가 도중에 죽으면 핀은 마지막 상태로 남고, 다음에 켜진 프로그램이 그것을 물려받습니다
- **누구나 쓴다**: 파일의 권한만 있으면 어느 프로그램이든 같은 `value`에 씁니다. 두 프로그램이 한 핀을 놓고 다퉈도 막는 것이 없습니다
- **문자 장치는 파일을 닫으면 끝난다**: libgpiod의 문서는 문자 장치가 장치 파일을 닫는 순간 잡았던 것을 모두 풀어 준다는 것을 첫째 장점으로 듭니다. 요청이 곧 임자의 표시입니다([「핀 하나를 프로그램이 쥔다는 것」](#/read/libgpiod/gp-what))

## 그 밖에 못 하는 것

- **여러 줄을 한 번에**: 줄마다 파일이 따로여서 여덟 줄을 바꾸려면 여덟 번 써야 하고, 그 사이에 핀들은 어중간한 상태를 지납니다
- **변화를 놓치지 않고 받기**: `edge`를 정하고 `value`에 `poll`을 걸 수는 있지만, 깨어난 뒤에 파일을 처음부터 다시 읽어 지금 값을 볼 뿐입니다. 그 사이에 몇 번 바뀌었는지, 언제 바뀌었는지는 남지 않습니다
- **풀업과 출력 방식**: 풀업과 풀다운, 오픈 드레인, 디바운스를 정하는 파일이 없습니다
- **새 기능은 오지 않는다**: 커널 문서는 옮겨 가는 동안만 유지하고 새 기능은 문자 장치에만 넣는다고 적습니다

## 옮겨 적기

| sysfs에서 | libgpiod 2에서 |
| --- | --- |
| `export`에 번호 쓰기 | 칩을 열고 줄을 요청한다 |
| `direction`에 `out`, `in` | 줄 설정의 방향 |
| `direction`에 `low`, `high` | 방향을 출력으로 하고 처음 값을 함께 적는다 |
| `value` 읽고 쓰기 | `gpiod_line_request_get_value`, `gpiod_line_request_set_value` |
| `edge`와 `poll` | 에지 감지를 켜고 이벤트를 기다려 읽는다 |
| `active_low` | 줄 설정의 액티브 로 |
| `unexport` | 요청을 놓는다 |

- **번호를 고친다**: 스크립트의 숫자에서 그 환경의 `base`를 빼면 오프셋입니다. 헤더의 줄이라면 GPIO 번호가 곧 오프셋입니다([「핀 번호: 헤더, BCM, 줄 오프셋」](#/read/libgpiod/gp-numbering))
- **셸에서 하던 일**: `gpioset`과 `gpioget`이 `echo`와 `cat`의 자리를 맡습니다([「gpioset과 gpioget」](#/read/libgpiod/tl-set-get))
- **프로그램이 끝난 뒤의 값**: sysfs에서는 값이 남았습니다. 문자 장치에서는 요청을 놓은 뒤의 상태가 보장되지 않습니다. 라즈베리파이의 커널은 옮겨 오기 쉽도록 놓은 뒤에도 값을 남겨 두는 쪽을 기본으로 삼았습니다([「놓아주기」](#/read/libgpiod/rq-release))

<Note>
파일의 이름과 뜻, 번호가 흔들린다는 말, 없앨 예정이라는 말은 리눅스 커널 문서에서 옮겼습니다. 문서에 없애는 날짜는 없습니다. 512와 454의 예는 각각 OpenWrt 개발 목록의 글과 RPi.GPIO의 문제 보고에 나온 것이고, 내 보드의 `base`가 얼마인지는 확인하지 못했습니다. 이 기능은 커널을 만들 때 넣지 않을 수도 있어서, 보드에 `/sys/class/gpio`가 있는지부터 `ls`로 봅니다. 셸 명령은 돌려 보지 않았고, 예제는 덧셈만 합니다. x86-64와 aarch64에서 같은 출력을 냈습니다.
</Note>

## 정리

- sysfs 방식은 `/sys/class/gpio`의 파일에 써서 핀을 다루며, 커널 문서가 낡은 것으로 정하고 없앨 예정이라고 밝힌 길이다
- 번호가 칩의 `base`에 달려 있어 커널에 따라 바뀌고, 내보낸 줄에 임자가 없으며, 여러 줄과 이벤트와 풀업을 다루지 못한다
- 옮길 때에는 번호를 오프셋으로 고치고, `export`와 `value`를 요청과 값 읽고 쓰기로 바꾼다
