이 책의 코드는 libgpiod 2의 함수로 쓰여 있습니다. 1.6과는 함수의 이름부터 달라서, 판이 어긋나면 첫 줄부터 컴파일되지 않습니다. 그래서 코드를 치기 전에 할 일은 둘입니다. 꾸러미를 깔고, 깔린 것이 정말 2인지 확인합니다.

## 꾸러미

```sh
sudo apt update
sudo apt install libgpiod-dev gpiod
```

| 꾸러미 | 든 것 | 필요한 곳 |
| --- | --- | --- |
| `libgpiod-dev` | `gpiod.h`와 링크에 쓰는 파일 | 컴파일하는 기기 |
| `libgpiod3` | 공유 라이브러리 `libgpiod.so.3` | 프로그램을 돌리는 모든 기기 |
| `gpiod` | 명령줄 도구 여섯 | 살펴보고 시험할 때 |
| `python3-libgpiod` | 파이썬 바인딩 | 파이썬으로 쓸 때 |

- **`libgpiod3`은 따라 깔린다**: `libgpiod-dev`를 깔면 함께 들어옵니다. 빌드한 프로그램만 옮겨 돌릴 기기에는 `libgpiod3` 하나면 됩니다
- **이름의 3은 판이 아니다**: 공유 라이브러리의 번호입니다. libgpiod 1.6의 꾸러미가 `libgpiod2`이고 2.x의 꾸러미가 `libgpiod3`입니다. 한 칸씩 어긋나 있어서 `libgpiod2`를 보고 2가 깔렸다고 여기기 쉽습니다
- **도구는 따로다**: `gpiod` 꾸러미가 없어도 프로그램은 빌드되고 돕니다. 도구는 [「gpiodetect와 gpioinfo」](#/read/libgpiod/tl-detect)부터 네 쪽에서 다뤘습니다

## 판 확인하기

```sh
pkg-config --modversion libgpiod    # 머리 파일과 링크용 파일의 판
gpiodetect --version                # 도구의 판
uname -r                            # 커널의 판
```

| 배포판 | libgpiod |
| --- | --- |
| 데비안 12(북웜) | 1.6.3 |
| 북웜의 백포트 | 2.1.3 |
| 데비안 13(트릭시) | 2.2.1 |

- **첫 명령이 2로 시작하면 된다**: 트릭시라면 `2.2.1`이 나옵니다. `1.6.3`이 나오면 아래의 「1.6뿐일 때」로 갑니다
- **라즈베리파이 OS**: 데비안의 꾸러미를 물려받습니다. 지금 판은 트릭시, Legacy는 북웜에 바탕을 둡니다([「Raspberry Pi OS, 우분투, 그 밖의 배포판」](#/read/sbc-start/os-choices))
- **커널은 5.10 이상**: libgpiod 2는 문자 장치의 v2 인터페이스만 씁니다([「문자 장치와 uAPI v2」](#/read/libgpiod/hs-chardev)). 트릭시와 북웜의 커널은 모두 그보다 새것입니다
- **2.x 안에서는**: 공유 라이브러리의 번호가 3으로 같고, 판이 오르며 함수가 더해질 뿐입니다. 2.1에서 `gpiod_line_request_get_chip_name`이 들어왔습니다

## 프로그램 안에서 확인하기

`pkg-config`가 알려 주는 것은 빌드할 때 쓰는 파일의 판입니다. 돌 때 물리는 라이브러리의 판은 프로그램이 직접 물어볼 수 있습니다.

```c gpiosim
// 프로그램에 물린 libgpiod의 판을 찍고, 헤더의 칩이 열리는지 확인한다
#include <gpiod.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    const char* version = gpiod_api_version();
    printf("libgpiod %s\n", version);
    if (atoi(version) < 2) {
        printf("이 책의 코드는 2.x에 맞춰 쓰였다\n");
        return 1;
    }
    const char* path = "/dev/gpiochip0";
    if (!gpiod_is_gpiochip_device(path)) {
        printf("%s: GPIO 칩의 장치 파일이 아니다\n", path);
        return 1;
    }
    struct gpiod_chip* chip = gpiod_chip_open(path);
    if (!chip) {
        perror(path);
        return 1;
    }
    struct gpiod_chip_info* info = gpiod_chip_get_info(chip);
    if (info) {
        printf("%s [%s] 줄 %zu개\n", gpiod_chip_info_get_name(info),
               gpiod_chip_info_get_label(info),
               gpiod_chip_info_get_num_lines(info));
        gpiod_chip_info_free(info);
    }
    gpiod_chip_close(chip);
    printf("준비가 됐다\n");
}
```

```text
libgpiod 2.2.1
gpiochip0 [pinctrl-bcm2711] 줄 58개
준비가 됐다
```

- **`gpiod_api_version`**: 지금 물려 있는 라이브러리의 판을 글자열로 돌려줍니다. 풀어 줄 필요가 없는 글자열입니다
- **`gpiod_is_gpiochip_device`**: 그 경로가 GPIO 칩의 장치 파일인지 봅니다. 칩을 열기 전에 길을 잘못 적었는지 가려 줍니다
- **빌드한 곳과 도는 곳이 다를 때**: 2로 빌드한 프로그램을 `libgpiod3`이 없는 기기에 옮기면 `libgpiod.so.3`을 찾지 못해 시작도 하지 못합니다. 그 기기에 `libgpiod3`을 깝니다
- **5에서도 같은 프로그램**: 둘째 줄만 `gpiochip0 [pinctrl-rp1] 줄 54개`로 바뀝니다

## 1.6뿐일 때

- **OS를 올린다**: 가장 깔끔한 길입니다. 세대를 넘는 판올림은 카드에 새로 설치합니다
- **백포트**: 데비안 12에는 2.1.3이 백포트로 올라와 있습니다. 백포트 저장소를 켠 뒤 `sudo apt install -t bookworm-backports libgpiod-dev gpiod`로 깝니다
- **소스에서 빌드한다**: 아래의 차례입니다. `/usr/local` 아래에 깔리므로 꾸러미로 깐 것과 섞이지 않습니다

```sh
sudo apt install autoconf automake autoconf-archive libtool pkg-config
git clone https://git.kernel.org/pub/scm/libs/libgpiod/libgpiod.git
cd libgpiod
git checkout v2.2.4
./autogen.sh --enable-tools=yes --prefix=/usr/local
make
sudo make install
sudo ldconfig
```

- **1.6의 `libgpiod-dev`는 지운다**: 머리 파일의 이름이 둘 다 `gpiod.h`입니다. 남겨 두면 어느 쪽이 잡히는지가 찾는 차례에 달리게 됩니다. `sudo apt remove libgpiod-dev`로 지우고 다음 쪽의 `pkg-config`로 빌드합니다
- **도구도 새로 생긴다**: `/usr/local/bin`에 2의 도구가 깔립니다. `which gpiodetect`로 어느 것이 잡히는지 봅니다

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, 판을 2.2.1로 답하게 해 두었습니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지만 따로 확인했습니다. 배포판마다의 판은 데비안의 꾸러미 목록에서, 빌드하는 차례와 필요한 도구는 libgpiod의 빌드 문서에서 옮겼습니다. 라즈베리파이 OS에 실제로 어느 판이 들어 있는지와 소스에서 빌드하는 과정은 직접 해 보지 못했습니다. 내 보드에서는 `pkg-config --modversion libgpiod`의 답을 믿습니다.
</Note>

## 정리

- `libgpiod-dev`와 `gpiod`를 깔고 `pkg-config --modversion libgpiod`가 2로 시작하는지 본다
- 꾸러미 `libgpiod3`이 libgpiod 2.x이고 `libgpiod2`는 1.6이다. 프로그램을 돌릴 기기에는 `libgpiod3`이 있어야 한다
- 1.6뿐이면 OS를 올리거나, 백포트를 쓰거나, 소스에서 빌드한다
