sysfs의 뒤를 이은 것이 GPIO 문자 장치입니다. 칩마다 `/dev/gpiochipN`이라는 장치 파일이 하나씩 있고, 프로그램은 그 파일에 `ioctl`을 불러 줄을 요청합니다. 커널과 프로그램 사이의 이 약속을 uAPI라고 부릅니다. libgpiod는 그 `ioctl`들을 감싼 라이브러리입니다. 이 쪽은 라이브러리의 밑바닥을 한 번 들여다봅니다. 함수가 왜 그렇게 생겼는지, 오류가 어디서 올라오는지를 아는 데 쓰입니다.

## 두 번의 판

| 견줄 것 | v1 | v2 |
| --- | --- | --- |
| 들어온 커널 | 4.8 | 5.10 |
| 줄을 얻는 길 | 값을 다루는 것과 이벤트를 받는 것이 따로 | 줄 요청 하나로 둘 다 |
| 이벤트 | 요청 하나에 줄 하나 | 요청 하나에 여러 줄 |
| 줄마다 다른 설정 | 함께 얻은 줄은 모두 같은 설정 | 줄마다 달리 줄 수 있다 |

- **v2는 v1을 다 품는다**: 커널 문서는 v1으로 하던 일이 모두 v2의 것으로 그대로 옮겨진다고 적습니다
- **v1도 낡은 것이 되었다**: 문서는 v1을 옮겨 가는 동안만 유지하고 앞으로 없앤다고 적습니다. 날짜는 없습니다
- **v2에서 생긴 것**: 디바운스, 이벤트의 순번, 이벤트에 찍는 시계를 고르는 설정입니다. 이 책의 에지 이벤트 장이 다루는 것들입니다
- **libgpiod의 판과 짝**: libgpiod 2는 v2가 있어야 돕니다. 그래서 커널이 5.10보다 옛것이면 쓸 수 없습니다. 지금의 Raspberry Pi OS는 이 조건을 넘습니다

## v2가 주고받는 것

물건은 둘입니다. 칩의 파일과, 줄을 요청하면 커널이 새로 내주는 요청의 파일입니다.

| 파일 | 할 수 있는 일 |
| --- | --- |
| 칩 | 칩 정보 읽기, 줄 정보 읽기, 줄 정보가 바뀌는지 지켜보기, 줄 요청하기 |
| 요청 | 값 읽기, 값 쓰기, 설정 바꾸기, 에지 이벤트 읽기 |

주고받는 구조체와 한도는 커널의 머리 파일 `linux/gpio.h`에 적혀 있습니다.

```c
// uAPI v2의 머리 파일에 적힌 한도와, 커널과 주고받는 구조체의 크기
#include <linux/gpio.h>
#include <stdio.h>

int main(void) {
    printf("줄 이름과 소비자 이름의 칸  %d바이트\n", GPIO_MAX_NAME_SIZE);
    printf("요청 하나에 담는 줄         %d개까지\n", GPIO_V2_LINES_MAX);
    printf("줄마다 달리 주는 속성       %d가지까지\n", GPIO_V2_LINE_NUM_ATTRS_MAX);
    printf("줄 요청      %zu바이트\n", sizeof(struct gpio_v2_line_request));
    printf("줄 정보      %zu바이트\n", sizeof(struct gpio_v2_line_info));
    printf("에지 이벤트  %zu바이트\n", sizeof(struct gpio_v2_line_event));
}
```

```text
줄 이름과 소비자 이름의 칸  32바이트
요청 하나에 담는 줄         64개까지
줄마다 달리 주는 속성       10가지까지
줄 요청      592바이트
줄 정보      256바이트
에지 이벤트  48바이트
```

- **32바이트**: 끝을 알리는 0을 빼면 31글자입니다. 소비자 이름을 이보다 길게 주면 잘립니다([「소비자 이름」](#/read/libgpiod/rq-consumer))
- **64줄**: 요청 하나가 묶을 수 있는 줄의 수입니다. 더 많은 줄은 요청을 나눕니다
- **속성 10가지**: 요청의 줄들에 서로 다른 설정을 줄 수 있는 갈래의 수입니다. 줄마다 설정을 제각각으로 주면 이 한도에 걸립니다
- **에지 이벤트 48바이트**: 이벤트 하나에 시각, 종류, 줄의 오프셋, 순번 둘이 들어 있습니다([「기다리고 읽기」](#/read/libgpiod/ed-wait))

## 날것으로 부르면

아래는 libgpiod 없이 같은 일을 하는 프로그램입니다. GPIO 17을 출력으로 요청해 1초 동안 켭니다.

```c norun
// libgpiod 없이 uAPI v2를 직접 부른다: GPIO 17을 출력으로 요청해 1초 동안 켠다
#define _POSIX_C_SOURCE 200809L
#include <fcntl.h>
#include <linux/gpio.h>
#include <stdio.h>
#include <sys/ioctl.h>
#include <unistd.h>

int main(void) {
    int chip_fd = open("/dev/gpiochip0", O_RDWR | O_CLOEXEC);
    if (chip_fd < 0) {
        perror("/dev/gpiochip0");
        return 1;
    }

    // 줄 요청: 어느 줄을, 어떤 성질로, 누가
    struct gpio_v2_line_request request = {
        .offsets = {17},
        .num_lines = 1,
        .consumer = "raw-blink",
        .config = {.flags = GPIO_V2_LINE_FLAG_OUTPUT},
    };
    if (ioctl(chip_fd, GPIO_V2_GET_LINE_IOCTL, &request) < 0) {
        perror("GPIO_V2_GET_LINE_IOCTL");
        return 1;
    }
    close(chip_fd);                          // 칩은 닫아도 요청은 산다

    // 값: mask의 0번 비트가 요청의 첫 줄을 고르고, bits의 같은 비트가 값이다
    struct gpio_v2_line_values values = {.bits = 1, .mask = 1};
    if (ioctl(request.fd, GPIO_V2_LINE_SET_VALUES_IOCTL, &values) < 0)
        perror("GPIO_V2_LINE_SET_VALUES_IOCTL");
    sleep(1);
    values.bits = 0;
    ioctl(request.fd, GPIO_V2_LINE_SET_VALUES_IOCTL, &values);

    close(request.fd);                       // 요청의 파일을 닫으면 줄을 놓는다
}
```

| 날것 | libgpiod 2 |
| --- | --- |
| `open`으로 칩의 파일 열기 | `gpiod_chip_open` |
| 구조체에 오프셋, 플래그, 이름 채우기 | 줄 설정, 줄 구성, 요청 구성의 세 객체 |
| `GPIO_V2_GET_LINE_IOCTL` | `gpiod_chip_request_lines` |
| `GPIO_V2_LINE_SET_VALUES_IOCTL` | `gpiod_line_request_set_value` |
| 요청의 파일을 `close` | `gpiod_line_request_release` |

- **값은 비트로 간다**: `mask`와 `bits`의 n번 비트가 요청의 n번째 줄입니다. 오프셋이 아니라 요청에 적은 차례입니다. 라이브러리는 오프셋을 받아 이 차례로 바꿔 줍니다
- **칩을 닫아도 된다**: 요청의 파일은 칩의 파일과 따로 삽니다. 커널 문서도 칩의 파일을 닫는 것이 이미 얻은 요청에 아무 영향이 없다고 적습니다
- **놓는다는 것**: 요청의 파일을 닫는 것이 줄을 놓는 것입니다. 프로그램이 죽으면 커널이 파일을 닫으므로 줄도 놓입니다
- **라이브러리를 쓰는 까닭**: 줄이 여럿이고 설정이 줄마다 다르면 비트와 속성의 배열을 손으로 채워야 합니다. 그 일을 대신해 주고, 도구와 다른 언어의 바인딩이 함께 옵니다. 커널 문서도 짜임새 있는 프로그램에는 libgpiod를 권합니다

<Note>
두 판의 차이와 할 수 있는 일의 목록은 리눅스 커널 문서에서, libgpiod 2가 v2를 요구한다는 것은 libgpiod의 README에서 옮겼습니다. 첫 예제는 검사 환경의 커널 머리 파일(6.8)로 x86-64와 aarch64에서 돌렸고 출력이 같았습니다. 둘째 예제는 두 아키텍처에서 경고 없이 컴파일되고 링크되는 것까지만 확인했습니다. 검사 환경에는 GPIO 칩이 없어서 돌리면 `/dev/gpiochip0`을 열지 못하고 끝납니다. 이 책의 나머지 예제는 `ioctl`을 직접 부르지 않고 libgpiod로 씁니다.
</Note>

## 정리

- GPIO 문자 장치의 uAPI는 4.8의 v1과 5.10의 v2가 있고, libgpiod 2는 v2 위에 서 있다
- v2는 칩의 파일에서 줄을 요청하고, 돌려받은 요청의 파일로 값을 읽고 쓰고 이벤트를 받는다
- 요청 하나에는 64줄까지, 이름은 31글자까지이고, 요청의 파일을 닫는 것이 줄을 놓는 것이다
