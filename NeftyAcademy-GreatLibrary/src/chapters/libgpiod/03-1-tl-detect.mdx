코드를 한 줄도 쓰기 전에 셸에서 칩을 찾고, 줄을 살피고, 핀을 켜고 읽어 볼 수 있습니다. libgpiod에는 그런 도구가 여섯 개 딸려 옵니다. 배선이 맞는지, 그 줄을 누가 쓰고 있는지, 단추가 정말 신호를 내는지를 프로그램 없이 확인할 수 있어서, 회로를 꾸민 뒤 가장 먼저 꺼내는 것이 이 도구들입니다. 이 쪽은 살펴보기만 하는 둘을 다룹니다.

## 도구 여섯 가지

| 도구 | 하는 일 | 다루는 쪽 |
| --- | --- | --- |
| `gpiodetect` | 칩의 목록을 보여 준다 | 이 쪽 |
| `gpioinfo` | 줄의 이름과 방향, 쥐고 있는 프로그램을 보여 준다 | 이 쪽 |
| `gpioget` | 줄의 값을 읽는다 | [「gpioset과 gpioget」](#/read/libgpiod/tl-set-get) |
| `gpioset` | 줄에 값을 내고 붙들고 있는다 | [「gpioset과 gpioget」](#/read/libgpiod/tl-set-get) |
| `gpiomon` | 에지를 기다렸다가 찍는다 | [「gpiomon」](#/read/libgpiod/tl-mon) |
| `gpionotify` | 줄이 쥐이고 놓이는 것을 지켜본다 | [「gpiomon」](#/read/libgpiod/tl-mon) |

- **꾸러미의 이름은 `gpiod`**: 없으면 `sudo apt install gpiod`로 깝니다. 라이브러리와는 다른 꾸러미입니다([「libgpiod 2.x 설치와 버전 확인」](#/read/libgpiod/st-install))
- **판이 둘이다**: 데비안 12(북웜)의 꾸러미는 1.6.3이고 13(트릭시)의 것은 2.2.1입니다. 문법이 다르므로 `gpiodetect --version`으로 내 것을 봅니다. 이 장은 2의 문법으로 적고, 1.6의 것은 쪽 끝의 표에 둡니다
- **도구도 libgpiod로 짠 프로그램이다**: 도구로 되는 일은 내 프로그램으로도 되고, 도구에서 나는 오류는 내 프로그램에서도 납니다

## gpiodetect: 칩 찾기

```sh
gpiodetect            # 모든 칩
gpiodetect 0          # 칩 하나만. gpiochip0이나 /dev/gpiochip0이라고 적어도 된다
```

```text
gpiochip0 [pinctrl-bcm2711] (58 lines)
gpiochip1 [raspberrypi-exp-gpio] (8 lines)
```

- **한 줄이 칩 하나**: 칩의 이름, 대괄호 안의 이름표, 줄의 수입니다. 위는 4의 출력입니다
- **헤더의 칩을 고르는 눈**: 이름표가 `pinctrl-`로 시작하는 칩입니다. 번호를 믿기 어려운 까닭은 [「라즈베리파이 5에서 깨진 것들」](#/read/libgpiod/hs-pi5)에서 봤습니다

## gpioinfo: 줄 살피기

```sh
gpioinfo                  # 모든 칩의 모든 줄
gpioinfo -c 0             # gpiochip0의 줄만
gpioinfo GPIO17 GPIO27    # 그 이름의 줄만
gpioinfo -c 0 17 27       # 칩을 정했으면 오프셋으로도 고른다
```

```text
gpiochip0 17 "GPIO17"         input
gpiochip0 27 "GPIO27"         input
```

- **칩을 적지 않으면 인수는 이름이다**: 칩을 번호 차례로 뒤져 그 이름을 처음 만난 줄을 보여 줍니다. 위가 셋째 명령의 출력 꼴이고, 맨 앞의 둘이 칩과 오프셋입니다
- **`-c`로 칩을 정하면**: 숫자로 읽히는 인수는 오프셋입니다. 숫자처럼 생긴 이름을 찾으려면 `--by-name`을, 이름이 겹칠 수 있는 보드에서는 끝까지 뒤지도록 `--strict`를 붙입니다
- **이름은 보드마다 다르다**: 4에서 `GPIO4`를 찾으면 `cannot find line 'GPIO4'`가 나옵니다. 4의 그 줄은 `GPIO_GCLK`입니다([「핀 번호: 헤더, BCM, 줄 오프셋」](#/read/libgpiod/gp-numbering))

## 한 줄을 읽는 법

`gpioinfo`가 줄마다 적는 것은 커널이 그 줄에 대해 알려 주는 정보입니다. 아래 예제는 줄 몇 개를 서로 다른 설정으로 쥐어 놓고, 그 정보를 `gpioinfo`와 같은 차례로 찍습니다.

```c gpiosim=quiet
// gpioinfo가 줄마다 적는 것을 libgpiod로 만들어 본다
#include <gpiod.h>
#include <stdio.h>

// 값마다의 낱말. 적지 않은 칸은 nullptr이고, 그런 값은 찍지 않는다
static const char* const bias_word[] = {
    [GPIOD_LINE_BIAS_PULL_UP] = "pull-up",
    [GPIOD_LINE_BIAS_PULL_DOWN] = "pull-down",
    [GPIOD_LINE_BIAS_DISABLED] = "disabled",
};
static const char* const edge_word[] = {
    [GPIOD_LINE_EDGE_RISING] = "rising",
    [GPIOD_LINE_EDGE_FALLING] = "falling",
    [GPIOD_LINE_EDGE_BOTH] = "both",
};

// 줄 하나를 gpioinfo와 같은 차례로 찍는다
static void show(struct gpiod_chip* chip, unsigned int offset) {
    struct gpiod_line_info* info = gpiod_chip_get_line_info(chip, offset);
    if (!info) return;
    char name[40] = "unnamed";
    if (gpiod_line_info_get_name(info))
        snprintf(name, sizeof name, "\"%s\"", gpiod_line_info_get_name(info));
    bool out = gpiod_line_info_get_direction(info) == GPIOD_LINE_DIRECTION_OUTPUT;
    printf("line %3u: %-16s %s", offset, name, out ? "output" : "input");
    if (gpiod_line_info_is_active_low(info)) printf(" active-low");
    const char* word = bias_word[gpiod_line_info_get_bias(info)];
    if (word) printf(" bias=%s", word);
    word = edge_word[gpiod_line_info_get_edge_detection(info)];
    if (word) printf(" edges=%s", word);
    unsigned long us = gpiod_line_info_get_debounce_period_us(info);
    if (us) printf(" debounce-period=%lums", us / 1000);
    if (gpiod_line_info_is_used(info)) {
        const char* who = gpiod_line_info_get_consumer(info);
        printf(" consumer=\"%s\"", who ? who : "kernel");
    }
    putchar('\n');
    gpiod_line_info_free(info);
}

// 줄 하나를 그 설정과 소비자 이름으로 쥔다
static struct gpiod_line_request* hold(struct gpiod_chip* chip, unsigned int offset,
                                       struct gpiod_line_settings* settings,
                                       const char* who) {
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    struct gpiod_line_request* request = nullptr;
    if (config && request_config &&
        gpiod_line_config_add_line_settings(config, &offset, 1, settings) == 0) {
        gpiod_request_config_set_consumer(request_config, who);
        request = gpiod_chip_request_lines(chip, request_config, config);
    }
    if (!request) perror(who);
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    struct gpiod_line_settings* st = gpiod_line_settings_new();
    if (!chip || !st) {
        perror("준비");
        return 1;
    }
    // 앞서 돈 프로그램이 GPIO 23을 출력으로 쓰고 끝난 뒤라고 치자
    gpiod_line_settings_set_direction(st, GPIOD_LINE_DIRECTION_OUTPUT);
    gpiod_line_request_release(hold(chip, 23, st, "earlier"));

    // 등: GPIO 17을 출력으로 쥔다
    struct gpiod_line_request* lamp = hold(chip, 17, st, "lamp");

    // 움직임 감지기: GPIO 26의 올라가는 에지를 디바운스 10ms로 기다린다
    gpiod_line_settings_reset(st);
    gpiod_line_settings_set_edge_detection(st, GPIOD_LINE_EDGE_RISING);
    gpiod_line_settings_set_debounce_period_us(st, 10'000);
    struct gpiod_line_request* pir = hold(chip, 26, st, "pir");

    // 단추: GPIO 27을 풀업 입력, 액티브 로로 쥐고 양쪽 에지를 본다
    gpiod_line_settings_reset(st);
    gpiod_line_settings_set_bias(st, GPIOD_LINE_BIAS_PULL_UP);
    gpiod_line_settings_set_active_low(st, true);
    gpiod_line_settings_set_edge_detection(st, GPIOD_LINE_EDGE_BOTH);
    struct gpiod_line_request* button = hold(chip, 27, st, "btn");

    const unsigned int look[] = {17, 23, 24, 26, 27, 42};
    for (size_t i = 0; i < sizeof look / sizeof look[0]; ++i) show(chip, look[i]);

    gpiod_line_request_release(button);
    gpiod_line_request_release(pir);
    gpiod_line_request_release(lamp);
    gpiod_line_settings_free(st);
    gpiod_chip_close(chip);
}
```

```text
line  17: "GPIO17"         output consumer="lamp"
line  23: "GPIO23"         output
line  24: "GPIO24"         input
line  26: "GPIO26"         input edges=rising debounce-period=10ms consumer="pir"
line  27: "GPIO27"         input active-low bias=pull-up edges=both consumer="btn"
line  42: "STATUS_LED_G_CLK" output consumer="led0"
```

- **방향은 언제나 적힌다**: `input`이나 `output`입니다. 쥔 프로그램이 없어도 적힙니다
- **`consumer`는 쥐고 있다는 표시**: 그 줄을 쥔 프로그램이 적어 낸 이름입니다. 이 낱말이 보이는 줄은 다른 프로그램이 요청할 수 없습니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy)). 쓰이고 있는데 이름이 비어 있으면 도구가 `kernel`이라고 적습니다
- **나머지 낱말은 쥔 쪽이 건 설정**: `active-low`, `bias=`, `edges=`, `debounce-period=`은 요청할 때 정한 것이고, 줄을 놓으면 커널이 지웁니다. 내 프로그램이 뜻한 대로 요청했는지를 다른 터미널에서 확인하는 데 씁니다
- **`bias`가 없다고 풀이 없는 것이 아니다**: 24번은 아무 낱말도 없지만 보드가 켤 때 걸어 둔 풀다운이 있습니다. 여기 적히는 것은 요청에 실린 설정뿐이고, 핀에 실제로 걸린 풀은 [「pinctrl」](#/read/libgpiod/tl-pinctrl)로 봅니다
- **임자 없는 `output`**: 23번은 앞서 돈 프로그램이 출력으로 쓰다가 놓은 줄입니다. 라즈베리파이의 커널은 놓은 줄의 상태를 그대로 두므로 핀은 아직 값을 내고 있습니다([「놓아주기」](#/read/libgpiod/rq-release))
- **커널이 쥔 줄**: 42번은 보드의 초록 LED로 가는 줄이고 커널의 LED 드라이버가 쥐고 있습니다. `led0`은 문서의 예에 나온 이름이라 커널에 따라 다를 수 있습니다
- **진짜 도구와 다른 점**: `gpioinfo -c 0`은 맨 위에 `gpiochip0 - 58 lines:`를 적고 58줄을 모두 찍으며, 칸을 탭으로 띄웁니다. 오픈 드레인으로 쥔 줄에는 `drive=open-drain`도 적습니다

## 1.6의 문법

| 하려는 일 | 2 | 1.6 |
| --- | --- | --- |
| 칩 하나의 줄 보기 | `gpioinfo -c gpiochip0` | `gpioinfo gpiochip0` |
| 이름으로 줄 찾기 | `gpioinfo GPIO17` | `gpiofind GPIO17` |
| 줄 몇 개만 보기 | `gpioinfo -c 0 17 27` | 없다. `grep`으로 거른다 |
| 칩 하나만 보기 | `gpiodetect 0` | 없다 |

- **`gpiofind`**: 1.6에만 있습니다. `gpiochip0 17`처럼 칩과 오프셋을 찍습니다. 2에서는 `gpioinfo`가 그 일을 합니다
- **출력의 낱말도 다르다**: 1.6의 `gpioinfo`는 쥔 이가 없는 줄에 `unused`를, 액티브 로가 아닌 줄에 `active-high`를 적습니다

<Note>
예제의 출력은 진짜 `gpioinfo`의 것이 아닙니다. 같은 차례로 찍도록 짠 프로그램을 이 책의 흉내 칩(4의 줄 이름을 넣은 것)에서 돌린 것이고, 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지만 따로 확인했습니다. 도구의 옵션과 출력 꼴은 2.2.4의 도구 소스와 문서를 읽어 적었고, 1.6.3의 것은 그 판의 도구를 `--help`로 돌려 보고 적었습니다. `gpiodetect`의 출력과 42번 줄의 `led0`은 libgpiod 문서에 실린 4 Model B의 예에서 왔습니다. 어느 것도 보드에서 돌려 보지는 못했습니다.
</Note>

## 정리

- 칩은 `gpiodetect`로 찾고 이름표로 고르며, 줄은 `gpioinfo`로 살핀다. 2의 도구는 줄을 이름으로 찾는다
- `gpioinfo`의 한 줄은 방향, 쥔 쪽이 건 설정, `consumer`의 차례다. `consumer`가 있으면 그 줄은 요청할 수 없다
- 적히는 설정은 요청에 실린 것뿐이다. 핀에 걸린 풀과 기능은 여기에 나오지 않는다
