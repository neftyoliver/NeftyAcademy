줄을 요청하려면 세 가지를 정해야 합니다. 줄이 어떻게 굴지, 어느 줄이 그렇게 굴지, 요청에 무엇을 붙일지입니다. libgpiod 2는 이 셋을 서로 다른 객체에 담아 넘기게 합니다. LED 하나를 켜는 데에는 번거로워 보이지만, 성질이 다른 줄 여럿을 요청 하나로 쥘 수 있는 것이 이 구조 덕분입니다.

## 객체 셋

| 객체 | 담는 것 | 만드는 함수 |
| --- | --- | --- |
| `gpiod_line_settings` | 줄 하나의 성질. 방향, 바이어스, 에지 같은 것 | `gpiod_line_settings_new` |
| `gpiod_line_config` | 어느 오프셋에 어느 성질을 줄지 | `gpiod_line_config_new` |
| `gpiod_request_config` | 요청에 붙는 것. 소비자 이름과 이벤트 버퍼의 크기 | `gpiod_request_config_new` |

셋을 `gpiod_chip_request_lines`에 넘기면 요청 객체 하나가 돌아옵니다. 그 뒤로 값을 읽고 쓰는 일은 모두 그 요청 객체로 합니다.

## 꾸미는 차례

```c gpiosim=quiet
// 설정 객체 셋으로 요청 하나를 꾸민다: 등 둘은 출력, 단추 하나는 풀업 입력
#include <gpiod.h>
#include <stdio.h>

enum { RED = 17, GREEN = 22, BUTTON = 27 };  // 헤더의 핀 11, 15, 13

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    struct gpiod_line_settings* settings = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_request_config* request_config = gpiod_request_config_new();
    if (!chip || !settings || !config || !request_config) {
        perror("준비");
        return 1;
    }
    // 1. 줄이 어떻게 굴지는 settings에, 어느 줄이 그럴지는 config에 적는다
    const unsigned int leds[] = {RED, GREEN};
    gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_OUTPUT);
    gpiod_line_config_add_line_settings(config, leds, 2, settings);

    // 2. config가 설정을 베껴 갔으므로 같은 settings를 고쳐 다음 줄에 쓴다
    const unsigned int button = BUTTON;
    gpiod_line_settings_reset(settings);
    gpiod_line_settings_set_direction(settings, GPIOD_LINE_DIRECTION_INPUT);
    gpiod_line_settings_set_bias(settings, GPIOD_LINE_BIAS_PULL_UP);
    gpiod_line_config_add_line_settings(config, &button, 1, settings);

    // 3. 요청 자체에 대한 것은 request_config에 적는다
    gpiod_request_config_set_consumer(request_config, "panel");

    // config에 무엇이 담겼는지 꺼내 본다
    unsigned int offsets[8];
    size_t n = gpiod_line_config_get_configured_offsets(config, offsets, 8);
    for (size_t i = 0; i < n; ++i) {
        struct gpiod_line_settings* s =
            gpiod_line_config_get_line_settings(config, offsets[i]);
        if (!s) continue;
        bool out =
            gpiod_line_settings_get_direction(s) == GPIOD_LINE_DIRECTION_OUTPUT;
        bool up = gpiod_line_settings_get_bias(s) == GPIOD_LINE_BIAS_PULL_UP;
        printf("config  %2u  %s%s\n", offsets[i], out ? "output" : "input",
               up ? " pull-up" : "");
        gpiod_line_settings_free(s);
    }

    // 4. 셋을 칩에 넘겨 요청을 받는다. 받은 뒤에는 셋 다 필요 없다
    struct gpiod_line_request* request =
        gpiod_chip_request_lines(chip, request_config, config);
    gpiod_request_config_free(request_config);
    gpiod_line_config_free(config);
    gpiod_line_settings_free(settings);
    if (!request) {
        perror("요청");
        gpiod_chip_close(chip);
        return 1;
    }
    printf("request 줄 %zu개, 칩 %s\n",
           gpiod_line_request_get_num_requested_lines(request),
           gpiod_line_request_get_chip_name(request));
    gpiod_line_request_release(request);
    gpiod_chip_close(chip);
}
```

```text
config  17  output
config  22  output
config  27  input pull-up
request 줄 3개, 칩 gpiochip0
```

- **1. 성질을 적고 줄에 붙인다**: `gpiod_line_config_add_line_settings`에 오프셋의 배열과 개수, settings를 넘깁니다. 같은 성질의 줄은 한 번에 붙입니다
- **2. config는 설정을 베껴 간다**: 붙인 뒤에 settings를 고쳐도 앞서 붙인 줄에는 닿지 않습니다. 그래서 settings 하나를 `gpiod_line_settings_reset`으로 비워 가며 돌려씁니다. 출력의 첫 두 줄이 `output`으로 남아 있는 것이 그 증거입니다
- **3. 요청에 붙일 것**: 소비자 이름은 다른 프로그램이 이 줄을 살필 때 보는 이름입니다([「소비자 이름」](#/read/libgpiod/rq-consumer)). `request_config` 자리에는 `nullptr`를 넘겨도 됩니다
- **4. 요청을 받으면 셋은 풀어 준다**: 요청 객체는 셋 가운데 어느 것도 붙들고 있지 않습니다
- **붙인 차례가 줄의 차례다**: 요청 안에서 줄은 config에 붙인 차례대로 놓입니다. 값을 한꺼번에 읽고 쓸 때 이 차례를 따릅니다([「여러 줄 한꺼번에 쓰기」](#/read/libgpiod/out-multi))
- **같은 오프셋을 두 번 붙이면**: 나중 것이 이깁니다. 자리는 처음 붙인 자리 그대로입니다
- **한 요청에 64줄까지**: 넘게 붙이면 `E2BIG`으로 실패합니다

## settings의 기본값

| 성질 | 기본값 | 자세히 다루는 쪽 |
| --- | --- | --- |
| 방향 | 그대로 둠 | [「LED 켜기」](#/read/libgpiod/out-led), [「값 읽기」](#/read/libgpiod/in-read) |
| 출력의 첫 값 | inactive | [「LED 켜기」](#/read/libgpiod/out-led) |
| 액티브 로 | 꺼짐 | [「액티브 로」](#/read/libgpiod/out-active-low) |
| 드라이브 | 푸시풀 | [「푸시풀, 오픈 드레인, 오픈 소스」](#/read/libgpiod/out-drive) |
| 바이어스 | 그대로 둠 | [「바이어스 설정」](#/read/libgpiod/in-bias) |
| 에지 감지 | 없음 | [「에지 감지 켜기」](#/read/libgpiod/ed-request) |
| 디바운스 | 0 | [「디바운스」](#/read/libgpiod/ed-debounce) |
| 이벤트의 시계 | 단조 시계 | [「타임스탬프와 시계 고르기」](#/read/libgpiod/ed-timestamp) |

- **방향의 기본은 그대로 두는 것이다**: 아무것도 적지 않은 settings로 요청하면 줄을 쥐기만 하고 방향을 건드리지 않습니다. 출력으로 쓸 줄에는 방향을 꼭 적습니다
- **함수의 이름은 한 꼴이다**: 바꾸는 함수는 `gpiod_line_settings_set_direction`처럼 `set_` 뒤에 성질의 이름이 오고, 읽는 함수는 `get_`으로 시작합니다
- **바꾸는 함수는 값이 틀렸을 때만 실패한다**: 없는 값을 넘기면 -1을 돌려주고 그 성질을 기본값으로 둡니다. 문서는 이 반환값을 살피지 않아도 된다고 적습니다
- **서로 안 맞는 조합은 여기서 걸리지 않는다**: 출력이면서 에지를 감지하라는 식의 설정도 settings에는 적힙니다. 거절은 요청할 때 커널이 합니다([「gpiod_chip_request_lines」](#/read/libgpiod/rq-request))

## 셋으로 나눈 까닭

- **성질이 다른 줄을 한 요청에**: 예제처럼 등과 단추를 함께 쥘 수 있습니다. 한 요청의 줄들은 값을 같은 순간에 읽고 쓰고, 함께 놓입니다
- **쥔 채로 바꾸기**: 요청을 놓지 않고 설정을 바꿀 때에도 config를 새로 꾸며 넘깁니다([「도중에 바꾸기」](#/read/libgpiod/reconfigure))
- **1.6의 한 줄이 길어졌다**: 1.6에서는 `gpiod_line_request_output` 하나로 끝나던 일입니다. 2에서는 줄 하나짜리 요청을 감싼 작은 함수를 만들어 두고 쓰는 것이 보통이고, 이 책의 예제들도 그렇게 합니다

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했습니다. 기본값, config가 설정을 베낀다는 것, 64줄의 한도는 2.2.4의 소스에서 읽었고 흉내 칩이 같게 굴도록 했습니다. 보드에서 돌려 보지는 못했습니다.
</Note>

## 정리

- 줄의 성질은 `gpiod_line_settings`에, 어느 줄에 줄지는 `gpiod_line_config`에, 요청에 붙일 것은 `gpiod_request_config`에 담는다
- config는 settings를 베껴 가므로 settings 하나를 돌려쓰고, 요청을 받은 뒤에는 셋을 모두 풀어 준다
- settings의 방향은 기본이 그대로 두는 것이다. 출력이나 입력으로 쓸 줄에는 방향을 적는다
