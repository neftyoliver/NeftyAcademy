libgpiod에는 같은 사람들이 만드는 C++ 바인딩이 함께 들어 있습니다. 머리 파일은 `gpiod.hpp`이고 모든 이름이 `gpiod` 이름 공간에 있습니다. 칩, 설정, 요청, 이벤트라는 개념은 C와 같습니다. 달라지는 것은 셋입니다. 객체가 스스로 정리되고, 오류가 예외로 오고, 요청을 이어 부르는 문장 하나로 만듭니다.

## C와 짝지어 보기

| C | C++ | 달라지는 것 |
| --- | --- | --- |
| `gpiod_chip_open`, `gpiod_chip_close` | `gpiod::chip` | 생성자가 열고 소멸자가 닫는다 |
| 설정 객체 셋을 만들고 채우기 | `prepare_request()` | 이어 불러서 채운다 |
| `gpiod_chip_request_lines` | `do_request()` | `gpiod::line_request`를 값으로 준다 |
| `gpiod_line_request_release` | `line_request`의 소멸자 | 범위를 벗어나면 놓는다 |
| -1과 `errno` | 예외 | 반환값을 살필 일이 없다 |
| `GPIOD_LINE_VALUE_ACTIVE` | `gpiod::line::value::ACTIVE` | 범위가 있는 열거형이다 |
| 나노초를 적은 정수 | `std::chrono`의 시간 | 단위를 틀릴 수 없다 |

- **함수의 이름은 거의 그대로다**: `set_value`, `get_values`, `wait_edge_events`, `read_edge_events`, `reconfigure_lines`처럼 C의 이름에서 앞머리만 떼면 됩니다. 이 책에서 익힌 것이 그대로 통합니다
- **오프셋에도 형이 있다**: `gpiod::line::offset`입니다. 정수에서 저절로 바뀌므로 `17`을 그대로 넘겨도 됩니다
- **복사되지 않는다**: `chip`과 `line_request`는 옮길 수만 있습니다. 함수에는 참조로 넘기거나 `std::move`로 넘깁니다. 줄의 주인이 둘이 될 수 없기 때문입니다

## 단추를 누르는 동안 켜는 예제

```cpp gpiodcxx
// 단추를 누르는 동안 LED를 켠다. libgpiod의 C++ 바인딩으로 쓴 것
#include <gpiod.hpp>

#include <chrono>
#include <csignal>
#include <iostream>
#include <system_error>

namespace {

const gpiod::line::offset LED = 17;          // GPIO 17, 핀 11
const gpiod::line::offset BUTTON = 27;       // GPIO 27, 핀 13

volatile std::sig_atomic_t stop = 0;
void on_signal(int) { stop = 1; }

// LED는 출력, 단추는 풀업을 켠 액티브 로 입력에 두 방향의 에지 감지
gpiod::line_request request_lines() {
    using namespace gpiod;
    return chip("/dev/gpiochip0")
        .prepare_request()
        .set_consumer("press-light")
        .add_line_settings(LED,
                           line_settings().set_direction(line::direction::OUTPUT))
        .add_line_settings(BUTTON,
                           line_settings()
                               .set_direction(line::direction::INPUT)
                               .set_bias(line::bias::PULL_UP)
                               .set_active_low(true)
                               .set_edge_detection(line::edge::BOTH)
                               .set_debounce_period(std::chrono::milliseconds(10)))
        .do_request();
}

}  // namespace

int main() {
    try {
        auto request = request_lines();      // 칩은 요청을 받자마자 닫힌다
        gpiod::edge_event_buffer buffer(16);
        std::signal(SIGINT, on_signal);
        while (!stop) {
            try {
                // 음수는 끝없이 기다리라는 뜻이다
                request.wait_edge_events(std::chrono::nanoseconds(-1));
            } catch (const std::system_error& error) {
                if (error.code() == std::errc::interrupted) continue;   // 신호
                throw;
            }
            request.read_edge_events(buffer);
            for (const auto& event : buffer) {
                const bool pressed =
                    event.type() == gpiod::edge_event::event_type::RISING_EDGE;
                request.set_value(LED, pressed ? gpiod::line::value::ACTIVE
                                               : gpiod::line::value::INACTIVE);
                std::cout << (pressed ? "눌림" : "뗌") << ", 줄 번호 "
                          << event.line_seqno() << '\n';
            }
        }
        request.set_value(LED, gpiod::line::value::INACTIVE);
    } catch (const std::system_error& error) {
        // errno가 담긴 실패: 줄이 쓰이고 있다(EBUSY), 권한이 없다(EACCES) 같은 것
        std::cerr << error.what() << '\n';
        return 1;
    }
}                                            // request가 사라지며 줄을 놓는다
```

- **요청이 문장 하나다**: `prepare_request()`가 돌려준 것에 소비자 이름과 줄마다의 설정을 이어 적고 `do_request()`로 끝냅니다. C에서 설정 객체 셋을 만들고 해제하던 스무 줄이 사라집니다([「설정 객체 셋: line_settings, line_config, request_config」](#/read/libgpiod/rq-objects))
- **칩은 그 문장 안에서 닫힌다**: `chip(...)`은 이름 없는 객체여서 문장이 끝나면 사라지고, 사라지면서 칩을 닫습니다. 요청은 칩 없이도 삽니다([「칩 열기」](#/read/libgpiod/ch-open))
- **버퍼를 돌며 읽는다**: `edge_event_buffer`는 범위 기반 `for`로 방금 읽은 이벤트만 내줍니다. 이벤트는 버퍼의 것이어서 다음 읽기에서 덮입니다. 남겨 두려면 복사합니다
- **끝없이 기다리기**: `wait_edge_events`에 음수를 주면 이벤트가 올 때까지 기다립니다. 0.5초라면 `std::chrono::milliseconds(500)`을 줍니다. 시간 안에 오지 않으면 `false`입니다
- **신호도 예외로 온다**: 기다리는 도중에 신호가 오면 C에서는 -1과 `EINTR`이었습니다. 여기서는 `std::system_error`가 던져지므로 잡아서 반복문을 다시 돕니다([「기다리고 읽기」](#/read/libgpiod/ed-wait))
- **놓는 줄이 없다**: `main`의 `try` 블록을 벗어나면 `request`가 사라지면서 줄을 놓습니다. 예외로 빠져나갈 때에도 그렇습니다([「놓아주기」](#/read/libgpiod/rq-release))

## 예외로 오는 오류

| 일어난 일 | 던져지는 것 |
| --- | --- |
| 줄이 쓰이고 있다, 권한이 없다, 그 밖의 `errno` | `std::system_error` |
| 인수가 틀렸다(`EINVAL`) | `std::invalid_argument` |
| 설정이 너무 많다(`E2BIG`) | `std::length_error` |
| 닫은 칩을 썼다 | `gpiod::chip_closed` |
| 놓은 요청을 썼다 | `gpiod::request_released` |

- **무슨 `errno`였는지 본다**: `error.code() == std::errc::device_or_resource_busy`처럼 견줍니다. `EBUSY`가 그것입니다([「이미 쓰이는 줄」](#/read/libgpiod/rq-busy))
- **예외가 아닌 것**: `get_line_offset_from_name`은 그 이름의 줄이 없으면 -1을 돌려줍니다. 기다리다 시간이 다 된 것도 예외가 아니라 `false`입니다
- **닫은 것과 놓은 것**: `chip_closed`와 `request_released`는 `std::logic_error`에서 갈라진 것입니다. 프로그램의 차례가 틀렸다는 뜻이어서, 잡기보다 고칩니다

## 빌드와 꾸러미

```sh
g++ -std=c++17 -Wall -Wextra press.cpp -o press \
    $(pkg-config --cflags --libs libgpiodcxx)
```

- **이름은 `libgpiodcxx`**: `pkg-config`에 주는 이름과 링크하는 라이브러리의 이름이 그렇습니다. CMake에서는 `pkg_check_modules`에 이 이름을 줍니다([「컴파일과 링크」](#/read/libgpiod/st-build))
- **C++17부터**: 문서가 그렇게 적고, 머리 파일이 `std::filesystem`을 씁니다
- **꾸러미는 같다**: 데비안 13에는 C++ 쪽 꾸러미가 따로 없습니다. 머리 파일과 `libgpiodcxx.pc`는 `libgpiod-dev`에, 공유 라이브러리는 `libgpiod3`에 함께 들어 있습니다([「libgpiod 2.x 설치와 버전 확인」](#/read/libgpiod/st-install))
- **1.6의 C++ 바인딩은 다른 것이다**: C가 그랬듯 2에서 새로 짠 것이어서 옛 코드는 그대로 컴파일되지 않습니다

## 어느 쪽으로 쓸지

- **하는 일은 같다**: C++ 바인딩은 C 라이브러리를 부르는 얇은 층입니다. 커널에 닿는 길도, 앞 장에서 잰 박자의 한계도 같습니다
- **C++ 프로그램이면 바인딩**: 정리를 잊을 수 없고 오류를 지나칠 수 없다는 것이 가장 큰 이득입니다
- **예외를 끈 코드라면 C**: 바인딩은 실패를 예외로만 알립니다. 예외를 쓰지 않기로 한 프로젝트에서는 C의 함수를 C++에서 그대로 부릅니다
- **이 책의 예제를 옮길 때**: 설정을 만드는 도우미 함수는 `prepare_request()`의 한 문장이 되고, `perror`를 부르던 자리는 `catch`가 됩니다

<Note>
이 쪽의 예제는 돌려 보지 못했습니다. 이 책의 흉내 칩은 C의 함수만 흉내 내기 때문입니다. 진짜 libgpiod 2.2.4의 C++ 머리 파일로 문법만 검사했습니다. GCC 14와 Clang 20으로, x86-64와 aarch64에서 했습니다. 링크도 실행도 하지 않았으므로 출력을 싣지 않았습니다. 소멸자가 닫고 놓는다는 것, 어떤 `errno`가 어떤 예외가 되는지, 버퍼의 이벤트가 덮인다는 것은 바인딩의 머리 파일과 소스를 읽어 적었습니다. 꾸러미에 든 파일은 데비안의 꾸러미 목록에서 봤습니다.
</Note>

## 정리

- C++ 바인딩은 `gpiod.hpp`와 `gpiod` 이름 공간이다. 개념과 함수의 이름은 C와 같다
- 객체가 사라지면서 칩을 닫고 줄을 놓는다. 실패는 예외로 오고, 기다리는 도중의 신호도 예외다
- `pkg-config`의 이름은 `libgpiodcxx`이고 C++17이 있어야 한다. 꾸러미는 C의 것과 같다
