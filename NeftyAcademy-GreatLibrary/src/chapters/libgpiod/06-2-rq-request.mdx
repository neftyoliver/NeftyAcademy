요청은 줄을 내 것으로 만드는 일입니다. `gpiod_chip_request_lines`에 config를 넘기면 커널이 그것을 뜯어보고, 받아들이면 요청 객체를 돌려줍니다. 커널은 요청을 통째로 받아들이거나 통째로 거절합니다. 그리고 받아들인 그 순간에 설정이 핀에 적용됩니다.

## 받아들여질 때와 거절될 때

```c gpiosim
// 요청이 거절되는 경우 넷과 받아들여지는 경우, 그리고 이미 쥐인 줄이 낀 요청
#include <errno.h>
#include <gpiod.h>
#include <stdio.h>
#include <string.h>

enum { RED = 17, GREEN = 22, SPARE = 23 };   // 헤더의 핀 11, 15, 16

// 줄 n개를 한 설정으로 요청해 보고 결과를 적는다
static struct gpiod_line_request* ask(struct gpiod_chip* chip, const char* what,
                                      const unsigned int* offsets, size_t n,
                                      struct gpiod_line_settings* settings) {
    struct gpiod_line_config* config = gpiod_line_config_new();
    if (!config) return nullptr;
    if (n > 0) gpiod_line_config_add_line_settings(config, offsets, n, settings);
    struct gpiod_line_request* request =
        gpiod_chip_request_lines(chip, nullptr, config);
    printf("%s: %s\n", what, request ? "받았다" : strerror(errno));
    gpiod_line_config_free(config);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    struct gpiod_line_settings* st = gpiod_line_settings_new();
    if (!chip || !st) {
        perror("준비");
        return 1;
    }
    const unsigned int leds[] = {RED, GREEN}, far = 99, pair[] = {RED, SPARE};

    ask(chip, "[1] 줄을 하나도 붙이지 않은 config", nullptr, 0, st);
    ask(chip, "[2] 칩에 없는 오프셋 99", &far, 1, st);

    gpiod_line_settings_set_bias(st, GPIOD_LINE_BIAS_PULL_UP);
    ask(chip, "[3] 방향 없이 바이어스만", leds, 2, st);

    gpiod_line_settings_reset(st);
    gpiod_line_settings_set_direction(st, GPIOD_LINE_DIRECTION_OUTPUT);
    gpiod_line_settings_set_edge_detection(st, GPIOD_LINE_EDGE_BOTH);
    ask(chip, "[4] 출력이면서 에지 감지", leds, 2, st);

    gpiod_line_settings_reset(st);
    gpiod_line_settings_set_direction(st, GPIOD_LINE_DIRECTION_OUTPUT);
    gpiod_line_settings_set_output_value(st, GPIOD_LINE_VALUE_ACTIVE);
    struct gpiod_line_request* mine =
        ask(chip, "[5] 등 둘을 출력으로, 첫 값은 active", leds, 2, st);

    struct gpiod_line_request* more =
        ask(chip, "[6] 17번과 23번을 함께", pair, 2, st);
    struct gpiod_line_info* info = gpiod_chip_get_line_info(chip, SPARE);
    if (info) {
        bool used = gpiod_line_info_is_used(info);
        printf("    23번은 %s\n", used ? "쥐였다" : "쥐이지 않았다");
        gpiod_line_info_free(info);
    }
    gpiod_line_request_release(more);
    gpiod_line_request_release(mine);
    gpiod_line_settings_free(st);
    gpiod_chip_close(chip);
}
```

```text
[1] 줄을 하나도 붙이지 않은 config: Invalid argument
[2] 칩에 없는 오프셋 99: Invalid argument
[3] 방향 없이 바이어스만: Invalid argument
[4] 출력이면서 에지 감지: Invalid argument
핀|   0.000s  GPIO 17 → HIGH
핀|   0.000s  GPIO 22 → HIGH
[5] 등 둘을 출력으로, 첫 값은 active: 받았다
[6] 17번과 23번을 함께: Device or resource busy
    23번은 쥐이지 않았다
```

- **[1]부터 [4]는 모두 `EINVAL`이다**: 커널은 말이 안 되는 요청을 거절하지만 어디가 틀렸는지는 알려 주지 않습니다. 아래의 규칙에 비춰 찾습니다
- **[5] 받아들인 순간 핀이 움직였다**: `핀|` 두 줄이 「받았다」보다 먼저 찍혔습니다. 요청이 돌아오기 전에 두 핀은 이미 출력이 되어 HIGH를 내고 있습니다
- **[6] 하나가 안 되면 전부 안 된다**: 17번이 쥐여 있어서 요청이 `EBUSY`로 실패했고, 함께 적은 23번도 쥐이지 않았습니다. 줄 몇 개만 쥔 어중간한 상태는 생기지 않습니다
- **`request_config` 자리의 `nullptr`**: 예제는 이름 없이 요청했습니다. config 자리에는 `nullptr`를 넘길 수 없고, 넘기면 `EINVAL`입니다

## 설정은 서로 맞아야 한다

| 적은 설정 | 함께 있어야 하는 것 |
| --- | --- |
| 출력의 첫 값, 드라이브 | 방향이 출력 |
| 에지 감지, 디바운스 | 방향이 입력 |
| 바이어스 | 방향이 입력이든 출력이든 적혀 있을 것 |

- **[3]이 걸린 규칙**: 방향을 그대로 두면서 바이어스만 바꿀 수는 없습니다
- **[4]가 걸린 규칙**: 에지 감지를 켜면 libgpiod가 그 줄을 입력으로 요청합니다. 방향을 출력으로 적어 둔 줄이면 입력과 출력이 함께 실려 거절됩니다
- **방향을 적지 않고 에지만 켜도 된다**: 같은 까닭으로 입력이 됩니다

## errno 읽기

| `errno` | 까닭 |
| --- | --- |
| `EBUSY` | 줄 가운데 하나를 누가 이미 쥐고 있다 |
| `EINVAL` | 설정이 서로 안 맞는다. 없는 오프셋이다. config가 비었다 |
| `E2BIG` | config에 줄을 64개 넘게 붙이려 했다 |
| `ENXIO` | 그 줄은 에지를 감지하지 못한다 |
| `EOPNOTSUPP` | 고른 이벤트 시계를 그 기기가 받치지 않는다 |

- **가장 자주 보는 것은 `EBUSY`다**: 누가 쥐었는지 찾는 법은 [「이미 쓰이는 줄」](#/read/libgpiod/rq-busy)에 있습니다
- **`E2BIG`은 요청보다 먼저 난다**: config에 줄을 붙이는 함수가 돌려줍니다([「설정 객체 셋: line_settings, line_config, request_config」](#/read/libgpiod/rq-objects))
- **뒤의 둘은 에지를 요청할 때의 일이다**: [「에지 감지 켜기」](#/read/libgpiod/ed-request)와 [「타임스탬프와 시계 고르기」](#/read/libgpiod/ed-timestamp)에서 다룹니다

## 받아들인 순간 벌어지는 일

- **줄이 내 것이 된다**: 놓을 때까지 다른 요청은 그 줄을 쥐지 못합니다. 같은 프로그램이 다시 요청해도 마찬가지입니다
- **출력은 첫 값을 바로 낸다**: 방향을 출력으로만 적으면 기본값인 inactive가 나갑니다. 요청한 뒤에 값을 쓰면 그 사이에 핀이 잠깐 엉뚱한 값을 냅니다. 첫 값을 `gpiod_line_settings_set_output_value`로 settings에 적어 두면 그 틈이 없습니다. 릴레이처럼 잠깐의 신호에도 움직이는 것을 달았을 때 중요합니다([「릴레이와 트랜지스터 몰기」](#/read/libgpiod/out-relay))
- **방향을 그대로 두면 핀도 그대로다**: 쥐기만 하고 아무것도 바꾸지 않습니다
- **요청 객체에 묻기**: 줄의 수는 `gpiod_line_request_get_num_requested_lines`, 오프셋의 차례는 `gpiod_line_request_get_requested_offsets`, 칩의 이름은 `gpiod_line_request_get_chip_name`이 알려 줍니다
- **칩은 닫아도 된다**: 요청은 제 파일 서술자를 따로 갖습니다([「칩 열기」](#/read/libgpiod/ch-open))

## 한 요청에 무엇을 넣을까

- **함께 읽고 쓸 줄은 한 요청에**: 여러 줄의 값을 호출 한 번으로 다룰 수 있는 것은 같은 요청 안에서뿐입니다
- **따로 놓을 줄은 따로**: 요청은 통째로 놓입니다. 수명이 다른 줄은 요청을 나눕니다
- **칩이 다르면 요청도 다르다**: 요청 하나는 칩 하나의 줄만 담습니다

<Note>
예제는 이 책의 흉내 칩에서 돌린 것이고, `핀|`으로 시작하는 줄은 흉내 칩이 핀의 전압이 바뀔 때 적은 것입니다. 거절의 규칙은 리눅스 커널 문서의 줄 요청 대목에 적힌 것을 흉내 칩에 옮겼고, 에지를 켜면 입력으로 요청한다는 것은 libgpiod 2.2.4의 소스에서 읽었습니다. 진짜 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했습니다. `ENXIO`와 `EOPNOTSUPP`가 라즈베리파이의 어느 줄에서 나는지는 보드에서 확인하지 못했습니다.
</Note>

## 정리

- 요청은 통째로 받아들여지거나 통째로 거절된다. 줄 하나가 쥐여 있으면 `EBUSY`, 설정이 안 맞으면 `EINVAL`이다
- 출력 값과 드라이브는 출력에, 에지와 디바운스는 입력에 붙고, 바이어스는 방향이 적혀 있어야 한다
- 받아들인 순간 핀이 바뀐다. 출력의 첫 값은 settings에 적어 요청과 함께 내보낸다
