기다리는 함수는 요청 하나만 지켜봅니다. 실제 프로그램에는 기다릴 것이 더 있습니다. 주기마다 할 일, 네트워크로 오는 명령, 다른 장치가 보내는 데이터가 그렇습니다. 리눅스에서는 이것들이 모두 파일 서술자이고, 여러 서술자를 한꺼번에 기다리는 함수가 `poll`과 `epoll`입니다. 줄 요청도 서술자 하나를 내줍니다.

## 요청의 파일 서술자

- **`gpiod_line_request_get_fd`**: 요청에 딸린 파일 서술자를 돌려줍니다. 실패하지 않습니다
- **읽을 것이 있다는 표시가 곧 이벤트다**: 커널의 버퍼에 에지 이벤트가 하나라도 있으면 이 서술자가 읽을 수 있는 상태(`POLLIN`)가 됩니다. 기다리는 함수도 속에서는 이 서술자 하나를 `poll`합니다([「기다리고 읽기」](#/read/libgpiod/ed-wait))
- **읽는 것은 libgpiod의 함수로**: 서술자를 직접 `read`하지 않고 `gpiod_line_request_read_edge_events`로 읽습니다
- **닫지 않는다**: 이 서술자의 임자는 요청입니다. `close`하지 않고, 요청을 놓으면 함께 닫힙니다. 놓은 뒤에는 지켜보던 목록에서도 뺍니다
- **칩에도 하나 있다**: `gpiod_chip_get_fd`는 줄 정보가 바뀐 것을 알려 주는 서술자를 줍니다. 같은 반복문에 올릴 수 있습니다([「줄 정보 읽기」](#/read/libgpiod/ch-info))

## 에지와 타이머를 한 반복문에서 기다리기

아래 예제는 LED를 0.5초마다 깜빡이면서 단추를 기다립니다. 단추를 누르면 깜빡임이 멈추고, 다시 누르면 이어집니다. 박자는 `timerfd`가 맡습니다. 정해 둔 간격마다 읽을 것이 생기는 파일 서술자입니다.

```c gpiosim=loop
// 단추의 에지와 0.5초 타이머를 한 반복문에서 기다린다. 단추가 깜빡임을 켜고 끈다
#define _POSIX_C_SOURCE 200809L              // CLOCK_MONOTONIC을 쓰려고
#include <errno.h>
#include <gpiod.h>
#include <poll.h>
#include <signal.h>
#include <stdint.h>
#include <stdio.h>
#include <sys/timerfd.h>
#include <unistd.h>

enum { LED = 17, BUTTON = 27, ROOM = 4 };    // GPIO 17은 핀 11, GPIO 27은 핀 13

static volatile sig_atomic_t stop;
static void on_signal(int) { stop = 1; }

// 한 요청에 LED(출력)와 단추(풀업, 액티브 로, 누르는 에지)를 함께 담는다
static struct gpiod_line_request* request_lines(struct gpiod_chip* chip) {
    struct gpiod_line_settings* led = gpiod_line_settings_new();
    struct gpiod_line_settings* button = gpiod_line_settings_new();
    struct gpiod_line_config* config = gpiod_line_config_new();
    struct gpiod_line_request* request = nullptr;
    if (led && button && config) {
        gpiod_line_settings_set_direction(led, GPIOD_LINE_DIRECTION_OUTPUT);
        gpiod_line_settings_set_direction(button, GPIOD_LINE_DIRECTION_INPUT);
        gpiod_line_settings_set_bias(button, GPIOD_LINE_BIAS_PULL_UP);
        gpiod_line_settings_set_active_low(button, true);
        gpiod_line_settings_set_edge_detection(button, GPIOD_LINE_EDGE_RISING);
        gpiod_line_settings_set_debounce_period_us(button, 10'000);
        gpiod_line_config_add_line_settings(config, &(unsigned int){LED}, 1, led);
        gpiod_line_config_add_line_settings(config, &(unsigned int){BUTTON}, 1,
                                            button);
        request = gpiod_chip_request_lines(chip, nullptr, config);
    }
    gpiod_line_config_free(config);
    gpiod_line_settings_free(button);
    gpiod_line_settings_free(led);
    return request;
}

int main(void) {
    struct gpiod_chip* chip = gpiod_chip_open("/dev/gpiochip0");
    if (!chip) {
        perror("/dev/gpiochip0");
        return 1;
    }
    struct gpiod_line_request* lines = request_lines(chip);
    gpiod_chip_close(chip);
    struct gpiod_edge_event_buffer* buffer = gpiod_edge_event_buffer_new(ROOM);
    // 0.5초마다 읽을 것이 생기는 파일 서술자
    int timer = timerfd_create(CLOCK_MONOTONIC, TFD_CLOEXEC);
    const struct itimerspec half = {.it_value = {.tv_nsec = 500'000'000},
                                    .it_interval = {.tv_nsec = 500'000'000}};
    if (!lines || !buffer || timer < 0 ||
        timerfd_settime(timer, 0, &half, nullptr) < 0) {
        perror("준비");
        return 1;
    }
    signal(SIGINT, on_signal);
    signal(SIGTERM, on_signal);

    struct pollfd watched[2] = {
        {.fd = gpiod_line_request_get_fd(lines), .events = POLLIN},  // 에지 이벤트
        {.fd = timer, .events = POLLIN},                             // 타이머
    };
    bool blinking = true;
    bool lit = false;
    unsigned long ticks = 0;
    int presses = 0;
    while (!stop) {
        // 둘 가운데 어느 쪽에든 일이 생길 때까지 잔다
        if (poll(watched, 2, -1) < 0) {
            if (errno == EINTR) continue;
            perror("poll");
            break;
        }
        if (watched[0].revents & POLLIN) {
            int count = gpiod_line_request_read_edge_events(lines, buffer, ROOM);
            for (int i = 0; i < count; ++i) {
                blinking = !blinking;
                ++presses;
                printf("단추: %s\n", blinking ? "다시 깜빡인다" : "멈춘다");
            }
        }
        if (watched[1].revents & POLLIN) {
            uint64_t expired = 0;            // 읽어 내야 다음 poll이 다시 잔다
            if (read(timer, &expired, sizeof expired) == sizeof expired) {
                ticks += expired;
                lit = !lit;
            }
        }
        if (!blinking) lit = false;
        gpiod_line_request_set_value(
            lines, LED, lit ? GPIOD_LINE_VALUE_ACTIVE : GPIOD_LINE_VALUE_INACTIVE);
    }
    gpiod_line_request_set_value(lines, LED, GPIOD_LINE_VALUE_INACTIVE);
    printf("타이머 %lu번, 단추 %d번\n", ticks, presses);
    close(timer);
    gpiod_edge_event_buffer_free(buffer);
    gpiod_line_request_release(lines);
}
```

```text
핀|   0.000s  단추 → HIGH
핀|   0.500s  LED → HIGH
핀|   1.000s  LED → LOW
핀|   1.200s  단추 → LOW
단추: 멈춘다
핀|   1.350s  단추 → HIGH
핀|   2.900s  단추 → LOW
단추: 다시 깜빡인다
핀|   3.000s  LED → HIGH
핀|   3.050s  단추 → HIGH
핀|   3.500s  LED → LOW
핀|   4.000s  LED → HIGH
핀|   4.200s  LED → LOW
타이머 8번, 단추 2번
```

- **한 번 자고 두 가지에 깬다**: `poll`은 두 서술자 가운데 어느 쪽에든 일이 생기면 돌아오고, 어느 쪽인지는 `revents`에 적혀 있습니다. 단추는 깜빡이는 박자와 상관없이 누른 즉시 처리됩니다
- **깜빡임이 밀리지 않는다**: 박자는 커널이 재므로, 단추를 처리하느라 쓴 시간이 다음 박자를 늦추지 않습니다. 잠을 자서 박자를 맞추는 반복문과 다른 점입니다
- **타이머는 읽어 내야 한다**: 만료된 횟수를 `read`로 꺼내지 않으면 서술자가 읽을 수 있는 상태로 남아서 `poll`이 쉬지 않고 돌아옵니다. 읽은 값은 그사이에 만료된 횟수입니다
- **출력과 입력을 한 요청에 담았다**: LED와 단추에 settings를 따로 붙였습니다. 에지 이벤트는 단추에서만 옵니다([「설정 객체 셋: line_settings, line_config, request_config」](#/read/libgpiod/rq-objects))
- **신호는 `EINTR`로 온다**: `poll`은 신호 처리기가 돌고 나면 -1로 돌아옵니다. 깃발을 보고 나와서 LED를 끄고 줄을 놓습니다
- **`_POSIX_C_SOURCE`**: `-std=c23`에서 `CLOCK_MONOTONIC`이 보이려면 있어야 합니다([「타임스탬프와 시계 고르기」](#/read/libgpiod/ed-timestamp))

## epoll로 바꾸기

지켜볼 서술자가 많거나 자주 바뀌면 `epoll`이 낫습니다. 한 번 올려 두면 커널이 기억하고, 일이 생긴 것만 돌려줍니다.

```c
// poll 대신 epoll로: 한 번 올려 두고, 일이 생긴 것만 돌려받는다
#include <sys/epoll.h>

// 서술자 하나를 지켜볼 목록에 올린다. 실패하면 -1
int watch(int loop, int fd) {
    struct epoll_event wanted = {.events = EPOLLIN, .data.fd = fd};
    return epoll_ctl(loop, EPOLL_CTL_ADD, fd, &wanted);
}

// 일이 생긴 서술자 하나를 돌려준다. 신호에 깼거나 오류면 -1
int wait_one(int loop) {
    struct epoll_event ready;
    return epoll_wait(loop, &ready, 1, -1) == 1 ? ready.data.fd : -1;
}
```

- **목록은 `epoll_create1`로 만든다**: 그것이 돌려준 서술자가 위의 `loop`입니다. 요청의 서술자와 타이머를 `watch`로 올려 두고, 반복문에서는 `wait_one`이 준 서술자가 어느 쪽인지 봅니다
- **기본은 `poll`과 같은 규칙이다**: `EPOLLIN`만 적으면 읽을 것이 남아 있는 동안 계속 알려 줍니다. 이벤트를 다 읽지 못하고 돌아가도 다음에 다시 깨워 줍니다
- **`EPOLLET`은 붙이지 않는다**: 바뀌는 순간에만 알려 주는 방식은 그때마다 끝까지 읽어 내야 하고, 그러려면 서술자가 막히지 않는 것이어야 합니다. 요청의 서술자는 막히는 쪽이 기본이어서, 끝까지 읽으려다 반복문 전체가 멈춥니다

## 반복문에서 지킬 것

- **한 가지 일에 오래 머물지 않는다**: 한 서술자의 일을 하는 동안 다른 서술자는 기다립니다. 타임스탬프는 그대로여도 반응은 늦습니다
- **읽을 때는 여러 개를 받는다**: 깨어난 한 번에 이벤트가 여럿 쌓여 있을 수 있습니다([「이벤트 버퍼」](#/read/libgpiod/ed-buffer))
- **오류 표시도 본다**: `revents`에 `POLLERR`나 `POLLHUP`이 서면 그 서술자는 더 지켜볼 수 없습니다. USB로 붙인 GPIO 칩을 뽑은 때처럼 칩이 사라지면 커널이 이 표시를 세웁니다. 예제는 헤더의 칩만 쓰므로 이 검사를 뺐습니다
- **소켓과 시리얼도 같은 식이다**: 네트워크 소켓, 시리얼 포트, 표준 입력도 파일 서술자입니다. 같은 배열에 한 칸씩 더합니다
- **스레드를 쓰는 길도 있다**: 스레드 하나가 기다리는 함수에 머물며 이벤트만 받게 할 수도 있습니다. 그때에도 libgpiod의 객체 하나는 한 번에 한 스레드만 만집니다([「칩 열기」](#/read/libgpiod/ch-open))

<Note>
`poll` 예제는 이 책의 흉내 칩에서 돌린 것이고, 단추와 Ctrl+C는 대본으로 넣었습니다. `핀|`으로 시작하는 줄은 흉내 칩이 핀의 전압이 바뀔 때 적은 것입니다. 흉내 칩의 시간은 가상이어서 `timerfd`도 흉내 칩이 가로채 그 시계에 맞춰 울리게 했습니다. `epoll` 조각은 컴파일만 확인했습니다. 칩이 사라졌을 때의 표시는 리눅스 커널 소스에서, `epoll`의 두 방식은 epoll(7)에서 읽은 것입니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지 따로 확인했고, 보드에서 돌려 보지는 못했습니다.
</Note>

## 정리

- `gpiod_line_request_get_fd`가 주는 서술자는 에지 이벤트가 쌓이면 읽을 수 있는 상태가 된다
- 그 서술자를 타이머나 소켓과 함께 `poll`에 넘기면 한 반복문에서 모두 기다린다
- 읽는 것은 libgpiod의 함수로 하고, 서술자를 직접 닫지 않는다
