핀의 전압과 전류에는 한도가 있고, 그 한도를 넘기는 것은 대개 회로가 아니라 프로그램입니다. 회로는 그대로인데 줄의 방향을 틀리게 요청하거나 번호 하나를 잘못 적은 순간에 사고가 납니다. 이 쪽은 프로그램이 낼 수 있는 사고를 늘어놓고, 그런 일이 벌어져도 칩이 상하지 않게 해 주는 저항의 값을 계산합니다. 한도의 숫자가 어디서 왔는지는 「라즈베리파이 시작하기」의 [「3.3V 논리와 전류 한계」](#/read/sbc-start/hdr-voltage)에서 봤습니다.

## 지킬 숫자

| 무엇 | 값 |
| --- | --- |
| 핀이 내고 받는 전압 | 0V에서 3.3V까지. 5V를 견디지 못한다 |
| 핀 하나의 전류 | 16mA까지 |
| 모든 GPIO 핀의 전류를 합한 것 | 50mA까지 |
| LOW와 HIGH로 읽히는 전압(4와 5) | 0.8V 아래, 2.0V 위 |
| 칩 안에 든 풀 저항(4) | 33kΩ에서 73kΩ |

## 프로그램이 내는 사고

- **출력끼리 맞붙는다**: 내 핀이 HIGH를 내는 선에 맞은편 부품이 LOW를 내면, 막아 주는 것 없이 전류가 흐릅니다. 센서의 출력이 닿아 있는 줄을 출력으로 요청했을 때 벌어집니다
- **출력에 단추가 달려 있다**: GND로 이어지는 단추가 달린 줄을 출력 HIGH로 두고 단추를 누르면 3.3V가 GND에 곧바로 닿습니다
- **번호 하나를 틀린다**: 17을 27로 잘못 적으면 LED의 줄이 아니라 단추의 줄이 출력이 됩니다. 컴파일러도 커널도 이것을 알아채지 못합니다
- **한꺼번에 켠다**: LED 여덟 개를 10mA씩 흐르게 달고 모두 켜면 80mA입니다. 하나하나는 한도 안이어도 합이 50mA를 넘습니다
- **프로그램이 없는 동안**: 보드가 켜지는 동안과 프로그램이 끝난 뒤에는 줄을 쥔 임자가 없습니다. 그때 핀이 어떤 값인지는 프로그램이 정하지 못합니다([「놓아주기」](#/read/libgpiod/rq-release))

## 보호 저항

핀과 바깥 부품 사이에 저항 하나를 한 줄로 이어 넣으면, 위의 사고가 나도 흐르는 전류는 3.3V를 그 저항으로 나눈 값을 넘지 못합니다. 값이 클수록 안전하지만 입력에서는 칩 안의 풀 저항과 전압을 나눠 가지므로, 너무 크면 단추를 눌러도 값이 바뀌지 않습니다. 아래 예제가 두 쪽을 함께 따집니다.

```c
// 핀과 바깥 사이에 넣는 보호 저항 고르기: 사고가 났을 때의 전류와 입력이 읽는 전압
#include <stdio.h>

enum {
    SUPPLY_MV = 3300,
    PIN_LIMIT_UA = 16'000,                   // 핀 하나가 견디는 전류
    LOW_BELOW_MV = 800,                      // 이 아래여야 LOW로 읽힌다
    HIGH_ABOVE_MV = 2000,                    // 이 위여야 HIGH로 읽힌다
    MARGIN_MV = 200,                         // 문턱에서 이만큼은 떨어지기를 바란다
    PULL_OHM = 33'000,                       // 칩 안의 풀 저항 가운데 가장 센 값
};

static const char* judge(long fault_ua, long low_mv, long high_mv) {
    if (fault_ua > PIN_LIMIT_UA) return "사고가 나면 핀 하나의 한도를 넘는다";
    if (low_mv >= LOW_BELOW_MV || high_mv <= HIGH_ABOVE_MV)
        return "단추를 눌러도 값이 바뀌지 않을 수 있다";
    if (low_mv > LOW_BELOW_MV - MARGIN_MV || high_mv < HIGH_ABOVE_MV + MARGIN_MV)
        return "읽히기는 하지만 문턱에 바짝 붙는다";
    return "괜찮다";
}

int main(void) {
    const long resistors[] = {100, 330, 1000, 4700, 10'000, 47'000};
    printf("  저항  맞붙으면  풀업에서  풀다운에서  판정\n");
    for (size_t i = 0; i < sizeof resistors / sizeof resistors[0]; ++i) {
        long r = resistors[i];
        // 출력 HIGH인 핀이 저항을 거쳐 GND에 닿았을 때 흐르는 전류
        long fault_ua = SUPPLY_MV * 1000L / r;
        // 풀업을 건 입력에서, 저항을 거쳐 GND에 닿는 단추를 눌렀을 때의 전압
        long low_mv = SUPPLY_MV * r / (r + PULL_OHM);
        // 풀다운을 건 입력에서, 저항을 거쳐 3.3V에 닿는 단추를 눌렀을 때의 전압
        long high_mv = SUPPLY_MV * PULL_OHM / (r + PULL_OHM);
        printf("%5ldΩ  %6.1fmA  %6ldmV  %8ldmV  %s\n", r,
               (double)fault_ua / 1000, low_mv, high_mv,
               judge(fault_ua, low_mv, high_mv));
    }
}
```

```text
  저항  맞붙으면  풀업에서  풀다운에서  판정
  100Ω    33.0mA       9mV      3290mV  사고가 나면 핀 하나의 한도를 넘는다
  330Ω    10.0mA      32mV      3267mV  괜찮다
 1000Ω     3.3mA      97mV      3202mV  괜찮다
 4700Ω     0.7mA     411mV      2888mV  괜찮다
10000Ω     0.3mA     767mV      2532mV  읽히기는 하지만 문턱에 바짝 붙는다
47000Ω     0.1mA    1938mV      1361mV  단추를 눌러도 값이 바뀌지 않을 수 있다
```

- **330Ω에서 1kΩ**: 사고가 나도 전류가 10mA에서 3.3mA로 한도 안이고, 입력의 전압도 문턱에서 멀리 떨어져 있습니다. 단추와 스위치, 다른 부품의 출력을 받는 줄에 이만한 값을 넣습니다
- **10kΩ은 풀업과 싸운다**: 가장 센 풀업을 만나면 눌렀을 때의 전압이 767mV로, LOW의 문턱인 800mV에 거의 닿습니다. 내 보드의 풀업이 그보다 약할 수는 있지만 거기에 기대지 않습니다
- **가장 나쁜 쪽으로 셈했다**: 풀 저항은 범위 가운데 가장 센 값을 넣었고, 사고 전류는 핀 안쪽의 저항을 0으로 쳤습니다. 실제로는 이보다 조금씩 낫습니다
- **LED의 저항이 같은 일을 한다**: LED를 켜는 줄에는 전류를 정하는 저항이 이미 있으므로 하나를 더 넣지 않습니다
- **넣지 않는 자리**: GPIO 2와 3에는 1.8kΩ 풀업이 납땜되어 있어서, 1kΩ을 사이에 넣으면 LOW가 3.3 × 1 ÷ 2.8 = 1.18V가 되어 LOW로 읽히지 않습니다. I2C와 같은 버스의 선에는 보호 저항을 이렇게 넣지 않습니다

## 사고를 줄이는 코드의 버릇

- **번호는 한곳에 모은다**: 줄 번호를 `enum`에 모으고 옆에 무엇이 달렸는지를 주석으로 적습니다. 회로를 바꾸면 그 자리만 고칩니다
- **모르면 입력으로 요청한다**: 무엇이 달렸는지 확실하지 않은 줄은 먼저 입력으로 요청해 값을 읽어 봅니다. 입력은 바깥의 신호와 싸우지 않습니다
- **처음 값을 함께 낸다**: 출력으로 요청할 때 처음 값을 설정에 적어 둡니다. 요청과 값 쓰기를 따로 하면 그 사이에 바라지 않은 값이 잠깐 나갈 수 있습니다([「LED 켜기」](#/read/libgpiod/out-led))
- **합을 먼저 계산한다**: 한꺼번에 켜질 수 있는 부하의 전류를 모두 더해 50mA 아래인지 봅니다. 넘으면 핀은 스위치만 움직이게 합니다([「릴레이와 트랜지스터 몰기」](#/read/libgpiod/out-relay))
- **이름을 붙인다**: 요청에 이름을 붙여 두면 어느 프로그램이 어느 줄을 출력으로 쥐고 있는지가 `gpioinfo`에 보입니다([「소비자 이름」](#/read/libgpiod/rq-consumer))

<Note>
표의 숫자는 라즈베리파이의 공식 문서에서 온 것이고, 문턱과 풀 저항은 4의 칩(BCM2711)의 값입니다. 보호 저항은 그 문서에 나오는 것이 아니라 전자 회로에서 흔히 쓰는 방법이고, 예제는 옴의 법칙으로 숫자만 계산합니다. 회로를 꾸며 재 본 것은 아닙니다. 예제는 x86-64와 aarch64에서 같은 출력을 냈습니다.
</Note>

## 정리

- 핀은 3.3V까지, 하나에 16mA, 모두 합해 50mA까지이고, 이 한도를 넘기는 사고는 줄의 방향이나 번호를 틀린 프로그램이 낸다
- 바깥의 신호와 맞붙을 수 있는 줄에는 330Ω에서 1kΩ의 저항을 한 줄로 넣는다. 너무 크면 풀 저항과 전압을 나눠 입력이 읽히지 않는다
- 줄 번호는 한곳에 모으고, 모르는 줄은 입력으로 먼저 요청하고, 출력은 처음 값과 함께 요청한다
