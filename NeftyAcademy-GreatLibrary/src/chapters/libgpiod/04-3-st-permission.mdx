빌드까지 된 프로그램이 처음 부딪히는 벽은 대개 `Permission denied`입니다. 칩은 `/dev/gpiochip0` 같은 장치 파일이고, 파일이므로 누가 열 수 있는지가 정해져 있습니다. `sudo`를 붙이면 넘어가지만 그것은 고친 것이 아닙니다. 권한이 어디에 적혀 있고 어떻게 얻는지를 봅니다.

## 장치 파일의 권한

```sh
ls -l /dev/gpiochip*
groups
```

```text
crw-rw---- 1 root gpio 254, 0 Nov 23 09:00 /dev/gpiochip0
crw-rw---- 1 root gpio 254, 1 Nov 23 09:00 /dev/gpiochip1
me adm dialout sudo video gpio i2c spi
```

- **첫 칸을 읽는다**: 맨 앞의 `c`는 문자 장치라는 뜻이고, `rw-rw----`는 임자와 그룹만 읽고 쓸 수 있다는 뜻입니다
- **임자와 그룹**: `root gpio`입니다. root가 아닌 사용자는 `gpio` 그룹에 들어 있어야 엽니다
- **읽기와 쓰기가 다 있어야 한다**: libgpiod는 칩을 읽고 쓰기로 엽니다. 값을 읽기만 하는 프로그램도 마찬가지입니다
- **라즈베리파이 OS에서는 이미 되어 있다**: udev 규칙이 GPIO 장치의 그룹을 `gpio`로, 권한을 0660으로 맞추고, 처음 만든 사용자는 그 그룹에 들어 있습니다. 위는 그 모습을 보인 것이고 숫자와 날짜, 그룹의 목록은 기기마다 다릅니다
- **같은 규칙 파일에**: I2C는 `i2c`, SPI는 `spi` 그룹으로 정해져 있습니다. 뒤의 책들에서 같은 일을 겪습니다

## 권한이 없을 때의 모습

아래 예제는 칩을 번호 차례로 열어 보고 결과를 적습니다. `gpio` 그룹에 들지 않은 사용자로 돌린 경우입니다.

```c gpiosim=deny
// 칩마다 열어 보고, 열리지 않으면 까닭을 적는다
#include <errno.h>
#include <gpiod.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    int opened = 0, refused = 0;
    for (int n = 0; n < 16; ++n) {
        char path[32];
        snprintf(path, sizeof path, "/dev/gpiochip%d", n);
        if (!gpiod_is_gpiochip_device(path)) continue;
        struct gpiod_chip* chip = gpiod_chip_open(path);
        if (chip) {
            printf("%s: 열린다\n", path);
            gpiod_chip_close(chip);
            ++opened;
            continue;
        }
        int why = errno;
        printf("%s: %s\n", path, strerror(why));
        if (why == EACCES) ++refused;
    }
    if (refused > 0) {
        printf("권한이 없어 열지 못한 칩이 %d개다. 다음을 본다\n", refused);
        printf("  ls -l /dev/gpiochip0    장치 파일의 그룹과 권한\n");
        printf("  groups                  내가 든 그룹\n");
    } else if (opened == 0) {
        printf("GPIO 칩이 보이지 않는다\n");
    }
}
```

```text
/dev/gpiochip0: Permission denied
/dev/gpiochip1: Permission denied
권한이 없어 열지 못한 칩이 2개다. 다음을 본다
  ls -l /dev/gpiochip0    장치 파일의 그룹과 권한
  groups                  내가 든 그룹
```

- **`errno`는 `EACCES`**: `gpiod_chip_open`이 `nullptr`를 돌려주고 `errno`에 까닭을 둡니다. 다음 함수를 부르기 전에 다른 변수로 옮겨 둡니다([「칩 열기」](#/read/libgpiod/ch-open))
- **도구도 같은 말을 한다**: `gpiodetect`는 `unable to open chip '/dev/gpiochip0': Permission denied`라고 적습니다
- **장치 파일인지는 권한 없이도 안다**: `gpiod_is_gpiochip_device`는 파일을 열지 않고 봅니다. 그래서 칩이 없는 것과 열 수 없는 것을 가를 수 있습니다
- **권한이 있으면**: 같은 프로그램이 두 줄에 `열린다`라고 적고 끝납니다

## 사용자를 그룹에 넣기

```sh
sudo usermod -aG gpio 사용자이름
```

- **`-a`를 빠뜨리지 않는다**: `-aG`는 그룹을 더하고, `-G`만 쓰면 적지 않은 그룹에서 모두 빠집니다
- **다시 로그인해야 통한다**: 그룹은 로그인할 때 정해집니다. SSH라면 접속을 끊었다가 다시 붙고, `groups`에 `gpio`가 보이는지 확인합니다
- **서비스로 돌릴 프로그램**: 사람이 로그인하지 않으므로 유닛 파일에 `User=`와 `SupplementaryGroups=gpio`로 적습니다. 「임베디드 리눅스 시스템」에서 다룹니다

## 그룹이 없는 배포판에서

다른 보드의 데비안이나 직접 꾸민 시스템에서는 `/dev/gpiochip0`이 `root root`에 `crw-------`일 수 있습니다. 그룹을 만들고 규칙을 하나 둡니다.

```sh
sudo groupadd --system gpio
sudo usermod -aG gpio 사용자이름
echo 'SUBSYSTEM=="gpio", KERNEL=="gpiochip*", GROUP="gpio", MODE="0660"' |
    sudo tee /etc/udev/rules.d/60-gpiochip.rules
sudo udevadm control --reload
sudo udevadm trigger --subsystem-match=gpio
```

- **규칙이 하는 일**: 커널이 GPIO 칩의 장치 파일을 만들 때마다 그룹과 권한을 고쳐 줍니다. 그래서 다시 켜도 남습니다. `chmod`로 손수 바꾼 것은 다시 켜면 사라집니다
- **마지막 두 줄**: 규칙을 다시 읽게 하고, 이미 있는 장치에 지금 적용합니다
- **0666은 쓰지 않는다**: 누구나 열게 하면 그 기기에 들어온 어떤 프로그램도 핀을 움직일 수 있습니다

## sudo로 돌리지 않는 까닭

- **실수가 닿는 범위**: root로 도는 프로그램의 버그는 시스템 전체에 닿습니다. 핀 몇 개를 다루자고 그 권한을 줄 까닭이 없습니다
- **뒤에 남는 것**: root로 만든 파일은 root의 것이 되어 다음에 보통 사용자로 돌릴 때 걸립니다
- **권한은 칩 단위다**: 칩을 열 수 있으면 그 칩의 줄은 무엇이든 요청할 수 있습니다. 줄마다 권한을 가르는 장치는 없습니다. 헤더에 없는 줄, 4라면 블루투스와 Wi-Fi를 켜는 줄까지 같은 권한 안에 있으므로 칩과 오프셋을 적을 때 조심합니다

<Note>
예제는 이 책의 흉내 칩에 칩을 열 때 `EACCES`를 내게 해 놓고 돌린 것입니다. 진짜 libgpiod 2.2.4의 머리 파일로 x86-64와 aarch64에서 컴파일되는지만 따로 확인했습니다. `ls -l`과 `groups`의 출력은 꼴을 보이려고 지어 적은 것이고, 이 쪽의 명령은 보드에서 돌려 보지 못했습니다. 라즈베리파이 OS의 규칙은 raspberrypi-sys-mods 저장소의 `99-com.rules`에서, 칩을 읽고 쓰기로 연다는 것과 도구의 오류 글귀는 libgpiod 2.2.4의 소스에서 읽었습니다.
</Note>

## 정리

- 칩은 장치 파일이고, 라즈베리파이 OS에서는 `root gpio`에 0660이다. 사용자가 `gpio` 그룹에 들어 있어야 열린다
- 그룹에 넣는 것은 `sudo usermod -aG gpio`이고, 다시 로그인해야 통한다. 그룹이 없는 배포판에서는 udev 규칙을 만든다
- `sudo`로 돌리지 않는다. 권한은 칩 단위라서 열 수 있으면 그 칩의 모든 줄에 손이 닿는다
