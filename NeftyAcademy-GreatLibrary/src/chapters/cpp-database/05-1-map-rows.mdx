지금까지의 예제는 `sqlite3_column_int64(st, 3)`처럼 열을 번호로 읽었습니다. 번호는 SELECT가 돌려주는 열의 순서에 묶여 있어서, `SELECT *`로 읽던 테이블에 누가 열을 하나 끼워 넣으면 컴파일도 실행도 멀쩡한 채 값이 엉뚱한 멤버로 들어갑니다. 구조체가 늘 때마다 같은 읽기·쓰기 코드를 손으로 되풀이하는 것도 실수가 끼기 쉬운 자리입니다. 이 쪽에서는 열과 멤버의 짝을 구조체마다 한 번만 적고, 읽기와 쓰기는 모든 구조체가 함께 쓰는 템플릿에 맡깁니다.

## 짝 표 한 번 적기

`Part::fields()`는 (열 이름, 멤버 포인터) 짝을 담은 `std::tuple`을 돌려줍니다. 멤버 포인터 `&Part::price`는 어느 `Part` 객체에서든 그 안의 `price`를 가리키므로, `row.*(f.member)`로 지금 읽는 행 객체의 멤버에 닿습니다. `std::apply`가 튜플을 짝들의 팩으로 풀고, 쉼표 접기 `(get(...), ...)`가 짝마다 한 번씩 `get`을 부릅니다. `get`과 `put`은 멤버의 형마다 하나씩 겹쳐 정의해서(오버로드) 어느 변환을 쓸지는 컴파일러가 고릅니다. [「PostgreSQL」](#/read/cpp-database/cs-postgres)의 `tx.query<int, std::string, Price>()`가 형에 따른 변환을 라이브러리가 맡은 모습이라면, 여기서는 거기에 어느 멤버로 넣을지까지 더한 셈입니다.

```cpp flags=-lsqlite3
#include <sqlite3.h>
#include <cstdio>
#include <optional>
#include <string>
#include <string_view>
#include <tuple>
#include <vector>

template <class T, class M> struct Field { const char* column; M T::*member; };
template <class T, class M> constexpr Field<T, M> field(const char* c, M T::*m) {
    return {c, m};
}

struct Part {                          // 열과 멤버의 짝을 구조체마다 한 번 적는다
    long long id = 0;
    std::string sku, name;
    std::optional<long long> price;            // NULL일 수 있는 열
    static constexpr auto fields() {
        return std::tuple{field("id", &Part::id), field("sku", &Part::sku),
                          field("name", &Part::name),
                          field("price_cents", &Part::price)};
    }
};

// 열 하나를 멤버 하나로 (형마다 다른 함수)
void get(sqlite3_stmt* s, int i, long long& v) { v = sqlite3_column_int64(s, i); }
void get(sqlite3_stmt* s, int i, std::string& v) {
    v = reinterpret_cast<const char*>(sqlite3_column_text(s, i));
}
void get(sqlite3_stmt* s, int i, std::optional<long long>& v) {
    if (sqlite3_column_type(s, i) == SQLITE_NULL) v.reset();
    else v = sqlite3_column_int64(s, i);
}
void put(sqlite3_stmt* s, int i, long long v) { sqlite3_bind_int64(s, i, v); }
void put(sqlite3_stmt* s, int i, const std::string& v) {
    sqlite3_bind_text(s, i, v.c_str(), -1, SQLITE_TRANSIENT);
}
void put(sqlite3_stmt* s, int i, const std::optional<long long>& v) {
    if (v) sqlite3_bind_int64(s, i, *v);
    else sqlite3_bind_null(s, i);
}

// 열 이름을 ", "로 잇는다 (이름은 코드에서 오므로 이어 붙여도 된다)
template <class T> std::string column_list(bool with_id) {
    std::string cols;
    auto add = [&](auto f) {
        if (!with_id && std::string_view(f.column) == "id") return;
        cols += (cols.empty() ? "" : ", ") + std::string(f.column);
    };
    std::apply([&](auto... f) { (add(f), ...); }, T::fields());
    return cols;
}

template <class T>
std::vector<T> select_all(sqlite3* db, const char* table, const char* tail = "") {
    std::string sql = "SELECT " + column_list<T>(true) + " FROM " + table + tail;
    std::vector<T> out;
    sqlite3_stmt* st;
    if (sqlite3_prepare_v2(db, sql.c_str(), -1, &st, nullptr) != SQLITE_OK) {
        std::printf("  준비 실패: %s\n", sqlite3_errmsg(db));
        return out;
    }
    while (sqlite3_step(st) == SQLITE_ROW) {
        T row;
        int i = 0;
        std::apply([&](auto... f) { (get(st, i++, row.*(f.member)), ...); },
                   T::fields());
        out.push_back(std::move(row));
    }
    sqlite3_finalize(st);
    return out;
}

template <class T> void insert(sqlite3* db, const char* table, T& obj) {
    std::string cols = column_list<T>(false), marks;   // id는 DB가 정한다
    for (char c : cols) if (c == ',') marks += "?, ";
    std::string sql = std::string("INSERT INTO ") + table + " (" + cols +
                      ") VALUES (" + marks + "?)";
    sqlite3_stmt* st;
    sqlite3_prepare_v2(db, sql.c_str(), -1, &st, nullptr);
    int i = 1;
    auto bind = [&](auto f) {
        if (std::string_view(f.column) != "id") put(st, i++, obj.*(f.member));
    };
    std::apply([&](auto... f) { (bind(f), ...); }, T::fields());
    sqlite3_step(st);
    sqlite3_finalize(st);
    obj.id = sqlite3_last_insert_rowid(db);
}

int main() {
    sqlite3* db;
    sqlite3_open(":memory:", &db);
    // 열의 순서가 구조체와 다르고, 구조체가 모르는 열(stock)도 있다
    sqlite3_exec(db, "CREATE TABLE parts (price_cents INTEGER, "
                     "stock INTEGER DEFAULT 0, name TEXT NOT NULL, "
                     "sku TEXT NOT NULL UNIQUE, id INTEGER PRIMARY KEY)",
                 nullptr, nullptr, nullptr);
    std::vector<Part> news = {{0, "P-100", "볼트", 120}, {0, "P-200", "너트", 80},
                              {0, "P-300", "와셔", std::nullopt}};
    for (Part& p : news) {
        insert(db, "parts", p);
        std::printf("넣음 id=%lld %s\n", p.id, p.sku.c_str());
    }
    for (const Part& p : select_all<Part>(db, "parts", " ORDER BY id"))
        std::printf("  %lld | %s | %s | %s\n", p.id, p.sku.c_str(), p.name.c_str(),
                    p.price ? std::to_string(*p.price).c_str() : "가격 없음");
    std::printf("없는 테이블에서 읽기:\n");
    select_all<Part>(db, "part");
    sqlite3_close(db);
}
```

```text
넣음 id=1 P-100
넣음 id=2 P-200
넣음 id=3 P-300
  1 | P-100 | 볼트 | 120
  2 | P-200 | 너트 | 80
  3 | P-300 | 와셔 | 가격 없음
없는 테이블에서 읽기:
  준비 실패: no such table: part
```

- **열 이름으로 고르기**: 테이블은 열의 순서가 구조체와 다르고 구조체가 모르는 `stock` 열도 있지만, SELECT가 `fields()`의 순서대로 열 이름을 적으므로 결과의 i번째 열은 늘 i번째 짝과 맞습니다. 같은 테이블을 `SELECT *`로 읽었다면 `price_cents`가 `id`로 들어갔을 것입니다
- **쉼표 접기의 순서**: 쉼표 연산자는 왼쪽부터 차례로 실행되므로 `i++`가 열 번호를 0, 1, 2, 3으로 매깁니다. 같은 것을 `g(get(st, i++, ...)...)`처럼 함수 인자로 펼치면 인자의 평가 순서가 정해져 있지 않아 번호가 섞일 수 있습니다
- **NULL은 optional로**: 와셔의 가격은 NULL이라 `std::nullopt`가 되었습니다. `sqlite3_column_int64`는 NULL에서 0을 돌려주므로 `long long`으로 받았다면 "0원"과 "모름"을 가를 수 없습니다. 반대로 NULL을 담을 수 없는 `std::string` 멤버의 열에는 `NOT NULL`을 걸어 스키마와 구조체가 같은 약속을 하게 했습니다. NULL에서 `sqlite3_column_text`는 널 포인터를 돌려주고, 그것을 `std::string`에 넣는 것은 정의되지 않은 동작입니다
- **id는 DB가 정한다**: `insert`는 id 열을 빼고 넣은 뒤 `sqlite3_last_insert_rowid`로 받은 값을 객체에 적습니다. PostgreSQL과 SQLite 3.35 이후에서는 `INSERT ... RETURNING id`로 한 번에 받을 수도 있습니다

형마다의 변환을 더 자세히, 큰 정수와 BLOB까지는 [「타입 변환과 NULL」](#/read/cpp-database/map-types)에서 다룹니다.

## 무엇이 언제 걸리나

이 방식에서 멤버는 포인터이고 이름은 문자열입니다. `&Part::prise`처럼 멤버 이름을 틀리거나 `get` 오버로드가 없는 형의 멤버를 짝에 넣으면 컴파일 단계에서 걸립니다. 반면 열 이름과 테이블 이름은 SQLite가 문장을 준비할 때에야 확인되어, 마지막 줄처럼 실행 중에 "no such table"로 드러납니다. 그래서 매핑마다 실제 스키마에 한 번씩 쓰고 읽는 테스트를 두는 것이 좋습니다([「테스트 DB와 픽스처」](#/read/cpp-database/dbtest-fixtures)). 이름을 SQL에 이어 붙여도 안전한 것은 그것이 코드에 적힌 상수이기 때문입니다. 사용자 입력에서 온 이름은 이어 붙이지 않고, 값은 언제나 묶습니다([「SQL 주입과 매개변수 바인딩」](#/read/cpp-database/injection)).

<Note>
멤버 이름이 `order`나 `group` 같은 예약어이면 이어 붙인 SQL이 문법 오류를 내므로, 이름을 큰따옴표로 감싼 인용 식별자로 적기도 합니다(MySQL과 MariaDB는 기본이 백틱). 그런데 SQLite는 옛 호환 때문에, 큰따옴표 이름이 어느 열과도 맞지 않으면 오류 대신 문자열로 읽습니다. 그러면 `"nmae"`처럼 틀린 이름이 오류도 없이 모든 행에 `nmae`라는 글자를 돌려줍니다. 연결을 연 뒤 `sqlite3_db_config`로 `SQLITE_DBCONFIG_DQS_DML`과 `SQLITE_DBCONFIG_DQS_DDL`을 0으로 꺼 두면 "no such column" 오류로 바로 드러납니다.
</Note>

## 리플렉션이 오면

`fields()`의 열 이름은 대개 멤버 이름을 한 번 더 적은 것입니다. Boost.PFR은 Boost 1.84부터 C++20에서 집합체(aggregate)의 필드 이름을 `boost::pfr::get_name<I, T>()`로 읽어 주어, 매크로 없이 이 중복을 줄입니다. C++26에는 정적 리플렉션(P2996)이 들어와서 컴파일러가 멤버 목록과 이름을 직접 내줍니다. GCC 16.1부터 `-std=c++26 -freflection`으로 쓸 수 있고, 아래는 `column_list`를 그렇게 다시 쓴 모습입니다.

```cpp nocheck
#include <meta>
#include <string>

template <class T> std::string column_list() {
    constexpr auto ctx = std::meta::access_context::current();
    std::string cols;
    template for (constexpr auto m :
                  define_static_array(nonstatic_data_members_of(^^T, ctx)))
        cols += (cols.empty() ? "" : ", ") + std::string(identifier_of(m));
    return cols;
}
```

`^^T`는 형 `T`를 나타내는 컴파일 시간 값이고, `template for`는 멤버마다 본문을 하나씩 펼칩니다. 멤버 이름과 열 이름이 다른 `price`와 `price_cents` 같은 경우는 C++26 애너테이션(P3394)으로 `[[=column("price_cents")]]`처럼 멤버에 열 이름을 달아 두고 읽을 수 있습니다. 짝 적기와 SQL 만들기를 통째로 맡는 라이브러리는 [「ORM과 쿼리 빌더」](#/read/cpp-database/map-orm)에서 봅니다.

## 정리

- 열은 번호가 아니라 이름으로 골라 SELECT에 적고, 열과 멤버의 짝은 구조체마다 한 곳에만 적는다
- 형마다 get과 put을 겹쳐 정의하면 변환은 컴파일러가 고르고, NULL이 올 수 있는 열은 std::optional로 받는다
- 멤버 포인터는 컴파일할 때, 열과 테이블 이름은 실행할 때 확인되므로 매핑마다 실제 스키마로 시험하고, C++26 리플렉션은 짝 적기를 컴파일러에 맡긴다
