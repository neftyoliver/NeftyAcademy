시험을 운영과 같은 데이터베이스, 같은 판에 대고 돌리려면 그 서버가 필요합니다. 개발자마다 손으로 설치해 두면 판과 설정이 제각각이 되고, CI에서는 깨끗한 서버가 매번 있어야 합니다. 컨테이너는 정해 둔 이미지로 몇 초 만에 서버를 띄우고, 시험이 끝나면 데이터째 버립니다.

## compose로 서버와 시험 띄우기

아래는 PostgreSQL 16 서버와 시험 프로그램을 함께 띄우는 Docker Compose 파일입니다.

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: academy
      POSTGRES_PASSWORD: academy        # 시험용 암호
      POSTGRES_DB: academy
    tmpfs: /var/lib/postgresql/data     # 데이터를 메모리에: 빠르고, 끝나면 사라진다
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U academy -d academy"]
      interval: 1s
      timeout: 3s
      retries: 30
  tests:
    build: .
    environment:
      PGHOST: db                        # 서비스 이름이 곧 호스트 이름
    depends_on:
      db:
        condition: service_healthy      # 건강 검사를 통과한 뒤에 시작
```

이미지의 판을 `postgres:16`처럼 적어 두면 누구의 기계에서나, CI에서나 같은 서버가 뜹니다. `latest`는 어느 날 판이 바뀌어 시험이 까닭 없이 깨질 수 있어 피합니다. 데이터 디렉터리를 `tmpfs`로 두면 디스크에 쓰지 않아 빠르고, 컨테이너를 내리면 흔적이 없습니다. 시험 프로그램 쪽의 연결 정보는 코드에 적지 않고 `PGHOST` 같은 libpq 환경 변수로 줍니다.

## 준비될 때까지 기다리기

컨테이너가 시작했다고 데이터베이스가 연결을 받는 것은 아닙니다. PostgreSQL은 처음 뜰 때 데이터 디렉터리를 만들고 한 번 다시 시작하므로, 바로 붙으면 실패합니다. compose의 `healthcheck`가 없는 환경(직접 띄운 컨테이너, 다른 CI)에서는 시험 프로그램이 스스로 기다립니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <thread>

using namespace std::chrono_literals;
using Clock = std::chrono::steady_clock;

// 서버가 연결을 받을 때까지 기다린다. 기다릴 이유가 없으면 바로 멈춘다
bool wait_ready(const char* conninfo, std::chrono::milliseconds limit) {
    auto deadline = Clock::now() + limit;
    auto delay = 50ms;
    for (int attempt = 1;; ++attempt) {
        switch (PQping(conninfo)) {
        case PQPING_OK:                          // 받는다 (인증은 아직 모른다)
            std::printf("  준비됨 (시도 %d번)\n", attempt);
            return true;
        case PQPING_NO_ATTEMPT:                  // 연결 정보가 틀림: 기다려도 헛일
            std::printf("  연결 정보가 잘못되어 멈춤\n");
            return false;
        case PQPING_REJECT:                      // 서버는 있지만 아직 시작하는 중
        case PQPING_NO_RESPONSE:                 // 아직 아무도 받지 않는다
            break;
        }
        if (Clock::now() + delay > deadline) {
            std::printf("  시간 초과 (시도 %d번)\n", attempt);
            return false;
        }
        std::this_thread::sleep_for(delay);
        delay = std::min<std::chrono::milliseconds>(delay * 2, 1s);
    }
}

int main() {
    std::printf("5499번 포트를 0.5초 동안 기다리기\n");
    wait_ready("host=localhost port=5499", 500ms);
    std::printf("오타가 난 연결 정보\n");
    wait_ready("hots=localhost", 500ms);
    std::printf("5432번 포트\n");
    const char* ci = "host=localhost port=5432 dbname=academy user=academy "
                     "password=academy";
    if (wait_ready(ci, 30s)) {
        PGconn* c = PQconnectdb(ci);             // 준비된 뒤에 진짜로 맺는다
        std::printf("  연결: %s\n", PQstatus(c) == CONNECTION_OK ? "성공" : "실패");
        PQfinish(c);
    }
}
```

```text
5499번 포트를 0.5초 동안 기다리기
  시간 초과 (시도 4번)
오타가 난 연결 정보
  연결 정보가 잘못되어 멈춤
5432번 포트
  준비됨 (시도 1번)
  연결: 성공
```

- **응답을 셋으로 나눈다**: `PQping`은 연결을 맺지 않고 서버의 상태만 봅니다. 아무도 받지 않거나(`NO_RESPONSE`) 시작하는 중이면(`REJECT`) 기다리고, 연결 정보 자체가 틀렸으면(`NO_ATTEMPT`) 기다려도 헛일이므로 바로 멈춥니다. 오타가 난 키워드 `hots`는 한 번 만에 멈췄습니다
- **기다림에 끝과 백오프**: 50ms에서 시작해 두 배씩 늘리며 다시 물었고, 0.5초 안에 네 번 묻고 시간 초과로 끝났습니다([「재연결과 타임아웃」](#/read/cpp-database/pool-reconnect))
- **ping은 인증을 모른다**: `PQping`의 OK는 서버가 연결을 받는다는 뜻일 뿐, 사용자와 암호가 맞는지는 알려 주지 않습니다. 그래서 준비된 뒤 `PQconnectdb`로 실제로 맺어 확인합니다

## 다른 데이터베이스의 공식 이미지

MariaDB(`mariadb`), MySQL(`mysql`), Redis(`redis`)도 Docker Hub의 공식 이미지가 있고, 저마다 사용자와 암호를 환경 변수로 받습니다. SQL Server는 Microsoft가 `mcr.microsoft.com/mssql/server`로 리눅스 이미지를 냅니다. `2025-latest`나 `2022-latest` 태그를 고르고, `ACCEPT_EULA=Y`로 사용권에 동의하며, `MSSQL_SA_PASSWORD`에 복잡도 규칙을 지킨 암호를 줍니다. `MSSQL_PID=Developer`는 운영이 아닌 개발과 시험에 무료로 쓰는 판입니다([「SQL Server」](#/read/cpp-database/cs-mssql)).

<Note>
컨테이너를 띄우는 비용이 아깝다면 시험 묶음 전체에서 서버 하나를 띄워 두고, 시험마다 트랜잭션을 되돌리거나 템플릿 데이터베이스를 복사합니다([「테스트 DB와 픽스처」](#/read/cpp-database/dbtest-fixtures)). 반대로 판 올리기를 앞두었다면 같은 시험을 옛 판과 새 판 이미지에서 함께 돌려 차이를 미리 찾습니다.
</Note>

## 정리

- 컨테이너로 운영과 같은 판의 서버를 정해진 이미지 태그로 띄우고, 데이터는 tmpfs에 두어 시험이 끝나면 버린다
- 컨테이너가 시작해도 데이터베이스는 늦게 준비되므로, healthcheck나 PQping 반복으로 기다리되 끝과 백오프를 두고, 틀린 연결 정보에는 바로 멈춘다
- PQping은 인증을 확인하지 않으므로 준비된 뒤 실제로 연결해 보고, SQL Server는 Microsoft의 공식 이미지를 사용권 동의와 함께 쓴다
