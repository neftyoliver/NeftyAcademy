SQLite와 달리 **서버형 데이터베이스**는 데이터를 맡은 서버 프로세스가 따로 돌고, 프로그램은 네트워크(PostgreSQL은 TCP 5432번 포트나 유닉스 소켓)로 붙어 SQL을 보냅니다. 사용자와 권한이 있고, 수많은 클라이언트가 동시에 읽고 씁니다. PostgreSQL은 연결마다 서버 쪽 프로세스를 하나씩 띄우기 때문에 연결을 맺는 일 자체가 비싸며, 이 때문에 연결 풀을 씁니다([「연결 풀」](#/read/cpp-database/pool-pool)). 공식 C 클라이언트 라이브러리가 **libpq**이고, 그 위에 만든 공식 C++ 라이브러리가 **libpqxx**입니다.

## 연결 문자열

연결 정보는 `host=localhost dbname=academy user=academy` 같은 `키=값` 문자열이나 `postgresql://academy@localhost:5432/academy` 같은 URI로 줍니다. 암호를 코드에 적지 않으려면 홈 폴더의 `.pgpass` 파일이나 환경 변수(`PGPASSWORD`), 비밀 관리 도구를 씁니다. 다른 기계의 서버에 붙을 때는 `sslmode=verify-full`로 암호화와 함께 서버 인증서까지 확인하고, `application_name`을 붙여 두면 서버에서 어느 프로그램의 연결인지 보입니다([「모니터링」](#/read/cpp-database/dbops-monitor)).

## libpqxx로 붙기

```cpp pkg=libpqxx flags=-std=c++17
#include <pqxx/pqxx>
#include <cstdio>
#include <optional>
#include <string>

using Price = std::optional<std::string>;      // NULL일 수 있는 값은 optional로

int main() {
    pqxx::connection c{"host=localhost dbname=academy user=academy "
                       "password=academy"};
    std::printf("서버 판 %d\n", c.server_version());
    {
        pqxx::nontransaction setup{c};
        setup.exec("SET client_min_messages = warning");
        setup.exec("DROP TABLE IF EXISTS pg_parts");
        setup.exec("CREATE TABLE pg_parts (id serial PRIMARY KEY, sku text UNIQUE "
                   "NOT NULL, name text NOT NULL, price numeric(10,2))");
    }

    pqxx::work tx{c};                          // 커밋할 때까지가 한 트랜잭션
    struct Part { const char* sku; const char* name; Price price; };
    Part parts[] = {{"P-100", "볼트", "0.12"}, {"P-200", "너트", "0.08"},
                    {"P-300", "와셔", std::nullopt}};
    for (const Part& p : parts) {
        int id = tx.exec_params1("INSERT INTO pg_parts (sku, name, price) "
                                 "VALUES ($1, $2, $3) RETURNING id",
                                 p.sku, p.name, p.price)[0].as<int>();
        std::printf("넣음: %s -> id %d\n", p.sku, id);
    }
    const char* all = "SELECT id, name, price::text FROM pg_parts ORDER BY id";
    for (auto [id, name, price] : tx.query<int, std::string, Price>(all))
        std::printf("  %d %s %s\n", id, name.c_str(),
                    price ? price->c_str() : "(NULL)");
    tx.commit();

    try {
        pqxx::work tx2{c};
        tx2.exec_params("INSERT INTO pg_parts (sku, name) VALUES ($1, $2)",
                        "P-100", "볼트 2");
        tx2.commit();
    } catch (const pqxx::unique_violation& e) {   // SQLSTATE마다 예외 형이 있다
        std::printf("같은 sku: unique_violation, SQLSTATE %s\n",
                    e.sqlstate().c_str());
    }

    pqxx::read_transaction rd{c};              // 읽기만 하는 트랜잭션
    pqxx::result r = rd.exec_params("SELECT name FROM pg_parts WHERE price > $1",
                                    "0.1");
    std::printf("0.1보다 비싼 것 %d개: %s\n", r.size(), r[0][0].c_str());
}
```

```text
서버 판 160015
넣음: P-100 -> id 1
넣음: P-200 -> id 2
넣음: P-300 -> id 3
  1 볼트 0.12
  2 너트 0.08
  3 와셔 (NULL)
같은 sku: unique_violation, SQLSTATE 23505
0.1보다 비싼 것 1개: 볼트
```

- **트랜잭션은 객체**: `pqxx::work`는 만들 때 `BEGIN`하고 `commit()`을 불러야 커밋합니다. 커밋하지 않고 사라지면(예외가 나서 블록을 빠져나가면) 소멸자가 되돌립니다. 읽기만 할 때는 `read_transaction`을, 트랜잭션 없이 실행할 때는 `nontransaction`을 씁니다
- **$1, $2 매개변수**: 값은 SQL 문자열에 섞이지 않고 따로 전송되므로 주입 걱정이 없고, `std::nullopt`은 NULL로 갑니다. 결과의 NULL도 `std::optional`로 받으면 빈 문자열과 헷갈리지 않습니다
- **RETURNING**: 새로 만든 행의 id를 같은 문장에서 돌려받았습니다. 넣고 나서 다시 묻는 질의가 필요 없고, 다른 연결이 끼어들 틈도 없습니다
- **SQLSTATE 예외**: 같은 sku는 `pqxx::unique_violation`(SQLSTATE 23505)으로 잡혔습니다. libpqxx는 오류 종류마다 예외 형을 두므로 필요한 것만 골라 잡고, `tx2`는 커밋되지 않은 채 사라져 저절로 되돌려졌습니다

<Note>
우분투 24.04의 libpqxx 7.8 패키지는 C++17로 빌드되어 있습니다. C++20 이상으로 컴파일하면 머리 파일은 `std::source_location`을 받는 함수를 찾는데 라이브러리에는 그런 함수가 없어 링크가 깨집니다. 그래서 이 예제만 `-std=c++17`로 빌드했습니다. 라이브러리와 프로그램을 같은 표준으로 빌드하면(소스에서 직접 빌드하거나 vcpkg, Conan 같은 패키지 관리자를 쓰면) 이런 일이 없습니다. C++ 라이브러리를 패키지로 받아 쓸 때 흔히 겪는 일입니다.
</Note>

## libpq 아래층

libpqxx가 감싼 libpq도 알아 둘 만합니다. `PQconnectdb`로 연결하고, `PQexecParams`에 SQL과 `$1` 자리의 값들을 문자열로 넘기고, 돌아온 `PGresult`에서 `PQntuples`, `PQgetvalue`로 값을 읽은 뒤 `PQclear`로 반드시 정리합니다. 함정이 하나 있습니다. NULL 칸에도 `PQgetvalue`는 빈 문자열을 돌려주므로 `PQgetisnull`로 따로 확인해야 합니다. libpq는 기다리지 않고 보내고 나중에 받는 비동기 API([「비동기 쿼리」](#/read/cpp-database/pool-async)), 대량으로 넣는 `COPY`([「배치 삽입」](#/read/cpp-database/dbperf-batch)), 서버가 알림을 보내는 `LISTEN`/`NOTIFY`도 제공합니다.

## 정리

- PostgreSQL은 연결마다 서버 프로세스를 띄우는 서버형 데이터베이스이며, C는 libpq, C++은 그 위의 libpqxx로 붙는다
- 연결 문자열에 암호를 적지 말고 .pgpass나 비밀 관리 도구를 쓰며, 원격 서버에는 sslmode=verify-full로 붙는다
- libpqxx는 트랜잭션을 RAII 객체로, 값을 $1 매개변수로, NULL을 optional로, 오류를 SQLSTATE별 예외로 다루며, libpq에서는 NULL을 PQgetisnull로 확인한다
