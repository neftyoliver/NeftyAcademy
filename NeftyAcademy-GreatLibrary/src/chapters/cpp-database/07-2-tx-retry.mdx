어떤 오류는 SQL이 틀렸다는 뜻이 아니라 "동시에 돈 다른 트랜잭션과 부딪혀 데이터베이스가 이 트랜잭션을 되돌렸으니 다시 하라"는 뜻입니다. PostgreSQL의 직렬화 실패(40001)와 교착(40P01)이 그렇습니다. PostgreSQL 문서도 SERIALIZABLE을 쓰는 프로그램은 어떤 트랜잭션이 되돌려질지 미리 알기 어려우므로 40001을 받으면 다시 하는 일반적인 방법을 갖추라고 권합니다. 다시 할 단위는 실패한 문장이 아니라 읽기부터 시작하는 트랜잭션 전체입니다.

## 다시 할 수 있게 짜기

아래의 `with_retry`는 트랜잭션의 본문을 함수로 받아, `BEGIN`과 `COMMIT`, 되돌리기, 다시 할지의 판단을 한곳에서 맡습니다. 당직 의사 둘이 "다른 사람이 있으니 나는 빠져도 된다"고 동시에 판단하는, [「트랜잭션과 격리 수준」](#/read/cpp-database/db-transactions)의 쓰기 치우침을 그대로 가져왔습니다. 앨리스가 읽고 쓰는 사이에 밥이 먼저 빠지고 커밋하도록 순서를 고정했습니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <chrono>
#include <cstdio>
#include <functional>
#include <random>
#include <stdexcept>
#include <string>
#include <thread>

struct DbError : std::runtime_error {
    std::string state;
    DbError(const char* s, const char* msg)
        : std::runtime_error(msg), state(s ? s : "") {}
};

std::string exec(PGconn* c, const char* sql) {   // 첫 칸을 돌려주고, 실패면 던진다
    PGresult* r = PQexec(c, sql);
    ExecStatusType st = PQresultStatus(r);
    if (st != PGRES_COMMAND_OK && st != PGRES_TUPLES_OK) {
        DbError e(PQresultErrorField(r, PG_DIAG_SQLSTATE),
                  PQresultErrorField(r, PG_DIAG_MESSAGE_PRIMARY));
        PQclear(r);
        throw e;
    }
    std::string v = PQntuples(r) > 0 ? PQgetvalue(r, 0, 0) : "";
    PQclear(r);
    return v;
}

// 직렬화 실패(40001)와 교착(40P01)만, 트랜잭션을 처음부터 다시 한다
template <class Body> auto with_retry(PGconn* c, Body body, int max_attempts = 5) {
    std::mt19937 rng(42);
    for (int attempt = 1;; ++attempt) {
        try {
            exec(c, "BEGIN ISOLATION LEVEL SERIALIZABLE");
            auto result = body(attempt);
            exec(c, "COMMIT");
            return result;
        } catch (const DbError& e) {
            PQclear(PQexec(c, "ROLLBACK"));      // 이미 끝났어도 해가 없다
            bool retryable = e.state == "40001" || e.state == "40P01";
            if (!retryable || attempt == max_attempts) throw;
            std::printf("    %s로 되돌려짐, 다시 한다\n", e.state.c_str());
            int base = 10 << attempt;            // 20, 40, 80ms에 흔들림을 더한다
            std::this_thread::sleep_for(std::chrono::milliseconds(
                base + std::uniform_int_distribution<>(0, base)(rng)));
        }
    }
}

int main() {
    const char* conninfo = "host=localhost dbname=academy user=academy "
                           "password=academy";
    PGconn* alice = PQconnectdb(conninfo);
    PGconn* bob = PQconnectdb(conninfo);
    exec(alice, "SET client_min_messages = warning");
    exec(alice, "DROP TABLE IF EXISTS rt_oncall");
    exec(alice, "CREATE TABLE rt_oncall (name text PRIMARY KEY, on_call bool)");
    exec(alice, "INSERT INTO rt_oncall VALUES ('앨리스', true), ('밥', true)");
    const char* count = "SELECT count(*) FROM rt_oncall WHERE on_call";

    // 규칙: 당직은 적어도 한 명. 둘 다 "다른 사람이 있으니 빠져도 된다"고 본다
    int runs = 0;
    std::printf("앨리스가 당직에서 빠지려 한다\n");
    bool left = with_retry(alice, [&](int attempt) {
        ++runs;
        int n = std::stoi(exec(alice, count));
        std::printf("  시도 %d: 당직 %d명\n", attempt, n);
        if (attempt == 1) {                      // 그 사이 밥이 먼저 빠지고 커밋
            exec(bob, "BEGIN ISOLATION LEVEL SERIALIZABLE");
            exec(bob, count);
            exec(bob, "UPDATE rt_oncall SET on_call = false WHERE name = '밥'");
            exec(bob, "COMMIT");
            std::printf("    (그 사이 밥이 빠지고 커밋)\n");
        }
        if (n < 2) return false;                 // 다시 읽어 보니 빠질 수 없다
        exec(alice, "UPDATE rt_oncall SET on_call = false WHERE name = '앨리스'");
        return true;
    });
    std::printf("  결과: %s, 트랜잭션 본문이 돈 횟수 %d\n",
                left ? "빠짐" : "빠질 수 없음", runs);
    std::printf("  지금 당직: %s\n",
                exec(alice, "SELECT string_agg(name, ', ') FROM rt_oncall "
                            "WHERE on_call").c_str());

    try {                                       // 다시 해도 같은 오류는 바로 올린다
        with_retry(alice, [&](int) {
            return exec(alice, "INSERT INTO rt_oncall VALUES ('밥', true)");
        });
    } catch (const DbError& e) {
        std::printf("중복 키는 다시 하지 않음: %s\n", e.state.c_str());
    }
    PQfinish(alice);
    PQfinish(bob);
}
```

```text
앨리스가 당직에서 빠지려 한다
  시도 1: 당직 2명
    (그 사이 밥이 빠지고 커밋)
    40001로 되돌려짐, 다시 한다
  시도 2: 당직 1명
  결과: 빠질 수 없음, 트랜잭션 본문이 돈 횟수 2
  지금 당직: 앨리스
중복 키는 다시 하지 않음: 23505
```

- **다시 읽고 다시 판단한다**: 두 번째 시도는 당직 수를 새로 읽어 1명임을 보고 빠지기를 거절했습니다. 실패한 UPDATE만 다시 했다면 규칙이 깨졌을 것입니다. 판단의 근거가 된 읽기까지 다시 해야 하므로, 본문 전체를 함수로 넘깁니다
- **다시 할 오류만**: 40001과 40P01만 다시 하고, 23505 같은 오류는 바로 올렸습니다. 같은 입력으로 다시 해도 같은 결과가 나오기 때문입니다. 횟수에도 끝을 둬서 계속 부딪히는 경우를 오류로 드러냅니다
- **본문은 여러 번 돈다**: 본문이 두 번 실행되었습니다. 그 안에서 메일을 보내거나 다른 서비스를 부르거나 메모리의 값을 바꿨다면 그 일도 두 번 일어납니다. 데이터베이스 바깥의 일은 커밋한 뒤에 하거나, 보낼 메시지를 같은 트랜잭션 안에서 테이블에 적어 두고 따로 보내는 방식(아웃박스)을 씁니다
- **백오프와 흔들림**: 기다리는 시간을 두 배씩 늘리고 무작위로 흔들어서, 부딪힌 트랜잭션들이 같은 순간에 다시 부딪히지 않게 합니다. 예제의 난수 씨앗을 42로 고정한 것은 실행마다 같게 하려는 것일 뿐이고, 실제로는 `std::random_device` 같은 것으로 씨앗을 줍니다

## 데이터베이스마다 다른 점

MySQL과 MariaDB의 InnoDB는 교착을 1213(SQLSTATE 40001)으로 알리고 트랜잭션 전체를 되돌리므로 같은 방식으로 다시 하면 됩니다. 그런데 잠금을 기다리다 시간이 다 된 1205는 기본 설정(`innodb_rollback_on_timeout`이 꺼짐)에서 그 문장 하나만 되돌리고 트랜잭션은 열어 둡니다. 이때는 직접 `ROLLBACK`한 뒤 처음부터 다시 할지 정해야 합니다. SQLite에서 다시 할 일은 주로 `SQLITE_BUSY`인데, 바쁜 동안 기다리는 시간과 `BEGIN IMMEDIATE`로 대부분을 피합니다([「트랜잭션」](#/read/cpp-database/sqlite-tx)).

<Note>
40001을 아예 피하는 방법도 있습니다. 행 하나를 고치는 일은 `UPDATE ... SET bal = bal - 10`처럼 데이터베이스 안에서 계산하고, 읽고 판단할 행은 `SELECT ... FOR UPDATE`로 잠가 두면 기다림은 생겨도 되돌림은 줄어듭니다([「낙관적 잠금」](#/read/cpp-database/tx-optimistic)). 다만 여러 행을 보고 판단하는 규칙에는 SERIALIZABLE과 재시도가 가장 덜 틀리는 길입니다.
</Note>

## 정리

- 40001과 40P01은 동시성 때문에 트랜잭션이 되돌려졌다는 뜻이므로, 읽기부터 포함한 트랜잭션 전체를 다시 한다
- 본문을 함수로 받아 BEGIN, COMMIT, 되돌리기, 다시 할 오류의 판단, 횟수 제한, 흔들린 백오프를 한곳에 두고, 다른 오류는 바로 올린다
- 본문은 여러 번 돌 수 있으므로 데이터베이스 바깥의 부수 효과는 커밋 뒤로 미루거나 아웃박스 테이블에 적는다
