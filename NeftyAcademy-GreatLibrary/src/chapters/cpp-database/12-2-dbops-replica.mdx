**복제**는 운영 서버(primary)의 변경을 대기 서버(standby, replica)로 계속 보내 같은 데이터를 유지하는 일입니다. 운영 서버가 죽으면 대기 서버를 올려 서비스를 잇고, 읽기 쿼리를 대기 서버로 나눠 운영 서버의 짐을 덜고, 다른 지역에 사본을 둡니다. 실수로 지운 데이터도 그대로 복제되므로 백업을 대신하지는 못합니다([「백업」](#/read/cpp-database/dbops-backup)).

## 대기 서버에 붙기

PostgreSQL의 스트리밍 복제는 운영 서버가 쓰는 WAL을 대기 서버로 흘려보내고, 대기 서버가 그것을 다시 적용(재생)합니다. 대기 서버는 `pg_basebackup -R`로 뜬 베이스 백업에서 시작하는데, `-R`이 운영 서버에 붙을 연결 정보(`primary_conninfo`)와 `standby.signal` 파일을 함께 써 둡니다. 재생하는 동안에도 읽기 쿼리를 받습니다. 아래 프로그램은 5432번에 운영 서버, 5433번에 대기 서버가 있다고 가정하고, 지연을 흉내 내려고 대기 서버의 재생을 잠시 멈춥니다. `pg_wal_replay_pause()`는 슈퍼유저나 EXECUTE 권한을 받은 역할만 부를 수 있고, 함수 권한은 데이터베이스마다 따로 줍니다.

```cpp pkg=libpq
#include <libpq-fe.h>
#include <chrono>
#include <cstdio>
#include <string>
#include <thread>

// 같은 기계에 운영 서버(5432)와 그 대기 서버(5433)가 있다고 가정한다
PGconn* open_as(const char* ports, const char* attrs) {
    std::string s = std::string("host=localhost,localhost port=") + ports +
                    " dbname=academy user=academy password=academy"
                    " target_session_attrs=" + attrs;
    return PQconnectdb(s.c_str());
}

// 첫 값을 돌려준다. 실패하면 SQLSTATE와 메시지
std::string one(PGconn* c, const char* sql) {
    PGresult* r = PQexec(c, sql);
    std::string v;
    if (PQresultStatus(r) == PGRES_TUPLES_OK)
        v = PQgetvalue(r, 0, 0);
    else if (PQresultStatus(r) == PGRES_FATAL_ERROR)
        v = std::string(PQresultErrorField(r, PG_DIAG_SQLSTATE)) + " " +
            PQresultErrorField(r, PG_DIAG_MESSAGE_PRIMARY);
    PQclear(r);
    return v;
}

// 대기 서버의 WAL 위치(받은 곳 또는 재생한 곳)가 lsn을 지났나
bool reached(PGconn* ro, const char* fn, const std::string& lsn) {
    std::string q = std::string("SELECT ") + fn + "() >= $1::pg_lsn";
    const char* v[] = {lsn.c_str()};
    PGresult* r = PQexecParams(ro, q.c_str(), 1, nullptr, v, nullptr, nullptr, 0);
    bool ok = PQresultStatus(r) == PGRES_TUPLES_OK && *PQgetvalue(r, 0, 0) == 't';
    PQclear(r);
    return ok;
}

bool wait_for(PGconn* ro, const char* fn, const std::string& lsn) {
    for (int i = 0; i < 500; ++i) {               // 10ms씩 최대 5초
        if (reached(ro, fn, lsn)) return true;
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
    return false;
}

int main() {
    struct { const char* ports; const char* attrs; } tries[] = {
        {"5433,5432", "read-write"},
        {"5432,5433", "standby"},
        {"5999,5432", "prefer-standby"},          // 5999에는 서버가 없다
    };
    for (auto& t : tries) {
        PGconn* c = open_as(t.ports, t.attrs);
        std::printf("%-15s port=%s → %s번, %s\n", t.attrs, t.ports, PQport(c),
                    one(c, "SELECT pg_is_in_recovery()") == "t" ? "대기 서버"
                                                               : "운영 서버");
        PQfinish(c);
    }

    PGconn* rw = open_as("5433,5432", "read-write");
    PGconn* ro = open_as("5432,5433", "standby");
    one(rw, "SET client_min_messages = warning");
    one(rw, "DROP TABLE IF EXISTS stock");
    one(rw, "CREATE TABLE stock (sku text PRIMARY KEY, qty int NOT NULL)");
    one(rw, "INSERT INTO stock VALUES ('A-1', 10)");
    wait_for(ro, "pg_last_wal_replay_lsn", one(rw, "SELECT pg_current_wal_lsn()"));
    std::printf("대기 서버에서 UPDATE → %s\n",
                one(ro, "UPDATE stock SET qty = 9").c_str());

    one(ro, "SELECT pg_wal_replay_pause()");      // 지연을 일부러 만든다
    for (int i = 0; i < 500; ++i) {
        if (one(ro, "SELECT pg_get_wal_replay_pause_state()") == "paused") break;
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
    one(rw, "UPDATE stock SET qty = 7 WHERE sku = 'A-1'");
    std::string lsn = one(rw, "SELECT pg_current_wal_lsn()");  // 커밋 뒤 위치
    bool got = wait_for(ro, "pg_last_wal_receive_lsn", lsn);
    bool applied = reached(ro, "pg_last_wal_replay_lsn", lsn);
    std::printf("재생을 멈춘 대기 서버, 운영 서버에서 qty를 7로 바꾼 뒤\n");
    std::printf("  받은 WAL: %s, 재생한 WAL: %s\n", got ? "커밋 지남" : "커밋 전",
                applied ? "커밋 지남" : "커밋 전");
    std::printf("  대기 서버에서 읽은 qty: %s\n",
                one(ro, "SELECT qty FROM stock").c_str());

    one(ro, "SELECT pg_wal_replay_resume()");
    bool done = wait_for(ro, "pg_last_wal_replay_lsn", lsn);
    std::printf("재생을 다시 시작하고 그 위치까지 기다린 뒤 (%s)\n",
                done ? "도착" : "시간 초과");
    std::printf("  대기 서버에서 읽은 qty: %s\n",
                one(ro, "SELECT qty FROM stock").c_str());
    one(rw, "DROP TABLE stock");
    PQfinish(ro);
    PQfinish(rw);
}
```

```text
read-write      port=5433,5432 → 5432번, 운영 서버
standby         port=5432,5433 → 5433번, 대기 서버
prefer-standby  port=5999,5432 → 5432번, 운영 서버
대기 서버에서 UPDATE → 25006 cannot execute UPDATE in a read-only transaction
재생을 멈춘 대기 서버, 운영 서버에서 qty를 7로 바꾼 뒤
  받은 WAL: 커밋 지남, 재생한 WAL: 커밋 전
  대기 서버에서 읽은 qty: 10
재생을 다시 시작하고 그 위치까지 기다린 뒤 (도착)
  대기 서버에서 읽은 qty: 7
```

- **연결 문자열로 고르기**: `host`와 `port`에 서버를 쉼표로 여럿 적으면 libpq는 차례대로 붙어 보고 `target_session_attrs`에 맞는 첫 서버에 머뭅니다. `read-write`는 앞에 적힌 대기 서버를 건너뛰고 운영 서버에, `standby`는 대기 서버에 붙었고, `prefer-standby`는 대기 서버가 없자 운영 서버로 물러섰습니다(`standby`와 `prefer-standby`는 14부터). 장애 조치로 운영 서버가 바뀌어도 같은 문자열로 새 운영 서버를 찾습니다
- **대기 서버는 읽기만**: 대기 서버의 트랜잭션은 모두 읽기 전용이라 UPDATE가 25006으로 거절되었습니다. 쓰기 연결과 읽기 연결을 따로 두고 쓰기는 늘 운영 서버로 보냅니다
- **복제 지연**: 기본인 비동기 복제에서 운영 서버는 대기 서버를 기다리지 않고 커밋을 끝냅니다. 재생을 멈춘 대기 서버는 커밋이 든 WAL을 이미 받았지만 재생 전이라 7로 바꾼 뒤에도 10을 읽었습니다. 평소의 지연은 밀리초 단위지만 큰 트랜잭션이나 네트워크 문제로 초 단위 넘게 벌어지기도 합니다
- **자기가 쓴 것 읽기**: 방금 쓴 사용자에게 옛 값을 보이면 안 되는 화면은, 쓴 뒤의 `pg_current_wal_lsn()`을 기억했다가 대기 서버의 `pg_last_wal_replay_lsn()`이 그 위치를 지난 뒤 읽거나, 그 사용자만 잠시 운영 서버에서 읽게 합니다. PostgreSQL 19부터는 대기 서버에서 `WAIT FOR LSN '위치' WITH (TIMEOUT '1s')` 한 문장으로 기다립니다

## 동기 복제

비동기 복제에서는 운영 서버가 죽을 때 아직 대기 서버로 가지 않은 커밋이 사라집니다. 이것이 안 되면 `synchronous_standby_names`에 대기 서버를 적어 동기 복제로 둡니다. 그러면 커밋은 `synchronous_commit` 값에 따라 대기 서버가 WAL을 받아 쓸 때(`remote_write`), 디스크에 내릴 때(`on`, 기본값), 재생까지 마칠 때(`remote_apply`)를 기다립니다. `remote_apply`면 커밋 직후 대기 서버에서 읽어도 새 값이 보입니다. 대신 커밋마다 왕복 지연이 붙고, 동기 대기 서버가 하나뿐인데 멈추면 운영 서버의 커밋도 멈추므로 `ANY 1 (s1, s2)`처럼 여럿 중 하나의 확인만 기다리게 둡니다. `synchronous_commit`은 트랜잭션마다 `SET LOCAL`로 바꿀 수 있어서, 주문은 기다리고 로그는 기다리지 않게 나눌 수 있습니다.

재생은 대기 서버의 쿼리를 오래 기다려 주지 않습니다. 운영 서버의 VACUUM이 지운 행을 대기 서버의 긴 쿼리가 아직 보고 있거나 운영 서버가 테이블에 배타 잠금을 걸면, 재생은 `max_standby_streaming_delay`(기본 30초)만 기다린 뒤 그 쿼리를 취소합니다(40001). `hot_standby_feedback`을 켜면 취소는 줄지만 운영 서버의 테이블이 부풀 수 있습니다. 대기 서버의 긴 보고서는 이 취소를 다시 시도할 오류로 다룹니다.

## 장애 조치

운영 서버가 죽으면 대기 서버를 `pg_promote()`로 운영 서버로 올립니다. 가장 위험한 것은 옛 운영 서버가 살아나 두 서버가 함께 쓰기를 받는 **스플릿 브레인**이라, 옛 서버를 확실히 막은 뒤 올리고, 옛 서버는 `pg_rewind`로 새 서버에 맞춰 대기 서버로 되돌립니다. 이 판단과 전환은 보통 Patroni, repmgr 같은 도구가 맡습니다. 프로그램은 끊긴 연결을 다시 맺고([「재연결과 타임아웃」](#/read/cpp-database/pool-reconnect)), 여러 서버를 적은 연결 문자열로 새 운영 서버를 찾으며, 비동기 복제였다면 마지막 몇 커밋이 없을 수 있음을 받아들입니다.

## 논리 복제와 MySQL

물리 복제는 클러스터 전체를 똑같이 만듭니다. **논리 복제**는 `CREATE PUBLICATION`과 `CREATE SUBSCRIPTION`으로 고른 테이블의 행 변경만 보내므로, 주 판이 다른 서버 사이에서도 되어 판 올림이나 일부 테이블 모으기에 씁니다. DDL은 복제되지 않아 스키마는 따로 맞추고, 시퀀스는 PostgreSQL 19부터 `FOR ALL SEQUENCES`로 값을 맞출 수 있습니다. MySQL과 MariaDB는 복제 서버가 binlog를 받아 재생합니다. 기본은 비동기이고, 반동기(semi-sync)를 켜면 복제 서버 하나 이상이 받았다는 확인을 기다립니다. 복제 서버는 `read_only`로 막아 두며 그때 쓰기는 1290 오류가 됩니다.

<Note>
대기 서버가 쓰는 **복제 슬롯**은 그 서버가 아직 받지 않은 WAL을 운영 서버가 지우지 못하게 붙잡습니다. 대기 서버를 없애고 슬롯을 잊으면 WAL이 끝없이 쌓여 디스크가 차고, WAL을 쓸 수 없게 된 운영 서버는 멈춥니다. `max_slot_wal_keep_size`로 붙잡을 양에 상한을 두거나 PostgreSQL 18부터는 `idle_replication_slot_timeout`으로 오래 쉬는 슬롯을 무효로 만들고, 슬롯과 지연을 늘 감시합니다([「모니터링」](#/read/cpp-database/dbops-monitor)).
</Note>

## 정리

- 스트리밍 복제는 WAL을 대기 서버로 보내 재생하고, 대기 서버는 읽기만 받으며(쓰기는 25006), libpq의 여러 호스트와 target_session_attrs로 운영 서버와 대기 서버를 골라 붙는다
- 비동기 복제의 대기 서버는 조금 늦으므로 자기가 쓴 것은 LSN까지 기다린 뒤(19부터 WAIT FOR LSN) 읽거나 운영 서버에서 읽고, 잃으면 안 되는 커밋은 동기 복제로 기다린다
- 장애 조치는 스플릿 브레인을 막은 뒤 대기 서버를 올리는 일이고, 프로그램은 재연결로 버티며, 복제 슬롯과 지연은 감시한다
