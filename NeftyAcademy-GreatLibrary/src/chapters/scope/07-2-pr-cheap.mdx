책상에 놓는 오실로스코프가 없어도 파형을 볼 길은 여러 가지입니다. 다만 싼 장비일수록 볼 수 있는 신호가 좁습니다. 이 쪽은 장비의 종류마다 이 책에서 본 신호 가운데 무엇이 보이는지를 따집니다. 값은 적지 않습니다. 자주 바뀌기 때문입니다.

## 다섯 가지

| 종류 | 보기 | 대역폭, 샘플링 속도 | 먼저 알아 둘 것 |
| --- | --- | --- | --- |
| 사운드 카드 | 컴퓨터의 소리 입력 | 20kHz쯤까지 | AC 결합이고 입력 전압이 작다 |
| 피코와 휴대폰 | Raspberry Pi Pico와 Scoppy 앱 | 150kHz, 500kS/s | 0V에서 3.3V까지만 받는다 |
| 조립식 | DSO138 | 200kHz, 1MS/s | 채널이 하나, 기록이 1024점 |
| USB 오실로스코프 | Hantek 6022BE | 20MHz, 48MS/s | 화면과 트리거를 PC가 맡는다 |
| 입문용 책상 장비 | Rigol DHO804 | 70MHz, 1.25GS/s | 채널을 다 켜면 샘플링 속도가 준다 |

- **숫자 둘을 함께 본다**: 대역폭은 변을 얼마나 눕히는지를, 샘플링 속도는 점을 얼마나 촘촘히 찍는지를 정합니다. 둘 가운데 먼저 걸리는 쪽이 그 장비의 한도입니다([「대역폭과 상승 시간」](#/read/scope/lm-bandwidth), [「샘플링 속도와 에일리어싱」](#/read/scope/lm-sampling))
- **채널이 나눠 쓴다**: 표의 샘플링 속도는 채널 하나만 켰을 때의 값입니다. 피코는 두 채널이 500kS/s를 나눠 쓰고, DHO804는 네 채널을 다 켜면 312.5MS/s가 됩니다
- **보기로 든 것일 뿐이다**: 종류마다 사양이 공개된 제품 하나를 골랐습니다. 같은 종류의 다른 제품은 숫자가 다릅니다

## 무엇이 보이나

```python
devices = [                              # (이름, 대역폭 Hz, 샘플링 속도 S/s)
    ("피코와 휴대폰", 150e3, 500e3),
    ("조립식", 200e3, 1e6),
    ("USB 오실로스코프", 20e6, 48e6),
    ("입문용 책상 장비", 70e6, 1.25e9),
]
signals = [("서보의 펄스", 50), ("UART 9600bps", 4800), ("UART 115200bps", 57600),
           ("I2C 100kHz", 100e3), ("벅 컨버터의 리플", 500e3), ("SPI 1MHz", 1e6),
           ("SPI 10MHz", 10e6), ("변 뒤의 울림", 80e6)]

def reach(bw, rate):                     # 대역폭과 속도 가운데 먼저 걸리는 쪽
    return min(bw, rate / 2.5)

def first(freq, times):                  # 주파수의 times배까지 닿는 첫 장비
    for name, bw, rate in devices:
        if reach(bw, rate) >= times * freq:
            return name
    return None

for name, freq in signals:
    a, b = first(freq, 1), first(freq, 5)
    rough = f"{a}부터 보인다" if a else "어느 것으로도 제 높이로 보이지 않는다"
    fine = f". 변의 모양은 {b}부터" if b else ""
    print(f"{name}: {rough}{fine}")
```

```text
서보의 펄스: 피코와 휴대폰부터 보인다. 변의 모양은 피코와 휴대폰부터
UART 9600bps: 피코와 휴대폰부터 보인다. 변의 모양은 피코와 휴대폰부터
UART 115200bps: 피코와 휴대폰부터 보인다. 변의 모양은 USB 오실로스코프부터
I2C 100kHz: 피코와 휴대폰부터 보인다. 변의 모양은 USB 오실로스코프부터
벅 컨버터의 리플: USB 오실로스코프부터 보인다. 변의 모양은 USB 오실로스코프부터
SPI 1MHz: USB 오실로스코프부터 보인다. 변의 모양은 USB 오실로스코프부터
SPI 10MHz: USB 오실로스코프부터 보인다. 변의 모양은 입문용 책상 장비부터
변 뒤의 울림: 어느 것으로도 제 높이로 보이지 않는다
```

- **"보인다"는 대역폭이 그 주파수에 닿는다는 뜻이다**: 그 끝에서는 높이가 30%쯤 깎입니다. 있다는 것과 주기는 알 수 있지만 변은 둥글게 뭉개집니다
- **변의 모양은 다섯 배부터**: 네모난 신호의 변과 꼭대기를 믿으려면 대역폭이 그 신호의 다섯 배쯤은 되어야 합니다. UART는 0과 1이 번갈아 올 때의 주파수가 속도의 반이어서 그 값을 넣었습니다
- **수백 kHz와 수십 MHz 사이가 빈다**: 조립식과 피코는 서보, 느린 UART, 단추의 떨림까지입니다. I2C의 둥근 변이나 전원의 리플을 보려면 USB 오실로스코프의 급이 필요합니다
- **울림은 입문용 장비로도 깎여 보인다**: 80MHz의 울림은 70MHz 장비에서 낮아진 채로 그려집니다. 봉우리의 높이를 그대로 믿으면 안 됩니다([「링잉과 오버슈트」](#/read/scope/sh-ringing))
- **사운드 카드는 이 셈에 넣지 않았다**: 평평한 곳이 기울고 0V의 자리가 없어서, 디지털 신호의 높이를 잴 수 없기 때문입니다([「DC 결합, AC 결합, 접지 기준선」](#/read/scope/sc-coupling))

## 적힌 숫자를 확인하기

```python
for seen in (1.75e-6, 17.5e-9, 5e-9):    # 화면에서 읽은 변의 시간(10%에서 90%까지)
    bw = 0.35 / seen
    unit, scale = ("MHz", 1e6) if bw >= 1e6 else ("kHz", 1e3)
    ns = seen * 1e9
    print(f"변이 {ns:6.1f}ns로 보이면 대역폭은 적어도 {bw / scale:.0f}{unit}")
```

```text
변이 1750.0ns로 보이면 대역폭은 적어도 200kHz
변이   17.5ns로 보이면 대역폭은 적어도 20MHz
변이    5.0ns로 보이면 대역폭은 적어도 70MHz
```

- **빠른 변 하나를 넣어 본다**: 장비에 달린 보정용 네모파나 보드의 GPIO가 내는 변을 가장 빠른 시간/칸으로 늘려, 10%에서 90%까지의 시간을 잽니다. 0.35를 그 시간으로 나눈 값이 대역폭의 어림입니다
- **"적어도"로 읽는다**: 화면의 변에는 신호가 본래 가진 느림과 장비의 느림이 함께 들어 있습니다. 넣은 변이 느렸다면 장비의 대역폭은 셈한 값보다 넓습니다. 거꾸로, 적힌 대역폭에서 나와야 할 시간보다 훨씬 긴 변만 보인다면 넣은 신호부터 의심합니다
- **찍는 간격보다 짧은 변은 잴 수 없다**: 1MS/s의 장비는 점이 1µs마다 찍힙니다. 1.75µs짜리 변은 점 두 개로 그려지므로 이 방법이 거칩니다
- **사양서의 뜻과 다를 수 있다**: 싼 장비의 상자에 적힌 MHz가 -3dB 대역폭인지 샘플링 속도인지부터 확인합니다

## 종류마다 조심할 것

- **사운드 카드**: 소리 입력은 AC 결합이고 20Hz 아래와 20kHz 위가 잘립니다. 보호 회로 없이 큰 전압을 넣으면 컴퓨터가 상할 수 있고, 화면의 전압 눈금도 믿을 수 없습니다. 소리 신호의 모양을 구경하는 데에 맞습니다
- **피코와 휴대폰**: 피코의 ADC에 선이 그대로 닿으므로 0V 아래나 3.3V 위의 전압을 넣으면 안 됩니다. 그 밖의 전압은 앞에 분배기나 보호 회로를 달아야 합니다([「입력 보호」](#/read/analog-digital/cd-protect))
- **조립식**: 채널이 하나라서 클럭과 데이터를 나란히 볼 수 없습니다. 입력은 1배 프로브로 50V까지입니다. 1kHz, 3.3V의 시험 신호가 달려 있어 화면 읽기의 첫 연습에는 넉넉합니다
- **USB 오실로스코프**: 화면이 PC에 있고, 트리거도 PC의 프로그램이 받은 점들에서 찾습니다. 접지는 USB를 거쳐 PC의 접지에 이어집니다([「접지 집게가 닿는 곳」](#/read/scope/pb-ground))
- **입문용 책상 장비**: 대역폭과 기록 길이가 넉넉하고 트리거가 장비 안에서 걸립니다. 그래도 프로브의 접지와 10배의 보정은 쓰는 사람의 몫입니다([「1배와 10배, 보정」](#/read/scope/pb-x10))

## 고를 때 볼 것

- **채널이 둘 이상인가**: I2C와 SPI는 클럭과 데이터를 함께 봐야 읽힙니다([「I2C: 시작, 주소, ACK」](#/read/scope/bs-i2c))
- **보려는 클럭의 다섯 배가 되는가**: 라즈베리파이로 I2C와 1MHz 안팎의 SPI, 전원의 리플까지 보려면 20MHz의 급이 바닥입니다
- **DC 결합과 세 가지 트리거 모드가 있는가**: 전원이 켜지는 순간이나 한 번 오고 마는 메시지는 단발로만 잡힙니다([「자동, 일반, 단발」](#/read/scope/tr-modes))
- **내용이 궁금한 것인가, 모양이 궁금한 것인가**: 주고받는 값이 궁금하다면 로직 분석기가 먼저입니다([「로직 분석기를 쓸 때」](#/read/scope/bs-logic))
- **재는 버릇은 장비를 가리지 않는다**: 어느 장비든 접지를 어디에 물리는지, 기대한 모양이 무엇인지부터 정합니다([「측정 전 점검표」](#/read/scope/pr-checklist))

<Note>
이 쪽의 장비 가운데 제가 직접 써 본 것은 없습니다. 표의 숫자는 참고 문서에 적은 제조사와 판매처의 사양, sigrok 위키, Scoppy의 안내 글에서 옮겼고, 보기로 든 제품을 권하는 뜻은 아닙니다. Scoppy는 새 판에서 샘플링 속도를 더 높일 수 있다고 적고 있습니다. 사운드 카드의 20kHz는 흔히 드는 어림이며 제품마다 다릅니다. "무엇이 보이나"의 셈은 대역폭의 다섯 배와 샘플링 속도의 2.5분의 1이라는 어림만으로 가른 것이어서, 잡음과 분해능, 기록 길이는 들어 있지 않습니다.
</Note>

## 정리

- 싼 장비는 대역폭과 샘플링 속도 가운데 먼저 걸리는 쪽이 한도다. 수백 kHz의 장비는 서보와 느린 UART까지 본다
- I2C의 변, 전원의 리플, 1MHz의 SPI를 모양까지 보려면 20MHz의 급이, 10MHz의 SPI에는 70MHz의 급이 필요하다
- 적힌 대역폭은 빠른 변 하나를 넣어 0.35를 변의 시간으로 나눈 값으로 어림해 본다. 그 값은 "적어도"다
