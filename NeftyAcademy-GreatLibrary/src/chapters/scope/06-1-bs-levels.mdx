- **문턱은 받는 쪽의 것이다**: 같은 파형도 누가 받느냐에 따라 읽히는 값이 다릅니다. 받는 칩의 데이터시트에서 입력 LOW의 최댓값과 입력 HIGH의 최솟값을 찾아, 그 두 값에 커서를 놓습니다
- **두 문턱의 사이는 약속이 없다**: 0.8V와 2.0V 사이의 전압이 0으로 읽힐지 1로 읽힐지는 정해져 있지 않습니다. 칩마다 다르고, 같은 칩에서도 그때그때 다를 수 있습니다
- **평평한 곳과 변을 따로 본다**: 평평한 곳은 두 문턱의 바깥에 넉넉히 떨어져 있어야 하고, 변은 두 문턱의 사이를 빨리 지나야 합니다. 그림의 변은 그 사이를 81ns에 지납니다
- **HIGH가 3.3V가 아닐 수 있다**: 그림의 HIGH는 2.98V입니다. 핀에서 선까지의 저항 510Ω과 풀다운 4.7kΩ이 3.3V를 나눠 가졌기 때문입니다

## 여유를 셈한다

```python
def check(receiver, low_max, high_min, low, high):
    lo, hi = low_max - low, high - high_min
    word = "읽힌다" if min(lo, hi) > 0 else "읽힌다는 보장이 없다"
    print(f"{receiver}: LOW 여유 {lo:+.2f}V, HIGH 여유 {hi:+.2f}V → {word}")

low, high = 0.00, 2.98                   # 화면의 평평한 곳에서 읽은 높이
check("라즈베리파이의 핀", 0.8, 2.0, low, high)
check("3.3V로 도는 I2C 장치", 0.3 * 3.3, 0.7 * 3.3, low, high)
check("5V로 도는 아두이노", 1.5, 3.0, low, high)
```

```text
라즈베리파이의 핀: LOW 여유 +0.80V, HIGH 여유 +0.98V → 읽힌다
3.3V로 도는 I2C 장치: LOW 여유 +0.99V, HIGH 여유 +0.67V → 읽힌다
5V로 도는 아두이노: LOW 여유 +1.50V, HIGH 여유 -0.02V → 읽힌다는 보장이 없다
```

- **화면에서 읽은 높이를 넣는다**: 보내는 칩의 사양서에 적힌 숫자가 아니라, 지금 이 선의 평평한 곳을 커서로 읽은 값입니다. 받는 칩의 핀 가까이에서 잽니다([「어디에 대야 하나: 측정점 고르기」](#/read/scope/pb-points))
- **여유는 잡음이 쓸 수 있는 몫이다**: HIGH 여유가 0.98V면 그만큼의 잡음이나 울림이 얹혀도 HIGH로 읽힙니다. 울림의 골이 0.99V까지 내려오던 선은 그 순간의 여유가 음수였습니다([「링잉과 오버슈트」](#/read/scope/sh-ringing))
- **5V 입력에는 빠듯하다**: 같은 2.98V가 5V로 도는 아두이노의 문턱 3.0V에는 닿지 않습니다. 될 때도 있고 안 될 때도 있는 연결이 이렇게 만들어집니다([「3.3V로 5V 입력 몰기」](#/read/analog-digital/lv-up))
- **GND가 다르면 높이도 다르다**: 두 보드의 GND 사이에 전압 차이가 있으면, 보내는 쪽의 0V가 받는 쪽에게는 0V가 아닙니다. 집게를 받는 쪽의 GND에 물리고 잽니다

## 문턱 사이에 머무는 모양

<Figure caption="CH1은 시정수가 1µs인 선을 지난 펄스 셋이고, 가운데 것은 폭이 0.6µs다. CH2는 HIGH를 내는 출력에 다른 출력이 6µs 동안 LOW를 낸 선이다. 가로 커서는 CH1의 0.8V와 2.0V">
  <Scope tdiv={5e-6} dt={5e-8} traces={[{ name: 'CH1 느린 선', data: runt, vdiv: 1, pos: 0.3 }, { name: 'CH2 맞붙은 선', data: fight, vdiv: 1, pos: -3.8 }]} cursorsV={[0.8, 2.0]} />
</Figure>

```python
import math

V, LOW, HIGH = 3.3, 0.8, 2.0

def band_time(tau):                      # 변이 두 문턱 사이에 머무는 시간
    return tau * math.log((V - LOW) / (V - HIGH))

def peak(width, tau):                    # 느린 선에서 펄스가 오르는 높이
    return V * (1 - math.exp(-width / tau))

def reads(v):
    if v > HIGH:
        return "HIGH"
    return "LOW" if v < LOW else "정해져 있지 않다"

tau = 1e-6                               # 1kΩ과 1nF
print(f"시정수 1µs인 선: 문턱 사이에 {band_time(tau) * 1e9:.0f}ns 머문다")
for width in (0.2e-6, 0.6e-6, 1e-6, 3e-6):
    v = peak(width, tau)
    print(f"폭 {width * 1e6:.1f}µs인 펄스: {v:.2f}V까지 → {reads(v)}")
r_high, r_low = 40, 40                   # 맞붙은 두 출력의 저항
level = V * r_low / (r_high + r_low)
print(f"맞붙은 출력: {level:.2f}V에 머문다 → {reads(level)}, "
      f"{V / (r_high + r_low) * 1e3:.0f}mA가 흐른다")
```

```text
시정수 1µs인 선: 문턱 사이에 654ns 머문다
폭 0.2µs인 펄스: 0.60V까지 → LOW
폭 0.6µs인 펄스: 1.49V까지 → 정해져 있지 않다
폭 1.0µs인 펄스: 2.09V까지 → HIGH
폭 3.0µs인 펄스: 3.14V까지 → HIGH
맞붙은 출력: 1.65V에 머문다 → 정해져 있지 않다, 41mA가 흐른다
```

- **다 오르지 못한 펄스**: CH1의 가운데 펄스는 선의 시정수보다 짧아서 1.49V에서 멈춥니다. 받는 칩이 이것을 셀지 말지는 정해져 있지 않습니다. "가끔 하나를 빠뜨린다"와 "가끔 하나를 더 센다"가 여기서 나옵니다. 폭으로 거는 트리거가 이런 펄스를 골라 잡습니다([「펄스 폭 트리거로 드문 사건 잡기」](#/read/scope/tr-pulse))
- **평평하게 머무는 어중간한 전압**: CH2는 3.3V이던 선이 6µs 동안 1.65V로 내려앉습니다. 잡음이라면 이렇게 평평하지 않습니다. 두 출력이 서로 다른 값을 내며 맞붙은 모습이고, 그동안 핀 하나의 한도 16mA를 넘는 41mA가 흐릅니다([「3.3V, 전류 한계, 보호 저항」](#/read/libgpiod/gp-electrical))
- **누운 변**: 시정수가 1µs인 선은 오를 때마다 654ns를 문턱 사이에서 보냅니다. 그동안 잡음이 얹히면 변 하나가 여러 번으로 읽힙니다([「단추의 떨림」](#/read/scope/sh-bounce))
- **0V까지 내려가지 않는 LOW**: 끌어내리는 트랜지스터에 비해 풀업 저항이 너무 작으면 LOW가 문턱 가까이에 떠 있습니다. 평평한 곳의 높이를 커서로 읽어 LOW의 문턱과 견줍니다

## 화면에 없는 것

- **칩이 어떻게 읽었는지**: 오실로스코프는 전압을 보여 줄 뿐입니다. 문턱 사이의 전압을 칩이 0으로 읽었는지 1로 읽었는지는 프로그램이 읽은 값이나 로직 분석기로 확인합니다([「로직 분석기를 쓸 때」](#/read/scope/bs-logic))
- **값이 바뀌는 정확한 전압**: 데이터시트의 두 숫자는 "이 바깥이면 틀림없다"는 약속입니다. 실제로 값이 바뀌는 전압은 그 사이의 어딘가이고 칩마다 다릅니다([「어중간한 전압이 하는 일」](#/read/analog-digital/tw-undefined))
- **프로브가 얹은 것인지 아닌지**: 긴 접지선이 만든 울림은 선에 없던 것입니다. 문턱을 넘나드는 울림이 보이면 접지를 짧게 하고 다시 봅니다([「접지 집게가 닿는 곳」](#/read/scope/pb-ground))

<Note>
두 그림은 ngspice 42로 돌린 결과입니다. 핀의 출력 저항 40Ω, 선의 커패시턴스 220pF, 느린 선의 1kΩ과 1nF, 두 출력이 맞붙는 때는 제가 고른 값이고 진짜 칩을 잰 것이 아닙니다. 표의 문턱은 라즈베리파이의 문서, NXP의 I2C 규격, SparkFun의 설명에서 옮겼습니다. 다른 칩은 그 칩의 데이터시트를 봐야 합니다. 장비를 찍은 화면이 아니라는 점은 앞 장과 같습니다.
</Note>

## 정리

- 받는 칩의 두 문턱에 가로 커서를 놓으면, 평평한 곳의 여유와 변이 문턱 사이에 머무는 시간이 보인다
- 여유는 화면에서 읽은 높이와 문턱의 차이다. 보호 저항과 풀다운, 전압이 다른 상대가 여유를 줄인다
- 어중간한 전압에 평평하게 머물면 맞붙은 출력이고, 다 오르지 못한 펄스가 보이면 선이 느린 것이다
